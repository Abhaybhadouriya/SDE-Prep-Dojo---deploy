Interview questions with best answers

Level 5 - Interview-ready
What does the Microsoft SDE2 design round look like?

Usually 60-75 minutes. Either a pure HLD, or HLD followed by LLD and code for one component. Behavioural questions are mostly kept for the AA round.

How to answer

Ask at the start whether they want code later, and budget time for it.

Likely follow-ups
  • Can you write the interface for this service?
  • How would you test it?
Design a URL shortener that works across regions. How do you make IDs unique?

Give each region (or ID service instance) its own range or a machine-ID bit field (Snowflake-style: time + machine + sequence), then Base62-encode. No cross-region coordination on the write path. See URL Shortener (TinyURL) and Distributed Unique ID Generator (Snowflake).

How to answer

Start simple (single counter), show where it breaks, then evolve.

Likely follow-ups
  • What if a machine's clock goes backwards?
  • How do you route reads to the nearest region?
OT or CRDT for a collaborative editor?

OT needs a central server to transform operations in order; it is proven (Google Docs). CRDTs merge without a central order, good for offline and peer-to-peer, but cost more metadata. For a server-based product, OT or a server-ordered CRDT both work. See Collaborative Editor (Google Docs).

How to answer

Explain convergence: all users must end with the same document.

Likely follow-ups
  • How do you store document history?
  • How do you show other users' cursors?
Design a service that pushes config changes to N microservices.

A versioned config store (strongly consistent, like etcd), services watch for changes or poll with a version number, changes roll out gradually with validation and instant rollback. See Distributed Configuration Service.

How to answer

Talk about safety: a bad config is a top cause of outages.

Likely follow-ups
  • What if a service misses an update?
  • How do you roll out to 1% first?
Design a distributed LRU cache with O(1) operations.

Each node: hash map plus doubly linked list. Across nodes: consistent hashing, replication for hot keys, and locks or striped locks for concurrency. See Distributed Cache (Redis-like).

How to answer

Do the single-node LLD crisply, then scale out.

Likely follow-ups
  • How do you test the eviction order?
  • What happens when a node dies?
Design a multi-tenant OTP service.

Generate a random code per request, store a hash with a short TTL keyed by user and request ID, rate limit sends and attempts per user, deliver via a queue to SMS/email providers with fallbacks. See Authentication & SSO Service.

How to answer

Security first: hash codes, limit attempts, never log the code.

Likely follow-ups
  • Same user logged in on web and mobile?
  • Provider is slow: what then?
I have never designed a rate limiter. How do I survive the question?

Reason from first principles: where it sits (gateway), what it counts (requests per key per window), where counts live (shared store), and what happens on overflow (reject with 429). A candidate passed exactly this way (post 7635697). See Distributed Rate Limiter.

How to answer

Think aloud and state assumptions; that is what Microsoft says it wants.

Likely follow-ups
  • Fixed window vs sliding window?
  • How do you debug a server that is suddenly slow?
What is the AA round?

An "As Appropriate" round with a senior manager near the end of the loop. It covers growth mindset, collaboration, a deep dive of your past project and sometimes a short design.

How to answer

Prepare one project you can draw end to end, with your exact role and numbers.

Likely follow-ups
  • What would you change in that design today?
  • How do you use AI tools?
Tell me about a time you learned something quickly (growth mindset).

For a networking engineer: learning Kubernetes networking by mapping Services to iptables NAT and CNI overlays to VXLAN, then shipping something real with it.

How to answer

Situation, what you did, result, and what you learned about how you learn.

Likely follow-ups
  • What was hardest?
  • How did you check you really understood it?
