Common mistakes and tips from the posts

  • Misreading a story-wrapped problem. One candidate solved a slightly different problem because the scenario was long (post 8473279). Restate the problem and confirm with an example before coding.
  • Not asking until it is clear. A follow-up about lakes inside islands stayed unclear and the loop was rejected (post 8564735). Ask for a concrete input and output.
  • Weak DP. A candidate strong elsewhere lost an onsite to a knapsack-style problem (post 8611299).
  • Over-preparing HLD for L3/L4. Several posts show weeks of system design prep that was never used. Confirm the format first.
  • Tip: when a coding problem grows into design, name a concrete tool you would use (a queue, a key-value store) and why (post 7693483).
  • Tip: for any design round, start simple and add load balancers or caches only when a bottleneck is shown (post 6668243).
