Worked example: dedupe device events within 10 seconds

An L4 phone screen (post 8500374, Sept 2026) asked to drop repeats of the same device event within 10 seconds, then asked system-design follow-ups. A similar "print a message only if not seen in the last 10 seconds" problem opened another L4 loop (post 8611299).

  1. Coding core. A hash map from event key to last-seen time. If now minus last-seen is under 10 seconds, drop it. O(1) per event.
  2. Memory follow-up. The map grows forever. Evict old keys with a queue ordered by time, or a time-bucketed ring of sets (like a timer wheel).
  3. Scale follow-up. Many devices: partition the stream by device ID (Kafka-style), so each worker keeps its own map. Same key, same worker.
  4. Failure follow-up. A worker restarts and loses its map: accept a few duplicates, or keep state in a shared store with a TTL.
