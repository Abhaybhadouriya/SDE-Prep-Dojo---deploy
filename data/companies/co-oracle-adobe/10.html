Interview Q&A

How do Oracle and Adobe design rounds differ?

Oracle often mixes DSA and design in one hour, may ask you to code the main methods after the HLD, and has an HM or bar-raiser style final round. Adobe tends to start from classes or APIs and then scale the same problem, with an HM round that often discusses AI integration and a director round that can bring a new domain.

How to answer

Show you know the format so you can manage time: in a mixed Oracle hour, agree on time split at the start.

Likely follow-ups
  • How do you split a mixed hour? (Ask; aim for about half each.)
  • What if the director asks a domain you don't know? (Clarify the business flow first, then map to known patterns.)
Design BookMyShow focusing only on seat-locking concurrency.

Each seat for a show is a row with a status and version. To hold a seat, run a conditional update (status AVAILABLE to HELD, with a hold expiry) or take a short Redis lock with TTL per seat. Payment confirms the hold; an expiry job releases stale holds. In code, avoid one global lock: lock per show or per seat, always in a fixed order to avoid deadlock.

How to answer

Give two options (optimistic version check vs pessimistic lock) and pick one with a reason. Mention lock ordering to show threading knowledge.

Likely follow-ups
  • What if the lock holder crashes? (TTL frees it.)
  • Many users want the same seat? (First conditional update wins; others get a fast 'taken'.)
  • How would you write this in Java? (ConcurrentHashMap per show, tryLock with timeout.)
Design top-100 users by event count over the last hour.

Events flow into Kafka. A stream processor (Flink) keeps counts per user in a sliding or hopping window, and each partition emits its local top-K; a final step merges them. For very high volume, a Count-Min Sketch plus a heap gives an approximate answer with small memory. Batch (Spark) can recompute exact numbers later.

How to answer

Say batch vs streaming out loud, then window type, then exact vs approximate. Be ready to code the heap merge.

Likely follow-ups
  • Why partition by user id? (All events for a user land in one counter.)
  • Late events? (Watermarks and allowed lateness.)
Design a log ingestion system.

Agents on each host ship logs to a collector tier, which writes to Kafka for buffering. Consumers index recent logs in a search store and archive older logs to object storage. Queries hit the index for recent data and scan archives for older data. Plan for spikes, back-pressure and per-service quotas.

How to answer

Use your experience with syslog or router logs. Talk about volume, retention tiers and what happens when the indexer falls behind.

Likely follow-ups
  • How do you keep the agent from hurting the host? (Rate limits, local buffer.)
  • How do you query a week of logs fast? (Time-partitioned indexes.)
Design a rate limiter, then a file upload system (Adobe style: start small, then scale).

Start with a RateLimiter interface and a token bucket class. Then scale: shared counters in Redis, atomic updates, sharding by key. For uploads: get a pre-signed URL, upload chunks directly to object storage, resume on failure, then trigger async processing and virus scan.

How to answer

Narrate the jump from one process to many: what breaks (shared state, races) and how you fix it.

Likely follow-ups
  • What if Redis is slow? (Local buckets with periodic sync.)
  • A 5 GB upload fails at 90 percent? (Chunked, resumable upload.)
Design a URL shortener, and show your numbers.

Write path: generate an id (counter range per server or a Snowflake id), encode in base62, store the mapping. Read path: cache, then DB, then redirect. For numbers, state assumptions (writes per day, read-to-write ratio, years kept) and compute storage and QPS step by step.

How to answer

Oracle called out made-up numbers, so show the arithmetic, not just the result.

Likely follow-ups
  • 301 or 302 redirect? (302 if you need analytics.)
  • Custom aliases? (Uniqueness check.)
Design an API gateway.

The gateway terminates TLS, authenticates (JWT check), applies rate limits, routes to services, and adds retries, timeouts and logging. It keeps routing config in a store and pushes it to gateway nodes. It is stateless, so it scales behind an L4 load balancer.

How to answer

This is the networking engineer's home ground: talk about the control plane (config) and data plane (requests) separately.

Likely follow-ups
  • Authn vs authz? (Who you are vs what you can do.)
  • How does config reach all nodes? (Watch a config store; versioned rollout.)
Design an autocomplete system for a large search box.

Build top-K suggestions per prefix offline from query logs and serve them from a trie or a prefix-to-list map in memory, sharded by prefix. Update periodically, cache popular prefixes at the edge, and rank by frequency and freshness.

How to answer

Adobe started from a trie and then asked about millions of queries, ranking and latency: follow that order.

Likely follow-ups
  • How do you add trending queries quickly? (A small real-time layer merged with the offline one.)
  • Typos? (Edit-distance fallback.)
How would you add an AI feature to a product, as an Adobe HM might ask?

Define the user task, choose a hosted or self-run model, add a gateway with quotas and caching, protect inputs and outputs (prompt injection, unsafe output), and measure quality and cost. Keep a non-AI fallback.

How to answer

Keep it practical: latency, cost per request, failure handling, evaluation.

Likely follow-ups
  • How do you stop costs exploding? (Quotas, caching, smaller models for easy cases.)
