Interview Q&A for the Flipkart loop

BookMyShow: two users click the same seat at the same moment. What happens?

Seat selection creates a short hold: a conditional update such as UPDATE show_seat SET status='HELD', held_by=?, hold_until=now()+10min WHERE show_id=? AND seat_id=? AND status='FREE'. Exactly one update succeeds (1 row affected); the other user sees "seat taken". Payment success flips HELD to BOOKED; a sweeper or the TTL releases expired holds. A unique constraint on (show, seat) in the bookings table is the final guard.

How to answer

Name the race, show the single atomic statement, then expiry and the final guard. Mention optimistic vs pessimistic locking and why the conditional update is optimistic.

Likely follow-ups
  • The third-party seat-lock API is slow and costly: how do you call it less?
  • Which API does the seat page call first, and what does it return?
Flash sale for 15 minutes: how do you avoid both overselling and underselling?

Overselling is prevented by an atomic decrement of stock in Redis (a Lua script that checks > 0 then decrements) before an order is created. Underselling happens when stock is reserved but never paid: fix it with a reservation TTL that returns stock, and a reconciler that compares Redis with the order DB. Put a waiting room in front so only as many users enter as the system can serve, and push a "sold out" flag to the CDN so late users stop hitting the backend.

How to answer

Say both failure words out loud, give one mechanism for each, then load protection.

Likely follow-ups
  • Redis crashes mid-sale?
  • One shard per product is too hot: split the counter?
You said "Elasticsearch" for song search. Explain how it finds "songs by Arijit" quickly.

Elasticsearch keeps an inverted index: for each word (after lower-casing and stemming), a sorted list of document ids containing it. A query looks up "arijit" and gets the list directly instead of scanning all songs. Fields like singer can be exact-match keyword fields for filtering. Data is split into shards across nodes, each with replicas; a query fans out to shards and merges the top results. Updates arrive from the main DB through a pipeline (for example CDC to Kafka to an indexer), so search is eventually consistent.

How to answer

Inverted index, analyzers, shards and replicas, how data gets in. Two candidates lost marks here.

Likely follow-ups
  • Why not just SQL LIKE '%arijit%'?
  • Typo tolerance?
Design round opens with "Design an airline ticket system." How do you split your 60 minutes?

Ask first: "Do you want LLD, HLD, or both?" If both: 5 min requirements, 15 min entities and relations (Flight, Schedule, Seat, Booking, Passenger, Payment), 10 min APIs and schema, 5 min one service's key method (for example holdSeats), then 20 min HLD (services, cache for search, DB, locking, payments) and 5 min for questions.

How to answer

Show a plan out loud; interviewers like seeing you manage time.

Likely follow-ups
  • Which design pattern fits fare rules?
Design payments with multiple gateways (Razorpay, PayU, ...). How do you pick a gateway and avoid double charges?

A payment service creates a payment record with an idempotency key (order id + attempt). A router chooses a gateway by rules and live health (success rate, latency), with fallback on failure. Every call to a gateway carries the key so a retry cannot charge twice. Gateway callbacks (webhooks) update status; a reconciliation job compares our records with gateway reports daily and fixes "unknown" states.

How to answer

Idempotency first, routing second, reconciliation third.

Likely follow-ups
  • Timeout from the gateway: charged or not?
Shopping feed: when a user unfollows a brand, its posts must disappear from their feed. How?

If feeds are precomputed (push / fan-out on write), store each feed entry with its author id; on unfollow, emit an event that removes that author's entries from the user's feed cache (or filter at read time against the current follow set until cleanup runs). For big brands with millions of followers use pull (fan-out on read) instead, which makes unfollow automatic.

How to answer

Tie the answer to push vs pull and show the read-time filter as the safety net.

Likely follow-ups
  • Schema for likes, comments and sticker reactions?
Machine coding: "Build an in-memory cache where the eviction policy is chosen at runtime." What structure do you show?

A Cache class depends on an EvictionPolicy interface (keyAccessed, keyAdded, evict) and a Storage interface. LRU and LFU are two implementations; a factory picks one from config. This is the Strategy pattern. Add a demo/driver class and handle capacity-full and missing-key cases.

How to answer

Interfaces first, one working policy, then the second policy to prove extensibility.

Likely follow-ups
  • Make it thread-safe.
  • Add TTL without changing existing classes.
Call manager for customer support: route calls to free agents and never drop a call.

Incoming calls go into a durable queue per skill/language. An agent-state service tracks each agent (free, busy, offline) via heartbeats. A dispatcher pops the oldest call and assigns it to a free agent atomically (compare-and-set on agent state). If no agent answers in N seconds, the call goes back to the front of the queue. Calls waiting too long get a callback option. Never dropping means the queue is persisted and assignment is acknowledged.

How to answer

Queue, state, atomic assignment, timeout and requeue.

Likely follow-ups
  • Priority customers?
