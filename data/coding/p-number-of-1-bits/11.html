Interview follow-ups

Prove that n & (n - 1) removes exactly the lowest set bit.

Let n = X·1·0t. Then n - 1 = X·0·1t (the borrow flips the lowest 1 and all zeros below it, and stops there). The AND keeps X where both agree and gives 0 at every flipped position: X·0·0t.

How to answer

Write one example (52 and 51) in binary and point at the flipped suffix.

Likely follow-ups
  • How do you isolate that bit instead? (n & -n, because -n = ~n + 1.)
The function is called billions of times. Make it faster.

Precompute a 256-entry table of byte popcounts and add four lookups; it is branch-free and the table stays in L1. Or use SWAR: n -= (n >> 1) & 0x55555555; n = (n & 0x33333333) + ((n >> 2) & 0x33333333); n = (n + (n >> 4)) & 0x0F0F0F0F; return (n * 0x01010101) >> 24; (unsigned arithmetic). Best of all is the CPU's POPCNT via the builtin.

How to answer

Mention the trade-off: the table costs memory and cache, SWAR costs a few ALU ops, the builtin depends on the target CPU flags.

Likely follow-ups
  • Why a 256 table and not 65,536? (64 K entries thrash L1; four 8-bit lookups are usually faster than two 16-bit ones.)
Count set bits for every number from 0 to n.

That is Counting Bits (LC 338): bits[i] = bits[i >> 1] + (i & 1), or bits[i] = bits[i & (i - 1)] + 1. Each entry reuses a smaller, already computed one: O(n) total, no per-number loop.

How to answer

Present it as DP: the state is i, the transition drops one bit.

Likely follow-ups
  • Total set bits in 1..n without the array? (Per bit position, count full cycles of length 2b+1 plus the remainder: O(log n).)
The input is an unsigned 32-bit value in Java. What breaks?

Values with bit 31 set arrive as negative ints. n > 0 conditions fail, and n >> 1 sign-extends forever. Use n != 0, >>>, or Integer.bitCount(n); Kernighan's loop is already correct because it only relies on two's-complement subtraction.

How to answer

Say "same bits, different interpretation"; only comparisons and right shifts care about the sign.

Likely follow-ups
  • Count the bits of a 64-bit long? (Same loop; Long.bitCount; masks become 64-bit.)
Given a 4,096-bit bitmap (like a kernel CPU mask), count the set bits fast.

Treat it as 64 words of 64 bits, popcount each word with the builtin and sum: 64 POPCNT instructions. With AVX2/AVX-512 there are vector popcount techniques, but per-word POPCNT is the expected answer. This is what bitmap_weight() does.

How to answer

Reduce to the word-sized problem you already solved; mention handling a partial last word with a mask.

Likely follow-ups
  • Find the k-th set bit? (Skip whole words by their popcount, then use n &= n - 1 k times inside the word.)
