The problem (in our words)

You get a positive integer n. Return how many 1 bits its binary representation has (its Hamming weight).

Signature: int hammingWeight(int n).

  • 1 <= n <= 231 - 1

Follow-up: if the function is called very many times, how would you make it faster?

Practice it: LeetCode 191 · GfG Count Set Bits · TUF article

Constraints tell you: n fits in 31 bits, so every method is O(1) in the strict sense; the comparison is "32 iterations" vs "k iterations" vs "a handful of operations". Older versions of this problem passed an unsigned 32-bit value (in Java, as a possibly negative int); code that loops while (n != 0) handles both, while (n > 0) does not.
