Approaches: brute -> better -> optimal

Hint 1

Write n and n - 1 one above the other in binary. Which bits differ?

Hint 2

For the "many calls" follow-up: what if you already knew the answer for every 8-bit value?

1. Brute force - string or test all 32 bits

Idea: convert to a binary string and count '1' characters, or loop 32 times: count += (n >> b) & 1. Use an unsigned / logical shift (>>> in Java) if the top bit may be set.

O(32)time
O(1)space

What is wasted: zeros cost as much as ones. For 64 = 1000000, 31 of 32 turns find nothing. -> skip the zeros.

2. Better - Kernighan: clear the lowest 1

count = 0
while n:
    n &= n - 1     # deletes exactly the lowest set bit
    count += 1
return count
O(k)time, k = set bits
O(1)space

Why it works: write n as X 1 0...0 (some prefix X, the lowest 1, then t zeros). Subtracting 1 borrows through the t zeros, so n - 1 = X 0 1...1: the prefix is unchanged, the lowest 1 became 0, and the zeros below it became 1s. ANDing the two keeps X, and every lower position has a 0 in one of them: n & (n - 1) = X 0 0...0. Exactly one 1 disappears per turn, so the loop runs k times. This is the form most top-voted solutions use; one of them also notes it averages about 16 turns on random 32-bit input versus 32 for the shift loop.

3. Optimal for many calls - table, SWAR or hardware

  • Lookup table: precompute pc[256] once (pc[i] = pc[i >> 1] + (i & 1)), then answer = pc[n & 255] + pc[(n >> 8) & 255] + pc[(n >> 16) & 255] + pc[n >> 24]. 4 loads, no branches; 256 bytes fit in L1.
  • SWAR (divide and conquer): add bits in pairs, then nibbles, then bytes, using masks 0x55555555, 0x33333333, 0x0F0F0F0F, then one multiply by 0x01010101 and >> 24. About a dozen ops, no table, no branches.
  • Built-in: __builtin_popcount, Integer.bitCount, bits.OnesCount32, int.bit_count() (Python 3.10+). One instruction where the CPU has it. In an interview, mention it, then implement one of the above.
