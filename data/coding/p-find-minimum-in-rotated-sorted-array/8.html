Common mistakes

Comparing with nums[lo]. if nums[mid] > nums[lo]: lo = mid + 1 is wrong on a sorted array: for [2, 5, 9, 13] it moves right and returns 13. The left end does not tell you which run mid is in.

hi = mid - 1 when nums[mid] < nums[hi]. mid may itself be the minimum (as in the dry run, step 3); dropping it loses the answer.

while (lo <= hi) with hi = mid. When lo == hi the loop never shrinks: an infinite loop. Pair "keep mid" with lo < hi.

Copying the "search in rotated array" template. LC 33 has a target and a third branch for equality; here there is no target. Extra == branches only add bugs.

Assuming it works with duplicates. With [3, 3, 1, 3], nums[mid] == nums[hi] and neither side can be ruled out. That is LC 154: shrink with hi -= 1, and the worst case becomes O(n).
