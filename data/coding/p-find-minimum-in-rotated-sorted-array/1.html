The problem (in our words)

A sensor log holds n distinct integer readings that were sorted in increasing order and then rotated between 1 and n times. One rotation moves the last element to the front: [a0, a1, ..., a(n-1)] becomes [a(n-1), a0, a1, ..., a(n-2)]. For example, [2, 5, 9, 11, 15] rotated 2 times is [11, 15, 2, 5, 9], and rotated 5 times it is the sorted array again.

Given the rotated array nums, return its minimum element. Your algorithm must run in O(log n) time.

  • Input: an integer array nums (sorted ascending, then rotated, all values unique).
  • Output: one integer, the smallest value. Signature: int findMin(int[] nums).

Constraints

  • n == nums.length
  • 1 <= n <= 5000
  • -5000 <= nums[i] <= 5000
  • All the integers of nums are unique.
  • nums is sorted and rotated between 1 and n times.

Constraints tell you: n is only 5000, so a linear scan would pass the judge, but the statement demands O(log n): the interviewer wants binary search. "Unique" matters a lot: it guarantees nums[mid] != nums[hi] whenever mid < hi, which is what makes a clean two-way decision possible (with duplicates you get LC 154, which is O(n) in the worst case). "Rotated n times" means the array may be fully sorted: your code must handle that with no special case.
