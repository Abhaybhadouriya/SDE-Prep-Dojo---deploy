How to recognise it:

  • "Sorted, but rotated / shifted / wrapped" and a log-time requirement.
  • There is no target: you look for a boundary (the drop, a peak, the first bad version).
  • One fixed element (here the last) splits every index into two classes.

Practice order:

  1. LC 704 for the loop template.
  2. This problem (lo < hi, compare with hi).
  3. LC 33, which reuses the "which half is sorted?" reasoning with a target.
  4. LC 154 and LC 81 for the duplicate case.
