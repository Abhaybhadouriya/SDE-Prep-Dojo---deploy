Common mistakes

Comparing with the number 1. The grid holds the characters '1'/'0'; grid[r][c] == 1 is always false in Java/C++.

Marking visited on pop. A cell can then be queued up to 4 times (once per land neighbour that sees it), so the queue and the run time grow by up to 4x. The total stays O(m·n), and the count is still right only if you also skip already-visited cells when popping. Marking on push is simpler and queues each cell once.

Checking bounds after indexing. Test 0 <= r < m and 0 <= c < n before reading grid[r][c]; Python's negative indices hide this bug by wrapping around.

Adding diagonal moves. LeetCode uses 4 directions; GfG's version uses 8. Read the statement, or ask.

Mutating the caller's grid without saying so. Sinking cells is fine in an interview if you say it; otherwise use a visited array.
