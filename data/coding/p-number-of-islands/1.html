The problem (in our words)

You get an m x n grid of characters, each '1' (land) or '0' (water). Two land cells belong to the same island when they share a side: up, down, left or right (corners do not count). Assume everything outside the grid is water. Return the number of islands.

Signature: int numIslands(char[][] grid).

  • m == grid.length, n == grid[i].length
  • 1 <= m, n <= 300
  • grid[i][j] is '0' or '1'

Practice it: LeetCode 200 · GfG Count Islands (note: GfG connects all 8 directions) · TUF article (8 directions)

Constraints tell you: at most 300 x 300 = 90,000 cells, so O(m·n) is expected. A recursive 4-direction DFS can recurse up to m·n = 90,000 frames deep in the worst case (an all-land grid, depending on the neighbour order). At roughly 50-100 bytes per frame that is 4.5-9 MB: it can fit in Linux's 8 MB default main-thread stack but is risky against Windows' 1 MB default, and it breaks Python's default recursion limit (1,000) unless you raise sys.setrecursionlimit. Prefer BFS or an explicit stack. The grid holds characters, not ints: compare with '1'.
