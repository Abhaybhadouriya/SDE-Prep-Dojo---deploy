Approaches: brute → better → optimal

Hint 1

When you find a land cell, how do you make sure the same island is not counted again from another of its cells?

Hint 2

Mark the whole island as visited (or turn it into water) right away.

1. Brute force - count each island's "first" cell

Idea: for every land cell, explore its island with a fresh visited set and count the cell only if it is the island's first cell in row-major order. Correct, but each island of size k is explored k times.

O((m·n)²)time worst case
O(m·n)space

What is wasted: the same island is explored again from each of its cells. Marking it once fixes that. -> rung 2.

2. Better - scan + recursive DFS that sinks the island

Graph: land cells, edges to the 4 side neighbours. Traversal: DFS from each new land cell. Visited rule: overwrite the cell with '0' (or keep a boolean grid). Answer: the number of DFS starts.

def sink(r, c):
    if not (0 <= r < m and 0 <= c < n) or grid[r][c] != "1": return
    grid[r][c] = "0"
    sink(r + 1, c); sink(r - 1, c); sink(r, c + 1); sink(r, c - 1)
O(m·n)time
O(m·n)recursion depth worst case

What is not enough: nothing in the time, but the call stack. A snake-shaped island makes the recursion very deep. -> rung 3 does the same with an explicit queue.

3. Optimal (and safe) - scan + iterative BFS

islands += 1; grid[r][c] = "0"; q = deque([(r, c)])
while q:
    cr, cc = q.popleft()
    for nr, nc in neighbours(cr, cc):
        if inside(nr, nc) and grid[nr][nc] == "1":
            grid[nr][nc] = "0"; q.append((nr, nc))
  1. A new island is a land cell the scan reaches first. Every earlier flood has already sunk its own cells, so this one is new.
  2. Mark a cell when it is pushed, not when it is popped. Otherwise a cell can be queued up to 4 times (once per land neighbour), so the queue and the run time grow by up to 4x; the island count stays correct only if you also skip already-visited cells when popping.
  3. Each cell is read by the scan once and pushed at most once. Total work O(m·n), whatever the island shapes.
O(m·n)time
O(m·n)queue worst case (often far less)

Why it works: BFS from a cell reaches exactly the cells connected to it by side steps over land, which is the definition of its island. After the flood, none of those cells is land any more, so the scan can never start a second flood inside the same island, and every island is started exactly once.

4. Alternative - union-find

Idea: start with count = number of land cells; for each land cell, union it with its right and down land neighbours, and each successful union (two different roots) does count--. Path compression + union by rank make each operation almost O(1).

O(m·n·α)time
O(m·n)parent array

When it is useful: when land appears over time (LC 305 Number of Islands II) or when the grid arrives row by row; BFS would have to restart, union-find just keeps merging.
