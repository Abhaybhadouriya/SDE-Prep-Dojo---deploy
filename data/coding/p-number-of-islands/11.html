Interview follow-ups

Land cells are added one by one. Report the island count after each addition.

Union-find over cell ids r*n + c. A new land cell adds 1; for each land neighbour, if find gives a different root, union and subtract 1. With path compression and union by rank each add is near O(1). Re-running BFS per addition would be O(m·n) each.

How to answer

Name the cost of the naive repeat, then switch the tool.

Likely follow-ups
  • The same cell is added twice? (Ignore the repeat.)

The grid is too large for memory and arrives one row at a time.

Keep only the previous row's labels. Label each land run in the new row, union it with labels above it (union-find on labels), and count a component as finished when none of its labels appear in the new row. Memory O(n) per row plus the live labels.

How to answer

This is connected-component labelling from image processing; say so.

Likely follow-ups
  • Split the grid into tiles on several machines: count per tile, then union across tile borders.
BFS or DFS: which and why?

Both are O(m·n). Recursive DFS is the shortest to write but its depth equals the longest path in the island (up to m·n). BFS or a DFS with an explicit stack has no recursion limit. In Python, always iterative.

How to answer

Pick one quickly, mention the stack-depth trade-off, move on.

Likely follow-ups
  • Which one gives shortest paths? (BFS.)
Count distinct island shapes, or return the biggest island.

Biggest: count cells per flood. Shapes: during the flood record each cell as (r - r0, c - c0) from the start cell (the scan always meets the same corner first), put the sorted tuple in a set, and return the set size.

How to answer

Show that a canonical form per island turns shapes into hashable keys.
