Approaches: brute → better → optimal

Hint 1

If you knew k, could you check in one pass whether h hours are enough?

Hint 2

If speed k works, does speed k + 1 work? What does that say about the set of good speeds?

1. Brute force - try k = 1, 2, 3, ...

Idea: for each speed from 1 upward, add up ceil(p / k) over all jobs and return the first k whose total is at most h.

O(n · max)time
O(1)space

What is wasted: the checks are monotone (✗✗✗✓✓), so one check at a middle speed rules out half of the range at once.

2. Better - tighter bounds (still linear)

Idea: the answer is at least ceil(sum / h) (you print at most k pages per hour for h hours) and at most max(piles) (one hour per job is always enough because h ≥ n). Scanning from the lower bound skips many useless speeds.

O(n · (max - sum/h))time, worst case still huge
O(1)space

What is wasted: the gap between the bounds can still be about 10^9. The bounds are useful, though: they are exactly the lo and hi of the binary search below.

3. Optimal - binary search on the speed

lo, hi = 1, max(piles)                  # core: 6 lines
while lo < hi:
    mid = (lo + hi) // 2
    if sum((p + mid - 1) // mid for p in piles) <= h: hi = mid
    else: lo = mid + 1
return lo
  1. hours(k) only goes down as k goes up. Each term ceil(p / k) is non-increasing in k, so the sum is too. That makes "fits(k)" a step function: false, then true forever.
  2. Keep the answer inside [lo, hi]. Start with lo = 1 and hi = max(piles), which always fits.
  3. If mid fits, the answer is mid or smaller: hi = mid (not mid - 1, because mid itself may be the answer).
  4. If mid does not fit, every speed ≤ mid fails: lo = mid + 1.
  5. Stop when lo == hi. The range has one value left, and it is the first ✓.
O(n log max)time (about 30 × n)
O(1)space

Why it works: the invariant is "hi fits, and every value below lo does not". Each step keeps it and shrinks the range by about half, and mid is always strictly below hi (it rounds down), so the loop always makes progress and never spins. When lo meets hi, that value fits and everything smaller fails: it is the minimum.

Proof (optional) - monotonicity of the check

For k < k', p / k > p / k', and ceil is monotone, so ceil(p / k) ≥ ceil(p / k') for every job. Summing over jobs, hours(k) ≥ hours(k'). So if hours(k) ≤ h, then hours(k') ≤ h. The set of good speeds is an interval [answer, ∞), and binary search finds the left end of an interval of a sorted true/false array in O(log range) checks.

Stuck? The two template forms

With while lo < hi use hi = mid / lo = mid + 1 and return lo. With while lo <= hi use hi = mid - 1 / lo = mid + 1, record ans = mid when it fits, and return ans. Mixing the two forms is the classic infinite loop.
