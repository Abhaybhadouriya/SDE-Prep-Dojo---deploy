Approaches: brute -> better -> optimal

Hint 1

When you copy node 1, you need the copy of node 2 for its list. What if node 2's copy is not made yet, or node 2 leads back to node 1?

Hint 2

Keep a dictionary from original to copy. Look in it before creating anything.

1. Naive - recursive copy, map filled after the neighbour loop (wrong)

Idea: copy(n) = new node with copy(nb) for each neighbour, and only after that loop write n -> copy into the map. It is how you would copy a tree, with the memo bolted on at the end.

Why it fails: every undirected edge is a 2-cycle, so it never terminates; even on a DAG it would duplicate shared nodes. With no map at all it is the same failure, only sooner. The fix has two parts: remember copies, and remember them early.

2. Two passes - collect nodes, then wire edges

Idea: pass 1: traverse with a visited set and create a copy of every node (map original -> copy). Pass 2: for every original node, for every neighbour, append map[neighbour] to the copy's list.

O(V + E)time
O(V)map + visited

Good: very easy to reason about; no node is linked before it exists. Cost: two traversals and a separate list of nodes. A fine answer if you say it first, then fold it into one pass.

3. Optimal - one DFS, map registered on first sight

  1. Map: copyOf[original] = clone. It is the visited set too: "in the map" means "seen".
  2. dfs(node): if node is in the map, return its copy. Otherwise create clone, store copyOf[node] = clone immediately, then for each neighbour append dfs(neighbour) to clone.neighbors. Return clone.
  3. Entry: null in, null out; else return dfs(node).
  1. Graph: the input nodes, with an edge per neighbour entry (undirected, so every edge appears in both lists).
  2. Traversal: DFS from the given node; each call clones one node and then walks its neighbour list.
  3. Visited rule: the map original -> copy is the visited set; a node is registered before its neighbours are visited, so a cycle finds the copy instead of recursing.
  4. Answer: the copy of the start node, map[node] (null for an empty graph).
O(V + E)time (each node created once, each list entry once)
O(V)map + recursion depth

Why it works: each node is created exactly once because creation only happens on a map miss and the map entry is written before any recursion. When a neighbour lookup hits a node whose copy is still "in progress" (its list half filled), returning that copy is still correct: we only need its address now, and its list will be complete by the time the outer call returns. Every original adjacency entry u -> v is turned into exactly one copy entry u' -> v', in the same order, so the structure matches.

4. Same, iterative BFS (no recursion)

copy_of = {node: Node(node.val)}
q = deque([node])
while q:
    cur = q.popleft()
    for nb in cur.neighbors:
        if nb not in copy_of:              # first sight: create, register, enqueue
            copy_of[nb] = Node(nb.val)
            q.append(nb)
        copy_of[cur].neighbors.append(copy_of[nb])   # wire this edge (each direction once)
return copy_of[node]

Same bound, O(V + E). Use it when the graph can be deep (a 10^5-node chain would overflow a recursive DFS; Python's default limit is 1000). The rule is identical: create and register when the node is discovered, not when it is dequeued.
