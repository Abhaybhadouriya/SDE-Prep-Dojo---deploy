The problem (in our words)

A city's metro map is stored as an undirected, connected graph. Each station is a node with an integer val and a list neighbors of the stations it links to directly. You are handed a reference to one station.

Return a deep copy of the whole map: a brand-new set of nodes with the same values and the same links, where no node or list in the copy is shared with the original. The reference you return must be the copy of the station you were given.

class Node {
    public int val;
    public List<Node> neighbors;
}

Test format: the judge numbers stations 1..n and the node with val = i is the i-th one. It describes the graph as an adjacency list (list of neighbour lists, 1-indexed), always gives you the node with val = 1 (or nothing, for an empty graph), and compares your copy with the original by value and structure, also checking that no original node is reused.

Signature: Node cloneGraph(Node node).

Constraints

  • The number of nodes is in [0, 100].
  • 1 <= Node.val <= 100, and each value is unique.
  • No repeated edges and no self-loops.
  • The graph is connected: every node can be reached from the given one.

Practice it: LeetCode 133 - Clone Graph · GfG - Clone an Undirected Graph

Constraints tell you: at most 100 nodes, so recursion depth and memory are trivial; the interviewer is checking that you handle cycles, the empty input and true independence of the copy, not speed. "Connected" means one traversal from the given node sees everything. Unique values mean you could key the map by val, but keying by node identity is the general answer.
