Now resolve symbolic links given as a map from path to target.

Process components left to right. After pushing a name, build the current prefix; if it is in the symlink map, replace the stack with the components of the (simplified) link target, absolute or relative to the parent, and continue with the remaining components. Guard against cycles with a hop limit (the kernel uses 40) or a visited set.

How to answer

Say why ".." after a symlink goes to the parent of the link's target, not of the link: that is why the substitution must happen before the next component.

Likely follow-ups
  • Cost? (Each expansion can add components; bound it by the hop limit times the longest link.)
Do it in C without split, in one pass.

Scan with an index, skip runs of '/', read a component up to the next '/'. Write into an output buffer that always ends at a directory boundary: on a name, append "/" + name; on "..", move the write position back to the last '/' (or stay at 0); on "." or empty, do nothing. Return "/" if the buffer is empty. O(n) time, the buffer is the only memory.

How to answer

Point out that the buffer is the stack: pop = move the end back to the previous slash.

Likely follow-ups
  • In place in the input buffer? (Yes: the write index never passes the read index.)

Why a stack and not a queue or a counter?

".." removes the most recently entered directory, which is last-in-first-out. A counter is enough only if you need the depth (Crawler Log Folder) and not the names.

How to answer

Tie the data structure to which element the cancel removes.
