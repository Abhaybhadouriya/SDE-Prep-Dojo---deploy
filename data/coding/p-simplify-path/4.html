Approaches: brute -> better -> optimal

Hint 1

Split on "/". What do the empty strings in the result correspond to?

Hint 2

Which earlier component does a ".." remove: the first one or the latest one still standing?

1. Brute force - rewrite the string until it stops changing

Idea: repeatedly replace "//" by "/", "/./" by "/", and "/name/../" by "/", until nothing changes; then strip the trailing slash.

O(n²)time
O(n)space

What is wasted: every pass rebuilds the string, and it is easy to get wrong: "/.../" must not match "/./", and "/../" at the root needs a special case. -> rung 2 handles each component once.

2. Optimal - split, then a stack of names

dirs = []
for part in path.split("/"):
    if part in ("", "."): continue      # "//", leading/trailing "/", or "this directory"
    if part == "..":
        if dirs: dirs.pop()              # parent; at the root stay at the root
    else:
        dirs.append(part)                # real name, even "..." or ".git"
return "/" + "/".join(dirs)
  1. Split on "/". Each empty part comes from a leading slash, a doubled slash or a trailing slash; all of them mean "no component".
  2. Stack invariant: after reading a prefix, the stack is the list of real directories you are inside, root first.
  3. ".." pops only if the stack is non-empty. Do not push it when the stack is empty.
  4. Join. A leading "/" plus the names joined with "/". An empty stack gives "/", the root.
O(n)time
O(n)space

Why it works: the meaning of a path is a walk from the root: each name moves one level down and each ".." one level up. The walk's current position is exactly the list of names that have not been cancelled, and ".." cancels the most recently entered directory, so the list behaves as a stack. The canonical path is that list written out, which is what the join produces.

Without split (manual scan)

In C or when the interviewer forbids library calls, scan with two indices: skip slashes, then read up to the next slash as the component. Same four cases. You can even build the answer in a char buffer and treat the buffer as the stack: on ".." move the write index back to the previous "/". That is how C implementations of path cleaning work, O(n) with one output buffer.
