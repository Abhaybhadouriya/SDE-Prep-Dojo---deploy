Common mistakes

Overwriting the stored index. On [2,7,7], k = 7 the remainders are 0, 2, 2, 2. Updating first[2] to 1 at index 1 means index 2 sees a gap of 1 and the answer [7,7] is missed. Keep the first index.

Forgetting the seed {0: -1}. A good prefix is missed: [3,4], k = 7 returns false.

Seeding with {0: 0}. That shifts every length by one: [3,4], k = 7 sees remainder 0 again at index 1 with a gap of 1 and returns false, though the whole array (sum 7) is good.

Using a sliding window. "Divisible by k" is not monotonic in the window size, so there is no rule for shrinking.

Copying old k = 0 handling. Older solutions guard if (k != 0); today k ≥ 1, and in languages where % on a negative gives a negative result you would need ((x % k) + k) % k only if values could be negative (they cannot here).
