Interview follow-ups

Return the indices of one good subarray.

At the hit, the subarray is nums[first[rem] + 1 .. i]. Return that pair instead of true.

How to answer

Show the map already holds the left end.

Likely follow-ups
  • The longest good subarray? Do not stop at the first hit; keep max(i - first[rem]) over the whole array.
What if nums can contain negative numbers?

The idea is unchanged, but in C++, Java and Go % can return a negative value, so -1 and k - 1 would be different keys for the same class. Normalise with ((rem + x) % k + k) % k. Python's % is already non-negative for k > 0.

How to answer

Name the language-specific behaviour of % and fix it in one line.

Likely follow-ups
  • Can the running sum overflow then? Keep only the remainder, never the raw sum.
Minimum length L instead of 2.

Change the test to i - first[rem] >= L. Keeping the first index is still optimal: it is the farthest partner.

How to answer

Show that only the constant changes.

Likely follow-ups
  • Maximum length L: the earliest partner can be too far; you need, per remainder, the earliest index ≥ i - L (a queue per remainder).
k is small (say k ≤ 1000). Can you avoid the hash map?

Yes: an int array of size k filled with -2, first[0] = -1. Same O(n) time, no hashing, O(k) memory. Also, if n ≥ k + 1 the pigeonhole principle guarantees a repeated remainder, but only the length rule decides the answer, so you still scan.

How to answer

Use the constraint to pick the data structure.

Likely follow-ups
  • Huge k (231)? The map holds at most n + 1 keys; an array is impossible.
Count the good subarrays (length ≥ 2) instead of testing existence.

Count map of remainders, but delay each insert by one step: at index i, first add count[rem_i], then insert the previous remainder rem_(i-1), starting with prev = 0 for the empty prefix. That way the partner is always at least two positions back. O(n).

How to answer

Turn the length rule into "insert one step late".

Likely follow-ups
  • Use 64-bit for the count: up to n²/2.
