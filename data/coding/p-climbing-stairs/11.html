Moves can be any size in a given list, e.g. {1, 3, 5}.

ways[i] = sum of ways[i - m] over every allowed m with i - m ≥ 0, ways[0] = 1. O(n · |moves|) time; keep a ring buffer of the last max(moves) values for O(max move) space.

How to answer

Generalise the same last-move split; the base case stays ways[0] = 1.

Likely follow-ups
  • Order does not matter ({1,2} = {2,1})? Put the loop over moves outside (Coin Change II).
Some steps are broken and cannot be stepped on.

Set ways[i] = 0 for a broken step i; the recurrence is otherwise unchanged, so no climb can pass through it. Still O(n) time and O(1) extra space with a set (or a boolean array) of broken steps.

How to answer

Show that a zero in the table propagates correctly.

Likely follow-ups
  • What if the top step is broken? The answer is 0.
n is 1018; return the answer mod 109+7.

Use matrix exponentiation: [[1,1],[1,0]]n by repeated squaring with every product taken mod 109+7, O(log n) 2x2 multiplications (use 64-bit for the products). Fast doubling (F(2k) = F(k)(2F(k+1) - F(k)), F(2k+1) = F(k)² + F(k+1)²) is the same speed with less code.

How to answer

Write the transition as a matrix, then reuse binary exponentiation from Pow(x, n).

Likely follow-ups
  • For k moves the matrix is k x k: O(k³ log n).
Print all the climbs, not just count them.

Backtracking: from the current step try +1 and +2, append to a path, recurse, pop. The output itself has ways(n) sequences of length up to n, so O(n · ways(n)) time is unavoidable; counting is only cheap because it never builds them.

How to answer

Point out that output size bounds the time; DP helps counting, not listing.

Likely follow-ups
  • Print the k-th climb in lexicographic order without listing all? Use the counts to choose each move.
