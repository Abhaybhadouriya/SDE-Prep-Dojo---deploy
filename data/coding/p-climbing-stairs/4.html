Approaches: brute → better → optimal

Hint 1

Do not think about the first move; think about the last one. Where could you have been just before step n?

1. Brute force - plain recursion

Idea: ways(n) = ways(n-1) + ways(n-2), with ways(0) = ways(1) = 1, written as a recursive function.

O(φn) ≈ O(1.62n)time
O(n)stack

What is wasted: the same sub-call is solved many times (w(3) twice, w(2) three times for n = 5). There are only n + 1 distinct calls. -> remember them.

2. Better - memoisation or a table

Idea: store each ways(i) the first time it is computed (top-down), or fill an array from 0 to n (bottom-up).

O(n)time
O(n)space

What is wasted: the table keeps all n + 1 values, but cell i only reads cells i-1 and i-2. -> two variables.

3. Optimal - two rolling variables

prev2, prev1 = 1, 1                  # ways(0), ways(1)
for _ in range(2, n + 1):
    prev2, prev1 = prev1, prev1 + prev2
return prev1
  1. State: ways[i] = number of move sequences that end exactly on step i.
  2. Transition: ways[i] = ways[i-1] + ways[i-2] (last move 1, or last move 2).
  3. Base case: ways[0] = 1 (the empty sequence) and ways[1] = 1.
  4. Answer: ways[n].
  5. Space optimisation: keep only the last two values; the loop slides them one step right.
O(n)time
O(1)space

Why it works: sort every valid climb to step i by its last move. Those ending with a 1-step are exactly a climb to i-1 plus that step (ways[i-1] of them); those ending with a 2-step are a climb to i-2 plus that step (ways[i-2]). Every climb is in one group (complete), and no climb is in both because their last moves differ (no overlap), so the counts add. This "complete and non-overlapping split" is the argument to say for every counting DP.

Even faster: O(log n) with matrices

[ways(i+1), ways(i)] = [[1,1],[1,0]] x [ways(i), ways(i-1)], so ways(n) comes from the matrix [[1,1],[1,0]] raised to the n-th power, in O(log n) multiplications by repeated squaring. A closed form via Binet's formula also exists, but floating-point rounding makes it risky for big n. For n ≤ 45 the loop is already instant; mention these only as follow-ups.
