60-second recall

  • Cue: number stored as a digit array / string, too long for int -> carry loop from the end.
  • Insight: +1 only changes the trailing 9s (to 0) and the digit before them (+1).
  • State: index i from n-1 down; being in the loop means carry = 1.
  • Trap: all 9s -> new array [1, 0, ..., 0]; never convert to long.
  • Cost: O(n) worst, O(1) extra; the general add-k loop is the same shape.
carry, i = 1, n - 1               # generic digit addition
while i >= 0 and carry:
    s = d[i] + carry
    d[i], carry = s % 10, s // 10
    i -= 1
if carry: d = [carry] + d

Quick quiz

What does [1,9,9] become?

  1. [1,9,10]
  2. [1,10,0]
  3. [2,0,0]
  4. [1,0,0,0]
Both 9s roll over to 0 and the 1 absorbs the carry.

When does the result have more digits than the input?

  1. When the last digit is 9
  2. Only when every digit is 9
  3. When the first digit is 9
  4. Never
Only all-nines leaves a carry after index 0.

Why not convert the digits to a long?

  1. Up to 100 digits overflow 64 bits
  2. It is too slow
  3. Digits can be negative
  4. It loses leading zeros
A long holds about 19 digits.
