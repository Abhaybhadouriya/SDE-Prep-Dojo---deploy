Use the difference tuple as the key instead. Is it equivalent?

Yes. The differences (w[i] - w[i-1]) mod 26 determine the shifted word by running sums from 0, and the shifted word determines the differences. Both have the length built in. Pick whichever you can encode without collisions.

How to answer

Show the two keys are functions of each other; that proves they define the same classes.

Likely follow-ups
  • Encoding in Java? Append (char)('a' + d) per difference, or join with commas.
Return only the number of groups.

Insert each key into a hash set and return its size. O(N · L) time, memory only for distinct keys.

How to answer

Keep the key function, drop the buckets.

Likely follow-ups
  • Very many words, approximate count is fine? HyperLogLog over the keys.
The alphabet also has digits that wrap separately (0-9), and other characters never shift.

Clarify the operation first. If one shift moves letters within a..z and digits within 0..9 independently, normalise each class by its own first member: letters by (c - first letter) mod 26, digits by (d - first digit) mod 10, and keep the other characters as they are. The key is the word built from those three rules; group by it as before.

How to answer

Ask what one shift does to each character class; the canonical key follows from the answer.

Likely follow-ups
  • One shift count k must move both classes together? Then the letter offset and the digit offset must come from the same k (k mod 26 and k mod 10 consistent), which the Chinese remainder theorem checks.
Sort the words inside each group, and the groups by size.

Group as before, sort each bucket (O(L · b log b) for a bucket of b words), then sort the buckets by size. The grouping step is unchanged.

How to answer

Say the cost of each post-processing step separately.

Likely follow-ups
  • Only the largest group? Track the max while grouping.
Words arrive as a stream; for each one, report how many earlier words are in its sequence.

Keep a map key → count. For each word compute the key in O(L), output the count, then increment it. Memory grows with the number of distinct sequences, not with the number of words.

How to answer

Point out that the words themselves never need to be stored.

Likely follow-ups
  • Distributed stream? Partition by hash(key) so one sequence always lands on one worker.
