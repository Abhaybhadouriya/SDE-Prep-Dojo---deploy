Approaches: brute → better → optimal

Hint 1

Every shifting sequence contains exactly one word that starts with 'a'. Can you compute it for any word?

1. Brute force - compare with every group leader

Idea: keep a list of groups. For each word, test it against the first word of every group: same length, and the same shift (w[i] - leader[i]) mod 26 at every position. Join the first matching group or open a new one.

O(N² · L)time (all words in different groups)
O(N · L)space (the output)

What is wasted: the scan over all groups. If each word could name its own group, a hash map would find it in O(1).

2. Better - smallest of the 26 shifts as the key

Idea: generate all 26 shifts of the word and take the lexicographically smallest one as its key. All members of a sequence generate the same 26 words, so they get the same key.

O(N · 26 · L)time
O(N · L)space

What is wasted: 25 of the 26 shifts. The smallest shift always starts with 'a' (when the first letter is 'a', no other shift can be smaller at position 0), so we can compute that one directly.

3. Optimal - shift each word to start at 'a'

for w in strings:                                    # core
    shift = ord(w[0])
    key = tuple((ord(c) - shift) % 26 for c in w)    # first entry is always 0
    groups[key].append(w)
  1. One subtraction per letter. Subtract the first letter from every letter and wrap modulo 26. The first letter becomes 'a' (0); the rest keep their distance from it.
  2. Keep the arithmetic non-negative. In C++, Java and Go, % of a negative number is negative (or a byte underflows), so add 26 before taking the modulo. Python's % is already non-negative.
  3. Group by the key. Existing key: append. New key: open a bucket. A side list keeps buckets in first-seen order so the output is deterministic.
O(N · L)time
O(N · L)space (keys + output)

Why it works: two words are in the same sequence exactly when they have the same length and there is one k with y[i] = x[i] + k (mod 26) for every i. Shifting x by -x[0] and y by -y[0] maps both to words that start with 'a'; if y = x + k, then y - y[0] = x + k - (x[0] + k) = x - x[0], so the keys are equal. Conversely, equal keys give k = y[0] - x[0] for every position. So "same key" is exactly "same sequence", and the hash map does the grouping.

The difference-key variant (optional)

Many top solutions use the tuple of differences (s[i] - s[i-1]) mod 26 instead. It is the same information: the shifted word is the running sum of those differences from 0. Single letters get the empty tuple, so they group together, and the length is built in because the tuple has L - 1 entries.
