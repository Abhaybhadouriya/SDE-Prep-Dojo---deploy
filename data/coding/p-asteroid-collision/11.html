Interview follow-ups

Why is it O(n) when there is a while loop inside the for loop?

Amortised analysis: every rock is pushed at most once and popped at most once, so the total number of pops over the whole run is at most n. The for loop plus all the while iterations is at most 2n steps.

How to answer

Count operations per element, not per loop.

Likely follow-ups
  • Worst case for one newcomer? (O(n) pops, e.g. [1,2,...,n-1,-n], but only once.)
Can you do it in O(1) extra space?

Yes: use the input array itself as the stack. Keep a write index top; "push" writes asteroids[top++] = a and "pop" is top--. The write index never overtakes the read index, so no unread value is overwritten. Return the first top elements.

How to answer

Say why it is safe: the stack never holds more elements than have been read.

Likely follow-ups
  • Is mutating the input acceptable? (Ask; many interviewers accept it if you say so.)
Asteroids arrive one at a time as a stream. Report the survivors at any moment.

The stack is exactly the survivor state of the prefix seen so far, so the algorithm is already online: process each arrival with the same loop and the stack is the answer at every moment. Amortised O(1) per arrival.

How to answer

Point out the invariant "stack = final state of the prefix" from the proof.

Likely follow-ups
  • Count how many survive without storing them? (You still need the right-movers on the stack; left-movers that escape can be counted instead of stored.)
When two rocks collide, the winner loses size equal to the loser's size. What changes?

The winner's new size is the difference, so after popping a smaller top the newcomer continues with |a| - top, and a bigger top stays with top - |a| (update it in place). The loop shape is the same, still amortised O(n).

How to answer

Show that only the stack top's value changes, so the stack shape invariant still holds.

Likely follow-ups
  • Health drops by 1 per win instead? (That is LC 2751 Robot Collisions.)
Return the time of the last collision, given the rocks' starting positions.

With equal speeds, two facing rocks at x1 < x2 meet at time (x2 - x1) / 2. Run the same stack, and on every collision record the meeting time of the newcomer and the top; the answer is the maximum. Every collision the stack resolves really happens, and both rocks moved at full speed until then, so its time is exactly (x2 - x1) / 2.

How to answer

Keep positions on the stack next to sizes.

Likely follow-ups
  • Different speeds? (The stack order no longer matches time order; you need an event queue.)
