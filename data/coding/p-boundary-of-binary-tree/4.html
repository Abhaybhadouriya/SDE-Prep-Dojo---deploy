Approaches: brute -> better -> optimal

Hint 1

Write down which nodes of example 2 belong to which part. Is any node in two parts?

Hint 2

The bottom node of the left edge is always a leaf. Who should print it: the edge walk or the leaf walk?

1. Brute force - collect three lists, then remove duplicates

Idea: collect the left edge including its last node, all leaves, and the right edge including its last node, then merge them and drop values already printed (with a set of node pointers, since values can repeat).

O(n)time
O(n)extra space for the seen-set

Why it is not enough: it works, but the set hides the fact that you did not define ownership. Interviewers read it as "patched until the tests passed". It also needs care: you must dedupe by node, not by value (two different leaves can both be 7).

2. Better - one DFS that tags every node with its role

Idea: walk the tree once, passing two flags down: "am I on the left edge?" and "am I on the right edge?". A left-edge node passes the flag to its left child, and to its right child only when it has no left child (mirror for the right edge). Leaves are written to the leaf list; flagged inner nodes go to the left or right list. This is the one-pass "preorder + postorder hybrid" from the top community answers: print left-edge nodes before recursing, right-edge nodes after.

O(n)time
O(h)space

Optimal, and elegant, but the flag rules are easy to get subtly wrong at the whiteboard. Our Python file uses exactly this version as an independent reference and checks 500 random trees against the optimal code below.

3. Optimal and simplest - root, left walk, leaf walk, right walk

out = [root]                         # unless root is a leaf: then return [root]
n = root.left                        # left edge, leaves excluded
while n and not leaf(n): out += n; n = n.left or n.right
out += leaves(root)                  # any DFS, left before right
right edge the same way (n.right or n.left), appended reversed
  1. The parts are disjoint by construction. Both edge walks stop before adding a leaf, the leaf walk adds only leaves, and the root is handled first and never counted as a leaf. So no node can be added twice, and no set is needed.
  2. Each walk follows the outside. "Left child if any, else right child" is exactly the outermost path down the left side. It is a single path, so it costs O(h).
  3. The leaf order is a DFS order. Preorder visits the left subtree before the right one, so leaves come out left to right.
  4. Anti-clockwise means the right edge is bottom-up. Collect it top-down (the natural walk) and reverse it, or push it on a stack.
O(n)time
O(h)extra space

Why it works: every boundary node is exactly one of: the root, an inner node on the outer-left path, a leaf, an inner node on the outer-right path. The two outer paths are in different subtrees of the root (left and right), so they cannot overlap each other, and both stop before their leaf, so they cannot overlap the leaf list. The root is excluded from the leaf list because the leaf walk only adds it when it is a lone node, and that case returns early.
