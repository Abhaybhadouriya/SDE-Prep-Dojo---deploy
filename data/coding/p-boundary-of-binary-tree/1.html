The problem (in our words)

You are given the root of a binary tree. Return the values on its boundary, read anti-clockwise starting at the root. The boundary is these four parts, joined in this order, with no node listed twice:

  1. The root.
  2. The left edge. If the root has a left child, that child is the first left-edge node; if the root has no left child, the left edge is empty. After a left-edge node, the next one is its left child if it has one, otherwise its right child. The walk stops at a leaf, and that leaf is not part of the left edge.
  3. The leaves, from the leftmost to the rightmost (a leaf is a node with no children; the root is never counted as a leaf).
  4. The right edge in reverse (bottom to top). It is defined like the left edge with left and right swapped: start at the root's right child, prefer the right child, fall back to the left child, and leave out the final leaf.

Signature: List<Integer> boundaryOfBinaryTree(TreeNode root). The tree arrives in LeetCode's level-order form, e.g. [5,null,8,6,9].

  • The number of nodes is in the range [1, 104].
  • -1000 <= Node.val <= 1000

Practice it: LeetCode 545 (Premium) · GfG Tree Boundary Traversal (free, same definition) · TUF article

Constraints tell you: 104 nodes means O(n) or O(n log n); any single traversal is fine. A skewed tree is 104 deep, which is too deep for Python's default recursion limit, so the leaf walk is iterative in our code.
