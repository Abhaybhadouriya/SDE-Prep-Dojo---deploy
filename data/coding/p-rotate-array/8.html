Common mistakes

Forgetting k %= n. It is the most common wrong answer: k can be 105 with n = 3, and the reversal of the first k cells walks off the array.

Rotating the wrong way. Reversing the first n - k cells and then the last k cells (after the full reverse) rotates left. Check on [1,2,3], k = 1: the answer must be [3,1,2].

Python: nums = nums[-k:] + nums[:-k]. That rebinds a local name; the judge still sees the old list. Use nums[:] = .... Also reduce k first: when k ≥ n, nums[-k:] is the whole list and nums[:-k] is empty, so nothing rotates.

Cycle version stopping after one cycle. Looping "until back at start" only once is correct only when gcd(n, k) = 1. Count moved values and keep starting new cycles until the count reaches n.
