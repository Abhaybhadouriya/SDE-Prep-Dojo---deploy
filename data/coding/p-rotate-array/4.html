Approaches: brute -> better -> optimal

Hint 1

Write down where index i goes: (i + k) % n. With a second array, the answer is one loop.

Hint 2

Reverse [1,2,3,4,5] and look where the last two values went. They are at the front, just backwards.

1. Brute force - k single ticks

Idea: repeat k % n times: save the last value, shift everything right by one, put the saved value at index 0. Correct, in place, and exactly what the statement describes.

O(n · k)time
O(1)extra space

What is wasted: every value is moved k times, one cell at a time, although its final cell (i + k) % n is known from the start. With n = k = 105 (k % n can still be n - 1) that is about 1010 moves.

2. Better - a copy

k %= n
tmp = nums[:]                     # O(n) buffer
for i in range(n):
    nums[(i + k) % n] = tmp[i]

Idea: each value jumps straight to its final cell. In Python, nums[:] = nums[-k:] + nums[:-k] is the one-liner of the same idea (it also builds new lists).

O(n)time
O(n)extra space

What is wasted: a whole second array, which the follow-up forbids. We need to move every value once (or a constant number of times) without a buffer.

3. Optimal - three reversals

k %= n
reverse(0, n - 1)                 # (A B) -> (B' A')
reverse(0, k - 1)                 # B' -> B
reverse(k, n - 1)                 # A' -> A
  1. Split the array. A = the first n - k values, B = the last k values. The answer is B followed by A.
  2. Reverse everything. Reversing (A B) gives (B' A'): both blocks are already in their final places, each one backwards.
  3. Reverse each block. Reversing B' (the first k cells) and A' (the rest) restores the order inside each block.
  4. Reduce k first. Without k %= n, reverse(0, k - 1) runs past the end when k > n.
O(n)time, each cell swapped at most twice
O(1)extra space

Why it works: reversing a concatenation reverses the order of the blocks and the inside of each block: rev(A B) = rev(B) rev(A). The blocks are now in the right order, only their insides are backwards, and reversing each one in place (reversal is its own inverse) turns rev(B) into B and rev(A) into A, giving B A. The most voted community solution is exactly these three calls, praised for being readable rather than clever.

Proof (optional)

Index arithmetic. After the full reversal, the value from old index i sits at n - 1 - i. If i ≥ n - k (it was in B), its new index n - 1 - i is in [0, k - 1], and reversing that block sends it to (k - 1) - (n - 1 - i) = i + k - n = (i + k) mod n. If i < n - k (it was in A), its index n - 1 - i is in [k, n - 1], and reversing that block sends it to k + (n - 1) - (n - 1 - i) = i + k = (i + k) mod n. Every value ends at (i + k) mod n, which is the definition of a right rotation by k.

4. Also optimal - cyclic replacements (gcd cycles)

Idea: take the value at index 0 and drop it at (0 + k) % n, pick up the value that was there, drop that one k further, and so on until you return to index 0. If n and k share a factor, that cycle closes early, so start the next cycle at index 1, then 2, until n values have moved. There are exactly gcd(n, k) cycles.

  1. Start: n = 6, k = 4. Each value at index i must land at (i + 4) % 6. We carry one value at a time instead of copying the array.
  2. New cycle at index 0: pick up 1.
  3. Drop 1 at index 4 = (0 + 4) % 6 and pick up the 5 it displaced. Moved 1 of 6.
  4. Drop 5 at index 2 = (4 + 4) % 6 and pick up the 3 it displaced. Moved 2 of 6.
  5. Drop 3 at index 0 = (2 + 4) % 6 and pick up the 1 it displaced. Moved 3 of 6. Back at the start index: this cycle is closed.
  6. New cycle at index 1: pick up 2. The first cycle closed after 3 moves, so not every index was visited: gcd(6, 4) = 2 cycles.
  7. Drop 2 at index 5 = (1 + 4) % 6 and pick up the 6 it displaced. Moved 4 of 6.
  8. Drop 6 at index 3 = (5 + 4) % 6 and pick up the 4 it displaced. Moved 5 of 6.
  9. Drop 4 at index 1 = (3 + 4) % 6 and pick up the 2 it displaced. Moved 6 of 6. Back at the start index: this cycle is closed. All 6 values moved exactly once: [3, 4, 5, 6, 1, 2].
O(n)time, every value moved once
O(1)extra space

Trade-off: fewer writes (n instead of up to 2n swaps) but jumps around memory with stride k, so it is less cache-friendly, and the "count moved values" stopping rule is easy to get wrong. Offer it as the second in-place answer for the follow-up.
