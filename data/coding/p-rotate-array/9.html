60-second recall

  • Cue: rotate / shift a block to the other end in place, O(1) extra space.
  • Insight: (A B) -> (B A) = reverse all, then reverse each block.
  • State: k %= n; blocks [0, k) and [k, n) after the full reverse (right rotation).
  • Trap: k > n, k = 0, left vs right order; cycles need gcd(n, k) starts.
  • Cost: O(n) time, O(1) space; copy is O(n) space; k ticks is O(n·k).
def rev(a, lo, hi):
    while lo < hi:
        a[lo], a[hi] = a[hi], a[lo]; lo += 1; hi -= 1
k %= n                     # right rotation by k
rev(a, 0, n - 1); rev(a, 0, k - 1); rev(a, k, n - 1)
# left by k: rev(0,k-1); rev(k,n-1); rev(0,n-1)

[1,2,3,4,5], k = 2. What does the array hold after the first reversal (the whole array)?

  1. [4,5,1,2,3]
  2. [2,1,5,4,3]
  3. [5,4,3,2,1]
The first step reverses everything; then [0..1] gives 4,5 and [2..4] gives 1,2,3.

With cyclic replacements, n = 8 and k = 6. How many cycles are there?

  1. 1
  2. 2
  3. 6
gcd(8, 6) = 2 cycles, each of length 4.

Right rotation by k equals left rotation by...

  1. n - k (after k %= n)
  2. k
  3. n + k
They are the same permutation: i + k ≡ i - (n - k) (mod n), so every value lands in the same cell.
