Interview follow-ups

Give a second O(1)-space solution.

Cyclic replacements: carry the value from index start to (start + k) % n, pick up the displaced value, repeat until you are back at start, then begin the next cycle at start + 1. Stop when n values have moved. There are gcd(n, k) cycles of length n / gcd(n, k).

How to answer

Draw n = 6, k = 4: the cycles 0 -> 4 -> 2 -> 0 and 1 -> 5 -> 3 -> 1 show why one cycle is not enough.

Likely follow-ups
  • Which version does fewer writes? Cycles: exactly n writes; reversals: up to n swaps (2n writes).
Rotate left instead of right.

Left by k equals right by n - k after k %= n. With reversals: reverse the first k, reverse the rest, then reverse everything (the same three calls in the opposite order).

How to answer

Verify on [1,2,3], k = 1: left gives [2,3,1].

Likely follow-ups
  • k may be negative? Normalise with ((k % n) + n) % n; in C/Java, % keeps the sign of the dividend.
Many rotation requests, then many "what is at index i?" queries.

Do not move data at all. Keep a single offset off = (off + k) % n per rotation; the value at logical index i is nums[(i - off + n) % n]. Each rotation and each query is O(1). It is exactly how a ring buffer tracks its head.

How to answer

Point out that physically rotating is only needed when someone wants a flat array.

Likely follow-ups
  • Rotate only a subrange [l, r] many times? A rope or an implicit treap with split/merge, O(log n) per operation.
Rotate the array in place by k using block swaps (the Gries-Mills block-swap idea).

Swap the shorter block with the matching part of the longer one; that places the shorter block, and what remains is a smaller rotation of the same kind. Repeat until the blocks are equal. It is Euclid's algorithm on (k, n - k): O(n) time, O(1) space.

How to answer

Mention it as the third classic in-place method; the reversal one is simplest to code under pressure.

Likely follow-ups
  • Which does std::rotate use? It depends on the iterator category; for forward iterators it is a block-swap loop.
The array is a huge file on disk. Rotate it with little memory.

Three reversals work with two file pointers and a small buffer each: read a chunk from the front and from the back, reverse both in memory, swap their positions. All accesses are sequential runs, which disks and page caches like, while the gcd-cycle version reads at stride k and would thrash.

How to answer

Compare access patterns: two sequential streams vs a stride walk.

Likely follow-ups
  • If a second file is allowed: just copy [n-k, n) then [0, n-k): two sequential passes.
