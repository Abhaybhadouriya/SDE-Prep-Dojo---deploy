The problem (in our words)

A scoreboard shows a row of integer readings nums. Every "tick" shifts the row one place to the right: each reading moves one cell right and the last reading wraps around to the first cell. Given a non-negative integer k, apply k ticks to the row in place.

Signature: void rotate(int[] nums, int k). Nothing is returned; the judge reads nums after the call.

Constraints

  • 1 <= nums.length <= 105
  • -231 <= nums[i] <= 231 - 1
  • 0 <= k <= 105

Follow-up (part of the original): find as many different solutions as you can (there are at least three), and do it in place with O(1) extra space.

Practice it: LeetCode 189 - Rotate Array · GfG - Rotate Array (rotate left by d) · GfG - Rotate by one · TUF - Left rotate by one

Constraints tell you: n and k can both be 105, so the "rotate by one, k times" brute force is up to 1010 moves: too slow. k can be larger than n (with n = 1 it can be 105 times larger), so reduce k %= n first. Values cover the whole 32-bit range, so never encode two values in one int or use a sentinel value.
