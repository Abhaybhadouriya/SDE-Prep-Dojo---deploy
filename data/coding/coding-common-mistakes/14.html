Interview questions

What do you do in the first five minutes of a coding round?

Restate the problem and the output format, ask about input size, order, duplicates, negatives and empty input, work one example and one edge case by hand, then say the brute force and a better approach with their complexities. Only after the interviewer agrees do I start coding.

How to answer

Give the steps in order, then show them on a real question: "for Two Sum I'd ask whether it is sorted and whether you want indices".

Likely follow-ups
  • What if the interviewer says "just start coding"? (Say the approach in one sentence anyway, then code.)
Your binary search loops forever on two elements. How do you find and fix it?

Infinite loops happen when an update does not shrink the range: with lo < hi and mid = (lo + hi) / 2, the update lo = mid never moves when hi = lo + 1. Fix it by stating the invariant and choosing updates that always shrink: half-open [lo, hi) with lo = mid + 1 / hi = mid, or round mid up when the update is lo = mid.

How to answer

Trace lo = 0, hi = 1 by hand; that two-element case finds every binary-search bug.

Likely follow-ups
  • Find the last index with a[i] <= target (upper bound minus one).
  • Binary search on the answer: the same loop with a predicate.
Reverse a 32-bit integer without using 64-bit types. Where can it overflow and how do you check?

Only at r = r * 10 + d. Check before it: overflow happens if r > INT_MAX / 10, or r == INT_MAX / 10 and d > 7 (the last digit of 2147483647). Mirror it for negatives with INT_MIN / 10 and d < -8, using that C++, Java and Go keep the sign in %. Return 0 on overflow. O(log |x|) time, O(1) space.

How to answer

Name the single risky line first, then the check, then test 1534236469 and INT_MIN.

Likely follow-ups
  • atoi with whitespace, sign and garbage (same check, plus clamping).
  • Why is abs(INT_MIN) a bug?
Number of Islands: you sank the islands by writing '0' into the grid. The interviewer asks if that is OK. What do you say?

It is O(1) extra space but destructive: the caller loses the grid, and the function is not safe to call twice or from two threads. If mutation is not allowed, keep a separate seen grid (O(mn) bits), or restore the cells after counting. I would also switch to an iterative DFS or BFS, because recursion depth can reach mn on a grid full of land.

How to answer

Present it as a trade-off you chose deliberately, then offer the non-destructive version.

Likely follow-ups
  • The grid is too big for memory (process row by row with union-find).
  • Islands are added one by one (Number of Islands II, union-find).
Your sliding-window solution has a while loop inside a for loop. Is it O(n2)?

No. The left pointer only moves forward and never past the right one, so across the whole run it moves at most n times. The inner loop's total work is O(n), the outer loop's is O(n): O(n) amortised. Show it by counting how many times each index enters and leaves the window.

How to answer

Use the word "amortised" and the counting argument, not "it feels linear".

Likely follow-ups
  • When is a nested loop really O(n2)? (When the inner index resets for each outer step.)
Your DFS on a tree is recursive. The interviewer says n can be 105. What changes?

Depth equals tree height, which is n for a chain. 105 frames exceeds Python's default limit of 1,000 and is risky for default C++ and Java stacks. Convert to an explicit stack: push (node, state) pairs so that post-order work (like computing heights) happens when a node is popped the second time. Space stays O(h) but on the heap.

How to answer

Say the worst-case depth before the interviewer does, then show the iterative version for one traversal.

Likely follow-ups
  • Morris traversal: O(1) extra space by temporarily rewiring pointers (mutates the tree while it runs).
You get stuck halfway. What do you do?

Say where you are stuck and why ("I need the smallest value in the window, but removing from the middle of a heap is slow"). Go back to the brute force and name the repeated work. Try a small example by hand to see the pattern. If a hint comes, use it at once. Silence is the only wrong choice.

How to answer

Show that being stuck is a normal step you handle with a method, not a failure.

Likely follow-ups
  • How do you use a hint without losing points? (Acknowledge it, build on it, finish strongly.)
