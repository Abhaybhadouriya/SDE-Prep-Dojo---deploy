Revision card

  • Cue: You feel ready to code in minute 2, or your code "almost" works.
  • Insight: Most rejections come from process slips (no clarify, no test) and off-by-ones, not from unknown algorithms.
  • State: Clarify, example, brute force, better idea, code, dry run: every time.
  • Trap: Mutating the input without asking; int overflow in sums; recursion deeper than about 10^4.
  • Cost: Two extra minutes of clarifying and testing save the round.

More to remember

  • Clarify, example, brute force, better idea, then code. Every time.
  • Write the loop invariant as a comment; derive < versus <= from it.
  • lo + (hi - lo) / 2; 64-bit sums and products; check before r * 10 + d.
  • Ask before changing the input; otherwise keep your own seen.
  • Recursion depth = height or path length; past ~104 use an explicit stack.
  • Count library calls inside loops; sliding windows are amortised O(n).
  • Names by role; talk through every decision.
