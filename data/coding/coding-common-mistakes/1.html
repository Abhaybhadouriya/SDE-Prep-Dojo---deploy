1. Jumping to code

Symptom: you hear "array" and "sum", start typing a hash map in the first minute, and at minute 20 learn that the input was sorted, or that you had to return all pairs, or that the array can be empty.

Fix: a fixed opening you run every time, even for problems you know.

  1. Restate the task in one sentence and the output format ("return the indices, 0-based, any order?").
  2. Ask about the input: size limits, sorted or not, duplicates, negatives, empty input, character set.
  3. Work one small example by hand and one edge case. Agree on the expected output.
  4. Say the brute force with its complexity in one sentence, then the better idea and its complexity. Get a nod.
  5. Only then code.

Example. "Find two numbers that add up to the target." Three questions change the answer: sorted? (two pointers, O(1) space), indices or values? (sorting loses indices), exactly one answer? (else return all, with duplicates). That is Two Sum versus Two Sum II versus 3Sum-style dedup.
