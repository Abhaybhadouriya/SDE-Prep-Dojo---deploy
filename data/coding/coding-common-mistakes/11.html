Smaller mistakes that still cost the round

  • Not testing. Saying "done" without tracing one example. Trace it line by line, then the edge cases: empty, one element, all equal, maximum size.
  • Off-by-one in loops such as range(n - k) instead of range(n - k + 1). Check the first and last window by hand.
  • Null and empty input. An empty tree, an empty string, grid[0] on an empty grid.
  • Comparing floats with == in geometry or division problems. Use integers (cross products, fractions) or an epsilon.
  • Language traps. Java Integer == Integer compares references above 127; C++ a.size() - 1 underflows for an empty vector; Python [[0] * n] * m shares one row m times.
  • Arguing with a hint. If the interviewer asks "what about duplicates?", there is a bug with duplicates. Thank them and test it.
