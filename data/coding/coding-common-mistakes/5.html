5. Recursion that is too deep

Symptom: DFS on a 1000 x 1000 grid, or on a tree that is a 105-node chain, passes the small tests and crashes on the big one with "maximum recursion depth exceeded", StackOverflowError or a segfault.

Fix: know the depth. Recursion depth is the height of the tree, or the longest DFS path, which can be every cell of a grid. If it can reach 104 or more, use an explicit stack (or BFS). sys.setrecursionlimit in Python only moves the crash to the C stack; mention it, but do not rely on it.

  1. Start cell (0,0) is land. Mark it in our own seen grid and push it. The input grid is only read.
  2. Pop (0,0). Check its four neighbours; only (0,1) is unseen land. Mark it when pushing, so no cell is pushed twice.
  3. Pop (0,1). (1,1) is new land: mark and push. (0,0) is already seen.
  4. Pop (1,1), push (2,1).
  5. Pop (2,1), push (2,2).
  6. Pop (2,2): nothing new. The stack is empty, so one island is finished. The depth lived in a heap-allocated array, not on the call stack.

Tree problems with n up to 104 are usually fine recursively (a balanced tree is only about 14 deep), but say the worst case: "if the tree is a chain, the depth is n; I can switch to an iterative traversal." That sentence alone earns the point.
