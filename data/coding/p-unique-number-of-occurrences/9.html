  • Cue: a question about the frequencies themselves -> count first, then work on the counts.
  • Insight: counts unique <=> number of distinct values == number of distinct counts.
  • State: map value -> count, set of counts seen.
  • Trap: do not check the values; negative values break naive array indexing.
  • Cost: O(n) time, O(k) space; sort + runs is O(n log n).
freq = Counter(items)           # level 1: value -> count
counts = list(freq.values())    # level 2: treat counts as data
return len(counts) == len(set(counts))

Quick quiz

freq = {a:2, b:3, c:2}. What is the answer?

  1. true
  2. false
  3. depends on the order
  4. cannot tell
a and c both occur twice, so the count 2 is not unique.

The array has n = 10 elements and 5 distinct values. Can the answer be true?

  1. yes, always
  2. yes, for some arrays
  3. no: 5 distinct counts need at least 1+2+3+4+5 = 15 elements
  4. only if values are positive
Distinct positive counts for k values sum to at least k(k+1)/2; for k = 5 that is 15 > 10.

Why is a plain int freq[2001] safe here?

  1. values are bounded in [-1000, 1000], so v + 1000 is a valid index
  2. n <= 2001
  3. it is not safe
  4. arrays are always faster
The value range, not the array length, sizes the table; the offset maps -1000..1000 to 0..2000.
