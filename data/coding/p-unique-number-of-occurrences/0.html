The story

Explain like I'm 5

A class votes for its favourite fruit. The teacher writes a tally for each fruit: apples 3, pears 2, plums 4, figs 1. The question is not about any fruit, it is about the tallies: is every tally a different number? If apples and pears both got 3 votes, there is a tie, and the answer is no.

The problem is a counting problem one level up. The first count is the usual histogram. The second step asks whether the histogram's values are all distinct, which is a duplicate check on the counts.

From your world

Think of per-flow packet counters on a NIC: the first table is flow -> packets. The question "do any two flows have the same packet count?" is a duplicate check on the second column, the same thing you would do with a second hash table keyed by the counter value. With small bounded values (here -1000..1000), both tables can be plain arrays, like a direct-indexed lookup table.
