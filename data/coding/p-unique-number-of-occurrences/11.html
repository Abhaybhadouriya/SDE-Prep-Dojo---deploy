Interview follow-ups

Values are bounded in [-1000, 1000]. Can you avoid hashing?

Yes: int freq[2001] indexed by v + 1000, then bool seen[1001] indexed by the count (a count is at most n = 1000). Walk the 2001 slots, skip zeros, and fail if seen[c] is already set. O(n + 2001) time, fixed memory, no hash collisions.

How to answer

Size both tables from the constraints and mention the offset for negatives.

Likely follow-ups
  • Values up to 109: back to hashing, or sort + runs.
The log has 1010 readings and does not fit in memory.

Stream it. If the number of distinct readings is small, the freq map fits even though the log does not, and phase 2 is unchanged. If it is not, hash-partition the readings by value into P files on disk (every copy of a value lands in the same file), count each file in memory, and stream all (value, count) pairs into the counts check. Phase 2 is small anyway: a true answer allows at most about sqrt(2n) distinct values.

How to answer

Separate the size of the input from the size of the state; partition by key so each partition counts independently.

Likely follow-ups
  • Distributed: map-reduce with value as the key, then a second reduce keyed by count.
The readings arrive as a stream. Answer "are the counts unique right now?" after every reading.

Keep freq[value] and countOf[c] = how many values currently have count c, plus clashes = number of c with countOf[c] >= 2. When a value goes from c to c+1, decrement countOf[c] and increment countOf[c+1], adjusting clashes when a bucket crosses 2. The answer is clashes == 0, O(1) per reading.

How to answer

Introduce the count-of-counts map; it is the same structure Maximum Equal Frequency and LFU Cache use.

Likely follow-ups
  • Support deletions too (c to c-1): the same update in reverse.
If the counts are not unique, return the minimum number of deletions to make them unique.

That is LeetCode 1647. Sort counts descending; keep the largest allowed value: each count is lowered to min(c, prevAllowed - 1) (not below 0), and the deletions are the total lowering. Or use a set: while a count is taken, decrement it and add one deletion. O(n + k log k).

How to answer

Show the greedy is safe: lowering the larger clashing count never helps less than lowering a smaller one.

Likely follow-ups
  • Insertions allowed as well as deletions: the cost model changes, ask which.
Why does the size comparison len(freq) == len(set(freq.values())) work?

freq has one entry per distinct value, so it produces k counts. A set of those k counts has size k exactly when no two counts are equal. If any two collide, the set is smaller. It is correct, but it cannot exit early, so the loop with seen is slightly better on false inputs.

How to answer

One sentence: k counts, k distinct counts, pigeonhole.

Likely follow-ups
  • Which is faster in Python in practice? (The one-liner, because set() runs in C.)
