Common mistakes

Initialising the edges with 0 or with min over a missing neighbour. best[-1][c] does not exist; treating it as 0 makes the top row look free. Either handle row 0 / column 0 separately (as here) or pad with +infinity.

Forgetting the start cell. The route cost includes grid[0][0] and grid[m-1][n-1]. Starting from best = 0 at (0,0) undercounts.

Using a greedy walk. Always stepping to the cheaper next cell fails. On [[1,2,9],[3,9,9],[1,1,1]] greedy takes 2 over 3, is then forced through a 9 and pays 1 + 2 + 9 + 1 + 1 = 14, while 1 + 3 + 1 + 1 + 1 = 7. A local choice cannot see the cost further on; the DP compares complete prefixes.

Reaching for Dijkstra or BFS. It works, but the extra log factor and code are unnecessary because right/down moves form a DAG with a known topological order. Say why the plain DP is enough.
