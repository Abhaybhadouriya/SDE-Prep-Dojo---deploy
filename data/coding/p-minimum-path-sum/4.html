Approaches: brute -> better -> optimal

Hint 1

Think about the LAST move into the bottom-right cell. It came from exactly one of two cells.

Hint 2

The cheapest route to (r, c) = cost of (r, c) + the cheaper of the cheapest routes to (r-1, c) and (r, c-1). Those two are "smaller" problems.

1. Brute force - try every route

Idea: cost(r, c) = grid[r][c] + min(cost(r+1, c), cost(r, c+1)) from the start, recursing until the bottom-right cell. Every route has m+n-2 moves, of which m-1 are "down", so there are C(m+n-2, m-1) routes.

O(2m+n)time
O(m+n)stack

Why it is not enough: the call for a cell like (1, 1) is reached by "right then down" and by "down then right", and its whole subtree is recomputed each time. There are only m·n different calls. -> remember them.

2. Better - memo or a full m x n table

Idea: cache cost(r, c) (top-down), or fill a table best[r][c] = cheapest cost from (0, 0) to (r, c) in row-major order (bottom-up). The top row can only be reached from the left and the left column only from above, so they are running sums.

O(m·n)time
O(m·n)space

What is wasted: row r only reads row r-1 and itself. The rows above are dead weight. -> keep one row.

3. Optimal - one rolling row

best = [0] * cols
for r in range(rows):
    for c in range(cols):
        if r == 0 and c == 0: best[c] = grid[0][0]
        elif r == 0:          best[c] = best[c-1] + grid[r][c]
        elif c == 0:          best[c] += grid[r][c]
        else:                 best[c] = min(best[c], best[c-1]) + grid[r][c]
return best[-1]
  1. State: best[r][c] = smallest cost of a right/down route from (0, 0) that ends at (r, c), both cells included.
  2. Transition: best[r][c] = grid[r][c] + min(best[r-1][c], best[r][c-1]), using only the neighbours that exist.
  3. Base case: best[0][0] = grid[0][0].
  4. Order: rows top to bottom, columns left to right: both inputs of a cell are finished before it.
  5. Space trick: in a single array, just before you overwrite best[c] it still holds the value of the row above (the "above" neighbour), and best[c-1] already holds the current row (the "left" neighbour).
  6. Answer: best[m-1][n-1], the last cell of the rolling row.
O(m·n)time
O(n)space

Why it works: take a cheapest route to (r, c). Remove its last cell: what is left is a route to (r-1, c) or to (r, c-1), and it must itself be a cheapest route to that cell - if a cheaper one existed, swapping it in would make the whole route cheaper (an "exchange" argument, also called optimal substructure). So the best route to (r, c) is the better of two best routes plus grid[r][c], which is exactly the recurrence. Non-negative costs also guarantee that no route that goes up or left could ever be cheaper, so the right/down restriction loses nothing when the problem allows only those moves.

O(1) extra space: write into the grid

Several top-voted solutions reuse grid itself as the table (grid[r][c] += min(above, left)). It is O(1) extra space, but it destroys the input. In an interview say so and ask whether the caller still needs the grid; the one-row version is the safe default. You can also roll over the shorter dimension (min(m, n) space) by transposing the loops.
