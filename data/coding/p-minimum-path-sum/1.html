The problem (in our words)

You are given an m x n grid of non-negative integers; grid[r][c] is the cost of entering cell (r, c). Start at the top-left cell (0, 0) and finish at the bottom-right cell (m-1, n-1). At every step you may move only one cell right or one cell down. The cost of a route is the sum of all the cells it visits, including the first and the last. Return the smallest possible cost of such a route.

Signature: int minPathSum(int[][] grid).

Constraints:

  • m == grid.length, n == grid[i].length
  • 1 <= m, n <= 200
  • 0 <= grid[i][j] <= 200

Practice it: LeetCode 64 · GfG practice · TUF article (DP 10)

Constraints tell you: 200 x 200 = 40,000 cells, so O(m·n) is instant, while trying every route (C(m+n-2, m-1) of them, about 10118 here) is hopeless. The largest possible answer is (m+n-1) x 200 = 399 x 200 = 79,800, so a 32-bit int is plenty. Non-negative costs mean you never want to wander, which is why only right/down matters; with negative cells or 4-direction moves this would become a different problem.
