Interview follow-ups

Return the route itself, not only its cost.

Keep the full m x n table (or a parent bit per cell: came from above / from left). Start at (m-1, n-1) and repeatedly step to whichever of above / left has the smaller best value (or follow the parent bit) until (0, 0), then reverse. O(m+n) extra time for the walk; the one-row trick no longer suffices unless you store the m·n parent bits.

How to answer

Point out that space optimisation trades away reconstruction; offer the bitset as the middle ground.

Likely follow-ups
  • Several cheapest routes? Return the lexicographically smallest by a fixed tie-break.
Moves are allowed in all four directions.

Now routes can loop and there is no fill order. With non-negative costs run Dijkstra from (0, 0): dist[start] = grid[0][0], relax the 4 neighbours, O(m·n log(m·n)). If costs were only 0/1, a deque (0-1 BFS) gives O(m·n).

How to answer

Name the property the DP relied on (a DAG) and show it breaks.

Likely follow-ups
  • Negative costs? Bellman-Ford, and a negative cycle makes the answer unbounded.
Some cells are blocked (walls).

Treat a wall as cost +infinity: best = INF for that cell, and min() naturally avoids it. If best[m-1][n-1] is still INF, no route exists; return -1. Use a large sentinel (e.g. INT_MAX / 2) to avoid overflow when adding a cell cost.

How to answer

Same recurrence, one guard; mention the overflow-safe sentinel.

Likely follow-ups
  • Count routes instead? Walls contribute 0 (Unique Paths II).
Can you do it without extra memory?

Yes, if the input may be modified: accumulate into grid in place (grid[r][c] += min(grid[r-1][c], grid[r][c-1])). Otherwise the O(min(m, n)) rolling array is the best you can do while keeping the input intact.

How to answer

Ask about ownership of the input first; it is a design question, not a trick.

Likely follow-ups
  • Grid is huge and streamed row by row? The rolling row already only needs the current row.
Find the minimum cost when you may also move diagonally down-right.

Add the third predecessor: best[r][c] = grid[r][c] + min(above, left, above-left). In one array, save the old best[c-1] of the previous row in a variable before overwriting it, because it is the diagonal for the next cell.

How to answer

Every new move adds a predecessor; the only subtlety is keeping the diagonal value in the rolling array.

Likely follow-ups
  • This "prev diagonal" variable is the same trick as in Edit Distance with one row.
