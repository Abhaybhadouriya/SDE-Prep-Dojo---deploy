Common mistakes

Off-by-one on k. k is 1-based: decrement first, then test for 0 (or count up and compare with k). Returning vals[k] from a list gives the (k+1)-th.

Not stopping the recursion. A recursive version that records the answer but keeps recursing is still O(n); return early from both children once the counter reaches 0.

Passing the counter by value. In C++/Java/Go a plain int k parameter is copied per call, so the left subtree's decrements are lost. Use a member, a pointer, or the iterative version.

Using pre-order or BFS. Only in-order (left, node, right) is sorted for a BST. Reverse in-order (right, node, left) gives the k-th largest.

Saying O(k) time. You first walk down the left spine, which can be h nodes long, so it is O(h + k), and O(n) worst case on a skewed tree.

Recomputing subtree sizes per query. For the follow-up, counting the left subtree with a DFS at every step makes each query O(n) or worse; the sizes must be stored and maintained on insert/delete.
