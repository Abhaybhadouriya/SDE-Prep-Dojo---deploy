The problem (in our words)

A ranking service keeps its scores in a BST: at every node, the whole left subtree holds smaller values and the whole right subtree holds larger ones. With the tree's root and a rank k in hand, report the value that is k-th in ascending order, counting from 1 (rank 1 is the minimum, rank n the maximum).

  • Input: the tree root (on the judge, a level-order list such as [40,20,60,10,30,50,70], with null for a missing child) and the integer k.
  • Output: an integer, the k-th smallest node value. Signature: int kthSmallest(TreeNode root, int k).

Constraints

  • The tree has n nodes, with 1 <= k <= n <= 10^4.
  • 0 <= Node.val <= 10^4.

Follow-up: if the tree is modified often (insertions and deletions) and you must answer the k-th smallest query many times, how would you speed it up?

Practice it: LeetCode 230 - Kth Smallest Element in a BST (the original) · GfG - k-th Smallest in BST · takeuforward

Constraints tell you: k is always valid (1..n), so you never return "not found". n ≤ 10^4 means even O(n log n) collect-and-sort passes, but the tree may be a 10^4-deep chain: recursive DFS depth 10^4 is fine in C++/Java/Go, yet close to Python's default recursion limit (1000) - another reason to use the iterative stack. Values fit in an int.
