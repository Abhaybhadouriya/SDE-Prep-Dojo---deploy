Interview follow-ups

The BST is modified often and kthSmallest is called many times. How do you optimise?

Augment every node with size (nodes in its subtree). A query walks one path: compare k with the left size L, go left, return, or go right with k -= L + 1. Insert/delete add or subtract 1 along their path; in a self-balancing tree (AVL/red-black) rotations recompute size from the children in O(1). Everything is O(log n). This is the classic order-statistic tree (CLRS chapter 14).

How to answer

Draw the three-way comparison on a small tree, then say what changes on insert, delete and rotation.

Likely follow-ups
  • Without changing the node struct? Keep a parallel hash map node → size, or use a library order-statistic tree (GNU pb_ds in C++).
Return the k-th largest instead.

Mirror the walk: go right first, pop, then go left (reverse in-order). Or reuse the same code with k' = n - k + 1, which needs n (a full count or the root's stored size).

How to answer

Prefer the mirrored walk: it stops after k nodes and needs no count.

Likely follow-ups
  • Both k-th smallest and k-th largest in one pass? Two iterators, as in LC 653.
Do it with O(1) extra space.

Morris in-order: for each node with a left child, find its in-order predecessor (rightmost of the left subtree); if its right pointer is null, point it back to the node and go left; if it already points to the node, remove the thread, visit the node, go right. Count visits and remember the k-th. Time O(n) because each edge is walked at most a few times; the tree is restored when the walk completes.

How to answer

Mention that stopping early would leave threads behind, so either finish the walk or undo them; that shows you know the cost.

Likely follow-ups
  • Is it safe with concurrent readers? No: it temporarily mutates the tree.
What are the time and space of your solution, exactly?

O(h + k) time: the first descent pushes up to h nodes, then k pops, and every push is matched by at most one pop. O(h) space for the stack. Balanced tree: O(log n + k) and O(log n); skewed tree: O(n) and O(n).

How to answer

Give both the general form and the two extremes.

Likely follow-ups
  • Why not O(k)? Because reaching the minimum alone already costs h steps.
The tree may contain duplicate values. Does anything change?

If duplicates go consistently to one side (say, equal keys to the right), in-order is still non-decreasing and the k-th popped node is the k-th smallest counting duplicates. If the question wants the k-th distinct value, skip a pop whose value equals the previous popped value before decrementing k.

How to answer

Ask which meaning of "k-th" is wanted, then show the one-line change.

Likely follow-ups
  • Store a count per node instead of duplicate nodes: then decrement k by the count.
It is a plain binary tree, not a BST.

The ordering is gone, so in-order is no longer sorted. Use a max-heap of size k while traversing (O(n log k)), or collect and quickselect (O(n) average).

How to answer

Point out exactly which property the BST solution relied on.

Likely follow-ups
  • Which heap and why? Max-heap of the k smallest seen; the top is the current k-th, evict it when a smaller value arrives.
