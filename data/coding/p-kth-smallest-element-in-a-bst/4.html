Approaches: brute → better → optimal

Hint 1

Ignore the BST property: how would you find the k-th smallest of any list of numbers?

Hint 2

Which traversal order of a BST already gives you the values sorted?

Hint 3

Do you have to visit the nodes after the k-th one? How do you stop a traversal in the middle?

1. Brute - collect every value, sort, index

Idea: any traversal (BFS or DFS) into an array, sort it, return a[k-1]. It works on any binary tree, BST or not.

O(n log n)time
O(n)space

Why it is weak: it throws away the one thing the problem gives you, the ordering. Mention it in one sentence and move on.

2. Better - full in-order into a list

Idea: recursive in-order (left, node, right) appends values already sorted; return list[k-1]. No sort needed.

def inorder(node, out):
    if node:
        inorder(node.left, out); out.append(node.val); inorder(node.right, out)
vals = []; inorder(root, vals); return vals[k - 1]
O(n)time
O(n)space (the list) + O(h) recursion

Why it works: in-order of a BST is sorted (see the pattern section). Waste: it visits all n nodes and stores them even when k = 1.

3. Optimal - iterative in-order with early stop

  1. Go left: from cur, push every node on the way down the left edge. The top of the stack is now the smallest value not yet counted.
  2. Visit: pop a node and decrement k. If k becomes 0, this node is the answer - return immediately.
  3. Go right: set cur = node.right and repeat from step 1. Every value in that right subtree lies between the popped node and the next node on the stack.
O(h + k)time (the left spine, then k pops; each pop does amortised O(1) pushes)
O(h)space (the stack holds one root-to-leaf path)

Why the stack is enough: at any moment the stack holds exactly the ancestors of cur whose left subtree we are inside and that we have not visited yet. They are smaller than nothing that is still pending except each other, so the top is always the next smallest. This is the same invariant as LC 173 (BST iterator), whose next() is amortised O(1).

Variant - recursive with a counter

A recursive in-order that decrements a shared counter and stops descending once it hits 0 has the same O(h + k) time. It is shorter to write but needs a member/closure variable for the counter and the answer, and in Python a 10^4-deep chain hits the recursion limit.

Variant - Morris in-order (O(1) space)

Thread each node's in-order predecessor's right pointer back to it, walk without a stack, and undo the threads. O(n) time, O(1) space, but it temporarily rewrites the tree; if you stop early at k you must still finish the walk (or undo the open threads) to leave the tree intact. Mention it for the "no extra memory" follow-up.

4. Follow-up - order-statistic tree (subtree sizes)

Idea: keep size in every node. At node v with left-subtree size L: if k ≤ L go left; if k == L + 1 return v; else go right with k -= L + 1. Insert and delete update the sizes along their path (and through rotations in a balanced tree), so every operation stays O(h) = O(log n) when balanced.

O(h)per query and per update
O(n)one int per node
