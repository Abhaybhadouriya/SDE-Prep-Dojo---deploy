The problem (in our words)

Design a codec that turns a list of strings into one string, which is sent over a network and turned back into the original list on the other side.

  • Machine 1 (sender) has String encode(List<String> strs) that returns one encoded string.
  • Machine 2 (receiver) has List<String> decode(String s) that must return exactly the original list (same strings, same order, empty strings kept).
  • The test does decode(encode(strs)) and compares the result with strs.
  • You must not use a built-in serialiser such as eval or a JSON library; write the format yourself.

Constraints:

  • 1 <= strs.length <= 200
  • 0 <= strs[i].length <= 200
  • strs[i] may contain any of the 256 valid ASCII characters.
  • Follow-up: could your approach work for any possible set of characters?

Practice it: LeetCode 271 (Premium) · free versions: GfG: Encode and Decode Strings and NeetCode: String Encode and Decode.

Constraints tell you: sizes are tiny (at most 40,000 characters), so speed is not the point. "Any of the 256 characters" is the real constraint: no character is free to use as a separator, and empty strings exist, so the format must mark where each string ends without relying on its content.
