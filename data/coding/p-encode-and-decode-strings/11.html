Interview follow-ups

Make it work for any characters, including Unicode.

The length prefix already does, as long as encode and decode count the same unit. Safest: convert to UTF-8 bytes and frame bytes, so the length is a byte count. In Java, length() counts UTF-16 units and substring uses the same units, so the round trip still holds within Java.

How to answer

Separate the framing (works for any bytes) from the text encoding (choose one, and use it on both ends).

Likely follow-ups
  • What if sender and receiver use different languages? Then agree on bytes (UTF-8), never "characters".
Use a fixed-size header instead of "len#".

Write each length as 4 bytes (big-endian), like gRPC or many binary protocols. The decoder reads 4 bytes, then the payload, no search at all. The cost is 4 bytes per string even for short ones; the gain is simpler, branch-free parsing. A variable-length integer (varint, as in protobuf) gets both: 1 byte for lengths under 128.

How to answer

Compare overhead and parsing simplicity; mention varints.

Likely follow-ups
  • Maximum string length with a 4-byte header? 232 - 1 bytes.
Write the escaping version instead.

Encode: replace each / in a string with //, then append /: after each string. Decode: scan; on / look at the next char: / means a literal slash, : means end of string. Empty strings become just /:, and an empty list is "", so they differ. O(L) time, output up to 2L + 2n.

How to answer

State the two-character rule clearly before coding; that is where bugs hide.

Likely follow-ups
  • Which is faster to decode? Length prefix: it skips payloads instead of reading every character.
The encoded data arrives in chunks over a socket. Decode as it streams in.

Keep a buffer and a small state machine: READING_HEADER (collect digits until '#') and READING_PAYLOAD (need k more bytes). Each chunk advances the state; emit a string when its payload completes. Never assume a chunk ends on a frame boundary: that is the classic TCP framing bug.

How to answer

Draw the two states and what moves between them.

Likely follow-ups
  • Defend against a malicious huge length: cap it and close the connection.
What if decode gets corrupted input?

Validate: the header must be non-empty digits followed by '#', and j + 1 + k must not pass the end. Otherwise raise an error instead of slicing past the end (Python silently returns a short string; Java throws). Production formats add a checksum per frame.

How to answer

List the checks the happy-path code skips.

Likely follow-ups
  • Can you resync after corruption? Not with plain length prefixes; that is why some protocols add a magic marker.
