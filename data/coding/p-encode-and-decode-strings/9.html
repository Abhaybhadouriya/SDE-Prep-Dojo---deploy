60-second recall

  • Cue: many strings -> one string, any character allowed -> length-prefix framing.
  • Insight: the header uses only digits + '#', so its first '#' is safe; the payload is taken by count, never scanned.
  • State: one index i that always points at the next header.
  • Trap: search for '#' from i; keep empty strings; never split on '#'.
  • Cost: O(total length) both ways. Production form: fixed 4-byte length.
def encode(strs): return "".join(f"{len(s)}#{s}" for s in strs)
def decode(s):
    out, i = [], 0
    while i < len(s):
        j = s.index("#", i); k = int(s[i:j])
        out.append(s[j + 1:j + 1 + k]); i = j + 1 + k
    return out

Why can the decoder safely stop at the first '#' it finds from i?

  1. Strings never contain '#'
  2. It checks the next character too
  3. The header contains only digits, and i is always at a header
The scan only ever covers the digits of a header; payloads are skipped by count.

What does [""] encode to with the length prefix?

  1. 0#
  2. an empty string
  3. #
Every string gets a header, even an empty one, so [""] and [] differ.

Which format does not need any '#' at all?

  1. Escaping with doubled '#'
  2. A fixed-width 4-byte length header
  3. Comma-separated values
A fixed-width header has a known size, so no terminator is needed.
