  • Cue: pick two indexes, score = width × min(value) -> two pointers from both ends.
  • Insight: the shorter wall caps every narrower tank, so drop it after one check.
  • State: l = 0, r = n - 1, best.
  • Trap: move the SHORTER side; width is r - l; inner posts do not matter.
  • Cost: O(n) time, O(1) space; brute O(n²); sort-by-height O(n log n).
l, r = 0, n - 1
while l < r:
    best = max(best, score(l, r))
    if a[l] < a[r]: l += 1     # the side that caps the score is finished
    else: r -= 1

heights[l] = 3, heights[r] = 8. Which pointer moves?

  1. r
  2. l, the shorter wall
  3. both
  4. whichever is farther from the middle
Every narrower tank that keeps l is capped by height 3 and is less wide, so none beats the current one. Drop l.

Do the posts between l and r reduce the water?

  1. yes, they block it
  2. no, only the two chosen walls matter
  3. only if taller than both
  4. only if shorter than both
This is not trapping rain water: the area is (r - l) × min(h[l], h[r]).

If heights[l] == heights[r], which move is safe?

  1. only l
  2. only r
  3. either, or both
  4. neither; stop
Any tank that keeps one of them and is narrower is capped by that same height, so moving either is safe.
