Interview follow-ups

Prove that maxCount <= (n + 1) / 2 is both necessary and sufficient.

Necessary: m copies of one letter need m - 1 separators between them, so 2m - 1 <= n. Sufficient: the even-slot construction places the top letter on the ceil(n/2) even slots and never makes a clash (the wrap argument), so whenever the bound holds an answer is produced.

How to answer

Say the bound before writing code; interviewers often ask for it first.

Likely follow-ups
  • What if only the count of valid strings is needed? (Much harder: inclusion-exclusion, not asked in this form.)
Equal letters must be at least k apart. Change your solution.

Use the heap version with a cooldown: pop the most frequent letter, append it, decrement, and put it in a FIFO with the index when it becomes available again (i + k). Before each pop, move letters whose time has come from the FIFO back to the heap. If the heap is empty while the string is not finished, return "". O(n log 26).

How to answer

Show that k = 2 is exactly this problem, then generalise the "previous letter is parked" idea.

Likely follow-ups
  • Can the even-slot trick handle k? (Stride k works only for the top letter; ties break it. The heap is the safe answer.)
Why does the heap solution pop two letters per round?

Popping one and pushing it back immediately could return the same letter next. Popping two guarantees two different letters per round, and since the larger one is appended first and the counts stay balanced, the first letter of a round differs from the last letter of the previous round. The equivalent alternative is to hold the previous letter out of the heap for one pop.

How to answer

Name the failure (same letter twice) and the fix in one sentence each.

Likely follow-ups
  • Complexity with an alphabet of size k? (O(n log k).)
Return the lexicographically smallest valid arrangement.

Build left to right; at each position try letters in a-z order, skip the previous letter, and accept the first letter c for which the r letters left after it can still be arranged without starting with c: the remaining top count must be at most (r + 1) / 2, and when r is odd, c itself must not have exactly (r + 1) / 2 copies left (it would need every even slot, including the first). O(26 · 26 · n) with a simple check, fine for n = 500.

How to answer

Greedy with a feasibility check per choice; reuse the bound.

Likely follow-ups
  • Why can't the even-slot fill do this? (It fixes positions by parity, not by letter order.)
The input is Unicode text, not lowercase letters.

Count with a hash map instead of an int[26]; finding the top count is O(distinct). The even-slot fill is still O(n) and the heap version becomes O(n log d) for d distinct symbols. In Java/C++ iterate over code points, not UTF-16 units or bytes.

How to answer

Point out that nothing in the proof depends on the alphabet size.

Likely follow-ups
  • Memory if the input streams in? (You need all counts before placing anything.)
