Approaches: brute → better → optimal

Hint 1

What does every permutation of s1 have in common? Describe it without listing them.

Hint 2

Going from window [i..i+n1-1] to [i+1..i+n1], which counts change?

1. Brute force - try every permutation

Idea: generate all permutations of s1 and search each in s2.

O(n1! · n1 · n2)time
O(n1)recursion space

What is wasted: n1 = 10 already gives 3.6 million permutations. Everything we need is the letter counts; the order is irrelevant.

2. Better - sort each window, or recount it

Idea: two strings are permutations of each other exactly when their sorted forms are equal (or their 26 counts are equal). For every start i, sort or count s2[i .. i+n1-1] and compare with s1.

O(n1 · (n2 - n1))time with counting (sorting adds a log)
O(26)space

What is wasted: neighbouring windows share n1 - 1 letters, yet we count all n1 of them again.

3. Better still - slide the counts, compare 26 slots

Idea: keep the window's 26 counts. Each step add the letter entering on the right and remove the one leaving on the left, then compare the two count arrays (26 steps). This is the most common accepted solution and is fine in an interview.

O(n1 + 26 · n2)time
O(26)space

4. Optimal - one diff array and a "matched" counter

diff[c] = count_s1(c) - count_window(c)      # 0 means letter c agrees
matched = number of c with diff[c] == 0       # 26 means the window is a permutation
slide:  update(in, -1); update(out, +1)        # update fixes matched only when diff crosses 0
  1. One array, not two. diff = s1's counts minus the window's counts. The window matches when all 26 entries are 0.
  2. Count the zeros. matched = how many entries are 0. Start it after the first window is loaded (letters that appear in neither string are 0 from the start, so it begins near 26).
  3. Update around a change. Before changing diff[c], if it was 0 we lose a match; after changing it, if it is 0 we gain one. Any other change does not touch matched.
  4. Same letter in and out? The two updates cancel: diff goes 0 → -1 → 0 and matched goes down and back up. No special case is needed.
  5. Check before each slide, including the first window and the last window.
O(n1 + n2)time: n1 to load, two O(1) updates per slide
O(26)space

Why it works: a window is a permutation of s1 if and only if every letter has the same count in both, that is, if and only if all 26 entries of diff are 0. The invariant "matched = number of zero entries of diff" holds after the setup loop and is kept by update, because a single +1 or -1 can only move an entry onto 0 or off 0, and update checks both sides of the change. So matched == 26 is exactly the permutation test, and every possible window (start 0 .. n2 - n1) is tested once.

The official editorial walks the same ladder (permutations → sorting → counts → sliding counts → optimised sliding window with a match count); the most voted community posts settle on approach 3 or 4.
