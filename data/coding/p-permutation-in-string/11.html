Interview follow-ups

The strings can contain any Unicode characters.

Replace the 26-slot array with a hash map from character to diff, holding only characters of s1 plus those currently in the window. Track mismatched (the number of keys with a non-zero diff) instead of matched-out-of-26; the window matches when it is 0. Remove a key when its diff returns to 0 to keep the map small.

How to answer

Keep the algorithm, swap the container, and flip the counter to "number of non-zero entries" because the alphabet size is no longer a constant.

Likely follow-ups
  • Java strings are UTF-16: iterate code points, not chars, for characters outside the BMP.
Return the start index of the first match, or all of them.

Return the window start (right - n1 + 1) instead of true. For all of them, do not return: collect every start where matched == 26. That is LC 438, Find All Anagrams in a String, with the same O(n1 + n2) bound.

How to answer

Point at the one line that changes.

Likely follow-ups
  • Count them only: an integer instead of a list.
Why not use a polynomial or sum hash of the window?

An order-independent hash (for example the sum of a random 64-bit value per letter) can be rolled in O(1) too, but equal hashes do not prove equal counts. You must verify a hit with a 26-slot compare, which brings back the cost on collisions. The matched counter is exact and just as fast, so prefer it; mention hashing as the idea that generalises to huge alphabets.

How to answer

Compare exactness and cost, and say when hashing would win.

Likely follow-ups
  • What hash makes collisions unlikely? (Random per-letter values, sum mod 2^64; an adversary who knows them can still collide.)
s2 arrives as a stream of characters. Can you answer online?

Yes, but you must remember the last n1 characters (a ring buffer of size n1) to know which letter leaves. Memory O(n1 + 26), time O(1) per character. Report the first time matched reaches 26.

How to answer

Name what the algorithm needs to keep: the window contents for the "out" letter, plus the diff array.

Likely follow-ups
  • Several patterns at once: one diff array and one counter per pattern, grouped by length.
Allow up to k letters to differ (an "almost permutation").

For a fixed length, the number of letters that must change is half the sum of |diff[c]| over c (each wrong letter adds one surplus and one shortage). Keep absSum = Σ|diff[c]| up to date on each update (it changes by ±1 per update) and test absSum / 2 <= k. Still O(n1 + n2).

How to answer

Show that the "matched" idea generalises: maintain any aggregate of diff that changes in O(1) per update.

Likely follow-ups
  • Prove the factor 1/2: the window and s1 have the same length, so total surplus equals total shortage.
