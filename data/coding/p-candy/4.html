Approaches: brute -> better -> optimal

Hint 1

Forget the right neighbour. What is the minimum if only "beat your left neighbour" mattered?

Hint 2

Now do the same for the right neighbour, scanning the other way. How do you combine the two answers without breaking either rule?

1. Brute force - relax until nothing changes

Idea: start everyone at 1. Sweep the line; whenever a child has a higher rating than a neighbour but not more candy, set it to neighbour + 1. Repeat sweeps until a sweep changes nothing.

O(n²)time (n sweeps worst case)
O(n)space

What is wasted: on a falling line [n, n-1, ..., 1] a left-to-right sweep fixes only one child per pass, because the fix must flow right to left. -> sweep in the right direction for each rule.

2. Optimal - two greedy passes

give = [1] * n
for i in range(1, n):                       # left rule
    if r[i] > r[i-1]: give[i] = give[i-1] + 1
for i in range(n-2, -1, -1):                # right rule, keep the bigger demand
    if r[i] > r[i+1]: give[i] = max(give[i], give[i+1] + 1)
  1. Pass 1 makes the left rule true with the smallest values: each child gets 1 + the length of the rising run ending at it.
  2. Pass 2 makes the right rule true scanning backwards, so give[i+1] is already final when you look at child i.
  3. Take the max, never overwrite. Raising a value never breaks the left rule (a higher child stays higher than its left neighbour), so both rules hold at the end.
  4. Equal ratings do nothing in either pass: both children may keep 1.
O(n)time (2 passes)
O(n)space

Why it is the minimum: any valid assignment must give child i at least L[i] (the left climb: a rising run of length k forces 1, 2, ..., k+1) and at least R[i] (the right climb, same argument). So it gives at least max(L[i], R[i]). The two-pass result is exactly max(L[i], R[i]) for every child, and it is valid, so nothing smaller exists.

Proof (optional): why pass 2 keeps the left rule

Suppose r[i] > r[i-1] and pass 2 raises give[i]. give[i-1] is changed in pass 2 only after give[i] (it is to the left), and it can only become give[i]+1 if r[i-1] > r[i], which is false. So give[i-1] keeps its pass-1 value, which is below give[i]'s pass-1 value, which is below the raised one.

3. Optimal space - count slopes in one pass

Only run lengths matter, so keep three counters: up (length of the current rising run), down (current falling run) and peak (the up value at the top of the last climb). On a step down, the new child gets 1 and every child already on the descent gets one more; the peak gets one more only once the descent is longer than its climb.

total, up, down, peak = 1, 0, 0, 0
for i in range(1, n):
    if r[i] > r[i-1]:   up += 1; peak, down = up, 0; total += 1 + up
    elif r[i] == r[i-1]: up = down = peak = 0;      total += 1
    else:                up = 0; down += 1;          total += down + (peak < down)
O(n)time (1 pass)
O(1)space

This is the idea behind the top-voted O(1)-space posts. It is easy to get the peak adjustment off by one, so in an interview code the two-pass version first and offer this as the follow-up. Our Python file tests it against the brute force on 3,000 random arrays.
