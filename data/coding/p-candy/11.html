Slope counting (rung 3): track the current rising length up, falling length down and peak. A rising step adds 1 + up; a tie adds 1 and resets; a falling step adds down (the new child and the earlier descenders) plus 1 more if the descent is now longer than the climb.

How to answer

Derive it from max(L, R): only run lengths matter, so you never need the arrays.

Likely follow-ups
  • Prove the peak adjustment. (The peak holds max(up, down) + 1; it grows only while down > up.)
The children sit in a circle.

Take the global minimum m: it is never higher than a neighbour, so it can always get 1. Run the linear algorithm on the line r[m], r[m+1], ..., r[m-1], r[m] (the minimum at both ends, so both of its neighbour rules are checked) and subtract the duplicated 1. O(n).

How to answer

Show that the global minimum can safely get 1, which turns the circle into a line.

Likely follow-ups
  • All ratings equal? (Everyone gets 1, n total.)
Equal neighbours must now get equal candy.

Compress each run of equal ratings into one block, solve the compressed line with the same two passes, then multiply each block's value by its length. Or keep the arrays and copy the neighbour value on equality in both passes, keeping the max.

How to answer

Point out that the new rule makes equal neighbours one unit.

Likely follow-ups
  • Does the max still give the minimum? (Yes; every bound is still forced.)
The kids form a grid; beat every higher-rated orthogonal neighbour.

Passes no longer work, because the dependencies form a DAG, not a line. Build edges from lower to higher rated neighbours and run a topological order (or DFS with memo): candies[v] = 1 + max over lower neighbours. That is the same as Longest Increasing Path in a Matrix, summed. O(mn).

How to answer

Generalise the "climb length" to the longest path in the dependency DAG.

Likely follow-ups
  • Why is it a DAG? (Edges only go to strictly higher ratings, so no cycle.)
Why is greedy correct here when greedy often fails?

Because each pass computes a lower bound that every valid answer must respect, and the combination of the two lower bounds is itself valid. A greedy that produces a feasible solution equal to a proven lower bound is optimal.

How to answer

Lower bound + matching construction is the standard greedy proof.
