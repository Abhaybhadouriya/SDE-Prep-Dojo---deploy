The problem (in our words)

n children stand in a line. Child i has a rating ratings[i]. Hand out candies so that:

  • every child gets at least one candy;
  • a child with a strictly higher rating than an adjacent child gets more candies than that neighbour.

Return the minimum total number of candies. Signature: int candy(int[] ratings).

  • n == ratings.length
  • 1 <= n <= 5 * 104
  • 0 <= ratings[i] <= 5 * 104

Practice it: LeetCode 135 · GfG Minimum Candy Distribution · TUF article

Constraints tell you: n up to 5·104. A careful O(n²) "relax until stable" can still be slow on a long falling run, and the follow-up always asks for O(n). The total is at most 1 + 2 + ... + n ≈ 1.25·109, which still fits in a signed 32-bit int (2.1·109), but only just: say so. Equal ratings impose no rule at all.
