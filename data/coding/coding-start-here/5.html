Let the constraints pick the complexity

The input limits in a problem statement are a hint from the setter. A typical judge runs very roughly 108 simple operations per second in C++ (a rule of thumb; Java and Python are slower), so the size of n tells you which complexity will fit.

From your world

This is the same habit as sizing a lookup in the data plane. If a table holds 16 entries, a linear scan is fine. If it holds a million routes and you get a packet every 70 ns, you need a trie or a hash, and you know it from the numbers before you write a line. Do the same arithmetic with n in the first five minutes of every round.
