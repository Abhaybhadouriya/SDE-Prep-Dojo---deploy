What each level is graded on

Every big company uses a rubric with roughly the same four boxes. The Tech Interview Handbook (written by an ex-Meta engineer, linked below) lists them as communication, problem solving, technical competency and testing. Here is what a strong mark in each box looks like at each level.

Box on the scorecardSDE-1 (new grad, L3/E3, 0-2 yrs)SDE-2 (L4/E4/E5, 2-6 yrs)SDE-3 / senior (L5/L6/E6)
CommunicationThinks out loud; asks about input size and edge cases before coding.Drives the session: states the plan, checks in at each step, takes hints quickly.Frames trade-offs like a design review; explains why the solution is optimal.
Problem solvingFinds a correct approach, maybe with a hint; knows brute force and one improvement.Finds the optimal approach mostly alone; knows the complexity of every step.Optimal without hints; handles twists (stream, distributed, memory cap) on the spot.
Technical competency (code)Working code, few bugs, reasonable names.Clean, modular, idiomatic code written at speed; small helper functions.Production-shaped code: clear interfaces, no duplicated logic, sensible errors.
TestingDry-runs one example when asked.Dry-runs unprompted, lists edge cases, finds own bugs.Designs the test set: boundaries, large input, adversarial cases; reasons about failure modes.

Interviewers love this: before you write any code, say the brute force and its complexity in one sentence, then say "I think we can do better with X; shall I go with that?" It ticks communication and problem solving in the first five minutes, at every level.

Level is also decided by the number and difficulty of follow-ups you clear. A typical onsite question has a base problem and one or two extensions. SDE-1 candidates are often hired on the base problem alone. SDE-2 candidates are expected to reach at least the first extension. SDE-3 candidates are expected to reach the last one, or to show clear judgement about how they would.
