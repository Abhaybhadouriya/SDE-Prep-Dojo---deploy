A full round, out loud

Here is a warm-up question as it would be asked in a phone screen, and what a strong candidate says at each step. The task is LeetCode 1 (Two Sum), restated.

Problem (our words). A sensor logs a list of integer readings. Given the list and an integer target, return the indices of the two different readings whose sum is exactly target. Exactly one valid pair exists, the same index cannot be used twice, and the two indices may be returned in any order.

Input / output: readings: int[], target: int → int[2]. Constraints: 2 ≤ length ≤ 104; -109 ≤ readings[i], target ≤ 109; exactly one answer. Follow-up: can you do better than O(n2)?

Practice it: LeetCode 1 - Two Sum · our write-up: /coding/p/two-sum.

Example: readings = [8, 3, 11, 5, 6], target = 16. Answer [2, 3], because 11 + 5 = 16. Step through the dry run; the caption is what you say aloud.

  1. "The brute force checks every pair, O(n²), which is 5 × 10⁷ pair checks at n = 10⁴. Fine, but we can do one pass: for each reading, ask whether its partner was seen before."
  2. "At index 0 the value is 8, so I need another 8. The map is empty, so I store 8 → 0 and move on."
  3. "Index 1: value 3, partner 13. Not seen. Store 3 → 1."
  4. "Index 2: value 11, partner 5. Not seen yet. Store 11 → 2."
  5. "Index 3: value 5, partner 11. The map has 11 at index 2, so the answer is [2, 3]. I return straight away."
  6. "Edge cases: with [4, 4] and target 8 I look up before I insert, so I never pair an index with itself. Time O(n), space O(n). If memory is tight, sort a copy of (value, index) pairs and use two pointers: O(n log n) time, no hash map."
