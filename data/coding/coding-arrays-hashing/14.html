Quiz

In one-pass two-sum, why do we look up target - x before inserting x?

  1. It is faster
  2. Hash maps reject duplicate keys
  3. So x cannot be used as its own partner
If x were stored first, x + x = target would match x with itself. Looking up first guarantees the partner has an earlier index.

Which key groups anagrams in O(L) time per word?

  1. The sorted letters
  2. The word itself
  3. The 26 letter counts
Counting letters is O(L). Sorting the letters is O(L log L). The word itself is different for each anagram.

In longest consecutive sequence, a walk starts at x only when...

  1. x is the smallest value overall
  2. x - 1 is not in the set
  3. x + 1 is in the set
Starting only at run beginnings means every value is walked once, which keeps the total O(n).

Kadane on [-4, -2, -7] (non-empty block) should return:

  1. -13
  2. -2
  3. 0
The best non-empty block is [-2]. Returning 0 is the "reset to zero" bug.

For first missing positive on an array of length n, the answer always lies in:

  1. 1..n+1
  2. 0..n
  3. 1..n
n slots can hold at most the values 1..n. If they are all present, the answer is n+1.

Boyer-Moore voting ends with candidate c on an input with no guaranteed majority. What next?

  1. Count c in a second pass
  2. Return c
  3. Run the vote again in reverse
The vote only says "c is the only value that could be a majority". A counting pass confirms it.

Your Go solution prints groups in a different order each run. Why?

  1. Slices are unordered
  2. Go randomises map iteration order
  3. A data race
Go deliberately randomises map iteration. If the task needs an order, sort the output.
