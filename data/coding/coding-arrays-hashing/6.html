Pattern 5: Kadane and the running best

Kadane's algorithm is not hashing, but it lives on this page because it is the other "one pass, remember one thing" idea for arrays. You keep a tiny state while you scan (here: the best sum of a subarray that ends at the current index) and update a global answer.

The problem, in our words. Daily profit numbers p[0..n-1] can be negative. Choose a non-empty contiguous block of days with the largest total profit, and return that total. 1 <= n <= 105; -104 <= p[i] <= 104. Example: [-3, 4, -1, 2, -6, 5] -> 5 (either [4, -1, 2] or [5]). Example: [-4, -2, -7] -> -2. Practice it: LeetCode 53 - Maximum Subarray (takeuforward), our write-up Maximum Subarray.

The one rule: the best block ending at day i either extends the best block ending at day i-1, or starts fresh at day i. It starts fresh exactly when the previous running total is negative, because a negative prefix only drags the sum down. cur = max(x, cur + x); best = max(best, cur).

Buy low, sell high is the same skeleton with a different state: keep the running minimum price seen so far, and at each day ask "what if I sell today?" (price - low). That is Best Time to Buy and Sell Stock.

func maxSubArray(nums []int) int {
	best, cur := nums[0], nums[0] // non-empty: start at nums[0]
	for _, x := range nums[1:] {
		cur = max(x, cur+x) // extend or restart (built-in max needs Go 1.21+)
		best = max(best, cur)
	}
	return best
}

func maxProfit(prices []int) int {
	low, best := prices[0], 0 // running minimum = best buy day
	for _, p := range prices[1:] {
		best = max(best, p-low)
		low = min(low, p)
	}
	return best
}
int maxSubArray(const vector<int>& nums) {
    int best = nums[0], cur = nums[0];          // non-empty answer: start at nums[0]
    for (size_t i = 1; i < nums.size(); i++) {
        cur = max(nums[i], cur + nums[i]);      // extend the run or restart at nums[i]
        best = max(best, cur);
    }
    return best;
}

def max_profit(prices):
    low, best = prices[0], 0           # running minimum = the best day to have bought
    for p in prices[1:]:
        best = max(best, p - low)
        low = min(low, p)
    return best

The classic Kadane bug. Writing cur = max(0, cur + x) and starting best = 0 returns 0 for [-4, -2, -7], but the block must be non-empty, so the answer is -2. Start both cur and best at nums[0]. The "reset to 0" form is only right when an empty block is allowed.

Proof (optional): why Kadane is correct

Let E[i] be the best sum of a non-empty block that ends exactly at i. Such a block is either [i] alone (sum x) or a block ending at i-1 plus x. The best block ending at i-1 has sum E[i-1], so E[i] = max(x, E[i-1] + x). Every block ends somewhere, so the answer is max over i of E[i], which is exactly what best tracks. This is a one-dimensional DP whose table has been squeezed into one variable.
