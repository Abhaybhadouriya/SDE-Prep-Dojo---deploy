Pattern 3: canonical keys (group anagrams)

The problem, in our words. You are given a list of lowercase words words. Put the words into groups so that two words are in the same group exactly when one is a rearrangement of the other's letters (an anagram). Return the list of groups; the groups and the words inside them may be in any order.

  • 1 <= words.length <= 104; 0 <= words[i].length <= 100; lowercase English letters only (the empty word is allowed).
  • Example: ["meat", "team", "tame", "pots", "stop", "ox"] -> [["meat","team","tame"], ["pots","stop"], ["ox"]]. Example: [""] -> [[""]].

Practice it: LeetCode 49 - Group Anagrams · takeuforward · our write-up: Group Anagrams.

The insight: comparing every pair of words is O(n2) comparisons. Instead, compute one canonical key per word: a value that is the same for all words in a group and different across groups. Then a hash map key -> list of words does the grouping in one pass. Two classic keys:

  • Sorted letters: "team" -> "aemt". Costs O(L log L) per word of length L. Simple to say, simple to write.
  • Letter-count signature: 26 counts, for example as a tuple in Python, a 26-byte string in C++ or a [26]byte array in Go. Costs O(L) per word. The better answer when words are long.
func groupAnagrams(words []string) [][]string {
	groups := map[[26]byte][]string{} // arrays are comparable, so they work as map keys
	for _, w := range words {
		var key [26]byte
		for i := 0; i < len(w); i++ {
			key[w[i]-'a']++
		}
		groups[key] = append(groups[key], w)
	}
	out := make([][]string, 0, len(groups))
	for _, g := range groups {
		out = append(out, g)
	}
	return out
}
vector<vector<string>> groupAnagrams(const vector<string>& words) {
    unordered_map<string, vector<string>> groups;   // canonical key -> words
    for (const string& w : words) {
        string key(26, '\0');                       // 26 counters packed in a string
        for (char ch : w) key[ch - 'a']++;          // fine while counts < 256 (len <= 100)
        groups[key].push_back(w);
    }
    vector<vector<string>> out;
    for (auto& kv : groups) out.push_back(move(kv.second));
    return out;
}
static List<List<String>> groupAnagrams(String[] words) {
    Map<String, List<String>> groups = new HashMap<>();   // canonical key -> words
    for (String w : words) {
        char[] c = w.toCharArray();
        Arrays.sort(c);                                   // sorted letters = the key
        groups.computeIfAbsent(new String(c), k -> new ArrayList<>()).add(w);
    }
    return new ArrayList<>(groups.values());
}
def group_anagrams(words):
    groups = defaultdict(list)         # canonical key -> words with that key
    for w in words:
        count = [0] * 26
        for ch in w:
            count[ord(ch) - 97] += 1
        groups[tuple(count)].append(w) # same letters, same counts -> same key
    return list(groups.values())
O(n · L)time with count key
O(n · L log L)with sorted key
O(n · L)space

Pick a key your language can hash. A Python list cannot be a dict key (use a tuple). A Java int[] hashes by identity, not by content, so use a String (sorted letters, or counts joined with a separator). Go arrays (not slices) are comparable, so [26]byte is a fine map key. In C++ a std::string of 26 counters works with unordered_map out of the box. The C++ version above stores each count in one char; that is safe here because a word has at most 100 letters.
