Common mistakes

  • Storing before asking in two-sum: an element pairs with itself (budget = 2x).
  • Returning values instead of indices, or 0-based when the task wants 1-based. Re-read the output line of the problem before coding.
  • Integer overflow in C++/Java/Go when you add two values near 109: target - x is safe here (the range fits in 32 bits), but sums of many values are not. Use long / long long / int64 for running sums.
  • Unhashable or identity-hashed keys: a Python list, a Java int[]. Use a tuple or a String.
  • Reading a missing key: C++ m[k] inserts a zero entry; use find or count when you only want to look. Go returns the zero value, so use v, ok := m[k] when 0 is a legal value. Java get returns null and unboxing it into int throws.
  • Relying on map order: Go randomises iteration order on purpose, C++ unordered_map and Java HashMap have no defined order. Python dicts keep insertion order (3.7+), which hides the bug until you switch language. If the output must be ordered, sort it.
  • Kadane with an empty answer: max(0, ...) on an all-negative array.
  • Cyclic sort without the "already home" check: duplicates such as [1, 1] swap forever.

Hash attacks are real. On online judges with hackable tests (Codeforces), people craft inputs that make C++ unordered_map collide on every insert, turning O(n) into O(n2). In interviews nobody does this, but "what is the worst case of your hash map?" is a fair follow-up: answer "O(n) per operation with adversarial keys; a randomised hash, a balanced tree map (O(log n)) or sorting avoids it".
