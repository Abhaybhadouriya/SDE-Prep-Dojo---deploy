Pattern 1: complement lookup (two-sum)

The problem, in our words. A shop sells items with prices prices[0..n-1] (integers, may be negative after a refund) and you have a gift card worth exactly budget. Return the two positions [i, j] of two different items whose prices add up to exactly budget. Exactly one such pair exists, you may not use the same position twice, and the two positions may be returned in any order.

  • 2 <= n <= 104; -109 <= prices[i] <= 109; -109 <= budget <= 109.
  • Exactly one valid answer. Follow-up: can you beat O(n2)?
  • Example: prices = [4, 9, 13, 2], budget = 11 -> [1, 3] (9 + 2). Example: prices = [5, 5], budget = 10 -> [0, 1].

Practice it: LeetCode 1 - Two Sum · takeuforward · our write-up: Two Sum.

Brute force: try every pair (i, j): n(n-1)/2 pairs, O(n2). With n = 104 that is 5 x 107 checks: it passes, but it is not the answer the interviewer is waiting for.

The insight: when you stand at x = prices[i], you do not need "some pair". You need one exact value, the complement need = budget - x. "Have I already seen need, and where?" is a single hash map question. So walk left to right, ask the question, and only then store x for the elements that come later.

  1. i = 0: we need 11 - 4 = 7. The map is empty, so no partner yet. Store 4 with its index 0.
  2. i = 1: we need 2. Not seen. Store 9 : 1.
  3. i = 2: we need -2. Not seen. Store 13 : 2. (Negative complements are normal; nothing special.)
  4. i = 3: we need 9, and the map says 9 sits at index 1. Answer [1, 3]. One pass, n lookups.

Why "ask first, store second" matters. With prices = [6, 3] and budget = 12, storing first would put 6 in the map and then find 6 as its own partner. Asking before storing guarantees the partner sits at an earlier index. It also handles duplicates for free: with [5, 5] the first 5 is stored, and the second 5 finds it.

Every version on this page, Go included, was compiled and run (Go 1.27, C++14, Java 21, Python 3.11) and passes its checks.

func twoSum(nums []int, target int) []int {
	seen := make(map[int]int, len(nums)) // value -> index
	for i, x := range nums {
		if j, ok := seen[target-x]; ok { // look BEFORE storing: no self-pairing
			return []int{j, i}
		}
		seen[x] = i
	}
	return nil
}
vector<int> twoSum(const vector<int>& nums, int target) {
    unordered_map<int, int> seen;              // value -> index where we saw it
    seen.reserve(nums.size() * 2);             // avoid rehashing while we insert
    for (int i = 0; i < (int)nums.size(); i++) {
        int need = target - nums[i];           // the partner nums[i] is waiting for
        auto it = seen.find(need);             // look BEFORE storing: no self-pairing
        if (it != seen.end()) return {it->second, i};
        seen[nums[i]] = i;
    }
    return {};
}
static int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();   // value -> index
    for (int i = 0; i < nums.length; i++) {
        Integer j = seen.get(target - nums[i]);    // look BEFORE storing: no self-pairing
        if (j != null) return new int[]{j, i};
        seen.put(nums[i], i);
    }
    return new int[0];
}
def two_sum(nums, target):
    seen = {}                          # value -> index where we saw it
    for i, x in enumerate(nums):
        need = target - x              # the partner x is waiting for
        if need in seen:               # look BEFORE storing x: x cannot pair with itself
            return [seen[need], i]
        seen[x] = i
    return []                          # the task promises an answer; keep a safe default

Same pattern, other clothes. "Contains duplicate within distance k" stores value -> last index and asks "is the last index within k?". "Count pairs with difference k" asks for x - k and x + k. "Subarray sum equals k" asks for the complement of a running prefix sum (prefix - k), which is two-sum on prefix sums; you will meet it in the prefix-sum problems.
