Pattern 2: frequency counting

Many string questions only care about how many of each thing there are, not where. Two words are anagrams (same letters, different order) exactly when their letter counts are equal. A ransom note can be cut out of a magazine when every letter count in the note is <= the count in the magazine.

Array or map? If the alphabet is small and known (lowercase letters, digits, bytes), use int cnt[26] (or 128 / 256). It is a plain array index, so there is no hashing and no allocation. If the "letters" are arbitrary integers or Unicode strings, use a hash map. Interviewers often ask the follow-up "what if the input is Unicode?": the answer is "switch the array for a map keyed by code point", and say it before they ask.

From your world

A count array is a histogram, the same thing as per-CPU counters in /proc/net/snmp or a byte-value histogram you might build when checking a packet payload. Index = the value, cell = how many. No hashing is needed because the value is already a small integer.
