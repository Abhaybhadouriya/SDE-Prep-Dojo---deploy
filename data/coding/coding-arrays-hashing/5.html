Pattern 4: set membership (longest consecutive sequence)

The problem, in our words. A sensor logged integer readings vals in no particular order (duplicates possible). Return the length of the longest run of consecutive integers (like 39, 40, 41) whose every value appears somewhere in vals. The values need not be next to each other in the input. Your algorithm must run in O(n) time.

  • 0 <= vals.length <= 105; -109 <= vals[i] <= 109.
  • Example: [40, 3, 41, 1, 2, 39, 2] -> 3 (both 1,2,3 and 39,40,41 have length 3). Example: [7, 6, 5, 4, 8, 3] -> 6. Example: [] -> 0.

Practice it: LeetCode 128 - Longest Consecutive Sequence · takeuforward · our write-up: Longest Consecutive Sequence.

Ladder. Sorting and counting runs is O(n log n): a fine first answer, but the task asks for O(n). Putting everything in a set and, for every x, walking x+1, x+2, ... is correct but can be O(n2) (each element of a long run starts its own walk). The fix is one extra question: only start walking at the beginning of a run, that is, when x - 1 is not in the set. Now every value is visited by at most one walk, so the total work is O(n).

  1. A set has no fixed order; say it hands us 40 first. Is 39 in the set? Yes, so 40 is in the middle of some run. Do not walk from here.
  2. x = 3 and x = 41: their left neighbours (2 and 40) exist. Skip both.
  3. x = 1: 0 is not in the set, so 1 is the start of a run. Walk right from here.
  4. The walk finds 2 and 3, then 4 is missing. Run length 3; best = 3.
  5. x = 2: 1 exists, skip. This "skip" is what keeps the total work O(n): 2 and 3 are never walked twice.
  6. x = 39: 38 is absent, so walk 40, 41. Length 3. Final answer 3. Every value was touched by at most one walk.
func longestConsecutive(nums []int) int {
	present := make(map[int]bool, len(nums))
	for _, x := range nums {
		present[x] = true
	}
	best := 0
	for x := range present {
		if present[x-1] { // not a run start
			continue
		}
		n := 1
		for present[x+n] {
			n++
		}
		if n > best {
			best = n
		}
	}
	return best
}
int longestConsecutive(const vector<int>& nums) {
    unordered_set<int> present(nums.begin(), nums.end());
    int best = 0;
    for (int x : present) {
        if (present.count(x - 1)) continue;         // not a run start: skip
        int len = 1;
        while (present.count(x + len)) len++;       // walk only from the start
        best = max(best, len);
    }
    return best;
}
static int longestConsecutive(int[] nums) {
    Set<Integer> present = new HashSet<>();
    for (int x : nums) present.add(x);
    int best = 0;
    for (int x : present) {
        if (present.contains(x - 1)) continue;   // not a run start
        int len = 1;
        while (present.contains(x + len)) len++;
        best = Math.max(best, len);
    }
    return best;
}
def longest_consecutive(nums):
    present = set(nums)
    best = 0
    for x in present:                  # iterate the set: duplicates are gone
        if x - 1 in present:           # not the start of a run: skip
            continue
        length = 1
        while x + length in present:   # walk the run only from its start
            length += 1
        best = max(best, length)
    return best

Loop over the set, not the input. If the input is [1, 1, 1, ..., 1, 2, 3, ..., 50000] style data with many duplicates of a run start, looping over the raw array starts the same walk once per duplicate. That is the bug behind many "Time Limit Exceeded" reports on this problem. Iterate the set (duplicates removed), or skip starts you have already processed.
