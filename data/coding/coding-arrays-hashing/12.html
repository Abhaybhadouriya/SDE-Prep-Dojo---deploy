Interview questions

Two-sum: you used a hash map. What if the array is sorted, or memory is tight?

Sorted input: two pointers from both ends, O(n) time and O(1) space. If the input is unsorted and memory is tight, sort a copy of (value, index) pairs and use two pointers: O(n log n) time, and the indices survive the sort. The hash map wins on time (O(n)) and is the default answer for unsorted input.

How to answer

State the three options as a table in your head: map O(n)/O(n), sort + two pointers O(n log n)/O(n) for the pairs (O(1) if indices are not needed), brute O(n2)/O(1). Then pick based on what they constrain.

Likely follow-ups
  • Return all pairs, not one (dedupe by value; count pairs with a count map).
  • The data is a stream (keep the map; answer each new element immediately).
  • 3Sum (sort, then two pointers per first element: O(n2)).
What is the real time complexity of a hash map lookup, and when does it break?

Expected O(1) when the hash spreads keys evenly and the table resizes to keep the load factor bounded (Java's default resize threshold is 0.75). Worst case O(n) per operation when many keys collide, for example adversarial keys against a known hash function. Java 8+ converts long bucket chains into red-black trees, bounding that worst case to O(log n). A resize is O(n) but happens rarely, so inserts are amortised O(1).

How to answer

Say "expected O(1), amortised over resizes, worst case O(n)". Mention one mitigation (randomised seed, tree bins, or a balanced tree map).

Likely follow-ups
  • Open addressing vs chaining (open addressing is cache friendly but needs tombstones on delete).
  • How would you implement one yourself (array of buckets, hash, mod capacity, chain, resize at load factor).
Group anagrams: sorted-string key or count key? What is the complexity of each?

Sorted key: O(n · L log L) time. Count key: O(n · (L + 26)) time, because building the key is O(L) and hashing it is O(26). For short words both are fine; for long words the count key wins. Space is O(n · L) either way for the output.

How to answer

Write the sorted-key version first (it is shorter and hard to get wrong), then say "if words are long I would switch to a 26-count signature" and show the one-line change.

Likely follow-ups
  • Unicode input (count map keyed by code point, then a sorted tuple of (char, count) as key).
  • Group strings that are rotations or shifts of each other (key = gaps between consecutive letters mod 26).
Longest consecutive sequence in O(n): prove that your solution is linear.

Each value x starts a walk only if x-1 is absent, so each maximal run is walked exactly once, from its smallest value. The walk over a run of length k costs k lookups. The runs are disjoint, so the total walk cost is the number of distinct values, at most n. Building the set and the outer loop are O(n). Total O(n) expected.

How to answer

Name the "start of run" check as the key line, then give the counting argument: every value is inside exactly one walk.

Likely follow-ups
  • Values arrive one at a time (union-find, or a map from run ends to run length that merges neighbours).
  • Return the sequence itself, not only its length (remember the best start).
First missing positive with O(1) extra space: walk me through it.

The answer is in 1..n+1, so only values in 1..n matter. Place each value v at index v-1 by swapping (cyclic sort), skipping values out of range and values already at home. Then the first index i with a[i] != i+1 gives i+1; if none, n+1. Each swap fixes one value at home forever, so there are at most n swaps: O(n) time, O(1) extra space.

How to answer

Start from the "answer is in 1..n+1" observation; that is what unlocks the in-place idea. Mention the alternative marking trick (replace bad values with n+1, then negate a[v-1] to mark v present).

Likely follow-ups
  • You may not modify the input (then O(n) space with a set, or O(n log n) by sorting a copy).
  • Find all missing numbers in 1..n (same placement, then collect every slot that is wrong).
Maximum subarray: extend Kadane to return the start and end index of the best block.

Keep start = where the current run began. When you restart (x > cur + x), set start = i. When cur beats best, record bestL = start, bestR = i. Still one pass, O(1) space.

How to answer

Show the two extra lines. Mention ties: decide whether you want the earliest or the shortest block and use > vs >= to match.

Likely follow-ups
  • Circular array (answer = max(normal Kadane, total - minimum subarray), unless all values are negative).
  • Maximum product (keep both the max and the min ending here, because a negative flips them).
Why does Boyer-Moore voting find the majority, and what breaks without a guaranteed majority?

Think of each decrement as removing a pair of two different values. Removing such pairs never changes which value is a strict majority of what remains. The majority value has more copies than everything else combined, so it can never be fully paired off, and the last candidate standing must be it. Without the guarantee, the final candidate is just "the only possible majority": you must count it in a second pass.

How to answer

Use the "pair cancellation" picture, then state the second-pass rule for n/3 and for unguaranteed input.

Likely follow-ups
  • Elements appearing more than n/k times (k-1 candidates, the Misra-Gries summary).
  • Majority in a data stream with limited memory (same algorithm, it is one pass).
When would you choose sorting over hashing for an array problem?

When O(1) extra space matters (sort in place), when the output must be ordered anyway, when keys are hard to hash, when you need neighbours (closest pair, ranges), or when worst-case guarantees matter more than average speed. Sorting costs O(n log n) but has no bad inputs and better cache behaviour than random hash probes.

How to answer

Name the trade-off: hashing = O(n) expected and O(n) space; sorting = O(n log n) worst case and O(1) to O(n) space, plus order for free.

Likely follow-ups
  • Data does not fit in memory (external sort, or hash-partition into files, then process each file).
  • Data is already nearly sorted (insertion sort or a heap of size k).
