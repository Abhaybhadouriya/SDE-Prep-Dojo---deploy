The toolbox: four ways to remember

Every problem on this page uses one of four "memories". Pick the cheapest one that answers the question you need to ask about the data.

MemoryThe question it answers in O(1)Use whenCost
Hash set"Have I seen value v?"duplicates, membership, "does x+1 exist?"O(n) space
Hash map value -> info"Where (or how often) did I see v?"pairs (two-sum), first/last index, countsO(n) space
Count array int cnt[26]"How many times did letter c appear?"small, known alphabet (a-z, digits, ASCII)O(alphabet) space, very fast
The input array itself"Is value v present?" (mark slot v-1)values are in 1..n and O(1) extra space is requiredO(1) space, destroys input order

Average vs worst case. "O(1)" for a hash lookup is the average. If many keys land in one bucket, a lookup walks a long chain: O(n) in the worst case. In an interview say "O(n) expected time" once; interviewers like hearing that you know the difference. Java 8+ turns long chains into small balanced trees, so its worst case per lookup is O(log n).
