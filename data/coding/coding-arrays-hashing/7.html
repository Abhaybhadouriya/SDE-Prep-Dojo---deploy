Pattern 6: the array is the hash table (cyclic sort)

Sometimes the interviewer says "O(1) extra space". No map, no set. The trick: when the values you care about are in the range 1..n and the array has n slots, slot v-1 can remember value v. You either swap each value into its home slot (cyclic sort) or mark slot v-1 (for example by making it negative).

The problem, in our words. Given an unsorted integer array a (any values, including negatives, zero and duplicates), return the smallest positive integer that does not appear in it. You must use O(n) time and O(1) auxiliary space (you may modify the array).

  • 1 <= n <= 105; -231 <= a[i] <= 231 - 1.
  • Example: [3, 4, -1, 1] -> 2. Example: [1, 2, 3] -> 4. Example: [8, 9, 10] -> 1. Example: [1, 1] -> 2.

Practice it: LeetCode 41 - First Missing Positive (Hard) · GfG - Smallest positive missing number · our write-up: First Missing Positive.

Key observation: with n slots, the answer is always in 1..n+1. If 1..n are all present the answer is n+1; otherwise it is the first missing one. So values <= 0 or > n can never be the answer and can be ignored. Put each useful value v into slot v-1. Then scan: the first slot i that does not hold i+1 gives the answer i+1.

  1. Start: n = 4, so only values 1..4 matter. a[0] = 3, whose home is slot 2. Swap a[0] and a[2].
  2. Slot 0 now holds -1. It can never be an answer, so leave it and move i to 1. Slot 2 is settled for good.
  3. a[1] = 4, whose home is slot 3. Swap a[1] and a[3].
  4. Do not move i yet: the value that arrived (1) is unchecked. Its home is slot 0, so swap again.
  5. Now a[1] = -1 (useless) and slots 2 and 3 already hold their own values. The placement pass is over.
  6. Scan left to right: slot 0 holds 1, slot 1 should hold 2 but holds -1. The answer is 2.
func firstMissingPositive(nums []int) int {
	n := len(nums)
	for i := 0; i < n; i++ {
		// value v belongs at index v-1; swap it home until slot i is settled
		for nums[i] >= 1 && nums[i] <= n && nums[nums[i]-1] != nums[i] {
			j := nums[i] - 1
			nums[i], nums[j] = nums[j], nums[i]
		}
	}
	for i := 0; i < n; i++ {
		if nums[i] != i+1 {
			return i + 1
		}
	}
	return n + 1
}
int firstMissingPositive(vector<int>& nums) {
    int n = nums.size();
    for (int i = 0; i < n; i++) {
        // value v belongs at index v-1; each swap puts one value home for good
        while (nums[i] >= 1 && nums[i] <= n && nums[nums[i] - 1] != nums[i])
            swap(nums[i], nums[nums[i] - 1]);
    }
    for (int i = 0; i < n; i++)
        if (nums[i] != i + 1) return i + 1;
    return n + 1;
}
static int firstMissingPositive(int[] nums) {
    int n = nums.length;
    for (int i = 0; i < n; i++) {
        // value v belongs at index v-1; swap it home until slot i is settled
        while (nums[i] >= 1 && nums[i] <= n && nums[nums[i] - 1] != nums[i]) {
            int j = nums[i] - 1;
            int t = nums[i]; nums[i] = nums[j]; nums[j] = t;
        }
    }
    for (int i = 0; i < n; i++)
        if (nums[i] != i + 1) return i + 1;
    return n + 1;
}
def first_missing_positive(nums):
    n = len(nums)
    for i in range(n):
        # value v belongs at index v-1; swap until slot i holds a useless value or its own value
        while 1 <= nums[i] <= n and nums[nums[i] - 1] != nums[i]:
            j = nums[i] - 1
            nums[i], nums[j] = nums[j], nums[i]
    for i in range(n):
        if nums[i] != i + 1:
            return i + 1
    return n + 1

Why is it O(n) with a while inside a for? Every swap puts one value into its home slot, and a value in its home slot is never moved again (the a[a[i]-1] != a[i] test stops it). There are at most n homes, so there are at most n swaps in total across the whole loop. The same test also stops an infinite loop on duplicates such as [1, 1].

Same trick, sibling problems. Missing Number (values 0..n: sum or XOR also work), Set Mismatch (one duplicate, one missing), Find All Duplicates (mark slot v-1 negative; a slot that is already negative means v was seen before).
