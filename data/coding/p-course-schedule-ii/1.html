The problem (in our words)

A training portal has numCourses modules, numbered 0 to numCourses - 1. You get a list prerequisites where each entry [a, b] means "module b must be finished before module a". Return an order in which you can finish all modules. If several orders work, return any of them. If it is impossible, return an empty array.

  • Input: an integer numCourses and an array of pairs prerequisites.
  • Output: an array containing every course exactly once in a valid order, or []. Signature: int[] findOrder(int numCourses, int[][] prerequisites).

Constraints

  • 1 <= numCourses <= 2000
  • 0 <= prerequisites.length <= numCourses * (numCourses - 1)
  • prerequisites[i].length == 2
  • 0 <= a, b < numCourses and a != b
  • All the pairs [a, b] are distinct.

Practice it: LeetCode 210 - Course Schedule II · GfG - A Valid Order to Complete Tasks · takeuforward

Constraints tell you: V ≤ 2000 but E can be close to V² ≈ 4 × 10^6, so the algorithm must be O(V + E) with an adjacency list; anything that rescans all edges per course (O(V · E)) is too slow. Self-loops are excluded, but longer cycles are not.
