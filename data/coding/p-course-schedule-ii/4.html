Approaches: brute → better → optimal

Hint 1

Which courses can be taken first? What happens to the others once they are taken?

Hint 2

If no course is free but some are left, what does the graph contain?

1. Brute force - repeatedly scan for a free course

Idea: keep a "done" set. Each round, scan all edges to find a not-done course whose prerequisites are all done; take it. If a round finds nothing and courses remain, return [].

O(V · (V + E))time (V rounds, each rescans)
O(V)space

What is wasted: each round rechecks every edge, though only the edges leaving the course just taken changed anything. → keep a counter of unmet prerequisites per course and update only those.

2. Optimal A - Kahn's algorithm (BFS on in-degrees)

ready = deque(c for c in range(n) if indeg[c] == 0)   # core
while ready:
    c = ready.popleft(); order.append(c)
    for d in nxt[c]:
        indeg[d] -= 1
        if indeg[d] == 0: ready.append(d)
return order if len(order) == n else []
  1. Graph. Nodes = courses; edge b → a for each [a, b] ("b unlocks a"). indeg[a] = number of unmet prerequisites.
  2. Traversal. A queue of courses whose in-degree is 0: they can be taken now, in any order.
  3. Visited rule. A course enters the queue exactly once, at the moment its in-degree hits 0. No separate visited array is needed.
  4. Answer. The pop order. If it has fewer than n courses, the rest are on (or behind) a cycle: return [].
O(V + E)time: each node and edge once
O(V + E)space: adjacency list + queue

Why it works: a course is appended only after all its prerequisites were appended (its in-degree counts them down to 0), so the order respects every edge. Conversely, every DAG has a node with in-degree 0, and removing it leaves a smaller DAG, so on a DAG the queue never runs dry early and all n courses come out. If it does run dry early, the remaining nodes all have in-degree ≥ 1 among themselves, which forces a cycle.

Proof (optional) - why leftovers mean a cycle

Let U be the courses never output. Every u in U has in-degree ≥ 1 from inside U (edges from output courses were already subtracted). Start at any u and keep walking backwards along an incoming edge inside U. U is finite, so the walk must repeat a node: that repeat is a directed cycle.

3. Optimal B - DFS with three colours

Idea: DFS from every unvisited course along b → a edges. Colour a node grey when you enter it and black when you finish. Meeting a grey node again means a back edge: a cycle. Push each node when it turns black; the reverse of that finish order is a topological order.

O(V + E)time
O(V + E)space, plus recursion depth up to V (2000)

Trade-off: same complexity. Kahn is iterative (no stack-depth risk) and gives "layers" for free, which the follow-ups often need; DFS is shorter if you already write the cycle-detection template from memory.
