Approaches: brute -> better -> optimal

Hint 1

How large can the digit-square sum of a 4-digit number be? Of a 3-digit number?

Hint 2

If the sequence never reaches 1 and the values are bounded, what must eventually happen?

First: why the loop always ends

Termination proof: a number with d digits is at least 10d-1, while its digit-square sum is at most 81·d. For d >= 4, 81·d < 10d-1 (324 < 1000, 405 < 10000, ...), so the value strictly decreases until it has at most 3 digits. A 3-digit value maps to at most 3 · 81 = 243, which again has at most 3 digits. So after a few steps the sequence lives in {1, ..., 243} forever. Infinitely many steps over a finite set must repeat a value, and since the next value depends only on the current one, a repeat means a cycle. Either that cycle is the fixed point 1 (happy), or it is a cycle without 1 (unhappy). It turns out there is exactly one such cycle: 4 -> 16 -> 37 -> 58 -> 89 -> 145 -> 42 -> 20 -> 4.

1. Simulate with a step cap (do not ship this)

Idea: iterate, say, 1,000 times; if 1 never appeared, say false. It passes, but you cannot justify the number without the proof above, and interviewers mark it as a guess.

2. Better - remember every value in a set

seen = set()
while n != 1 and n not in seen:
    seen.add(n)
    n = digit_square_sum(n)
return n == 1
O(log n)time
O(log n)space

Step 1 costs O(number of digits) = O(log n); after that there are at most ~243 distinct values, so the total is O(log n). The set is small here, but it is O(path length) memory in general. -> Floyd removes it.

3. Optimal - Floyd's tortoise and hare

slow, fast = n, step(n)
while fast != 1 and slow != fast:
    slow = step(slow)
    fast = step(step(fast))
return fast == 1
O(log n)time
O(1)space

Why it works: the sequence is a tail followed by a cycle. Once both pointers are on the cycle, fast gains one position per turn, so the gap shrinks by 1 each turn and they meet within one lap. If the cycle is the fixed point 1, fast arrives there first and the fast != 1 check stops the loop. If they meet anywhere else, the cycle does not contain 1. Starting fast one step ahead (as the most-voted C solution's do-while does implicitly) avoids the loop condition being true before the first move.

The "magic" shortcut: because the only unhappy cycle contains 4, while n != 1 and n != 4: n = step(n) also works. It is fine to mention, but the interviewer wants the general method; you would have to prove the cycle structure first.
