60-second recall

  • Cue: repeat x = f(x) until target or loop -> implicit linked list, cycle detection.
  • Proof: d >= 4 digits shrinks (81d < 10d-1); then values stay <= 243, so a repeat is forced.
  • Set: stop at 1 or at a seen value. Floyd: slow 1 hop, fast 2 hops, stop at 1 or meet.
  • Trap: start fast = f(n), not n; the only bad cycle is 4-16-37-58-89-145-42-20.
  • Cost: O(log n) time; set O(log n) space, Floyd O(1).
slow, fast = n, f(n)
while fast != 1 and slow != fast:
    slow, fast = f(slow), f(f(fast))
return fast == 1

Why must the sequence eventually repeat?

  1. because 1 is happy
  2. values drop to at most 243 and stay there, a finite set
  3. integers overflow
  4. digit sums are even
For 4+ digits the value shrinks; 3-digit values map to at most 243, so pigeonhole forces a repeat.

Floyd starts with slow = n and fast = step(n). Why not fast = n?

  1. a while (slow != fast) loop would stop before moving
  2. it would be slower
  3. fast must be odd
  4. step(n) is always 1
With equal starts the loop condition is false immediately (or use a do-while).

Which value is on the only cycle that does not contain 1?

  1. 7
  2. 10
  3. 89
  4. 100
The unhappy cycle is 4, 16, 37, 58, 89, 145, 42, 20.
