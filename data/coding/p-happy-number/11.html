Interview follow-ups

How do you know the loop terminates?

For d >= 4 digits the next value is at most 81·d, which is less than 10d-1 <= n, so the value decreases. Once at most 3 digits, it stays at most 243. A sequence in a finite set must repeat, and a repeat in a deterministic sequence is a cycle: either {1} or a cycle without 1.

How to answer

Give the two numbers (81·d and 243) and the pigeonhole step; this is the answer the question is really about.

Likely follow-ups
  • How many unhappy cycles exist? (One, of length 8, found by brute force over 1..243.)
Remove the hash set. Why does Floyd's algorithm find the cycle?

After the tail, both pointers are inside a cycle of length L. Each turn the distance from slow to fast (measured forward) grows by 1 mod L, i.e. the gap fast must close shrinks by 1, so they meet within L turns. Total turns are at most tail + L.

How to answer

Say "it is Linked List Cycle with next = f(x)", then give the gap argument.

Likely follow-ups
  • Find the first value of the cycle? (Reset one pointer to n and move both by one step until they meet, as in LC 142.)
  • Brent's algorithm? (Teleport the slow pointer at powers of two; fewer f calls.)
Generalise: sum of the k-th powers of the digits, in base b.

The same bound works: a d-digit number maps to at most d·(b-1)k, which is eventually smaller than bd-1, so values are bounded and the sequence is again a rho. Floyd still works unchanged; only step() changes. The set of cycles is different (for cubes in base 10 there are several fixed points such as 153 and 370).

How to answer

Separate the cycle detection (generic) from f (problem-specific).

Likely follow-ups
  • Find all happy numbers up to 109? (Only the first step depends on n; precompute happiness for 1..810 once, then each n is one step plus a lookup.)
Is the "stop at 4" trick acceptable?

It is correct for this exact f, because the only cycle besides {1} passes through 4. But it relies on a fact you must prove by enumerating 1..243, and it breaks the moment f changes. Offer it as a remark after the general answer.

How to answer

Show you know it, explain why it holds, and prefer the general solution.

Likely follow-ups
  • How would you verify that claim in code? (Run the set version for every start value in 1..243 and collect the cycle members.)
What is the time complexity, precisely?

The first step reads O(log10 n) digits and produces a value <= 810. After that each step is O(1) (at most 3 digits) and the number of steps is bounded by a constant (the values live in 1..243 and the cycle has length 8). So O(log n) total, O(1) space with Floyd.

How to answer

Split into "first step" and "everything after", and say both bounds.

Likely follow-ups
  • How many f calls does Floyd make vs the set? (About 3x as many: slow does 1 and fast 2 per turn; still a constant.)
