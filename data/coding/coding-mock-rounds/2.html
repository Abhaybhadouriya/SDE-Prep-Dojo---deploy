The 45-minute, two-problem format

This is the default Dojo mock. It matches the common shape of a 45-minute coding round at large product companies: a short intro, one warm-up-to-Medium problem, one Medium-to-Hard problem, and a few minutes for your questions. Some companies run one longer problem with follow-ups instead; the same clock works if you treat the follow-up as "problem 2".

MinutesPhaseWhat you do and say
0-3IntroOne-line background. In a solo mock: start the timer, open the first statement, nothing else.
3-10P1 clarify + planRestate the task, ask about input size, duplicates, empty input, return format. Say the brute force and its cost, then the better idea. Get a nod before you code.
10-18P1 codeCode the plan you said, narrating the non-obvious lines. Helpers for anything longer than three lines.
18-22P1 testThe five-step test routine: dry run with a variable table, edge sweep, fix the smallest thing, state time and space.
22-28P2 clarify + planSame as P1, but faster: P2 is usually the harder one, so protect its coding time.
28-38P2 codeCode. If the optimal idea has not come by minute 30, code the best version you have and say what you would improve.
38-42P2 testDry run on a small input, the two or three riskiest edge cases, complexity.
42-45Your questionsIn a real round, ask one real question about the team. In a mock, use it to write the raw notes for grading.

Interviewers love this: visible time awareness. "I have about ten minutes left, so I will code the O(n log n) version now and describe the O(n) one at the end" is a strong signal at every level. Running out of time in silence is a weak one.
