Walking the clock: one mock, minute by minute

Click through one SDE-2 mock. Problem 1 is Longest Substring Without Repeating Characters, problem 2 is Number of Islands. The marker is the clock; the box under it is what you should be saying at that moment.

  1. Minute 0. Start the timer and read the first statement once, completely. In a solo mock, set the rules now: no notes, no autocomplete, no running code before you have tested it by hand.
  2. Minutes 3-10. Clarify, then say the brute force and its cost before the better idea. Ask for a go-ahead. This is the cheapest five minutes of signal in the whole round.
  3. Minute 12, first checkpoint. Coding on problem 1 should have started. If you are still searching for the idea, code the brute force now and improve it after.
  4. Minutes 18-22. Test before you say "done": a small dry run that hits the tricky branch, then the edge sweep, then complexity.
  5. Minute 22, second checkpoint. Problem 1 is closed and tested. Start problem 2 with the same clarify-then-plan rhythm, a little faster.
  6. Minute 32, third checkpoint. Problem 2 should be about half-coded. If not, say so and cut scope: one clean working version beats two half versions.
  7. Minutes 38-42. Test problem 2: a tiny trace, the two or three riskiest edge cases, and the cost including recursion depth.
  8. Minute 45. Stop, even mid-line. Write raw notes before looking at any solution, so the grade is honest. Then grade, then debrief.

The checkpoints are the heart of the format. At each one you ask "am I on plan?" and, if not, take the pre-decided action below, so you never invent a strategy while the clock runs.
