Approaches: brute -> better -> optimal

Hint 1

Which structure picks a uniformly random element in O(1)? Which one finds an element by value in O(1)?

Hint 2

Deleting from the middle of an array is slow only because you keep the order. Does a set need an order?

1. Brute force - a hash set only

Idea: insert and remove in a hash set; for getRandom, draw k in [0, size) and iterate to the k-th element.

O(1) / O(1) / O(n)insert / remove / getRandom
O(n)space

What is wasted: a hash table cannot jump to "the k-th element"; buckets are uneven and some are empty. (Picking a random bucket and retrying until non-empty is not uniform either: elements in crowded buckets are under-sampled.) -> rung 2.

2. Better - an array only

Idea: keep values in a dynamic array. getRandom is vals[rand(size)], O(1). But insert must scan for duplicates and remove must find the value and shift the tail: O(n) each.

3. Optimal - array + map value -> index, delete by swapping with the last

insert(v): if v in pos: return False
           pos[v] = len(vals); vals.append(v); return True
remove(v): if v not in pos: return False
           i, last = pos[v], vals[-1]
           vals[i] = last; pos[last] = i      # move the last value into the hole
           vals.pop(); del pos[v]             # delete v's key LAST
           return True
getRandom(): return vals[randrange(len(vals))]
  1. Invariant: vals holds exactly the set's elements with no holes, and pos[x] is the index of x in vals for every element x.
  2. insert appends at the end and records the index: the invariant holds. Amortised O(1) (dynamic array growth) plus an O(1) average hash operation.
  3. remove overwrites index i with the last value, fixes that value's index, then pops the end. Only two entries change, so it is O(1), and the array stays packed.
  4. getRandom picks an index uniformly; since the array is a bijection between indexes 0..n-1 and the n elements, each element has probability exactly 1/n.
O(1)average per call
O(n)space

Why it works: the order of elements in a set is irrelevant, so we may reorder the array freely; swapping the last element into the hole is the cheapest reorder that keeps it dense. The map makes "where is v?" O(1), and the array makes "give me the k-th element" O(1). The update order matters only when v is the last element: then last == v, and writing pos[last] = i after deleting pos[v] would put v back into the map.
