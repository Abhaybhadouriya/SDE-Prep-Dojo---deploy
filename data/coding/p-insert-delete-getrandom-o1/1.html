The problem (in our words)

Design a class RandomizedSet that stores a set of distinct integers:

  • RandomizedSet() creates an empty set.
  • bool insert(int val) adds val if it is not present. Returns true if it was added, false if it was already there.
  • bool remove(int val) removes val if present. Returns true if it was removed, false if it was not there.
  • int getRandom() returns one of the current elements, each with equal probability. It is only called when the set is not empty.

Each function must run in average O(1) time. The judge's input is two arrays: method names and argument lists, e.g. ["RandomizedSet","insert","remove"] with [[],[7],[4]]; the output lists each call's return value (null for the constructor).

  • -231 <= val <= 231 - 1
  • At most 2 * 105 calls in total to insert, remove and getRandom.
  • There is at least one element in the set when getRandom is called.

Practice it: LeetCode 380 · GfG article: insert, delete, search, getRandom in O(1)

Constraints tell you: 2 · 105 calls, so an O(n) operation could cost 4 · 1010 steps in total: every call must be O(1). Values span the full 32-bit range, so you cannot use a direct-address array; you need hashing.
