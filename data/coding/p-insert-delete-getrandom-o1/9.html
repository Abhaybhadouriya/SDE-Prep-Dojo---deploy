  • Cue: O(1) insert, delete AND uniform random -> array + map value -> index.
  • Insight: a set has no order, so delete = move the last value into the hole, then pop.
  • State: vals (dense), pos[val] = index; one shared random generator.
  • Trap: update pos[last] BEFORE deleting pos[val]; Java remove by index; no duplicates.
  • Cost: O(1) average per call, O(n) space.
i, last = pos[v], vals[-1]
vals[i] = last; pos[last] = i     # fill the hole
vals.pop(); del pos[v]            # shrink, then forget v
return vals[randrange(len(vals))] # getRandom

Why swap the removed value with the last element before popping?

  1. Removing from the middle of an array is O(n); popping the end is O(1)
  2. To keep the array sorted
  3. getRandom needs the last slot empty
Move the last value into the hole, then pop the end.

After that swap, what else must be updated?

  1. Nothing
  2. The map entry of the moved (former last) value now points to the hole's index
  3. Every index in the map
Forgetting this leaves a stale index and breaks the next remove.

How does getRandom stay uniform?

  1. Pick a random key from the map
  2. Pick a random index 0..size-1 in the array
  3. Keep a running counter
The array is dense, so every stored value has the same chance.
