Dry run

Insert 7, 4, 9, 2; try a duplicate; remove from the middle; remove the last element; draw. The top row is vals, the bottom row is pos.

  1. 7 is not in pos: append it at index 0 and record pos[7] = 0.
  2. Append 4 at index 1, pos[4] = 1.
  3. Two more appends. The array is packed: indexes 0..3 are all in use, no holes.
  4. 4 is already in pos: return false and change nothing. One hash lookup.
  5. remove(4): the map says it is at index 1. Deleting from the middle of an array would shift 9 and 2 (O(n)). Instead, copy the last value (2) into index 1...
  6. ...update pos[2] = 1, pop the last slot, and delete key 4. Three O(1) steps; the order of the array changed, which a set does not care about.
  7. 9 is the last element: the "move last into the hole" is a copy onto itself. That is why the code deletes pos[val] after writing pos[last]; the other order would re-insert 9.
  8. Pick a uniform index in [0, size). Because the array has no holes, every stored value has exactly the same chance.
