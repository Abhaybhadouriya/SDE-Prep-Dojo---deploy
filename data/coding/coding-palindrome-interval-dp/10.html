Interview questions

Longest palindromic substring: which approach do you pick, and why not the n x n table?

Expand around all 2n-1 centres: O(n2) time, O(1) memory, short code. The isPal table is also O(n2) time but needs O(n2) memory and a careful fill order. Manacher's algorithm is O(n) and worth naming, but it is rarely expected.

How to answer

Mention brute force O(n3), then the table, then centres as the final answer. Run it on an even-length example.

Likely follow-ups
  • Count palindromic substrings? (Same loop, count.)
  • Very long strings? (Manacher, or hashing with binary search on length.)
Longest palindromic subsequence: give the recurrence and the fill order.

dp[i][i] = 1. If s[i] == s[j]: dp[i][j] = dp[i+1][j-1] + 2 (0 inside for length 2). Else max(dp[i+1][j], dp[i][j-1]). Each cell reads shorter intervals, so fill by length, or with i from n-1 down to 0 and j from i+1 up. O(n2) time; O(n) memory with one rolling row in the i-descending order.

How to answer

Draw the upper triangle and the three arrows. Mention the LCS(s, reverse s) equivalence as a cross-check.

Likely follow-ups
  • Fewest insertions or deletions to make a palindrome? (n - LPS.)
  • Remove at most k letters to get a palindrome? (n - LPS <= k.)
  • Print one longest palindromic subsequence? (Trace back from dp[0][n-1].)
Palindrome partitioning II in O(n2) time and O(n) memory: how?

cut[i] = fewest cuts for the prefix of length i, cut[0] = -1. Expand around each centre left to right. Each palindrome s[l..r] gives cut[r+1] = min(cut[r+1], cut[l] + 1). When cut[l] is read, every palindrome ending at l-1 has a centre before the current one, so cut[l] is final. There is no isPal table, so memory is O(n).

How to answer

Give the two-phase version first (isPal table, then cuts), then merge them. State the "cut[l] is final" argument.

Likely follow-ups
  • Return the pieces? (Store the l that won for each r+1.)
  • Each piece of length at most L? (Stop expanding past length L.)
Burst balloons: why choose the last balloon and not the first?

After you burst k first, its neighbours touch, so the left and right parts interact and the state would need the whole set of remaining balloons (exponential). If k is the last one burst in the open range (l, r), then while the others go, l, k and r are all present. The left part only sees walls l and k, and the right part only sees k and r. So dp[l][r] = max over k of dp[l][k] + a[l]a[k]a[r] + dp[k][r], with 1s padded at both ends. O(n3) time, O(n2) memory.

How to answer

Show why "first" breaks independence with a 3-balloon example, then the "last" recurrence and fill by gap.

Likely follow-ups
  • Print the burst order? (Store the best k per interval and recurse: children first, k last.)
  • Cutting a stick, triangulation: same shape. Which event splits there?
Egg drop: give the O(k n2) recurrence, then a faster one.

dp[e][f] = 1 + min over x of max(dp[e-1][x-1], dp[e][f-x]). The first term grows with x and the second shrinks, so binary search for the crossing gives O(k n log n). Better: let f[t][e] be the most floors resolvable with t moves and e eggs. Then f[t][e] = f[t-1][e-1] + f[t-1][e] + 1 (breaks below, survives above, plus this floor). Increase t until f[t][k] >= n: O(k · answer) time, O(k) memory.

How to answer

Explain the min-max (we choose x, the egg chooses the outcome), then show the flip. Check it with 2 eggs: t(t+1)/2 >= 100 gives t = 14.

Likely follow-ups
  • Which floors do you drop from with 2 eggs and 100 floors? (14, 27, 39, 50, ...: each gap one smaller.)
  • Unlimited eggs? (Binary search: ceil(log2(n+1)).)
Minimum cost to cut a stick: why can n be 106 when the DP is O(m3)?

The DP runs over the sorted cut positions plus the two ends, about m + 2 <= 102 points, not over every unit of length. dp[l][r] = min over l < k < r of dp[l][k] + dp[k][r], plus p[r] - p[l] for the cut that first splits this piece. About 106 steps.

How to answer

Compress to positions first, then the recurrence. Mention that greedy "cut the middle first" is wrong (give a small counterexample, or say you would test it against the DP).

Likely follow-ups
  • Merging instead of cutting? (Reverse view: merging adjacent piles, LeetCode 1000 with a k-pile rule.)
  • Knuth's optimisation? (For some cost functions the best k is monotone, giving O(m2). Name it as an extra.)
Predict the winner: how do you set up a two-player game as interval DP?

Let dp[i][j] = the best (my score minus opponent's score) the player to move can get from a[i..j]. Taking a[i] leaves the opponent the range [i+1, j], whose value from their side is dp[i+1][j], so dp[i][j] = max(a[i] - dp[i+1][j], a[j] - dp[i][j-1]). The first player wins (or ties) if dp[0][n-1] >= 0. O(n2).

How to answer

The difference trick removes the need to track whose turn it is. Fill by length.

Likely follow-ups
  • Stone Game with an even count and an odd total: why does the first player always win? (They can take all even-index or all odd-index piles.)
