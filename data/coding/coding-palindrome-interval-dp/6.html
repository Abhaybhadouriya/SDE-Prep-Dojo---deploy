Egg drop: from O(kn2) to "moves x eggs"

Problem (restated from LeetCode 887, Super Egg Drop). You have k identical eggs and a building with floors 1 to n. There is a floor f (0 <= f <= n) such that an egg dropped from any floor above f breaks and an egg dropped from f or below does not. In one move you drop an unbroken egg from a floor of your choice. A broken egg is gone; an unbroken one can be used again. Return the fewest moves that guarantee you learn f, whatever it is. Example: k = 2, n = 10 needs 4 moves; k = 2, n = 100 needs 14. Limits: 1 <= k <= 100, 1 <= n <= 104.

The textbook DP. dp[e][f] = the fewest moves with e eggs and f floors still unknown. Try every first floor x. If the egg breaks, f floors below x remain with e-1 eggs. If it survives, f - x floors above remain with e eggs. The adversary picks the worse outcome and we pick the best x: dp[e][f] = 1 + min over x of max(dp[e-1][x-1], dp[e][f-x]). That is O(k n2), about 1010 steps at the limits, which is too slow. The first branch grows with x and the second shrinks, so a binary search for their crossing gives O(k n log n). That passes, but it is fiddly.

Flip the question. Ask instead: with t moves and e eggs, what is the largest number of floors f[t][e] we can always resolve? Drop once from the best floor. If the egg breaks, we can resolve f[t-1][e-1] floors below. If it survives, f[t-1][e] floors above. Plus the floor we dropped from. So:

f[t][e] = f[t-1][e-1] + f[t-1][e] + 1

Grow t until f[t][k] >= n. With one array over e, updated from e = k down to 1 so that f[e-1] still holds the value for t-1, this is O(k · answer) time and O(k) memory. The answer is at most n (with one egg you walk up floor by floor) and about log2 n when eggs are plentiful. With 2 eggs, f[t][2] = t(t+1)/2, which is where "14 drops for 100 floors" comes from.

// Super egg drop, flipped: f[e] = most floors resolvable with e eggs in t moves.
// f_t[e] = f_{t-1}[e-1] (egg breaks) + f_{t-1}[e] (survives) + 1 (this floor).
func superEggDrop(k, n int) int {
	f := make([]int, k+1)
	t := 0
	for f[k] < n {
		t++
		for e := k; e >= 1; e-- {
			f[e] = f[e-1] + f[e] + 1
		}
	}
	return t
}
// Super egg drop, flipped: f[e] = the most floors we can fully resolve with
// e eggs and t moves. One drop splits floors into "breaks" (e-1 eggs left)
// + "survives" (e eggs) + the floor itself: f_t[e] = f_{t-1}[e-1] + f_{t-1}[e] + 1.
// Answer = first t with f[k] >= n. O(k * answer) <= O(k log n) for k >= log n.
int superEggDrop(int k, int n) {
    vector<long long> f(k + 1, 0);
    int t = 0;
    while (f[k] < n) {
        t++;
        for (int e = k; e >= 1; e--) f[e] = f[e - 1] + f[e] + 1;  // backwards: f[e-1] is still t-1
    }
    return t;
}
// Super egg drop, flipped: f[e] = most floors resolvable with e eggs in t moves.
// f_t[e] = f_{t-1}[e-1] (egg breaks) + f_{t-1}[e] (survives) + 1 (this floor).
static int superEggDrop(int k, int n) {
    long[] f = new long[k + 1];
    int t = 0;
    while (f[k] < n) {
        t++;
        for (int e = k; e >= 1; e--) f[e] = f[e - 1] + f[e] + 1;
    }
    return t;
}
def super_egg_drop(k: int, n: int) -> int:
    """f[e] = most floors resolvable with e eggs in t moves:
    f_t[e] = f_{t-1}[e-1] (breaks) + f_{t-1}[e] (survives) + 1 (this floor)."""
    f = [0] * (k + 1)
    t = 0
    while f[k] < n:
        t += 1
        for e in range(k, 0, -1):     # backwards: f[e-1] still holds t-1
            f[e] = f[e - 1] + f[e] + 1
    return t

Interviewers love this. Many interviewers stop at the O(k n2) recurrence and want you to explain the min-max: we choose x, the egg decides. If you then offer the flipped "moves x eggs" form and prove it in three lines, that is a strong SDE-3 signal. The 2-egg, 100-floor puzzle (answer 14: drop from 14, 27, 39, ...) is a common warm-up for it.
