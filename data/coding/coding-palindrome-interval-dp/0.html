The story: folding a paper strip

Explain like I'm 5

Write a word on a strip of paper and fold it in the middle. If every letter lands on the same letter, the word reads the same both ways: it is a palindrome, like "kayak" or "noon". To check a long word you do not need to look at everything at once. Check the two end letters. If they match, the question is now about the shorter strip inside. That is a smaller copy of the same question.

Now a different game. Five balloons sit in a row. Each pop gives you points based on the balloon and its two neighbours. What order is best? Here the trick is to ask which balloon pops last. That one splits the row into a left part and a right part that do not affect each other.

Both games use the same state: a range from i to j. We call this interval DP. dp[i][j] is the answer for the piece s[i..j] (both ends included), and it is built from shorter pieces inside it. Two ways to shrink a range show up again and again:

  • Peel the ends: look at s[i] and s[j], then go to [i+1, j-1], [i+1, j] or [i, j-1]. Palindromes work this way.
  • Split at some k between i and j: combine [i, k] and [k, j], and try every k. Burst balloons, cutting sticks and matrix chains work this way. This costs O(n) per cell, so O(n3) in total.

If DP on prefixes is new, read the DP primer and LIS and two-string DP first. Interval DP is the same idea with a two-sided state.

From your world

A table filled by length is a dependency order, like a build system or the kernel's initcall levels: a cell may only read cells that are already done. Shorter intervals are "earlier initcalls". Bugs here behave like a driver reading a structure before its init ran: no crash, just a zero where a real value should be.
