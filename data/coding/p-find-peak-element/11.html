Interview follow-ups

Prove that the half you keep always contains a peak.

If nums[mid] < nums[mid+1], start at mid + 1 and walk right while the next reading is higher. Readings strictly increase on the walk, so it cannot loop, and it must stop at or before hi because the reading after hi is lower than nums[hi] (minus infinity at the end, or a previous downhill step). The stop point beats both neighbours. The downhill case is the mirror image.

How to answer

Say "walk uphill, it has to stop, where it stops is a peak". Then name the invariant on the range ends.

Likely follow-ups
  • Does it find the global maximum? (No, any peak; the global max needs O(n).)
What if equal neighbours are allowed?

A flat stretch makes nums[mid] == nums[mid+1], which says nothing about either side. In the worst case (all equal except one hidden peak) any algorithm must look at every element: Ω(n). You can still binary search when the slope is non-zero and fall back to a scan on ties.

How to answer

Point at the constraint "nums[i] != nums[i+1]" and say it is what makes log n possible.

Likely follow-ups
  • Which other problem has the same issue? (Rotated sorted array with duplicates, LC 154.)
Find a peak in a 2D grid (bigger than all four neighbours).

Binary search on columns: take the middle column, find its maximum cell (O(m)), and compare it with the cells to the left and right. Move toward a bigger neighbour; if none is bigger, that cell is a peak. O(m log n). This is LC 1901.

How to answer

Explain why the column maximum is needed: it already beats its up and down neighbours, so only left/right matter.

Likely follow-ups
  • Why does a greedy climb from a random cell not give log time? (It can wander O(mn) cells.)
Return a valley (local minimum) instead.

Flip the comparison: if nums[mid] > nums[mid+1], go right (downhill), else hi = mid. Edges are treated as plus infinity.

How to answer

Same invariant with the signs reversed; no new code structure.

Likely follow-ups
  • Return both a peak and a valley in one pass? (Two separate searches, still O(log n).)
Write it recursively. What is the space cost?

solve(lo, hi): if lo == hi return lo; compare mid with mid + 1 and recurse into one half. The depth is log n, so O(log n) stack. The loop version is O(1) and is what you should submit.

How to answer

Show it is tail-recursive, so the loop is a direct translation.

Likely follow-ups
  • Does C++/Java remove the tail call? (Not guaranteed; Java never does.)
