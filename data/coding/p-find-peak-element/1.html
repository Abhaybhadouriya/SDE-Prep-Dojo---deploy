The problem (in our words)

A sensor logs a row of altitude readings nums (0-indexed). A reading is a peak if it is strictly greater than each of its neighbours. Imagine an invisible reading of minus infinity just before index 0 and just after index n - 1 (nums[-1] = nums[n] = -∞), so an end reading only has to beat its single real neighbour. Return the index of any one peak; if there are several, any of them is accepted.

Your algorithm must run in O(log n) time.

Signature: int findPeakElement(int[] nums) - read the array, return one index.

  • 1 <= nums.length <= 1000
  • -231 <= nums[i] <= 231 - 1
  • nums[i] != nums[i + 1] for every valid i (neighbours are never equal)

Practice it: LeetCode 162 · GfG Peak in Array · TUF article

Constraints tell you: n is only 1000, so a linear scan would pass the judge, but the statement demands O(log n): the interviewer wants binary search. "Neighbours differ" is the key promise: without it (a flat plateau) the slope at mid could be zero and tell you nothing. Values reach the int limits, so never use a sentinel such as INT_MIN for the outside readings; compare real elements only.
