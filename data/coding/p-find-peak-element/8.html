Common mistakes

Using while (lo <= hi) with hi = mid. When lo == hi, mid == hi and nothing changes: an infinite loop. With hi = mid the loop condition must be lo < hi.

Reading nums[mid + 1] or nums[mid - 1] out of range. The three-way version (check both neighbours of mid) needs guards for index 0 and n - 1. The two-way version above never needs them, because mid < hi.

Throwing away mid on a downhill. hi = mid - 1 can drop the only peak, for example on [1,3,2] with mid = 1.

Saying "binary search needs sorted input". It needs a monotone decision. Explaining why the uphill half must hold a peak is the whole interview; code without that sentence scores low.
