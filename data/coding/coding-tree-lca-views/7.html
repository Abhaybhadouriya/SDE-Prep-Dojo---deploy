Building a tree from two traversals

Problem (restated from LeetCode 105, Construct Binary Tree from Preorder and Inorder Traversal). You get two integer arrays, preorder and inorder, which are the preorder and inorder traversals of the same binary tree. Build that tree and return its root. Example: preorder [1, 2, 4, 5, 3, 6] and inorder [4, 2, 5, 1, 3, 6] give root 1 with children 2 and 3; 2 has children 4 and 5; 3 has only a right child, 6. Limits: 1 to 3,000 nodes, both arrays the same length, values in [-3000, 3000] and all different, and the input is always a valid pair.

Preorder says who is the root (the first value). Inorder says who is on which side (everything left of the root's position is in the left subtree). Recurse: take the next preorder value as the root, split the current inorder range at its position, build the left part, then the right part. Two details make it O(n): a hash map from value to inorder index (no linear search per node), and one shared preorder index that only moves forward (no array slicing).

  1. pre[0] = 1 is the root of the whole tree. Find 1 in inorder (index 3, via the map): [4, 2, 5] is its left subtree, [3, 6] its right subtree.
  2. Build the left subtree first, because preorder lists it next. pre[1] = 2 is its root; in the range [4, 2, 5], 2 splits it into [4] and [5].
  3. pre[2] = 4, range [4]: both sides of 4 are empty ranges (lo > hi), so 4 is a leaf. Return.
  4. pre[3] = 5, range [5]: another leaf. Node 2's subtree is done. Note that the preorder pointer only moves forward: one pass over it.
  5. Back at the root's right side: pre[4] = 3, range [3, 6]. 3 is first in the range, so its left range is empty and its right range is [6].
  6. pre[5] = 6, range [6]: a leaf. Every value was used once and every split was one map lookup: O(n) time, O(n) for the map.

Template: build from preorder and inorder

// Preorder gives the root; its index in inorder splits the subtrees. Index map: O(n) total.
func buildTree(preorder, inorder []int) *TreeNode {
	pos := make(map[int]int, len(inorder))
	for k, v := range inorder {
		pos[v] = k
	}
	i := 0 // index of the next unused preorder value
	var build func(lo, hi int) *TreeNode
	build = func(lo, hi int) *TreeNode {
		if lo > hi {
			return nil
		}
		n := &TreeNode{Val: preorder[i]} // next preorder value is this subtree's root
		i++
		m := pos[n.Val]
		n.Left = build(lo, m-1) // left first: preorder lists it next
		n.Right = build(m+1, hi)
		return n
	}
	return build(0, len(inorder)-1)
}
// Preorder gives the root; its index in inorder splits the subtrees. Index map: O(n) total.
TreeNode* buildRange(const vector<int>& pre, int& i, int lo, int hi, unordered_map<int, int>& pos) {
    if (lo > hi) return nullptr;
    TreeNode* n = new TreeNode(pre[i++]);       // next preorder value is this subtree's root
    int m = pos[n->val];
    n->left = buildRange(pre, i, lo, m - 1, pos);   // left first: preorder lists it next
    n->right = buildRange(pre, i, m + 1, hi, pos);
    return n;
}
TreeNode* buildTree(const vector<int>& preorder, const vector<int>& inorder) {
    unordered_map<int, int> pos;
    for (int k = 0; k < (int)inorder.size(); k++) pos[inorder[k]] = k;
    int i = 0;
    return buildRange(preorder, i, 0, (int)inorder.size() - 1, pos);
}
// Preorder gives the root; its index in inorder splits the subtrees. Index map: O(n) total.
static int nextPre;                          // index of the next unused preorder value
static TreeNode buildTree(int[] preorder, int[] inorder) {
    Map<Integer, Integer> pos = new HashMap<>();
    for (int k = 0; k < inorder.length; k++) pos.put(inorder[k], k);
    nextPre = 0;
    return buildRange(preorder, 0, inorder.length - 1, pos);
}
static TreeNode buildRange(int[] pre, int lo, int hi, Map<Integer, Integer> pos) {
    if (lo > hi) return null;
    TreeNode n = new TreeNode(pre[nextPre++]);   // next preorder value is this subtree's root
    int m = pos.get(n.val);
    n.left = buildRange(pre, lo, m - 1, pos);    // left first: preorder lists it next
    n.right = buildRange(pre, m + 1, hi, pos);
    return n;
}
def build_tree(preorder, inorder):
    """Preorder gives the root; its position in inorder splits left and right subtrees.
    A value -> index map makes each split O(1): O(n) total."""
    pos = {v: i for i, v in enumerate(inorder)}
    it = iter(preorder)

    def go(lo, hi):                        # build the subtree whose inorder range is [lo, hi]
        if lo > hi:
            return None
        v = next(it)                       # next preorder value is this subtree's root
        node = TreeNode(v)
        m = pos[v]
        node.left = go(lo, m - 1)          # left first: preorder lists the left subtree next
        node.right = go(m + 1, hi)
        return node
    return go(0, len(inorder) - 1)
  • Inorder + postorder (LeetCode 106): same limits. Read postorder from the end (the last value is the root) and build the right subtree first, because reading backwards meets the right subtree before the left.
  • Preorder + postorder (LeetCode 889): not unique. A node with one child gives the same two traversals whether the child is on the left or the right, so the problem lets you return any valid tree.
  • BST from preorder (LeetCode 1008): the inorder of a BST is the sorted preorder, so you could sort and reuse this template, but the bounds-based decoder from the 449 note is O(n) without sorting.
