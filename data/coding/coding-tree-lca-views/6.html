Serialize and deserialize: one string, one tree

Problem (restated from LeetCode 297, Serialize and Deserialize Binary Tree). Write two functions. serialize(root) turns a binary tree into a string; deserialize(data) turns that string back into a tree with exactly the same shape and values. You choose the format; the only rule is that deserialize(serialize(t)) rebuilds t. Your functions must not keep state between calls (no global variables or class fields that survive a call). Limits: 0 to 104 nodes, values in [-1000, 1000].

Write every node in preorder, and write a marker such as # for every missing child. A tree with n nodes has n + 1 empty child slots, so the string has 2n + 1 tokens. Decoding reads tokens in the same preorder: a number makes a node, then decodes its left subtree, then its right; a # returns null. There is never a choice to make, so a single pass with a moving token index rebuilds the exact tree.

Template: serialize and deserialize

// Preorder with '#' for every missing child, comma separated.
func serialize(root *TreeNode) string {
	var parts []string
	var ser func(n *TreeNode)
	ser = func(n *TreeNode) {
		if n == nil {
			parts = append(parts, "#")
			return
		}
		parts = append(parts, strconv.Itoa(n.Val))
		ser(n.Left)
		ser(n.Right)
	}
	ser(root)
	return strings.Join(parts, ",")
}

// Read the tokens back in the same preorder; '#' ends a branch.
func deserialize(data string) *TreeNode {
	tokens := strings.Split(data, ",")
	i := 0
	var des func() *TreeNode
	des = func() *TreeNode {
		t := tokens[i]
		i++
		if t == "#" {
			return nil
		}
		v, _ := strconv.Atoi(t)
		n := &TreeNode{Val: v}
		n.Left = des()
		n.Right = des()
		return n
	}
	return des()
}

def serialize(root):
    """Preorder with '#' for every missing child. n nodes -> n values + n + 1 markers."""
    out = []

    def go(node):
        if not node:
            out.append("#")
            return
        out.append(str(node.val))
        go(node.left)
        go(node.right)
    go(root)
    return ",".join(out)


def deserialize(data):
    """Read tokens in the same preorder; '#' ends a branch. Each token is consumed exactly once."""
    tokens = iter(data.split(","))

    def build():
        t = next(tokens)
        if t == "#":
            return None
        node = TreeNode(int(t))
        node.left = build()
        node.right = build()
        return node
    return build()
  • Why preorder? The root comes first, so the decoder can create a node before it reads its children. Postorder also works if you decode from the right end. Inorder with markers does not work: you cannot tell which value is the root.
  • Level order (LeetCode's own format) is just as good and avoids deep recursion: a BFS writes children of each node in turn, and decoding uses a queue of nodes waiting for children.
  • BST variant (LeetCode 449): 0 to 104 nodes, distinct values in [0, 104], "as compact as possible". Preorder without markers is enough: decode with value bounds (a node belongs here only if it is inside (low, high)), exactly like validating a BST. Fixed-width binary values make it smaller still.
  • Find duplicate subtrees (LeetCode 652): serialize every subtree bottom-up and count the strings in a map. Two subtrees are equal exactly when their serializations are equal; giving each distinct string a small id keeps it O(n).
