Interview questions

Find the lowest common ancestor of two nodes in a binary tree. Why is it correct when p is an ancestor of q?

Each call returns null (neither below), p or q (one below), or the LCA (both below). Base case: null, p or q returns itself. Otherwise combine the children: both non-null means the paths split here, so return the node; else pass up the non-null one. When p is above q, the call at p returns p without looking further; no other subtree returns anything, so p bubbles up to the root unchanged and is the answer. O(n) time, O(h) space.

How to answer

State the return contract in one sentence before coding; the four lines follow. Then mention the two root-path alternative and why the one-pass version is better.

Likely follow-ups
  • What if p or q may not exist? (Recurse fully, count found nodes; return the LCA only if both were seen.)
  • The tree is a chain of 105 nodes? (Recursion depth; use a parent map and the ancestor-set walk.)
  • LCA of k nodes? (Same code with "node is in the set" as the base case.)
LCA in a BST: how do you do better than the general version?

Use the ordering. With lo = min(p, q) and hi = max(p, q): if hi < node go left, if lo > node go right, else this node is the LCA. It is a loop with no stack: O(h) time, O(1) space. It also works when one node is an ancestor of the other, since then node equals lo or hi.

How to answer

Point out that the general version is still correct, then say "but the BST property tells me which side to go". Write the loop, not recursion.

Likely follow-ups
  • The nodes might not be in the BST? (Walk to each one to confirm, O(h) each.)
  • Worst case? (A sorted-insert chain: h = n. A balanced BST keeps it O(log n).)
Nodes have parent pointers and you are not given the root. Find the LCA in O(1) extra space.

Each parent chain is a linked list ending at the root, and the two lists merge at the LCA. Option 1: a hash set of p's ancestors, then walk up from q (O(h) space). Option 2: compute both depths, lift the deeper one, walk up together. Option 3: two pointers that each restart from the other start node when they pass the top; both cover the same total distance and meet at the LCA. Options 2 and 3 are O(h) time, O(1) space.

How to answer

Say "this is linked-list intersection" early; interviewers like hearing the link. Give the set version first as the safe baseline, then the O(1) one.

Likely follow-ups
  • Why do the switching pointers meet even if depths are equal? (Then they reach the LCA in the first pass, before any switch.)
  • Many queries on one fixed tree? (Binary lifting: O(n log n) precompute, O(log n) per query.)
Return the right side view of a binary tree. Give two approaches.

BFS by levels: freeze the queue size, pop that many, and the last node popped is the visible one: O(n) time, O(w) space. DFS: visit right child before left, carry the depth, and record a node when depth equals the answer's length (first time at that depth): O(n) time, O(h) space.

How to answer

Draw a tree where a left node is visible because the right side is shorter; it kills the "follow right children" idea, and shows you thought about it.

Likely follow-ups
  • Left, top, bottom views? (First per level; first / last per column with BFS.)
  • Which uses less memory on a balanced tree? (DFS: O(log n) stack against O(n/2) for the last BFS level.)
Vertical order traversal: what is the difference between LeetCode 314 and 987, and how does it change the code?

Both group nodes by column, left to right, top to bottom. They differ only on ties (same row and same column): 314 keeps left-to-right order, 987 sorts by value. For 314, BFS with (node, col) appends each node to its column's list, and BFS order is the tie rule: O(n) with a min/max column instead of a sorted map. For 987, collect (col, row, val) triples and sort: O(n log n).

How to answer

Ask which tie rule they want before coding. Then name why DFS is wrong for 314 (a deep left node is visited before a shallow right node).

Likely follow-ups
  • Avoid the sort for 987? (Bucket by column, then sort only within each column by (row, val).)
  • Return only the top view? (Keep the first value per column in BFS.)
Find all nodes at distance K from a target node. Can you avoid the parent map?

Standard: one DFS builds child-to-parent links, then BFS from the target over left, right and parent with a seen set, k rings; the last ring is the answer. O(n) time and space. Without the map: a recursive function returns the distance from the current node down to the target (or -1). When the target is d below one child, the current node is at d + 1; if that equals k, take it; otherwise collect nodes at depth k - d - 2 in the other child. Same O(n), no map, trickier off-by-ones.

How to answer

Say "the tree is really an undirected graph" and code the BFS. Offer the map-free version as a follow-up, with its formula.

Likely follow-ups
  • Time to infect the whole tree from one node? (Same BFS, count rings: LeetCode 2385.)
  • Distance between two given nodes? (depth(p) + depth(q) - 2 · depth(LCA).)
Serialize and deserialize a binary tree. Why do you need null markers, and which traversal do you pick?

Without markers different trees share a traversal (a root with one child gives the same preorder whether the child is left or right). With a marker for each of the n + 1 empty slots, preorder decodes in one pass: number means "make a node, then decode left, then right", marker means null. Level order also works and avoids deep recursion. Inorder does not work even with markers, because it never tells you which value is the root. O(n) time and space.

How to answer

Show a two-tree counterexample for "no markers", then write both functions; mention the separator and negative numbers.

Likely follow-ups
  • It is a BST? (Preorder without markers; decode with value bounds.)
  • Make it compact? (Binary encoding: fixed-width ints and a bitmap of present children.)
  • N-ary tree? (Write each node's child count, or an end-of-children marker, like a DTB's end-node token.)
Build a binary tree from its preorder and inorder traversals. What is the complexity, and does preorder plus postorder work?

The next preorder value is the root of the current subtree; its position in inorder splits the range into left and right. With a value-to-index map and one moving preorder index, each node costs O(1): O(n) time, O(n) space (map plus stack). Preorder plus postorder is not enough in general: a node with a single child looks the same either way, so the tree is unique only when every node has 0 or 2 children.

How to answer

Do a 5-node example by hand first. Name the two O(n) details (map, no slicing) before the interviewer asks.

Likely follow-ups
  • Inorder plus postorder? (Root from the end; build right first.)
  • Values may repeat? (The split becomes ambiguous; the problem is not well defined.)
Give the shortest directions ("L", "R", "U") from node s to node t in a binary tree.

Find the root-to-s path and the root-to-t path as strings of L and R (one DFS each, appending and backtracking). Drop the common prefix: that is the path to their LCA. The answer is "U" repeated for each remaining step of s's path, followed by the rest of t's path. O(n) time. This is LeetCode 2096 (up to 105 nodes), and it shows that "LCA" can also mean "longest common prefix of two root paths".

How to answer

Say LCA first, then why paths as strings are convenient. Build the path iteratively or with a list and pop, to avoid O(n2) string copies.

Likely follow-ups
  • Just the number of steps? (depth(s) + depth(t) - 2 · depth(LCA).)
