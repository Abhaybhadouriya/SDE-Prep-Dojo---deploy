Common mistakes

  • Comparing values instead of nodes. LCA takes nodes. If values repeat (some GfG versions allow it), value comparison finds the wrong node. Compare pointers or references; in Python use is.
  • Using the early-return LCA when a node may be missing. It returns p when q does not exist. For 1644 recurse fully and count.
  • BST LCA by "p goes left, q goes right". Use lo = min, hi = max; the case where one node is the answer (lo == node or hi == node) falls out of the "else" branch.
  • Right view by "always go right". Following right children misses a left node that is deeper than the whole right side: in [1, 2, 3, 4], node 4 hangs under 2 and is still visible from the right, so the answer is [1, 3, 4]. Use levels.
  • Vertical order with DFS for 314. DFS visits a deep left node before a shallow right node in the same column. Use BFS, or record the row and sort stably.
  • Boundary: leaves twice, or the root as a leaf. Edge passes skip leaves; the leaf pass is the only one that adds them; a one-node tree returns just [root].
  • Distance K without a seen set. With parent links the graph has cycles of length 2 (child to parent and back); without "seen" the BFS bounces forever or reports wrong nodes.
  • Serializing without null markers, or splitting "-12" wrongly. Use a separator between tokens and parse with stoi / Integer.parseInt, which handle the minus sign.
  • Slicing arrays when building. preorder[1:m+1] per call is O(n2) in the worst case. Pass index bounds and keep one moving preorder index.
  • Deep recursion in Python. Chains of 104 or 105 nodes overflow the default limit. Raise it with sys.setrecursionlimit or use the BFS/stack versions.
