LCA in a binary tree: the post-order return

Problem (restated from LeetCode 236, Lowest Common Ancestor of a Binary Tree). A company keeps its reporting chain as a binary tree. You get the root and two different nodes p and q, both in the tree. Return their lowest common ancestor: the deepest node that has both p and q in its subtree, where a node counts as part of its own subtree (so if p sits above q, the answer is p). In the tree drawn below, LCA(2, 9) = 4, LCA(4, 9) = 4 and LCA(6, 19) = 10. Limits: 2 to 105 nodes, values in [-109, 109] and all different, p != q, and both p and q exist.

The first idea most people have is the ELI5 one: find the path from the root to p, find the path to q, and walk both lists until they differ. That works and is O(n), but it needs two searches, two lists and careful path-recording code. Interviewers expect the one-pass version, which comes from a single question: what should a call on a subtree return?

Let lca(node) return, for the subtree under node:

  • null if neither p nor q is inside it;
  • p or q if exactly one of them is inside (it returns the one it found);
  • the LCA if both are inside.

Then the code writes itself. If node is null, p or q, return node. Otherwise ask both children. If both answers are non-null, p is on one side and q on the other, so node is the split point: return it. If only one is non-null, pass it up. The early return at p is safe even when q is under p: then p is the answer anyway, and nothing else in the tree will return non-null to compete with it.

  1. Call lca(10). It is not p or q, so it asks its left child, 4, which asks its left child, 2. Node 2 is p, so it returns itself at once. It does not look below: whatever is under p, the answer cannot be deeper than p.
  2. Back at 4, the right side starts: 7 asks 6. Node 6 is neither p nor q and has no children, so both its calls return null and 6 returns null.
  3. 7 asks 9. Node 9 is q: return 9. At 7 the left answer is null and the right answer is 9, so 7 passes 9 upward. 7 is not the LCA; it is only a messenger saying "q is down here".
  4. Back at 4: the left call returned 2 (non-null) and the right call returned 9 (non-null). p and q are on different sides of 4, so 4 is where their paths split. 4 returns itself.
  5. 10 now asks its right child 15. Nothing in that subtree is p or q, so 12, 19 and then 15 all return null. This walk is the price of the simple version: O(n) in the worst case.
  6. At 10: left = 4, right = null. Only one side found something, so 10 passes it up unchanged. The final answer is 4. Each node did O(1) work after its two calls: O(n) time, O(h) stack.

Template: LCA in a binary tree

// LCA in a binary tree (p and q both present). Post-order: each call returns p, q, their LCA,
// or nil for its own subtree.
func lca(root, p, q *TreeNode) *TreeNode {
	if root == nil || root == p || root == q {
		return root // found one (or fell off the tree)
	}
	l := lca(root.Left, p, q)
	r := lca(root.Right, p, q)
	if l != nil && r != nil {
		return root // split point
	}
	if l != nil {
		return l // pass up whatever was found
	}
	return r
}
// LCA in a binary tree (p and q both present). Post-order: each call returns p, q, their LCA,
// or nullptr for its own subtree.
TreeNode* lca(TreeNode* root, TreeNode* p, TreeNode* q) {
    if (!root || root == p || root == q) return root;   // found one (or fell off the tree)
    TreeNode* l = lca(root->left, p, q);
    TreeNode* r = lca(root->right, p, q);
    if (l && r) return root;                             // split point
    return l ? l : r;                                    // pass up whatever was found
}
// LCA in a binary tree (p and q both present). Post-order: each call returns p, q, their LCA,
// or null for its own subtree.
static TreeNode lca(TreeNode root, TreeNode p, TreeNode q) {
    if (root == null || root == p || root == q) return root;  // found one (or fell off the tree)
    TreeNode l = lca(root.left, p, q);
    TreeNode r = lca(root.right, p, q);
    if (l != null && r != null) return root;                  // split point
    return l != null ? l : r;                                 // pass up whatever was found
}
def lca(root, p, q):
    """LCA in a binary tree (p and q both present). Post-order: each call returns
    p, q, their LCA, or None, for its own subtree."""
    if root is None or root is p or root is q:
        return root                      # found one of them (or fell off the tree)
    left = lca(root.left, p, q)
    right = lca(root.right, p, q)
    if left and right:
        return root                      # p on one side, q on the other: root is the split point
    return left or right                 # pass up whatever was found

Cost: O(n) time, O(h) stack, where h is the height (n for a chain). With 105 nodes in a chain, Python's default recursion limit (1,000) is too small and deep recursion can crash C++ and Java too. If the interviewer pushes on that, use the iterative fallback: one BFS or DFS to fill a parent map, then the "set of p's ancestors" walk from the next section.

Variant: p or q may be missing (LeetCode 1644, Premium). Same task, but either node might not be in the tree; then return null. Limits: 1 to 104 nodes, distinct values in [-109, 109]. The early return breaks here: if p is found, we never look under it for q, and we cannot tell "q is under p" from "q does not exist". Fix: do not stop at a match. Recurse into both children first, count how many of p and q you have seen, then apply the same combine rule. Return the result only if the count is 2.
