How to recognise which tree tool you need

Cue words: "lowest / nearest common ancestor", "common manager", "first shared folder", "distance between two nodes", "path from node a to node b" (all LCA); "view from the right / left / top / bottom", "vertical order", "column", "boundary", "outline" (coordinates + BFS); "distance k", "within k steps", "infection spreads / burns each minute" (parent map + BFS); "encode / decode / store / send a tree", "same structure", "duplicate subtrees" (serialization); "given preorder and inorder", "rebuild" (construction).

  1. Two nodes and "where do they meet": LCA. Check first: BST? (walk by value). Parent pointers and no root? (two pointers). May a node be missing? (no early return).
  2. Distance or path between two nodes: also LCA. dist(p, q) = depth(p) + depth(q) - 2 · depth(LCA). Directions from p to q are "U" up to the LCA, then the LCA-to-q path.
  3. Anything a camera would see: give each node (row, col) and pick by level (BFS) or by column (map or sort).
  4. Distance measured in every direction from one node: the tree is really a graph. Add parent links and BFS.
  5. The tree must survive as text: a traversal plus null markers. One traversal without markers is not enough (inorder alone never is).

Counter-cue: if the question is about a value property of the whole tree (height, diameter, max path sum), it is a bottom-up return on the Binary trees page, not an LCA problem. If many LCA queries arrive on one fixed tree, mention binary lifting (precompute 2j-th ancestors, O(log n) per query), but you will rarely be asked to code it.
