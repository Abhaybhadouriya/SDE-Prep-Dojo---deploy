Interview follow-ups

Why is the one-pass stack O(n) when there is a while loop inside the for loop?

Each index is pushed exactly once and popped at most once, so the total number of inner-loop iterations over the whole run is at most n + 1. That is amortised analysis: count operations per element, not per outer step.

How to answer

Name the potential argument: stack size goes up by one per push, down by one per pop, never below zero.

Likely follow-ups
  • What is the worst-case stack size? (n, on strictly rising input.)
Now find the largest rectangle of 1s in a binary matrix (LC 85).

Keep h[c] = number of consecutive 1s ending at the current row in column c (reset to 0 on a 0). After each row, run this function on h. O(rows × cols) time, O(cols) space.

How to answer

Say "reduce 2D to 1D": each row is the base of a histogram.

Likely follow-ups
  • Largest square instead (LC 221, a simpler DP).
  • Count all-ones submatrices (LC 1504).
Do it without a stack.

Build L[] with jumps: start at p = i - 1 and while heights[p] >= heights[i] set p = L[p]; do the same for R[] from the right. The jumps skip runs already known to be tall, giving O(n) amortised. Or divide and conquer on the minimum with a sparse table for O(n log n).

How to answer

Point out that the jump chain is the stack, stored implicitly in the array.

Likely follow-ups
  • Why is plain divide and conquer O(n²) on sorted input?
Return the start, end and height of the best rectangle, not just the area.

When a pop improves best, record (leftWall + 1, i - 1, heights[top]). With ties, decide upfront which one you report (first found, or widest).

How to answer

Ask which tie-break is wanted before coding.

Likely follow-ups
  • List all rectangles with the maximum area.
Bars arrive as a stream; report the best area so far after each bar.

The stack pass is already online for bars whose right wall has arrived. For the running answer, also consider the bars still on the stack as if the stream ended now: each stack entry j with the entry s below it gives heights[j] × (i - s) where i is the current length. Scanning the stack per query is correct but O(stack) per bar; interviewers usually want the reasoning, not a faster structure.

How to answer

Separate "finalised" rectangles (popped) from "open" ones (still on the stack).

Likely follow-ups
  • What if bars can also be removed from the left (a sliding window)?
What changes if bars have different widths?

Replace index arithmetic with prefix sums of widths: width of the rectangle for a popped bar is pre[i] - pre[leftWall + 1]. Use 64-bit areas since widths can be large.

How to answer

Show the formula i - leftWall - 1 is just "sum of widths between the walls" with all widths 1.
