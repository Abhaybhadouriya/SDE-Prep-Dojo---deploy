  • Cue: "rectangle limited by its lowest bar", "each element as the range minimum" -> monotonic stack.
  • Insight: fix the lowest bar; it stretches to the first lower bar on each side.
  • State: stack of indices, heights rising; pop on >=; right wall = i, left wall = new top or -1.
  • Trap: width i - leftWall - 1; flush with a height-0 bar at i = n.
  • Cost: O(n) time and space; each index pushed and popped once.
for i in range(n + 1):
    h = 0 if i == n else a[i]
    while st and a[st[-1]] >= h:
        top = st.pop(); left = st[-1] if st else -1
        best = max(best, a[top] * (i - left - 1))
    st.append(i)

When bar j is popped at index i, what width does its rectangle get?

  1. i - j
  2. i - newTop - 1, where newTop is the index left on the stack (or -1)
  3. j - newTop
The new top is the nearest shorter bar on the left and i is the nearest shorter bar on the right; bar j spans everything strictly between them.

What does the stack hold?

  1. Indices with strictly increasing heights bottom -> top (non-decreasing also works)
  2. Heights in decreasing order
  3. All indices seen so far
A bar stays while every later bar is at least as tall, so it can still extend to the right.

Why append a sentinel height 0 at the end?

  1. To handle an empty input only
  2. It pops every bar still on the stack, so their rectangles are counted
  3. It makes the stack sorted
Without it, bars that never meet a shorter bar to the right are never measured.
