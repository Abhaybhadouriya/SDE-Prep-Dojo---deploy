The problem (in our words)

A path in a binary tree is a sequence of nodes where each consecutive pair is joined by an edge, and no node appears more than once. A path has at least one node and does not have to pass through the root. The path sum is the sum of the node values on it. Given the root of a binary tree whose nodes carry integer values (positive or negative), return the maximum path sum over all non-empty paths.

Signature: int maxPathSum(TreeNode root) (LeetCode style; the tree is given as a level-order list with null for missing children).

  • The number of nodes is in the range [1, 3 · 104]
  • -1000 <= Node.val <= 1000

Practice it: LeetCode 124 · GfG Maximum Path Sum from Any Node · TUF article

Constraints tell you: 3·104 nodes means one O(n) pass; an O(n²) "try every top node and rescan" is about 9·108 steps and too slow. The sum is at most 3·104 · 1000 = 3·107 in size, so int is safe. A skewed tree can be 3·104 deep: recursion is fine in C++/Java/Go defaults, but Python needs a raised recursion limit (or an iterative post-order).
