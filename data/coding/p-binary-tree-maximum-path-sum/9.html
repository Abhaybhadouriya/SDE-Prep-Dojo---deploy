  • Cue: best path anywhere in a tree (sum, length) -> post-order, return arm, record bend.
  • Insight: each path has one top; bend = val + L + R; parent may extend only one side.
  • State: L = max(arm(left), 0), R = max(arm(right), 0); global best = root.val.
  • Trap: best starts at root.val (not 0); return val + max(L, R), never L + R.
  • Cost: O(n) time, O(h) stack; recomputing arms per node is O(n²).
def dfs(node):
    if not node: return 0                    # neutral value for a missing child
    l, r = gain(dfs(node.left)), gain(dfs(node.right))
    best = combine(best, node, l, r)         # path whose top is node
    return extend(node, l, r)                # one-sided value for the parent

The path must contain at least one node, so start best at root.val (or -inf), never 0.

What does the helper return to its parent?

  1. val + L + R
  2. val + max(L, R), one arm
  3. the best path so far
  4. max(L, R)
A parent can extend only one side. The bend val + L + R is recorded in best, never returned.

Why clamp each child's arm with max(arm, 0)?

  1. to avoid overflow
  2. a negative arm only lowers the sum, so you take nothing from that side
  3. to make the tree balanced
  4. it is wrong
Dropping a negative branch is the same as ending the path at this node.
