Approaches: brute → better → optimal

Hint 1

Every path has exactly one node closest to the root. Call it the top. What does the path look like below the top?

Hint 2

If you knew, for every node, the best sum of a path that starts there and goes straight down, could you get the best path with that node as top?

Hint 3

The value you return to the parent and the value you compare against the answer are not the same. Why can the parent not use both of your children?

1. Brute force - every node as the top, rescan below

Idea: for each node v, compute down(v.left) and down(v.right) (the best downward chain from each child) by a fresh DFS, and take v.val + max(0, down(left)) + max(0, down(right)). The maximum over all v is the answer.

O(n²)time (skewed tree)
O(h)space

What is wasted: down(child) is recomputed for every ancestor. But down(v) only depends on down(v.left) and down(v.right): compute it once, bottom-up. -> rung 2.

2. Optimal - one post-order DFS, two numbers per node

def arm(node):
    if not node: return 0
    l, r = max(arm(node.left), 0), max(arm(node.right), 0)
    best = max(best, node.val + l + r)      # path bending here
    return node.val + max(l, r)             # chain the parent may extend
  1. Arm = best chain from the node straight down. arm(v) = v.val + max(0, arm(left), arm(right)). It always contains v; an empty child contributes 0.
  2. Clamp negative arms to 0. A child chain with a negative sum would only lower any path, so the path simply stops at v on that side.
  3. Bend = v.val + left + right. This is the best path whose top is v. Compare it with the global best.
  4. Return only one side. If the parent extends through v, v already has an edge to the parent, so it can use at most one child; returning l + r would build a fork, not a path.
  5. Start best at root.val, not 0. The path must be non-empty; with all-negative values the answer is negative.
O(n)time
O(h)space (recursion), h ≤ n

Why it works: each path is counted at exactly one node, its top, and there it equals top + (best left chain or nothing) + (best right chain or nothing). The DFS evaluates that expression at every node with the true best chains, because a chain below v is v plus the best chain of one child: optimal substructure.

Proof (optional)

Claim 1: arm(v) returns the maximum sum of a downward path starting at v. By induction on height: a downward path from v is v alone, or v followed by a downward path from one child c; the best such is v.val + max(0, arm(c)) over c. Claim 2: the answer is max over v of v.val + max(0, arm(v.left)) + max(0, arm(v.right)). Any path P has a unique top t; removing t splits P into at most two downward paths starting at children of t, each bounded by the child's arm (or replaced by 0 if dropped), so sum(P) ≤ the bend at t. Conversely, each bend value is the sum of a real path. The DFS computes every bend once, so the maximum it records is the answer.
