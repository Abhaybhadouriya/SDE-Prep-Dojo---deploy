The tree is 106 nodes deep. What breaks and how do you fix it?

Recursion overflows the stack. Do an iterative post-order: push nodes on an explicit stack, compute arms into a map (or a field) once both children are done. Memory O(n) on the heap instead of the call stack.

How to answer

Mention that in C you would also worry about the 8 MB default thread stack; the explicit stack is the portable fix.

Likely follow-ups

Keep the two largest positive child arms at each node: bend = val + top1 + top2, arm = val + top1. O(n) overall, since each child is looked at once.

The path must go from leaf to leaf.

No clamping: a node with two children has bend = val + arm(left) + arm(right) and arm = val + max of the two; a node with one child just passes val + arm(child) up and records nothing. Leaves return their value. Watch the case where the root has one child.

How to answer

Point out that "may stop anywhere" is what allowed the clamp at 0.
