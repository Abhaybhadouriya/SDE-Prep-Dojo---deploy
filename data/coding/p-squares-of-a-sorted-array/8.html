Common mistakes

Filling from the front. The smallest square is somewhere in the middle, not at an end; comparing the ends and writing the smaller one at the front gives the wrong order. Fill from the back, or start from the zero and merge outward.

Loop condition lo < hi. It skips the last element. Loop on the write index (n steps), or use lo <= hi.

Squaring in place before comparing. If you overwrite nums with squares first, the two-pointer logic still works (squares of a sorted array are a valley), but you must not then also compare absolute values of the originals. Pick one: compare squares or compare abs().

Overflow in a variant. With values up to 105 or a quadratic a x² + b x + c, use 64-bit.
