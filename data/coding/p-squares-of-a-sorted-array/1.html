The problem (in our words)

You get an integer array nums sorted in non-decreasing order. It may contain negative numbers, zero and duplicates. Return a new array holding the square of every element, also sorted in non-decreasing order.

Signature: int[] sortedSquares(int[] nums).

Constraints

  • 1 <= nums.length <= 10^4
  • -10^4 <= nums[i] <= 10^4
  • nums is sorted in non-decreasing order.

Follow-up in the original: squaring and sorting is easy; can you find an O(n) solution?

Practice it: LeetCode 977 - Squares of a Sorted Array · GfG - Sort array after converting elements to their squares

Constraints tell you: n is only 104, so even O(n log n) passes the judge; the interviewer wants the O(n) follow-up. The largest square is 108, which fits in a 32-bit int (limit about 2.1 * 109), so no overflow here; it would overflow if values went up to 105.
