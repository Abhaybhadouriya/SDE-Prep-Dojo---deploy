Interview follow-ups

Instead of x², apply f(x) = a x² + b x + c. Return the sorted results.

f is a parabola, so on a sorted input its values are a valley (a > 0) or a hill (a < 0). For a > 0 the largest values are at the ends: same algorithm, fill from the back. For a < 0 the smallest values are at the ends: compare the ends and write the smaller one from the front. For a = 0, f is linear: the output is the input mapped, reversed if b < 0. Use 64-bit if the values can be large.

How to answer

Say "the transform has one turning point, so the extremes are at the ends", then handle the sign of a.

Likely follow-ups
  • Can one loop handle both signs? (Yes: choose the fill direction and the comparison from the sign of a.)
Do it in place, with O(1) extra space and no output array.

Not in O(n) with simple two pointers: writing a square at the back would overwrite an element you still need. The honest answers are: square in place and sort in place (O(n log n), O(1) or O(log n) stack), or use an in-place merge, which is complicated. Say that the output array is normally not counted as extra space, and the original problem allows it.

How to answer

Explain why the back write collides with unread data before proposing anything.

Likely follow-ups
  • What is the in-place cost of each option?
Return the squares without duplicates (each distinct square once).

Same loop; before writing, skip if the value equals the last value written. Because you write from the back, compare with out[w+1], and at the end return the suffix out[w+1..]. Or merge from the zero outward and compare with the previous written value.

How to answer

Note that -3 and 3 collide after squaring, so the input's own duplicate check is not enough.

Likely follow-ups
  • Count distinct absolute values without building the output (two pointers, skip equal magnitudes).
The input is a stream you can read only once, left to right. What changes?

You cannot reach the right end first. Push negatives onto a stack as they arrive (their squares come out increasing when popped); when non-negatives start, merge the stack top with the stream, emitting the smaller square each time. Output comes in increasing order, memory O(number of negatives).

How to answer

Switch from "fill from the back" to "merge outward from zero".

Likely follow-ups
  • Can you emit anything before seeing the first non-negative? (No: a later 0 could be smaller.)
Is O(n log n) "square then sort" ever the better choice?

For n = 104 both are instant, and the sort version is shorter and harder to get wrong. In production code you might pick it for clarity. In the interview, give it first, then say the sorted input lets you merge two sorted runs in O(n), and code that.

How to answer

Show you know the trade-off, then deliver the optimal one.

Likely follow-ups
  • What does the library sort cost in space in your language?
