Interview follow-ups

Billions of queries s against one fixed t. What changes?

Preprocess t into 26 sorted position lists (O(|t|)). Each query does one lower-bound search per letter: O(|s| log |t|). Or build a next-occurrence table nxt[j][c] in O(26·|t|) and answer in O(|s|).

How to answer

State that greedy is unchanged; only "find the next c after p" becomes a lookup instead of a scan.

Likely follow-ups
  • Memory for the table if t were 109 long? (26 ints per position is too much; use position lists.)
Count how many words from a list are subsequences of t.

LeetCode 792. Bucket every word by the letter it is waiting for; scan t once, and for each letter move the words in that bucket to their next letter's bucket. Total O(|t| + total word length).

How to answer

Present it as running all greedy pointers in parallel during one scan of t.

Likely follow-ups
  • Duplicate words? (Count them once with a map, multiply.)
Return the indices in t where s is matched (or the leftmost such set).

Record j each time i advances. The greedy matching is also the lexicographically smallest index set, by the exchange argument.

How to answer

One extra line in the match branch.

Likely follow-ups
  • Rightmost matching? (Run greedy from the right end of both strings.)
How many characters must be appended to the end of t so that s becomes a subsequence of it?

Append to t's end: run greedy and the unmatched tail of s, |s| - i, must be appended (LeetCode 2486 asks this with the roles named differently). No extra structure needed.

How to answer

Show the same loop returns i, not just i == |s|.

Likely follow-ups
  • Minimum deletions from t to make s equal to t? (|t| - |s| if s is a subsequence, else impossible.)
t is a stream you cannot store; many patterns s are known in advance.

Keep one pointer per pattern and the "waiting for letter c" buckets from 792; each stream byte advances the bucket for that byte. Memory is O(number of patterns), independent of the stream length.

How to answer

Relate it to the streaming packet-filter idea: state per pattern, no buffering of the stream.

Likely follow-ups
  • Substring (contiguous) patterns instead? (Then you need Aho-Corasick or KMP automata.)
