Approaches: brute -> better -> optimal

Hint 1

When s[0] appears several times in t, which copy should you match it with?

Hint 2

For the follow-up: what would let you jump straight to "the next 'c' after position p" without scanning?

1. Brute force - try every way to match (recursion)

Idea: f(i, j) = can s[i..] be matched inside t[j..]? If the letters match, either use this t letter or skip it; if not, skip it. Without memo this branches on every match.

O(2|t|)time (worst)
O(|t|)stack

What is wasted: the same (i, j) pair is solved many times, and the "skip a matching letter" branch is never needed (rung 3 shows why). Memoising gives rung 2.

2. Better - DP table (or LCS length == |s|)

State: dp[i][j] = true if s[i..] is a subsequence of t[j..]. Transition: dp[i][j] = (s[i] == t[j] and dp[i+1][j+1]) or dp[i][j+1]. Base case: dp[|s|][j] = true, dp[i][|t|] = false for i < |s|. Answer: dp[0][0]. Equivalently, s is a subsequence of t exactly when LCS(s, t) = |s|.

O(|s|·|t|)time
O(|s|·|t|)space (O(|s|) with one row)

What is wasted: the DP keeps both choices open, but when s[i] == t[j] the "use it" choice is always at least as good. Once that is proved, the table collapses to one path. -> rung 3.

3. Optimal - greedy two pointers

i = 0
for ch in t:
    if i < len(s) and s[i] == ch:
        i += 1
return i == len(s)
  1. i is the progress in s. s[0..i-1] is matched inside the part of t read so far.
  2. Every letter of t is read once. j only moves forward; letters that do not match s[i] are skipped.
  3. A match is taken immediately. Using the earliest copy of s[i] leaves the longest possible rest of t for s[i+1..].
  4. Answer: s is a subsequence exactly when i reaches |s|. Stop early once it does.
O(|s| + |t|)time
O(1)extra space

Why it works: take any valid matching of s into t. If s[0] is matched to some position p but an earlier position q < p also holds s[0], move that match to q: the rest of the matching still fits after q because it fit after p. Repeat for each letter, left to right, and you get exactly the greedy matching. So if any matching exists, the greedy one does, and the greedy scan finds it.

Proof (optional)

Formally, let gk be the position greedy uses for s[k] and mk any valid matching. By induction gk ≤ mk: for k = 0 greedy takes the first copy; if gk-1 ≤ mk-1, then mk is a copy of s[k] after gk-1, and greedy takes the first such copy, so gk ≤ mk. Hence greedy never runs out of t before a valid matching would.

4. Follow-up - many queries against one t

Idea: preprocess t once into 26 sorted position lists. For a query, keep next = the first index of t still free. For each letter c of s, binary-search pos[c] for the first index ≥ next; if none, return false; else set next to that index + 1. This is exactly the greedy rule, with the scan replaced by a jump.

O(|t|)build, once
O(|s| log |t|)per query
O(|t|)memory

Alternative: a next-occurrence table nxt[j][c] (first index ≥ j holding c), built right to left in O(26·|t|). Queries become O(|s|) with no log, for 26× the memory. With |t| = 104 both fit easily; say which one you pick and why.
