Approaches: brute -> better -> optimal

Hint 1

If you have used i characters of s1 and j characters of s2, which character of s3 must come next?

Hint 2

Draw a grid with s1 down the side and s2 across the top. A move down consumes from s1, a move right from s2. What path are you looking for?

1. Brute force - try both choices recursively

Idea: go(i, j): if i + j == len(s3) return true; try taking s1[i] if it equals s3[i + j], and taking s2[j] if it equals s3[i + j].

O(2^(m+n))time
O(m + n)stack

What is wasted: many different choice sequences reach the same (i, j), and each one re-solves it. For s1 = s2 = "aaaa...", every path is explored.

2. Better - memoise (i, j)

The result of go(i, j) depends only on (i, j), so cache it. There are (m + 1)(n + 1) states, each doing O(1) work.

O(m × n)time
O(m × n)memo + stack

3. Optimal - bottom-up table, then one row

Let dp[i][j] = "s1[0..i) and s2[0..j) can interleave into s3[0..i+j)". Then:

  • dp[0][0] = true
  • dp[i][j] = (dp[i-1][j] and s1[i-1] == s3[i+j-1]) or (dp[i][j-1] and s2[j-1] == s3[i+j-1])
  • Answer: dp[m][n], but first return false if m + n != len(s3).

Why it works: in any valid interleaving of the prefixes, the last character of s3[0..i+j) came either from s1 (it is s1[i-1], and the rest is a valid interleaving of s1[0..i-1) with s2[0..j)) or from s2 (symmetrically). The recurrence checks exactly these two cases, so dp is true iff an interleaving exists. The length check is needed because the grid only ever looks at s3[0..m+n).

One row (the follow-up): row i only reads row i - 1 (straight up) and the current row (left). Keep one array ok[0..n]: before updating, ok[j] still holds the value from the row above, and ok[j-1] already holds the current row. Swap s1 and s2 first if you want O(min(m, n)).

O(m × n)time
O(n)space (one row)

BFS view (from a top community solution): the grid is a graph; search for a path from (0, 0) to (m, n). Same worst case, but it often stops early because only reachable cells are expanded.
