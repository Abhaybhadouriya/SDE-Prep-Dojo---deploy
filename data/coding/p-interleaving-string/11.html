Interview follow-ups

Reduce memory to O(min(m, n)).

Swap s1 and s2 so the shorter one is s2 (the columns), then use the single row. The answer is symmetric in s1 and s2.

Return one actual interleaving (which character came from where).

Keep the full 2-D table, then walk back from (m, n): if the cell above is true and s1[i-1] == s3[i+j-1], that character came from s1; otherwise from s2. Reverse the recorded choices. O(mn) memory is needed for the walk back.

Count the number of distinct ways to interleave.

Replace OR with addition: ways[i][j] = (match_up ? ways[i-1][j] : 0) + (match_left ? ways[i][j-1] : 0), modulo if large. Each grid path is one way of assigning every character of s3 to s1 or s2, so this counts assignments, not distinct pairs of piece lists.

Three source strings instead of two.

State (i, j, k) with the s4 position implied as i + j + k; three incoming moves per cell. O(n1 n2 n3) time, O(n2 n3) memory with a rolling layer.

Solve it as a graph search.

Nodes are (i, j); edges go down or right when the character matches s3[i + j]. BFS or DFS with a visited set from (0, 0); return true on reaching (m, n). Same O(mn) bound, often faster in practice.

Why does memoised recursion not need the third index either?

Same reason: the recursion signature go(i, j) fully determines the remaining subproblem because the s3 position is i + j.
