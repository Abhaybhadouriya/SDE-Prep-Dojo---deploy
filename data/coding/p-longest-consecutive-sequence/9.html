  • Cue: unsorted values + "consecutive" + O(n) required -> hash set membership.
  • Insight: start walking only where x-1 is missing; each run is walked once.
  • State: seen (set of values), best; per start: y walks x+1, x+2, ...
  • Trap: loop over the set, not the array (duplicate starts); empty -> 0.
  • Cost: O(n) expected time, O(n) space; sorting O(n log n).
seen = set(items)
for x in seen:
    if is_start(x, seen):          # canonical element only
        y = walk_from(x, seen)     # amortised: each item visited once
        best = max(best, y - x)

When do you start walking x, x+1, x+2, ...?

  1. for every x
  2. only when x - 1 is NOT in the set
  3. only for the smallest x
  4. when x + 1 is in the set
Only run starts walk, so every value is visited at most twice in total: O(n).

Why loop over the set and not the input array?

  1. it is sorted
  2. duplicates in the array would start the same long run many times
  3. the array may be empty
  4. sets are faster to index
[1, 1, 1, ..., 2, 3, ...] with many copies of a start would make the array loop O(n²).
