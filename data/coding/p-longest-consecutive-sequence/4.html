Approaches: brute → better → optimal

Hint 1

Sorting gives O(n log n). What data structure lets you ask "is x+1 present?" in O(1) without sorting?

Hint 2

With a set, walking up from every number can cost O(n²) on [1..n]. From which numbers is it pointless to start walking?

1. Brute force - walk up from every value, search the array

Idea: for each x, check whether x+1, x+2, ... appear by scanning the whole array each time.

O(n³)time (n starts · n steps · n scan)
O(1)space

What is wasted: the scan for membership. -> rung 2 removes order from the problem by sorting.

2. Better - sort, then one pass

Idea: after sorting, a run is a stretch where each value is the previous + 1. Skip equal neighbours (duplicates), reset the counter on a gap.

nums.sort(); best = cur = 1 if nums else 0
for a, b in zip(nums, nums[1:]):
    if b == a: continue
    cur = cur + 1 if b == a + 1 else 1; best = max(best, cur)
O(n log n)time
O(1)-O(n)space (sort)

What is wasted: sorting orders every value, but we only need to know whether x+1 exists. That is a membership question. -> rung 3.

3. Optimal - hash set, walk only from run starts

seen = set(nums)
for x in seen:
    if x - 1 not in seen:                  # x starts a run
        y = x + 1
        while y in seen: y += 1
        best = max(best, y - x)
  1. Build a set. O(n); duplicates disappear, membership is O(1) on average.
  2. Find the starts. x is the first value of its run exactly when x-1 is not in the set.
  3. Walk each run once. From a start, step to x+1, x+2, ... while present. The run is [x, y-1], length y-x.
  4. Skip everything else. A non-start is inside a run that is (or will be) walked from its start.
O(n)time (average, hashing)
O(n)space

Why it works: the runs split the distinct values into disjoint blocks. Each block has one start, and the inner while loop moves only inside the block of that start. So the inner loop runs at most (number of distinct values) times in total over the whole outer loop, not per value: an amortised O(n).

Alternative: union-find or a boundary map (optional)

Union x with x+1 whenever both exist and track component sizes: O(n · α(n)). Or keep a map from each run's two end values to the run length and merge when a new value touches a run (the second most-voted community answer): one pass, O(n). Both are valid and good to mention; the set walk is the easiest to get right.
