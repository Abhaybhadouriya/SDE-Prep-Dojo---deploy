Common mistakes

Walking from every value. Without the x - 1 not in seen check, the input 1..105 walks 105 + (105-1) + ... steps: O(n²), a time-out.

Looping over nums instead of the set. If the start value of a long run appears many times, each copy re-walks the whole run. With 50,000 copies of 1 and the run 1..50,000 that is about 2.5·109 steps. Loop over the set (each value once).

Sorting version: duplicates reset the counter. In [1, 2, 2, 3], treating the second 2 as a "gap" gives 2 instead of 3. Skip equal neighbours before comparing.

Calling it O(n) worst case. Hash sets are O(1) on average; adversarial inputs can degrade them. Say "O(n) expected"; sorting is the guaranteed O(n log n) fallback.
