Common mistakes

One plain window for "exactly". Shrinking while sum > goal and counting when sum == goal undercounts as soon as zeros sit just after left: on [0,0,1], goal 1 it finds 1 of the 3 subarrays.

No guard for atMost(-1). With goal = 0 the second call gets S = -1; the shrink loop then runs past right (sum 0 > -1 forever). Return 0 for a negative limit.

Counting 1 per step instead of right - left + 1. In an "at most" window, every start from left to right is valid for this end.

Prefix version: forgetting seen[0] = 1, or indexing seen[run - goal] when run < goal. With an array instead of a map, guard the negative index.
