  • Cue: count subarrays with exactly k (ones, odds, distinct) -> atMost(k) - atMost(k - 1).
  • Insight: "≤ k" starts form a suffix [left..right] a window can track; "= k" is the band between two such edges.
  • State: left, window sum, count += right - left + 1.
  • Trap: atMost(-1) = 0; add the whole range, not 1; one window alone undercounts with zeros.
  • Cost: O(n) time, O(1) space; prefix count map O(n) space also fine.
def at_most(S):
    if S < 0: return 0
    left = s = cnt = 0
    for right, x in enumerate(nums):
        s += x
        while s > S: s -= nums[left]; left += 1
        cnt += right - left + 1
    return cnt
return at_most(goal) - at_most(goal - 1)

Quick quiz

What does atMost(S) add for each right end?

  1. 1 if the sum is S
  2. The window sum
  3. right - left
  4. right - left + 1: every start in [left..right]
Removing elements from the left of a valid window keeps it valid (no negatives), so all those starts work.

nums = [0,0,0], goal = 0. What are atMost(0) and atMost(-1)?

  1. 3 and 0
  2. 6 and 0
  3. 6 and 6
  4. 3 and 3
All 6 subarrays have sum 0; nothing has a negative sum. Answer 6.

The array may now contain -1. Which approach still works?

  1. Prefix sums + count map
  2. atMost - atMost windows
  3. Both
  4. Neither
Negatives break the monotonic window; the prefix map does not care about signs (LC 560).
