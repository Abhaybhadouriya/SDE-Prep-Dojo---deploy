Interview follow-ups

You wrote the prefix-sum map. Can you do it in O(1) extra space?

Yes: atMost(goal) - atMost(goal - 1) with two forward-only windows. It needs values ≥ 0 (true here), so that "sum ≤ S" is monotonic in the window.

How to answer

Say why the window is safe here (no negatives) and what the subtraction counts.

Likely follow-ups
  • Do it in one pass: track both left edges in the same loop.
Do it in a single pass.

Keep the left edge l of the "sum ≤ goal" window and a second edge m that is pushed right past leading zeros while the window still sums to goal. For each end with sum = goal, the starts l..m are valid: add m - l + 1. Equivalent: count the zeros right after l. Same O(n), one loop, but more state to get wrong; the two-call version is the safer interview code.

How to answer

Describe the band [l..m] and how each edge moves; then say you would still code the two-call version unless asked.

Likely follow-ups
  • Edge case goal = 0 in the one-pass version: windows of only zeros.
Count subarrays with exactly k odd numbers.

Map each value to x % 2 (in Python; in C++/Java use x & 1 to avoid negative remainders) and run the same code. This is LC 1248.

How to answer

Show the reduction to this problem in one line.

Likely follow-ups
  • Exactly k distinct values instead? Count array + distinct counter (LC 992).
The values are now any non-negative integers, not just 0/1. Does the window still work?

Yes: atMost(S) only needs "adding never lowers the sum", which holds for non-negative values. exactly(goal) = atMost(goal) - atMost(goal - 1) still holds for integer sums. The prefix map also still works. Only negatives break the window.

How to answer

Name the exact property used (non-negative), not "binary".

Likely follow-ups
  • Count subarrays with sum in [lo, hi]: atMost(hi) - atMost(lo - 1).
Can the count overflow?

At most n(n+1)/2 = 3·104 x (3·104 + 1) / 2 ≈ 4.5·108 subarrays, below 231: int32 is fine. With n = 105 it would be 5·109: use 64-bit.

How to answer

Compute the bound out loud.

Likely follow-ups
  • In atMost(goal) - atMost(goal - 1), both terms are bounded the same way.
