Interview follow-ups

Prove your code produces no invalid string and misses none.

Invariant: every built prefix has close ≤ open ≤ n. Leaves have length 2n, so open = close = n, and every prefix had close ≤ open: valid. Any valid string satisfies the same inequalities on every prefix, so each of its characters passes the two rules and the recursion follows it to a leaf. Different paths give different strings, so no duplicates.

How to answer

State the invariant first, then the two directions (sound and complete).

Likely follow-ups
  • Why is there no dead end? (Any such prefix can be closed out.)
What is the exact time complexity?

The number of answers is the Catalan number C(n) ≈ 4^n / (n^1.5 √π). Each costs O(n) to copy, and since there are no dead ends the internal nodes are at most 2n per leaf path, so the total is O(n · C(n)) = O(4^n / √n). Space besides the output is O(n).

How to answer

Say "output-sensitive" and give the Catalan count, not 2^(2n).

Likely follow-ups
  • Derive C(n) from the "first group + rest" split: C(n) = Σ C(k) · C(n-1-k).
Only return how many strings there are, for n up to 10^5 (mod 10^9+7).

Do not generate. Use C(n) = (2n)! / ((n+1)! n!) with precomputed factorials and modular inverses: O(n) precomputation, O(1) per query. Or the DP C(i) = Σ C(k) C(i-1-k) in O(n^2) for small n.

How to answer

Recognise that counting changes the problem from enumeration to combinatorics.

Likely follow-ups
  • Where else do Catalan numbers show up? (Unique BSTs, triangulations, Dyck paths.)
Three bracket types: (), [], {}. Generate all valid strings with n pairs in total.

Counts no longer say which bracket to close, so keep a stack of open types. Moves: push any of the three openers while opened < n; or pop and append the matching closer if the stack is non-empty. Output size is C(n) · 3^n.

How to answer

Point out that the counter was a compressed stack; with several types you need the real stack.

Likely follow-ups
  • Undoing a pop: push the type back after the recursive call.
Return the k-th string in sorted order without generating the others.

Count completions: ways(len, bal) = number of ways to finish from a prefix with remaining length and balance (a small DP). At each position, if placing '(' is legal and its completion count ≥ k, place '('; otherwise subtract that count from k and place ')'. O(n^2) DP plus O(n) walk.

How to answer

Same "count, then skip whole subtrees" trick as k-th permutation.

Likely follow-ups
  • Iterate to the next string in place (next-permutation style) instead.
