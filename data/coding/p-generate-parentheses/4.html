Approaches: brute -> better -> optimal

Hint 1

At each position you have only two choices. Which of them can be illegal, and when?

Hint 2

Track how many '(' and ')' you have placed so far. A ')' is safe only while it has a partner to close.

1. Brute force - every string, then filter

Idea: generate all 2^(2n) strings of '(' and ')' (recursion or a bitmask from 0 to 4^n - 1) and keep the ones that pass a balance check.

O(4^n · n)time (4^n strings, O(n) check each)
O(n)extra, besides output

What is wasted: almost everything. At n = 8 about 98% of the strings are invalid, and most of them were already doomed after their first character (any string starting with ')').

2. Better - backtrack with a balance check on each prefix

Idea: build left to right; after each character compute the balance and stop when it goes negative or exceeds the characters left. This prunes early, but the check is still "try, then test".

What is wasted: nothing big, but rung 3 says the same thing more simply with two counters and no test after the fact.

3. Optimal - backtrack with open/close counters

  1. State: the current buffer, open = '(' used, close = ')' used.
  2. Choice 1: if open < n, append '(' and recurse with open + 1.
  3. Choice 2: if close < open, append ')' and recurse with close + 1.
  4. Leaf: when the buffer length is 2n, record it. Undo the last character after each recursive call (one shared buffer, no string copies on the way down).
O(4^n / √n)time (C(n) answers × O(n) to copy each)
O(n)buffer + recursion depth, besides output

Why it works (no wrong answers, none missed): every prefix we build satisfies close ≤ open ≤ n, and such a prefix can always be completed (add the missing ')' after any remaining '('), so no branch is a dead end and every leaf, which has open = close = n, is well-formed. Conversely, any well-formed string has close ≤ open ≤ n on every prefix, so each of its characters was allowed at its step: the recursion reaches it. Distinct paths spell distinct strings, so there are no duplicates. The output is in lexicographic order because '(' is tried first and '(' < ')'.

How many answers? (optional)

The count is the n-th Catalan number C(n) = (2n)! / ((n+1)! n!) = 1, 2, 5, 14, 42, 132, 429, 1430 for n = 1..8, which grows like 4^n / (n^1.5 √π). Each answer costs O(n) to copy out, so the total is O(4^n / √n). The tree has at most 2n levels and no dead ends, so the internal nodes are bounded by 2n times the leaves.

4. Alternative - build from smaller answers (closure number)

def gen(n):                       # every valid string is "(" + A + ")" + B
    if n == 0: return [""]
    return ["(" + a + ")" + b
            for k in range(n)     # A has k pairs, B has n-1-k pairs
            for a in gen(k) for b in gen(n - 1 - k)]

Split each string at the ')' that closes its first '('. The part inside has k pairs, the part after has n-1-k. Same output size; with memoisation it reuses smaller lists. Mention it as the "Catalan recurrence" view; code the counter version.
