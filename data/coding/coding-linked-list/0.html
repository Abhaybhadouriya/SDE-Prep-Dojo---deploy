The story: a treasure hunt of notes

Explain like I'm 5

Your teacher hides a treasure hunt in the school. The first note is in your hand. It says "a toy car" and "next note: under the red chair". Under the red chair you find "a crayon" and "next note: behind the door". The last note says "a sticker" and "next note: none, you are done". You cannot jump straight to the fifth note, because only the fourth note knows where the fifth one is. But adding a new note in the middle is easy: write a new card, point it at the old next place, and change one line on the note before it.

That is a linked list. Each note is a node. It holds a value and the address of the next node, called the next pointer. The note in your hand is the head. "None, you are done" is the null pointer that ends the list.

Interviewers like linked lists because the code is short but every line moves a pointer, and one wrong order loses half the list. They are not testing whether you know what a list is. They are testing whether you can rewire pointers calmly, handle the empty list and the one-node list, and explain why your loop stops.

From your world

You have used struct list_head from <linux/list.h> for years. Two habits from there carry straight into interviews. First, the kernel list has a sentinel head that is never a real entry, so insert and delete never special-case "empty" or "first". That is exactly the dummy head trick below. Second, list_for_each_entry_safe exists because deleting the current entry destroys its next; you save next before you touch the node. That is the first line of every reversal. The one difference: interview lists are usually singly linked, with plain next fields inside the node rather than an embedded list_head plus container_of.
