Interview questions and answers

Reverse a singly linked list. Iterative and recursive, and which would you ship?

Iterative: prev = null, curr = head; loop: save next, flip, advance both; return prev. O(n) time, O(1) space. Recursive: reverse the rest, then head.next.next = head; head.next = null; return the new head from the bottom of the recursion. Same time, O(n) stack.

How to answer

Write the iterative version, state the invariant (prefix reversed at prev, suffix untouched at curr), dry-run on 1-2-3, then mention the recursive one and say you would ship the iterative one because a long list can overflow the call stack.

Likely follow-ups
  • Reverse only positions left..right? (dummy, walk to the node before left, reverse right-left+1 nodes, stitch both ends)
  • Reverse in groups of k? (find the k-th node first; if missing, stop; reverse the block with prev starting at the block's next)
Detect a cycle and return the node where it begins, in O(1) memory.

Floyd. Phase 1: slow moves 1, fast moves 2; if fast hits null there is no cycle; otherwise they meet inside the loop. Phase 2: one pointer from the head, one from the meeting point, both at speed 1; they meet at the cycle start. Proof: slow walked a + b, fast 2(a + b) = a + b + kL, so a = (k-1)L + c.

How to answer

Give the hash-set idea first (O(n) memory), then Floyd. Draw the a / b / c picture before writing the equation; interviewers care more that you can justify phase 2 than that you remember it.

Likely follow-ups
  • Length of the loop? (after meeting, keep one pointer still and count steps until the other returns)
  • Why can't fast skip over slow? (inside the loop the gap shrinks by exactly 1 per step, so it reaches 0)
Remove the n-th node from the end in one pass.

Dummy in front; fast and slow at the dummy; move fast n steps; then move both until fast.next is null. Now slow is just before the victim: slow.next = slow.next.next. Return dummy.next. The dummy handles n = length (removing the head).

How to answer

Say "two passes would be: count, then walk length-n; one pass keeps a fixed gap". Dry-run on [1,2] with n = 2 to show the head case works.

Likely follow-ups
  • Swap the k-th from the start with the k-th from the end? (same gap trick to find both, then swap values or relink, LeetCode 1721)
Check whether a linked list is a palindrome in O(1) extra space.

Find the middle with fast/slow, reverse the second half in place, walk both halves together comparing values, then reverse the second half back to restore the input. O(n) time, O(1) space.

How to answer

Mention the stack or array approach (O(n) space) first, then the in-place one. Point out the restore step without being asked; it shows you think about callers.

Likely follow-ups
  • What if the list is shared with another thread? (in-place reversal is unsafe; use the O(n) copy or lock)
Deep-copy a list with random pointers. Can you avoid the hash map?

Hash map: original -> copy, two passes, O(n) space. Without it: weave each copy right after its original, set copy.random = orig.random ? orig.random.next : null, then unweave by restoring orig.next = copy.next and copy.next = copy.next ? copy.next.next : null.

How to answer

Start with the map because it is obviously correct. When asked for O(1), explain that the woven list is the map: the copy of X is X.next. Draw A, A', B, B'.

Likely follow-ups
  • Clone a general graph? (BFS or DFS with a map from original to clone; the weave trick needs a single next chain)
  • Is the weave version thread-safe for readers of the original? (no: the original is temporarily modified)
Reverse nodes in k-groups. Walk me through the pointer updates.

Dummy; groupPrev = dummy. Loop: walk k nodes from groupPrev to find kth; if null, stop. groupNext = kth.next. Reverse from groupPrev.next up to groupNext with prev = groupNext. Then first = groupPrev.next; groupPrev.next = kth; groupPrev = first. O(n) time, O(1) space.

How to answer

Name your four anchors (groupPrev, kth, groupNext, first) before coding. Draw two blocks of 3 and show the arrows after one block. Mention that the short tail block stays as it is.

Likely follow-ups
  • Reverse the short last block too? (drop the "fewer than k: stop" check and reverse whatever is left)
  • Recursive version? (reverse first k, recurse on the rest, attach; O(n/k) stack)
Find where two lists intersect without extra memory.

Two pointers, one per head. Each walks its list; when it falls off the end, it jumps to the other list's head. Both walk a + c + b nodes in total (a and b are the unique parts, c the shared tail), so they arrive at the intersection at the same step, or both reach null together if there is none.

How to answer

Mention the length-difference version (count both lengths, advance the longer by the difference) and then the switch-heads version. Compare nodes, not values.

Likely follow-ups
  • What if the lists may contain cycles? (detect each cycle start with Floyd first; the cases split by whether they share the loop)
Sort a linked list in O(n log n) time. Why merge sort and not quicksort?

Merge sort fits lists: splitting needs only fast/slow (no random access) and merging is a splice with O(1) extra memory. Recursion uses O(log n) stack; a bottom-up version merging runs of size 1, 2, 4, ... uses O(1). Quicksort's partition needs random access to pick good pivots and has an O(n^2) worst case.

How to answer

State the split rule precisely (first middle on even lengths, cut the first half's tail) because that is where bugs hide.

Likely follow-ups
  • Merge k sorted lists? (min-heap of front nodes, O(N log k); or pairwise merge rounds)
