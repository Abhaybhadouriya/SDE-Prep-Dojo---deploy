Common mistakes

  • Losing the rest of the list. Writing curr.next = prev before saving curr.next. The fix is always the same first line: next = curr.next.
  • Returning the wrong head. After reversal the head is prev, not curr (which is null) and not the old head (which is now the tail). With a dummy, return dummy.next, never the saved old head.
  • Null dereference in the fast loop. Checking only fast.next, or checking them in the wrong order, crashes on an empty or even-length list.
  • Off-by-one in the gap. For "remove the n-th from the end" you need the node before the victim. Starting both pointers at the dummy and moving fast exactly n steps gives that; starting at the head does not handle n = length.
  • Wrong middle for splitting. For merge sort you need the first middle on even lengths; with the second middle, a two-node list splits into two and zero nodes and recursion never ends.
  • Forgetting to cut. Not setting the first half's tail to null after a split.
  • Comparing values instead of nodes in intersection or cycle checks.
  • Leaving the input modified when the problem (or the interviewer) expects it unchanged, for example in Palindrome Linked List. Reverse the second half back before returning, or at least say you would.
  • Copying values into an array when the question asked for O(1) space. It works, but the interviewer will ask for the in-place version anyway.
