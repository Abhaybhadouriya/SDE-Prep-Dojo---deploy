Move 5: deep copy with random pointers

In Copy List with Random Pointer (138) every node has next and also random, which may point at any node or at null. You must build a completely new list where the copies point only at copies. The hard part: when you create the copy of node A, the copy of A.random may not exist yet.

The simple answer is a hash map from original to copy: one pass creates all copies, a second pass sets copy.next = map[orig.next] and copy.random = map[orig.random]. That is O(n) time and O(n) extra memory, and in an interview it is a perfectly good first answer. The follow-up is always "can you do it in O(1) extra memory?" The trick is to store the map inside the list itself.

The same "map original to copy" idea clones graphs (BFS with a map) and binary trees with random pointers (1485). Flatten a Multilevel Doubly Linked List (430) is the other common "rich node" question: each node may have a child list, and you splice the child list in between the node and its next, either with recursion or with an explicit stack of the saved next pointers. In a doubly linked list remember to fix both next and prev on every splice and to clear the child pointer.

From your world

The LRU cache question (146) is the kernel's page LRU in miniature: a doubly linked list ordered by recency, plus a hash map from key to node so you can unlink any node in O(1) and move it to the front. It is the one place interviewers expect a doubly linked list with dummy head and dummy tail, the same shape as list_head. Its write-up lives with the design problems, but the list half is exactly the moves on this page.
