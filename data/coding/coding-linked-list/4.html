Move 3: in-place reversal with three pointers

To reverse a list you flip every next pointer. The danger is that flipping curr.next destroys the only path to the rest of the list. So every iteration does four things in a fixed order: save next, flip curr.next to prev, move prev up, move curr up.

  1. Start: prev = null, curr = head. Nothing flipped yet.
  2. Save next (2), point 1 back at null, then prev = 1, curr = 2. The list is now two pieces: the reversed part starting at prev and the untouched rest starting at curr.
  3. Save next (3), point 2 back at 1, step forward. Reversed part: 2 -> 1.
  4. Save next (4), point 3 back at 2, step forward. Reversed part: 3 -> 2 -> 1.
  5. Flip 4, step forward: curr is null, so the loop stops. prev holds 4, the new head.

The loop behind the steps. Invariant: prev is the head of the already reversed part and curr the head of the rest; save curr.next before you overwrite it. Lifted unchanged from the tested templates below.

// Reverse the whole list with three pointers. O(n) time, O(1) space.
ListNode* reverseList(ListNode* head) {
    ListNode* prev = nullptr;
    ListNode* curr = head;
    while (curr) {
        ListNode* next = curr->next;  // 1. save the rest of the list
        curr->next = prev;            // 2. flip one arrow
        prev = curr;                  // 3. step both pointers forward
        curr = next;
    }
    return prev;                      // prev is the new head
}
def reverse_list(head: Optional[ListNode]) -> Optional[ListNode]:
    prev, curr = None, head
    while curr:
        nxt = curr.next        # 1. save the rest of the list
        curr.next = prev       # 2. flip one arrow
        prev, curr = curr, nxt # 3. step both pointers forward
    return prev                # new head

The invariant is the thing to say out loud: "everything before curr is already reversed and starts at prev; everything from curr on is untouched." The loop keeps it true and ends when the untouched part is empty. Time O(n), memory O(1). The recursive version is shorter but uses O(n) stack, which matters on a list of 100,000 nodes; say so if you write it.

Reversing a sub-range and k-groups

Harder reversal questions reverse only part of the list: positions left..right (LeetCode 92), pairs (24), or every block of k nodes (25, a very common Hard). They all use the same three-pointer loop on a block, plus two extra pointers that remember the node before the block and the node after it, so the reversed block can be stitched back.

Starting prev at groupNext instead of null is the neat part: when the block is reversed, its new tail already points at the rest of the list, so there is no separate "reconnect the tail" step.
