Pointer-safety habits (from kernel code)

  1. Save before you sever. Before writing x.next = ..., ask "do I still need the old x.next?" If yes, store it first. This is the _safe iterator rule.
  2. Check before you dereference. Write the guard in left-to-right order: fast && fast->next. Every a.next.next needs both a and a.next to be non-null.
  3. One sentinel, no special cases. A dummy (like the kernel's list head) is cheaper to reason about than an if (prev == NULL) branch you must test separately.
  4. Terminate what you cut. When you split a list, the last node of the first part must get next = null, or you have a list that secretly continues (or loops).
  5. Compare nodes by identity, not value. Intersection and cycle questions compare pointers (== in C++/Java/Go, is in Python). Two different nodes may hold the same value.
  6. Know who owns memory. In C++, deleting a removed node is polite but not required on LeetCode; say which you chose. Never touch a node after delete, the classic use-after-free.
  7. Dry-run the small cases. Empty list, one node, two nodes, and the case where the change hits the head or the tail. Most wrong answers fail on one of these four.
