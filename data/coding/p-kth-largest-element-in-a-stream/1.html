The problem (in our words)

Design a class that reports the kth largest value of a stream of integers after each new value. "kth largest" counts duplicates (it is the kth element of the values sorted in descending order, not the kth distinct value).

  • KthLargest(int k, int[] nums) sets up the object with k and the values already in the stream.
  • int add(int val) appends val to the stream and returns the current kth largest value.

Constraints:

  • 0 <= nums.length <= 104
  • 1 <= k <= nums.length + 1
  • -104 <= nums[i], val <= 104
  • At most 104 calls to add.
  • There are always at least k values in the stream when the kth largest is asked for.

Practice it: LeetCode 703 · GfG Kth Largest in a Stream · TUF article

Constraints tell you: k can be nums.length + 1, so the start may hold only k-1 values: the first add fills the heap. Up to 2·104 values in total and 104 queries, so sorting on every add (O(n log n) each) is too slow in the worst case; O(log k) per add is the target.
