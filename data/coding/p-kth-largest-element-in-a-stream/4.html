Approaches: brute -> better -> optimal

Hint 1

Once k values are bigger than some value x, can x ever be the answer again?

Hint 2

Of the k values you keep, which one do you need to see and replace quickly?

1. Brute force - sort on every add

Idea: keep every value in a list; on each add, append, sort descending and return index k-1.

O(n log n)per add
O(n)space, grows for ever

What is wasted: we re-sort values that can never be the answer again and keep memory for all of them. -> keep the list sorted instead.

2. Better - keep a sorted list and insert in place

Idea: binary search the insert position (bisect) and read a[len-k]. Search is O(log n) but shifting the array is O(n). Trimming the list to the k largest makes it O(k) per add.

O(k)per add (shifts)
O(k)space after trimming

What is wasted: we keep the k values fully sorted, but we only ever look at the smallest of them. A heap keeps just enough order for that. -> rung 3.

3. Optimal - min-heap of the k largest

def add(self, val):
    if len(self.top) < self.k: heapq.heappush(self.top, val)
    elif val > self.top[0]:    heapq.heapreplace(self.top, val)  # drop the weakest
    return self.top[0]
  1. Invariant: the heap holds the k largest values seen so far (or all of them while fewer than k have arrived).
  2. The top is the kth largest. The heap's minimum is the smallest of the k largest, i.e. the kth in descending order.
  3. A value not bigger than the top is useless for ever: k values already beat or tie it, and values only get added, so drop it.
  4. A bigger value replaces the top (pop then push, or replace the root and sift down) and the invariant holds again.
O(log k)per add
O(n log k)constructor (or O(n) heapify)
O(k)space

Why it works: the set "k largest so far" changes only when a new value beats its smallest member, and then exactly that member leaves. A min-heap supports "look at the smallest" in O(1) and "replace the smallest" in O(log k), which is all the update needs.

The constructor can simply call add for each starting value (O(n log k)), as the top Java solution does. Python can also heapify all of nums in O(n) and pop down to k.
