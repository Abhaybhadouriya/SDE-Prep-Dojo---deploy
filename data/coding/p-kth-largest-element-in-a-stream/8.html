Common mistakes

Using a max-heap. The max is the largest, not the kth; you would need k pops per query. For the kth largest, the heap you keep is a min-heap.

Letting the heap grow to n. Pushing every value and popping only when size > k is correct but does a push+pop for values that lose immediately. Compare with the top first.

Peeking an empty heap in the constructor. When nums has k-1 values (or 0), code like if val > heap[0] without the size check crashes. Check the size first.

Picking the wrong default. Java PriorityQueue and Python heapq are min-heaps already, so adding Collections.reverseOrder() out of habit breaks them. C++ priority_queue is a max-heap by default: you need greater<int>.
