The problem (in our words)

Build a word store for a word game that supports adding words and checking whether any stored word matches a pattern. Implement the class WordDictionary:

  • WordDictionary() creates an empty store.
  • void addWord(word) stores word, so it can be matched later.
  • bool search(word) returns true if some stored word matches word, else false. The pattern may contain dots '.'; a dot matches any one letter. A match must have the same length (a stored word that only starts with the pattern does not count).

Example call sequence (LeetCode format): ["WordDictionary","addWord","addWord","addWord","search","search","search","search"] with arguments [[],["cab"],["tab"],["cap"],["dab"],["tab"],[".ab"],["ca."]] returns [null,null,null,null,false,true,true,true].

Constraints:

  • 1 <= word.length <= 25
  • word in addWord consists of lowercase English letters.
  • word in search consists of '.' or lowercase English letters.
  • There will be at most 2 dots in word for search queries.
  • At most 104 calls will be made to addWord and search.

Practice it: LeetCode 211 · warm-up: LeetCode 208 Implement Trie

Constraints tell you: up to 104 words of length 25 means scanning all words per search (2.5·105 chars) times 104 searches is too slow in the worst case. At most 2 dots bounds the wildcard fan-out to 262 = 676 branches per query: a trie DFS is safe.
