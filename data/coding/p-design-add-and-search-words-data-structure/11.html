Interview follow-ups

Searches with many dots are slow. How do you speed them up?

Bucket words by length first (a separate trie per length, or store at each node the set of word lengths below it, as a bitmask) and prune a branch when no word of the needed remaining length lies below. For all-dot patterns, answer from a "lengths present" set in O(1).

How to answer

Show the pruning check: (node.lenMask >> (L - i)) & 1.

Likely follow-ups
  • Cost? (One extra int per node, updated on insert.)
Support '*' meaning any run of letters (including none).

On '*', branch two ways: skip the star (advance in the pattern, stay at the node) or consume one letter (move to any child, stay on the star). Memoise on (node, i) to avoid exponential blow-up; the cost becomes O(nodes · L).

How to answer

Relate it to Wildcard Matching DP, run over a trie instead of one string.

Likely follow-ups
  • Memo key size? (nodes × L booleans; clear per query.)
Many threads call addWord and search concurrently.

Simplest: a read-write lock (many searches, one adder). Better for read-heavy loads: inserts only add nodes and set flags, so with atomic child-pointer publication (compare-and-swap on an empty slot) readers can run lock-free and see either the old or the new state.

How to answer

Point out that nodes are never deleted: that is what makes lock-free reads easy (RCU-style).

Likely follow-ups
  • Add deleteWord? (Then reclamation needs RCU or epochs.)
Memory is tight: 106 words.

26 pointers per node is 208 bytes on 64-bit. Use a hash map or sorted small array of children per node, or a compressed (radix) trie that merges single-child chains; or a sorted array of words with binary search for dot-free queries.

How to answer

Estimate nodes × bytes per node first, then choose.

Likely follow-ups
  • Static dictionary? (A DAWG / minimal automaton shares suffixes too.)
Return all matching words, not just true/false.

Same DFS, but do not stop at the first success; carry the path (or store the word at its end node) and collect every end node reached at depth L. Output-sensitive cost: O(26d·L + output).

How to answer

Mention storing the full word at the end node to avoid rebuilding it.

Likely follow-ups
  • Top-k by frequency? (Keep counts at end nodes and a heap.)
