60-second recall

  • Cue: store words, query with single-letter wildcards -> trie + DFS.
  • Insight: letters follow one edge; '.' tries every child; stop on the first true.
  • State: node, index i into the pattern (no substring copies).
  • Trap: at the end return node.end, not "exists"; do not return early on the first child.
  • Cost: add O(L); search O(26dots·L); space O(total chars).
def match(n, i):
    if i == len(p): return n.end
    if p[i] != '.':
        c = n.kids.get(p[i]); return c is not None and match(c, i+1)
    return any(match(c, i+1) for c in n.kids.values())

With words cab, tab, cap stored, search("ca") returns:

  1. true, because the path exists
  2. an error
  3. false, because ca is not a word end
  4. true, because cab starts with ca
Only nodes with the end flag are words.

Why does the problem limit search patterns to 2 dots?

  1. To keep add O(1)
  2. Each dot multiplies the branches by up to 26
  3. Tries cannot store dots
  4. To avoid recursion
26² = 676 paths is cheap; an all-dot pattern would visit the whole trie.

What does the DFS do when a branch under a dot fails?

  1. It returns to that dot and tries the next child
  2. It returns false immediately
  3. It restarts from the root
  4. It deletes the branch
Backtracking: the loop over children continues.
