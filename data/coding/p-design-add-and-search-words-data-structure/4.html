Approaches: brute -> better -> optimal

Hint 1

Without dots, which data structure answers "is this exact word stored?" in O(L)?

Hint 2

In a trie, what is the set of nodes a . could lead to from the current node?

1. Brute force - a list of words, compare each one

Idea: keep every word in a list. For a search, check each stored word of the same length position by position, treating . as a match.

def search(p):
    return any(len(w) == len(p) and all(a == '.' or a == b for a, b in zip(p, w))
               for w in self.words)
O(N·L)per search
O(1)per add

What is wasted: "cab" and "cap" are compared from scratch for every query, though they share "ca", and words starting with other letters are scanned even when the pattern starts with a letter. -> rung 2.

2. Better - group words by length, or a hash set for dot-free queries

Idea: a hash set answers dot-free queries in O(L). For patterns with dots, scan only the bucket of words with the same length (map length -> list).

O(L)no dots
O(Nlen·L)with dots

What is wasted: with dots it is still a scan, and many interview tests put all words in one length. The fixed letters of the pattern are not used to cut the search. -> rung 3.

3. Optimal - trie + DFS that branches only on .

def match(node, i):
    if i == len(p): return node.end
    if p[i] != '.': return p[i] in node.kids and match(node.kids[p[i]], i + 1)
    return any(match(c, i + 1) for c in node.kids.values())
  1. addWord is a plain trie insert. Walk or create one node per letter, mark the last node as a word end. O(L).
  2. A letter follows one edge. If the edge is missing, this branch fails at once.
  3. A dot tries every existing child and returns true at the first child that matches the rest. This is backtracking: a failed branch unwinds to the last dot.
  4. The end flag decides. When the pattern is used up, answer node.end, not "the node exists": prefixes are not words.
O(L)add
O(26d·L)search, d = dots ≤ 2
O(total chars)space

Why it works: each trie node at depth i corresponds to one distinct prefix of length i of the stored words. A stored word matches the pattern exactly when there is a root-to-end-node path of length L whose i-th edge equals p[i] wherever p[i] is a letter. The DFS explores exactly the paths consistent with the letters so far, so it finds such a path if one exists, and it never reports a path that ends on a non-end node.

Cost detail (optional)

Without dots the walk is a single path. Each dot multiplies the number of live paths by at most 26 (in practice by the real number of children, often far less). With at most 2 dots, the worst case is 676 paths of length ≤ 25, about 1.7·104 node visits per query, and 104 queries stay well under 109. Space: at most 26 pointers per node, one node per stored character.
