60-second recall

  • Cue: all unique quadruplets with a sum -> 3Sum plus one loop.
  • Insight: sorted range: the sign of the pair sum discards one value per step.
  • State: i, j fixed; lo, hi move; skip repeats per slot.
  • Trap: 64-bit sums; j > i+1; continue vs break when pruning.
  • Cost: O(n³) time, O(1) extra space; k-Sum is O(nk-1).
nums.sort()
for i in range(n - 3):
    if i and nums[i] == nums[i-1]: continue
    for j in range(i + 1, n - 2):
        if j > i + 1 and nums[j] == nums[j-1]: continue
        lo, hi, need = j + 1, n - 1, target - nums[i] - nums[j]
        while lo < hi: move by sign; on match record, lo++, hi--, skip equal

Pruning on i (array sorted): in case A even the smallest sum using i is above target; in case B even the largest sum using i is below target. What do you do?

  1. A: break, B: continue
  2. A: continue, B: break
  3. Break in both cases
  4. Continue in both cases
A larger i only raises the smallest sum, so stop. A larger i may still raise the largest sum enough, so move on to the next i.

Values can reach 10^9 in absolute value. Why add them in 64 bits?

  1. Four values of 10^9 sum to 4·10^9, which wraps in 32-bit int and can equal a target such as -294967296
  2. It is faster
  3. Only Java needs it
  4. There is no need
In C++ signed overflow is undefined; in Java it wraps silently. Use long long or long for the sums.

Skipping duplicates for j: why j > i + 1 && nums[j] == nums[j-1] and not j > 0?

  1. With j > 0 you skip j = i + 1 when nums[i + 1] == nums[i] and lose answers like [2,2,2,2] for target 8
  2. Both are the same
  3. It only prevents out-of-bounds reads
  4. It is faster
Skip a repeat only within the same slot: j's first candidate is always i + 1.
