Generalise to k-Sum.

Recursive kSum(start, k, target): base case k == 2 is the two-pointer search on [start, n); otherwise loop i from start, skip i > start && nums[i] == nums[i-1], prune with the average (nums[i] * k > target -> break, nums[n-1] * k < target -> return), and recurse with (i+1, k-1, target - nums[i]), prefixing nums[i]. O(nk-1).

How to answer

Show the base case and the prune; the rest is the same loop.

Likely follow-ups
  • Why is the average a valid pruning bound?
Only count the quadruplets (index quadruples, duplicates counted), n up to 2000.

Meet in the middle. Walk c from left to right. Before handling c, add every pair sum nums[a] + nums[c-1] with a < c-1 to a hash map, so the map holds all pairs a < b < c. Then, for each d > c, add map[target - nums[c] - nums[d]] to the count. Every quadruple a < b < c < d is counted exactly once. O(n²) time and space.

How to answer

Name LC 454 and the "pair sums in a hash map" idea; be careful that a < b < c < d.

Likely follow-ups
  • What is the memory cost of storing n²/2 sums?

Is O(n³) optimal? Can you do O(n² log n)?

For listing all unique quadruplets, the output itself can be Θ(n³) in size, so no. If only existence or a count is needed, pair sums in a hash map (or sorted pair sums with two pointers) give O(n²) to O(n² log n), with care so the two pairs do not share an index.

How to answer

Separate "list everything" from "decide/count".

Likely follow-ups
  • How do you prevent the two pairs from overlapping?
Why sort first instead of hashing everything?

Sorting gives three things at once: the two-pointer move rule (sign of the sum), the duplicate rule (equal values are adjacent, skip per slot), and pruning (bounds from the smallest and largest values). Its O(n log n) is free next to O(n³).

How to answer

List the three benefits; mention the cost is dominated.

Likely follow-ups
  • If you may not modify the input, what does sorting cost you?
