Common mistakes

32-bit sums. nums[i] + nums[j] + nums[lo] + nums[hi] in int overflows; LeetCode has a test exactly for this. Cast the first operand to long.

Skipping j with j > 0 instead of j > i + 1. For [3,3,3,3,3,3], j = 1 equals nums[0], which is i's own value in a different slot, so every j is skipped and [3,3,3,3] is lost. The skip must only compare with the previous candidate for the same slot.

Breaking instead of continuing on the "too small" prune. If i plus the three largest is too small, a larger i may still work: continue. Only the "too big" prune may break.

Copying 3Sum's if nums[i] > 0: break. With an arbitrary (possibly negative) target, a positive first value does not mean the sum is too big. Use the four-smallest check.

Skipping duplicates of lo/hi before checking the match. Skip only after recording a quadruplet; skipping earlier can jump over the partner you need.
