The problem (in our words)

You get a string s. Return the longest contiguous piece of s that reads the same forwards and backwards (a palindromic substring). If several pieces share the maximum length, returning any one of them is accepted.

Signature: String longestPalindrome(String s) (LeetCode style).

  • 1 <= s.length <= 1000
  • s contains only digits and English letters (upper and lower case; comparisons are case-sensitive).

Practice it: LeetCode 5 · GfG Longest Palindrome in a String · TUF article

Constraints tell you: n ≤ 1000 means O(n²) = 106 steps is easily fast enough and is the expected target; O(n³) (around 108 char comparisons in the worst case) is borderline and will be called out. The string is never empty, so a single character is always a valid answer.
