Approaches: brute → better → optimal

Hint 1

If s[i..j] is a palindrome, what do you know about s[i+1..j-1]?

Hint 2

Turn it around: start from a tiny palindrome (one char, or two equal chars) and try to grow it by one char on each side.

1. Brute force - check every substring

Idea: for every pair i ≤ j, test whether s[i..j] is a palindrome with two pointers, keep the longest.

O(n³)time
O(1)space

What is wasted: checking s[i..j] repeats the check of s[i+1..j-1], which we did before. -> rung 2 remembers it.

2. Better - interval DP table

State: pal[i][j] = true if s[i..j] is a palindrome.

Transition: pal[i][j] = (s[i] == s[j]) and (j - i < 2 or pal[i+1][j-1]).

Base case: every single char is a palindrome (pal[i][i] = true); a pair is one if its two chars match.

Answer: the true cell with the largest j - i. Fill by increasing length (or i from n-1 down to 0) so pal[i+1][j-1] is ready.

O(n²)time
O(n²)space

What is wasted: 106 booleans for n = 1000, and most cells are false. Each true cell only ever feeds the cell one step outward, along the same centre. -> rung 3 walks each centre directly.

3. Optimal for interviews - expand around every centre

for c in range(n):
    for lo, hi in ((c, c), (c, c + 1)):          # odd centre, even centre
        while lo >= 0 and hi < n and s[lo] == s[hi]: lo -= 1; hi += 1
        if hi - lo - 1 > best: best, start = hi - lo - 1, lo + 1
  1. 2n - 1 centres. n on a char (odd lengths) and n - 1 between chars (even lengths). Every palindrome has exactly one.
  2. Grow while the ends match. The first mismatch ends that centre: if s[lo..hi] is not a palindrome, no wider string with the same centre is.
  3. Length from the stopped pointers. The loop stops one step past each end, so the length is hi - lo - 1 and the start is lo + 1 (or c - (len - 1) / 2, which works for both kinds of centre).
O(n²)time
O(1)space

Why it works: this is the DP table read diagonal by diagonal along each centre. A palindrome of length L centred at c contains palindromes of lengths L - 2, L - 4, ... with the same centre, so growing from the middle visits exactly the true cells of that diagonal and stops at the first false one. Worst case (all chars equal) is about n²/4 comparisons; random strings stop almost at once, so it is much faster than the table in practice.

4. Name only - Manacher's algorithm, O(n)

Idea: insert separators (#a#b#a#) so every centre is odd, then reuse the mirror of a centre inside the rightmost palindrome found so far to skip comparisons. O(n) time and space.

When to use it: say its name and the "mirror inside the current right boundary" idea if asked for better than O(n²); interviews at SDE-1/2 level almost never ask you to code it (n ≤ 1000 here).
