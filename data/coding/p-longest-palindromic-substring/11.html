Why is expand-around-centre O(n²) and not O(n³)?

Each centre expands at most n/2 steps, each step O(1), and there are 2n - 1 centres: O(n²) total. We never re-check a substring from scratch; each step extends the previous palindrome by two chars.

How to answer

Name the worst case ("aaaa...") where every centre expands fully.

Likely follow-ups
  • What is the best case? (All distinct chars: O(n).)
Can you do better than O(n²)?

Manacher's algorithm: transform to #s# form, keep the centre C and right edge R of the rightmost palindrome seen; for a new centre i < R, start its radius at min(R - i, radius[mirror]) and only expand beyond R. R only moves right, so the total work is O(n). A second route is binary search on length with rolling hashes, O(n log n), done separately for odd and even lengths.

How to answer

Give the mirror idea and the "R only moves right" argument; offer to code it only if asked.

Likely follow-ups
  • Why must odd and even lengths be binary-searched separately? (Palindromes of length L do not imply length L - 1.)

Return the longest palindromic subsequence instead (not contiguous).

Different recurrence: dp[i][j] = dp[i+1][j-1] + 2 if s[i] == s[j], else max(dp[i+1][j], dp[i][j-1]). O(n²) time, O(n) space with a rolling row. Equivalently LCS(s, reverse(s)).
