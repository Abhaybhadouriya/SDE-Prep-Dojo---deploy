Common mistakes

  • Validating against the parent only. The bound comes from all ancestors. Use (lo, hi) bounds or strictly increasing inorder.
  • Using INT_MIN as "no previous value". A tree whose smallest key is INT_MIN then fails. Use a long, a nullable, or a boolean "first" flag.
  • Allowing duplicates by accident. Compare with <= in validation unless the problem defines where equal keys go.
  • Forgetting to return the new root from recursive insert and delete. Deleting the root, or inserting into an empty tree, changes the root pointer. The recursive style root.left = delete(root.left, key) handles this for free.
  • Deleting the successor from the wrong subtree. After copying the successor's key, delete it from root.right, not from root (that would find the node you just overwrote).
  • Recover BST: setting second only on the second dip. If the swapped keys are neighbours there is only one dip, and second stays null. Set second = cur on every dip.
  • Claiming O(log n) for a plain BST. It is O(h).
  • Kth smallest with a full inorder list when the interviewer asked for O(h + k). Stop the walk at k.
  • Closest value: comparing ints with a double target using integer math or overflowing abs(a - b) with large ints. Compute the distance in floating point or 64-bit.
