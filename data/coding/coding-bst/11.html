Remember this

Revision card

  • Cue: "Binary search tree", sorted order, kth smallest, successor, range sum, validate.
  • Insight: Whole subtrees, not just children, obey left < node < right, so inorder is sorted.
  • State: A lo/hi interval passed down, or a stack of the left spine (iterator).
  • Trap: Checking only parent-child pairs when validating; using int bounds when values hit INT_MIN/INT_MAX.
  • Cost: O(h) per operation: O(log n) only when balanced, O(n) for a chain.

More to remember

  • The rule is about whole subtrees: left subtree all smaller, right subtree all bigger. Inorder is therefore sorted.
  • Every operation is O(h): O(log n) only if balanced. Insert order decides the shape.
  • Iterator = paused inorder: a stack of the left spine; next() pops, then pushes the right child's left spine. O(1) amortized, O(h) memory.
  • Kth smallest = k calls to next(). Frequent queries: store subtree sizes.
  • Delete with two children: copy the inorder successor, delete it from the right subtree.
  • Successor without parents: every left turn is a candidate; the last one wins.
  • Recover: first = prev at the first dip, second = cur at every dip, swap.
  • Balanced build: middle of the sorted range is the root.
