How to recognise a BST question (and pick the tool)

You readToolCost
"kth smallest / largest", "in sorted order", "is it a valid BST", "minimum difference between two nodes"Inorder walk (iterator), stop earlyO(h + k) or O(n)
"design an iterator", "next() and hasNext() in O(1) average, O(h) memory"Stack of the left spineO(1) amortized
"two nodes were swapped", "fix without changing structure"Inorder with prev, first, secondO(n), O(h) or Morris O(1)
"search", "insert", "floor / ceiling", "successor", "closest value", "LCA in a BST"One downward walk from the rootO(h)
"delete a key"Three cases; successor for two childrenO(h)
"sorted array / list to BST", "make it balanced", "minimum height"Middle of the range is the rootO(n)
"two values in a BST sum to k"Two iterators (ascending and descending) as two pointersO(n), O(h) memory
"largest subtree that is a BST", "max sum BST"Postorder returning (isBST, min, max, size or sum)O(n)
"count numbers smaller after self", "kth largest in a stream with deletes"Usually not a hand-written BST: Fenwick tree, merge sort, or an ordered set (std::set, TreeMap)O(n log n)

In a real interview where you only use an ordered structure (calendar booking, stock price ranges, nearest timestamp), reach for the library: C++ std::set::lower_bound, Java TreeMap.floorKey / ceilingKey. Python has no built-in balanced BST; use bisect on a sorted list (O(n) insert, often fine) or say you would use sortedcontainers.SortedList. Go has none either; a sorted slice with sort.Search is the usual stand-in.
