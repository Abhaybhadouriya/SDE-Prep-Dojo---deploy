The one rule and its two consequences

A binary search tree (BST) is a binary tree where, for every node, all keys in its left subtree are smaller and all keys in its right subtree are larger. LeetCode's BST problems use strict inequality and no duplicates unless the statement says otherwise; if duplicates are allowed, pick a side (for example "equal goes right") and say it out loud.

Consequence 1: inorder is sorted. Inorder visits the left subtree, then the node, then the right subtree. The left subtree holds exactly the smaller keys and the right subtree the bigger ones, so by induction the output is sorted. Any question that sounds like "the kth something", "in order", "the next bigger", or "two values out of place" is an inorder question.

Consequence 2: you can search from the root. Compare the target with the node, go left or right, never come back. That is binary search where the "middle" is the current node. Insert, search, floor, ceiling, successor, closest value and lowest common ancestor are all one downward walk.

Never claim O(log n) for a plain BST. Say O(h), then add "O(log n) if it is balanced, O(n) if it degenerates". Interviewers listen for this.
