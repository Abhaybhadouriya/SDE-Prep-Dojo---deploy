Validate a BST: two correct ways, one classic wrong one

The wrong way checks only parent and child: "left child smaller, right child bigger". Root 6 with right child 9 and 9's left child 4 passes that check and is not a BST, because 4 sits in the right subtree of 6. The rule is about whole subtrees.

  1. Bounds, top-down. Carry an open interval (lo, hi) down the tree. The root gets (-inf, +inf); going left sets hi = node, going right sets lo = node. Every node must sit strictly inside its interval. Our binary trees primer has that template.
  2. Inorder, strictly increasing. Walk inorder and compare each value with the previous one. One prev variable is all the state you need. This is the version below, because it reuses the iterator.

Both are O(n) time and O(h) space. Two details sink people: use a wider type or a "no previous yet" flag (keys can be INT_MIN or INT_MAX, so a sentinel like prev = INT_MIN breaks), and compare with <= so a duplicate fails.
