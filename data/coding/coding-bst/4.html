Search, insert, delete and the inorder successor

Insert is a search that falls off the tree: walk down comparing keys and hang the new node on the null link where the search ended. It never moves existing nodes. LeetCode 701 accepts any valid BST as the answer, and this one is the simplest.

Delete has three cases, decided by how many children the node has:

Node to delete hasDo thisWhy it stays a BST
0 children (a leaf)Return null to the parent.Nothing else moves.
1 childReturn that child to the parent (splice it up).The whole child subtree was already on the correct side of the parent.
2 childrenFind the inorder successor (leftmost node of the right subtree), copy its key into this node, then delete the successor from the right subtree.The successor is the smallest key bigger than the node: it is bigger than everything on the left and smaller than everything else on the right. It has no left child, so its own delete is case 1 or 2.

Step through deleting 3, the hard case:

  1. Search: 3 < 8, so the key is in the left subtree.
  2. Found 3. It has two children, so we cannot just splice it out.
  3. Inorder successor = leftmost node of the right subtree: step to 6, then left as far as possible: 4.
  4. Copy the successor's key into the node. The tree still holds 4 twice for a moment.
  5. Delete 4 from the right subtree. The successor never has a left child, so this is the easy 0/1-child case.

Using the predecessor (rightmost node of the left subtree) is equally correct. If the interviewer cares about keeping node identity (other code holds pointers to the node), relink the successor node into the deleted node's place instead of copying the key; with a copied key, the pointer someone held to node "3" now points at a node holding 4.

Inorder successor without parent pointers

The successor of p is the smallest key bigger than p's key. Walk down from the root like a search for p: whenever p's key is smaller than the current node, the current node is a candidate (it is bigger than p) and a better candidate can only be further left, so record it and go left. Otherwise go right. The last recorded candidate is the answer. O(h), O(1) space, and it works even when p has no right subtree. With parent pointers (LeetCode 510), it is: leftmost of the right subtree if there is one, else climb until you arrive from a left child.

// insertBST walks down like a binary search and hangs the node on the null link.
func insertBST(root *TreeNode, key int) *TreeNode {
	if root == nil {
		return &TreeNode{Val: key}
	}
	if key < root.Val {
		root.Left = insertBST(root.Left, key)
	} else {
		root.Right = insertBST(root.Right, key)
	}
	return root
}

// deleteBST: 0 or 1 child -> splice the child up; 2 children -> copy the
// inorder successor (leftmost of the right subtree) here, then delete it there.
func deleteBST(root *TreeNode, key int) *TreeNode {
	if root == nil {
		return nil
	}
	switch {
	case key < root.Val:
		root.Left = deleteBST(root.Left, key)
	case key > root.Val:
		root.Right = deleteBST(root.Right, key)
	case root.Left == nil:
		return root.Right
	case root.Right == nil:
		return root.Left
	default:
		s := root.Right
		for s.Left != nil {
			s = s.Left
		}
		root.Val = s.Val
		root.Right = deleteBST(root.Right, s.Val)
	}
	return root
}

// successor of p (smallest key > p.Val), no parent pointers.
// Every time we go left, the current node is a candidate.
func successor(root, p *TreeNode) *TreeNode {
	var best *TreeNode
	for root != nil {
		if p.Val < root.Val {
			best, root = root, root.Left
		} else {
			root = root.Right
		}
	}
	return best
}
// Insert: walk down like a binary search and hang the new node on the null link.
TreeNode* insertBST(TreeNode* root, int key) {
    if (!root) return new TreeNode(key);
    if (key < root->val) root->left = insertBST(root->left, key);
    else root->right = insertBST(root->right, key);
    return root;
}

// Delete: 0 or 1 child -> splice the child up; 2 children -> copy the inorder
// successor (leftmost of the right subtree) into this node, then delete it there.
TreeNode* deleteBST(TreeNode* root, int key) {
    if (!root) return nullptr;
    if (key < root->val) { root->left = deleteBST(root->left, key); return root; }
    if (key > root->val) { root->right = deleteBST(root->right, key); return root; }
    if (!root->left || !root->right) {
        TreeNode* child = root->left ? root->left : root->right;
        delete root;
        return child;
    }
    TreeNode* s = root->right;
    while (s->left) s = s->left;
    root->val = s->val;
    root->right = deleteBST(root->right, s->val);
    return root;
}

// Inorder successor of node p (smallest key > p->val), no parent pointers.
// Every time we go left, the current node is a candidate.
TreeNode* successor(TreeNode* root, TreeNode* p) {
    TreeNode* best = nullptr;
    while (root) {
        if (p->val < root->val) { best = root; root = root->left; }
        else root = root->right;
    }
    return best;
}

static TreeNode insertBST(TreeNode root, int key) {
    if (root == null) return new TreeNode(key);
    if (key < root.val) root.left = insertBST(root.left, key);
    else root.right = insertBST(root.right, key);
    return root;
}

// Delete: 0 or 1 child -> splice the child up; 2 children -> copy the inorder
// successor (leftmost of the right subtree) into this node, then delete it there.
static TreeNode deleteBST(TreeNode root, int key) {
    if (root == null) return null;
    if (key < root.val) { root.left = deleteBST(root.left, key); return root; }
    if (key > root.val) { root.right = deleteBST(root.right, key); return root; }
    if (root.left == null) return root.right;
    if (root.right == null) return root.left;
    TreeNode s = root.right;
    while (s.left != null) s = s.left;
    root.val = s.val;
    root.right = deleteBST(root.right, s.val);
    return root;
}

// Every time we go left, the current node is a candidate.
static TreeNode successor(TreeNode root, TreeNode p) {

        else root = root.right;
    }
    return best;
}
def insert_bst(root: Optional[TreeNode], key: int) -> TreeNode:
    """Walk down like a binary search and hang the new node on the null link."""
    if not root:
        return TreeNode(key)
    if key < root.val:
        root.left = insert_bst(root.left, key)
    else:
        root.right = insert_bst(root.right, key)
    return root


def delete_bst(root: Optional[TreeNode], key: int) -> Optional[TreeNode]:
    """0 or 1 child: splice the child up. 2 children: copy the inorder successor
    (leftmost of the right subtree) into this node, then delete it there."""
    if not root:
        return None
    if key < root.val:
        root.left = delete_bst(root.left, key)
        return root
    if key > root.val:
        root.right = delete_bst(root.right, key)
        return root
    if not root.left:
        return root.right
    if not root.right:
        return root.left
    s = root.right
    while s.left:
        s = s.left
    root.val = s.val
    root.right = delete_bst(root.right, s.val)
    return root


def successor(root: Optional[TreeNode], p: TreeNode) -> Optional[TreeNode]:
    """Smallest key > p.val. Every time we go left, the current node is a candidate."""
    best = None
    while root:
        if p.val < root.val:
            best, root = root, root.left
        else:
            root = root.right
    return best

From your world

The kernel's rb_next() is the parent-pointer version: if the node has a right child, go right and then left as far as possible; otherwise climb while you are your parent's right child. It is O(1) amortized for a full walk for the same reason as our iterator. In C, the delete's "copy the key" shortcut is usually not allowed because the node is embedded inside a bigger struct (container_of), so rb_erase relinks the successor instead.
