Recover a BST where two keys were swapped

LeetCode 99: exactly two nodes had their values swapped by mistake; fix the tree without changing its shape. Think in the sorted inorder sequence. Swapping two values in a sorted list creates "dips", places where a value is bigger than the one after it:

  • If the swapped keys are far apart, there are two dips. The wrong big value is the left side of the first dip; the wrong small value is the right side of the second dip.
  • If they are neighbours in inorder, there is one dip, and both of its sides are the culprits.

One rule covers both cases: on the first dip set first = prev; on every dip set second = cur. After the walk, swap the two values. O(n) time, O(h) space with the stack. The follow-up "O(1) space" means Morris inorder traversal (threads through null right pointers; see the trees primer), with the same dip logic, and you must let Morris finish so every thread is removed.
