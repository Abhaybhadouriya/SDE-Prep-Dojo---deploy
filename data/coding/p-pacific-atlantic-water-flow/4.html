Approaches: brute -> better -> optimal

Hint 1

Which cells certainly drain into the Pacific without any search at all?

Hint 2

If water can go from A down to B, then going from B to A is a step to an equal or higher cell. Start at the cells from Hint 1 and walk that way.

1. Brute force - a search from every cell

Idea: for each cell, run a DFS that moves to neighbours with height <= the current one, and record whether it touches a Pacific edge and an Atlantic edge.

O((m·n)²)time
O(m·n)space per search

What is wasted: neighbouring cells repeat almost the same search. The answer for one cell is not reused for the next. Our tests still use this version as the reference checker on small random grids.

2. Better - memoise per cell (and why it is tricky)

Idea: cache "reaches Pacific / reaches Atlantic" for each cell. The catch: equal heights make cycles (a plateau of 5s), so a cell's answer can depend on a neighbour whose search is still running. You would need to treat each plateau as one node (strongly connected component) first. Correct but fiddly, and an interviewer will steer you away from it.

What fixes it: reverse the direction, so there is nothing to memoise. -> rung 3.

3. Optimal - two reverse floods from the oceans

pacific  = climb(top row + left column)
atlantic = climb(bottom row + right column)
return [cell for cell in grid if pacific[cell] and atlantic[cell]]
# climb: multi-source BFS; step to a neighbour only if it is >= the current height
  1. The border is the seed. Every top-row and left-column cell drains into the Pacific with no move at all; push all of them at once (multi-source BFS).
  2. Walk uphill, not downhill. From cell u, enter neighbour v only if heights[v] >= heights[u]: then rain on v can flow to u, and from u to the ocean.
  3. One visited grid per ocean. A cell is pushed at most once per flood, so each flood is O(m·n).
  4. Answer = AND. A cell is in the result exactly when both floods marked it.
O(m·n)time (2 floods)
O(m·n)two visited grids + queue

Why it works: rain from v reaches the Pacific iff there is a path v = c0, c1, ..., ck with each height non-increasing and ck on the Pacific edge. Read backwards, that is a path from an edge cell where each height is non-decreasing, which is exactly what the uphill flood follows. So the flood marks v iff v drains to that ocean. Doing it once per ocean gives both facts for every cell at once.

Proof (optional)

Let R be the set the flood marks. (Soundness) Every marked cell was entered from a marked cell of lower-or-equal height, so by induction on BFS order it has a non-increasing path to a seed, hence to the ocean. (Completeness) Take a cell v with a valid downhill path to edge cell ck. ck is a seed. If some cell on the path were unmarked, pick the one closest to ck; its successor on the path is marked and is no higher, so when that successor was popped, the flood would have entered it. Contradiction, so every cell on the path, including v, is marked.

DFS works equally well. Recursive DFS can go 40,000 frames deep on a 200 x 200 snake, which breaks Python's default limit, so the tested code below uses BFS.
