When would you still choose the DP?

When the cost of a piece is not monotone in the cap, for example "minimise the sum of squares of piece sums" or "minimise total cost with a per-piece fee". Binary search needs a yes/no test that flips once; the DP works for any piece cost. With negative values the greedy check also breaks (a later value can shrink a piece).

How to answer

Name the property binary search needs (monotone feasibility) and give a cost that breaks it.

Likely follow-ups
  • Can the DP be sped up? (Knuth / divide-and-conquer optimisation applies to some costs; out of scope for most rounds.)
What if values can be negative?

Then a bigger piece is not always heavier, the greedy "fill until it overflows" is no longer optimal, and the range [max, sum] is wrong. Fall back to the DP over (pieces, prefix) with prefix sums.

How to answer

Point at the exact step that breaks: the greedy exchange argument assumes adding a value never lowers a sum.

Likely follow-ups
  • Which other "binary search on the answer" problems break the same way?
Maximise the smallest piece instead (k + 1 people share a bar).

Flip the check: "can I cut into at least k + 1 pieces with every piece ≥ x?" Greedy: close a piece as soon as it reaches x. Feasibility is now T..T F..F, so search for the last true: mid = (lo + hi + 1) / 2, lo = mid on success, hi = mid - 1 otherwise.

How to answer

Say "mirror image", then show the upper-mid change that avoids the infinite loop.

The array is huge and stored across machines. How do you run the search?

Each binary-search step is one pass. Machines hold contiguous shards; each one returns, for a cap, its greedy piece count plus the open sums at its left and right edges, and a coordinator stitches neighbouring shards. About 30 rounds total, each a parallel scan. Prefix sums per shard let you jump to piece ends with a binary search instead of scanning.

How to answer

Count rounds (log of the value range), then describe what each shard must report so the coordinator can merge.

Likely follow-ups
  • With prefix sums, how fast is one check? (O(k log n): k jumps by binary search.)
