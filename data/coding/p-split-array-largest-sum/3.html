Recognise the pattern

When you see "minimise the maximum" (or "maximise the minimum") + "split into k contiguous groups / k days / k workers", think binary search on the answer with a greedy feasibility check.

When you see a check that gets easier as the limit grows (a bigger cap never needs more pieces), think monotone predicate: find the first value where it turns true.

Try a few caps on [4,9,3,6,2], k = 2: cap 10 needs 4 pieces (no), 12 needs 3 (no), 13 needs 2 (yes), 16 needs 2 (yes), 24 needs 1 (yes). The answers line up as no, no, ..., yes, yes. That one switch point is what binary search finds.

Taxonomy: Binary search → on the answer (minimise the max). Pattern lesson: Binary search on the answer; the DP rung is a front-partition DP, see Dynamic programming.
