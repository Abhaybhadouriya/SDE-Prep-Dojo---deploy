Common mistakes

Starting lo at 0 or 1 without a guard in the check. If the cap is below a single value, the greedy opens a new piece for it but that piece still exceeds the cap, and the count looks fine. Start lo at max(nums), or return "infeasible" when x > cap.

Using lo <= hi with hi = mid. That loops forever when lo == hi. Pair while lo < hi with hi = mid / lo = mid + 1, and return lo.

Counting cuts instead of pieces. Starting the counter at 0 and comparing with k (instead of k - 1 cuts) is off by one. Start parts = 1 and compare parts <= k.

Checking "exactly k" in the greedy. The greedy gives the minimum count; demanding exactly k rejects valid caps. "At most k" is correct because any piece of 2+ values can be split further.

Sorting the array. The pieces must be contiguous in the original order; sorting changes the problem (it becomes the non-contiguous LC 2305, which needs backtracking).
