The problem (in our words)

You are given an integer array nums of non-negative weights and an integer k. Cut nums into exactly k non-empty contiguous pieces (subarrays). The cost of a cut is the largest piece sum. Return the smallest possible cost over all ways to cut.

Signature: int splitArray(int[] nums, int k).

Constraints

  • 1 <= nums.length <= 1000
  • 0 <= nums[i] <= 10^6
  • 1 <= k <= min(50, nums.length)

Practice it: LeetCode 410 - Split Array Largest Sum · GfG - Split Array Largest Sum · TUF - Split Array Largest Sum

Constraints tell you: n ≤ 1000 and k ≤ 50 allow an O(k·n²) DP (5·10^7, slow but it passes), so DP is a valid answer. The sum is at most 10^9, so log2(sum) ≈ 30 and binary search on the cap costs about 30·n = 3·10^4 steps. 10^9 still fits a 32-bit int, but run + x and lo + hi get close to the limit, so use 64-bit sums to be safe. Values can be 0, so a piece can have sum 0.
