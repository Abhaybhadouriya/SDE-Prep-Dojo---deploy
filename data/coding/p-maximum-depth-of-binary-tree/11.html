Interview follow-ups

Do it without recursion.

How to answer: BFS with a level-size loop (shown above), or an explicit stack of (node, depth) pairs for a DFS that tracks the maximum depth seen.

Likely follow-ups: which uses less memory? DFS stack is O(h), BFS queue is O(width); a full tree has a wide last level, a chain is deep.

What is the space complexity of the recursive version, exactly?

How to answer: O(h) for the call stack: O(log n) for a balanced tree and O(n) for a skewed one. The worst case for this problem is a 10^4-node chain.

Return the deepest leaf (or all nodes at the deepest level).

How to answer: with BFS, the last level processed is the deepest one; keep its nodes. With DFS, return (depth, node) pairs and keep the deeper one.

Likely follow-ups: the lowest common ancestor of the deepest leaves (LC 865 / 1123).

Can you do it in O(1) extra space?

How to answer: Morris traversal threads the tree temporarily and visits nodes without a stack; tracking depth needs care (count the steps along each thread when it is removed). It is rarely expected; mention it as an option.

The tree is huge and stored on disk or across machines.

How to answer: the bottom-up form is a natural map-reduce: each subtree computes its own depth independently and the parent combines. BFS by levels maps to one pass per level.

Is the tree balanced? (LC 110)

How to answer: reuse the same recursion, but return -1 as soon as |L - R| > 1 or a child returned -1. One pass, O(n).
