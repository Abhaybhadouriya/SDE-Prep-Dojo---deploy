The problem (in our words)

An org chart is stored as a binary tree and you hold its root. Report how many levels the chart has: count the nodes on the deepest chain that starts at the top and ends at a leaf (a node with no children). A chart with no nodes at all has 0 levels.

The tree is given (in examples and in the judge) as a level-order list where null marks a missing child.

Signature: int maxDepth(TreeNode root)

  • Constraints:
  • The number of nodes is in the range [0, 10^4]
  • -100 <= Node.val <= 100

Practice it: LeetCode 104 - Maximum Depth of Binary Tree · GfG - Height of Binary Tree

Constraints tell you: up to 10^4 nodes means O(n) is the target and trivially fast. But a skewed tree (a chain) can be 10^4 deep: recursion is fine in C++/Java/Go defaults, while CPython's default recursion limit (1,000) needs raising or the BFS version. Values do not matter at all.
