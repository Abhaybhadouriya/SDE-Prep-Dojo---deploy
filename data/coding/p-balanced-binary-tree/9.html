  • Insight: return the height, or -1 for "unbalanced below"; check |lh - rh| <= 1 on the way up.

  • Cost: O(n) time, O(h) stack; brute top-down O(n²).

The root's left subtree is a chain of 3 nodes going left, and its right subtree is a chain of 3 nodes going right. Is the tree height-balanced?

  1. Yes: |3 - 3| = 0 at the root
  2. No: the top node of each chain has child heights 2 and 0
  3. Yes: all leaves are at the same depth
  4. No: the root's children differ
The rule applies at every node, not only at the root. Checking only the root is the classic trap.

In the bottom-up helper, h(node.left) returns -1. What must happen before abs(lh - rh) is computed?

  1. Return -1 straight away (propagate it)
  2. Treat -1 as height 0
  3. Compute max(lh, rh) + 1 anyway
  4. Call h again
If -1 is compared with a real height of 0, abs(-1 - 0) = 1 passes the test and the imbalance below is lost.

Top-down version: every node calls height() on both children and then recurses. What is its time on a balanced tree?

  1. O(n)
  2. O(n log n)
  3. O(n^2)
  4. O(log n)
Each node's height is recomputed once per ancestor, and a balanced tree has O(log n) ancestors per node. The bottom-up version visits each node once: O(n).
