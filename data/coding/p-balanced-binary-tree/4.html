Approaches: brute -> better -> optimal

Hint 1

Write the definition literally first. How many times does it compute the height of the deepest node?

Hint 2

The height function already visits both subtrees. Could it report "unbalanced" at the same time?

1. Brute force - top-down, straight from the definition

def balanced(n):
    if n is None: return True
    return abs(depth(n.left) - depth(n.right)) <= 1 and balanced(n.left) and balanced(n.right)

Idea: at every node, compute both subtree heights with a separate depth() walk, compare, and recurse. Correct, and the code is the definition.

O(n²)time worst case (O(n log n) if balanced)
O(h)stack

What is wasted: a node at depth d is measured again by each of its d ancestors. On a near-chain that is 1 + 2 + ... + n = O(n2). The heights below a node never change, so we should compute each one once and hand it upward.

2. Optimal - bottom-up height with a -1 sentinel

def height(n):
    if n is None: return 0
    lh = height(n.left);  rh = height(n.right)
    if lh < 0 or rh < 0 or abs(lh - rh) > 1: return -1
    return 1 + max(lh, rh)
return height(root) >= 0
  1. Post-order: a node can only judge itself after both children have reported, so the work happens on the way back up.
  2. One return value, two meanings: a height is always >= 0, so -1 is free to mean "some node in here is unbalanced".
  3. Propagate the failure: once a child returns -1, the parent returns -1 without comparing. Checking the left result before recursing right (as in our code) also skips the right subtree.
  4. Answer: the tree is balanced exactly when the root's call does not return -1.
O(n)time (each node once)
O(h)stack; h = n for a chain, log n if balanced

Why it works: "balanced" is a statement about every node, and every node's test needs only its two children's heights. Post-order guarantees those are known when the node is processed. The most-voted community solution makes the same point: the top-down version recomputes depths, the bottom-up version returns them, which turns O(n2) into O(n).

Proof (optional)

Claim: height(n) returns -1 if the subtree at n contains an unbalanced node, otherwise its true height. Induction on subtree size. Empty: 0, correct. Otherwise, by induction each child returns -1 or its true height. If either is -1, the subtree contains an unbalanced node and we return -1. If both are heights, the only node not yet checked is n itself; we return -1 exactly when |lh - rh| > 1, else the true height 1 + max(lh, rh).

3. Iterative post-order (follow-up: no recursion)

Idea: the same check with an explicit stack. Push (node, false); when popped with false, push it back as (node, true) and push its children; when popped with true, both children are finished, so read their heights from a map, check, and store this node's height.

O(n)time
O(n)map + stack

Use it in Python for deep trees (a 5000-node chain) or when the interviewer forbids recursion.
