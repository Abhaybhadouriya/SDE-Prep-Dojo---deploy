Interview follow-ups

Why is your first version O(n²), and what is it on a balanced tree?

Each node is measured once per ancestor. On a chain that is n + (n-1) + ... = O(n2). On a balanced tree each level of recursion does O(n) depth work across all its nodes and there are O(log n) levels, so O(n log n).

How to answer

Count "how many times is one node visited" instead of guessing; then give both bounds.

Likely follow-ups
  • Can memoising depth() fix the brute force? Yes, a map node -> height makes it O(n); the bottom-up version is that memo without the map.
Return the lowest node that is unbalanced instead of a boolean.

The first node at which the -1 is created in post-order is a deepest unbalanced node (its children are both balanced). Record it in an outer variable at that moment and keep returning -1.

How to answer

Show that the creation point of the sentinel is exactly the answer; nothing else changes.

Likely follow-ups
  • Return all unbalanced nodes: do not stop early; record every node where |lh - rh| > 1 and return the true height.
Do it without recursion.

Iterative post-order with a stack of (node, childrenDone) pairs and a map of heights (rung 3). Alternatively, take the reverse of a "root, right, left" pre-order, which is a post-order, and process the nodes in that order.

How to answer

Explain why pre-order cannot work: a node needs its children's heights first.

Likely follow-ups
  • O(1) extra space? Only with Morris-style threading; mention it, do not code it.
The tree is an AVL tree whose nodes store their height. Verify it in O(n) without recomputing.

Check at every node that the stored height equals 1 + max(stored child heights) and that the stored child heights differ by at most 1. Both checks are local, so a single traversal in any order works.

How to answer

Point out that a wrong stored height is the real bug an AVL verifier hunts for, not only the balance rule.

Likely follow-ups
  • Also verify the BST order: pass (low, high) bounds down while heights come up.
What is the largest possible height of a balanced tree with n nodes?

About 1.44 log2 n. The sparsest balanced tree of height h has N(h) = N(h-1) + N(h-2) + 1 nodes (a Fibonacci-like recurrence), so h grows like log base the golden ratio of n. That is why a balanced tree gives O(log n) lookups and O(log n) recursion depth here.

How to answer

Build the worst case: one side of height h-1, the other h-2, recursively.

Likely follow-ups
  • Red-black trees allow up to 2 log2(n+1): looser balance, fewer rotations.
