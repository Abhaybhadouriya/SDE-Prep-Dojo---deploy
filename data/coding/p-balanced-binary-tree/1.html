The problem (in our words)

You are given the root of a binary tree that describes a company's reporting chart. Decide whether the chart is height-balanced: for every node, the heights of its left and right subtrees differ by no more than 1. Return true if so, false otherwise. An empty subtree has height 0; a leaf has height 1.

Signature: boolean isBalanced(TreeNode root). Trees are written in LeetCode's level-order form, with null for a missing child; the tree may be empty.

  • The number of nodes is in the range [0, 5000].
  • -104 <= Node.val <= 104

Practice it: LeetCode 110 · GfG Balanced Tree Check · TUF article

Constraints tell you: n <= 5000, so the O(n2) top-down check still passes on LeetCode, but the interviewer wants the O(n) version. A 5000-node chain is 5000 deep: fine for C++/Java/Go stacks, but over Python's default recursion limit of 1000. Values do not matter at all; only the shape does.
