Now go the other way: convert an integer 1..3999 to a Roman numeral.

Keep 13 (value, symbol) pairs from 1000 "M" down to 1 "I", including 900 "CM", 400 "CD", 90 "XC", 40 "XL", 9 "IX", 4 "IV". Greedy: for each pair, while num >= value, append the symbol and subtract. At most 15 symbols, so O(1).

How to answer

Point out that greedy is safe because each value is the canonical way to write that amount; an alternative is per-digit lookup tables for thousands, hundreds, tens and ones.

Likely follow-ups
  • Why must the pairs be in the table here but not in Roman to Integer?
The input may be invalid (IIII, IL, VX, MMMM). Validate it.

Simplest robust check: convert with the sign rule, then convert the result back with Integer to Roman and compare strings; a valid canonical numeral round-trips. Otherwise encode the rules: only I, X, C may be subtracted, only from the next two bigger symbols (I from V/X, X from L/C, C from D/M); V, L, D never repeat; I, X, C, M repeat at most three times.

How to answer

Offer the round-trip trick first (short and obviously correct), then sketch the rule-based check if they want a single pass.

Likely follow-ups
  • A regex for valid numerals: ^M{0,3}(CM|CD|D?C{0,3})(XC|XL|L?X{0,3})(IX|IV|V?I{0,3})$.
Why is comparing with the next symbol enough? Prove it.

A valid numeral is non-increasing except inside the six pairs, each of which is (small, big). So "next is bigger" happens exactly at the first symbol of a pair. Writing a pair as -small + big gives the pair's value, and every other symbol keeps its plus sign, so the signed sum equals the numeral.

How to answer

Two sentences: the ordering property, then the algebra of a pair.

Likely follow-ups
  • Does the rule still work for non-canonical "IIX"? It gives 1 - 1 + 10 = 10 rather than 8: the rule assumes validity.
Make the lookup as fast as possible.

Replace the hash map with a switch or a small array indexed by the character code (an int val[128] table filled once). That removes hashing and is branch-predictable; the loop is then a few instructions per character.

How to answer

Mention that for n ≤ 15 this is micro-optimisation, but it shows you know the constant factors.

Likely follow-ups
  • Handle lowercase input too: fold case first or fill both cases in the table.
Sum a list of Roman numerals and return the result as a Roman numeral.

Convert each to an integer with this solution, add them, then convert back with the greedy Integer to Roman. If the total can exceed 3999, agree on a notation first (overline for thousands, or repeated M).

How to answer

Reuse the two functions instead of trying symbolic addition on strings.

Likely follow-ups
  • Sort a list of Roman numerals: sort by their integer value (key function).
