  • Cue: symbol string to number, meaning depends on the neighbour → one pass, peek one ahead.
  • Insight: a pair XC = -X + C; "next is bigger" marks the minus.
  • State: just the running total.
  • Trap: strict <, bounds check on i + 1, last symbol always added.
  • Cost: O(n) time, O(1) space.
total, prev = 0, 0
for ch in reversed(s):            # right-to-left variant
    v = VALUE[ch]
    total += -v if v < prev else v
    prev = v

Quick quiz

What does the rule give for "XL"?

  1. 60
  2. -40
  3. 40
  4. 10
X (10) is smaller than the next L (50): -10, then +50 = 40.

In the right-to-left version, what do you compare the current value with?

  1. The value of the symbol just to its right
  2. The running total
  3. The largest value seen so far
  4. The first symbol
Same rule as left-to-right, seen from the other side: smaller than its right neighbour means subtract. (Comparing with the max seen so far also works for valid inputs.)

Why does the rule not need a list of the six special pairs?

  1. Because the input is short
  2. In a valid numeral, a smaller symbol precedes a bigger one only inside those pairs
  3. Because Python dictionaries are ordered
  4. It does need them
Validity guarantees the order is otherwise non-increasing, so the comparison identifies the pairs for us.
