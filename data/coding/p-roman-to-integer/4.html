Approaches: brute → better → optimal

Hint 1

In IV, which symbol is "wrong" compared with the normal big-to-small order?

Hint 2

Can you decide the sign of each symbol by looking only at the symbol right after it?

1. Special-case the six pairs

Idea: walk the string; at each position first check whether the next two characters are one of IV, IX, XL, XC, CD, CM. If so add the pair's value (4, 9, 40...) and jump two; else add the single symbol and jump one. Equivalent: a map with 13 keys (7 singles + 6 pairs), try the two-character key first.

O(n)time
O(1)space (13-entry table)

What is wasted: nothing in speed, but it hard-codes six cases you have to remember and get right; a bigger map means more places for typos.

2. Better - string replacement

Idea: replace each pair with an additive spelling (IV → IIII, IX → VIIII, XL → XXXX, ...) and then sum all symbols. Short in Python, but it builds new strings and still lists the six pairs.

O(n)time (small constant passes)
O(n)space for the new strings

3. Optimal - compare with the next symbol

total = 0                                    # core: 5 lines
for i, ch in enumerate(s):
    v = VALUE[ch]
    if i + 1 < len(s) and v < VALUE[s[i + 1]]: total -= v
    else: total += v
  1. Look up the value of symbol i.
  2. Peek at symbol i + 1 (if it exists).
  3. If the next one is bigger, symbol i is the small half of a subtractive pair: subtract it.
  4. Otherwise (next is equal, smaller, or there is none) add it. The last symbol is always added.
O(n)time, one pass
O(1)space

Why it works: a subtractive pair like XC means "C minus X" = -10 + 100. So instead of reading the pair as one token, give its first symbol a minus sign and add the second normally; the sum is the same. In a valid numeral, a symbol is followed by a bigger symbol only when it is the first half of such a pair (everything else is written big-to-small), so "next is bigger" is exactly the test for a minus sign.

Variant - scan right to left

Walk from the end, remember the value of the previous symbol you saw (the one to the right). If the current value is smaller than it, subtract, else add. Same rule, and it avoids the bounds check on i + 1. Many top-voted answers use this form.
