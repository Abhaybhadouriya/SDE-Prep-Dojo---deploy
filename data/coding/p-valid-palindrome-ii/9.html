60-second recall

  • Cue: palindrome after at most one deletion -> opposite-end two pointers.
  • Insight: matched outer pairs never need deleting; the first mismatch forces "delete lo or delete hi".
  • State: lo, hi; a helper is_pal(lo, hi) with no budget.
  • Trap: try BOTH sides; no second deletion inside the branch; k deletions = DP (LC 1216).
  • Cost: O(n) time, O(1) space.
while lo < hi:
    if s[lo] != s[hi]:
        return is_pal(lo + 1, hi) or is_pal(lo, hi - 1)
    lo += 1; hi -= 1
return True

At the first mismatch s[lo] != s[hi], which deletions can still work?

  1. Any index in s
  2. Only s[lo] or s[hi]
  3. Only the middle character
The outer part already matches, so the fix must remove one of the two mismatched characters.

"cuucu": first mismatch 'c' vs 'u'. What must the code do?

  1. Skip the left char only
  2. Skip the right char only
  3. Try both sides
Skipping left gives "uucu" (fails), skipping right gives "cuuc" (works). Code that tries one side fails such inputs.

Inside each branch check, how many more deletions are allowed?

  1. None
  2. One
  3. As many as needed
The single budget was spent at the mismatch; recursing with more deletions changes the problem (and the cost).
