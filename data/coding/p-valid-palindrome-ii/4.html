Approaches: brute -> better -> optimal

Hint 1

Compare from both ends. While characters match, is there any reason to delete one of them?

Hint 2

At the first mismatch s[lo] != s[hi], which characters could the deletion possibly be?

1. Brute force - try every deletion

Idea: if s is a palindrome, done. Otherwise for each index i, build s without s[i] and check it.

O(n²)time
O(n)space for each copy

What is wasted: deleting a character inside the already-matched outer part cannot help, and most of the n candidates are such characters. -> rung 2.

2. Better - two pointers with a reversed-substring check

Idea: move lo and hi inward while they match. At the first mismatch, test the two candidate substrings by comparing each with its reverse (t == t[::-1]).

O(n)time
O(n)space for the slices

What is not ideal: the slicing and reversing allocate up to two strings of length n. Fine in Python, but in an interview the O(1) version is just as short. -> rung 3.

3. Optimal - two pointers, branch once, check in place

lo, hi = 0, len(s) - 1
while lo < hi:
    if s[lo] != s[hi]:
        return is_pal(lo + 1, hi) or is_pal(lo, hi - 1)
    lo += 1; hi -= 1
return True
  1. Matched pairs are safe. If s[lo] == s[hi], an optimal solution never needs to delete either of them (deleting one would only shift the problem inward).
  2. The first mismatch pins the deletion. All outer pairs match, so the deleted character must be s[lo] or s[hi]; nothing else can make this pair match.
  3. No budget is left after that. Each branch is a plain palindrome check with no further deletions, so there is no recursion tree: two linear scans at most.
O(n)time (one pass + at most two partial passes)
O(1)space

Why it works: (1) When the ends match, keeping both is never worse: s[lo..hi] can be fixed with one deletion exactly when s[lo+1..hi-1] can (an exchange argument: a fix that deletes one of two matching ends can be swapped for a fix that deletes a character inside; we also checked the whole algorithm against brute force on every string of length up to 10 over a 3-letter alphabet). (2) At the first mismatch the budget is still unused, and the fixed string's first and last characters must match; since s[lo] != s[hi], one of them has to go. So the two candidate checks are complete: if both fail, no single deletion works.
