Now allow up to k deletions.

Branching at each mismatch gives up to 2k paths, and with memoisation on (lo, hi) it becomes the interval DP dp[lo][hi] = min deletions for s[lo..hi]. Equivalently, min deletions = n - LPS(s). O(n²) time, O(n) space with rolling rows. That is LC 1216.

How to answer

Explain why the greedy "one branch" breaks: the budget lets branches nest.

Likely follow-ups
  • Recursion with memo on (lo, hi, k) works too, but k adds a factor: prefer the LPS view.

Is it really O(n)? You call is_pal twice.

The main loop covers the matched outer part once. Each is_pal scans only the inner part [lo, hi], and they run at most twice, never nested. Total at most about 2n comparisons: O(n). There is no recursion, so O(1) extra space.

How to answer

Count comparisons, not calls.

Likely follow-ups
  • Can you do it in one pass? (Not simply; two short passes are fine.)
The string is a stream too large for memory, but you know its length.

Two pointers need random access from both ends. With a stream you can hash: keep rolling hashes of the forward prefix and of the reversed text for the "no deletion" check. One deletion makes this much harder, so say the honest answer: read it into a file or memory-mapped buffer and use two pointers there (sequential reads from both ends are still cheap on disk).
