Now the values only need to be close: |nums[i] - nums[j]| <= t as well as |i - j| <= k.

That is Contains Duplicate III. Keep the same window, but make it ordered (TreeSet / std::set): for each x, find the smallest value >= x - t and check it is <= x + t. O(n log k). The O(n) version puts each value in a bucket of width t + 1; two values in one bucket always match, and only the two neighbouring buckets need a check.

How to answer

Say that the window part does not change; only the "is there a partner" query changes from equality to a range query.

Likely follow-ups
  • Overflow in x - t? Use 64-bit arithmetic for bucket ids and differences.
Return the closest pair of equal values (minimum distance), not just true/false.

Use the last-seen map and keep best = min(best, i - last[x]) instead of returning early. One pass, O(n). This is LeetCode 2260 (Minimum Consecutive Cards to Pick Up) in disguise.

How to answer

Point out that the window set loses the indices, so the map version is the natural one here.

Likely follow-ups
  • Return the indices too: store them with best.
The readings arrive as an endless stream. Flag a reading as soon as it repeats within the last k.

The window set is already a streaming algorithm: keep a ring buffer of the last k readings plus the hash set. On a new reading: check the set, push it into the ring, and when the ring is full pop the oldest and remove it from the set. Memory O(k), O(1) per reading. Here the ring is needed because the stream cannot be re-read to find nums[i-k].

How to answer

Name the two structures (ring for order, set for lookup) and why both are needed.

Likely follow-ups
  • Repeats inside the window (no early return)? Use a count map, and remove a key only when its count drops to 0.
k is 10^7 and memory is tight. What can you trade?

A Bloom filter cannot delete, but a counting Bloom filter (or a cuckoo filter) can, so the window can be approximate with a small false-positive rate; confirm a reported hit exactly if the data can be re-read. Alternatively, partition the value range and process each partition separately with the exact algorithm (more passes, less memory).

How to answer

State the trade clearly: exactness vs memory vs passes.

Likely follow-ups
  • False negatives allowed instead? Sample or hash-partition the values.
Count how many windows of size k contain at least one duplicate.

Slide a window with a count map and a counter of "values with count >= 2". Adding x: if its count becomes 2, increment dup. Removing x: if its count drops from 2 to 1, decrement. A window is bad when dup > 0. O(n).

How to answer

Show that the set version breaks once repeats can live inside the window, and that a count map plus one summary counter fixes it.

Likely follow-ups
  • Count windows with all distinct values (the complement).
Window set or last-seen map: which one do you submit?

Both are O(n) time. The map is shorter and also gives distances; the set bounds memory by k. If k is small relative to n (or the input is a stream), choose the set; otherwise either is fine. Say both, code one, state its space.

How to answer

Interviewers like hearing the space difference, O(n) vs O(min(n, k)).

Likely follow-ups
  • Which has better cache behaviour? The set is smaller, so it stays hot in cache.
