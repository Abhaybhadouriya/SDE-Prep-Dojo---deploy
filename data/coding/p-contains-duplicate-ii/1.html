The problem (in our words)

A sensor writes one integer reading per tick into an array nums. You are also given a distance limit k. Report true if two different ticks i and j recorded the same reading and are at most k ticks apart, that is nums[i] == nums[j] and |i - j| <= k. Otherwise report false.

  • Input: an integer array nums and an integer k.
  • Output: a boolean. Signature: boolean containsNearbyDuplicate(int[] nums, int k).

Constraints

  • 1 <= nums.length <= 10^5
  • -10^9 <= nums[i] <= 10^9
  • 0 <= k <= 10^5 (k may be larger than the array)

Practice it: LeetCode 219 - Contains Duplicate II · GfG - Any Duplicate Within K Distance

Constraints tell you: n = 10^5 with k up to 10^5 makes checking every pair inside the distance limit up to 10^10 comparisons, far too slow; the target is one pass. Values up to 10^9 in absolute value rule out a direct-address array: you need a hash set or map. k = 0 is allowed and can never succeed, because i and j must differ.
