Approaches: brute -> better -> optimal

Hint 1

To delete a node in a singly linked list, which node do you actually need a pointer to?

Hint 2

If pointer A is exactly n nodes ahead of pointer B, where is B when A is on the last node?

1. Brute force - store every node

Idea: walk the list once and push every node pointer into an array. The node to delete is at index L - n; its predecessor is at L - n - 1. If L - n == 0, return head.next; otherwise relink the predecessor.

O(L)time, one pass
O(L)extra space

What is wasted: we store L pointers but only use one. A smaller version keeps only the last n + 1 pointers in a circular buffer (O(n) space), which is the stepping stone to the optimal idea: we only ever need the node n + 1 behind the cursor.

2. Better - count, then walk again (two passes)

Idea: pass 1 counts the length L. If n == L, the head goes: return head.next. Otherwise pass 2 walks L - n - 1 steps from the head to reach the predecessor and unlinks pred.next.

O(L)time, two passes
O(1)extra space

What is wasted: nothing asymptotically; this is a perfectly good answer. It misses only the "one pass" follow-up, and the off-by-one in L - n - 1 plus the head special case are where people slip.

3. Optimal - dummy head + gap of n (one pass)

dummy = ListNode(0, head)
lead = trail = dummy
for _ in range(n): lead = lead.next      # gap of n
while lead.next:                         # stop when lead is the LAST node
    lead, trail = lead.next, trail.next
trail.next = trail.next.next             # trail is the predecessor
return dummy.next
  1. Put a dummy before the head. Now every real node, including the head, has a predecessor.
  2. Open a gap. Move lead n steps; trail stays on the dummy. Valid because n <= L.
  3. Slide both. Move both one step until lead.next is null, so lead is on the last node.
  4. Unlink. trail is n nodes behind the last node, which is exactly one before the n-th from the end. Skip it and return dummy.next.
  1. Put a dummy D in front of the head; lead and trail both start on D.
  2. Move lead alone, step 1 of n = 2.
  3. Step 2: lead is n nodes ahead of trail. That gap never changes from now on.
  4. Move both. lead.next exists, so lead goes to 30 and trail to 10.
  5. Move both: lead 40, trail 20.
  6. Move both: lead 50, trail 30.
  7. Move both: lead 60, trail 40. lead.next is null, so we stop. lead is the last node, and trail is n nodes behind it: just before the 2nd node from the end.
  8. Unlink: trail.next = trail.next.next, so 40 now points at 60 and 50 is gone. Return D.next (10). One pass, O(1) space.
O(L)time: lead visits each node once
O(1)extra space: dummy + two pointers

Why it works: number the dummy as position 0 and the real nodes 1..L. After the gap loop, lead is at position n and trail at 0, so lead - trail = n, and the slide loop keeps that difference. It stops when lead is at position L, so trail is at L - n. The n-th node from the end is at position L - n + 1, which is trail's next. When n = L, trail is still the dummy, and unlinking dummy.next deletes the head with no special branch.

Is it really "one pass"? (a fair point to raise)

The two-pass version reads about 2L - n nodes; the gap version moves lead L times and trail L - n times, so the pointer moves are about the same. The difference is that the gap version touches the list front to back only once in time order, which matters when the list is a stream you cannot rewind or when each node fetch is a cache miss far from the previous one (trail lags only n nodes, so its nodes were touched recently). Saying this shows you understand the follow-up instead of reciting it.
