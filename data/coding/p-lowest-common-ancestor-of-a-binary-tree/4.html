Approaches: brute → better → optimal

Hint 1

If you had the root-to-p path and the root-to-q path, where would the answer be?

Hint 2

Can a single function call tell its parent "I found p", "I found q" or "I found both"?

Hint 3

When a call reaches p, does it need to look below p at all? Remember q is guaranteed to exist.

1. Brute force - two root-to-node paths

Idea: DFS from the root to p, recording the path; do the same for q. Walk both paths from the root while they agree; the last common node is the LCA.

O(n)time
O(h)space (two paths)

What is wasted: two or three traversals and two path lists. Correct and linear, but more code and more places for off-by-one mistakes. A worse brute force, "for each node, check whether p and q are both below it", is O(n2). -> rung 2.

2. Better - parent pointers and an ancestor set

Idea: one iterative DFS/BFS stores parent[node] until both p and q have been seen. Put all ancestors of p (including p) in a set, then walk up from q until you hit a node in the set.

parent = {root: None}; stack = [root]
while p not in parent or q not in parent:      # map parents until both are seen
    node = stack.pop()
    for c in (node.left, node.right):
        if c: parent[c] = node; stack.append(c)
up = set()
while p: up.add(p); p = parent[p]
while q not in up: q = parent[q]
return q
O(n)time
O(n)space

Good: no recursion at all, so no stack overflow on a 105-deep chain; this is the Python-safe answer. What is wasted: a hash map of n parents and a set. -> rung 3 needs nothing but the call stack.

3. Optimal - one post-order DFS that reports what it found

if root in (None, p, q): return root
left = lca(root.left, p, q)
right = lca(root.right, p, q)
return root if left and right else left or right
  1. Give the function a bigger meaning. lca(t) returns the LCA if both p and q are in t's subtree, the one of them that is there if only one is, and null if neither is.
  2. Stop at p or q. If t is p (or q), return t without searching below. If the other node is below t, t is the answer anyway; if it is elsewhere, some ancestor will see t from one side and the other from the other side.
  3. Both sides non-null means the split is here. p is on one side and q on the other, so no deeper node holds both: t is the lowest.
  4. Otherwise pass up the non-null side. It is either p, q, or an LCA already found lower down.
O(n)time
O(h)space (call stack)

Why it works: the answer is the unique node where the root-to-p and root-to-q paths diverge (or the one that is on the other's path). Only at that node do the two "found" signals arrive from different children, or does the node itself equal one target with the other below it, which the early return covers because nothing above can see the second target on another branch.

Proof (optional)

Let L be the true LCA. (1) No node above L returns anything other than what L returned: every proper ancestor A of L has both p and q in the one child subtree that contains L, so the other child returns null and A passes the value up. (2) L returns L: if L is p or q it returns itself at once. Otherwise p and q are in different child subtrees of L (else a child would be a lower common ancestor), each child subtree contains exactly one target, and by induction a subtree containing exactly one target returns that target (a subtree with one target never sees two non-null children, so it passes the target up). Hence both children are non-null and L returns itself. Every node is visited at most once: O(n).
