How to recognise a prefix sum problem

When you see "contiguous subarray" and an exact target (sum = k, equal counts, divisible by k, XOR = k) and values that may be negative or zero, think prefix total plus a hash map.

  • Many range-sum questions, array never changes: plain prefix array, O(1) per query.
  • "How many subarrays ..." with an exact condition: map of prefix value to count.
  • "Longest subarray ..." with an exact condition: map of prefix value to first index.
  • "Equal number of A and B": score +1 / -1, look for sum 0.
  • "Multiple of k" / "divisible by k": key = prefix mod k.
  • "Even number of each ...": key = parity bitmask (prefix XOR of bits).
  • Many range updates, one read at the end: difference array. Sparse coordinates: difference map plus sweep.
  • Range sums while the array also changes: prefix sums break (one update shifts O(n) totals). Use a Fenwick tree: range queries.

Not this pattern: "at most / at least" conditions on non-negative values (a sliding window is simpler and O(1) space), "maximum subarray sum" with no target (Kadane's algorithm, a tiny DP; though it can also be read as "current prefix minus the smallest prefix so far"), and "shortest subarray with sum at least k" with negatives, which needs prefix sums plus a monotonic deque.
