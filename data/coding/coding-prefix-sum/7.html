Prefix XOR

Everything above used one fact about +: it can be undone with -. XOR can be undone with itself, because x ^ x = 0. So with X[0] = 0 and X[i + 1] = X[i] ^ a[i]:

xor(a[l..r]) = X[r + 1] ^ X[l]
  • XOR Queries of a Subarray: build X, answer each query with one XOR.
  • Count subarrays with XOR equal to k (a Striver A2Z staple): the hash-map loop with run ^= x and lookup run ^ k (because X[j] ^ X[i] = k means X[i] = X[j] ^ k).
  • Count Triplets That Can Form Two Arrays of Equal XOR: "left part XOR equals right part XOR" means the whole block XORs to 0, so every pair of equal prefix values i < k gives k - i - 1 triplets.
  • The vowel problem above uses XOR too: flipping one bit per vowel keeps a parity mask, and two equal masks mean every vowel appeared an even number of times in between.

From your world

RAID-5 parity is the same algebra. The parity block is the XOR of the data blocks, so a lost block is the XOR of parity and the survivors: XOR undoes XOR. A prefix XOR is that parity kept as a running value. (The Internet checksum in IP and TCP headers is a running ones'-complement sum, which is a prefix sum you can also update incrementally, as RFC 1624 describes.)
