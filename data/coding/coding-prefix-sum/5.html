Difference arrays: prefix sums in reverse

So far we read many ranges. Now flip it: you must write to many ranges ("add 3 to every index from 2 to 900") and read the final array once at the end. Doing each update cell by cell costs O(length). The difference array stores only where the value changes:

diff[l] += v          # from l on, everything is v higher
diff[r + 1] -= v      # from r + 1 on, back to normal
# at the end: value[i] = diff[0] + ... + diff[i]   (a prefix sum)

Each update is two writes, O(1). One prefix-sum sweep at the end rebuilds the values. Prefix sum and difference are inverses, like integral and derivative: the prefix sum of the differences is the original array.

The classic interview version is Car Pooling: a car with some capacity drives east; each trip is [people, from, to]; can it serve every trip? The car only drives one way, so this is "add people to every stop in [from, to)", then check that no stop exceeds capacity.

  1. Stops 0..7, capacity 4. Start with a difference array of zeros: diff[s] = how the load changes at stop s.
  2. Trip 1: 2 people get on at stop 1 and are off by stop 5. Two writes only: diff[1] += 2, diff[5] -= 2. A trip over 1,000 stops would still cost 2 writes.
  3. Trip 2: 3 people get on at stop 3 and are off by stop 7. Two writes only: diff[3] += 3, diff[7] -= 3. A trip over 1,000 stops would still cost 2 writes.
  4. Now one prefix-sum sweep turns differences into loads: stop 0 = 0, stop 1 = 2, stop 2 = 2.
  5. Stop 3: load = 5, more than capacity 4. Return false. (Riders who leave at stop t are removed AT t, so a pickup at t can reuse their seats.)
  6. The full sweep: loads 0, 2, 2, 5, 5, 3, 3, 0. Peak 5. O(trips + stops) instead of O(trips × trip length).

Note the half-open range: riders are gone at stop to, so the minus goes at diff[to], not diff[to + 1]. Read each statement for which end is included. In Range Addition Premium and Corporate Flight Bookings both ends are included, so the minus goes at r + 1.

From your world

A difference array is an event log of increments and decrements, like reference counts: get is +1, put is -1, and the live count at any moment is the running sum. It is also how you would compute "how many connections were open at each second" from a log of SYN and FIN timestamps without replaying every connection: one +1 at open, one -1 at close, one sweep.

When the coordinates are huge or sparse (times up to 109), keep the differences in an ordered map keyed by coordinate instead of an array and sweep the keys in order. That is Meeting Rooms II and My Calendar III; see the range query lesson and intervals.
