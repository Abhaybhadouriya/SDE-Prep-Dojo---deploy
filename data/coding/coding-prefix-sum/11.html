Common mistakes

  • Forgetting the seed. {0: 1} for counts, {0: -1} for first indexes. Without it every subarray that starts at index 0 is missed. Test with an input where the whole array is the answer.
  • Inserting before looking up. With k = 0 the current prefix matches itself. Look up, then record.
  • Overwriting the first index. For "longest", write the index only if the key is new.
  • Negative remainders. -7 % 5 is -2 in C, C++, Java, Go and JavaScript. Use ((x % k) + k) % k.
  • 32-bit overflow. 105 values of 109 sum to 1014. Use long long / long / int64 for run and for map keys.
  • Wrong end in a difference array. Inclusive [l, r]: minus at r + 1, and size the array n + 1. Half-open [l, r): minus at r.
  • Not undoing in Path Sum III. Without the decrement after the recursion, prefixes from the left subtree leak into the right one and you count paths that do not exist.
  • Using a sliding window with negatives. It passes the sample (all positive) and fails the hidden tests.
