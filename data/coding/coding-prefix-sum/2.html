Prefix sum plus a hash map: count subarrays with sum k

The anchor problem is Subarray Sum Equals K: given an integer array (values may be negative) and k, count the subarrays whose sum is exactly k. It is one of the most asked medium problems: 15 recent interview reports in our problem database name it, and the newest six are all from Meta.

The brute force tries every (start, end) pair: O(n²) with a running sum, O(n³) without. The prefix idea turns the question around. A subarray ending at index j sums to k when

P[j + 1] - P[i] = k     which is     P[i] = P[j + 1] - k

So while you walk left to right with a running total run, the number of good subarrays that end here is "how many earlier prefix totals were equal to run - k". Keep those totals in a hash map from total to count. Click through it on [1, 2, -1, 2, 1] with k = 3:

  1. Start with run = 0 and seen = {0: 1}: the empty prefix exists once. It lets a subarray that starts at index 0 be counted. k = 3.
  2. i = 0, value 1: run = 1. Look up run - k = -2 in {0:1}: not there, nothing ends here. Then record run 1 in the map.
  3. i = 1, value 2: run = 3. Look up run - k = 0 in {0:1, 1:1}: found 1 time(s), so 1 subarray(s) ending here sum to 3 (highlighted: a[0..1]). answer = 1. Then record run 3 in the map.
  4. i = 2, value -1: run = 2. Look up run - k = -1 in {0:1, 1:1, 3:1}: not there, nothing ends here. Then record run 2 in the map.
  5. i = 3, value 2: run = 4. Look up run - k = 1 in {0:1, 1:1, 3:1, 2:1}: found 1 time(s), so 1 subarray(s) ending here sum to 3 (highlighted: a[1..3]). answer = 2. Then record run 4 in the map.
  6. i = 4, value 1: run = 5. Look up run - k = 2 in {0:1, 1:1, 3:1, 2:1, 4:1}: found 1 time(s), so 1 subarray(s) ending here sum to 3 (highlighted: a[3..4]). answer = 3. Then record run 5 in the map.
  7. End: answer = 3. One pass, one map lookup per element: O(n). A sliding window cannot do this: the -1 makes the sum go down when the window grows, so "shrink when too big" has no meaning.
seen = {0: 1}          # the empty prefix, seen once
run = ans = 0
for x in nums:
    run += x
    ans += seen.get(run - k, 0)     # 1. look up first
    seen[run] = seen.get(run, 0) + 1   # 2. then record

Two details decide whether this is right:

  1. Seed the map with {0: 1}. It stands for P[0], the empty prefix. Without it, a subarray that starts at index 0 (like [1, 2] above) is never counted.
  2. Look up before you insert. If you add the current total first and k = 0, the current prefix matches itself and you count an empty subarray.

Why not a sliding window? A window needs a condition that only gets worse as it grows. With negative numbers, adding an element can make the sum smaller, so you never know whether to grow or shrink. When the values are all positive a window works (O(1) space); the moment the statement allows negatives or zeros-with-k=0, reach for prefix plus hash map. Cost: O(n) time (one map operation per element, expected O(1)) and O(n) space for the map.
