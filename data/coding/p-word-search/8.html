Common mistakes

Forgetting to unmark. Without restoring the cell, a failed branch leaves cells blocked and a later valid path is missed; the board is also left damaged for the caller.

Checking "k == len(word)" only after moving. Then a one-letter word on a 1×1 board needs a step to a neighbour that does not exist. Test "matched the last letter" on the current cell, as in our code.

Using a global visited set that is never cleared. That is flood-fill logic. Here a cell may belong to the answer path even if an earlier, failed path used it.

Returning early before restoring. if dfs(...): return True before board[i][j] = saved leaves a # in the board. Store the result, restore, then return (or accept the damage only if the caller never reads the board).
