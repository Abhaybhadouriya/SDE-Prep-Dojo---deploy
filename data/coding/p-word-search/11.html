Interview follow-ups

How would you make it fast on a large board (the statement's follow-up)?

Three prunings: reject if the word is longer than the board; reject if any letter is needed more often than it appears; and search from whichever end of the word has the rarer letter. Optionally, precompute the start cells for that letter instead of scanning the grid.

How to answer

Give the adversarial input first ("aaaa...ab" on all a's), then show which prune kills it.

Likely follow-ups
  • Does reversing ever make it slower? (It can, on a different input, but counting first lets you pick the better end.)
Now search for a list of words (Word Search II).

Running this algorithm once per word costs words × m·n·3L. Instead, insert all words into a trie and run one DFS per cell that follows trie edges; a node that ends a word records it. Remove found words and empty trie branches so the search shrinks.

How to answer

Say "the trie shares the prefix work across words".

Likely follow-ups
  • How do you avoid reporting a word twice? (Clear the word at the trie node once found.)
You may not modify the board (it is read-only). What changes?

Use a separate visited boolean matrix (O(m·n)) or, since m·n ≤ 36, a 64-bit mask with bit i*n + j: set before recursing, clear after. The mask is a register-sized visited set, very cheap.

How to answer

Mention the bitmask: it shows you read the constraints.

Likely follow-ups
  • Pass the mask by value instead of undoing it? (Also works: the undo is implicit.)
Allow diagonal moves, or allow reusing a cell but not consecutively. What changes?

Diagonals: eight directions, branching factor 7, bound O(m·n·7L). Reuse allowed: the visited mark goes away; the state is just (cell, k), so memoise it: O(m·n·L·8) DP instead of exponential search.

How to answer

Point out that the "no reuse" rule is what makes it exponential; without it, memoisation applies.

Likely follow-ups
  • Why can't you memoise the original? (The result depends on which cells are used, not only on (cell, k).)
Return the path (list of cells), not just true/false.

Push (i, j) onto a path list when a cell matches and pop it when backtracking; when the last letter matches, copy the list. Same complexity.

How to answer

Show that the path list mirrors the marks exactly.

Likely follow-ups
  • Return all paths? (Do not stop at the first true; the count can be exponential.)
