  • Cue: grid path of adjacent cells, no reuse, small limits -> DFS backtracking.
  • Insight: mark the cell while it is on the path, unmark on return; reject on first mismatch.
  • State: (i, j, k); board cell set to '#' = on path.
  • Trap: restore before returning; check the last letter on the current cell; case matters.
  • Cost: O(m·n·3^L) worst, O(L) stack; prune by letter counts + start from the rarer end.
def dfs(cell, k):
    if invalid(cell) or not matches(cell, k): return False
    if k == last: return True
    mark(cell)
    ok = any(dfs(nb, k + 1) for nb in neighbours(cell))
    unmark(cell)                 # backtrack
    return ok

Why restore board[i][j] before returning from the DFS?

  1. to save memory
  2. another path from another start may need that cell
  3. LeetCode checks the board
  4. it is optional
The '#' mark means 'on the current path' only. Leaving it blocks later searches.

Can one cell be used twice in the same word?

  1. yes
  2. no; the mark prevents it
  3. only for repeated letters
  4. only diagonally
board [["a"]], word "aa" is false.

Pruning: why start from the end of the word when its last letter is rarer on the board?

  1. required
  2. fewer starting cells means fewer DFS trees; the answer is the same reversed
  3. it is faster to compare
  4. to avoid recursion
Count letters first; also return false at once if the board lacks enough of some letter.
