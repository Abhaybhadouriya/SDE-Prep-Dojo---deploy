  • Cue: "level by level" + alternate direction -> BFS with a frozen level width.
  • Insight: keep the queue plain; write value i at slot i or width-1-i.
  • State: queue, width = q.size(), row[width], leftToRight flag (flip per level).
  • Trap: q.size() in the loop condition; swapping child order with one queue; [] input.
  • Cost: O(n) time, O(w) extra; "level order + reverse odd rows" is the warm-up.
q = deque([root]) if root else deque()
while q:
    width = len(q)                       # freeze the level
    for i in range(width):
        node = q.popleft(); visit(node, i, width)
        push(node.left); push(node.right)
    end_level()                          # flip flags, store row

What changes between a plain level-order traversal and zigzag?

  1. The queue order
  2. Only the order you write each finished level (flip a direction flag per level)
  3. You need two queues and a stack
The BFS itself is identical; reverse (or fill from the back) every second level.

Why is it safer to fill a level array by index (or reverse it) than to push children right-first on odd levels?

  1. Pushing children in a changed order also changes the next level's order, which breaks later levels
  2. It is faster
  3. Queues cannot hold nulls
Child order feeds the next level; keep the queue order fixed and only flip the output.

Time and extra space for n nodes?

  1. O(n log n), O(1)
  2. O(n), O(w) where w is the widest level
  3. O(n^2), O(n)
Each node is enqueued and dequeued once; the queue holds at most one level.
