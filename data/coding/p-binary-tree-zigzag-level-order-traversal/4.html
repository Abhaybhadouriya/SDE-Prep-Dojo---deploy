Approaches: brute -> better -> optimal

Hint 1

Forget the zigzag. Can you produce the plain level-by-level lists?

Hint 2

When you start a level, the queue holds exactly that level's nodes. How many values will this level's list hold?

Hint 3

If you know the length in advance, you can fill the list from either end.

1. Level order, then reverse every odd level

Idea: run the standard BFS (or a DFS that appends node.val to levels[depth]), then reverse levels[1], levels[3], ... It is correct by the table above and is perfectly acceptable as the first answer.

O(n)time (BFS + one reverse pass)
O(n)space (queue + output)

What is wasted: each odd-level value is touched twice (append, then reverse). Asymptotically nothing, but interviewers often ask "can you do it without the reverse?" -> rung 2 or 3.

2. Two stacks (or a deque that flips ends)

Idea: keep the current level on one stack and push the next level onto another. On a left-to-right level push children left then right; on a right-to-left level push right then left. Popping a stack reverses the order for free. A deque version pops from the front and pushes to the back on even levels, and the opposite on odd levels.

O(n)time
O(width)space

What is wasted: nothing in cost, but the child order now depends on the level, which is the classic source of bugs (one wrong order and level 3 comes out mirrored). -> rung 3 keeps the queue plain.

3. Optimal - plain BFS, write into slot i or width-1-i

width = len(q); row = [0] * width
for i in range(width):
    node = q.popleft()
    row[i if left_to_right else width - 1 - i] = node.val
    # push node.left, node.right as usual
  1. The queue order never changes. Children are always pushed left, then right, so at the start of every level the queue holds that level from left to right.
  2. The width is known before you pop. width = queue.size() is frozen before any child is pushed, so the row can be allocated with its final size.
  3. Only the write slot flips. On a right-to-left level the i-th node from the left belongs at position width - 1 - i.
  4. Flip once per level, after the level is complete, not once per node.
O(n)time, each node queued once
O(w)extra space, w = max level width (≤ n/2 + 1)

Why it works: BFS with a frozen width processes exactly one level per outer iteration, in left-to-right order (induction: the children of a left-to-right sequence, pushed left then right, are themselves left to right). Writing the i-th of w values at w-1-i is exactly the reversal of that sequence, done in place while filling.

Proof (optional)

Claim: at the start of iteration d, the queue contains exactly the nodes at depth d, ordered left to right. True for d = 0 (only the root). If it holds for d, then popping those w nodes in order and appending each one's left child then right child appends the depth-(d+1) nodes in left-to-right order, because for two nodes a left of b on level d, every child of a is left of every child of b. After w pops only those children remain. So row d lists level d left to right when written at slot i, and right to left when written at slot w-1-i, which is the required output.
