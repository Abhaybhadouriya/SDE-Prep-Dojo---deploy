Same task, but nodes in the same cell must be listed left to right (LC 314). Can you do it in O(n)?

Yes: BFS with (node, col) pairs, append each value to cols[col], and track min and max col. BFS visits rows top to bottom and, inside a row, left to right, which is exactly the required order, so no sort is needed. Output cols[min..max].

How to answer

Explain why BFS (not DFS) gives the order for free, and that min/max col avoids sorting the keys.

Likely follow-ups
  • Why does a plain DFS give the wrong order for 314?
Avoid sorting the column keys. How?

Columns form a contiguous range, because a child's column differs from its parent's by exactly 1. Track min and max while traversing and index an array by col - min (or by col + n before you know min). Then only cells with several nodes need a value sort.

How to answer

State the "contiguous range" argument; that is what the interviewer wants to hear.

Likely follow-ups
  • What is the worst case of the remaining per-cell sorts?
Print the top view and the bottom view.

BFS with columns. Top view: keep the first value seen for each column. Bottom view: overwrite, so the last value (lowest row) stays. Output by increasing column. O(n).

How to answer

One BFS, one map, a single "first vs last" choice.

Likely follow-ups
  • For bottom view with ties in the same cell, which one wins on GfG? (the later one in level order)
Does the traversal order matter for your solution?

No. The sort on (col, row, val) fully determines the output, so pre-order, in-order, post-order, BFS or an iterative stack all give the same answer. That is also why the Python version uses an explicit stack without worrying about order.

How to answer

Say it confidently; it shows you understand that the key, not the walk, encodes the rule.

Likely follow-ups
  • Then which traversal would you pick in production? (iterative, to avoid deep recursion)
The tree has 107 nodes and does not fit in memory with all triples.

Stream the triples out to disk (or to per-column bucket files keyed by col), then sort each bucket by (row, val) externally; columns are already in order by file name. This is external sorting with a natural partition key.

How to answer

Name the partition key (col) and the per-partition sort key (row, val).
