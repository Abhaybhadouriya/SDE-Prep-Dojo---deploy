The problem (in our words)

You are given the root of a binary tree. Place the root at position (row 0, col 0). For a node at (row, col), its left child sits at (row + 1, col - 1) and its right child at (row + 1, col + 1).

The vertical order traversal is a list of columns, from the leftmost column index to the rightmost. Each column is the list of its node values read from top to bottom (smaller row first). If several nodes share the same row and the same column, list them in increasing value order. Return this list of lists.

Signature: List<List<Integer>> verticalTraversal(TreeNode root). The tree is given in LeetCode's level-order form, e.g. [5,2,8,null,null,6,9].

  • The number of nodes is in the range [1, 1000].
  • 0 <= Node.val <= 1000

Practice it: LeetCode 987 · GfG Vertical Tree Traversal · TUF article

Constraints tell you: only 1000 nodes, so an O(n log n) sort is trivially fast; the difficulty is the ordering rule, not speed. Columns run from -999 to 999 at most, so a hash map or an offset array both work. Values can repeat, and equal values in the same cell must both appear.
