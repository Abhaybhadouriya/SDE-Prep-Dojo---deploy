  • Cue: group tree nodes by column with an exact order inside -> tag + sort.
  • Insight: the order rule is lexicographic on (col, row, val).
  • State: one list of triples; left child (r+1, c-1), right child (r+1, c+1).
  • Trap: row before value; keep duplicates; 314 ties are left-to-right, 987 ties are by value.
  • Cost: O(n log n) time, O(n) space.
cells = [(col, row, val) for every node]   # any traversal
cells.sort()
for col, _, val in cells:
    if new col: out.append([])
    out[-1].append(val)

Inside one column, how are nodes ordered?

  1. By value only
  2. By row, then by value for nodes in the same row and column
  3. By insertion order
That tie rule is what makes this problem harder than the premium vertical-order variant.

If a node is at (row, col), where is its right child?

  1. (row + 1, col + 1)
  2. (row - 1, col + 1)
  3. (row + 1, col)
Left child goes to (row + 1, col - 1), right child to (row + 1, col + 1).

Time for n nodes with the sort-all-triples approach?
