How to state complexity aloud

Interviewers want a short, correct, justified answer. Use the same four beats every time:

  1. Define the variables. "Let n be the number of intervals."
  2. Name the dominant step. "Sorting is n log n; the merge pass is linear."
  3. Give time and space. "So O(n log n) time and O(n) space for the output, O(log n) extra for the sort's stack."
  4. Justify any non-obvious part. "The inner while looks nested, but the left pointer only moves forward, so it runs n times in total."

Do it twice per problem: once for the brute force ("checking every pair is O(n²), 10¹⁰ for this n, too slow") and once for the final solution. If there is a trade-off, name it: "a hash set gives O(n) time but O(n) space; sorting first is O(n log n) time with O(1) extra space if I can modify the input".

Avoid "it's basically linear". Say exactly what it is and why. If you are not sure about an amortised bound, say what you do know: "worst case per operation is O(n), but over n operations it's O(n) total because each element is pushed and popped once".
