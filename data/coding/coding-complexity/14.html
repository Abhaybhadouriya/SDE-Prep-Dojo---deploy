Interview questions

Your solution has a while loop inside a for loop. Why is it O(n) and not O(n²)?

Because the inner loop's index never resets. Count the total number of inner iterations across the whole run, not per outer iteration: the inner pointer starts at 0, only increases, and stops at n, so the inner body runs at most n times in total. Outer n + inner n = O(n). This is the aggregate amortised argument, and it applies to sliding windows, two pointers and monotonic stacks.

How to answer

Point at the variable that only moves forward and say "it moves at most n times over the whole algorithm".

Likely follow-ups
  • When would the same shape really be O(n²)? (If the inner index resets to i or 0 on each outer iteration.)
  • What about a stack that pops in a loop? (Each element is pushed once and popped at most once: O(n) total.)
n is up to 10⁵. Is an O(n²) solution acceptable?

Usually not. 10⁵ squared is 10¹⁰ basic steps; at a rough 10⁸ simple steps per second that is about 100 seconds against a 1 to 2 second limit. The target is O(n log n) or O(n). I would say the brute force out loud to show I understand it, then move to sorting, hashing, a heap or a sliding window.

How to answer

Do the arithmetic aloud, give the target complexity, and name a candidate technique.

Likely follow-ups
  • What about n ≤ 2,000? (4 × 10⁶ steps: O(n²) is fine, often the intended DP.)
  • Is the 10⁸ figure exact? (No, a rule of thumb; constant factors and the language matter.)
Why is appending to a dynamic array O(1) if it sometimes copies the whole array?

Because the capacity grows geometrically. With doubling, the copies over n appends are 1 + 2 + 4 + ... + n/2 < n, so the total work for n appends is under 3n and the amortised cost per append is O(1). A single append can still be O(n). If growth were by a fixed amount, the copies would sum to O(n²).

How to answer

Define amortised (total over a sequence divided by the count, worst case over sequences), then show the geometric sum.

Likely follow-ups
  • How do you avoid the latency spike? (Reserve capacity up front, or grow incrementally like an incremental rehash.)
  • Is amortised the same as average case? (No: amortised is a worst-case bound on a sequence; average case assumes a distribution of inputs.)
What is the complexity of plain recursive Fibonacci, and of the memoised version?

Plain: the call tree branches in two and overlaps, giving about φⁿ ≈ 1.6ⁿ calls, so O(2ⁿ) is an acceptable upper bound and Θ(φⁿ) is tight. Space is O(n) for the deepest call chain. Memoised: n distinct states, each computed once with O(1) work, so O(n) time and O(n) space (the memo plus the recursion depth). Bottom-up with two variables is O(n) time and O(1) space.

How to answer

Draw three levels of the tree to show repetition, then use "states × work per state".

Likely follow-ups
  • Can you do better than O(n)? (Yes, O(log n) with matrix exponentiation or fast doubling.)
  • Why is space O(n) even for the exponential version? (The stack only holds one root-to-leaf path at a time.)
What is the space complexity of a recursive DFS on a binary tree?

O(h), where h is the height of the tree, because the call stack holds one frame per level on the current path. For a balanced tree h = O(log n); for a skewed tree h = n, so the worst case is O(n). In Python or Java a very deep tree can overflow the stack; an iterative DFS with an explicit stack has the same O(h) bound but stores it on the heap.

How to answer

Say "O(h)" first, then give both extremes. Interviewers often ask precisely to see whether you count the stack.

Likely follow-ups
  • Can you traverse in O(1) extra space? (Yes, Morris traversal temporarily rewires right pointers.)
  • And BFS? (O(w), the maximum width; up to about n/2 for the last level of a complete tree.)
Apply the master theorem to merge sort and to binary search.

Merge sort: T(n) = 2T(n/2) + O(n). Here a = 2, b = 2, nlog_b a = n, and f(n) = n matches it, so the balanced case gives Θ(n log n). Intuitively, each of log n levels does n total merge work. Binary search: T(n) = T(n/2) + O(1). a = 1, b = 2, n0 = 1 matches f(n) = 1, so Θ(log n).

How to answer

Write the recurrence, name a, b and f(n), compare with nlog_b a, and back it with the recursion-tree picture.

Likely follow-ups
  • Quicksort worst case? (T(n) = T(n-1) + O(n) = O(n²); master theorem does not apply because the size shrinks by 1, not by a factor.)
  • T(n) = T(n/2) + n? (Root dominates: O(n), as in average quickselect.)
A hash map lookup is O(1). When is it not?

O(1) is the average with a good hash function and a bounded load factor. The worst case is O(n) when many keys collide into one bucket, which an attacker can force against a predictable hash. Hashing a string also costs O(L). Java 8+ HashMap converts long buckets to balanced trees, capping the worst case at O(log n); Python and Go randomise string hashing per process to make collisions hard to engineer.

How to answer

Separate the three costs: computing the hash, finding the bucket, and scanning the bucket.

Likely follow-ups
  • When would you choose a sorted map instead? (When you need ordering, floor/ceiling or range queries; O(log n) guaranteed.)
  • What does resizing cost? (O(n) once, O(1) amortised per insert, like a dynamic array.)
