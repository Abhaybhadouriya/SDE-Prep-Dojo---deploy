What Big-O actually counts

Big-O describes an upper bound on growth. You count the basic steps (a comparison, an addition, an array read) as a function of the input size n, then keep only the fastest-growing term and drop constant factors. 3n² + 20n + 7 becomes O(n²): when n is a million, the 20n part is noise. Two related words come up: Big-Omega (Ω) is a lower bound, and Big-Theta (Θ) means the upper and lower bounds match. In interviews people say "O" and mean the tight bound; that is fine, but know the difference if asked.

Three rules cover most of the arithmetic:

  1. Sequential steps add. Sort (n log n) then one scan (n) is O(n log n + n) = O(n log n).
  2. Nested steps multiply. For each of n elements, do a binary search (log n): O(n log n).
  3. Different inputs keep different letters. Comparing every word in a list of m words against a dictionary of k entries in a hash set is O(m · L) where L is word length, not O(n). Name your variables: "n is the array length, m is the number of queries".

Also say which case you mean. Quicksort is O(n log n) on average but O(n²) in the worst case. A hash map lookup is O(1) on average and O(n) in the worst case (every key in one bucket). Interviewers expect the average for hash maps and the worst case for everything else unless you say otherwise.
