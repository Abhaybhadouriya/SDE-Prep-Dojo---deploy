Hidden costs in library calls

Knowing the cost of the standard operations of your language is part of complexity analysis. The language toolkit page covers each language in depth; these are the traps that change the Big-O.

OperationCostTrap
hash map / set insert, lookupO(1) average, O(n) worsthashing a string key costs O(L); a list of strings as a key costs its total length
sorted map (TreeMap, std::map)O(log n)still the right choice when you need floor / ceiling / ordered iteration
sortO(n log n)comparison sorts cannot beat n log n; counting sort is O(n + k) when values are small
string + in a loopO(n²) totalO(n²) in Java and Go, whose strings are immutable; CPython sometimes optimises s += c in place, but it is not guaranteed, so use ''.join
Python slice a[i:j], Java substringO(j - i)copies; recursing on slices adds a factor of n
x in list, list.index, contains on ArrayListO(n)use a set
list.pop(0), vector.erase(begin()), ArrayList.remove(0)O(n)shifts everything; use a deque
heap push / pop; peekO(log n); O(1)building a heap from n items at once (heapify) is O(n)
BFS / DFS on adjacency listsO(V + E)an adjacency matrix makes it O(V²)
