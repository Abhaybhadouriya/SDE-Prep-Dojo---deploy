How to recognise what is expected

  • n ≤ 20 and "all combinations" / "all arrangements" → exponential backtracking or bitmask is intended.
  • n up to 10⁵ and an array → O(n log n) or O(n): think sort, hash map, two pointers, sliding window, heap, prefix sums.
  • The input is sorted, or the answer is monotonic ("minimum speed", "smallest capacity that works") → binary search, O(log n) or O(n log range).
  • "Follow up: can you do it in O(1) extra space?" → in-place tricks: two pointers, reusing the input array as a marker, reversing a linked list.
  • "Follow up: the data is a stream" → a heap or a fixed-size window; per-element cost matters more than total.
  • A value up to 10⁹ or 10¹⁸ with no array → O(log n) (fast power, binary search) or O(√n) (divisors).
  • The same sub-question asked repeatedly in a recursion → memoise; complexity = states × work per state.
