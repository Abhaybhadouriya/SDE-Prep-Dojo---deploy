Revision card

  • Cue: reverse the order of blocks, keep each block → reverse all, then reverse each block.
  • Insight: rev(A B C) = rev(C) rev(B) rev(A); reversing each block undoes the spelling.
  • State: read pointer r, write pointer w (w ≤ r), start of the current word.
  • Trap: split(" ") keeps empties; space only when w > 0; cut to w at the end.
  • Cost: O(n) time; O(1) extra in C/C++, one buffer in Java/Python/Go.
reverse(a, 0, n - 1); w = r = 0
while r < n:
    if a[r] == " ": r += 1; continue
    if w: a[w] = " "; w += 1
    start = w
    while r < n and a[r] != " ": a[w] = a[r]; w += 1; r += 1
    reverse(a, start, w - 1)
return a[:w]

Quick quiz

After reversing all of "red fox", the buffer is...

  1. "fox red"
  2. "xof der"
  3. "der xof"
  4. "red fox"
Order of words is final ("fox" first), but each word is spelled backwards.

Why is copying s[r] to s[w] in place safe?

  1. Strings are immutable
  2. Spaces are never copied
  3. w never gets ahead of r
  4. The buffer was reversed
We only write where r has already read, so no unread character is overwritten.

The same "reverse all, reverse parts" trick also solves...

  1. Rotate an array by k in place
  2. Valid palindrome
  3. Two sum
  4. Longest common prefix
