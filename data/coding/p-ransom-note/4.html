Approaches: brute -> better -> optimal

Hint 1

Does the position of a letter in the magazine ever matter?

Hint 2

For each of the 26 letters, compare "how many the note needs" with "how many the magazine has". Can one array hold both?

1. Brute force - cross out letters

Idea: for every letter of the note, scan the magazine for an unused copy and mark it used. If some letter finds no unused copy, return false.

O(n·m)time
O(m)used flags

What is wasted: we search the magazine again and again for the same letter. Every scan rediscovers counts we could have written down once.

2. Better - sort both and walk them together

Idea: sort the note and the magazine. Walk two pointers: when the letters match, advance both; when the magazine letter is smaller, skip it (unused); when the note letter is smaller, that letter is missing, so return false.

O((n+m) log(n+m))time
O(n+m)sorted copies

What is wasted: sorting builds a full order just to compare counts. Counting is enough, and with 26 letters it is O(1) memory.

3. Optimal - fill a stock, spend it

stock = [0] * 26
for ch in magazine: stock[ord(ch) - 97] += 1
for ch in note:
    stock[ord(ch) - 97] -= 1
    if stock[ord(ch) - 97] < 0: return False
return True
  1. Optional early exit. A note longer than the magazine can never fit; return false before counting.
  2. Fill. One pass over the magazine: stock[c] = copies of c available.
  3. Spend. One pass over the note: take one copy per letter. The first time a slot drops below 0, the note needs more of that letter than exists.
O(m + n)time
O(1)26 ints

Why it works: after the note's first k letters, stock[c] = (copies of c in the magazine) - (copies of c in those k letters). The note fits exactly when, for every letter, need <= have, i.e. the final value of every slot is >= 0. Each slot only decreases during the spend pass, so the first negative value is already a proof of failure, and if none ever appears, every final value is >= 0.

Variants from the top-voted community answers: the most-voted Java answer checks stock[c] == 0 before decrementing instead of checking for a negative afterwards (same logic). A popular Python one-liner is not (Counter(note) - Counter(magazine)): Counter subtraction drops non-positive entries, so an empty result means nothing is missing. It is short but always builds two maps and never exits early.
