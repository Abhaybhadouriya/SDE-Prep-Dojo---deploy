Interview follow-ups

The strings can contain any Unicode character. What changes?

Replace the 26-slot array with a hash map from code point to count (Counter, HashMap<Integer,Integer>, unordered_map<char32_t,int>). Iterate by code point, not by byte or UTF-16 unit, so a multi-byte letter counts once. Time stays O(n + m); space becomes O(distinct characters of the magazine).

How to answer

Say the algorithm is unchanged; only the counter container changes, and name the code-point iteration detail.

Likely follow-ups
  • Case-insensitive: normalise each character before counting.
The magazine is 1 GB but the note is 50 letters. Can you avoid reading the whole magazine?

Flip the roles: count the note's needs (at most 50 entries) and keep missing = note length. Stream the magazine; when a letter has a positive need, decrement it and missing. Stop as soon as missing == 0. Worst case still reads everything, but a typical yes exits early, and memory is O(note alphabet).

How to answer

Count the small side, stream the big side, keep one "remaining" counter for an O(1) done test.

Likely follow-ups
  • This is the same "missing counter" trick as Minimum Window Substring.
One magazine, a million different notes to check.

Count the magazine once (26 ints, or a map). Each note then costs O(len(note)): copy the 26 counts (O(1)) and spend them, or count the note and compare 26 pairs. Never re-scan the magazine per query: total O(m + sum of note lengths).

How to answer

Move the supply counting into preprocessing; each query is independent and cheap.

Likely follow-ups
  • Notes and magazines both change: keep counts updated incrementally per insert/delete.
Return how many identical magazines you need to buy to write the note.

For every letter the note needs, the magazines needed = ceil(need / have); if some needed letter has have = 0, the answer is impossible (-1). The answer is the maximum over letters. One pass to count each string, then 26 divisions.

How to answer

Turn the boolean into a ratio per letter and take the bottleneck letter.

Likely follow-ups
  • Different magazines with different contents: that is Stickers to Spell Word (DP over remaining needs).
The note must be made of whole words cut from the magazine, not single letters.

Same algorithm one level up: split both texts into words, count magazine words in a hash map, spend one count per note word, fail on a negative. Cost O(total characters) for hashing the words. Decide case and punctuation rules first (normalise before counting).

How to answer

Show the pattern is "multiset containment" and the element type (letter or word) is a detail.

Likely follow-ups
  • Very large vocabulary: a trie or hashing words to ids first.
Why is the 26-int array O(1) space and not O(n)?

Its size depends on the alphabet, which the constraints fix at 26, not on the input length. Doubling the magazine does not grow the array. With a general alphabet of size k, the honest bound is O(k), which is why the map version is O(distinct characters).

How to answer

State the bound in terms of the alphabet, then say it is constant for this problem.

Likely follow-ups
  • Byte strings: 256 slots, still constant.
