  • Cue: longest contiguous block + "at most k bad items" -> variable sliding window.
  • Insight: flip k zeros = longest window with at most k zeros; never choose which zeros.
  • State: left, right, zeros in window, best.
  • Trap: only a leaving 0 decrements; record best after the while loop.
  • Cost: O(n) time, O(1) space; brute O(n²), prefix + binary search O(n log n).
left = bad = best = 0
for right, x in enumerate(a):
    bad += is_bad(x)
    while bad > k:
        bad -= is_bad(a[left]); left += 1
    best = max(best, right - left + 1)

When must the window shrink?

  1. When it contains more than k zeros
  2. When it contains a zero
  3. When its length exceeds k
The window is valid while zeros <= k; flipping those zeros makes it all ones.

Why can the 'never shrink, slide by one' version still return the right answer?

  1. The window size never drops, and it only grows when a longer valid window exists
  2. It checks every window
  3. Because k is small
The window size is the best answer so far; an invalid window just slides without growing.

Time and extra space?

  1. O(n), O(1)
  2. O(n log n), O(n)
  3. O(nk), O(1)
Each index enters and leaves the window at most once; only a zero counter is kept.
