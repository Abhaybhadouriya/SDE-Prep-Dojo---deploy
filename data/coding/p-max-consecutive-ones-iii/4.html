Approaches: brute -> better -> optimal

Hint 1

Which zeros you flip does not matter. What does a block look like that can be made all ones?

Hint 2

A block works if and only if it contains at most k zeros. Now it is "longest subarray with a property".

Hint 3

When the window has k + 1 zeros, which edge has to move, and can it ever need to move back?

1. Brute force - every start, extend until the (k+1)-th zero

Idea: for each start i, walk j to the right counting zeros; stop as soon as the count passes k. The longest j - i + 1 seen is the answer.

O(n²)time
O(1)space

What is wasted: when start i moves to i + 1, we re-count every zero we already counted. -> rung 2 or 3.

2. Better - prefix count of zeros + binary search

Idea: let pre[j] be the number of zeros in nums[0..j-1]. For each right end j, the best start is the smallest i with pre[j+1] - pre[i] <= k; since pre is non-decreasing, binary search finds it.

O(n log n)time
O(n)space

What is wasted: the best start for j + 1 is never left of the best start for j, so the search can be replaced by a pointer that only moves forward. -> rung 3.

3. Optimal - sliding window that counts zeros

for right, x in enumerate(nums):
    zeros += x == 0
    while zeros > k:                     # too many flips needed
        zeros -= nums[left] == 0; left += 1
    best = max(best, right - left + 1)
  1. Invariant: after the inner loop, nums[left..right] holds at most k zeros, so it can be turned into all ones.
  2. The right edge always moves. Every index is tried once as the right end of a window.
  3. The left edge only moves forward, and only while the window is invalid. Removing a 1 does not reduce zeros, so the loop keeps going until a zero leaves.
  4. Record after fixing, never before: the window is only valid once the while loop finished.
O(n)time, each index enters and leaves once
O(1)space

Why it works: for each right end, left is the smallest start whose window has at most k zeros. If a start s gave too many zeros for right end r, it also gives too many for every r' > r (the window only gains elements), so a start we discarded never becomes useful again. That is why left never moves back, and why the total work is O(n).

Proof (optional) and the "never shrink" variant

Claim: when the loop records right - left + 1, left = L(right), the smallest valid start for that right end. Induction: L is non-decreasing in right, because a valid window [s, r+1] implies a valid [s, r]. We stop moving left exactly when the window becomes valid, which is the first valid start. The maximum over all right ends of right - L(right) + 1 is the longest valid window, which is the answer.

The most-voted community solution goes one step further: replace while by if, so the window never shrinks. When it is invalid it just slides by one (left and right both move). Its length can only grow when a longer valid window appears, so the final n - left is the answer and no best variable is needed. Same O(n); worth knowing, but the while form is easier to explain and to adapt.
