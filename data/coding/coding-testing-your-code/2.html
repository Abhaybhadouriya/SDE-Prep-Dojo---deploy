Dry runs with a variable table

A dry run is running the code by hand. The table makes it honest: every assignment in the code becomes a cell you write down, so you cannot skip a line. Keep the table small: only the variables that change inside the loop, plus the branch taken.

Below, the function is lower_bound(a, x): the first index i with a[i] >= x, or len(a) if there is none. It uses a half-open range [lo, hi): lo is inside the range, hi is one past the end. Input a = [1, 3, 3, 5, 8], x = 3; the answer should be 1 (the first 3).

def lower_bound(a, x):
    lo, hi = 0, len(a)              # [lo, hi)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if a[mid] < x:
            lo = mid + 1            # mid too small: answer is right of it
        else:
            hi = mid                # mid may be the answer: keep it
    return lo
  1. Range [0, 5) holds all five cells; hi points at the imaginary "end" slot. mid = 2, a[2] = 3 is not less than 3, so it might be the answer: hi = 2 keeps index 2 just outside the range.
  2. Range [0, 2). mid = 1, a[1] = 3, again not less than x: hi = 1.
  3. Range [0, 1) is one cell. mid = 0, a[0] = 1 < 3, so index 0 is too small: lo = 1.
  4. lo == hi == 1: the range is empty, the loop stops and returns 1, the first 3. The size column went 5, 2, 1, 0, so termination is proven, not hoped for.

Rules that make a dry run useful

  • Pick an input that exercises every branch. [1, 3, 3, 5, 8] with x = 3 takes both branches and has a duplicate, so "first" versus "any" is tested too.
  • Read the code, not your intention. Point at each line as you trace it. Most interview bugs are a line that says something different from what you meant (<= written for <, i written for j).
  • Add a "size" column for loops that shrink a range. If the size does not drop in some row, you have found an infinite loop (see the stepper further down).
  • For recursion, draw the call tree two levels deep with the return value written next to each call, instead of a table.
  • For pointer code, draw the boxes and arrows before and after one iteration. A table of addresses is unreadable; a picture of prev, cur, next is not.
