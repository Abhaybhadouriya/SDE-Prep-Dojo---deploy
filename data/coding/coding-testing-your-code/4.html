Finding off-by-one errors

An off-by-one error is a loop or index that is one step too long or too short: <= instead of <, n instead of n - 1, a range that skips its last element. They are the most common interview bug because the normal example usually still passes. The cure is to decide, before you write the loop, what your range means, and then check three places against that meaning.

The three-place check. For any loop over a range, check (1) the initial values (does hi start at n or n - 1?), (2) the loop condition (does it stop exactly when the range is empty?), and (3) every update (does each branch shrink the range by at least one, and does it keep or drop mid on purpose?). Then (4) the return value: is it lo, hi, lo - 1? Test it on the "not found" input where the answer is n or -1.

The classic trap is a range of size two. Below, the task is "the last index with a[i] <= x" on a closed range. The code looks reasonable, passes most inputs, and loops forever on some of them.

  1. Closed range [0, 4], size 5. mid = 2, a[2] = 4 <= 4, so index 2 could be the answer: lo = mid keeps it.
  2. Range [2, 4], size 3. mid = 3, a[3] = 4 <= 4: lo = 3.
  3. Range [3, 4], size 2. Integer division rounds down, so mid = 3 = lo. a[3] <= 4 sets lo = 3: nothing changed. The size column did not drop.
  4. The same row repeats forever. The rule: when a branch does lo = mid, mid must never equal lo, so it must round up.
  5. Fix one line: mid = (lo + hi + 1) // 2. Now mid = 4, a[4] = 7 > 4, hi = 3, the range is empty of choices and the answer is 3. Re-run the earlier rows: they are unchanged.

Pairing rule for binary search. lo = mid + 1 pairs with hi = mid and a rounded-down mid. lo = mid pairs with hi = mid - 1 and a rounded-up mid. Any other mix is either an infinite loop or a skipped element. The binary search page builds every variant from the half-open template.

Other off-by-one hot spots

  • Window length. The window [l, r] (both inclusive) has length r - l + 1; the slice s[l:r] in Python or s.substring(l, r) in Java has length r - l.
  • Last pair. A loop that reads a[i + 1] must stop at i < n - 1.
  • Prefix sums. With pre[0] = 0 and pre[i + 1] = pre[i] + a[i], the sum of a[l..r] is pre[r + 1] - pre[l]. Draw the two arrays one above the other once and the formula is obvious.
  • DP tables. A table of size n + 1 where row 0 means "empty prefix". Ask: is the answer at dp[n] or dp[n - 1]?
  • Fenceposts. k fence sections need k + 1 posts; a path through k edges visits k + 1 nodes. BFS levels versus distances is the same trap.

From your world

A ring buffer with head == tail meaning "empty" cannot tell "full" from "empty" unless you leave one slot unused or keep a count. That is an off-by-one decision made once, written in a comment, and checked at every index update. The kernel's CIRC_CNT and CIRC_SPACE macros in include/linux/circ_buf.h encode exactly that choice. Interview ranges are the same: decide what hi means, then check every line against it.
