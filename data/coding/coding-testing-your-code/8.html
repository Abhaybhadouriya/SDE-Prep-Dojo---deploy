How to recognise which cases to test

The statement itself tells you where the bugs will be. Scan it for these cues while you plan, and write the matching test inputs in a corner of the board before you code.

When the statement says...Test this
"sorted", "find the first / last"duplicates of the target, target smaller than all, larger than all, absent in the middle
"subarray", "contiguous", "sum equals k"negatives and zeros, k = 0, the whole array as the answer, a single element as the answer
"k" anywherek = 0, k = 1, k = n, k larger than n (if allowed)
"in place", "return the new length"nothing to remove, everything to remove, the element at index 0 and n-1
"32-bit integer", "return modulo 109+7", values up to 109overflow of sums, products and (lo + hi); INT_MIN
"linked list", "remove the nth node"remove the head, remove the only node, n equal to the length
"tree" with valuesnull root, one node, skewed tree, all negative values
"graph", "connected", "prerequisites"a cycle, a disconnected part, a node with no edges, a self-loop
"intervals", "meetings"touching end and start, nested intervals, unsorted input
"string", "palindrome", "anagram"empty string, one character, even and odd length, repeated characters
