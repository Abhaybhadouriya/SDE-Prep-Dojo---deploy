Numeric traps: overflow, signs and rounding

C engineers know overflow well, but interview languages hide it in different places. A short list to scan when the inputs are numbers:

TrapWhere it bitesSafe habit
Sum or product of intsC++ int, Java int, Go int32; Go int is 64-bit on 64-bit targets; Python never overflowsuse long long / long for sums of many values and for any product
(lo + hi) / 2lo and hi near 231 (the bug that sat in the JDK's binary search for years)lo + (hi - lo) / 2
abs(INT_MIN), -INT_MINreverse integer, atoi, divide two integerswork in 64-bit, or in negative numbers, and check against the limit before multiplying by 10
Integer division and modulo of negativesC, C++, Java, Go truncate toward 0 (-7 / 2 = -3, -7 % 3 = -1); Python floors (-4 and 2)for a non-negative mod in C-family languages: ((a % m) + m) % m
Comparator by subtractionJava (a, b) -> a - b overflows for large opposite-sign valuesInteger.compare(a, b)
Floating point equalityslopes (max points on a line), averages, square rootskeep fractions as reduced integer pairs, or compare with an epsilon
