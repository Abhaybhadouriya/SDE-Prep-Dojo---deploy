Fixing bugs calmly

Finding a bug in front of the interviewer is normal and is not a failure. What is graded is how you handle it. Strong candidates treat it like a production incident with a small blast radius: reproduce, locate, explain, patch, verify.

  1. Say it. "This input returns 0 but should return -1." Naming the symptom calmly buys you time and shows control.
  2. Reproduce on the smallest input. Shrink the failing case: if [-5, -1] fails, does [-1] fail? The smallest failing input usually points at the line.
  3. Locate by tracing that input only, using the same table. Stop at the first row where a cell differs from what it should be.
  4. Explain the cause in one sentence before touching the code: "best starts at 0, so an all-negative array can never beat it."
  5. Patch one line. Resist rewriting the function or switching approach. A rewrite at minute 38 usually brings two new bugs.
  6. Re-run the failing input and the main example. Mention any other case the same bug could affect.

Scenario: the all-negative array

You wrote Kadane's algorithm for "largest sum of a non-empty contiguous subarray" with best = 0, cur = 0. During your edge sweep, you try [-5, -1]. The code returns 0. The interviewer is watching.

Weak: "Hmm, let me just redo this with prefix sums." Erases the loop, starts a new O(n2) approach, runs out of time.

Strong: "This returns 0, but the answer is -1, because the subarray must be non-empty. The bug is the initial value: 0 is a sum no subarray here can reach. I will start both best and cur at a[0] and loop from index 1. Re-checking: [-5, -1] gives cur = -5, then max(-1, -6) = -1, best = -1. The main example still gives 6. Time O(n), space O(1)."

Likely follow-ups
  • Return the start and end indices too (track where cur restarted).
  • What if empty subarrays were allowed? (then best = 0 is correct: the requirement decides the initial value).

When you are truly stuck on a bug, say what you know: "the loop is correct for sizes 1 and 3, so the problem is in the size-2 case". Interviewers often give a hint when they can see your reasoning; they cannot help a silent candidate.
