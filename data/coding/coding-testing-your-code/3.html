Edge cases, chosen by data type

An edge case is an input at the boundary of what the problem allows: the smallest size, the largest value, all elements equal. Bugs live at boundaries because the "normal" example never touches them. Six cases cover most inputs; the table after the picture adds the ones specific to each data type.

Data typeAlways tryTypical bug it catches
Arrayempty; one; two; all equal; already sorted; reverse sorted; target at index 0 and n-1; target absent below, between and above all valuesreading a[0] on empty input, missing the last element, wrong answer when all values tie
Numbers0; negative; INT_MAX and INT_MIN; a sum of n large values; division by a negative; odd and even n32-bit overflow, -7 / 2 is -3 in C, C++, Java and Go but -4 in Python, -7 % 3 is -1 versus 2
String""; one char; all the same char; palindrome of odd and even length; upper and lower case; spaces and punctuation if the statement allows themwindow never shrinks, case-sensitivity, an off-by-one in s[i:j]
Linked listnull head; one node; two nodes; delete the head; delete the tail; a cycle (if the statement allows it)lost head pointer (use a dummy node), null dereference on cur.next.next
Binary treenull root; a single node; a skewed tree (a "linked list"); duplicate values; negative node valuesrecursion depth for n = 105 skewed, max path initialised to 0 when all values are negative
Graphno edges; a disconnected graph; a self-loop; parallel edges; a cycle; one nodeBFS from only node 0, missing the visited set, wrong cycle check in an undirected graph (the parent edge)
Matrix / grid1 x 1; 1 x n; n x 1; all walls; start equals targetswapped rows and columns, missing bounds check on one side
Intervalstouching ([1,3] and [3,5]); nested ([1,10] and [2,3]); unsorted input; a single intervaloverwriting end with the inner end instead of max, open versus closed ends
Hash map / countskey seen for the first time; count dropping to 0; k = 0; k larger than the number of distinct keyscounting the element as its own complement (two-sum with x + x = target)
DPn = 0 and n = 1 (the base cases); the answer at the last cell versus the max over all cellsreturning dp[n] when the answer is max(dp), uninitialised base row

Read the constraints first. They tell you which edge cases exist. "1 <= n" removes the empty case; "-104 <= a[i] <= 104" with n up to 105 means sums reach 109, still inside 32 bits (2.1 x 109), but a product of two values or a sum of 105 values of 109 does not fit. Saying this out loud is itself a test.
