Revision card

  • Cue: next / previous ordering, next bigger number with the same digits.
  • Insight: the non-increasing suffix is maxed out; change the value just before it.
  • State: pivot i, successor j (rightmost > a[i]), suffix i+1..n-1.
  • Trap: use >= and <= in the scans (duplicates); reverse from i+1 even when i = -1.
  • Cost: O(n) time, O(1) space; with sort O(n log n); brute O(n!·n).
i = n - 2
while i >= 0 and a[i] >= a[i+1]: i -= 1
if i >= 0:
    j = n - 1
    while a[j] <= a[i]: j -= 1
    a[i], a[j] = a[j], a[i]
reverse(a, i + 1, n - 1)

Quick quiz

Why can we reverse the suffix instead of sorting it?

  1. Reverse is always a sort
  2. The suffix is non-increasing, before and after the swap
  3. The suffix has at most two values
  4. Duplicates are not allowed
The pivot scan proves the suffix is non-increasing, and the swap with the rightmost bigger value keeps that order, so reversing it gives ascending.

What is the next permutation of [2, 3, 1]?

  1. [1, 2, 3]
  2. [3, 2, 1]
  3. [3, 1, 2]
  4. [2, 1, 3]
Pivot 2 (index 0), successor 3, swap gives [3, 2, 1], reverse the suffix: [3, 1, 2].

How do you get the previous permutation instead?

  1. Flip both comparisons: pivot a[i] > a[i+1], successor = rightmost value < a[i]
  2. Reverse the array, call next, reverse again
  3. Call next n! - 1 times
  4. Sort descending
Same three steps with every comparison mirrored. (Option 2 gives a different ordering, not the previous one.)
