Now do the previous permutation.

Mirror every comparison: the pivot is the rightmost i with nums[i] > nums[i+1] (the suffix is non-decreasing, at its minimum); the successor is the rightmost value smaller than the pivot; swap; reverse the suffix so it becomes non-increasing (its maximum). No pivot means the array is the first ordering: wrap to descending.

How to answer

Say "same proof, every inequality flipped", then write only the two changed comparisons.

Likely follow-ups
  • With duplicates, which equal value do you swap with? (The leftmost of a run of equal values, as LC 1053 requires.)
Give the k-th permutation of 1..n directly.

Use the factorial number system: with n values, each choice of the first value covers (n-1)! orderings, so the first value is index (k-1) / (n-1)! in the sorted list of unused values; repeat with the remainder. O(n²) with a list, O(n log n) with a Fenwick tree. That is LC 60.

How to answer

Contrast it with calling next permutation k times, O(n·k), which is fine only for small k.

Likely follow-ups
  • The reverse question: the rank of a given permutation (count smaller unused values per position).
Smallest number bigger than n with the same digits, or -1.

That is LC 556: digits, next permutation without the wrap (return -1 when there is no pivot), then check the result fits in a signed 32-bit int; use a 64-bit value or compare as strings before converting.

How to answer

Mention the overflow case first: 2147483476 -> 2147483647 fits, but 1999999999 -> 9199999999 does not.

Likely follow-ups
  • Largest number smaller than n with the same digits (previous permutation, and watch leading zeros).
How would you print all distinct permutations with this function?

Sort the array, print it, and call next permutation until it wraps back to the sorted order. Each distinct ordering appears exactly once, duplicates included, with O(1) extra memory and no recursion; the number of calls is n! / (c1!·c2!·...) for value counts c.

How to answer

Compare with backtracking: same output order, but no visited array and no "skip duplicates" rule.

Likely follow-ups
  • Cost per call? Worst case O(n); averaged over the whole cycle it is a small constant, because long suffixes are rare.
Do it on a string, or on a doubly linked list.

Same steps. In Java or Python convert the string to a char array or list first (strings are immutable). On a doubly linked list, walk from the tail with prev pointers for both scans and reverse the suffix by swapping values from both ends inward; still O(n), O(1).

How to answer

Point out the algorithm only needs backward scans and an in-place reverse, so any bidirectional sequence works (that is why std::next_permutation needs bidirectional iterators).

Likely follow-ups
  • Singly linked list? (Reverse it first, or use O(n) extra space.)
