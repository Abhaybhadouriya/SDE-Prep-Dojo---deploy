Approaches: brute → better → optimal

Hint 1

To get the next bigger ordering, you want to keep the longest possible prefix unchanged. Which is the rightmost position you can change and still go up?

Hint 2

If a suffix is in descending order, no rearrangement of it alone is bigger. So look for the first place, from the right, where the values stop climbing.

Hint 3

After you raise that position, the part to its right should be as small as possible. What order is it in at that moment?

1. Brute force - list every ordering

Idea: generate all distinct permutations, sort them, find the current one, and copy the one after it (or the first one if it is last).

O(n!·n)time
O(n!·n)space

What is wasted: we build n! arrays to use one of them. At n = 12 that is already about 479 million orderings. We only need to know where the next one first differs from the current one. -> rung 2.

2. Better - find the pivot, swap, then sort the suffix

Idea: scan from the right for the first i with nums[i] < nums[i+1] (the pivot). Among the values to its right, pick the smallest one that is bigger than nums[i], swap them, and sort everything after i ascending. No pivot means the array is the last ordering: sort it all.

O(n log n)time
O(1)space (in-place sort)

What is wasted: the sort. The suffix is already in non-increasing order before and after the swap, so a plain reverse sorts it in O(n). -> rung 3.

3. Optimal - pivot, successor, reverse

i = n - 2
while i >= 0 and a[i] >= a[i + 1]: i -= 1         # pivot
if i >= 0:
    j = n - 1
    while a[j] <= a[i]: j -= 1                     # rightmost value > pivot
    a[i], a[j] = a[j], a[i]
a[i + 1:] = reversed(a[i + 1:])                    # smallest order of the suffix
  1. The suffix after the pivot is at its maximum. It is non-increasing, so no ordering that keeps nums[0..i] is bigger. The change must happen at index i.
  2. Raise the pivot by the smallest possible step. Replace nums[i] with the smallest suffix value that is bigger. In a non-increasing suffix, that is the rightmost value bigger than the pivot, so scan from the right.
  3. The swap keeps the suffix non-increasing. Values left of j are at least nums[j], which is bigger than the old pivot; values right of j are at most the old pivot. Dropping the old pivot into slot j fits that order.
  4. Reverse the suffix. A non-increasing run reversed is non-decreasing: the smallest ordering of those values. With no pivot (i = -1) this reverses the whole array, which is exactly the wrap-around.
O(n)time (three linear scans at most)
O(1)space

Why it works: the next ordering shares the longest possible prefix with the current one (any change further left would jump past it). The pivot is the rightmost position that can grow at all; it grows by the least amount; and everything after it is put in its smallest order. No ordering can fit between the old array and the new one.

Proof (optional)

Let i be the pivot and S = nums[i+1..] (non-increasing). (1) Any ordering bigger than nums that keeps nums[0..i] would need a bigger ordering of S, which does not exist, so the next ordering keeps exactly nums[0..i-1] and changes position i. (2) Position i must hold a value bigger than nums[i] taken from S (values left of i are fixed); the smallest such value gives the smallest result. (3) With prefix and position i fixed, the smallest completion is the remaining values ascending. The swap leaves the remaining values non-increasing (step 3 above), so reversing gives ascending. Duplicates are handled because the scans use >= and <=: equal values are treated as "not bigger", so the result is the next distinct ordering.
