Solve it without a queue (recursively). What is the space now?

The right-first DFS with depth == len(view). Space is the recursion depth, O(h): O(log n) for a balanced tree, O(n) for a chain. BFS is O(w), which can be n/2 for a perfect tree, so neither dominates.

How to answer

Compare O(h) vs O(w) on two shapes: a chain and a perfect tree.

Likely follow-ups
  • Iterative DFS with an explicit stack of (node, depth)?
Return the view from the left AND the right, then the top view.

Left and right are first/last per level. The top view groups by column (root = 0, left child = col - 1, right child = col + 1) and keeps the first node seen per column in BFS order, then outputs columns from min to max. O(n) with a hash map, O(n log n) if you sort the columns.

How to answer

Name the key: views from the side are per row, views from the top/bottom are per column.

Likely follow-ups
  • Bottom view? (Keep the LAST node per column in BFS order.)
The tree has 106 nodes in a single long chain. Which version do you ship?

BFS: a chain has width 1, so the queue stays tiny, while recursive DFS would need 106 stack frames and can overflow the call stack (Java, Python default limit 1000, C++ default 1-8 MB stacks).

How to answer

Tie the choice to the shape: deep and thin -> BFS; wide and shallow -> DFS.

Likely follow-ups
  • Can you make the DFS iterative? (Stack of (node, depth), push left then right.)
It is an n-ary tree (each node has a list of children). What changes?

Nothing in BFS except pushing all children in order. In DFS, recurse over the children from last to first.

How to answer

The algorithm only needs the order of children, not that there are two.

Likely follow-ups
  • A graph with cycles? (Add a visited set; "level" becomes BFS distance from the root.)
