  • Cue: one value per tree level, top to bottom -> BFS with a width snapshot.
  • Insight: visible node = LAST of its level (may live in the left subtree).
  • State: queue, width = len(q) per level; DFS: depth vs len(view).
  • Trap: not "go right"; snapshot width before popping; empty tree -> [].
  • Cost: O(n) time; BFS O(width) space, DFS O(height).
q = deque([root])
while q:
    width = len(q)
    for i in range(width):
        node = q.popleft()
        per_level_action(i, width, node)
        push_children(node)

Tree: root 1, left child 2 with left child 4; right child 3 (leaf). Right view?

  1. [1, 3]
  2. [1, 3, 4]
  3. [1, 2, 4]
  4. [1, 3, 2]
Level 2 has only node 4, which is in the LEFT subtree but is still visible. 'Always go right' misses it.

BFS: why read width = len(queue) before popping a level?

  1. for speed
  2. the queue grows while you pop; the snapshot tells you where the level ends
  3. to avoid duplicates
  4. it is optional
Without it you cannot tell which popped node is the last of its level.

DFS version: when do you append a node's value?

  1. at every leaf
  2. when depth == len(view), visiting right before left
  3. on the way back up
  4. when depth is even
The first node reached at a new depth, going right first, is the rightmost one of that depth.
