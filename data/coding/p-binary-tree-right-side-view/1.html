The problem (in our words)

You get the root of a binary tree. Imagine standing to the right of the tree and looking left. Return the values of the nodes you can see, listed from the top level to the bottom level. On each level you see exactly one node: the rightmost node of that level. An empty tree gives an empty list.

Signature: List<Integer> rightSideView(TreeNode root). In the examples the tree is written in LeetCode's level-order format, with null for a missing child.

  • The number of nodes is in the range [0, 100].
  • -100 <= Node.val <= 100

Practice it: LeetCode 199 · GfG Right View of Binary Tree · TUF left and right views

Constraints tell you: at most 100 nodes, so speed is never the issue; the interviewer is testing whether you see that the answer is per level. Recursion depth is at most 100, so the DFS version is safe too. Values can be negative, so do not use a value like 0 or -1 as a "missing" marker.
