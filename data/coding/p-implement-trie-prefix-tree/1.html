The problem (in our words)

A log-tagging tool needs a small index of keywords it can extend at run time and query by exact word or by beginning. Build the class Trie with these operations:

  • Trie() creates an empty index.
  • void insert(String word) adds word to the index.
  • boolean search(String word) returns true if word was inserted earlier (the exact word), else false.
  • boolean startsWith(String prefix) returns true if at least one inserted word begins with prefix, else false.

Input format (LeetCode design style): a list of method names and a list of argument lists, called in order on one object. Output: the list of return values, with null for the constructor and for insert.

Constraints:

  • 1 <= word.length, prefix.length <= 2000
  • word and prefix contain only lowercase English letters a-z.
  • At most 3 * 104 calls in total to insert, search and startsWith.

Practice it: LeetCode 208 · GfG Implement Trie · TUF Trie implementation

Constraints tell you: a call can carry 2000 letters and there are up to 3·104 calls, so 6·107 letter steps in total is the budget: each call must cost O(length), not O(number of words × length). The alphabet is fixed at 26, which makes an array of 26 child pointers per node a natural choice.
