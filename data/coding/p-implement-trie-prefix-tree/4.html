Approaches: brute -> better -> optimal

Hint 1

Which of the three calls is slow if you keep the words in a hash set?

Hint 2

Two words with the same first three letters could share the storage for those three letters. What would the shared part look like?

1. Brute force - a hash set of words

Idea: keep every inserted word in a hash set. insert and search hash the word; startsWith loops over all stored words and checks each one's beginning.

O(L)insert / search
O(N·L)startsWith
O(total letters)space

What is wasted: a prefix query reads every word, although at most the words that share the first letter can match. With 3·104 calls that is up to 108-109 character comparisons. -> rung 2.

2. Better - an ordered set and a lower bound

Idea: keep the words sorted (std::set, Java TreeSet). All words that start with p sit in one contiguous run, and the first word >= p is the only one you need to look at: startsWith(p) is true exactly when that word begins with p.

O(L log N)every call
O(total letters)space

What is wasted: each of the log N comparisons re-reads the shared beginning of two words. That is a good fallback answer (our Java test uses exactly this as the reference), but the cost still grows with N. -> rung 3.

3. Optimal - a trie (prefix tree)

cur = root
for ch in word:                       # insert: create only the missing edges
    cur = cur.child.setdefault(ch, TrieNode())
cur.is_end = True                     # search = same walk + check is_end
  1. A node is a prefix. The root is the empty prefix; following edge c from the node for p leads to the node for p + c. Each node holds up to 26 child links and one flag isEnd.
  2. Insert walks and builds. Follow the letters; whenever a child link is missing, create the node. At the last letter set isEnd = true. Inserting a word twice changes nothing.
  3. Both queries are the same walk. Follow the letters, and stop with false as soon as a link is missing. startsWith returns true if the walk finished; search also needs isEnd on the final node.
  4. Cost depends on the query, not on N. Each call touches at most L+1 nodes, whether 10 or 106 words are stored.
O(L)every call
O(total letters × 26)space (array nodes)

Why it works: by construction there is exactly one node per distinct prefix of the inserted words, and the path to it spells that prefix. So "some word starts with p" is the same statement as "the node for p exists", and "p was inserted" is "the node for p exists and is marked as an end". The walk finds that node, if it exists, in |p| steps.

Proof (optional)

Invariant: after any sequence of inserts, the set of nodes equals the set of prefixes of inserted words (including the empty prefix), and isEnd is true exactly on the inserted words. It holds for the empty trie (only the root, the empty prefix). An insert of w creates nodes exactly for the prefixes of w that did not exist yet and marks w, so the invariant still holds. A query walks from the root along p; it reaches a node iff p is a stored prefix, by the invariant. Both answers follow directly.
