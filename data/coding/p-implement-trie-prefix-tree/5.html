Dry run

Eight calls on one trie. The picture is the whole trie after each call; the orange ring marks the node where the walk ended.

  1. The trie starts as a lone root. insert("car") finds no edge for c, then a, then r, so it creates three nodes and marks the last one, r, as a word end (green ring).
  2. insert("cat") reuses c and a (the shared prefix costs nothing) and creates only t. Mark t as a word end.
  3. search("ca") walks c, a and stops on a node that exists but is not a word end. Answer false: "ca" was never inserted, it is only a prefix.
  4. startsWith("ca") does the same walk and only asks whether the walk finished. It did: answer true. The two queries differ in the very last check, nothing else.
  5. search("cart") walks c, a, r, then looks for a child t under r: the slot is empty. Stop at once with false; the rest of the word is never read.
  6. startsWith("cx") fails one level down: c has no child x. A miss costs at most the length of the query.
  7. insert("ca") creates nothing: the path already exists. It only sets the end flag on a. A word can end in the middle of a longer word's path.
  8. search("ca") again: same walk, and now the end flag is set, so the answer is true. Five nodes hold three words.
