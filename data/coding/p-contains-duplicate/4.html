Approaches: brute → better → optimal

Hint 1

If the array were sorted, where would two equal values be?

Hint 2

What structure answers "have I already read this value?" in O(1)?

1. Brute force - compare every pair

Idea: two loops, i < j; return true as soon as nums[i] == nums[j].

O(n2)time
O(1)space

What is wasted: for each value we look for an equal one by scanning. Grouping equal values together (sort) or indexing them (hash) removes that scan. It times out at n = 105.

2. Better - sort, then compare neighbours

Idea: after sorting, equal values sit next to each other, so check a[i] == a[i-1] for every i.

O(n log n)time (the sort)
O(1) to O(n)space (depends on the sort; a copy is O(n))

Why it works: if x occurs twice, every value between the two copies in sorted order is also x, so at least one adjacent pair is equal. Cost to mention: sorting in place changes the caller's array; say so, or sort a copy.

3. Optimal (for time) - one pass with a hash set

seen = set()
for x in nums:
    if x in seen: return True    # second time we meet x
    seen.add(x)
return False
  1. Invariant: before reading index i, seen holds exactly the values of nums[0..i-1].
  2. Check, then insert. If x is already in the set, an earlier index had the same value: a real repeat.
  3. Early exit. The loop stops at the second copy of the first repeated value; with no repeat it reads all n values and returns false.
O(n)time (expected, hashing)
O(n)space (up to n distinct values)

Why it works: let p < q be the first two positions of any repeated value. At step q, nums[p] was inserted at step p and never removed, so the lookup hits. Conversely a hit at step q means an earlier index stored the same value, so true is never wrong. In C++ and Java you can fold the check and the insert into one call: insert(x).second / add(x) return false when x was already there.

The one-liner len(set(nums)) < len(nums) is correct and short (the most-voted community answers show it in every language), but it always builds the whole set; the loop can stop early. Say both, code the loop.
