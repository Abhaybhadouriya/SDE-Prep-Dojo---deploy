Interview questions

Meta gives two problems in 45 minutes. How do you budget the time?

About 3 minutes to clarify and agree on examples, 15 minutes to code and test the first, the same for the second, and a few minutes for complexity and questions. The brute force gets one sentence ("O(n2) by checking every pair; we can do O(n) with a stack"), not five minutes. If the first problem runs long, say so and ask whether to finish or move on.

How to answer

Show the budget, and say that you practise Meta's top 50 on a 20-minute timer each.

Likely follow-ups
  • What do you skip when time is short? (Long brute-force discussion; never testing.)
  • How do you handle an AI-assisted round? (Direct the tool, read every line it writes, test it yourself.)
Minimum Remove to Make Valid Parentheses: can you do it with O(1) extra space?

Yes, with two passes and a counter. Left to right: count open brackets, and drop a ')' when the count is 0. Right to left over the result: count close brackets, and drop a '(' when that count is 0. Each pass removes exactly the brackets that cannot be matched in that direction. The output string itself is O(n), but the extra state is one integer (in C or C++ you can compact in place with a write index).

How to answer

Start from the stack version, then point out the stack only ever needs its size for ')' and the positions of leftover '(' which a reverse pass finds.

Likely follow-ups
  • Return all valid strings with the minimum removals (BFS or backtracking: Remove Invalid Parentheses, Hard).
  • Three bracket types (then a counter is not enough; you need the stack).
Rotting Oranges: why multi-source BFS, and why not run a BFS from each rotten cell?

All rotten cells spread at the same time, so the answer for a fresh cell is its distance to the nearest rotten cell. Putting all sources in the queue at distance 0 computes exactly that in one pass: O(m n) time and space. One BFS per source is O(k m n) and then needs a minimum over sources.

How to answer

Say "nearest source distance = multi-source BFS", then point out the layer loop (minute counter) and the fresh counter for the -1 case.

Likely follow-ups
  • Some fruit take two minutes to rot (0-1 BFS or Dijkstra).
  • Do not change the input grid (copy it, or keep a separate distance grid).
Google asks a problem you have never seen. How do you get to a solution?

Use pattern cues, not memory. Restate the problem, work two small examples by hand, and read the constraints (n up to 105 means O(n log n) at most). Then try each family aloud: sort? hash map? graph? optimal substructure? binary search on the answer? Say why each fails or works.

How to answer

Show a process. Google interviewers score reasoning and communication, not only the final code.

Likely follow-ups
  • What if the input is a stream / does not fit in memory?
  • Can you prove your greedy step?
Alien Dictionary: what are the traps?

Build edges only from the first differing character of each adjacent pair of words. If a word is followed by its own proper prefix ("abc" then "ab"), the order is invalid: return "". Include every letter that appears, even with no edges. Then topological sort (Kahn's algorithm); if the output is shorter than the letter count, there is a cycle: return "". O(total characters).

How to answer

List the three traps before coding: first difference only, prefix case, isolated letters.

Likely follow-ups
  • Return all valid orders (backtracking over zero in-degree nodes).
  • Is the order unique? (Unique if the queue never holds more than one node.)
Koko Eating Bananas: why binary search, and what exactly is monotonic?

The answer is a speed k. The predicate "Koko can finish within h hours at speed k" is monotonic: if it is true for k, it is true for every k' > k. So binary search on k in [1, max(piles)] for the first true. Each check is O(n), total O(n log max). Use (p + k - 1) / k for the ceiling and 64-bit for the hour sum.

How to answer

Write canFinish(k) first and state its monotonicity, then the search. That order is the whole technique.

Likely follow-ups
  • Split Array Largest Sum, Capacity to Ship Packages: same skeleton.
Design problems (LRU, Max Stack, GetRandom O(1)): what do interviewers check first?

That you pick the structures and say the cost of every operation before coding: LRU = hash map to list nodes + doubly linked list, all O(1); GetRandom = array + map of value to index, delete by swapping with the last element; Max Stack = two structures (a list plus a heap or sorted map with lazy deletion), O(log n) per op. Then clean code with helper methods (unlink, pushFront) and a short test.

How to answer

Draw the structure, write the op table, then code. A kernel engineer can mention list_head and why the sentinel node removes all null checks.

Likely follow-ups
  • Make it thread safe (one lock, or lock striping by key).
  • LFU instead of LRU (frequency buckets of lists).
