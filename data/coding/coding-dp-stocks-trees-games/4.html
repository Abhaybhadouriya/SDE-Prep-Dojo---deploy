Tree DP: return a pair from every node

House Robber III (LeetCode 337), told our way: houses form a binary tree, each node holding some cash. A thief may not rob two houses joined by an edge (a parent and its child). Return the most cash he can take. Constraints: 1 to 104 nodes, values between 0 and 104. Example: level order [4, 6, 5, 2, 3, null, 1] gives 11 (rob 6 and 5).

The tempting shortcut "sum the even levels, sum the odd levels, take the bigger" happens to work here (11 against 10) but is wrong in general: on [2, 1, 3, null, 4] it gives 6, while robbing 3 (level 1) and 4 (level 2) gives 7, because the best choice can skip two levels in a row in one branch. The state for a subtree is "is its root robbed or not?", so each DFS call returns two numbers:

  • take = best for this subtree if this node is robbed = val + left.skip + right.skip.
  • skip = best if it is not robbed = max(left.take, left.skip) + max(right.take, right.skip).

Why not memoise "best(node)" and "best(grandchildren)"? You can (that is the first solution in most editorials), but it touches grandchildren from every node. Returning a pair is the same DP with the state made explicit, and it never recomputes anything.

Binary Tree Cameras: three states and a greedy proof

Binary Tree Cameras (LeetCode 968), told our way: you may put a camera on any node of a binary tree; a camera watches its own node, its parent and its children. Return the fewest cameras that watch every node. Constraints: 1 to 1000 nodes. Each DFS call returns one of three states:

  • NOT_COVERED: nobody watches me yet; my parent must place a camera.
  • HAS_CAMERA: I have a camera (so my parent is covered too).
  • COVERED: someone below watches me; I need nothing. A null child counts as COVERED, so leaves never get cameras.

Rule at a node: if any child is NOT_COVERED, put a camera here. Else if any child has a camera, I am COVERED. Else I am NOT_COVERED and pass the job up. At the root, a NOT_COVERED result needs one extra camera. The greedy is safe because a camera on a leaf's parent covers everything a camera on the leaf would cover, and more.

  1. Leftmost leaf: both children are null (COVERED), so it returns NOT_COVERED and asks its parent for help.
  2. The other leaf under the same parent: also NOT_COVERED.
  3. Their parent sees an exposed child, so it takes a camera (1). That camera also watches the root.
  4. The deepest leaf on the right: NOT_COVERED.
  5. Its parent sees an exposed child: camera (2). It also watches the node above it.
  6. The right child of the root: one null child (COVERED) and one child with a camera, so it is COVERED.
  7. The root: one child has a camera, so it is COVERED. It is not NOT_COVERED, so no extra root camera.
  8. Answer 2. Putting cameras on leaves would need 3 or more; pushing them one level up is never worse.
// rob: House Robber III (LC 337); each node returns (best if robbed, best if skipped).
func rob(root *TreeNode) int {
	var dfs func(*TreeNode) (int, int)
	dfs = func(node *TreeNode) (int, int) {
		if node == nil {
			return 0, 0
		}
		lt, ls := dfs(node.Left)
		rt, rs := dfs(node.Right)
		take := node.Val + ls + rs // children must be skipped
		skip := max(lt, ls) + max(rt, rs)
		return take, skip
	}
	take, skip := dfs(root)
	return max(take, skip)
}

// minCameraCover: Binary Tree Cameras (LC 968), greedy-from-leaves tree DP with 3 states.
const (
	notCovered = iota
	covered
	hasCamera
)

func minCameraCover(root *TreeNode) int {
	cams := 0
	var dfs func(*TreeNode) int
	dfs = func(node *TreeNode) int {
		if node == nil {
			return covered // null needs nothing and wants nothing
		}
		l, r := dfs(node.Left), dfs(node.Right)
		if l == notCovered || r == notCovered { // a child is exposed: camera here
			cams++
			return hasCamera
		}
		if l == hasCamera || r == hasCamera {
			return covered
		}
		return notCovered // let the parent cover me
	}
	if dfs(root) == notCovered { // the root has no parent to help
		cams++
	}
	return cams
}
// House Robber III (LC 337): each node returns {best if robbed, best if skipped}.
pair<int, int> robDfs(TreeNode* node) {
    if (!node) return {0, 0};
    auto l = robDfs(node->left), r = robDfs(node->right);
    int take = node->val + l.second + r.second;          // children must be skipped
    int skip = max(l.first, l.second) + max(r.first, r.second);
    return {take, skip};
}
int rob(TreeNode* root) {
    auto res = robDfs(root);
    return max(res.first, res.second);
}

// Binary Tree Cameras (LC 968), greedy-from-leaves tree DP with 3 states.
enum { NOT_COVERED = 0, COVERED = 1, HAS_CAMERA = 2 };
int camDfs(TreeNode* node, int& cams) {
    if (!node) return COVERED;                       // null needs nothing and wants nothing
    int l = camDfs(node->left, cams), r = camDfs(node->right, cams);
    if (l == NOT_COVERED || r == NOT_COVERED) {      // a child is exposed: camera here
        cams++;
        return HAS_CAMERA;
    }
    if (l == HAS_CAMERA || r == HAS_CAMERA) return COVERED;
    return NOT_COVERED;                              // let the parent cover me
}
int minCameraCover(TreeNode* root) {
    int cams = 0;
    if (camDfs(root, cams) == NOT_COVERED) cams++;   // the root has no parent to help
    return cams;
}

static int[] robDfs(TreeNode node) {
    if (node == null) return new int[]{0, 0};
    int[] l = robDfs(node.left), r = robDfs(node.right);
    int take = node.val + l[1] + r[1];               // children must be skipped
    int skip = Math.max(l[0], l[1]) + Math.max(r[0], r[1]);
    return new int[]{take, skip};
}
static int rob(TreeNode root) {
    int[] res = robDfs(root);
    return Math.max(res[0], res[1]);
}

Say the states out loud before coding: "each call returns (robbed, not robbed)" or "each call returns one of three coverage states". Interviewers grade the state definition more than the code. Many follow-ups (Maximum Path Sum, Diameter, Longest ZigZag, Distribute Coins) are the same shape: return what the parent needs, update a global answer at each node.
