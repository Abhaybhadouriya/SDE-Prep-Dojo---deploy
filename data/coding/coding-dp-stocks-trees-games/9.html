Common mistakes

  • Updating states with today's values when the formula needs yesterday's. In the cooldown machine, rest = max(rest, sold) must read yesterday's sold. Use a tuple assignment or temporaries. (In Stock I-IV in-place updates happen to be safe; know why.)
  • Initialising "holding" to 0. Holding a share you never bought is impossible: start it at minus infinity (or -prices[0]). In C/Java/Go use a large negative like INT_MIN / 2 so hold + price cannot overflow.
  • Forgetting the k >= n/2 guard in Stock IV: an O(n k) loop or a k-sized allocation with a huge k.
  • Answering max(hold, ...) at the end: you must finish without a share.
  • Tree DP that calls the child DFS twice (once for take, once for skip). It turns O(n) into exponential. Call each child once and use both returned numbers.
  • Cameras: forgetting the root. If the root returns NOT_COVERED, add one camera.
  • Game DP with two separate scores and a min/max alternation that gets the turn order wrong. Use the difference and one max.
  • Job scheduling: end < start instead of end <= start, or a binary search over all jobs instead of only the first i - 1.
