Game DP: store the score difference, not two scores

Predict the Winner (LeetCode 486), told our way: a row of numbered cards lies on a table. Two players take turns, player 1 first; on each turn a player takes the card at the left end or the right end and adds it to their score. Both play perfectly. Return true if player 1 finishes with a score at least as large as player 2's (a tie counts as a win for player 1). Constraints: 1 <= n <= 20, values between 0 and 107. Example: [3, 8, 100, 6] is true; [2, 9, 4] is false.

The trap is to track "my score" and "your score" separately and alternate between max and min. The clean state is one number: diff[i][j] = (score of the player about to move) minus (the other player's score), when only cards i..j are left. After I take a card, the roles swap, so the opponent's best difference is subtracted:

diff[i][i] = nums[i]
diff[i][j] = max(nums[i] - diff[i+1][j],   # take the left card
                 nums[j] - diff[i][j-1])   # take the right card
player 1 wins  <=>  diff[0][n-1] >= 0

This is the minimax in one max trick (negamax). It works for any zero-sum, perfect-information, two-player game where both players have the same moves: Stone Game, Stone Game II (state adds M), Stone Game III (take 1 to 3 from the front), Stone Game VII. The table is filled by interval length, shortest first:

  1. Fill the diagonal: with one card left, the player to move takes it.
  2. Cards [3, 8]: taking 8 leaves the opponent the 3, so the mover is 5 ahead.
  3. Cards [8, 100]: take 100, lead by 92.
  4. Cards [100, 6]: take 100, lead by 94.
  5. Cards [3, 8, 100]: taking 100 (right) leaves [3, 8] where the opponent leads by 5, so the mover leads by 95.
  6. Cards [8, 100, 6]: either end hands 100 to the opponent; the mover is behind by 86 whatever they do.
  7. All four: taking the 3 hands the opponent that losing position, so player 1 leads by 89. Counter-intuitive: the best first move is the smallest card.

Only the row below and the cell to the left are read, so one 1D array is enough (iterate i from n-2 down, j from i+1 up). The template does exactly that.

// predictTheWinner (LC 486): diff[i][j] = (my score - your score) on nums[i..j], I move first.
func predictTheWinner(nums []int) bool {
	n := len(nums)
	diff := append([]int(nil), nums...) // length-1 intervals: diff[i][i] = nums[i]
	for i := n - 2; i >= 0; i-- {        // row i, reusing row i+1 in place
		for j := i + 1; j < n; j++ {
			diff[j] = max(nums[i]-diff[j], // take left: opponent plays on i+1..j
				nums[j]-diff[j-1]) // take right: opponent plays on i..j-1
		}
	}
	return diff[n-1] >= 0 // a tie counts as a win for player 1
}

bool predictTheWinner(const vector<int>& nums) {

def predict_the_winner(nums: List[int]) -> bool:
    """LC 486: diff[i][j] = (my score - your score) on nums[i..j], I move first."""
    n = len(nums)
    diff = nums[:]  # length-1 intervals: diff[i][i] = nums[i]
    for i in range(n - 2, -1, -1):  # row i, reusing row i+1 in place
        for j in range(i + 1, n):
            diff[j] = max(nums[i] - diff[j],  # take left: opponent plays on i+1..j
                          nums[j] - diff[j - 1])  # take right: opponent plays on i..j-1
    return diff[n - 1] >= 0  # a tie counts as a win for player 1

For an even number of cards (Stone Game, LeetCode 877), player 1 can always take all even-indexed or all odd-indexed cards, whichever sum is bigger, so the answer is always true. Interviewers like asking "why" after you code the DP.
