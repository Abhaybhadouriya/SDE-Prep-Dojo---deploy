At most k transactions: a chain of 2k states

Stock IV (LeetCode 188), told our way: an integer k and daily prices; you may complete at most k buy-sell transactions, holding at most one share at a time. Return the maximum profit. Constraints: 1 <= k <= 100, 1 <= n <= 1000, prices between 0 and 1000. Stock III (LeetCode 123) is the same with k = 2 and n up to 105.

Now the state must remember how many transactions you have used. Unroll the machine into a chain: each transaction is one "buy" state and one "sell" state, and you can only move right.

The bold 4 is the moment the machine "decides" to take its first profit (5) and buy again at 1: sell[1] - 1 = 4. Updating the states in place, left to right, within one day is safe: it can only add "buy and sell on the same day", which earns 0 and never beats a real option.

The big-k guard. A transaction needs two different days, so at most n / 2 transactions can ever help. If k >= n / 2, k does not bind: return the Stock II answer. This turns O(n k) with a huge k into O(n). Today's LeetCode limit is k <= 100, but interviewers often ask "what if k is 109?" to see whether you allocate a k-sized array.

// maxProfitK: at most k transactions (LC 188). k = 1 is LC 121, k = 2 is LC 123.
func maxProfitK(k int, prices []int) int {
	n := len(prices)
	if k >= n/2 { // k never binds: take every rise (LC 122)
		profit := 0
		for i := 1; i < n; i++ {
			profit += max(0, prices[i]-prices[i-1])
		}
		return profit
	}
	// buy[j]  = best cash while holding a share in transaction j
	// sell[j] = best cash after finishing j transactions
	buy, sell := make([]int, k+1), make([]int, k+1)
	for j := range buy {
		buy[j] = math.MinInt32
	}
	for _, p := range prices {
		for j := 1; j <= k; j++ {
			buy[j] = max(buy[j], sell[j-1]-p) // stay holding, or buy today
			sell[j] = max(sell[j], buy[j]+p)  // stay sold, or sell today
		}
	}
	return sell[k]
}

def max_profit_k(k: int, prices: List[int]) -> int:
    """At most k transactions (LC 188). k = 1 is LC 121, k = 2 is LC 123."""
    n = len(prices)
    if k >= n // 2:  # k never binds: take every rise (LC 122)
        return sum(max(0, prices[i] - prices[i - 1]) for i in range(1, n))
    # buy[j]  = best cash while holding a share in transaction j
    # sell[j] = best cash after finishing j transactions
    buy = [float("-inf")] * (k + 1)
    sell = [0] * (k + 1)
    for p in prices:
        for j in range(1, k + 1):
            buy[j] = max(buy[j], sell[j - 1] - p)  # stay holding, or buy today
            sell[j] = max(sell[j], buy[j] + p)  # stay sold, or sell today
    return sell[k]

From your world

The state tables here are tiny arrays you overwrite every iteration, like a per-CPU counter block or the struct tcp_sock fields that only keep the latest smoothed RTT. You never store the whole history; you store the summary that the next step needs. If you ever see an O(n x states) table in your answer, ask yourself whether only the previous row is read. Usually it is, and the table collapses to O(states).
