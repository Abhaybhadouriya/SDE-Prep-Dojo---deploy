How to recognise these shapes

  • "Buy / sell", "at most k times", "cooldown", "fee", "must wait after": state machine. List the situations you can be in at the end of a step (holding, resting, j transactions used), draw arrows, read the max off the arrows.
  • A rule that depends on the previous choice ("no two adjacent", "cannot paint two neighbours the same colour", "alternating signs"): a state per choice (Paint House, Maximum Alternating Subsequence Sum, Delete and Earn after counting).
  • A tree plus "pick nodes with a rule about parent and child": DFS that returns a pair (or a small tuple) per node. Cameras, robbery, coins, BST checks inside a path sum.
  • Two players, "both play optimally", take from the ends or from the front: game DP with the score difference as the value. Answer "wins" means difference > 0 (or >= 0 if ties win).
  • Intervals with weights, pick non-overlapping, times up to 109: sort by end, dp over prefixes, binary search for the last compatible job. If the count of picks is limited (Maximum Number of Events II), add a dimension k.
  • n <= 20 and a game where any item can be taken (Can I Win): the state is a bitmask of what is used, see Bitmask DP.
