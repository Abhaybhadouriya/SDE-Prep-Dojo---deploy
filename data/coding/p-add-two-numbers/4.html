Approaches: brute -> better -> optimal

Hint 1

What order do you add digits in on paper? Which digit is at the head?

Hint 2

How large can digit + digit + carry be, and what does that say about the next carry?

1. Brute force - convert to integers, add, convert back

Idea: read each list into a number (digit × 10^position), add, then write the digits of the sum ones-first into a new list.

O(m + n)time
overflowsat 20+ digits in 64-bit

What is wasted: it only works with big-integer types (Python, Java BigInteger), and even then you build two huge numbers just to take them apart again. In C++, C or Go it gives wrong answers beyond 19 digits. Interviewers want the digit-wise version.

2. Better - recursion with a carry argument

Idea: add(a, b, carry) makes one node for (a.val + b.val + carry) % 10 and sets its next to add(a.next, b.next, newCarry); it stops when both lists are null and carry is 0.

O(max(m, n))time
O(max(m, n))stack depth

What is wasted: a stack frame per digit. Correct and neat, but the loop does the same with O(1) extra space.

3. Optimal - one pass with a carry and a dummy head

while a or b or carry:
    total = carry + (a.val if a else 0) + (b.val if b else 0)
    carry, digit = divmod(total, 10)
    tail.next = ListNode(digit); tail = tail.next
    a = a.next if a else None; b = b.next if b else None
  1. Add position by position from the head. The head is the ones digit, so the list order is the order of schoolbook addition.
  2. A finished list counts as 0. That handles different lengths without a second loop.
  3. The carry is 0 or 1. The largest column sum is 9 + 9 + 1 = 19.
  4. Loop while the carry is set, too. 999 + 1 needs a fourth digit that neither input has.
  1. Both numbers are stored backwards: a = 7 → 4 → 9 is 947, b = 5 → 6 is 65. The head is the ones digit, so we can add from the head. carry = 0.
  2. Ones: 7 + 5 + 0 = 12. Write 2, carry 1. The new node goes after the dummy.
  3. Tens: 4 + 6 + 1 = 11. Write 1, carry 1.
  4. Hundreds: b has run out, so it counts as 0. 9 + 0 + 1 = 10. Write 0, carry 1.
  5. Both lists are empty but carry = 1, so the loop runs once more and writes 1. Without the carry check the answer would lose its top digit.
  6. Done: the result list 2 → 1 → 0 → 1 is 1012 written backwards, which is 947 + 65. One pass, one node per output digit.
O(max(m, n))time: one step per output digit
O(1)extra space (output not counted)

Why it works: after processing i positions, the output holds the lowest i digits of the true sum and carry is the amount (0 or 1) that those positions pass to position i. That is exactly the invariant of long addition, so when both inputs and the carry are exhausted, the output is the whole sum.

Proof (optional)

Let A and B be the numbers and S_i = (A mod 10^i) + (B mod 10^i). Claim: after i steps the output is S_i mod 10^i (as digits) and carry = floor(S_i / 10^i). Step i + 1 adds a_i + b_i + carry, which is the i-th column of S_(i+1) plus what the lower columns pass up; its last digit is digit i of the sum and its tens part (0 or 1) is the new carry. When both lists are done and carry = 0, S_i = A + B.
