The digits are stored most significant first. Now what?

Three options: reverse both lists, add as here, reverse the result (O(1) extra but it modifies the input); push the digits onto two stacks and pop while adding, inserting each new node at the head (O(m + n) extra, inputs untouched); or pad the shorter list and recurse so the carry comes back up the call stack.

How to answer

Ask whether you may modify the input, then pick reversal (yes) or stacks (no).

Likely follow-ups
  • This is LC 445; the stack version is the usual expected answer.
Can you avoid allocating new nodes?

Yes: write the sums into the nodes of the longer list (or of l1, switching to l2's nodes when l1 runs out) and allocate only one node if a final carry is left. Extra space is O(1) including the output, but the inputs are destroyed, so say that trade-off out loud.

How to answer

Offer it as an option and name the cost: the caller loses the original lists.

Likely follow-ups
  • What if the caller still needs l1? (Then allocate; the output is O(max(m, n)) anyway.)
Subtract the two numbers instead (A ≥ B).

Same walk with a borrow: d = a - b - borrow; if d < 0, add 10 and set borrow = 1. At the end, strip leading zeros, which are now at the tail of the list (keep at least one node).

How to answer

Borrow replaces carry; the new edge case is trailing zero nodes.

Likely follow-ups
  • What if you do not know which is larger? (Compare lengths, then digits from the most significant end, and swap.)
Make it work in any base, or add k numbers at once.

Replace 10 by the base; the carry stays below the base. For k numbers, walk all k lists together; the carry can now be up to k - 1, so keep it as an int and use carry, d = divmod(total, base), which still works.

How to answer

Show the only change is the size of the carry.

Likely follow-ups
  • How big can the carry get for k numbers? (At most k - 1 in base 10 with digit sums.)
Why not just convert to integers in Python?

It works in Python and with Java BigInteger, but it is not what is being tested, it does not port to C++ or Go, and it builds two big numbers only to split them again. Mention it in one sentence, then code the digit loop.

How to answer

Acknowledge it, name the 64-bit limit (about 19 digits), move on.

Likely follow-ups
  • What is the cost of big-integer addition? (Also linear in the number of digits.)
