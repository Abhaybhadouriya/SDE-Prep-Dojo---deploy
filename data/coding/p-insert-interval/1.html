The problem (in our words)

You get an array intervals of booked blocks, where intervals[i] = [starti, endi]. The blocks do not overlap and are sorted in increasing order of starti. You also get one more block newInterval = [start, end]. Two blocks overlap if they share at least one point (so [1,4] and [4,6] overlap). Insert newInterval so that the list stays sorted by start and still has no overlapping blocks, merging blocks where needed, and return the resulting list. You may build and return a new array; changing the input in place is not required.

Signature: int[][] insert(int[][] intervals, int[] newInterval).

  • 0 <= intervals.length <= 104
  • intervals[i].length == 2
  • 0 <= starti <= endi <= 105
  • intervals is sorted by starti in ascending order.
  • newInterval.length == 2
  • 0 <= start <= end <= 105

Practice it: LeetCode 57 · GfG Insert Interval · TUF article

Constraints tell you: the list can be empty (length 0), which Merge Intervals never allows. It is already sorted and disjoint, so re-sorting (O(n log n)) is a hint you missed the point: O(n) is expected, and O(log n) to find the spot with binary search is a common follow-up (the copy is still O(n)). Values ≤ 105 fit in any int.
