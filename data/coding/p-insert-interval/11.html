Interview follow-ups

Can you find where the merge starts and ends in O(log n)?

Yes: binary search the first interval with end >= lo (ends are sorted too) and the first with start > hi. Everything between them merges with the new one. The search is O(log n), but building the output array is still O(n), so it only pays off when the structure supports splicing (a balanced tree, a linked list, or an in-place erase of a range).

How to answer

Say why the ends are sorted (disjoint + sorted starts), then state that the copy dominates.

Likely follow-ups
  • Which library call? bisect, lower_bound with a comparator on end, Collections.binarySearch.
Many inserts arrive over time (a booking system). How do you keep it fast?

Store the disjoint blocks in an ordered map keyed by start (TreeMap, std::map). For each insert, look at the floor entry and walk forward over entries with start <= hi, deleting them, then put one merged entry. Each entry is deleted at most once, so the cost is amortised O(log n) per insert. That is Range Module / Data Stream as Disjoint Intervals.

How to answer

Point out that the array version is O(n) per insert because of the copy.

Likely follow-ups
  • Also support delete and "is [a, b] fully covered?" queries.
Do it in place, with O(1) extra space.

Find the run [i, j) that merges. Write the merged block to intervals[i], then shift the tail left by j - i - 1 (or right by one when nothing merged, which needs one extra slot). O(n) time, O(1) extra. In Java with int[][] you cannot resize, so the new array is the honest answer.

How to answer

Ask which container you have; then pick erase-range (C++ vector::erase) or a new array.

Likely follow-ups
  • Python: slice assignment a[i:j] = [[lo, hi]] does it in one line.
Touching blocks should not merge (half-open bookings [start, end)).

Change both tests: copy left while end <= lo, absorb while start < hi. Clarify this before you code; the default here is closed intervals.

How to answer

Name the convention and show the two changed comparisons.

Likely follow-ups
  • Reject the booking instead of merging if it overlaps anything (My Calendar I).
Insert k new intervals at once.

Sort the k new ones (O(k log k)), then do a two-list merge with the existing sorted list, feeding the Merge Intervals sweep: O(n + k log k). Calling the single insert k times is O(n·k).

How to answer

Compare the two costs; pick the merge when k is large.

Likely follow-ups
  • k is tiny and the list is huge: binary search each insert point instead.
