Common mistakes

Forgetting to output the new block when nothing overlaps. If you only emit inside the merge loop, an insert into a gap disappears. Emit it once, after phase 2, always.

Wrong strictness. Phase 1 must use end < lo and phase 2 start <= hi. With <= / < the touching case [3,5] + [5,7] comes out as two blocks.

Comparing with the new interval's original end after it has grown. Use the running hi; it is harmless here (see the proof) but in the general "merge as you go" code it is the bug.

Setting lo = start instead of min(lo, start). With [[1,9]], [3,4] that is right, but with [[4,6]], [1,5] it would turn the block into [4,6].

Inserting into the input array in a loop (Java ArrayList.add(i, x) / remove, Python list.insert / pop(i)). Each one shifts the tail, so the "one pass" becomes O(n²). Build a new list.
