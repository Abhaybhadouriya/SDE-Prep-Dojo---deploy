Approaches: brute → better → optimal

Hint 1

Two words far apart in the list: do they tell you anything that their neighbours in between do not? (Sorting is transitive.)

Hint 2

Once you have "x before z" style facts, this is Course Schedule II with letters as courses.

1. Brute force - try every alphabet

Idea: generate every permutation of the m distinct letters, and for each one check whether words is sorted under it.

O(m! · C)time (m letters, C characters)
O(m)space

What is wasted: 26! is about 4·1026. The words only ever constrain a few letter pairs; we should read those constraints directly instead of guessing. -> rung 2.

2. Better - all pairs of words

Idea: compare every pair (i, j) with i < j, take the first differing letter as an edge, then topologically sort.

O(n2 · L)time (n words of length L)
O(1)extra (26 x 26)

What is wasted: a rule from words i and j (not neighbours) is already implied by the chain of neighbours between them, because "sorted" is transitive. Only the n - 1 adjacent pairs matter. -> rung 3.

3. Optimal - adjacent pairs + Kahn's algorithm

for a, b in zip(words, words[1:]):
    for x, y in zip(a, b):
        if x != y: add_edge(x, y); break      # only the first difference
    else:
        if len(a) > len(b): return ""         # longer word before its prefix
order = kahn(letters)                         # BFS over in-degree-0 letters
return order if len(order) == len(letters) else ""
  1. Graph: nodes = every letter that appears (even letters with no rules); edge x -> y when x must come before y.
  2. Rules: for each adjacent pair, the first position where they differ gives one edge; equal prefixes with a longer first word return "" at once.
  3. Dedupe: the same rule can appear twice; increase the in-degree only for a new edge (a 26 x 26 boolean matrix does this for free).
  4. Traversal: Kahn's BFS: queue all letters with in-degree 0; pop one, append it, decrement its neighbours, enqueue the ones that reach 0.
  5. Answer: if all m letters were output, that is the alphabet; if some letters never reached in-degree 0, they sit on a cycle: return "".
O(C + 262)time, C = total characters
O(262)space

Why it works: lexicographic order is decided pair by pair at the first difference, and a list is sorted exactly when every adjacent pair is in order. So "words is sorted under alphabet P" is equivalent to "P satisfies every adjacent-pair rule and no prefix pair is reversed". Those rules are the edges, so a valid alphabet is exactly a topological order of the graph, which exists if and only if the graph has no cycle, and Kahn's algorithm finds one or proves the cycle by getting stuck.

DFS alternative

Post-order DFS with three colours (unvisited, on the current path, finished): reaching a node that is on the current path is a cycle. Reverse the finish order to get the alphabet. Same complexity; Kahn is easier to explain and has no recursion depth to think about.
