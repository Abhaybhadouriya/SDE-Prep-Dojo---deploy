Interview follow-ups

Is the alphabet unique? Return it only if it is.

In Kahn's loop, if the queue ever holds two or more letters, either could go next, so the order is not unique. A unique order exists exactly when the queue size is 1 at every step (equivalently, the order is a Hamiltonian path of the DAG: each consecutive pair is joined by an edge).

How to answer

Point to the queue size; that is a one-line change.

Likely follow-ups
  • Count how many valid alphabets exist? (Counting topological orders is #P-hard in general; for 26 letters a bitmask DP over subsets works.)
Use DFS instead of BFS. How do you detect the cycle?

Three colours: 0 = unvisited, 1 = on the current DFS path, 2 = done. Visiting a colour-1 node means a back edge, so a cycle. Append a node when it finishes, then reverse the list (or build edges reversed and skip the reverse).

How to answer

Say why two colours are not enough: a finished node reached again is fine, a node on the path is not.

Likely follow-ups
  • Recursion depth? At most 26 here, so no issue.
Why is it enough to compare only adjacent words?

Sorted order is transitive: if w1 ≤ w2 ≤ ... ≤ wj pair by pair, then w1 ≤ wj. Every rule that a non-adjacent pair would give follows from the chain of adjacent rules, so it adds no new constraint, only a redundant edge.

How to answer

Give the transitivity argument in one sentence, then the cost saving (n - 1 pairs instead of n²/2).

Likely follow-ups
  • Can a non-adjacent pair ever reveal a contradiction the adjacent pairs miss? (No, by the same argument.)
The alphabet is huge (Unicode) and the dictionary has 106 words.

Replace the 26 x 26 matrix by a hash map from letter to a set of next letters and a hash map of in-degrees. Time becomes O(C + E) with E ≤ n - 1 edges. For a dictionary that does not fit in memory, stream it: you only ever need the previous word to produce the next rule.

How to answer

Notice that rule extraction is a streaming pass with O(one word) memory; only the graph is kept.

Likely follow-ups
  • How much memory does the graph need? At most one edge per adjacent pair.
Return the smallest valid alphabet in normal a-z order.

Use a min-heap instead of a FIFO queue in Kahn's algorithm: always output the smallest available letter. That gives the lexicographically smallest topological order, at O(log 26) per pop.

How to answer

Swap the queue for a priority queue; everything else stays.

Likely follow-ups
  • Why does DFS not give this easily? Its order depends on the finish times, not on a greedy choice.
