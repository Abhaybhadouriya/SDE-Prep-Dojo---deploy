Two keys, two structures: IPO and friends

Problem (restated from LeetCode 502, IPO). A small company has starting capital w and may finish at most k projects before going public. Project i can be started only if current capital is at least capital[i]; finishing it adds profits[i] to the capital (the capital needed is not spent). Projects are done one at a time. Return the largest capital possible after at most k projects. Example: k = 2, w = 0, profits = [1, 2, 3], capital = [0, 1, 1] gives 4 (do the free project for +1, then the +3 one). Limits: 1 <= k, n <= 105, 0 <= w <= 109, 0 <= profits[i] <= 104, 0 <= capital[i] <= 109; the answer fits in a 32-bit signed int.

Two different keys decide things here. Capital decides what you may take. Profit decides what you want. One heap cannot be ordered by both. So split the projects by state: locked ones in an array sorted by capital (a pointer marks how far you can afford), and unlocked ones in a max-heap by profit.

Why greedy is right. Capital never goes down. Taking the largest available profit gives the largest new w, and a larger w unlocks a superset of the projects a smaller w would unlock. So any plan that starts with a smaller profit can be changed to start with the larger one and do at least as well (the exchange argument). If the heap is empty before k rounds, stop: nothing is affordable, and waiting will not change that.

// Locked projects sorted by capital; unlocked ones in a max-heap of profit.
func findMaximizedCapital(k, w int, profits, capital []int) int {
	idx := make([]int, len(profits))
	for i := range idx {
		idx[i] = i
	}
	sort.Slice(idx, func(a, b int) bool { return capital[idx[a]] < capital[idx[b]] })
	avail := &MaxInt{}
	i := 0
	for ; k > 0; k-- {
		for i < len(idx) && capital[idx[i]] <= w { // unlock everything we can afford
			heap.Push(avail, profits[idx[i]])
			i++
		}
		if avail.Len() == 0 {
			break // nothing affordable: stop early
		}
		w += heap.Pop(avail).(int) // take the biggest profit
	}
	return w
}
// Locked projects sorted by capital; unlocked ones in a max-heap of profit.
int findMaximizedCapital(int k, int w, const vector<int>& profits, const vector<int>& capital) {
    int n = profits.size();
    vector<pair<int, int>> proj(n);                      // (capital, profit)
    for (int i = 0; i < n; i++) proj[i] = {capital[i], profits[i]};
    sort(proj.begin(), proj.end());
    priority_queue<int> avail;
    int i = 0;
    while (k-- > 0) {
        while (i < n && proj[i].first <= w) avail.push(proj[i++].second);  // unlock what we can afford
        if (avail.empty()) break;                        // nothing affordable: stop early
        w += avail.top(); avail.pop();                   // take the biggest profit
    }
    return w;
}
// Locked projects sorted by capital; unlocked ones in a max-heap of profit.
static int findMaximizedCapital(int k, int w, int[] profits, int[] capital) {
    int n = profits.length;
    Integer[] idx = new Integer[n];
    for (int i = 0; i < n; i++) idx[i] = i;
    Arrays.sort(idx, (a, b) -> Integer.compare(capital[a], capital[b]));
    PriorityQueue<Integer> avail = new PriorityQueue<>(Collections.reverseOrder());
    int i = 0;
    while (k-- > 0) {
        while (i < n && capital[idx[i]] <= w) avail.offer(profits[idx[i++]]);  // unlock
        if (avail.isEmpty()) break;            // nothing affordable: stop early
        w += avail.poll();                     // take the biggest profit
    }
    return w;
}
def find_maximized_capital(k, w, profits, capital):
    """Locked projects sorted by capital; unlocked ones in a max-heap of profit."""
    projects = sorted(zip(capital, profits))
    avail, i = [], 0
    for _ in range(k):
        while i < len(projects) and projects[i][0] <= w:   # unlock everything we can afford now
            heapq.heappush(avail, -projects[i][1])
            i += 1
        if not avail:
            break                                          # nothing affordable: more rounds will not help
        w -= heapq.heappop(avail)                          # take the biggest profit
    return w

Time O(n log n) for the sort plus O(k log n) for the heap. Space O(n).

Sort by one key, heap the other

The same split solves a family of Hard problems where a group's cost or score is set by its worst member on one key and by a sum on the other. Sort by the "worst member" key so that, as you scan, the current item is always the worst so far. Keep a heap of the other key, limited to size k, and a running sum.

Problem (restated from LeetCode 857, Minimum Cost to Hire K Workers). There are n workers; worker i has a quality and a minimum wage expectation. Hire exactly k of them so that (a) each hired worker is paid in proportion to their quality compared with the others in the group, and (b) each is paid at least their minimum. Return the least total pay, as a double (answers within 10-5 are accepted). Example: quality [10, 20, 5], wage [70, 50, 30], k = 2 costs 105.0 (hire worker 0 at 70 and worker 2 at 35). Limits: 1 <= k <= n <= 104, 1 <= quality, wage <= 104.

In any valid group, everyone is paid at the same rate per unit of quality, and that rate must satisfy the most demanding worker: rate = max(wage / quality) over the group. Cost = rate × (sum of qualities). Sort workers by wage / quality. Scan; the current worker is the "captain" whose ratio sets the rate. Among the workers seen so far, you want the k smallest qualities: keep them in a max-heap of size k and pop the largest when it grows past k.

// Sort by wage/quality ratio (the "captain" sets the rate); keep the k smallest qualities in a max-heap.
func mincostToHireWorkers(quality, wage []int, k int) float64 {
	idx := make([]int, len(quality))
	for i := range idx {
		idx[i] = i
	}
	ratio := func(i int) float64 { return float64(wage[i]) / float64(quality[i]) }
	sort.Slice(idx, func(a, b int) bool { return ratio(idx[a]) < ratio(idx[b]) })
	h := &MaxInt{}
	qsum, best := 0, math.MaxFloat64
	for _, i := range idx {
		heap.Push(h, quality[i])
		qsum += quality[i]
		if h.Len() > k {
			qsum -= heap.Pop(h).(int) // drop the largest quality
		}
		if h.Len() == k {
			best = math.Min(best, ratio(i)*float64(qsum))
		}
	}
	return best
}
// Sort by wage/quality ratio (the "captain" sets the rate); keep the k smallest qualities in a max-heap.
double mincostToHireWorkers(const vector<int>& quality, const vector<int>& wage, int k) {
    int n = quality.size();
    vector<pair<double, int>> w(n);                      // (ratio, quality)
    for (int i = 0; i < n; i++) w[i] = {(double)wage[i] / quality[i], quality[i]};
    sort(w.begin(), w.end());
    priority_queue<int> h;
    long long qsum = 0;
    double best = 1e18;
    for (auto& p : w) {
        h.push(p.second); qsum += p.second;
        if ((int)h.size() > k) { qsum -= h.top(); h.pop(); }   // drop the largest quality
        if ((int)h.size() == k) best = min(best, p.first * qsum);
    }
    return best;
}
// Sort by wage/quality ratio (the "captain" sets the rate); keep the k smallest qualities in a max-heap.
static double mincostToHireWorkers(int[] quality, int[] wage, int k) {
    int n = quality.length;
    double[][] w = new double[n][2];                 // (ratio, quality)
    for (int i = 0; i < n; i++) w[i] = new double[]{(double) wage[i] / quality[i], quality[i]};
    Arrays.sort(w, (x, y) -> Double.compare(x[0], y[0]));
    PriorityQueue<Integer> h = new PriorityQueue<>(Collections.reverseOrder());
    long qsum = 0;
    double best = Double.MAX_VALUE;
    for (double[] p : w) {
        h.offer((int) p[1]); qsum += (int) p[1];
        if (h.size() > k) qsum -= h.poll();          // drop the largest quality
        if (h.size() == k) best = Math.min(best, p[0] * qsum);
    }
    return best;
}
def mincost_to_hire_workers(quality, wage, k):
    """Sort by ratio wage/quality (the 'captain' sets the pay rate), keep the k smallest qualities
    in a max-heap. cost = ratio * sum(quality of the group)."""
    workers = sorted((w / q, q) for q, w in zip(quality, wage))
    h, qsum, best = [], 0, float("inf")
    for ratio, q in workers:
        heapq.heappush(h, -q)
        qsum += q
        if len(h) > k:
            qsum += heapq.heappop(h)       # drop the largest quality (stored negated)
        if len(h) == k:
            best = min(best, ratio * qsum)
    return best

The same skeleton solves Maximum Performance of a Team (sort by efficiency descending, min-heap of the k largest speeds, score = speed sum × current efficiency; teams of up to k members, 64-bit sums, and the answer is returned modulo 109 + 7, so take the max before the mod) and Maximum Subsequence Score (identical shape with exactly k).

From your world

IPO is admission control: requests wait in a queue sorted by the resource they need, and as a budget grows, newly admissible ones join a ready queue sorted by value. Schedulers that separate a "blocked" set from a "runnable" set ordered by priority have the same shape.
