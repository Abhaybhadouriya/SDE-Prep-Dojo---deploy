k-way merge: a heap of heads

Merging k sorted lists is the base case. The heap primer covers it with arrays; here is the linked-list version interviewers ask, then two problems that look different but are the same machine.

Problem (restated from LeetCode 23, Merge k Sorted Lists). You get an array of k singly linked lists, each sorted in ascending order. Join them all into one sorted linked list and return its head. Example: [3 -> 5 -> 8], [1 -> 6], [2 -> 7 -> 9] becomes 1 -> 2 -> 3 -> 5 -> 6 -> 7 -> 8 -> 9. Limits: 0 <= k <= 104, each list has 0 to 500 nodes, values are in [-104, 104], and the total number of nodes is at most 104. Lists may be empty, and the whole array may be empty.

// Heap of list heads ordered by value. O(N log k).
type NodeHeap []*ListNode

func (h NodeHeap) Len() int            { return len(h) }
func (h NodeHeap) Less(i, j int) bool  { return h[i].Val < h[j].Val }
func (h NodeHeap) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *NodeHeap) Push(x interface{}) { *h = append(*h, x.(*ListNode)) }
func (h *NodeHeap) Pop() interface{} {
	old := *h
	x := old[len(old)-1]
	*h = old[:len(old)-1]
	return x
}

func mergeKLists(lists []*ListNode) *ListNode {
	h := &NodeHeap{}
	for _, l := range lists {
		if l != nil {
			*h = append(*h, l)
		}
	}
	heap.Init(h)
	dummy := &ListNode{}
	tail := dummy
	for h.Len() > 0 {
		node := heap.Pop(h).(*ListNode)
		tail.Next = node
		tail = node
		if node.Next != nil {
			heap.Push(h, node.Next)
		}
	}
	return dummy.Next
}
// Heap of list heads ordered by value. O(N log k).
ListNode* mergeKLists(vector<ListNode*>& lists) {
    auto cmp = [](ListNode* a, ListNode* b) { return a->val > b->val; };  // "a below b" = min-heap
    priority_queue<ListNode*, vector<ListNode*>, decltype(cmp)> h(cmp);
    for (ListNode* l : lists) if (l) h.push(l);
    ListNode dummy(0), *tail = &dummy;
    while (!h.empty()) {
        ListNode* node = h.top(); h.pop();
        tail->next = node; tail = node;
        if (node->next) h.push(node->next);
    }
    return dummy.next;
}
// Heap of list heads ordered by value. O(N log k).
static ListNode mergeKLists(ListNode[] lists) {
    PriorityQueue<ListNode> h = new PriorityQueue<>((a, b) -> Integer.compare(a.val, b.val));
    for (ListNode l : lists) if (l != null) h.offer(l);
    ListNode dummy = new ListNode(0), tail = dummy;
    while (!h.isEmpty()) {
        ListNode node = h.poll();
        tail.next = node; tail = node;
        if (node.next != null) h.offer(node.next);
    }
    return dummy.next;
}
def merge_k_lists(lists):
    """Heap holds one (value, tiebreak, node) head per list. O(N log k)."""
    h = [(node.val, i, node) for i, node in enumerate(lists) if node]
    heapq.heapify(h)
    dummy = tail = ListNode()
    while h:
        val, i, node = heapq.heappop(h)
        tail.next = node
        tail = node
        if node.next:
            heapq.heappush(h, (node.next.val, i, node.next))   # i breaks ties: ListNode is not comparable
    return dummy.next

O(N log k) time, O(k) heap. The no-heap alternative is to merge pairs of lists in rounds (1+2, 3+4, ...), which is also O(N log k) and uses O(1) extra space if done iteratively. Mention it; some interviewers ask for it as the follow-up.

Smallest range covering one item from each list

Problem (restated from LeetCode 632, Smallest Range Covering Elements from K Lists). You get k lists of integers, each sorted in non-decreasing order. Find the smallest range [a, b] that contains at least one number from every list. Range [a, b] is smaller than [c, d] if b - a < d - c, or if the widths are equal and a < c. Return [a, b]. Example: lists [1, 8, 20], [5, 9], [2, 30] give [1, 5]. Limits: 1 <= k <= 3500, each list has 1 to 50 numbers, values in [-105, 105].

Hold exactly one "current" item per list. Those k items always cover every list, so [min, max] of them is a valid range. To find a narrower one you must raise the min (lowering the max is impossible: lists only go up). So pop the min, advance that list, and track the max in a plain variable (the heap gives only the min). The moment one list runs out, stop: no later window can include that list.

  1. Seed the heap with every list's first item: 4, 0, 5. The heap's top is the window's left end (0); keep the max (5) in a plain variable. Window [0, 5] holds one item from each list. Width 5 is the first best.
  2. The only way to get a narrower window is to raise the left end, so pop the min (0) and push list 1's next item, 9. New window [4, 9], width 5: not strictly better, so best stays [0, 5] (equal width, smaller start wins).
  3. Pop 4 (list 0), push 10. Heads 10, 9, 5: window [5, 10], width 5.
  4. Pop 5 (list 2), push 18. The max jumps to 18: window [9, 18], width 9. Widths can go up as well as down; we only remember the best.
  5. Pop 9 (list 1), push 12. Window [10, 18], width 8.
  6. Pop 10 (list 0), push 15. Window [12, 18], width 6.
  7. Pop 12 (list 1), push 20. Window [15, 20], width 5.
  8. Pop 15 (list 0), push 24. Window [18, 24], width 6.
  9. Pop 18 (list 2), push 22. Heads 24, 20, 22: window [20, 24], width 4. New best.
  10. Pop 20 (list 1): list 1 has no next item. Any later window would have to leave list 1 out, so we stop. Answer [20, 24]. Each item is pushed and popped at most once: O(N log k) for N items in k lists.
// Heap of heads gives the window's min; track the max by hand. Advance the list that owns the min.
func smallestRange(lists [][]int) []int {
	h := &TriHeap{} // key = value, i = list, j = index
	hi := math.MinInt64
	for i, l := range lists {
		*h = append(*h, Tri{l[0], i, 0})
		if l[0] > hi {
			hi = l[0]
		}
	}
	heap.Init(h)
	bestLo, bestHi := (*h)[0].key, hi
	for {
		t := heap.Pop(h).(Tri)
		if hi-t.key < bestHi-bestLo {
			bestLo, bestHi = t.key, hi
		}
		if t.j+1 == len(lists[t.i]) {
			return []int{bestLo, bestHi} // list i used up
		}
		nxt := lists[t.i][t.j+1]
		if nxt > hi {
			hi = nxt
		}
		heap.Push(h, Tri{nxt, t.i, t.j + 1})
	}
}
// Heap of heads gives the window's min; track the max by hand. Advance the list that owns the min.
vector<int> smallestRange(const vector<vector<int>>& lists) {
    typedef tuple<int, int, int> T;                      // (value, list, index)
    priority_queue<T, vector<T>, greater<T>> h;
    int hi = INT_MIN;
    for (int i = 0; i < (int)lists.size(); i++) { h.push(T(lists[i][0], i, 0)); hi = max(hi, lists[i][0]); }
    int bestLo = get<0>(h.top()), bestHi = hi;
    while (true) {
        T t = h.top(); h.pop();
        int lo = get<0>(t), i = get<1>(t), j = get<2>(t);
        if ((long long)hi - lo < (long long)bestHi - bestLo) { bestLo = lo; bestHi = hi; }
        if (j + 1 == (int)lists[i].size()) return {bestLo, bestHi};   // list i used up
        int nxt = lists[i][j + 1];
        hi = max(hi, nxt);
        h.push(T(nxt, i, j + 1));
    }
}
// Heap of heads gives the window's min; track the max by hand. Advance the list that owns the min.
static int[] smallestRange(List<List<Integer>> lists) {
    PriorityQueue<int[]> h = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0])); // (value, list, index)
    int hi = Integer.MIN_VALUE;
    for (int i = 0; i < lists.size(); i++) {
        int v = lists.get(i).get(0);
        h.offer(new int[]{v, i, 0});
        hi = Math.max(hi, v);
    }
    int bestLo = h.peek()[0], bestHi = hi;
    while (true) {
        int[] t = h.poll();
        int lo = t[0], i = t[1], j = t[2];
        if ((long) hi - lo < (long) bestHi - bestLo) { bestLo = lo; bestHi = hi; }
        if (j + 1 == lists.get(i).size()) return new int[]{bestLo, bestHi};   // list i used up
        int nxt = lists.get(i).get(j + 1);
        hi = Math.max(hi, nxt);
        h.offer(new int[]{nxt, i, j + 1});
    }
}
def smallest_range(lists):
    """Heap of heads gives the window's min; track the max by hand. Advance the list that owns the min."""
    h = [(lst[0], i, 0) for i, lst in enumerate(lists)]
    heapq.heapify(h)
    hi = max(lst[0] for lst in lists)
    best = (h[0][0], hi)
    while True:
        lo, i, j = heapq.heappop(h)
        if hi - lo < best[1] - best[0]:
            best = (lo, hi)
        if j + 1 == len(lists[i]):
            return list(best)              # list i is used up: no window can cover it any more
        nxt = lists[i][j + 1]
        hi = max(hi, nxt)
        heapq.heappush(h, (nxt, i, j + 1))

O(N log k) for N numbers in all. The strict < in the "better" test keeps the earliest window on equal widths, which is exactly the tie rule (an earlier window has a smaller start). An equivalent answer is a sliding window over all numbers merged and tagged by list, with a count of lists covered: O(N log N) for the sort, and a good bridge to the sliding window primer.

K pairs with the smallest sums

Problem (restated from LeetCode 373, Find K Pairs with Smallest Sums). Two integer arrays a and b are sorted in non-decreasing order, and you get an integer k. A pair takes one number from a and one from b. Return the k pairs with the smallest sums (any order among equal sums is accepted). Example: a = [1, 7, 11], b = [2, 4, 6], k = 3 gives [1, 2], [1, 4], [1, 6]. Limits: 1 <= |a|, |b| <= 105, values in [-109, 109], 1 <= k <= 104, and k is at most |a| · |b|.

// Row i = pairs (a[i], b[0..]) is a sorted list. Seed min(k, len(a)) rows at column 0, then move right.
func kSmallestPairs(a, b []int, k int) [][]int {
	h := &TriHeap{} // key = sum, i, j
	for i := 0; i < len(a) && i < k; i++ {
		*h = append(*h, Tri{a[i] + b[0], i, 0})
	}
	heap.Init(h)
	var out [][]int
	for h.Len() > 0 && len(out) < k {
		t := heap.Pop(h).(Tri)
		out = append(out, []int{a[t.i], b[t.j]})
		if t.j+1 < len(b) {
			heap.Push(h, Tri{a[t.i] + b[t.j+1], t.i, t.j + 1})
		}
	}
	return out
}
// Row i = pairs (a[i], b[0..]) is a sorted list. Seed min(k, |a|) rows at column 0, then move right.
vector<vector<int>> kSmallestPairs(const vector<int>& a, const vector<int>& b, int k) {
    typedef tuple<long long, int, int> T;                // (sum, i, j)
    priority_queue<T, vector<T>, greater<T>> h;
    for (int i = 0; i < min(k, (int)a.size()); i++) h.push(T((long long)a[i] + b[0], i, 0));
    vector<vector<int>> out;
    while (!h.empty() && (int)out.size() < k) {
        T t = h.top(); h.pop();
        int i = get<1>(t), j = get<2>(t);
        out.push_back({a[i], b[j]});
        if (j + 1 < (int)b.size()) h.push(T((long long)a[i] + b[j + 1], i, j + 1));
    }
    return out;
}
// Row i = pairs (a[i], b[0..]) is a sorted list. Seed min(k, |a|) rows at column 0, then move right.
static List<List<Integer>> kSmallestPairs(int[] a, int[] b, int k) {
    PriorityQueue<long[]> h = new PriorityQueue<>((x, y) -> Long.compare(x[0], y[0]));  // (sum, i, j)
    for (int i = 0; i < Math.min(k, a.length); i++) h.offer(new long[]{(long) a[i] + b[0], i, 0});
    List<List<Integer>> out = new ArrayList<>();
    while (!h.isEmpty() && out.size() < k) {
        long[] t = h.poll();
        int i = (int) t[1], j = (int) t[2];
        out.add(List.of(a[i], b[j]));
        if (j + 1 < b.length) h.offer(new long[]{(long) a[i] + b[j + 1], i, j + 1});
    }
    return out;
}
def k_smallest_pairs(a, b, k):
    """Row i = pairs (a[i], b[0..]) is a sorted list. Seed the first min(k, len(a)) rows at column 0."""
    h = [(a[i] + b[0], i, 0) for i in range(min(k, len(a)))]
    heapq.heapify(h)
    out = []
    while h and len(out) < k:
        _, i, j = heapq.heappop(h)
        out.append([a[i], b[j]])
        if j + 1 < len(b):
            heapq.heappush(h, (a[i] + b[j + 1], i, j + 1))   # only move right along the row
    return out

Seeding only min(k, |a|) rows matters: |a| can be 105 while k is small. Heap size stays at most that, so the cost is O(k log min(k, |a|)). Sums reach 2 · 109, past the 32-bit limit, so keys are 64-bit in C++, Java and Go.

Other problems built from the same machine:

  • Kth Smallest Element in a Sorted Matrix: rows are the sorted lists; pop k times. (Binary search on the value is the O(n log range) alternative.)
  • Ugly Number II: three virtual lists (2 ×, 3 ×, 5 × the ugly numbers so far). A heap with a "skip duplicates" check works; three pointers are the neat O(n) form.
  • Super Ugly Number: the same with k primes, so a heap of k heads.
  • Find K-th Smallest Pair Distance: a heap of rows is O(k log n) and too slow when k is near n2; binary search on the distance with a two-pointer count is the intended answer. Knowing when the heap is the wrong tool is part of the skill.
