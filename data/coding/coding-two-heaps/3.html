Sliding window median: lazy deletion

Problem (restated from LeetCode 480, Sliding Window Median). You get an integer array and a window size k. A window of k consecutive items starts at the left and moves one step right each time until it touches the end. Return an array of floating-point numbers: the median of each window, in order (n - k + 1 values). For example, with values [2, 6, -2, 0, 7, 6, 8, 9] and k = 3 the windows are [2, 6, -2], [6, -2, 0], ... and the answer starts [2.0, 0.0, ...]. Limits: 1 <= k <= n <= 105, each value is any 32-bit signed integer, and answers within 10-5 are accepted.

Brute force sorts every window: O(n k log k), around 1011 steps at the limits. The running median above only ever adds. A window also removes the item that falls off the left, and a binary heap has no fast "remove this value": you would have to find it first, which is O(k).

There are three good answers. Know all three and pick by language:

ApproachRemove an itemTotalBest in
Two heaps + lazy deletionmark it in a hash map; pop it when it reaches a topO(n log n)Python, Go, Java (any language with only a heap)
Two balanced trees (multisets)erase one copy by iterator, O(log k)O(n log k)C++ multiset, Java TreeMap with counts
One sorted listbinary search + shift, O(k)O(n k)Python bisect.insort when k is small; say the cost

Lazy deletion, the version the editorial and most top community answers use, works like this. When y leaves the window, increase delayed[y] and leave y in its heap. Decide which heap it "belongs" to by comparing with lo's top: if y <= top(lo) it was in lo. Track a small balance number bal for this step: -1 when lo lost a valid item, +1 when hi did. Then add the new item x to the correct side (and adjust bal), and move one top across if bal is not zero. Finally prune: while a heap's top is a delayed value, pop it and decrease its count. Only the tops are read, so stale items deeper down do no harm.

// Two heaps + lazy deletion. bal = change in (valid items in lo) - (valid items in hi) this step.
func medianSlidingWindow(nums []int, k int) []float64 {
	lo, hi := &MaxInt{}, &MinInt{}
	delayed := map[int]int{} // value -> stale copies still in a heap
	loTop := func() int { return lo.MinInt[0] }
	hiTop := func() int { return (*hi)[0] }
	pruneLo := func() {
		for lo.Len() > 0 && delayed[loTop()] > 0 {
			delayed[loTop()]--
			heap.Pop(lo)
		}
	}
	pruneHi := func() {
		for hi.Len() > 0 && delayed[hiTop()] > 0 {
			delayed[hiTop()]--
			heap.Pop(hi)
		}
	}
	median := func() float64 {
		if k%2 == 1 {
			return float64(loTop())
		}
		return (float64(loTop()) + float64(hiTop())) / 2
	}
	for i := 0; i < k; i++ { // first window: plain MedianFinder pushes
		heap.Push(lo, nums[i])
		heap.Push(hi, heap.Pop(lo))
		if hi.Len() > lo.Len() {
			heap.Push(lo, heap.Pop(hi))
		}
	}
	out := []float64{median()}
	for i := k; i < len(nums); i++ {
		x, y, bal := nums[i], nums[i-k], 0 // x enters, y leaves
		delayed[y]++                       // y stays in its heap for now
		if y <= loTop() {
			bal--
			if y == loTop() {
				pruneLo()
			}
		} else {
			bal++
			if y == hiTop() {
				pruneHi()
			}
		}
		if lo.Len() > 0 && x <= loTop() {
			heap.Push(lo, x)
			bal++
		} else {
			heap.Push(hi, x)
			bal--
		}
		if bal < 0 {
			heap.Push(lo, heap.Pop(hi))
		} else if bal > 0 {
			heap.Push(hi, heap.Pop(lo))
		}
		pruneLo() // tops must be valid before we read them
		pruneHi()
		out = append(out, median())
	}
	return out
}
// Two heaps + lazy deletion. bal = (valid items in lo) - (valid items in hi) change in this step.
vector<double> medianSlidingWindow(const vector<int>& nums, int k) {
    priority_queue<int> lo;                              // max-heap
    priority_queue<int, vector<int>, greater<int>> hi;   // min-heap
    unordered_map<int, int> delayed;                     // value -> stale copies still in a heap
    auto pruneLo = [&]() { while (!lo.empty() && delayed[lo.top()]) { delayed[lo.top()]--; lo.pop(); } };
    auto pruneHi = [&]() { while (!hi.empty() && delayed[hi.top()]) { delayed[hi.top()]--; hi.pop(); } };
    auto median = [&]() { return k % 2 ? (double)lo.top() : ((double)lo.top() + hi.top()) / 2.0; };

    for (int i = 0; i < k; i++) {                        // first window: plain MedianFinder pushes
        lo.push(nums[i]); hi.push(lo.top()); lo.pop();
        if (hi.size() > lo.size()) { lo.push(hi.top()); hi.pop(); }
    }
    vector<double> out{median()};
    for (int i = k; i < (int)nums.size(); i++) {
        int x = nums[i], y = nums[i - k], bal = 0;       // x enters, y leaves
        delayed[y]++;                                    // y stays in its heap for now
        if (y <= lo.top()) { bal--; if (y == lo.top()) pruneLo(); }
        else               { bal++; if (y == hi.top()) pruneHi(); }
        if (!lo.empty() && x <= lo.top()) { lo.push(x); bal++; }
        else                              { hi.push(x); bal--; }
        if (bal < 0)      { lo.push(hi.top()); hi.pop(); }
        else if (bal > 0) { hi.push(lo.top()); lo.pop(); }
        pruneLo(); pruneHi();                            // tops must be valid before we read them
        out.push_back(median());
    }
    return out;
}
// Two heaps + lazy deletion. bal = change in (valid items in lo) - (valid items in hi) this step.
static double[] medianSlidingWindow(int[] nums, int k) {
    PriorityQueue<Integer> lo = new PriorityQueue<>(Collections.reverseOrder());
    PriorityQueue<Integer> hi = new PriorityQueue<>();
    Map<Integer, Integer> delayed = new HashMap<>();   // value -> stale copies still in a heap
    for (int i = 0; i < k; i++) {                      // first window: plain MedianFinder pushes
        lo.offer(nums[i]); hi.offer(lo.poll());
        if (hi.size() > lo.size()) lo.offer(hi.poll());
    }
    double[] out = new double[nums.length - k + 1];
    out[0] = median(lo, hi, k);
    for (int i = k; i < nums.length; i++) {
        int x = nums[i], y = nums[i - k], bal = 0;     // x enters, y leaves
        delayed.merge(y, 1, Integer::sum);             // y stays in its heap for now
        if (y <= lo.peek()) { bal--; if (y == lo.peek()) prune(lo, delayed); }
        else                { bal++; if (y == hi.peek()) prune(hi, delayed); }
        if (!lo.isEmpty() && x <= lo.peek()) { lo.offer(x); bal++; }
        else                                 { hi.offer(x); bal--; }
        if (bal < 0) lo.offer(hi.poll());
        else if (bal > 0) hi.offer(lo.poll());
        prune(lo, delayed); prune(hi, delayed);        // tops must be valid before we read them
        out[i - k + 1] = median(lo, hi, k);
    }
    return out;
}

static void prune(PriorityQueue<Integer> h, Map<Integer, Integer> delayed) {
    while (!h.isEmpty() && delayed.getOrDefault(h.peek(), 0) > 0) {
        delayed.merge(h.poll(), -1, Integer::sum);
    }
}

static double median(PriorityQueue<Integer> lo, PriorityQueue<Integer> hi, int k) {
    return k % 2 == 1 ? lo.peek() : ((double) lo.peek() + hi.peek()) / 2.0;
}
def median_sliding_window(nums, k):
    """Two heaps + lazy deletion. 'bal' = (valid items in lo) - (valid items in hi);
    the heaps may also hold stale items that are removed only when they reach the top."""
    lo, hi = [], []                      # lo: max-heap (negated), hi: min-heap
    delayed = defaultdict(int)           # value -> how many stale copies are still inside a heap

    def prune(h, sign):                  # pop stale items sitting on top of heap h
        while h and delayed[sign * h[0]]:
            delayed[sign * h[0]] -= 1
            heapq.heappop(h)

    def median():
        return float(-lo[0]) if k % 2 else (-lo[0] + hi[0]) / 2.0

    for i in range(k):                   # first window: plain MedianFinder pushes
        heapq.heappush(lo, -nums[i])
        heapq.heappush(hi, -heapq.heappop(lo))
        if len(hi) > len(lo):
            heapq.heappush(lo, -heapq.heappop(hi))
    out = [median()]
    for i in range(k, len(nums)):
        x, y = nums[i], nums[i - k]      # x enters, y leaves
        bal = 0
        delayed[y] += 1                  # y stays in its heap for now
        if y <= -lo[0]:
            bal -= 1                     # lo lost one valid item
            if y == -lo[0]:
                prune(lo, -1)
        else:
            bal += 1                     # hi lost one valid item
            if y == hi[0]:
                prune(hi, 1)
        if lo and x <= -lo[0]:
            heapq.heappush(lo, -x); bal += 1
        else:
            heapq.heappush(hi, x); bal -= 1
        if bal < 0:                      # lo is short by one: move hi's top down
            heapq.heappush(lo, -heapq.heappop(hi))
        elif bal > 0:                    # hi is short by one
            heapq.heappush(hi, -heapq.heappop(lo))
        prune(lo, -1)                    # tops must be valid before we read them
        prune(hi, 1)
        out.append(median())
    return out

Why it is O(n log n) and not worse. Every value is pushed once and popped once (either as a live item moved across, or as a stale one pruned). The heaps can hold up to n items when stale ones pile up below the tops, so each operation is O(log n), not O(log k). That is still fast enough. The multiset version keeps only k items, so it is O(n log k), and the code is shorter in C++:

// C++ alternative: one multiset of the k window values and an iterator that always points at
// the middle (index k/2). Invariant: mid = next(w.begin(), k / 2) after every step.
vector<double> medianSlidingWindowMultiset(const vector<int>& nums, int k) {
    multiset<int> w(nums.begin(), nums.begin() + k);
    auto mid = next(w.begin(), k / 2);
    vector<double> out;
    for (int i = k;; i++) {
        out.push_back(k % 2 ? *mid : ((double)*prev(mid) + *mid) / 2.0);
        if (i == (int)nums.size()) break;
        w.insert(nums[i]);                          // equal values go after mid (upper bound)
        if (nums[i] < *mid) mid--;                  // one more value left of mid: step left
        if (nums[i - k] <= *mid) mid++;             // the leaving value is left of (or at) mid: step right first
        w.erase(w.lower_bound(nums[i - k]));        // erase one copy, never the whole key
    }
    return out;
}

Compiled with C++14 and checked against a brute-force median on 400 random windows with many duplicates (coding-code/coding-two-heaps/cpp/main.cpp). The order of the two mid moves matters: step left for the insert first, then step right before erasing, so mid never points at the copy being erased.

Two traps the tests always hit. (1) top(lo) + top(hi) overflows a 32-bit int when both are near 231 - 1: convert to double (or 64-bit) before adding. (2) Duplicates: decide which heap a leaving value is in by comparing with lo's top using <=, the same rule you used to insert it, or the balance count drifts.
