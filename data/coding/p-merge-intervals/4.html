Approaches: brute → better → optimal

Hint 1

If the intervals were sorted by start, which interval could the next one possibly overlap with?

Hint 2

Only the last block you built. Keep it open and stretch its end.

1. Brute force - overlap graph and connected components

Idea: make each interval a node and join two nodes when they overlap. Intervals in one connected component merge into [min start, max end]. This is the editorial's first approach, and it shows a subtle point: [1,5] and [6,10] do not overlap, but both overlap [4,7], so they end up in one block.

Graph: n nodes, an edge when a.start <= b.end && b.start <= a.end. Traversal: DFS/BFS from each unvisited node. Visited rule: a node joins one component only. Answer: min start, max end per component.

O(n²)time
O(n²)space (edges)

What is wasted: we test every pair, although after sorting an interval can only touch its neighbours' block. -> rung 2.

2. Optimal - sort by start, sweep once

intervals.sort(key=lambda iv: iv[0])
for s, e in intervals:
    if out and s <= out[-1][1]: out[-1][1] = max(out[-1][1], e)
    else: out.append([s, e])
  1. Sorting makes every merged block contiguous. Any interval that sorts between the open block and a later member of it starts no later than that member, so it also starts before the block ends and joins it too.
  2. Only the last block can grow. Every earlier block ended before the last block started, and starts only increase, so nothing later can reach back to it.
  3. Overlap test is one comparison. start <= open.end; then open.end = max(open.end, end), because a contained interval must not shrink the block.
O(n log n)time (the sort)
O(n)output (+ the sort's own O(log n) to O(n))

Why it works: after the sort, the open block's end is the furthest point covered so far. An interval that starts at or before it is connected to the block; one that starts after it is separated by a gap that no later interval can fill, because later intervals start even further right.

Proof (optional)

Invariant: after processing the first k sorted intervals, out is exactly the merge of those k. Step: interval k+1 has the largest start so far. If s <= last.end it shares a point with the last block (which reaches last.end), so it joins it; it cannot touch an earlier block, because those end before last.start <= s. If s > last.end, no point of it is covered yet and it opens a new block. Induction on k gives the result.
