Intervals arrive one at a time and you must answer the merged list after each one.

Keep the disjoint blocks in an ordered map keyed by start (TreeMap, std::map). On insert, find the block just before the new start and every block that starts before the new end; replace them by one block. O(log n) plus the number of blocks absorbed, which is amortised O(log n). This is LC 352 / 715 territory.

How to answer

Say why a sorted array is O(n) per insert and the tree fixes it.

Likely follow-ups
  • Python has no TreeMap: use bisect on a list (O(n) shifts) or sortedcontainers.
What if the input is already sorted? And can you do it in place?

Skip the sort: O(n). In place: keep a write index w; for each interval either stretch a[w] or copy it to a[++w]; return the first w+1 entries. O(1) extra space.

How to answer

Mention that the sort is the only O(n log n) part.

Likely follow-ups
  • Which sort does your language use, and its extra space?
Touching intervals should NOT merge (half-open [start, end)). What changes?

Only the test: start < open.end. Ask this in the clarifying phase; it is the most common hidden requirement in booking problems.

How to answer

State the open/closed convention before coding.

Likely follow-ups
  • Does a zero-length booking [5,5) conflict with anything?
Now return the total covered length, or the gaps between blocks.

Same sweep: add end - start of each final block, or emit [prev.end, cur.start] when a gap opens. Employee Free Time is exactly the gap version over several schedules.

How to answer

Reuse the sweep; do not merge first and loop again unless it is clearer.

Likely follow-ups
  • k sorted lists: heap-merge instead of concatenate and sort.
Ten billion intervals do not fit in memory. How do you merge them?

External sort by start (sorted runs on disk, then a k-way merge with a heap), and run the sweep on the merged stream: it needs only the open block in memory. Output is written as it becomes final.

How to answer

Point out the sweep is streaming-friendly; only the sort needs the big machinery.

Likely follow-ups
  • Distributed: range-partition by start, merge per partition, then fix blocks across partition borders.
