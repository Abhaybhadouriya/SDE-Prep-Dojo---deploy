The problem (in our words)

You get an array intervals where intervals[i] = [starti, endi], in any order. Combine every pair of intervals that overlap (sharing even one point, so [1,4] and [4,6] overlap) until none overlap, and return the resulting list of non-overlapping intervals that covers exactly the same points as the input. Any order of the output is accepted; sorted order is the natural one.

Signature: int[][] merge(int[][] intervals).

  • 1 <= intervals.length <= 104
  • intervals[i].length == 2
  • 0 <= starti <= endi <= 104

Practice it: LeetCode 56 · GfG Overlapping Intervals · TUF article

Constraints tell you: n <= 104 allows O(n²) in a pinch, but sorting gives O(n log n) and is what is expected. Values <= 104 also allow a counting sweep over a 104-cell line (a follow-up). A single interval is valid input, and start == end (a point) is allowed.
