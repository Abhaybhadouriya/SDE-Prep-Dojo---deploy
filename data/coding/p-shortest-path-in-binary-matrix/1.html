The problem (in our words)

You get an n x n grid grid of 0s (free) and 1s (blocked). Return the length of the shortest clear path from the top-left cell (0, 0) to the bottom-right cell (n - 1, n - 1), or -1 if there is none.

  • A clear path visits only cells with value 0, including the first and the last cell.
  • Consecutive cells on the path are 8-directionally adjacent: they share an edge or a corner.
  • The length of a path is the number of cells it visits (so a 1x1 open grid has answer 1).

Signature: int shortestPathBinaryMatrix(int[][] grid).

Constraints:

  • n == grid.length == grid[i].length
  • 1 <= n <= 100
  • grid[i][j] is 0 or 1

Practice it: LeetCode 1091 · TUF: shortest distance in a binary maze (a 4-direction, any-source-any-target version).

Constraints tell you: at most 100 x 100 = 10,000 cells and 8 edges each, so anything linear in the cells (BFS, about 80,000 edge checks) is instant. Trying all paths (DFS with backtracking) is exponential and times out. Unit cost per step means BFS, not Dijkstra.
