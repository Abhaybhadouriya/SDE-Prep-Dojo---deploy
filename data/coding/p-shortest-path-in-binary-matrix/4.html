Approaches: brute -> better -> optimal

Hint 1

Treat each free cell as a node and each of its 8 free neighbours as an edge of cost 1. What finds the fewest edges from one node to another?

Hint 2

When is a cell "done" in BFS? Do you ever need to visit it a second time?

1. Brute force - DFS over all simple paths

Idea: from (0,0), try every free neighbour recursively, un-marking on the way back, and keep the shortest path that reaches the goal.

O(8^(n²))time, worst case
O(n²)recursion depth

What is wasted: the same cell is reached again and again along different paths. DFS reaches a cell first along some path, not the shortest, so it cannot stop early. -> rung 2.

2. A tempting wrong turn - DP in reading order

Idea: dp[r][c] = 1 + min(dp of the 8 neighbours), filled row by row. One of the most-voted community posts on this problem asks exactly why this fails a big test.

Why it fails: DP needs an order in which every dependency is finished first. Here a shortest path can go up and left, so a cell can depend on cells the scan has not reached. Re-running the sweep until nothing changes does work, but needs up to O(n²) sweeps: O(n⁴). -> rung 3.

3. Optimal - BFS by levels

q = deque([(0, 0)]); grid[0][0] = 1; length = 1
while q:
    for _ in range(len(q)):
        r, c = q.popleft()
        if (r, c) == (n - 1, n - 1): return length
        push every free, unvisited 8-neighbour (mark it now)
    length += 1
  1. Check both corners first. If grid[0][0] or grid[n-1][n-1] is 1, return -1 before doing any work.
  2. The queue holds one level at a time. Processing len(q) cells per round means every cell popped in round k is exactly k cells from the start.
  3. Mark on push, not on pop. Setting grid[nr][nc] = 1 when a cell is queued stops it from being queued again by another neighbour in the same level.
  4. Stop at the first pop of the goal. BFS pops cells in non-decreasing distance order, so the first time is the shortest.
O(n²)time: each cell pushed once, 8 checks
O(n²)queue (the grid doubles as the visited set)

Why it works: the queue only ever holds cells of level k followed by cells of level k + 1. A cell first pushed at level k + 1 has no path of k cells or fewer, because then a neighbour of it would sit in an earlier level and would have pushed it earlier. So each cell's level is its true shortest length, and it never needs a second visit.

Beyond the interview answer: a most-voted solution uses A* with the Chebyshev distance max(|dr|, |dc|) to the goal as the heuristic. It is admissible for 8-direction moves, so the answer is still exact, and it usually expands far fewer cells. Mention it as a follow-up; code BFS.
