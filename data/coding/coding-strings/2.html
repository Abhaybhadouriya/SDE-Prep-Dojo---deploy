In-place tricks: two pointers and a write head

"In place" means O(1) extra space: you change the input array itself. Two shapes cover nearly every case.

Shape 1: two pointers from both ends

Put l at the start and r at the end, act on s[l] and s[r], and move them towards each other. Reverse: swap and step. Palindrome check: compare and step. Reverse only vowels: advance each pointer to a vowel, then swap.

Reverse the words: reverse twice

A classic: turn "cat eats fish" into "fish eats cat" with O(1) extra space (in C++ or on a char[]). The trick: reverse the whole string, then reverse each word back.

LeetCode 151 adds extra spaces: squash them first with the second shape below, then reverse twice. With immutable strings, split, reverse the list and join (O(n) space) is fine if you mention the in-place version.

Shape 2: a read head and a write head

When the output is never longer than the input, let a fast read pointer scan and a slow write pointer record what you keep. The write head can never overtake the read head, so you never overwrite something you have not read yet. Removing spaces, removing duplicates and run-length compression all work this way.

  1. Compress p p p q r r r r in place. Both heads start at 0. R will find each run of equal letters; W writes the letter and, if the run is longer than 1, its count.
  2. R scans the run ppp (length 3) and stops at index 3. W writes p then 3; W is now 2. The old letters at 0-1 were already read, so overwriting them is safe.
  3. Run q has length 1: write only the letter (no "1"). W moves to 3, R to 4.
  4. Run rrrr: write r and 4. A count like 12 would be written digit by digit. R reached the end.
  5. The answer is the new length 5. Cells from 5 on still hold old letters; the caller only reads the first 5. O(n) time, O(1) space.

Why can W never pass R? A run of length k becomes at most 1 + digits(k) characters, never more than k. State this invariant; it proves in place is safe.
