Common mistakes

  1. Concatenating in a loop. O(n2) in Java and Python. Use a builder or a list and join.
  2. Forgetting even-length palindromes. Only expanding from characters misses "abba". Expand from both (i, i) and (i, i+1).
  3. Overflow checked too late. Testing val * 10 + d > MAX after computing it in a 32-bit int. Rearrange to val > (MAX - d) / 10, or use a 64-bit accumulator and say why it is safe (stop as soon as it passes 231).
  4. Skip loops that run off the end. In valid palindrome, while (!isalnum(s[l])) l++ without l < r reads past the string on "!!!".
  5. Trusting split. Java's split drops trailing empty parts and takes a regex (so split(".") splits on everything); Python's split() with no argument collapses runs of spaces, split(" ") does not. Know which one you called.
  6. Bytes versus characters. In Go, s[i] is a byte; range over runes for non-ASCII text. Most constraints say "English letters only": say you rely on it.
  7. Delimiter encoding. Joining with a separator that may appear in the data. Use a length prefix.
  8. Off-by-one after expansion. The loop stops one step too far on each side, so the palindrome is s[lo+1 .. hi-1], length hi - lo - 1.
