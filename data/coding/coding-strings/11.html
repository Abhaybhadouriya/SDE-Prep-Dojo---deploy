Interview questions

Find the longest palindromic substring. What is your approach and its cost?

Every palindrome mirrors around a centre, and a string of length n has 2n-1 centres (n letters plus n-1 gaps). From each centre, expand while the two sides match and remember the longest window. O(n2) time, O(1) extra space. A DP table isPal[i][j] also gives O(n2) but needs O(n2) memory, so the centre method is strictly better here.

How to answer

Mention brute force O(n3) in one sentence, then the centre idea, then code the expand(lo, hi) helper and call it twice per index. Dry-run on a short even case like "abba" to show the even centre works.

Likely follow-ups
  • Count all palindromic substrings instead (add 1 per successful expansion).
  • Can it be linear? (Manacher's algorithm; describe the mirror idea, do not code it unless asked.)
  • Longest palindromic subsequence? (Different problem: 2D DP, O(n2).)
Implement atoi. How do you detect overflow without using a 64-bit integer?

Walk once: skip spaces, read at most one sign, then read digits while they last; stop at the first other character. Before val = val * 10 + d, check val > (INT_MAX - d) / 10; if true, return INT_MAX or INT_MIN by sign. Because the clamp value for negatives is exactly -231, the asymmetric range needs no special case.

How to answer

List the cases first: empty, only spaces, "+-1", " -0042", "12abc", "abc12", over 231 on both sides. Then code the four-state walk. Test with "-2147483648" and "2147483648" out loud.

Likely follow-ups
  • Support hex with a 0x prefix (another state, base 16).
  • What changes for 64-bit? (Same check with LLONG_MAX.)
  • Why is checking after the multiply wrong in C? (Signed overflow is undefined behaviour; the compiler may delete the check.)
Encode a list of strings into one string and decode it back. Any character may appear.

Prefix every string with its length and a marker: len + "#" + s. The decoder reads digits up to #, then takes exactly that many characters without looking at them, and repeats. Separators inside the data are harmless because the payload is never scanned. O(total length) both ways.

How to answer

Show why a plain delimiter fails with one example (["a,b"]), offer escaping as the alternative, then choose the length prefix and relate it to TLV / HTTP Content-Length. Test with an empty string in the list and with an empty list.

Likely follow-ups
  • Make it binary and compact (fixed 4-byte big-endian length).
  • Stream the decode when the input arrives in chunks (keep partial-length state).
Compare two version strings like "1.01" and "1.001.0".

Two indices, one per string. Repeatedly read the next number up to a dot or the end (a finished string yields 0), compare, and return as soon as they differ. Building the number digit by digit removes leading zeros for free; treating missing parts as 0 makes "1.0" equal "1". O(n + m) time, O(1) space.

How to answer

Mention split(".") plus parsing as the quick version, and point out the Java regex trap (split("\\.")). Then write the two-index loop.

Likely follow-ups
  • Parts with suffixes like "1.2-beta" (define an ordering first, then parse in states).
  • Very long numeric parts (compare by length after stripping zeros, then lexically).
strStr in linear time: explain KMP in two minutes.

Precompute lps[i], the length of the longest proper prefix of pat[0..i] that is also its suffix. Scan the text with k = characters currently matched. On a match, k++; on a mismatch with k > 0, set k = lps[k-1] and retry the same text character; if k == m, report a match. The text index never moves back, so O(n + m).

How to answer

Start with the naive O(nm) method and point at the wasted re-reading. Draw the lps table for a small pattern like "aabaaab". Then write the shared three-line loop.

Likely follow-ups
  • Rabin-Karp instead (rolling hash, verify on hash hit; expected O(n + m)).
  • Find all matches (after a full match, set k = lps[k-1] and continue).
  • Shortest palindrome by adding characters in front (lps of s + "#" + reverse(s)).
Valid palindrome when you may delete at most one character.

Two pointers from both ends. At the first mismatch you must delete either s[l] or s[r], so check whether s[l+1..r] or s[l..r-1] is a palindrome with a plain loop. You branch only once, so the total work is O(n), space O(1).

How to answer

Explain why greedy matching before the first mismatch is safe (deleting a matched character never helps), then code a helper isPal(l, r).

Likely follow-ups
  • At most k deletions (becomes DP: longest palindromic subsequence >= n - k).
Is this string a valid number ("2e10", "-.9", "1e", ".")?

One pass with flags seenDigit, seenDot, seenExp. Digit: set seenDigit. Sign: only at index 0 or right after an exponent. Dot: only if no dot and no exponent yet. e/E: only if no exponent yet and a digit was seen; then reset seenDigit so the exponent needs its own digits. Anything else: invalid. Answer: seenDigit at the end.

How to answer

Write the grammar first: [sign] (digits [. digits?] | . digits) [(e|E) [sign] digits]. Turn each rule into a flag check. Run "-.9" (valid), "." (invalid), "1e" (invalid), "e3" (invalid).

Likely follow-ups
  • Why not a regex? (Fine to mention; interviewers want to see the states.)
  • Allow surrounding spaces (trim first, or add START and END states).
