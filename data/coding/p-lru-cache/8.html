Common mistakes

Evicting before checking whether the key exists. put on an existing key in a full cache then throws out a different key for no reason.

Forgetting that get is a use. If get does not move the node, the eviction order is wrong (example 3).

Not storing the key in the node. At eviction you hold only the tail node; without its key you cannot delete the map entry, and the map keeps a dangling pointer.

Pointer order when linking. In pushFront, set the new node's prev/next first, then fix head.next.prev before overwriting head.next; swapping the last two lines makes the new node point back at itself and leaves the old first node's prev pointing at HEAD.

Checking size after inserting with the wrong bound. Evict when size == capacity before a new insert, or when size > capacity after it; mixing the two is off by one.
