Revision card

  • Cue: "Sort by", custom order, kth element, counting with small value range, "largest number".
  • Insight: The right order turns a search problem into a single pass; small keys make sorting linear.
  • State: comparator (strict, a + b vs b + a), counting array, quickselect partition.
  • Trap: Non-strict comparators (<=) crash C++ sort; a - b overflows in Java; quickselect worst case without random pivot.
  • Cost: O(n log n) comparison sort; O(n + k) counting; quickselect O(n) average.

More to remember

  • Comparators must be strict weak orders: return a < b, never a <= b.
  • Use Integer.compare in Java, never a - b.
  • Counting sort or buckets when values fit a small range; radix for fixed-width keys.
  • Quickselect for one k-th value: random pivot, recurse into one side only.
  • Largest Number: compare a + b with b + a as strings.
