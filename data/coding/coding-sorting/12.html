You need the 3 most frequent values among n integers. Which runs in O(n)?

  1. Min-heap of size 3
  2. Binary search on the answer
  3. Sort the values, then scan
  4. Bucket by frequency, read from the high end
Frequencies are at most n, so buckets 1..n index them directly. Sorting is O(n log n); a size-3 heap is O(n log 3) after an O(n) count, also fine in practice, but buckets are the strict O(n) answer.

In the Dutch flag loop, a[i] is 2. You swap it with a[hi]. What next?

  1. i++ only
  2. lo++ and hi--
  3. i++ and hi--
  4. hi-- only
The value that came from hi has not been looked at, so i stays where it is. Only hi shrinks.

Why can merge sort count pairs crossing the middle with one forward pointer j?

  1. Because merge sort is stable
  2. Because j is reset for every i
  3. Both halves are sorted, so if right[j] pairs with left[i], it pairs with every later left item too
  4. Because the array has no duplicates
left is sorted ascending, so the condition left[i] > 2 · right[j] only gets easier as i grows. j never needs to move back, which makes the counting pass linear.

Which comparator is safe in Java for sorting Integer objects ascending?

  1. (a, b) -> a == b ? 0 : 1
  2. (a, b) -> a <= b ? -1 : 1
  3. (a, b) -> Integer.compare(a, b)
  4. (a, b) -> a - b
a - b overflows for values far apart; the second never returns 0 and is not consistent; the third is not antisymmetric. Integer.compare is correct.

Quickselect with "first element as pivot" on an already sorted array of n items costs:

  1. O(n log n)
  2. O(log n)
  3. O(n)
  4. O(n2)
Each partition removes only one element, so the work is n + (n-1) + ... = O(n2). A random pivot fixes it in expectation.

You must sort records by city, and within a city by name. With a stable sort you can:

  1. Sort by name, then by city
  2. Only sort with a combined key
  3. Sort by city, then by name
  4. Not do it with two sorts
Sort by the minor key first, then stably by the major key; the second sort keeps the name order inside each city. This is LSD radix sort in miniature.
