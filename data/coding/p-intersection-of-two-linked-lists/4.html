Approaches: brute -> better -> optimal

Hint 1

If both lists had the same length, how would you find the join?

Hint 2

What is the length of "A followed by B"? And of "B followed by A"?

1. Brute force - compare every pair

Idea: for each node of A, walk all of B and check nodeA == nodeB. The first hit (in A's order) is the answer.

O(m·n)time
O(1)extra space

What is wasted: each node of B is re-walked m times.

2. Better - hash set of A's nodes

Idea: put every node address of A into a set, then walk B and return the first node already in the set.

O(m + n)time
O(m)extra space

What is wasted: m stored pointers, which the follow-up forbids. A second O(1) option is to count both lengths, advance the longer list's pointer by |m - n|, then walk both together. It is correct, but needs two extra passes and a little bookkeeping.

3. Optimal - switch heads at the end

p, q = headA, headB
while p is not q:
    p = headB if p is None else p.next
    q = headA if q is None else q.next
return p
  1. Name the parts. A = a own nodes + c shared nodes; B = b own nodes + the same c.
  2. Each pointer walks its list, then the other. When p becomes null it jumps to headB; when q becomes null it jumps to headA.
  3. Count the moves. p reaches the join for the second time after a + c + 1 + b moves (the +1 is the null step); q after b + c + 1 + a. The same number, so they are equal there at the same moment. In fact they line up as soon as both have switched, and the first equal node is the join.
  4. No join? Then c = 0 and both hit null together after a + b + 1 moves. p is q (both null) ends the loop and null is returned.
  1. Start: p = headA (3), q = headB (6). They differ, so both move one step.
  2. p = 1, q = 2. Still different.
  3. p reaches the shared 8 first, because A's own part is one node shorter. q is on 9.
  4. p = 4, q = 8. Both are in the shared tail but one step apart: plain stepping would never line them up.
  5. p = 5, q = 4.
  6. p falls off A (null). That null is a real step: next time p jumps to headB. q = 5.
  7. p was null, so p = headB (6). q falls off B (null).
  8. q was null, so q = headA (3). p = 2. From here both are the same distance from 8: p needs 2 steps (9, then 8) and q needs 2 (1, then 8).
  9. p = 9, q = 1. One step left for each.
  10. p = q = node 8: the loop stops and returns it. Each pointer made a + c + 1 + b = 9 moves (the +1 is the null step).
O(m + n)time: each pointer makes at most m + n + 1 moves
O(1)extra space: two pointers

Why it works: count moves from the start. p lands on the join for the second time at move a + c + 1 + b (its own list, the null step, then B's own part); q lands on it at move b + c + 1 + a. Those are equal, so the pointers are together on the join at that move at the latest. Could they meet earlier on a wrong node? Before either switches, after t moves p is at position t of A and q at position t of B; they are the same node only if it is shared and equally far from the end, which needs a = b, and then it is the join itself. Once one has switched they are on different laps of the combined path and their positions differ until both reach the join. With no join (c = 0), both reach null at move a + b + 1, and p is q stops the loop.

Why can't it loop forever? (optional proof)

Each pointer switches at most once before the loop ends: after one switch both pointers have the same remaining distance to the end of the combined path (c, or 0 when there is no join), so at the latest they are equal at null after a + b + c + 1 moves. If the lists may have cycles, this argument breaks; the problem guarantees none.
