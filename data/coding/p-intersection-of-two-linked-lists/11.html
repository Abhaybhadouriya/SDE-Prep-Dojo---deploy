Solve it by turning it into a cycle problem.

Link A's tail to headB. If the lists meet, the combined structure starting at headA has a cycle whose entry is exactly the join; Floyd's algorithm (LC 142) finds the entry in O(m + n) and O(1). Then set A's tail's next back to null, because the original lists must be unchanged.

How to answer

Show the reduction and the restore step; say why the switch-heads version is simpler.

Likely follow-ups
  • Why is the cycle entry the join? (From the join, walking forward goes through B's own part back to the join.)
What if either list may contain a cycle?

Find each list's cycle entry with Floyd. If one list has a cycle and the other does not, they cannot share a node. If neither has a cycle, use the normal method. If both do: if their entries are equal, the join is on the tails before the cycle, so run the length method on the parts up to that entry; otherwise walk once around A's cycle and check whether B's entry is on it (if yes, either entry is a valid "first shared node"; if no, they are disjoint).

How to answer

Split into the three cases by "which lists have a cycle".

Likely follow-ups
  • Why can two lists with cycles not share only part of a cycle? (A node has one next, so sharing one cycle node means sharing the whole cycle.)
Return the number of shared nodes, not the node.

Find the join with the same method, then walk from it to the end and count. Or, with the length method, count while walking in lockstep after the first equal node. Still O(m + n), O(1).

How to answer

Reuse the join; the count is the suffix length.

Likely follow-ups
  • Return the length of the own parts (skipA, skipB).
Extend to k lists that all end in the same tail.

Compute every length, advance each pointer by (its length - the minimum length), then step all k pointers together until they are all equal. O(total nodes) time, O(k) pointers. Switch heads does not generalise cleanly to k lists, so the length method is the one to show here.

How to answer

Say why the length method scales and the switching trick does not.

Likely follow-ups
  • What if only some of the k lists share the tail? (Use a hash map from node to count.)
Why is the hash-set version sometimes preferred in real code?

It also works when the lists may contain cycles (stop when a node repeats) and it is obvious to review. The two-pointer version relies on "no cycles", which is a precondition a caller can break. In a kernel-style setting with fixed memory, the O(1) version is the one you would ship, with the precondition documented.

How to answer

Compare robustness and memory; do not claim the O(1) version is always better.

Likely follow-ups
  • How much memory does a set of 3 * 104 pointers take? (Hundreds of KB with hash overhead.)
