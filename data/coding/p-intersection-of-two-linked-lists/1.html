The problem (in our words)

You get the heads of two singly linked lists, headA and headB. Return the first node that both lists share (the same node object, by identity), or null if the lists never meet. After a shared node, both lists continue through the same nodes to the end. The lists contain no cycles, and they must keep their original structure after the function returns.

Signature: ListNode getIntersectionNode(ListNode headA, ListNode headB).

How the judge builds the test (you never see these values): intersectVal (0 if there is no join), the two value lists, and skipA / skipB, the number of nodes before the join in each list. Only your returned node is checked.

Constraints

  • List A has m nodes and list B has n nodes; 1 <= m, n <= 3 * 10^4.
  • 1 <= Node.val <= 10^5
  • 0 <= skipA <= m, 0 <= skipB <= n
  • intersectVal is 0 if the lists do not meet; otherwise intersectVal == listA[skipA] == listB[skipB].

Follow-up asked by the original: O(m + n) time and O(1) extra memory.

Constraints tell you: 3 * 104 nodes per list rules out the O(m·n) double loop in a strict judge (9 * 108 pointer compares), so aim for O(m + n). The follow-up then removes the hash set. Values repeat freely, so comparing values is wrong from the start.
