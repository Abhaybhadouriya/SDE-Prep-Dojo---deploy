Approaches: brute -> better -> optimal

Hint 1

When you turn one 0 into a 1, which islands can it merge with? Only those touching it.

Hint 2

If every land cell knew "which island am I in, and how big is it", how much work would scoring one 0 take?

Hint 3

Two neighbours of the 0 may be in the same island.

1. Brute force - flip each 0 and flood-fill the whole grid

Idea: for every 0, set it to 1, compute the largest island with a full flood fill (as in Max Area of Island), then set it back. Also handle the "no zeros" case.

O(n4)time
O(n2)space

What is wasted: every flood recomputes the same islands; flipping one cell only changes the islands next to it. The test files use this as an oracle on small grids. -> rung 2.

2. Better - flood only from the flipped cell

Idea: for each 0, run one flood starting at that cell (treating it as land), counting cells, with a fresh visited mark. It skips unrelated islands, but a huge island next to many zeros is still re-counted for each of them: O(n4) worst case on a checkerboard-like grid of large islands.

3. Optimal - paint islands with ids, then score each 0

area = [0, 0]                       # ids 0 (water) and 1 (unpainted land) reserved
for each cell == 1:                 # pass 1: flood with id = len(area), count cells
    paint island, area.append(size)
best = max(area)                    # the answer if there is no 0
for each cell == 0:                 # pass 2
    ids = {grid of the 4 neighbours}   # a SET: an island touching twice counts once
    best = max(best, 1 + sum(area[i] for i in ids))
  1. Pass 1 labels components. Flood fill from each unpainted 1 visits exactly its island, so each island gets one id and its exact size. Painting in place doubles as the visited mark.
  2. A flip merges exactly its neighbouring islands. The new island is the flipped cell plus every island adjacent to it, and nothing else: any other island is not connected to the cell.
  3. Distinct ids give the exact size. The islands are disjoint, so the merged size is 1 plus the sum of their areas, counting each id once. Water neighbours have id 0 with area 0.
  4. No-zero grids. best starts as the largest existing island, so a grid of all 1s returns n2.
  1. Graph: grid cells are vertices; land cells connect to their 4 land neighbours.
  2. Traversal: DFS/BFS from every unpainted 1, painting the whole island with a new id (2, 3, ...) and recording area[id].
  3. Visited rule: the id written into the cell itself; a cell holding an id >= 2 is never flooded again.
  4. Answer: max over 0-cells of 1 + the sum of area over the distinct neighbour ids; if there is no 0, n · n.
O(n2)time
O(n2)space (stack + area)

Why it works: the expensive question "how big is the island I join?" has the same answer for every 0 next to that island, so compute it once per island (pass 1) instead of once per 0. Each cell is painted once and looked at by at most four zeros, so the whole thing is linear in the grid size. This "paint the picture" idea is the most-voted community approach.

Union-find version: union every pair of adjacent 1s, keeping a size per root; for each 0, collect the distinct roots of its neighbours and add their sizes. Same scoring step, O(n2 · α(n)). It is what TUF teaches, and it extends to a stream of flips (LC 305 style), where the painting approach would have to repaint.
