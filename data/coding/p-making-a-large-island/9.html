  • Cue: flip at most one 0 to join islands -> label components, then test each 0's neighbour ids.
  • Insight: a flipped 0 merges exactly the distinct islands touching it: 1 + sum of their areas.
  • State: grid painted with ids 2, 3, ...; area[id]; a set of up to 4 ids per zero.
  • Trap: de-duplicate ids; all-land grid; explicit stack for deep floods.
  • Cost: O(n2) time and space; brute force O(n4).
area = [0, 0]
for cell in land: if unpainted: area.append(flood(cell, id=len(area)))
best = max(area)
for cell in water:
    ids = {label of each neighbour}           # set!
    best = max(best, 1 + sum(area[i] for i in ids))

Why put the neighbour ids of a 0 cell into a set before summing?

  1. Two neighbours can belong to the same island, and counting its area twice gives a wrong, too large answer
  2. Sets are faster than lists
  3. To sort the ids
Example: a 0 touching ids {1, 2, 1} must add area[1] + area[2], not area[1] twice.

What is the answer if the grid has no 0?

  1. 0
  2. n * n
  3. n
Nothing can be flipped, and the whole grid is one island.

Time for an n x n grid?

  1. O(n^2)
  2. O(n^4)
  3. O(n^2 log n)
One labelling pass plus one pass over the 0 cells, each looking at 4 neighbours.
