The problem (in our words)

A square map grid of side n holds 1 for land and 0 for sea. An island is a group of land cells joined through shared edges (up, down, left, right). You are allowed to reclaim at most one sea cell (turn one 0 into a 1). Report how many cells the biggest island can have once that single change is made (or without it, if it does not help).

An island is a group of 1s connected 4-directionally (up, down, left, right); its size is the number of cells in it. If the grid has no 0 at all, the answer is the size of the whole grid.

Signature: int largestIsland(int[][] grid).

  • n == grid.length == grid[i].length
  • 1 <= n <= 500
  • grid[i][j] is either 0 or 1.

Practice it: LeetCode 827 · TUF article (Disjoint Set version)

Constraints tell you: up to 250,000 cells. Re-flooding the grid for each 0 is O(n4) = 6 · 1010: far too slow. We need roughly O(n2). One island can contain all 250,000 cells, so a recursive DFS may overflow the stack: use an explicit stack, BFS, or union-find.
