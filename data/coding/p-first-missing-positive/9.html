60-second recall

  • Cue: smallest missing / duplicates, values ~1..n, O(1) space -> index as hash.
  • Insight: answer ∈ 1..n+1; ignore everything outside 1..n.
  • Move: while v in 1..n and nums[v-1] != v: swap v home.
  • Trap: compare values in the guard (duplicates); compute the home index before the swap.
  • Cost: ≤ n swaps total: O(n) time, O(1) space.
for i in range(n):
    while 1 <= a[i] <= n and a[a[i]-1] != a[i]:
        h = a[i]-1; a[i], a[h] = a[h], a[i]
for i in range(n):
    if a[i] != i+1: return i+1
return n+1

For an array of length n, the answer can be at most:

  1. n - 1
  2. n
  3. n + 1
  4. max(nums) + 1
n slots can hold 1..n at best; then n + 1 is missing.

Why is the nested while loop still O(n) in total?

  1. The while loop runs at most once per i
  2. Each swap fixes one value at home forever, so there are ≤ n swaps
  3. Values are bounded by 231
  4. It is not; it is O(n²)
A value at home is never moved again, and there are n homes.

What happens on [1,1] with the guard nums[i] != i + 1 alone?

  1. An infinite loop
  2. Answer 1
  3. Answer 3
  4. Index out of range
The second 1 keeps swapping with the 1 already at home; compare values instead.
