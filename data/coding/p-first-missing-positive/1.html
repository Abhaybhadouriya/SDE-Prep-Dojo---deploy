The problem (in our words)

A ticket machine has handed out tickets, and you get the unsorted integer array nums of the numbers seen so far (any values: negative, zero, huge, repeated). Return the smallest positive integer (1, 2, 3, ...) that does not appear in nums.

You must design an algorithm that runs in O(n) time and uses O(1) auxiliary space (modifying the input array is allowed).

Signature: int firstMissingPositive(int[] nums).

Constraints:

  • 1 <= nums.length <= 105
  • -231 <= nums[i] <= 231 - 1

Practice it: LeetCode 41 · GfG Smallest Positive Missing Number

Constraints tell you: n ≤ 105 allows O(n log n) (sort) or O(n) with a hash set, but the problem itself forbids both extra memory and sorting time. Values up to 231 - 1 mean you must never compute v + 1 or v + n on an arbitrary value in 32-bit ints; only use values already checked to be in 1..n.
