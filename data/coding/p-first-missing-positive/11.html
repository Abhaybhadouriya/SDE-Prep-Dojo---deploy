Interview follow-ups

You may not modify the input array. What now?

O(1) space and O(n) time are then not both possible in general. Options: a bitset of n + 1 bits (n/8 bytes, far smaller than a hash set) gives O(n) time; copying the array and running cyclic sort on the copy costs O(n) words; with truly O(1) space you fall back to the O(n²) scan of rung 1, because duplicates make "count the values ≤ k" unreliable for a binary search.

How to answer

State the trade-off plainly; the bitset is the practical answer.

Likely follow-ups
  • Restore the array after cyclic sort? (Not possible in general; the original order is lost. Copy first.)
Return the k smallest missing positives.

After cyclic sort, walk the slots and collect i + 1 for every wrong slot; if fewer than k are found, continue with n + 1, n + 2, ... skipping any value larger than n that appeared (keep those in a small set, at most k of them matter).

How to answer

Reuse the same first pass; only the read-out changes.

Likely follow-ups
  • Sorted input instead? (LC 1539: binary search on the missing count.)
Numbers arrive as a stream; answer "smallest missing" after every insert.

Keep a boolean array (or bitset) of seen values up to the current bound and a pointer ans; on insert of ans, advance the pointer while the next value is seen. Each value moves the pointer once, so the total is amortised O(1) per insert. With deletes, use a min-heap or a balanced set of free numbers (LC 2336).

How to answer

Point out that this is the lowest free fd allocator.

Likely follow-ups
  • Distributed across shards? (Each shard owns a range; the answer is the minimum over shards.)
Why is the sum or XOR trick not enough here?

Those work when the values are a known range with exactly one gap (LC 268). Here there may be many gaps, duplicates and noise, so a single aggregate cannot tell which number is missing; you need per-value presence, which is what the index marking provides.

How to answer

Give a counter-example: [1,4] and [2,3] have the same length and the same sum (5), yet the answers are 2 and 1.

Likely follow-ups
  • When is the sum formula risky? (Overflow; use XOR or 64-bit.)
Write the sign-marking version and compare it with cyclic sort.

Pass 1: values ≤ 0 or > n become n + 1. Pass 2: for each v = |nums[i]| ≤ n, set nums[v-1] = -|nums[v-1]|. Pass 3: first positive slot i gives i + 1, else n + 1. No swaps and a simpler loop shape; cyclic sort leaves the array partly sorted, which helps if a follow-up needs the duplicates too.

How to answer

Mention the abs() on read: a slot may already be negated.

Likely follow-ups
  • Which version is easier to make branch-free? (Sign marking.)
