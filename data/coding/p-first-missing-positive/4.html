Approaches: brute -> better -> optimal

Hint 1

With n numbers, what is the largest possible answer?

Hint 2

If you could only keep a yes/no flag for each of 1..n, where in memory could those n flags live?

1. Brute force - try 1, 2, 3, ... and scan each time

Idea: for k = 1, 2, ..., scan the whole array for k; the first k not found is the answer. By the bound above, k never exceeds n + 1.

for k in range(1, n + 2):
    if k not in nums:          # O(n) scan
        return k
O(n²)time
O(1)extra space

What is wasted: the array is re-scanned n times. 1010 steps at n = 105. -> rung 2.

2. Better - sort, or use a hash set

Idea: put all values in a set and count up from 1 (O(n) time, O(n) space), or sort and walk the positives, skipping duplicates (O(n log n) time, O(1) space).

seen = set(nums)
k = 1
while k in seen:
    k += 1
return k
O(n)time (set)
O(n)extra space

What is wasted: the set stores up to n values, but we only ever ask about 1..n+1: a yes/no flag per index would do. And the array already has n slots we are allowed to overwrite. -> rung 3.

3. Optimal - cyclic sort: every value in 1..n goes to slot v-1

for i in range(n):
    while 1 <= nums[i] <= n and nums[nums[i] - 1] != nums[i]:
        h = nums[i] - 1; nums[i], nums[h] = nums[h], nums[i]
return next((i + 1 for i in range(n) if nums[i] != i + 1), n + 1)
  1. The answer is in 1..n+1. n slots can hold at most the n values 1..n; anything else is noise.
  2. Send each useful value home. While nums[i] is in 1..n and its home slot nums[i]-1 does not already hold it, swap. The value that arrives at i is handled by the same while loop.
  3. Stop on duplicates. The guard nums[home] != nums[i] (compare values, not home != i) ends the loop when the home already holds a copy; without it, [1,1] swaps forever.
  4. Read the gap. The first i with nums[i] != i+1 gives i + 1; if every slot is right, the answer is n + 1.
O(n)time (≤ n swaps in total)
O(1)extra space

Why it is O(n) despite the nested loop: every swap puts one value into its home slot, and a value at home is never moved again (the guard sees it is already there). There are only n slots, so there are at most n swaps over the whole run, plus n loop checks that do not swap.

Sign-marking variant (the second most voted idea): first replace every value outside 1..n by n + 1; then for each |v| in 1..n, make nums[|v|-1] negative; the first positive slot is the answer. Same O(n)/O(1), no swaps, but it needs the clean-up pass so that negative inputs do not look like marks.

Proof (optional)

After the first loop, for every value v in 1..n that occurs in the input, nums[v-1] = v: a value in range is only ever moved to its own home or swapped out of a slot that is not its home, and the while loop at index i ends only when nums[i] is out of range, at home, or a duplicate of the home's value. So slot k-1 holds k exactly when k is in the input. The smallest k in 1..n with nums[k-1] != k is therefore the smallest missing positive, and if none exists, 1..n are all present and n + 1 is the answer.
