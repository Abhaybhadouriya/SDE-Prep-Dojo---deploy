Approaches: brute → better → optimal

Hint 1

Take any longest path. Which of its nodes is the closest to the root? What does the path look like on each side of that node?

Hint 2

For a fixed bend node, the longest path bending there is height(left child) + height(right child), counted in edges from the bend.

Hint 3

Your height function already visits every node and knows both child heights. Can it record the sum while it is there?

1. Brute force - compute heights again at every node

Idea: for each node, call a separate height() on its left and right child, take the sum, and keep the maximum over all nodes: diam(t) = max(height(l) + height(r), diam(l), diam(r)).

O(n2)time (chain)
O(h)space

What is wasted: the height of a subtree is recomputed once for every ancestor. On a chain that is 1 + 2 + ... + n = O(n2). On a balanced tree it is O(n log n). -> rung 2.

2. Optimal - one post-order pass: return height, record the bend

def height(node):
    if not node: return 0
    l, r = height(node.left), height(node.right)
    best = max(best, l + r)          # the path that bends here
    return 1 + max(l, r)             # only one branch continues upward
  1. Every path has a unique top node. Going along a tree path, depth goes down to that node and then up again; that top node is the "bend".
  2. The longest path bending at t is l + r. With height counted in nodes, the deepest node in the left subtree is l edges below t, and the deepest on the right is r edges below t.
  3. Return one branch, record two. The parent can only extend one of t's branches, so return 1 + max(l, r); the two-branch value l + r goes into best.
  4. Take the max over all bends. Every node is a bend candidate exactly once, so best ends as the diameter.
O(n)time
O(h)space (call stack)

Why it works: the answer is a max over bend nodes, and each bend's value only needs its two child heights, which post-order already computes. The function returns what the parent needs (one branch) and writes on the side what the answer needs (two branches). Mixing those two up is the classic bug.

Proof (optional)

Let P be a longest path and t its highest node. The part of P below t on each side is a downward path, so its length is at most the height (in edges, plus one for the edge from t) of that child subtree: |P| <= h(t.left) + h(t.right), with h counted in nodes and h(null) = 0. The algorithm records exactly h(t.left) + h(t.right) at t, and that value is realised by a real path (deepest left node, t, deepest right node), so best >= |P| and best <= |P|. By induction on the post-order, height() returns the correct h for each node, and each node is visited once: O(n).

3. Alternative - iterative post-order (no recursion)

Idea: push nodes on an explicit stack in post-order and keep a hash map height[node]; when a node is popped for the second time, both children's heights are in the map, so do the same two lines. Same O(n) time, O(n) space, and no stack-depth limit for a 104-node chain in Python.
