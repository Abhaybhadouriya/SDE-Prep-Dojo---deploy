Return the path itself (the list of nodes), not only its length.

Return (height, deepest node) from each call, and when a node sets a new best, remember (node, deepest-left, deepest-right). Afterwards walk from the bend down to each end, or keep parent links and rebuild. Still O(n).

How to answer

Say what extra each call returns and what you store when best improves.

Likely follow-ups
  • Return the two end nodes only.
The tree is a general undirected tree given as an edge list.

Two BFS passes: from any node find the farthest node a; from a find the farthest node b; dist(a, b) is the diameter. Or run the same DFS on the adjacency list keeping the two largest child heights per node. Both O(n).

How to answer

Give the two-BFS trick and say why a is always an end of some diameter (the farthest node from any vertex is an endpoint).

Likely follow-ups
  • Why does the two-BFS trick fail with negative edge weights?
Edges have weights (latencies). Find the longest weighted path.

Same skeleton: each call returns the best downward weighted length, max(child_len + w(edge)), and the bend is the sum of the two best. With non-negative weights nothing else changes; with negative ones clamp branches at 0 as in LC 124.

How to answer

Point out that only "height" changes meaning; the control flow is identical.

Likely follow-ups
  • Find the center of the tree (the node minimising the farthest distance).
Can you avoid the global / member variable?

Yes: return a pair (height, best diameter in this subtree). At a node, best = max(l.best, r.best, l.h + r.h). It is purely functional and thread-safe, at the cost of a small struct per call.

How to answer

Show the pair version in a few lines; interviewers like that it removes shared state.

Likely follow-ups
  • In Java, pass an int[1] holder instead of a field; why is that common?
The tree is a 106-node chain. What breaks?

Recursion depth 106 overflows default thread stacks and CPython's limit. Use an iterative post-order with an explicit stack and a height map, or process nodes in reverse BFS order (children before parents) so heights are ready when a node is handled.

How to answer

Mention reverse BFS order: it is the simplest recursion-free post-order.
