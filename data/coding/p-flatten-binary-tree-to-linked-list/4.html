Approaches: brute -> better -> optimal

Hint 1

In the final chain, which node comes right after the last node of the left subtree?

Hint 2

If you visit nodes in the order right, left, root, what is the "previous" node you visited when you reach a node?

1. Brute force - collect preorder, then relink

Idea: run a preorder traversal into a list of nodes, then for each i set nodes[i].left = null and nodes[i].right = nodes[i + 1].

O(n)time
O(n)extra space: the node list

What is wasted: O(n) memory for a list whose only job is to remember the order, which the tree already encodes. Still a fine first sentence.

2. Better - reverse preorder with a "prev" pointer

Idea: visit right subtree, then left subtree, then the node (the exact reverse of preorder). When you reach a node, prev is the node that follows it in preorder, so set node.right = prev, node.left = null, prev = node. The chain is built back to front.

Reverse-preorder version (Python, tested in the same driver) 
class SolutionReverse:
    """Visit right, left, root (reverse preorder) and link each node to the one built before it."""
    def flatten(self, root):
        self.prev = None

        def go(node):
            if node is None:
                return
            go(node.right)
            go(node.left)
            node.right = self.prev      # prev = the node that follows in preorder
            node.left = None
            self.prev = node

        go(root)
O(n)time
O(h)stack: tree height, up to n when skewed

Why the order is safe: when a node is processed, both of its subtrees are already finished, and overwriting node.right loses nothing because the right subtree was visited first. A plain preorder (root first) version breaks here: setting root.right = root.left before visiting the old right subtree loses it unless you saved it.

3. Optimal - rewire along the right spine, O(1) space

  1. Walk cur from the root along right pointers.
  2. If cur has a left child, find pre = the rightmost node of cur.left (go right until null).
  3. Rewire: pre.right = cur.right, cur.right = cur.left, cur.left = null.
  4. Step: cur = cur.right and repeat until null.
O(n)time: every node is passed by cur once and by a pre walk at most once
O(1)extra space: two pointers

Why it works: invariant - the preorder of the whole tree never changes, and every node before cur on the right spine has a null left pointer. The rewire keeps the preorder because pre is the rightmost node of the left subtree, so it has no right child, and a right child attached to it is visited after everything in cur's left subtree: exactly where the old right subtree was in preorder. After the rewire cur has no left child, so the next preorder node is cur.right. When cur falls off the spine, every node is on it with left = null, and the order along it is the unchanged preorder. Cost: a node is on some pre walk only while it is on the right spine of a left subtree; once that subtree moves onto the main spine, those edges are never walked by a pre search again, so all walks together are O(n).
