The story

Explain like I'm 5

A family tree is drawn on a wall. You want everyone in one single line, in the order you would read them: a parent, then the parent's whole left family, then the right family. You do not repaint anyone; you only move the strings between them so that every person holds just one string to the next person.

From your world

It is converting an rb-tree or a nested config tree into an intrusive singly linked list for a one-shot walk, without allocating: you already have one pointer field per child, so you reuse right as next and clear left. Doing it with O(1) extra memory matters in contexts where you cannot recurse deeply (kernel stacks are small).
