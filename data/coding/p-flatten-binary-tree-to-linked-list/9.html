60-second recall

  • Cue: tree to right-only chain in preorder, in place.
  • Insight: right subtree goes right after the whole left subtree.
  • O(1): pre = rightmost of cur.left; pre.right = cur.right; cur.right = cur.left; cur.left = null.
  • Recursive: visit right, left, node; node.right = prev.
  • Trap: clear every left; skewed trees break Python recursion.
cur = root
while cur:
    if cur.left:
        pre = cur.left
        while pre.right: pre = pre.right
        pre.right, cur.right, cur.left = cur.right, cur.left, None
    cur = cur.right

Why is hanging cur.right on the rightmost node of cur.left safe?

  1. That node is a leaf
  2. It has no right child, so its new right child is visited after the whole left subtree: the preorder does not change
  3. It is the smallest value
It may have a left child, which is fine; only its right pointer must be free.

In the recursive version, why visit the right subtree first?

  1. It is faster
  2. Preorder requires it
  3. So that when a node is processed its successor is already known, and overwriting node.right loses nothing
Right, left, node is reverse preorder; the chain is built back to front.

What is the extra space of the rewiring version?

  1. O(1)
  2. O(h)
  3. O(n)
Only cur and pre; no stack, no recursion.
