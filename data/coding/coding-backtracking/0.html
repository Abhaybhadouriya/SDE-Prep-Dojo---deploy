The story: the suitcase lock

Explain like I'm 5

You forgot the 3-digit code of your suitcase. You set the first wheel to 0, the second to 0, and spin the third through 0 to 9. No luck. You move the second wheel to 1 and spin the third again. When the second wheel has tried everything, you step back to the first wheel, move it to 1, and start the others again.

You never try the same code twice, and you never skip one. When a wheel runs out of options, you go back one wheel. That stepping back is backtracking. If you notice early that a code cannot work (say you remember the first digit is odd), you skip every code that starts with an even digit. That skipping is pruning.

Backtracking is depth-first search over a tree of choices. Each level of the tree is one decision. A path from the root is a partial answer. A leaf, or any node that passes a check, is a complete answer. We walk this tree depth first and keep only one path in memory: the current one.

From your world

Choose, explore, unchoose has the same shape as the goto err_unwind ladder in a kernel probe function: each step acquires something, and on the way back every acquisition is released in reverse order, so the state is exactly as it was before. A missing "unchoose" is the backtracking version of a leaked lock. And as on a 16 KB kernel stack, recursion depth matters: the depth here is the length of one answer (at most 16 to 81 in these problems), so it is safe.
