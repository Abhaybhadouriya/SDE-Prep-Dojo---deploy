Interview questions

Subsets: give two different ways to generate them, and their cost.

Backtracking with a start index (record at every node), or the "include / exclude" binary tree (two calls per item, record at leaves). Both visit O(2n) answers and copy each in O(n). A third, iterative way: bitmasks from 0 to 2n - 1, where bit i says whether item i is in.

How to answer

Write the start-index version (shortest), then mention the bitmask loop; it is a natural follow-up for a C programmer and avoids recursion.

Likely follow-ups
  • Input has duplicates. (Sort, skip siblings with i > start and a[i] == a[i-1].)
  • Only subsets of size k. (Stop at size k; prune when fewer than k - size items remain.)
Why does the duplicate skip use i > start and not i > 0?

The skip should stop two siblings (two choices at the same depth) from having the same value, because they would grow identical subtrees. A child may share its parent's value: [1, 1, 6] needs the second 1 directly under the first. i > start means "not the first option at this depth", which is exactly a sibling test; i > 0 would also block the child.

How to answer

Draw the tree for sorted [1, 1, 2] and target 3, cross out the second root child, and show [1, 1] still exists.

Likely follow-ups
  • Same idea for permutations? (Skip a[i] when a[i] == a[i-1] and used[i-1] is false.)
  • Could a HashSet of answers replace it? (Yes, but it still explores all duplicate subtrees: slower and uses more memory.)
Combination Sum and Combination Sum II: what exactly changes in the code?

Two things. The recursive call passes i (reuse) or i + 1 (use once). And with repeated values in II you sort and skip equal siblings. Both sort so that if a[i] > remain: break can cut the loop.

How to answer

Write one function with a reuse flag, as in the template. Then state the complexity as exponential with depth target / min(candidate).

Likely follow-ups
  • Count combinations instead of listing them. (Coin change II style DP over the target.)
  • Order matters (Combination Sum IV). (DP over the target with the loop over candidates inside.)
Word Search: how do you track visited cells, and what is the complexity?

Overwrite the cell with a marker before the four recursive calls and restore it after; no visited set needed. Time O(m x n x 3L): any start, then each step has at most 3 new directions (it cannot go back the way it came). Space O(L) for recursion.

How to answer

Mention two cheap prunes: if the word has a letter the board lacks, or more of a letter than the board has, return false at once; and if the last letter is rarer than the first, search the reversed word.

Likely follow-ups
  • Many words (Word Search II). (Trie of words, one DFS per cell, delete found leaves.)
  • Board is read-only. (Use a visited bitmask or boolean grid.)
N-Queens: how do you check conflicts in O(1), and how would you speed it up?

One queen per row; sets for columns, row - col diagonals and row + col anti-diagonals (offset row - col by n - 1 to index an array). Faster: three bitmasks, iterate free columns with free & -free, shift the diagonal masks per row. Also use symmetry: solve with the first queen in the left half and double (handle the middle column for odd n).

How to answer

Code the set version first (clear), then offer bitmasks as the optimisation. Give counts as a sanity check: n = 4 has 2, n = 8 has 92.

Likely follow-ups
  • Return just one solution for large n. (Constructive formulas exist; in an interview, say backtracking with good ordering finds one fast.)
  • Why O(n!)? (Row r has at most n - r free columns.)
Sudoku Solver: what makes a backtracking solver fast enough?

O(1) validity with 27 bitmasks (rows, columns, boxes), and choosing the blank with the fewest candidates next. A cell with one candidate is forced; a cell with zero ends the branch at once. With these two the search on normal puzzles touches very few nodes.

How to answer

Write the plain "next blank, try 1 to 9" version, then add masks, then MRV. Explain that the function returns a boolean so the first solution stops the search.

Likely follow-ups
  • Check whether a puzzle has exactly one solution. (Keep searching after the first; stop at the second.)
  • Valid Sudoku (just validate). (One pass with the same masks; no search.)
When does a backtracking solution turn into DP, and when should it?

When the result of a call depends only on a small part of the state (an index, a remaining sum) and the same call happens many times. Then cache it: that is top-down DP. Word Break II caches the list of sentences per start index; counting versions (Combination Sum IV, Word Break) become plain DP because only the number matters. If you must list every answer and the answers do not share structure, there is nothing to cache and backtracking is the right tool.

How to answer

Name the state of your recursive function. If it is small and repeats, memoise; if the output itself is exponential, explain that no DP can beat the output size.

Likely follow-ups
  • Memory cost of caching lists of strings. (Can be exponential; that is why counting versions are preferred when possible.)
  • Iterative instead of recursive. (Explicit stack of (index, state) frames; same order.)
