String partitioning: the choice is where to cut

Palindrome Partitioning. Given a lowercase string of length 1 to 16, split it into pieces so that every piece reads the same forwards and backwards, and return every such split. (Original: LeetCode 131.) For "aab" the answer is [a, a, b] and [aa, b].

The path is the list of pieces so far; start is where the next piece begins; the choices are every end from start to the last index. We only recurse when s[start..end] is a palindrome, which is the pruning. The path is complete when start reaches the end of the string.

The same skeleton solves Restore IP Addresses (exactly four pieces, each 0 to 255, no leading zeros, so at most 34 paths) and Word Break II (a piece is valid if it is in the dictionary; add memoisation on start to avoid repeated work).

From your world

Restore IP Addresses is the backtracking version of an inet_pton that does not know where the dots go. The validity rules you already enforce in a parser (octet 0 to 255, no leading zero except "0") are exactly the pruning checks.
