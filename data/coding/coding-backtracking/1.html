The template: choose, explore, unchoose

Every backtracking solution answers three questions before writing code:

  1. What is the path? The partial answer you carry: a list of picked numbers, the queens placed so far, the cells used.
  2. What are the choices at this node? Which items may be added next: those after a start index, those not used yet, the cells next to the current one.
  3. When is the path complete? Length n, sum equals target, the string is fully cut, the board is full. Some problems (subsets) record every node.
def backtrack(path, choices):
    if is_complete(path):
        record(copy(path))           # copy: path keeps changing after this
        return
    for c in choices(path):
        if not valid(path, c):       # prune early
            continue
        path.append(c)               # choose
        backtrack(path, choices)     # explore
        path.pop()                   # unchoose

The unchoose line is what makes this backtracking instead of plain recursion. We share one path object across the whole search, so after exploring a choice we must restore it before trying the next one. The other version, passing a fresh copy into every call, also works but allocates at every node.

Record a copy of the path (path[:], new ArrayList<>(path), out.push_back(path) in C++, which copies). Appending the path object itself leaves you with many references to one list that is empty at the end.
