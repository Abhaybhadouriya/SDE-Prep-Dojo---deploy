Combination sum: reuse, no reuse, and dedup

Combination Sum. Given distinct candidates (1 to 30 of them, values 2 to 40) and a target (1 to 40), return every unique combination that sums to the target. A candidate may be used any number of times; two combinations are the same if they use the same counts. (Original: LeetCode 39.) For candidates 2, 3, 5 and target 8 the answer is [2,2,2,2], [2,3,3], [3,5].

Combination Sum II. Candidates may now repeat (1 to 100 of them, values 1 to 50, target 1 to 30), each position may be used at most once, and the output must contain no duplicate combinations. (Original: LeetCode 40.)

Both use the subsets skeleton with a remain counter. The differences are single tokens:

Combination Sum (reuse)Combination Sum II (once, with duplicates)
recurse withi (the same item may be picked again)i + 1
dedupnot needed (distinct values, start index)sort, then if i > start and a[i] == a[i-1]: continue
prunesort, then if a[i] > remain: break (every later value is bigger too)

Complexity. For Combination Sum a safe bound is O(nT/m) nodes, where T is the target and m the smallest candidate (that is the deepest path). Say "exponential, bounded by the depth T/m, and pruning by sorted break cuts most branches". Interviewers want the shape of the bound, not a tight formula.
