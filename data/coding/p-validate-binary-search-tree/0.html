The story

Explain like I'm 5

A library sorts books on a branching shelf: at every fork, smaller call numbers go left and bigger ones go right. A book is in the right place only if it obeys every fork on the way down, not just the last one. A book that went "left at 50, then right at 30" must have a number between 30 and 50; number 55 obeys the fork at 30 but broke the rule at 50.

That is the whole trap of this problem: the local check "left child < node < right child" passes on broken trees. The fix is to carry the allowed interval from the root down.

From your world

It is a radix or route-lookup trie check: a prefix entry deep in the tree is valid only if it lies inside every range its ancestors cover. You validate by passing the current [lo, hi) window down, exactly like checking that a nested page-table entry stays inside the parent region.
