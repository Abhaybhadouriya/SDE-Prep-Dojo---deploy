Recognise the pattern

Cue: "BST" + "check" / "is valid" / "find the broken node" -> use one of the two BST invariants: (1) every node lies in the interval its ancestors allow, (2) the in-order traversal is strictly increasing. Both are O(n).

Try the local rule on tiny trees:

TreeLocal check (child vs parent)Real answerIn-order
[2,1,3]passtrue1, 2, 3 (rising)
[5,4,6,null,null,3,7]passfalse4, 5, 3, 6, 7 (drops at 3)
[1,1]depends on < vs <=false1, 1 (not strictly rising)

The middle row is the classic counter-example: the bug is invisible to any check that only looks one level up.
