Interview follow-ups

Why does the simple "left < node < right" check fail? Give a counter-example.

[5,4,6,null,null,3,7]: 3 is a valid left child of 6, but it lives in 5's right subtree and 3 < 5. The BST rule is about whole subtrees, so the constraint from 5 must travel down to 3.

How to answer

Draw the tree; say which ancestor's bound is violated.

Likely follow-ups
  • Which ancestors give the tightest bounds? (The nearest left-turn and right-turn ancestors.)
Do it without recursion.

Iterative in-order: push left spine, pop, compare with prev, move to the right child. Or a stack of (node, lo, hi) triples for the interval version (any order works, since each node only needs its own interval).

How to answer

Mention that the explicit stack still holds O(h) entries; Morris traversal gives O(1) extra space.

Likely follow-ups
  • Explain Morris in-order and why it restores the tree.
What if the language has no 64-bit integers, or keys can be any comparable type?

Pass nullable bounds (TreeNode* lo, TreeNode* hi or Integer objects): null means unbounded. That works for any comparable key and never overflows.

How to answer

Say it before being asked: it shows you noticed the full int range.

Likely follow-ups
  • Generic version with a comparator.
Duplicates are allowed, but only in the left subtree. What changes?

The left child's interval becomes (lo, val]: upper bounds always come from left turns and lower bounds from right turns, so the test becomes lo < v <= hi everywhere. The in-order check cannot be patched by allowing cur == prev: a non-decreasing sequence no longer tells you on which side the equal key sits, so the interval version is the safe one.

How to answer

Point out that in-order loses side information once equality is allowed.

Likely follow-ups
  • Counter-example where in-order is non-decreasing but the left-duplicates rule is broken ([5,null,5]).
Find the size of the largest subtree that is a BST.

Post-order: each call returns (isBST, min, max, size). A node is a BST root if both children are, and left.max < val < right.min; then size = left + right + 1. O(n) total, unlike calling isValidBST on every node (O(n²)).

How to answer

Contrast top-down bounds (good for one check) with bottom-up summaries (good for every subtree).

Likely follow-ups
  • Maximum key sum instead of size (LC 1373).
Given a preorder array, decide whether it can be the preorder of a BST.

Keep a stack and a running lower bound: for each value, pop while the top is smaller and set lower to the last popped; if a value is below lower, answer false; push it. O(n). It is the same interval idea, applied to a sequence.

How to answer

Explain that popping means "we turned right", which raises the lower bound.

Likely follow-ups
  • Build the BST from that preorder in O(n) (LC 1008).
