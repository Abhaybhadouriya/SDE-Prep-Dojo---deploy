Common mistakes

Comparing only with the children. [5,4,6,null,null,3,7] passes every local check and is not a BST.

Using INT_MIN / INT_MAX as "no bound". A node with value 2^31 - 1 then fails val < hi. Use long/long long/int64 bounds, float('inf'), or nullable bounds.

<= instead of <. LeetCode's definition forbids equal keys on both sides; some textbooks allow duplicates on one side, so ask.

In-order with prev = INT_MIN. Fails on a tree whose smallest key is -2^31. Track "no previous value yet" separately.

Collecting the whole in-order list. Works, but costs O(n) memory and loses the early exit; compare on the fly.
