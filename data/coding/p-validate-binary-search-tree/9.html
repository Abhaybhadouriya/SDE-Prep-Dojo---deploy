  • Cue: "is this a valid BST" -> interval DFS or strictly increasing in-order.
  • Insight: a node must satisfy every ancestor, not just its parent.
  • State: (lo, hi) open interval; left child gets (lo, val), right child (val, hi).
  • Trap: INT_MAX/INT_MIN sentinels; <= vs <; local-only checks.
  • Cost: O(n) time, O(h) stack; iterative in-order avoids deep recursion.
def ok(n, lo=float("-inf"), hi=float("inf")):
    if n is None: return True
    if not lo < n.val < hi: return False
    return ok(n.left, lo, n.val) and ok(n.right, n.val, hi)

Why is checking only node.left.val < node.val < node.right.val wrong?

  1. It is too slow
  2. A deep node can break an ancestor's bound, e.g. a 12 inside the left subtree of 10
  3. It fails on a single node
The BST rule is about whole subtrees, so every node must sit inside the (low, high) interval set by all its ancestors.

Going into the right child of a node v, the bounds become?

  1. (v, high)
  2. (low, v)
  3. (low, high)
Everything right of v must be greater than v and still below v's own upper bound.

Why use long / null bounds instead of INT_MIN and INT_MAX?

  1. Node values can equal INT_MIN or INT_MAX, and a strict check against them would wrongly fail
  2. It is faster
  3. Java needs it for recursion
Values reach the 32-bit limits, so use a wider type or 'no bound' markers.
