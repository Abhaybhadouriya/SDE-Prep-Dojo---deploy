Approaches: brute -> better -> optimal

Hint 3

What does an in-order walk of a BST print?

1. Brute force - compare each node with its subtree's max and min

Idea: the definition literally: for every node, compute the maximum of its left subtree and the minimum of its right subtree (each a full subtree walk) and require maxLeft < node.val < minRight.

O(n²)time on a skewed tree (O(n log n) balanced)
O(h)space

What is wasted: each subtree is walked once per ancestor. -> rung 2 or 3 push the information down (or return it up) in a single walk.

2. Better - in-order traversal, values must strictly rise

Idea: a binary tree is a BST exactly when its in-order sequence is strictly increasing. Walk in order (recursively, or iteratively with an explicit stack) and compare each value with the previous one; stop at the first cur <= prev. Keep prev as a pointer or a "seen anything yet" flag, not as INT_MIN, because -2^31 is a legal key.

O(n)time, early exit on the first violation
O(h)space (the stack)

What is good: the iterative version has no recursion depth risk, and the same loop solves Kth Smallest (230) and Recover BST (99). Many interviewers accept this as optimal.

3. Optimal (and the one we code) - DFS with an open interval

def ok(node, lo, hi):            # node must be in (lo, hi)
    if not node: return True
    if not (lo < node.val < hi): return False
    return ok(node.left, lo, node.val) and ok(node.right, node.val, hi)
  1. The root may be anything: start with (-inf, +inf).
  2. Going left keeps the lower bound and lowers the upper bound to the node's value.
  3. Going right keeps the upper bound and raises the lower bound to the node's value.
  4. Strict comparisons reject duplicates on both sides.
  5. Bounds are 64-bit (or nullable) so the extreme 32-bit keys are still testable.
O(n)time, each node checked once
O(h)recursion depth, h = height (n worst case)

Why it works: the interval passed to a node is exactly the set of values allowed by the BST rule of all its ancestors: going left under ancestor a adds "< a", going right adds "> a", and the tightest of those constraints are the nearest left-turn and right-turn ancestors - the two bounds we carry. A node fails the definition if and only if it falls outside that interval.

Proof (optional)

(=>) If the tree is a BST, every node v lies in the left subtree of each ancestor where the path turned left, so v < that ancestor, and symmetric for right turns; hence v lies in the interval, and the DFS returns true. (<=) If the DFS returns true, take any node u and any w in u's left subtree: on the path to w, the step from u went left, so w's interval has upper bound <= u.val (later steps only tighten it), so w < u.val. Symmetrically for the right subtree. That is the BST definition at every node.
