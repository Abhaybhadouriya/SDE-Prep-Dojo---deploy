Approaches: brute -> better -> optimal

Hint 1

Which operators can change a value you have already "finished"? Which cannot?

Hint 2

Act on a number only when it ends, and use the operator that came before it.

Hint 3

Put the sign into the term: "-9 / 4" is the term (-9) / 4, truncated.

1. Brute force - two passes over a token list

Idea: tokenise into numbers and operators. In pass one, walk the list and collapse every a * b or a / b into one number (left to right). In pass two, add and subtract what is left.

O(n)time
O(n)space

What is wasted: a full token list. Done naively, by deleting from the middle of a list, it is O(n2). It also mirrors the textbook "shunting-yard" approach, which is correct but much more code than an interview needs.

2. Better - stack of signed terms

Idea: keep op = the operator seen before the current number (start with '+'). When a number ends (at the next operator or the end of the string):

  • '+': push num; '-': push -num.
  • '*': replace the top with top * num; '/': replace the top with top / num, truncated toward zero.

The answer is the sum of the stack.

O(n)time
O(n)space

Why it works: each stack entry is one additive term with its sign attached. A '*' or '/' always belongs to the term that is still open, which is the top. Terms below the top can never change again, because only higher-precedence operators could touch them and those only act to their right.

3. Optimal - total plus last term (O(1) space)

The stack is only ever read at its top, and the elements below are only ever summed. So replace it with two numbers: total (the sum of everything below the top) and last (the top).

  1. Digits: num = num * 10 + digit.
  2. Operator or last character: apply op to num. '+' / '-': total += last; last = ±num. '*' / '/': last = last op num. Then op = c, num = 0.
  3. Spaces: skip, but note the "last character" check must run even if that character is a space.
  4. Answer: total + last.
O(n)time
O(1)space

Why it works: invariant after each number: total + last equals the value of the prefix read so far, and last is the full value of the open term including its sign. '+' and '-' close the open term (move it into total) and open a new one; '*' and '/' extend the open term, which by precedence is exactly the operand they bind to. Because the sign lives inside last, "a - b / c" computes (-b) / c, and truncation toward zero is symmetric, so (-b) / c = -(b / c): the same as the mathematically intended a - (b / c).

The stream-reading trick from the top community solutions

A popular C++ answer wraps the string as '+' + s + '+' and reads (operator, number) pairs with a string stream, which skips spaces for free. It is the same total/term state machine in very few lines; mention it, but write the explicit loop in an interview so the parsing is visible.
