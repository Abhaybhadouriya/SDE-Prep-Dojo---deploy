The problem (in our words)

You get a string s that holds a valid arithmetic expression. Compute its value and return it as an integer.

  • The expression contains non-negative integers and the four operators '+', '-', '*' and '/'. There are no brackets and no unary minus.
  • Any number of spaces may appear between numbers and operators; they carry no meaning.
  • Normal precedence applies: * and / before + and -, left to right within the same level.
  • Integer division truncates toward zero (so -7 / 2 = -3).
  • You may not call a built-in expression evaluator such as eval().

Signature: int calculate(String s).

Constraints:

  • 1 <= s.length <= 3 * 105
  • s consists of digits, the operators + - * / and spaces; it is always a valid expression.
  • Every integer in the expression is in [0, 231 - 1].
  • Every intermediate result fits in a 32-bit signed integer, and so does the answer.

Practice it: LeetCode 227 · GfG arithmetic expression evaluation

Constraints tell you: 3 x 105 characters means one linear pass; anything that rescans the string per operator (repeated "find the next *") is O(n2) and too slow. Numbers can be up to ten digits, so they must be accumulated digit by digit, not read as single characters.
