"2-3*5/4"-1The term is (-15) / 4 = -3 toward zero. Python's // gives -4 and the answer -2: wrong.
"1-7/2"-2Minus followed by a division: (-7) / 2 = -3, same as -(7 / 2).
"0*7+0"0Zeros as operands; division by zero never happens because the input is valid.
"3*4/5*5"10Same precedence goes left to right: 12 / 5 = 2, then 2 * 5. Computing 4/5 first or 5*5 first gives the wrong 0 or 60. (The code also uses 64-bit accumulators as a cheap guard; the tests include a total that passes 231 midway.)
