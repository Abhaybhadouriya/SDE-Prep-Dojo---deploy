Do it in O(1) extra space.

The stack is only read at its top and only summed below it, so keep total = sum below the top and last = the top. '+' and '-' move last into total; '*' and '/' update last.

How to answer

Start from the stack version and point at which entries are ever read; the reduction then falls out.

Likely follow-ups
  • Why is it still correct for "a - b / c"? The sign is part of the term and truncation is symmetric.
Now add parentheses.

At '(' push the current (total, last, op) and start fresh; at ')' finish the inner value (total + last) and treat it as the num for the outer level's pending op. Recursion with a shared index is equivalent and often shorter. Still O(n).

How to answer

Say a bracketed group is just "a number" for the level outside it.

Likely follow-ups
  • Unary minus, as in "-(2+3)": treat it as 0 - (...) or keep a sign flag.
The expression may contain invalid input (two operators in a row, division by zero). What changes?

Add a small validator state: "expecting a number" vs "expecting an operator". An operator while expecting a number, or end of input while expecting one, is an error; check the divisor before dividing. Return an error code or throw, as the interviewer prefers.

How to answer

Ask first how errors should be reported; it is a design question as much as a coding one.

Likely follow-ups
  • Overflow detection with 64-bit accumulators and a range check.
Support variables, for example "x * 2 + y" with a map of values.

Only the tokeniser changes: when a letter starts, read the whole identifier and look it up to get num. The evaluation state machine stays exactly the same.

How to answer

Separate tokenising from evaluating; that is the main design point.

Likely follow-ups
  • Unknown variable: error or symbolic result (LC 770, Basic Calculator IV).
Add a power operator '^' that binds tighter than '*' and is right-associative.

A third precedence level breaks the two-variable trick. Use the general method: recursive descent (expr -> term -> factor -> power) or shunting-yard with a precedence table, where right associativity means "do not pop an operator of equal precedence".

How to answer

Say why the O(1) version stops working: more than one open level can be pending.
