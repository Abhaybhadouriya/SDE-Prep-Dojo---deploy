Interview follow-ups

Prove that a repeated value must exist.

Pigeonhole: n + 1 entries, only n possible values, so two entries share a value. The cycle view gives a constructive proof too: the walk from 0 must revisit a node (finitely many nodes), and the first revisited node has two predecessors.

How to answer

One sentence of pigeonhole, then connect it to the graph picture you are about to use.

Likely follow-ups
  • Why is 0 never on the cycle? No value equals 0.
Why do slow and fast meet at all, and why in O(n)?

Once both are in the cycle, the gap between them shrinks by one every move (fast +2, slow +1), so it reaches 0 within C moves. Slow enters the cycle after F moves, so phase 1 takes at most F + C <= n + 1 moves; phase 2 takes F more.

How to answer

Relative speed of 1 is the key phrase.

Likely follow-ups
  • Would fast = 3 hops work? It still meets (gcd argument), but the phase-2 proof is cleaner with 2.
What if you are allowed to modify the array?

Index marking: for each v = |nums[i]|, if nums[v] is already negative, v is the duplicate; otherwise negate nums[v]. Restore the signs before returning if the caller needs the array. Or cyclic sort: swap each value into slot v until a slot already holds v. Both O(n) time, O(1) space.

How to answer

Say the trade-off: simpler code, but it mutates shared input (not thread-safe, not usable on read-only memory).

Likely follow-ups
  • Return all duplicates (LC 442).
Explain the binary-search solution and when you would prefer it.

Search the value range: count(nums <= mid) > mid means the duplicate is <= mid. It needs only the "values in 1..n" fact, not the index-graph insight, so it is easier to prove on a whiteboard and also works on a stream you can re-read but not index randomly (e.g. a file). Cost O(n log n).

How to answer

Offer it first if you do not remember Floyd, then improve.

Likely follow-ups
  • Bit version: for each bit b, if the count of nums with bit b set exceeds the count among 1..n, the duplicate has bit b.
Several different values may repeat. Does Floyd still work?

No. The walk from 0 finds the entry of the one cycle it reaches, which is some duplicated value, but other duplicates may sit on other components. To list all of them you need marking (mutating) or extra space; read-only with O(1) space and all duplicates is not possible in linear time in general.

How to answer

Point at which assumption the proof used: exactly one value has two predecessors.

Likely follow-ups
  • Return any one duplicate in that setting: Floyd from 0 still returns a valid one.
