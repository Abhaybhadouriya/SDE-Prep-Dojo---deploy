Approaches: brute -> better -> optimal

Hint 1

Every value is between 1 and n, and the array has indices 0..n. What happens if you follow nums[i] as if it were a "next" pointer?

Hint 2

Two indices hold the same value, so one node has two incoming arrows. In a linked list, which node has two incoming arrows? The entry of a cycle.

1. Brute force - compare every pair (or use a set)

Idea: two loops, return the first nums[i] == nums[j]. O(n2), times out at 105. A hash set (or a seen[] array of size n + 1) gives O(n) time but O(n) space; sorting gives O(n log n) but modifies the array. Both break a rule, which is the point of the question.

O(n)time (set)
O(n)space - not allowed

2. Better - binary search on the value, count with pigeonhole

Idea: guess a value mid in [1, n] and count how many entries are <= mid. If that count is greater than mid, the repeated value is <= mid; otherwise it is > mid. Halve the range until one value remains.

Why it works: every non-repeated value appears at most once, so values in 1..mid that are not the duplicate contribute at most mid entries. Only the duplicate, if it lies in 1..mid, can push the count over mid (it contributes 2+). If the duplicate is above mid, the count is at most mid. The predicate "count(<= mid) > mid" is therefore false ... false, true ... true, and we want the first true.

O(n log n)time
O(1)space, read-only

What is left: log n full passes over the array. The follow-up asks for one linear pass. -> use the structure the values give you.

3. Optimal - Floyd's tortoise and hare on i -> nums[i]

  1. Graph: nodes are indices 0..n; node i has one outgoing arrow to nums[i]. Every node has out-degree 1, so walking from any node must eventually repeat a node: it ends in a cycle.
  2. Index 0 is outside the cycle: no value is 0, so no arrow enters 0. The walk 0 -> nums[0] -> ... therefore has a tail of length at least 1 before the cycle.
  3. The entry is the answer: the cycle entry e is reached from its predecessor on the tail and from its predecessor on the cycle. Those are two different indices i, j with nums[i] = nums[j] = e, so e has two or more arrows in (the repeated value may appear several times, e.g. [2,2,2,2,2]). Only the repeated value is stored at more than one index, so e is the duplicate.
  4. Phase 1: slow moves one hop, fast moves two; inside the cycle fast gains one node per move, so they must meet.
  5. Phase 2: put a pointer at 0, keep slow at the meeting point, move both one hop at a time; they meet at e.

Why phase 2 lands on the entry: let the tail have F nodes and the cycle C nodes, and say they meet a nodes past the entry. Slow walked F + a, fast walked 2(F + a), and fast is ahead by whole laps: F + a = kC. So a + F is a multiple of C: walking F more hops from the meeting point brings slow back to the entry, and a pointer starting at 0 also reaches the entry after F hops. They arrive together. This is exactly Linked List Cycle II; the most-voted community solution makes the same reduction.

Two styles, do not mix them: if phase 1 starts at nums[0] (slow = nums[0], fast = nums[nums[0]], one hop ahead of 0), phase 2 must start finder at nums[0] too.
Or start both phases at 0 with move-then-compare, as our code does.

O(n)time
O(1)space, read-only
