Revision card

  • Cue: n + 1 values in 1..n, read-only, O(1) space -> linked list i -> nums[i].
  • Insight: nothing points to 0, so a tail then a cycle; the entry has two or more arrows in = the duplicate.
  • State: slow/fast from 0 until they meet; then finder from 0 and slow, 1 hop each, meet at the entry (F + a = kC).
  • Trap: start both phases from index 0 (or both from nums[0]); never mix the two styles.
  • Cost: O(n) time, O(1) space; fallback binary search on value, count(<= mid) > mid -> go left, O(n log n).
meet = run(slow=1 hop, fast=2 hops, from start)   # Floyd phase 1
entry = walk(a=start, b=meet, 1 hop each)       # phase 2: first a == b

Quick quiz

Why must the walk start at index 0?

  1. It is the smallest index
  2. No value is 0, so index 0 has no incoming arrow and lies on the tail, outside the cycle
  3. nums[0] is always the duplicate
  4. Any index works equally
A start outside the cycle guarantees a tail, and the tail's end is the doubly-entered node.

nums = [1,3,4,2,1] (n = 4). For mid = 2, how many entries are <= 2, and where is the duplicate?

  1. 2, right half
  2. 2, left half
  3. 3, so it is <= 2
  4. 4, so it is <= 1
1, 2, 1 are <= 2: count 3 > 2, so the duplicate is in [1, 2] (it is 1).

Why does sum(nums) - n(n+1)/2 fail on [3,3,3,3]?

  1. The duplicate repeats more than twice and 1, 2 are missing
  2. Integer overflow
  3. The array is unsorted
  4. n is too small
12 - 6 = 6, not 3. The formula assumes every value is present and the duplicate is there exactly twice.
