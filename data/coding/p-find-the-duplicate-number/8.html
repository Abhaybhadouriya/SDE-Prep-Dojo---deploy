Common mistakes

Returning the meeting point of phase 1. The pointers meet somewhere inside the cycle (index 1 in the dry run), not necessarily at the entry. You need phase 2.

Starting the walk at index n or at a random index. Only index 0 is guaranteed to be outside the cycle (no value is 0). From an index inside the cycle there is no tail and the "entry" is meaningless.

Using sum or XOR. They assume the duplicate appears exactly twice and all other values are present. The constraints allow "two or more times".

Comparing before moving with both pointers at 0. while (slow != fast) with slow = fast = 0 never runs. Move first (do-while), or start from nums[0] / nums[nums[0]].

Binary search on indices instead of values. The array is not sorted; the search space is the value range 1..n and the test is a count over the whole array.
