The story

Explain like I'm 5

A vending machine must pay back change using as few coins as possible, and it has an endless supply of each coin type. For normal money, "always give the biggest coin that fits" works. But in a strange country with coins 1, 3 and 4, paying 6 that way gives 4 + 1 + 1 (three coins) while 3 + 3 needs only two. So the machine cannot be greedy. It has to remember, for every smaller amount, the fewest coins that make it, and build up from there.

Every amount is a small puzzle whose answer reuses the answers of smaller amounts. That reuse is the whole of dynamic programming here.

From your world

Think of shortest path on a number line: nodes are amounts 0..amount, and each coin c is an edge of weight 1 from a - c to a. The fewest coins is the shortest path from 0 to amount. The DP table is a BFS / Bellman-Ford over that graph, filled in order because every edge goes forward. Routers do the same with hop counts.
