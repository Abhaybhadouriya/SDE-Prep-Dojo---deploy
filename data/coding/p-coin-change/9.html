  • Cue: fewest items to hit an exact sum, items reusable -> unbounded knapsack table.
  • Insight: fix the LAST coin: best[a] = 1 + min(best[a - c]); greedy fails (1,3,4 -> 6).
  • State: best[0..amount], best[0] = 0, others amount + 1 (= unreachable).
  • Trap: INT_MAX + 1 overflow; check c <= a; return -1 when still the sentinel.
  • Cost: O(amount · coins) time, O(amount) space; plain recursion exponential.
dp = [0] + [INF] * target
for t in range(1, target + 1):
    for item in items:
        if item <= t:
            dp[t] = min(dp[t], dp[t - item] + 1)   # + for "ways", max for "most"
return dp[target] if dp[target] < INF else -1

Why fill the table with amount + 1 instead of INT_MAX?

  1. it is smaller
  2. 1 + INT_MAX overflows to a negative number and wins the min
  3. INT_MAX is not allowed
  4. to save memory
No answer uses more than amount coins, so amount + 1 means 'unreachable' and 1 + it is still safe.

Coins {1, 3, 4}, amount 6. What does greedy (largest first) give, and what is right?

  1. 3 coins (4+1+1); right is 2 (3+3)
  2. 2 and 2
  3. 3 and 3
  4. greedy fails to find any
Greedy works only for canonical coin systems. The DP tries every last coin.
