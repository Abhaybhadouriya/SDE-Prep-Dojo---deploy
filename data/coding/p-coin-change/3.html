Recognise the pattern

When you see "fewest / most / number of ways" to reach a target sum with items you can reuse, think unbounded knapsack, a 1D table indexed by the sum. Fewest -> min; number of ways -> + (and then the loop order matters, see Coin Change II).

Try greedy on a few coin sets:

CoinsAmountGreedy (largest first)BestGreedy OK?
1, 5, 10, 253025+5 = 22✓
1, 3, 464+1+1 = 33+3 = 2✗
2, 565 then stuck2+2+2 = 3✗ (even finds nothing)

Greedy only works for special ("canonical") coin systems, so the general answer is DP.
