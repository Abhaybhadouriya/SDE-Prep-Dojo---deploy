Common mistakes

Using greedy. Sorting coins and taking the largest first is wrong for {1, 3, 4} and can even miss a solution for {2, 5} and amount 6.

INT_MAX + 1. Filling the table with INT_MAX and computing best[a - c] + 1 overflows to a negative number, which then wins every min. Use amount + 1 as the sentinel.

Forgetting c <= a. A negative index reads garbage in C++ and wraps around in Python (best[-1] is the last cell), silently giving wrong answers.

Mixing up with Coin Change II. Counting combinations needs coins in the outer loop; counting with amounts outer counts orderings (1+2 and 2+1 twice). For the minimum, both loop orders are correct.
