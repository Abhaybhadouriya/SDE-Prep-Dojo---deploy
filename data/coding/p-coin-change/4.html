Approaches: brute → better → optimal

Hint 1

Do not think about all coins at once. Look at the last coin of an optimal answer. If it is c, what is left?

Hint 2

What is left is amount - c, and it must also be paid optimally. So you need the answer for every smaller amount.

1. Brute force - try every last coin, recursively

Idea: f(a) = 0 if a = 0, otherwise 1 + min over coins c <= a of f(a - c), with "impossible" propagating up.

O(kamount)time, k = #coins
O(amount)stack depth

What is wasted: there are only amount + 1 different arguments, but the tree computes each of them many times. -> cache them.

2. Better - memoised recursion (top-down)

Idea: the same recursion with a memo[a] array. Each amount is solved once, by trying k coins.

@cache
def f(a):
    if a == 0: return 0
    return min((f(a - c) + 1 for c in coins if c <= a), default=INF)
O(amount · k)time
O(amount)memo + stack

What is wasted: recursion depth up to 104 (coin 1) hits Python's default limit and costs call overhead. -> fill the same table bottom-up.

3. Optimal - bottom-up table

best = [0] + [amount + 1] * amount        # amount + 1 = "unreachable"
for a in range(1, amount + 1):
    for c in coins:
        if c <= a: best[a] = min(best[a], best[a - c] + 1)
  • State: best[a] = the fewest coins that sum to exactly a.
  • Transition: best[a] = 1 + min(best[a - c]) over coins c <= a (c is the last coin).
  • Base case: best[0] = 0; every other cell starts at amount + 1, a value no real answer can reach (the most coins ever needed is amount, all 1s).
  • Answer: best[amount], or -1 if it is still amount + 1.
  • Space optimisation: already 1D; the table itself is the minimum, since any amount may be needed.
O(amount · k)time
O(amount)space

Why it works: any optimal way to pay a ends with some coin c, and the rest is a way to pay a - c; if that rest were not optimal, swapping in a better one would improve the whole (optimal substructure). Cells are filled in increasing order, and every transition reads a smaller index, so each read is already final.

Proof (optional)

By induction on a. best[0] = 0 is correct. Suppose best[x] is correct for all x < a. Any multiset of coins with sum a and size m contains some coin c; removing it gives sum a - c with size m - 1 >= best[a - c], so m >= best[a - c] + 1 >= best[a]. Conversely the table value is achieved by the optimal set for a - c plus c. So best[a] equals the true minimum; if no c leads to a reachable a - c, the cell stays at the sentinel, meaning impossible.

4. Alternative - BFS over amounts

Idea: level k of a BFS from 0 holds the amounts payable with exactly k coins; the first level that contains amount is the answer. Same O(amount · k) bound, and it can stop early when the answer is small. Useful to mention because it shows the shortest-path view.
