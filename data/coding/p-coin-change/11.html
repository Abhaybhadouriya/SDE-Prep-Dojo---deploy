Count the number of ways instead (Coin Change II).

ways[0] = 1; for each coin (outer loop), for a from coin to amount: ways[a] += ways[a - coin]. Coins outer means each combination is counted once, in coin order.

How to answer

Each coin can be used at most once.

That is 0/1 knapsack: iterate amounts downwards inside the coin loop (for a in range(amount, c - 1, -1)) so each coin is read only from the previous coin's row.

How to answer

Explain that the upward loop lets a cell reuse the same coin; the downward loop prevents it.

Likely follow-ups
  • Each coin has a limited count (bounded knapsack; binary splitting of counts).
Is greedy ever correct? When can you use it?

For canonical coin systems such as 1, 2, 5, 10, 20, 50, ... greedy is optimal. In general it is not, and checking whether a system is canonical is itself a known (polynomial) problem. In an interview, give the counter-example and use DP.

How to answer

One counter-example beats any argument: {1, 3, 4} and 6.

Likely follow-ups
  • Prove greedy is right for {1, 5, 10, 25} (exchange argument).
amount is 109 but there are only 3 coins. What now?

A table of 109 cells is too big. Use the largest coin as many times as possible and run DP only on a bounded remainder (the answer uses at most max coin copies of the smaller coins, by a pigeonhole argument on remainders), or BFS on remainders modulo the largest coin (shortest path in a graph of size max coin).

How to answer

Show you notice the table size first, then reduce the state space; exact bounds can be worked out together.

Likely follow-ups
  • Frobenius number: the largest amount that cannot be made with two coprime coins a, b is ab - a - b.
