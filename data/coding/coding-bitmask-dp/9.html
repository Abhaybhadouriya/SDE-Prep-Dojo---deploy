Common mistakes

  • Operator precedence. In C, C++ and Java, mask & 1 << i == 0 does not mean what it looks like: == binds tighter than &, so it computes mask & ((1 << i) == 0). Always write (mask >> i & 1) == 0 or (mask & (1 << i)) == 0. (Go puts & above ==, but use the brackets anyway.)
  • 1 << 31 or 1 << n with n >= 31 in 32-bit int. Use 1L / 1LL / uint64 when masks go past bit 30 (masks over 40 hats, say).
  • Memory of 2n x n. dp[1 << 20][20] of 64-bit values is 160 MB. Use int32, drop a dimension, or BFS layer by layer.
  • Allowing an item twice. Check mask & (1 << i) before setting the bit; mask | bit == mask means "already used".
  • Wrong order for submask DP. Increasing mask order works because every submask is numerically smaller. Iterating in another order (by popcount, say) needs a reason.
  • Forgetting the empty submask in the (sub - 1) & mask loop, which stops before 0. Handle "this person takes nothing" separately when it is allowed.
  • BFS on (node, mask) with a visited array over nodes only. That forbids the revisits the problem needs.
  • 3n where n = 20. Submask enumeration is for n up to about 16; for 20 you need an n 2n formulation.
