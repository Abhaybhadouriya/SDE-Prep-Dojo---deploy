Also return the route, not just the price.

Keep a parent table per round: par[r][v] = u when round r improved v through u (when a round does not improve v, it inherits par[r - 1][v] at round r - 1). Walk back from (k + 1, dst). A single parent array is wrong, because the best route to v with r flights and with r + 1 flights can come from different predecessors. O(k · n) extra space.

How to answer

Point out that the parent depends on the round, the same way cost does.

Likely follow-ups
  • With Dijkstra on (city, flights), store the parent state instead.
Bellman-Ford or Dijkstra here: which one, and when?

Bellman-Ford: O(k · E), O(n) space, no heap, and it handles the hop limit by construction. Dijkstra on (city, flights): can stop early the moment dst is popped, so it is faster when the cheap route is short and the graph is large, but it uses O(k · E) heap space and needs the dominance pruning. For n ≤ 100 both are instant; pick the one you can write without bugs.

How to answer

Compare by the bound on work and memory, then say what you would code and why.

Likely follow-ups
  • What if some prices were negative (no negative cycles)? Dijkstra breaks; the k + 1 round Bellman-Ford still works.
Many queries: different (src, dst, k) on the same network.

For a fixed source, one run with K = max k gives the answer for every dst and every k ≤ K if you keep each round's array: O(K · E) once, O(1) per query. For many sources, run it once per distinct source, or precompute an n × n "min-plus" matrix power: A^r[i][j] = cheapest with at most r edges, O(n^3 log K) with repeated squaring.

How to answer

Group queries by source first; matrix min-plus products are the general answer.

Likely follow-ups
  • Why does min-plus matrix multiplication give "at most r edges"? Add a zero self-loop on each node.
What if the limit is on total travel time, with every flight having a duration?

The budget becomes a number up to maxTime instead of a count up to k. Use DP over (time, city) when maxTime is small (LC 1928: cost[t][v]), or Dijkstra on cost with the state (city, time used) and pruning on "less time used". Same idea: the second resource goes into the state.

How to answer

Name LC 1928 Minimum Cost to Reach Destination in Time as the generalisation.

Likely follow-ups
  • Complexity depends on maxTime: pseudo-polynomial.
Can you do it with BFS?

Yes: BFS by levels where level = flights used. Queue entries are (city, cost); for each level, for each popped entry and each flight, push (v, cost + p) only if it beats best[v]. Stop after k + 1 levels. With that pruning it is SPFA restricted to k + 1 levels, O(k · E) worst case. Without the pruning it explodes.

How to answer

Say why BFS needs the "cheaper than best" check even though plain BFS uses a visited set.

Likely follow-ups
  • Why not a visited set? A city may be worth revisiting at a later level with a lower cost.
