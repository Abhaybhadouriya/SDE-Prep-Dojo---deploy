Approaches: brute → better → optimal

Hint 1

Rewrite "at most k stops" as a limit on the number of edges.

Hint 2

If you knew the cheapest cost to every node using at most r edges, how would you get it for r + 1 edges?

Hint 3

That is one Bellman-Ford round. Make sure a round cannot use an edge twice in a chain.

1. Brute force - DFS over all routes

Idea: from src, try every outgoing flight recursively, carrying the cost so far and the flights used; stop a branch when it uses more than k + 1 flights; record the best cost when you land on dst.

def dfs(u, cost, used):
    if u == dst: best = min(best, cost); return
    if used == k + 1: return
    for v, p in adj[u]: dfs(v, cost + p, used + 1)   # no memo: exponential
O(d^(k+1))time (d = out-degree)
O(k)stack

What is wasted: the same (city, flights used) pair is reached by many routes and explored again each time. Pruning with "cost ≥ best so far" helps but the worst case stays exponential. The repeated pair is the state we should store.

2. Better - Dijkstra on the state (city, flights used)

Idea: push (cost, city, flights) into a min-heap. When you pop a state, the cost is the cheapest for that many flights or more. Keep fewest[city] = the smallest flight count already popped for that city: if a new pop has flights ≥ fewest[city], an earlier pop was both cheaper and shorter, so skip it. Return the cost the first time dst is popped.

heap = [(0, src, 0)]; fewest = [inf] * n
while heap:
    cost, u, used = heappop(heap)
    if u == dst: return cost
    if used >= fewest[u] or used == k + 1: continue   # dominated, or no flights left
    fewest[u] = used
    for v, p in adj[u]: heappush(heap, (cost + p, v, used + 1))
return -1
O(k · E log(k · E))time
O(k · E)heap

Why it works: on the expanded graph whose nodes are (city, flights), all weights are positive, so Dijkstra is correct there. The fewest check prunes states that are dominated in both cost and flights. The most-voted community post shows that the version without this pruning now times out on LeetCode.

3. Optimal (simplest to get right) - Bellman-Ford for k + 1 rounds

cost = [inf] * n; cost[src] = 0           # core: 7 lines
for _ in range(k + 1):                    # one round = one more flight allowed
    nxt = cost[:]                         # read OLD costs, write new ones
    for u, v, p in flights:
        if cost[u] + p < nxt[v]: nxt[v] = cost[u] + p
    cost = nxt
return -1 if cost[dst] == inf else cost[dst]
  1. Translate the limit. k stops = at most k + 1 flights.
  2. State: cost[v] = cheapest price to reach v using at most r flights, for the current round r. Start with cost[src] = 0, everything else infinity (r = 0).
  3. One round: for every flight u → v, a route to u with at most r flights plus this flight is a route to v with at most r + 1 flights. Take the minimum.
  4. Read from the old round only. Write into a copy nxt; read from cost. Otherwise a value improved earlier in the same round is extended again, and a round adds several flights at once.
  5. Stop after k + 1 rounds. cost[dst] is the answer, or -1 if still infinite.
  1. Graph: depots are vertices, each flight a directed weighted edge.
  2. Traversal: k + 1 rounds of Bellman-Ford; each round relaxes every edge once, reading last round's cost and writing a copy nxt.
  3. Visited rule: none needed: the round counter bounds the number of flights, and reading from the copy stops one round from chaining two flights.
  4. Answer: cost[dst] after k + 1 rounds, or -1 if it is still infinite.
O((k + 1) · E)time (≤ 495,000 relaxations here)
O(n)space (two arrays)
Proof (optional) - why the invariant holds

By induction on r. For r = 0 only src is reachable with zero flights, at cost 0. Assume cost holds the true optimum for at most r flights. A best route to v with at most r + 1 flights either has at most r flights (then nxt[v] starts as cost[v], which already holds it) or ends with some flight u → v whose prefix is a route to u with at most r flights, costing at least cost[u]; the round tries cost[u] + p for every such flight. Every value written is the price of a real route with at most r + 1 flights, because it only extends values from the previous round. So after the round, nxt[v] is exactly the optimum. Writing into the same array would break the second half: cost[u] could already be an (r + 1)-flight value.

Stuck? The BFS-by-levels variant

Many top solutions use BFS: the queue holds (city, cost) for the current level; each level is one flight; push a neighbour only if cost + p < best[v]. Process at most k + 1 levels. It is the same algorithm as above, relaxing only from cities that changed in the last level (an SPFA-style queue). Worst case O(k · E) too.
