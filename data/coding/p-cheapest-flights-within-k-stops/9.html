Revision card

  • Cue: cheapest path + "at most k stops/edges" → Bellman-Ford with k + 1 rounds.
  • Insight: after round r, cost[v] = cheapest with ≤ r edges; k stops = k + 1 edges.
  • State: cost[] for the previous round, nxt[] for the one being built.
  • Trap: copy each round; k + 1 rounds, not k; plain Dijkstra fails; guard INF + price.
  • Cost: O(k · E) time, O(n) space; Dijkstra on (city, flights) O(kE log kE).
cost = [INF] * n; cost[src] = 0
repeat R rounds:                 # R = edges allowed
    nxt = copy(cost)
    relax every edge (u, v, w) from cost into nxt
    cost = nxt

Quick quiz

k = 3 stops are allowed. How many Bellman-Ford rounds do you run?

  1. 2
  2. 3
  3. 4
  4. n - 1
3 stops = at most 4 flights, and each round adds one flight.

Why does each round read from a copy of the previous array?

  1. So one round adds at most one flight to any route
  2. To save memory
  3. To avoid negative cycles
  4. Because flights are unsorted
Reading values written in the same round lets one round chain several flights.

Plain Dijkstra (one distance per node) fails here because...

  1. Prices can be negative
  2. A cheaper route to a node may use too many flights to continue
  3. The graph is undirected
  4. It is too slow
The state must include the flights used; a dearer, shorter route can be the only valid one.
