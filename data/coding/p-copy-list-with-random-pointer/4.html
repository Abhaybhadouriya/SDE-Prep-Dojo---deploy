Approaches: brute → better → optimal

Hint 1

If you had a function copyOf(oldNode), every pointer of the copy would be copyOf(old.next) and copyOf(old.random). How do you implement it?

Hint 2

Can you put each copy somewhere you can reach from the original in O(1), without a hash map? Look at the original's next field.

1. Brute force - find random targets by index

Idea: copy the next chain first. For each original node, walk from the head to find the index of its random target, then walk the copy to that index.

O(n²)time
O(1)extra space

What is wasted: each lookup walks the list again. The question "where is the copy of X?" should take O(1). -> a map.

2. Better - hash map old -> new

Idea: pass 1 creates a copy for every node and stores map[old] = new. Pass 2 sets map[old].next = map[old.next] and map[old].random = map[old.random] (with map[null] = null).

O(n)time
O(n)extra space

Why it is the safe answer: it is short, obviously correct, and the same code clones any graph (LC 133). What is wasted: the map is n extra entries, and hashing costs time. -> rung 3 stores the map inside the list.

3. Optimal - weave, wire, unweave

cur = head
while cur: cur.next = Node(cur.val, cur.next); cur = cur.next.next       # weave
cur = head
while cur: cur.next.random = cur.random.next if cur.random else None; cur = cur.next.next
# unweave: cur.next = copy.next; copy.next = copy.next.next
  1. Weave. Insert each copy right after its original: A -> A' -> B -> B' -> C -> C'. Now X.next is copyOf(X).
  2. Wire random. For each original X: X.next.random = X.random.next, i.e. copyOf(X).random = copyOf(X.random). Guard X.random == null.
  3. Unweave. Walk again: original skips its copy (X.next = X'.next), copy jumps to the next copy (X'.next = X'.next.next, or null at the end).
  4. Return the first copy (saved as head.next before unweaving). The input list is exactly as it was.
O(n)time (3 passes)
O(1)extra space (the copy itself is output)

Why it works: the weaving keeps every original reachable in its old order (every second node), and makes "the copy of X" a fixed offset of one step from X. Random wiring must finish before unweaving, because unweaving destroys that offset.

Proof (optional)

After pass 1, for every original X, X.next = X' and X'.next = the original that followed X. Pass 2 only writes random fields of copies, so the structure is unchanged and X.random.next = (X.random)' holds for every X with a non-null random. Pass 3 restores X.next to the original successor and sets X'.next = (X.next)'. So the copies form a list in the same order with the correct random targets, and no copy pointer ever stores an original node.
