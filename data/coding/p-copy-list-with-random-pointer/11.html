Interview follow-ups

Do it without a hash map.

Weave the copies into the list, wire random through X.random.next, then unweave. Three passes, O(1) extra space.

How to answer

Draw A A' B B' first; the formula for random falls out of the picture.

Likely follow-ups
  • Can you merge passes 2 and 3? (No: unweaving early breaks X.random.next for later nodes whose random points backwards.)
Write it recursively.

copy(node): if null return null; if node in map return map[node]; create the copy, store it in the map before recursing, then set next = copy(node.next), random = copy(node.random). Storing first stops infinite recursion on cycles through random.

How to answer

Point out the recursion depth is n (1000 here, fine), but a 106-node list would overflow the stack.

Likely follow-ups
  • Convert it to an explicit stack.
The input list must not be modified, even temporarily (another thread reads it).

Then weaving is not allowed; use the hash map version, which only reads the input. Trade-off: O(n) extra space for safety under concurrent readers.

How to answer

Say that the O(1) trick mutates shared state, which matters in real systems.

Likely follow-ups
  • What if writers can change the list during the copy? (You need a lock or a snapshot / RCU-style read side.)
Serialise the list to send it over the network, then rebuild it.

Give each node an index in next-order, send [val, randomIndex] pairs (the judge's own format), and rebuild with an array of new nodes: nodes[i].random = nodes[r]. Indices replace pointers, the way a relocation table replaces addresses.

How to answer

Mention that pointers are meaningless across address spaces; indices are stable.

Likely follow-ups
  • Same for a general graph (adjacency list of indices).
How do you test your copy?

Serialise both lists to [val, randomIndex] and compare; check that no copy node (or copy random target) is an original node by identity; check the input serialises the same after the call.

How to answer

List the three properties: same shape, disjoint nodes, input unchanged. Our test drivers check exactly these.

Likely follow-ups
  • Random testing against the hash map version.
