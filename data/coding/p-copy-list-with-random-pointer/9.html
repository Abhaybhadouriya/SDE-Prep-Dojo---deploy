  • Cue: deep copy with pointers that can point anywhere -> need old -> new mapping.
  • Insight: weave A -> A' -> B: then copyOf(X) = X.next, no hash map.
  • State: cur (original), copy = cur.next; 3 passes: weave, random, unweave.
  • Trap: null random guard; finish random wiring before unweaving; restore input.
  • Cost: O(n) time, O(1) extra; hash map version O(n) extra.
clone = {None: None}
for old in all_nodes(start):            # pass 1: make every copy
    clone[old] = Node(old.val)
for old in all_nodes(start):            # pass 2: wire pointers by lookup
    clone[old].next = clone[old.next]
    clone[old].random = clone[old.random]
return clone[start]

After weaving A → A' → B → B', what is A'.random?

  1. A.random
  2. A.random.next (when A.random is not null)
  3. A.next.random
  4. B'
Each copy sits right after its original, so copyOf(X) = X.next.

Why must all random pointers be wired before you unweave?

  1. unweaving breaks X.next, which the random wiring needs
  2. it is faster
  3. random can only point forward
  4. to keep the copy sorted
Once the lists are separated, X.next no longer leads to X's copy.

What does the hash-map version cost compared with the weave?

  1. the same
  2. O(n) extra space for old → new
  3. O(n²) time
  4. it cannot handle cycles in random
Both are O(n) time. The weave reuses the list itself as the map, so it is O(1) extra.
