The problem (in our words)

You get the head of a singly linked list of n nodes. Each node has an integer val, a next pointer and a random pointer that is either null or points to some node of this same list. Build a deep copy: exactly n brand-new nodes, where each new node has the same value as its original, and its next and random point to the new nodes that correspond to the originals' targets. No pointer of the copy may point into the original list. Return the head of the copy.

Signature: Node copyRandomList(Node head). For testing, a list is written as an array of [val, random_index] pairs, where random_index is the 0-based index of the node that random points to, or null. Your function only receives the head node.

Constraints

  • 0 <= n <= 1000
  • -104 <= Node.val <= 104
  • Node.random is null or points to a node in the list.

Practice it: LeetCode 138 · GfG Clone a linked list with next and random pointer · TUF article

Constraints tell you: n ≤ 1000 means even O(n²) passes, so the interview is about the space: hash map O(n) versus weaving O(1). Values can repeat (the "4, 4, 4" example), so you cannot map by value; you must map by node identity.
