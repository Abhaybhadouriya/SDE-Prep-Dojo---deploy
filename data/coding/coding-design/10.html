How to recognise the pattern

Cues: the problem is a class with several methods and a cost per method. "Evict least recently used": map + doubly linked list. "Least frequently used": buckets by count + minFreq. "getRandom": array + index map. "min / max while pushing and popping": store the running answer per item. "In the last N seconds": deque or ring of buckets. "At time t": sorted history + binary search. "Iterator": a stack of the frontier, work in hasNext.

Ask yourselfIf yes
Do I need to find an item by key and also move it in an order?map whose value is a list node
Does an aggregate (min, max, sum) only change at one end?store the aggregate with each element
Do counts change by exactly one?buckets of counts in a linked list (O(1) neighbours)
Is old data useless after a window?ring buffer with fixed memory, or a deque you trim from the front
Is the input already in time order?append-only lists stay sorted; binary search them
