Interview follow-ups

Why BFS and not DFS?

BFS pops nodes in row order and, inside a row, left to right, which is exactly the required order inside a column. DFS visits a whole subtree first, so a deep node can be recorded before a shallower node of the same column. DFS works only if you also record the row and a left-to-right rank and then sort.

How to answer

Give the counter-example tree (a deep left node drifting right).

First pass: DFS to find min and max column (or use n as a safe offset). Then allocate hi - lo + 1 lists and BFS with index col - lo. Two passes, still O(n), and cache-friendlier.

Now same-cell ties must be ordered by value (LC 987).

BFS order is no longer enough. Record (col, row, val) per node and sort once, or keep BFS and sort only within each (col, row) cell. O(n log n) worst case.

How to answer

Print only the top view and the bottom view.

Same BFS. Top view: write first[col] only if empty. Bottom view: always overwrite last[col]. Output from lo to hi.

Return the sum of each column instead of the values. What changes?

The order requirement disappears, because addition does not care about order. Keep one running sum per column (a map, or an array offset by -lo after a first pass) and use any traversal: a recursive DFS needs only O(h) stack instead of a BFS queue that can hold a whole level (up to n/2 nodes).

How to answer

Notice that sums drop the ordering requirement, so any traversal works.
