Approaches: brute -> better -> optimal

Hint 1

Which traversal visits nodes top to bottom, and left to right inside a row?

Hint 2

A child's column differs from its parent's by exactly 1. What does that say about the set of columns that appear?

1. Brute force - DFS with (col, row, order), then sort

Idea: any DFS records (col, row, left-to-right rank, value) per node, then one sort by the first three fields and a grouping pass. The rank can be the position in BFS order, or the root-to-node path as a 0/1 string.

O(n log n)time
O(n)space

Why it is not enough: correct, but you are sorting to rebuild an order that BFS gives for free. It is also easy to forget the row (see the figure above), which makes DFS output wrong.

2. Better - BFS into a sorted map

Idea: BFS with (node, col), appending into a TreeMap<col, list>. Values in each list are already in the right order; the ordered map sorts the column keys.

O(n log w)time, w = number of columns
O(n)space

This is the top-voted community answer's shape and is perfectly fine. The last log factor goes away with one observation.

3. Optimal - BFS into a hash map plus min/max column

q = [(root, 0)]; cols = defaultdict(list); lo = hi = 0
for node, c in q (BFS):
    cols[c].append(node.val); lo = min(lo, c); hi = max(hi, c)
    push (left, c - 1), (right, c + 1)
return [cols[c] for c in range(lo, hi + 1)]
  1. BFS gives the in-column order. BFS pops all of row r before any node of row r + 1, and inside a row it pops nodes left to right (children are pushed left before right, parents were popped left to right). So, inside any column, values are appended top to bottom, ties left to right: exactly the required order.
  2. The columns are contiguous. A child's column is its parent's +/- 1, so the columns seen form one unbroken range [lo, hi]. Walking lo..hi lists every column, in order, with no key sort.
  3. Every node is pushed and popped once. O(n) total.
O(n)time
O(n)space

Why DFS fails without help: DFS finishes the whole left subtree before the right one. A deep node in the left subtree can drift right into a column that also holds a shallow node of the right subtree, and DFS records the deep one first. BFS is level-synchronous, so this cannot happen. (A DFS fix needs the row in the key and a sort, which is rung 1.)
