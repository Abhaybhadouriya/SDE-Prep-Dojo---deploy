Interview follow-ups

Merge k strings alternately (round-robin over k words).

Put the (word, index) pairs of non-empty words in a queue. Pop one, append its next letter, push it back if letters remain. O(total letters) time, O(k) queue. With all lengths known, you can also loop i to the max length and visit the k words in order.

How to answer

Present the queue as the general form; the two-word loop is k = 2 unrolled.

Likely follow-ups
  • As an iterator with hasNext/next? (LeetCode 281 Zigzag Iterator: the same queue, lazily.)
Take p letters from word1, then q from word2, per round.

Two pointers i and j; each round appends word1[i : i+p] then word2[j : j+q], clipped at the ends, until both are used up. Still O(n + m).

How to answer

Switch from one index to two pointers, because the words now advance at different speeds.

Likely follow-ups
  • Weighted round-robin for k queues? (Same with per-queue quotas; this is WRR scheduling.)
Undo it: given the merged string and n, recover word1 and word2.

The first 2·min(n, m) letters alternate: even positions are word1, odd are word2. After that, the tail belongs to the longer word (n > m means word1). O(n + m).

How to answer

Derive m = len - n first, then split by parity and the tail.

Likely follow-ups
  • Without knowing n? (Ambiguous: several splits give the same merge.)
The words are huge streams; output must also stream.

Read one byte from each stream per round and write it out immediately; when one stream hits EOF, copy the other through. O(1) memory with buffered I/O.

How to answer

Point out that the algorithm never looked back, so it is naturally streaming.

Likely follow-ups
  • Unicode strings? (Alternate code points or grapheme clusters, not bytes; Go range over a string yields runes.)
Do it in C with a caller-provided buffer.

Compute n + m, require the buffer to have n + m + 1 bytes, write with one index per source plus an output index, and terminate with '\0'. Return the length or an error if the buffer is too small.

How to answer

Talk about the size contract first; the loop itself is unchanged.

Likely follow-ups
  • In place, when word2 is already appended after word1 in one array? (Possible with rotations, but O(n·m) or tricky in-place shuffle algorithms; usually not worth it.)
