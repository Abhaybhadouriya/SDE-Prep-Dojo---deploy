Approaches: brute → optimal

Hint 1

Which characters are you allowed to ignore, and does "0P" read the same both ways? (Digits count, and 'A' equals 'a'.)

Hint 2

Which characters must the first kept character be equal to?

1. Clean copy, then compare with its reverse

Idea: build t from the letters and digits of s, lower-cased, and return t == reverse(t). Correct, and a fine first sentence.

O(n)time
O(n)extra space (copy + reverse)

What is wasted: two extra strings of up to n characters, and the comparison always runs to the end even when the first pair already differs.

2. Optimal - two pointers in place

while l < r:                                   # core
    if not s[l].isalnum(): l += 1
    elif not s[r].isalnum(): r -= 1
    elif s[l].lower() != s[r].lower(): return False
    else: l += 1; r -= 1
  1. The pointers stand on a pair that must match. The k-th kept character from the left must equal the k-th kept character from the right.
  2. Skip one side at a time. If s[l] is not alphanumeric, only l moves. Moving both on a skip would pair the wrong characters.
  3. Compare case-insensitively. Lower-case both before comparing; digits stay digits.
  4. Stop at l >= r. A middle character (odd length) has no partner and always matches itself.
O(n)time (each index visited once)
O(1)space

Why it works: after skipping, l and r point at the k-th kept character from each end, for k = 1, 2, ... A palindrome is exactly "every such pair is equal", so checking pairs until the pointers meet is the definition, evaluated lazily. It can also stop at the first mismatch.
