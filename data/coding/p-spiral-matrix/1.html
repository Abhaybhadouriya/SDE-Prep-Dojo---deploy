The problem (in our words)

You get a grid matrix with m rows and n columns of integers. Return a list of all m·n values in clockwise spiral order: start at the top-left cell, go right along the first row, then down the last column, then left along the last row, then up the first column, and keep going inward in the same way until every cell has been listed exactly once.

Signature: List<Integer> spiralOrder(int[][] matrix) (LeetCode style; read the grid, return the list).

  • m == matrix.length
  • n == matrix[i].length
  • 1 <= m, n <= 10
  • -100 <= matrix[i][j] <= 100

Practice it: LeetCode 54 · GfG Spirally traversing a matrix · TUF article · CodeChef SPMAT

Constraints tell you: at most 100 cells, so speed is never the issue; every cell must be read once anyway, so O(m·n) is optimal. The constraint that matters is m, n >= 1: the grid is never empty, but it can be a single row or a single column, and those are exactly the shapes that break careless code.
