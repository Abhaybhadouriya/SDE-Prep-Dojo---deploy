Revision card

  • Cue: visit a grid in spiral / layer order -> simulate with shrinking boundaries.
  • Insight: the unread cells always form one rectangle top..bottom × left..right.
  • State: top, bottom, left, right; output list.
  • Trap: guard bottom row with top<=bottom and left col with left<=right.
  • Cost: O(m·n) time, O(1) extra; visited-grid version O(m·n) space.
t, b, l, r = 0, m - 1, 0, n - 1
while t <= b and l <= r:
    row(t, l..r); t += 1
    col(r, t..b); r -= 1
    if t <= b: row(b, r..l); b -= 1
    if l <= r: col(l, b..t); l += 1

Quick quiz

Which input breaks a version that has no guard on the bottom row?

  1. [[1,2],[3,4]]
  2. [[1,2,3],[4,5,6],[7,8,9]]
  3. [[1,2,3]]
  4. [[7]]
A single row: after top++ the "bottom row" is the same row, so 3, 2 would be appended again. 1×1 survives because the reversed range right..left is empty.

The left-column pass is guarded by which condition?

  1. top <= bottom
  2. left <= right
  3. top < bottom
  4. none needed
A column needs columns left. After right--, left may have passed right, and the left column would be the one just read as the right column.

For a 3×4 grid, what are the run lengths in the step-count version?

  1. 4, 2, 3, 1, 2
  2. 4, 3, 4, 3
  3. 4, 2, 4, 2, 2
  4. 3, 4, 2, 3, 1
Horizontal runs n, n-1, n-2 = 4, 3, 2; vertical runs m-1, m-2 = 2, 1; they alternate, and the next vertical run is 0.
