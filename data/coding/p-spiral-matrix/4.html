Approaches: brute → better → optimal

Hint 1

Draw the walk on a 3×4 grid. After the top row is read, can that row ever be visited again?

Hint 2

So the unread part is always a smaller rectangle. Four numbers describe it.

Hint 3

After reading the top row and the right column, check that a different bottom row and left column still exist before reading them.

1. Simulation - direction vector and a visited grid

Idea: stand on (0,0) facing right. Record the cell, mark it visited, and try to step forward. If the next cell is outside the grid or already visited, turn right (right → down → left → up) and step. Stop after m·n cells.

dirs = [(0, 1), (1, 0), (0, -1), (-1, 0)]
for _ in range(m * n):
    out.append(g[r][c]); seen[r][c] = True
    nr, nc = r + dirs[d][0], c + dirs[d][1]
    if not (0 <= nr < m and 0 <= nc < n) or seen[nr][nc]:
        d = (d + 1) % 4; nr, nc = r + dirs[d][0], c + dirs[d][1]
    r, c = nr, nc
O(m·n)time
O(m·n)space (visited)

What is wasted: the visited grid stores something we already know: the visited cells always form the outer rings. Four integers can describe the unvisited rectangle. (You could mark visited cells in the input itself, but the values range over -100..100, so there is no safe sentinel unless you use something like 101, and changing the input is rarely welcome.) -> rung 2.

2. Optimal - shrink four boundaries

while top <= bottom and left <= right:
    read row top (left..right);      top += 1
    read col right (top..bottom);    right -= 1
    if top <= bottom: read row bottom (right..left);  bottom -= 1
    if left <= right: read col left (bottom..top);    left += 1
  1. The unread cells always form one rectangle. Rows top..bottom and columns left..right. Each side we read is the edge of that rectangle.
  2. Reading a side removes it. After the top row, top++; after the right column, right--; and so on. The rectangle shrinks by one row or column per side.
  3. The first two sides are always safe. The loop condition guarantees a top row exists; the right column loop simply runs zero times if no rows are left.
  4. The last two sides need a guard. If top just passed bottom, the "bottom row" is the row we already read as the top row, and reading it again would repeat values. Same for the left column after right--.
O(m·n)time
O(1)extra space (output not counted)

Why it works: every cell is appended exactly when the side that contains it is read, and that side is then cut off the rectangle, so no cell is appended twice. The loop runs while the rectangle is non-empty, so no cell is missed. The two guards are the only places where a "side" could be the same line as one we just read.

Proof (optional)

Invariant at the top of each loop: the output holds exactly the cells outside rows top..bottom × columns left..right, in spiral order. Reading the top row appends cells of row top within the column range, then top++ restores the invariant. The right column reads rows top..bottom (possibly none) of column right, then right--. The bottom row is read only if top <= bottom, so it is a row still inside the rectangle; same for the left column with left <= right. Each iteration removes at least one row, so the loop ends, and at the end the rectangle is empty: every cell was output once.

3. Alternative - step counts per direction

Idea: a top community solution notices that the walk is "right n, down m-1, left n-1, up m-2, right n-2, ..." Horizontal counts drop by one after every horizontal run, vertical counts after every vertical run. Start just left of (0,0) and walk with one loop and a direction table; stop when the next count is 0.

steps = [n, m - 1]; d = 0; r, c = 0, -1
while steps[d % 2]:
    for _ in range(steps[d % 2]):
        r += dirs[d][0]; c += dirs[d][1]; out.append(g[r][c])
    steps[d % 2] -= 1; d = (d + 1) % 4
O(m·n)time
O(1)space

When it is useful: there are no guards to forget, and changing the direction table gives counter-clockwise or other start corners for free. It is harder to explain on a whiteboard, so most people code rung 2.
