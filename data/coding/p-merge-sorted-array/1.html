The problem (in our words)

Two sorted lists of sensor readings must be combined. The first array nums1 has room for both: its first m entries are real readings in non-decreasing order, and its last n entries are placeholders (they hold 0 and must be ignored). The second array nums2 holds n readings, also in non-decreasing order. Merge nums2 into nums1 so that nums1 holds all m + n readings in non-decreasing order. Do it in place: the function returns nothing, and the result must be stored inside nums1.

  • Input: nums1 of length m + n, integer m, nums2 of length n, integer n.
  • Output: none; nums1 is modified. Signature: void merge(int[] nums1, int m, int[] nums2, int n).

Constraints

  • nums1.length == m + n
  • nums2.length == n
  • 0 <= m, n <= 200
  • 1 <= m + n <= 200
  • -10^9 <= nums1[i], nums2[j] <= 10^9

Follow-up asked by the original: can you do it in O(m + n) time?

Practice it: LeetCode 88 - Merge Sorted Array · GfG - Merge Without Extra Space (a harder twin: no buffer) · takeuforward

Constraints tell you: n ≤ 200 is tiny, so even "copy and sort" passes. The interview is really about the O(m + n), O(1)-extra-space merge and about handling m = 0 or n = 0 without a special case.
