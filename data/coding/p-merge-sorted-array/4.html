Approaches: brute → better → optimal

Hint 1

Where is the empty space in nums1? Which value of the final array do you know for sure first?

Hint 2

The largest value overall is the larger of nums1[m-1] and nums2[n-1]. Where does it go?

1. Brute force - copy in, then sort

Idea: write nums2 into the placeholder slots nums1[m..m+n-1], then sort all of nums1.

O((m+n) log(m+n))time
O(1) to O(log n)space (sort's stack)

What is wasted: both inputs are sorted, so a linear merge is possible. This answer misses the follow-up.

2. Better - forward merge with a copy

Idea: copy the first m values of nums1 aside, then run the usual merge step (take the smaller head) writing into nums1 from index 0.

O(m + n)time
O(m)extra space

What is wasted: the copy exists only because forward writes would overwrite unread values. Writing from the back needs no copy.

3. Optimal - merge from the back

i, j, w = m - 1, n - 1, m + n - 1        # core: 5 lines
while j >= 0:
    if i >= 0 and nums1[i] > nums2[j]: nums1[w] = nums1[i]; i -= 1
    else: nums1[w] = nums2[j]; j -= 1
    w -= 1
  1. The biggest remaining value is one of the two tails. Both arrays are sorted, so compare nums1[i] and nums2[j] and place the larger at w.
  2. The write head never passes the nums1 read head. w = i + j + 1 at all times, so w > i while nums2 still has values: the slot we write is free or already read.
  3. Stop when nums2 is empty. Whatever is left in nums1[0..i] is already sorted and already in its final place.
  4. If nums1 runs out first, keep copying nums2. The i >= 0 guard sends every remaining value to the else branch.
O(m + n)time
O(1)extra space

Why it works: the invariant is "nums1[w+1..] holds the largest values seen so far, in sorted order, and every value not yet placed sits in nums1[0..i] or nums2[0..j]". Each step moves the largest unplaced value into slot w, which keeps the invariant. When j < 0, the unplaced values are exactly nums1[0..i], already sorted and already at indices 0..i = 0..w.

Proof (optional) - no unread value is overwritten

Initially w = m + n - 1 = i + j + 1. Each step decrements w and exactly one of i or j, so w = i + j + 1 stays true. While j ≥ 0, that gives w ≥ i + 1 > i, so slot w is never an unread nums1 position. Slot w is either a placeholder or a nums1 value that was already moved.
