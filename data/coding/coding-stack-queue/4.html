Pattern 3: evaluating expressions

Reverse Polish notation first

In postfix (Reverse Polish) notation, 2 1 + 3 * means (2 + 1) * 3. There are no brackets and no precedence: each operator applies to the two most recent values. So numbers are pushed; an operator pops two, computes, and pushes the result (LeetCode 150). Pop order matters: the first pop is the right operand, so a - b and a / b come out the right way round. Division truncates toward zero; in Python that is int(a / b), not a // b, which floors (-7 // 2 is -4, the expected answer is -3).

Infix with precedence: the "pending operator" calculator

Basic Calculator II (227) gives a normal string like 3+2*2-4/2 with + - * / and spaces, no brackets. The trick avoids a full parser: keep a stack of terms that will be added at the end, and remember the operator that came before the number you are reading. When the number ends: after + push it, after - push its negative, after * or / combine it with the top term. Multiplication binds tighter simply because it changes the last term instead of starting a new one.

  1. Read the number 3. At the next operator +, apply the pending operator (initially +): push 3. Pending becomes +.
  2. Read 2. At *: pending is +, so push 2 as a new term. Pending becomes *.
  3. Read 2. At -: pending is *, so multiply it into the top term: 2 * 2 = 4. Pending becomes -.
  4. Read 4. At /: pending is -, push -4. Pending becomes /.
  5. Read 2, reach the end: pending is /, so the top term becomes -4 / 2 = -2 (truncating toward zero).
  6. Add up the terms: 3 + 4 - 2 = 5. One pass, O(n) time; the stack could even be replaced by two variables (sum and last term).

The loop behind the steps. Invariant: the stack holds terms that will be added at the end; + and - push a new term, * and / fold the number into the top term at once, so precedence needs no second stack. A bracket starts a new level (a recursive call) whose sum becomes one number. Lifted unchanged from the tested templates below.

// 5. Calculator for + - * / ( ) and spaces (covers LC 224, 227, 772).
//    Each level keeps a stack of signed terms; * and / fold into the top term.
//    '(' recurses; ')' or the end of the string closes the level.
long long calcLevel(const string& s, size_t& i) {
    vector<long long> terms;
    long long num = 0;
    char op = '+';                                       // operator BEFORE num
    while (true) {
        char c = i < s.size() ? s[i] : '\0';
        ++i;
        if (c == ' ') continue;
        if (isdigit((unsigned char)c)) { num = num * 10 + (c - '0'); continue; }
        if (c == '(') { num = calcLevel(s, i); continue; }
        // c is + - * / ) or end: apply the pending operator to num
        if (op == '+') terms.push_back(num);
        else if (op == '-') terms.push_back(-num);
        else if (op == '*') terms.back() *= num;
        else terms.back() /= num;
        if (c == ')' || c == '\0') break;
        op = c;
        num = 0;
    }
    long long sum = 0;
    for (long long t : terms) sum += t;
    return sum;
}
def calculate(s: str) -> int:
    """+ - * / ( ) and spaces (LC 224, 227, 772)."""
    i = 0

    def level() -> int:
        nonlocal i
        terms, num, op = [], 0, "+"
        while True:
            c = s[i] if i < len(s) else "\0"
            i += 1
            if c == " ":
                continue
            if c.isdigit():
                num = num * 10 + int(c)
                continue
            if c == "(":
                num = level()
                continue
            if op == "+": terms.append(num)
            elif op == "-": terms.append(-num)
            elif op == "*": terms[-1] *= num
            else: terms[-1] = int(terms[-1] / num)  # truncate toward zero
            if c in ")\0":
                return sum(terms)
            op, num = c, 0

    return level()

Adding brackets: one level per bracket

Basic Calculator (224) adds ( ) and unary minus with only + and -. Basic Calculator III (772) has everything. A bracket is just a nested expression, so the clean way is: on (, recursively evaluate until the matching ) and treat the result as a number. The recursion stack is the stack of saved states. Unary minus needs no special code: at the start of a level the pending operator is + and the number is 0, so -(2+3) becomes 0 - 5. The iterative alternative for 224 keeps a running result and sign; on ( it pushes both and resets them, on ) it pops and combines: result = savedResult + savedSign * result. Both are fine; pick the one you can write without bugs, and say how the other works. The general method for any precedence table is Dijkstra's shunting-yard algorithm with an operator stack and a value stack; it is good to name, but interviewers rarely need it.
