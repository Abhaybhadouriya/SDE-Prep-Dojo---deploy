Interview questions and answers

Check whether a string of (), [] and {} is valid. What changes if there is only one type?

Push openers; on a closer, fail if the stack is empty or the top is not its partner, else pop; at the end, valid only if the stack is empty. O(n) time, O(n) space. With one type the stack only ever holds copies of (, so a counter replaces it: increment, decrement, fail if it goes negative, and require 0 at the end. O(1) space.

How to answer

Name the three failure cases (wrong partner, closer with nothing open, opener never closed) and show the line that catches each.

Likely follow-ups
  • Remove the minimum number of brackets to make it valid? (push indices of '('; mark unmatched ')' and leftover '(' indices for deletion, LC 1249)
  • Longest valid substring? (stack of indices with the last unmatched index as the base, LC 32)
Evaluate a string with + - * / and spaces, no brackets, without eval.

Scan once, building the current number. When an operator or the end arrives, apply the previous operator: + pushes the number, - pushes its negative, * and / combine it into the top. The answer is the sum of the stack. O(n) time; O(1) space if you keep only sum and lastTerm instead of a stack.

How to answer

Explain why precedence works: * and / modify the last term, + and - start a new term. Dry-run 3+2*2. Mention truncation toward zero.

Likely follow-ups
  • Add brackets? (recurse on '(' and return on ')'; or push the running state; LC 224 and 772)
  • Add variables or functions? (tokenise first, then a recursive-descent parser with one function per precedence level)
How do you handle brackets and unary minus in a calculator?

Treat a bracketed part as a number: on (, recursively evaluate until ). Each level starts with pending operator + and number 0, so a leading minus becomes 0 - x without special code. The iterative version for + and - only keeps result and sign, pushes both on (, and on ) computes saved + savedSign * result.

How to answer

Show -(2+3) and 1-(-2) as your test cases. Say the recursion depth equals the bracket depth, so very deep input could overflow the call stack; the iterative version avoids that.

Likely follow-ups
  • Convert infix to postfix? (shunting-yard: operator stack, pop while the top has higher or equal precedence, brackets as barriers)
Decode a string like 3[a2[c]]. What goes on the stack?

On [ push (count, textSoFar) and reset both; on ] pop and set cur = textSoFar + cur * count; letters append to cur; digits build count. Time is proportional to the output length; stack depth equals nesting depth.

How to answer

Describe the frame as "what I owe the outer level". Test with a multi-digit count and with letters after a bracket (2[abc]3[cd]ef).

Likely follow-ups
  • Recursive version? (a function that parses until ']' and returns the string and the index)
  • Output could be huge: return only the k-th character? (compute lengths instead of strings and walk backwards, LC 880)
For each day, how many days until a warmer temperature? Explain why your solution is O(n).

Monotonic stack of indices whose answer is unknown, with temperatures decreasing bottom to top. For day i, pop every index with a lower temperature and set its answer to i - index; then push i. Leftovers get 0. Each index is pushed once and popped at most once, so the total work is O(n) even with the inner loop.

How to answer

Start from the O(n^2) scan, point out the wasted work (we re-scan days that are already known to be colder), then introduce the stack with its invariant.

Likely follow-ups
  • Circular array? (iterate 2n times with i % n, push only in the first pass, LC 503)
  • Previous smaller element instead? (flip the comparison and read the top before pushing)
Sliding window maximum in O(n). Why a deque and not a heap?

A heap works in O(n log n) with lazy deletion of expired indices. The deque keeps only candidates: indices with decreasing values; pop the front when it leaves the window, pop the back while its value is <= the new one, push the new index, read the front. Each index enters and leaves once: O(n) time, O(k) space.

How to answer

Give the dominance argument in one line: a smaller, older element can never be a window maximum once a bigger, newer one exists.

Likely follow-ups
  • Longest subarray with max - min <= limit? (two deques plus a moving left edge, LC 1438)
  • Median of every window? (two heaps, not a deque)
Implement a queue using two stacks. What is the cost of pop?

Push to in. For pop or peek, if out is empty, move all of in into out, then use out's top. A single pop can cost O(n), but each element is moved at most once in its life, so n operations cost O(n) in total: amortised O(1).

How to answer

Stress "only when out is empty"; moving every time breaks the order and the cost. Explain amortised as "total cost over a sequence".

Likely follow-ups
  • Stack using queues? (push then rotate the queue n-1 times so the newest is at the front; push O(n), pop O(1), LC 225)
  • Need a worst-case O(1) queue? (a ring buffer, or a linked list with head and tail pointers)
Asteroid collision: why is a while loop inside a for loop still O(n)?

Only a right-mover on top of the stack and a new left-mover collide. The new asteroid may pop several smaller right-movers before it dies or settles. Every asteroid is pushed at most once and popped at most once, so all the inner iterations together are at most n.

How to answer

List the three outcomes (top smaller: pop and continue; equal: pop and stop, both die; top larger: new one dies) and test [8, -8] and [-2, -1, 1, 2] (no collisions at all).

Likely follow-ups
  • Return the number of collisions instead? (count pops plus deaths in the same loop)
