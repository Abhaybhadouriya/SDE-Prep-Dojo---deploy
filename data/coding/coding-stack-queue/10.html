How to recognise a stack or queue question

The question says...Reach forExamples
brackets, "valid", "balanced", "well-formed"Stack of openers (or indices); a counter if only one type20, 1249, 921, 32
"remove adjacent", "backspace", "..", collisionsStack holding the already-settled prefix1047, 1209, 2390, 71, 735
an expression string, operators, precedencePending-operator stack of terms; recursion for brackets150, 227, 224, 772
k[...], nested groups, start/end logsStack of saved frames (count, prefix) or call chain394, 726, 636, 1190
"next greater / smaller", "previous ...", "how many days until", "span"Monotonic stack of waiting indices496, 739, 901, 503
"maximum / minimum of every window", "max - min within a window"Monotonic deque239, 1438
"process in arrival order", "level by level", "shortest steps"Plain queue (this is BFS)933, 102, 994
"design a stack/queue with ...", "O(1) getMin"Two stacks, or store extra state per entry232, 155, 622

Ask: "when I meet this item, which earlier item does it resolve?" If the answer is "the most recent unresolved one", it is a stack. If it is "the oldest one", it is a queue. If old items expire from one end while new items dominate at the other, it is a deque.
