Common mistakes

  • Reading the top of an empty stack. On a closer, check "empty" before comparing the top. In C++ this is undefined behaviour, in Java an exception, in Python an IndexError, in Go a panic.
  • Forgetting the final check. (( never fails during the scan; only "stack not empty at the end" catches it.
  • Wrong operand order in RPN: the first pop is the right-hand operand.
  • Floor instead of truncate in Python division (//). Use int(a / b).
  • Forgetting the last number in the calculator. The pending operator must also be applied at the end of the string (or at )); the templates treat "end" as one more operator.
  • Single-digit assumption. Numbers and repeat counts can be multi-digit: accumulate k = k*10 + d.
  • if instead of while when popping. One new item can resolve several waiting items (asteroids, next greater).
  • Values instead of indices on a monotonic stack, then needing a distance or a window check you can no longer compute.
  • Strict versus non-strict comparison with duplicates: decide whether equal values pop each other, and test with [2, 2].
  • Using list.pop(0) in Python or Java's Stack: O(n) dequeue and a synchronized legacy class. Use deque and ArrayDeque.
