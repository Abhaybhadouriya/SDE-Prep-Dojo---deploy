Recognise the pattern

Cue: "sort a linked list" in O(n log n) -> merge sort: split at the middle (slow/fast), sort halves, merge with a dummy head; O(1) space -> bottom-up passes.

When you see "sort a linked list" with an O(n log n) target, think merge sort: middle by slow/fast, cut, recurse, merge with a dummy head.

When you see "O(1) memory" on top, think bottom-up merge sort: passes with run size 1, 2, 4, ... and no recursion.

The problem is three building blocks you already know glued together: find the middle (fast/slow pointers), merge two sorted lists (dummy + tail), and divide and conquer. Interviewers ask it precisely to see whether you can compose them without pointer bugs.

Taxonomy: Linked list → merge, split & rebuild → merge lists. Pattern lessons: Linked lists, Sorting.
