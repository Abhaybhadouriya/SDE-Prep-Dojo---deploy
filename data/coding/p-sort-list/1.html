The problem (in our words)

You are given the head of a singly linked list of integers. Rearrange the list so that its values appear in non-decreasing order and return the head of the sorted list. You may relink the existing nodes (the usual approach) rather than allocate new ones.

Signature: ListNode sortList(ListNode head). Input and output are linked lists, written as arrays in the examples: [5, 1, 4, 2] means 5 → 1 → 4 → 2.

Constraints

  • The number of nodes is in the range [0, 5 * 10^4] (the list may be empty).
  • -10^5 <= Node.val <= 10^5

Follow-up asked by the original: sort in O(n log n) time with O(1) memory (constant extra space).

Practice it: LeetCode 148 - Sort List · GfG - Merge Sort for Linked List · TUF - Sort a linked list using merge sort

Constraints tell you: 5 * 104 nodes rules out O(n2) insertion sort (about 1.25 * 109 steps in the worst case). The recursion depth of top-down merge sort is only about log2(5 * 104) ≈ 16, so recursion is safe; the follow-up is about O(1) space, not stack overflow.
