Interview follow-ups

Do it in O(1) extra space.

Use the output array as the prefix array and keep the suffix product in one variable during a backward pass. The output does not count as extra space.

How to answer

Show the arrays version first, then point out that suf is read strictly right to left, so a scalar is enough.

Likely follow-ups
  • Can it be one pass? (Yes, fill from both ends in the same loop, but it is no faster and harder to read.)
Division is now allowed. Write it and handle zeros.

Count zeros and multiply the non-zero values. Two or more zeros: all 0. One zero at index z: answer[z] = product of non-zeros, others 0. No zeros: total / nums[i].

How to answer

List the three zero cases before coding; that is what the interviewer is checking.

Likely follow-ups
  • Overflow of the total? (It is not covered by the guarantee; use 64 bits or the two-pass method.)
Return the answer modulo 109+7 for large values. Does division by modular inverse work?

Only for values not divisible by the modulus; a zero (or a multiple of the modulus) has no inverse. The two-pass method needs no inverse, so it works for any modulus, which is why LC 2906 (mod 12345, not prime) is solved this way.

How to answer

Say "prefix/suffix needs associativity only; division needs an inverse".

Likely follow-ups
  • Which other operations fit? (min, max, gcd, xor, matrix product.)
The array is updated often and you must answer "product of all except i" queries.

Keep a segment tree of products: the answer for i is query(0, i-1) × query(i+1, n-1), O(log n) per update and query. A zero count alone is not enough because values change.

How to answer

Name the trade: static data -> two passes; dynamic -> segment tree or Fenwick (Fenwick needs an inverse, so prefer a segment tree).

Likely follow-ups
  • Why can a Fenwick tree not do range products without division?
The data is split across k machines. How do you compute it?

Each machine computes the product of its block. Exclusive prefix and suffix scans over the k block products give each machine its "left of me" and "right of me" factors; then each machine runs the two passes locally starting from those factors. O(n/k) per machine plus O(k) coordination.

How to answer

It is a distributed exclusive scan; mention it is the same idea as the local algorithm, one level up.

Likely follow-ups
  • A block that contains a zero? (Its product is 0; the scans still work.)
