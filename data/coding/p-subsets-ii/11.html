Do it iteratively, without recursion.

Sort. Keep the result list and the index where the previous round's additions started. For nums[i], if it equals nums[i-1], extend only the subsets added in the previous round; otherwise extend all of them. This produces each distinct subset once, in O(n * 2n).

How to answer

Explain why only the newest subsets are extended: older ones already got a copy of this value last round.

Likely follow-ups
  • The count-based version (extend with 1..c copies) is the same idea, written per group.
What is the time complexity, exactly?

The number of nodes is the number of distinct subsets, at most 2n, and copying each costs up to n, so O(n * 2n). The skipped siblings cost O(1) each and there are at most n per node. The sort is O(n log n), negligible.

How to answer

Tie the bound to the output size: you cannot do better than writing the output.

Likely follow-ups
  • Tighter: Θ(sum of subset lengths) = Θ(n 2n-1) when all values are distinct.
Only subsets of size k, still without duplicates.

Record only when len(cur) == k and return there; keep the skip rule. Prune when fewer than k - len(cur) elements remain after i.

How to answer

Show that the skip rule is independent of where you record.

Likely follow-ups
  • Count them without listing: a DP over distinct values with counts.
Only subsets whose sum equals a target.

That is Combination Sum II: carry the remaining target, record at 0, and since the array is sorted, break as soon as nums[i] exceeds the remainder (only valid for non-negative values).

How to answer

Mention that negatives disable the break pruning.

Likely follow-ups
  • Only the count of such subsets: subset-sum DP, no enumeration.
n is 40 and you only need the number of distinct subsets.

Do not enumerate. Count each distinct value's multiplicity c and return the product of (c + 1). O(n) with a hash map.

How to answer

Derive the product rule from "a subset = how many copies of each value".

Likely follow-ups
  • Modulo 109 + 7 if the product overflows.
Can you dedupe with bitmasks instead?

Iterating all 2n masks still produces duplicates. You would sort and accept a mask only if, for every chosen copy of a value, all earlier copies of that value are also chosen. That is the same leftmost-copy rule, and it still visits 2n masks, so it is slower when duplicates are many.

How to answer

Relate the mask condition to the skip rule; it shows you understand why the skip is correct.

Likely follow-ups
  • Gray-code order for O(1) changes between consecutive subsets.
