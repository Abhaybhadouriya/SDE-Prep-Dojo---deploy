Approaches: brute -> better -> optimal

Hint 1

When are two index-subsets the same value-subset? Think about how many copies of each value they contain.

Hint 2

After sorting, equal values are neighbours. At one level of the recursion, does it matter which copy of a value you pick first?

1. Brute force - generate all 2n, deduplicate with a set

Idea: run plain Subsets (each index in or out), sort each subset (or sort the input first), insert it into a hash set as a tuple, return the set.

O(2n * n log n)time
O(2n * n)space

What is wasted: with many duplicates, most generated subsets are thrown away ([5,5,5,...] builds 2n lists for n + 1 answers), and you need hashing of lists. It is acceptable as a first sentence, but interviewers ask "can you avoid the set?".

2. Better - iterative with value counts

Idea: sort and group equal values. Start with [[]]. For a value v that appears c times, extend every existing subset with v, v v, ..., c copies of v. Each subset is produced once, because a subset is fully described by how many copies of each value it takes: (c1+1)(c2+1)... results.

res = [[]]
for v, c in sorted(Counter(nums).items()):
    res += [s + [v] * t for s in res for t in range(1, c + 1)]
O(n * 2n)time
O(n * 2n)output

Not wasted, but less general: this is already optimal for this problem. The backtracking form below is what transfers to Combination Sum II and Permutations II, so most interviewers expect it.

3. Optimal - backtracking with the equal-sibling skip

def build(start):
    out.append(cur[:])                         # every node is a subset
    for i in range(start, len(nums)):
        if i > start and nums[i] == nums[i - 1]: continue   # same value, same level
        cur.append(nums[i]); build(i + 1); cur.pop()
  1. Every node is an answer. Unlike combinations of size k, a subset is recorded on entry to each call, not only at leaves.
  2. A level chooses the next (smallest remaining) element. The loop at level start decides which value comes next in the sorted subset.
  3. Equal siblings build equal subtrees. Choosing nums[i] or an equal nums[i-1] at the same level leads to the same set of completions (the first copy's subtree already contains them all), so skip every copy after the first.
  4. i > start, not i > 0. Going one level deeper, the first copy of a value is allowed again, so [3, 3] can still be built.
O(n * 2n)time
O(n)extra stack

Why it works: in sorted order, write each distinct value-subset as its sorted list. There is exactly one root-to-node path that builds it: at each level, pick the leftmost index holding the next needed value among indexes ≥ start. The skip rule removes every other path, because any other path at some level picks a non-leftmost copy (i > start with nums[i] == nums[i-1]). So every distinct subset is produced once, and no subset is produced twice.

The other recursion shape: take / don't take

With a binary "include nums[i] or not" recursion, the rule becomes: if you decide not to take a value, skip all its copies (jump to the next different value). Equivalently, take a copy only if the previous equal copy was taken. Both shapes are in the top community solutions; the start-index loop is shorter and is the one shared with Combination Sum II.

Proof (optional): the count matches

Group the sorted array into distinct values with counts c1, ..., cm. A value-subset is a choice of tj ∈ {0..cj} for each j, so there are ∏(cj + 1) of them. The leftmost-copy path is a bijection onto these choices, so the algorithm outputs exactly ∏(cj + 1) lists. Our test checks this product rule on [1,2,2,3,3,3,0,0,0,0]: 2 x 3 x 4 x 5 = 120.
