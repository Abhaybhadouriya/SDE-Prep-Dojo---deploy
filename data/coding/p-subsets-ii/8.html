Common mistakes

Not sorting first. The rule only compares with the previous index. In [3,1,3] the two 3s are not neighbours, so [3] and [1,3] are produced twice.

i > 0 instead of i > start. That also blocks the first copy at deeper levels, so [3,3] and [1,3,3] are never built.

Appending cur instead of a copy. Every stored subset is the same list object, which ends up empty after backtracking. Copy with cur[:], new ArrayList<>(cur), or append([]int(nil), cur...) in Go.

Recursing with start + 1 instead of i + 1. Then later elements can be picked before earlier ones and subsets repeat in different orders.

Using a set of lists without sorting each list. [1,3] and [3,1] hash differently, so the "brute force with a set" still returns duplicates.
