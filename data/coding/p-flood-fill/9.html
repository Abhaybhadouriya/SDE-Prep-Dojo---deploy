60-second recall

  • Cue: grid + same-value connected region -> DFS/BFS over 4 neighbours.
  • Mark: the repaint is the visited flag; paint when you push.
  • Trap: if color == old, return the image at once.
  • Depth: recursion can go m·n deep; use an explicit stack in Python or on big images.
  • Cost: O(m·n) time, O(m·n) stack/queue worst case.
old = img[sr][sc]
if old == color: return img
img[sr][sc] = color; st = [(sr, sc)]
while st:
    r, c = st.pop()
    for nr, nc in ((r-1,c),(r+1,c),(r,c-1),(r,c+1)):
        if 0 <= nr < m and 0 <= nc < n and img[nr][nc] == old:
            img[nr][nc] = color; st.append((nr, nc))

What happens if color equals the start pixel's colour and there is no early return?

  1. Nothing changes, correctly
  2. Only the start pixel changes
  3. Diagonal pixels get filled
  4. The fill revisits pixels forever (or overflows the stack)
The repaint is the visited mark; repainting with the same colour marks nothing.

Why can a recursive DFS fail in Python on a 50 x 50 single-colour image?

  1. Python lists are slow
  2. The recursion can go 2,500 deep, past the default limit of 1,000
  3. Integers overflow
  4. Python has no stack
Use an explicit stack or a BFS queue.

Pixels are painted when pushed, not when popped. What does this guarantee?

  1. Each pixel is pushed at most once
  2. BFS order
  3. Diagonal connectivity
  4. O(1) extra space
Once pushed, a pixel no longer has the old colour, so no neighbour can push it again.
