The problem (in our words)

An image is an m x n integer grid image, where image[i][j] is the colour of a pixel. You are also given a start pixel (sr, sc) and a colour color.

Perform a flood fill: change the start pixel to color, and also every pixel that is connected to it 4-directionally (up, down, left, right) through a chain of pixels that all had the same original colour as the start pixel. Return the modified image.

Signature: int[][] floodFill(int[][] image, int sr, int sc, int color).

  • m == image.length, n == image[i].length, 1 <= m, n <= 50
  • 0 <= image[i][j], color < 216
  • 0 <= sr < m, 0 <= sc < n

Practice it: LeetCode 733 · GfG Flood fill Algorithm · TUF article

Constraints tell you: at most 2,500 pixels, so any linear traversal is instant. 2,500 is deeper than Python's default recursion limit of 1,000, so a recursive DFS on a one-colour 50 x 50 image can crash in Python; an explicit stack or a BFS queue avoids it.
