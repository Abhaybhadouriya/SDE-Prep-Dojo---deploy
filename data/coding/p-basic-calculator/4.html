Approaches: brute -> better -> optimal

Hint 1

Without brackets, how would you evaluate 4 - 6 + 10 in one pass? What do you keep?

Hint 2

When you meet (, which two values from the outside will you need again when it closes?

Hint 3

Unary minus: what happens if you treat -(4+5) as 0 - (4+5)?

1. General parser - shunting-yard to postfix, then evaluate

Idea: tokenize, convert infix to postfix (Reverse Polish) with an operator stack, then evaluate the postfix with an operand stack. Unary minus needs a special token (or insert a 0 before it).

O(n)time, two passes
O(n)space (tokens + two stacks)

What is wasted: it is built for precedence, which this problem does not have. All the machinery (token list, output queue, precedence table) can go. -> rung 2.

2. Recursive descent - one call per bracket

Idea: evaluate(i) reads numbers and signs from position i, keeping a running total. On ( it calls itself and gets back (value, next index); on ) or end of string it returns.

def evaluate(i):                      # returns (value, index after this level)
    total, sign, num = 0, 1, 0
    while i < len(s):
        c = s[i]
        if c.isdigit(): num = num * 10 + int(c)
        elif c in "+-": total += sign * num; num = 0; sign = 1 if c == "+" else -1
        elif c == "(": num, i = evaluate(i + 1); continue
        elif c == ")": return total + sign * num, i + 1
        i += 1
    return total + sign * num, i
O(n)time
O(depth)call stack

What is wasted: nothing asymptotically, but each bracket costs a call frame; at 105 nesting levels Python hits its recursion limit and Java may overflow its stack. The only state a frame holds is (total, sign), so an explicit stack of those pairs does the same job. -> rung 3. (Rung 2 is still the best base for Calculator III, where precedence is also needed.)

3. Optimal - one pass with a stack of (total, sign)

  1. Digit: num = num * 10 + digit (multi-digit numbers).
  2. + or -: the previous number is complete: total += sign * num, num = 0, sign = ±1. A leading or post-bracket unary minus works automatically: it adds sign * 0 and sets sign = -1.
  3. (: push (total, sign); reset total = 0, sign = +1. The pushed sign is the one written just before the bracket.
  4. ): finish the inner number (total += sign * num, num = 0), pop (outerTotal, outerSign), set total = outerTotal + outerSign * total. The bracket is now an ordinary finished term.
  5. End: return total + sign * num for the last pending number.
O(n)time, one pass
O(depth)explicit stack

Why it works: invariant: at any moment, the value of the expression read so far equals saved[0].total + saved[0].sign · (saved[1].total + saved[1].sign · ( ... (total + sign · num))). Digits only change num; an operator moves sign · num into total (no change in value); ( pushes a level whose inner value is 0 so far; ) collapses the innermost level using the same formula. Because + and - are left-associative and of equal precedence, a bracket's content can only be added or subtracted as a whole, which is exactly the saved sign.

Sign-stack variant: since a bracket only flips signs, you can keep one global total and a stack of effective signs (the product of all bracket signs around the current position). Each number is added as total += effective · own sign · num; ( pushes the current effective sign, ) pops. Same O(n) / O(depth), and a nice answer to "can you avoid storing totals?".
