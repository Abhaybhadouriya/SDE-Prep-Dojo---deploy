Interview follow-ups

Add * and / (Calculator III). How does your code change?

Inside one bracket level, use the Calculator II loop: keep the previous operator and a stack of terms (+/- push ±num, *// pop, combine, push). On ( recurse (or push the whole level state: term stack plus pending operator) and treat the returned value as num. The answer is the sum of the term stack. O(n) time.

How to answer

Say the bracket handling stays, the "how to fold a number in" changes. Truncate division toward zero (careful in Python: use int(a / b)).

Likely follow-ups
  • Add exponent ^, which is right-associative: shunting-yard with associativity rules.
Do it without storing totals on the stack.

Stack of effective signs: start with [+1]. A number's contribution is stack.top · ownSign · num, added to one global total. At ( push stack.top · ownSign; at ) pop. Same O(n) time, O(depth) space, one integer per level.

How to answer

Explain with the sign picture: -(3-(2+1)) makes 2 and 1 positive because two minuses cancel.

Likely follow-ups
  • Can you do it in O(1) space? Only by rescanning (O(n2)) or if nesting is bounded.
The input may be invalid. How do you detect it?

Track the expected next token (number/(/unary minus vs operator/)): two operators in a row, ) with an empty stack, a non-empty stack at the end, an unknown character or a trailing operator are errors. Report the position. Overflow: check num > (INT_MAX - d) / 10 before accumulating.

How to answer

Turn the scan into a small state machine with two states (expect operand / expect operator).

Likely follow-ups
  • Return a typed error instead of throwing.
Support variables and evaluate the same expression for many inputs.

Parse once into an AST (or postfix list), then evaluate it per input. With only + - the expression is linear: precompute each variable's coefficient (its effective sign summed) and a constant, so each evaluation is O(#variables).

How to answer

Separate parsing from evaluation; this is how real interpreters and query engines work.

Likely follow-ups
  • LC 770 Basic Calculator IV: simplify to a polynomial.
Why is recursion risky here, and when is it still fine?

Nesting can be ~1.5·105 deep with a 3·105-character input. Python's default limit is 1000 frames; Java's default thread stack fits a few thousand to tens of thousands of frames. The explicit stack stores two integers per level on the heap. Recursion is fine when nesting is bounded (most real expressions) or with a raised limit.

How to answer

Quote the constraint and convert recursion to a stack: the frame state is exactly the pushed pair.

Likely follow-ups
  • Tail-call elimination: why it does not help here (work remains after the call returns).
