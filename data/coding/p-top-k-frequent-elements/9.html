  • Cue: "k most frequent" -> count with a map, then top-k by count.
  • Insight: counts are integers in [1, n] -> use the count as an array index (bucket sort).
  • State: freq map, bucket[0..n] lists, result list.
  • Trap: allocate n + 1 buckets; index by count, not value; stop at k.
  • Cost: buckets O(n); min-heap of size k O(n log k); sort O(n log n).
freq = Counter(a)
bucket = [[] for _ in range(len(a) + 1)]
for v, c in freq.items(): bucket[c].append(v)
out = []
for c in range(len(a), 0, -1):
    out += bucket[c]
    if len(out) >= k: return out[:k]

Bucket sort by count: how many buckets do you need for n numbers?

  1. k
  2. n
  3. n + 1 (counts go from 1 to n)
  4. the number of distinct values
A value can appear n times, so bucket[n] must exist. Index 0 stays empty.

What indexes the buckets?

  1. the value
  2. the count of the value
  3. the first index of the value
  4. the value modulo n
bucket[c] holds every value that appears c times; scanning c from n down to 1 gives the most frequent first.

A min-heap of size k is O(n log k). Why a MIN-heap for the most frequent?

  1. it is faster to build
  2. its top is the least frequent of the current best k, the one to drop
  3. Python has no max-heap
  4. it keeps values sorted
Same rule as k-th largest: the heap holds the best k, the weakest on top.
