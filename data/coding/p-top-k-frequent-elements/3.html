Recognise the pattern

When you see "the k most / k largest / k closest", think a size-k heap (O(n log k)) or quickselect (O(n) average). When the key is a count bounded by n, the key itself can index an array -> bucket sort, O(n) worst case.

Try a few and see which part of the work is unavoidable:

InputkCountsAnswerNote
[2,2,8]12:2, 8:1[2]Counting is always needed; one pass with a map.
[5,6,7]3all 1[5,6,7]k = u: return every distinct value (ties are fine because all are taken).
[1,1,1,1]11:4[1]The largest possible count is n, hence n + 1 buckets.
