The problem (in our words)

You are given an integer array nums (think of it as a log of product ids, one per sale) and an integer k. Return the k values that occur most often in nums. You may return them in any order. The input is built so that the answer is unique: there is never a tie at the k-th place that would let two different sets be correct.

Signature: int[] topKFrequent(int[] nums, int k) (LeetCode style: read the array and k, return an array of k integers).

  • 1 <= nums.length <= 105
  • -104 <= nums[i] <= 104
  • k is in the range [1, number of distinct values in nums]
  • The answer is guaranteed to be unique.
  • Follow-up from the original: your algorithm should be better than O(n log n), where n is the array length.

Practice it: LeetCode 347 · GfG Top K Frequent in Array · TUF article · Code360 K Most Frequent Elements

Constraints tell you: n up to 105 allows O(n log n), but the follow-up asks for better, which points at O(n log k) (heap) or O(n) (bucket sort / quickselect). The number of distinct values u is at most min(n, 2·104 + 1). "Answer is unique" means you never need a tie-break rule.
