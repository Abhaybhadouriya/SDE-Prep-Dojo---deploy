Common mistakes

Overwriting the stored index. Writing first[bal] = i on every step keeps the LAST index, which gives the shortest run. On [0,1,0,1] the answer drops from 4 to 2.

Forgetting the seed 0 -> -1. A balanced prefix is never measured: [0,1] returns 0.

Counting 0 as 0. Then the "sum" is just the number of 1s and equal values mean "no 1s in between", a different question. The 0 must become -1.

Indexing the array without the offset. bal can be negative; first[bal] reads out of bounds in C++ (undefined behaviour) and throws in Java. Use first[bal + n] with size 2n + 1.

Using a count map here. Counts answer "how many balanced subarrays" (a different problem); the longest needs positions.
