The problem (in our words)

A sensor log nums holds only the readings 0 (switch off) and 1 (switch on). Return the length of the longest contiguous subarray that contains the same number of 0s and 1s. If there is none, return 0.

Signature: int findMaxLength(vector<int>& nums).

Constraints:

  • 1 <= nums.length <= 105
  • nums[i] is either 0 or 1.

Practice it: LeetCode 525 - Contiguous Array · GfG - largest subarray with equal 0s and 1s

Constraints tell you: n = 105 rules out the O(n2) "every start, every end" scan (1010 steps), so the target is O(n). The balance stays in [-n, n], so a plain array of size 2n + 1 can replace the hash map: no hashing, cache-friendly, and the kind of answer a C engineer gives.
