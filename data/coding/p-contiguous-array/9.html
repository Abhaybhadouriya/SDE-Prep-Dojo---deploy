Revision card

  • Cue: longest subarray with equal 0s and 1s (or any two classes) -> +1/-1, sum 0.
  • Insight: equal balances at l and r mean nums[l+1..r] is balanced; length r - l.
  • State: bal (prefix), first[bal] = earliest index, best.
  • Trap: seed first[0] = -1; store the FIRST index only; 0 must count as -1.
  • Cost: O(n) time, O(n) space (array of 2n+1); brute O(n²) with a running diff.
first = {0: -1}; run = best = 0
for i, x in enumerate(a):
    run += f(x)                       # here: +1 for 1, -1 for 0
    if run - target in first:
        best = max(best, i - first[run - target])
    first.setdefault(run, i)          # first index only
return best

Quick quiz

The balance after index 3 equals the balance after index 9. What do you know?

  1. nums[3..9] is balanced
  2. nums[0..9] is balanced
  3. nums[4..9] is balanced, length 6
  4. Nothing
Equal prefix balances cancel out: the part after index 3 up to 9 has as many 1s as 0s.

Why is first[bal] never updated after it is set?

  1. An earlier index always gives a longer run for the same end
  2. To save memory
  3. Hash maps cannot update keys
  4. Because bal is never repeated
For a fixed end r the length is r - l, maximised by the smallest l.

What changes to COUNT the balanced subarrays instead?

  1. Nothing
  2. Store how many times each balance occurred, seed {0: 1}, add count[bal] each step
  3. Use a sliding window
  4. Sort the array
