Approaches: brute → better → optimal

Hint 1

Replace every 0 with -1. What is the sum of a subarray with equal 0s and 1s?

Hint 2

A subarray sums to 0 when two prefix sums are equal. For the longest one ending at r, which earlier prefix do you want: the first or the last with that value?

1. Brute force - every subarray, counted from scratch

Idea: for every start l and end r, count zeros and ones in nums[l..r]; keep the longest equal one.

O(n3)time
O(1)space

What is wasted: moving r one step only adds one element, yet we recount the whole range. -> rung 2.

2. Better - fix the start, keep a running difference

Idea: for each l, walk r to the right with d += (x == 1 ? 1 : -1); whenever d is 0, nums[l..r] is balanced. This is the top community brute force, and it is worth saying aloud.

O(n2)time
O(1)space

What is wasted: d for the start l is just bal[r] - bal[l-1], a difference of two prefix balances. Instead of trying every l, ask once: "where did I first see the balance I have now?" -> rung 3.

Why not a sliding window? "Balanced" is not monotonic: extending a balanced window can make it unbalanced and extending again can rebalance it ([1,0] -> [1,0,1] -> [1,0,1,0]). There is no rule for when to move the left edge, so a window cannot decide.

3. Optimal - balance + first index of each balance

first = {0: -1}; bal = best = 0
for i, x in enumerate(nums):
    bal += 1 if x else -1
    if bal in first: best = max(best, i - first[bal])
    else: first[bal] = i               # first time only
  1. Balance is a prefix sum. With 0 -> -1, bal after index i is (#1 - #0) in nums[0..i].
  2. Equal balances mean balanced in between. If bal after l equals bal after r (l < r), nums[l+1..r] has as many 1s as 0s; its length is r - l.
  3. Keep the first index only. For a fixed r, the smallest l with the same balance gives the longest run, so a later copy of the same balance is never useful; never overwrite.
  4. Seed balance 0 at index -1. A balanced prefix nums[0..r] then measures r - (-1) = r + 1.
  5. Array instead of map. bal is in [-n, n]; store first[bal + n] in an int array of 2n + 1 slots with -2 meaning "not seen". This is what the tested code does.
O(n)time
O(n)space (2n + 1 ints)

Why it works: every balanced subarray nums[l+1..r] is a pair of equal balances (after l, after r). For each r we look at the one balance value we hold and pair it with its earliest occurrence, which is the longest balanced subarray ending at r. Taking the best over all r covers every possible end, so the global maximum is found.

Proof (optional)

Let B(i) be the balance after index i, B(-1) = 0. nums[l+1..r] is balanced iff B(r) - B(l) = 0. For a fixed r, the length r - l is maximised by the smallest l in {-1, ..., r-1} with B(l) = B(r), which is exactly first[B(r)] at the moment r is processed (entries are written once, at their first occurrence, and before any later index reads them). So best = max over r of (r - first[B(r)]), which is the maximum length of any balanced subarray.
