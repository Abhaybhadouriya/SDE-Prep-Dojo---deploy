Interview follow-ups

Return the start and end index of the longest balanced subarray, not just its length.

When best improves at index i, record start = first[bal] + 1 and end = i. Because best only changes on a strict improvement, ties keep the leftmost run (same length, smallest end, so smallest start).

How to answer

Show that the same state already holds both ends; only two extra variables.

Likely follow-ups
  • Return all longest ones: collect every (start, end) whose length equals best.
How many balanced subarrays are there?

Same +1/-1 transform, but store how many times each balance has been seen (seed count[0] = 1) and add count[bal] before incrementing it. That is LC 560 with k = 0, O(n).

How to answer

Contrast "first index" (longest) with "count" (how many) in one sentence.

Likely follow-ups
  • Can the count overflow 32 bits? Up to n²/4 ≈ 2.5·109 for n = 105: use 64-bit.
Three symbols (0, 1, 2): longest subarray with equal counts of all three.

Track two differences, (c1 - c0, c2 - c0). A run is balanced when this pair is the same at both ends, so key the first-index map by the pair. Still O(n).

How to answer

Generalise "balance" to a vector of differences; the map key becomes a tuple.

Likely follow-ups
  • Parity only (even counts of each)? Use a bitmask key (LC 1371).
Can you do it with O(1) extra memory?

Not in O(n) time in general: you must remember where each balance first appeared, and there can be up to n distinct balances. With O(1) memory the O(n2) running-difference scan is the honest answer. The array version at least avoids hashing and fits in 2n + 1 ints (800 KB for n = 105).

How to answer

Give the trade-off, not a fake trick.

Likely follow-ups
  • Input too large for memory but streamed? The first-index table is still the state; it grows with the balance range.
The log is a stream; after each reading report the longest balanced run so far.

The algorithm is already online: bal, best and the first-index table update in O(1) per reading. Use a hash map (or a growable array with offset) because n is unknown.

How to answer

Point out that nothing looks ahead.

Likely follow-ups
  • Only the last W readings count: entries older than the window must be dropped, and "first index" becomes "first index inside the window" (a deque per balance).
