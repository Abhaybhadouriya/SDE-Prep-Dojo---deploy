  • Cue: max a[j] - a[i] with i < j, one buy and one sell.
  • Insight: best buy for sell day j is the minimum of the prefix before j.
  • State: cheapest so far, best profit so far (starts at 0).
  • Trap: not max - min (order); floor at 0 for falling prices.
  • Cost: O(n) time, O(1) space; brute force O(n^2). Kadane on day-to-day changes is equal.
best_left = a[0]           # running prefix aggregate
ans = 0
for x in a[1:]:
    ans = max(ans, x - best_left)
    best_left = min(best_left, x)

Prices [7, 6, 4, 3, 1]. What is the answer?

  1. -1
  2. 0
  3. 6
  4. -6
Prices only fall, so the best is not to trade. The profit starts at 0 and never goes negative.

Why is max(prices) - min(prices) wrong?

  1. it overflows
  2. the max may come before the min, and you must buy before you sell
  3. it ignores duplicates
  4. it is right
For [5, 1] it would give 4, but you cannot sell at 5 before buying at 1. You need the minimum to the LEFT of each sell day.

Each day runs profit = max(profit, p - cheapest) and cheapest = min(cheapest, p). Does the order of the two lines matter?

  1. yes, cheapest must come first
  2. no; buying and selling on the same day adds 0, so both orders give the same answer
  3. yes, profit must come first or the answer is too high
  4. only when prices repeat
Updating cheapest first allows a same-day trade, which earns 0 and never beats the floor of 0. Profit-then-cheapest still reads better, because it matches 'buy before you sell'.
