Interview follow-ups

Readings arrive as a stream. Can you report the max after each new value?

Yes; the deque is already online. Keep a running index counter, and on each new value do the expiry check, the back pops and the push, then report the front. Memory is O(k); each update is O(1) amortised.

How to answer

Point out that nothing in the loop looks ahead, so it is a class with an add(x) method.

Likely follow-ups
  • Is any single update O(k)? (Yes in the worst case, e.g. a big value after a long decreasing run; amortised O(1).)
The window is the last T seconds, not the last k readings.

Store (timestamp, value) in the deque. Expire from the front with a while (several readings can expire at once) when timestamp <= now - T. The back pops are unchanged. This is how a "max latency in the last minute" metric is kept exactly.

How to answer

Change only the expiry rule, and note that it becomes a loop.

Likely follow-ups
  • Memory is too high at high rates: approximate with bucketed maxima per second, or a 3-sample filter like BBR.
Return both the max and the min of each window.

Run two deques in the same loop: one with decreasing values for the max, one with increasing values for the min. Still O(n). The same pair of deques solves LC 1438.

How to answer

Show the mirrored comparison and that the expiry rule is shared.

Likely follow-ups
  • Count windows where max - min ≤ limit.
Do it on a 2D grid: the max of every k × k square.

Apply the 1D algorithm to every row (window k), giving a grid of row maxima, then apply it to every column of that grid. Each pass is O(rows × cols), so the whole thing is O(R·C) instead of O(R·C·k²).

How to answer

Max is separable: max of a square = max over columns of the row-window maxima.

Likely follow-ups
  • Does this work for sums? (Yes, but 2D prefix sums are simpler.)
Design a queue with push, pop and getMax, all O(1) amortised.

Keep the real queue plus a deque of decreasing values. Push appends to both (after popping smaller values from the deque back). Pop removes from the queue, and from the deque front if it holds the same value. getMax reads the deque front. Another way: two stacks, each storing the running max.

How to answer

Recognise that this problem is that queue with a fixed size k.

Likely follow-ups
  • Why must the deque keep equal values here? (Pop by value would otherwise remove a copy too early.)
