Common mistakes

Storing values instead of indices. With duplicates you cannot tell which copy left the window. Store indices and read values through nums[idx].

Wrong expiry test. The window for step i is [i-k+1, i], so index j is out when j <= i - k. Using < i - k keeps one stale index.

Popping with < and expiring by value. If you store values and compare dq.front() == nums[i-k], you must pop with strict < so equal copies stay. Mixing the two rules loses or keeps the wrong copy.

Calling it O(n·k) because of the inner while loop. The while loop pops each index at most once in total, so the whole run is O(n). Say "amortised".

Starting the output too early or too late. The first answer belongs to i = k - 1, and there are exactly n - k + 1 answers.
