Approaches: brute → better → optimal

Hint 1

If a new value is bigger than an older value in the window, will the older one ever be the answer again?

Hint 2

The queue does not need to hold k values; it only needs values that could still become the maximum.

1. Brute force - scan every window

Idea: for each start i from 0 to n-k, loop over nums[i..i+k-1] and take the max.

O(n·k)time
O(1)extra space

What is wasted: two neighbouring windows share k-1 values, and we compare them again every time.

2. Better - max-heap with lazy deletion

Idea: push (value, index) into a max-heap as the window moves. Before reading the top, pop it while its index is outside the window (index ≤ i - k). The top is then the window max. A balanced tree (C++ multiset, Java TreeMap with counts) also works and removes the leaving value directly.

O(n log n)time (heap; O(n log k) with a tree)
O(n)space (old entries stay until they surface)

What is wasted: the heap keeps values that can never win (a small value next to a larger newer one) and pays log n for every push.

3. Also O(n) - block prefix and suffix maxima

Idea: cut the array into blocks of k. Compute leftMax[i] = max from the start of i's block up to i, and rightMax[i] = max from i to the end of its block. Any window [i, i+k-1] spans at most two blocks, so its max is max(rightMax[i], leftMax[i+k-1]).

O(n)time, two passes
O(n)space

When to mention it: as a neat second O(n) answer with no deque; it is offline (needs the whole array) and uses more memory.

4. Optimal - monotonic deque of indices

for i, x in enumerate(nums):
    if dq and dq[0] <= i - k: dq.popleft()          # expired
    while dq and nums[dq[-1]] <= x: dq.pop()         # dominated
    dq.append(i)
    if i >= k - 1: out.append(nums[dq[0]])
  1. Store indices, not values. The index tells you when an entry has left the window.
  2. Values in the deque strictly decrease from front to back. So the front is the max of everything still kept.
  3. Back pops remove dominated values. If nums[j] ≤ x and j < i, j leaves earlier and is never larger: drop it forever.
  4. Front pop removes the expired index. At most one index expires per step, so an if is enough.
  5. Output once the first window is full (i ≥ k - 1).
O(n)time, amortised: each index is pushed once and popped at most once
O(k)deque (plus the n - k + 1 output)

Why it works: the deque always holds, in order, every index of the current window that has no larger-or-equal value to its right in the window. The window max has nothing larger to its right, so it is in the deque, and because values decrease from the front, it is the front.

Proof (optional)

Invariant before reading the answer for window [i-k+1, i]: the deque is the list of indices j in the window with nums[j] > nums[t] for every t in (j, i], in increasing order of j. Pushing i after popping every back index with value ≤ nums[i] keeps exactly the indices that beat everything to their right, now including i. Popping the front when it equals i-k removes the only index that left. The window maximum m (take the rightmost if tied) beats everything to its right, so it is in the deque; every other deque value is smaller than some value to its right, and the values strictly decrease, so m is the front. Each index enters once and leaves once, so the total work is O(n).
