  • Cue: best contiguous product -> Kadane with TWO states.
  • Insight: a negative makes the smallest product ending here the largest one next step.
  • State: hi / lo = max / min product of a subarray ending at i; best = max hi.
  • Trap: swap on x < 0 BEFORE updating; init with nums[0], not 0 or 1.
  • Cost: O(n) time, O(1) space. Alt proof: best block touches a zero-free segment end (prefix/suffix scans).
hi = lo = best = a[0]
for x in a[1:]:
    if x < 0: hi, lo = lo, hi
    hi, lo = max(x, hi * x), min(x, lo * x)
    best = max(best, hi)

What does plain Kadane (only the max product ending here) return for [-2,3,-4]?

  1. 24
  2. -24
  3. 3
  4. 12
It keeps max(-6, 3) = 3 at index 1 and forgets -6, so at -4 it can only build -12 or -4. The right answer, 24, needs the min.

A zero-free segment holds an odd number of negatives. The best block inside it...

  1. is always the whole segment
  2. is a prefix or a suffix of the segment
  3. never contains a negative
  4. has length 1
Dropping everything up to the first negative, or from the last negative on, leaves an even count; one of those two (a suffix or a prefix) is optimal.

Why is no special case needed for x = 0 in the max/min method?

  1. Both hi and lo become 0, so the next step starts over from the next value
  2. Zeros never appear
  3. best ignores zeros
  4. The swap handles it
max(0, hi·0) = 0 and min(0, lo·0) = 0; the next x then wins against 0·x on its own.
