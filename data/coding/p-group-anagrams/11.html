Can you build a key in O(K) that is a single number?

Map each letter to a distinct prime and multiply: equal products exactly for anagrams (unique factorisation). It overflows quickly (101^100), so use it with big integers or modular hashing plus a check. A cleaner single-number key is a polynomial hash of the count vector.

How to answer

Give the prime idea, then point out overflow and why the count vector is the practical choice.

Likely follow-ups
  • Collisions with modular hashing? Verify group members with a real count compare.
10^9 words in files on many machines. Group them.

MapReduce: the mapper emits (key(word), word), the shuffle sends equal keys to the same reducer (hash partitioning by key), and the reducer writes each group. Same idea, the hash map becomes the shuffle.

How to answer

Mention skew: one huge anagram class can overload a reducer; split hot keys or combine early.

Likely follow-ups
  • Only the count of groups? Emit keys and count distinct (HyperLogLog if approximate is fine).
Return only the groups with more than one word, largest first.

Build the map the same way, filter buckets with size ≥ 2, and sort by size descending (O(G log G) for G groups).

How to answer

Keep the grouping step unchanged and add a post-processing step; say its cost separately.

Likely follow-ups
  • Top k groups only? A heap of size k over the buckets.
Words arrive one at a time; answer "how many anagrams of this word have we seen?"

Keep a map key → count. Each query computes the key in O(K) and returns the count, then increments it. O(K) per word, memory proportional to the number of distinct classes.

How to answer

Point out that you never store the words themselves, only their keys and counts.

Likely follow-ups
  • Expire old words (sliding time window)? A queue of (time, key) to decrement counts.
