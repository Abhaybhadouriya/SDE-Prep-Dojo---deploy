The problem (in our words)

A librarian has a list of catalogue codes words, each made of lower-case letters. Two codes are anagrams if one can be turned into the other by rearranging its letters (same letters, same counts). Put the codes into groups so that each group holds exactly the codes that are anagrams of each other. Return the groups; the order of the groups and the order inside each group do not matter.

  • Input: an array of strings strs.
  • Output: a list of lists of strings, one list per anagram group, every input string in exactly one group (duplicates included). Signature: List<List<String>> groupAnagrams(String[] strs).

Constraints

  • 1 <= strs.length <= 10^4
  • 0 <= strs[i].length <= 100 (the empty string is allowed)
  • strs[i] consists of lower-case English letters.

Practice it: LeetCode 49 - Group Anagrams · GfG - Print Anagrams Together · takeuforward

Constraints tell you: N = 10^4 words makes comparing every pair (5 × 10^7 pair checks of up to 100 letters) too slow; one pass with a hash map is the target. K ≤ 100 and 26 letters mean a count key is 26 small numbers (each ≤ 100, so one byte each), and sorting each word costs only K log K ≈ 700 steps.
