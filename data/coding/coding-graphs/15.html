Quiz

You need the minimum number of moves for a knight to reach a square on an empty board. Which walk?

  1. DFS, keeping the best depth found
  2. BFS from the start square
  3. Dijkstra with weight 1 on every edge, since it is more general
  4. Topological sort
Every move costs the same, so BFS finds the minimum in O(V + E). Dijkstra would also be correct but adds a log factor for nothing; DFS explores far too many paths.

In a directed graph DFS, which edge proves a cycle?

  1. An edge to any visited vertex
  2. An edge to a BLACK (finished) vertex
  3. An edge to the parent vertex
  4. An edge to a GRAY vertex (still on the current path)
Only a back edge to a vertex still on the recursion path closes a loop. Edges to finished vertices are cross or forward edges and are harmless.

Kahn's algorithm outputs 7 of 9 vertices and the queue is empty. What do you conclude?

  1. The graph has a directed cycle
  2. The graph is disconnected
  3. Two vertices had in-degree 0 and were skipped
  4. The order is valid but partial
The remaining vertices never reached in-degree 0 because each waits on another remaining vertex: that is a cycle. Disconnected DAGs still output every vertex.

Which structure answers "are a and b connected?" after each new edge, in near-constant time?

  1. BFS from a after each edge
  2. Adjacency matrix
  3. Union-find with path compression and union by size
  4. Min-heap
Union-find handles online edge additions with amortised O(α(n)) per operation. Re-running BFS each time costs O(V + E) per query.

A graph contains a triangle (a cycle of 3 vertices). Is it bipartite?

  1. It depends on the start vertex of the BFS
  2. No, an odd cycle cannot be 2-coloured
  3. Only if it is directed
  4. Yes, any graph with a cycle is bipartite
Going round an odd cycle with alternating colours returns to the start with the opposite colour: a clash. Bipartite = no odd cycle.

Edges have weights 1 to 100. Why not BFS for the shortest path?

  1. BFS minimises the number of edges, not the total weight
  2. BFS cannot handle cycles
  3. BFS is slower than Dijkstra
  4. BFS needs a sorted adjacency list
A path with more edges can be cheaper. BFS's layer argument only holds when every edge costs the same.

Multi-source BFS on a grid with K sources costs:

  1. O((R x C)2)
  2. O(K log K + R x C log(R x C))
  3. O(R x C), the same as one BFS
  4. O(K x R x C)
All sources start in the queue at distance 0, and every cell is still discovered once. That is the whole point of seeding them together.
