BFS shortest path in disguise

The hard part of BFS questions is rarely the BFS. It is seeing that the problem is "fewest steps from a start state to a goal state", then defining the state and its neighbours. Ask yourself three questions:

  1. What is one state? A cell (r, c); a word; a 4-digit lock string; a cell plus "obstacles removed so far" (r, c, k); a node plus a bitmask of visited nodes.
  2. What is one move? Step to a neighbour cell; change one letter; turn one dial up or down; take one bus.
  3. Does every move cost the same? If yes, BFS. If moves cost 0 or 1, use 0-1 BFS (a deque: push 0-cost moves to the front). If costs vary, Dijkstra.

Interviewers love this: when asked "why BFS and not DFS for the minimum?", answer: DFS finds a path, not the shortest; to get the minimum with DFS you would explore every path, which is exponential. BFS settles distances layer by layer in O(V + E).

Level-by-level BFS. When the answer is "number of rounds" (minutes until all oranges rot), process the queue one layer at a time: read size = len(queue), pop exactly that many, then add 1 to the round counter.
