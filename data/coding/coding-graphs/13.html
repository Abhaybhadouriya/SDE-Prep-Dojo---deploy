Interview questions

BFS or DFS: how do you decide?

Use BFS when the question asks for the fewest steps in an unweighted graph, or anything that spreads in rounds; BFS gives shortest distances by construction. Use DFS when you only need reachability, components, cycle detection, or a topological order, or when you need to explore and undo choices (backtracking). For plain "visit everything" either works with the same O(V + E) cost; pick the one with the safer memory profile (iterative) for big inputs.

How to answer

Name the question's goal first (minimum vs existence), then the walk, then its cost.

Likely follow-ups
  • Can DFS find a shortest path? (Only by exploring all paths, exponential in general; on a tree there is just one path so DFS is fine.)
  • What is the memory of each? (BFS holds a whole frontier, which can be O(V) wide; DFS holds the current path, O(depth).)
Count the islands in a grid. What is the complexity, and what if the grid is 104 x 104?

Scan every cell; when an unvisited land cell appears, count one island and flood it with DFS or BFS marking all connected land. Every cell is visited a constant number of times: O(R x C) time, O(R x C) worst-case extra space for the seen array and stack. At 108 cells, avoid recursion, avoid a separate seen array (mark in place, or use a bitset), and if the grid does not fit in memory, process it row by row with union-find over the current and previous row only, keeping labels per row as in connected-component labelling for images.

How to answer

Give the simple flood fill first, then talk about the real machine: stack depth, memory per cell, streaming.

Likely follow-ups
  • Count distinct island shapes? (Record the move sequence of each flood, including backtrack markers, relative to its first cell, and put the strings in a set.)
  • Land is added one cell at a time; report the count after each? (Union-find: each new land cell is a new set, union with land neighbours; Number of Islands II.)
Given courses and prerequisites, can you finish them all? Return an order.

Courses are vertices, a prerequisite pair [a, b] is a directed edge b → a. Run Kahn's algorithm: compute in-degrees, queue every in-degree-0 course, pop, append to the order and decrement the in-degree of each successor, queueing those that reach 0. If the order contains all n courses it is a valid schedule; otherwise there is a cycle and the answer is impossible. O(V + E) time and space.

How to answer

Model the edge direction explicitly, say why in-degree 0 means "free to take", and say how the count reveals a cycle.

Likely follow-ups
  • Minimum number of semesters if any number of courses can run in parallel? (Count BFS layers in Kahn's.)
  • Which courses are in the cycle? (Those whose in-degree never reached 0, or the GRAY path at the moment a back edge is found in DFS.)
How do you detect a cycle in an undirected graph versus a directed graph?

Undirected: during DFS/BFS, a visited neighbour that is not the parent closes a cycle; or with union-find, an edge whose two ends already share a root. Directed: three-colour DFS, where an edge into a GRAY vertex (still on the recursion path) is a back edge; or Kahn's algorithm, where a cycle exists if fewer than V vertices get output. The undirected rule is wrong for directed graphs because two separate paths reaching the same vertex do not form a cycle.

How to answer

Give both cases, and a one-line counterexample for using the wrong rule (A → B, A → C, C → B has no cycle but B is reached twice).

Likely follow-ups
  • Return the nodes that can never reach a cycle? (Find Eventual Safe States: vertices that finish BLACK, or Kahn on the reversed graph.)
Why does Dijkstra fail with negative edges, and what do you use instead?

Dijkstra finalises a vertex when it is popped, assuming no later path can be cheaper. A negative edge can make a path through a not-yet-popped vertex cheaper than the finalised one, so the answer is wrong. Use Bellman-Ford: relax every edge V-1 times, O(V x E); one more round that still improves something proves a negative cycle. If the costs are only 0 and 1, 0-1 BFS with a deque is linear.

How to answer

State the greedy invariant and show which assumption breaks.

Likely follow-ups
  • Cheapest flight with at most K stops: why not plain Dijkstra? (The cheapest route to a city may use too many stops; you need state (city, stops) or K+1 rounds of Bellman-Ford using the previous round's copy.)
  • Complexity of the heap version? (O(E log V) with a binary heap.)
Merge accounts that share at least one email.

Treat emails as vertices; each account says "all these emails belong together", so union every email of an account with the account's first email. Map each email to an integer id first. After all unions, group emails by their root, sort each group, and attach the owner's name. With union by size and path compression this is O(N α(N)) for the unions plus O(N log N) for sorting, where N is the total number of emails. A DFS over an email graph also works; union-find is shorter.

How to answer

Say what the vertices are (emails, not accounts), why union-find fits ("group by shared key"), then the output step.

Likely follow-ups
  • Accounts stream in? (Union-find handles additions online; deletions it cannot, so rebuild or use another design.)
Word Ladder: shortest transformation sequence. How do you make it fast?

Each word is a vertex; two words are adjacent if they differ in one letter. BFS from the start word gives the minimum number of steps. Generating neighbours by comparing every pair is O(N2 x L); instead, for each position try the 26 letters and check a hash set, O(N x L x 26) neighbour checks overall, or pre-bucket words by wildcard patterns such as h*t. Remove words from the set as they are visited. Bidirectional BFS from both ends, always expanding the smaller frontier, cuts the explored states sharply on long ladders.

How to answer

Model it as a graph first, then BFS, then the neighbour-generation optimisation, then bidirectional as the follow-up.

Likely follow-ups
  • Return all shortest sequences? (Word Ladder II: BFS that records parents per layer, then DFS back from the end over the parent DAG.)
