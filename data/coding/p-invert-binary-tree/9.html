60-second recall

  • Cue: "mirror", "flip left and right everywhere" -> one recursive function, null base case.
  • Insight: mirror = same root + mirror(right) on the left + mirror(left) on the right.
  • State: none beyond the node; each swap is independent, so any traversal order works.
  • Trap: save both child results before assigning; avoid naive in-order.
  • Cost: O(n) time, O(h) stack; BFS for deep trees.
def invert(node):
    if not node: return None
    node.left, node.right = invert(node.right), invert(node.left)
    return node

In C++ you write root->left = invert(root->right); root->right = invert(root->left);. What do you get?

  1. A correct mirror
  2. Both children end up as the old right subtree; the old left subtree is lost
  3. Infinite recursion
  4. A compile error
After the first line root->left already holds the mirrored old right subtree, and the second line mirrors it back. Save both results first, or swap the children and then recurse.

Each visit swaps the node's two children. Which traversal orders give a correct mirror?

  1. Pre-order and post-order only
  2. Every order, including plain in-order
  3. BFS only
  4. Pre-order, post-order and BFS, but not plain in-order
In-order swaps between the two recursive calls, so the second call runs on the subtree it has already flipped (the old left) and flips it back, while the old right subtree is never visited.

Outside LeetCode (which caps the tree at 100 nodes), a 10^5-node chain goes to the recursive Python version. What happens?

  1. It works fine
  2. RecursionError: the default limit is 1000 frames, so use BFS or an explicit stack
  3. It takes O(n^2) time
  4. It needs O(n) extra arrays besides the stack
Recursion depth equals the tree height. A queue or stack version swaps the children of every node with no depth limit.
