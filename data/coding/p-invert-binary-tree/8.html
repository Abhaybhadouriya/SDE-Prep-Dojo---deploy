Common mistakes

Overwriting a child before saving it. root.left = invert(root.right); root.right = invert(root.left); in Java/C++/Go: the second line reads the new left (already the mirrored right), so the old left subtree is lost. Save both results first (as our code does), or use a temp, or Python's tuple assignment which evaluates the right side first.

The in-order trap. "invert(left); swap; invert(right)" inverts the old left subtree twice (it is now the right child) and the old right subtree never. If you want in-order, the second call must be invert(left) again. Simpler: use pre- or post-order.

Swapping values instead of subtrees. Swapping left.val and right.val fixes one level and fails when the children have different shapes or one is null.

Forgetting to return the root. A void helper that inverts in place is fine, but invertTree itself must return the root (and null for an empty tree).
