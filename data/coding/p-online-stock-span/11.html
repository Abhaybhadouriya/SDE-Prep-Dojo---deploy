Interview follow-ups

Prove the amortised O(1) bound.

Aggregate argument: across n calls there are exactly n pushes, and a pop removes something pushed earlier, so at most n pops. Total work O(2n), so O(1) per call on average. A single call can still take O(n) (60 after a long falling run).

How to answer

Say "aggregate analysis" and separate worst case per call from total cost.

Likely follow-ups
  • Can you make every call O(log n) worst case? Binary search on the stack of prices, but then the stack is not shrunk lazily; usually not worth it.
Now the span counts only strictly lower prices.

Change the pop condition to top.price < price. Equal prices then stay on the stack and stop the span, and the stack becomes non-increasing instead of strictly decreasing.

How to answer

Tie the comparison to the definition; it is the one-character decision interviewers probe.

Likely follow-ups
  • Sum of Subarray Minimums uses < on one side and <= on the other to avoid double counting.
Answer "span as of day k" for any past day k.

Record the span returned on each day in an array; the past answer never changes because later prices do not affect earlier spans. O(1) query, O(n) memory.

How to answer

Notice the answer is determined at insertion time.

Likely follow-ups
  • "Span of day k as seen with a threshold price p" needs a sparse table or segment tree of maxima plus binary search.
Only the last W days matter (a sliding window), and memory must be O(W).

Store (price, day) in a deque instead of a stack: pop lower-or-equal prices from the back as before, and drop entries older than W days from the front. Span = today - day of the back entry after popping, capped at W.

How to answer

Link it to Sliding Window Maximum: same deque, both ends.

Likely follow-ups
  • Why store the day instead of the span? Because window expiry is about absolute time.
Many stock tickers arrive interleaved in one stream.

Keep a hash map from ticker to its own StockSpanner. Each update touches only that ticker's stack, so the amortised bound holds per ticker; total memory is the sum of the stack sizes.

How to answer

Make it a small design: map + per-key state, and talk about evicting idle tickers.

Likely follow-ups
  • Thread safety: one lock per ticker, or shard tickers across worker threads.
