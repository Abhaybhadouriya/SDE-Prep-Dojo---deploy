Interview follow-ups

Why not just one window that counts when distinct == k?

Because the good starts for an end form a band: starts that are too far left have more than k distinct, starts too far right have fewer. A window keeps one left edge, so it can only bound one side. On [1,2,1], k = 2 it counts 2 instead of 3. The subtraction supplies the second edge.

How to answer

Give the tiny counterexample; interviewers often ask exactly this.

Likely follow-ups
  • Which conditions are safe for one window? Monotonic ones: "at most", "at least".
Do it in one pass.

Keep left, mid and right. After adding nums[right], push mid right while freq[nums[mid]] > 1 (decrementing), so [mid..right] is the shortest good window. If a (k+1)-th value arrived, zero freq[nums[mid]], mid++ and left = mid. When the window has k distinct, add mid - left + 1. O(n), one loop.

How to answer

Explain what left and mid mean (longest and shortest good start), then the reset rule.

Likely follow-ups
  • Is it faster in practice? One pass, but the constant work per step is similar.
The values are arbitrary integers (up to 109, maybe negative). What changes?

Replace the count array with a hash map (or compress the values to 0..m-1 first, then use an array). Negative values do not matter here: the window condition is about distinct values, not sums.

How to answer

Point out the array only works because values are in 1..n; mention coordinate compression for speed.

Likely follow-ups
  • With a hash map, how do you track distinct? Erase keys whose count hits 0 and use the map size, or keep a counter.
Return the longest subarray with exactly k distinct values.

Use the "at most k" window and record the length whenever distinct == k (after shrinking while distinct > k). The longest window with exactly k is the longest "at most k" window that actually reaches k. No subtraction needed for "longest".

How to answer

Contrast: counting needs two edges, the longest needs only the far one.

Likely follow-ups
  • Shortest with exactly k: shrink while the left value is duplicated in the window (the mid pointer).
Count subarrays with between lo and hi distinct values.

atMost(hi) - atMost(lo - 1). The same identity: a range condition on a monotonic quantity is a difference of two "at most" counts.

How to answer

Generalise the trick in one line.

Likely follow-ups
  • Could you share work between the two calls? Run both windows in one loop; the cost stays O(n).
Can the result overflow?

At most n(n+1)/2 ≈ 2·108 for n = 2·104: fits in int32. Each atMost term is bounded by the same number. At n = 105 use 64-bit.

How to answer

Do the arithmetic out loud.

Likely follow-ups
  • Memory: two arrays of n + 1 ints, or reuse one by clearing it between calls.
