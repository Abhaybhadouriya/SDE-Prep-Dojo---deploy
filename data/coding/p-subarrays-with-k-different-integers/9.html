  • Cue: count subarrays with exactly k distinct values -> atMost(k) - atMost(k - 1).
  • Insight: "at most k distinct" holds on a suffix of starts, so a window tracks it; "exactly" is a band with two edges.
  • State: freq[1..n], distinct, left; count += right - left + 1.
  • Trap: distinct changes only on 0 ↔ 1; while not if; fresh array per call; size n + 1.
  • Cost: O(n) time, O(n) space; one-pass three-pointer variant exists.
def at_most(k):
    freq = [0] * (n + 1); distinct = left = cnt = 0
    for right, x in enumerate(nums):
        if freq[x] == 0: distinct += 1
        freq[x] += 1
        while distinct > k:
            freq[nums[left]] -= 1
            if freq[nums[left]] == 0: distinct -= 1
            left += 1
        cnt += right - left + 1
    return cnt
return at_most(k) - at_most(k - 1)

Quick quiz

nums = [1,2,1], k = 2. atMost(2) and atMost(1) are:

  1. 3 and 3
  2. 5 and 2
  3. 6 and 3
  4. 6 and 0
All 6 subarrays have ≤ 2 distinct; only the 3 single elements have ≤ 1. Answer 3.

Why can a window not count "exactly k distinct" directly?

  1. For a fixed end the good starts form a band with two edges, and a window tracks one edge
  2. The values are not sorted
  3. It needs a hash map
  4. k can be 1
Too many distinct and too few distinct are both bad, so validity is not monotonic in the start.

What is atMost(0) for any non-empty array?

  1. n
  2. 1
  3. -1
  4. 0
Every non-empty subarray has at least one value; the window empties itself each step and adds 0.
