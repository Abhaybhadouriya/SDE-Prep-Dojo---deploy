Shape 4: balance counters (parenthesis strings)

For brackets you do not need a stack when only one bracket type exists: a single counter of open brackets is enough. ( adds one, ) takes one away. The string is valid when the counter never drops below zero and ends at zero. Greedy problems on top of this counter:

  • Minimum Add to Make Parentheses Valid (LC 921): when a ) would push the counter below zero, count one insertion and keep the counter at zero. At the end add the leftover opens.
  • Minimum Swaps to Make the String Balanced (LC 1963): find the deepest unmatched ] count m; each swap fixes two, so the answer is (m + 1) / 2.

Valid Parenthesis String. The string holds only (, ) and *, length 1 to 100. Each * may act as (, as ), or as nothing. Return true if some choice for the stars makes the string a valid bracket sequence. (Original: LeetCode 678.)

Trying all choices is 3k. Instead, track the range of possible open counts, [lo, hi]. A ( moves both up; a ) moves both down; a * widens the range (lo down, hi up). If hi < 0, even reading every star as ( leaves too many closes: fail. Clamp lo at 0, because a negative open count is not a real state (it would mean we used a star as ) where we did not have to). Valid at the end if lo == 0: some choice closes everything.

From your world

An open-bracket counter behaves like credit-based flow control on a link (PCIe or InfiniBand credits): each send consumes a credit, each return adds one, and the counter must never go below zero. The [lo, hi] range is what you would track if some events were ambiguous: the smallest and largest credit level that is still possible.
