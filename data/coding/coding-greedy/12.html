Interview questions

How do you convince an interviewer that your greedy solution is correct?

Use an exchange argument: take any optimal answer that differs from greedy at the first decision, swap in the greedy choice, and show the answer stays valid and no worse. By induction greedy is optimal. Or use "stays ahead": after k steps greedy is at least as good as any other strategy after k steps.

How to answer

Name the greedy choice in one line, then give the swap in two sentences on the actual problem ("OPT's first interval ends later than mine, so swapping mine in cannot collide with OPT's second"). Mention the counterexample you tried for the rejected orders.

Likely follow-ups
  • Give a problem where greedy fails. (Coin change with {1, 3, 4} and 6; 0/1 knapsack.)
  • How would you check a greedy you cannot prove? (Brute force on random small inputs and compare.)
Jump Game: why is one "reach" variable enough? Then: what changes for the fewest jumps?

The reachable indices always form a prefix [0, reach], because from any index you can jump any length up to its value. So the set is fully described by its right end. For the fewest jumps, the indices reachable in exactly k jumps form consecutive blocks; scan with curEnd and far and count a jump each time you pass the end of a block. Both are O(n), O(1).

How to answer

Start from the DP (can[i] true if some earlier j with j + nums[j] ≥ i is true), point out it is O(n2), then show the prefix fact that collapses it to one number.

Likely follow-ups
  • Jumps can go left or right by exactly nums[i] (Jump Game III). (Plain BFS/DFS with visited; greedy no longer applies.)
  • Minimum taps to water a garden. (Convert each tap to a reach from its left end, then Jump Game II.)
Gas Station: prove that after a failure at i you can skip every start between the old start and i.

Starting at s, we arrived at every station k in (s, i] with a tank ≥ 0. Starting at k instead means arriving with 0, which is no more than we had. If even the larger tank failed at i, the smaller one fails at i or earlier. So the next candidate is i + 1. Together with "a lap exists iff total gain ≥ 0", one pass finds the unique start.

How to answer

Give the O(n2) "simulate from each start" first, then this skip lemma. No second lap is needed: the total check covers the wrap.

Likely follow-ups
  • Why is the start unique when it exists? (Given by the problem; with ties several starts could work and the pass returns the first.)
Candy: why two passes? Can you do it in O(1) extra space?

Each child has a left rule and a right rule. The left pass makes each value the minimum for the left rule; the right pass raises it to the minimum for the right rule; the max satisfies both and is minimal for each child, so the sum is minimal. An O(1)-space version counts rise and fall lengths along the slopes; mention it, but write the two-pass version unless asked.

How to answer

Show the failing single pass on a falling slope like 4, 3, 2, 1, then the fix. Complexity O(n) time, O(n) space.

Likely follow-ups
  • Children on a circle. (Break the circle at a local minimum, which always gets 1, then solve the line.)
  • Equal neighbours: is there a constraint? (No; equal ratings may get any counts.)
Non-overlapping intervals: why sort by end and not by start? What changes for "minimum arrows"?

Ending earliest leaves the most room for the rest (exchange argument). Sorting by start fails on one long interval covering two short ones. You can sort by start if, on overlap, you drop the one with the larger end; that is the same rule in another form. For arrows (LC 452), an arrow at x bursts balloons with start ≤ x ≤ end, so touching balloons share an arrow and the test becomes start > lastEnd for a new arrow.

How to answer

Draw three intervals: [1,10], [2,3], [4,5]. By start keeps 1; by end keeps 2. That one picture settles it.

Likely follow-ups
  • Minimum meeting rooms. (Sort by start plus a min-heap of end times, or a sweep of +1/-1 events.)
  • Weighted intervals. (Greedy fails; DP with binary search on the previous compatible interval.)
Largest Number: why is the comparator a + b > b + a a valid sort order?

Map a string s of length L to the value v(s) / (10L - 1), the repeating decimal 0.sss... Then ab > ba exactly when that value for a is larger, so the comparator is ordering by a real number: it is transitive and a strict weak order. Given a valid order, any adjacent pair in the wrong order can be swapped to increase the result, so the sorted order is the maximum.

How to answer

The adjacent-swap argument plus "the comparator is consistent" is usually enough. Mention the all-zeros case.

Likely follow-ups
  • Smallest number instead. (Flip the comparator; strip leading zeros carefully.)
  • Cost of the sort. (O(n log n) comparisons, each O(L) for the concatenation.)
Valid Parenthesis String: walk me through the [lo, hi] idea and its alternatives.

lo and hi are the smallest and largest open counts any choice of stars can give. Fail if hi drops below 0; clamp lo at 0; accept if lo is 0 at the end. Alternatives: two stacks of indices (opens and stars), matching closes with opens first, then stars, and finally pairing leftover opens with later stars, O(n) time and space; or DP over (index, open count), O(n2).

How to answer

Say why the range has no holes (every value between lo and hi is reachable because each star moves by one), which is what makes two numbers enough.

Likely follow-ups
  • Return one valid assignment of the stars. (Use the two-stack method; it builds the matching.)
  • Three bracket types. (Needs a stack; the counter trick only works for one type.)
You proposed greedy and the interviewer says "I don't think that works". What now?

Treat it as a hint. Ask for, or search for, a small counterexample (3 to 4 items). If one exists, say what the failure teaches (a choice now affects later options in a way you ignored) and move to DP over the state that greedy threw away. If you believe greedy is right, give the exchange argument calmly and offer to check a small case together.

How to answer

Stay concrete: run your rule and brute force on a small input by hand. A quick switch to DP scores better than a stubborn defence.

Likely follow-ups
  • What would the DP state be? (Usually index plus whatever the greedy rule ignored: remaining capacity, last chosen item, open count.)
  • Could greedy still be used as a bound? (Yes, as a pruning bound in branch and bound.)
