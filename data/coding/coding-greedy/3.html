Shape 1: reachability (jump game, gas station)

Jump Game. You stand on index 0 of an array of non-negative integers. The value at index i is the longest jump you may make from there (any jump from 1 up to that value). Return true if you can reach the last index, else false. Length 1 to 104, values 0 to 105. (Original: LeetCode 55.)

We never care which path we used, only how far right we can get. Keep one number, reach = the furthest index we can stand on so far. Walk left to right. If the current index is beyond reach, no path gets here, so we are stuck. Otherwise update reach = max(reach, i + nums[i]). Every index up to reach is reachable, because the jumps can be shorter than the maximum; that "no gaps" fact is why one number is enough.

  1. Start on index 0. Only index 0 is reachable, so reach = 0.
  2. From index 0 we can jump 1. reach becomes 1.
  3. Index 1 is within reach. It allows a jump of 2, so reach becomes 3: indices 0 to 3 are all reachable.
  4. Index 2 holds 0. It adds nothing, but it does not hurt either: reach stays 3.
  5. Index 3 also holds 0. reach is still 3.
  6. Index 4 is beyond reach. No path can land here, so the answer is false. One pass, O(n) time, O(1) space.

The loop behind the steps. Invariant: reach is the farthest index reachable from any index seen so far; if the loop arrives at an index beyond reach, nothing later is reachable. Lifted unchanged from the tested templates below.

// 1. Reachability: can we stand on the last index?
bool canJump(const vector<int>& nums) {
    int reach = 0;                              // furthest index reachable so far
    for (int i = 0; i < (int)nums.size(); ++i) {
        if (i > reach) return false;            // i is past everything we can reach: stuck
        reach = max(reach, i + nums[i]);
    }
    return true;
}
# 1. Reachability: can we stand on the last index?
def can_jump(nums):
    reach = 0                          # furthest index reachable so far
    for i, step in enumerate(nums):
        if i > reach:                  # i is past everything we can reach: stuck
            return False
        reach = max(reach, i + step)
    return True

Jump Game II (LeetCode 45) asks for the fewest jumps, and promises the end is reachable. Think of it as BFS without a queue: level k is the block of indices you can reach with exactly k jumps. Track curEnd (the last index of the current level) and far (the furthest index the next level reaches). When i hits curEnd, you must jump once more, and the next level ends at far. This is the "greedy stays ahead" proof: after k jumps nobody can be further right than far.

Gas Station. n stations sit on a circle. Station i gives you gas[i] units of fuel, and driving from i to i + 1 costs cost[i]. You start with an empty tank at a station of your choice and drive clockwise. Return the start index that lets you complete one full lap, or -1 if none does. If an answer exists it is unique. n is 1 to 105, all values 0 to 104. (Original: LeetCode 134.)

Two facts make it a single pass. First, a lap is possible from somewhere if and only if total gas ≥ total cost. Second, if you start at s and the tank first goes negative at station i, then no station between s and i can be the start either: each of them would have arrived at i with the same or less fuel (you reached each one with a tank ≥ 0, so starting there only throws that fuel away). So you jump the start straight to i + 1 and reset the tank.

  1. Write gain = gas - cost per station. The total is 0, so a lap is possible from exactly one start.
  2. Try start 0. After station 0 the tank holds 1.
  3. After station 1 the tank is 1 - 3 = -2. We cannot reach station 2. Starting at 1 would be even worse (it skips the +1), so both 0 and 1 are ruled out.
  4. Move the start to 2 and reset the tank to 0. After station 2 the tank holds 3.
  5. After station 3: 3 - 2 = 1. Still fine.
  6. After station 4: 1 + 1 = 2. We reached the end of the array without going negative and the total is not negative, so start 2 also covers stations 0 and 1. Answer: 2.

The loop behind the steps. Invariant: when the tank goes negative after station i, no station from the current start to i can be the start, so the next candidate is i + 1; a total gain >= 0 guarantees the last candidate works. Lifted unchanged from the tested templates below.

// 2. Gas station: one pass, reset the start when the tank goes negative
int canCompleteCircuit(const vector<int>& gas, const vector<int>& cost) {
    int total = 0, tank = 0, start = 0;
    for (int i = 0; i < (int)gas.size(); ++i) {
        int d = gas[i] - cost[i];
        total += d;
        tank += d;
        if (tank < 0) { start = i + 1; tank = 0; }      // no station in [start..i] can be the start
    }
    return total >= 0 ? start : -1;
}
