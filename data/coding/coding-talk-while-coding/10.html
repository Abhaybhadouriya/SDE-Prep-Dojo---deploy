What changes from SDE-1 to SDE-3

The words are similar at every level; who drives the conversation and how deep the trade-offs go is what changes.

SDE-1 / new gradSDE-2SDE-3 / senior
ClarifyingAsks about input and edge cases before coding.Asks the questions that pick the algorithm (size, order, mutation) and proposes defaults.Also asks about the context: one call or many, streaming, memory limits, concurrency.
ApproachBrute force, then a better idea, perhaps with a hint.Brute force to optimal without hints; compares two options.Explains why it is optimal (a lower bound or a known limit) and what changes under follow-ups.
While codingExplains blocks; code mostly correct.States invariants; clean helpers; few bugs, found by self.Production habits out loud: input validation, overflow, naming, API shape; finishes with time to spare.
TestingRuns the given example.Runs own examples and edge cases, dry-runs with a variable table.Also says how they would test it for real: a brute-force oracle, random inputs, property checks.
Follow-upsAnswers when asked.Anticipates the obvious one ("if the input were a stream...").Drives them: scale, parallelism, a different data model, the trade-off in a real system.

From your world

For a senior systems engineer, the cheapest SDE-3 signal is bringing your production instincts into a toy problem in one sentence each: "this would be called per packet, so I would avoid the allocation in the loop", "on a 32-bit counter this overflows after about 4 billion events", "if two threads call this, the map needs a lock or per-CPU copies". Say it, do not build it, then get back to the problem.
