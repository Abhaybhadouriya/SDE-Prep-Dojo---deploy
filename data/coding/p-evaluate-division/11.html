Interview follow-ups

There are a million queries and only a few hundred variables. What changes?

Per-query DFS costs O(V + E) each, which now dominates. Weighted union-find makes each query two near-O(1) finds. If variables are few and the set is static, the Floyd-Warshall table (O(V³) once, O(1) per query) also works.

How to answer

Compare preprocessing vs per-query cost and pick by the ratio of queries to variables.

Likely follow-ups
  • Cache answers of past DFS queries as new edges (path caching): it moves toward the same idea.
Currency conversion: given rates between pairs, find the best rate from currency A to B.

If the rates are consistent, every path gives the same rate (this problem). If they are not (real markets), "best" is the max-product path: take -log(rate) as edge weights and run Bellman-Ford (negative edges); a negative cycle means an arbitrage loop. With few currencies, BFS/DFS over simple paths is acceptable.

How to answer

Ask first whether rates are consistent; the answer decides between this page and shortest paths.

Likely follow-ups
  • Detect arbitrage (negative cycle in -log space).
The equations might contradict each other. Detect it.

In the union step, if a and b already share a root, the implied value is wa / wb; if it differs from v by more than a tolerance, report a contradiction. That is LC 2307.

How to answer

Show the invariant gives you the implied value for free.

Likely follow-ups
  • Why compare with a tolerance and not ==? (Floating-point rounding.)
Why is it enough to find any path, not the shortest?

Consistency: along any path from c to d the ratios telescope to c/d, so all paths give the same product (up to rounding). Shortest paths only matter when edge values can disagree.

How to answer

Write the telescoping product in one line.

Likely follow-ups
  • Which path would you prefer numerically? (Shorter paths accumulate less rounding error.)
Equations arrive over time, interleaved with queries.

Weighted union-find is online by nature: each equation is a union, each query two finds. A DFS solution would have to update an adjacency list and re-search; still fine for tiny inputs but not for streams.

How to answer

Point out that union-find never needs to see the whole input.

Likely follow-ups
  • Could an equation be deleted? (Union-find cannot undo cheaply; that needs a different structure.)
