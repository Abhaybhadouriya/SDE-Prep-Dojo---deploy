Approaches: brute -> better -> optimal

Hint 1

If you know a/b and b/c, how do you get a/c? What structure does a chain of such facts form?

Hint 2

Each equation gives you two directed edges. What does "cannot be determined" mean in that graph?

1. Brute force - derive everything (Floyd-Warshall style)

Idea: keep a table ratio[x][y] of known values (with ratio[x][x] = 1 for known x). For every middle variable k and every pair (i, j): if ratio[i][k] and ratio[k][j] are known, set ratio[i][j] = ratio[i][k] · ratio[k][j]. Then each query is a table lookup.

O(V³ + Q)time
O(V²)space

When it is fine: with V <= 40, V³ = 64,000 steps, so it actually passes; it is the right choice when queries vastly outnumber variables. What is wasted: it computes all V² ratios even if only a few are asked. -> rung 2.

2. Better - graph + DFS/BFS per query

Graph: variables are nodes; a / b = k adds a -> b with weight k and b -> a with weight 1/k. Query c / d: if either is not a node, -1. Otherwise BFS from c carrying the running product; when you reach d, return the product. If BFS ends without d, -1.

q = deque([(c, 1.0)]); seen = {c}
while q:
    x, prod = q.popleft()
    if x == d: return prod
    for y, w in graph[x]:
        if y not in seen: seen.add(y); q.append((y, prod * w))
return -1.0
O(E + Q·(V + E))time
O(V + E)space

Why any path works: the equations are consistent (the problem promises no contradictions), so every path from c to d gives the same product: along a path c, x1, x2, ..., d the ratios telescope, (c/x1)(x1/x2)...(xk/d) = c/d. So the first path BFS finds is correct, and no shortest-path logic is needed.

What is not ideal: every query re-walks the graph. With many queries (a follow-up favourite) that is the bottleneck. -> rung 3.

3. Optimal - weighted union-find

Idea: keep a union-find where each variable x stores parent[x] and ratio[x] = x / parent[x]. Then find(x) returns the root r and the product of ratios on the way, which is x / r.

  1. Find with compression: after find(x), parent[x] = root and ratio[x] = x / root (multiply the ratios along the old path).
  2. Union a / b = v: let a = wa · ra and b = wb · rb. If ra != rb, hang ra under rb with ratio[ra] = ra / rb = v · wb / wa (from a / b = (wa·ra)/(wb·rb) = v).
  3. Query c / d: unknown variable or different roots -> -1; same root -> (c/root) / (d/root) = wc / wd.
O((E + Q)·α(V))time, with path compression
O(V)space

Why it works: the invariant "ratio[x] = x / parent[x]" holds for every node at all times. Path compression keeps it because x/root = (x/parent) · (parent/root). The union formula is just that invariant solved for the new edge ra -> rb. Two variables are related by the equations exactly when they are in the same component, which is exactly when they share a root.
