Two numbers are missing from 0..n+1 (array of n).

XOR everything to get x ^ y (nonzero, since x ≠ y). Pick any set bit, e.g. d = xr & -xr. Split both the range and the array by that bit and XOR each half separately: each half contains exactly one missing number. Alternatively use sum and sum of squares, but that overflows sooner.

How to answer

"The XOR gives me x ^ y; a set bit tells me where x and y differ, so it separates them."

Likely follow-ups
  • k missing numbers? (A bitmap or the negation trick, O(n) space or in-place marking.)
The array is sorted. Can you beat O(n)?

Yes: binary search for the first index i where nums[i] != i (equivalently nums[i] > i). Before the gap every value equals its index; after it every value is index + 1. If no such index exists, return n. O(log n).

How to answer

Name the monotone predicate first, then write the lower-bound template.

Likely follow-ups
  • k-th missing positive in a sorted array (LC 1539): missing before i = nums[i] - i - 1, binary search on it.
The numbers arrive as a stream too large to store.

XOR (or a 64-bit running difference) needs one word of state and one pass, and it is order-independent, so it works on a stream and can even be computed in parallel shards and combined with one more XOR.

How to answer

Point out that XOR is associative and commutative, which is exactly what makes it shardable.

Likely follow-ups
  • What if the stream may contain duplicates? (Then neither trick works; you need a bitmap of n + 1 bits.)
Why prefer XOR over the sum formula?

No overflow (every intermediate value is below 2⌈log₂(n+1)⌉), no multiplication, and it extends directly to the "two missing" and "single number" variants. The sum version is easier to explain and also O(1); both are accepted. In C and Java, the sum version with int overflows silently for n above ~65,000 (Java's wraparound happens to cancel, C's signed overflow is undefined behaviour).

How to answer

Give the sum version, then upgrade to XOR when asked about overflow.

Likely follow-ups
  • Would unsigned arithmetic fix the sum version? (Yes, modular arithmetic still cancels exactly, as long as the true answer fits.)
Do it by placing each value at its own index (cyclic sort).

For each i, while nums[i] < n && nums[i] != i, swap it to index nums[i]. The value n has no slot and is left wherever it lands. Then the first i with nums[i] != i is the answer, else n. Each swap fixes one value, so O(n) total.

How to answer

Use it to show the family that solves First Missing Positive; note it mutates the input.

Likely follow-ups
  • Why is it O(n) despite the inner while? (Each swap puts one value in its final place; at most n swaps.)
