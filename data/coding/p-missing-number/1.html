The problem (in our words)

A ticket machine was meant to print every number from 0 to n, but one number was skipped. You get an array nums of length n holding the numbers that were printed, in any order. All values in nums are distinct and lie in the range [0, n].

Return the single number in [0, n] that does not appear in nums.

Signature: int missingNumber(int[] nums).

Constraints

  • n == nums.length
  • 1 <= n <= 104
  • 0 <= nums[i] <= n
  • All the numbers of nums are unique.

Follow-up (part of the original): can you solve it with O(1) extra space and O(n) running time?

Practice it: LeetCode 268 - Missing Number · GfG - Missing in Array (values 1..n, otherwise the same) · TUF - Missing Number

Constraints tell you: n ≤ 104, so even O(n log n) sorting is instant; the interview is about the O(1)-space follow-up. The largest sum is 104 · 104/2 ≈ 5 · 107, which fits in a 32-bit int, but say out loud that the sum trick can overflow for larger n and XOR cannot.
