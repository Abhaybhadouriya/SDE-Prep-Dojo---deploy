  • Cue: values are a known range 0..n with one absent; O(1) space asked.
  • Insight: expected set minus actual set = the answer; XOR or subtraction cancels pairs.
  • State: one accumulator, starting at n (the index with no slot).
  • Trap: forgetting index n; answer 0 is valid; sum overflow for big n.
  • Cost: O(n) time, O(1) space; sorted input -> binary search O(log n).
acc = n                       # the expected element that has no array slot
for i, x in enumerate(nums):
    acc ^= i ^ x              # expected element i and actual element x
return acc                    # survivors of the cancellation

Why does the XOR loop start with acc = n?

  1. n is always the answer
  2. The indices 0..n-1 miss the number n from the full range
  3. XOR needs a non-zero start
The range 0..n has n + 1 numbers; the array has only n indices.

Input [4,0,1,2]: what does the XOR approach return?

  1. 0
  2. 4
  3. 3
XOR of 0..4 is 4, XOR of the array is 4^0^1^2 = 7, and 4 ^ 7 = 3.

The array is already sorted. Fastest method?

  1. Binary search for the first i with nums[i] != i
  2. XOR all values
  3. Hash set
The predicate "nums[i] == i" is true then false, so it is monotone: O(log n).
