Approaches: brute -> better -> optimal

Hint 1

You know exactly which numbers should be there. What single number summarises "the whole set 0..n"?

Hint 2

The array has n slots with indices 0..n-1. Add one more index, n, and the indices form the full range. Compare indices against values.

1. Brute force - check every candidate

Idea: for each v in 0..n, scan the array for v; return the first v you do not find.

O(n²)time
O(1)extra space

What is wasted: the array is rescanned n + 1 times to answer yes/no questions.

2. Better - sort, or a "seen" table

Sort: after sorting, nums[i] == i for every i before the gap; the first i with nums[i] != i is the answer, and if there is none the answer is n. O(n log n) time, and it modifies the input. On an array that is already sorted, binary search for the first i with nums[i] != i in O(log n).

Seen table: a boolean array (or hash set) of size n + 1; mark every value, then return the unmarked index. O(n) time, O(n) space.

What is wasted: the extra table stores n + 1 facts, but we only need one number: the difference between "what should be there" and "what is there".

3. Optimal - sum difference or XOR

Sum: n(n+1)/2 - sum(nums). The present values subtract themselves away; the missing one is left. One pass, O(1) space. Its only weakness is overflow when n is large (n(n+1)/2 exceeds 231 at n ≈ 65,536); you can keep a running acc += i - nums[i] to stay small.

XOR: start acc = n (the index that has no slot), then for each i do acc ^= i ^ nums[i]. XOR is commutative and associative, x ^ x = 0 and x ^ 0 = x, so every number that appears both as an index and as a value vanishes; the missing number appears only as an index and survives. No overflow, no ordering requirement.

Why it works: the multiset {0, 1, ..., n} ∪ nums contains every present value exactly twice and the missing value exactly once. XOR of a multiset depends only on which elements occur an odd number of times, so the total is the missing value. The same argument with + and - gives the sum version.

Proof (optional)

Let m be the missing value and S = {0..n}. Then nums = S \ {m}. XOR over S ⊕ XOR over nums = XOR over S ⊕ XOR over (S \ {m}). Every s ≠ m is in both and contributes s ⊕ s = 0; m is in S only. Since ⊕ is associative and commutative we can regroup freely, so the result is m. The loop computes exactly this: acc starts with n, and iteration i adds index i and value nums[i], so after the loop every index 0..n and every value has been XORed in once.

  1. Start with acc = n = 4: index 4 has no slot in the array, so it enters on its own.
  2. i = 0: acc ^= 0 ^ 4. Value 4 meets index 4 and both vanish (x ^ x = 0); index 0 is still waiting. acc = 4 ^ 0 ^ 4 = 0.
  3. i = 1: acc ^= 1 ^ 0. Value 0 cancels index 0; index 1 is waiting. acc = 1 (001).
  4. i = 2: acc ^= 2 ^ 1. Value 1 cancels index 1; index 2 is waiting. acc = 2 (010).
  5. i = 3: acc ^= 3 ^ 3. Index 3 and value 3 cancel at once; acc stays 2.
  6. All five indices and four values are in. Every number except one appears twice and cancels; index 2 never met its value. Return 2. Order never mattered: XOR is commutative.
