  • Cue: ALL ways to split a string with a rule per piece -> backtrack on the end of the next piece.
  • Insight: partition = first palindromic piece + partition of the rest.
  • State: start index, path of pieces; pal[i][j] table filled with i going down.
  • Trap: copy the path; pop after the call; base case start == n.
  • Cost: O(n · 2n) time (output-bound), O(n2) table.
def explore(start):
    if start == n: out.append(path[:]); return
    for end in range(start, n):
        if ok(start, end):          # O(1) table lookup
            path.append(s[start:end+1]); explore(end + 1); path.pop()

At each step the recursion chooses what?

  1. The next character to delete
  2. The end of the next piece: any prefix of the rest that is a palindrome
  3. A centre to expand
Cut a palindromic prefix, recurse on the remainder, undo the cut.

Why precompute isPal[i][j]?

  1. To avoid re-checking the same substring many times across branches
  2. It is required for correctness
  3. To sort the output
The table is O(n^2) to fill and makes each check O(1).
