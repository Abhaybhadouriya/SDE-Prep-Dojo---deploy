What is the time complexity, exactly, and why can't you do better?

At most 2n-1 partitions exist (one per subset of gaps), each written in O(n), so O(n · 2n). The all-same-letter string reaches it. Any algorithm must output that many characters, so it is optimal for the "return all" version.

How to answer

Name the worst-case input; it makes the bound concrete.

Can you build the pal table without the O(n2) memory?

For the search, check pieces with two pointers instead: same worst-case bound, O(n) extra memory. Or store, for each start, the list of ends that form palindromes (found by expanding around centres): memory proportional to the number of palindromic substrings.

How to answer

Trade-off: the table is 16 x 16 here, so memory does not matter; for large n, generate palindromes by centre.

Likely follow-ups
  • How many palindromic substrings can a string have? (O(n2))
Return the partitions in lexicographic order of pieces / with the fewest pieces first.

For fewest pieces first, run BFS over start positions (each level adds one piece) or sort the output by length. For a lexicographic order on the list of pieces, the default loop already produces partitions in increasing order of the first piece's length, which is not lexicographic in general; simply sort the output.

How to answer

Don't over-engineer: sorting 215 lists is cheap.
