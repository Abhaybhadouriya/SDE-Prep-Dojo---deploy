Approaches: brute -> better -> optimal

Hint 1

The first piece is s[0..end] for some end. Once you fix it, what problem is left?

Hint 2

The same substring s[i..j] gets tested for being a palindrome in many branches. Can you answer all those questions up front?

1. Brute force - try every set of cuts

Idea: a string of length n has n - 1 gaps. Every bitmask over the gaps is one way to cut. For each of the 2n-1 masks, cut the string and check that every piece is a palindrome.

O(n · 2n)time
O(n)extra space

What is wasted: once the first piece is not a palindrome, every mask that starts with that cut is hopeless, but the brute force still builds and checks all of them. We use it in the test files as an oracle. -> rung 2.

2. Better - backtracking with a two-pointer check

Idea: explore(start): if start == n, save a copy of the path. Otherwise for each end from start to n - 1, if s[start..end] is a palindrome (two pointers), push it, call explore(end + 1), pop it.

This is the three-step template the top community post describes: choose a piece, explore the rest, unchoose. Invalid prefixes cut whole subtrees, but each check still costs O(length of the piece).

O(n · 2n)time (worst)
O(n)stack + path

3. Optimal - precompute pal[i][j], then backtrack

for i in n-1 .. 0:
    for j in i .. n-1:
        pal[i][j] = s[i] == s[j] and (j - i < 2 or pal[i+1][j-1])
explore(start):
    if start == n: out.append(copy(path))
    for end in start .. n-1:
        if pal[start][end]: path.push(s[start..end]); explore(end+1); path.pop()
  1. Every partition is found once. A partition is determined by its first piece and the partition of the rest. The loop tries each possible first piece exactly once, and the recursion enumerates the rest, so every valid partition is produced, with no duplicates.
  2. Nothing invalid is produced. A piece enters the path only if pal says it is a palindrome, and we save only when the pieces cover all of s.
  3. The table is correct. s[i..j] is a palindrome iff its ends match and the inside s[i+1..j-1] is a palindrome (empty or one letter counts). Filling i downward makes the inside ready first.
O(n · 2n)time
O(n2)table + O(n) path

Why it works and why it is optimal: the search never enters a dead branch, because each step checks the next piece in O(1). The remaining cost is building the output: up to 2n-1 partitions, each copied in O(n). Any algorithm must at least write that output, so the bound is tight. The DP table is the "DP + DFS" variant from the top community solutions; on LeetCode it is the fastest because n is tiny but palindrome checks repeat a lot.
