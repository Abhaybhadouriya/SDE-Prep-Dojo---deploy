Approaches: brute -> better -> optimal

Hint 1

With an array, two indices from both ends solve it. What stops you doing that on the list?

Hint 2

You are allowed to change next pointers temporarily. Which half would you turn around?

1. Brute force - copy to an array, two pointers

Idea: walk the list once, push every value into an array, then compare a[i] with a[n-1-i] for i < n/2.

O(n)time
O(n)space

What is wasted: a full copy of the data, just to be able to walk backwards. It is the right first sentence in an interview, and a fine answer if memory does not matter.

2. Better (looks clever, same space) - recursion or a stack

Idea: recurse to the tail while a front pointer waits outside; on the way back up, compare each node with the front pointer and advance it. Or push the first half on a stack while finding the middle, then pop while walking the second half.

front = head
def check(node):
    nonlocal front
    if node is None: return True
    if not check(node.next): return False
    ok = node.val == front.val; front = front.next
    return ok
O(n)time
O(n)call stack (105 frames)

What is not enough: the call stack is memory too, and 105 frames crash Python and risk C++. The follow-up asks for O(1). -> rung 3.

3. Optimal - middle, reverse back half, compare, restore

slow = fast = head
while fast.next and fast.next.next: slow, fast = slow.next, fast.next.next
back = reverse(slow.next)                  # the back half now points toward the middle
ok = all_equal(head, back)                 # stop when back runs out
slow.next = reverse(back)                  # undo
  1. slow lands on the last node of the front half. With the loop test fast.next and fast.next.next, for n = 4 slow stops at index 1, for n = 5 at index 2 (the middle).
  2. Reverse only slow.next onward. The standard prev/cur/next loop, O(1) space. The back half is now a separate list starting at the old tail.
  3. The back half drives the comparison. It has floor(n/2) nodes, never more than the front, so while back is the only test needed and the odd middle is skipped automatically.
  4. Restore before returning. Reverse the back half again and reattach it to slow. Callers (and interviewers) expect inputs untouched; also, do it even when the answer is false, so do not return from inside the loop.
O(n)time (about 2n pointer moves)
O(1)extra space

Why it works: a sequence is a palindrome iff its first floor(n/2) values equal its last floor(n/2) values read backwards; the odd middle has no partner. Reversing the back half gives exactly "the last floor(n/2) values, read backwards", as a list we can walk forward, so one forward walk over both lists checks the definition.

Proof (optional)

Each loop iteration moves fast by 2 and slow by 1, so after t iterations slow = t and fast = 2t. The loop runs while 2t + 2 <= n - 1, so it stops at t = floor((n - 1)/2). The back half is indices t + 1 .. n - 1: that is n - 1 - t = floor(n/2) nodes, never more than the t + 1 front nodes. Comparing back[k] (= index n - 1 - k) with front[k] for k < floor(n/2) is exactly the palindrome definition.

A neat variant from the top-voted solutions reverses the front half while the fast pointer runs, saving one pass. It is shorter but harder to explain under pressure; the version above is the one most interviewers expect.
