Approaches: brute → better → optimal

Hint 1

There are only three values. Could you just count them?

Hint 2

For one pass: where should the next 0 go? Where should the next 2 go? Keep an index for each.

Hint 3

After you swap a 2 to the right end, what do you know about the value that came back?

1. Brute force - any comparison sort

Idea: write a simple sort yourself (insertion sort, or quicksort), since the library sort is not allowed.

O(n²)time (insertion) / O(n log n) (quicksort)
O(1)space

What is wasted: a comparison sort learns the order by comparing items, but here the final position of each value is known without any comparison: all 0s first. -> rung 2.

2. Better - count, then overwrite (two passes)

Idea: count the 0s, 1s and 2s in one pass, then write that many 0s, 1s and 2s over the array in a second pass. This is counting sort with three buckets.

c = [0, 0, 0]
for x in nums: c[x] += 1
nums[:] = [0] * c[0] + [1] * c[1] + [2] * c[2]
O(n)time (2 passes)
O(1)space (3 counters)

What is wasted: nothing, asymptotically, and it is a fine answer. But it reads the array twice, and it only works because the items are bare numbers: if each item carried data (a colour and an object), you cannot rebuild it from counts. The follow-up asks for one pass that moves the actual items. -> rung 3.

3. Optimal - Dutch national flag (one pass)

lo = mid = 0; hi = n - 1
while mid <= hi:
    if a[mid] == 0: a[lo], a[mid] = a[mid], a[lo]; lo += 1; mid += 1
    elif a[mid] == 1: mid += 1
    else: a[mid], a[hi] = a[hi], a[mid]; hi -= 1
  1. Four zones at all times. [0, lo) holds 0s, [lo, mid) holds 1s, [mid, hi] is not looked at yet, (hi, n) holds 2s. At the start the unknown zone is the whole array.
  2. A 0 at mid: swap with lo, move both. The value at lo is the first 1 (or, if no 1 has been seen, it is the 0 itself). Either way, after the swap both slots are in the right zone, so both pointers step forward.
  3. A 1 at mid: just move mid. It extends the 1-zone.
  4. A 2 at mid: swap with hi, move only hi. The value that came from hi was in the unknown zone; it could be 0, 1 or 2, so mid must look at it on the next round.
O(n)time, one pass (≤ n loop rounds)
O(1)space

Why it works: each round shrinks the unknown zone by exactly one slot (mid moves right, or hi moves left), so the loop runs at most n times, and each branch keeps the four-zone invariant. When mid > hi the unknown zone is empty, and the three remaining zones are exactly 0s, 1s, 2s in order.

Proof (optional)

Assume the invariant holds and mid <= hi. Case 0: if lo < mid, a[lo] is a 1 (first slot of the 1-zone); after the swap a[lo] = 0 and a[mid] = 1, so lo+1 and mid+1 keep both zones correct. If lo == mid the swap is a no-op and the 0 joins the 0-zone. Case 1: the 1-zone grows by one. Case 2: after the swap a[hi] = 2, so hi-1 keeps the 2-zone correct; the new a[mid] came from the unknown zone and stays unknown, which is why mid is unchanged. The quantity hi - mid + 1 (unknown size) drops by one in every case, so the loop ends after at most n rounds with the unknown zone empty.
