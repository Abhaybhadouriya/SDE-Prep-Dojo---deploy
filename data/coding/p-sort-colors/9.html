Revision card

  • Cue: 3 classes, group in place, one pass -> Dutch national flag partition.
  • Insight: zones [0,lo)=0 · [lo,mid)=1 · [mid,hi]=unknown · (hi,n)=2.
  • State: lo (next 0 slot), mid (scan), hi (next 2 slot).
  • Trap: after swapping with hi do NOT move mid; loop while mid <= hi.
  • Cost: O(n) one pass, O(1) space; counting is O(n) in two passes.
lo, mid, hi = 0, 0, n - 1
while mid <= hi:
    if low(a[mid]):  swap(lo, mid); lo += 1; mid += 1
    elif mid_class(a[mid]): mid += 1
    else:            swap(mid, hi); hi -= 1

Quick quiz

nums[mid] is 2. What happens?

  1. swap(mid, hi); mid++; hi--
  2. swap(lo, mid); lo++
  3. swap(mid, hi); hi--
  4. mid++
The value that comes from hi has not been checked yet, so mid stays where it is.

Why is it safe to move mid after swapping a 0 to lo?

  1. It is not safe
  2. a[lo] was a 1 (or the same 0), so the slot at mid is classified
  3. a[lo] is always 0
  4. lo always equals mid
Everything in [lo, mid) is a 1; if that zone is empty, lo == mid and the swap does nothing.

The items are objects with a colour and must keep their original order within a colour. Which approach still works?

  1. Dutch national flag
  2. Count and overwrite
  3. Quicksort
  4. Three output lists (or a stable counting sort), then copy back
Swapping breaks stability, and counts cannot rebuild objects. A stable counting sort with O(n) extra space does both.
