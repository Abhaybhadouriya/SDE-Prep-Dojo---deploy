The problem (in our words)

You get an array nums of n items, each painted red, white or blue, written as the integers 0 (red), 1 (white) and 2 (blue). Rearrange the array in place so that equal colours are next to each other, in the order red, white, blue (all 0s, then all 1s, then all 2s). You must not call the language's library sort. Nothing is returned.

Signature: void sortColors(int[] nums).

  • n == nums.length
  • 1 <= n <= 300
  • nums[i] is 0, 1 or 2

Follow-up asked by the original: can you do it in one pass with only constant extra space?

Practice it: LeetCode 75 · GfG Sort 0s, 1s and 2s · TUF article

Constraints tell you: n ≤ 300 means any approach passes; the real test is the follow-up. Only three distinct values exist, so comparison sorting (n log n) is overkill: counting is O(n), and a partition can do it in one pass because every value's final zone is known the moment you see it.
