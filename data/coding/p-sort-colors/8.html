Common mistakes

Moving mid after swapping with hi. The value that arrives from hi was never inspected. On [2,0,2,0,1] advancing mid leaves a 2 or a 0 in the middle.

Loop condition mid < hi. The slot at hi is still unknown, so the loop must run while mid <= hi. With <, [1,0] stays unsorted.

Not moving mid after swapping with lo. When lo == mid, lo then overtakes mid, and the next 0 rule swaps an unchecked value into the 0-zone. [0,2,1] ends as [1,2,0]. Move both: a[lo] was already classified (a 1, or the 0 itself).

Using unsigned hi in C/C++. hi can become -1 (for [2] or any all-2s array). With size_t it wraps to a huge number and the loop runs off the array. Use a signed int.
