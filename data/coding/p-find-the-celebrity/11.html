Interview follow-ups

Prove that the survivor of pass 1 is the only possible celebrity.

Every call removes one person from consideration (the table in "Recognise the pattern"). After n - 1 calls, n - 1 people are removed, all except the survivor. A celebrity can never be removed, because both rules only remove non-celebrities.

How to answer

State the two rules, then count: n - 1 calls, n - 1 people out.

Likely follow-ups
  • Why can there not be two celebrities? Celebrity A must be known by B and B must know nobody: contradiction.
Stay within 3n calls. Can you do even fewer?

Our code uses (n - 1) + cand + (n - 1) calls, at most 3n - 3. Caching the pass-1 answers (for example, the call knows(0, 2) in step 5 of the dry run was already asked) saves a few more. A known lower bound says that in the worst case about 3n - ⌊log2 n⌋ - 3 calls are needed, so the bound is nearly tight.

How to answer

Count the calls of each pass in front of the interviewer; mention the cache as the next easy saving.

Likely follow-ups
  • What does the cache cost? O(n) memory for the answers involving the final candidate.
knows() is a slow network call. Parallelise it.

Pass 1 is a tournament: pair people up and ask all n/2 questions at once, keep the survivors, repeat: log2 n rounds and n - 1 calls in total. Pass 2's 2(n - 1) checks are independent and can all run in parallel, so the whole thing takes about log n + 1 round trips.

How to answer

Turn the sequential chain into a knockout bracket; the call count stays O(n), only the latency drops.

Likely follow-ups
  • With a rate limit of k calls per round, the number of rounds is about n/k for each pass.
Solve it when the matrix is given directly (GfG version).

Same two passes, reading M[a][b] instead of calling knows. Or the degree view: count in-degree and out-degree for each node in O(n2) and return the node with (n-1, 0). The two-pass version is O(n) and shows you understand the elimination.

How to answer

Start with degrees (obvious), then show the O(n) pass and why it reads only O(n) cells.

Likely follow-ups
  • Two pointers version: i = 0, j = n-1; if M[i][j], i++ else j--; the meeting point is the candidate.
What if there can be several "local celebrities" (known by everyone in their group)?

Then the uniqueness argument breaks and elimination does not apply. Model it as a graph: find strongly connected components, condense to a DAG, and look for a component with no outgoing edges that every other component reaches. That needs the full graph, O(n2) calls.

How to answer

Point out which assumption made the O(n) trick possible ("at most one"), and what fails without it.

Likely follow-ups
  • Is there an Ω(n2) lower bound then? Yes for general reachability questions with an edge oracle.
