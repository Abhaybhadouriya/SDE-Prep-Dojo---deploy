60-second recall

  • Cue: at most one "special" item + a pairwise test that always rules one out -> elimination.
  • Insight: knows(a,b) yes -> a out; no -> b out. n-1 calls leave one survivor; verify it.
  • State: one variable cand; pass 2 checks both directions for every i != cand.
  • Trap: the survivor is not proven; skip self-pairs; for i > cand, knows(cand, i) is known.
  • Cost: < 3n calls, O(1) space; brute force O(n²) calls.
cand = 0
for i in range(1, n):            # pass 1: tournament
    if knows(cand, i): cand = i  # cand knows someone: out
for i in range(n):               # pass 2: verify; knows(cand, i) for i > cand is already "no"
    if i != cand and ((i < cand and knows(cand, i)) or not knows(i, cand)): return -1
return cand

Pass 1 leaves one candidate. Why must pass 2 still check it?

  1. If no celebrity exists, the survivor is just whoever was not eliminated
  2. knows() can return wrong answers
  3. Pass 1 only checks half the people
  4. To count the calls
Elimination proves only that nobody else can be the celebrity. It does not prove that the candidate is one.

Why can pass 2 skip knows(cand, i) for i > cand?

  1. Pass 1 already asked knows(cand, i) for every i > cand, and the answer was no
  2. People after cand cannot be celebrities
  3. knows is symmetric
  4. Those calls are free
Once cand took its final value, every later i was compared with it. A yes would have moved cand to i.

With that skip, what is the worst-case number of knows() calls?

  1. Fewer than 3n
  2. About n^2
  3. Exactly 2n
  4. n log n
n - 1 calls in pass 1, n - 1 calls of knows(i, cand), and at most cand calls of knows(cand, i): below 3n, which is the LeetCode follow-up bound.
