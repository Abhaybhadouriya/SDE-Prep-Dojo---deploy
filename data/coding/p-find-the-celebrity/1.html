The problem (in our words)

A conference has n attendees labelled 0 to n - 1. A celebrity is someone whom all the other n - 1 attendees know, while the celebrity knows none of them. There is at most one celebrity. You cannot see who knows whom; you can only call a helper boolean knows(int a, int b), which tells you whether attendee a knows attendee b.

Implement int findCelebrity(int n): return the celebrity's label, or -1 if there is none. Use as few calls to knows as you can.

Input format on the judge: an n x n matrix graph where graph[i][j] == 1 means i knows j; your code never sees it directly, only through knows.

  • n == graph.length == graph[i].length
  • 2 <= n <= 100
  • graph[i][j] is 0 or 1.
  • graph[i][i] == 1 (everyone knows themselves; ignore self-pairs).

Follow-up: if knows may be called at most 3 * n times, can you find the answer without going over?

Practice it: LeetCode 277 Premium · free version: GfG The Celebrity Problem (the matrix is given directly)

Constraints tell you: n <= 100, so running time is not the issue; the measure is the number of API calls. Asking every pair is n(n-1) ≈ 104 calls; the follow-up caps it at 3n = 300, which forces the linear elimination idea.
