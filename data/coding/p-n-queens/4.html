Approaches: brute -> better -> optimal

Hint 1

Every row must hold exactly one queen. So a layout is just "which column in each row".

Hint 2

Two cells are on the same diagonal when r1 - c1 == r2 - c2 or r1 + c1 == r2 + c2.

1. Brute force - try every column permutation

Idea: one queen per row and per column means a layout is a permutation of 0..n-1. Generate all n! permutations and keep those whose r - c values are all different and whose r + c values are all different.

for p in permutations(range(n)):
    if len({r - c for r, c in enumerate(p)}) == n and \
       len({r + c for r, c in enumerate(p)}) == n:
        boards.append(draw(p))
O(n! * n)time
O(n)space

What is wasted: a clash in the first two rows is detected only after all n rows are filled, and that bad prefix is extended (n-2)! times. -> check while building.

2. Better - backtracking with a scan of earlier rows

Idea: place row by row; before placing at (r, c), scan rows 0..r-1 for a queen in the same column or diagonal. Bad prefixes are cut as soon as they appear.

O(n! * n)time (worst)
O(n)space

What is wasted: each safety check costs O(n). The same three questions (column used? diagonal used?) can be answered in O(1) with arrays. -> rung 3.

3. Optimal - backtracking with column and diagonal flags

for c in range(n):
    d, a = r - c + n - 1, r + c
    if col[c] or diag[d] or anti[a]: continue
    col[c] = diag[d] = anti[a] = True
    place(r + 1)
    col[c] = diag[d] = anti[a] = False   # undo
  1. Rows are never shared. Recursion depth r owns row r, so the row rule holds by construction.
  2. Each line family gets an id. Columns c (n ids), "\" diagonals r - c + n - 1 (2n - 1 ids, shifted to be non-negative), "/" diagonals r + c (2n - 1 ids).
  3. Claim, recurse, release. Set the three flags, go to row r + 1, clear them on return. The undo is what lets one set of arrays serve the whole search.
  4. Reaching row n means a full board. Every row has a queen and none attack each other; record it.
O(n!)time (loose bound)
O(n)extra space
O(1)per safety check

Why it works: the recursion enumerates every way to put one queen in each row (that is all candidate layouts), and it only skips a column when that cell is attacked by an earlier queen, which would make every extension invalid. So no valid board is skipped, and every board recorded passed all three checks for every pair of queens.

Proof (optional) - why O(n!) bounds the search

Row 0 has at most n choices, row 1 at most n - 1 (one column is taken), row 2 at most n - 2, and so on, so the recursion tree has at most n + n(n-1) + ... + n! = O(n!) nodes (the sum is at most e * n!). Diagonal pruning cuts this a lot in practice: for n = 8 the search visits 2,057 nodes (we counted) instead of 40,320 permutations. Building each recorded board costs O(n^2), which adds O(S * n^2) for S solutions.

Even faster - bitmasks (interview bonus)

Keep three integers instead of arrays: cols, d1, d2. At each row, free cells are ~(cols | d1 | d2) & ((1 << n) - 1); take the lowest one with p = free & -free, then recurse with cols | p, (d1 | p) << 1, (d2 | p) >> 1. Shifting moves each diagonal's block one column per row. Same complexity class, much smaller constant; this is the trick the most-voted C++ post shows.
