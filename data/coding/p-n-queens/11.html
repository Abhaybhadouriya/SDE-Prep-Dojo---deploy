Interview follow-ups

Only count the solutions (N-Queens II).

How to answer: keep the same search and increment a counter at r == n; drop the board. Bitmasks make it very fast: free = ~(cols | d1 | d2) & full, loop over its set bits.

Likely follow-ups: use symmetry: count boards with row 0's queen in the left half and double it (handle the middle column for odd n).

Return just one solution for a large n (say 1,000).

How to answer: backtracking alone gets slow; there are explicit constructions (the classic formula by n mod 6) and min-conflicts local search, which finds a solution for very large n quickly. Mention them; nobody expects the formula from memory.

Why is the time O(n!) and not O(n^n)?

How to answer: the column flag removes one column per row, so the branching is n, n - 1, n - 2, ...; the number of tree nodes is at most about e * n!. Diagonal pruning makes the real number far smaller.

Some cells are blocked (holes in the board).

How to answer: add one more check, blocked[r][c], before claiming a cell. If a row may stay empty, the "one queen per row" shortcut breaks: recurse over cells instead and allow a skip.

Place k queens on an n x n board (k < n).

How to answer: each row holds at most one queen, so at each row choose "skip" or one free column, and stop when k are placed or when the rows left are fewer than the queens left (pruning).

Can you avoid recursion?

How to answer: yes, keep queenCol[] as an explicit stack: advance the column in the current row, step forward on a safe cell, step back (and clear flags) when the row runs out. Same complexity; recursion depth here is only n <= 9, so recursion is fine.
