Revision card

  • Cue: fewest intervals to remove / most intervals to keep with no overlap.
  • Insight: earliest end first is always safe (exchange argument); answer = n - kept.
  • State: intervals sorted by end, lastEnd (end of the last kept), kept.
  • Trap: sort by end, not start; touching is fine (>=); lastEnd starts at -inf.
  • Cost: O(n log n) time, O(1) extra; DP O(n²); subsets O(2^n).
items.sort(key=lambda iv: iv.end)
kept, last_end = 0, -inf
for iv in items:
    if iv.start >= last_end:      # compatible with everything kept so far
        kept += 1; last_end = iv.end
answer = len(items) - kept

Quick quiz

Which sort order makes the one-pass greedy correct with "keep the first that fits"?

  1. By start, ascending
  2. By length, ascending
  3. By end, ascending
  4. By start, descending
The earliest finisher leaves the most room. Sorting by start descending and taking the latest start also works (it is the mirror image), but not by plain start ascending.

[[1,2], [2,3], [3,4], [1,3]]: what is the answer?

  1. 1
  2. 0
  3. 2
  4. 3
Keep [1,2], [2,3], [3,4] (they only touch) and remove [1,3].

Each interval now has a weight and you want the largest total weight kept. What changes?

  1. Nothing, the same greedy works
  2. Greedy fails; use DP over intervals sorted by end with binary search
  3. Use a heap
  4. Sort by weight
Weighted interval scheduling: dp[i] = max(dp[i-1], w_i + dp[p(i)]), with p(i) found by binary search. O(n log n).
