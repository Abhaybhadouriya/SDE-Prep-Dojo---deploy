The problem (in our words)

A label printer stores a word as an array of characters s. Reverse the order of the characters in place: change the given array itself, using only O(1) extra memory. Do not build a second array or string and copy it back.

Signature: void reverseString(char[] s) (Go: func reverseString(s []byte)). Nothing is returned; the judge reads s after your function finishes.

  • 1 <= s.length <= 105
  • Every s[i] is a printable ASCII character (letters, digits, spaces, punctuation).

Practice it: LeetCode 344 · GfG Reverse a String · GfG Reverse an Array

Constraints tell you: n up to 105 means O(n) is expected and O(n) recursion depth is risky (a 105-deep call stack can overflow in Python and Java). "Printable ASCII" means one character = one byte, so there is no Unicode trap here; in an interview, say out loud that real strings with multi-byte UTF-8 would need care.
