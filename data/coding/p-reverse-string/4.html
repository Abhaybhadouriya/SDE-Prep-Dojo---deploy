Approaches: brute -> better -> optimal

Hint 1

Where does the character at index 0 have to end up? And the one at index 1?

Hint 2

If index i and index n-1-i swap, does that disturb any other pair?

1. Brute force - copy into a second array

Idea: allocate t of length n, set t[i] = s[n-1-i], then copy t back into s. Library one-liners like s[:] = s[::-1] in Python do the same under the hood.

O(n)time
O(n)extra space

What is wasted: the buffer. The problem forbids it explicitly (O(1) extra memory), and an interviewer will ask you to remove it.

2. Better - recursion on the outer pair

def rec(lo, hi):
    if lo >= hi: return
    s[lo], s[hi] = s[hi], s[lo]
    rec(lo + 1, hi - 1)

Idea: swap the outer pair, then reverse the inside. It is in place on the data, but each call adds a stack frame: n/2 frames, so O(n) hidden space, and for n = 105 Python hits its default recursion limit (1000). Worth knowing because some interviewers ask for it as a recursion exercise.

O(n)time
O(n)stack

What is wasted: the call stack. The recursion is a tail call, so it turns directly into a loop.

3. Optimal - two pointers, swap inward

lo, hi = 0, len(s) - 1
while lo < hi:
    s[lo], s[hi] = s[hi], s[lo]
    lo += 1; hi -= 1
  1. Invariant: before each check of lo < hi, slots [0, lo) and (hi, n-1] already hold their final characters; the middle [lo, hi] is still in input order.
  2. Each step swaps the outermost unfinished pair, which puts both of them in their final place, and shrinks the middle by 2.
  3. Stop at lo >= hi: for odd n the pointers meet on the middle character (its own mirror); for even n they cross. Either way nothing is left to do.
O(n)time, n/2 swaps
O(1)space

Why it works: reversing maps index i to n-1-i. Those mirror pairs are disjoint, so swapping one pair never disturbs another, and walking lo from the left visits each pair exactly once. The top-voted community posts show the same loop and point out that it is the iterative form of the recursive "swap ends, reverse the inside".
