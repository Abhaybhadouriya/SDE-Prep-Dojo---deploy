Common mistakes

Stopping when nums[mid] == target. That is classic search: you get a copy, not the first. In a boundary search equality is just "passes" (or "fails" for the strict test); the loop keeps going.

Mixing templates. while lo <= hi with hi = mid loops forever; while lo < hi with hi = mid - 1 skips the answer. Use one template consistently: lo < hi, hi = mid, lo = mid + 1, hi starts at n.

Starting hi at n - 1. Then "target is bigger than everything" and "target is the last element" both end at n - 1, and for the strict search you cannot express "no bigger value exists", so last comes out one short on [6,6,6,6].

Reading nums[first] before checking first < n. Out of bounds on an empty array or when the target is larger than all values.

Using Java's Arrays.binarySearch for the first copy. With duplicates it may return any of them; it is not a lower bound.
