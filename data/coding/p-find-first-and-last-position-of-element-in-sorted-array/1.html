The problem (in our words)

You are given an integer array nums sorted in non-decreasing order (equal values are allowed and sit next to each other) and an integer target. Return a two-element array [first, last]: the smallest and the largest index i with nums[i] == target. If target does not occur in nums, return [-1, -1].

Your algorithm must run in O(log n) time.

Signature: int[] searchRange(int[] nums, int target).

  • 0 <= nums.length <= 105 (the array may be empty)
  • -109 <= nums[i] <= 109
  • nums is a non-decreasing array.
  • -109 <= target <= 109

Practice it: LeetCode 34 · GfG First and Last Occurrences · TUF article

Constraints tell you: the O(log n) requirement rules out "find any copy, then walk left and right", which is O(n) when the whole array is the target. 105 elements need about 17 halvings per search. Values up to 109 fit in int32; target + 1 also fits (2·109 would not, but 109 + 1 does), and our version avoids it anyway.
