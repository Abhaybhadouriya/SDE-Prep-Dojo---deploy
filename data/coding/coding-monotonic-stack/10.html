Interview questions

The next greater element solution has a while loop inside a for loop. Why is it O(n) and not O(n2)?

Amortised analysis. Every index is pushed exactly once, and an index can be popped at most once because it never comes back. The while loop body is one pop, so across the whole run it executes at most n times. Total work is n pushes plus at most n pops plus n loop checks that fail: O(n). Space is O(n) in the worst case, a decreasing input where nothing is ever popped.

How to answer

Count pops, not loop iterations. Name the worst case for space (strictly decreasing input for next greater).

Likely follow-ups
  • Can you do it with O(1) extra space? (Not in general for all elements; for a single query, yes, by scanning.)
Daily Temperatures: return, for each day, how many days until a warmer one (0 if none). Walk me through your approach.

It is next strictly greater, with the answer as a distance. Keep a stack of day indexes whose temperatures decrease from bottom to top. For each day i, while the top's temperature is below today's, pop it and write res[top] = i - top. Then push i. Days left on the stack keep 0. O(n) time, O(n) space.

An alternative from the editorial runs from right to left and jumps using already computed answers (j += res[j]), with O(1) extra space besides the output. It is a nice follow-up, but the stack version is the one to give first.

Likely follow-ups
  • Temperatures arrive as a stream: which days can you answer when a new one arrives? (Exactly the ones you pop.)
Largest Rectangle in Histogram: explain why one pass with a stack finds the answer.

Every maximal rectangle has a shortest bar, and for a fixed shortest bar i the best rectangle spans from just after the previous smaller bar to just before the next smaller bar. So the answer is the max over i of h[i] * (next[i] - prev[i] - 1).

With an increasing stack, both boundaries are available at the moment bar i is popped: the popping index is its next smaller (or equal) bar and the new top is its previous smaller bar. A sentinel 0 at the end pops the rest. Each bar is pushed and popped once: O(n) time, O(n) space.

Ties: popping on >= gives some equal bars a too-short rectangle, but the last equal bar popped gets the full width, so the maximum is unaffected.

Likely follow-ups
  • Maximal rectangle in a 0/1 matrix (row histograms, O(rows x cols)).
  • The rectangle must include index k (LC 1793): grow outwards from k with two pointers, always toward the taller side.
Sum of Subarray Minimums: how do you avoid listing all O(n2) subarrays, and how do you handle equal values?

Count each element's contribution. If p is the previous index with a smaller value and q the next, a[i] is the minimum of every subarray that starts in (p, i] and ends in [i, q): (i - p) * (q - i) subarrays. Sum a[i] * (i - p) * (q - i) modulo 109 + 7.

For duplicates, use a strict comparison on one side and a non-strict one on the other: previous strictly smaller and next smaller-or-equal. Then a subarray with several equal minimums is credited to exactly one of them. Show it on [2, 2, 2]: the answer is 12; with both sides strict you would get 20.

How to answer

Contribution formula first, tie rule second, then a two-pass or one-pass stack, then overflow (64-bit and modulo per multiplication).

Likely follow-ups
  • Sum of subarray ranges (LC 2104): sum of maxes minus sum of mins.
  • Do it in one pass: settle each element when it is popped.
Remove K Digits: why is the greedy stack correct, and what edge cases do you handle?

A number with the same length is smaller if its first differing digit is smaller. If digit d is immediately followed (in the kept sequence) by a smaller digit e, deleting d makes that position smaller without touching the prefix, so it beats any choice that keeps d. Popping while the top is bigger and k > 0 applies that rule at the first possible position each time.

Edge cases: if k is left over, the kept digits are non-decreasing, so cut the last k. Strip leading zeros. If nothing remains, return "0". Equal digits are not popped. O(n) time.

Likely follow-ups
  • Largest number instead: flip the comparison.
  • Keep exactly k digits from an array (LC 1673): pop only while the remaining elements can still fill k.
Remove Duplicate Letters: return the smallest string, as a subsequence, that contains every distinct letter exactly once.

Greedy stack with a different budget. Record the last index of every letter. Scan left to right; skip a letter already on the stack. Otherwise, while the top is bigger than the current letter and the top appears again later (last[top] > i), pop it and mark it unused. Push the current letter. "cbacdcbc" gives "acdb".

Why it is safe: we only remove a bigger letter when we are sure we can pick it again later, and putting the smaller letter first makes the string smaller. O(n) time, O(alphabet) space.

Buildings With an Ocean View: the ocean is to the right; return the indexes of buildings with no building of equal or greater height to their right.

Two clean answers. The stack: scan left to right and pop every building whose height is less than or equal to the current one (it is blocked); what remains on the stack, in order, is the answer. Or scan right to left with a running maximum: a building sees the ocean if it is taller than everything seen so far; reverse the collected indexes. Both are O(n); the second uses O(1) extra space.

Likely follow-ups
  • The ocean is on both sides (compute both directions).
  • The input is a stream arriving left to right: the stack version is the one that works, since you cannot scan right to left.
Trapping Rain Water has a two-pointer solution. How would you solve it with a monotonic stack, and which would you present?

Keep a decreasing stack of indexes. When bar i is taller than the top, pop the top as the "floor"; the new top is the left wall and i is the right wall. Water above that floor is (min(h[left], h[i]) - h[floor]) * (i - left - 1). This fills water in horizontal layers. O(n) time, O(n) space.

Two pointers fill water column by column with O(1) space and are shorter, so present those first and give the stack version when asked for another method, or when the follow-up needs the walls explicitly.
