The idea: a stack of unanswered questions

Take a = [2, 1, 2, 4, 3] and ask for the next greater value to the right of each element. The answer is [4, 2, 4, -1, -1]: the 2 at index 0 waits until the 4, the 1 at index 1 is answered by the 2 right next to it, and nothing to the right of 4 or 3 is bigger.

The brute force checks every pair, O(n2). The stack version does this instead:

  1. Walk i from left to right.
  2. While the stack is not empty and the value on top is smaller than a[i]: pop it. a[i] is its next greater element; write the answer now.
  3. Push i. It is now waiting for its own answer.
  4. After the loop, whatever is still in the stack has no answer: write -1.

Two facts make this correct and fast:

  • The stack stays sorted. We only push a[i] after removing everything smaller, so values on the stack decrease from bottom to top. That is the "monotonic" in the name.
  • Each index is pushed once and popped at most once. The inner while can run many times for one i, but over the whole loop it runs at most n times in total. So the total work is O(n), amortised O(1) per element. Always say this sentence in an interview; it is the reason the nested loop is not O(n2).

Store indexes on the stack, not values. From an index you can read the value (a[st.top]), compute a distance (i - st.top, which daily temperatures needs) and know a boundary (which the histogram needs). From a value you can do only the first.

Step through it. Watch the moment at i = 3, when the 4 arrives and answers two waiting elements at once:

  1. The stack starts empty. The res row shows answers as they get written; question marks are still unknown.
  2. i = 0, value 2. The stack is empty, nothing to pop. Push index 0: it waits for something bigger than 2.
  3. i = 1, value 1. The top (value 2) is not smaller than 1, so 1 cannot answer it. Push index 1. Stack values 2, 1: decreasing.
  4. i = 2, value 2. The top (value 1) is smaller, so pop it and write res[1] = 2. The new top has value 2, which is not strictly smaller than 2, so stop. Push index 2.
  5. i = 3, value 4. Pop index 2 (res[2] = 4) and then index 0 (res[0] = 4). One arrival answered two questions. Push index 3.
  6. i = 4, value 3. The top (value 4) is bigger, so nothing pops. Push index 4.
  7. The loop ends. Indexes 3 and 4 are still waiting: nothing bigger came, so their answer is -1. Five pushes and three pops in total.

The loop behind the steps. Invariant: the stack holds indexes still waiting for their answer, and their values are decreasing from bottom to top; a bigger value answers (and pops) every smaller one on top. Lifted unchanged from the tested templates below.

// NEXT GREATER: stack of indexes with decreasing values; the answer is written at pop time.
vector<int> nextGreater(const vector<int>& a) {
    vector<int> res(a.size(), -1), st;
    for (int i = 0; i < (int)a.size(); i++) {
        while (!st.empty() && a[st.back()] < a[i]) { res[st.back()] = i; st.pop_back(); }
        st.push_back(i);
    }
    return res;
}
# ---- 1. NEXT GREATER: decreasing stack of indexes, answer decided at pop time ----
def next_greater(nums):
    """res[i] = index of the first j > i with nums[j] > nums[i], else -1."""
    res = [-1] * len(nums)
    stack = []                                    # indexes, values strictly decreasing
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:      # x is the answer for everyone smaller
            res[stack.pop()] = i
        stack.append(i)
    return res
