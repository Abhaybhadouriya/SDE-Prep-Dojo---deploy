You want, for every element, the nearest element to its LEFT that is strictly smaller. When do you write the answer?

  1. When the element is popped
  2. Right before pushing it, from the top left after popping
  3. After the loop, from the leftover stack
  4. When the next element arrives
Previous answers are read at push time: after popping everything greater or equal, the top is the nearest strictly smaller element on the left.

In the histogram stack for heights [2, 1, 5, 6, 2, 3], bar 2 (height 5) is popped by i = 4 and the new top is bar 1. What area does bar 2 give?

  1. 5
  2. 10
  3. 20
  4. 15
Width = i - newTop - 1 = 4 - 1 - 1 = 2, area = 5 x 2 = 10.

In Sum of Subarray Minimums, what goes wrong if you use "strictly smaller" for both the previous and the next boundary?

  1. Subarrays with repeated minimums are counted more than once
  2. The run time becomes O(n2)
  3. Subarrays with repeated minimums are never counted
  4. Nothing, it is still correct
Each equal minimum claims the subarray, so it is counted once per copy. Make one side non-strict.

Remove K Digits on "10200" with k = 1. What is the answer?

  1. "100"
  2. "0200"
  3. "200"
  4. "1020"
The 0 pops the 1 (k = 0), leaving "0200"; stripping leading zeros gives "200".

Which problem needs a monotonic deque rather than a monotonic stack?

  1. Remove Duplicate Letters
  2. Daily Temperatures
  3. Sliding Window Maximum
  4. Largest Rectangle in Histogram
In a sliding window, old indexes also leave from the far end of the structure, which a stack cannot do.

For the circular Next Greater Element II, what is the standard trick?

  1. Sort the array first
  2. Run the loop from right to left only
  3. Loop over 2n indexes using i % n, pushing only during the first lap
  4. Use two stacks, one per direction
The second lap lets late elements find answers at the start; pushing only in the first lap keeps each index once.
