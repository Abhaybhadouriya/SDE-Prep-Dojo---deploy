Largest rectangle in a histogram

LC 84: given bar heights (each bar has width 1), find the area of the largest rectangle inside the histogram. Example: heights [2, 1, 5, 6, 2, 3] give 10, from the bars of height 5 and 6 using height 5.

The key change of view: every rectangle has a shortest bar. So instead of trying every pair of edges, fix each bar i as the shortest one and stretch the rectangle as wide as possible. It can stretch left until it hits a bar shorter than h[i], and right until it hits a bar shorter than h[i]. Those are exactly the previous smaller and next smaller elements.

You could compute both arrays with two passes. The classic solution gets both in one pass with an increasing stack. When bar top is popped by bar i:

  • i is its next smaller bar (that is why it got popped: h[i] <= h[top], see the tie note below).
  • The element now under it on the stack is its previous smaller bar (the stack is increasing, so the one below is smaller), or -1 if the stack is empty.
  • So its rectangle is h[top] * (i - newTop - 1), settled right there.

A sentinel height 0 at position n flushes everything left on the stack at the end, so you do not need a second loop. (Some solutions also push a -1 sentinel at the bottom to avoid the empty check.)

  1. i = 0, height 2. The stack is empty, so push 0.
  2. i = 1, height 1. Bar 0 (height 2) is not shorter than 1, so pop it. Nothing is under it, so its left boundary is -1 and its width is 1 - (-1) - 1 = 1. Area 2. Push 1.
  3. i = 2 and i = 3: heights 5 and 6 are both taller than the top, so nothing is popped. Push both. Stack heights 1, 5, 6: increasing.
  4. i = 4, height 2. Pop bar 3 (height 6). The bar under it is bar 2, so the width is 4 - 2 - 1 = 1. Area 6.
  5. Still i = 4. Pop bar 2 (height 5). The bar under it is bar 1, so the width is 4 - 1 - 1 = 2, covering bars 2 and 3. Area 10, the answer. Bar 1 (height 1) is shorter than 2, so stop and push 4.
  6. i = 5, height 3. Taller than the top, so push 5.
  7. i = 6 is the sentinel, height 0. It pops everything: bar 5 (3 x 1 = 3), bar 4 (2 x 4 = 8, from bar 2 to bar 5), bar 1 (1 x 6 = 6). Every bar was pushed once and popped once. Best = 10.

The loop behind the steps. Invariant: bar heights on the stack are increasing; when a lower bar arrives, each popped bar has found its right limit (the new bar) and its left limit (the bar now under it), so its widest rectangle is known. Lifted unchanged from the tested templates below.

// LC 84: increasing stack; when bar top is popped by i, its widest rectangle is (newTop, i).
long long largestRectangle(const vector<int>& h) {
    vector<int> st;
    long long best = 0;
    int n = h.size();
    for (int i = 0; i <= n; i++) {
        int cur = i < n ? h[i] : 0;                         // sentinel flushes the stack
        while (!st.empty() && h[st.back()] >= cur) {
            int top = st.back(); st.pop_back();
            int left = st.empty() ? -1 : st.back();
            best = max(best, (long long)h[top] * (i - left - 1));
        }
        st.push_back(i);
    }
    return best;
}
# ---- 2. HISTOGRAM: increasing stack, a bar's rectangle is settled when it is popped ----
def largest_rectangle(heights):
    """LC 84. When bar `top` is popped by i, its rectangle spans (new top, i)."""
    stack, best = [], 0                           # indexes, heights increasing
    for i in range(len(heights) + 1):
        h = heights[i] if i < len(heights) else 0  # sentinel 0 flushes the stack
        while stack and heights[stack[-1]] >= h:
            top = stack.pop()
            left = stack[-1] if stack else -1      # first smaller on the left
            best = max(best, heights[top] * (i - left - 1))
        stack.append(i)
    return best

Ties

The template pops on h[top] >= h[i]. With equal heights, the earlier bar is popped by the later equal bar and gets a rectangle that is too narrow on the right. That is fine: the later equal bar, popped later, gets the full width, because its left boundary passes over the bar that was already popped. The maximum is still correct. Popping on > is also correct. For a maximum a tie only means some bars get a too-small rectangle, which never wins. For counting, the next section shows ties need much more care.

Maximal rectangle (LC 85)

Given a matrix of '0' and '1', find the largest rectangle of all ones. Process the matrix row by row and keep, for each column, the number of consecutive ones ending at this row. Each row is now a histogram, and LC 84 finds the best rectangle whose bottom edge is that row.
