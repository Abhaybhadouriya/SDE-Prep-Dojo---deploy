Use an int[26] or int[128] array instead of a hash map when the alphabet is small. It is faster and, in C terms, it is just a histogram on the stack.

The max of a window: the monotonic deque

A sum is easy to undo. A maximum is not: when the max leaves, what is the new max? A heap works in O(n log n) but needs lazy deletion. The interview answer is a deque of indexes whose values are strictly decreasing. When a new value arrives, every smaller value at the back can never be a maximum again (the newcomer is bigger and will stay in the window longer), so pop them. The front is always the current max; pop it when its index falls out of the window. The example below, [5, 3, 4, 1, 2] with k = 3, shows both pops: from the back when a bigger value arrives, and from the front when the old maximum expires.

  1. right = 0 brings 5. Nothing smaller at the back to pop. Push index 0. Window not full yet.
  2. right = 1 brings 3. Nothing smaller at the back to pop. Push index 1. Window not full yet.
  3. right = 2 brings 4. Pop 3 from the back: each is <= 4 and older, so it can never be a window max again. Push index 2. Front index 0 > right - k = -1, so the front is still inside. Window full: max = front = 5.
  4. right = 3 brings 1. Nothing smaller at the back to pop. Push index 3. Front check: the front index 0 is <= right - k = 0, so 5 has left the window: pop it from the front. This is the dq[0] <= right - k line. Window full: max = front = 4.
  5. right = 4 brings 2. Pop 1 from the back: each is <= 2 and older, so it can never be a window max again. Push index 4. Front index 2 > right - k = 1, so the front is still inside. Window full: max = front = 4.

Each index is pushed once and popped at most once, so this is O(n) too.
