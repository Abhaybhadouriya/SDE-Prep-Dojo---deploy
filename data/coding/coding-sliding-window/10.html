Common mistakes

  • Recording in the wrong place. For "longest", record after the shrink loop. For "shortest", record inside it. Swapping them gives answers that are off by one window.
  • Forgetting to delete zero counts. If you use map.size() as "distinct", a key with count 0 must be removed, or distinct never goes down.
  • Using a window on a non-monotone condition. Exact sums with negatives, "exactly K" directly, medians. Check monotonicity before you code.
  • Off-by-one in the fixed slide. The item leaving is a[right - k], not a[right - k + 1]. Test on k = 1 and k = n.
  • Deque of values instead of indexes. You cannot tell when a value has expired. Store indexes.
  • Recomputing the state. Calling sum(window) or rebuilding the count map inside the loop silently turns O(n) back into O(n·k).
  • Integer overflow on sums. A window of 105 values up to 109 needs 64-bit (long long, long).
