Why it is fast: two edges that only move forward

Take the simplest question: the best sum of any 3 neighbours in [4, 2, -1, 7, 3, 1]. The brute force picks every start and adds 3 values: (n - k + 1) × k additions. With n = 100,000 and k = 50,000 that is 2.5 billion additions. Too slow.

The sliding window keeps the sum. Moving one step costs one addition (the newcomer) and one subtraction (the leaver). The total is O(n) no matter how big k is.

For variable windows the same promise holds for a different reason: right moves forward n times, and left also only moves forward, at most n times in total. Even though there is a while loop inside the for loop, the two together run at most 2n steps. This is an amortised argument: the cost of the inner loop is paid for by the elements, each of which can leave the window only once.

When you write a nested loop in an interview, say this sentence: "the inner loop moves left, which never goes back, so the total work is O(n), not O(n²)." Interviewers listen for it.
