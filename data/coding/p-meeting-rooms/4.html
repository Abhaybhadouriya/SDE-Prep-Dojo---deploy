Approaches: brute -> better -> optimal

Hint 1

If you sort by start time, which meeting is the most likely to clash with meeting i?

1. Brute force - check every pair

Idea: for each pair (i, j), test a[i].start < a[j].end and a[j].start < a[i].end. Any true pair means false.

for i in range(n):
    for j in range(i + 1, n):
        if s[i] < e[j] and s[j] < e[i]:
            return False
return True
O(n^2)time
O(1)space

What is wasted: most pairs are far apart in time and can never clash. Ordering the meetings tells us which single pair per meeting is worth checking. -> rung 2.

2. Optimal - sort by start, compare neighbours

intervals.sort(key=lambda m: m[0])
for prev, cur in zip(intervals, intervals[1:]):
    if cur[0] < prev[1]:      # starts before the previous ends
        return False
return True
  1. Sort by start. Now start never decreases down the list.
  2. Only neighbours can be the first clash. If no neighbour pair overlaps, then end[i-1] <= start[i] < end[i] <= start[i+1] ..., so the meetings form a chain and no farther pair can overlap either.
  3. Strict less-than. cur.start < prev.end is a clash; equal times are a handover, not a clash.
O(n log n)time
O(1)extra (sort aside)

Why it works: suppose meetings i < j (in sorted order) overlap but no neighbours do. Then start[j] >= end[j-1] > start[j-1] >= ... >= end[i], so start[j] >= end[i] and they cannot overlap. Contradiction. So checking n - 1 neighbour pairs is enough.

Another O(n log n): sort starts and ends separately

Sort the start times and the end times into two arrays. One person can attend all meetings iff starts[i] >= ends[i-1] for every i. This is the same two-array sweep that solves Meeting Rooms II, so it is worth knowing; for this problem the single sort is simpler.
