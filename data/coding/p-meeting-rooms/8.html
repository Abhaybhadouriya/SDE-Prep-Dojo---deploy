Common mistakes

  • Using <= in the clash test. Then [5,9] and [9,12] report a clash, but the task treats end times as exclusive.
  • Forgetting to sort. The input is unsorted: on [[9, 12], [1, 4], [5, 9]] the unsorted scan sees 1 < 12 and wrongly returns false.
  • Comparing only with the previous meeting's start. The clash test must use the previous end.
  • Crashing on an empty array by reading intervals[0] before the loop.
  • Java comparator (a, b) -> a[0] - b[0] is fine here (values up to 10^6), but use Integer.compare as a habit: subtraction overflows with large or negative values.
