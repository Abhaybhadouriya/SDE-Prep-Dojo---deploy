Interview follow-ups

How many rooms are needed? (Meeting Rooms II)

How to answer: the answer is the maximum number of meetings running at once. Sort starts and ends separately and sweep, or keep a min-heap of end times: pop when the earliest end <= the new start, push the new end, and the heap size peak is the answer.

Likely follow-ups: which room each meeting gets (keep room ids in the heap).

Return the first pair that clashes.

How to answer: sort indices instead of values (keep the original index with each meeting) and return the two indices at the first failing neighbour check.

Meetings arrive one by one; reject a booking that clashes.

How to answer: keep a balanced BST keyed by start (TreeMap, std::map). For a new [s, e), only the floor (largest start <= s) and the ceiling (smallest start >= s) can clash. O(log n) per booking (LC 729).

Likely follow-ups: allow double bookings but not triple (LC 731): difference counts on a sorted map.

The end time is inclusive ([9, 12] and [12, 15] clash).

How to answer: change the test to cur.start <= prev.end. Always ask which convention the interviewer means.

Can you do it without sorting?

How to answer: with small integer times (here up to 10^6) a difference array over time works: +1 at start, -1 at end, prefix sum, and fail if any value exceeds 1. O(n + T) time and O(T) space, a win only when T is small compared with n log n.

Two people's calendars: find the free slots both share.

How to answer: merge each calendar (sort + merge), then walk both lists with two pointers, outputting the gaps that are free in both and at least the requested length.
