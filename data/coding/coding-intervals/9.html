Common mistakes

  • Wrong endpoint rule. Decide closed vs half-open from the examples, then use <= or < on purpose. Test with two intervals that touch.
  • Overwriting the end instead of taking the max. In merge, last.end = cur.end breaks on [1,10], [2,3]. Always max(last.end, cur.end).
  • Sorting by start for maximum non-overlap. Sort by end. One long early interval breaks the by-start greedy.
  • Comparator overflow. (a, b) -> a[1] - b[1] overflows for values near the int limits (Arrows problem). Use Integer.compare.
  • Starting "last end" at 0. Intervals can start at negative values. Start at minus infinity or take the first interval explicitly.
  • Ties in the sweep. With half-open meetings, an end and a start at the same time must process the end first, or you count one room too many.
  • Difference array off by one. Closed range [l, r] puts -v at r + 1 (size the array n + 2). Car Pooling's "drop off at to" puts it at to.
  • Mutating the input. Some languages sort in place. If the caller still needs the original order (for example, to answer queries by index), sort indices or a copy.
