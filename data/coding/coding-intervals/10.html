Interview questions

Merge overlapping intervals. Why do you only compare with the last merged one?

Sort by start, then walk once and either stretch the last output block (start <= last.end) or start a new one. After sorting, all earlier output blocks end before the last block starts, and the current interval starts no earlier than the last block, so it can only touch the last block. O(n log n) time, O(n) output.

How to answer

Say the invariant out loud: "the output is sorted and disjoint at every step". Then the code is short. Ask whether touching intervals should merge.

Likely follow-ups
  • Intervals arrive one at a time and you must keep the merged set? (A balanced BST or ordered map keyed by start; find the neighbours, merge, O(log n) amortised; this is Data Stream as Disjoint Intervals.)
  • Can you do it without extra space? (Merge in place into the front of the sorted array and return the prefix length.)
Insert an interval into a sorted list of disjoint intervals.

Three phases in one pass: copy intervals whose end is before the new start; absorb every interval whose start is <= the new end, growing the new interval with min of starts and max of ends; append it; copy the rest. O(n), no sort.

How to answer

Mention the O(n log n) "append and merge" option first, then note the input is sorted and give the O(n) pass. Test with the new interval before all, after all, and covering all.

Likely follow-ups
  • Find the phase boundaries faster? (Binary search for the first end >= new start and the last start <= new end; the copy is still O(n) unless you use a linked or tree structure.)
  • Remove an interval instead? (Same walk; split the intervals that partly overlap into a left piece and a right piece.)
Non-overlapping Intervals: why sort by end and not by start or by length?

Keeping the interval that ends first leaves the most room for the rest, and an exchange argument proves it: replacing the first interval of any optimal answer with the earliest-ending one keeps it valid and the same size. By start fails on [1,10], [2,3], [4,5]. By length fails on [1,5], [4,7], [6,10], where the short middle one blocks the two others.

How to answer

State the greedy, give the exchange argument in two sentences, then a counterexample for each wrong key. Answer = n - kept.

Likely follow-ups
  • Each interval has a weight and you want the max total weight? (Weighted interval scheduling: sort by end, DP with binary search for the last compatible interval, O(n log n).)
  • How is the arrows problem related? (Same greedy; each kept interval's end is an arrow position.)
Meeting Rooms II: give two solutions and compare them.

Heap: sort by start, min-heap of end times, pop if the earliest end is <= the current start, push the current end; answer is the heap size. Sweep: sort starts and ends separately, two pointers, +1 per start, -1 per end that has passed, track the max. Both O(n log n). The sweep has lower constants and no heap; the heap tells you which room each meeting can reuse.

How to answer

Reframe first: "rooms needed = maximum overlap at any time". Then either solution follows. Mention the tie rule (end before start at the same time).

Likely follow-ups
  • Times are integers in a small range? (Difference array over time, O(n + range).)
  • Assign actual room numbers, lowest free first? (Two heaps: free ids and busy (end, id); that is Meeting Rooms III.)
Intersect two lists of sorted, disjoint intervals.

Two pointers. The candidate overlap is [max(a.start, b.start), min(a.end, b.end)]; output it if start <= end. Then advance the pointer whose interval ends first, because it cannot overlap anything later in the other list. O(m + n).

How to answer

Draw the two lists as bars and show why the one that ends first is finished. Point out that equal ends can advance either pointer.

Likely follow-ups
  • k lists instead of 2? (Sweep all endpoints with a counter and output the stretches where the counter equals k.)
  • Lists are not sorted? (Sort each, O(n log n), then the same walk.)
Car Pooling: when would you use a difference array and when a sorted sweep?

Both put +people at the pickup and -people at the drop-off and check the running sum against the capacity. If stop numbers are small (up to 1000 here), an array indexed by stop is O(n + range) and very simple. If coordinates are large or sparse (times in milliseconds, up to 109), sort the 2n events (ends before starts on ties) or use an ordered map: O(n log n), independent of the range.

How to answer

Read the constraints out loud and let them pick: small coordinate range means array, otherwise sort the events. Mention coordinate compression as the middle ground.

Likely follow-ups
  • Also report the busiest segment? (Track the argmax of the running sum.)
  • Updates and queries interleave online? (A Fenwick tree over the difference array gives O(log n) range update and point query.)
Employee Free Time: find the common free gaps of all employees.

Every employee's busy list is sorted. Merge all busy intervals into one sorted list (either flatten and sort, O(N log N), or a k-way merge with a heap of list heads, O(N log k)), merging overlaps as you go. Every gap between consecutive merged blocks is common free time. The open-ended time before the first and after the last block is not counted.

How to answer

Reduce to a known template: "free time of everyone = gaps in the union of busy time". Then pick sort or heap based on k.

Likely follow-ups
  • Find slots where at least m of k people are free? (Sweep endpoints with a busy counter; output where k - busy >= m.)
  • Gaps must be at least d long? (Filter the gaps by length.)
