Merge [[1,4],[2,3],[5,7],[6,8]]. What is the result?

  1. [[1,4],[5,7],[6,8]]
  2. [[1,4],[5,8]]
  3. [[1,3],[5,8]]
  4. [[1,8]]
[2,3] sits inside [1,4], so the end stays max(4,3) = 4. 5 > 4 starts a new block, which [6,8] stretches to 8.

To keep the largest number of non-overlapping intervals, sort by:

  1. it does not matter
  2. length
  3. end time
  4. start time
The earliest end leaves the most room for later intervals (exchange argument). By start and by length both have counterexamples.

In the two-pointer intersection of two sorted interval lists, which pointer moves after each comparison?

  1. Both
  2. The one whose interval ends first
  3. Always the first list's
  4. The one with the smaller start
The interval that ends first cannot overlap anything later in the other list, so it is done.

A closed range update "add v to positions l..r" on a difference array is:

  1. diff[l] += v, diff[r] -= v
  2. diff[l - 1] += v, diff[r] -= v
  3. diff[l] += v, diff[r + 1] -= v
  4. add v to every position from l to r
The change starts at l and stops after r, so the -v goes at r + 1. A prefix sum then rebuilds the values.

In a +1/-1 sweep for meeting rooms with half-open meetings, an end and a start share time t. What order?

  1. Skip both
  2. Either order
  3. Start first
  4. End first
A meeting ending at t frees the room for one starting at t. Processing the start first would count a room that is not needed.
