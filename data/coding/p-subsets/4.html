Approaches: brute -> better -> optimal

Hint 1

For one element there are 2 subsets. If you already have all subsets of the first k elements, how do you get all subsets of the first k + 1?

Hint 2

Write the subsets of 3 elements as 3-bit numbers. What range of integers do they cover?

All three rungs are Θ(n·2n), the size of the output. The ladder here is not about speed: it goes from the most mechanical method to the one that extends best to the follow-up problems (duplicates, size k, a target sum).

1. Brute force - count a bitmask from 0 to 2n - 1

Idea: mask m describes one subset: element b is in when bit b of m is set. Loop over all masks and build each subset by testing n bits.

for m in range(1 << n):
    out.append([nums[b] for b in range(n) if m >> b & 1])
O(n·2n)time
O(n)extra space

What is wasted: nothing in time, but it tests all n bits for every mask (even empty ones), only works while n fits in a machine word, and cannot prune: there is no way to skip a whole branch when a follow-up says "stop when the sum exceeds T". -> rung 2.

2. Better - cascading (doubling the list)

Idea: start with [[]]. For each number x, copy every subset you already have and append x to the copy. After k numbers you hold all 2k subsets of the first k.

out = [[]]
for x in nums:
    out += [s + [x] for s in out]
O(n·2n)time
O(n·2n)space (the output)

What is wasted: it is iterative and short, but all subsets live in memory at once and it also offers no point to prune. -> rung 3.

3. Optimal - backtracking with a start index

def build(start):
    out.append(cur[:])                 # every call is one subset
    for i in range(start, len(nums)):
        cur.append(nums[i]); build(i + 1); cur.pop()
  1. A call = a subset. cur holds the elements chosen so far. Record a copy at the start of every call, so the empty set and all partial sets are output.
  2. Only later elements may join. The loop starts at start and the child call gets i + 1. A subset is always built in index order, so each one has exactly one path.
  3. Choose, recurse, un-choose. Append, recurse, pop: one shared list instead of a new list per call.
  4. The loop is the pruning point. In Combination Sum, Subsets II or Combinations you add one if or break to this loop; the rest stays.
O(n·2n)time
O(n)extra space (recursion + cur)

Why it works: map each subset to its elements sorted by index, i1 < i2 < ... < ik. The recursion reaches it by choosing i1 at the root, then i2 in the next call (allowed because i2 > i1), and so on: so it is produced. Any call path chooses strictly increasing indexes, so that is the only path to it: so it is produced once.

Proof (optional)

The recursion tree has one node per strictly increasing index sequence (including the empty one), and those sequences are in bijection with subsets. There are 2n nodes; each does O(1) work besides copying cur (length ≤ n), so the total is O(n·2n). More exactly, the copies cost Σ|S| = n·2n-1.
