Approaches: brute → better → optimal

Hint 1

Fix the start. As the end moves right, the sum only grows. When can you stop?

Hint 2

If [l..r] is the first window from l that reaches the target, can the best window starting at l+1 end before r?

1. Brute force - every start, extend until it reaches the target

Idea: for each l, add nums[l], nums[l+1], ... and stop at the first r where the sum reaches the target; r - l + 1 is the shortest window starting at l. Take the minimum.

O(n2)time
O(1)space

What is wasted: when we move to l + 1, we restart the sum from scratch and walk past ends that cannot work. -> rung 2 removes the restart, rung 3 removes the walk.

2. Better - prefix sums + binary search (the O(n log n) follow-up)

Idea: build pre[0] = 0, pre[i+1] = pre[i] + nums[i]. Because values are positive, pre is strictly increasing, so it is sorted. For each start l, the shortest window ends at the first index j with pre[j] ≥ pre[l] + target; find j with lower_bound, length j - l.

pre = [0] + list(accumulate(nums))
best = n + 1
for l in range(n):
    j = bisect_left(pre, pre[l] + target)   # first prefix far enough ahead
    if j <= n:
        best = min(best, j - l)
return best % (n + 1)
O(n log n)time
O(n)space

Why it is worth saying: it is the stated follow-up, and it is the version that generalises to "binary search the answer" (does any window of length L reach the target? that test is monotonic in L, so binary search L with a fixed-size window: also O(n log n), O(1) extra space).

3. Optimal - variable sliding window

  1. Grow. Move right one step and add nums[right] to the window sum.
  2. Squeeze while valid. While sum ≥ target: record right - left + 1, drop nums[left], move left.
  3. Never move back. When the loop stops, [left..right] is too small, and so is every shorter window that starts at left, so the next useful step is to grow right.
  4. Sentinel. Start best at n + 1 (impossible length) and return 0 if it never changed.
O(n)time (each index enters and leaves once)
O(1)space

Why it works: let best(l) be the shortest valid window that starts at l, ending at e(l). Because values are positive, e(l) never decreases as l grows: dropping nums[l] lowers the sum, so start l+1 needs an end at least as far right. The window visits every pair (l, e(l)): when right reaches e(l) with left = l, the sum reaches the target and the length is recorded before left moves past l. So the minimum over all recorded lengths is the minimum over all starts. Each pointer moves at most n times, so the nested while loop is still O(n) overall (amortised).
