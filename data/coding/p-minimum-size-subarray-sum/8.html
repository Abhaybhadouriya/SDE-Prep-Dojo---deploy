Common mistakes

Using if instead of while for the shrink. On [1,1,1,10] with target 10, adding 10 makes [1,1,1,10] valid; one shrink records length 4 and stops, but [10] alone (length 1) is the answer. Keep shrinking while the window stays valid.

Recording after the loop. After the while loop the window is too small; record inside the loop, before you drop nums[left].

Returning the sentinel. Forgetting to map n + 1 (or INT_MAX) to 0 fails the "no answer" case.

Using > instead of ≥. The problem says "greater than or equal". The GfG version says strictly greater: read which one you have.

Applying it with negative numbers. If values can be negative (LC 862), dropping an element can increase the sum, and the window misses answers. Say so if the interviewer changes the constraint.
