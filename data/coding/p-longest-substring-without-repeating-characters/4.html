Approaches: brute → better → optimal

Hint 1

If s[l..r] has a repeat, can any window that starts at l and ends after r be valid?

Hint 2

When the new character c repeats, which is the smallest left that makes the window valid again?

1. Brute force - try every start, stop at the first repeat

Idea: for each start i, extend j with a fresh "seen" set until a character repeats; record j - i. (Checking every substring separately for distinctness is O(n³); stopping at the first repeat already makes it O(n · min(n, alphabet)).)

O(n · Σ)time (Σ = alphabet, ≤ 128)
O(Σ)space

What is wasted: after start i fails at j, start i+1 re-reads s[i+1..j-1], which we already know are distinct. → keep the window and only fix its left edge.

2. Better - sliding window with a set

Idea: keep a set of the characters in s[left..right]. When s[right] is already in the set, remove s[left] and move left forward, one step at a time, until it is gone. Then add s[right] and record the length.

O(n)time (each char enters and leaves once: ≤ 2n steps)
O(Σ)space

What is wasted: the inner loop walks left one step at a time. We can jump there directly if we remember where each character was last seen.

3. Optimal - sliding window with last-seen index

for right, ch in enumerate(s):          # core: 4 lines
    if last.get(ch, -1) >= left: left = last[ch] + 1
    last[ch] = right
    best = max(best, right - left + 1)
  1. The window is always valid. After processing right, s[left..right] has no repeated character.
  2. Only a repeat inside the window moves left. If last[ch] >= left, the old copy is in the window, so the smallest valid left edge is last[ch] + 1. If the old copy is before left, it is already gone: do nothing.
  3. left never moves back. The >= left test (or left = max(left, last[ch] + 1)) guarantees it. Without it, "abba" returns 3.
  4. Record every step. The best window ending at right is exactly s[left..right], so best = max(best, right - left + 1).
O(n)time, one pass, O(1) per char
O(Σ)space (an int[256] or a map)

Why it works: for each end right, the valid starts form a range [L(right), right], and L never decreases as right grows (a window that is bad stays bad when you add more on the right). So tracking only the smallest valid start, and moving it forward, sees the best window for every end.

Proof (optional)

Claim: after step right, left = L(right), the smallest index such that s[left..right] is distinct. Induction: s[L(right-1)..right-1] is distinct. Adding c = s[right] creates a repeat only if c occurs in that range, and then only its last occurrence p = last[c] ≥ left matters, so L(right) = p + 1. Otherwise L(right) = L(right-1). The code does exactly this, and the answer is max over right of right - L(right) + 1.
