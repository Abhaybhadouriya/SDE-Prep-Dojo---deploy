Approaches: brute -> better -> optimal

Hint 1

Write the matrix out row after row as one line. What do you see?

Hint 2

Given a position k on that line, which row and column is it?

1. Brute force - scan every cell

Idea: check all m·n values.

O(m·n)time
O(1)space

What is wasted: both sort orders are ignored.

2. Better - staircase from the top-right corner

Idea: start at (0, n - 1). If the value is smaller than the target, the whole row to its left is smaller too: move down. If it is larger, the whole column below is larger: move left. Each step drops a row or a column.

O(m + n)time
O(1)space

What is wasted: it uses only "rows and columns are sorted" and ignores that rows do not overlap, so it misses the required log bound. A two-step search (binary search the first column for the row, then binary search that row) does reach O(log m + log n) = O(log(m·n)), but needs two loops and careful "last row whose first value ≤ target" logic.

3. Optimal - one binary search over the flat index

lo, hi = 0, m * n - 1
while lo <= hi:
    mid = (lo + hi) // 2
    v = matrix[mid // n][mid % n]
    if v == target: return True
    if v < target: lo = mid + 1
    else: hi = mid - 1
return False
  1. The matrix is a sorted array. Row r covers flat indices r·n .. r·n + n - 1, and the row rule makes the last of row r smaller than the first of row r + 1.
  2. Search indices, not values. lo = 0, hi = m·n - 1, the usual closed-interval binary search.
  3. Translate only when reading. row = mid / n, col = mid % n. Divide by the number of columns, n.
  1. Target 34. lo = 0, hi = 11 (m * n - 1).
  2. mid = 5 → (1, 1) = 17 < 34, so the target is to the right: lo = 6.
  3. mid = 8 → (2, 0) = 30 < 34: lo = 9. Rows 0 and 1 are gone without ever picking a row.
  4. mid = 10 → (2, 2) = 41 > 34: hi = 9.
  5. mid = 9 → (2, 1) = 34: return true. 4 probes for 12 cells, about log2(12) + 1.
O(log(m·n))time: at most 14 probes for 104 cells
O(1)space

Why it works: the map k → (k / n, k % n) is the row-major order, and the two given properties say values never decrease along that order. Binary search only needs a sorted sequence with O(1) random access, and this gives both, so its usual invariant holds: if the target exists, its index stays in [lo, hi].
