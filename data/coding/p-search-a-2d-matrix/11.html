Interview follow-ups

What if each row is sorted and each column is sorted, but rows can overlap?

That is LC 240. Flattening no longer gives a sorted order. Start at the top-right corner: smaller than the target, go down (the row is done); larger, go left (the column is done). At most m + n - 1 steps. Starting at the bottom-left works the same way; the top-left and bottom-right do not, because both moves would go the same direction in value.

How to answer

Explain which corner gives "one move increases, the other decreases".

Likely follow-ups
  • Count the cells ≤ x in O(m + n) with the same walk (used by LC 378).
Return the position of the target, or where it would be inserted.

Run a lower-bound search on the flat index: the first k with value(k) >= target. If k < m·n and the value equals the target, return (k / n, k % n); otherwise k is the insert position in reading order.

How to answer

Reuse the flat map with the lower-bound template.

Likely follow-ups
  • Count occurrences when values repeat: upper bound minus lower bound.
The matrix is huge (m·n beyond 32 bits). What changes?

Use 64-bit indices for lo, hi and mid, and compute mid as lo + (hi - lo) / 2. The row/column math is the same. If the matrix does not fit in memory, rows are pages on disk: the flat search still costs O(log(m·n)) page reads; first searching the row minimums (kept in memory) and then one row needs only one page read.

How to answer

Overflow first, then the memory hierarchy: this is how a B-tree index works.

Likely follow-ups
  • Which version has better cache behaviour? (Row-then-column: one row is contiguous.)
Why not binary search the rows first, then the row?

It is also O(log m + log n) = O(log(m·n)), and it is fine. Find the last row whose first value is ≤ target (an upper-bound style search on column 0), then search that row. It is two loops with different templates, so there are more places to get an off-by-one; the flat version is one standard loop.

How to answer

Agree it is correct, then explain the trade-off in code risk.

Likely follow-ups
  • What if the target is smaller than matrix[0][0]? (No row qualifies: return false early.)
Rows are sorted but each row may be rotated (like LC 33).

The flat order is no longer sorted. Search each row with the rotated-array binary search: O(m log n). If the whole flattened array is one rotated sorted array, apply LC 33 directly on the flat index.

How to answer

Ask what exactly is rotated, then pick per-row or flat.

Likely follow-ups
  • With duplicates the worst case becomes linear (LC 81).
