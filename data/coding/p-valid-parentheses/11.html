Interview follow-ups

Only one bracket type: can you do it in O(1) space?

Yes. Keep a balance counter: +1 on (, -1 on ). Fail if it ever goes negative; succeed if it ends at 0. With several types, O(1) space is not possible in general, because you must remember the sequence of open types.

How to answer

Say why the counter is enough for one type (the identity of the top is always the same) and not for several.

Likely follow-ups
  • Minimum additions to make it valid? (LC 921: negatives count + final balance.)
The string also contains letters and digits (a code snippet). What changes?

Skip every character that is not a bracket. In real code you also skip brackets inside string literals and comments, which needs a small state machine in front of the stack.

How to answer

Mention the lexer layer briefly; the stack logic is unchanged.

Likely follow-ups
  • Report the position of the first error (keep indexes on the stack).
Return the index of the first error, or of the unclosed bracket.

Push (closer, index) pairs. On a mismatch, report the current index. At the end, if the stack is not empty, report the index stored at the bottom (the oldest unclosed opener) or the top, whichever the spec wants.

How to answer

Ask which error the user wants; editors usually highlight the unmatched opener.

Likely follow-ups
  • Minimum removals to fix it (LC 1249).
The input is a huge file streamed in chunks.

The stack algorithm is already streaming: keep the stack between chunks. Memory is O(max nesting depth), not O(n). For a single type the state is one integer.

How to answer

Point out that memory is bounded by depth; add a depth limit to protect against hostile input (like JSON parsers do).

Likely follow-ups
  • Check it in parallel? Each chunk reduces to "unmatched closers then unmatched openers"; combine chunks left to right.
Wildcards: '*' can be '(' , ')' or empty. Is the string valid?

That is LC 678. Track the range [lo, hi] of possible open counts: '(' raises both, ')' lowers both, '*' lowers lo and raises hi. Clamp lo at 0, fail if hi < 0, accept if lo == 0 at the end. O(n), O(1).

How to answer

Start with the counter idea, then generalise the single count to a range.

Likely follow-ups
  • Locked positions (LC 2116): two passes, left-to-right and right-to-left.
