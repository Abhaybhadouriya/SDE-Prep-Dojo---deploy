Interview follow-ups

What is the time complexity?

An upper bound is O(9m) for m blanks, since each blank has at most 9 choices; each step is O(1) with masks. The bound is loose: constraints cut most branches, and for a fixed 9x9 board it is technically a constant. Say both, and that real puzzles take thousands of nodes, not billions.

How to answer

State the bound, then explain why pruning makes it irrelevant in practice.

Likely follow-ups
  • What makes a puzzle slow for this solver? (Few givens and early wrong guesses that are refuted only deep down.)
How would you make it faster?

Choose the blank with the fewest legal digits each time (popcount of the free mask); fill forced cells (one legal digit) without branching; stop at once when any blank has zero options. The tree shrinks by orders of magnitude.

How to answer

Name the heuristic ("minimum remaining values") and the propagation step.

Likely follow-ups
  • Cost of picking the best cell? (O(blanks) per level, still worth it.)
Check whether the puzzle has exactly one solution.

Do not stop at the first solution: count solutions and stop when the count reaches 2. Return "unique" if the count is 1, "none" if 0, "many" if 2.

How to answer

Change the return type from bool to a count with an early cut-off.

Likely follow-ups
  • How do puzzle generators use this? (Remove givens one by one while the solution stays unique.)
The input might be invalid (two equal digits in a row). What happens?

With XOR toggles, a duplicate given clears the bit instead of setting it, so the masks become wrong. Validate the givens first (Valid Sudoku, LC 36), or build the masks with OR and reject when a bit is already set.

How to answer

Say that XOR is only safe when every place is matched by exactly one un-place.

Likely follow-ups
  • What should the API return then? (A boolean or an error, instead of void.)
Generalise to an n² x n² board (16x16, 25x25).

The same code with n² digits and boxes of n x n; masks need n² + 1 bits (use 64-bit ints up to 63 digits). Plain backtracking gets slow quickly for 16x16; the most-constrained heuristic becomes necessary.

How to answer

Parameterise the box index as (r / n) * n + c / n.

Likely follow-ups
  • Exact cover (Algorithm X)? (Mention it as the standard heavy-duty method; not expected in code.)
