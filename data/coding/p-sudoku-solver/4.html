Approaches: brute -> better -> optimal

Hint 1

Fill one blank at a time. When should you check the rules: after the board is full, or right after each placement?

Hint 2

Checking a row, a column and a box costs 27 reads. Can you keep the answer to "is digit d in row r?" up to date instead of recomputing it?

1. Brute force - fill everything, then check

Idea: try all 9m ways to fill the m blanks and test each full board.

O(9m · 81)time
O(m)space

What is wasted: a clash in the first two cells is detected only after all the other blanks are filled, billions of times. -> rung 2 rejects it immediately.

2. Better - backtracking with a scan check

Idea: find the first blank; for d = 1..9, if d is not in its row, column or box (a 27-cell scan), place it and recurse; if the recursion fails, reset the cell to '.'. If no digit works, return false.

O(9m)worst case, far less in practice
O(m)recursion depth

This is the most-voted community answer and is accepted. Two costs remain: each check is 27 reads, and each level re-scans the board for the next blank.

3. Optimal for interviews - bitmasks + precomputed blank list

used = row_used[r] | col_used[c] | box_used[(r // 3) * 3 + c // 3]
for d in range(1, 10):
    if used & (1 << d): continue       # clash
    toggle(r, c, d); board[r][c] = str(d)
    if fill(k + 1): return True          # solved: keep the board
    toggle(r, c, d); board[r][c] = "."   # undo
  1. Precompute the masks from the givens (bit d of rowUsed[r] = digit d already in row r) and the list of blanks in scan order.
  2. Level k fills blank k. One OR gives every blocked digit; zero bits are legal.
  3. Place = toggle the three bits with XOR; undo = the same toggle.
  4. Return true all the way up as soon as k reaches the end, so the solved board is never undone.
O(9m)worst-case bound, O(1) per check
O(m)space (27 ints + blank list + depth)

Why it works: the search visits partial boards in depth-first order and only ever extends a board that satisfies all rules so far, so every board it completes is valid. It never skips a valid completion: at each blank it tries every digit not already blocked, and a blocked digit cannot appear in any valid completion of the current partial board. So if a solution exists, the DFS reaches it. The masks are exact because every toggle on the way down has a matching toggle on the way up.

Going further (optional): most-constrained cell first

Instead of the next blank in scan order, pick the blank with the fewest legal digits (count the zero bits with popcount). A blank with exactly one option is forced, and one with zero options fails at once. This "minimum remaining values" heuristic, combined with propagating forced cells, is what the fastest community solvers do (one of them solves most magazine puzzles with no guessing at all). Mention it; code it only if asked. Exact-cover methods (Knuth's Algorithm X / dancing links) are the competitive-programming extreme and out of scope for interviews.
