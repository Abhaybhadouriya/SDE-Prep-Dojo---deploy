Dry run

The same algorithm on the 4x4 mini board 4... / 2..3 / 3.12 / 123. (digits 1-4, 2x2 boxes). Grey = given, blue = placed, orange = the cell just filled, red = dead end or undone choice. The right side shows the recursion: one frame per placed blank. The trace is generated by running the algorithm, not drawn by hand.

  1. Blank (r0, c1): row, column and box allow {1, 3}. Try the smallest, 1. Recurse to the next blank.
  2. Blank (r0, c2): row, column and box allow {2}. The only legal digit is 2: place it. Recurse to the next blank.
  3. Blank (r0, c3) has no legal digit left to try: dead end, return false. The caller undoes its choice (r0, c2) = 2 (clear the cell, clear its bits) and tries its next digit.
  4. Blank (r0, c2) has no legal digit left to try: dead end, return false. The caller undoes its choice (r0, c1) = 1 (clear the cell, clear its bits) and tries its next digit.
  5. Blank (r0, c1): row, column and box allow {1, 3}. 1 already failed here, so try 3. Recurse to the next blank.
  6. Blank (r0, c2): row, column and box allow {2}. The only legal digit is 2: place it. Recurse to the next blank.
  7. Blank (r0, c3): row, column and box allow {1}. The only legal digit is 1: place it. Recurse to the next blank.
  8. Fill the forced cells: (r1, c1) allows only {1}, (r1, c2) only {4}, (r2, c1) only {4}, (r3, c3) only {4}. With the right first guess every remaining blank has exactly one legal digit, so each is placed and the recursion goes straight down.
  9. No blanks left: fill() returns true all the way up and nothing is undone. The board is solved in place after 2 dead ends.
