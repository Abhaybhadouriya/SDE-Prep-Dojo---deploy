Approaches: brute -> better -> optimal

Hint 1

Which two nodes can be the first node of the answer?

Hint 2

A fake node in front of the answer means you never have to special-case the head.

1. Brute force - collect, sort, rebuild

Idea: copy every value into an array, sort it, and build a new list from it.

O((m+n) log(m+n))time
O(m+n)extra space + new nodes

What is wasted: both inputs are already sorted, and the task says to reuse the nodes. Sorting throws the order away and allocating breaks the "splice" rule.

2. Better - recursion

Idea: the smaller front is the head of the answer; its next is the merge of everything else. merge(a, b) = a with a.next = merge(a.next, b) if a.val <= b.val, else the same with b. Base case: if one list is null, return the other.

O(m + n)time
O(m + n)stack depth

What is wasted: one stack frame per output node. Fine for 100 nodes, but on a list of a million nodes it overflows the stack, and interviewers often ask for the iterative form.

3. Optimal - dummy head + tail, splice in place

dummy = tail = ListNode()
while a and b:
    if a.val <= b.val: tail.next, a = a, a.next
    else:              tail.next, b = b, b.next
    tail = tail.next
tail.next = a or b
  1. The merged part ends at tail and is sorted. It starts as just the dummy.
  2. The next node is the smaller front. Each list's front is its minimum, so the smaller front is the global minimum of what is left.
  3. Move one pointer per step. Splice that front after tail, advance its list, move tail.
  4. The leftover is already sorted and not smaller than tail. Attach it with one pointer write; no loop needed.
  1. Start: a dummy node D and tail = D. a points at 2, b points at 1.
  2. 1 < 2: link b's node 1 after tail and move b to 5. tail moves to 1.
  3. 2 < 5: link a's node 2, move a to 5.
  4. Tie 5 vs 5: the <= takes a's 5 first (stable). a moves to 8.
  5. 5 < 8: link b's 5, move b to 9.
  6. 8 < 9: link a's 8. a is now null, so the loop stops.
  7. One list is empty: point tail.next at the rest of b (9 → 10) in one step. Return D.next = 1 → 2 → 5 → 5 → 8 → 9 → 10.
O(m + n)time: each node is linked once
O(1)extra space: dummy + two pointers

Why it works: after every step, the list from dummy.next to tail holds the smallest nodes taken so far in sorted order, and every node still in a or b is at least tail.val. When the loop ends one list is empty, and the other list's nodes are all ≥ tail and sorted, so attaching them keeps the order.

Proof (optional)

Invariant: the merged list is sorted and every remaining node is ≥ its last value. Initially it is empty. In a step, let x be the smaller front. Every remaining node in x's list is ≥ x (sorted) and every node in the other list is ≥ its front ≥ x, so x is the minimum remaining node; appending it keeps the merged list sorted and the remaining nodes are still ≥ x. Each step removes one node, so after m + n - (length of leftover) steps one list is empty, and the leftover satisfies the invariant as a block.
