Revision card

  • Cue: two sorted lists/arrays -> one sorted output; head of the result may change.
  • Insight: the smaller front is the global next; leftover is already sorted, attach it whole.
  • State: dummy, tail, a, b.
  • Trap: move tail every step; attach leftover; return dummy.next; <= keeps it stable.
  • Cost: O(m + n) time, O(1) space; recursion O(m + n) stack.
dummy = tail = Node()
while a and b:
    take = a if a.val <= b.val else b
    tail.next = take; tail = take
    if take is a: a = a.next
    else: b = b.next
tail.next = a or b
return dummy.next

The loop while a and b ends with a = null. What is left to do?

  1. Loop over b and link each node
  2. One write: tail.next = b
  3. Nothing, b is already linked
b's remaining nodes are already a sorted chain, all at least tail.val, so attaching its head attaches all of them.

Why return dummy.next and not dummy?

  1. dummy is freed at the end
  2. dummy.next is always list1
  3. dummy is a placeholder whose value was never in the input
The dummy only exists so the first real node has a predecessor; the answer starts after it.

What is the extra space of the recursive version?

  1. O(m + n) stack frames
  2. O(1), it is tail recursive
  3. O(log(m + n))
Each call does a.next = merge(...) after the call returns, so it is not a tail call; the depth is the output length.
