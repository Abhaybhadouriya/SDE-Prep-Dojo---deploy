Approaches: brute -> better -> optimal

Hint 1

If you already had every permutation of the last n - 1 numbers, how would you get every permutation of all n?

Hint 2

At each step, what is the set of numbers that may go into the next position?

The output has n! rows of length n, so every correct method is at least Θ(n·n!). The ladder is about wasted work and about a template that extends to duplicates (LC 47) and to "k-th permutation" style follow-ups.

1. Brute force - generate all nn sequences, keep the ones with no repeats

Idea: every slot may take any of the n numbers; build all nn sequences, then keep only those where all numbers are distinct.

for seq in itertools.product(nums, repeat=n):
    if len(set(seq)) == n:
        out.append(list(seq))
O(n·nn)time
O(n)extra space

What is wasted: for n = 6, 46,656 sequences are built to keep 720 (1.5%). The check comes too late: a repeat is visible the moment it is placed. -> rung 2.

2. Better - insert the next number into every gap

Idea: start with [[]]. For each number x, take every permutation built so far and insert x into each of its len + 1 gaps. After k numbers you hold all k! permutations of the first k.

perms = [[]]
for x in nums:
    perms = [p[:g] + [x] + p[g:] for p in perms for g in range(len(p) + 1)]
O(n·n!)time
O(n·n!)space (all levels live)

What is wasted: nothing in time, but every intermediate level is materialised, and there is no point where a pruning rule (duplicates, a constraint on neighbours) fits naturally. -> rung 3.

3. Optimal - backtracking over slots with a used[] mask

def build():
    if len(cur) == n: out.append(cur[:]); return
    for i in range(n):
        if used[i]: continue
        used[i] = True; cur.append(nums[i]); build(); cur.pop(); used[i] = False
  1. A call fills one slot. cur is the prefix so far; the call decides position len(cur).
  2. Every unused element is a candidate. The loop starts at 0 each time (not at a start index) because 8 may come after 3 and 3 may come after 8.
  3. Choose, recurse, un-choose. Mark used, append, recurse, pop, unmark. Siblings see the same state.
  4. Record at the leaves only. A permutation is complete when len(cur) == n; copy it (the list keeps changing).
Θ(n·n!)time
O(n)extra space (mask + path + stack)

Why it works: take any permutation p1, p2, ..., pn. At depth 0 the loop tries p1 (unused), at depth 1 p2 (still unused, since all values are distinct), and so on: so it is produced. Two different leaves differ in the first slot where their paths diverge, so no permutation is produced twice.

The in-place swap variant (the top C++ community answer): keep nums[0..k-1] fixed, and for each i ≥ k swap nums[k] with nums[i], recurse on k + 1, swap back. It needs no mask and no separate path list, but the output order is not lexicographic, and the duplicate-skipping rule for LC 47 is harder to get right with swaps. Interviewers accept either; know both.

Proof of the bound (optional)

The number of calls at depth d is n!/(n-d)!, so the total is n!·Σ 1/k! < e·n!. Each call loops over n indexes, and each of the n! leaves copies n numbers: Θ(n·n!) overall. The recursion depth is n, so the extra space is O(n) besides the output.
