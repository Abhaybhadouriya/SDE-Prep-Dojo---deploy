Interview follow-ups

Prove that XOR of the whole array is the single element.

XOR is associative and commutative, so the result does not depend on order. Group each value with its twin: every group is x ^ x = 0, and 0 ^ s = s. Equivalently, every bit column has an even count of 1s from the pairs, plus the lonely value's bit.

How to answer

Name the three properties, then do the regrouping in one line.

Likely follow-ups
  • Does it work for negative numbers? (Yes: XOR acts on the two's-complement bit pattern.)
Every other value appears three times. Find the single one in O(1) space.

For each of the 32 bit positions, count how many numbers have that bit set; the count mod 3 is the single number's bit. In C++/Java rebuild the int with res |= (cnt % 3) << b; bit 31 restores the sign automatically. O(32n) time, O(1) space. The ones/twos bitmask machine does the same in one pass.

How to answer

Generalise the column argument: pairs vanish mod 2, triples vanish mod 3.

Likely follow-ups
  • In Python? (Ints are unbounded: if bit 31 is set, subtract 232.)
Two values appear once, everything else twice. Return both.

XOR all: you get a ^ b, which is non-zero because a != b. Take any set bit, e.g. the lowest: d = x & -x. a and b differ on that bit, so split the array by (num & d): each group is a Single Number problem with pairs intact. XOR each group.

How to answer

Explain why pairs stay in the same group: equal values have the same bit d.

Likely follow-ups
  • x & -x on INT_MIN in Java/C++? (Use unsigned or x & ~(x - 1) carefully; in C++ negating INT_MIN is UB, so cast to unsigned.)
The array is a stream too big for memory. Does the solution still work?

Yes, unchanged: the state is a single integer and the order of arrival does not matter. It also parallelises: XOR the shards independently, then XOR the partial results.

How to answer

Point out that XOR is a monoid (associative with identity 0), which is exactly what map-reduce needs.

Likely follow-ups
  • What if the guarantee "every other value exactly twice" is not trusted? (XOR cannot detect a violation; you need counts.)
Why not sort, or use a set?

Both are correct, but each breaks one bound: the set is O(n) extra space, sorting is O(n log n) time (and mutates the input). The problem explicitly asks for linear time and constant space.

How to answer

Offer the set first if you like, then upgrade when the interviewer restates the space bound.

Likely follow-ups
  • When is the set version better? (When the guarantee is weaker, e.g. counts other than 2.)
