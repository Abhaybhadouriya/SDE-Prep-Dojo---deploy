  • Cue: everything paired except one + O(1) space -> XOR fold.
  • Insight: x^x = 0, x^0 = x, order free; per bit column, pairs add an even count, so the parity is the lonely bit.
  • State: one int acc = 0, XOR every value into it.
  • Trap: answer may be 0 or negative; triples need mod-3 bit counts (LC 137).
  • Cost: O(n) time, O(1) space; hash set O(n) space, sort O(n log n).
acc = 0
for x in nums: acc ^= x
return acc
# two lonely values: d = acc & -acc splits nums into two groups, XOR each

Why does XOR-ing all numbers leave the single one?

  1. XOR sorts the numbers
  2. x ^ x = 0 and x ^ 0 = x, and order does not matter, so every pair cancels
  3. Because the single is the largest
Each bit column holds an even count from pairs plus the single's bit.

What is the XOR fold of [7, 3, 5, 3, 7]?

  1. 3
  2. 5
  3. 7
7 and 3 each appear twice and cancel, leaving 5.

If every other number appeared three times, which idea works?

  1. XOR everything
  2. Count each bit position modulo 3
  3. Sum and divide by 3
That is LC 137; pairs cancel with XOR, triples need mod-3 counting per bit.
