Approaches: brute -> better -> optimal

Hint 1

Which binary operation turns a value and itself into the neutral element?

Hint 2

Look at one bit position across the whole array. How many 1s does it have if you ignore the lonely value?

1. Brute force - count each value by scanning

Idea: for every element, count its occurrences with a second loop; return the one with count 1.

O(n²)time
O(1)space

2. Better - hash map, sorting, or the 2·sum trick

  • Hash map / set: count, or add on first sight and remove on second; what is left is the answer. O(n) time, O(n) space.
  • Sort: after sorting, pairs are adjacent; check nums[i] != nums[i+1] in steps of 2. O(n log n) time, O(1) space if in place.
  • Math: 2 · sum(distinct) - sum(all). O(n) time, but the distinct set costs O(n) space.

What is wasted: each of these meets only one of the two required bounds. -> rung 3 meets both.

3. Optimal - XOR everything

acc = 0
for x in nums:
    acc ^= x       # pairs cancel, order does not matter
return acc
O(n)time
O(1)space

Why it works: because XOR is commutative and associative, the XOR of the whole array equals the XOR of the same numbers in any order. Reorder them so that partners sit together: (a^a) ^ (b^b) ^ ... ^ s = 0 ^ 0 ^ ... ^ s = s. Bit-level view: XOR is addition mod 2 in every bit column independently. Each pair adds 2 ones to a column (even, no effect), so each column's parity is exactly the lonely value's bit.
