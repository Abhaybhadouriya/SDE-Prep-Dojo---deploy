Return only row k using O(k) extra space.

Keep one array of size k + 1 filled with 1s at the end. For each row i from 1 to k, update row[j] += row[j-1] for j from i - 1 down to 1. Going right to left reads the old value of row[j-1] before it is overwritten. O(k²) time, O(k) space. Or use the multiplicative formula for O(k) time.

How to answer

Explain the direction of the inner loop; that is the whole trick (same as 0/1 knapsack).

Likely follow-ups
  • What goes wrong left to right? (row[j-1] is already the new value, so you add the wrong parent.)
Compute a single C(n, r) for n up to 60 without overflow.

Use r = min(r, n - r) and the loop res = res * (n - r + k) / k for k = 1..r in 64-bit. After step k, res equals C(n - r + k, k), an integer, so every division is exact. Multiply before dividing; if the product could overflow, divide by gcd(res, k) first.

How to answer

Say why each partial result is an integer: it is itself a binomial coefficient.

Likely follow-ups
  • Largest n for which all C(n, r) fit in 64 bits? (n = 66 for signed; 67 overflows at the middle.)
Answer many C(n, r) mod 109+7 queries with n up to 106.

Precompute factorials and inverse factorials mod p in O(N): inv_fact[N] = fact[N]^(p-2) by Fermat, then inv_fact[i-1] = inv_fact[i] · i. Each query is fact[n] · inv_fact[r] · inv_fact[n-r] in O(1). A Pascal table would be O(N²) memory, too much here.

How to answer

Pascal table for small n (n <= ~5000), factorials for large n with a prime modulus.

Likely follow-ups
  • Modulus not prime? (Pascal table if small, or Lucas / CRT on prime powers.)
Why is the sum of row i equal to 2i?

Each entry of row i - 1 is added into exactly two entries of row i (below-left and below-right), so the row sum doubles each step, starting from 1. Combinatorially, the sum of C(i, j) over j counts all subsets of an i-element set.

How to answer

Give the doubling argument; it needs no formulas.

Likely follow-ups
  • Alternating sum? (0 for i >= 1: (1 - 1)i.)
