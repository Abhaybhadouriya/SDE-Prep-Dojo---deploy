Approaches: brute -> better -> optimal

Hint 1

To compute row i, which row do you need? Do you need anything older?

Hint 2

Which entries of a row are fixed without looking at the previous row?

1. Brute force - compute each entry as C(i, j) from factorials

Idea: fill entry (i, j) with i! / (j! (i-j)!). Each entry costs O(i) multiplications, so O(numRows³) total, and 29! overflows 64-bit integers, so this only works with big integers.

O(n³)time
overflowrisk

2. Better - one row at a time with C(i, j) = C(i, j-1)·(i-j+1)/j

Idea: generate each row on its own from left to right: start with 1 and multiply by (i - j + 1) / j. The division is always exact if you multiply first. O(1) per entry, no dependency on the previous row, useful when only one row is wanted.

O(n²)time
O(1)extra

Caveat: the intermediate product prev · (i - j + 1) is larger than the result, so use 64-bit arithmetic; for 30 rows it peaks near 1.16·109, over half the signed 32-bit limit; building one more row (row 30) would overflow it.

3. Optimal - sum the two parents

tri = []
for i in range(numRows):
    row = [1] * (i + 1)
    for j in range(1, i):
        row[j] = tri[i-1][j-1] + tri[i-1][j]
    tri.append(row)
return tri
O(n²)time (= output size)
O(1)extra beyond the output

Why it works: this is the rule that defines the triangle, so correctness is direct. It also equals C(i, j) by Pascal's rule: to choose j items out of i, either the last item is chosen (choose j - 1 from the first i - 1) or it is not (choose j from the first i - 1). Only additions, no division, and every intermediate value is a final answer, so no overflow inside the limits. It is optimal because the output itself has n(n+1)/2 numbers.
