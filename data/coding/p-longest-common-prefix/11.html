Interview follow-ups

Why does sorting and comparing only the first and last string work?

In sorted order, if the smallest and largest strings agree on their first L characters, every string between them must start with the same L characters too (otherwise it would sort outside them). And the common prefix of all strings cannot be longer than that of the first and last. So LCP(all) = LCP(min, max).

How to answer

Give the "squeezed between" argument, then the cost O(S log n), and say the vertical scan is faster.

Likely follow-ups
  • Do you need to sort? (No: one pass for the lexicographic min and max is O(S).)
The array is fixed, but many queries ask "LCP of the array plus this new string q". How?

Compute P = LCP(array) once. Each query answer is LCP(P, q), O(|P|) per query, because LCP is associative.

How to answer

Name the associativity; it is the whole trick.

Likely follow-ups
  • Queries on a range strs[l..r]? (A sparse table of LCPs between neighbours after sorting, or a segment tree of prefixes.)
Solve it with a trie. When is that the right choice?

Insert all strings; then walk from the root while the node has exactly one child and is not the end of a word. The walked path is the LCP. Building costs O(S) time and space, so it only pays when the trie is reused (autocomplete, many queries, pairwise questions).

How to answer

Mention the "end of word" check: ["ab","abc"] stops at "ab".

Likely follow-ups
  • Longest prefix shared by at least k strings? (Store a count per trie node; deepest node with count ≥ k.)
The strings are huge files on disk that do not fit in memory.

The vertical scan streams naturally: read the next block of each file in lockstep and compare position by position; stop at the first mismatch or end of file. Memory is one block per file; reads are sequential.

How to answer

Show that the algorithm only ever needs the current column, so it is an external-memory algorithm already.

Likely follow-ups
  • Compare blocks with memcmp? (Yes; find the first differing byte inside the first unequal block.)
What about Unicode strings?

Compare code points (or grapheme clusters if the product needs user-visible characters), not UTF-16 units or bytes, or you can cut a character in half. In Java use codePointAt; in Go range over the string to get runes.

How to answer

Ask what "character" means for the product, then pick the unit.

Likely follow-ups
  • Case-insensitive prefix? (Fold case first; beware languages where folding changes length.)
