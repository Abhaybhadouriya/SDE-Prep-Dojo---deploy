Approaches: brute → better → optimal

Hint 1

The answer is a prefix of strs[0]. So the question is only "how long?"

Hint 2

Check one column at a time across all strings. When must you stop?

1. Brute force - try every prefix of the first string

Idea: for len = |strs[0]| down to 0, check whether strs[0][:len] is a prefix of every string (startsWith). Return the first that works.

O(n·m²)time
O(m)space

What is wasted: each candidate re-checks characters that the longer candidate already compared. -> rung 2.

2. Better - horizontal scan (shrink a running prefix)

Idea: prefix = strs[0]; for each next string, cut prefix down until the string starts with it. Stop early if it becomes empty. Because LCP(a, b, c) = LCP(LCP(a, b), c), the running prefix is always right.

O(S)time
O(m)space

What is wasted: if strs[0] is long and a short mismatch hides at the end of the array, all the earlier strings are compared deeply for nothing. -> rung 3.

3. Optimal - vertical scan (column by column)

for i, c in enumerate(strs[0]):
    for w in strs[1:]:
        if i == len(w) or w[i] != c:
            return strs[0][:i]
return strs[0]
  1. The answer is a prefix of strs[0]. So iterate over its columns.
  2. A column is good only if every string has it and agrees. Check the length first, then the letter; the first failure ends the answer at i.
  3. Never read more than one column past the answer. At most n·(|answer| + 1) character reads: this beats the horizontal scan when strings are long but the prefix is short.
  4. No mismatch at all means strs[0] is the answer.
O(S)time, S ≤ n·(answer + 1)
O(1)extra space

Why it works: a prefix of length L is common to all strings exactly when every column 0..L-1 exists in every string and all letters in that column are equal. The scan tests columns in order, so the first failing column i is the first L for which the condition breaks, and the answer is i. The output string itself is O(answer), which most people do not count as extra space.

The sort trick (good to mention)

Sort the strings. In lexicographic order, the common prefix of the whole array equals the common prefix of the first and the last string, because every string in between is squeezed between them: if the first and last agree on a column, everything in between must too. Cost O(S log n) for the sort, so it is slower than the vertical scan, but it is a neat two-line answer and the top community solutions use it. Our test files use it as the reference.

Divide and conquer / binary search (optional)

Divide and conquer: LCP of the left half and of the right half, then the LCP of those two: O(S) time, O(m log n) stack. Binary search on the length L with a "is strs[0][:L] common?" check: O(S log m). Both appear in editorials; neither beats the vertical scan, so mention them only if asked.
