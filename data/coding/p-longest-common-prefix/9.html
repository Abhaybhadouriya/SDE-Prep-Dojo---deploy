  • Cue: common prefix of all strings -> vertical scan; many queries -> trie.
  • Insight: answer is a prefix of strs[0]; stop at the first column that ends or differs.
  • State: column i, letter c = strs[0][i].
  • Trap: check i == len(w) before w[i]; a later string may be the shortest.
  • Cost: O(S) time, O(1) extra; sort trick O(S log n): compare only min and max.
for i in range(len(first)):
    for w in others:
        if i == len(w) or w[i] != first[i]:
            return first[:i]      # first column that breaks
return first

strs = ["stamp", "stack", "stair"]. Answer?

  1. "stam"
  2. "sta"
  3. "st"
  4. ""
Column 3 has m, c, i: the first mismatch, so the prefix is "sta".

Vertical scan: what must you check before reading w[i]?

  1. w is not empty
  2. i == len(w) (w ended), then stop
  3. w is sorted
  4. nothing
A later string may be shorter than strs[0]; reading past its end is out of bounds in C++.

The sort trick compares only the smallest and largest strings. Why is that enough?

  1. they are the shortest
  2. any prefix shared by the lexicographic min and max is shared by everything between them
  3. it is not enough
  4. sorting removes duplicates
It costs O(S log n) for the sort, so the vertical scan O(S) is still better.
