Approaches: brute → better → optimal

Hint 1

If you remove two different values from the array, is the majority still the majority of what is left?

Hint 2

Keep one candidate and a counter. What should happen to the counter when the next value differs from the candidate?

1. Brute force - count each value

Idea: for each index i, count how many times nums[i] appears; return it once the count exceeds n/2.

O(n²)time
O(1)space

What is wasted: the same value is counted again for every copy of it.

2. Better - hash map, or sort

Hash map: one pass, count[x]++, return x as soon as count[x] > n/2. O(n) time, O(n) space.

Sort: after sorting, the majority covers more than half the array, so it must cover the middle index: return nums[n/2]. O(n log n) time, O(1) extra if sorting in place (it mutates the input). nth_element in C++ makes this O(n) on average.

Bits: for each of the 32 bit positions, the majority's bit is the bit set in more than n/2 values. O(32n), O(1); careful with the sign bit in Java and Python.

O(n) / O(n log n)time (map / sort)
O(n) / O(1)space (map / sort in place)

What is wasted: the map remembers counts for every value, but we only care about one: the current leader.

3. Optimal - Boyer-Moore majority vote

cand, count = 0, 0                          # core: 4 lines
for x in nums:
    if count == 0: cand = x
    count += 1 if x == cand else -1
return cand
  1. count is "unpaired copies of cand". A different value cancels one copy: count--.
  2. count == 0 means the prefix cancelled out. The prefix splits into pairs of different values, so in it no value has more than half. Start fresh with the next value.
  3. The majority survives the reset. Dropping a prefix in which the majority holds at most half leaves it with more than half of the suffix.
  4. At the end, cand is the majority. In the last segment (after the last reset) the candidate never changes and its count stays above 0, so it holds a strict majority of that segment. The true majority also does, and only one value can.
O(n)time, one pass
O(1)space

Why it works: count the majority value m as +1 and every other value as -1. Since m appears more than n/2 times, the total is positive. Each time the counter resets to 0, the prefix we drop has a total of at most 0 for m (it was paired off), so the remaining suffix still has a positive total for m. In the final segment the candidate never changes and ends with count = (its copies) - (all other values) > 0, so it is a strict majority of that segment. m is too, and a segment cannot have two strict majorities, so the candidate is m.

Proof (optional) - the pairing view

The algorithm implicitly builds disjoint pairs (candidate copy, different value). Each pair contains at most one m. If p pairs are formed, at most p copies of m are used, and 2p ≤ n. Since m has more than n/2 copies, more than n/2 - p ≥ 0 copies of m are unpaired. Every unpaired element at the end equals the final candidate (unpaired copies are exactly the final count), so the final candidate is m.
