60-second recall

  • Cue: a string with "skip k" tokens checked against a full string -> two same-direction pointers.
  • Insight: letters must match one-for-one; a number jumps the word pointer without reading.
  • State: i in word, j in abbr; parse the whole number before jumping.
  • Trap: a number starting with '0' is invalid; end test is i == n and j == m; guard overflow.
  • Cost: O(n + m) time, O(1) space.
while i < n and j < m:
    if abbr[j].isdigit():
        if abbr[j] == "0": return False
        k = 0
        while j < m and abbr[j].isdigit(): k = k*10 + int(abbr[j]); j += 1
        i += k
    elif word[i] != abbr[j]: return False
    else: i += 1; j += 1
return i == n and j == m

word = "ab", abbr = "a". Why is the answer false?

  1. 'a' does not match
  2. The abbreviation has a leading zero
  3. The word pointer stops at 1, not at n = 2
Both pointers must reach their ends; "b" is never covered.

Which check rejects both "0" and "05"?

  1. The first digit of a number is '0'
  2. The number is less than 1
  3. The number has more than one digit
Any number whose first digit is '0' is either zero or has a leading zero.

What does "t33l" mean for an 8-letter word?

  1. Two numbers, 3 and 3
  2. One number, 33: too long, so false
  3. Invalid input
Digits next to each other form one number; this is exactly why adjacent replacements are not allowed.
