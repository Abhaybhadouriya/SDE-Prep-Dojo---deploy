Approaches: brute -> better -> optimal

Hint 1

You never need to build the expanded string. What does a number tell you about where you are in word?

Hint 2

Which single character makes a number invalid no matter what follows?

1. Expand and compare

Idea: rebuild a pattern from abbr: each letter stays, each number k becomes k wildcard characters. Then compare the pattern with word position by position. A Most Votes post does this in one line with a regex: turn every number k into .{k} and full-match.

O(n + Σk)time
O(Σk)space for the pattern

What is wasted: a number like "999999999" would build a huge pattern for a 20-letter word, and the regex trick needs a separate check for leading zeros ("01" must be rejected, and a plain \d+ accepts it). -> rung 2.

2. Optimal - two pointers, jump on numbers

while i < n and j < m:
    if abbr[j].isdigit():
        if abbr[j] == "0": return False
        read the number k; i += k
    elif word[i] != abbr[j]: return False
    else: i += 1; j += 1
return i == n and j == m
  1. A letter is a promise about one position. abbr[j] must equal word[i]; then both pointers move by 1.
  2. A number is a jump. Read all its digits (moving j), then add the value to i. The hidden letters are never looked at.
  3. The first digit decides validity. If a number starts with '0', it is either "0" (an empty replaced substring) or has a leading zero. Both are invalid: return false.
  4. Both must end together. If i jumped past n, or one string has leftovers, the loop exits with i != n or j != m: false.
O(n + m)time
O(1)space

Why it works: after each step the invariant holds: "abbr[0..j) is a valid abbreviation of word[0..i)". A letter keeps it only if the letters match; a valid number keeps it by definition. The adjacency rule ("t33l") needs no code: the parser reads "33" as one number, which is exactly how the statement says it must be read. At the end the whole abbreviation must cover the whole word, which is the i == n and j == m test.
