The problem (in our words)

A word can be abbreviated by replacing any number of non-adjacent, non-empty substrings with their lengths. The lengths are written in decimal with no leading zeros.

For the word "terminal": "t6l", "ter2n2" and "8" are valid; "t06l" (leading zero), "t0erminal" (empty substring) and "t33l" (the two replaced substrings would be adjacent) are not.

Given a string word and an abbreviation abbr, return whether abbr is a valid abbreviation of word.

Signature: boolean validWordAbbreviation(String word, String abbr).

Constraints:

  • 1 <= word.length <= 20; word has only lowercase English letters.
  • 1 <= abbr.length <= 10; abbr has lowercase English letters and digits.
  • Every number in abbr fits in a 32-bit integer.

Constraints tell you: the inputs are tiny, so the interviewer is testing correct parsing, not speed. The "fits in 32 bits" line is a hint that a number like "999999999" can be far longer than the word; in C++/Java, stop or use a 64-bit value instead of overflowing when you add it to the index.
