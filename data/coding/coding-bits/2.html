XOR tricks: pairs cancel

Three laws make XOR useful: x ^ x = 0, x ^ 0 = x, and the order does not matter (it is commutative and associative). Put together: if you XOR a bag of numbers, every value that appears an even number of times vanishes. Whatever appears an odd number of times is what is left.

Single Number: one value appears once, all others twice

XOR them all. That is the whole solution: O(n) time, one variable. Watch the accumulator below. It does not need the pairs to be next to each other.

  1. Start with acc = 0. XOR with 0 changes nothing, so 0 is the safe starting value.
  2. acc ^= 6 gives 0110 = 6. A glowing cell is a bit that just flipped.
  3. acc ^= 3 gives 0101 = 5. The 6 is still "inside" acc, mixed with the 3.
  4. acc ^= 5 gives 0000. Not because 5 cancels, but because 6 ^ 3 ^ 5 happens to be 0. The order does not matter.
  5. acc ^= 3 gives 0011 = 3. The second 3 has now met the first 3: that pair is gone for good.
  6. acc ^= 6 gives 0101 = 5. Both pairs are gone; only the lonely 5 is left. One pass, one variable.

The same law solves Missing Number (0..n with one missing): XOR all indices 0..n together with all values; every present number meets itself once, and the missing one is left over. It also gives "which bits differ": a ^ b has a 1 exactly where a and b disagree, so the Hamming distance is popcount(a ^ b).

Single Number III: two values appear once

XOR everything and you get x = a ^ b, not a or b. But x is useful: it is non-zero, and any 1 bit in it marks a place where a and b differ. Take the lowest one, low = x & -x, and split the array in two by that bit. Each group now has exactly one single, so the first trick finishes the job.

Single Number II: others appear three times

XOR fails here: three copies leave one copy behind. Go one level lower and count per bit column. Three copies add 0 or 3 to every column, so count % 3 is the single number's bit in that column.

The column-count version is easy to explain and runs in O(32 n). The famous two-variable version stores the same 32 counters (each 0, 1 or 2) in two words: a bit is in ones after it is seen once, in twos after it is seen twice, and in neither after the third time.

ones = twos = 0
for x in nums:
    ones = (ones ^ x) & ~twos   # add x to "seen once", unless it was already "seen twice"
    twos = (twos ^ x) & ~ones   # add x to "seen twice", unless it just moved to "seen once"
return ones

Interviewers love this: say the column count first, then show ones/twos as the packed form. The column version generalises to "every number appears k times" by changing 3 to k, which is the usual follow-up.
