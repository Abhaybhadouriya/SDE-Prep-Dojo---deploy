How to recognise a bit problem

Cues. "Every element appears twice/three times except" -> XOR or bit counts mod k. "O(1) extra space" on a counting problem with integers -> look at the bits. "Without using + / * /" -> carry or shift loops. "Count of set bits", "power of two", "Hamming" -> n & (n-1) and x ^ y. "n ≤ 20" with subsets, assignments or "visit all" -> bitmask enumeration or dp[mask]. "Lowercase letters only" with set questions -> a 26-bit mask. "Maximise XOR" -> greedy from the top bit with a trie.

When it is not a bit problem: if values can be huge and there is no "appears k times" structure, a hash map is usually the intended answer. Bit tricks are an optimisation of space, not a replacement for a clear algorithm. Say the simple version first.
