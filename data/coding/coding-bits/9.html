Common mistakes

  • Precedence. In C, C++ and JavaScript, == binds tighter than &, so if (n & 1 == 0) means n & (1 == 0), which is always false. Java has the same precedence but rejects the line at compile time (int & boolean). Always write (n & 1) == 0. Go and Python are the exceptions: there & binds tighter than ==.
  • Sign-extending shift. A Java loop while (n != 0) n >>= 1; never ends for a negative n. Use >>>, or loop exactly 32 times.
  • Undefined behaviour in C/C++. 1 << 31 on an int (UB in C), x << 32, -INT_MIN and left-shifting a negative value are all undefined behaviour. Use 1u << i, 1LL << i for i ≥ 31, and unsigned for x & -x.
  • Python's infinite ints. ~5 is -6, not 4294967290. Mask with & 0xFFFFFFFF, and turn values above 0x7FFFFFFF back into negatives at the end.
  • Forgetting n ≤ 0 in power-of-two checks: 0 & -1 == 0 would say yes.
  • Reverse Bits stopping early when n becomes 0. You must shift r exactly 32 times.
