The story: a row of light switches

Explain like I'm 5

Imagine a row of 8 light switches on a wall. Each switch is up (1) or down (0). The whole row, read left to right, is a number. With 8 switches you can make 256 different patterns.

Now play games with the row. "Flip the switch that is on, the same way twice, and it is back where it started." That is XOR. "Turn off the right-most switch that is on." That is n & (n - 1). "Each switch means one friend: up means the friend is coming to the party." Now one number tells you the whole guest list. That is a bitmask.

Bit tricks are just games with switches. Every game here moves a few switches at once, in one step, which is why they are so fast.

From your world

You have done this for years. A status register is a bitmask: if (readl(base + STATUS) & LINK_UP) tests a bit, and a read-modify-write val &= ~MASK; val |= FIELD_PREP(MASK, x); clears a field and sets it. The kernel's helpers are the interview idioms with names: BIT(n) and GENMASK(h, l) (linux/bits.h), hweight32() is popcount, __ffs() finds the lowest set bit, is_power_of_2() is literally n && !(n & (n - 1)), bitrev32() reverses bits, and for_each_set_bit() walks a bitmap. A subnet test (ip & mask) == (net & mask) is a bitmask intersection, and a cpumask is a set of CPUs stored as bits. The interview only asks you to say out loud what these macros do.
