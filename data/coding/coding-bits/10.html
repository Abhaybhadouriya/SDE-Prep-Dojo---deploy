Interview questions

Every number in an array appears twice except one. Find it in O(n) time and O(1) extra space.

XOR all the numbers. XOR is commutative and associative, x ^ x = 0 and x ^ 0 = x, so every pair cancels no matter where its two copies sit, and the single value is left. A hash set also works but costs O(n) space, and sorting costs O(n log n).

How to answer

Say the hash-set answer first (O(n) space), then the XOR answer, then the three XOR laws that make it correct. Mention that it works for negative numbers too, because XOR works on the raw bit pattern.

Likely follow-ups
  • What if one number is missing from 0..n instead? (XOR the indices 0..n with the values: Missing Number.)
  • What if the others appear three times? (Count bits mod 3: Single Number II.)
  • What if two numbers are single? (Split by the lowest set bit of the XOR: Single Number III.)
Every number appears three times except one, which appears once. O(1) space. How?

Look at one bit column at a time. The triples add 0 or 3 ones to every column, so count % 3 in each column is exactly that column's bit in the single number. Doing this for 32 columns is O(32 n). The ones/twos version packs the 32 mod-3 counters into two words: ones = (ones ^ x) & ~twos; twos = (twos ^ x) & ~ones;. Each bit moves 0 -> ones -> twos -> 0 as it is seen 1, 2, 3 times.

How to answer

Explain the per-column count first (anyone can verify it), then show the two-variable state machine as the optimisation. In C or Java build the answer with an int so bit 31 gives back the sign; in Python convert from 32-bit at the end.

Likely follow-ups
  • Generalise to 'every number k times except one'. (Count each column mod k.)
  • Why does the Python per-bit version need care with negatives? (The rebuilt value is unsigned; subtract 2^32 if bit 31 is set.)
Two numbers appear once, all others twice. Return both in O(n) time and O(1) space.

XOR everything to get x = a ^ b, which is non-zero because a and b differ. Take low = x & -x, a bit where they differ. Partition every number by that bit and XOR each group: pairs stay inside one group and cancel, and a, b end up in different groups.

How to answer

Draw the two buckets. Then mention the trap: in C++ -x on INT_MIN is undefined behaviour, so compute low in unsigned (Java and Go wrap safely).

Likely follow-ups
  • Why can any set bit of x be used, not only the lowest? (Any 1 bit is a place where a and b differ.)
  • Three singles? (No clean O(1) trick; interviewers accept a hash set here.)
Count the set bits of a 32-bit number. What are the options and their costs?

(1) Check all 32 bits with n & 1 and n >>= 1 (unsigned shift): 32 steps. (2) Kernighan: n &= n - 1 clears the lowest set bit, so the loop runs popcount(n) times. (3) A 256-entry byte table: 4 lookups. (4) The SWAR formula that adds bits in pairs, nibbles and bytes. (5) The hardware: __builtin_popcount, Integer.bitCount, bits.OnesCount32, int.bit_count().

How to answer

Give Kernighan as the interview answer, explain why n & (n-1) clears exactly one bit, then name the table and the built-in as follow-ups for 'called millions of times'.

Likely follow-ups
  • Popcount of every number 0..n? (bits[i] = bits[i >> 1] + (i & 1), O(n).)
  • Why must the Java loop use >>> and not >>? (>> copies the sign bit, so a negative number never reaches 0.)
Add two integers without using + or -.

a ^ b is the sum of each column without carries. (a & b) << 1 is the carry, moved to the column it belongs to. Repeat with (sum, carry) until the carry is 0. For 32-bit ints this takes at most 32 rounds. Negative numbers work because two's complement addition is the same bit operation.

How to answer

Do 5 + 3 on the whiteboard in 4-bit columns. Then cover each language: C++ must shift as unsigned (left-shifting a negative int is UB before C++20); Python must mask with 0xFFFFFFFF because its ints never overflow, or the loop never ends for negative input.

Likely follow-ups
  • How would you subtract? (a + (~b + 1): add the two's complement.)
  • Is this faster than +? (No. The CPU's adder does this in hardware in one cycle; this is a test of understanding.)
Reverse the bits of a 32-bit unsigned integer. What if the function is called very often?

Loop 32 times: r = (r << 1) | (n & 1); n >>= 1;. For many calls, either precompute a 256-entry table of reversed bytes and combine 4 lookups, or use the divide-and-conquer swap: swap the 16-bit halves, then the bytes, nibbles, pairs and single bits with masks like 0x55555555. That is 5 steps.

How to answer

Write the loop first. Then show the mask idea for one level (((n >> 1) & 0x55555555) | ((n & 0x55555555) << 1) swaps neighbours) and say the other four levels look the same.

Likely follow-ups
  • Java has no unsigned int. Does it matter? (The bit pattern is the same; use >>> and compare bit patterns, not signed values.)
  • Library call? (Integer.reverse, bits.Reverse32, bitrev32 in the Linux kernel.)
Check whether n is a power of two, and then whether it is a power of four.

A power of two has exactly one set bit, so n > 0 && (n & (n - 1)) == 0. A power of four is a power of two whose single bit is at an even position: also check (n & 0x55555555) != 0. Another check is n % 3 == 1, because 4k leaves remainder 1 when divided by 3.

How to answer

Do not forget n <= 0: zero would pass the AND test, and INT_MIN has one set bit but is negative.

Likely follow-ups
  • Round n up to the next power of two? (Smear the top bit right: n-1, then n |= n >> 1, 2, 4, 8, 16, then +1.)
  • Power of three? (No bit trick; divide by 3, or check that 3^19 = 1162261467 divides n.)
When would you use a bitmask instead of a boolean array or a hash set?

When the universe is small and fixed: up to about 20 items for subset enumeration (220 is about a million), 26 letters, 9 digits in Sudoku, the visited set in a bitmask DP such as travelling salesman (dp[mask][last]). A mask is one integer, so it is cheap to copy, hash, compare and use as an array index, and set operations are single instructions: union |, intersection &, difference & ~.

How to answer

Give the size limit (n <= 20 for 2^n work, n <= 64 to fit one machine word) and one concrete use, for example the 26-bit letter mask in Maximum Product of Word Lengths.

Likely follow-ups
  • How do you loop over all submasks of a mask? (for s = m; s; s = (s - 1) & m. Over all masks that is 3^n in total.)
  • What if you need more than 64 items? (An array of words, like std::bitset, java.util.BitSet or the kernel's bitmap API.)
