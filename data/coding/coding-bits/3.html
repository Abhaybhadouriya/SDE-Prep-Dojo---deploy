Counting bits and n & (n - 1)

Subtracting 1 from a number turns its lowest 1 into a 0, and every 0 below it into a 1. The bits above stay the same. So n & (n - 1) is n with its lowest set bit removed. Loop on that and you count set bits in popcount(n) rounds instead of 32. This is called Brian Kernighan's trick.

  1. n = 44 = 101100. Three bits are set. A loop over all 32 bits would run 32 times; this one will run 3 times.
  2. n - 1 = 101011: the lowest 1 (bit 2) became 0 and the zeros below it became 1 (highlighted row). AND with n keeps only the untouched high part: 101000 = 40. count = 1.
  3. Again: 40 - 1 = 100111, 40 & 39 = 100000 = 32. Bit 3 is gone. count = 2.
  4. 32 - 1 = 011111, 32 & 31 = 0. The last set bit is gone. count = 3. (This step is also the power-of-two test: one step to zero means one set bit.)
  5. n == 0, the loop stops. popcount(44) = 3, after 3 iterations, not 32.
  • Power of two: exactly one bit is set, so n > 0 && (n & (n - 1)) == 0.
  • Counting Bits for 0..n: i >> 1 is i without its last bit, so bits[i] = bits[i >> 1] + (i & 1). Another form is bits[i] = bits[i & (i - 1)] + 1. Both are O(n) with no inner loop.
  • Reverse Bits: take bits off the bottom of n and push them into the bottom of r: r = (r << 1) | (n & 1); n >>= 1, 32 times. Push in exactly 32 bits, even after n becomes 0, or the result is shifted wrong.
  • Lowest set bit position: __builtin_ctz (C++, undefined for 0), Integer.numberOfTrailingZeros, bits.TrailingZeros, (x & -x).bit_length() - 1 in Python.
