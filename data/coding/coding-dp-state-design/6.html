How many dimensions? Adding, dropping, and checking

Add a dimension when the photo is missing a fact

The test for a correct state is: if two different histories lead to the same state value, do they really have the same best future? If not, the state is missing something. Typical missing facts are a remaining budget (knapsack capacity, k transactions left), the previous choice (last colour, last index in LIS), a parity or modulus (sum mod 3), or whose turn it is (game DP). Add the fact as a coordinate and check again.

Drop a dimension when it is implied by the others

Interleaving String, restated: given strings s1, s2 (each up to 100 characters) and s3 (up to 200), decide whether s3 can be formed by merging s1 and s2 while keeping the order of characters within each. The obvious state is (i, j, k): positions in all three strings. But every character of s3 used so far came from s1 or s2, so k is always i + j. The state is just (i, j), and the table is 101 x 101 instead of 101 x 101 x 201.

// DROPPED dimension: (i, j, k) with k = i + j, so the state is just (i, j).
func isInterleave(s1, s2, s3 string) bool {
	n, m := len(s1), len(s2)
	if n+m != len(s3) {
		return false
	}
	ok := make([][]bool, n+1) // ok[i][j]: s1[:i] + s2[:j] make s3[:i+j]
	for i := range ok {
		ok[i] = make([]bool, m+1)
	}
	ok[0][0] = true
	for i := 0; i <= n; i++ {
		for j := 0; j <= m; j++ {
			if i > 0 && s1[i-1] == s3[i+j-1] && ok[i-1][j] {
				ok[i][j] = true
			}
			if j > 0 && s2[j-1] == s3[i+j-1] && ok[i][j-1] {
				ok[i][j] = true
			}
		}
	}
	return ok[n][m]
}
// DROPPED dimension: (i, j, k) with k = i + j, so the state is just (i, j).
bool isInterleave(const string& s1, const string& s2, const string& s3) {
    int n = s1.size(), m = s2.size();
    if (n + m != (int)s3.size()) return false;
    vector<vector<char>> ok(n + 1, vector<char>(m + 1, 0));     // ok[i][j]: s1[0..i) + s2[0..j) make s3[0..i+j)
    ok[0][0] = 1;
    for (int i = 0; i <= n; i++)
        for (int j = 0; j <= m; j++) {
            if (i && s1[i - 1] == s3[i + j - 1] && ok[i - 1][j]) ok[i][j] = 1;
            if (j && s2[j - 1] == s3[i + j - 1] && ok[i][j - 1]) ok[i][j] = 1;
        }
    return ok[n][m];
}

# DROPPED dimension: (i, j, k) with k = i + j, so the state is just (i, j).
def is_interleave(s1, s2, s3):
    n, m = len(s1), len(s2)
    if n + m != len(s3):
        return False
    ok = [[False] * (m + 1) for _ in range(n + 1)]   # ok[i][j]: s1[:i] + s2[:j] make s3[:i+j]
    ok[0][0] = True
    for i in range(n + 1):
        for j in range(m + 1):
            if i and s1[i - 1] == s3[i + j - 1] and ok[i - 1][j]:
                ok[i][j] = True
            if j and s2[j - 1] == s3[i + j - 1] and ok[i][j - 1]:
                ok[i][j] = True
    return ok[n][m]

The same "one coordinate is a function of the others" appears in Cherry Pickup (two walkers moving together: the step number fixes r1 + c1 = r2 + c2, so one coordinate goes) and in many grid problems where "steps taken" equals row + column.

Choose the state that makes transitions cheap

Two valid states can have very different transition costs. For LIS, "dp[i] = longest increasing subsequence ending at i" needs O(n) work per state (look back at every j < i), O(n2) total. Changing the state to "tails[len] = the smallest last value of any increasing subsequence of length len" makes each step a binary search, O(n log n). For Word Break, the state is a prefix; the transition tries every dictionary word or every end position, whichever is smaller. When the time limit looks too tight for states x work, the fix is usually a different state, not micro-optimisation.
