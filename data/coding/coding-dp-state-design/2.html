From brute force to memo: read the state off the parameters

The most reliable way to find a state is not to think about tables at all. Write the plain recursive search first, keep its parameters as small as possible, and then notice that the parameters are the state.

The problem (Solving Questions With Brainpower, restated). An exam has n questions that must be considered in order. Question i is worth points[i]. If you answer it you earn the points, but it tires you out: you must then skip the next skip[i] questions. You may also pass on any question for free and move to the next one. Return the largest total you can score. (LeetCode gives the input as pairs [points, brainpower], with 1 ≤ n ≤ 105 and both values between 1 and 105, so the total needs 64 bits. Our small examples also use skip 0, which the code handles.)

Brute force: at question i there are two choices. Answer it, and continue from question i + 1 + skip[i]. Pass, and continue from i + 1. The only thing the rest of the exam depends on is which question you are at. Not the points so far (we add those on the way back up), not which questions you answered. So the function needs one parameter, and best(i) = "most points from question i to the end" is the state.

Example: four questions worth (5, skip 1), (2, skip 2), (6, skip 1), (3, skip 0). The recursion tree already repeats work at this size:

With n = 105 the tree is exponential, yet there are only n + 1 different calls. Cache each one and the cost becomes n states x 2 choices = O(n). Because best(i) only ever calls larger indices, the table version fills from the right:

  1. The state is a suffix: best[i] = most points from question i to the end. The memo calls best(i+1) and best(i+1+skip), both larger indices, so the table fills right to left.
  2. Base case: one cell past the last question is worth 0. Any jump that overshoots is clamped to this cell.
  3. Question 3 (+3, skip 0): solving it gives 3 + best[4] = 3, skipping gives 0. The two orange cells are the only inputs read.
  4. Question 2 (+6, skip 1): solving jumps to the end, 6 + 0 = 6, which beats skipping (best[3] = 3).
  5. Question 1 (+2, skip 2): solving gives only 2 + best[4] = 2; skipping keeps best[2] = 6. Greedy "solve whatever is next" would lose here.
  6. Question 0 (+5, skip 1): 5 + best[2] = 11 beats best[1] = 6.
  7. The answer is best[0] = 11. Each cell was filled once from two reads: O(n) time, where the plain recursion was exponential.
// Step 1 (brute force -> memo): best(i) = most points from questions i..n-1 (a SUFFIX state).
// Choices at i: solve it (gain points, jump past the skipped ones) or skip it (move to i+1).
func mostPointsMemo(q [][]int) int64 {
	n := len(q)
	memo := make([]int64, n)
	for i := range memo {
		memo[i] = -1
	}
	var best func(i int) int64
	best = func(i int) int64 {
		if i >= n { // base: no questions left
			return 0
		}
		if memo[i] != -1 {
			return memo[i]
		}
		memo[i] = max(int64(q[i][0])+best(i+1+q[i][1]), // solve i
			best(i+1)) // skip i
		return memo[i]
	}
	return best(0)
}

// Step 2 (memo -> table): the memo fills from the end, so loop i from n-1 down to 0.
func mostPoints(q [][]int) int64 {
	n := len(q)
	best := make([]int64, n+1) // best[n] = 0
	for i := n - 1; i >= 0; i-- {
		best[i] = max(int64(q[i][0])+best[min(n, i+1+q[i][1])], best[i+1])
	}
	return best[0]
}

long long mostPointsMemo(const vector<vector<int>>& q) {
    int n = q.size();
    vector<long long> memo(n, -1);
    function<long long(int)> best = [&](int i) -> long long {
        if (i >= n) return 0;                                    // base: no questions left
        if (memo[i] != -1) return memo[i];
        return memo[i] = max(q[i][0] + best(i + 1 + q[i][1]),    // solve i
                             best(i + 1));                       // skip i
    };
    return best(0);
}

// Step 2 (memo -> table): the memo fills from the end, so loop i from n-1 down to 0.
long long mostPoints(const vector<vector<int>>& q) {

        best[i] = max(q[i][0] + best[min(n, i + 1 + q[i][1])], best[i + 1]);
    return best[0];
}
// Step 1 (brute force -> memo): best(i) = most points from questions i..n-1 (a SUFFIX state).
// Choices at i: solve it (gain points, jump past the skipped ones) or skip it (move to i+1).
static long mostPointsMemo(int[][] q, int i, long[] memo) {
    if (i >= q.length) return 0;                                 // base: no questions left
    if (memo[i] != -1) return memo[i];
    return memo[i] = Math.max(q[i][0] + mostPointsMemo(q, i + 1 + q[i][1], memo),   // solve i
                              mostPointsMemo(q, i + 1, memo));                     // skip i
}

def most_points_memo(questions):
    n = len(questions)

    @lru_cache(maxsize=None)
    def best(i):
        if i >= n:                                   # base: no questions left
            return 0
        pts, skip = questions[i]
        return max(pts + best(i + 1 + skip),         # solve i
                   best(i + 1))                      # skip i
    return best(0)

# Step 2 (memo -> table): the memo fills from the end, so loop i from n-1 down to 0.
def most_points(questions):
    n = len(questions)
    best = [0] * (n + 1)                             # best[n] = 0
    for i in range(n - 1, -1, -1):
        pts, skip = questions[i]
        best[i] = max(pts + best[min(n, i + 1 + skip)], best[i + 1])
    return best[0]

Notice three things that generalise. The memo version is the recursion plus two lines. The table loop runs in the reverse of the direction the recursion calls (calls go to bigger i, so fill smaller i last). And a jump past the end is clamped to the base cell n, so there is no special case.

Shrinking the parameters

A first-draft recursion often carries too much: the list of chosen items, the remaining array as a slice, the running total. Turn each into the smallest equivalent:

  • The remaining array becomes an index (nums[i:] is just i).
  • The running total usually moves out of the parameters: return "best from here" and add on the way up. Keep it only when the future really depends on it (a budget, a target that is still to be hit).
  • A set of used items becomes a bitmask when n ≤ 20, or a single count if only "how many" matters.
  • The last item chosen becomes its index (LIS: "previous index"), or a small mode (which colour, holding or not).

When every parameter is an integer in a small range, multiply the ranges: that product is the number of states, and it tells you immediately whether the DP fits in time.
