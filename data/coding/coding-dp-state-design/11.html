Interview questions

How do you come up with the DP state for a problem you have never seen?

I write the brute-force recursion first, in one sentence ("at index i I either take it and jump, or skip it"). Its parameters are a candidate state. I shrink each parameter to a small integer (an index instead of a sub-array, a mask instead of a set) and drop anything the future does not depend on, like the running score. Then I check the state with one question: do two different histories that reach the same state have the same best future? If yes, I can memoise; if no, I add the missing fact as another coordinate. Finally I count states times work per state against the constraints.

How to answer

Describe the process (brute force, shrink parameters, the "same future" test, cost check) and demonstrate it on a small problem the interviewer names.

Likely follow-ups
  • What if the brute force needs the whole set of used items? (Bitmask when n ≤ 20; otherwise look for a property, such as sorted order, that replaces the set with an index.)
Your memoised solution is correct but times out. What do you check?

First the count: number of reachable states times the work per state. If that product is too big, the state is too large (often a running total that should not be there) or the transition is too expensive (an inner loop that a prefix sum, a binary search or a better state would remove). Second, the constant factors: a hash-map memo keyed on tuples is far slower than an array; Python recursion is slow and may hit the depth limit, so go bottom-up. Third, make sure the memo actually hits: a key that includes something which changes every call (a list, a total) means nothing is reused.

How to answer

Asymptotic first (states x work), then the memo key, then the constant factor.

Likely follow-ups
  • Give an example of changing the state to cut the transition cost. (LIS: from "ending at i", O(n2), to "smallest tail of each length", O(n log n).)
Why does the LCS state use prefixes, and what are the base cases?

Because the only decision is about the last characters of the two current prefixes: if they are equal they can be matched together, otherwise at least one of them is not in the answer. Each choice leaves two shorter prefixes, so (i, j) closes over itself. Row 0 and column 0 represent an empty prefix and are 0; including them in the table removes every boundary check. The answer is lcs[n][m], O(nm) time, and the space drops to one row plus a saved diagonal because each cell reads only up, left and up-left.

How to answer

State sentence, the last-character case split, base row, answer cell, cost, then the space trick.

Likely follow-ups
  • Print the subsequence, not just its length. (Keep the full table and walk back from (n, m): on a match take the character and go diagonal, otherwise move toward the larger neighbour.)
  • Shortest common supersequence? (Length n + m - LCS; build it from the same walk-back.)
In Burst Balloons, why do we choose the balloon burst last, not first?

If balloon k is burst first in a range, its score depends on its current neighbours, but afterwards the left and right parts become adjacent and interact, so the two sides are not independent subproblems. If k is burst last in the open range (l, r), then every other balloon in it is already gone when k bursts, so its neighbours are exactly l and r, and its score is nums[l] x nums[k] x nums[r]. The left part (l, k) and right part (k, r) are independent, because k separates them until the end. State: best[l][r] for the open interval, transitions over k, O(n3) with n ≤ 300.

How to answer

Show why "first" breaks independence, then show that "last" fixes the neighbours. Name the general rule: pick the decision whose consequences the state fully describes.

Likely follow-ups
  • Which other problems use the same idea? (Minimum Cost to Cut a Stick, matrix-chain multiplication, Minimum Score Triangulation of a Polygon.)
Walk me through the stock-with-cooldown states. Why can you not buy from "sold"?

At the end of a day you are in one of three modes: holding a share, just sold today, or resting with no share. hold = max(hold, rest - price): keep it or buy today, and buying is only allowed from rest, because a sale yesterday forces today to be a cooldown. sold = hold + price. rest = max(rest, sold): stay idle, or yesterday's sale finished its cooldown. Before day 0, hold is minus infinity (you cannot own a share yet) and the others are 0. The answer is max(sold, rest) at the end; you never end holding. O(n) time, O(1) space.

How to answer

Draw the three-node machine first, then write one line per node. Interviewers check the initial values.

Likely follow-ups
  • At most k transactions? (Add the count to the mode: hold[j], free[j] for j transactions used, O(nk).)
  • A fee per transaction? (Subtract it on sell; the cooldown mode disappears.)
Interleaving String: the state looks like three indices. Can you do better?

Yes. If i characters of s1 and j of s2 have been used, exactly i + j characters of s3 have been produced, so k = i + j is not free; the state is (i, j). ok[i][j] is true when s1[:i] and s2[:j] can interleave into s3[:i+j]: it comes from ok[i-1][j] when s1[i-1] matches s3[i+j-1], or from ok[i][j-1] when s2[j-1] does. First reject when the lengths do not add up. That gives O(nm) time and, with one rolling row, O(m) space.

How to answer

Point out the dependency (k = i + j), then state the reduced recurrence and the length check.

Likely follow-ups
  • Why does greedy (take from s1 whenever it matches) fail? (When both s1 and s2 can supply the next character, the wrong pick can dead-end later; the DP tries both.)
Dungeon Game: why does a forward DP fail and a backward one work?

A knight walks right or down from the top-left to the bottom-right; cells add or remove health, and health must stay at least 1. A forward state like "best health on arrival at (r, c)" is not enough, because two paths with different current health and different minimum-so-far cannot be compared with one number: one may be higher now but have dipped lower earlier. Going backward, need[r][c] = the minimum health required when entering (r, c) to survive the rest; it depends only on the future: need = max(1, min(need of right, need of down) - cell). One number per cell is now a complete state, and need[0][0] is the answer.

How to answer

Show the two-path counterexample for the forward state, then define the backward state and its recurrence.

Likely follow-ups
  • Could you binary search the starting health instead? (Yes: for a fixed start, a forward max-health DP checks survival; O(RC log range). Correct, but the backward DP is cleaner.)
Top-down memo or bottom-up table when you design a new state?

I design top-down, because the recursion is the definition of the state and the base cases are the recursion's stopping conditions, so there is less room for an off-by-one. It also visits only reachable states, which matters when the state includes a value like a remaining sum. Once it is correct, I convert to bottom-up when n is large (recursion depth), when the interviewer wants O(1) or O(row) space, or when the language makes recursion slow. The fill order is the reverse of the call direction.

How to answer

Give a default and the reasons to switch; mention recursion depth and space compression.

Likely follow-ups
  • How do you find the fill order of an unusual state? (Draw which states each state calls; any topological order of that graph works. If the graph has cycles, it is not a DP as defined.)
