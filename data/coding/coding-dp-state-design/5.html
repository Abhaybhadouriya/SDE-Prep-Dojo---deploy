An index plus a mode: state machines

Sometimes the position alone is not the whole photo, because a rule depends on what you did just before: "no two adjacent", "wait a day after selling", "at most k transactions", "you are holding a share". Add a small extra coordinate, a mode, that records exactly that fact.

The problem (Best Time to Buy and Sell Stock with Cooldown, restated). You get a list of daily prices (up to 5,000 days). You may buy and sell as many times as you like, but you can hold at most one share, and the day after you sell you may not buy. Return the maximum profit. For prices 1, 2, 3, 0, 2 the answer is 3: buy at 1, sell at 2, rest a day, buy at 0, sell at 2.

At the end of each day you are in exactly one of three modes, and each mode allows different moves tomorrow:

  • hold = best profit if you own a share tonight: kept it from yesterday, or bought today from rest (not from sold, that is the cooldown).
  • sold = best profit if you sold today: yesterday's hold + price.
  • rest = best profit if you own nothing and did not sell today: yesterday's rest or yesterday's sold.

The full state is (day, mode), 3n states, but each day reads only the previous day, so three variables are enough. Initialise hold to minus infinity: before day 0 you cannot own anything, and a large negative stops the code from pretending you can.

// INDEX + MODE state (state machine): after each day you are holding, just sold, or resting.
func maxProfitCooldown(prices []int) int {
	hold, sold, rest := math.MinInt64/2, 0, 0 // before day 0: cannot hold yet
	for _, p := range prices {
		hold, sold, rest = max(hold, rest-p), hold+p, max(rest, sold)
	}
	return max(sold, rest)
}
// INDEX + MODE state (state machine): after each day you are holding, just sold, or resting.
int maxProfitCooldown(const vector<int>& prices) {
    long long hold = LLONG_MIN / 2, sold = 0, rest = 0;          // before day 0: cannot hold yet
    for (int p : prices) {
        long long h = max(hold, rest - p), s = hold + p, r = max(rest, sold);
        hold = h; sold = s; rest = r;
    }
    return (int)max(sold, rest);
}

static int maxProfitCooldown(int[] prices) {

def max_profit_cooldown(prices):
    hold, sold, rest = float('-inf'), 0, 0           # before day 0: cannot hold yet
    for p in prices:
        hold, sold, rest = max(hold, rest - p), hold + p, max(rest, sold)
    return max(sold, rest)

Once you see it, the whole stock series is one template with different modes: a transaction fee subtracts on sell (LC 714), "at most k transactions" adds a counter to the mode (LC 188). House robber is the same idea with modes "robbed the last house" / "did not". Paint House has a mode "colour of the last house".

From your world

This is the TCP state machine with a payoff attached. sold followed by a forced rest is a one-day TIME_WAIT: a transition that blocks the next "open" for a while. The DP just runs every possible path through the machine at once and keeps, for each state, the best value that can be in it today. If you have written a packet parser as an explicit FSM, you already think this way.
