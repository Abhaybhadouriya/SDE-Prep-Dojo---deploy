The five questions

Write the answers to these down, literally, before writing code. In an interview, say them out loud; it is the clearest signal that you know what you are doing.

QuestionWhat you writeExample (house robber)
1. StateOne exact sentence: "dp[...] = the best/number/whether ... for ..."best[i] = most money from houses i..n-1
2. ChoicesThe options for the next (or last) decision, and which smaller state each leads torob i (go to i+2) or skip i (go to i+1)
3. Base casesStates you can answer without choosing anythingbest[i] = 0 for i ≥ n
4. AnswerWhich state is the original questionbest[0]
5. Order and costA fill order where every input is ready; states x work per statei from n-1 down to 0; O(n)

A good state sentence has three parts: what is measured (max money, number of ways, true/false), over which part of the input (a prefix, a suffix, a slice, two prefixes), and under which extra condition (with k left, while holding a share, ending exactly at i). If you cannot say all three, the state is not designed yet.

Prefix or suffix? Both work for most linear problems. A suffix state ("from i to the end") falls out of a recursion that starts at index 0 and moves forward, so it is the natural first draft. A prefix state ("using the first i items") is the usual bottom-up form. Pick whichever makes the choices read most naturally; the complexity is the same.
