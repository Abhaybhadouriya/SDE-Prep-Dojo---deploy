A slice of one input: the interval state

Some problems on one sequence cannot be cut into "prefix plus last item", because the decision at one end interacts with the other end: palindromes, bursting or merging neighbours, cutting a stick, matrix-chain order. The state is a slice (l, r).

The problem (Longest Palindromic Subsequence, restated). Given a lowercase string of up to 1,000 characters, return the length of its longest subsequence that reads the same forwards and backwards. For "bbbab" it is 4 ("bbbb"); for "cbbd" it is 2.

  • State: pal[l][r] = the answer for the slice s[l..r].
  • Choices, by looking at both ends: if s[l] == s[r], they wrap the best inner palindrome: pal[l+1][r-1] + 2. Otherwise at least one end is unused: max(pal[l+1][r], pal[l][r-1]).
  • Base: pal[l][l] = 1; an empty slice (l > r) is 0.
  • Order: every input is a shorter slice. Either loop over lengths 1..n, or run l from n-1 down to 0 with r going up from l. Both guarantee row l+1 is finished before row l.

The table for "bbbab". Only the upper triangle is meaningful, and the answer sits in the top-right corner, not the bottom-right as in the pair-index case:

// INTERVAL state: pal[l][r] = longest palindromic subsequence inside s[l..r]. l descending.
func longestPalindromeSubseq(s string) int {
	n := len(s)
	if n == 0 {
		return 0
	}
	pal := make([][]int, n)
	for i := range pal {
		pal[i] = make([]int, n)
	}
	for l := n - 1; l >= 0; l-- {
		pal[l][l] = 1
		for r := l + 1; r < n; r++ {
			if s[l] == s[r] {
				pal[l][r] = pal[l+1][r-1] + 2
			} else {
				pal[l][r] = max(pal[l+1][r], pal[l][r-1])
			}
		}
	}
	return pal[0][n-1]
}

int longestPalindromeSubseq(const string& s) {
    int n = s.size();
    if (n == 0) return 0;
    vector<vector<int>> pal(n, vector<int>(n, 0));
    for (int l = n - 1; l >= 0; l--) {
        pal[l][l] = 1;
        for (int r = l + 1; r < n; r++)
            pal[l][r] = s[l] == s[r] ? pal[l + 1][r - 1] + 2 : max(pal[l + 1][r], pal[l][r - 1]);
    }
    return pal[0][n - 1];
}

# INTERVAL state: pal[l][r] = longest palindromic subsequence inside s[l..r]. Fill by length.
def longest_palindrome_subseq(s):
    n = len(s)
    pal = [[0] * n for _ in range(n)]
    for l in range(n - 1, -1, -1):                   # l descending so pal[l+1][*] is ready
        pal[l][l] = 1
        for r in range(l + 1, n):
            if s[l] == s[r]:
                pal[l][r] = pal[l + 1][r - 1] + 2
            else:
                pal[l][r] = max(pal[l + 1][r], pal[l][r - 1])
    return pal[0][n - 1] if n else 0

The harder interval problems have a third index: a split point k inside the slice, tried in O(n) per state, giving O(n3). Burst Balloons is the classic: the trick is to let k be the balloon burst last in (l, r), because then its neighbours at that moment are known to be l-1 and r+1. Choosing "first" instead leaves the neighbours unknown and the state breaks. That is a state design lesson in itself: pick the decision whose consequences are fully described by the state.

LPS has a shortcut: it equals LCS(s, reverse(s)). It is a good sanity check, but the interval form is the one that generalises to Palindromic Substrings, Minimum Insertion Steps to Make a String Palindrome (n - LPS) and the split-point family.
