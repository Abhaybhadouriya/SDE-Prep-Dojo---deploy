Common mistakes

  • A state sentence without a condition. "dp[i] = LIS of the first i elements" cannot be extended, because you do not know the last value. "LIS ending at i" can. When a transition needs a fact the state does not hold, the sentence is wrong, not the code.
  • Keeping the running total as a parameter when the future does not depend on it. It multiplies the state space by the range of the total and usually kills the memo hit rate.
  • A state that misses a fact, so two histories collide: forgetting the cooldown, the last colour, or whose turn it is. The code runs and gives a plausible wrong answer. Use the photo test.
  • Wrong fill order. Fill in the reverse of the direction the recursion calls. Interval tables need l descending or length ascending; plain row-major order reads cells that are not computed yet.
  • The prefix versus suffix trap. Some problems work only one way round. In Dungeon Game the health you need at a cell depends on the cells after it, so a forward (prefix) state cannot express the constraint and the backward (suffix) state can.
  • Identity values: using 0 as "impossible" in a max-DP that can go negative, or INT_MIN that overflows when you add to it. Use a sentinel like -1018 or math.MinInt64/2.
  • Off-by-one between dp index and string index. With prefix states, dp[i] talks about s[i-1]. Decide once and comment it.
  • Python recursion depth on n = 105: lru_cache recursion hits the limit. Convert to a loop (you have the order already).
  • Compressing too early. Get the full table right first, on paper if needed; then keep only the rows it reads. Reconstructing the actual choices needs the full table anyway.
