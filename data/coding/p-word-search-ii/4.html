Approaches: brute -> better -> optimal

Hint 1

Many words start with the same letters. How can one board walk test all of them at the same time?

Hint 2

If the path so far spells "cx" and no word starts with "cx", what should the DFS do?

1. Brute force - Word Search I once per word

Idea: for each word, try every cell as a start and run the classic DFS (match letter, mark, recurse into 4 neighbours, unmark). Add the word if any start succeeds.

O(W·m·n·4·3L-1)time, W words of length L
O(L)recursion stack

What is wasted: words that share a prefix redo the same walks, and a hopeless start cell is rediscovered once per word. With W = 3 * 104 this times out.

2. Better - trie + DFS, keep words in a set

Idea: insert all words into a trie (each node has up to 26 children and an end-of-word marker). DFS from every cell carrying the current trie node: step only to a neighbour whose letter is a child of the node. When you reach a node that ends a word, add the word to a result set (it can be traced from several places).

O(m·n·4·3L-1)time, independent of W
O(total letters)trie memory

What is wasted: after "care" has been found, every later walk along c-a-r-e still goes through those nodes and finds the same word again. Paths into fully-found branches cost time and the set hides the duplicates.

3. Optimal - trie + DFS with one-shot words and branch pruning

def dfs(r, c, parent):
    ch = board[r][c]; node = parent.kids.get(ch)
    if node is None: return                      # no word goes this way
    if node.word: found.append(node.word); node.word = None   # report once
    board[r][c] = "#"                            # on the path
    for nr, nc in neighbours(r, c): dfs(nr, nc, node)
    board[r][c] = ch                             # backtrack
    if not node.kids and node.word is None: del parent.kids[ch]  # prune
  1. Store the word itself on its end node. No string building during the DFS; when you land on an end node, the answer is right there.
  2. Clear it once reported. Setting node.word = None means a second path to "care" adds nothing, so no result set is needed.
  3. Mark the board cell, not a visited array. Writing '#' into the cell and restoring it afterwards is O(1) memory, and '#' is never a trie key, so it also blocks reuse.
  4. Prune on the way back. If the child has no children and no word left, delete it from its parent. Branches shrink as words are found, and once every word is found the trie is empty and every DFS stops after one lookup.
  1. Start at (0,0) = c. The root has a child c, so we step into the trie and mark the cell #.
  2. Neighbours are tried down, up, right, left. Down is o, and c → o exists (cord, code).
  3. Down to d, then right to e: the trie node for c-o-d-e stores a word. Report code, clear the word, and since that node has no children, delete it on the way back (then d's node, now empty, too).
  4. Back on o, try right: r, and c-o-r exists. But r's neighbours are a, e, e and the used o: no child d. Dead end, so cord is not on the board (d is only diagonal to r).
  5. Back on c, try right: a, then down to r. The c-a-r node stores car: report it and keep going, because a longer word can still continue here.
  6. From r go down to e: care. The e node is now empty and is deleted; so is the r node (no word, no children).
  7. Back on a, try right: t gives cat. Now the whole c-a branch is empty and is cut off. Only c-o-r-d is left under c.
  8. Cell (0,1) = a starts nothing (the root has no child a). Start (0,2) = t: down e, down n gives ten; that branch is deleted too.
  9. (1,0) = o starts nothing. Start (1,1) = r: r-e-n works via (2,1) and (2,2), but n's free neighbour is the other e, not t. rent fails. The other cells start nothing. Answer: [code, car, care, cat, ten] (any order).
O(m·n·4·3L-1)worst case; pruning makes typical runs far faster
O(total letters)trie; O(L) stack, L ≤ 10

Why it works: a board path spells a string; it can only be the start of a word if that string is a path from the trie root. The DFS keeps "current trie node = node for the string spelled so far" as its invariant, so it explores exactly the board paths that are prefixes of some word, and it reports a word exactly when the spelled string ends on a word node. Pruning only removes nodes with no word in their subtree, so no unfound word is ever lost.

Where does 4·3L-1 come from? (optional proof)

From the start cell there are at most 4 directions; after that the cell you came from is marked, so at most 3 new directions per letter. A path of L letters therefore has at most 4·3L-1 continuations, and there are m·n start cells. The trie cuts this hard in practice, because a path dies at the first letter that no word continues with.
