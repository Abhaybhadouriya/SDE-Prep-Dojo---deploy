Revision card

  • Cue: many words on one grid; per-word Word Search is W times too slow.
  • Insight: trie of words, and DFS carries (cell, trie node) together.
  • State: mark cell '#', recurse 4 ways, restore; word stored on its end node.
  • Trap: do not return on a found word; clear it to avoid duplicates; prune empty children.
  • Cost: O(m·n·4·3^(L-1)) worst case, O(total letters) memory.
def dfs(r, c, parent):
    ch = board[r][c]; node = parent.kids.get(ch)
    if not node: return
    if node.word: out.append(node.word); node.word = None
    board[r][c] = "#"
    for nr, nc in nbrs(r, c): dfs(nr, nc, node)
    board[r][c] = ch
    if not node.kids and not node.word: del parent.kids[ch]

Why is a trie better than running Word Search I for each word?

  1. It uses less memory than the word list
  2. Words that share a prefix share one board walk
  3. It removes the need for backtracking
One DFS checks every word on the current trie path at once.

When can a trie node be deleted during the search?

  1. As soon as its word is found
  2. When the DFS leaves it
  3. When it has no children and no unreported word
Only then is there nothing left to find below it.

What does writing '#' into the cell do?

  1. Stops the same cell being reused in one word, with no visited array
  2. Marks a found word
  3. Ends the whole search
'#' is never a trie child, so a path cannot step onto it; it is restored on the way back.
