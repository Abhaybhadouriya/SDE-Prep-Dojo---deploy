Do it without the "bottom-up" ordering trick.

Use two booleans: row0Zero and col0Zero, computed first by scanning row 0 and column 0. Mark into row 0 / column 0 using cells with i, j ≥ 1, apply to the inner cells (i, j ≥ 1) in any order, then zero row 0 and column 0 if their flags say so. Same O(1) space, easier to explain.

How to answer

Say that row 0 and column 0 are handled last, explicitly, so order inside the inner block does not matter.

Likely follow-ups
  • Which version reads each cell fewer times? (Both are two passes; the two-flag version adds one scan of row 0 and column 0.)
The matrix is sparse: k zeros in a huge m × n grid.

Store the set of zero rows and zero columns (O(k) space) and report the result lazily: get(i, j) returns 0 if i or j is in the sets, else the original value. Writing the full result is still Θ(m·n) if someone needs it materialised.

How to answer

Separate "compute the answer" from "materialise it"; the sets are the answer.

Likely follow-ups
  • What if zeros arrive as a stream of updates? (Keep the sets; each update is O(1).)
Zeros should spread recursively: a newly zeroed cell also zeroes its row and column.

Then the closure is easy: one zero at (i, j) zeroes all of row i, so every column now holds a zero; those columns zero every row. If the grid has at least one zero, the answer is the all-zero grid; otherwise it is unchanged. One O(m·n) scan decides it. Say this out loud: the "only original zeros spread" rule is what makes the problem non-trivial.

How to answer

Reason about the closure: one zero zeroes its row, which hits every column, which hits every row.

Likely follow-ups
  • What if spreading only goes to the 4 neighbours? (Multi-source BFS, like Rotting Oranges.)
The grid is too big for memory and is stored row by row in a file.

Pass 1 streams the rows and collects the zero-column set (at most n bits) and, per row, whether it had a zero (write that to a second file or keep m bits). Pass 2 streams again and writes each output row: all zeros if its row bit is set, else zero only the marked columns. Two sequential passes, O(m + n) bits of memory.

How to answer

The O(m + n) array version is the right one for streaming; the in-place trick needs random access.

Likely follow-ups
  • Can it be one pass? (Not for row-major order: a zero in the last row changes the first row's output.)
Parallelise it.

Pass 1 is a reduction: each thread scans a block of rows and builds local row/column bitsets, then OR them together. Pass 2 is embarrassingly parallel: each thread writes its block of rows using the shared read-only bitsets. The in-place marker trick is a bad fit because threads would race on row 0.

How to answer

Name the two phases as map-reduce and keep shared state read-only in the second phase.

Likely follow-ups
  • Memory per thread? (n bits for the column set plus its rows' bits.)
