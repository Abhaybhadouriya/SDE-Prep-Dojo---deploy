Revision card

  • Cue: in-place grid update that depends on the ORIGINAL values; O(1) extra space asked.
  • Insight: row 0 = column flags, column 0 = row flags; one extra bool for column 0.
  • State: col0Zero; marks [i][0] and [0][j]; inner loops start at j = 1.
  • Trap: zeroing while scanning; [0][0] doing double duty; applying top-down.
  • Cost: O(m·n) time, O(1) space; arrays version O(m + n); copy O(m·n).
# phase 1: record decisions from the original state, in space you will overwrite anyway
for cell in grid: if trigger(cell): mark(head_of_row(cell)); mark(head_of_col(cell))
# phase 2: apply, visiting the marker cells LAST
for cell in reversed(grid): if marked(row) or marked(col): apply(cell)

Why is the second pass bottom-up?

  1. It is faster on large grids
  2. Column 0 must be rewritten first
  3. Row 0 holds the column marks, so it must be rewritten after all other rows have read them
Rewriting row 0 early would erase the column flags.

What does the extra boolean col0Zero store?

  1. Whether column 0 contained an original zero
  2. Whether row 0 contained an original zero
  3. Whether the grid has any zero
Cell [0][0] already speaks for row 0, so column 0 needs its own flag.

Why not mark future zeros with -1?

  1. -1 is slower to compare
  2. Any int, including -1, can be real data here
  3. The judge forbids negative numbers
Values span the whole 32-bit range, so no value is free to act as a sentinel.
