Rolling hash (Rabin-Karp)

Turn every window of length m into a number, then compare numbers instead of strings. A polynomial hash reads the window as digits in base B, modulo a large prime M:

h(c0 c1 ... cm-1) = c0·Bm-1 + c1·Bm-2 + ... + cm-1 (mod M)

Sliding one step costs O(1): subtract the leaving character times Bm-1, multiply by B, add the new character.

// rabinKarp: rolling hash; every hash hit is confirmed with a real compare.
func rabinKarp(text, pat string) []int {
	const MOD, B = 1_000_000_007, 131
	res := []int{}
	n, m := len(text), len(pat)
	if m == 0 || m > n {
		return res
	}
	var hp, ht, pw int64 = 0, 0, 1
	for i := 0; i < m; i++ {
		hp = (hp*B + int64(pat[i])) % MOD
		ht = (ht*B + int64(text[i])) % MOD
		if i > 0 {
			pw = pw * B % MOD
		}
	}
	for i := 0; ; i++ {
		if ht == hp && text[i:i+m] == pat {
			res = append(res, i)
		}
		if i+m == n {
			break
		}
		ht = (ht - int64(text[i])*pw%MOD + MOD) % MOD
		ht = (ht*B + int64(text[i+m])) % MOD
	}
	return res
}
// Rabin-Karp: rolling hash of every window of length m, confirm each hash hit with a real compare.
vector<int> rabinKarp(const string& text, const string& pat) {
    const long long MOD = 1000000007LL, B = 131;
    vector<int> res;
    int n = text.size(), m = pat.size();
    if (m == 0 || m > n) return res;
    long long hp = 0, ht = 0, pw = 1;             // pw = B^(m-1)
    for (int i = 0; i < m; i++) {
        hp = (hp * B + (unsigned char)pat[i]) % MOD;
        ht = (ht * B + (unsigned char)text[i]) % MOD;
        if (i) pw = pw * B % MOD;
    }
    for (int i = 0;; i++) {
        if (ht == hp && text.compare(i, m, pat) == 0) res.push_back(i);
        if (i + m == n) break;
        ht = (ht - (unsigned char)text[i] * pw % MOD + MOD) % MOD;   // drop the leaving char
        ht = (ht * B + (unsigned char)text[i + m]) % MOD;            // add the entering char
    }
    return res;
}
// Rabin-Karp with a real compare on every hash hit.
static List<Integer> rabinKarp(String text, String pat) {
    final long MOD = 1_000_000_007L, B = 131;
    List<Integer> res = new ArrayList<>();
    int n = text.length(), m = pat.length();
    if (m == 0 || m > n) return res;
    long hp = 0, ht = 0, pw = 1;
    for (int i = 0; i < m; i++) {
        hp = (hp * B + pat.charAt(i)) % MOD;
        ht = (ht * B + text.charAt(i)) % MOD;
        if (i > 0) pw = pw * B % MOD;
    }
    for (int i = 0; ; i++) {
        if (ht == hp && text.regionMatches(i, pat, 0, m)) res.add(i);
        if (i + m == n) break;
        ht = (ht - text.charAt(i) * pw % MOD + MOD) % MOD;
        ht = (ht * B + text.charAt(i + m)) % MOD;
    }
    return res;
}
def rabin_karp(text: str, pat: str) -> list[int]:
    """Rolling hash; every hash hit is confirmed with a real compare."""
    MOD, B = 1_000_000_007, 131
    n, m = len(text), len(pat)
    if m == 0 or m > n:
        return []
    hp = ht = 0
    for i in range(m):
        hp = (hp * B + ord(pat[i])) % MOD
        ht = (ht * B + ord(text[i])) % MOD
    pw = pow(B, m - 1, MOD)
    res = []
    for i in range(n - m + 1):
        if ht == hp and text[i:i + m] == pat:
            res.append(i)
        if i + m < n:
            ht = ((ht - ord(text[i]) * pw) * B + ord(text[i + m])) % MOD
    return res

Collisions: the part an SDE-3 must get right

Equal strings always have equal hashes; equal hashes only probably mean equal strings. How you use the hash decides what a collision costs:

  • Search with verification (the template above): on every hash hit, compare the window for real. A collision then costs time, never a wrong answer. Expected O(n + m); worst case O(n · m) if an adversary forces many hits.
  • Hash used as identity (put hashes in a set, compare hashes between strings): a collision gives a wrong answer. Estimate the risk with the birthday bound: with k hashed windows and modulus M, the expected number of colliding pairs is about k2 / (2M).

The fixes, in the order to mention them: (1) verify every hit when you can afford it; (2) use two moduli (109+7 and 109+9) and combine them into one 64-bit key, or one 61-bit Mersenne modulus 261-1 with 128-bit multiply; (3) pick the base at random at start-up, so no fixed test input can be crafted against it. Never use the "free" modulus 264 (unsigned overflow) on its own: the Thue-Morse string makes it collide for any base, a known anti-hash construction.

From your world

This is the same reasoning as choosing a flow-table hash: jhash with a random seed (get_random_bytes at boot) so remote senders cannot aim packets at one bucket, and a full tuple compare after the bucket lookup, because the hash only narrows the search. Rabin-Karp with verification is exactly "hash to a bucket, then memcmp".
