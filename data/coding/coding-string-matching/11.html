Common mistakes

  1. Off by one in the fall-back. It is k = pi[k-1], not pi[k]: pi is indexed by the last character of the matched prefix, which is k - 1.
  2. Forgetting to fall back after a full match. Leaving k = m makes the next access pat[m] read out of bounds (in C, a silent bug). Set k = pi[m-1] to keep finding overlapping matches.
  3. Missing the separator in pi-of-concatenation tricks. In shortest palindrome, without # the border of "aa" + "aa" is 3, longer than s. Use a character that cannot appear in the input.
  4. Negative values in the rolling update. (h - c * pw) % M is negative in C++, Java and Go when h is small. Add M before the final remainder. Python's % is always non-negative.
  5. Overflow in the multiply. With M around 109, h * B fits in 64 bits only if B is small; h1 * h2 of two residues near 109 needs 64 bits (and 261-1 needs 128-bit multiply). In Java, an int product overflows silently: use long.
  6. Trusting a single hash as identity. Fine for "verify on hit" search, wrong for distinct counts and duplicate detection at n = 104 and up. Use two moduli and say why with the birthday bound.
  7. Using a fixed, known base on a judge with anti-hash tests. Randomise the base at start-up.
  8. Treating KMP as the default. For "is p in s" with small inputs, the library call is the right first answer. Bring KMP when the follow-up asks for linear time or a stream.
