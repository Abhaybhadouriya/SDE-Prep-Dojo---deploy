Interview questions

Explain the prefix function and prove that KMP runs in O(n + m).

pi[i] is the length of the longest proper prefix of pat[0..i] that is also its suffix. When a mismatch happens after k matched characters, the next candidate alignment that can still succeed keeps exactly the longest border of the matched part, so k becomes pi[k-1]; borders of borders give the further candidates. The text index never moves back. Proof of linearity: k increases by at most 1 per text character, so at most n in total; each fall-back strictly decreases k, and k never goes below 0, so there are at most n fall-backs. Building pi is the same argument over the pattern, O(m).

How to answer

Start from the naive method and point at the re-read characters. Draw pi for a small pattern with a fall-back (abacabab is a good one). Then write the three-line loop and give the potential argument in one sentence.

Likely follow-ups
  • Find all matches, overlapping ones included (fall back to pi[m-1] after a match).
  • Why not just compute pi of pat + "#" + text? (Works; needs O(n + m) memory and a safe separator.)
  • How does Aho-Corasick generalise it? (Failure links on a trie of many patterns.)
Shortest palindrome by adding characters only in front. Can you beat O(n2)?

The answer is reverse(s[P..]) + s where P is the length of the longest palindromic prefix. The brute force checks every prefix from longest to shortest: O(n2), which times out at n = 5·104. Linear: compute pi of t = s + "#" + reverse(s). pi[last] is the longest prefix of s that equals a suffix of reverse(s), which is exactly a palindromic prefix. The separator stops the border from crossing into reverse(s).

How to answer

State the reduction first ("everything hinges on the longest palindromic prefix"), then show the brute force cost, then the concatenation trick on "aacecaaa". Mention that a rolling hash comparing forward and backward hashes of each prefix also works in O(n) expected.

Likely follow-ups
  • Why is the separator needed? (Without it, for "aaaa" the border would be 7 > n.)
  • Adding characters at the end instead? (Mirror: longest palindromic suffix, pi of reverse(s) + "#" + s.)
  • Adding anywhere? (Different problem: n - longest palindromic subsequence, DP.)
Repeated string match: why is the answer always q or q + 1 or -1?

Any occurrence of b in a repeated a starts at some offset o in [0, |a|) inside a copy of a. Covering o + |b| characters needs ceil((o + |b|) / |a|) copies, which is q = ceil(|b| / |a|) for o = 0 and at most q + 1 for any o < |a|. Adding more copies only adds identical, periodic text, so if b is not inside q + 1 copies it is nowhere. Two searches, each O(|a| · q + |b|) with KMP.

How to answer

Give the offset argument with a small picture, then code it with the library find, then offer KMP or Rabin-Karp if asked for a worst-case bound.

Likely follow-ups
  • Avoid building the repeated string (index the text as a[i % |a|] inside KMP).
  • Quick reject: every character of b must appear in a.
Rabin-Karp: what happens on a collision, how likely is it, and how do you defend against it?

In search, a collision is a false hash hit; verifying the window with a real compare makes it cost O(m) time and never a wrong answer. When hashes stand in for strings (sets, duplicate detection), a collision is a wrong answer. Birthday bound: k hashes modulo M collide in about k2 / (2M) pairs. With M about 109 and 3·104 windows that is about 0.45, too high. Defences: two independent moduli (about 1018 combined) or 261-1; a random base chosen at runtime; verification when affordable. Avoid 264 wrap-around alone: Thue-Morse strings break it for every base.

How to answer

Split the two uses (search versus identity) in your first sentence; that shows you understand where the risk is. Then give the number from the birthday bound. That is the SDE-3 signal.

Likely follow-ups
  • Worst-case input for verification (many true or false hits: "aaaa...a" with pattern "aa...a" gives O(n · m) compares; KMP does not suffer).
  • How would you choose B and M? (B random in [256, M-1], M prime, products fit in 64 bits.)
Longest duplicate substring in a string of length 3·104.

Binary search the length L: if some substring of length L occurs twice, so does its prefix of length L - 1, so "a duplicate of length L exists" is monotone. For each L, slide a rolling hash and look for a repeated value in a hash map from hash to start index; on a hit, verify with a compare (or use a double hash). O(n log n) expected time, O(n) space. A suffix array with LCP gives the exact O(n log n) answer as a follow-up.

How to answer

Say the monotonic property out loud, because it justifies the binary search. Then write the check(L) helper with the rolling hash, and mention collisions before the interviewer does.

Likely follow-ups
  • n <= 2,000 version (LC 1062): DP on lcp[i][j] = lcp[i+1][j+1] + 1, O(n2).
  • Return every duplicate of maximum length.
Count the distinct substrings of a string. Walk me from brute force to the best you know.

Brute force: a set of all substrings, O(n3). Better: insert all suffixes into a trie and count nodes, O(n2) time and memory. Or, for each length, a set of rolling hashes, O(n2) expected time and O(n) memory, with two moduli so collisions do not undercount. Best known: n(n+1)/2 minus the sum of the LCP array of the suffix array, O(n log n), or the number of paths in a suffix automaton, O(n).

How to answer

Code the hash or trie version; name the suffix structures and the formula, and say you would not write them from scratch in 45 minutes. That honest boundary is what SDE-3 interviewers want to hear.

Likely follow-ups
  • Distinct substrings of one length only (one hash pass).
  • Distinct substrings that are of the form aa (LC 1316, Distinct echo substrings: hash both halves).
Is a string made by repeating one of its substrings? Prove your O(n) check.

Let b = pi[n-1] and p = n - b. A border of length b means s[i] = s[i + p] for all valid i, so p is a period, and it is the smallest period because b is the longest border. s is a whole number of copies of its first p characters exactly when b > 0 and n % p == 0. Equivalent one-liner: s occurs in (s + s)[1 : 2n - 1].

How to answer

Give the doubling one-liner first (easy to remember), then the pi version as the linear, deterministic proof. Test "abab" (true), "aba" (false), "aaaa" (true).

Likely follow-ups
  • Return the smallest repeating block (s[0 : p] when the check passes, else s).
  • How many characters to append to make it periodic? (p - n % p when n % p != 0.)
The text arrives as a stream of chunks (packets). Find every occurrence of a pattern, including ones that cross chunk boundaries.

KMP is the natural fit: its entire state between characters is the integer k (plus the pattern and pi, built once). Process each chunk with the search loop and carry k across chunks; a match that straddles two chunks is found with no buffering. Report positions as a global offset = bytes seen before this chunk + local index. Memory O(m), time O(total bytes + m), worst case, not just expected. A rolling hash also streams but needs the last m - 1 bytes kept for verification and the leaving character.

How to answer

Name the state you carry between chunks; that is the key point. Mention that the kernel's textsearch API and xt_string work exactly this way, with a per-search state passed in for each fragment of a non-linear skb.

Likely follow-ups
  • Many patterns (Aho-Corasick: one state = one trie node).
  • Case-insensitive (fold both pattern and input; build pi on the folded pattern).
  • Thread safety: each stream needs its own k; pi can be shared read-only.
