Building the prefix function in O(m)

Go left to right. Keep k = the longest border of the prefix you just finished. To extend it by the next character s[i]:

  1. Try to extend. If s[i] == s[k], the border grows: k++.
  2. Otherwise fall back. While k > 0 and s[i] != s[k], set k = pi[k-1] (the next shorter border) and try again.
  3. Store. pi[i] = k.
  1. Build pi for abacabab. Start: pi[0] = 0 and k = 0.
  2. i = 1: 'b' != s[0], k stays 0, so pi[1] = 0. i = 2: 'a' == s[0], so the border grows to 1: pi[2] = 1.
  3. i = 3: we try to extend the border a with 'c', but s[1] is 'b'. Fall back to k = pi[0] = 0; 'c' != 'a' too, so pi[3] = 0.
  4. i = 4, 5, 6: a, b, a each match s[k], so k climbs 1, 2, 3. The prefix aba now equals the suffix ending at 6.
  5. i = 7: 'b' != s[3] = 'c', so the border aba cannot grow. Jump to its own border: k = pi[2] = 1. Now s[1] = 'b' matches, so pi[7] = 2 (border ab). No letter was compared from scratch.
  6. Done. Why linear: k goes up by at most 1 per character (n increases in total), and every fall-back lowers it by at least 1, so there are at most n fall-backs over the whole run. O(m) time, O(m) space.

Interviewers love this. The amortised argument in the last step is the answer to "isn't the inner while loop O(m2)?". Say it in one sentence: "k rises at most once per character and every iteration of the while loop lowers it, so the total work is O(m)." It is the same potential argument as for a dynamic array or a monotonic stack.
