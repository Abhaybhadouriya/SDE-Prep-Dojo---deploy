Approaches: brute → better → optimal

Hint 1

A single "current min" variable breaks on pop. What would you need to know to restore the previous min?

Hint 2

The minimum of a stack only depends on the elements below the top. So it is fixed at the moment an element is pushed, and nothing above can change it.

1. Brute force - scan on getMin

Idea: keep a plain array. push, pop, top are O(1); getMin scans all n elements.

O(n)getMin
O(1)other ops
O(n)space

What is wasted: the min of the bottom k elements is recomputed on every call, even though it cannot change while those k elements stay. -> save it once.

2. Better - a second stack of minimums

Idea: keep a main stack and a min stack. Push val onto the min stack only when val <= minStack.top(); on pop, pop the min stack too only when the popped value equals its top. getMin = min stack top.

O(1)all ops
O(n)space, often less

Why it is good: when values are pushed in increasing order, the min stack stays tiny. Trap: the comparison on push must be <=, not <, or a duplicate minimum is popped too early (example 2).

3. Optimal (simplest to get right) - store (value, min so far) in each entry

def push(self, val):
    low = val if not self.st else min(val, self.st[-1][1])
    self.st.append((val, low))        # getMin = st[-1][1], pop = st.pop()
  1. An entry's min is fixed at push time. The min of the stack with that entry on top depends only on the entries below, and those cannot change while it is there.
  2. So save it in the entry. low = min(val, low of the entry below), one comparison.
  3. Pop needs no repair. After a pop, the new top's low was correct when it was pushed and is still correct now.
  4. No arithmetic on values. We only compare, so the full 32-bit range is safe.
O(1)all ops
O(n)space (2 ints per entry)

Why it works: a stack only changes at the top. Whatever is below the top is exactly the stack as it was when the top was pushed, so the answer stored with the top is the answer now. This is the whole proof.

Proof (optional)

Invariant: for every index i, st[i].low = min(st[0].val .. st[i].val). Push keeps it: the new entry gets min(val, st[i-1].low), which by the invariant is the min of all values up to it. Pop removes the last entry and does not touch the others, so their invariant holds. Hence st[top].low is the min of the whole stack.

4. Alternative - one stack of differences (O(1) extra space)

Idea: keep one variable min and push val - min (as a 64-bit value). A negative stored value means "this push lowered the min"; on pop, restore min = min - stored. It saves the second field but needs 64-bit storage and careful sign logic; mention it as the follow-up answer to "can you use only one extra variable?".
