Recognise the pattern

When you see "design a stack/queue that also answers X in O(1)", think augment each element with the answer for the structure as it was when that element was added. Works for any answer that only depends on the elements below (min, max, gcd). It does not work for a queue directly, because a queue removes from the bottom; there you combine two such stacks.

Try the naive "one variable" idea on tiny inputs and see where it breaks:

OperationsReal minOne variable mWorks?
push 3, push 533✓
push 3, push 111✓

The failing rows show the fix: the old minimum must be saved somewhere when a new one arrives.
