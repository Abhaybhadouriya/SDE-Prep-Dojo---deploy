  • Cue: "stack plus O(1) min/max" -> augment each entry with the answer below it.
  • Insight: a stack changes only at the top, so an entry's min is fixed at push time.
  • State: stack of (value, minSoFar); top = st[-1][0], getMin = st[-1][1].
  • Trap: two-stack version: push to min stack on <= (duplicates); Integer == in Java.
  • Cost: O(1) every op, O(n) space; scan version O(n) getMin.
st = []
def push(x):
    agg = x if not st else combine(x, st[-1][1])   # min, max, gcd ...
    st.append((x, agg))
def pop():   st.pop()
def query(): return st[-1][1]

Pair stack: push 5, push 3, push 7, pop. What is getMin?

  1. 7
  2. 5
  3. 3
  4. undefined
Entries are (5,5), (3,3), (7,3). Popping (7,3) leaves (3,3) on top.

Two-stack version: push to the min stack on < or on <=?

  1. <
  2. <=, so a duplicate minimum survives one pop
  3. either
  4. always push
push 2, push 2, pop: with < the min stack loses its only 2 on the first pop although a 2 remains.

Java two-stack version compares minStack.peek() == stack.peek() on Integer objects. Why is that a bug?

  1. it is not
  2. == compares references; values outside -128..127 are different objects
  3. peek returns int
  4. it throws
Use .equals() or unbox to int first.
