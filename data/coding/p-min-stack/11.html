Interview follow-ups

Use only O(1) extra space beyond the stack of values.

Store differences: keep min; push val - min as a 64-bit value and update min if val is smaller. On pop, a negative stored value means that push lowered the min, so restore min = min - stored. top is min if stored < 0, else stored + min.

How to answer

Explain the sign as a one-bit flag ("this entry changed the min"), then point out the overflow and why the stored type is 64-bit.

Likely follow-ups
  • Encode instead as 2*val - min (the GfG / TUF version): same idea, same overflow concern.
Now make it a queue with O(1) getMin.

Build the queue from two min stacks (in-stack and out-stack). Push to the in-stack; when the out-stack is empty, move everything over. getMin = min of both tops. Amortised O(1). Or use a monotonic deque of candidates (the Sliding Window Maximum structure).

How to answer

Say why the pair trick alone fails (a queue removes from the bottom), then compose it.

Likely follow-ups
  • Worst case per operation? (O(n) for one transfer; amortised O(1).)
Support getMin and getMax together.

Store a triple (value, minSoFar, maxSoFar). Any aggregate that combines with the element below (min, max, gcd, sum) fits the same slot.

How to answer

Name the property: the aggregate must be computable from (new value, aggregate below).

Likely follow-ups
  • Median? (No: it does not combine that way; you need two heaps or an order-statistics tree.)
Make it thread-safe for many producers and consumers.

Simplest correct answer: one mutex around each operation, since the value and its min must change together. A lock-free Treiber stack with a CAS on the head pointer also works, because each node is immutable after push and carries its own min (like the linked-list version), so a reader of the head sees a consistent (value, min) pair.

How to answer

Point out that the pair-per-node design makes the CAS version easy: there is no second structure to keep in sync.

Likely follow-ups
  • ABA problem on pop, and how hazard pointers or tagged pointers avoid it.
Implement it without any library stack.

A singly linked list where each node stores val, min and next; push creates a node with min = min(val, head.min) and makes it the head. This is the most-voted community solution and has no resizing cost.

How to answer

Code the node class first; every operation is one or two lines.

Likely follow-ups
  • Array vs linked list: cache locality versus no resize spikes.
