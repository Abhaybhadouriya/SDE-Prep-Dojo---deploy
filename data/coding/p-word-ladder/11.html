Interview follow-ups

Return the ladder itself, not just its length.

Store parent[word] when a word is first claimed. With one-directional BFS, walk parents back from endWord and reverse. With bidirectional BFS, keep a parent map per side and join the two half-paths at the meeting pair.

How to answer

Parent pointers cost O(N) extra and do not change the time.

Likely follow-ups
  • All shortest ladders (LC 126): keep every parent from the previous level, then backtrack.
The dictionary is huge and the same query runs many times. Precompute something.

Precompute wildcard buckets (c*rd -> [card, cord]) once, O(N · L²). Each query is then a BFS over buckets with no 26-letter loop. For repeated queries between fixed pairs, cache results or precompute connected components (different components -> answer 0 immediately).

How to answer

Separate preprocessing cost from per-query cost, as you would for an index.

Likely follow-ups
  • Memory of the buckets: N · L entries of L characters.
Why is bidirectional BFS faster? Give numbers.

With branching factor b and distance d, one-sided BFS touches about bd words; two sides touch about 2 · bd/2. With b = 10 and d = 6 that is 106 versus 2,000. The worst case is the same O(N · L · 26) because the dictionary bounds both.

How to answer

Give the bd versus bd/2 argument, then the worst-case caveat.

Likely follow-ups
  • When does it not help? (When one end has a huge fan-out; the size swap limits the damage.)
Changing some letters costs more than others. What changes?

Edges now have weights, so BFS is no longer correct. Use Dijkstra with a min-heap keyed by cost, or A* with an admissible heuristic such as "number of differing letters × cheapest change".

How to answer

Name the rule: BFS is shortest path only when all edges cost the same (or 0/1 with a deque).

Likely follow-ups
  • Costs are only 0 or 1: 0-1 BFS with a deque.
Allow insertions and deletions of a letter too.

Neighbours now include words of length L - 1 and L + 1, so the candidate count grows to about 26 · (2L + 1) + L per word. Group the dictionary by length; the BFS itself is unchanged.

How to answer

Show that only the neighbour generator changes; the search is generic.

Likely follow-ups
  • That is edit distance 1; for "within k edits" use a BK-tree or a trie walk.
