Approaches: brute -> better -> optimal

Hint 1

Write the four rules as four short loops/ifs on the same index i.

Hint 2

You want to know whether value · 10 + d > INT_MAX without computing value · 10 + d. Rearrange the inequality.

Hint 3

Do you need a separate check for the negative side, where the limit is 231 instead of 231 - 1?

1. Brute force - slice out the digits, then convert

Idea: strip spaces, take the sign, take the longest digit prefix as a substring, convert it with a big integer (Python int(), Java BigInteger) and clamp.

O(n)time
O(n)space

What is wasted: it works, but it leans on library parsing and big integers, which is the part the interviewer wants to see you write. In C++, stoll throws on 200 digits. -> rung 2.

2. Better - accumulate in 64 bits, clamp as you go

Idea: keep long value; after each digit, if value > 231 stop and clamp. A 64-bit value cannot overflow when it is checked after every digit (it never passes about 2.2·1010).

O(n)time
O(1)space

What is wasted: nothing really; this is accepted. The interviewer's next question is usually "and if you only had 32-bit integers?" (as in LC 7 Reverse Integer, which forbids 64-bit storage). -> rung 3.

3. Optimal - 32-bit accumulator with a pre-check

while i < n and "0" <= s[i] <= "9":
    d = int(s[i])
    if value > (INT_MAX - d) // 10:      # value*10 + d > INT_MAX
        return INT_MAX if sign == 1 else INT_MIN
    value = value * 10 + d; i += 1
  1. Spaces: while s[i] == ' ': i++ (only the space character).
  2. Sign: one optional +/-, then i++.
  3. Digits: keep the magnitude value in [0, INT_MAX] and the sign apart.
  4. Pre-check: value · 10 + d > INT_MAX is the same as value > (INT_MAX - d) / 10 (integer division), and neither side overflows.
  5. Clamp by sign: if the check fires, return INT_MAX for +, INT_MIN for -.
O(n)time
O(1)space

Why one check covers both signs: the check fires as soon as the magnitude would exceed 231 - 1. For a minus sign the true limit is 231, one more, but the only magnitude that lands exactly on 231 is "-2147483648", and clamping it gives INT_MIN, which is the exact answer anyway. So clamping at the first magnitude above INT_MAX is always correct.

Proof of the pre-check (optional)

For integers v ≥ 0 and 0 ≤ d ≤ 9: v·10 + d > M ⇔ v·10 > M - d ⇔ v > (M - d)/10 (real division) ⇔ v > ⌊(M - d)/10⌋, because v is an integer and M - d ≥ 0. The common form value > INT_MAX / 10 || (value == INT_MAX / 10 && d > 7) is the same test written out for M = 2147483647.
