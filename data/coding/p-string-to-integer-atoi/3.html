Recognise the pattern

Cue: "parse / validate a string by rules applied in order" -> a single scan with an index i and one small loop per phase (or an explicit state machine). Plus "fit into 32 bits" -> check for overflow before the operation that could overflow.

Try a few inputs that each test one rule:

sOutputRule it tests
"+-12"0Only one sign; the second one is a non-digit.
" +0 123"0The space after 0 ends the number.
"3.14159"3The dot is a non-digit; no decimals.
"-2147483649"-2147483648Clamped at the low end.
