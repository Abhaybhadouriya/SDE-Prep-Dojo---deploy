The problem (in our words)

Write myAtoi(s), which turns a string into a 32-bit signed integer by these rules, applied in order:

  1. Spaces: skip any leading space characters ' '.
  2. Sign: if the next character is '-' or '+', it sets the sign (negative or positive). With neither, the number is positive.
  3. Digits: read the following digits, skipping leading zeros, until a non-digit or the end of the string. If no digit was read, the result is 0.
  4. Rounding into range: if the number is outside [-231, 231 - 1], clamp it: values below -231 become -231, values above 231 - 1 become 231 - 1.

Return the resulting integer. Signature: int myAtoi(string s) (LeetCode style).

  • 0 <= s.length <= 200
  • s contains English letters (upper and lower case), digits 0-9, ' ', '+', '-' and '.'.

Practice it: LeetCode 8 · GfG Implement Atoi · TUF (recursive version)

Constraints tell you: n <= 200, so speed is a non-issue; this is a correctness problem. Its 22% acceptance rate comes from the rules, not from the algorithm: only spaces are skipped, only one sign is allowed, the parse stops at the first non-digit, and 200 digits can overflow even a 64-bit integer, so "read into a long and clamp at the end" is not safe in general.
