60-second recall

  • Cue: parse a string by ordered rules -> one index, one small loop per phase.
  • Insight: phases are spaces -> one sign -> digits -> stop at the first non-digit.
  • State: i, sign (+1/-1), value = magnitude in [0, INT_MAX].
  • Trap: check value > (INT_MAX - d) / 10 BEFORE value*10 + d; clamp by sign.
  • Cost: O(n) time, O(1) space; no 64-bit needed.
while i < n and s[i] == ' ': i += 1
if i < n and s[i] in '+-': sign = -1 if s[i] == '-' else 1; i += 1
while i < n and '0' <= s[i] <= '9':
    d = ord(s[i]) - 48
    if value > (MAX - d) // 10: return MAX if sign > 0 else MIN
    value = value * 10 + d; i += 1
return sign * value

value = 214748364 and the next digit is 8. What does the guard value > (INT_MAX - d) / 10 decide?

  1. Overflow: clamp to INT_MAX, or INT_MIN for a minus sign
  2. It fits: value becomes 2147483648
  3. It fits only for a minus sign
  4. The result is undefined
(2147483647 - 8) / 10 = 214748363, which is less than value. For "-2147483648" the clamp gives INT_MIN, the correct answer.

Input " -+12". What is the result?

  1. 0
  2. -12
  3. 12
  4. An error
Only one sign is read. The '+' is not a digit, so parsing stops with no digits read.

Why check before computing value*10 + d and not after?

  1. In C++ and Java the overflow has already happened by the time you check (undefined in C++, a silent wrap in Java)
  2. It is faster
  3. Python needs it
  4. It makes no difference
The check keeps value inside [0, INT_MAX] the whole time, so no 64-bit type is needed.
