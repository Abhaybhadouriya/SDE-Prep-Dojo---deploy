The problem (in our words)

A packing robot reads an integer array nums of length n (item weights, negatives allowed) and an integer target. Choose three items at three different indices whose sum is as close as possible to target, i.e. minimises |sum - target|, and return that sum (not the indices, not the distance).

You may assume the input has exactly one best answer.

Signature: int threeSumClosest(int[] nums, int target).

  • 3 <= nums.length <= 500
  • -1000 <= nums[i] <= 1000
  • -104 <= target <= 104

Practice it: LeetCode 16 · GfG 3 Sum Closest

Constraints tell you: n <= 500 makes O(n³) about 2 * 107 triplets: it may pass, but it is the brute force. O(n²) is the expected answer (about 1.25 * 105 steps). Any sum lies in [-3000, 3000] and the distance to the target is at most 13,000, so 32-bit ints are safe as long as you start best from a real sum, not from INT_MAX.
