Interview follow-ups

Return the three indices in the original array, not the sum.

Sort an array of indices by value (or pairs (value, index)) instead of the values, run the same squeeze on it, and keep the three original indices of the best sum. Still O(n²), with O(n) extra for the index array.

How to answer

Say that the sort destroys positions, so you carry them with the values; do not search for indices afterwards (duplicates make that ambiguous).

Likely follow-ups
  • Several triplets tie: return the lexicographically smallest index triple.
Ties are allowed: two sums are equally close. Which one do you return?

Decide a rule and encode it in the update: for "prefer the larger sum" (GfG's version), update when the distance is smaller, or equal and the new sum is larger. Nothing else changes, because the pruning argument does not depend on the tie rule.

How to answer

Show the one-line comparison change; ask the interviewer which rule they want.

Likely follow-ups
  • Return every triplet that achieves the best distance: collect them, with 3Sum's duplicate skipping.
Can you prune more than the duplicate skip?

Yes, two bounds per i: if nums[i] + nums[i+1] + nums[i+2] (the smallest sum for this i) is already above the target, it is the best for this i and for every later i, so update and stop. If nums[i] + nums[n-2] + nums[n-1] (the largest sum for this i) is below the target, update with it and skip to the next i. Same worst case, often much faster.

How to answer

Explain why each bound is safe from the sorted order, then say the worst case stays O(n²).

Likely follow-ups
  • Which bound lets you stop the outer loop completely, and which only skips one i?
Generalise to k numbers closest to the target.

Recurse: fix one element and solve "(k-1) numbers closest to target - nums[i]" on the suffix, down to the two-pointer base case for k = 2. That is O(nk-1). Unlike exact k-sum, a hash set does not help with "closest"; for k = 4 you can sort all n² pair sums and squeeze over them (O(n² log n)), but then you must reject two pairs that share an index.

How to answer

Give the recursive template and its cost; mention that "closest" needs ordered structures (sorting) rather than hashing.

Likely follow-ups
  • What changes for 64-bit overflow when k and values grow? Use long sums.
You may not modify the input array.

Copy it and sort the copy: O(n) extra space, same time. If memory is tight, the O(n³) brute force works in O(1) extra, and for n <= 500 it is about 2 * 107 sums: slow but acceptable in C++.

How to answer

Make the trade-off explicit: space for the copy vs a factor n in time.

Likely follow-ups
  • The array is streamed and does not fit in memory: what can you still compute exactly?
