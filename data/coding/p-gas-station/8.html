Common mistakes

  • Dropping the total check. On [4, 0] / [0, 5] the greedy ends with start = 1 and a non-negative tank, but the answer is -1.
  • Resetting to start = i instead of i + 1. Pad i itself is part of the dead block (it was reached with tank >= 0 and still failed).
  • Testing tank <= 0. Arriving with exactly 0 charge is fine; a <= reset skips valid starts (it fails [5] / [5] by returning 1).
  • Simulating a second lap with modulo indexing to "check" the candidate. It is not needed: the total argument already proves it, and it adds wrap bugs.
  • Returning start when it equals n. That can only happen when the last reset was at i = n - 1, which means total < 0 under the unique-answer rule; still, keep the total check first.
