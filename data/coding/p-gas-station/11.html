Interview follow-ups

Prove that total >= 0 is enough for a start to exist.

How to answer: take the index m where the prefix sum P is lowest; from m every partial sum is P(k) - P(m) >= 0, and after the wrap it is P(n) - P(m) + P(k), which is even larger because P(n) = total >= 0.

Likely follow-ups: why the greedy's last reset is exactly m (resets happen at new strict lows).

Return every valid start (drop the uniqueness guarantee).

How to answer: lay the route out twice (length 2n) and take prefix sums Q. Start s works iff the lowest Q in the window (s, s + n] is at least Q[s]. A monotonic deque gives every window minimum in O(1) amortised, so all starts are found in O(n).

Likely follow-ups: the greedy alone returns only one start; with a surplus (total > 0) several starts can work, for example net = [1, 1].

The tank has a capacity C.

How to answer: the "block of dead pads" argument breaks, because overflow wastes fuel. Simulate from each candidate with clamping, or use a doubled array with a monotonic deque; say plainly that the O(n) greedy no longer applies as is.

Likely follow-ups: what is the minimum capacity that allows a full lap? (binary search on C plus a check).

The drone may travel counter-clockwise too.

How to answer: run the same greedy on the reversed route, where pad i gives gas[i] and the hop i -> i - 1 costs cost[i - 1]. Return any direction that works.

Stations arrive as a stream and the route is very long.

How to answer: the algorithm is already streaming: three integers of state. Total, tank and start are updated per station; the answer is known after the last one.

Likely follow-ups: use 64-bit totals if values or n grow.

Minimum number of refuelling stops to reach a target on a line.

How to answer: that is LC 871: drive as far as the fuel allows, push passed stations into a max-heap, and pop the largest when you run short. O(n log n).
