Approaches: brute -> better -> optimal

Hint 1

Replace the two arrays by one: net[i] = gas[i] - cost[i]. Now the question is about a running sum.

Hint 2

Suppose you start at a and first fail when leaving pad b. Could any pad between a and b have worked?

1. Brute force - simulate a full lap from every pad

Idea: for each start s, walk n hops with a battery counter; stop early when it goes negative. Return the first s that survives.

for s in range(n):
    tank = 0
    for k in range(n):
        tank += net[(s + k) % n]
        if tank < 0: break
    else:
        return s
return -1
O(n^2)time
O(1)space

What is wasted: after a start a fails at b, we retry a + 1, a + 2, ... and walk the same stretch again, although all of them fail at or before b. -> rung 2.

2. Optimal - one pass, reset the start after each failure

for i in range(n):
    total += net[i]; tank += net[i]
    if tank < 0:            # [start, i] are all dead
        start, tank = i + 1, 0
return start if total >= 0 else -1
  1. A failure kills a whole block. If the tank from start drops below 0 at i, every pad k in (start, i] also fails: when the drone reached k from start it had a tank of at least 0, so starting at k with 0 is never better.
  2. So skip straight to i + 1. Each pad is visited once; no restarts.
  3. The total decides existence. If sum(net) >= 0, the last candidate start works (proof below); if not, nothing works.
O(n)time
O(1)space
1pass

Why it works: the resets prove every pad before the final start is dead. The final start reaches the end of the array without underflow. Each reset happened at a new lowest point of the running sum, so the final start sits just after the global lowest point; from there, a non-negative total carries the drone through the wrap-around part as well (the proof below makes this exact).

Proof (optional) - start after the lowest prefix

Let P(k) = net[0] + ... + net[k-1], with P(0) = 0 and P(n) = total >= 0. Pick m where P(m) is the smallest. Starting at pad m, the tank after reaching position k > m is P(k) - P(m) >= 0. After wrapping to position k <= m, it is P(n) - P(m) + P(k) >= P(k) - P(m) >= 0, since total >= 0. So pad m works. The greedy resets exactly when the running sum hits a new strict low, so its last start is this m (or 0 when the minimum is P(0)). This is the argument the most-voted proof post makes, rewritten in prefix notation.

3. Same cost, other view - argmin of the prefix sum

Idea: compute the running sum once, remember where it is lowest, and answer "the pad after the lowest point" if the total is not negative. It is the proof turned into code, handy when an interviewer asks "why does the greedy work?".
