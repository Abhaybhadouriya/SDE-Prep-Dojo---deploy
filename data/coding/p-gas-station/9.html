  • Cue: circular route, resource must stay >= 0, find the start index.
  • Insight: fail from a at b means all of [a, b] fail; total >= 0 means a start exists.
  • State: net = gas - cost; tank (since start), total (all), start.
  • Trap: reset to i + 1 (not i), test tank < 0 (not <= 0), check total at the end.
  • Cost: O(n) time, O(1) space; brute every start O(n^2).
total = tank = start = 0
for i, x in enumerate(net):
    total += x; tank += x
    if tank < 0:
        start, tank = i + 1, 0
return start if total >= 0 else -1

If the tank goes negative going from i to i + 1, why can start jump straight to i + 1?

  1. Any start between the old start and i reached that point with tank >= 0, so it would fail there too
  2. Because the stations are sorted
  3. It is a guess that usually works
Starting later only removes a non-negative prefix of fuel, so it cannot help before i + 1.

When is the answer -1?

  1. When some gas[i] < cost[i]
  2. When sum(gas) < sum(cost)
  3. When n is odd
If the total is non-negative, a valid start always exists (and it is unique here).

Time and space of the greedy?

  1. O(n), O(1)
  2. O(n^2), O(1)
  3. O(n log n), O(n)
One pass with a running tank and a total.
