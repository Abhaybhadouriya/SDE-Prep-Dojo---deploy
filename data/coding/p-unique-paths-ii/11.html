Interview follow-ups

Reduce the space from O(m·n) to O(n). Why is the in-place update correct?

Keep one array indexed by column. Before writing ways[c] it holds the cell above; ways[c-1] was written earlier in this row, so it holds the cell to the left. ways[c] += ways[c-1] therefore computes up + left. A rock writes 0.

How to answer

Draw the array under the grid and point at which slot is "old" and which is "new".

Likely follow-ups
  • Could you use O(1) extra space? (Overwrite the grid itself, if mutation is allowed; rocks become 0 and free cells become counts.)
The answer could exceed 64 bits. What changes?

Either return it modulo a prime (usual on GfG and in contests: add, then % MOD), or use big integers (Python does this for free; Java BigInteger). The DP itself is unchanged; only the number type changes.

How to answer

State where overflow can happen (inner cells, not just the goal) before choosing the fix.

Likely follow-ups
  • Why does modulo stay correct? (Addition commutes with mod.)
Return one actual path, or all of them.

For one path, keep the full table and walk back from the goal: from (r, c) step to whichever of up/left has a non-zero count. For all paths, backtrack (DFS) but prune with the table: never enter a cell with count 0 toward the goal. Listing them is output-sensitive: O(number of paths · (m+n)).

How to answer

Point out the 1D optimisation is lost when you need reconstruction; keep the 2D table.

Likely follow-ups
  • Lexicographically smallest path ("D" < "R")? (Greedy: prefer down whenever down still reaches the goal.)
The grid is 109 x 109 with only k rocks. Count the paths modulo a prime.

No table fits. Sort the rocks by (row, col). Let f(i) = paths from the start to rock i that touch no earlier rock = C(start -> i) - sum over rocks j before i of f(j) · C(j -> i), where C(a -> b) is a binomial coefficient. Treat the goal as rock k+1. O(k2) with precomputed factorials.

How to answer

Name it "inclusion-exclusion over the first rock hit"; it is the same "subtract paths through the rock" idea as the 10 - 6 = 4 check in the dry run.

Likely follow-ups
  • How do you compute C(n, r) mod p fast? (Factorials and inverse factorials via Fermat.)
Moves may also go diagonally down-right. What changes?

Add the up-left cell: ways = up + left + diag. With a 1D row you need one extra variable that remembers the old ways[c-1] before it is overwritten (the same trick as in Maximal Square).

How to answer

"Sum over predecessors" generalises to any move set that keeps the graph acyclic.

Likely follow-ups
  • What if moves can go up as well? (Cycles appear: the count may be infinite unless paths are simple, and then it is a backtracking problem.)
