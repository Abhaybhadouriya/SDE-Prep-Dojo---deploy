60-second recall

  • Cue: count right/down paths on a grid -> ways = up + left.
  • Rock: write 0; never skip the write (it also clears the start).
  • Space: one row; ways[c] += ways[c-1] left to right = up (old) + left (new).
  • Traps: first row/column after a rock is 0; blocked start/goal; 64-bit cells.
  • Cost: O(m·n) time, O(n) space; no rocks -> C(m+n-2, m-1).
ways = [1] + [0] * (n - 1)
for row in grid:
    for c in range(n):
        ways[c] = 0 if row[c] else ways[c] + (ways[c-1] if c else 0)
return ways[-1]

In the rolling row, just before ways[c] += ways[c-1], what does ways[c] hold?

  1. the cell to the left
  2. the cell above (previous row)
  3. the up-left cell
  4. always 0
It has not been overwritten in this row yet, so it is still the previous row's value.

Grid [[1]]: what is the answer?

  1. 1
  2. undefined
  3. 0
  4. -1
The start is a rock, so no path exists; a hard-coded start value of 1 is the bug.

Why use 64-bit cells when the answer is at most 2·109?

  1. inner cells can exceed INT_MAX even if the goal does not
  2. Java needs long arrays
  3. for speed
  4. the answer may be negative
A large open area that is later cut off from the goal collects huge counts.
