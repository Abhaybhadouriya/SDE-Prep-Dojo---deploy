Common mistakes

Filling row 0 / column 0 with 1s. That is correct for Unique Paths I only. With rocks, everything after the first rock in the first row (or below it in the first column) must be 0. The rolling-row code gets this for free.

32-bit cells. The guarantee "answer <= 2·109" is about the goal cell only. A big open region that is later walled off can hold enormous counts. Use long long / long cells and cast at the end; Python and Go (64-bit int) are fine for the judge's tests.

Forgetting the blocked start or goal. Check both, or write the loop so that a rock always writes 0 even at (0,0).

Updating the 1D array right to left. Then ways[c-1] is still the old row's value (the up-left cell), and you count the wrong thing. Left to right is required here.
