The problem (in our words)

You get an m x n integer grid grid. A robot starts on the top-left cell grid[0][0] and wants to reach the bottom-right cell grid[m-1][n-1]. In one move it goes either one cell down or one cell right.

A cell holding 1 is an obstacle and a cell holding 0 is free. A path may not step on any obstacle cell (this includes the start and the goal).

Return the number of distinct paths from the start to the goal. The tests guarantee that the answer is at most 2 * 109.

Signature: int uniquePathsWithObstacles(int[][] obstacleGrid).

  • m == grid.length, n == grid[i].length
  • 1 <= m, n <= 100
  • grid[i][j] is 0 or 1.

Practice it: LeetCode 63 · GfG Unique Paths in a Grid · TUF article

Constraints tell you: at most 104 cells, so O(m·n) is instant and even O(m·n) memory is fine; the interviewer still likes to see the O(n) row. Plain recursion is 2m+n and dies. The answer fits in a 32-bit int, but intermediate cells do not have to (see Common mistakes).
