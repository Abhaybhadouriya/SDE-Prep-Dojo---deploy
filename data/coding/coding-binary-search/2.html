Exact match versus lower and upper bound

There are two common shapes. Learn both and know which question each one answers.

Exact match (closed)Bound / first true (half-open)
Range[lo, hi], hi = n - 1[lo, hi), hi = n
Loopwhile lo <= hiwhile lo < hi
Updateslo = mid + 1 / hi = mid - 1lo = mid + 1 / hi = mid
Ends withfound index, or -1 when lo > hilo == hi = first true (n if none)
Answers"is x here, where?"first >= x, first > x, insert position, first bad, smallest valid answer
 
def lower_bound(a, x):          # first i with a[i] >= x
    lo, hi = 0, len(a)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if a[mid] < x: lo = mid + 1
        else:          hi = mid
    return lo
# upper_bound: same with  a[mid] <= x   -> first i with a[i] > x

Step through lower_bound([2, 4, 4, 4, 7, 9, 12, 15], 4):

  1. Find the first index with a value >= 4. Half-open range: lo = 0, hi = 8 (one past the end, so "not found" has a place to land).
  2. mid = 4, value 7 >= 4: mid could be the answer, so keep it: hi = mid = 4 (not mid - 1).
  3. mid = 2, value 4 >= 4: mid could be the answer, so keep it: hi = mid = 2 (not mid - 1).
  4. mid = 1, value 4 >= 4: mid could be the answer, so keep it: hi = mid = 1 (not mid - 1).
  5. mid = 0, value 2 < 4: mid and everything left of it are too small. lo = mid + 1 = 1.
  6. lo == hi == 1: the range is empty and the loop stops. Invariant: everything before lo is < 4, everything from hi on is >= 4, so 1 is the answer. 4 probes for 8 items.

Two bounds answer a lot of questions:

  • First and last position of x: [lower_bound(x), upper_bound(x) - 1], empty if they cross.
  • How many copies of x: upper_bound(x) - lower_bound(x).
  • Insert position: lower_bound(x).
  • Largest value <= x (floor): index upper_bound(x) - 1, if it is >= 0.
  • Smallest value > x (ceiling, strictly): index upper_bound(x), if it is < n.

Every language has these built in: C++ std::lower_bound / upper_bound, Python bisect_left / bisect_right, Go sort.Search / sort.SearchInts, Java Arrays.binarySearch (returns -(insertion point) - 1 when missing, and any index among duplicates) or TreeMap.floorKey / ceilingKey. Use them in real code; write the loop by hand when the interviewer asks or when the predicate is not "compare with x".
