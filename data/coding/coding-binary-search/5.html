Peak finding: binary search without sorting

"Return any index whose value is bigger than both neighbours; neighbours are never equal; outside the array counts as minus infinity." The array is not sorted, yet O(log n) is possible.

Look at a[mid] and a[mid + 1]. Uphill (a[mid] < a[mid + 1]): a peak exists in (mid, hi], so lo = mid + 1. Downhill: a peak exists in [lo, mid], so hi = mid. The invariant is "there is a peak in [lo, hi]". When lo == hi you are standing on one.

The same "which side still holds an answer" question solves the mountain array (one peak), "find in mountain array" (find the peak, then two normal searches, one ascending and one descending), and "single element in a sorted array" where pairs sit at even/odd indexes until the single one breaks the pattern.
