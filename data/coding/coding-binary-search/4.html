Rotated sorted arrays

A sorted array was cut at some point and the two parts were swapped: [30, 40, 50, 60, 10, 20, 25]. It is not sorted any more, so "compare mid with the target" alone does not tell you which side to drop. But it is two sorted ramps:

So at each step: find the sorted half (compare a[lo] with a[mid]), check whether the target lies inside that half's range, and go there or to the other half.

  1. A sorted list of ten-minute slots was rotated: [30, 40, 50, 60, 10, 20, 25]. Find 25. Closed range: lo = 0, hi = 6.
  2. mid = 3. a[lo] = 30 <= a[mid] = 60, so the left half [0..3] is sorted. Is 30 <= 25 < 60? No: the target can only be on the right. lo = 4.
  3. mid = 5. a[lo] = 10 <= a[mid] = 20, so the left half [4..5] is sorted. Is 10 <= 25 < 20? No: the target can only be on the right. lo = 6.
  4. mid = 6, value 25 is the target. Return 6. Every step threw away about half, even though the array is not fully sorted.

Find the minimum (the rotation point) is simpler: compare a[mid] with a[hi]. If a[mid] > a[hi] the drop is to the right of mid (lo = mid + 1); otherwise mid to hi is sorted and the minimum is at mid or to its left (hi = mid). Compare with a[hi], not a[lo]: with no rotation, a[lo] <= a[mid] is true and tells you nothing about where the minimum is.

With duplicates ([2, 2, 2, 0, 2]) you cannot tell which half is sorted when a[lo] == a[mid] == a[hi]. The standard fix is to shrink by one (lo++ or hi--), which makes the worst case O(n). Say this out loud; it is the usual follow-up.
