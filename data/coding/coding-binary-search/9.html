How to recognise a binary search problem

When you see sorted input (or a sorted dimension), "O(log n)" in the follow-up, or a yes/no question that flips once as a number grows, think binary search.

  • Sorted array / matrix / list of timestamps and a lookup: bounds or exact match.
  • "First / last / smallest / largest index such that": first-true template.
  • Sorted but rotated, or a mountain: find which half still has the answer.
  • "Any peak", "the single one": a local test at mid tells you the side.
  • "Value at time t", "latest version before": floor lookup with upper_bound - 1.
  • Huge answer range (up to 109) and an easy check "is answer <= X feasible?": binary search on the answer.
