The one idea: a loop invariant

Almost every bug in binary search is an off-by-one: < or <=, mid or mid - 1, return lo or hi. You stop guessing these by stating an invariant: a sentence about lo and hi that is true before the loop, stays true after every update, and gives the answer when the loop ends.

Think of the array as a row of answers to a yes/no question, pred(i). For "first index with a[i] >= x" on a sorted array, the row looks like F F F F T T T T. We want the first T.

With that picture the code writes itself:

  • If pred(mid) is F, mid and everything left of it are F: lo = mid + 1.
  • If pred(mid) is T, mid might be the first T, so keep it: hi = mid.
  • Stop when lo == hi: the gap is empty, and lo is the first T (or n if there is none).

How many steps? Each one halves the gap, so about log2(n). For n = 109 that is 30 steps. That is why "n up to 109" in the constraints is a strong hint.
