Off-by-one rules that never fail

  1. Pick one template per problem and say its invariant. Do not mix while lo <= hi with hi = mid: that can loop forever when lo == hi.
  2. Compute mid without overflow. lo + (hi - lo) / 2, not (lo + hi) / 2. In 2006 Joshua Bloch showed that the JDK's own binary search had this bug for arrays over 230 elements. In Java (lo + hi) >>> 1 is also safe.
  3. Make sure every branch shrinks the range. With mid = lo + (hi - lo) / 2 (rounds down), lo = mid can stall when hi = lo + 1. If a branch must be lo = mid ("last true" searches), round mid up: lo + (hi - lo + 1) / 2.
  4. Check the empty and the edges. Test n = 0, n = 1, the target smaller than everything, larger than everything, and all duplicates.
  5. Squares and products need 64 bits. mid * mid for mid near 46,341 already overflows a 32-bit int.

Say the invariant before you code: "lo is always a candidate and everything before lo is too small; hi is past the last candidate." Interviewers trust code more when you can tell them why it terminates and why the return value is right.

The general form: first true

Nothing above needs an array. Any monotone yes/no question over integers works: "is x*x > n?" gives the integer square root; "is version v bad?" gives the first bad version; "can we ship everything in d days with capacity c?" gives the smallest capacity (binary search on the answer: see the "next step" problems at the end of the practice list). Write the template once as first_true(lo, hi, pred) and reuse it.
