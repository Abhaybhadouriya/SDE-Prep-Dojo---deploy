Search in time-stamped records

A common design-flavoured coding question: store set(key, value, timestamp) and answer get(key, timestamp) with the value that was current at that time, meaning the record with the largest timestamp that is not after the query. Timestamps per key arrive in increasing order.

Because sets arrive in time order, appending keeps each list sorted for free. A get is upper_bound(times, t) - 1: O(log m) for m versions of that key. If the index is -1, the key did not exist yet.

The same shape: "snapshot array" (each index keeps a list of (snap_id, value); a get is a floor lookup on snap_id), "version of a config at time t", or finding a log line by timestamp in a file whose lines are sorted by time. In Java a TreeMap<Integer, String> with floorEntry(t) does it in one line; in C++ std::map::upper_bound then step back.

From your world

This is a multi-version store: each write appends a version, reads pick the newest version not newer than the reader's time. Databases with MVCC and snapshot reads do the same lookup. A sorted ring of sequence numbers searched for "last entry <= seq" is the same floor search.
