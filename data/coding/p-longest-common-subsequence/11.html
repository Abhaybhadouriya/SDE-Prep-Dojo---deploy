Interview follow-ups

Return the subsequence itself, not only its length.

Keep the full table. From (m, n): if a[i-1] == b[j-1], take the letter and go to (i-1, j-1); else move to the larger of (i-1, j) and (i, j-1). Reverse the collected letters. O(m + n) extra time. With only one row you cannot walk back; Hirschberg's divide and conquer gets the string in O(min(m, n)) space and O(m·n) time.

How to answer

Trace back on the dry-run table: d, c, a -> "acd".

Likely follow-ups
  • Return all LCS strings (backtrack on ties, with a set to remove duplicates).
Use less memory.

Row i only reads row i-1, so keep two rows, or one row and a diag variable. Put the shorter string on the columns: O(min(m, n)) space.

How to answer

Show the dependency picture (diagonal, up, left) and explain why the saved diagonal is needed.

Likely follow-ups
  • Can you also reconstruct the string? (Not directly; Hirschberg.)
How is this related to Edit Distance and diff?

If only insertions and deletions are allowed, the edit distance is m + n - 2 · LCS. diff prints the LCS lines as unchanged and the rest as - / +. With replacements allowed (Levenshtein), use the Edit Distance table with min over three moves.

How to answer

Give the formula and a one-line example.

Likely follow-ups
  • Weighted costs per operation.
The strings are 105 long. Is there anything faster?

General LCS has no strongly subquadratic algorithm under standard assumptions. Special cases help: if one string has all distinct letters (a permutation), LCS reduces to Longest Increasing Subsequence of positions, O(n log n). Hunt-Szymanski is fast when matches are few. Bit-parallel LCS gives a 64× constant speed-up.

How to answer

Mention the permutation -> LIS reduction; it is the one interviewers expect.

Likely follow-ups
  • Minimum operations to make a subsequence (LeetCode 1713) uses exactly that reduction.
LCS of three strings?

Add a dimension: dp[i][j][k], diagonal + 1 if all three last letters are equal, else max of dropping each one. O(m·n·p) time; space can roll on one dimension.

How to answer

Note that LCS(LCS(a, b), c) is NOT correct, because the pairwise LCS is not unique.

Likely follow-ups
  • k strings: exponential in k (NP-hard in general).
