Approaches: brute -> better -> optimal

Hint 1

Look only at the last characters of the two strings. If they are equal, must they both be in some longest answer?

Hint 2

If they differ, one of them is useless at the end. You do not know which, so try both: f(i-1, j) and f(i, j-1).

1. Brute force - recursion on the last characters

Idea: f(i, j) = LCS of the first i letters of a and the first j letters of b. f(0, *) = f(*, 0) = 0. If a[i-1] == b[j-1]: 1 + f(i-1, j-1); else max(f(i-1, j), f(i, j-1)).

O(2m+n)time (each mismatch branches)
O(m + n)stack depth

What is wasted: only (m+1)(n+1) distinct pairs (i, j) exist, but the tree visits the same pairs again and again. -> memoise.

2. Better - memo or a full 2D table

dp = [[0] * (n + 1) for _ in range(m + 1)]
for i in range(1, m + 1):
    for j in range(1, n + 1):
        if a[i-1] == b[j-1]: dp[i][j] = dp[i-1][j-1] + 1
        else:                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
return dp[m][n]
  • State: dp[i][j] = LCS length of a[0..i) and b[0..j).
  • Transition: diagonal + 1 on a match, else max(up, left).
  • Base case: row 0 and column 0 are 0 (an empty prefix).
  • Answer: dp[m][n].
O(m · n)time
O(m · n)space

Why it works (the exchange argument behind the match rule): if a[i-1] == b[j-1] = c, take any LCS L of the two prefixes. If L does not end by using both of these last c's, you can make its last letter be matched to them (or append c if L uses neither) without making it shorter. So some optimal answer matches them, and the rest is an LCS of the shorter prefixes. If the letters differ, they cannot both be the final matched pair, so at least one is unused, and dropping it loses nothing.

What is wasted: row i only reads row i-1. -> keep one row.

3. Optimal - one rolling row

Idea: keep row[j] for the previous i; overwrite it left to right. Before overwriting row[j], save it: it is the "up" value now and becomes the "diagonal" for j + 1. Swap the strings so the row is the shorter one.

O(m · n)time
O(min(m, n))space

The top community answers show both the two-row version (dp[i % 2]) and this one-row version with a diag variable; both are fine in an interview. The full table is still needed if you must print the subsequence (see follow-ups).
