Kruskal reaches edge (u, v) and find(u) == find(v). What does it do?

  1. Skips it: it would close a cycle
  2. Takes it and unions u and v
  3. Stops: the tree is done
  4. Swaps it with the heaviest tree edge
u and v are already connected by lighter edges, so this edge would form a cycle in which it is the heaviest. The cycle property says it is not needed.

1,000 points; connecting two costs their Manhattan distance. Which MST method is the most natural?

  1. Kruskal over all pairs
  2. Prim with arrays, O(V2)
  3. Floyd-Warshall
  4. Hierholzer
The graph is complete. Array Prim does V scans of V entries and never stores the roughly 500,000 edges.

What is the key in Prim's heap?

  1. Distance from the start vertex
  2. Weight of the single edge connecting the vertex to the tree
  3. Degree of the vertex
  4. Number of edges from the start
That is the difference from Dijkstra, whose key is the total path distance.

Tree edge u-v (v a child of u). When is it a bridge?

  1. low[v] ≥ tin[u]
  2. low[u] > tin[v]
  3. tin[v] > tin[u]
  4. low[v] > tin[u]
Nothing in v's subtree can reach u or above without this edge. The ≥ form is the cut-vertex test.

Why skip the parent edge by its id rather than skipping the parent vertex?

  1. It is faster
  2. It avoids recursion
  3. Vertex ids may be negative
  4. With two parallel edges, the second one is a real back edge and must count
Two parallel cables mean neither is a bridge. Skipping the parent vertex would ignore the second cable and report a false bridge.

An undirected connected graph has exactly 4 vertices of odd degree. Does it have an Euler path?

  1. Yes, an Euler circuit
  2. No
  3. Yes, from any odd vertex
  4. Only if it is a tree
Only the start and the end of an Euler path can have odd degree, so at most 2 odd vertices are allowed.

In Hierholzer's algorithm, when is a vertex appended to the output?

  1. When it is first visited
  2. When it is pushed on the stack
  3. When it has no unused outgoing edge left
  4. When all its neighbours are visited
Post-order emit is what lets later sub-tours be spliced in before dead ends. The output is reversed at the end.
