Common mistakes

  • Confusing Prim with Dijkstra. Prim's key is the one edge into the tree (w), Dijkstra's is the path total (d + w). Mixing them gives a shortest-path tree, which is not an MST.
  • Forgetting the connectivity check. Kruskal on a disconnected graph quietly returns a forest's weight. Count the edges you took.
  • Union-find without path compression or union by size. Still correct, but a chain can make each find O(V).
  • Building all pairs for Kruskal when Prim needs none. 1,000 points means about 500,000 edges to store and sort; array Prim uses two arrays of 1,000.
  • Skipping the parent vertex instead of the parent edge in Tarjan: wrong with parallel edges.
  • Using ≥ for bridges or > for cut vertices. Bridges need low[v] > tin[u]; cut vertices need low[v] ≥ tin[u], plus the root rule.
  • Updating low[u] from low[w] of a back-edge neighbour. For a back edge use tin[w]. For bridges it happens to give the same answer, but it breaks articulation points and is a red flag to interviewers.
  • Recursion depth of 105 in Python (or Java on a small stack).
  • Greedy itinerary without Hierholzer's post-order emit: fails on dead ends.
  • Mutating a list while iterating it in Hierholzer: pop the ticket before you push the next airport.
