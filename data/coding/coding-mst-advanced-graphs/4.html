MST variants interviewers ask

The virtual vertex

Optimize Water Distribution in a Village (Premium): each house can dig its own well at a given cost or be connected by pipe to another house. "Choose a cost per vertex OR connect it" does not look like an MST, until you add one extra vertex 0, the water source, with an edge 0-i of weight well[i]. Every valid plan is now a spanning tree of V + 1 vertices, and Kruskal finds the cheapest.

Maximum spanning tree and "remove the most edges"

Sort descending instead of ascending and Kruskal gives a maximum spanning tree. Remove Max Number of Edges to Keep Graph Fully Traversable has edges usable by Alice only, Bob only, or both. Keep two union-finds. Process the shared edges first (each one helps both people at once), then each person's own edges in their own DSU. Every edge that joins nothing new is removable. If either DSU does not end with one component, return -1.

Critical and pseudo-critical edges

Find Critical and Pseudo-Critical Edges in Minimum Spanning Tree: an edge is critical if removing it raises the MST weight (or disconnects the graph), and pseudo-critical if it is in some MST but not all. With E ≤ 200 the intended solution is brute force over Kruskal: compute the true MST weight W once. For each edge e, run Kruskal without e; if the result is > W or not connected, e is critical. Otherwise run Kruskal with e forced in first; if the result equals W, e is pseudo-critical. O(E2 α(V)) after one sort.

Minimax paths: the MST already knows the answer

The path between two vertices inside an MST minimises the largest edge on the way (it is a minimum bottleneck path). That is why the union-find solution of Path With Minimum Effort and Swim in Rising Water works: add edges in weight order and stop the moment start and target join. It also powers Checking Existence of Edge Length Limited Paths: for each query (p, q, limit), is there a path whose every edge is shorter than the limit? Sort the queries by limit, sort the edges by length, and sweep. Each query unions all edges below its limit and then asks "same root?". O((E + Q) log) total instead of a BFS per query.

# 7. Offline minimax queries: sort edges and queries by limit, union as the limit grows.
def limited_paths(n, edges, queries):    # offline: sort edges and queries by limit
    parent = list(range(n))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    edges.sort(key=lambda e: e[2])
    ans, i = [False] * len(queries), 0
    for qi in sorted(range(len(queries)), key=lambda q: queries[q][2]):
        p, q, limit = queries[qi]
        while i < len(edges) and edges[i][2] < limit:
            parent[find(edges[i][0])] = find(edges[i][1])
            i += 1
        ans[qi] = find(p) == find(q)
    return ans

This "answer queries offline in sorted order while a union-find grows" move is one of the most reusable ideas on this page. Number of Good Paths uses the same sweep, ordered by vertex value instead of edge weight.
