Interview questions

Kruskal or Prim? How do you decide, and what is the complexity of each?

Kruskal sorts edges and uses union-find: O(E log E). It is natural when you are handed an edge list and the graph is sparse. Prim grows one tree: O(E log V) with a heap on an adjacency list, or O(V2) with plain arrays. When every pair of vertices is a possible edge (points on a plane), E is about V2/2, so array Prim at O(V2) beats Kruskal at O(V2 log V) and needs no edge list in memory.

How to answer

Name the input form first (edge list, adjacency list, implicit complete graph), then pick. Mention both rest on the cut property.

Likely follow-ups
  • Points are in 2D with Manhattan distance and n = 105? (Only O(n) candidate edges matter, found by sorting in four directions, then Kruskal. Mentioning it is enough.)
Prove that Kruskal's algorithm produces a minimum spanning tree.

By the cut property. When Kruskal accepts edge (u, v), take the cut between u's current component and the rest of the vertices. All lighter edges were already examined: each was either accepted (and so lies inside a component) or rejected because its ends were already in one component. Either way, none crosses this cut. So (u, v) is a lightest crossing edge and belongs to some MST consistent with the edges chosen so far. Induction over the accepted edges gives a full MST. Rejected edges close a cycle in which they are the heaviest, so the cycle property says skipping them loses nothing.

How to answer

State the cut property, then the "no lighter edge crosses" argument. Ninety seconds is enough.

Likely follow-ups
  • When is the MST unique? (When all weights are distinct; with ties, several MSTs can share the total.)
Each house can dig a well at its own cost or be piped to another house. Minimise the total cost.

Add a virtual vertex 0 (the water source) with an edge 0-i weighted by house i's well cost. Any valid plan is a spanning tree of the V + 1 vertices: a house with a well connects to 0, a piped house connects through others. Run Kruskal on wells plus pipes. O((V + E) log(V + E)).

How to answer

Say "virtual vertex" early; it is the whole insight. Then it is template 1.

Likely follow-ups
  • Some houses must use wells? (Force their 0-i edges in first.)
Find every connection whose failure disconnects part of a network of 105 servers.

These are bridges. One DFS computing tin (visit time) and low (lowest visit time reachable from the subtree with one back edge). Tree edge u-v is a bridge when low[v] > tin[u]. O(V + E). Skip the incoming edge by id to handle parallel connections, and make the DFS iterative or enlarge the stack because the depth can reach 105.

How to answer

Give the brute force (remove each edge, BFS, O(E(V + E))) in one line, then define tin and low precisely and the one comparison.

Likely follow-ups
  • Servers instead of connections? (Articulation points: ≥ and the root-with-two-children rule.)
  • Make the network survive any single failure with the fewest new links? (Contract 2-edge-connected components into a tree; with L leaves you need ceil(L / 2) links.)
What is the difference between the bridge condition and the articulation-point condition, and why does the root need a special rule?

Bridge: low[v] > tin[u], v's subtree cannot even reach u by another route, so the edge u-v is the only link. Cut vertex: low[v] ≥ tin[u], the subtree may reach u itself but nothing above u, so removing the vertex u strands it. The root has nothing above it, so low[v] ≥ tin[root] is always true; instead the root is a cut vertex exactly when it has two or more DFS children, since the DFS would have reached the second child through the first if any other path existed.

How to answer

Draw two triangles sharing one vertex: no bridges at all, but the shared vertex is a cut vertex.

Likely follow-ups
  • Is every endpoint of a bridge a cut vertex? (Not if it has degree 1.)
Reconstruct Itinerary: why does "always take the smallest next airport" fail, and what fixes it?

Greedy can enter an airport that has no tickets left while other tickets are unused, as with JFK → AMS, JFK → BOM, BOM → JFK: greedy flies to AMS and is stuck. Hierholzer keeps a stack: push the smallest unused destination while one exists; when the top has none, pop it to the output. A dead end is emitted first and ends up last after reversal, and the loop JFK → BOM → JFK gets spliced in before it. O(E log E) for sorting, O(E) for the walk.

How to answer

Show the three-ticket counterexample, then say "Euler path, Hierholzer, post-order emit, reverse".

Likely follow-ups
  • No starting airport given? (Directed: start at the vertex with out - in = 1, else anywhere with an edge.)
  • How do you know a valid trip exists? (Degree conditions plus all edges in one connected piece.)
Answer 105 queries "can p reach q using only edges shorter than limit?" on a graph with 105 edges.

A BFS per query is O(Q(V + E)), too slow. Process offline: sort edges by length and queries by limit. Sweep queries in increasing limit; before answering each, union every edge shorter than its limit; then answer with find(p) == find(q). Write answers back by original index. O(E log E + Q log Q) plus near-constant DSU work. This is Kruskal used as a growing reachability structure.

How to answer

Say "offline", "sort both", "pointer into the edges". Remember to keep each query's original index.

Likely follow-ups
  • Queries arrive online? (Build the MST once; the answer is "max edge on the tree path < limit", found with binary lifting in O(log V) per query.)
Which edges are in every MST, and which are in some but not all?

Compute the MST weight W. For each edge e: Kruskal without e; if the weight is above W or the graph is disconnected, e is in every MST (critical). Otherwise, Kruskal with e taken first; if that weight is W, e is in some MST (pseudo-critical); else in none. With E up to a few hundred, O(E2 α(V)) is fine. A faster answer groups edges of equal weight and finds bridges among them in the graph of already-merged components; mention it as the scalable version.

How to answer

Give the brute force with clear definitions first; it is what most top solutions do for this problem.

Likely follow-ups
  • Second-best MST? (Try adding each non-tree edge and removing the heaviest tree edge on the cycle it makes.)
