The invariant and the three operations

Store indexes, not values, in the deque. You need the index to know when an item has slid out of the window; you can always read the value as nums[idx]. The invariant:

  • The deque holds indexes in increasing order (oldest at the front).
  • Their values are strictly decreasing from front to back.
  • Every index in the deque is inside the current window.

Each new index i does three things, always in this order:

  1. Pop back while dominated. While nums[back] <= nums[i], pop the back. This keeps "strictly decreasing".
  2. Push back. Push i.
  3. Pop front if expired. If the front index is <= i - k, pop it. Then, once i >= k - 1, the answer for window [i-k+1 .. i] is nums[front].

Why O(n) and not O(n k)? The inner while can pop many items at once, so one step can cost a lot. But each index is pushed exactly once and popped at most once over the whole run. Total pops <= n, total pushes = n, so the whole loop is O(n): O(1) amortised per step. Memory is O(k), because only window indexes are stored.

Only one expiry pop per step is needed in the window-max problem, because the window moves by exactly one, so at most one index leaves. In problems where the left edge can jump (the two-deque problem below), use while for the front too.

Watch it run on [4, 2, 12, 3, 8, 1, 7] with k = 3. Look at step 3: 12 arrives and wipes out 4 and 2 at once. And at step 6: 12 finally expires from the front.

  1. i=0, value 4: nothing smaller at the back, push 4. Window not full yet.
  2. i=1, value 2: nothing smaller at the back, push 2. Window not full yet.
  3. i=2, value 12: pop 2 and 4 from the back (smaller than 12, never the max again), then push 12. Window [0..2] is full: max = front = 12.
  4. i=3, value 3: nothing smaller at the back, push 3. Window [1..3] is full: max = front = 12.
  5. i=4, value 8: pop 3 from the back (smaller than 8, never the max again), then push 8. Window [2..4] is full: max = front = 12.
  6. i=5, value 1: nothing smaller at the back, push 1. Front 12 (i=2) is outside the window, pop it from the front. Window [3..5] is full: max = front = 8.
  7. i=6, value 7: pop 1 from the back (smaller than 7, never the max again), then push 7. Window [4..6] is full: max = front = 8.
  8. Done: [12, 12, 12, 8, 8]. Seven pushes, and every pop removed something pushed earlier, so the work is O(n) no matter what k is.

The loop behind the steps. Invariant: the deque holds indexes inside the window with strictly decreasing values; the front is the maximum, and it leaves when its index is <= right - k. Lifted unchanged from the tested templates below.

// Max of every window of size k. dq holds INDEXES, values strictly decreasing front -> back.
vector<int> maxSlidingWindow(const vector<int>& nums, int k) {
    deque<int> dq;
    vector<int> out;
    for (int i = 0; i < (int)nums.size(); i++) {
        while (!dq.empty() && nums[dq.back()] <= nums[i]) dq.pop_back(); // they can never be the max again
        dq.push_back(i);
        if (dq.front() <= i - k) dq.pop_front();                       // front slid out of the window
        if (i >= k - 1) out.push_back(nums[dq.front()]);
    }
    return out;
}
def max_sliding_window(nums, k):
    """Max of every window of size k. dq holds indexes, values strictly decreasing."""
    dq, out = deque(), []
    for i, x in enumerate(nums):
        while dq and nums[dq[-1]] <= x:   # they can never be the max again
            dq.pop()
        dq.append(i)
        if dq[0] <= i - k:                # front slid out of the window
            dq.popleft()
        if i >= k - 1:
            out.append(nums[dq[0]])
    return out

From your world

In C you would not use a linked list for this. The deque never holds more than k entries, so a fixed array of k (or n) slots with head and tail indexes works, exactly like a NIC descriptor ring or a kfifo, except the producer side can also un-push (move tail back). Go has no deque type: a slice with dq = dq[1:] for the front is fine because the backing array is reused.
