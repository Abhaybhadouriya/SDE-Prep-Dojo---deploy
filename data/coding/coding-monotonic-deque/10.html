Common mistakes

  • Storing values instead of indexes. You then cannot tell when the front has expired, and duplicates break it. Store indexes, read nums[idx].
  • Wrong comparison at the back. For a max deque pop while nums[back] <= nums[i]. Both < and <= give correct answers for window max (with < equal values stay, which is safe because expiry is by index), but <= keeps the deque smaller. Popping on > builds the wrong order.
  • Reading the answer before the window is full. Only emit when i >= k - 1.
  • Expiry check off by one. Window [i-k+1 .. i]: expired means front <= i - k (or front < i - k + 1).
  • Using if instead of while for the shrink in the two-deque problem or the front rule in the prefix-sum problem.
  • Plain sliding window on an array with negatives for "sum at least K". It gives wrong answers, not just slow ones.
  • 32-bit prefix sums. Sums of 105 values of size 105 need 64 bits.
  • Java: Deque<Integer> compared with ==. dq.peekFirst() == dq.peekLast() compares boxed objects. Compare the int values, or use an int[] ring buffer for speed.
