Two deques: longest subarray with max - min <= limit

Now the window is not a fixed size. LeetCode 1438, told our way: given integer readings and a tolerance limit, find the length of the longest non-empty run of consecutive readings in which any two readings differ by at most limit. Constraints: 1 <= n <= 10^5, readings between 1 and 109, 0 <= limit <= 10^9. Example: [10, 1, 2, 4, 7, 2], limit = 5 gives 4 (the run [2, 4, 7, 2]).

"Any two differ by at most limit" is the same as max - min <= limit. And if a window is valid, every smaller window inside it is valid too, so this is a normal variable sliding window (expand hi, shrink lo while invalid). The only new part is the state: we need the window max and min while both ends move. So we keep two deques:

  • maxQ: values decreasing, front = window max (exactly as above).
  • minQ: values increasing, front = window min (the mirror: pop back while nums[back] >= nums[i]).

Expiry now happens when lo moves: after lo++, pop a front whose index is < lo. Here is the full run.

  1. hi=0, value 10: push it on both deques (popping dominated values first). Window [0..0] is valid, length 1; best = 1.
  2. hi=1, value 1: push it on both deques (popping dominated values first). Now max - min = 9 > 5, so move lo from 0 to 1, popping deque fronts that fall left of lo. Window [1..1] is valid, length 1; best = 1.
  3. hi=2, value 2: push it on both deques (popping dominated values first). Window [1..2] is valid, length 2; best = 2.
  4. hi=3, value 4: push it on both deques (popping dominated values first). Window [1..3] is valid, length 3; best = 3.
  5. hi=4, value 7: push it on both deques (popping dominated values first). Now max - min = 6 > 5, so move lo from 1 to 2, popping deque fronts that fall left of lo. Window [2..4] is valid, length 3; best = 3.
  6. hi=5, value 2: push it on both deques (popping dominated values first). Window [2..5] is valid, length 4; best = 4.

The loop behind the steps. Invariant: one deque keeps the window maximum at its front, the other the minimum; while front(max) - front(min) > limit, move left forward and drop fronts that fall out. Lifted unchanged from the tested templates below.

// Longest subarray with max - min <= limit. Two deques: maxQ decreasing, minQ increasing.
int longestSubarray(const vector<int>& nums, int limit) {
    deque<int> maxQ, minQ;
    int lo = 0, best = 0;
    for (int hi = 0; hi < (int)nums.size(); hi++) {
        while (!maxQ.empty() && nums[maxQ.back()] <= nums[hi]) maxQ.pop_back();
        while (!minQ.empty() && nums[minQ.back()] >= nums[hi]) minQ.pop_back();
        maxQ.push_back(hi);
        minQ.push_back(hi);
        while (nums[maxQ.front()] - nums[minQ.front()] > limit) { // shrink until valid again
            lo++;
            if (maxQ.front() < lo) maxQ.pop_front();
            if (minQ.front() < lo) minQ.pop_front();
        }
        best = max(best, hi - lo + 1);
    }
    return best;
}
def longest_subarray(nums, limit):
    """Longest subarray with max - min <= limit. max_q decreasing, min_q increasing."""
    max_q, min_q = deque(), deque()
    lo = best = 0
    for hi, x in enumerate(nums):
        while max_q and nums[max_q[-1]] <= x:
            max_q.pop()
        while min_q and nums[min_q[-1]] >= x:
            min_q.pop()
        max_q.append(hi)
        min_q.append(hi)
        while nums[max_q[0]] - nums[min_q[0]] > limit:   # shrink until valid again
            lo += 1
            if max_q[0] < lo:
                max_q.popleft()
            if min_q[0] < lo:
                min_q.popleft()
        best = max(best, hi - lo + 1)
    return best

Complexity: hi and lo each move n times, and each index enters and leaves each deque once: O(n) time, O(n) memory in the worst case (sorted input fills one deque).

Many people answer this with a TreeMap / multiset of the window values: O(n log n), easy to write, and it is fine to say it first. Then offer the two deques for O(n). Saying both, with the trade-off, is the senior answer.

The same two-deque state solves LeetCode 2762, Continuous Subarrays (count windows with max - min <= 2: add hi - lo + 1 each step instead of taking the max), and one deque plus a running sum solves LeetCode 2398 (window max of charge times plus k times the running cost sum must stay within budget).
