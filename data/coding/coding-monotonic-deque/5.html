Deque over prefix sums: shortest subarray with sum at least K

LeetCode 862, told our way: given an integer array that may contain negative numbers and a target K, return the length of the shortest non-empty run of consecutive elements whose sum is at least K, or -1 if no run reaches it. Constraints: 1 <= n <= 10^5, values between -105 and 105, 1 <= K <= 10^9. Example: [3, -2, 4, -1, 2], K = 5 gives 3.

Why the normal sliding window breaks. With only positive values, "shrink while sum >= K" is safe: dropping an element from the left always lowers the sum. With negatives, dropping a -2 raises the sum, and the window that looked too small may become valid after removing elements. The monotone property the window needs is gone. (If all values are positive, use the plain window from Sliding Window: LeetCode 209.)

Switch to prefix sums. Let P[0] = 0 and P[j] = nums[0] + ... + nums[j-1]. The sum of nums[i .. j-1] is P[j] - P[i]. For each end j we want the latest start i < j with P[i] <= P[j] - K. Two pruning rules, both from dominance:

  1. Back rule (later and lower wins). If i1 < i2 and P[i1] >= P[i2], start i1 is useless: whenever i1 works for some j, i2 also works (its P is lower or equal) and gives a shorter subarray (it is later). So before pushing j, pop the back while P[back] >= P[j]. The deque keeps increasing P.
  2. Front rule (use it once, then retire it). If P[j] - P[front] >= K, record j - front and pop the front. Any later end j' > j paired with the same start would be longer, so this start has given its best answer. Repeat while it holds: the next front has a higher P but is later, and may also qualify with a shorter length.

Step through the example. Watch the back rule delete P[1] = 3 when P[2] = 1 arrives, and the front rule fire at j = 3 and j = 5.

  1. j=0, P[j]=0. Push j=0.
  2. j=1, P[j]=3. Front start 0: P[1] - P[0] = 3 < 5, not enough yet. Push j=1.
  3. j=2, P[j]=1. Front start 0: P[2] - P[0] = 1 < 5, not enough yet. Pop P[1]=3 from the back: j is later and not higher. Push j=2.
  4. j=3, P[j]=5. P[3] - P[0] = 5 >= 5: subarray length 3; pop start 0 from the front (a later j would only be longer). Front start 2: P[3] - P[2] = 4 < 5, not enough yet. Push j=3.
  5. j=4, P[j]=4. Front start 2: P[4] - P[2] = 3 < 5, not enough yet. Pop P[3]=5 from the back: j is later and not higher. Push j=4.
  6. j=5, P[j]=6. P[5] - P[2] = 5 >= 5: subarray length 3; pop start 2 from the front (a later j would only be longer). Front start 4: P[5] - P[4] = 2 < 5, not enough yet. Push j=5. Answer = 3.

The loop behind the steps. Invariant: the deque holds prefix-sum indexes with increasing sums; pop the front while it gives a sum >= K (it can never give a shorter one later), and pop the back while it is not smaller than the new prefix. Lifted unchanged from the tested templates below.

// Shortest non-empty subarray with sum >= k (values may be negative). -1 if none.
// P[j] - P[i] >= k with i < j. dq holds prefix indexes with INCREASING P.
int shortestSubarray(const vector<int>& nums, long long k) {
    int n = nums.size();
    vector<long long> P(n + 1, 0);
    for (int i = 0; i < n; i++) P[i + 1] = P[i] + nums[i];
    deque<int> dq;
    int best = n + 1;
    for (int j = 0; j <= n; j++) {
        while (!dq.empty() && P[j] - P[dq.front()] >= k) { // front is the best start for j; no later j can beat it
            best = min(best, j - dq.front());
            dq.pop_front();
        }
        while (!dq.empty() && P[dq.back()] >= P[j]) dq.pop_back(); // j is a later AND lower start: strictly better
        dq.push_back(j);
    }
    return best <= n ? best : -1;
}
def shortest_subarray(nums, k):
    """Shortest subarray with sum >= k (negatives allowed), -1 if none.
    dq holds prefix indexes with increasing P."""
    P = [0]
    for x in nums:
        P.append(P[-1] + x)
    dq, best = deque(), len(nums) + 1
    for j, pj in enumerate(P):
        while dq and pj - P[dq[0]] >= k:   # best start for j; no later j can beat it
            best = min(best, j - dq.popleft())
        while dq and P[dq[-1]] >= pj:      # j is a later AND lower start: strictly better
            dq.pop()
        dq.append(j)
    return best if best <= len(nums) else -1

Each prefix index enters and leaves once: O(n) time, O(n) memory. Use 64-bit prefix sums: 105 x 105 = 1010 overflows a 32-bit int.

The order of the two rules matters less than people think (both orders are accepted), but the front rule must use while. With if you can miss a shorter answer from the next front at the same j. A second classic bug is forgetting P[0] = 0, which loses subarrays that start at index 0.

The same "deque over prefix sums with a length limit" idea solves LeetCode 918, Maximum Sum Circular Subarray another way: double the array, then for each j take the minimum prefix among the last n starts (window min deque). Kadane is the usual answer there; the deque version is the one that generalises.
