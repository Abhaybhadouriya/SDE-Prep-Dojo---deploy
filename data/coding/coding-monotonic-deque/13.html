Quiz

For a window-max deque, a new value x arrives. What do you pop from the back?

  1. Only the single back value
  2. Values greater than x
  3. Values less than or equal to x
  4. Nothing; you only pop from the front
Smaller-or-equal older values are dominated by x and can never be the max again.

Why does the deque store indexes rather than values?

  1. It is required for O(n)
  2. Values cannot be compared
  3. Indexes are smaller to store
  4. To know when the front has left the window
Expiry is a question about position: front <= i - k.

Window max over [4, 2, 12, 3, 8, 1, 7] with k = 3: what is in the deque (as values) right after i = 4 (value 8)?

  1. [12, 8]
  2. [8]
  3. [3, 8]
  4. [12, 3, 8]
8 pops 3 from the back; 12 (i = 2) is still inside window [2..4], so it stays at the front.

Shortest subarray with sum >= K, values may be negative. Which approach is correct?

  1. Binary search on the length with a fixed window sum check
  2. Plain sliding window, shrink while sum >= K
  3. Prefix sums with an increasing deque
  4. Sort the array, then two pointers
Negatives break the window's monotonicity, and "a length works" is not monotone either. The deque over prefix sums is the O(n) answer.

In the prefix-sum deque, P[back] = 7 and the new P[j] = 4. What happens?

  1. Pop 7: j is later and lower, so it is a better start
  2. Stop: no answer exists
  3. Keep both; 7 is older
  4. Pop the front instead
Any end that works with start back also works with start j, and gives a shorter subarray.

Which problem is NOT a monotonic deque problem?

  1. Constrained Subsequence Sum
  2. Jump Game VI
  3. Longest subarray with max - min <= limit
  4. Sliding window median
The median needs order statistics: two heaps or an ordered multiset.

Total number of pop operations over a whole run on n elements is at most...

  1. n k
  2. k
  3. n
  4. n log n
Each index is pushed once and can be popped at most once.
