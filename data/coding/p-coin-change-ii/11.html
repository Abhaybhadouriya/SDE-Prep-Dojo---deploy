Why does swapping the loops give a different answer? Prove which one is right.

Amounts outer computes W(a) = sum over c of W(a - c): it classifies sequences by their LAST coin, so every ordering of a multiset is a different sequence. Coins outer builds each multiset by deciding coin types in a fixed order, so each is counted once. Show amount 3 with {1, 2}: 3 vs 2.

How to answer

Name what each loop order counts (sequences vs multisets) and give the tiny counter-example.

Likely follow-ups
  • Which order do you need for Climbing Stairs? (sequences: amounts outer.)
Each coin can be used at most once. What changes?

Iterate amounts DOWN inside the coin loop: for a in range(amount, c - 1, -1): ways[a] += ways[a - c]. Going down, ways[a - c] still holds the previous row (without c), so c is used at most once.

How to answer

Point to the 2D recurrence: 0/1 reads dp[i-1][a-c], unbounded reads dp[i][a-c]; the loop direction picks which one the 1D array holds.

Likely follow-ups
  • Each coin has a count ki: prefix-sum over the window of ki + 1 cells, or binary splitting.
The answer can be huge. Return it modulo 109+7.

Apply % MOD after every addition (or a conditional subtract since both terms are below MOD). Additions are compatible with the modulus, so the final cell is correct mod 109+7.

How to answer

Mention that LeetCode's 32-bit guarantee only covers the final value; the same reasoning is why unsigned wrap-around works in C++.

Likely follow-ups
  • Why is the wrap-around (mod 264) answer exact when the true answer is below 231?
List all the combinations, not just count them.

Backtracking with a start index (LC 39 Combination Sum): at index i, either take coins[i] again or move to i + 1. The output can be exponential, so the count DP is no longer the bottleneck; you can still use the DP table to prune branches whose remaining amount has 0 ways.

How to answer

Note that enumerating is output-sensitive; counting is polynomial.

Likely follow-ups
  • Return the k-th combination in lexicographic order using the counts.
Can you sort coins to make it faster?

Sorting does not change the answer or the O(n · amount) bound; any fixed coin order counts each multiset once. Skipping coins larger than amount saves time, and the inner loop starting at c already does that implicitly.

How to answer

Show you know which details matter (loop nesting, direction) and which do not (coin order).

Likely follow-ups
  • Generating functions view: the answer is the coefficient of xamount in the product of 1/(1 - xc).
