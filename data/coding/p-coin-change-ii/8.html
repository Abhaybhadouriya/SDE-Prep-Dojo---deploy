Common mistakes

Amounts in the outer loop. Counts permutations: amount 3 with {1, 2} gives 3 instead of 2. This is the single most common bug on this problem.

Inner loop going down. for a in range(amount, c - 1, -1) allows each coin at most once (0/1 knapsack) and undercounts.

Returning 0 for amount 0. There is exactly one way to pay nothing. Writing if amount == 0: return 0 fails a test.

Signed int in C++. Only the final answer is promised to fit. Cells below the target can overflow (the even-coins case above), and signed overflow is undefined behaviour in C++, so a sanitizer build reports "signed integer overflow". unsigned long long (or unsigned) fixes it, since unsigned wrap-around keeps the final cell exact.
