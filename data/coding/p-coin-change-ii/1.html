The problem (in our words)

You get an integer amount and an array coins of distinct coin values, with an unlimited supply of each. Return the number of combinations of coins that add up to exactly amount. Two combinations are the same if they use the same count of every coin value (order does not matter). If no combination works, return 0. The answer is guaranteed to fit in a signed 32-bit integer.

Signature: int change(int amount, int[] coins).

Constraints

  • 1 <= coins.length <= 300
  • 1 <= coins[i] <= 5000, all values distinct
  • 0 <= amount <= 5000

Practice it: LeetCode 518 · GfG Coin Change (Count Ways) · TUF Coin Change II

Constraints tell you: amount · coins ≤ 5000 · 300 = 1.5·106, so the O(amount · coins) table is instant. Only the final answer is promised to fit in 32 bits: cells for smaller amounts can be astronomically larger (with even coins 2..100 and amount 4999 the answer is 0, but ways[4998] has 44 digits). In C++ use unsigned arithmetic, which wraps modulo 264 legally; the final cell is then still exact. Java and Go ints wrap by definition, Python has big integers.
