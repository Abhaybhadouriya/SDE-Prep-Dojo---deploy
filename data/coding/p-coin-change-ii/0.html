The story

Explain like I'm 5

You need to pay 6 rupees with an endless pile of 1, 2 and 4 rupee coins, and you want to know how many different handfuls work. "2 then 4" and "4 then 2" are the same handful. A tidy way to count each handful once: first decide how many 1s, then how many 2s, then how many 4s. If you always add coin types in the same fixed order, no handful can be counted twice.

That fixed order is the whole problem. The table is the same as in Coin Change; what changes is + instead of min and, crucially, which loop is outside.

From your world

Think of counting distinct packet-size mixes that fill an MTU exactly. If you enumerate "the next packet", you count every permutation of the same mix (that is Combination Sum IV). If you enumerate "how many packets of size 64, then of size 128, ...", each mix appears once. The second is what this problem asks.
