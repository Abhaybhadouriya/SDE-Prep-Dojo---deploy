60-second recall

  • Cue: count combinations to a sum, reusable items, order irrelevant.
  • Insight: add coin types one at a time -> each multiset built in one order.
  • Loops: coins OUTER, amounts UP from c: ways[a] += ways[a - c]; ways[0] = 1.
  • Trap: swapped loops count orderings; down loop = use once; C++ signed overflow.
  • Cost: O(amount · coins) time, O(amount) space.
ways = [1] + [0] * target
for item in items:                      # combinations: items outer
    for t in range(item, target + 1):   # up = reuse allowed (down = once)
        ways[t] += ways[t - item]
# permutations: for t in 1..target: for item in items: ways[t] += ways[t - item]

Amount 3, coins {1, 2}. The amounts-outer loop gives 3. The correct answer is

  1. 1
  2. 3
  3. 2
1+1+1 and 1+2; amounts outer also counts 2+1 as a separate sequence.

What does making the inner loop run DOWNWARDS change?

  1. Each coin can be used at most once
  2. Nothing
  3. It counts permutations
Going down, ways[a - c] still holds the previous row, so coin c is not reused.

Why is ways[0] = 1 and not 0?

  1. To avoid a division by zero
  2. The empty combination pays amount 0
  3. LeetCode requires it
Every combination ends by reaching 0 through the empty set; with 0 every cell would stay 0.
