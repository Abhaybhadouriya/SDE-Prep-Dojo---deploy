Approaches: brute -> better -> optimal

Hint 1

To avoid counting 2+4 and 4+2 twice, make every combination be built in one canonical order. Which order?

Hint 2

Decide coin by coin: "how many of coins[0]?", then "how many of coins[1]?", ... A state is (which coin you are deciding, amount still to pay).

1. Brute force - recursion on (coin index, remaining amount)

Idea: f(i, a) = ways to pay a using coins i..end. Either skip coin i forever (f(i + 1, a)) or use one more of it (f(i, a - coins[i])). f(i, 0) = 1; f(n, a > 0) = 0.

exponentialtime without a memo
O(n + amount)depth

What is wasted: only n · (amount + 1) distinct (i, a) pairs exist, but the tree solves each many times.

2. Better - 2D table

Idea: dp[i][a] = ways to pay a with the first i coins. dp[i][a] = dp[i-1][a] + dp[i][a - c] (do not use c at all, or use it and stay on the same row so it may be used again).

O(n · amount)time
O(n · amount)space

What is wasted: row i reads only row i - 1 and itself, so one row is enough.

3. Optimal - one row, coins outer

ways = [1] + [0] * amount
for c in coins:                       # rows of the 2D table, one coin at a time
    for a in range(c, amount + 1):    # left to right: ways[a - c] is already this row's value
        ways[a] += ways[a - c]
return ways[amount]
  • State: after processing coins[0..i], ways[a] = combinations of those coins that sum to a.
  • Transition: ways[a] (new) = ways[a] (old, no c) + ways[a - c] (new, at least one c).
  • Base case: ways[0] = 1 (the empty combination).
  • Answer: ways[amount].
O(n · amount)time
O(amount)space

Why it works: split the combinations of the first i coins that pay a into those with no c (counted by the previous row, still sitting in ways[a]) and those with at least one c (remove one c: a combination of the first i coins paying a - c, which the current row already holds because a - c < a was updated earlier in this pass). The two groups are disjoint and cover everything, so the sum is exact. Since every combination is assembled coin type by coin type, its order is fixed and it is counted once. With amounts outer, ways[a] instead sums over "the last coin added", which counts every ordering: for amount 3 and coins {1, 2} it gives 3 (1+1+1, 1+2, 2+1) instead of 2.
