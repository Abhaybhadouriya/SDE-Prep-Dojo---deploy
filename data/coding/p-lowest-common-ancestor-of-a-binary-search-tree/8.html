Common mistakes

Using strict comparisons for the stop test. Writing "stop if p < v < q" misses the case where the node IS p or q, and the walk falls off the tree.

Assuming p.val < q.val. The input does not promise an order. Take min and max first.

Multiplying differences. The popular one-liner (root.val - p.val) * (root.val - q.val) > 0 is neat, but with values up to 109 it overflows in C++, Java and Go unless you cast to 64 bits.

Running the general O(n) LCA. It is correct, but the interviewer asked about a BST precisely to see if you use the ordering.
