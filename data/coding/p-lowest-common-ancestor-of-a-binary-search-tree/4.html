Approaches: brute -> better -> optimal

Hint 1

Compare p and q with the root. In which cases do you know for sure that the root is NOT the answer?

Hint 2

If both are smaller than the root, the answer is somewhere in the left subtree, and the same question repeats there.

1. Brute force - store both root-to-node paths

Idea: find the path from the root to p and to q (in a BST each is a simple search), then walk both lists together; the last common node is the LCA. Or ignore the BST and use the general post-order LCA of LC 236.

O(h)time (O(n) for the general version)
O(h)extra space for the paths

What is wasted: the two paths are identical up to the split point, so we do not need to store them; we only need to walk the shared part once.

2. Better - recursion on one child

Idea: if max(p, q) < root.val, return the answer for root.left; if min(p, q) > root.val, the answer for root.right; otherwise return root.

O(h)time
O(h)call stack

What is wasted: it is tail recursion: nothing happens after the recursive call returns, so the stack frames are pure overhead (and up to 105 of them on a chain).

3. Optimal - the same walk as a loop

lo, hi = min(p.val, q.val), max(p.val, q.val)
node = root
while True:
    if hi < node.val:   node = node.left     # both on the left
    elif lo > node.val: node = node.right    # both on the right
    else:               return node          # they part ways here
O(h)time (log n balanced, n on a chain)
O(1)space

Why it works: invariant: the current node is an ancestor of both p and q (true at the root). If both values are smaller, both are in the left subtree, so the left child is also a common ancestor and is lower: moving keeps the invariant. When lo <= node.val <= hi, either the node is p or q itself, or p and q are in different subtrees; no child can contain both, so no lower common ancestor exists. The node is the LCA.
