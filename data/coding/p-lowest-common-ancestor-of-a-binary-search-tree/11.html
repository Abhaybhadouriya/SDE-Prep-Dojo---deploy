Now the tree is an ordinary binary tree, not a BST.

Post-order DFS: return the node if it is p or q; otherwise search both children. If both searches return non-null, this node is the LCA; else pass up whichever is non-null. O(n) time, O(h) stack.

How to answer

Say what you lose: without ordering you cannot pick a side, so every node may need to be visited.

Likely follow-ups
  • What if p or q might not be in the tree (LC 1644)? Count how many were found and return null if fewer than 2.
Each node has a parent pointer and you are not given the root.

Walk two pointers up from p and q; when one reaches the top, restart it at the other node. They meet at the LCA after at most depth(p) + depth(q) steps, the same trick as the intersection of two linked lists. O(h) time, O(1) space.

How to answer

Draw the two upward paths as two linked lists that merge.

Likely follow-ups
  • Alternative: put p's ancestors in a hash set, then walk up from q (O(h) space).
p and q are given as values that might not exist in the BST.

Find the split node as before, then do two O(h) searches from it to confirm both values exist; return null if either is missing. Still O(h).

How to answer

Ask about this assumption at the start; it is a good clarifying question.

Likely follow-ups
  • Distance between the two nodes: depth(p) + depth(q) - 2 depth(lca), all from the split node.
Answer millions of LCA queries on the same large (not BST) tree.

Preprocess: binary lifting (up[k][v] = 2k-th ancestor) answers each query in O(log n) after O(n log n) setup; an Euler tour plus a sparse table for range-minimum answers in O(1) after O(n log n). For a BST the plain walk is already O(h).

How to answer

Name binary lifting and give its two phases (lift the deeper node, then lift both while ancestors differ).

Likely follow-ups
  • Offline: Tarjan's LCA with union-find in near O(n + q).
What is the complexity if the tree is a chain?

O(n), since h = n. The algorithm is O(h); only a balanced BST (AVL, red-black) guarantees O(log n). The iterative version still uses O(1) space, which is why it is preferred over recursion.

How to answer

Always state complexity in terms of h, then say what h is for balanced and degenerate trees.

Likely follow-ups
  • How would a self-balancing tree keep h = O(log n)? (rotations on insert).
