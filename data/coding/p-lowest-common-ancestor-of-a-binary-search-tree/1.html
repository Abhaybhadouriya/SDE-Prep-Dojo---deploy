The problem (in our words)

You get the root of a binary search tree and two nodes p and q that are both in the tree. Return their lowest common ancestor: the deepest node that has both p and q in its subtree. A node counts as a descendant of itself, so if p is an ancestor of q, the answer is p.

Signature: TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q). The tree is given in LeetCode level order, for example [20,10,30,5,15,25,40,null,null,12,18].

Constraints

  • The number of nodes is in [2, 105].
  • -109 <= Node.val <= 109; all values are unique.
  • p != q, and both p and q exist in the BST.

Practice it: LeetCode 235 · GfG Lowest Common Ancestor in a BST · TUF LCA in BST

Constraints tell you: up to 105 nodes and nothing says the tree is balanced, so the height can be 105 (a sorted insert order makes a chain). A recursive walk can then be 105 frames deep, which overflows Python's default stack; the loop has no such problem. Values up to 109 in magnitude mean (root - p) * (root - q) overflows a 32-bit int, so compare instead of multiplying.
