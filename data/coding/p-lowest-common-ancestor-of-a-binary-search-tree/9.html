60-second recall

  • Cue: two nodes in a BST -> the ordering picks one child per step.
  • Insight: LCA = first node with lo <= val <= hi on the way down (where p and q part).
  • Moves: hi < val -> left; lo > val -> right; else return node.
  • Trap: use <= (node can be p or q); do not assume p < q; no product overflow.
  • Cost: O(h) time, O(1) space as a loop; O(n) only on a degenerate tree.
lo, hi = sorted((p.val, q.val))
while not (lo <= node.val <= hi):
    node = node.left if hi < node.val else node.right
return node

At the current node, p = 12, q = 18 and node.val = 15. What do you do?

  1. Return 15
  2. Go left
  3. Go right
12 <= 15 <= 18: p and q part ways here, so 15 is the LCA.

Why is the answer O(1) space only for the iterative version?

  1. The tree is balanced
  2. BST nodes store parents
  3. Recursion keeps up to h frames on the call stack
The walk is tail recursive; a loop removes the h stack frames.

p = 10 and q = 12, where 12 is inside 10's subtree. The answer is

  1. 10's parent
  2. 10
  3. 12
A node is its own descendant, so the ancestor itself is the LCA: the stop test must use <=.
