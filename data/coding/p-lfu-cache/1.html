The problem (in our words)

Build a class LFUCache that stores key-value pairs up to a fixed capacity and evicts the least frequently used key:

  • LFUCache(int capacity) creates an empty cache that holds at most capacity keys.
  • int get(int key) returns the value of key if it is present, else -1.
  • void put(int key, int value) updates the value of key if it is present, or inserts it. If inserting a new key would exceed capacity, first remove the key with the smallest use count; if several keys share that count, remove the one used least recently among them.
  • Each key has a use counter. A new key starts at 1. Every successful get and every put on an existing key adds 1.
  • get and put must each run in O(1) average time.

Input format (LeetCode): a list of operation names and a list of argument lists; the output is the list of return values, with null for the constructor and for put.

Constraints:

  • 1 <= capacity <= 104
  • 0 <= key <= 105
  • 0 <= value <= 109
  • At most 2 * 105 calls in total to get and put.

Practice it: LeetCode 460 · GfG LFU Cache

Constraints tell you: 2·105 calls with capacity 104 rules out scanning for the victim (2·109 steps). O(log n) with a heap or sorted set would pass, but the spec says O(1), and that is the point of the question. Values up to 109 still fit a 32-bit int.
