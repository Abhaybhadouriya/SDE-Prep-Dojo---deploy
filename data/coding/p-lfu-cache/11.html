Interview follow-ups

Old popular keys never leave. How do you fix that?

Add ageing: periodically halve every count (Redis's LFU decays its counter by time since last access), or count only within a window. Halving every count is O(n) but rare; with buckets you can also relabel whole buckets. Real systems often use TinyLFU: a compact frequency sketch decides whether a newcomer may replace the LRU victim.

How to answer

Name the failure (cache pollution by stale popularity), then one decay scheme.

Likely follow-ups
  • Count-min sketch memory vs exact counts?
You have 20 minutes left. What do you code?

The sorted-set version: map key -> (value, count, tick) and a std::set / TreeSet of (count, tick, key). It is about 25 lines, obviously correct, and O(log n). Then describe how buckets make it O(1).

How to answer

Say the trade-off out loud; a working O(log n) beats a broken O(1).

Likely follow-ups
  • Why is a heap harder here? (Updating a count means a decrease-key or lazy deletion.)
Make it thread-safe.

Every get mutates the structure (count + list move), so a read-write lock does not help; use one mutex, or shard keys into N independent LFU caches each with its own lock. Sharding makes the policy approximate (per-shard LFU), which is usually acceptable.

How to answer

Point out the hidden write in get, then shard.

Likely follow-ups
  • Can hits avoid the lock? Buffer them and apply in batches (what Caffeine does).
Why not a single list sorted by count?

Incrementing a count could require moving the node past many nodes with the same count, which is O(n) in the worst case. Buckets avoid it: the node jumps to the front of the next bucket directly through the count map.

How to answer

Give the worst case (all keys at the same count) in one sentence.

Likely follow-ups
  • Linking buckets instead of a map: when is that needed? (When counts also decrease, as in All O'one.)
Each entry also has a time-to-live.

Store the expiry in the node; treat an expired node as a miss on get and remove it (lazy). For memory, keep a min-heap or timer wheel by expiry and purge on each call. Eviction order: expired keys first, then LFU.

How to answer

Keep the two orders separate: frequency (buckets) and time (heap or wheel).

Likely follow-ups
  • Does a get refresh the TTL? Ask the interviewer.
