Dry run

Example 1, capacity 2. Each row is a use-count bucket (most recent on the left); the ringed row is minFreq; highlighted = the key just used; red = evicted.

  1. put(5,50) then put(8,80): both are new, each starts with 1 use in bucket 1; 8 is newer so it sits left. minFreq = 1.
  2. get(8) twice: each hit moves 8 up one bucket (1 -> 2 -> 3). Bucket 1 still holds 5, so minFreq stays 1.
  3. put(5,55): 5 exists, so the value changes and the call counts as a use: 5 moves to bucket 2. Bucket 1 is now empty and it was minFreq, so minFreq = 2.
  4. put(6,60): full and 6 is new. The victim is the least recent key of bucket minFreq = 2: that is 5. Insert 6 with 1 use; minFreq resets to 1.
  5. get(5): evicted, so -1. A miss changes nothing.
  6. get(6): hit, 6 moves to bucket 2. Bucket 1 is empty and was minFreq: minFreq = 2 (exactly f + 1, because 6 is now there).
  7. put(7,70): full, 7 is new. Bucket 2 holds only 6, so 6 is evicted even though it was just read: 8 has more uses. Insert 7; minFreq = 1.
  8. get(8): hit, 8 moves from bucket 3 to bucket 4. Bucket 1 is untouched, minFreq stays 1.
  9. get(6): 6 was evicted by put(7), so -1.
  10. get(7): hit, 7 moves to bucket 2; bucket 1 empties, so minFreq = 2. Every call did O(1) map and list work.
