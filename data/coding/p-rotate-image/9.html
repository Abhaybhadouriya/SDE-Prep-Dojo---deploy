  • Cue: rotate / flip a square matrix in place.
  • Insight: clockwise (r, c) -> (c, n-1-r) = transpose then reverse each row (anticlockwise: transpose then reverse row order; 180°: both reversals).
  • State: the matrix itself, swapped in place; transpose only the cells with c > r.
  • Trap: inner transpose loop starts at r + 1; check one corner.
  • Cost: O(n²) time, O(1) space.
for r in range(n):
    for c in range(r + 1, n):
        m[r][c], m[c][r] = m[c][r], m[r][c]   # transpose
for row in m:
    row.reverse()                             # mirror left-right

Where does cell (r, c) go after a 90° clockwise turn?

  1. (n-1-c, r)
  2. (c, n-1-r)
  3. (n-1-r, n-1-c)
Row r becomes column n-1-r; column c becomes row c. (n-1-c, r) is the anticlockwise mapping, (n-1-r, n-1-c) the 180° one.

What happens if the transpose loop runs c over 0..n-1?

  1. It still works
  2. It crashes
  3. Every pair is swapped twice, so nothing changes
Pair (r, c) is swapped once at (r, c) and again at (c, r).

How do you turn 90° anticlockwise?

  1. Transpose, then reverse the order of the rows
  2. Transpose, then reverse each row
  3. Reverse each row twice
Transpose gives (c, r); flipping top-bottom gives (n-1-c, r), the anticlockwise mapping.
