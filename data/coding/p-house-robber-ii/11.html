Interview follow-ups

Solve it in a single pass.

Run four variables at once: the line robber over 0..n-2 and the one over 1..n-1, updated in the same loop (index i feeds pass A when i ≤ n-2 and pass B when i ≥ 1). Or carry the "house 0 taken" flag of rung 2. The cost is the same O(n); it only saves one loop.

How to answer

Show that the two passes are independent, so they can share one loop.

Likely follow-ups
  • Is one pass actually faster? (Same work; maybe better cache use for a huge array.)
Return which houses to rob.

Keep the best[] arrays of the winning pass and walk back: if best[i] equals best[i-1], house i was skipped; else it was taken, jump to i-2. Shift indices by 1 for pass B.

How to answer

Reconstruct only for the pass that won.

Likely follow-ups
  • Can you avoid the arrays? (Store one bit per index: taken or not.)
Houses are in a circle and you must rob exactly k of them.

Break the circle the same way, and add the count: best[i][j] = best on the line using j robbed houses, with transition max(best[i-1][j], best[i-2][j-1] + nums[i]). O(n·k) time per pass. LC 1388 (pizza slices) is exactly this with k = n/3.

How to answer

Keep the circle trick; extend only the state.

Likely follow-ups
  • A faster greedy with a heap and "regret" nodes exists for this; mention it only if asked.
Robbed houses must be at least k apart, still in a circle.

Now house 0 conflicts with houses n-k+1..n-1, not only n-1. Case split: house 0 not robbed → line 1..n-1; house 0 robbed → nums[0] + line k..n-k. Each line uses best[i] = max(best[i-1], best[i-k] + nums[i]).

How to answer

Ask which houses an end conflicts with; split on whether that end is taken.

Likely follow-ups
  • Why split on "house 0 taken" instead of "skip each end"? (With k > 2 the two "skip" lines are not enough.)
