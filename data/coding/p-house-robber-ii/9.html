  • Cue: no two adjacent + maximise + items in a circle (first and last touch).
  • Insight: some end is always skipped: answer = max(line(0..n-2), line(1..n-1)).
  • State: line robber: prev2, prev1 = best up to i-2, i-1; take max(prev1, prev2 + x).
  • Trap: n = 1 returns nums[0]; do not drop both ends in one pass.
  • Cost: O(n) time, O(1) space; subsets O(2^n · n).
def line(lo, hi):                       # House Robber I on a[lo..hi]
    p2 = p1 = 0
    for i in range(lo, hi + 1):
        p2, p1 = p1, max(p1, p2 + a[i])
    return p1
return a[0] if n == 1 else max(line(0, n - 2), line(1, n - 1))

Why is it enough to solve the two lines 0..n-2 and 1..n-1?

  1. Every valid circle plan skips house 0 or house n-1
  2. Because the values are non-negative
  3. Because n ≤ 100
The ends are neighbours, so no plan takes both; each plan fits one of the two lines.

What does the circle answer give for [5,1,1,5]?

  1. 10
  2. 5
  3. 6
Line 0..2 gives 5 + 1 = 6, line 1..3 gives 1 + 5 = 6. The line answer 10 uses both ends.

What must the code return for [8]?

  1. 0
  2. 8
  3. 16
One house has no neighbour; both ranges are empty, so handle n = 1 first.
