Interview follow-ups

Edges arrive one at a time; report the count after each.

Union-find is already online: keep the running count and print it after each union. DFS would have to rerun per edge, O(e(n + e)).

How to answer

This is the reason to prefer union-find; say it before being asked.

Likely follow-ups
  • Number of Islands II (LC 305): cells turn into land one by one, same idea on a grid.
Now edges can also be deleted.

Union-find cannot split sets. If all operations are known in advance, process them in reverse (deletions become additions). Fully online deletions need dynamic connectivity structures (link-cut trees or offline divide and conquer), which are beyond a normal interview: say so and give the offline trick.

How to answer

Name the limitation first, then the reverse-time idea.

Likely follow-ups
  • Rerun BFS from the deleted edge's endpoints for a simple O(n + e) per deletion.
Return the size of the largest component.

Union by size already keeps size[root]; the answer is the max over roots (or update a running max on each union). With DFS, count nodes per flood.

How to answer

Point out that the size array is already there for balancing.

Likely follow-ups
  • Count pairs of nodes that cannot reach each other: sum over components of size * (n - size), halved.
Why does union by size plus path halving give near-constant time?

Union by size alone keeps every tree height O(log n), because a node's depth grows only when its tree at least doubles. Adding path halving makes the amortised cost O(α(n)) per operation, the inverse Ackermann function, which is at most 4 for any input that fits in memory.

How to answer

Give the doubling argument for the log bound; quote α(n) without proving it.

Likely follow-ups
  • Path halving vs full path compression: same bound, halving needs no recursion.
The graph is too big for memory and comes as a file of edges.

Union-find needs only O(n) memory for parent and size, and reads each edge once: stream the file. If even n does not fit, shard by node id and merge shard-level union-finds, or use an external-memory connected components algorithm (a MapReduce label propagation).

How to answer

Separate O(n) state from O(e) input; only the state must be in memory.

Likely follow-ups
  • Label propagation converges in O(diameter) rounds.
