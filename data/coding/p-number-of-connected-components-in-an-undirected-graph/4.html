Approaches: brute -> better -> optimal

Hint 1

If you start a flood from one node, which nodes does it reach? How many floods do you need?

Hint 2

Without building any adjacency list: what happens to the count of groups when an edge joins two different groups?

1. Brute force - relabel groups on every edge

Idea: give each node a label label[i] = i. For each edge (a, b) with different labels, scan all n nodes and rewrite every label[b] to label[a]. At the end, count distinct labels.

O(n * e)time
O(n)space

What is wasted: a whole-array rewrite per merge. It passes these limits (107 steps), but it is the "quick-find" baseline that union-find improves on.

2. Better - DFS or BFS from every unvisited node

Idea: build an adjacency list (add both directions). Loop over the nodes; each time you find an unvisited node, the count goes up by one and you flood its whole component (DFS stack or BFS queue), marking everything you reach.

O(n + e)time
O(n + e)space

Why it works: a flood from u visits exactly u's component, because it follows every edge out of every visited node. A later start node is unvisited, so it is in none of the components counted so far: each start is one new component, and every node belongs to exactly one start. This is optimal in time; prefer an explicit stack over recursion when n can be large (a path of 2,000 nodes is fine, 105 may overflow the call stack).

3. Optimal for edge lists - union-find

  1. Start: parent[i] = i, components = n.
  2. For each edge (a, b): find the roots of a and b. Same root -> the edge is inside one component (a cycle edge), skip it. Different roots -> link one root under the other and do components--.
  3. Keep the trees flat: path halving in find (parent[x] = parent[parent[x]]) and union by size (the smaller tree goes under the bigger).
O((n + e) α(n))time
O(n)space

Why it works: invariant: after processing some edges, the union-find sets are exactly the connected components of the graph made of those edges, and components is their number. Adding edge (a, b) either joins two different components into one (count - 1) or lands inside one (count unchanged, and the graph gains a cycle). Order of edges does not matter, because connectivity does not. α(n) is the inverse Ackermann function, at most 4 for any real n, so this is linear in practice. It needs no adjacency list and works even if edges arrive one at a time.

From the top community solutions: which one to choose

The most-voted posts give all three versions. Their common advice: union-find is the shortest to write from an edge list and handles a stream of edges; DFS/BFS is better when you also need the members of each component or when the graph is already an adjacency list. Without union by size, path compression alone still gives O(log n) amortised per operation.
