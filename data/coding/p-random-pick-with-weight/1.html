The problem (in our words)

You are given a 0-indexed array of positive integers w, where w[i] is the weight of index i (think of it as the number of raffle tickets index i bought). Build an object that supports one operation, pickIndex(): it returns a random index in the range [0, w.length - 1], where index i is returned with probability exactly w[i] / sum(w).

For example, with w = [2, 6] index 0 must come back with probability 2/8 = 25% and index 1 with probability 6/8 = 75%.

Signature (LeetCode style): a class Solution with a constructor Solution(int[] w) and a method int pickIndex(). The judge calls the constructor once, then pickIndex() many times, and checks the distribution of the answers, so any output that follows the right probabilities is accepted.

  • 1 <= w.length <= 104
  • 1 <= w[i] <= 105
  • pickIndex is called at most 104 times.

Practice it: LeetCode 528 - Random Pick with Weight

Constraints tell you: the total weight is at most 104 · 105 = 109, which fits in a signed 32-bit int (max about 2.1·109), so the prefix sums do not need 64 bits here. Materialising one slot per ticket (up to 109 slots) is impossible. 104 picks over 104 weights means even O(n) per pick (108) is borderline; O(log n) per pick is the target.
