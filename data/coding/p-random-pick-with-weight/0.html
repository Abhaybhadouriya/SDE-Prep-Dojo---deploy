The story

Explain like I'm 5

A school fair raffle: Asha bought 3 tickets, Ben 1, Chen 4 and Dev 2. Number the tickets 1 to 10 in that order, so Asha holds 1-3, Ben holds 4, Chen holds 5-8 and Dev holds 9-10. Pull one number out of a hat. Whoever holds that number wins. Chen wins 4 times out of 10 because she owns 4 of the 10 numbers. To find the winner fast, you only need the last ticket number of each person: 3, 4, 8, 10.

The whole trick is turning "pick with unequal probabilities" into "pick uniformly, then look up the owner". The uniform part is one call to the random number generator; the lookup is a lower-bound search on a sorted array.

From your world

This is weighted load balancing, as in weighted round-robin for backends or a lottery scheduler for CPU shares: each backend gets a slice of a number range proportional to its weight, and a random draw picks the slice. Kernel and network code often keeps exactly this cumulative-weight table and does a binary search per packet or per connection.
