  • Cue: "pick index i with probability w[i] / sum", many picks -> prefix + draw + lower bound.
  • Insight: index i owns tickets (prefix[i-1], prefix[i]]: w[i] of them.
  • State: prefix array built once; t uniform in [1, total].
  • Trap: [1, total] with >=, or [0, total) with >; never mix. Avoid rand() %.
  • Cost: O(n) build, O(log n) pick, O(n) space; alias method gives O(1) pick.
prefix = list(itertools.accumulate(w))
def pick():
    t = random.randint(1, prefix[-1])
    return bisect.bisect_left(prefix, t)

With w = [2, 5, 3] the prefix array is [2, 7, 10]. Ticket t = 7 is drawn from [1, 10]. Which index does the lower bound (first prefix >= t) pick?

  1. 0
  2. 1
  3. 2
  4. None: 7 is out of range
The first prefix >= 7 is prefix[1] = 7. Index 1 owns tickets 3..7, which is w[1] = 5 tickets.

You switch to drawing t from [0, total). Which search keeps every index's share at w[i] / total?

  1. Lower bound: first prefix >= t
  2. Upper bound: first prefix > t
  3. Either one
  4. Neither: the range must be [1, total]
With t in [0, total), index i owns [prefix[i-1], prefix[i]). For t = 2 with prefix[0] = 2 the lower bound would wrongly give index 0, so index 0 would get 3 tickets instead of 2.

Why is rand() % total a poor draw in C++?

  1. It is too slow for 10^4 picks
  2. RAND_MAX can be as small as 32767, below a total of up to 10^9, and modulo adds bias
  3. It can return negative numbers
  4. It is not allowed on LeetCode
Use std::mt19937 with uniform_int_distribution(1, total): full range and no modulo bias.
