Common mistakes

Off-by-one between the draw and the search. Drawing from [0, total - 1] and then searching for the first prefix >= t gives index 0 the extra ticket t = 0 (w[0] + 1 tickets) and never draws ticket total, so the last index gets one ticket too few; with w = [1, 1] the split becomes 2:0 instead of 1:1. Pair [1, total] with >=, or [0, total) with >.

Using floating point. Normalising weights to probabilities and drawing random() * total works, but rounding can map a draw just below a boundary to the wrong side and makes the code harder to reason about. Integer tickets are exact.

Rebuilding the prefix array inside pickIndex. That turns every pick into O(n). Build once in the constructor.

Random modulo bias in C/C++. rand() % total is biased when total does not divide RAND_MAX + 1, and RAND_MAX can be as small as 32767, far below 109. Use std::uniform_int_distribution with mt19937.

Returning hi or mid from a lo <= hi loop without care. Mixing loop styles gives the wrong index on boundaries. Pick one template (here lo < hi, hi = mid) and return lo.
