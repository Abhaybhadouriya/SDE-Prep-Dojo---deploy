Same direction 1: read and write pointers (compaction)

The problem, in our words. A sorted (non-decreasing) integer array a must be cleaned in place so that each distinct value appears once, keeping their order. Return k, the number of distinct values; the first k slots of a must hold them. What is left after slot k does not matter. 1 <= a.length <= 3 x 104; -100 <= a[i] <= 100. Example: [1, 1, 2, 3, 3, 3, 5] -> k = 4, a starts with [1, 2, 3, 5]. Practice it: LeetCode 26 - Remove Duplicates from Sorted Array, our write-up Remove Duplicates from Sorted Array.

This shape solves a whole group: Remove Element (keep if a[r] != val), Move Zeroes (keep non-zeros, then fill zeros, or swap a[w] and a[r]), and Remove Duplicates II (at most two copies: keep if w < 2 or a[r] != a[w-2], the same template with a 2 instead of a 1).

From your world

This is how you would drop filtered packets from a batch in a poll loop without allocating: walk the descriptor array with one index, copy survivors down with another, and hand back the new count. Writes never overtake reads (w <= r), so nothing unread is ever overwritten, the same reason memmove can copy forward when the destination is below the source.
