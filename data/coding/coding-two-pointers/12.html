Interview questions

Prove that the two-pointer scan for pair sum on a sorted array never misses the answer.

Invariant: if a valid pair exists, both of its indices lie in [lo, hi]. It holds at the start. If a[lo] + a[hi] < target, then for every j in (lo, hi], a[lo] + a[j] <= a[lo] + a[hi] < target, so lo is in no valid pair and dropping it keeps the invariant. The > case is symmetric. Each step shrinks the range, so after at most n - 1 steps we either hit the pair or the range is empty.

How to answer

State the invariant first, prove one move, say "symmetric" for the other, then give the termination argument. The row/column elimination picture is a nice 10-second sketch on the whiteboard.

Likely follow-ups
  • Return all pairs with duplicates handled (skip equal values on both sides after a hit).
  • The array is huge and on disk (two sequential readers, one from each end).
Container with most water: why is it correct to move the shorter wall?

Say h[lo] <= h[hi]. Every container that uses lo together with some j in (lo, hi) is narrower than (lo, hi) and its level is at most h[lo], so its area is less than or equal to the one just measured. So lo cannot be part of a better answer and can be dropped. Moving hi instead could drop the best container.

How to answer

Use the "the level is capped by the shorter wall, the width only shrinks" argument in one sentence; then show the O(n) loop.

Likely follow-ups
  • Trapping rain water (two pointers with leftMax/rightMax; move the side with the smaller max).
  • What if walls have width (still O(n) with the same idea, adjust the width formula).
3Sum: how do you avoid duplicate triplets without a hash set, and what is the complexity?

Sort. Skip i when a[i] == a[i-1]. After recording a hit, advance lo past all copies of a[lo] (and optionally hi past copies of a[hi]). Break when a[i] > 0. Time O(n2): n outer steps, each an O(n) two-pointer scan; sort is O(n log n). Extra space O(1) besides the output (or O(log n) to O(n) for the sort itself, depending on the language).

How to answer

Start from "fix one element, the rest is two-sum on a sorted suffix", then the dedup rules, then complexity. Mention that a hash set works too but costs memory and hides the structure.

Likely follow-ups
  • kSum in general (recursion down to 2Sum: O(nk-1)).
  • Count triplets instead of listing (use counts of equal values to avoid enumerating).
Valid palindrome with at most one deletion: why do you only need to branch once?

Up to the first mismatch the ends match, and any palindrome-after-one-deletion keeps those matches. At the mismatch one of the two characters must be the deleted one, so there are exactly two candidates, each checked by a plain palindrome scan of the inner part. No further branching is allowed because the one deletion is used up. O(n) time, O(1) space.

How to answer

Say the two candidate substrings out loud, write the helper isPal(i, j), and keep the main loop tiny.

Likely follow-ups
  • At most k deletions (that becomes DP: longest palindromic subsequence >= n - k, O(n2)).
  • Ignore non-letters and case (skip with inner while loops).
Sort colors in one pass: state the invariant of the Dutch flag algorithm.

[0, lo) holds 0s, [lo, mid) holds 1s, [mid, hi] is unknown, (hi, n) holds 2s. Each step classifies a[mid] and shrinks the unknown region by one: a 0 is swapped to lo (lo++, mid++), a 1 stays (mid++), a 2 is swapped to hi (hi--, mid stays because the incoming value is unknown). The loop ends when the unknown region is empty, mid > hi. At most n steps, O(1) space.

How to answer

Draw the four regions first, then write three branches. Mention the counting-sort alternative (two passes) to show you know the trade-off.

Likely follow-ups
  • k colours (counting sort in O(n + k), or recursive partitioning in O(n log k)).
  • Stable version (not possible in place in one pass with this method: swaps reorder equal keys).
Merge two sorted arrays in place when the first has room at the end. Why from the back?

The free slots are at the end of a. Filling from the largest value backwards writes only into free slots or into slots whose old values were already copied (w >= i always holds), so nothing unread is overwritten. Front-to-back would overwrite a[0] before reading it, or need an O(m) buffer. O(m + n) time, O(1) space.

How to answer

State the "w never overtakes i" fact, show while j >= 0, and test m = 0 and n = 0 out loud.

Likely follow-ups
  • Merge k sorted arrays (a min-heap of k heads: O(N log k)).
  • Merge without any extra slots at the end (gap method or rotations; rarely asked in full).
Two-sum: hash map or sort plus two pointers? When do you pick each?

Unsorted input and indices required: hash map, O(n) time and O(n) space. Already sorted, or memory is tight and values are enough: two pointers, O(n) (or O(n log n) with the sort) and O(1) extra. Many pair queries on the same static data: sort once, then each query is O(n) with no extra memory, or keep the map for O(1)-per-element checks.

How to answer

Ask "is the input sorted, and do you need original indices?" before coding. That question alone shows pattern awareness.

Likely follow-ups
  • The input is a stream (map; two pointers needs all the data).
  • Design a class with add(x) and find(sum) (trade-off: fast add with a count map, or fast find with a sorted list).
Trapping rain water with two pointers: what is the invariant?

Keep leftMax over [0, lo] and rightMax over [hi, n). If leftMax <= rightMax, the water above lo is decided by leftMax (the right side has a wall at least that tall somewhere), so add leftMax - h[lo] and move lo. Otherwise do the mirror step at hi. Each cell is settled once: O(n) time, O(1) space, versus O(n) space for the prefix-max arrays version.

How to answer

Start from the formula water[i] = min(maxLeft[i], maxRight[i]) - h[i] (prefix arrays), then show that the smaller of the two running maxima is already final, which removes the arrays.

Likely follow-ups
  • The 2D version (a min-heap over the border: Trapping Rain Water II).
  • Solve it with a monotonic stack instead (water is added layer by layer).
