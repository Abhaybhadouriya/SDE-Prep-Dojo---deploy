Common mistakes

  • Two pointers on unsorted data for pair sum. The move rule depends on order; without sorting it silently misses answers.
  • lo <= hi instead of lo < hi in pair problems: lo == hi pairs an element with itself.
  • 3Sum dedup with a set of tuples: correct but slower and it hides that you did not find the invariant. Interviewers notice. Use the two skip rules.
  • Skipping duplicates before recording (skipping lo copies before checking the sum) loses triplets like [-2, 1, 1] that use two equal values.
  • Moving the taller wall in the container problem, or moving both walls on a tie "to be safe" and then missing the next measurement.
  • Advancing mid after a swap with hi in Dutch flag, or looping with mid < hi.
  • Merging from the front of the same buffer, which overwrites unread values.
  • Overflow in 4Sum and in container area: values up to 109 summed four times, or 105 x 104 = 109 area (fits in 32-bit, but 4Sum sums do not). Use 64-bit when in doubt.
