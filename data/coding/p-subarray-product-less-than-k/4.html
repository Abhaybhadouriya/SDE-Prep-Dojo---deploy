Approaches: brute -> better -> optimal

Hint 1

Fix the right end of the subarray. Which starts are valid for it?

Hint 2

If [i..r] is valid, is [i+1..r] valid too? What does that say about the set of valid starts?

Hint 3

Keep the smallest valid start in a pointer. How many subarrays end at r then?

1. Brute force - every start, extend while the product is small

Idea: for each start i, multiply forward; count each j while the product stays below k, and stop at the first j where it does not (positive values: it can only grow from there).

O(n²)time (early break helps, worst case all ones)
O(1)space

What is wasted: moving the start from i to i+1 recomputes the same products again. -> rung 2 or 3.

2. Better - logarithms, prefix sums and binary search

Idea: products turn into sums under log: prod(i..j) < k iff pre[j+1] - pre[i] < log k, where pre is the prefix sum of log(nums[x]). pre is non-decreasing (all logs >= 0), so for each i a binary search finds the largest valid j. The official editorial lists this as its second approach.

O(n log n)time
O(n)space

What is wasted: floating point needs an epsilon (products exactly equal to k must not count), and the boundary moves monotonically anyway, so a pointer can replace the search. -> rung 3.

3. Optimal - sliding window, add the window size

if k <= 1: return 0
for right, x in enumerate(nums):
    prod *= x
    while prod >= k:                     # too big: shrink
        prod //= nums[left]; left += 1
    count += right - left + 1            # all valid subarrays ending at right
  1. Invariant: after the inner loop, prod is the product of nums[left..right] and it is < k; left is the smallest such start.
  2. Count by right end. The subarrays ending at right that are valid are exactly those starting in [left, right]: right - left + 1 of them. Each subarray has one right end, so none is counted twice.
  3. The guard k <= 1 matters: with k = 1, even the empty window has product 1, and while prod >= k would run left past right.
O(n)time, each index enters and leaves once
O(1)space

Why it works: all values are >= 1, so removing elements can only lower the product and adding can only raise it. If start s is too small for end r (product >= k), it is also too small for every later end, so left never has to come back. And once [left..right] is valid, every part of it that still ends at right is valid too. Those two facts are the whole proof.

Overflow check (optional)

Before multiplying, prod < k <= 10^6, and nums[right] <= 1000, so prod never exceeds about 10^9. That fits in a 32-bit int, but our C++/Java code uses a 64-bit type anyway so a changed constraint does not silently break it. Division is exact because nums[left] is a factor of prod; in Python use //=, not /=, to stay in integers.
