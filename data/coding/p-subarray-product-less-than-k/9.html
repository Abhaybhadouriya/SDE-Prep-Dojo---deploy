  • Cue: count subarrays with product (or sum) < k, all values positive -> sliding window.
  • Insight: per right end, the valid starts are one block [left, right]: add right - left + 1.
  • State: left, prod of the window, count.
  • Trap: k <= 1 returns 0; shrink while prod >= k (not >).
  • Cost: O(n) time, O(1) space; logs + binary search O(n log n).
left = count = 0; agg = identity
for right, x in enumerate(a):
    agg = add(agg, x)
    while left <= right and bad(agg):
        agg = remove(agg, a[left]); left += 1
    count += right - left + 1

Why do we add right - left + 1 and not 1?

  1. To count the window itself
  2. Every subarray ending at right that starts in [left, right] is valid
  3. Because k is positive
A part of a valid window that keeps the same right end has a product no larger, so it is valid too.

What breaks if nums can contain 0?

  1. Growing a window can make the product drop, so the window logic fails
  2. Nothing
  3. Only the overflow check
Any window containing a 0 has product 0 < k, so validity is no longer monotone in the usual way and division by 0 appears.

k = 1, nums = [1,1]. Answer?

  1. 3
  2. 2
  3. 0
Every product is at least 1, and the condition is strictly less than k.
