Generalise to "more than n/k times".

Keep k - 1 (value, count) slots, in a small map. A matching value increments its slot; otherwise it takes an empty slot; otherwise decrement every slot and drop zeros. Verify the at most k - 1 survivors. O(nk) time, O(k) space.

How to answer

Repeat the counting argument: each decrement-all throws away k different values, at most one copy of any heavy value.

Likely follow-ups
  • Make the decrement-all cheaper: an amortised argument shows total decrements ≤ n.
Why can there be at most two answers?

Three values with more than n/3 copies each would need more than n cells in total. So two slots suffice.

How to answer

Say it before coding: it justifies the O(1) state.

The data is a stream you can read only once. What changes?

One pass gives the candidates with no false negatives, but you cannot verify. Either keep exact counts for the survivors from that point (approximate), accept false positives, or report the Misra-Gries counters with their error bound (each count is under by at most n/k).

How to answer

Name Misra-Gries and the guarantee: true frequency - n/k ≤ counter ≤ true frequency.

Likely follow-ups
  • Merging summaries from many machines: add matching counters, then subtract the k-th largest from all.
Return the answer sorted, as GfG asks.

At most two values: compare and swap. Sorting a list of size 2 is O(1), so the total stays O(n).

Can you use the sorting trick from Majority Element I?

Partly: after sorting, any value with more than n/3 copies must cover index n/3 or index 2n/3 (a run longer than n/3 cannot fit between them). Check the values at those two indices with binary search for their run lengths. O(n log n) time.

How to answer

Good to show range; then move to the vote for O(n) / O(1).
