Approaches: brute -> better -> optimal

Hint 1

How many values can possibly appear more than n/3 times?

Hint 2

If you remove three different values from the array, does any value that was above n/3 drop below the new n/3?

1. Brute force - count each value

Idea: for each index, count its value over the whole array; add it to the answer if the count exceeds n/3 and it is not already there.

O(n²)time
O(1)space

What is wasted: the same value is recounted for every copy.

2. Better - hash map, or sort

Hash map: count everything in one pass, then collect keys with count > n/3. O(n) time, O(n) space. The most-voted community post shows this as the interview's natural first answer.

Sort: after sorting, equal values form runs; scan the runs and keep those longer than n/3. O(n log n) time, O(1) extra in place (mutates the input).

O(n) / O(n log n)time (map / sort)
O(n) / O(1)space

What is wasted: the map stores counts for up to n values, yet at most two can matter.

3. Optimal - two-slot Boyer-Moore vote + verify

  1. Pass 1 - elect two candidates. For each x: if it equals candidate 1, bump count 1; else if it equals candidate 2, bump count 2; else if count 1 is 0, x takes slot 1; else if count 2 is 0, x takes slot 2; otherwise decrement both counts.
  2. Pass 2 - verify. Count the two candidates exactly and keep those with count > ⌊n/3⌋.

Why it works (the triple argument): the "decrement both" branch throws away three different values at once: one copy of candidate 1, one copy of candidate 2, and x. Suppose t triples are thrown away; then 3t ≤ n. A value v with more than n/3 copies loses at most one copy per triple, so it keeps more than n/3 - t ≥ 0 copies. Every copy not thrown away is sitting in one of the two slots at the end, so v must be one of the two final candidates. The converse is false (a survivor might be light), which is exactly why pass 2 exists.

Why check "matches a slot" before "slot is empty"?

If x equals candidate 2 but count 1 is 0, checking emptiness first would put x into slot 1 as well. Now both slots hold the same value, one real candidate is lost, and the verification pass would count the same value twice and report it twice. Always test both matches first.

O(n)time, two passes
O(1)space
