60-second recall

  • Cue: more than n/3 (n/k) times, O(1) space -> k - 1 candidate slots.
  • Insight: drop triples of different values; a heavy value loses at most one copy per triple.
  • Order: match slot 1, match slot 2, empty slot 1, empty slot 2, else decrement both.
  • Trap: always verify; survivors can be light. Different placeholders.
  • Cost: O(n) time (2 passes), O(1) space; hash map O(n)/O(n).
c1, c2, n1, n2 = 0, 1, 0, 0
for x in a:
    if x == c1: n1 += 1
    elif x == c2: n2 += 1
    elif n1 == 0: c1, n1 = x, 1
    elif n2 == 0: c2, n2 = x, 1
    else: n1 -= 1; n2 -= 1
ans = [c for c in (c1, c2) if a.count(c) > len(a) // 3]

Quick quiz

How many candidate slots do you need for "more than n/4 times"?

  1. 1
  2. 2
  3. 3
  4. 4
At most k - 1 = 3 values can each exceed n/4 (four of them would need more than n cells).

Why is the second pass needed even though at most two answers exist?

  1. The first pass may miss a heavy value
  2. A survivor may appear only once or twice
  3. The order of the answer must be sorted
  4. The counts overflow
The vote never misses a heavy value, but it may keep a light one; only exact counting rejects it.

In the "decrement both" branch, what is thrown away?

  1. Three different values: one copy of each candidate and x
  2. Two copies of the same value
  3. The whole prefix seen so far
  4. Only x
That triple contains at most one copy of any heavy value, which is the whole proof.
