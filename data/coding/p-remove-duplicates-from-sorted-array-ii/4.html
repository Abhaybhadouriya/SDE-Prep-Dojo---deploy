Approaches: brute -> better -> optimal

Hint 1

Solve "keep one copy" first: a value is new when it differs from the last value you kept.

Hint 2

With at most two copies, which kept slot tells you whether two copies of x are already in?

1. Brute force - count runs into a second array

Idea: walk the runs of equal values, append min(run length, 2) copies of each to a new list, then copy the list back over the start of nums and return its length.

O(n)time
O(n)extra space

What is wasted: the second buffer, which the task forbids. It is still worth saying aloud: it is exactly the reference our tests compare against. -> rung 2.

2. Better - in place with a run counter, shifting the tail

Idea: scan with a counter of how many times the current value has appeared. When the counter passes 2, delete the element by shifting everything after it one slot left (or call erase) and shrink the logical length.

O(n²)time (long runs)
O(1)extra space

What is wasted: a kept value is moved once for every deleted element before it. Each kept value has exactly one final slot (the current write position), so it can be dropped there directly with one write. -> rung 3.

3. Optimal - write pointer with a guard two slots back

k = 0
for x in nums:
    if k < 2 or x != nums[k - 2]:
        nums[k] = x; k += 1
return k
  1. The prefix is the answer so far. nums[0..k-1] holds the thinned, sorted output for everything read so far.
  2. The first two always stay. While k < 2 no value can have two copies kept yet.
  3. The guard decides. The prefix is sorted and x is at least every kept value. If nums[k-2] == x, then nums[k-1], which lies between them, equals x too: two copies are already in, so skip. Otherwise at most one copy is in, so write.
  4. Writes never destroy unread input. k ≤ i at all times, so slot k has already been read.
O(n)time
O(1)extra space

Why it works: the loop keeps the invariant "nums[0..k-1] = the original nums[0..i-1] with every run cut to at most two". A value x is appended exactly when fewer than two copies of x sit at the end of the prefix, and in a sorted prefix those copies can only be the last two slots, so checking slot k-2 is enough. Replace 2 by m and the same argument gives "at most m copies"; m = 1 is LeetCode 26.

Proof (optional)

Why compare with nums[k-2] and not nums[i-2]? Slot i-2 may already have been overwritten by a write, so it no longer holds the input value. Example: on [1,1,1,2,2,3], i = 3 writes the first 2 into slot 2 (over a 1). At i = 4 the input test reads nums[i-2] = nums[2], which is now that written 2, equal to x, so the second 2 is wrongly dropped and the function returns 4 instead of 5. The kept-prefix form only reasons about the output, which is never rewritten behind k, so its proof is the two-line invariant above. The x > nums[k-2] form in some solutions is the same test: in sorted input x ≥ nums[k-2] always holds.
