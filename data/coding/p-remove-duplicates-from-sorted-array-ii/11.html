Make it work for "at most m copies" for any m.

Keep x if k < m or x != nums[k - m]. The proof is unchanged: in the sorted kept prefix, nums[k-m] == x means the last m kept values are all x.

How to answer

Write the general function first and call it with m = 2; show that m = 1 is LeetCode 26.

Likely follow-ups
  • m = 0? (Return 0; guard it, since nums[k-0] would read slot k.)
The array is not sorted. Keep each value at most twice, first occurrences first.

The same write loop, but the "how many kept?" test needs a hash map value -> kept count: O(n) time, O(n) space. Order of first appearance is preserved because we still scan left to right.

How to answer

Point out that sorting is what made the O(1) guard possible; without it you pay memory or O(n log n) sorting (and lose the order).

Likely follow-ups
  • Values in a small range? (A counting array is O(range) space, O(1) if the range is fixed.)
Do the same on a sorted linked list.

Keep a pointer to the last kept node and a count for its value; when the next node has the same value and the count is already 2, unlink it. O(n) time, O(1) space. No write pointer is needed because unlinking is O(1).

How to answer

Contrast: arrays need compaction because deletion is O(n); lists need careful pointer rewiring instead.

Likely follow-ups
  • Drop every value that appears more than once? (LeetCode 82: dummy head, skip whole runs.)
The data is a sorted stream too large for memory. Emit the thinned stream.

Keep only the last two emitted values (or the current value and its count). For each incoming x, emit it unless it equals the value emitted two steps ago. O(1) memory, one pass, the same guard as the array version.

How to answer

Show that the array was only ever needed as a two-slot history: this is a filter with constant state.

Likely follow-ups
  • Several sorted streams? (Merge them with a heap first, then apply the filter.)
Return the removed values too, or count how many were removed.

Removed count is just n - k. To list them, note that every skipped x is one removed copy; collect them in the skip branch (O(n) output space).

How to answer

Keep the loop; add work only in the skip branch.

Likely follow-ups
  • Restore the original array afterwards? (Not possible in place: the overwritten slots are lost unless you saved the removed values with their positions.)
