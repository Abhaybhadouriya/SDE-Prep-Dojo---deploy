The problem (in our words)

A weather station returns an integer array nums of readings, sorted in non-decreasing order. Thin it in place so that every distinct reading appears at most twice, keeping the readings in their original (sorted) relative order. If k readings remain, they must occupy the first k slots of nums; whatever is left in slots k and later is ignored. Return k.

Signature: int removeDuplicates(int[] nums). You may not allocate another array: the change happens in the given array with O(1) extra memory. The judge calls your function, asserts that the returned k equals the expected length, and then compares nums[0..k-1] with the expected array element by element.

Constraints:

  • 1 <= nums.length <= 3 * 104
  • -104 <= nums[i] <= 104
  • nums is sorted in non-decreasing order.

Practice it: LeetCode 80 · warm-up on GfG: Remove duplicate elements from sorted array (one copy instead of two).

Constraints tell you: n ≤ 3·104 would allow O(n²), but "in place, O(1) extra memory" forbids a second array or a counting map. n ≥ 1, so the first two slots (when they exist) are always kept. Sorted input is the key: all copies of a value are adjacent, so the kept prefix is sorted too, and "how many copies are kept" can be read off the prefix.
