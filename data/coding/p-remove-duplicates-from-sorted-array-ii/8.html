Common mistakes

Comparing with the input, nums[i-2]. Slots behind i may already hold written values, so the test reads the output in some places and the input in others. Compare with the kept prefix, nums[k-2].

Comparing with nums[k-1] only. That is the one-copy rule (LeetCode 26); it drops the second copy of every value.

Reading nums[k-2] before checking k < 2. In C++/Java that is an out-of-bounds read at k = 0 or 1; in Python nums[-2] silently reads the wrong end. Put k < 2 first so the || short-circuits.

Keeping a run counter and forgetting to reset it. A counter works, but it must reset to 1 whenever the value changes; the guard version has no counter to get wrong.
