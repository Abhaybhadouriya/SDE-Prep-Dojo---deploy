Revision card

  • Cue: sorted + in place + "each value at most m times" -> read/write pointers.
  • Insight: keep x iff k < m or x != nums[k-m]; the KEPT prefix is sorted, so that slot counts copies.
  • State: k = number kept (starts 0); x = each value read in order.
  • Trap: compare with nums[k-2] (output), never nums[i-2] (may be overwritten).
  • Cost: O(n) time, O(1) space; shifting is O(n²); m = 1 gives LeetCode 26.
k = 0
for x in nums:
    if k < m or x != nums[k - m]:   # fewer than m copies kept
        nums[k] = x; k += 1
return k

For [2,2,2,2,6,6,6] (at most two copies), what is returned?

  1. 7
  2. 2
  3. 4
  4. 5
Two 2s and two 6s are kept: [2,2,6,6], so k = 4.

Why is checking only nums[k-2] enough?

  1. The kept prefix is sorted, so nums[k-2] == x forces nums[k-1] == x
  2. Values are small
  3. k starts at 0
  4. The input has no negatives
nums[k-2] ≤ nums[k-1] ≤ x; if the outer two are equal, the middle one is too.

To allow at most 3 copies, the test becomes...

  1. x != nums[k-1]
  2. k < 3 or x != nums[k-3]
  3. x != nums[i-3]
  4. k < 2 or x != nums[k-2]
Replace 2 by m everywhere: the guard is m slots back in the kept prefix.
