What a heap really is: a tree inside an array

A binary heap is a complete binary tree (every level full, the last one filled from the left) with one rule. In a min-heap, every parent is <= its children. In a max-heap, every parent is >= its children. The rule only links parent and child, so siblings and cousins are in no order. That "half sorted" state is cheap to keep.

Because the tree is complete, it needs no pointers. It lives in a plain array, level by level:

Both operations keep the shape first, then fix the order along a single root-to-leaf path. A path has only log2 n nodes, so both are O(log n):

  • Sift up (after push): put the new item at the end, then swap it with its parent while it is smaller.
  • Sift down (after pop): move the last item to the root, then swap it with its smaller child while it is bigger.
  1. A min-heap of five numbers: [2, 4, 3, 9, 6]. The root (2) is the smallest. Nothing else is sorted.
  2. push(1): put the new value in the first free slot, index 5. The shape stays complete, but 1 may be smaller than its parent.
  3. Sift up: parent of 5 is (5-1)/2 = 2, holding 3. 1 < 3, so swap. One comparison per level.
  4. Parent of 2 is 0, holding 2. 1 < 2, swap again. We reached the root: push cost = height = O(log n).
  5. pop(): the answer is the root (1). Fill the hole with the LAST element (3) so the array stays gap-free.
  6. Sift down: compare 3 with the SMALLER child (2 at index 2) and swap. Index 2 has no children, so stop. Also O(log n).

Building a heap from n items you already have is O(n) with heapify (sift down from the last parent back to the root), because most nodes sit near the bottom. Python's heapq.heapify, C++'s make_heap and Java's new PriorityQueue<>(collection) all do this.
