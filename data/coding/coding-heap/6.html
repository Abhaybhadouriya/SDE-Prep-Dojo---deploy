Heap vs quickselect vs bucket sort (and the timer wheel)

"Find the k-th largest" has three standard answers. Interviewers like to hear all three, with the trade-off:

MethodTimeExtra spaceWorks on a stream?When to pick it
Sort everythingO(n log n)O(1)-O(n)noBaseline; fine when n is small
Size-k heapO(n log k)O(k)yesDefault answer; k much smaller than n; online data
QuickselectO(n) average, O(n2) worstO(1), changes the arraynoOne k-th value, offline, array may be changed; use a random pivot
Bucket sort by keyO(n + range)O(n + range)noKeys are small integers, e.g. counts in Top K Frequent (count <= n)

Quickselect is the partition step of quicksort, but it recurses into only one side. A random pivot makes the expected work n + n/2 + n/4 + ... = O(n). Use a 3-way partition (less / equal / greater) so that arrays full of duplicates do not turn quadratic:

// Quickselect (3-way partition), average O(n).
func quickselectKthLargest(nums []int, k int) int {
	a := append([]int(nil), nums...)
	target, lo, hi := len(a)-k, 0, len(a)-1
	rng := rand.New(rand.NewSource(12345))
	for {
		p := a[lo+rng.Intn(hi-lo+1)]
		lt, i, gt := lo, lo, hi
		for i <= gt {
			if a[i] < p {
				a[lt], a[i] = a[i], a[lt]
				lt++
				i++
			} else if a[i] > p {
				a[gt], a[i] = a[i], a[gt]
				gt--
			} else {
				i++
			}
		}
		if target < lt {
			hi = lt - 1
		} else if target > gt {
			lo = gt + 1
		} else {
			return p
		}
	}
}
// Quickselect (3-way partition), average O(n).
int quickselectKthLargest(vector<int> a, int k) {
    int target = (int)a.size() - k, lo = 0, hi = (int)a.size() - 1;
    mt19937 rng(12345);
    while (true) {
        int p = a[lo + (int)(rng() % (unsigned)(hi - lo + 1))];
        int lt = lo, i = lo, gt = hi;
        while (i <= gt) {
            if (a[i] < p) swap(a[lt++], a[i++]);
            else if (a[i] > p) swap(a[gt--], a[i]);
            else i++;
        }
        if (target < lt) hi = lt - 1;
        else if (target > gt) lo = gt + 1;
        else return p;
    }
}
// Quickselect (3-way partition), average O(n).
static int quickselectKthLargest(int[] nums, int k) {
    int[] a = nums.clone();
    int target = a.length - k, lo = 0, hi = a.length - 1;
    Random rng = new Random(12345);
    while (true) {
        int p = a[lo + rng.nextInt(hi - lo + 1)];
        int lt = lo, i = lo, gt = hi;
        while (i <= gt) {
            if (a[i] < p) { int t = a[lt]; a[lt++] = a[i]; a[i++] = t; }
            else if (a[i] > p) { int t = a[gt]; a[gt--] = a[i]; a[i] = t; }
            else i++;
        }
        if (target < lt) hi = lt - 1;
        else if (target > gt) lo = gt + 1;
        else return p;
    }
}
def quickselect_kth_largest(nums, k):
    """Average O(n): partition until the pivot lands at index n-k (3-way to survive duplicates)."""
    import random
    a = list(nums)
    target = len(a) - k
    lo, hi = 0, len(a) - 1
    while True:
        p = a[random.randint(lo, hi)]
        lt, i, gt = lo, lo, hi
        while i <= gt:
            if a[i] < p:
                a[lt], a[i] = a[i], a[lt]; lt += 1; i += 1
            elif a[i] > p:
                a[gt], a[i] = a[i], a[gt]; gt -= 1
            else:
                i += 1
        if target < lt:
            hi = lt - 1
        elif target > gt:
            lo = gt + 1
        else:
            return p

Bucket sort for Top K Frequent: a value's count is between 1 and n, so make n + 1 buckets, put each value in bucket[count], and read the buckets from the high end until you have k values. That is O(n) with no comparisons at all:

def top_k_frequent_bucket(nums, k):
    cnt = Counter(nums)
    buckets = [[] for _ in range(len(nums) + 1)]
    for val, c in cnt.items():
        buckets[c].append(val)
    out = []
    for c in range(len(nums), 0, -1):
        for val in buckets[c]:
            out.append(val)
            if len(out) == k:
                return out
    return out

From your world

The Linux timer wheel is bucket sort for deadlines. Most kernel timers (retransmits, timeouts) are cancelled before they fire, so O(1) insert and cancel beat exact order (the LWN article in Resources covers the rework that traded far-timer precision for no cascading). hrtimers need exact order, so they use a red-black tree: the heap's role. Interview rule: small integer keys and no order needed inside a key means buckets; otherwise a heap.
