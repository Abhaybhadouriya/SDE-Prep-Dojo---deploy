How to recognise a heap problem

Cue words: "k largest / k smallest / k closest / k most frequent", "k-th largest", "merge k sorted", "always pick the most / least ...", "next available room / server / CPU", "median of a stream", "maximise profit with limited picks", "cooldown between equal tasks".

  1. The best item changes over time. Items arrive, or get used up, and you need the current best every round. A sort done once cannot follow the changes. A heap can.
  2. You need only the top, not the full order. Sorting everything is O(n log n). A size-k heap is O(n log k), and k is often tiny.
  3. You merge several sorted streams. Only the k heads can be next: put them in a heap.
  4. Two sets of things with different keys (rooms free vs busy, projects locked vs unlocked, lower half vs upper half): use two heaps, or a sorted array plus one heap.

Counter-cue: one k-th value from offline data means quickselect (O(n) average); small integer keys mean bucket sort (O(n)).
