Pattern 3: scheduling with one or two heaps

Scheduling problems have a clock and a greedy rule: "pick the best one available now". A heap holds the available items; a second structure (heap, sorted array or queue) holds the not yet available ones, ordered by when they become available. Three classic problems show the three forms.

Task Scheduler: one max-heap plus a cooldown queue

Task Scheduler: CPU tasks are letters; each unit of time runs one task or stays idle, and two equal tasks need at least n units between them. Find the shortest total time. Greedy: at each tick, run the available task with the most remaining copies, because it is the one most likely to force idle time later. A max-heap holds the counts of available tasks; a FIFO queue holds cooling tasks with the tick they are ready again. The follow-up is the counting formula, straight from the picture:

// Task scheduler, O(N) counting formula.
func leastInterval(tasks []byte, n int) int {
	var cnt [26]int
	mx, ties := 0, 0
	for _, c := range tasks {
		cnt[c-'A']++
	}
	for _, c := range cnt {
		if c > mx {
			mx = c
		}
	}
	for _, c := range cnt {
		if c == mx {
			ties++
		}
	}
	if v := (mx-1)*(n+1) + ties; v > len(tasks) {
		return v
	}
	return len(tasks)
}
// Task scheduler, O(N) counting formula (the heap simulation gives the same number).
int leastInterval(const vector<char>& tasks, int n) {
    int cnt[26] = {0};
    for (char c : tasks) cnt[c - 'A']++;
    int mx = *max_element(cnt, cnt + 26), ties = 0;
    for (int c : cnt) if (c == mx) ties++;
    return max((int)tasks.size(), (mx - 1) * (n + 1) + ties);
}
// Task scheduler, O(N) counting formula.
static int leastInterval(char[] tasks, int n) {
    int[] cnt = new int[26];
    for (char c : tasks) cnt[c - 'A']++;
    int mx = Arrays.stream(cnt).max().getAsInt(), ties = 0;
    for (int c : cnt) if (c == mx) ties++;
    return Math.max(tasks.length, (mx - 1) * (n + 1) + ties);
}
def least_interval(tasks, n):
    """Task scheduler: max-heap of remaining counts + cooldown queue, simulated per time unit."""
    from collections import deque
    h = [-c for c in Counter(tasks).values()]
    heapq.heapify(h)
    cool = deque()                    # (time when ready again, -remaining)
    t = 0
    while h or cool:
        t += 1
        if h:
            c = heapq.heappop(h) + 1  # run one unit of the most frequent task
            if c:
                cool.append((t + n, c))
        if cool and cool[0][0] == t:
            heapq.heappush(h, cool.popleft()[1])
    return t

def least_interval_formula(tasks, n):
    """Same answer in O(N): frame of (maxCount-1) blocks of size n+1, plus the tasks tied at maxCount."""
    cnt = Counter(tasks).values()
    mx = max(cnt)
    ties = sum(1 for c in cnt if c == mx)
    return max(len(tasks), (mx - 1) * (n + 1) + ties)

Why it is right: task A alone forces the frame (max - 1)(n + 1) + ties; if other tasks overflow it, widen the blocks and no idle slot is needed, so the answer is the task count. Hence the max(...). Reorganize String is the same idea with n = 1: it fails exactly when the top count is more than (len + 1) / 2.

Meeting Rooms III: two heaps, free and busy

Meeting Rooms III: n rooms 0..n-1, meetings with distinct starts. A meeting takes the lowest-numbered free room; if none is free it waits for the room that frees first (lowest number on ties) and keeps its duration. Return the room used most (lowest number on ties).

  • free: a min-heap of room numbers.
  • busy: a min-heap of (end time, room).
  • For each meeting in start order: move every busy room with end <= start back to free. If free is not empty, take its smallest room. Otherwise pop the earliest busy room and push it back with end + duration.

Time O(m log m + m log n). The trap is overflow: with up to 105 delayed meetings of length up to 5 · 105, end times can pass 231. Use 64-bit ends.

IPO: a sorted array plus a max-heap

IPO: you start with capital w and may finish at most k projects. Project i needs capital[i] to start and adds profits[i] when done. Maximise the final capital. Sort projects by capital. Each round, a pointer unlocks every newly affordable project into a max-heap of profit; take the top. The biggest profit is never worse: it unlocks a superset of what a smaller pick would.

// Meeting rooms III: free = rooms by id (IntMinHeap), busy = (end, room) in ItemHeap.
// int is 64-bit on every Go target interviewers use, so ends up to ~5e10 fit.
func mostBooked(n int, meetings [][]int) int {
	sort.Slice(meetings, func(i, j int) bool { return meetings[i][0] < meetings[j][0] })
	free := &IntMinHeap{}
	for r := 0; r < n; r++ {
		*free = append(*free, r) // 0..n-1 is already a valid heap
	}
	busy := &ItemHeap{}
	count := make([]int, n)
	for _, m := range meetings {
		s, e := m[0], m[1]
		for busy.Len() > 0 && (*busy)[0].key <= s {
			heap.Push(free, heap.Pop(busy).(Item).a)
		}
		var r int
		if free.Len() > 0 {
			r = heap.Pop(free).(int)
			heap.Push(busy, Item{e, r, 0})
		} else {
			b := heap.Pop(busy).(Item)
			r = b.a
			heap.Push(busy, Item{b.key + (e - s), r, 0})
		}
		count[r]++
	}
	best := 0
	for r := 1; r < n; r++ {
		if count[r] > count[best] {
			best = r
		}
	}
	return best
}

// IPO: sort by capital, unlock affordable projects into a max-heap (store -profit in a min-heap).
func findMaximizedCapital(k, w int, profits, capital []int) int {
	idx := make([]int, len(profits))
	for i := range idx {
		idx[i] = i
	}
	sort.Slice(idx, func(a, b int) bool { return capital[idx[a]] < capital[idx[b]] })
	h := &IntMinHeap{}
	i := 0
	for ; k > 0; k-- {
		for i < len(idx) && capital[idx[i]] <= w {
			heap.Push(h, -profits[idx[i]])
			i++
		}
		if h.Len() == 0 {
			break
		}
		w += -heap.Pop(h).(int)
	}
	return w
}
// Meeting rooms III: free rooms by id, busy rooms by (end, id). Ends can reach ~5e10: use long long.
int mostBooked(int n, vector<vector<int>> meetings) {
    sort(meetings.begin(), meetings.end());
    priority_queue<int, vector<int>, greater<int>> freeRooms;
    for (int r = 0; r < n; r++) freeRooms.push(r);
    typedef pair<long long, int> B;
    priority_queue<B, vector<B>, greater<B>> busy;
    vector<int> count(n, 0);
    for (auto& m : meetings) {
        long long s = m[0], e = m[1];
        while (!busy.empty() && busy.top().first <= s) { freeRooms.push(busy.top().second); busy.pop(); }
        int r;
        if (!freeRooms.empty()) { r = freeRooms.top(); freeRooms.pop(); busy.push(B(e, r)); }
        else { B b = busy.top(); busy.pop(); r = b.second; busy.push(B(b.first + (e - s), r)); }
        count[r]++;
    }
    return int(max_element(count.begin(), count.end()) - count.begin());   // first max = smallest id
}

// IPO: sort by capital, unlock affordable projects into a max-heap of profit.
int findMaximizedCapital(int k, int w, const vector<int>& profits, const vector<int>& capital) {
    vector<pair<int, int>> p;
    for (size_t i = 0; i < profits.size(); i++) p.push_back(make_pair(capital[i], profits[i]));
    sort(p.begin(), p.end());
    priority_queue<int> h;                                  // max-heap
    size_t i = 0;
    while (k-- > 0) {
        while (i < p.size() && p[i].first <= w) h.push(p[i++].second);
        if (h.empty()) break;
        w += h.top(); h.pop();
    }
    return w;
}
// Meeting rooms III: free rooms by id, busy rooms by (end, id). Ends need long.
static int mostBooked(int n, int[][] meetings) {
    Arrays.sort(meetings, (a, b) -> Integer.compare(a[0], b[0]));
    PriorityQueue<Integer> free = new PriorityQueue<>();
    for (int r = 0; r < n; r++) free.offer(r);
    PriorityQueue<long[]> busy = new PriorityQueue<>((a, b) -> a[0] != b[0] ? Long.compare(a[0], b[0]) : Long.compare(a[1], b[1]));
    int[] count = new int[n];
    for (int[] m : meetings) {
        long s = m[0], e = m[1];
        while (!busy.isEmpty() && busy.peek()[0] <= s) free.offer((int) busy.poll()[1]);
        int r;
        if (!free.isEmpty()) { r = free.poll(); busy.offer(new long[]{e, r}); }
        else { long[] b = busy.poll(); r = (int) b[1]; busy.offer(new long[]{b[0] + (e - s), r}); }
        count[r]++;
    }
    int best = 0;
    for (int r = 1; r < n; r++) if (count[r] > count[best]) best = r;   // ties keep the smaller id
    return best;
}

// IPO: sort by capital, unlock affordable projects into a max-heap of profit.
static int findMaximizedCapital(int k, int w, int[] profits, int[] capital) {
    int n = profits.length;
    Integer[] idx = new Integer[n];
    for (int i = 0; i < n; i++) idx[i] = i;
    Arrays.sort(idx, (a, b) -> Integer.compare(capital[a], capital[b]));
    PriorityQueue<Integer> h = new PriorityQueue<>(Collections.reverseOrder());
    int i = 0;
    while (k-- > 0) {
        while (i < n && capital[idx[i]] <= w) h.offer(profits[idx[i++]]);
        if (h.isEmpty()) break;
        w += h.poll();
    }
    return w;
}
def most_booked(n, meetings):
    """Meeting rooms III: free rooms (min room id) + busy rooms (min end time, then room id)."""
    meetings.sort()
    free = list(range(n))             # already a valid heap
    busy = []                         # (end, room)
    count = [0] * n
    for s, e in meetings:
        while busy and busy[0][0] <= s:
            _, r = heapq.heappop(busy)
            heapq.heappush(free, r)
        if free:
            r = heapq.heappop(free)
            heapq.heappush(busy, (e, r))
        else:
            end, r = heapq.heappop(busy)   # wait for the earliest room; keep the duration
            heapq.heappush(busy, (end + (e - s), r))
        count[r] += 1
    return max(range(n), key=lambda r: (count[r], -r))

def find_maximized_capital(k, w, profits, capital):
    """IPO: projects sorted by capital; unlock the affordable ones into a max-heap of profit."""
    projects = sorted(zip(capital, profits))
    h, i = [], 0
    for _ in range(k):
        while i < len(projects) and projects[i][0] <= w:
            heapq.heappush(h, -projects[i][1])
            i += 1
        if not h:
            break
        w -= heapq.heappop(h)
    return w

From your world

Free and busy heaps are a run queue and a sleep queue. A task sleeps until a time; when the clock reaches it, it moves back to the runnable set, and the scheduler picks the best runnable one. Meeting Rooms III is literally "wake every sleeper whose deadline passed, then dispatch".

Two heaps for a running median

Find Median from Data Stream: keep the smaller half in a max-heap lo and the larger half in a min-heap hi, with len(lo) equal to len(hi) or one more. The median is lo's top, or the average of both tops. To add x: push into lo, move lo's top to hi (keeps lo <= hi), and move one back if hi got bigger. O(log n) per add, O(1) per query.

class MedianFinder:
    def __init__(self):
        self.lo, self.hi = [], []          # lo: max-heap (stored negated), hi: min-heap
    def add(self, x):
        heapq.heappush(self.lo, -x)
        heapq.heappush(self.hi, -heapq.heappop(self.lo))
        if len(self.hi) > len(self.lo):
            heapq.heappush(self.lo, -heapq.heappop(self.hi))
    def median(self):
        if len(self.lo) > len(self.hi):
            return float(-self.lo[0])
        return (-self.lo[0] + self.hi[0]) / 2.0
