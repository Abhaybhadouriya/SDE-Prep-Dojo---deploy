Interview questions

Find the k-th largest element in an unsorted array. Give more than one approach.

Sort: O(n log n). Size-k min-heap: push each value and pop when the size is over k; the root is the answer; O(n log k) time, O(k) space, and it works on a stream. Quickselect: partition around a random pivot and recurse into the side that holds index n - k; O(n) average, O(n2) worst, O(1) extra space, changes the array.

How to answer

State the heap solution first because it is safe and short. Then offer quickselect as the O(n) average option and mention the 3-way partition for duplicates and the random pivot for adversarial input.

Likely follow-ups
  • Worst case of quickselect? (O(n2) with bad pivots; median-of-medians gives O(n) worst case but is rarely coded in interviews.)
  • What if the data is a stream? (Only the heap works: keep it between calls.)
Top K Frequent Elements: can you beat O(n log k)?

Yes. Counts lie in 1..n, so bucket the values by count (n + 1 buckets) and read from the top until you have k values: O(n) time and space. Quickselect on the (value, count) pairs is also O(n) on average.

How to answer

Give the hash map plus size-k heap first, then point out the bounded key range and switch to buckets. Name the trade-off: buckets use O(n) memory even when k = 1.

Likely follow-ups
  • Ties must be broken alphabetically? (Top K Frequent Words: heap with comparator (count asc, word desc) so the worst is popped first.)
  • Data does not fit in memory? (Count per shard, keep a top-k per shard, merge; exact only if each shard holds whole keys, e.g. hash-partitioned.)
Merge k sorted linked lists. What is the complexity and what are the alternatives?

Min-heap of the k current heads, keyed by value. Pop, append to the result, push that node's next. O(N log k) time, O(k) space. Alternative: divide and conquer, merging lists in pairs over log k rounds, also O(N log k) with O(1) extra space for an iterative version. Naive one-by-one merging is O(N k).

How to answer

Explain why only heads can be next (the invariant), then the heap, then the complexity. In Python add a tie-break index to the tuple because ListNode is not comparable.

Likely follow-ups
  • k is huge and the lists are on disk? (External merge: one buffered reader per run, heap of size k, or several merge passes if k readers do not fit.)
  • Which is faster in practice, heap or pairwise? (Similar; pairwise has better locality and no heap overhead.)
Task Scheduler: explain the greedy and the formula.

Greedy: at each tick run the available task with the most copies left, using a max-heap and a cooldown queue. Formula: with the top count m and t tasks tied at m, the answer is max(len(tasks), (m - 1)(n + 1) + t). The most frequent task forces m - 1 gaps of n slots; other tasks fill the gaps; if they overflow, no idle is needed at all.

How to answer

Draw the frame (A _ _ A _ _ A). Show where B and C go. Then derive the formula from the drawing and explain the max().

Likely follow-ups
  • Output the actual schedule? (Use the heap simulation, which produces it.)
  • Tasks must keep the given order (Task Scheduler II)? (No heap: a hash map of next-allowed day per task, walk in order.)
Meeting Rooms III: which data structures and why two heaps?

Rooms have two states with different orderings. Free rooms are chosen by lowest number: a min-heap of ids. Busy rooms are chosen by earliest end, then lowest id: a min-heap of (end, id). For each meeting in start order, release every busy room with end <= start, then take the lowest free room; if none, pop the earliest busy room and extend its end by the meeting's duration. Count per room. O(m log m + m log n).

How to answer

Name the two states first and the order each one needs; the heaps follow. Point out the 64-bit end times and that the delayed meeting keeps its duration, not its end.

Likely follow-ups
  • Only the minimum number of rooms is needed? (That is Meeting Rooms II: one heap of end times, or a sweep.)
  • Why not scan rooms linearly? (O(m n); fine for n = 100 as in the original limits, but the heap scales.)
IPO: why is "take the most profitable affordable project" optimal?

Capital only grows, so the largest profit now unlocks a superset of what any other pick unlocks; an exchange argument finishes it. Projects sorted by capital, a pointer pushing newly affordable profits into a max-heap, k pops: O(n log n + k log n).

How to answer

Name the two collections (locked, unlocked), then the exchange argument.

Likely follow-ups
  • The heap is empty before k picks? (Stop early: nothing more is affordable.)
  • Projects can lose money? (Never pick a negative one; the greedy still holds for the non-negative ones.)
Design a structure that returns the median of a stream.

Two heaps: a max-heap for the lower half and a min-heap for the upper half, sizes equal or the lower one bigger by one. Add: push to lower, move lower's top to upper, rebalance. Median: the top of lower, or the average of both tops. O(log n) add, O(1) median.

How to answer

State the invariant (every element of lower <= every element of upper, sizes balanced), then show that the "push then move the top" trick keeps it.

Likely follow-ups
  • All values are in 0..100? (A count array of 101 buckets; walk to the middle: O(100) per query.)
  • Sliding window median? (Lazy deletion with a hash map, or two ordered multisets.)
