Revision card

  • Cue: k largest / smallest / closest, merge k sorted, "next task to run", running median.
  • Insight: A heap keeps only the current best in O(1) and updates in O(log n); nothing else is ordered.
  • State: min-heap of size k for k largest; one head per list for k-way merge; two heaps for the median.
  • Trap: Wrong heap direction per language (C++ max, Java/Python min); comparing pairs without a tie key.
  • Cost: O(n log k) for top k; O(N log k) for merge; quickselect O(n) average for one k-th value.

More to remember

  • A heap gives the current minimum (or maximum) in O(1) and changes in O(log n). Nothing else is ordered.
  • k largest: min-heap of size k. k smallest: max-heap of size k. The root is the weakest member you keep.
  • k-way merge: the heap holds one head per list and remembers where each head came from. O(N log k).
  • Scheduling: one structure for "available now" (heap by the greedy key) and one for "available later" (sorted by time).
  • Median of a stream: two heaps, lower half max-heap, upper half min-heap.
  • Offline single k-th value: quickselect O(n) average. Small integer keys: bucket sort O(n). Timer wheel = buckets; hrtimer tree = heap.
