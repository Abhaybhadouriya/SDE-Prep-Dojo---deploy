Pattern 2: k-way merge

You have k sorted lists and you want one sorted output. At any moment, the next output must be one of the k current heads: everything else sits behind a head that is no bigger. So keep only the heads in a min-heap. Pop the smallest, output it, and push the next element from the same list.

Total work is O(N log k) for N elements in all, with O(k) extra space. Concatenate-then-sort is O(N log N); merging one list at a time is O(N k); balanced pairwise merging is the no-heap O(N log k) alternative.

// k-way merge: key = value, a = list, b = index. O(N log k).
func mergeK(lists [][]int) []int {
	h := &ItemHeap{}
	for i, l := range lists {
		if len(l) > 0 {
			heap.Push(h, Item{l[0], i, 0})
		}
	}
	var out []int
	for h.Len() > 0 {
		t := heap.Pop(h).(Item)
		out = append(out, t.key)
		if t.b+1 < len(lists[t.a]) {
			heap.Push(h, Item{lists[t.a][t.b+1], t.a, t.b + 1})
		}
	}
	return out
}
// k-way merge: one head per list in the heap. O(N log k).
vector<int> mergeK(const vector<vector<int>>& lists) {
    typedef tuple<int, int, int> T;                         // (value, list, index)
    priority_queue<T, vector<T>, greater<T>> h;
    for (int i = 0; i < (int)lists.size(); i++)
        if (!lists[i].empty()) h.push(T(lists[i][0], i, 0));
    vector<int> out;
    while (!h.empty()) {
        T t = h.top(); h.pop();
        int v = get<0>(t), i = get<1>(t), j = get<2>(t);
        out.push_back(v);
        if (j + 1 < (int)lists[i].size()) h.push(T(lists[i][j + 1], i, j + 1));
    }
    return out;
}
// k-way merge: one head (value, list, index) per list. O(N log k).
static List<Integer> mergeK(int[][] lists) {
    PriorityQueue<int[]> h = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
    for (int i = 0; i < lists.length; i++) if (lists[i].length > 0) h.offer(new int[]{lists[i][0], i, 0});
    List<Integer> out = new ArrayList<>();
    while (!h.isEmpty()) {
        int[] t = h.poll();
        out.add(t[0]);
        int i = t[1], j = t[2] + 1;
        if (j < lists[i].length) h.offer(new int[]{lists[i][j], i, j});
    }
    return out;
}
def merge_k_sorted(lists):
    """k-way merge: heap holds one (value, list, index) head per list. O(N log k)."""
    h = [(lst[0], i, 0) for i, lst in enumerate(lists) if lst]
    heapq.heapify(h)
    out = []
    while h:
        val, i, j = heapq.heappop(h)
        out.append(val)
        if j + 1 < len(lists[i]):
            heapq.heappush(h, (lists[i][j + 1], i, j + 1))
    return out

Go: Item, ItemHeap and IntMinHeap are the types from the Top-K template above; the later Go blocks reuse them.

The heap entry carries where it came from (list id and index), not just the value. In Merge k Sorted Lists the node pointer itself does that job. The same skeleton solves less obvious problems:

  • Find K Pairs with Smallest Sums: row i is the list nums1[i] + nums2[0..]; seed with (nums1[i] + nums2[0], i, 0).
  • Kth Smallest in a Sorted Matrix: each row is a sorted list. Pop k times. (Binary search on the value is the other classic answer.)
  • Smallest Range Covering Elements from K Lists: the heap gives the min of the heads; track their max too, and advance the list that owns the min.

From your world

This is the merge phase of an external sort, and the compaction step of a log-structured store (LSM tree): several sorted runs on disk, one read cursor per run, and a small heap that picks which cursor to advance. The heap's size is the number of runs, not the number of records. That is why it fits in RAM.
