The matrix as its own scratch memory

Some problems say "update every cell based on the original values of other cells, in place". If you update cell by cell, later cells read values you already changed. The fix is to store the new information somewhere the scan can still tell apart from the old: in spare bits of each cell, or in cells whose fate you record separately.

Set Matrix Zeroes (73): first row and first column as markers

Rule: if a cell is 0, set its whole row and whole column to 0. The O(R + C) solution keeps two boolean arrays zeroRow[] and zeroCol[]. The O(1) solution stores those arrays inside the matrix: m[r][0] marks row r and m[0][c] marks column c. One cell, m[0][0], would have to mark both row 0 and column 0, so column 0 gets its own variable col0.

  1. Input with zeros at (0, 1) and (2, 2). Column 0 contains no zero, so col0 = false. The orange row and column will hold the marks.
  2. Pass 1 finds (0, 1): mark its row in m[0][0] and its column in m[0][1].
  3. Pass 1 finds (2, 2): mark row 2 in m[2][0] and column 2 in m[0][2]. The original data in those cells is gone, but we only needed to know "zero or not".
  4. Pass 2, bottom-up. Row 2 is marked (m[2][0] == 0), so columns 1..3 of row 2 become 0.
  5. Row 1 is not marked; cells in marked columns 1 and 2 become 0. Row 1 keeps 1 and 3.
  6. Row 0 last: its own marker m[0][0] is 0, so it is wiped, including the 7. Column 0 is left alone because col0 is false. Result: [[0,0,0,0],[1,0,0,3],[0,0,0,0]].

The order of the second pass matters: if you wiped row 0 first, every column marker would read as 0 and the whole matrix would turn to zeros. Processing bottom-up (or doing rows 1.. first, then row 0, then column 0) avoids it.

Game of Life (289): two states in one cell

Each cell is 0 (dead) or 1 (alive), and all cells update at the same instant from their eight neighbours: a live cell survives with 2 or 3 live neighbours, a dead cell becomes alive with exactly 3. Since the values use only bit 0, store the next state in bit 1. While counting neighbours read cell & 1 (the current state, untouched); when the rule says "alive next", do cell |= 2. A final pass shifts every cell right by one: cell >>= 1. O(R * C) time, O(1) extra space, and the neighbour count never sees half-updated values.

From your world

This is how you would add a flag to a page-table entry without a side table: reuse spare bits that the current reader masks off. The "next state in bit 1, shift at the end" pattern is also a double buffer folded into one word, like a shadow register that is latched on the next clock edge.

Follow-up interviewers like: "the board is infinite" (store only the live cells in a hash set and count neighbours from them), and "the board is huge and on disk" (process three rows at a time, a sliding window of rows).
