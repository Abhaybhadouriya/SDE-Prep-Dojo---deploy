Interview follow-ups

Why exactly does "i > start" avoid duplicates but keep [1,1,2]?

The loop at one recursion level fills one slot. Two equal values for the same slot would lead to the same set of completions (the later copy sees a subset of the earlier copy's remaining cards), so only the first is tried. The next level fills the next slot, where i starts at start again, so the same value may be chosen there.

How to answer

Say "same slot vs next slot" and show the two-level picture.

Likely follow-ups
  • Apply the same rule to Subsets II and Permutations II.
Only return how many unique combinations there are.

Group into (value, count) and run a bounded-knapsack DP: ways[s] over distinct values, where for each value you may add 0..count copies. O(distinct x target x maxCount), tiny for target <= 30. Listing needs backtracking; counting does not.

How to answer

Switch tools when the output changes from "list" to "count".

Likely follow-ups
  • If order mattered it would be LC 377 (permutation count).
What is the time complexity?

Worst-case bound O(2n · k): the tree has at most one node per distinct sub-multiset, and copying an answer costs its length k. Practically it is output-sensitive and bounded by the number of distinct multisets with sum <= target, which the target limit keeps small. Sorting is O(n log n).

How to answer

Give the honest exponential bound, then explain why pruning makes it fast here.

Likely follow-ups
  • Space: O(k) for the path and stack, plus the output.
Each value may now be used up to c times, given as (value, c) pairs.

Iterate over distinct values; for the current one, try taking 0, 1, ..., min(c, left / value) copies and recurse to the next distinct value. No skip rule is needed because the input already has no repeated entries.

How to answer

This is the (value, count) view of the same problem; mention it is how you would dedup if sorting was not allowed.

Likely follow-ups
  • Negative numbers? Pruning by left breaks; the search becomes unbounded unless each card is used once.
Can you dedup with a hash set instead?

Yes: sort each found combination and insert into a set. It is correct but explores every repeated branch (exponential on many equal cards) and costs extra memory. The skip rule prevents the repeats instead of filtering them.

How to answer

Mention it as a first draft, then improve.

Likely follow-ups
  • Show an input where the set version is far slower (a hundred 1s).
