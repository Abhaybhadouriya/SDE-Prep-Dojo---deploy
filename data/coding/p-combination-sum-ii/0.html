The story

Explain like I'm 5

You have a pile of coin-like tokens, some with the same number printed on them, and you want every different handful that adds up to exactly the price of a toy. Two handfuls that hold the same numbers count as the same, even if you picked different physical tokens. So line the tokens up from small to big, and when you choose "the next token in my handful", never pick a second token with the same number for that same choice: it would only repeat handfuls you already made.

Combination Sum I lets you reuse a value forever; this version gives you a multiset where each card is used once, and the output must contain each combination of values once. The interview test is whether you dedup structurally (sort + skip) or reach for a hash set of sorted tuples.

From your world

Think of choosing buffers from a pool with repeated sizes to fill an exact DMA length. Sizes, not buffer ids, define a solution. Sorting groups equal sizes, and "first of its group at this decision level" is the canonical representative, like taking the lowest-numbered free slot so two equivalent states are never both explored.
