Approaches: brute -> better -> optimal

Hint 1

Where do duplicate combinations come from? From choosing a different physical copy of the same value for the same position in the combination.

Hint 2

After sorting, equal values are adjacent. When you choose the k-th element of the combination, how many times should you try the value 1?

1. Brute force - every subset, dedup with a set

Idea: generate all 2n subsets (pick / skip each card), keep those that sum to target, sort each and insert into a set of tuples.

O(2n · n)time
O(2n)set, worst case

Why it is not enough: with a hundred 1s and target 30 there is one answer, but the pick/skip tree generates C(100, 30) ≈ 3 x 1025 copies of it. Even with pruning on the sum, you explore every way of choosing which 1s to use. The set fixes the output, not the work.

2. Better - pick/skip, but skip a whole run of equal values

Idea: sort; at index i either take a[i] and go to i + 1, or skip a[i] and every following card with the same value (jump to the first index with a different value). If you skip one 1 you must skip all remaining 1s at this point, otherwise "skip the first, take the second" duplicates "take the first, skip the second".

Equivalent counting view: group equal values into (value, count) and for each distinct value choose how many copies to take, 0..count. Both are correct and produce each combination once.

O(2n · n)worst case bound
O(n)recursion depth

3. Optimal - "choose the next card" loop with skip + break

  1. Sort the candidates.
  2. dfs(start, left): the combination so far is in pick; we choose its next element from a[start..]. If left == 0, record a copy of pick.
  3. Loop i from start: if i > start and a[i] == a[i-1], continue (this value was already tried in this slot). If a[i] > left, break (sorted: every later value is too big too).
  4. Choose a[i], recurse with dfs(i + 1, left - a[i]) (each card once), then pop it.

Why the skip rule is exactly right: (1) No duplicates. In one slot, the first copy of a value v at index i and a later copy at j > i both lead to dfs over suffixes a[i+1..] and a[j+1..]. The second suffix is a sub-multiset of the first (the first also contains the copy at j), so every combination the j-branch can complete, the i-branch completes too. Skipping j loses nothing and removes the repeat. (2) Nothing missed. The rule compares with a[i-1] only when i > start, i.e. inside the same slot. In the next slot, i == start, so the same value can be chosen again; that is how [1,1,1,5] is still produced. Each combination is generated in exactly one way: its values in sorted order, each taken from the leftmost available copy.

O(2n · k)worst-case bound, k = answer length
O(k)stack + pick

The 2n bound is loose: every call either records an answer or tries a value that fits, so the work is proportional to the number of distinct partial combinations whose sum is <= target. With target <= 30 that number is small, which is why the code runs in microseconds on a hundred 1s.
