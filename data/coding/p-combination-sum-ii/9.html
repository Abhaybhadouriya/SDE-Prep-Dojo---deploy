Revision card

  • Cue: combinations to a target, input has duplicates, each card once, unique output.
  • Insight: duplicates come from choosing another copy of the same value for the same slot (family: reuse -> i; no reuse -> i + 1; dup input -> skip rule).
  • State: sorted cards, start index, remaining target, current path; recurse with i + 1.
  • Trap: skip i > start && a[i] == a[i-1] (not i > 0); prune a[i] > left -> break only because sorted.
  • Cost: O(2^n · n) worst case time, O(n) recursion depth + output.
a.sort()
def dfs(start, left):
    if left == 0: out.append(pick[:]); return
    for i in range(start, len(a)):
        if i > start and a[i] == a[i-1]: continue   # same value, same slot
        if a[i] > left: break
        pick.append(a[i]); dfs(i + 1, left - a[i]); pick.pop()

Quick quiz

Sorted a = [1,1,2], target 2. With the skip written as i > 0 && a[i] == a[i-1], what is returned?

  1. [[1,1],[2]]
  2. [[1,1]]
  3. [[2]]
  4. []
Inside [1], i = 1 is skipped because i > 0, so [1,1] is lost; only [2] remains. The guard must be i > start.

What single change turns this into Combination Sum I (distinct values, unlimited reuse)?

  1. Recurse with dfs(i, ...) instead of dfs(i + 1, ...)
  2. Remove the sort
  3. Use continue instead of break
  4. Start the loop at 0
Staying on i lets the same card be chosen again in the next slot. (With distinct values the skip rule never fires anyway.)

Why is it safe to break (not just continue) when a[i] > left?

  1. Values are distinct
  2. The array is sorted, so every later a[j] >= a[i] > left
  3. left is always positive
  4. It is not safe
Sorting makes the loop's values non-decreasing, so once one is too big, all remaining ones are too.
