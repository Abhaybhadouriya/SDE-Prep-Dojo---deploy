Sorting with comparators

Sorting by a custom order appears in interval problems, "largest number", meeting rooms, and any "sort by frequency then alphabetically". Each language has a key style, a comparator style, or both.

iv := [][]int{{5, 6}, {1, 3}, {2, 4}}
sort.Slice(iv, func(i, j int) bool { return iv[i][0] < iv[j][0] }) // not stable
cnt := map[string]int{}
for _, w := range words {
    cnt[w]++
}
order := make([]string, 0, len(cnt))
for w := range cnt {
    order = append(order, w)
}
sort.Slice(order, func(i, j int) bool {
    if cnt[order[i]] != cnt[order[j]] {
        return cnt[order[i]] > cnt[order[j]]
    }
    return order[i] < order[j]
})
s := make([]string, len(nums))
for i, x := range nums {
    s[i] = fmt.Sprint(x)
}
sort.Slice(s, func(i, j int) bool { return s[i]+s[j] > s[j]+s[i] })
// sort.SliceStable keeps equal elements in order; Go 1.21+ also has slices.SortFunc
vector<vector<int>> iv = {{5, 6}, {1, 3}, {2, 4}};
sort(iv.begin(), iv.end());                       // vectors compare lexicographically
unordered_map<string, int> cnt;
for (auto& w : words) cnt[w]++;
vector<string> order;
for (auto& kv : cnt) order.push_back(kv.first);
sort(order.begin(), order.end(), [&](const string& a, const string& b) {
    if (cnt[a] != cnt[b]) return cnt[a] > cnt[b];   // strict: > not >=
    return a < b;
});
vector<string> s;
for (int x : nums) s.push_back(to_string(x));
sort(s.begin(), s.end(), [](const string& a, const string& b) { return a + b > b + a; });
// stable_sort keeps equal elements in input order; sort does not
int[][] iv = {{5, 6}, {1, 3}, {2, 4}};
Arrays.sort(iv, (a, b) -> Integer.compare(a[0], b[0]));   // not a[0] - b[0]
Map<String, Integer> cnt = new HashMap<>();
for (String w : words) cnt.merge(w, 1, Integer::sum);
List<String> order = new ArrayList<>(cnt.keySet());
order.sort(Comparator.comparing((String w) -> -cnt.get(w))
                     .thenComparing(Comparator.naturalOrder()));
String[] s = Arrays.stream(nums).mapToObj(String::valueOf).toArray(String[]::new);
Arrays.sort(s, (a, b) -> (b + a).compareTo(a + b));
// Arrays.sort(int[]) is a quicksort; object sorts are stable (TimSort)
iv = [[5, 6], [1, 3], [2, 4]]
iv.sort(key=lambda x: x[0])                    # in place, stable (Timsort)
cnt = Counter(words)
order = sorted(cnt, key=lambda w: (-cnt[w], w))  # count desc, then word asc
def cmp(a, b):                                 # when a key is awkward
    return -1 if a + b > b + a else (1 if a + b < b + a else 0)
largest = "".join(sorted(map(str, nums), key=cmp_to_key(cmp)))

Comparator rules. A comparator must be a strict weak ordering: cmp(a, a) must be false. In C++, writing <= instead of < is undefined behaviour and can crash std::sort. In Java, (a, b) -> a - b overflows when values have opposite signs near the int limits and sorts wrongly; use Integer.compare. Java's TimSort may throw "Comparison method violates its general contract" when the order is inconsistent.

Stability (equal elements keep their input order): Python sort, Java object sorts (TimSort) and C++ stable_sort are stable; C++ sort, Java Arrays.sort(int[]) and Go sort.Slice are not (Go has sort.SliceStable). When a tie order matters, add a tie-breaker to the comparator instead of relying on stability.
