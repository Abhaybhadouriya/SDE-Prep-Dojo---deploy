Heaps (priority queues)

A heap gives you the smallest (or largest) element in O(1) and inserts or removes in O(log n). Use it for top-k, merging k sorted lists, scheduling, running medians and Dijkstra.

  1. A binary heap is a complete tree stored in an array. For index i the children are 2i + 1 and 2i + 2 and the parent is (i - 1) / 2: no pointers at all.
  2. Push appends the new value at the end of the array, the first free leaf. The shape stays complete; only the order may be broken.
  3. Sift up: compare with the parent. 1 is smaller than 3, so they swap.
  4. Compare again with the new parent, the root 2. Swap.
  5. The value reached the root. At most one swap per level, so push and pop are O(log n); peeking at the root is O(1). Pop moves the last element to the root and sifts it down.

The defaults are the trap. C++ priority_queue is a max-heap; Java PriorityQueue and Python heapq are min-heaps; Go's container/heap is whatever your Less says. Memorise one line for each direction.

type Item struct{ dist, node int }
type PQ []Item

func (h PQ) Len() int            { return len(h) }
func (h PQ) Less(i, j int) bool  { return h[i].dist < h[j].dist } // min-heap by dist
func (h PQ) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *PQ) Push(x any)         { *h = append(*h, x.(Item)) }
func (h *PQ) Pop() any           { old := *h; x := old[len(old)-1]; *h = old[:len(old)-1]; return x }

// use: pq := &PQ{}; heap.Push(pq, Item{5, 1}); best := heap.Pop(pq).(Item)
priority_queue<int> maxh(nums.begin(), nums.end());        // MAX-heap by default, O(n) build
priority_queue<int, vector<int>, greater<int>> minh;       // min-heap
minh.push(5); minh.push(2);
using P = pair<int, int>;                                  // (dist, node)
priority_queue<P, vector<P>, greater<P>> pq;               // min by dist, then node
pq.push({5, 1}); pq.push({2, 7});
P best = pq.top(); pq.pop();                               // top() then pop()
auto cmp = [](const P& a, const P& b) { return a.second > b.second; };
priority_queue<P, vector<P>, decltype(cmp)> byNode(cmp);   // custom: "a after b"
PriorityQueue<Integer> minh = new PriorityQueue<>();      // MIN-heap by default
PriorityQueue<Integer> maxh = new PriorityQueue<>(Collections.reverseOrder());
for (int x : nums) { minh.offer(x); maxh.offer(x); }
PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
pq.offer(new int[]{5, 1}); pq.offer(new int[]{2, 7});   // {dist, node}
int[] best = pq.poll();                                  // {2, 7}
h = []
heapq.heappush(h, (5, "b"))        # min-heap; tuples compare field by field
heapq.heappush(h, (2, "a"))
dist, node = heapq.heappop(h)      # (2, 'a')
mx = [-x for x in nums]            # max-heap: store negatives
heapq.heapify(mx)                  # O(n)
biggest = -mx[0]                   # peek is h[0]
top3 = heapq.nlargest(3, nums)     # O(n log k)
  • C++ comparator direction is inverted: cmp(a, b) returning true means a has lower priority (sits below b). greater<> therefore gives a min-heap.
  • Python has no max-heap: push negated numbers, or tuples with a negated first field. With tuples, a tie on the first field compares the second, so add a counter ((dist, seq, obj)) if the payload is not comparable.
  • None of these heaps support "decrease key". Push a new entry and skip stale ones when popped (lazy deletion): the standard Dijkstra trick.
  • Building a heap from an existing array (heapify, the C++ range constructor) is O(n), cheaper than n pushes.
