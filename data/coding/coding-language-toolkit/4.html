Hash maps and sets

The hash map is the most used container in interviews: counting, grouping, "have I seen this before", and index lookups for Two Sum. The calls differ mostly in how a missing key behaves.

freq := map[rune]int{}
for _, ch := range "banana" {
    freq[ch]++ // missing key reads as the zero value
}
groups := map[string][]string{}
for _, w := range []string{"eat", "tea", "tan"} {
    k := []byte(w)
    sort.Slice(k, func(i, j int) bool { return k[i] < k[j] })
    groups[string(k)] = append(groups[string(k)], w) // append to nil slice is fine
}
v, ok := freq['x'] // comma-ok tells "missing" from "zero"
type cell struct{ r, c int }
grid := map[cell]string{{2, 3}: "cell"} // comparable structs are valid keys
seen := map[int]bool{42: true}          // a set is map[T]bool or map[T]struct{}
unordered_map<char, int> freq;
for (char ch : string("banana")) freq[ch]++;   // [] inserts 0 if missing
unordered_map<string, vector<string>> groups;
for (string w : {"eat", "tea", "tan"}) {
    string k = w; sort(k.begin(), k.end());
    groups[k].push_back(w);
}
bool hasX = freq.count('x');                   // lookup WITHOUT inserting
auto it = freq.find('n');                      // or find() != end()
int n = (it != freq.end()) ? it->second : 0;
map<pair<int, int>, string> grid;              // pair has no std::hash:
grid[{2, 3}] = "cell";                         // use map, or encode r * COLS + c
unordered_set<int> seen = {42};
Map<Character, Integer> freq = new HashMap<>();
for (char ch : "banana".toCharArray()) freq.merge(ch, 1, Integer::sum);
Map<String, List<String>> groups = new HashMap<>();
for (String w : new String[]{"eat", "tea", "tan"}) {
    char[] k = w.toCharArray(); Arrays.sort(k);
    groups.computeIfAbsent(new String(k), x -> new ArrayList<>()).add(w);
}
int n = freq.getOrDefault('x', 0);    // no NullPointerException on unboxing
Map<List<Integer>, String> grid = new HashMap<>();
grid.put(List.of(2, 3), "cell");      // List has value equals/hashCode; int[] does not
Set<Integer> seen = new HashSet<>(List.of(42));
freq = Counter("banana")           # {'a': 3, 'n': 2, 'b': 1}
groups = defaultdict(list)         # missing key -> new empty list
for w in ["eat", "tea", "tan"]:
    groups["".join(sorted(w))].append(w)
grid = {(2, 3): "cell"}            # tuples are hashable keys; lists are not
v = grid.get((9, 9), "none")       # .get avoids KeyError
seen = set()
seen.add(42)
has = 42 in seen                   # O(1) average
  • C++ m[k] inserts a default value when k is missing. Use count or find to test without inserting, especially while iterating.
  • Java get returns null for a missing key, and unboxing null to int throws. Use getOrDefault, merge and computeIfAbsent.
  • Python d[k] raises KeyError; use get, Counter or defaultdict.
  • Go returns the zero value; use v, ok := m[k] when zero is a valid value.
  • Composite keys. Python: tuples. Java: List.of(r, c) or a record (an int[] key compares by identity, a classic bug). Go: a struct or array. C++: pair has no standard hash, so use map, encode as r * COLS + c or a 64-bit (long long)r << 32 | c, or write a hash functor.
  • Iteration order is unspecified in C++ and Java HashMap and deliberately randomised in Go. Python dicts keep insertion order (guaranteed since 3.7). Never rely on order in an answer; sort if output order matters.
