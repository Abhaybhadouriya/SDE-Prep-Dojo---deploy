Arrays and strings

Arrays behave as you expect, with bounds checks in Java, Python and Go (an out-of-range index throws or panics instead of corrupting memory). Strings are where C habits break. In C a string is a mutable char array; in Java, Python and Go a string is immutable, so "changing" one builds a new copy. Editing character by character means converting to a mutable array first, and building a result in a loop means using a builder, otherwise each + copies everything so far and the loop becomes O(n²). C++ std::string is mutable, so s[0] = 'R' and += are fine there.

b := []byte(s) // string is immutable: edit a []byte (ASCII) or []rune (Unicode)
b[0] = 'R'
t := string(b)
var sb strings.Builder // O(n) build; avoid += in a loop
sb.WriteString(t)
sb.WriteByte('r')
idx := int('c' - 'a')     // 2
letter := byte('a' + 3)   // 'd'
first := s[0]             // a byte (uint8), not a character
for i, r := range "héllo" { // range decodes runes; i is the BYTE offset
    _ = i
    _ = r
}
counts := [26]int{}
for i := 0; i < len(s); i++ {
    counts[s[i]-'a']++
}
s[0] = 'R';                          // std::string is mutable
s += "r";                            // amortised O(1) append
int idx = 'c' - 'a';                 // 2: letter to index
char letter = 'a' + 3;               // 'd'
string rev(s.rbegin(), s.rend());    // reversed copy
string part = s.substr(1, 3);        // substr(pos, LENGTH), copies: O(len)
int counts[26] = {0};                // fixed alphabet: array beats a map
for (char ch : s) if (islower(ch)) counts[ch - 'a']++;
char[] cs = s.toCharArray();           // String is immutable: edit a char[]
cs[0] = 'R';
String t = new String(cs);
StringBuilder sb = new StringBuilder();  // O(n) build; never += in a loop
sb.append(t).append('r');
String rev = new StringBuilder(s).reverse().toString();
int idx = 'c' - 'a';                   // 2 (char arithmetic gives int)
char letter = (char) ('a' + 3);        // 'd' needs the cast
String part = s.substring(1, 4);       // substring(begin, END), copies
boolean same = t.equals("Route");      // never == for string contents
int[] counts = new int[26];
for (char ch : s.toCharArray()) counts[ch - 'a']++;
chars = list(s)                    # str is immutable: edit a list of chars
chars[0] = "R"
t = "".join(chars)                 # O(n) build; avoid += in a loop
idx = ord("c") - ord("a")          # 2: letter to index
letter = chr(ord("a") + 3)         # 'd'
rev = s[::-1]                      # slicing copies: O(n)
counts = [0] * 26                  # fixed alphabet: an array beats a dict
for ch in s:
    counts[ord(ch) - ord("a")] += 1
  • Character arithmetic works everywhere: c - 'a' gives 0 to 25. Java needs a cast back to char; Python uses ord and chr.
  • Substring arguments differ: C++ substr(pos, length), Java substring(begin, end), Python s[begin:end], Go s[begin:end]. All of them copy, except Go slicing of strings (which shares memory).
  • Go: s[i] is a byte and for _, r := range s yields runes (Unicode code points). For interview inputs that are ASCII letters, bytes are what you want.
  • Java compares string contents with equals, never ==.
