Interview questions

Which language will you use, and why?

Give a short, confident reason: "C++, because I've written C for years and the STL gives me the containers I need" or "Python, because it lets me focus on the algorithm with the least boilerplate". Then mention one thing you know about its pitfalls ("I'll keep an eye on overflow and use long long for products"). Interviewers care that you are fluent, not which language you pick.

How to answer

One sentence of reason, one sentence showing you know the language's traps.

Likely follow-ups
  • Can you write it in C? (Usually yes, but you would build your own hash map; say you prefer C++ for that reason.)
  • Would you change language for performance? (Only if a time limit forces it; asymptotic complexity matters far more.)
How do you get a min-heap and a max-heap in your language?

C++: priority_queue<int> is max; priority_queue<int, vector<int>, greater<int>> is min. Java: new PriorityQueue<>() is min; pass Collections.reverseOrder() for max. Python: heapq is min; push negatives for max. Go: implement heap.Interface with Less as < for min or > for max.

How to answer

Say the default first, then the one-line way to flip it.

Likely follow-ups
  • How do you order by a field of an object? (A comparator or a tuple key such as (dist, node).)
  • How do you update a priority? (Push a new entry and skip stale ones on pop.)
Why is (a, b) -> a - b a bad comparator in Java?

Because the subtraction can overflow. With a = 2,000,000,000 and b = -2,000,000,000 the true difference is 4 × 10⁹, which wraps to a negative int, so the comparator says a < b. The sort then produces a wrong order or throws "Comparison method violates its general contract". Integer.compare(a, b) or Comparator.comparingInt avoids it.

How to answer

Give the concrete overflowing pair; it shows you think in fixed-width integers.

Likely follow-ups
  • Does C++ have the same issue? (Its comparator returns bool, so there is no subtraction, but <= breaks strict weak ordering and is undefined behaviour.)
  • What is stability and when do you need it? (Equal keys keep input order; needed when sorting by a second key in a separate pass.)
What does m[key] do on a missing key in C++, Java, Python and Go?

C++ unordered_map::operator[] inserts a value-initialised entry (0 for int) and returns a reference. Java get returns null (and unboxing it to int throws NullPointerException). Python d[key] raises KeyError unless it is a defaultdict or Counter. Go returns the zero value without inserting; the two-value form v, ok := m[key] tells you whether it existed.

How to answer

Mention the bug each behaviour causes: silent inserts in C++, NPE in Java.

Likely follow-ups
  • How do you check membership in C++ without inserting? (count(key) or find(key) != end(); C++20 adds contains.)
  • Is lookup O(1)? (Average O(1); hashing a string key costs O(L).)
You need "largest key ≤ x" with inserts. What do you use in each language?

An ordered map. C++: map::upper_bound(x) then step back one (check against begin()). Java: TreeMap.floorKey(x), which returns null when none. Python: bisect_right on a sorted list if inserts are rare, otherwise SortedList where available. Go: a sorted slice with sort.Search, accepting O(n) inserts, or a different design.

How to answer

State the operation's cost (O(log n)) and the null / begin edge case.

Likely follow-ups
  • What if the data never changes? (Sort once and binary search: O(n log n) build, O(log n) per query.)
  • Which LeetCode problem uses this? (Time Based Key-Value Store, My Calendar.)
How do you avoid overflow when multiplying under a modulus like 10⁹ + 7?

Keep every intermediate value reduced modulo M, so each factor is below M ≈ 10⁹. The product of two such values is below about 10¹⁸, which fits in a signed 64-bit integer (max about 9.2 × 10¹⁸). So widen to 64 bits before multiplying (1LL * a * b % M in C++, (long) a * b % M in Java, int64 in Go) and reduce again. Python never overflows, but reducing still keeps numbers small and fast.

How to answer

Show the bound arithmetic: (10⁹)² = 10¹⁸ < 9.2 × 10¹⁸.

Likely follow-ups
  • And subtraction? (Add M before taking the remainder: (a - b + M) % M, because % can be negative in C++, Java and Go.)
  • What about a modulus near 10¹⁸? (Use 128-bit multiplication or mulmod by doubling.)
Why can a correct recursive DFS fail in Python or Java on large inputs?

Stack depth. Python stops at 1,000 frames by default, and Java threads have a fixed stack size, so recursing once per node on a 10⁵-node path or a long linked list throws RecursionError or StackOverflowError. Raising Python's limit can then crash the interpreter's own C stack. The robust fix is an iterative DFS with an explicit stack (a list or ArrayDeque), which keeps the same O(n) space on the heap.

How to answer

Name the limit, give the input shape that triggers it, offer the iterative rewrite.

Likely follow-ups
  • Does C++ have the problem? (Less often: the main stack is commonly 8 MB on Linux, but 10⁶ frames can still overflow.)
  • Go? (Goroutine stacks grow dynamically, so deep recursion usually works.)
