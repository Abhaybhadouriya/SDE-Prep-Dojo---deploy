  • Cue: longest chain, order fixed, skips allowed, each next bigger → LIS.
  • Insight: keep the smallest tail per length; tails is sorted, so lower_bound and overwrite.
  • State: tails[k] = min end of an increasing run of length k + 1 (DP: dp[i] ends at i).
  • Trap: strict = lower_bound (bisect_left); tails is not the LIS; DP answer is max(dp).
  • Cost: O(n log n) time, O(n) space; DP O(n²); brute O(2^n).
tails = []
for x in seq:
    k = bisect_left(tails, x)       # bisect_right for non-decreasing
    if k == len(tails): tails.append(x)
    else: tails[k] = x
return len(tails)

Quick quiz

tails = [2, 5, 9] and the next number is 6. What happens?

  1. Append: [2, 5, 9, 6]
  2. Replace 9: [2, 5, 6]
  3. Replace 5: [2, 6, 9]
  4. Nothing
The first tail ≥ 6 is 9; 6 is a smaller end for length 3.

What does dp[i] mean in the O(n²) solution?

  1. LIS of nums[0..i]
  2. LIS starting at i
  3. LIS ending exactly at i
  4. Number of LIS up to i
"Ends at i" makes the transition possible (compare nums[j] with nums[i]); the answer is max(dp).
