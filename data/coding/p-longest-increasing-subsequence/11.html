Return one actual longest subsequence, not just its length.

With the DP: keep parent[i] = the j that gave dp[i], then walk back from the argmax. With tails: store tailIdx[k] (the index whose value sits in tails[k]) and, for each element, parent[i] = tailIdx[k-1] at the moment it was placed; walk back from tailIdx[last]. Still O(n log n).

How to answer

Say up front that tails itself is not the answer, then add the parent pointers.

Likely follow-ups
  • The lexicographically smallest LIS? Needs more care: compare candidates level by level.
Count the number of longest increasing subsequences (LC 673).

O(n²) DP with len[i] and cnt[i]: for j < i with nums[j] < nums[i], if len[j] + 1 > len[i] take len and copy cnt; if equal, add cnt[j]. Answer: sum of cnt[i] over i with the max length. O(n log n) needs a Fenwick tree keyed by value that stores (best length, count) pairs.

How to answer

Explain why tails fails: it forgets how many chains reach each length.

Likely follow-ups
  • Counts can be huge: take them modulo 1e9+7.
Envelopes (w, h) nest only if both are strictly larger. Longest nesting chain?

Sort by width ascending and, for equal widths, height descending; then run the strict LIS on heights. The descending tie-break stops two envelopes of the same width from both being picked. O(n log n). This is LC 354.

How to answer

Justify the tie-break with a two-envelope example: (3, 4) and (3, 5).

Likely follow-ups
  • Three dimensions (boxes): no sort trick removes two dimensions; O(n²) DP or a 2-D data structure.
Do it with a segment tree or a Fenwick tree instead.

Compress values to ranks. Scan left to right; for x with rank r, best = 1 + max over ranks < r (a prefix max query), then update position r with best. O(n log n). This generalises where tails does not: a bounded gap between neighbours (LC 2407 Longest Increasing Subsequence II) or the maximum-sum increasing subsequence.

How to answer

Mention it as the flexible tool; tails is simpler for the plain length.

Likely follow-ups
  • Only allow a difference of at most k between neighbours: a range max over [x - k, x - 1].
Minimum deletions to make the array strictly increasing.

Keep the LIS and delete everything else: n - LIS. For "minimum changes" (you may replace values with any integer), use LIS on nums[i] - i with non-decreasing order, because changed values need room between kept ones.

How to answer

Clarify delete vs change; they give different reductions.

Likely follow-ups
  • Make it a mountain with minimum removals (LC 1671).
