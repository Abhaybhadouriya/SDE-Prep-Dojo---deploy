The problem (in our words)

A climber logs the altitude at each checkpoint in an array nums. She wants to pick some checkpoints, keeping their original order (you may skip any, but never reorder), so that the chosen altitudes are strictly increasing. Return the length of the longest such choice: the longest strictly increasing subsequence of nums.

  • Input: an integer array nums.
  • Output: one integer, the length. Signature: int lengthOfLIS(int[] nums).
  • A subsequence keeps the order but need not be contiguous; equal values do not count as increasing.

Constraints

  • 1 <= nums.length <= 2500
  • -10^4 <= nums[i] <= 10^4

Follow-up asked by the original: can you do it in O(n log n) time?

Practice it: LeetCode 300 - Longest Increasing Subsequence · GfG - Longest Increasing Subsequence (larger n, needs n log n) · takeuforward

Constraints tell you: n ≤ 2500 means O(n²) = about 6 × 10^6 steps passes, so the DP is an acceptable first answer; the follow-up (and the GfG version with n up to 10^4 and beyond) needs O(n log n). Values fit easily in an int.
