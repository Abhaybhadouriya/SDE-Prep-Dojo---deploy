  • Cue: rebuild from preorder (root first) + inorder (root in the middle).
  • Insight: root's inorder position splits the range; left size = mid - lo.
  • State: map value -> inorder index; one preorder cursor; build(lo, hi).
  • Trap: build left before right; no slicing; distinct values only.
  • Cost: O(n) time, O(n) map + O(h) stack. Postorder: cursor from the end, right first.
where = {v: i for i, v in enumerate(inorder)}; nxt = 0
def build(lo, hi):
    if lo > hi: return None
    root = TreeNode(preorder[nxt]); nxt += 1   # (nonlocal nxt)
    mid = where[root.val]
    root.left, root.right = build(lo, mid - 1), build(mid + 1, hi)
    return root

Quick quiz

The root is at inorder index 4 of the range [2..9]. How many nodes does its left subtree have?

  1. 4
  2. 2
  3. 3
  4. 5
mid - lo = 4 - 2 = 2 (indices 2 and 3).

With postorder + inorder (LC 106), what changes in the cursor version?

  1. Nothing
  2. Build left first, cursor from the start
  3. Cursor from the end of postorder, build right first
  4. You need a second map
Read backwards, postorder is root, right, left: the mirror of preorder.

Why is preorder + postorder (without inorder) not enough in general?

  1. A node with one child could have it on either side
  2. It is enough
  3. Values may be negative
  4. The arrays have different lengths
Preorder [1,2] and postorder [2,1] fit both 1->left 2 and 1->right 2. LC 889 accepts any valid answer.
