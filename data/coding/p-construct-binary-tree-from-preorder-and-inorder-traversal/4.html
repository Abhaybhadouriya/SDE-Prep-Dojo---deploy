Approaches: brute -> better -> optimal

Hint 1

Which array tells you the root of the whole tree, and which one tells you what is on each side of it?

Hint 2

If the root sits at position mid of the inorder range [lo..hi], the left subtree has mid - lo nodes, and they are the next mid - lo entries of preorder.

1. Straightforward - search and slice

Idea: root = preorder[0]; scan inorder for it (index k); recurse on preorder[1..k] with inorder[0..k-1] and on preorder[k+1..] with inorder[k+1..].

Why it works: in preorder, the root is followed by all of its left subtree and then all of its right subtree, and the left subtree has exactly k nodes (the inorder count before the root). So both slices are again "preorder + inorder of one tree".

O(n2)time (chain)
O(n2)space if slices are copied

What is wasted: the linear scan for the root and the array copies. On a chain each level scans and copies almost everything.

2. Optimal - index ranges + value -> index map

  1. Map: where[v] = position of v in inorder. Values are distinct, so this is well defined. O(n) to build.
  2. One cursor into preorder: next starts at 0. Because we build root, then the whole left subtree, then the right subtree, we consume preorder in exactly its own order, so we never need preorder ranges.
  3. build(lo, hi): builds the subtree made of inorder[lo..hi]. If lo > hi return null. Else root = preorder[next++], mid = where[root], left = build(lo, mid - 1), right = build(mid + 1, hi).
  4. Order matters: left before right, or the cursor hands the wrong values to the wrong side.
O(n)time
O(n)map + O(h) stack

Why it works: by induction on the range size. Claim: when build(lo, hi) is called, preorder[next] is the root of the subtree whose inorder is [lo..hi], and the call consumes exactly hi - lo + 1 entries. The first entry it takes is that root (preorder lists the root first); the left call consumes the mid - lo left-subtree entries, which in preorder come right after the root, so after it the cursor points at the right subtree's root. Distinct values make where[root] the only possible split, so the tree is unique.

3. Alternative - O(n) without the map ("stop" value)

A well-known top-voted solution drops the map: build(stop) creates nodes from preorder until inorder's current value equals stop (the value of the ancestor that this subtree must end before). Left subtree: build(root.val); then advance the inorder cursor past the root; right subtree: build(stop).

def build(stop):
    nonlocal p, i
    if i < n and inorder[i] != stop:
        root = TreeNode(preorder[p]); p += 1
        root.left = build(root.val)   # left part ends where inorder reaches root
        i += 1                        # skip root in inorder
        root.right = build(stop)      # right part ends where the parent's range ends
        return root
    return None

O(n) time and only O(h) extra space, but harder to explain under pressure. Lead with the map version; mention this if asked to remove the O(n) map. An iterative stack version exists as well (push while preorder goes left; pop while the stack top matches inorder, then attach a right child).
