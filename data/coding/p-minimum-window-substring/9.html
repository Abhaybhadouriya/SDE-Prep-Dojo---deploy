  • Insight: expand r until covered, shrink l while covered; record inside the shrink.
  • State: need[c] (negative = spare), missing = copies still absent, best start/len.
  • Trap: missing changes only when need crosses 0; sentinel len m+1; cut string once.
  • Cost: O(m + n) time, O(Σ) space; brute O(m²·Σ).

When does adding s[r] decrease missing?

  1. When need[s[r]] was > 0 before the decrement
  2. Always
  3. When s[r] is the first character of t
Only a copy the window still lacked is useful; spare copies just make need negative.

Where is the best window recorded?

  1. After the shrink loop
  2. Inside the shrink loop, before removing s[l]
  3. Only when r reaches the end
Inside the loop the window is valid; that is the moment it is a candidate.

Why is the algorithm O(m + n) despite the nested loops?

  1. Because Σ = 52
  2. Because the answer is unique
  3. l and r each move right at most m times in total
The inner loop advances l, which never goes back, so all inner iterations together are at most m.
