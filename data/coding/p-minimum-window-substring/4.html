Approaches: brute → better → optimal

Hint 1

Once s[l..r] covers t, is there any point in trying a larger r with the same l?

Hint 2

How can you tell, in O(1), whether the window covers t after adding or removing one character?

1. Brute force - check every substring

Idea: for every pair (i, j), count the letters of s[i..j] and check that each count is at least t's count. Keep the shortest that passes.

O(m²·Σ)time with a running count per start (O(m³) if each substring is re-counted)
O(Σ)space, Σ = 52 letters

What is wasted: for a fixed start, once the window covers t, every longer window is pointless; and a start that fails tells us nothing we reuse for the next start.

2. Better - two pointers with a full count comparison

Idea: the sliding window itself, but after each move compare the window's 52 counts with t's counts to decide "covered or not".

O(Σ·m + n)time
O(Σ)space

What is wasted: each move changes one count, yet we re-check all 52. With a general alphabet (Unicode, or words instead of letters) Σ is large and this hurts.

3. Optimal - sliding window with a "missing" counter

for right, c in enumerate(s):
    if need[c] > 0: missing -= 1
    need[c] -= 1
    while missing == 0:
        record(left, right); need[s[left]] += 1
        if need[s[left]] > 0: missing += 1
        left += 1
  1. need[c] is "how many more c the window needs". Start it at t's counts. A negative value means the window has spare copies.
  2. missing counts the useful characters still absent. It starts at len(t). Adding c helps only if need[c] was > 0 before the decrement.
  3. missing == 0 means the window covers t. This is the O(1) check.
  4. Shrink while covered, and record inside the loop. Removing s[left] breaks coverage only if need[s[left]] becomes > 0 after the increment.
  5. Both pointers only move right. Each index is added once and removed at most once.
O(m + n)time: n to build need, at most 2m pointer moves
O(Σ)space (128 counters)

Why it works: for every right edge r, the inner loop moves left to the largest position where s[left..r] still covers t, and records that window. That is the shortest covering window ending at r. The answer ends at some r, so it is recorded. And left never needs to move back: if s[l..r] does not cover t, no s[l..r'] with r' < r does either.

Proof (optional)

Invariant: after processing r, missing = Σc max(0, need[c]) where need[c] = countt(c) - countwindow(c). Decrementing need[c] lowers the positive part by one exactly when need[c] was > 0, and incrementing raises it exactly when the new value is > 0, so the updates keep the invariant. missing = 0 is then exactly "window covers t". Let s[a..b] be the optimal window. The left pointer moves past a position p only right after s[p..r'] was recorded as covering for some r' ≤ current r. If left passed a before r reached b, s[a..r'] with r' < b would cover t and be shorter than the optimum, a contradiction. So when r = b, left ≤ a, every s[left..b] with left ≤ a covers t (it contains s[a..b]), and the shrink loop advances left to a and records s[a..b].

When t is tiny and s is huge: first build a list of (index, char) for the positions of s whose char is in t, and slide over that list. Same bound, fewer steps in practice.
