Interview follow-ups

t and s can hold any Unicode characters.

Replace the 128-slot array with a hash map from character (code point) to count. Everything else is the same; the bound becomes O(m + n) expected time and O(distinct characters of t) space if you only store t's characters and ignore the rest.

How to answer

Keep the algorithm, swap the container, and mention code points vs UTF-16 units in Java.

Likely follow-ups
  • Why can you skip characters not in t entirely? (They never change missing.)
If several shortest windows exist, return the leftmost one.

Update the best only on a strictly shorter window (<, not <=). Windows are found in increasing order of their right edge, so the first one of a given length is also the leftmost.

How to answer

Name the comparison and why the scan order gives "leftmost".

Likely follow-ups
  • Return all of them: collect when equal, reset when strictly shorter.
Count the substrings of s that contain all of t.

For each right edge r, once the shrink loop has made the window just invalid at left, every start in [0, left-1] gives a valid window ending at r, so add left to the total. O(m + n). LC 1358 is the special case t = "abc".

How to answer

Turn "record the shortest" into "count the valid starts" using the same left pointer.

Likely follow-ups
  • Count windows of length at most L. (Subtract the starts that are too far left.)
The characters of t must appear in order.

That is LC 727, Minimum Window Subsequence. Counts no longer capture validity. Scan forward to find the end where t is matched as a subsequence, then scan backward from that end to find the latest start, record, and restart from start + 1. Worst case O(m·n); a DP dp[i][j] = latest start for t[0..j] ending at s[i] also gives O(m·n).

How to answer

Say why the window property breaks (order matters), then give the forward/backward scan.

Likely follow-ups
  • Speed it up with next-occurrence tables: next[i][c] = next index of c at or after i.
Now find the longest substring with at most k distinct characters.

Same template, mirror image: validity is "distinct ≤ k", which breaks when the window grows. Expand r; while distinct > k, shrink l; record the length after the shrink loop. This is LC 340 (k given) and LC 159 (k = 2).

How to answer

Show that the one template covers both: record inside the loop for shortest, after the loop for longest.

Likely follow-ups
  • Exactly k distinct: atMost(k) - atMost(k - 1).
s is a stream too large to keep. Can you still answer?

The length of the best window: yes, but you must keep the current window's characters (a queue) to know what leaves at the left, so memory is O(current window), not O(1). To return the window text itself, keep a copy of the best window when it improves.

How to answer

Separate what the algorithm needs (the current window) from what the output needs (the best window).

Likely follow-ups
  • Bound memory by storing only positions of characters that are in t.
