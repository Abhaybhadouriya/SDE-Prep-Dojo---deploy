Common mistakes

A min-heap of all n points. Push everything into a min-heap and pop k: that is O(n + k log n) with heapify, or O(n log n) with n pushes, and O(n) memory. Fine, but it is not the bounded-heap answer the interviewer is fishing for.

The wrong heap direction. For the k smallest, the kept set needs fast access to its largest: a max-heap. In Python push -d; in Java pass a reversed comparator.

Comparator subtraction overflow. (a, b) -> dist(b) - dist(a) is safe here (values ≤ 2·108) but overflows for larger inputs; Integer.compare is the habit to have.

Using sqrt and doubles. Slower, and float rounding can swap two nearly equal distances. Squared integers are exact.

Quickselect with a fixed pivot or many ties. A last-element pivot is O(n²) on sorted input; many equal distances make Lomuto partition degrade too (use a random pivot, and a three-way partition if ties are common).
