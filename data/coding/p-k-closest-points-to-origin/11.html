Interview follow-ups

Heap or quickselect: which would you ship, and why?

The heap: O(n log k) is close to linear for small k, it is deterministic, it does not reorder the caller's array, and it works on a stream. Quickselect is O(n) average and in place, but O(n²) worst case and it mutates the input. If the interviewer asks for the fastest average case on an in-memory array, quickselect.

How to answer

Name the trade-off axes: stream vs batch, worst vs average, mutation, memory.

Likely follow-ups
  • Code the partition step now. (Meta often asks for this.)
Points arrive as an infinite stream; answer "k closest so far" at any time.

Keep the size-k max-heap alive between calls: each new point costs O(log k), and a query returns the heap contents in O(k). Quickselect does not work here because it needs all points.

How to answer

Point out that the heap solution is already online.

Likely follow-ups
  • Points also expire after T seconds (a sliding window)? (A heap cannot delete arbitrary items cheaply: use a balanced BST / sorted container or lazy deletion.)
Many queries: k closest points to a different query point each time.

Preprocess the points into a k-d tree (or a grid / geohash buckets) once, O(n log n). Each query walks the tree with a bounded max-heap and prunes subtrees whose box is farther than the current k-th distance: about O(log n + k) for well-spread data. This is how ride-hailing "nearest drivers" works at a small scale; at scale, geohash or S2 cells.

How to answer

Separate preprocessing from per-query cost; name the pruning rule.

Likely follow-ups
  • Points move (drivers)? (Grid buckets are cheap to update; k-d trees are not.)
The answer must be sorted by distance.

Pop the heap into an array and reverse it (the max-heap pops farthest first): O(k log k) extra. With quickselect, sort the first k afterwards: also O(k log k).

How to answer

Show it only adds O(k log k).

Likely follow-ups
  • Ties: sort by distance, then x, then y.
The points do not fit in one machine's memory.

Each machine computes its local k closest with a heap (O(k) memory each), sends k points to a coordinator, which merges m·k candidates with another size-k heap. The global k closest are always among the local ones, so this is exact. Communication O(m·k).

How to answer

Argue why local top-k contains the global top-k, then give the merge cost.

Likely follow-ups
  • k is also huge? (Distributed quickselect: sample pivots, count per machine, narrow the range.)
