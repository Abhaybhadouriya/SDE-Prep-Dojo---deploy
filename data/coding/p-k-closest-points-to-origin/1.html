The problem (in our words)

You get an array points, where points[i] = [xi, yi] is a point on the plane, and an integer k. Return the k points nearest to the origin (0, 0), using Euclidean distance √(x² + y²). You may return them in any order. The answer is guaranteed to be unique (apart from order).

Signature: int[][] kClosest(int[][] points, int k).

  • 1 <= k <= points.length <= 104
  • -104 <= xi, yi <= 104

Practice it: LeetCode 973 · GfG K Closest Points to Origin

Constraints tell you: n ≤ 104, so even sorting (O(n log n)) passes; the interview is about doing less than sorting and explaining the trade-offs. x² + y² ≤ 2·108 fits in a 32-bit int (max about 2.1·109), so no overflow. "Unique answer" means no tie at the k-th distance, so you do not need a tie-break rule.
