Approaches: brute -> better -> optimal

Hint 1

You are at a node and know the number formed by the digits above it. What is the number including this node?

Hint 2

When exactly is a number complete? What should a null child contribute?

1. Brute force - collect every path as a string

Idea: DFS with a string (or list) of digits; at each leaf, convert the string to an integer and add it.

O(n · h)time (copying paths)
O(n · h)space worst case

Why it is not enough: it stores or copies each path, and parsing at the leaf re-does work the parent already did. The prefix of a path is shared by all leaves below it, so it should be computed once.

2. Optimal - DFS carrying prefix * 10 + digit

def dfs(node, prefix):
    if not node: return 0
    cur = prefix * 10 + node.val
    if leaf(node): return cur
    return dfs(node.left, cur) + dfs(node.right, cur)
answer = dfs(root, 0)
  1. Appending a digit is "times 10 plus digit". If the digits above spell p, the digits above plus this one spell 10p + d. Each node does O(1) work.
  2. Each leaf ends exactly one number. Root-to-leaf paths and leaves are in one-to-one correspondence, so summing cur at the leaves counts each number once.
  3. A missing child adds 0. That makes a one-child node behave correctly: it is not a leaf, and its missing side contributes nothing.
  4. No undo step. prefix is a value parameter, so returning from a child automatically "forgets" its digit; that is why there is no backtracking code.
O(n)time
O(h)space (h <= 10 here)

Why it works (one line): the sum over leaves of the path value can be computed by the recurrence S(node, p) = S(left, 10p+d) + S(right, 10p+d), with S(null) = 0 and S(leaf, p) = 10p + d; the code is that recurrence. The iterative version (our Python) pushes (node, prefix) pairs on a stack, which is the same thing without recursion.

O(1) extra space? (Morris traversal, optional)

Morris inorder threads each node's predecessor back to it, so you can walk without a stack. Track cur as you go down; when you follow a thread back up over k steps, divide by 10k (count the steps while restoring the thread). Real, but rarely expected; the top-voted multi-approach post walks through it.
