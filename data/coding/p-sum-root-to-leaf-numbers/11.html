Do it without recursion.

Stack (or queue) of (node, prefix) pairs. Pop, compute cur, add it if leaf, else push the children with cur. Order does not matter because addition is commutative, so BFS works equally well.

How to answer

Point out that the pair on the stack replaces the stack frame.

The tree can be 105 deep, so numbers no longer fit. Return the sum modulo 109+7.

Take cur = (prefix * 10 + d) % MOD and the total modulo MOD; modular arithmetic respects both multiplication and addition. And switch to an iterative walk, since recursion depth 105 overflows the default stack.

How to answer

Two changes: modulus at each step, iterative traversal.

Likely follow-ups
  • Why is it safe to reduce the prefix before multiplying by 10?
Nodes hold multi-digit values (e.g. 12, 345) and a path concatenates them.

Shift by the number of digits of the value: cur = prefix * 10^len(val) + val. Precompute powers of 10. Value 0 has length 1.

How to answer

Generalise "times 10" to "times 10 to the digit count".

Likely follow-ups
  • How do you count digits without converting to a string?
Solve it in O(1) extra space.

Morris traversal: thread each node's inorder predecessor to it. Going down a left edge, update cur = cur * 10 + d; when a thread takes you back up over k edges (count them while removing the thread), divide by 10k. Add cur when the predecessor is a leaf, just before you remove its thread.

How to answer

Sketch it; the interviewer mainly checks that you know threads exist and that the tree is restored.

Likely follow-ups
  • Is the tree safe to read from another thread during a Morris walk?
Return the largest root-to-leaf number instead of the sum.

Same DFS; return max(left, right) instead of the sum, with null returning -infinity (or skip missing children) so a one-child node does not pick the empty side.

How to answer

Point at the null case: 0 works for a sum, not for a max.
