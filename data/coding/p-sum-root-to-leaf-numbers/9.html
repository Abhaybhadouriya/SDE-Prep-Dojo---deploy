60-second recall

  • Cue: each root-to-leaf path forms a value; sum over all paths.
  • Insight: append a digit = prefix * 10 + d; pass it down.
  • State: one integer argument; add only at leaves.
  • Trap: null returns 0 (not prefix); one-child nodes are not leaves.
  • Cost: O(n) time, O(h) space.
def dfs(node, prefix):
    if not node: return 0
    cur = prefix * 10 + node.val
    if not node.left and not node.right: return cur
    return dfs(node.left, cur) + dfs(node.right, cur)

The paths are 231 and 25. Node 3 has a child, so it is not a leaf and 23 is not counted. Counting it gives 279.

Why does the null case return 0 and not the prefix?

  1. A missing child is not the end of a path; returning the prefix would count a one-child node as a leaf
  2. It saves a multiplication
  3. The prefix is always 0 there
  4. It avoids overflow
Add the number only at a real leaf, where both children are null.

A parent passed prefix p to a node with digit d. What does the node pass to its children?

  1. p * 10 + d
  2. p + d * 10
  3. p + d
  4. d * 10 + p
Appending a decimal digit shifts the prefix left by one place.
