  • Cue: same item must be n apart, minimum total time -> greedy on the top count.
  • Insight: top-1 rows of n+1 slots + last row of width ties; overflow = no idles.
  • State: freq[26], top, width (count of types with freq == top).
  • Trap: max with len(tasks); + width, not + 1; row width n + 1.
  • Cost: O(n) time, O(26) space; heap simulation O(T log 26) if order is needed.
freq = counts(items)
top = max(freq); width = freq.count(top)
frame = (top - 1) * (gap + 1) + width
return max(len(items), frame)

What does (maxCount - 1) * (n + 1) + countOfMax compute?

  1. The number of distinct tasks
  2. The length of the frame built around the most frequent task, including idle slots
  3. The number of idle slots
maxCount - 1 full blocks of n + 1 slots, plus a last row holding every task that has the top count.

When does len(tasks) win over that formula?

  1. Never
  2. When there are enough different tasks to fill every idle slot, so no idling is needed
  3. When n = 0 only
The answer is max(len(tasks), formula); with no idle slots left the schedule is just the tasks.

Time of the counting solution for m tasks?

  1. O(m) (26 counters)
  2. O(m log m)
  3. O(m * n)
Count, find the maximum and how many reach it, then apply the formula.
