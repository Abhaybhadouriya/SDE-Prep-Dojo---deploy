Interview follow-ups

Return an actual schedule, not just its length.

Use rung 2: max-heap of (count, type), FIFO of (ready time, count, type). Each unit pop the heap (or write "idle"), push back from the FIFO when ready. Or build the frame grid column by column and read it row by row.

How to answer

Say which one you pick and why: the heap generalises; the grid is shorter.

Likely follow-ups
  • Lexicographically smallest schedule? Tie-break the heap by letter.
The order of tasks is fixed (they must run as given). How long does it take?

That is Task Scheduler II: walk the list, keep next[type] = the earliest time it may run again, set time = max(time + 1, next[type]). O(n) with a hash map; no greedy choice exists.

How to answer

Point out that "any order" is what makes the greedy matter here.

Likely follow-ups
  • Types are arbitrary strings or ints: hash map instead of a 26-array.
Each type has its own cooldown nt.

The frame formula no longer applies. Simulate with a heap of ready types ordered by remaining count (or by remaining count times cooldown as a heuristic) and an event queue of ready times. Optimality is no longer guaranteed by the simple exchange argument; say so.

How to answer

Be honest about where the proof breaks; offer the simulation as a solid heuristic.

Likely follow-ups
  • Can you test it? Brute force on tiny inputs, like the tested files do.
Now there are k identical machines.

Each time unit runs up to k different ready types. The heap simulation extends directly: pop up to k per unit, park each in the cooldown queue. The single-row frame argument does not carry over cleanly, so the simulation is the safe answer.

How to answer

Reuse rung 2 with a batch pop; mention that k ≥ 26 makes the cooldown the only constraint.

Likely follow-ups
  • Machines with different speeds -> a min-heap of machine free times.
Why is picking the most frequent ready task always safe?

Exchange argument: take an optimal schedule that runs a rarer type B when the more frequent type A was ready. Swapping a later A with this B keeps all gaps valid (A has more copies left, so moving one earlier only spreads them; B moves later, still after its previous copy) and does not lengthen the schedule.

How to answer

State the swap in one sentence; the interviewer mainly wants to hear "exchange argument".

Likely follow-ups
  • Show a case where alphabetical order fails (A A A B C, n = 2).
