Common mistakes

Forgetting max(len(tasks), ...). On the overflow case the frame says 9 but you cannot run 12 jobs in 9 units.

Using + 1 instead of + width. With two types tied at the top (example 2), the last row has two cells; the answer would be 9 instead of 10.

Row width n instead of n + 1. n is the gap between copies; a row holds the copy itself plus the gap.

Greedy that picks any ready task (alphabetical, or round-robin). It can strand the heavy type at the end: for A A A B C with n = 2, starting B C leaves B C A _ _ A _ _ A (9 units), while A B C A _ _ A takes 7. Always run the ready type with the most copies left.

Off-by-one in the cooldown queue. A job run at time t is ready again at t + n + 1; if you store t + n, compare at the end of the step (as the tested code does), not at the start.
