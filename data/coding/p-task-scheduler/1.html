The problem (in our words)

You get an array tasks of jobs for one machine. Each job is an uppercase letter 'A' to 'Z' (its type). You also get an integer n. In each time unit the machine either runs one job or stays idle. Jobs may run in any order, but two jobs of the same type must be at least n time units apart (at least n other units, jobs or idles, between them). Return the smallest number of time units needed to finish every job.

Signature: int leastInterval(char[] tasks, int n).

  • 1 <= tasks.length <= 104
  • tasks[i] is an uppercase English letter.
  • 0 <= n <= 100

Practice it: LeetCode 621 · GfG Geek's Task Schedule · TUF article

Constraints tell you: only 26 types, so a 26-slot count array replaces a hash map and a heap of at most 26 entries is O(1) per operation. 104 jobs with n up to 100 means a slot-by-slot simulation can run about 106 steps; fine, but the formula is O(n) with no simulation. You only return a count, never the schedule.
