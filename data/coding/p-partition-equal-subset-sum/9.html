Revision card

  • Cue: split into two equal-sum groups, small positive values -> subset sum to total / 2.
  • Insight: one bag at exactly half makes the rest the other half; odd total -> false.
  • State: can[s] = sum s reachable with numbers seen so far; can[0] = true.
  • Trap: inner loop must go DOWN (0/1); up = unbounded reuse of the same number.
  • Cost: O(n * total/2) time, O(total/2) space; bitset shift for a 64x speed-up.
can = [True] + [False] * cap         # 0/1 knapsack, feasibility
for w in items:
    for c in range(cap, w - 1, -1):  # downward = each item once
        can[c] |= can[c - w]
return can[cap]

Quick quiz

nums = [2], target 4, inner loop goes upward. What does can[4] become?

  1. false
  2. true, which is wrong
  3. an index error
  4. true, which is right
s = 2 sets can[2] from can[0]; s = 4 then reads the fresh can[2] and sets can[4]: the single 2 was used twice.

Total is 22. Which sum must be reachable?

  1. 22
  2. any even sum
  3. 11
  4. the largest element
One subset must sum to half the total; its complement then sums to the other half.

What does bits |= bits << x represent?

  1. Adding x to every reachable sum, once
  2. Doubling every sum
  3. Removing x
  4. Counting subsets
Bit s moves to bit s + x, and OR keeps the old sums: exactly R ∪ (R + x).
