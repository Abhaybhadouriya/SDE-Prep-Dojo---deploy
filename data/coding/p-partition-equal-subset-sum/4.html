Approaches: brute -> better -> optimal

Hint 1

If one subset sums to S, what does the other one sum to? What must S be?

Hint 2

For each number you either put it in the first bag or not. What is the smallest state that remembers enough to continue?

Hint 3

The state is (index, sum so far). The sum is at most 10,000.

1. Brute force - try every assignment

Idea: recurse over the array; each number goes into bag A or bag B. At the end, check whether the two sums match. With the reduction, track only bag A's sum and stop when it equals total / 2.

O(2n)time
O(n)stack

What is wasted: many different choices reach the same (index, sum) pair, and each is explored again from scratch. With n = 200 that is hopeless.

2. Better - memoised recursion / 2-D table

State: can(i, s) = some subset of the first i numbers sums to exactly s.

Transition: can(i, s) = can(i-1, s) or (s >= x and can(i-1, s - x)) with x = nums[i-1]: skip x, or take it once.

Base case: can(0, 0) = true (the empty subset); can(0, s) = false for s > 0.

Answer: total is even and can(n, total / 2).

Top-down version: the same recursion with a memo keyed by (i, s); it often finishes early because it stops at the first success.

O(n * T)time
O(n * T)space

What is wasted: row i only reads row i - 1, so keeping all n rows is memory you never look at again.

3. Optimal - one boolean row, walked downward

can = [True] + [False] * target
for x in nums:
    for s in range(target, x - 1, -1):   # downward: x used at most once
        can[s] = can[s] or can[s - x]
return can[target]
  1. Reduce first. Odd total -> false. Otherwise target = total / 2; one bag at target makes the rest the other half.
  2. One row is enough. can[s] holds "s is reachable with the numbers seen so far". Processing x updates it in place.
  3. Downward is the whole trick. When s goes from high to low, can[s - x] is read before it can be changed in this round, so it is still the old row: x is added once. Upward would read cells x just set and use x again and again.
  4. Exit early. As soon as can[target] is true, return.
O(n * T)time
O(T)space
T ≤ 104target

Why it works: by induction over the numbers. Before x is processed, the row is exactly the set R of sums reachable with the earlier numbers. A sum is reachable after adding x iff it was in R (skip x) or s - x was in R (take x). The downward loop computes exactly R ∪ (R + x): every read of can[s - x] hits an index smaller than any written so far in this round, so it still holds the value from R. Cells above target are never needed, because sums only grow.

The bitset one-liner from the top community solutions

Treat the row as one big integer: bit s is set iff s is reachable. Adding x is bits |= bits << x, which applies the whole downward loop in one word-parallel shift. In C++ use bitset<10001>; in Python an int works directly. It is the same DP, about 64x faster; say it as a follow-up, after the clear version.

Proof (optional): why the reduction is exact

If a valid split exists, either side is a subset summing to total / 2. Conversely, if a subset A sums to total / 2, its complement sums to total - total / 2 = total / 2. So "equal split exists" ⇔ "total is even and total / 2 is a subset sum". Positivity of values is not needed for this step; it is needed for the table to have a bounded, non-negative index range.
