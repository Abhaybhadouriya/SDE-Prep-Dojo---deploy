Return the two subsets, not just true/false.

Keep the 2-D table (or, with one row, a parent[s] = the item that first made s reachable). Walk back from s = target: if can(i-1, s) is false, item i was taken, so s -= nums[i-1]. The taken items form one half, the rest form the other.

How to answer

Say the 1-D row loses the "which item" information, then add it back with a parent array.

Likely follow-ups
  • Memory of the 2-D table: n x T booleans = 200 x 10,001, about 2 MB as bytes or 250 KB as bits.
Why must the inner loop run downward? Show a failing input for upward.

Downward guarantees every read can[s - x] is from before this x was processed. Upward, with nums = [2] and target 4: s = 2 sets can[2], then s = 4 reads that fresh can[2] and sets can[4], so a single 2 counts twice.

How to answer

Give the two-line counterexample; it is more convincing than a general argument.

Likely follow-ups
  • When is upward correct? Unbounded supply (Coin Change, Coin Change II).
Values are up to 109 but n ≤ 30.

The sum table is far too large. Use meet in the middle: enumerate all 215 subset sums of each half, sort one list, and for each sum a of the first half binary-search target - a in the other. O(2n/2 * n) time.

How to answer

Name the cost driver: the DP is polynomial in the sum, not in the input length, so big values break it.

Likely follow-ups
  • Minimum difference version: LC 2035, also meet in the middle.
Minimise the difference between the two groups instead.

Run the same row up to total / 2, then take the largest reachable s ≤ total / 2. The answer is total - 2s. Same complexity.

How to answer

Show that only the row changes meaning: from "is target reachable" to "closest reachable to target".

Likely follow-ups
  • That is exactly LC 1049 Last Stone Weight II.
Count how many subsets sum to total / 2.

Replace booleans by counts: ways[s] += ways[s - x], still downward, ways[0] = 1. Both a subset and its complement sum to total / 2, so every unordered split is counted twice: divide by 2.

How to answer

Mention modulo arithmetic if the count can grow large.

Likely follow-ups
  • Zeros in the input double the count per zero (LC 494 edge case).
Make it faster without changing the asymptotic idea.

Use a bitset: bits |= bits << x processes 64 sums per machine word, so the work is about n x T / 64. Also sort descending and exit as soon as bit target is set.

How to answer

Connect it to the boolean row: the shift-or is the downward loop done in parallel.

Likely follow-ups
  • Why is the shift automatically "0/1"? The shift reads the whole old value before the OR writes.
