Approaches: brute -> better -> optimal

Hint 1

Write the recursion: at index i with running sum s, try +nums[i] and -nums[i]. Which (i, s) pairs repeat?

Hint 2

Call the '+' numbers P and the '-' numbers N. You know P - N and P + N. Solve for P.

Hint 3

Now it is "count subsets with sum S", which is Partition Equal Subset Sum with integers instead of booleans.

1. Brute force - try all sign patterns

Idea: recurse go(i, s): at the end, count 1 if s == target; otherwise return go(i+1, s + x) + go(i+1, s - x).

O(2n)time
O(n)stack

What is wasted: the running sum can only take about 2 x total + 1 values, so many of the 2n calls ask the same (i, s) question.

2. Better - memo on (index, running sum)

State: ways(i, s) = number of ways to sign nums[i..] so the final value is target, given running sum s. Memoise in a map, or in a table with an offset of +total so negative sums become valid indexes.

Transition: ways(i, s) = ways(i+1, s + x) + ways(i+1, s - x); base ways(n, s) = (s == target).

O(n * total)time
O(n * total)space

This is a perfectly good interview answer and the one the most-voted "how to think about DP" post builds up to. The next step removes the offset and the factor of 2.

3. Optimal - count subsets with sum (total + target) / 2

  1. Reduce. With P = sum of '+' numbers and N = sum of '-' numbers: P - N = target and P + N = total, so 2P = total + target. If |target| > total or total + target is odd, return 0.
  2. Count. ways[s] = number of subsets of the numbers seen so far with sum s; ways[0] = 1.
  3. Add each number x downward: for s = P .. x: ways[s] += ways[s - x]. Downward keeps each number at most once per subset.
  4. Answer: ways[P].
O(n * P)time
O(P)space
P ≤ 1000row size

Why it works: sign patterns and subsets are in one-to-one correspondence (the subset is "who got '+'"), and a pattern hits target exactly when its subset sums to P, by the two equations. The row counts subsets by induction: subsets of the first k numbers with sum s are those without x (old ways[s]) plus those with x (old ways[s - x]); the downward loop reads ways[s - x] before this x has changed it. A zero gives ways[s] += ways[s], doubling every count: exactly the +0 / -0 choice.

Proof (optional): why the parity check is exact

2P = total + target, and P is an integer, so total + target must be even; otherwise no pattern can work. If |target| > total, P would be negative or larger than total: impossible. Any other value of P in [0, total] is a legal target for the subset count. Using the smaller side, N = (total - target) / 2, gives the same answer with a shorter row when target > 0.
