Approaches: brute -> better -> optimal

Hint 1

Which pads can be reached with exactly one hop? With at most two hops? Do these sets have gaps?

Hint 2

If pad j is reachable with k hops, so is every pad before j. So you only need the right end of each set.

1. Brute force - try every hop length

Idea: f(i) = minimum hops from pad i to the end; f(n-1) = 0, f(i) = 1 + min f(i + j) for j = 1..nums[i].

exponentialtime (the same suffixes are solved again and again)
O(n)stack

2. Better - DP over the array

Idea: best[0] = 0; for each i, relax every j in i+1 .. i+nums[i]: best[j] = min(best[j], best[i] + 1). Memoising rung 1 gives the same cost.

O(n · m)time, m = max jump (≤ 1000), so n·m ≤ 10^7
O(n)space

What is wasted: best is non-decreasing along the array (if you can reach j in k hops you can reach any earlier pad in ≤ k), so each relaxation range only matters at its far end. That monotonicity is the greedy.

3. Optimal - greedy level scan (implicit BFS)

jumps = level_end = farthest = 0
for i in range(n - 1):                 # pad n-1 is never a launch pad
    farthest = max(farthest, i + nums[i])
    if i == level_end:                 # finished scanning level `jumps`
        jumps += 1
        level_end = farthest           # next level = (level_end, farthest]
  1. levelEnd = right end of the pads reachable with jumps hops; farthest = right end reachable with one more hop, over the pads scanned so far.
  2. Scan i from 0 to n-2. Update farthest. When i hits levelEnd, the whole current level is scanned: count a hop and move levelEnd to farthest.
  3. Stop before n-1. Counting from the last pad would add a hop that is not needed (an off-by-one that breaks [1,2], and [0] must return 0). Optional early exit once levelEnd ≥ n-1.
O(n)time, one pass
O(1)space

Why it works: let R(k) be the set of pads reachable with at most k hops. R(k) is always a prefix [0, end_k]: if pad i is reachable and i hops up to i + nums[i], every pad in between is reachable too, and anything before i is reachable by induction. So BFS level k+1 is exactly (end_k, end_{k+1}] with end_{k+1} = max(i + nums[i]) over i ≤ end_k. The scan computes those ends in order, and the answer is the first k with end_k ≥ n-1. It is BFS, so it is a shortest path, not a heuristic. Each pad is read once.

Exchange-argument view (optional)

Take any optimal path p_0 = 0 < p_1 < ... < p_k = n-1. By induction p_t ≤ end_t: p_{t+1} ≤ p_t + nums[p_t] ≤ max over i ≤ end_t of (i + nums[i]) = end_{t+1}. So end_k ≥ n-1 and greedy needs at most k hops. Greedy is a valid strategy (land on the pad that achieved the max), so it needs exactly k.
