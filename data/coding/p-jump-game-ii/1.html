The problem (in our words)

A courier robot moves along a row of n charging pads numbered 0..n-1 and starts on pad 0. Pad i holds nums[i], the longest forward hop allowed from it: from pad i the robot may move to any pad i + j with 0 <= j <= nums[i] and i + j < n.

Return the minimum number of hops needed to reach pad n - 1. The input is guaranteed to make pad n - 1 reachable.

Signature: int jump(int[] nums).

Constraints

  • 1 <= nums.length <= 10^4
  • 0 <= nums[i] <= 1000
  • Pad n - 1 can always be reached.

Practice it: LeetCode 45 - Jump Game II · GfG - Minimum Jumps · TUF - Jump Game II

Constraints tell you: n ≤ 10^4 and jumps ≤ 1000, so the O(n · max jump) DP (10^7 steps) passes, and O(n^2) is borderline. The interviewer wants the O(n) greedy and, above all, an argument for why greedy is optimal. "Always reachable" removes the -1 case; GfG's version keeps it, so be ready for it.
