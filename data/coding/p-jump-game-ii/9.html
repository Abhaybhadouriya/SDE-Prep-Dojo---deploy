  • Cue: min hops on a line, each pad allows a range of next pads.
  • Insight: pads reachable in k hops form a prefix, so BFS levels are ranges.
  • State: levelEnd (end of this level), farthest (end of the next); hop when i == levelEnd.
  • Trap: loop to n-2; "max hop" greedy fails on [2,4,0,1,3].
  • Cost: O(n) time, O(1) space; DP O(n · max jump).
steps = end = far = 0
for i in range(n - 1):          # implicit BFS by levels
    far = max(far, reach(i))
    if i == end: steps, end = steps + 1, far

Why can BFS be done with two integers instead of a queue?

  1. Because jumps are at most 1000
  2. Because the pads reachable in k hops are always a contiguous prefix
  3. Because the end is always reachable
A level is then just the range (previous end, current end].

What does [5] return?

  1. 0
  2. 1
  3. 5
You start on the last pad; the loop over 0..n-2 is empty.

For [2,4,0,1,3], what does "always hop as far as possible" give?

  1. 2
  2. 3
  3. It gets stuck on the 0
0 -> 2 lands on nums[2] = 0. The level scan sees that pad 1 reaches 5 and answers 2.
