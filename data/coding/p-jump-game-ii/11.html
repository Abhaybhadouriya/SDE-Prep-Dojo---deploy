Interview follow-ups

Prove the greedy is optimal.

Pads reachable within k hops form a prefix [0, end_k], and end_{k+1} = max(i + nums[i]) for i ≤ end_k. The scan computes exactly these ends, so it is BFS on the implicit graph and returns the shortest path length. Alternatively, by induction any path's t-th pad is ≤ end_t, so no path is shorter.

How to answer

Lead with "this is BFS where levels are ranges"; it ends the "why greedy" debate.

Likely follow-ups
  • Why is the set a prefix? (Any hop can be shortened.)
The end may be unreachable: return -1.

When you close a level (i == levelEnd) and farthest == i, the next level is empty: return -1. Equivalently, if at any time i > farthest, return -1.

How to answer

"An empty BFS level means the target is not reachable."

Likely follow-ups
  • Test: [3,2,1,0,4] returns -1.
Also return the path (which pads to land on).

While scanning a level, remember the index that gave farthest (argmax of i + nums[i]). When a level closes, that pad is the next landing pad. This gives one optimal path in O(n); the farthest-reaching pad in each level is always a safe choice by the induction above.

How to answer

Show that "best pad of this level" is the argmax you already compute.

Likely follow-ups
  • All optimal paths? (Then you need the DP and parent lists.)
Each landing costs cost[i]; minimise total cost instead of hops.

Greedy breaks: the cheapest path may use more hops. best[j] = cost[j] + min(best[i]) over i with i + nums[i] ≥ j. With a fixed window k (Jump Game VI style) use a monotonic deque for O(n); for per-pad ranges use a segment tree or a heap with lazy deletion, O(n log n).

How to answer

Say why the prefix argument no longer gives the answer (it counts hops, not cost), then name the data structure.

Likely follow-ups
  • Why can't you use Dijkstra directly? (You can, O(n·m log n); the DP is simpler on a DAG.)
Hops may go backwards as well (any pad within nums[i] on either side).

Reachable sets are now intervals around the start, but backward hops can help reach far pads. Run BFS, and avoid O(n·m) edge scans by keeping unvisited pads in a sorted set (or a "next unvisited" union-find); each pad is removed once, giving O(n log n) or near O(n).

How to answer

Reuse BFS; the trick is deleting visited pads so each is enqueued once.
