  • Cue: spreads to 4 neighbours each tick from many starts; minimum time for all.
  • Insight: push all sources at time 0; BFS level = minute; nearest source wins.
  • State: queue of cells, fresh counter, minutes; grid itself is the visited set.
  • Trap: mark on push; no extra minute for the last level; no fresh -> 0.
  • Cost: O(m·n) time and space; brute simulation O((m·n)^2).
q = deque(all_rotten); fresh = count_fresh(); t = 0
while q and fresh > 0:            # stops when the last fresh one rots: no extra minute
    for _ in range(len(q)):           # one BFS level = one minute
        u = q.popleft()
        for v in nbrs(u):
            if grid[v] == FRESH:      # the grid is the visited set
                grid[v] = ROTTEN; fresh -= 1; q.append(v)   # mark on push
    t += 1
return t if fresh == 0 else -1        # no fresh at all -> loop never runs -> 0

The grid has no fresh oranges at all. What do you return?

  1. -1
  2. 0
  3. 1
  4. the number of rotten oranges
Nothing needs to rot, so 0 minutes. Loop while q and fresh > 0: it never starts, fresh == 0, return 0.

Why is there no extra minute after the last BFS level?

  1. the loop runs only while fresh > 0, so it stops as soon as the last fresh orange rots
  2. the last level is never pushed
  3. minutes start at -1
  4. there is one, it is subtracted at the end
If you loop on q alone, the last level (which infects nobody) adds one minute too many. Stopping when fresh hits 0, or starting at -1, avoids it.

Why push every rotten orange into the queue before the BFS starts?

  1. to save memory
  2. they all spread at the same time; one start each would overcount minutes
  3. the queue must not be empty
  4. so the grid can be read-only
Multi-source BFS: level t is every cell exactly t steps from its nearest source, which is the minute it rots.
