Interview follow-ups

Return the minute at which each crate turns, not only the total.

How to answer: store dist[r][c] when you push (dist of parent + 1). That is LC 542's output.

Likely follow-ups: do it without extra memory - write 2 + minute into the grid cell itself.

Mould also spreads diagonally (8 directions).

How to answer: only the direction list changes (8 offsets). Complexity stays O(m·n).

Some crates resist: they take 2 minutes to turn.

How to answer: edge weights are now 1 or 2, so plain BFS is wrong. Use Dijkstra, or split each slow cell into a chain of two unit steps; for weights 0/1 a 0-1 BFS with a deque.

The grid is 10^4 x 10^4 and does not fit in memory.

How to answer: keep only two frontiers (current and next level) plus a bitmap of visited cells (1 bit per cell, about 12.5 MB), or process the grid in row bands with frontier exchange - like a distributed BFS.

Can DFS solve it?

How to answer: yes, by passing the time down and only revisiting a cell when you reach it earlier, but a cell may be rewritten many times and the worst case is far above O(m·n). BFS processes each cell once in the right order.

Which crates would you remove to save the most good crates?

How to answer: a different problem (a cut / blocking question, see LC 749 Contain Virus). Clarify the goal before coding; it is not a BFS tweak.
