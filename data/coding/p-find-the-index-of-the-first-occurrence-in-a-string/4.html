Approaches: brute -> better -> optimal

Hint 1

Write the two nested loops first. Where does the work repeat?

Hint 2

After matching j characters and failing, you know those j text characters exactly: they are needle[0..j-1]. What is the longest shift that keeps part of them matched?

1. Brute force - try every start

Idea: for each start i from 0 to n - m, compare needle with haystack[i..i+m-1] and stop at the first mismatch.

for i in range(n - m + 1):
    if haystack[i:i + m] == needle: return i
return -1
O(n·m)time worst case
O(1)space (the slice is O(m) in Python)

What is wasted: on haystack = "aaaa...ab", needle = "aaa...ab" every start matches m-1 chars before failing, and the next start re-reads them all. Our tests include this case (5,000 a's + b in 9,999 a's + b): about 25 million compares for brute force, 15,000 steps for KMP.

2. Better - rolling hash (Rabin-Karp)

Idea: hash the needle and every length-m window of the text, sliding the window in O(1) (subtract the outgoing char, multiply, add the incoming one, mod a prime). Compare strings only when hashes match.

O(n + m)expected time
O(1)space

What is not enough: the bound is only expected; adversarial collisions make it O(n·m) again, and the modular arithmetic is easy to get wrong under pressure. KMP is deterministic. -> rung 3.

3. Optimal - KMP with the lps (prefix) table

j = 0
for i, ch in enumerate(haystack):
    while j and ch != needle[j]: j = lps[j - 1]   # fall back, keep the border
    if ch == needle[j]: j += 1
    if j == m: return i - m + 1
  1. lps[i] is the needle's longest border. The longest proper prefix of needle[0..i] that is also its suffix. Build it by matching the needle against itself with the same loop.
  2. On a mismatch, j drops to lps[j-1], not to 0. The last lps[j-1] text chars are already equal to the needle's first lps[j-1] chars: no need to check them again.
  3. i only moves forward. Each text char is read once; the inner while can only undo increments that j made earlier.
  4. j == m is a match ending at i. It starts at i - m + 1; return it, since we want the first.
O(n + m)time
O(m)lps table

Why it works: when j characters match and the next fails, any earlier-starting alignment that could still succeed must have a prefix of the needle equal to a suffix of the j matched chars, which is a border of needle[0..j-1]. The longest border is the smallest safe shift, so no match is skipped; trying shorter borders next (lps[lps[j-1]-1]...) covers the rest.

Proof (optional)

Linear time: j increases by at most 1 per text char, so over the scan j increases at most n times in total. Every fallback strictly decreases j and j never goes below 0, so the total number of fallbacks is also at most n. The same argument on the needle gives O(m) for building lps. Correctness: the invariant "j = length of the longest prefix of needle that ends at text position i" holds after each step; a full match is exactly j = m.

The Z-function gives the same O(n + m): compute Z on needle + "#" + haystack and return the first position where Z equals m. Use whichever you can write without bugs.
