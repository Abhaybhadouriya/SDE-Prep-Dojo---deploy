60-second recall

  • Cue: find a pattern in a text in linear time / prefix that is also a suffix -> KMP lps.
  • Insight: on a mismatch keep the longest border: j = lps[j-1]; the text pointer never goes back.
  • State: lps[0..m-1]; i over text; j = chars of needle matched now.
  • Trap: while-loop fallback (not if), answer i-m+1, C++ size_t underflow when m > n.
  • Cost: O(n + m) time, O(m) space; brute O(n·m), accepted at 10^4.
lps, k = [0] * m, 0
for i in range(1, m):
    while k and p[i] != p[k]: k = lps[k - 1]
    k += p[i] == p[k]; lps[i] = k
j = 0
for i, ch in enumerate(t):
    while j and ch != p[j]: j = lps[j - 1]
    j += ch == p[j]
    if j == m: return i - m + 1

What is the lps array of the needle "aabaaab"?

  1. [0,1,0,1,2,2,3]
  2. [0,1,0,1,2,3,3]
  3. [0,1,0,0,1,2,3]
  4. [0,0,0,1,2,2,3]
At index 5 the match of length 2 fails ('a' vs 'b'), falls back to lps[1] = 1, then extends to 2. Index 6 extends that to 3 ("aab").

Why is the fallback while j and ch != p[j]: j = lps[j-1] a while and not an if?

  1. The shorter border can mismatch too; keep falling back until a border matches or j = 0
  2. An if would make it O(n·m)
  3. Only the last character needs it
  4. It handles j == m
Each step tries the next shorter border. The total number of fallbacks is bounded by the number of advances, so it stays O(n + m).

In C++: for (size_t i = 0; i <= h.size() - n.size(); ++i) with h = "ab", n = "abc". What happens?

  1. h.size() - n.size() wraps to a huge unsigned value and the loop reads past the end
  2. It returns -1 correctly
  3. A compile error
  4. It returns 0
Return -1 first when the needle is longer, or compare i + n.size() <= h.size().
