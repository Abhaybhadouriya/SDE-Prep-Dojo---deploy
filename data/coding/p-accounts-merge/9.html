60-second recall

  • Cue: records merge when they share any key, transitively -> connected components / union-find.
  • Insight: link each account to the email's first owner; union-find makes chains transitive.
  • State: parent[] over accounts, map email -> first owner, then root -> emails.
  • Trap: never merge by name; sort and dedupe the emails; name comes from the root account.
  • Cost: O(N·α + N log N) time, O(N) space for N emails.
for i, acc in enumerate(accounts):
    for e in acc[1:]:
        if e in owner: union(i, owner[e])
        else: owner[e] = i
for e, i in owner.items(): groups[find(i)].append(e)
return [[accounts[r][0]] + sorted(es) for r, es in groups.items()]

Only a shared email proves the same person; names can repeat.

A shares an email with B, B shares one with C, A and C share nothing. Output?

  1. Three accounts
  2. One account with all emails
  3. A+B and B+C as two accounts
Same person is transitive; union-find joins all three.

Why union account i with the email's FIRST owner only, not every earlier owner?

  1. All earlier owners are already in the first owner's set
  2. It is a heuristic that can miss merges
  3. To keep the output sorted
Each later owner joined the first owner's set when it was read, so one union per repeat connects everyone.
