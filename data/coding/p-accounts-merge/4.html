Approaches: brute -> better -> optimal

Hint 1

Which is the right node: the account, the email, or both? What makes two nodes connected?

Hint 2

You never need an edge between every pair of accounts that share an email; linking each one to the email's first owner is enough.

1. Brute force - merge pairs until nothing changes

Idea: turn each account into a set of emails. Repeatedly compare every pair of sets; if they intersect, union them into one and restart. Stop when a full pass merges nothing.

O(A² · L · passes)time (A accounts, L emails each)
O(N)space

What is wasted: pairs are compared again and again, and every merge restarts the scan. A map from email to account finds the overlaps directly. -> rung 2.

2. Better - graph of emails + DFS

Graph: nodes are emails. In each account, connect its first email to each of the others (a star is enough; no need for all pairs). Traversal: DFS from each unvisited email collects one person's emails. Remember any email's owner name. Sort each component.

for acc in accounts:
    for e in acc[1:]: adj[acc[1]].add(e); adj[e].add(acc[1]); name[e] = acc[0]
for e in adj: if e not in seen: comp = dfs(e); out.append([name[e]] + sorted(comp))
O(N log N)time (sorting dominates)
O(N)graph + visited

What is not ideal: nothing big; it is a completely valid answer. You build an adjacency list first and need recursion or a stack. -> rung 3 unions on the fly with less memory.

3. Optimal - union-find over account indices

  1. Nodes are account indices 0..A-1; parent[i] = i.
  2. Scan each email of account i: if it is new, record firstOwner[email] = i; if it was seen, union(i, firstOwner[email]).
  3. Collect: each distinct email goes to the group find(firstOwner[email]). Because the map holds each email once, duplicates vanish for free.
  4. Emit: for each root, [name of the root account] + sorted(emails).
O(N·α + N log N)time (N = total emails)
O(N)map + parent array

Why it works: "same person" is the transitive closure of "shares an email". Every time an email repeats, we union the two accounts that hold it, so after the scan any two accounts linked by a chain of shared emails are in one set (union-find makes connectivity transitive). Conversely, we only union accounts that really share an email, so different people never merge. Linking to the first owner is enough: all later owners join that one, so they are connected to each other too.

Union by index keeps the parent array small (A entries, not N) and lets the name come from accounts[root][0]. Unioning emails instead also works; then you need an email -> name map.
