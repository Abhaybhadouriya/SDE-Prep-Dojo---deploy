60-second recall

  • Cue: 0/1 grid, 4-directional groups, measure each group -> flood fill.
  • Insight: an island is a connected component; the fill returns its cell count.
  • State: the grid itself (sink 1 -> 0) or a visited grid; best so far.
  • Trap: mark before recursing / when pushing; bounds before value.
  • Cost: O(mn) time; O(mn) worst-case stack or queue.
def sink(r, c):
    if not (0 <= r < R and 0 <= c < C) or g[r][c] != 1: return 0
    g[r][c] = 0
    return 1 + sink(r+1, c) + sink(r-1, c) + sink(r, c+1) + sink(r, c-1)
best = max((sink(r, c) for r in range(R) for c in range(C)), default=0)

Quick quiz

Why is the whole algorithm O(mn) even though a fill can start from many cells?

  1. Islands are small
  2. Each cell is sunk once and later fills skip it
  3. DFS is faster than BFS
  4. The grid is at most 50 × 50
Sunk cells are water to every later fill and to the outer scan, so each cell does constant work overall.

In a BFS version, when must a cell be marked visited?

  1. When it is popped
  2. After the whole island is done
  3. When it is pushed
  4. Never, use a counter
Marking on push stops a second neighbour from pushing the same cell.

What is the worst-case recursion depth on a 50 × 50 grid?

  1. About 2,500 (a snake-shaped island)
  2. 50
  3. 100
  4. 4
A single path that visits every cell makes the DFS go as deep as the number of cells.
