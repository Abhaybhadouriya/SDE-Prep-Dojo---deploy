Do it without recursion.

Use an explicit stack (or a queue for BFS) of (r, c) pairs. Mark on push. The Python tab above is exactly this; memory moves from the call stack to the heap.

How to answer

Mention why: recursion depth equals island size, which can blow the stack on a big grid.

You may not modify the grid.

Keep a separate boolean visited[m][n] (or a bitset, 2,500 bits here). Same algorithm, O(mn) extra memory.

Diagonal cells count as connected too.

Use the 8 neighbour offsets. Nothing else changes. This is the GfG "largest region" variant.

Land is added one cell at a time; report the largest island after each addition.

Union-Find with size per root. Adding a cell creates a set of size 1 and unions it with land neighbours; the answer is the running maximum of root sizes (sizes only grow). O(α) per addition.

How to answer

Point out that DFS would redo O(mn) work per addition.

Likely follow-ups
  • Cells can also be removed: Union-Find cannot split; process removals offline in reverse.
What if you could flip one water cell to land?

That is Making a Large Island: one pass labels islands with ids and records each size; a second pass, at every 0, sums the sizes of its distinct neighbour ids + 1.

The grid is too big for memory (a huge image on disk).

Stream it row by row with Union-Find on the current and previous row only (connected-component labelling, two-pass). Keep size per label and merge labels when two touch in the next row.
