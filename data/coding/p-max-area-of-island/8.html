Common mistakes

Marking after recursing. If the cell is set to 0 after the neighbour calls, a neighbour can walk straight back and the recursion never ends. Mark first.

BFS that marks on pop. A cell gets pushed by two neighbours and is counted twice, inflating the area. Mark when pushing.

Checking bounds after indexing. grid[r][c] == 1 && r >= 0 reads out of range first. Put the bounds check before the value check.

Adding diagonal neighbours. The task says horizontal or vertical only; the 8-direction version is a different problem (the GfG twin).

Mutating input silently. Sinking is fine on LeetCode, but say it out loud in an interview and offer a visited grid if the caller needs the map back.
