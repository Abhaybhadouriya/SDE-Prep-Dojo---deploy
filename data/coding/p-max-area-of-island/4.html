Approaches: brute -> better -> optimal

Hint 1

When you find a land cell, how do you find every cell of its island?

Hint 2

How do you make sure the same island is not measured again from another of its cells?

1. Brute force - restart a search per cell with a fresh visited set

Idea: for every land cell, run a DFS with its own new visited set and measure the island it is in; keep the maximum.

O((mn)²)time
O(mn)space

What is wasted: an island of size A is measured A times.

2. Optimal - DFS flood fill that sinks cells

  1. Scan every cell. When the cell is 1, it is the first cell of an island we have not seen.
  2. Call sink(r, c): if (r, c) is outside the grid or not 1, return 0. Otherwise set it to 0 and return 1 + the results of its four neighbours.
  3. Keep the maximum returned value.

Why it works: the DFS reaches exactly the cells connected to the start through land, which is the definition of the island. Setting a cell to 0 the moment it is reached does two jobs: no cell inside the fill is counted twice (no infinite loop around a lake), and the outer scan will never start a second fill on the same island. Each cell is set to 0 once and examined from at most four neighbours, so the total work is O(mn).

O(m × n)time
O(m × n)stack in the worst case (one snake island)

3. Alternatives - BFS or Union-Find

BFS / explicit stack: same counting, but the frontier lives in a queue or stack on the heap. Mark a cell when you push it, not when you pop it, or a cell can be pushed by two neighbours and counted twice. This is the safe choice in Python or when the grid can be large.

Union-Find: union every land cell with its right and down land neighbours and track component sizes. Same O(mn α) time; it shines when land is added over time (Number of Islands II).

Not mutating the input: use a separate visited boolean grid; O(mn) extra memory. Ask the interviewer whether modifying grid is acceptable.
