60-second recall

  • Cue: fewest removals to make brackets valid, return one answer -> balance scan.
  • Insight: bad = ')' with nothing open + '(' still open at the end; remove only those.
  • State: stack of '(' indices (or: balance counter, then keep the first opens-balance '(').
  • Trap: store indices not chars; build once; leftover '(' must go from the right.
  • Cost: O(n) time; O(n) stack or O(1) extra with two passes; LC 301 needs search.
st, bad = [], set()
for i, c in enumerate(s):
    if c == OPEN: st.append(i)
    elif c == CLOSE:
        if st: st.pop()
        else: bad.add(i)
bad |= set(st)        # unmatched opens
return "".join(c for i, c in enumerate(s) if i not in bad)

s = "a)b(c)d(". Which indices get removed?

  1. 1 and 7
  2. 1 and 3
  3. 5 and 7
  4. Only 1
The ')' at 1 has nothing open. The '(' at 3 pairs with the ')' at 5. The '(' at 7 is still open at the end. Result: "ab(c)d".

Why does the stack hold indices and not '(' characters?

  1. At the end you need to know which positions to delete
  2. All '(' are the same, so it saves memory
  3. To sort them later
  4. Characters cannot be pushed
Collect the bad indices, then build the output once while skipping them.

Counter version (no stack): after the first pass 2 '(' are unmatched. Which ones do you drop?

  1. The last two (scan from the right)
  2. The first two
  3. Any two
  4. The two nearest a ')'
In "(()(" dropping the first two leaves ")(", which is invalid. Dropping from the right leaves "()".
