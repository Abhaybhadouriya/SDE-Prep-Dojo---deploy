Approaches: brute -> better -> optimal

Hint 1

Read left to right and keep a count of open brackets. When exactly do you know a ')' can never be matched?

Hint 2

At the end, some '(' are still open. Which ones? Keep their positions.

1. Brute force - try removals by increasing count

Idea: for k = 0, 1, 2, ... try every way to delete k brackets and return the first valid result (a BFS over strings, as in LC 301). Correct and finds the minimum, but the number of candidates is binomial in the number of brackets.

O(2ⁿ · n)time worst case
O(2ⁿ)space for the BFS level

What is wasted: we only need one answer, and the scan below shows the set of brackets that must go is forced by a simple counting argument, so no search is needed.

2. Optimal - stack of open indices

for i, c in enumerate(s):
    if c == '(': st.append(i)
    elif c == ')':
        if st: st.pop()
        else: drop.add(i)          # nothing open: this ')' is bad
drop |= set(st)                    # still open at the end: bad '('
  1. Push the index of every '('. The stack holds the brackets still waiting for a partner, the most recent on top.
  2. A ')' pops the top (matching the nearest open bracket). If the stack is empty, no '(' before it is free, so this ')' can never be matched: mark it.
  3. After the scan, every index left on the stack is a '(' with no ')' after it: mark those too.
  4. Build the result by copying unmarked characters once (a builder, or erase-remove in C++).
O(n)time
O(n)stack + marks + output

Why it is minimal: look at the balance (opens minus closes) of each prefix. Each ')' marked bad is a moment where the balance of the kept part would hit -1, and some ')' at or before that point must be deleted for each such moment; so at least that many ')' must go. Likewise the final balance B of what remains must reach 0, and only deleting '(' lowers it, so at least B '(' must go. The stack removes exactly those two counts, and the remaining string is valid by construction. The top community solutions all rest on this: remove the unmatched brackets and nothing else.

Proof (optional)

Let c = number of ')' found with an empty stack, and o = size of the stack at the end. Lower bound: in any valid subsequence, every kept ')' is matched to an earlier kept '('. Of the ')' in s, at most (number of '(' before it) can be kept in any prefix, and the greedy matching keeps the maximum possible, so at least c ')' are deleted; symmetric reasoning from the right shows at least o '(' are deleted. Upper bound: the greedy matching pairs every kept bracket, so the result is valid with exactly c + o deletions.

3. Same cost, no stack - two counter passes

# pass 1: drop bad ')', count balance and opens
# pass 2: keep only the first (opens - balance) '(' of what is left

Idea: pass 1 is the stack pass with a counter instead of a stack: it drops bad ')' and ends with balance = number of extra '('. Removing any balance of the '(' is not safe, but removing the rightmost ones is: each suffix of the pass-1 string has at least as many ')' as kept '('. So pass 2 keeps the first opens - balance '(' and drops the rest.

O(n)time
O(1)extra besides the output

This is the answer to "can you do it without a stack?". The answer string may differ from the stack version (it removes different '(' when several choices are minimal), and both are accepted.
