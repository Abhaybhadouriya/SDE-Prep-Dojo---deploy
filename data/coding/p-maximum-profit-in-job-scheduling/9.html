  • Cue: weighted intervals, no overlap, maximise total weight -> weighted interval scheduling.
  • Insight: sort by end; jobs compatible with k form a prefix found by binary search.
  • State: best[k] = max profit with first k jobs; best[k+1] = max(best[k], best[fit] + p).
  • Trap: upper bound (end ≤ start is OK); always include skip so best[] stays monotone.
  • Cost: O(n log n) time, O(n) space; linear scan for fit is O(n²).
items.sort(key=end)                    # pick-or-skip over sorted items
best = [0] * (n + 1)
for k, it in enumerate(items):
    j = last_compatible_count(it, k)   # binary search on ends[:k]
    best[k + 1] = max(best[k], best[j] + value(it))
return best[n]

Why can best[fit] be used directly, without a max over best[0..fit]?

  1. best[] is non-decreasing because skip is always allowed
  2. Profits are positive
  3. The array is sorted by start
  4. fit is always k - 1
best[k+1] = max(best[k], ...) ≥ best[k], so the largest prefix is also the best.
