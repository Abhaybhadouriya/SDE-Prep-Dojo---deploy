The story

Explain like I'm 5

A food truck gets offers to park at events: each event has a start hour, an end hour and a fee. The truck can only be at one event at a time, but it can drive off the moment one event ends and arrive just as the next one starts. Go through the offers in the order they finish. For each one ask: "is my best plan better if I take this event, or if I skip it?". Taking it means "this fee + the best plan among events that were over by the time it starts".

This is weighted interval scheduling, a textbook DP. The interview checks three things: the sort order (by end), the binary search for the compatible prefix (with the touching-ends rule), and that best[] is monotone so the search is valid.

From your world

Think of booking non-overlapping DMA windows on one bus, each worth a throughput gain. Sorting by end and asking "the last window that finishes before mine starts" is the same lookup a timer wheel does: find the latest slot at or before a time, in O(log n).
