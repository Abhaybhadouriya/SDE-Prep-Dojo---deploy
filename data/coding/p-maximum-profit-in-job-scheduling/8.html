Common mistakes

Lower bound instead of upper bound. Searching for ends < start drops a job that ends exactly at the start, so [1,4) + [4,8) is never combined. Use bisect_right / upper_bound on the start.

Sorting the three arrays separately. Sorting endTime alone loses which start and profit belong to it. Sort an index array or a list of (end, start, profit) tuples.

Writing best[k+1] = best[fit] + p (no skip). Then best[] is not monotone, best[fit] is not "the best by time s", and the binary search reads the wrong value.

Greedy by profit or by earliest end. Both fail on weighted inputs (see the table in "Recognise the pattern"). Greedy by end is only correct for the unweighted count.

Searching the whole ends array. Limit the search to the first k entries (or rely on start < end so later ends cannot be ≤ start). In Python, bisect_right(ends, s, 0, k) makes the intent explicit.
