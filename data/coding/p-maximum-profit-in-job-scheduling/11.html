Return the chosen jobs, not just the profit.

Keep best[] and walk back from k = n: if best[k] == best[k-1], job k-1 was skipped, so k -= 1; otherwise it was taken, record it and jump to k = fit(k-1). Store fit per job during the forward pass so the walk is O(n).

How to answer

Reconstruct from the table; do not store whole job lists per state (that is O(n2) memory).

Likely follow-ups
  • Several optimal plans: any tie-break rule is fine; state yours.
You may take at most k jobs.

Add a count dimension: best[c][i+1] = max(best[c][i], best[c-1][fit] + p). O(n k + n log n) time; fit is computed once per job and reused for every c. This is LC 1751.

How to answer

Point out that fit does not depend on c, so the binary search is not repeated k times.

Likely follow-ups
  • Memory: keep two rows of length n + 1, O(n).
Ends are inclusive: a job ending at 4 overlaps one starting at 4.

Count ends strictly less than the start: bisect_left(ends, s), or equivalently search for s - 1 with upper bound. Nothing else changes.

How to answer

Ask about touching ends at the start of the interview; it is the most common hidden detail.

Likely follow-ups
  • Real-valued times: same, as long as you compare consistently.
Jobs arrive one at a time, already in end order. Answer after each one.

Maintain an ordered map end -> best profit by that end, kept strictly increasing. For a new job, look up the floor entry for its start, add the profit, and insert only if it beats the last value. Each arrival is O(log n), and the current answer is the last value.

How to answer

This is the most-voted community solution; explain why dominated entries can be dropped.

Likely follow-ups
  • Arrivals in arbitrary order break the prefix property; you would need a segment tree over compressed times.
Why sort by end and not by start?

With end order, the compatible earlier jobs form a prefix, and best[] over prefixes is monotone, so one binary search gives the answer. Sorting by start also works, but then the DP runs right to left: f(i) = max(f(i+1), pi + f(next(i))), with next(i) = first job starting at or after endi.

How to answer

Show both directions are valid; pick one and stay consistent with the search.

Likely follow-ups
  • Can you do it with a heap? Yes, sort by start and pop finished jobs into a running max; also O(n log n).
Two machines can each run one job at a time.

The one-dimensional DP no longer applies: a state must describe both machines. For unweighted jobs a greedy with a multiset of machine free-times works; for weighted jobs on m machines it becomes a min-cost flow problem. Say this honestly rather than force the DP.

How to answer

Name what breaks (the prefix property per machine) and the general tool.

Likely follow-ups
  • Minimum number of machines for all jobs: Meeting Rooms II (sweep or heap).
