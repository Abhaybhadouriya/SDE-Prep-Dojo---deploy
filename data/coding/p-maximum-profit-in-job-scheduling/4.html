Approaches: brute -> better -> optimal

Hint 1

If you decide about jobs in order of end time, what does "taking job k" leave you free to choose among the earlier jobs?

Hint 2

The earlier jobs compatible with job k form a prefix of the end-sorted list. How do you find where that prefix ends?

1. Brute force - every subset

Idea: try all 2n subsets, keep those with no overlap, take the best sum. Our test driver uses exactly this as an oracle on random small inputs.

O(2n * n)time
O(n)space

What is wasted: after deciding about a job, the rest of the problem only depends on "which jobs are still allowed", and that set is always a prefix (or suffix) of the sorted list: only n different subproblems.

2. Better - take-or-skip DP with a linear scan

State: sort by end time; best[k] = max profit using only the first k jobs.

Transition: for job k (0-based, the (k+1)-th by end): best[k+1] = max(best[k], profit + best[fit]), where fit = number of earlier jobs whose end ≤ this job's start.

Base case: best[0] = 0 (no jobs, no profit).

Answer: best[n].

Top-down version: sort by start, f(i) = max(f(i+1), profit[i] + f(next(i))) with next(i) = first job starting at or after end[i]; memo f.

Finding fit by scanning backwards costs O(n) per job.

O(n2)time
O(n)space

What is wasted: the end times are sorted, so "how many end ≤ start" is a binary search, not a scan.

3. Optimal - same DP, binary search for the compatible prefix

jobs = sorted(zip(end, start, profit)); ends = [e for e, _, _ in jobs]
best = [0] * (n + 1)
for k, (e, s, p) in enumerate(jobs):
    fit = bisect_right(ends, s, 0, k)          # jobs ending at or before s
    best[k + 1] = max(best[k], best[fit] + p)
return best[n]
  1. Sort by end. Then every job that ends by time s is in one prefix of the list.
  2. best[] is non-decreasing. best[k+1] ≥ best[k] because "skip" is always allowed. So the best plan using jobs that end by s is simply best[fit]; no max over the prefix is needed.
  3. fit is an upper bound. bisect_right(ends, s) counts ends ≤ s, so a job ending exactly at s is compatible (touching is allowed).
  4. Take or skip. Exactly the House Robber recurrence, with "the previous house" replaced by "the last compatible job".
O(n log n)time
O(n)space

Why it works: look at the optimal plan for the first k+1 jobs (by end). Either it does not use job k, and then it is a plan for the first k jobs (value best[k]), or it uses job k. In that case every other chosen job ends no later than job k (it comes earlier in end order), so to avoid overlapping job k it must finish by job k's start s. Those are exactly the first fit jobs, and the best plan among them is best[fit]. Both cases are covered by the max, and both values are achievable.

The ordered-map version from the most-voted solution

Keep a map from end time to the best profit achievable by that time, holding only entries that strictly improve the best so far. For each job (by end), look up the last entry with key ≤ start, add the profit, and insert (end, value) only if it beats the current maximum. It is the same DP with the array replaced by a monotone staircase; useful when jobs arrive already sorted by end, one at a time.

Proof (optional): why only prefixes appear

Let jobs be sorted e0 ≤ e1 ≤ ... A job j < k is compatible with job k iff ej ≤ sk (it ends first because ej ≤ ek, so the only possible overlap is ej > sk). Since the ej are sorted, {j : ej ≤ sk} = {0, ..., fit - 1}. Jobs among that prefix are compatible with job k, and any two chosen among them must already be mutually compatible, which best[fit] guarantees by induction.
