Interview questions

Write inorder traversal without recursion. Why would you ever prefer it?

Use an explicit stack: dive left pushing nodes, pop and visit, then move to the popped node's right child; stop when the pointer is null and the stack is empty. It does exactly what the call stack did in the recursive version, but the memory is on the heap, so a skewed tree of 105 nodes cannot overflow the thread stack. It also lets you pause between visits, which is how a BST iterator works.

How to answer

Write the three-phase loop (dive, pop-visit, turn right), dry-run it on a 3-level tree, then state O(n) time and O(h) space. Mention Morris as the O(1)-space alternative before they ask.

Likely follow-ups
  • Postorder with one stack? (Track the last visited node; visit the top only if it has no right child or its right child was just visited.)
  • Can you do it in O(1) space? (Morris threads through the inorder predecessor's null right pointer.)
Binary Tree Maximum Path Sum: why does the function return one thing but update another?

A path can bend at most once, at its highest node. At each node the function returns the best downward chain starting there, val + max(L, R) with negative child gains clamped to 0, because the parent can only extend one arm. It also updates the global best with val + L + R, the path that bends here, which no ancestor can extend. Start the global at minus infinity so an all-negative tree returns its largest value. O(n) time, O(h) space.

How to answer

Draw a node with two arms. Say "returns one arm, records both arms". Then the edge cases: a single negative node, a best path that skips the root.

Likely follow-ups
  • Return the path itself, not only the sum? (Also return the chain's nodes, or record the bending node and rebuild both arms by following the larger gain.)
  • What if the path must start at the root? (Then it is top-down: carry the sum and take the max at every node.)
Validate a BST. What is wrong with checking each node against its children?

The BST property is about whole subtrees, not just children. With root 6 and right child 9 whose left child is 4, every parent-child pair looks fine, but 4 sits in the right subtree of 6. Pass an open interval (lo, hi) down: the left child gets (lo, val), the right child gets (val, hi). Or run inorder and check that values strictly increase. Use 64-bit or nullable bounds so a node equal to INT_MIN or INT_MAX is handled.

How to answer

Give the counter-example first, then the interval code. Ask whether duplicates are allowed and on which side; that changes strict to non-strict on one bound.

Likely follow-ups
  • Iterative version? (Iterative inorder keeping the previous value.)
  • Largest BST inside a non-BST tree? (Bottom-up: return isBST, min, max and size from each subtree.)
Design serialize and deserialize for a binary tree. Why do you need null markers?

Without markers, different trees share a preorder: [1, 2] could be 2 on the left or on the right. Writing "#" for every null makes the encoding unique, so one preorder pass is enough to rebuild it: read a token; "#" means null; otherwise create the node and recursively build left then right. Both directions are O(n) time and the string has 2n + 1 tokens. For a BST you can skip the markers, because value bounds decide each node's place.

How to answer

State the format, show the example string, write both functions with a shared index or iterator. Mention the trade-off with LeetCode's level-order format (easy to read, trailing nulls to trim).

Likely follow-ups
  • How do you make it compact? (Binary encoding: fixed-width values plus a bitmap of which children exist.)
  • Deep trees and recursion limits? (Use an explicit stack for both directions, or level order with a queue.)
Right side view: BFS or DFS?

Either works in O(n). BFS by levels takes the last node of each frozen level. DFS visits right before left and records a node when its depth equals the current length of the answer list, meaning it is the first node seen at that depth. BFS uses O(width) memory, DFS O(height); a deep thin tree favours BFS, a wide bushy one favours DFS.

How to answer

Code BFS (it is the obvious one), then mention the DFS one-liner and the memory trade-off. Meta often asks for the left view, or both, right after.

Likely follow-ups
  • Top view instead? (BFS with column numbers; keep the first node per column, then output columns in order.)
  • Vertical order with ties sorted by value? (Collect (column, row, value) and sort, or a map of column to (row, value) lists.)
Lowest common ancestor in a binary tree (not a BST).

Recurse: if the node is null, p or q, return it. Otherwise ask both children. If both return non-null, p and q are on different sides, so this node is the LCA. If only one side is non-null, pass that up. O(n) time, O(h) space. It assumes both nodes exist; if not guaranteed (LCA II), count how many targets you actually found.

How to answer

Explain what the return value means: "the LCA if both are below me, or whichever target is below me". The code is then six lines.

Likely follow-ups
  • Nodes have parent pointers? (Same as the intersection of two linked lists: two pointers that switch heads.)
  • Many queries on a static tree? (Binary lifting or Euler tour + RMQ, O(log n) per query after preprocessing.)
Kth smallest in a BST, if the BST is modified often and kth is queried often.

A one-off query is an inorder walk that stops at the kth visit, O(h + k). For frequent queries, augment each node with the size of its subtree (updated on insert and delete). Then at each node compare k with the left size: equal + 1 means this node; smaller means go left; larger means go right with k reduced by left size + 1. That is O(h), O(log n) if the tree is balanced. This is an order-statistic tree.

How to answer

Give the simple inorder answer, then upgrade when they add "frequent". Point out that the augmented field must be maintained on every rotation if the tree self-balances.

Likely follow-ups
  • No custom tree allowed in your language? (Two heaps for a median, or a Fenwick tree over compressed values for kth.)
  • Iterator over the BST in O(h) memory? (The paused iterative inorder stack.)
