How to recognise which tree move you need

The problem says...Reach for
"level", "row", "depth-wise", "view from the side", "minimum depth", "width"BFS with frozen size
"path between any two nodes", "diameter", "longest ...", "maximum sum path"Bottom-up return + global answer
"root-to-leaf", "path sum equals", "good nodes", "numbers formed by paths"Top-down state (with backtracking if you collect paths)
"sorted", "kth smallest", "BST", "valid", "two nodes were swapped"Inorder (iterative or Morris) and the interval rule
"is it the same / mirror / subtree"Paired recursion over two nodes at once
"lowest common ancestor", "distance between nodes", "nodes at distance k"LCA recursion, or parent map + BFS
"construct from ... traversal", "serialize", "encode"Preorder with null markers, or root + inorder split with an index map
"O(1) extra space", "without recursion or stack"Morris
"complete tree", "count nodes faster than O(n)"Compare left-most and right-most heights: equal means perfect, 2h - 1 nodes; O(log2 n)
TechniqueTimeExtra space
Recursive DFS (any order)O(n)O(h) call stack
Iterative DFSO(n)O(h) explicit stack
MorrisO(n)O(1), but mutates the tree temporarily
BFS by levelsO(n)O(w), w = widest level (up to n/2 in a perfect tree)
BST search / insert / deleteO(h)O(1) iterative, O(h) recursive
