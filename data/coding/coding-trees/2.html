Three depth-first orders: where you "visit" decides everything

A depth-first traversal goes as deep as it can before backing up. The only question is when you do the work at a node: before its children (preorder), between them (inorder), or after both (postorder). The recursive code is the same three lines in a different order:

void pre (struct node *n) { if (!n) return; visit(n); pre(n->left);  pre(n->right); }
void in  (struct node *n) { if (!n) return; in(n->left);  visit(n); in(n->right);  }
void post(struct node *n) { if (!n) return; post(n->left); post(n->right); visit(n); }
OrderOn the example treeUse it when
Preorder (node, left, right)8 3 1 6 10 14You must handle a parent before its children: copy or serialize a tree, pass state down (path sums), print a folder listing.
Inorder (left, node, right)1 3 6 8 10 14BSTs: inorder is sorted. Kth smallest, validate, recover a swapped pair, BST iterator.
Postorder (left, right, node)1 6 3 14 10 8The answer at a node needs its children's answers: height, diameter, max path sum, delete or free a tree.
Level order (BFS)8 | 3 10 | 1 6 14Anything "per level": averages, right side view, zigzag, minimum depth, width.

From your world

Freeing a tree in C must be postorder: you cannot free(n) and then read n->left. Copying a tree is naturally preorder: allocate the parent, then attach copies of the children. If you have ever written rb_erase cleanup code, you have already chosen a traversal order for exactly these reasons.

Trick for remembering: the name says where the node goes. Pre = node first, in = node in the middle, post = node last. Left always comes before right.
