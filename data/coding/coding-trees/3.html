Iterative traversal: the stack you manage yourself

Interviewers ask for the iterative version for two reasons: to check you understand what recursion does, and because a skewed tree with 100,000 nodes can overflow a real call stack (Python's default recursion limit is 1,000 frames). The inorder version is the one to memorise:

  1. Dive left. From cur, push every node while walking left. Those are ancestors whose left side is not finished.
  2. Pop and visit. The top of the stack has no unvisited left part any more, so visit it.
  3. Turn right. Set cur to the popped node's right child and repeat. Stop when cur is null and the stack is empty.

Click through it on the example tree:

  1. Dive left from the root: push 8, push 3, push 1. Node 1 has no left child, so the dive stops.
  2. Pop 1: nothing is left of it, so visit it. Its right child is null, so there is nothing new to push.
  3. Pop 3 and visit it: its whole left side (just 1) is done. Turn right: cur = 6.
  4. Dive left from 6: push 6. Its left is null, so the dive stops at once.
  5. Pop 6 and visit. Its right is null. The left subtree of 8 is now completely done.
  6. Pop 8 and visit: the root comes out exactly after its left subtree. Turn right: cur = 10.
  7. Push 10, no left child, pop and visit it at once. Turn right: cur = 14.
  8. Push 14, pop and visit. cur is null and the stack is empty: the output 1 3 6 8 10 14 is sorted, because this tree is a BST.

Preorder iteratively is even simpler: push the root; loop "pop, visit, push right, push left" (right first so left comes out first). Postorder: run that preorder with the pushes swapped (node, right, left) and reverse the output, or use one stack plus a "last visited" pointer so you only visit a node after its right child is done. The one-stack version is the one interviewers probe as a follow-up, because it is easy to loop forever on a node whose right child you already processed.
