BFS by levels: the frozen queue size

Breadth-first search visits the tree row by row with a FIFO queue. The one line that turns a plain BFS into a "levels" BFS is: read the queue size before you start the level. Exactly that many nodes belong to the current level; everything you push while processing them belongs to the next one.

  1. Start with the root in the queue. Before the loop body runs, freeze n = queue size = 1: level 0 has one node.
  2. Pop 8 into level 0 and push its children 3 and 10. They wait for the next level; the n = 1 budget is used up, so level 0 = [8] is complete.
  3. Freeze n = 2 for level 1. Pop 3, push its children 1 and 6 to the back. They queue behind 10, so they cannot leak into this level.
  4. Pop 10 (second and last node of the budget) and push 14. Level 1 = [3, 10].
  5. Freeze n = 3. Pop 1 and 6: both are leaves, nothing is pushed.
  6. Pop 14, the third node of the budget. Level 2 = [1, 6, 14] and the queue is empty, so the loop ends.
  7. Many "view" problems are a one-line change: the right side view takes the last node of every level (8, 10, 14), the left view the first.
func levelOrder(root *TreeNode) [][]int {
	out := [][]int{}
	if root == nil {
		return out
	}
	q := []*TreeNode{root}
	for len(q) > 0 {
		n := len(q) // freeze the size: exactly this level
		level := make([]int, 0, n)
		for i := 0; i < n; i++ {
			node := q[i]
			level = append(level, node.Val)
			if node.Left != nil {
				q = append(q, node.Left)
			}
			if node.Right != nil {
				q = append(q, node.Right)
			}
		}
		q = q[n:] // drop the finished level
		out = append(out, level)
	}
	return out
}
vector<vector<int>> levelOrder(TreeNode* root) {
    vector<vector<int>> out;
    if (!root) return out;
    queue<TreeNode*> q;
    q.push(root);
    while (!q.empty()) {
        int n = q.size();                  // freeze the size: exactly this level
        out.emplace_back();
        for (int i = 0; i < n; i++) {
            TreeNode* node = q.front(); q.pop();
            out.back().push_back(node->val);
            if (node->left) q.push(node->left);
            if (node->right) q.push(node->right);
        }
    }
    return out;
}
static List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> out = new ArrayList<>();
    if (root == null) return out;
    Deque<TreeNode> q = new ArrayDeque<>();
    q.offer(root);
    while (!q.isEmpty()) {
        int n = q.size();                      // freeze the size: exactly this level
        List<Integer> level = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            TreeNode node = q.poll();
            level.add(node.val);
            if (node.left != null) q.offer(node.left);
            if (node.right != null) q.offer(node.right);
        }
        out.add(level);
    }
    return out;
}
def level_order(root: Optional[TreeNode]) -> List[List[int]]:
    if not root:
        return []
    out, q = [], deque([root])
    while q:
        level = []
        for _ in range(len(q)):         # len(q) is frozen: exactly this level
            node = q.popleft()
            level.append(node.val)
            if node.left:
                q.append(node.left)
            if node.right:
                q.append(node.right)
        out.append(level)
    return out

One template, many problems

ProblemChange to the template
Right / left side viewRecord only i == n-1 (or i == 0). DFS also works: visit right child first and record the first node seen at each new depth.
Zigzag level orderReverse every odd level (or fill the level array from the back). Do not try to alternate the queue's push order: it breaks the next level.
Average / max / sum per levelFold the level as you pop it.
Minimum depthReturn the level number at the first leaf you pop. BFS beats DFS here: it stops early on a wide, shallow side.
Maximum widthQueue (node, index) with children at 2i+1 and 2i+2; width = last - first + 1. Subtract the level's first index before doubling, or the indices overflow on a deep skewed tree.
Top / bottom / vertical viewQueue (node, column); left child column - 1, right + 1. Top view keeps the first node per column, bottom view the last. Vertical order traversal (the Hard version) also sorts ties at the same row and column by value.
Connect next-right pointersLink each popped node to the next one in the same level. The O(1)-space version walks level k using the next links built while processing level k - 1.

From your world

The frozen size is a batch boundary, like a NAPI poll budget: you process exactly the packets that were ready when this round started, and anything that arrives during the round waits for the next one.
