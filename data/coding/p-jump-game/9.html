  • Cue: "reach the end" with jumps of up to nums[i] → the reachable set is a prefix.
  • Insight: one number reach = max(i + nums[i]); fail only when i > reach.
  • State: i (scan), reach (farthest index reachable from 0..i).
  • Trap: do not pick the biggest jump; i > reach, not >=; target is n - 1.
  • Cost: O(n) time, O(1) space; DP O(n²), recursion O(2^n).
reach = 0
for i in range(n):
    if i > reach: return False          # a gap no earlier move covers
    reach = max(reach, i + jump(i))
    if reach >= n - 1: return True
return True

Quick quiz

Why is one variable enough to describe all reachable indices?

  1. Because nums is sorted
  2. Jumps are "up to" k, so reachable indices form a prefix
  3. Because n ≤ 10^4
  4. Because zeros are rare
Reaching x implies reaching every index below x, so [0, reach] is the whole set.

nums = [2, 1, 1, 0, 5]. What is reach after i = 3?

  1. 2
  2. 4
  3. 3
  4. 5
i = 2 gives 3, and i = 3 adds nothing (3 + 0). Then i = 4 > 3: false.

The move rule becomes "jump exactly nums[i], left or right". What do you use?

  1. BFS or DFS with a visited set
  2. The same greedy
  3. Binary search
  4. Sorting
