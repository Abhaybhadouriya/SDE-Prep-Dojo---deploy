Common mistakes

Always taking the biggest jump. On [2, 3, 1, 0, 4], jumping 2 from index 0 lands on the 1, then the 0: stuck. Jumping 1 to the 3 reaches the end. Greedy must track reach, not pick one route.

Treating every zero as fatal. A zero only matters if reach stops on it. [3, 1, 0, 2, 4] is true.

Checking i >= reach instead of i > reach. Standing exactly at reach is allowed; the strict check fails [0] and many true cases.

Comparing with n instead of n - 1. The goal is the last index. Ending with return reach >= n answers false for [1, 0], where reach = 1 lands exactly on the last index n - 1 = 1.
