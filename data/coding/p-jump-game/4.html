Approaches: brute → better → optimal

Hint 1

If you can reach index 7, can you also reach index 5?

Hint 2

So the reachable indices form a prefix. What single number describes a prefix?

1. Brute force - try every jump (recursion)

Idea: can(i) = true if i is the last index, else true if can(i + s) for some s in 1..nums[i].

O(2^n)time worst case
O(n)stack

What is wasted: can(i) does not depend on how you got to i, yet it is recomputed for every route.

2. Better - DP from the right (memoised)

State: good[i] = can the last index be reached from i. Transition: good[i] = any(good[i+s] for s in 1..nums[i]). Base case: good[n-1] = true. Answer: good[0].

O(n · max jump)time (O(n²) with the cap at n)
O(n)space

What is wasted: from the right, you only need the leftmost good index. If i can reach it (i + nums[i] ≥ leftmostGood), i is good. That turns the inner loop into one comparison: the "move the goal" greedy, O(n) and O(1).

3. Optimal - greedy farthest reach (left to right)

reach = 0                                 # core: 4 lines
for i, step in enumerate(nums):
    if i > reach: return False
    reach = max(reach, i + step)
return True
  1. The reachable set is a prefix. If you can land on x, you can land on any y < x reachable on the way, because jumps are "up to", never "exactly".
  2. One number describes it. reach = the largest index reachable using stones 0..i.
  3. A stone beyond reach is a wall. If i > reach, no stone before i can get you to i, and nothing later can be used: return false.
  4. Early exit. Once reach ≥ n - 1 you are done (the code returns true there).
O(n)time
O(1)space

Why it works: by induction, after processing stone i, the set of indices reachable from stone 0 using only stones 0..i as launch points is exactly [0, reach]. If stone i + 1 is in that set, it adds [i + 2, i + 1 + nums[i+1]], which is contiguous with the prefix, so the set stays a prefix. If it is not in the set, no launch point exists for it or any later stone.

Proof (optional) - the "move the goal" version

Scan from the right with goal = n - 1. If i + nums[i] ≥ goal, set goal = i. Answer: goal == 0. This is correct because "can reach the end" is equivalent to "can reach the leftmost index already known to reach the end": anything to its right that is good is reachable from it with smaller jumps, or by stepping through it. Both scans are O(n), O(1); pick whichever you can explain best.
