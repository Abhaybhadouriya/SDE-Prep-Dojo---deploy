Common mistakes

  • Wrong lower bound. Ship packages with lo = 1 gives a capacity smaller than the heaviest parcel, and the greedy then "ships" a parcel that does not fit. Start at max(w), or make the check return false when an item exceeds the cap.
  • Floating-point ceil. Math.ceil(p / s) on integers in Java/C++ is integer division first, then ceil of an integer. Use (p + s - 1) / s.
  • Overflow inside the check. Koko's hours can reach 104 x 109; trips by time t can exceed 64 bits. Use 64-bit and stop early once the target is reached.
  • Mixing minimise and maximise. For "maximise the minimum" the predicate is T..T F..F. Running first-true on it directly returns the first T (= lo), which is wrong. Negate it, or write a last-true loop with mid = lo + (hi - lo + 1) / 2.
  • Infinite loop. lo = mid with mid rounded down never moves on a range of two. Use the half-open first-true loop above and never write lo = mid in it.
  • Not proving monotonicity. Say the sentence. If you cannot, the predicate might not be monotone.
  • Median: searching the longer array. Then j = half - i can go negative. Always swap so A is the shorter one.
  • Forgetting the impossible case. Bouquets with m * k > n, book allocation with fewer books than students: return -1 before searching.
