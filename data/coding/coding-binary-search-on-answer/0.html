The story: how fast must I walk?

Explain like I'm 5

You have to visit four friends before dinner, and you want to walk as slowly as you can (you are lazy). Is "1 step per second" fast enough? Try it: no, you are late. Is "10 steps per second" fast enough? Yes, but you are out of breath. So the answer is somewhere between 1 and 10.

Here is the nice part: if 6 is fast enough, then 7, 8, 9 and 10 are also fast enough. If 3 is too slow, so are 1 and 2. So you can play "guess my number" with speeds: try 5. Too slow? Then try 8. Fast enough? Then try 6... A few tries and you know the slowest speed that still gets you home for dinner.

Normal binary search looks for a position in a sorted array. Binary search on the answer looks for a value of the answer itself: a speed, a capacity, a distance, a day. You never sort anything. You only need a check ok(x) that says "x is good enough" and that, once true, stays true as x grows.

From your world

Linux TCP MTU probing does exactly this. It keeps search_low (a packet size known to get through) and search_high (a size known to be too big), sends a probe of the size in the middle, and moves one bound depending on whether the probe was acked. The predicate "a packet of this size reaches the peer" is monotone, so the bounds close in on the path MTU. Same with sizing a ring buffer by replaying a traffic capture: if 2,048 slots drop nothing, 4,096 will not either, so you can bisect the smallest size that drops nothing.
