How to recognise it

  • "Minimum ... such that ..." or "maximum ... such that ...", especially "minimise the largest" or "maximise the smallest".
  • The answer is a number in a big range (speed, capacity, day, distance, time) and the constraints go up to 109 or 1014.
  • Checking a guess is easy, finding the best directly is hard. If you can write "given X, can I do it?" as a greedy O(n) loop, you are done.
  • "k-th smallest" over a huge implicit set (pairs, products, a sorted matrix) where you can count items <= x quickly.
  • Contiguous groups ("split into k subarrays", "consecutive days", "adjacent flowers") with a min-max objective.

Red flag: if ok(x) is not monotone, binary search gives wrong answers silently. Example: "shortest subarray with sum >= K" with negative numbers; a length L working does not mean L + 1 works for a fixed window check. Test the one-sentence monotonicity argument before coding.
