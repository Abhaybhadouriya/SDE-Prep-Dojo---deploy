Minimise the maximum: ship packages, split array, book allocation

LeetCode 1011, told our way: parcels with weights w[0..n-1] sit on a conveyor and must be loaded in this order. Each day one truck takes the next parcels as long as their total stays within its capacity. Return the smallest capacity that ships everything within days days. Constraints: 1 <= days <= n <= 5 * 10^4, 1 <= w[i] <= 500. Example: weights 1 to 10, days = 5 gives 15.

Range: the capacity must be at least max(w) (the heaviest parcel must fit) and sum(w) always works (one day). Check: greedy, start a new day only when the next parcel would overflow.

Why the greedy check is exact. Suppose some plan ships everything in d days with capacity c. The greedy's first day ends at or after that plan's first day ends (greedy took as much as possible), so the greedy is never "behind" the plan. By induction it finishes within d days too. That one argument covers the whole family.

The family, all with the same code:

  • LeetCode 410, Split Array Largest Sum: cut an array of non-negative integers (1 <= n <= 1000, values up to 106) into exactly k non-empty contiguous pieces (1 <= k <= min(50, n)) so that the largest piece sum is as small as possible; return that sum. "Exactly k" versus "at most k" does not matter: if fewer pieces fit, you can always split a piece further without raising the maximum. Example: [7, 2, 5, 10, 8], k = 2 gives 18.
  • Book allocation (TUF, GfG): give contiguous books to m students, minimise the most pages any student reads. Same as 410, but return -1 when there are fewer books than students.
  • Painter's partition: k painters paint contiguous boards, minimise the time of the slowest. Same again.

Interviewers often ask "can you do it with DP?" for split array. Yes: dp[i][j] = best largest sum for the first i items in j pieces, O(n2 k). Then say why binary search wins: O(n log(sum)) and far less code. Knowing both is a strong signal.

From your world

Contiguous groups under a cap is how you would pack packets into frames or segments: fill until the next one would exceed the MTU, then start a new frame. "Smallest MTU so the burst fits in d frames" would be exactly this problem.
