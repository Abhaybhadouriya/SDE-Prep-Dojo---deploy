Search the answers, not the array

The first problem everyone meets (LeetCode 875, Koko Eating Bananas), told our way: a panda has n piles of bamboo, pile i has piles[i] shoots, and the keeper returns in h hours. Each hour the panda picks one pile and eats up to s shoots from it; if the pile has fewer than s, she finishes it and waits for the next hour. Return the smallest integer speed s that lets her finish every pile within h hours. Constraints: 1 <= n <= 10^4, n <= h <= 10^9, 1 <= piles[i] <= 10^9. Example: piles [3, 6, 7, 11], h = 8 gives 4.

Hours needed at speed s: sum(ceil(piles[i] / s)). As s grows, every term can only shrink, so "finishes in time" is false for small s and true from some point on. That is the whole method:

Compare with plain binary search (see Binary Search): there, pred(i) was "a[i] >= x" over array indexes. Here ok(s) is "speed s finishes in time" over the integers 1..max(piles). The loop is identical; only the meaning of the cells changes.
