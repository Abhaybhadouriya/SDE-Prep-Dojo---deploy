Earliest day: bouquets and time-based checks

LeetCode 1482, told our way: a row of n plants, plant i flowers on day bloom[i] and stays in flower. A bouquet needs k adjacent flowered plants, and each plant can be used once. Return the earliest day on which you can make m bouquets, or -1 if it is impossible. Constraints: 1 <= n <= 10^5, 1 <= bloom[i] <= 10^9, 1 <= m <= 10^6, 1 <= k <= n. Example: bloom [7, 7, 7, 7, 12, 7, 7], m = 2, k = 3 gives 12.

  • Impossible case first: if m * k > n there are not enough plants on any day. Compute m * k in 64 bits (106 x 105 overflows int).
  • Range: [min(bloom), max(bloom)]. On the last bloom day everything is in flower, so it works when m * k <= n.
  • Check for day d: scan, count runs of flowered plants (bloom[i] <= d), and every time a run reaches k, make a bouquet and reset the run. Later days only add flowers, so the check is monotone.

The same "time t is enough" shape: 2187, Minimum Time to Complete Trips (trips by time t = sum(t / time[i])), 2594, Minimum Time to Repair Cars (a mechanic of rank r fixes floor(sqrt(t / r)) cars in time t), and 1870, Minimum Speed to Arrive on Time.

Cap your counters. In 2187, sum(t / time[i]) with t up to 1014 can overflow even 64 bits after many terms; stop summing as soon as the total reaches the target. The same early exit makes every check faster.
