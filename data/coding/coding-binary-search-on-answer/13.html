Interview questions

Koko Eating Bananas: find the minimum eating speed. Why is binary search valid here?

The answer is a speed in [1, max(piles)]. Hours at speed s = sum(ceil(p / s)), and every term is non-increasing in s, so "finishes within h" is false then true. First-true over the speeds: O(n log max(piles)). Speed max(piles) always works because each pile takes one hour and h >= n.

How to answer

Say the four steps out loud: answer and range, check, monotone sentence, first true. Then code it in under five minutes.

Likely follow-ups
  • Can the upper bound be tighter? (Yes: ceil(sum / h) is a lower bound and max(piles) an upper bound; it saves a few iterations, not the complexity.)
  • Why not a linear scan over speeds? (Up to 109 speeds x n.)
Split Array Largest Sum. Prove the greedy check is correct.

For a cap c, greedy packs each piece until the next value would overflow. Claim: if any split into <= k pieces with max <= c exists, greedy uses <= k pieces. Proof: compare piece by piece; greedy's t-th piece always ends at or after the other split's t-th piece ends, because greedy extends as far as the cap allows. So greedy never needs more pieces. If it uses fewer than k, split any piece of length > 1 (there is one, since k <= n) without raising the max.

How to answer

Give the range [max, sum], the check, the exchange argument, and the complexity O(n log sum). Mention the O(n2 k) DP as the alternative.

Likely follow-ups
  • Book allocation with fewer books than students? (Return -1.)
  • Return the actual split? (Re-run the greedy at the final cap and record the cut points.)
Aggressive cows / Magnetic Force: maximise the minimum distance.

Sort positions. Answer is a gap in [1, last - first]. canPlace(g): greedily place a cow in the first stall and in every stall at least g after the last cow; true if you placed c. Smaller gaps are always placeable if larger ones are, so it is T..T F..F: find the last true (first false minus one). O(n log n + n log range).

How to answer

Call out explicitly that this is the "last true" shape, and show how you reuse first-true on the negated check. That avoids the off-by-one everyone makes here.

Likely follow-ups
  • Why greedy leftmost placement? (Placing each cow as early as allowed leaves the most room; any valid placement can be shifted left to the greedy one.)
Kth smallest element in a sorted matrix. Compare heap and binary search solutions.

Heap: push the first element of each row, pop k times, pushing the next element of the popped row: O(k log n), O(n) memory. Binary search on value: range [m[0][0], m[n-1][n-1]], check count(x) >= k with a staircase from the bottom-left in O(n): O(n log(range)) time and O(1) memory. The result is always an element of the matrix, because the first x with count >= k must equal some value (otherwise x - 1 would also qualify).

How to answer

Give the heap first if k is small, binary search when k is near n2 or memory matters. The "why is the answer in the matrix" argument is the usual follow-up; have it ready.

Likely follow-ups
  • Negative values? (Use lo + (hi - lo) / 2 so the midpoint rounds down.)
  • Rows sorted but columns not? (Count with a binary search per row: O(n log n log range).)
Median of two sorted arrays in O(log(m + n)).

Binary search the number of items i the shorter array A puts in the combined left half; B puts j = (m + n + 1) / 2 - i. With aL, aR, bL, bR around the cuts (infinities past the ends), the cut is right when aL <= bR and bL <= aR. If aL > bR, decrease i; if bL > aR, increase i. The median is max(aL, bL) for an odd total, otherwise the average with min(aR, bR). O(log min(m, n)).

How to answer

Draw the two arrays with the cut lines before coding. Explain why you search the shorter one (j must stay in range). Test with an empty array and with all of A smaller than all of B.

Likely follow-ups
  • K-th element of two sorted arrays? (Same cut with left size k, i in [max(0, k - n), min(k, m)].)
  • Median of k sorted arrays? (Binary search on value and count with bisect in each array: O(k log n log range).)
Minimum days to make m bouquets of k adjacent flowers.

If m * k > n return -1 (compute in 64 bits). Otherwise first-true over days in [min, max]: on day d scan the row, count a running streak of flowered plants, and each time the streak hits k add a bouquet and reset. More days only add flowers, so the check is monotone. O(n log(max bloom)).

How to answer

Mention the adjacency detail (resetting the streak) and the overflow on m * k; both are where candidates lose points.

Likely follow-ups
  • Can you avoid binary search? (Sort days and add plants with union-find, tracking runs: O(n log n), more code.)
How do you decide the search range and the loop shape for binary search on the answer?

lo = the smallest value that could possibly be the answer (often a hard lower bound like max(weight) or 1), hi = one past a value that surely works. Use the half-open first-true loop for "minimise", and negate the check (first false minus one) for "maximise". Then test on the two smallest ranges ([x, x + 1] and [x, x + 2]) by hand to be sure it stops.

How to answer

One template for everything, plus a sentence on why the range is safe. Interviewers want to see that you do not tweak +1 / -1 until the samples pass.

Likely follow-ups
  • Real-valued answer? (Fixed number of iterations, about 100, with lo = mid / hi = mid.)
Swim in Rising Water: binary search or Dijkstra?

The answer is the smallest time t such that a path from top-left to bottom-right uses only cells with height <= t. That check is a BFS in O(n2) and it is monotone in t, so binary search over t in [grid[0][0], n2 - 1] gives O(n2 log n). A min-max Dijkstra (always expand the lowest-height frontier cell) gives O(n2 log n) too, and union-find over cells sorted by height gives near O(n2 log n) with sorting.

How to answer

Offer the binary search plus BFS version as the safe one to code, then mention Dijkstra as the "one pass" version. Both are accepted.

Likely follow-ups
  • Path With Minimum Effort? (Same, check = BFS using edges with height difference <= x.)
