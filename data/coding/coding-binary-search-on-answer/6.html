The k-th smallest by counting

A different kind of monotone check: "are there at least k items <= x?". The count only grows as x grows, so the smallest x with count >= k is exactly the k-th smallest value. You never list the items; you only count them.

LeetCode 378, told our way: an n x n grid of integers where every row and every column is sorted in non-decreasing order. Return the k-th smallest value in the whole grid (counting duplicates, so it is the k-th in sorted order, not the k-th distinct). Constraints: 1 <= n <= 300, values between -109 and 109, 1 <= k <= n^2; aim for memory better than O(n2). Example: [[1, 5, 9], [10, 11, 13], [12, 13, 15]], k = 8 gives 13.

Search x over [grid[0][0], grid[n-1][n-1]] with ok(x) = count(x) >= k. The first true x is always a value that is in the grid: if x were not in the grid, then x - 1 would have the same count and would also be true, so x would not be the first.

ApproachTimeMemory
Flatten and sortO(n2 log n)O(n2)
Min-heap of row heads, pop k timesO(k log n)O(n)
Binary search on value + staircase countO(n log(max - min))O(1)

The same "count <= x" idea solves 668, Kth Smallest Number in Multiplication Table (count in row i is min(x / i, n)), 719, Find K-th Smallest Pair Distance (sort, then count pairs with distance <= d by two pointers), and 878, Nth Magical Number (count = x/a + x/b - x/lcm).

Negative bounds: with values down to -109, (lo + hi) / 2 rounds toward zero in C++, Java and Go, not down. Write lo + (hi - lo) / 2: since hi - lo >= 0, it always rounds down and the loop still terminates.
