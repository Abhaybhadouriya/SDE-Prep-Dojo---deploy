The recipe: four steps, every time

  1. Name the answer and its range. What number are you asked for? Find a lo that is surely no bigger than the answer and a hi that surely works. Koko: [1, max(piles)]. Ship packages: [max(weight), sum(weights)].
  2. Write ok(x), usually a greedy O(n) check. Not "what is the best?" but "is x enough?". Checking is much easier than optimising: that is the reason this trick exists.
  3. Prove monotonicity in one sentence. "If capacity c is enough, c + 1 is enough, because every day can carry what it carried before." If you cannot say this sentence, binary search is the wrong tool.
  4. Run first-true (minimise) or last-true (maximise). One loop, below. Cost: O(check x log(hi - lo)).

The one loop, the same half-open "first true" from the Binary Search page:

def first_true(lo, hi, ok):      # smallest x in [lo, hi) with ok(x), or hi
    while lo < hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid             # mid works: keep it
        else:
            lo = mid + 1         # mid fails, and so does everything below it
    return lo

# maximise: last x with ok(x) = first_true(lo, hi, lambda x: not ok(x)) - 1

Now watch it find Koko's speed. Notice it only evaluates 4 of the 11 speeds.

  1. Search range [lo, hi) = [1, 12): speed 11 = max pile always works, so the answer is in 1..11 and hi = 12 means "none" (never returned here).
  2. [1, 12): mid = 6, Koko needs 6 hours. 6 <= 8: T, mid may be the answer, so hi = mid = 6.
  3. [1, 6): mid = 3, Koko needs 10 hours. 10 > 8: F, every slower speed also fails, so lo = mid + 1 = 4.
  4. [4, 6): mid = 5, Koko needs 8 hours. 8 <= 8: T, mid may be the answer, so hi = mid = 5.
  5. [4, 5): mid = 4, Koko needs 8 hours. 8 <= 8: T, mid may be the answer, so hi = mid = 4.
  6. lo == hi == 4: the gap is empty. Answer 4, found with 4 feasibility checks of O(n) each.

Range size matters, not n. With answers up to 109, the loop runs about 30 times. With an O(n) check and n = 105, that is 3 x 106 operations: comfortable. So "values up to 109" in the constraints is a hint, not a threat.
