The problem (in our words)

A sign maker has a box of letter tiles described by the string s, which holds lowercase and uppercase English letters. Using some or all of those tiles, in any order, the maker wants to lay out the longest possible palindrome (a word that reads the same forwards and backwards). Return its length (an integer); you do not have to return the palindrome itself. Letters are case-sensitive: 'A' and 'a' are different tiles, so "Aa" is not a palindrome.

Signature: int longestPalindrome(String s).

Constraints

  • 1 <= s.length <= 2000
  • s consists of lowercase and/or uppercase English letters only.

Practice it: LeetCode 409 Longest Palindrome · yes/no version: GfG Anagram Palindrome

Constraints tell you: n is only 2000, so even an O(n2) counting loop passes, but the clean answer is one O(n) pass. The alphabet is 52 letters (two cases), so a fixed table of 52 or 128 counters (or one 64-bit parity mask) replaces a hash map. The answer is at least 1 because s is never empty.
