Use preorder DFS with a depth parameter: open rows[d] the first time depth d is reached and append to it. Left is visited before right, so each row is in order. O(n) time, O(h) stack instead of O(w) queue.

Say what decides the order (left before right within each depth) and compare h vs w.

Return the levels in zigzag order (left-to-right, then right-to-left).

Keep the BFS exactly as is and build each row into a fixed-size array: on odd levels write position width-1-i instead of i. Or reverse odd rows at the end. Do not change the push order of children: that breaks the next level.

How to answer

Separate "visit order" (always BFS) from "write order" (per row).

  • Can you do it with two stacks? (Yes: one per direction, pushing children in alternating order.)
Connect every node to its right neighbour on the same level, in O(1) extra space.

For a perfect tree (LC 116): walk level d using the next pointers you already set, and wire level d+1: left.next = right and right.next = node.next.left. The finished level replaces the queue. For any tree (LC 117), keep a dummy head and a tail pointer for the next level.

How to answer

The queue only stores "the next node on this level"; once next pointers exist, the level is a linked list.

Likely follow-ups
  • Why does recursion not count as O(1)? (The call stack is O(h).)
The tree is huge and the widest level does not fit in memory.

BFS needs the whole level in memory. Iterative deepening trades time for memory: for each depth d, run a depth-limited DFS that outputs nodes exactly at depth d (O(h) memory, O(n·h) time). If the tree is on disk, stream each level to a file and read it back as the next level's queue, like an external-memory BFS.

How to answer

Name the memory owner (the queue), then offer the time-for-memory trade.
