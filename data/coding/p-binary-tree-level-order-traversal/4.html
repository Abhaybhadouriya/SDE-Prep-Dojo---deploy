Approaches: brute -> better -> optimal

Hint 1

Which data structure hands out nodes in the order they were discovered?

Hint 2

At the moment you finish level d, what exactly is in the queue?

1. Brute force - one pass per depth

Idea: compute the height h. For each depth d = 0..h-1, walk the whole tree recursively and collect the nodes whose depth equals d (left subtree before right keeps the order).

O(n·h)time (O(n²) on a chain)
O(h)stack

What is wasted: every pass re-walks the upper levels that were already reported. For a 2000-node chain that is about 2 million node visits instead of 2000.

2. Better - DFS that carries the depth

Idea: one preorder DFS with a depth argument. When depth equals the number of rows so far, open a new row; then append the value to rows[depth]. Preorder visits left before right, so each row is filled left to right.

def dfs(node, d):
    if not node: return
    if d == len(rows): rows.append([])
    rows[d].append(node.val)
    dfs(node.left, d + 1); dfs(node.right, d + 1)
O(n)time
O(h)recursion stack

Why it is not the default answer: it is correct and short, but it is not what "level order" means to most interviewers, and on a 2000-deep chain Python's default recursion limit (1000) crashes it. Mention it as the alternative; it wins when the tree is wide and shallow (stack h vs queue w).

3. Optimal - BFS with a frozen level width

q = deque([root])
while q:
    row = [ ]
    for _ in range(len(q)):        # len(q) read once = this level's size
        node = q.popleft(); row.append(node.val)
        q.extend(c for c in (node.left, node.right) if c)
    levels.append(row)
  1. The queue holds exactly one level at the top of the loop. True at the start (just the root), and kept true by the next point.
  2. Freeze the width. Read width = len(q) once, then pop exactly width nodes. Those are all of level d, in left-to-right order.
  3. Children go to the back. Every child pushed during the drain is at depth d+1, and pushing left before right keeps them in order. After the drain, the queue holds exactly level d+1.
  4. Empty tree first. Return [] before creating the queue, or the loop would read a null root.
O(n)time: each node pushed and popped once
O(w)queue, w ≤ (n+1)/2 for a full tree

Why it works: a FIFO queue never lets a deeper node overtake a shallower one, because a node at depth d+1 is only pushed by a node at depth d. So the queue is always "rest of level d, then start of level d+1". Reading the size when the rest of level d is empty gives the exact boundary, with no depth tags or sentinels.

Proof (optional)

Induction on d. Claim: at the top of round d the queue holds all depth-d nodes, left to right. Round 0: only the root. Step: round d pops exactly those nodes in order and appends each one's children, left then right. Every depth-(d+1) node is the child of exactly one depth-d node, and a left-to-right walk of the parents with left-then-right children lists level d+1 left to right. Nothing else is pushed, so the claim holds for d+1.
