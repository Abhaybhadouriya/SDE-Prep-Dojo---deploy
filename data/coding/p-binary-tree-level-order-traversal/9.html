  • Cue: "level by level", "per depth", "left to right per row" on a tree -> BFS by levels.
  • Insight: at the top of each round the queue is exactly one level; freeze its size, drain that many.
  • State: queue of nodes, width (read once), row list, levels list.
  • Trap: re-reading q.size() inside the loop; forgetting the empty-tree check.
  • Cost: O(n) time, O(w) queue; DFS-with-depth is O(n) time, O(h) stack.
q = deque([root]) if root else deque()
while q:
    width = len(q)                    # freeze
    for _ in range(width):
        node = q.popleft(); visit(node)
        for child in children(node): q.append(child)
    end_of_level()

Why read the queue size before the inner loop?

  1. It is faster than calling size() each time
  2. Children pushed during the loop belong to the next level and must not be counted
  3. The queue can become empty during the loop
The size at the top of the round is exactly the number of nodes on this level.

What is the peak queue size for a full binary tree of n nodes?

  1. O(log n)
  2. O(1)
  3. About n/2
The last level of a full tree holds (n+1)/2 nodes, all queued at once.

Which traversal can produce the same output without a queue?

  1. Preorder DFS that passes the depth and appends to rows[depth]
  2. Postorder DFS without a depth
  3. Inorder DFS that prints values
Any DFS that visits left before right and knows the depth can fill rows[depth] in order.
