Common mistakes

  • Memorising answers instead of patterns. A quarter of reports were variants. A memorised Number of Islands breaks the moment it becomes "count distinct shapes".
  • Treating a low count as "not asked". Google's 84 reports reflect how Google candidates write, not how many problems Google asks.
  • Using only one source. This list (what candidates report) and the Premium company lists (what LeetCode users tag) disagree in useful ways; check both.
  • Skipping the follow-up. Finishing the base problem with ten minutes left and no answer to "now make it thread-safe" reads as SDE-1 at an SDE-2 loop.
  • Using the library LRU without asking. OrderedDict or LinkedHashMap can look like avoiding the question.
  • Recursive DFS on a large grid without a word about depth. A 300 x 300 grid of land is 90,000 frames deep in the worst case; say "I would use BFS or an explicit stack in production".
  • Marking BFS cells when popped. The same cell enters the queue several times; the answer can still be right but time and memory blow up.
  • Grinding the list in order once. Without spaced review, the first 20 problems are gone by the time you reach the last 20.
