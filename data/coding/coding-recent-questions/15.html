Google has 84 reports and Meta 577. What is the best reading?

  1. Google asks fewer coding questions
  2. Google interviews are easier
  3. Google candidates rarely name a LeetCode problem in their posts
Google writes its own problems, so posts describe them in prose and the script cannot match them. The count measures naming, not asking.

In the LRU cache, why does each node store its key?

  1. To compare nodes during get
  2. To sort the list
  3. So that evicting tail.prev can also delete its map entry
Eviction starts from the list, but the map is keyed by key. Without the key in the node, you cannot find the map entry in O(1).

A cache's get moves the node to the front. Can you protect it with a reader-writer lock, taking the read lock in get?

  1. No, get writes to the list
  2. Yes, if the capacity is large
  3. Yes, get only reads
Moving a node changes four pointers. Two readers moving nodes at once corrupt the list. Use one mutex, or shard.

Multi-source BFS on Rotting Oranges: what does the level number mean?

  1. The number of rotten oranges
  2. The minute at which those cells rot
  3. The row index
All sources start at level 0; each level is one minute of spreading, so the last level reached is the answer.

Which round type had the highest share of Hard problems in the data?

Merge Intervals becomes "intervals arrive one by one". Which structure fits?

  1. A hash map keyed by start
  2. An ordered map keyed by start
  3. A min-heap of ends
You need "the interval just before this start" and in-order neighbours, which only an ordered structure gives in O(log n).
