  • Cue: count routes on a grid, moves only right/down (a DAG); no obstacles here.
  • Insight: last move is from above or from the left: ways = up + left; also C(m+n-2, m-1).
  • State: ways[c] for the current row; edges are 1; ways[c] += ways[c-1].
  • Trap: formula overflow (64-bit, multiply then divide); edges must start at 1.
  • Cost: DP O(m·n) time, O(n) space; formula O(min(m,n)); brute 2^(m+n).
ways = [1] * cols                 # first row
for r in range(1, rows):
    for c in range(1, cols):
        ways[c] += ways[c - 1]        # above + left (add 0 for a blocked cell)
return ways[-1]

In ways[c] += ways[c-1], what does the old ways[c] hold?

  1. The cell to the left
  2. The answer so far
  3. The cell directly above (previous row)
Before the update the slot still holds the previous row's value; ways[c-1] was already updated in this row.

How many routes for m = 4, n = 3?

  1. 10
  2. 12
  3. 7
C(5, 2) = 10. The grid is symmetric in m and n.

Why do the two terms of the transition never double-count?

  1. Because the grid has no obstacles
  2. A route's last move is either down or right, never both
  3. Because the answer is below 2 × 10^9
The two groups are split by the last move, so they are disjoint.
