Approaches: brute → better → optimal

Hint 1

The last move into the target is either "down" or "right". Where was the robot just before?

Hint 2

Every route has the same number of down moves and the same number of right moves.

1. Brute force - try both moves from every cell

Idea: f(r, c) = routes from (r, c) to the target = f(r+1, c) + f(r, c+1), with 1 at the target and 0 outside the grid.

O(2^(m+n))time
O(m+n)stack

What is wasted: the call tree has one leaf per route (and C(198, 99) ≈ 10^58 routes exist on a 100 × 100 grid). Yet there are only m·n different calls.

2. Better - full table (memo or bottom-up)

  1. State: ways[r][c] = number of routes from (0, 0) to (r, c).
  2. Transition: ways[r][c] = ways[r-1][c] + ways[r][c-1]: the last move came from above or from the left, and those two sets of routes never overlap.
  3. Base case: row 0 and column 0 are all 1.
  4. Answer: ways[m-1][n-1].
O(m·n)time
O(m·n)space

What is wasted: row r only reads row r - 1. All older rows are dead.

3. Optimal (DP) - one rolling row

ways = [1] * n
for _ in range(1, m):
    for c in range(1, n):
        ways[c] += ways[c - 1]     # above (old ways[c]) + left (new ways[c-1])
return ways[n - 1]
  1. Space optimisation: before the update, ways[c] still holds the value from the row above; ways[c-1] already holds the new value to the left. One in-place add does both.
  2. Go left to right. The left neighbour must be updated before it is read.
  3. Use the shorter side as the row (swap m and n) for O(min(m, n)) space, if asked.
  1. Base: every cell in row 0 and column 0 holds 1. The robot can reach them in exactly one way (all right, or all down).
  2. (1,1) = from above 1 + from the left 1 = 2.
  3. (1,2) = above 1 + left 2 = 3.
  4. (1,3) = above 1 + left 3 = 4. Row 1 is done; row 0 is never read again.
  5. (2,1) = above 2 + left 1 = 3.
  6. (2,2) = above 3 + left 3 = 6.
  7. (2,3) = above 4 + left 6 = 10. The goal cell holds the answer: 10 paths.
  8. Each cell only read the cell above (same column, previous row) and the cell to the left (same row). One array of n numbers updated in place, ways[c] += ways[c-1], is enough.
O(m·n)time
O(n)space

4. Optimal (math) - choose where the downs go

Idea: every route is a word of exactly (m-1) D's and (n-1) R's, and every such word is a route. So the count is C(m+n-2, k) with k = min(m, n) - 1. Compute it as a running product res = res × (total - k + i) / i for i = 1..k. After step i, res equals C(total - k + i, i), an integer, so each division is exact.

O(min(m, n))time
O(1)space

Why it works: the DP counts routes by their last move, and those two groups are disjoint and cover everything, so adding them never double-counts. The formula counts the same routes as move words. The two agree because Pascal's rule C(a, b) = C(a-1, b) + C(a-1, b-1) is exactly the DP transition.

Proof (optional)

A route from (0,0) to (m-1,n-1) changes the row index from 0 to m-1 using only +1 steps, so it has exactly m-1 D moves, and likewise n-1 R moves: m+n-2 moves in all. Mapping a route to its move word is a bijection onto words with m-1 D's (any such word stays inside the grid because the row and column counts never exceed m-1 and n-1). The number of such words is C(m+n-2, m-1).

Stuck on overflow?

Multiply first, then divide, in 64 bits: res × (next numerator) ≤ 2 × 10^9 × 199 ≈ 4 × 10^11. Dividing first (res / i × ...) is not exact and gives wrong answers.
