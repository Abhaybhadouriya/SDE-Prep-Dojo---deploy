Some cells are blocked.

That is LC 63. A blocked cell gets 0; the first row and column are 1 only up to the first block. In the rolling row: ways[c] = 0 if blocked else ways[c] + ways[c-1] (and handle c = 0 separately). The binomial shortcut no longer works.

How to answer

Say which line changes: the combine step becomes "0 if blocked".

Likely follow-ups
  • What if the start itself is blocked? (Answer 0.)
Compute it in O(1) space without DP.

Use C(m+n-2, k) with k = min(m-1, n-1) as a running product in 64 bits: multiply by the next numerator, then divide by i. Each partial result is itself a binomial coefficient, so the division is exact. For answers modulo a prime p, use factorials and modular inverses (Fermat) instead of division.

How to answer

State the bijection (routes = move words), then the overflow-safe loop.

Likely follow-ups
  • Why is the division exact at every step?
The robot may also move diagonally (down-right).

Add a third parent: ways[r][c] = up + left + diag. With a rolling row, keep the old value of ways[c-1] from before its update in a temporary (it is the diagonal). These are the Delannoy numbers; there is no single binomial any more.

How to answer

The DP generalises to any set of monotone moves; just list the parents.

Likely follow-ups
  • Moves in all four directions with no revisits? (Then it is not a DAG: backtracking, LC 980.)
Count paths that must pass through a given cell (x, y).

Paths through (x, y) = paths(start → (x, y)) × paths((x, y) → target) = C(x+y, x) × C((m-1-x)+(n-1-y), m-1-x). Each part is the same problem on a smaller grid.

How to answer

Split the route at the forced cell; the halves are independent, so multiply.

Likely follow-ups
  • Paths that avoid a cell: total minus paths through it.
