Revision card

  • Cue: min rooms / platforms / servers for intervals -> max overlap depth.
  • Insight: depth = #starts - #ends so far; starts and ends can be sorted separately.
  • State: sorted starts, sorted ends, pointer e, rooms (or a min-heap of end times).
  • Trap: half-open: start == end shares a room (s < ends[e] means busy).
  • Cost: O(n log n) time, O(n) space; brute O(n²); diff array O(n + T).
starts, ends = sorted(starts), sorted(ends)
used = e = 0
for s in starts:
    if s < ends[e]: used += 1    # all still busy: new resource
    else: e += 1                 # reuse the one freed earliest
return used

Meetings [1, 5] and [5, 9]. How many rooms?

  1. 1, the first ends when the second starts
  2. 2
  3. 0
  4. it depends on the order
Intervals are half-open: a room freed at 5 can be reused at 5. Use start < ends[e] for 'still busy'.

Why can starts and ends be sorted separately?

  1. it is an approximation
  2. the overlap depth at any time is (#starts so far) - (#ends so far), whoever owns them
  3. only when meetings do not nest
  4. to save memory
Room count does not care which meeting ends, only how many have.

What does a min-heap of end times give you?

  1. the longest meeting
  2. the room that frees up first; reuse it if it is free by the next start
  3. the sorted output
  4. nothing extra
The heap size at the end is the number of rooms.
