Approaches: brute → better → optimal

Hint 1

Forget rooms for a moment. At the busiest instant, how many meetings are running? Can you do it with fewer rooms than that?

Hint 2

Process meetings by start time. When a new one starts, which existing room is the best one to try?

Hint 3

To know whether "some room is free", you only need the earliest end time among busy rooms.

1. Brute force - count overlaps at every start

Idea: the overlap depth only changes at a start time, so for each meeting's start t count the meetings with s ≤ t < e. The maximum count is the answer.

O(n²)time
O(1)space

What is wasted: each count rescans all n meetings; after sorting, the count at the next start differs from the current one only by the meetings that ended in between. -> rung 2.

2. Better - sort by start, min-heap of end times

Idea: keep one heap entry per busy room, holding the time that room becomes free. For each meeting in start order: if the smallest end ≤ start, that room is free, so pop it; then push this meeting's end. The heap size at the end (its largest size ever) is the answer.

busy = []                                  # end times of rooms in use
for s, e in sorted(intervals):
    if busy and busy[0] <= s: heapq.heapreplace(busy, e)   # reuse the earliest free room
    else: heapq.heappush(busy, e)                          # open a new room
return len(busy)
O(n log n)time
O(n)space

When it is the right one: this version actually assigns meetings to rooms, so it extends to "which room does each meeting get" and to Meeting Rooms III. If the question is only "how many", the heap is more machinery than needed. -> rung 3.

3. Optimal (simplest) - two sorted arrays, one sweep

starts, ends = sorted(s for s, _ in iv), sorted(e for _, e in iv)
for s in starts:
    if s < ends[e]: rooms += 1       # nobody has left yet
    else: e += 1                     # one meeting has ended: reuse its room
  1. Only counts matter, not pairs. The depth at time t is (#starts ≤ t) - (#ends ≤ t), so starts and ends can be sorted independently.
  2. Walk the starts in order. ends[e] is the earliest end not yet "used to free a room".
  3. A start before that end needs a new room. Every meeting counted so far is still running.
  4. Otherwise a room has been freed. Consume one end (e++) instead of adding a room. Using < (not <=) makes back-to-back meetings share.
O(n log n)time (two sorts)
O(n)space

Why it works: rooms only grows when the number of started meetings minus the number of ended ones exceeds every earlier value, so it ends as the maximum overlap depth. That many rooms are necessary (those meetings run at one instant), and the greedy reuse shows they are enough: a room freed at ends[e] ≤ s is idle when the new meeting starts.

Proof (optional)

Let D = max over t of |{i : si ≤ t < ei}|. Lower bound: at the instant of maximum depth, D meetings pairwise overlap and need D rooms. Upper bound: consider the heap version. When a meeting starting at s opens a new room, every busy room ends after s, so all of them plus the new one run at time s: the heap size never exceeds D. The two-array sweep computes D directly. Every start increments exactly one of rooms and e, so after k starts rooms = k - e. An end is consumed only when it is ≤ the current start, so e ≤ (#ends ≤ sk). Upper bound: when rooms grows at sk, ends[e] > sk, so e is exactly #ends ≤ sk and rooms = k - #ends ≤ sk ≤ depth(sk) ≤ D. Lower bound: let t be an instant of depth D and sk the last start ≤ t; then rooms ≥ k - e ≥ k - #ends ≤ sk ≥ k - #ends ≤ t = D.

Third option, difference array: +1 at each start, -1 at each end, then a prefix sum; the maximum is the answer. O(n + T) with T = 106, or O(n log n) with a sorted map of events (C++ map, Java TreeMap), which is the version to reach for when meetings are added online (My Calendar III).
