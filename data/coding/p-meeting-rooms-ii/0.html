The story

Explain like I'm 5

A dentist's office has a pile of appointments for tomorrow, each with a start and an end time. How many chairs must be ready? Walk through the day in order of start times. When a patient arrives, look at the chair that will be free soonest: if its patient has already left, reuse it; if not, everyone is still busy and you need one more chair. The number of chairs you ever had to add is the answer.

The answer does not depend on which meeting goes to which room, only on how many overlap at the busiest moment. That observation lets us drop the pairing of starts with ends entirely.

This is "peak concurrent connections" from a trace of open/close timestamps, or the minimum size of a worker pool so no request waits. The min-heap version is a timer queue: the earliest expiry sits on top, and a new arrival checks it before allocating another slot.
