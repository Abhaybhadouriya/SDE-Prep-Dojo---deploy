Interview follow-ups

Return which room each meeting gets.

Use the heap version with pairs (end, roomId): sort meetings by start (keep the original index), pop the earliest-ending room if it is free and reuse its id, else create id = heap size. O(n log n).

How to answer

Point out that the two-array sweep loses the pairing, so this follow-up is why the heap version exists.

Likely follow-ups
  • Always prefer the lowest-numbered free room (two heaps, LC 2402).
Meetings are booked one at a time; after each booking report the rooms needed.

Keep a sorted map time -> delta (+1 at start, -1 at end). Each booking updates two keys; recomputing the max by a scan is O(n) per booking (LC 732 accepts it). For O(log T) per booking use a segment tree with range add and global max over compressed times.

How to answer

Start with the map (simple), then offer the segment tree if they push on complexity.

Likely follow-ups
  • Support cancellations (range add of -1 on the same tree).
At what time is the office busiest, and for how long?

Sweep sorted events (ends before starts at equal times, for half-open intervals); when the running count reaches a new max, record the time; the peak lasts until the next event.

How to answer

Spell out the tie rule; it is the same as the < vs <= choice in the code.

Likely follow-ups
  • Return all maximal busy windows.
Each room has a capacity and each meeting a head-count.

It becomes a bin-packing-like assignment and is NP-hard in general. With identical rooms of capacity C and meetings that always fit, a greedy best-fit by room capacity is a heuristic; for an exact answer on small inputs, backtracking. Say this out loud instead of forcing the sweep.

How to answer

Recognise when the problem leaves the "max overlap" family.

Likely follow-ups
  • Rooms with sizes and meetings with sizes, but each meeting needs size ≤ room: sort rooms, use a balanced tree per size class.
The times are small integers (minutes in a day). Can you avoid sorting?

Yes: an array of 1441 counters, +1 at start, -1 at end, prefix sum, take the maximum. O(n + T) with T = 1440.

How to answer

Read the value range: a small T turns sorting into counting.

Likely follow-ups
  • What if T = 109? (Coordinate-compress, which is sorting again.)
