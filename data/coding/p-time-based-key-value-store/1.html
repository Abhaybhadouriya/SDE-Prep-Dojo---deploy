The problem (in our words)

Design a key-value store that keeps several values per key, each tagged with the time it was written, and can answer "what was the value of this key at time t?". Implement class TimeMap:

  • TimeMap() creates an empty store.
  • void set(String key, String value, int timestamp) records that key had value from time timestamp on.
  • String get(String key, int timestamp) returns a value stored by an earlier set(key, value, timestamp_prev) with timestamp_prev <= timestamp. If several such calls exist, it returns the value with the largest timestamp_prev (the latest one). If no such call exists, return "".

Input format (LeetCode style): a list of operation names and a parallel list of argument lists, for example ["TimeMap","set","get"], [[],["eth0","up",8],["eth0",9]]; the output is the list of return values, with null for the constructor and for set.

  • 1 <= key.length, value.length <= 100
  • key and value consist of lowercase English letters and digits.
  • 1 <= timestamp <= 107
  • All the timestamps of set calls are strictly increasing.
  • At most 2 · 105 calls in total to set and get.

Practice it: LeetCode 981

Constraints tell you: 2 · 105 calls means get must be about O(log n); scanning a key's whole history per get is O(n²) = 4 · 1010 in the worst case (one key, half sets, half gets). "Strictly increasing timestamps" is the gift: appending keeps every list sorted, so you never need a balanced tree.
