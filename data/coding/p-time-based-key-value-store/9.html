  • Cue: "value as of time t" / latest version <= t -> floor lookup per key.
  • Insight: set times strictly increase, so appending keeps each key's list sorted.
  • State: map key -> [(time, value)]; get = upper_bound(t) - 1.
  • Trap: upper (not lower) bound for <=; i == 0 -> ""; no copies, no inserts on reads.
  • Cost: set O(1), get O(log n), O(n) memory; TreeMap floorEntry if times arrive unordered.
def floor_index(times, t):        # last index with times[i] <= t, or -1
    lo, hi = 0, len(times)
    while lo < hi:
        mid = (lo + hi) // 2
        if times[mid] <= t: lo = mid + 1
        else: hi = mid
    return lo - 1

Key k was set at times [1, 4, 9]. get(k, 7) returns the value set at which time?

  1. 4
  2. 9
  3. 1
  4. None: return ""
It is the latest time <= 7.

With upper_bound(t) - 1 on [1, 4, 9], what index do you get for t = 9 and for t = 0?

  1. 2, and -1 (return "")
  2. 1, and 0
  3. 2, and 0
  4. 3, and -1
upper_bound(9) = 3, so the index is 2. upper_bound(0) = 0, so the index is -1 and there is no value.

Why is lower_bound(t) - 1 wrong?

  1. When t equals a stored time, lower_bound points at it and -1 steps back to the older version
  2. It is slower
  3. It fails only on empty lists
  4. It gives the same answer
For a floor (<= t) you need the first time > t, minus one.
