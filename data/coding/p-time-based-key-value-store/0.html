The story

Explain like I'm 5

A school keeps one notebook per child, and every time a child changes seats the teacher writes the time and the new seat on the next line. Later someone asks "where was Maya sitting at 10:40?" The teacher opens Maya's notebook and finds the last line written at or before 10:40. Because lines are written in time order, she can flip to the middle, see if it is too late, and halve the pages each time.

Two lookups: which notebook (a hash map), then which line (binary search in a sorted list).

From your world

This is a multi-version store, the idea behind MVCC snapshots in databases and etcd's revision history: read "the value of a key as of revision t". Closer to the kernel, it is how you would answer "what was the route / ARP entry at time t" from an append-only change log, or look up which timer slot a timestamp falls in.
