Approaches: brute → better → optimal

Hint 1

Look at the last locker. In the best plan, is it opened or not? What does each case leave you with?

Hint 2

If it is opened, the locker before it is closed, so the rest is the best plan for the first n-2 lockers.

1. Brute force - plain recursion over both choices

Idea: let f(i) be the best total using lockers 0..i. Either locker i stays closed, giving f(i-1), or it is opened, giving nums[i] + f(i-2). Return the larger, with f(-1) = f(-2) = 0.

O(1.6^n)time (Fibonacci-sized call tree)
O(n)stack

What is wasted: the same f(i) is computed again and again. There are only n distinct calls.

2. Better - memoised recursion (top-down)

Idea: the same recursion, plus an array memo[i]. The first call for i computes and stores it; every later call returns the stored value.

O(n)time
O(n)memo + stack

What is wasted: a recursion stack of depth n and an n-sized array. Python's default recursion limit (1000) is fine for n = 100 but not for a follow-up with n = 10^5.

3. Better - bottom-up table

  1. State: best[i] = the largest total using only lockers 0..i.
  2. Transition: best[i] = max(best[i-1], best[i-2] + nums[i]) - skip locker i, or open it and use the best plan that ends two lockers earlier.
  3. Base case: best[0] = nums[0], best[1] = max(nums[0], nums[1]); or treat best[-1] = best[-2] = 0.
  4. Answer: best[n-1].
O(n)time
O(n)space

What is wasted: each cell is read only by the next two cells, so most of the array is dead weight.

4. Optimal - two rolling variables

prev2, prev1 = 0, 0          # best up to i-2, best up to i-1
for x in nums:
    prev2, prev1 = prev1, max(prev1, prev2 + x)
return prev1
  1. Space optimisation: keep only best[i-1] (prev1) and best[i-2] (prev2).
  2. Start both at 0. That is the "no lockers yet" plan, so n = 1 needs no special case.
  3. Slide them together. The new prev2 is the old prev1; the new prev1 is the max of skip and take. Do the update in one step (tuple assignment or a temporary), never in the wrong order.
  4. Top-down version: rung 2; say it if the interviewer prefers recursion, then convert.
O(n)time
O(1)space

Why it works: an optimal plan for lockers 0..i either leaves locker i closed (then it is an optimal plan for 0..i-1) or opens it (then locker i-1 is closed and the rest is an optimal plan for 0..i-2). Both options are checked, so best[i] is optimal. Because values are ≥ 0, best[i] never decreases, which is also why skipping is always safe.

Proof (optional)

Induction on i. Assume best[j] is optimal for every j < i. Take any valid plan P for 0..i. If i ∉ P, P is valid for 0..i-1, so sum(P) ≤ best[i-1]. If i ∈ P, then i-1 ∉ P and P \ {i} is valid for 0..i-2, so sum(P) ≤ nums[i] + best[i-2]. Both bounds are reached by real plans, so best[i] = max of the two is the optimum.
