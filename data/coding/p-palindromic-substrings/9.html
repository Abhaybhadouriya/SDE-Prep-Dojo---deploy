  • Cue: "palindromic substrings" count/longest -> expand around centres.
  • Insight: 2n - 1 centres; palindromes per centre are nested, first mismatch ends them.
  • State: c in [0, 2n-2], lo = c/2, hi = lo + c%2; count each successful expansion.
  • Trap: forgetting gap centres; counting distinct strings; wrong DP fill order.
  • Cost: O(n²) time, O(1) space; DP O(n²) space; Manacher O(n).
for c in range(2 * n - 1):
    lo, hi = c // 2, c // 2 + c % 2
    while lo >= 0 and hi < n and s[lo] == s[hi]:
        total += 1; lo -= 1; hi += 1

How many centres does expand-around-centre try for a string of length n?

  1. n
  2. 2n - 1 (each character and each gap between two characters)
  3. n^2
Odd-length palindromes centre on a character, even-length ones on a gap.

What does each successful expansion step add to the answer?

  1. The palindrome's length
  2. Exactly 1 palindromic substring
  3. 2 substrings
Every step outwards that still matches is one more distinct (start, end) palindrome.

Time and extra space of expand-around-centre?

  1. O(n^2), O(1)
  2. O(n), O(n)
  3. O(n^3), O(1)
2n - 1 centres, each expanding up to O(n); no table is needed (Manacher gets O(n)).
