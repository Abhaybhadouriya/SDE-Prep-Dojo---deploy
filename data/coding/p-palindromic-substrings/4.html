Approaches: brute -> better -> optimal

Hint 1

If s[i..j] is a palindrome, what do you know about s[i+1..j-1]?

Hint 2

Where is the "middle" of a palindrome of odd length? Of even length?

Hint 3

How many different middles can a string of length n have?

1. Brute force - test every substring

Idea: for every pair i <= j, check s[i..j] with two pointers.

O(n³)time
O(1)space

What is wasted: checking s[i..j] repeats the work of checking s[i+1..j-1]. -> rung 2 stores that answer, rung 3 reuses it implicitly.

2. Better - interval DP table

Idea: pal[i][j] is true when s[i] == s[j] and the inside is a palindrome: j - i < 2 (one or two letters) or pal[i+1][j-1]. Fill by increasing length (or i from n-1 down to 0, j from i up), and count the true cells.

  1. State: pal[i][j] = true when s[i..j] reads the same both ways.
  2. Transition: pal[i][j] = (s[i] == s[j]) and (j - i < 2 or pal[i+1][j-1]): equal ends around a palindromic inside.
  3. Base case: every single letter (i == j) is a palindrome; a pair j = i + 1 needs only s[i] == s[j].
  4. Answer: the number of true cells; fill by increasing length (or i from n-1 down) so pal[i+1][j-1] is ready.
O(n²)time
O(n²)space (10^6 booleans at n = 1000)

What is good: the table answers "is s[i..j] a palindrome" in O(1) afterwards, which is exactly what Palindrome Partitioning (131/132) needs. For counting alone it is memory you do not need.

3. Optimal for interviews - expand around 2n - 1 centres

  1. Enumerate centres with one index c from 0 to 2n - 2: lo = c / 2, hi = lo + c % 2. Even c is a letter (odd-length palindromes), odd c is a gap (even-length ones).
  2. Expand while lo >= 0, hi < n and s[lo] == s[hi]: count one palindrome, then lo--, hi++.
  3. Stop at the first mismatch - every longer substring with this centre contains it.
O(n²)time worst case ("aaaa...")
O(1)extra space

Why it works: each palindromic substring s[i..j] has exactly one centre, c = i + j, and it is reached from that centre after (j - i) / 2 successful expansions (each inner layer is a palindrome too). Different (i, j) pairs either have different centres or different lengths, so no substring is counted twice and none is missed.

O(n): Manacher's algorithm (optional)

Manacher computes, for every centre, the radius of its longest palindrome in linear time by reusing the mirror image inside the rightmost palindrome found so far. The count is then the sum over centres of (number of palindromes per centre) = (radius + 1) / 2 in the "#"-separated string. Mention it; interviewers rarely want it coded for this problem.
