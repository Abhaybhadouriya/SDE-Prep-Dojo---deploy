Approaches: brute → better → optimal

Hint 1

The median splits the merged list into a left half and a right half of equal size (the left gets one extra when the total is odd). How many of the left half come from a?

Hint 2

If you knew that count i, the count from b would be fixed. What two comparisons tell you whether i is right, too small or too large?

1. Brute force - merge (or concatenate and sort)

Idea: build the merged sorted array with the two-pointer merge from merge sort, then read the middle one or two values. Concatenating and calling sort is O((m + n) log(m + n)) and also fine as a first sentence.

O(m + n)time
O(m + n)space

What is wasted: we build and store the whole merged list, but we only need one or two values from its middle.

2. Better - merge walk without storing

Idea: run the same two pointers but keep only the last two values seen; stop after (m + n) / 2 + 1 steps. The middle value(s) are the last ones you passed.

O(m + n)time
O(1)space

What is wasted: we still walk past half of all elements one at a time. Both arrays are sorted, so we can jump: guess a split and fix it by halving the search range.

3. Optimal - binary search on the cut of the shorter array

i = (lo + hi) // 2; j = half - i                 # core: cut a at i, b at j
if a[i-1] <= b[j] and b[j-1] <= a[i]: answer from max(a[i-1], b[j-1]) and min(a[i], b[j])
elif a[i-1] > b[j]: hi = i - 1                    # too many from a
else: lo = i + 1                                  # too few from a
  1. The median is a cut, not a value. Split the merged list into a left part of size half = (m + n + 1) / 2 and a right part. Odd total: the median is the largest left value. Even: the average of the largest left and smallest right.
  2. One unknown. The left part is a[0..i) plus b[0..j) with i + j = half. Choose i and j is forced.
  3. Two cross checks decide. Each array is sorted on its own, so the cut is right exactly when a[i-1] ≤ b[j] and b[j-1] ≤ a[i]. If a[i-1] > b[j], a gave too many: go left. If b[j-1] > a[i], a gave too few: go right.
  4. Search the shorter array. With m ≤ n, every i in [0, m] gives j = half - i inside [0, n], so j never goes out of range. The search costs O(log m).
  5. Sentinels for empty sides. a[-1] is -infinity and a[m] is +infinity (same for b). Then i = 0, i = m and an empty array need no special code.
O(log min(m, n))time (meets O(log(m + n)))
O(1)space

Why it works: as i grows, a[i-1] grows and b[j] shrinks (j falls), so "a[i-1] > b[j]" is false for small i and true from some point on; "b[j-1] > a[i]" is true for small i and false later. The valid cut is the one i where both are false, and halving the range always keeps it inside. Choosing half = (m + n + 1) / 2 puts the extra element on the left, so odd and even totals share one formula.

Proof (optional)

Let L = a[0..i) ∪ b[0..j) with i + j = half. If both cross checks hold, then max(L) ≤ min(rest) because inside each array order is given and across arrays the two checks cover the only two unchecked pairs. So L is exactly the half smallest elements and the median formula is correct. Existence: take the true merged order and count how many of its first half elements come from a; that i passes both checks (ties broken by position). Uniqueness of direction: if a[i-1] > b[j] then any i' ≥ i also fails (a[i'-1] ≥ a[i-1], b[j'] ≤ b[j]), so discarding [i, hi] loses nothing; the mirror holds for the other check. Hence the loop finds the cut in O(log m) iterations.
