Return the split as well, not only the capacity.

Run the greedy loader once more with the final capacity and record where each day starts. It uses at most D days; if the caller insists on exactly D non-empty days, split the longest days further (always possible since D <= n).

How to answer

The search gives the value; one extra O(n) pass gives the witness.

Likely follow-ups
  • Is the split unique? (No; greedy gives the one that front-loads.)
Can you tighten the bounds?

Yes: lo = max(max(weights), ceil(sum / days)), since D days of capacity c carry at most D·c. hi can be ceil(sum / days) + max(weights), because greedy with that capacity never wastes more than one package per day. The number of steps drops to log(max), about 9 for weights up to 500.

How to answer

Derive lo from the average load and hi from "each day loses less than one package".

Likely follow-ups
  • Does it change the big-O? (O(n log max) instead of O(n log sum); same in practice.)
The packages may be loaded in any order.

Then it is bin packing (NP-hard): minimise the bin size for D bins. Exact answers need search with pruning (sort descending, backtrack into D bins, binary search the capacity outside) for small n; for large n use heuristics like first-fit decreasing.

How to answer

Recognise that the fixed order is what makes the greedy check exact.

Likely follow-ups
  • Small n version? (LC 1723 Find Minimum Time to Finish All Jobs.)
Many queries: different values of days on the same weights.

Build prefix sums once. The greedy check then jumps day by day with a binary search on the prefix sums (the farthest index whose load fits), so one check costs O(D log n) instead of O(n). For many queries with small D that is a large saving.

How to answer

Replace the linear scan inside the check with "next cut = upper_bound(prefix, start + c)".

Likely follow-ups
  • Precompute the answer for every D? (Answers are non-increasing in D; divide and conquer over D.)
How would you solve it with DP, and why is binary search better?

dp[d][i] = the minimum capacity to ship the first i packages in d days = min over j of max(dp[d-1][j], sum(j..i-1)). That is O(D·n²), up to about 1014 steps here. Binary search uses the monotone structure and is O(n log sum).

How to answer

Give the DP state, then show its cost, then switch.

Likely follow-ups
  • When would you keep the DP? (When the cost of a group is not monotone, e.g. it depends on more than the sum.)
