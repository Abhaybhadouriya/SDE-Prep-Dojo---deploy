Approaches: brute -> better -> optimal

Hint 1

If someone gives you a capacity, how fast can you tell whether D days are enough?

Hint 2

What is the smallest capacity that could possibly work? The largest one you would ever need?

1. Brute force - try every capacity upward

Idea: for c = max(weights), max+1, ..., run the greedy day count; return the first c that needs at most days days.

O(n · (sum - max))time
O(1)space

What is wasted: the checks for consecutive capacities give the same ✗ again and again. Because the answers are sorted (✗ then ✓), one check can rule out half the range. -> rung 2.

2. Optimal - binary search on the capacity with a greedy check

lo, hi = max(weights), sum(weights)
while lo < hi:
    mid = (lo + hi) // 2
    if days_needed(mid) <= days: hi = mid      # mid works: answer <= mid
    else:                         lo = mid + 1  # mid fails: answer > mid
return lo
  1. The check is greedy: load each day as full as possible. Loading less today can never reduce the total days, because it only pushes packages later.
  2. The check is monotone: a bigger capacity never needs more days (every day can hold at least what it held before).
  3. The bounds are tight: lo = max(weights) is the least that can carry the heaviest package; hi = sum(weights) always works (one day).
  4. Lower-bound search: keep hi on a capacity known to work and lo just above capacities known to fail; when they meet, that is the first ✓.
O(n log(sum))time, about 25 checks
O(1)space

Why the greedy check is right: take any valid split of the packages into at most D days with capacity c. Compare day 1 with the greedy day 1: greedy packs at least as many packages. By induction, after any number of days the greedy has shipped at least as many packages as the other split, so it never needs more days. Hence "greedy needs <= D days" is exactly "some split works".

Proof (optional): why the loop returns the minimum

Invariant: f(hi) is true and f(lo - 1) is false (or lo is the lower bound). Each step keeps it: f(mid) true sets hi = mid, f(mid) false sets lo = mid + 1. The range shrinks every step because mid < hi. At lo = hi, f(lo) is true and f(lo - 1) is false, so lo is the first feasible capacity.
