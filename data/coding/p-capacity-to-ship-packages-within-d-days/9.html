60-second recall

  • Cue: "minimum X so that it fits within a limit", easy check, hard formula -> search on X.
  • Insight: feasible(c) is monotone; greedy loading gives the fewest days for c.
  • State: lo = max(w), hi = sum(w); hi always feasible, lo-1 infeasible.
  • Trap: lo must be max(w); hi = mid / lo = mid + 1 with lo < hi; used starts at 1.
  • Cost: O(n log sum) time, O(1) space; brute is O(n · sum).
lo, hi = smallest_possible, largest_needed   # first true of a monotone f
while lo < hi:
    mid = (lo + hi) // 2
    if feasible(mid): hi = mid
    else: lo = mid + 1
return lo

What is the correct lower bound for the capacity?

  4. min(weights)
The heaviest package must fit on some day.

Why can we binary search on the capacity?

  1. The weights are sorted
  2. The days are sorted
  3. The greedy check is O(log n)
  4. A bigger capacity never needs more days
Feasibility is monotone: false ... false, true ... true.

With while lo < hi, a feasible mid should set...

  1. hi = mid
  2. hi = mid - 1
  3. lo = mid
  4. lo = mid + 1
mid itself may be the answer, so keep it in range.
