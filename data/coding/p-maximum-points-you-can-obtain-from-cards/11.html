Instead of exactly k cards, remove cards from the ends until the removed total is exactly x. Fewest removals?

The kept middle part must sum to total - x. Find the longest subarray with that sum: with positive values, a variable sliding window (grow right, shrink left while the sum is too big). Answer n - longest, or -1 if none exists; if total - x is 0, the answer is n. This is LC 1658.

How to answer

Reuse the complement view: "ends removed" = "middle kept".

Likely follow-ups
  • With negative values the window breaks; use prefix sums and a hash map of first occurrence.
The i-th card you take is multiplied by mult[i]. What changes?

Now the order matters, so the split argument fails. DP on (cards taken from the left, step number): the right index is determined by the two. O(m²) time with O(m) memory by rolling rows (LC 1770).

How to answer

Point to the exact property the O(k) solution relied on ("order does not change the score") and show it is gone.

Likely follow-ups
  • Why is the state 2D and not 3D? (left + right = step.)
Return which cards to take, not only the score.

Record the best i (cards from the right) when best improves. The answer is indices 0..k-i-1 and n-i..n-1. With the complement version, record the start of the minimum window: the taken cards are everything outside it.

How to answer

Store the split, not the list; build the list at the end.

Likely follow-ups
  • Several splits tie; which one do you return? (Say the rule.)
Two players alternate taking from the ends; both play optimally. Can the first player win?

That is a game, not this problem: dp[l][r] = best score difference the player to move can get on cards l..r = max(a[l] - dp[l+1][r], a[r] - dp[l][r-1]). O(n²). (LC 486 Predict the Winner, LC 877 Stone Game.)

How to answer

Name the difference: an opponent's choices make the order matter again.

Likely follow-ups
  • For an even number of piles with an odd total, why does the first player always win LC 877?
Which of your two O(1)-space versions would you code, and why?

The trading loop is O(k) and has no k = n special case. The complement window is O(n) but is the idea that transfers to LC 1658 and similar "remove from the ends" problems. Code one, mention the other in one sentence.

How to answer

Compare complexity and edge cases in one breath.
