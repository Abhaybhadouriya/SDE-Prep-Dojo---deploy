In a one-array 0/1 knapsack, what happens if the capacity loop runs upward?

  1. Some items are never considered
  2. Nothing; both directions are correct
  3. The answer is always zero
  4. An item can be used more than once
Upward reads cells already updated with the current item, so it becomes the unbounded knapsack.

Numbers [1, 2, 3, 4] and target 2 in Target Sum: which subset sum do you count?

  1. 6
  2. 2
  3. 10
  4. 4
P = (total + target)/2 = (10 + 2)/2 = 6. Subsets {2, 4} and {1, 2, 3}, so 2 ways.

Which base case is right for counting the ways to make an amount?

  1. ways[0] = 1
  2. ways[0] = infinity
  3. all cells start at 1
  4. ways[0] = 0
There is exactly one way to make 0: choose nothing. Every count grows from that seed.

Coin Change (fewest coins) initialises cells with amount + 1 rather than INT_MAX because:

  1. It is faster
  2. INT_MAX + 1 overflows when we add a coin
  3. INT_MAX is not allowed in Java
  4. amount + 1 is the real answer
Any real answer is at most amount (all 1-coins), so amount + 1 means "impossible" and survives the + 1.

"Split the array into two groups whose sums differ as little as possible." This is:

  1. Unbounded knapsack
  2. 0/1 subset sum up to total/2
  3. Coin change II
  4. Interval DP
Find the largest reachable sum s ≤ total/2; the answer is total - 2s (Last Stone Weight II).

Why is O(n x W) called pseudo-polynomial?

  1. It uses recursion
  2. It is only an approximation
  3. It ignores n
  4. It grows with the numeric value of W, which is exponential in W's bit length
Adding one bit to W doubles the table. That is why knapsack stays NP-hard despite the neat DP.
