When you still need the full table

The one-row version remembers values, not decisions. If the interviewer asks which items were packed, keep the 2D table and walk back from best[n][W]: if best[i][c] == best[i-1][c] the item was skipped, otherwise it was taken and c drops by its weight. Keep the 2D form, too, when you are first deriving the recurrence on the whiteboard; compress at the end.

Pseudo-polynomial time

O(n x W) looks polynomial, but W is a number in the input, not a count of items. Doubling the number of bits in W squares it. That is why 0/1 knapsack is NP-hard in general and the DP is called pseudo-polynomial. In practice: the DP is right when the capacity or the sum is small (sum ≤ 2 x 104 in Partition Equal Subset Sum). If the values are huge but n is around 40, split the items in two halves, list all 220 subset sums of each half, sort one side and binary-search it (meet in the middle). If values are small but weights huge, swap the roles: minWeight[value].

From your world

Pseudo-polynomial is the same trade-off as a direct-indexed lookup table versus a hash: a table indexed by value is perfect while the value range is small, like a 256-entry protocol table, and absurd when the key is a 64-bit address. When an interviewer says "the capacity can be 109", they are telling you the table is no longer an option.
