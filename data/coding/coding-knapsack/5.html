Combinations or orderings: which loop goes outside?

Coin Change II restated: given distinct coin values and an amount, count the number of combinations of coins that make the amount (5 = 2 + 2 + 1 and 5 = 1 + 2 + 2 are the same combination). Combination Sum IV asks the same thing but counts ordered sequences, so 1 + 2 + 2 and 2 + 1 + 2 are different. The recurrence is identical in both, ways[a] += ways[a - coin] with ways[0] = 1. The loop order is the entire difference.

  1. Base case for counting: ways[0] = 1. Paying nothing is one way, and it is the seed every count grows from.
  2. Coin 1, amounts going up: every amount can be paid with 1s only, one way each.
  3. Coin 3, still going up: ways[6] reads ways[3], which this coin already updated, so two 3s are allowed. Upward = unlimited copies.
  4. Coin 4 adds the combinations that contain a 4. Because 4 comes last in the outer loop, a 4 is never placed before a 1 or a 3.
  5. Answer 4. Coins outside and amounts inside counts each multiset exactly once: combinations, not orderings.
  • Coins outside, amounts inside: combinations. All uses of coin 1 are counted before coin 3 is ever considered, so every combination is built in one fixed order (non-decreasing by coin index) and counted once.
  • Amounts outside, coins inside: ordered sequences. For each amount we ask "what was the last coin?" and allow any coin. 1 + 2 (last coin 2) and 2 + 1 (last coin 1) land in different terms, so both are counted.
// Unbounded, count COMBINATIONS (order ignored): coins outer, amounts inner.
func change(amount int, coins []int) int {
	ways := make([]int, amount+1)
	ways[0] = 1
	for _, c := range coins {
		for a := c; a <= amount; a++ {
			ways[a] += ways[a-c]
		}
	}
	return ways[amount]
}

// Unbounded, count ORDERED sequences (permutations): amounts outer, items inner.
func combinationSum4(nums []int, target int) int {
	ways := make([]uint64, target+1) // wraps instead of overflowing; LC 377 answer fits
	ways[0] = 1
	for a := 1; a <= target; a++ {
		for _, x := range nums {
			if x <= a {
				ways[a] += ways[a-x]
			}
		}
	}
	return int(ways[target])
}
// Unbounded, count COMBINATIONS (order ignored): coins outer, amounts inner.
long long change(int amount, const vector<int>& coins) {
    vector<long long> ways(amount + 1, 0);
    ways[0] = 1;
    for (int c : coins)
        for (int a = c; a <= amount; a++)
            ways[a] += ways[a - c];
    return ways[amount];
}

    ways = [1] + [0] * amount

Overflow in Combination Sum IV. The final answer fits in 32 bits, but intermediate cells for amounts you never need can overflow. Python does not care; in C++ use unsigned (wrap-around is defined) or long long with a cap; in Java int silently wraps, which is harmless for the same reason.
