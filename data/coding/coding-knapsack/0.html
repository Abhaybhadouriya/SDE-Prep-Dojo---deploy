The story: packing a bag for a trek

Explain like I'm 5

You are packing a small bag for a trek. The bag holds 7 kilos. On the floor are a few things, each with a weight and a "how happy it makes me" score: a torch, a jacket, a stove, a tent. You cannot cut a tent in half, and you only own one of each, so for every item the choice is simply take it or leave it. That is the 0/1 knapsack. Now imagine a shop that sells coins of 1, 3 and 4 rupees in any quantity, and you must pay exactly 6. Now each coin type can be taken again and again. That is the unbounded knapsack. Nearly every problem on this page is one of these two bags.

Trying every subset of n items costs 2n. The knapsack DP is faster because the only thing that matters about the items you already decided on is how much room they used. Two different packings that both used 4 kilos leave exactly the same future, so we only remember "best value for every possible amount of room used". That gives n x W states (W = capacity), each solved in O(1).

From your world

You have done knapsack reasoning before: fitting the most useful TLVs into a 1,500-byte MTU, or deciding which per-CPU caches fit into a fixed memory budget. The DP is the exhaustive version of that decision, made cheap by the observation that "bytes used so far" is the whole state.
