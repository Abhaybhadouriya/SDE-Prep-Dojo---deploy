Interview questions

Why does the one-array 0/1 knapsack loop over capacity from high to low?

Because best[c] must be built from the previous item's row. When we go from high to low, the cell best[c - w] that we read is smaller than c and has not been visited yet in this pass, so it still holds the value without the current item. Going low to high, best[c - w] may already include the current item, so we would add it a second time: that is the unbounded knapsack. I usually show it with one item of weight 2 and capacity 4: upward gives two copies.

How to answer

Point to the 2D recurrence (reads row i-1), then explain which cells the 1D loop has already overwritten.

Likely follow-ups
  • What changes for the unbounded version? (Only the direction: upward, because reuse is allowed.)
Partition Equal Subset Sum: walk me through it and give the complexity.

If the total is odd, return false. Otherwise look for a subset with sum half = total/2. The state can[s] means some subset of the items processed so far sums to s, with can[0] = true. For each number x, loop s from half down to x and set can[s] |= can[s - x]. Return can[half]. Time O(n x half), space O(half). With n = 200 and values up to 100 that is about 200 x 10,000 = 2 x 106 steps. A bitset shift-or brings it down by a factor of 64.

How to answer

Reduce to subset sum, define the state, give the downward loop, then the bitset as the speed-up.

Likely follow-ups
  • Split into k equal groups? (No longer a knapsack: bitmask DP or backtracking, see Partition to K Equal Sum Subsets.)
  • Return the actual subset? (Keep a 2D table or a parent array and walk back.)
How do you turn Target Sum into a knapsack?

Let P be the sum of the numbers that get a plus sign and N the sum of those with a minus. P - N = target and P + N = total, so P = (total + target)/2. Each sign assignment is a choice of the plus subset, so I count subsets with sum P using a 0/1 counting knapsack with ways[0] = 1 and a downward loop. If total + target is odd or |target| > total the answer is 0. Zeros double the count, which the loop handles automatically.

How to answer

Write the two equations on the board; the reduction is the whole insight.

Likely follow-ups
  • Why not just memoise (index, running sum)? (That also works, O(n x total) states with an offset for negative sums; the algebra halves the range and avoids the offset.)
Coin Change II and Combination Sum IV have the same recurrence. Why are the answers different?

They nest the loops differently. Coin Change II puts coins outside and amounts inside, so every combination is built by adding coins in a fixed order and is counted once. Combination Sum IV puts amounts outside and tries every item as the last step for each amount, so 1 + 2 and 2 + 1 are counted separately. With coins {1, 2} and amount 3, the first gives 2 and the second gives 3. Overflow is also different: Combination Sum IV's intermediate counts can overflow 32 bits even when the final answer fits.

How to answer

Name "combinations vs orderings", show the tiny example, explain why each loop order counts what it counts.

Likely follow-ups
  • Count combinations with at most k coins? (Add a dimension for the number of coins used.)
Coin Change: why does greedy fail, what sentinel do you use, and is there another approach?

Greedy fails for non-canonical coin systems: {1, 3, 4} with amount 6 gives 4 + 1 + 1 instead of 3 + 3. The DP is f[a] = min(f[a - c] + 1) with f[0] = 0 and every other cell at amount + 1, which is larger than any real answer and cannot overflow; at the end, amount + 1 means -1. Time O(amount x coins). The alternative is BFS over amounts, where each coin is an edge of cost 1: the first time BFS reaches the amount is the fewest coins, and it can stop early.

How to answer

Counterexample, recurrence, sentinel reasoning, complexity, BFS as a second view.

Likely follow-ups
  • Each coin can be used at most once? (Then it is 0/1: same recurrence, downward loop.)
Is the knapsack DP polynomial?

It is O(n x W), which is polynomial in the value of W but exponential in the number of bits needed to write W, so it is pseudo-polynomial; 0/1 knapsack is NP-hard. It is the right tool when W or the target sum is small. If W is huge but n is about 40, I would use meet in the middle: enumerate the 220 subsets of each half, sort one list, and for each sum of the other half binary-search the best partner. If weights are huge but values are small, flip the state to "minimum weight for each total value".

How to answer

Define pseudo-polynomial precisely, then show you know what to do when the table would be too big.

Likely follow-ups
  • Fractional knapsack? (Items can be split, so greedy by value per weight is optimal; that is a greedy problem, not DP.)
After you compress to one row, the interviewer asks which items were chosen. What now?

One row only keeps the best values, not the decisions. I keep the full (n+1) x (W+1) table, then walk back from best[n][W]: if best[i][c] == best[i-1][c], item i-1 was skipped; otherwise it was taken, so record it and move to best[i-1][c - w]. That costs O(n x W) memory. If memory is tight, a separate n x W bit array of "taken" flags is 8 to 32 times smaller than the value table.

How to answer

Say "values vs decisions", then show the walk-back on the 4-item example.

Likely follow-ups
  • Can you do it with a memo instead? (Yes, re-run the recursion and follow whichever branch reproduces the memoised value.)
Ones and Zeroes: how does a second budget change the knapsack?

Each string is an item with two weights: its count of zeros and its count of ones. The capacity becomes a pair (m, n), so the state is best[i][j] = most strings using at most i zeros and j ones. For each string, loop i from m down to its zeros and j from n down to its ones, and set best[i][j] = max(best[i][j], best[i - zeros][j - ones] + 1). Both loops run downwards for the same 0/1 reason. Time O(len x m x n).

How to answer

"One dimension per budget, every capacity loop downward."

Likely follow-ups
  • What if there were a third budget? (Another dimension; watch the product of the budgets.)
