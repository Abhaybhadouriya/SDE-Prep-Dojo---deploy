Common mistakes

  • Upward capacity loop in a 0/1 problem. The item is silently reused and the answer is too large. Test with a single item that fits twice: weights [2], capacity 4 must give one copy, not two.
  • Swapping the loops when counting. Coins outside gives combinations; amounts outside gives orderings. Re-read the question for "order matters" before you write the first loop.
  • Wrong base. Counting needs ways[0] = 1; "fewest" needs f[0] = 0 and a sentinel elsewhere; "max value with capacity at most c" starts all zeros; "max value with weight exactly c" starts at minus infinity except 0.
  • A sentinel that overflows. INT_MAX + 1 is undefined behaviour in C++ and wraps negative in Java and Go. Use amount + 1 or check before adding.
  • Forgetting the parity and range checks in Target Sum: if total + target is odd, or |target| > total, return 0 before indexing a negative or fractional size.
  • Mishandling zeros in counting problems: with a loop that starts at s = x they are counted correctly (each doubles the count); with a hand-written s > 0 guard they get dropped.
  • Dropping the modulus when the problem says "modulo 109+7": reduce after every addition.
  • Compressing too early and then being asked for the chosen items. Keep the 2D table if reconstruction might come up.
