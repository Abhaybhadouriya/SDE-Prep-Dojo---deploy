nCr, Pascal and counting

Three ways to get C(n, k), from smallest to largest n:

MethodWhenCost
Pascal table C[n][k] = C[n-1][k-1] + C[n-1][k]n up to a few thousand; any modulus, even a non-primeO(n · k)
Multiplicative r = r * (n - i) / (i + 1)one value, no modulus, result fits in 64 bitsO(k); the division is exact at every step
Factorials + inverse factorials mod pmany queries, n up to 106, p primeO(n) setup, O(1) per query
  • Unique Paths in an m x n grid = C(m + n - 2, m - 1): you choose which of the moves go down.
  • Unique BSTs with n keys is the Catalan number C(2n, n) / (n + 1).
  • Permutation Sequence (k-th permutation of 1..n): there are (n-1)! permutations for each first digit, so the first digit is at index (k-1) / (n-1)! of the remaining digits. Repeat with the remainder. This is the factorial number system.
