Randomised picks: weights and reservoirs

Two templates cover the "random" interview questions. If you know all the weights up front, use prefix sums + binary search. If the items arrive as a stream of unknown length, use reservoir sampling.

  1. The first item is always kept: nothing else has been seen.
  2. Item 2 replaces the kept one with probability 1/2. The coin said yes, so we keep p2.
  3. Item 3 replaces it with probability 1/3. The coin said no, so p2 stays.
  4. Item 4: probability 1/4. No again. The stream ends; we never needed its length.
  5. Why it is fair: an item survives if it is picked at its turn and is not replaced later. For item i that is (1/i) x (i/(i+1)) x ... x ((n-1)/n) = 1/n.
  • Shuffle an Array: Fisher-Yates. For i from 0 to n-1, swap a[i] with a[j], j uniform in [i, n-1]. That gives each of the n! orders with probability 1/n!. Swapping with any j in [0, n-1] is biased, because nn outcomes cannot split evenly into n! orders.
  • Rand10 from Rand7: (rand7() - 1) * 7 + rand7() is uniform on 1..49. Reject 41..49, and return 1 + (x - 1) % 10. This is rejection sampling.
  • Random Pick Index (many duplicates, little memory): reservoir sampling over the positions equal to the target.
