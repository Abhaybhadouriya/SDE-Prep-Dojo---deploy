Common mistakes

  • Checking overflow after it happened. if (r * 10 + d > INT_MAX) can never be true for an int. Compare against INT_MAX / 10 first, or use 64-bit if the problem allows it.
  • Negating INT_MIN. In pow(x, n), n = -n stays negative in Java and Go, and is undefined behaviour in C++. Copy n into a 64-bit variable first.
  • Forgetting the modulo on one term. (a * b * c) % m overflows before the modulo. Reduce after each multiply. Subtraction needs + m.
  • Floats for exact answers. Slopes as doubles, sqrt for comparing distances, and pow() for integer powers (it returns a double and can be off by one for large values).
  • Off by one in the weighted pick. A random t in [0, total) needs upper_bound; t in [1, total] needs lower_bound.
  • Biased shuffle and biased modulo. Swapping with any j is biased. So is rand() % n when the generator's range is not a multiple of n. Use the library's uniform-range function.
  • Sieve inner loop overflow. In C++ and Java, p * p overflows an int when p is above 46340. Use 64-bit, or loop with p <= n / p.
