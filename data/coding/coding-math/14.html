Interview questions

Implement pow(x, n) for a double x and a 32-bit integer n.

Binary exponentiation: walk the bits of n. Square the base each round and multiply it into the result when the bit is 1. That is O(log n) multiplications. For negative n, use 1/x and -n, but first copy n into a 64-bit variable, because -(-231) does not fit in a 32-bit int. The recursive form half = pow(x, n/2); return n even ? half*half : half*half*x is just as good and is O(log n) stack.

How to answer

State the brute force (n multiplications), then the halving idea (x^n = (x^(n/2))^2), then the iterative bit form. Call out the INT_MIN trap before the interviewer does.

Likely follow-ups
  • Compute a^b mod m with b up to 1e18? (The same loop with % m after each multiply; 64-bit is enough while m < about 3e9.)
  • Matrix power? (The same loop with matrix multiply: Fibonacci in O(log n).)
Reverse the digits of a 32-bit signed integer; return 0 if the result overflows. You may not use 64-bit integers.

Pop the last digit with d = x % 10; x /= 10 and push it with r = r * 10 + d. Before pushing, check r > INT_MAX / 10 || (r == INT_MAX / 10 && d > 7) and the mirror check for negatives (d < -8). In C, C++, Java and Go, % keeps the sign of x, so negative numbers need no special case. Python's % does not keep the sign, so handle the sign separately there.

How to answer

Say why you check before the operation: after the overflow happens the value is already wrong (or UB in C++). The constants 7 and 8 are the last digits of 2147483647 and 2147483648.

Likely follow-ups
  • Do String to Integer (atoi) next? (Same overflow check, plus spaces, sign and clamping instead of returning 0.)
  • Palindrome Number without a string? (Reverse only half the digits, which also avoids overflow.)
Multiply two non-negative integers given as strings, without converting them to big integers.

Allocate an int array of length m + n (the product has at most that many digits). For every pair (i, j) from the right, add a[i] * b[j] to slot i + j + 1, keep the last digit there and add the carry to slot i + j. Strip leading zeros at the end, and special-case "0". That is O(m · n) time.

How to answer

Draw the slot grid for a small example (123 x 45). Mention that Add Strings, Add Binary and Plus One are the same carry loop.

Likely follow-ups
  • Faster for huge inputs? (Karatsuba, about O(n^1.58), or FFT. Name them only; nobody codes them in an interview.)
  • Negative numbers or decimals? (Handle the sign and the decimal point separately, then multiply the digit strings.)
Count the primes below n (n up to 5 * 10^6).

Sieve of Eratosthenes: a boolean array of size n; for each p with p*p < n that is still unmarked, mark p*p, p*p + p, ... as composite. Starting at p*p is safe because any smaller multiple has a smaller prime factor and is already marked. The cost is O(n log log n) time and n bytes. Trial division of each number up to its square root would be O(n sqrt n).

How to answer

Explain the p*p start and the p*p < n stop. In Java and C++ compute p*p in 64-bit, or loop with i <= n / i, so it cannot overflow.

Likely follow-ups
  • Primes in a range [L, R] with R up to 1e12? (Segmented sieve with the primes up to sqrt(R).)
  • Factorise many numbers quickly? (Sieve the smallest prime factor once, then divide by spf[x] repeatedly.)
Pick an index at random, with probability proportional to its weight. pick() is called many times.

Build prefix sums once (O(n)). For each pick, draw a uniform integer t in [1, total] and return the first index whose prefix is >= t (lower bound), in O(log n). With integer weights there is no floating-point bias. If picks vastly outnumber weights, the alias method gives O(1) per pick after O(n) setup.

How to answer

Draw the number line with each index's stretch. Get the boundary right: t from 1 to total with lower_bound, or t from 0 to total-1 with upper_bound. Mixing the two is the classic off-by-one.

Likely follow-ups
  • Weights change between picks? (A Fenwick tree over the weights: update and search both O(log n).)
  • Pick k distinct indices by weight? (Remove each pick from the Fenwick tree, or use weighted reservoir sampling with keys u^(1/w).)
Return a uniformly random node from a linked list (or a stream) whose length you do not know, in one pass and O(1) space.

Reservoir sampling: keep the i-th item with probability 1/i, replacing the current pick. Item i ends up chosen with probability (1/i) · (i/(i+1)) · ... · ((n-1)/n) = 1/n. For k samples, keep the first k, then let item i replace a random slot with probability k/i.

How to answer

Give the two-pass answer first (count, then walk to a random index), then the one-pass reservoir and the one-line proof. Random Pick Index is the same idea over the indices that match the target.

Likely follow-ups
  • Shuffle an array uniformly? (Fisher-Yates: for i from 0, swap a[i] with a[j], j uniform in [i, n-1]. The naive 'swap with any j' is biased.)
  • Rand10 from Rand7? (Make 1..49 uniform with two calls, reject 41..49, return 1 + (x-1) % 10.)
Given points on a plane, find the largest number of points on one straight line.

Fix each point as an anchor. For every later point, compute the slope as a reduced fraction: g = gcd(dy, dx), then (dy/g, dx/g) with one sign rule (make dx positive, or dy positive when dx = 0). Count the slopes in a hash map. The best line through the anchor is 1 + the largest count. O(n2) time. Floats fail here: different slopes can round to the same double, and vertical lines divide by zero.

How to answer

Say why you avoid doubles before you write the gcd key. If duplicates are allowed, count them separately and add them to every line through the anchor.

Likely follow-ups
  • Are three points collinear? (Cross product = 0.)
  • Do two segments intersect? (Each segment's endpoints are on opposite sides of the other: cross-product signs differ, plus the collinear special cases.)
Convert an integer (1..3999) to a Roman numeral and back.

To Roman: greedy over 13 values in descending order (1000 M, 900 CM, 500 D, 400 CD, ..., 4 IV, 1 I). The subtractive pairs are included as their own symbols, so a plain greedy is correct. From Roman: scan left to right; if a symbol is smaller than the next one, subtract it, otherwise add it.

How to answer

List the 13 pairs from memory. Mention the same family: Excel column title is base 26 with no zero digit, so subtract 1 before each % 26.

Likely follow-ups
  • Validate a Roman string? (Check the allowed subtractive pairs and at most three repeats of I, X, C, M.)
  • Base -2 or other bases? (The same divide-and-remainder loop; for a negative base, fix negative remainders by adding |base|.)
