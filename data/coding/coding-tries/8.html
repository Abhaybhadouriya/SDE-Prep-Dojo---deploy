How to recognise a trie problem

Cue in the problemTrie move
"prefix", "starts with", "autocomplete", "suggestions as you type"Basic trie, maybe with counts or top-k per node
Many words searched in one grid or one long textTrie of the words + one DFS/scan (Word Search II; Aho-Corasick is the advanced version for text)
Wildcard . in queriesDFS that branches only at the wildcard
"replace each word with its shortest root", "word is built one letter at a time from other words"Walk until the first end node / check every prefix is an end node
"maximum XOR", "XOR with limit", "count pairs with XOR"Bit trie, MSB first
"stream of characters, does any word end here"Trie of reversed words, walked over the last L characters
File paths, folders, URLsTrie keyed by path segment (map children)

And when not to use one: if you only need "is this exact word present", a hash set is simpler and usually faster. A trie earns its memory when prefixes, ordering, or "many words at once" matter.
