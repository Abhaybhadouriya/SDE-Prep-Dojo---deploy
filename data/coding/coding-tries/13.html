A trie holds "car" and "card". Why does each node need an end flag?

  1. Because "car" ends at a node that still has a child, so "has children" cannot mean "not a word"
  2. To count how many words there are
  3. To store the node's letter
  4. To make insert O(1)
Words can end at inner nodes. Only an explicit flag distinguishes "car" (a word) from "ca" (just a prefix).

What is the time to search a word of length L in a trie holding n words?

  1. O(n)
  2. O(L)
  3. O(n · L)
  4. O(log n)
One step per character; the number of stored words does not matter.

In Word Search II, what makes the trie version fast?

  1. The DFS stops as soon as the current path is not a prefix of any word
  2. Each word is searched separately in parallel
  3. The trie stores grid coordinates
  4. The trie sorts the grid
Pruning by prefix, for all words at once, is the whole speed-up.

To maximise x XOR y with a bit trie, what do you do at each bit?

  1. Pick the child with more numbers below it
  2. Take the opposite bit of x if that child exists, otherwise the same bit
  3. Follow the same bit as x
  4. Always go to the 1 child
A 1 at a higher XOR bit outweighs all lower bits, so the greedy opposite-bit choice is optimal.

The input says "characters can be any printable ASCII, and the trie may hold 105 words". Best child structure?

  1. A single string
  2. Array of 26
  3. Hash map (or a node pool with maps), because a 95-slot array per node wastes memory
  4. Linked list of all words
Large alphabets make fixed arrays mostly empty; a map stores only the children that exist.

Which problem needs a trie of reversed words?

  1. Stream of Characters (does a word end at the latest character?)
  2. Implement Trie
  3. Maximum XOR of Two Numbers
  4. Search Suggestions System
Each new character is the last letter of a candidate word, so you walk backwards over recent characters through a trie of reversed words.
