Interview follow-ups

All values are in [0, 100]. Can you do better?

Keep a count array of 101 buckets and a total n. addNum is O(1). findMedian walks the buckets until the running count passes n/2 (and (n+1)/2 for the even case): O(101) = O(1).

How to answer

Name it counting sort applied to a stream; the bucket walk is bounded by the value range, not by n.

Likely follow-ups
  • Make the walk O(log 101) with a Fenwick tree over the buckets.
99% of the values are in [0, 100]. What now?

Buckets for [0, 100] plus two counters (or two small sorted lists) for values below 0 and above 100. The median is almost surely inside the buckets, because the outliers are only 1% on either side; you only touch the overflow lists if the median falls outside the range.

How to answer

Argue with counts: with 1% outliers the n/2-th value cannot be an outlier unless the outliers are all on one side and n is tiny.

Likely follow-ups
  • What if the distribution drifts? (Fall back to the heaps.)
Readings expire after a time window. How do you remove one?

Heaps cannot delete an arbitrary value fast. Either use a sorted multiset (C++ multiset, Java TreeMap with counts) and keep an iterator at the middle, or keep the heaps with lazy deletion: record pending deletions in a hash map and pop them when they reach a top, tracking the live sizes separately.

How to answer

Point to LC 480; say which part of the invariant becomes hard (the sizes) and how the live counters fix it.

Likely follow-ups
  • Memory bound of lazy deletion? (Dead values stay until they surface: O(n) worst case.)
Return the 90th percentile instead of the median.

Same two heaps, different size rule: keep len(low) = ceil(0.9 * n). After each add, move tops until the size target holds; the answer is low's top.

How to answer

Show that only the split point changed; the order rule and the code shape are identical.

Likely follow-ups
  • Several percentiles at once? (An order-statistic tree, or a sketch.)
The stream is billions of values across many machines. Exact median?

Exact needs a lot of memory or several passes (per-shard histograms over value ranges, then zoom into the range that holds the median). In production you use an approximate quantile sketch (t-digest, KLL, GK) that merges across shards with a bounded error.

How to answer

Separate "exact in one pass" (needs O(n) memory) from "approximate with a stated error".

Likely follow-ups
  • How would you merge two sketches? (Both support merge; heaps do not.)
Many threads call addNum and findMedian. What changes?

The three heap operations of an add must be atomic as a group, or a reader can see a broken size rule. A single mutex around both methods is the simple answer; a reader-writer lock helps only if reads dominate. Cache the last median in an atomic for lock-free reads if slightly stale values are fine.

How to answer

Name the invariant that a race breaks, then the smallest lock that protects it.

Likely follow-ups
  • Can you batch adds to cut lock traffic?
