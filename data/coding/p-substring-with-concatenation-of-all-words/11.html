Interview follow-ups

Can you avoid slicing and hashing a w-length string at every step?

Yes. Precompute, for every index j, the id of the word that starts at j (or -1): a rolling hash of every length-w substring in O(n), or a trie walk of the words from each j in O(n · w) once. Then each lane works on small integers, and the maps become arrays of size k. The window part drops to O(n); the precomputation dominates.

How to answer

Separate "recognise the token" (string work) from "count tokens" (integer work), and speed up the first.

Likely follow-ups
  • Rolling-hash collisions: confirm with a string compare when a hash matches a word's hash.
The words have different lengths.

The lanes argument breaks: words no longer line up on a grid. For each start, a backtracking search (or a DP over positions with a multiset of remaining words) is needed, which is exponential in the worst case. With a small k, try each start with DFS over the remaining word counts and a trie for matching. Say clearly that the equal-length condition is what makes LC 30 linear.

How to answer

Identify which assumption the fast solution used, and what you lose without it.

Return only how many starts exist, using as little memory as possible.

Replace the result list with a counter. The memory left is the two maps, O(distinct words · w); with precomputed word ids they become two integer arrays of size k. One lane at a time means only one have map is live.

How to answer

List what is stored and why each piece is needed.

Likely follow-ups
  • Can the lanes run in parallel? Yes: they share only the read-only need map.
Parallelise it for a very long s.

The w lanes are independent: run each in its own thread with a private have map and merge the results. For more parallelism, split a lane into chunks that overlap by k - 1 tokens (so a window crossing a boundary is seen by one chunk), and deduplicate starts in the overlap.

How to answer

Name the independent units (lanes), then the overlap rule for chunking a sliding window.

Likely follow-ups
  • Why k - 1 tokens of overlap and not k?
Why not simply slide the window one character at a time?

Moving the start by one character re-cuts every word, so nothing from the previous window can be reused: that is the brute force. Moving by w keeps k - 1 words, which is what makes the window O(1) per step. The w lanes are how you still visit every character start.

How to answer

Explain what is reused between neighbouring windows in each scheme.

  • What is the total number of tokens over all lanes? About n.
