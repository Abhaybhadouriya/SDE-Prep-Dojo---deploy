  • Cue: substring = all words of equal length w, any order: anagram search over words.
  • Insight: w lanes (offset mod w); in each, a word window: add right, shrink while over-used.
  • State: need map, have map, left, count; stranger = reset; count == k = record + drop one.
  • Trap: duplicates in words; all offsets; k · w > n; drop a word after each hit.
  • Cost: O(n · w + k · w) time, O(k · w) space; brute O(n · k · w).
for off in range(w):
    left = off; have.clear(); count = 0
    for r in range(off, n - w + 1, w):
        t = s[r:r+w]
        if t not in need: left = r + w; have.clear(); count = 0; continue
        have[t] += 1; count += 1
        while have[t] > need[t]: drop(s[left:left+w]); left += w; count -= 1
        if count == k: out.append(left); drop(s[left:left+w]); left += w; count -= 1

How many independent passes over s does the optimal solution make?

  1. k
  2. w
  3. n
One per offset 0 .. w-1; each pass steps by w.

The token at right is not in words. What do you do?

  1. Clear the window and set left = right + w
  2. Drop one word from the left
  3. Skip it and keep the window
No valid window can contain a stranger, so everything up to it is useless.

Why is count == k enough to know the window is a concatenation?

  1. Because the words are sorted
  2. Because w is fixed
  3. No word exceeds its need and the counts add up to k, so each is exactly at its need
Sum of have = k = sum of need, with have ≤ need everywhere: equality everywhere.
