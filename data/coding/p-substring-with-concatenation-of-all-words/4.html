Approaches: brute → better → optimal

Hint 1

If a match starts at index i, where do its words start?

Hint 2

Group the start indices by i mod w. What does s look like when you only read from one group?

1. Brute force - check every start

Idea: for each start i in 0 .. n - k·w, cut s[i .. i + k·w) into k pieces of length w and compare their counts with the words' counts (a copy of the map, decremented; fail on the first piece that goes negative or is unknown).

O((n - k·w + 1) · k · w)time
O(k · w)space for the maps

What is wasted: starts i and i + w share k - 1 words, yet each is checked from scratch. Early exit on a bad word helps on random inputs but not on adversarial ones (for example s = "aaaa...", words = ["a", "a", ..., "b"]).

2. Optimal - one sliding window of words per offset

for offset in range(w):                        # lanes: offset, offset + w, offset + 2w ...
    left, count, have = offset, 0, {}
    for right in range(offset, n - w + 1, w):
        word = s[right:right + w]
        if word not in need: reset(left = right + w); continue
        add(word)
        while have[word] > need[word]: drop_left()
        if count == k: record(left); drop_left()
  1. Lanes. A match that starts at i has its words at i, i + w, i + 2w ... All of these are ≡ i (mod w). So process the w offsets separately; in each, s is a list of about n / w tokens.
  2. Window of tokens. have counts the words in the window s[left .. right), count is how many words it holds.
  3. Stranger token. If the token is not in need, no valid window can contain it: clear the window and start after it.
  4. Over-used token. If adding a word makes have[word] > need[word], drop words from the left until it fits. Every window that still contains all those copies would also be invalid.
  5. Hit. If count == k, the window holds exactly the multiset of words: record left, then drop the leftmost word so the window can move on (matches may overlap by k - 1 words).
O(n · w + k · w)time: n tokens over all lanes, each sliced and hashed in O(w); building need costs k · w
O(k · w)space for the two maps

Why it works: within one lane, the window always holds a run of consecutive tokens in which no word exceeds its needed count and no stranger appears; it is the longest such run ending at right, because left only moves when it must (a stranger at right forces every window ending there to be invalid; an over-used word forces left past its oldest copy). A run with no over-used word and exactly k tokens has every word at exactly its needed count, since the counts sum to k. So when count == k the window is a concatenation, and every concatenation ending at right is found: it would be a valid run of k tokens, and the longest valid run contains it, so both have length k and coincide. Left and right only move forward, so each token enters and leaves at most once per lane.

The two most voted community posts are exactly these two rungs: the "two maps per start" brute force, and the per-offset window with the explanation "each word is visited at most twice per lane". The editorial is Premium.
