Common mistakes

Checking two digits with <= 26 only. "06" parses to 6, which is ≤ 26, but it is not a valid code. The lower bound >= 10 is what rejects a leading zero.

Returning early on the first '0'. A zero is fine when it ends "10" or "20". Return 0 only through the recurrence (both gates closed), not on sight.

Setting ways(0) = 0. Then every two-digit start is lost ("12" gives 1). The empty prefix counts as one decoding.

Forgetting to shift both variables. Update with a temporary (cur) or a tuple assignment; writing prev1 = cur; prev2 = prev1 in that order copies cur into both.

Counting letter strings instead of splits. Two different splits always give different letter strings, so there is no double counting to remove; do not add a set.
