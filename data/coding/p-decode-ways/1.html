The problem (in our words)

A message of capital letters was encoded with the mapping 'A' → "1", 'B' → "2", ..., 'Z' → "26", and the codes were written next to each other with no separator. Given the digit string s, return the number of ways to decode it back into letters.

  • To decode, split s into pieces that are each one of the codes "1" .. "26". A piece with a leading zero such as "06" is not valid (it is not the same as "6"), and "0" alone is not a code.
  • If the string cannot be decoded at all, return 0.
  • Input: a string s of digits.
  • Output: an integer count. Signature: int numDecodings(String s).
  • The test data guarantees the answer fits in a 32-bit integer.

Constraints

  • 1 <= s.length <= 100
  • s contains only digits and may contain leading zeros.

Practice it: LeetCode 91 - Decode Ways · GfG - Total Decoding Messages

Constraints tell you: n ≤ 100, so the number of decodings can be exponential (a string of forty 1s already has 165,580,141) and brute-force enumeration is out; a linear DP over prefixes is expected. The 32-bit guarantee means no modulo is needed here (the Hard sequel, Decode Ways II, adds one). "May contain leading zeros" is the hint that zeros are where the bugs are.
