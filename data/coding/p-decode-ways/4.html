Approaches: brute → better → optimal

Hint 1

Look at the last letter of any decoding. How many digits can it use?

Hint 2

If you knew the answer for the first i-1 and the first i-2 digits, how would you get the answer for the first i?

1. Brute force - plain recursion

Idea: count(i) = ways to decode s[i..]. If s[i] == '0' return 0. Otherwise take one digit (count(i+1)) and, if s[i..i+1] is 10..26, also two digits (count(i+2)). count(n) = 1.

O(2^n)time (Fibonacci-like tree)
O(n)recursion depth

What is wasted: count(i) depends only on i, yet it is recomputed along every path that reaches i.

2. Better - memoise, or a table

Top-down: cache count(i) in an array of size n + 1. Bottom-up: dp[i] = ways for the first i digits, dp[0] = 1, then fill left to right with the two gated terms. Both are O(n) time and O(n) space.

O(n)time
O(n)space

What is wasted: dp[i] reads only dp[i-1] and dp[i-2]; the rest of the table is dead weight.

3. Optimal - two rolling variables

prev2, prev1 = 1, (1 if s[0] != "0" else 0)   # core: ways(i-2), ways(i-1)
for i in range(2, len(s) + 1):
    cur = (prev1 if s[i-1] != "0" else 0) + (prev2 if 10 <= int(s[i-2:i]) <= 26 else 0)
    prev2, prev1 = prev1, cur
return prev1
  1. State: ways(i) = number of decodings of the prefix of length i.
  2. Base: ways(0) = 1 (the empty prefix decodes one way: to nothing); ways(1) = 1 unless s[0] is '0'.
  3. Transition: ways(i) = [s[i-1] in 1..9] · ways(i-1) + [s[i-2..i-1] in 10..26] · ways(i-2).
  4. Answer: ways(n). Keep only the last two values.
O(n)time, one pass
O(1)space

Why it works: every decoding of the first i digits ends with a last letter, and that letter is either the single digit s[i-1] or the two digits s[i-2..i-1]. These two cases do not overlap (the last piece has a different length), and they cover everything, so the counts add. Removing the last piece leaves a decoding of a shorter prefix, and every decoding of that prefix can be extended, so case one contributes exactly ways(i-1) and case two exactly ways(i-2), each only if its gate is open.

Why ways(0) = 1 and not 0

Take s = "12". The decoding "12" (L) uses the two-digit piece and leaves the empty prefix. If ways(0) were 0, that decoding would be lost and you would get 1 instead of 2. "One way to decode nothing" is the identity for this sum, like 0! = 1.
