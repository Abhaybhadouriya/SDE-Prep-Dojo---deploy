Return all the decoded strings, not just the count.

Backtracking: from index i, if s[i] is 1..9 recurse with that letter appended; if s[i..i+1] is 10..26 recurse with that letter. At the end of the string, record the built message. Output size can be exponential (Fibonacci in n), so time is O(n · answer count); mention that this is why the original asks only for the count.

How to answer

Reuse the same two gates; only the aggregation changes from "+" to "collect".

Likely follow-ups
  • Can you prune? Precompute ways from each suffix; skip branches whose count is 0.
'*' can be any digit 1-9 (Decode Ways II). Return the count mod 10^9 + 7.

Same rolling DP, but each term is multiplied by the number of valid choices: single '*' = 9; pairs: "1*" = 9 (11..19), "2*" = 6 (21..26), "*d" = 2 if d ≤ 6 (1d, 2d) else 1, "**" = 15. Accumulate in 64-bit and reduce mod after each step.

How to answer

Write the case table first; most bugs are in "*0" (= 2: 10, 20) and "**".

Likely follow-ups
  • Why mod after every step and not at the end? Overflow.
Write it top-down first, then convert to bottom-up.

Top-down: f(i) on suffix s[i..], f(n) = 1, f(i) = 0 if s[i] is '0', else f(i+1) + (two-digit ok ? f(i+2) : 0), memoised. Bottom-up runs i from n-1 down to 0 with the same formula, which then reduces to two variables. Both are O(n).

How to answer

Show that the memo table is filled in a fixed order, which is what makes the rolling version possible.

Likely follow-ups
  • Recursion depth for n = 100 is fine; for n = 10^6 you must go bottom-up.
The digits arrive as a stream. Report the count after each digit.

The two-variable DP is already streaming: keep (ways(i-2), ways(i-1), previous digit). On each new digit compute ways(i) with the two gates and shift. O(1) memory per stream, which is the "network parser" version of the problem.

How to answer

Point out that the state is exactly the last two counts plus the last digit.

Likely follow-ups
  • Once the count hits 0, can it recover? No: a 0 means the new digit is '0' with no valid pair (and "0x" pairs are invalid), or both previous counts are 0, so every later count is 0 too. The stream can stop early.
The mapping changes: codes are 1..k for some k up to 1000. Generalise.

The last piece now has length 1..d where d is the number of digits of k. ways(i) = sum over L = 1..d of ways(i-L) if s[i-L..i-1] has no leading zero and its value is in 1..k. Keep a ring buffer of the last d counts: O(n · d) time, O(d) space.

How to answer

Same proof: classify decodings by the length of the last piece.

Likely follow-ups

Is this greedy-solvable? Why do you need DP?

No: choosing "12" early in "1201" looks fine until the '0' forces "20" and invalidates it. A local choice changes which later splits are possible, and we need a count over all choices, so we sum over overlapping subproblems instead of committing.

How to answer

Give the "1201" counterexample; it shows both the zero trap and the need to count both branches.

Likely follow-ups
  • Minimum number of letters in a decoding: same DP with min instead of sum.
