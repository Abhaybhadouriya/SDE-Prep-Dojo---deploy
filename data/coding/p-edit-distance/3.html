Recognise the pattern

When you see two strings + "minimum operations to convert", "longest common ...", or "number of ways to match", think 2D DP on prefixes: d[i][j] for a[0..i) and b[0..j).

When you see the transition reading only the row above and the cell to the left, think two rolling rows.

Try counting position-by-position mismatches; it fails as soon as one string is shifted:

word1 → word2mismatches + length gapTruth
abc → bca32 (delete a, insert a)✗
plan → planet0 + 2 = 22✓ (aligned prefix)
sunday → saturday5 + 2 = 73✗

The right alignment of the two strings is unknown, and a choice at one character shifts everything after it. Every choice only shrinks one or both prefixes, so the subproblems are pairs (i, j): (m + 1)(n + 1) of them.
