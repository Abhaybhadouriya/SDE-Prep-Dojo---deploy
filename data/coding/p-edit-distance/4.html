Approaches: brute → better → optimal

Hint 1

Look only at the last character of each string. What can an optimal sequence of edits do with them?

Hint 2

Each of the three operations, applied at the end, leaves a smaller version of the same question.

1. Brute force - recurse on the three operations

Idea: compare a[i] and b[j] from the front. Equal: move both. Different: try replace (i+1, j+1), delete (i+1, j) and insert (i, j+1), each costing 1, and keep the minimum. When one string runs out, the rest of the other is pure inserts or deletes.

O(3^(m+n))time
O(m+n)stack

What is wasted: the pair (i, j) is reached along many different edit orders and solved each time. There are only (m+1)(n+1) pairs.

2. Better - memo on (i, j), or the full table

  1. State: d[i][j] = minimum edits to turn the first i letters of word1 into the first j letters of word2.
  2. Transition: if word1[i-1] == word2[j-1], d[i][j] = d[i-1][j-1]; else d[i][j] = 1 + min(d[i-1][j-1], d[i-1][j], d[i][j-1]) for replace, delete, insert.
  3. Base case: d[0][j] = j (insert everything), d[i][0] = i (delete everything).
  4. Answer: d[m][n].
O(m·n)time
O(m·n)space

What is wasted: row i reads only row i - 1 and itself. Keep the table only if you must print the edits.

3. Optimal - two rolling rows

prev = list(range(n + 1))
for i in range(1, m + 1):
    cur = [i] + [0] * n
    for j in range(1, n + 1):
        cur[j] = prev[j-1] if a[i-1] == b[j-1] else 1 + min(prev[j-1], prev[j], cur[j-1])
    prev = cur
  1. Space optimisation: prev is row i - 1, cur is row i. Diagonal = prev[j-1], up = prev[j], left = cur[j-1].
  2. Reset the first cell of each row to i: that is the "delete all i letters" base case.
  3. Swap the rows after each i (C++ swap, Java/Go reassign), so no allocation per row.
  4. Top-down version: rung 2 with a memo array memo[i][j]; fine to say, but 500 × 500 recursion depth is up to 1,000 frames.
O(m·n)time
O(n)space (use the shorter word for the row)

Why it works: write any edit sequence as an alignment: columns that pair a letter of word1 with a letter of word2 (cost 0 if equal, 1 if not), columns with only a word1 letter (a delete), and columns with only a word2 letter (an insert). The last column of an optimal alignment is one of these three kinds, and removing it leaves an optimal alignment of shorter prefixes. So the minimum over the three cases is the true minimum.

Proof (optional): why a match can skip the min

Neighbouring cells differ by at most 1 (one extra letter costs at most one extra edit, and saves at most one). So d[i-1][j-1] ≤ d[i-1][j] + 1 and d[i-1][j-1] ≤ d[i][j-1] + 1. When the last letters match, the diagonal is never worse than the other two options, and taking it directly is safe.
