Also print the sequence of edits.

Keep the full table. Walk back from (m, n): if the letters match and d equals the diagonal, step diagonally (no edit); else step to whichever neighbour gave the value (diagonal = replace, up = delete, left = insert). Reverse the list at the end. O(m + n) steps after the O(m·n) fill.

How to answer

Say that the two-row version loses the choices, so printing needs the table (or Hirschberg's divide and conquer for O(n) space).

Likely follow-ups
  • Several optimal scripts exist; which one do you print? (Any fixed tie-break order.)
Is the distance at most 1? (One Edit Distance)

No table needed. If the lengths differ by more than 1, no. Otherwise walk both strings until the first mismatch; then the rest must match after skipping one letter in the longer string (lengths differ) or one letter in both (same length). O(n) time, O(1) space.

How to answer

Use the bound: a small k means only a band of the table matters.

Likely follow-ups
  • Generalise to "at most k": fill only cells with |i - j| ≤ k, O(n·k).
Insert, delete and replace have different costs.

Replace the 1's by the three costs: min(diag + cRep, up + cDel, left + cIns), and the base row/column become j·cIns and i·cDel. The match case stays diag + 0 only if a match is free. If replace costs more than delete + insert, the DP will never pick it, which is correct.

How to answer

Point to the one line and the two base cases that change.

Likely follow-ups
  • Cost depends on which letters (keyboard distance): a 26 × 26 cost matrix in the diagonal term.
Find all dictionary words within distance 2 of a typed word.

Put the dictionary in a trie and run the DP row by row while walking it: each trie node owns one row (computed from its parent's row and its letter). Prune a branch when the minimum of its row exceeds 2. Shared prefixes share rows, so it beats running the DP per word. A BK-tree is the other standard answer.

How to answer

Notice that row i depends only on the first i letters of the dictionary word: that is a trie path.

Likely follow-ups
  • Rank suggestions by word frequency as well as distance.
Can you do it in O(min(m, n)) memory, and why does the order of loops matter?

Make the shorter string the column (the row length), since the distance is symmetric. The loop must go i ascending, j ascending, because each cell needs diag, up and left already final. Diagonal-by-diagonal order also works and is how GPU versions parallelise it.

How to answer

Name the three dependencies and show that row-major order satisfies them.

Likely follow-ups
  • Why is d(a, b) = d(b, a)? (Swap insert and delete in any script.)
