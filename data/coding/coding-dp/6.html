How to recognise a DP problem

  • The question asks for a count, a minimum/maximum, or yes/no over many possible choices ("number of ways", "fewest coins", "longest", "can you partition"). It rarely asks you to list all solutions; that is backtracking.
  • Choices are made in a sequence and each choice leaves a smaller problem of the same kind.
  • A greedy rule has a counterexample. Coins {1, 3, 4} and amount 6: greedy gives 4+1+1 (3 coins), the best is 3+3 (2 coins). If you can break greedy in a minute, think DP.
  • The constraints fit a table. n up to 103-104 suggests O(n2); n up to 105 suggests O(n) or O(n log n) 1D DP; n up to 20 suggests a bitmask; two strings up to 103 suggest an n x m table.
  • Your brute force recursion has few distinct arguments. If the recursive function takes (index) or (index, remaining) and those values are small, memoise it: that is the DP.

When stuck on the state, write the brute-force recursion first and look at its parameters: whatever changes between calls is your state. If it takes the whole remaining array, replace it with an index; if it takes a set of used items, that is a bitmask.
