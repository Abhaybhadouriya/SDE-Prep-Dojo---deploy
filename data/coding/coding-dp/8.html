Common mistakes

  • A vague state. "dp[i] is the answer for i" is not a state. Say exactly which prefix, which constraint, and whether element i must be used (LIS: "longest increasing subsequence ending at i" is the state that works).
  • Off-by-one between "first i items" and "item i". Pick one convention; dp of size n+1 with dp[0] = empty is usually cleaner.
  • Wrong base case. dp[0] = 1 for counting (one way to do nothing), dp[0] = 0 for sums, infinity for "minimum" states that are impossible. Mixing these silently gives wrong totals.
  • Filling in the wrong order. Every state's inputs must be ready. In 0/1 knapsack with one array, the capacity loop must run downwards, or an item is used twice.
  • Loop order in coin counting. Coins outer, amounts inner counts combinations (Coin Change II); amounts outer, coins inner counts ordered sequences (Combination Sum IV). Know which one the question wants.
  • Overwriting what you still need when compressing space (the up-left diagonal in a one-row grid DP).
  • Memo keyed on mutable or huge objects (lists, whole strings). Key on indices.
  • Recursion depth for memo on n = 105 in Python. Go bottom-up.
  • Forgetting the modulus when the problem says "return the answer modulo 109+7": apply it at every addition, not only at the end, or the numbers overflow (in C++, Java and Go).
