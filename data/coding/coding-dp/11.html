Plain recursive Fibonacci is slow because:

  1. Recursion is always slower than loops
  2. The numbers grow too large
  3. It has no base case
  4. The same subproblems are recomputed exponentially many times
The call tree grows roughly 1.6n while there are only n+1 distinct subproblems. A memo makes it O(n).

For house robber, which state works?

  1. dp[i] = most money from houses 0..i
  2. dp[i] = value of house i
  3. dp[i] = whether house i is robbed
  4. dp[i] = number of houses robbed so far
"Best total for the prefix 0..i" lets you write best[i] = max(best[i-1], best[i-2] + nums[i]).

How many ways can "106" be decoded?

  1. 2
  2. 1
  3. 3
  4. 0
'0' cannot stand alone, so "10" must be a pair: 10-6 ("JF") is the only decoding. "1-06" is invalid because "06" is not a code.

Unique Paths on a 3 x 3 grid (right/down moves only) gives:

  1. 4
  2. 9
  3. 3
  4. 6
Rows: 1 1 1 / 1 2 3 / 1 3 6. Also C(4, 2) = 6: choose which 2 of the 4 moves go down.

The time complexity of a DP is best estimated as:

  1. The depth of the recursion
  2. Size of the input squared
  3. Number of states x work per transition
  4. Number of base cases
Each state is computed once, and computing it costs the transition's work. LIS: n states x O(n) = O(n2).

"Given n up to 15 tasks and k workers, can the tasks be split so every worker gets the same total?" Which family?

  1. Bitmask DP
  2. Grid DP
  3. Two strings
  4. 1D linear
Small n with "assign all items into groups" is the bitmask family: a state is the set of tasks already used.

In a single-array 0/1 knapsack, the capacity loop runs downwards because:

  1. It is faster
  2. Going upwards would let the same item be counted twice
  3. The base case is at the end
  4. It saves memory
Upward updates read values already updated with the current item, which turns 0/1 knapsack into unbounded knapsack.
