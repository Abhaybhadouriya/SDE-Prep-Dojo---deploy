Grid DP

Grid DP is 1D DP in two directions. The classic: a robot in the top-left cell of an R x C grid can move only right or down; count the paths to the bottom-right cell (Unique Paths), or find the cheapest path when each cell has a cost (Minimum Path Sum).

  • State: dp[r][c] = number of paths (or cheapest cost) to reach cell (r, c).
  • Transition: the last move came from above or from the left: dp[r][c] = dp[r-1][c] + dp[r][c-1] for counting, grid[r][c] + min(dp[r-1][c], dp[r][c-1]) for cost.
  • Base: the first row and first column (only one way to reach them: straight along the edge). Obstacles get 0 paths.
  • Order: row by row, left to right: both inputs are always ready. O(R x C) time.
  1. Base cases: every cell in the first row or first column has exactly one path.
  2. Cell (1,1) adds the cell above and the cell to the left (orange): 1 + 1 = 2.
  3. Finish row 1 left to right; each cell's inputs are already filled.
  4. Row 2: (2,1) = 2 + 1 and (2,2) = 3 + 3. Notice each row reads only the row above it.
  5. The goal cell: 4 + 6 = 10 paths. Choose 2 downs among 5 moves, C(5,2) = 10, confirms it.
  6. Space optimisation: one array of C entries, updated left to right, replaces the whole table.

The same idea for Minimum Path Sum, with one rolling row:

import "math"

func minPathSum(grid [][]int) int {
    C := len(grid[0])
    row := make([]int, C) // row[c] = best cost to reach (r, c)
    for c := 1; c < C; c++ {
        row[c] = math.MaxInt32
    }
    for _, g := range grid {
        for c := 0; c < C; c++ {
            best := row[c] // still holds the cell above
            if c > 0 && row[c-1] < best {
                best = row[c-1] // the cell to the left (this row)
            }
            row[c] = g[c] + best
        }
    }
    return row[C-1]
}
int minPathSum(const vector<vector<int>>& grid) {
    int C = grid[0].size();
    vector<int> row(C, INT_MAX);                     // row[c] = best cost to reach (r, c)
    row[0] = 0;
    for (const auto& g : grid)
        for (int c = 0; c < C; c++) {
            int best = row[c];                       // still holds the cell above
            if (c > 0) best = min(best, row[c - 1]); // the cell to the left (this row)
            row[c] = g[c] + best;
        }
    return row[C - 1];
}
static int minPathSum(int[][] grid) {
    int C = grid[0].length;
    int[] row = new int[C];
    Arrays.fill(row, Integer.MAX_VALUE);
    row[0] = 0;
    for (int[] g : grid)
        for (int c = 0; c < C; c++) {
            int best = row[c];
            if (c > 0) best = Math.min(best, row[c - 1]);
            row[c] = g[c] + best;
        }
    return row[C - 1];
}
def min_path_sum(grid):
    C = len(grid[0])
    row = [float('inf')] * C                      # row[c] = best cost to reach (r, c)
    row[0] = 0
    for r in range(len(grid)):
        for c in range(C):
            left = row[c - 1] if c > 0 else float('inf')
            row[c] = grid[r][c] + min(row[c], left)   # row[c] still holds the cell above
    return row[-1]

Variants you should recognise: obstacles (Unique Paths II: an obstacle cell is 0); a triangle (Triangle: go bottom-up so each cell picks the min of its two children, and the answer lands at the top); the largest all-ones square (Maximal Square: for a 1 cell, dp[r][c] = 1 + min(up, left, up-left)). When a transition needs the up-left diagonal, the one-row trick needs one extra variable to remember the old value of row[c-1] before it is overwritten. Longest Increasing Path in a Matrix has no fixed fill order (moves go any direction), so it uses memoised DFS instead of loops.
