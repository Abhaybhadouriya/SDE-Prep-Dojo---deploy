Interview questions

Memoisation or tabulation: which do you choose?

Both have the same time complexity for the same state space. Memoisation (top-down) follows directly from the recursion, so it is quicker to write correctly and computes only the states that are actually reachable, which helps when the space is sparse. Tabulation (bottom-up) avoids recursion depth limits and call overhead, makes the fill order explicit, and is the form you need to compress space to one row or two variables. In an interview I usually derive the recursion, memoise it, and then convert to bottom-up if time allows or if n is large.

How to answer

Compare on four points: ease of derivation, states computed, recursion depth, space optimisation.

Likely follow-ups
  • When is top-down strictly better? (When most states are unreachable, for example a memo keyed on (index, remaining) where only a few remainders occur.)
  • When is bottom-up required? (Large n in languages with small stacks, or when you want O(1) or O(row) space.)
How do you know a problem needs DP and not greedy?

DP needs optimal substructure and overlapping subproblems. Greedy needs more: a locally best choice that is always part of some optimal solution (the greedy-choice property), which you must be able to argue, usually by an exchange argument. My test is to try to break the greedy rule with a small input. Coin change with coins {1, 3, 4} and amount 6 breaks "largest coin first" (greedy 3 coins vs optimal 2). If I find a counterexample, I go to DP; if I can prove the exchange argument, greedy is simpler and faster.

How to answer

Name the two DP properties, the extra greedy property, and show a concrete counterexample.

Likely follow-ups
  • Name a problem where greedy works. (Jump Game reachability, interval scheduling by earliest end time, Gas Station.)
Climbing stairs, but you may take any step size from a given set, and n is up to 1018. How?

For a set of steps S, ways(i) = sum of ways(i - s) for s in S, with ways(0) = 1: O(n x |S|) time and O(max S) space with a rolling window. For n up to 1018 a loop is impossible; because the recurrence is linear with constant coefficients, write it as a k x k matrix (k = max step) times the vector of the last k values, and raise the matrix to the n-th power by repeated squaring: O(k3 log n), with the modulus applied at every multiplication.

How to answer

Give the general recurrence, then the window, then the matrix-power idea only for the huge-n follow-up.

Likely follow-ups
  • Order of steps does not matter (count combinations)? (That is Coin Change II: loop over step sizes outside, amounts inside.)
House Robber II: the houses form a circle. What changes?

The first and last houses are now neighbours, so at most one of them is robbed. Split into two linear problems: houses 0..n-2 (the last is excluded) and houses 1..n-1 (the first is excluded), run the linear take/skip DP on each, and return the larger. Handle n = 1 separately (just that house). Still O(n) time, O(1) space.

How to answer

Turn the new constraint into "one of two cases" and reuse the solved linear version.

Likely follow-ups
  • Houses on a binary tree? (House Robber III: a DFS returns the pair (best if this node is robbed, best if not) and the parent combines them.)
Decode Ways: what are the edge cases?

All of them involve '0'. A '0' cannot stand alone, so it only contributes through a valid pair "10" or "20". A leading '0' or a '0' after anything other than '1' or '2' makes the answer 0. Pairs above "26" are invalid, as are pairs starting with '0' ("05"). With dp[0] = 1 for the empty prefix and the two checks (single digit 1-9, pair 10-26), the code handles every case without special branches; I test "0", "06", "10", "226", "2101" and "27".

How to answer

State the recurrence, then list the zero cases and show the test strings you would run.

Likely follow-ups
  • The string may contain '*' meaning any digit 1-9? (Decode Ways II: the same recurrence with counts of how many digits each symbol can stand for, modulo 109+7.)
You compressed the DP to O(1) space. Now the interviewer wants the actual choices (which houses). What do you do?

Two variables only remember values, not decisions. Keep either the full table and walk back from the answer (at each i, check whether best[i] came from best[i-1] or from best[i-2] + nums[i]), or keep an O(n) array of choices made at each step. Both cost O(n) space. For two-dimensional tables like LCS or edit distance, reconstruction walks back from dp[n][m] the same way. Hirschberg's algorithm gets an LCS string in linear space with divide and conquer, worth naming but rarely asked to code.

How to answer

Say clearly that reconstruction needs the decisions, then show the walk-back on the small example.

Likely follow-ups
  • Can you reconstruct from a memo? (Yes: call the same recursion again and follow the branch whose memoised value matches the answer.)
Coin Change: why does greedy fail, and what is the complexity of the DP?

Greedy fails for coin systems that are not "canonical": coins {1, 3, 4}, amount 6, greedy takes 4+1+1 while 3+3 is optimal. The DP: dp[a] = fewest coins for amount a; dp[0] = 0; dp[a] = 1 + min(dp[a - c]) over coins c ≤ a; unreachable amounts stay at infinity and the answer is -1 if dp[amount] is infinite. Time O(amount x number of coins), space O(amount). A BFS over amounts (each coin is an edge of cost 1) gives the same answer and stops early at the target.

How to answer

Counterexample, state, transition, base, the "impossible" value, complexity.

Likely follow-ups
  • Count the combinations instead? (Coin Change II: dp[0] = 1, coins outer loop, amounts inner loop so each combination is counted once.)
In grid DP, when does the one-row space optimisation work, and when does it need more?

It works when each cell depends only on the cell above (still in the array, not yet overwritten) and the cell to the left (already updated this row): Unique Paths, Minimum Path Sum. If a cell also needs the up-left diagonal (Maximal Square, LCS, Edit Distance), that value is overwritten by the time you need it, so save it in one extra variable before each write. If a cell needs the cell to its upper right or the full previous row in another order, keep two rows and swap them. If the dependencies have no fixed direction (Longest Increasing Path in a Matrix), use memoised DFS rather than a fill order.

How to answer

Draw the dependency arrows of one cell, then say which ones survive in a single array.

Likely follow-ups
  • Which dimension should the rolling row run over? (The smaller one, so the space is O(min(R, C)).)
