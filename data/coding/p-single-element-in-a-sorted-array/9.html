  • Cue: sorted, all pairs but one, O(log n) -> binary search on a predicate, not on a value.
  • Insight: before the single, pairs start at even indexes; after it, at odd ones.
  • State: lo, hi, mid forced even; nums[mid] == nums[mid+1] -> lo = mid + 2, else hi = mid.
  • Trap: lo = mid + 1 (parity broken) and hi = mid - 1 (skips the answer).
  • Cost: O(log n) time, O(1) space; XOR is O(n) and only the warm-up.
lo, hi = 0, n - 1                    # first index where good(i) is False
while lo < hi:
    mid = (lo + hi) // 2
    if good(mid): lo = mid + 1       # boundary is to the right
    else: hi = mid                   # mid may be the boundary
return lo

An intact pair at an even index means no shift has happened yet, so the single is after index 3 (it is 8 at index 4).

Why is the index of the single value always even?

  1. An even number of cells (complete pairs) come before it
  2. Because n is odd
  3. Because the array is sorted
  4. It is not always even
Everything before the single forms complete pairs, so the count before it is even.
