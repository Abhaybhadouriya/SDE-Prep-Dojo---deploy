The story

Explain like I'm 5

Socks are laid out in a long row, sorted by colour, and every colour comes as a pair standing side by side. One colour has lost its partner. Point at any sock in an "even" seat (seat 0, 2, 4...). If its partner is sitting right after it, nothing has gone wrong yet, so the lonely sock is further along. If its partner is not there, the row is already out of step, so the lonely sock is here or earlier. Half the row is ruled out with one look.

The array is sorted, but the search is not a value search: we never compare with a target. We search for the first index where a yes/no property flips. That is the skill this problem tests, and the same skill solves Find Peak Element and the rotated-array problems.

From your world

Think of a ring of 2-word descriptors where one descriptor was written with a single word. Every descriptor after the bad one is misaligned by one word. To find the bad one you do not scan: you check alignment at a midpoint (is word 2k the start of a descriptor?) and bisect, exactly like git bisect on "is the layout still aligned here?".
