Approaches: brute -> better -> optimal

Hint 1

Write the indexes under the example. Where do pairs start before the single value? Where do they start after it?

Hint 2

If you only ever probe even indexes, the check is one comparison: nums[mid] == nums[mid + 1].

1. Brute force - scan pairs

Idea: walk i = 0, 2, 4, ... and return nums[i] the first time nums[i] != nums[i+1] (or when i is the last index).

O(n)time
O(1)space

What is wasted: the sortedness and the pairing structure are ignored; the stated O(log n) bound is missed.

2. Better - XOR everything

Idea: x ^ x = 0 and x ^ 0 = x, so XOR of all elements leaves the single value. This is the Single Number (LC 136) trick and works even when the array is not sorted.

O(n)time
O(1)space

What is wasted: it still reads all n values. Mention it to show you know it, then say "sorted means we can do better".

3. Optimal - binary search on pair parity

lo, hi = 0, n - 1                 # both even, answer in [lo, hi]
while lo < hi:
    mid = (lo + hi) // 2
    if mid % 2: mid -= 1          # probe the start of a pair
    if nums[mid] == nums[mid + 1]: lo = mid + 2
    else: hi = mid
return nums[lo]
  1. Predicate: P(i) = "nums[i] == nums[i+1]" for even i. It is true for every even i before the single value and false from the single value on.
  2. Invariant: the single value's index is in [lo, hi], and lo, hi are even.
  3. Step: force mid even. P(mid) true -> the single is after mid + 1, so lo = mid + 2 (still even). P(mid) false -> the single is mid or earlier, so hi = mid (still even).
  4. Termination: lo < hi and both even means hi ≥ lo + 2, so mid + 1 ≤ hi is always a valid index, and the window shrinks every round.
O(log n)time
O(1)space

Why it works: let the single value sit at index s. Every index before s belongs to a complete pair, and pairs never straddle s, so pairs there occupy (0,1), (2,3), ..., (s-2, s-1): every even index before s is the left half of a pair. The single value takes one slot, so from s + 1 on everything is shifted by one: pairs occupy (s+1, s+2), ..., and since s is even (an even number of cells come before it), every even index ≥ s is either s itself or the right half of a pair. Either way nums[i] != nums[i+1]. So P is true, true, ..., true, false, false, ...: a monotone predicate whose first false is exactly s.

The XOR shortcut used in top community solutions

Instead of forcing mid even, compare nums[mid] with nums[mid ^ 1]: for even mid, mid ^ 1 = mid + 1; for odd mid, mid ^ 1 = mid - 1. "Equal to my partner" means the pairing is intact at mid, so lo = mid + 1; else hi = mid. It is the same predicate written for every index, in fewer lines. Use whichever you can explain without hesitation.
