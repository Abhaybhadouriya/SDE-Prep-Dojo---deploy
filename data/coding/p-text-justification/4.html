Approaches: brute -> better -> optimal

Hint 1

Split it into two functions: "which words go on this line?" and "build the line string from them".

Hint 2

For k words of total length L, the minimum line length is L + (k - 1). When does the next word fit?

Hint 3

Which two kinds of line skip the even-spacing rule?

1. Straightforward - build, then re-pad

Idea: keep a current line as a list; when the next word does not fit, insert spaces one at a time into the gaps, round-robin from the left, until the line is maxWidth long (the most-voted Python solution does exactly this with cur[i % gaps] += ' ').

O(n · maxWidth)time (one step per space)
O(maxWidth)extra space

What is wasted: very little for these limits, and the code is short. Its weakness in an interview is clarity of edge cases: the or 1 trick for a single-word line hides a rule the interviewer wants to hear said out loud. -> rung 2 makes every rule explicit.

2. Optimal - greedy line, then divmod

while j < n and letters + len(words[j]) + (j - i) <= maxWidth:
    letters += len(words[j]); j += 1
gaps = j - i - 1
if j == n or gaps == 0:  left-justify and pad
else:                    each, extra = divmod(maxWidth - letters, gaps)
  1. Pick the line. Starting at word i, add word j while letters + len(words[j]) + (j - i) <= maxWidth. The (j - i) term is the one mandatory space before each added word.
  2. Classify it. gaps = j - i - 1. If j == n (last line) or gaps == 0 (one word): join with single spaces and pad on the right.
  3. Otherwise spread. spaces = maxWidth - letters; each = spaces / gaps; extra = spaces % gaps. Gap t (0-based from the left) gets each + 1 if t < extra, else each.
  4. Advance. i = j and repeat until all words are placed.
O(C)time, C = total output characters
O(maxWidth)extra per line

Why greedy is right here: the problem defines the layout as greedy ("pack as many words as you can in each line"), so there is no optimisation to prove; the only correctness question is the fit test. A line of k words needs at least L + k - 1 characters, and spaces only grow from there, so the next word fits exactly when the minimum length with it is <= maxWidth. (Minimising raggedness instead of being greedy is a different, DP problem: see the follow-ups.)

Total work: every word is visited once by the packing loop, and every output character is written once, so time is O(C) where C = lines · maxWidth ≤ n · maxWidth.
