Minimise the raggedness instead of packing greedily (like TeX).

That is a DP: cost(i, j) = (maxWidth - minimum length of words i..j)2 if they fit, infinity otherwise; dp[i] = min over j of cost(i, j) + dp[j + 1], with the last line free. O(n · k) where k is the most words per line. Greedy can leave one very short line where DP spreads the slack.

Words longer than maxWidth are allowed: hyphenate or split them.

Before packing, cut any word longer than maxWidth into pieces of maxWidth - 1 characters plus a hyphen (and a final tail). Then the normal algorithm applies because every token fits again.

How to answer

Support center and right alignment as well.

Keep the packing step and swap the line builder: right = pad on the left; center = split the padding into floor/ceil halves. The structure "choose the words, then format the line" makes each alignment a small function.

How to answer

Show the design: pack(words, width) returns ranges, format(range, mode) builds strings.

The text is a stream that does not fit in memory.

Greedy packing only needs the current line, so read tokens one at a time, buffer at most one line (≤ maxWidth characters), and emit it when the next token does not fit. The only lookahead is "is this the last line?", answered at end of stream.

How to answer

Note that this is why greedy layout is used for terminals and logs, while DP layout needs the whole paragraph.

Likely follow-ups
  • Memory bound? (O(maxWidth) for the line buffer.)
How do you test this?

Assert invariants rather than only exact strings: every line has length maxWidth; joining the words of the output in order gives the input; in middle lines, gap sizes differ by at most 1 and never increase from left to right; the last line has single spaces. Then add the classic cases: one word, one-word lines, an exactly full line.

How to answer

Invariant-based checks catch bugs that a few hand-picked examples miss.
