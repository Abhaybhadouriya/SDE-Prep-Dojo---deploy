Approaches: brute → better → optimal

Hint 1

Which nodes can possibly be the first node of the answer?

Hint 2

Only the k heads. After you take one, which node replaces it as a candidate?

Hint 3

You need "minimum of k numbers" with one number changing per step. Which structure does that in O(log k)?

1. Brute force - collect, sort, rebuild

Idea: walk every list, put all N values in an array, sort it, and build (or relink) a list in that order.

O(N log N)time
O(N)extra space

What is wasted: the input is already sorted inside each list, and we throw that away. We also need an extra array of N values. It is a fine thing to say first, but the interviewer will ask you to use the order.

2. Better - merge the lists one after another

Idea: reuse the two-list merge (LeetCode 21). Merge list 0 with list 1, merge the result with list 2, and so on.

O(N·k)time (worst)
O(1)extra space

What is wasted: the merged result grows, and every new merge walks it again. With k lists of n = N/k nodes, the merges cost 2n + 3n + ... + kn, which is about N·k/2. Nodes from the first list are walked k - 1 times. Two fixes exist: never walk the result again (the heap, rung 3), or keep every merge balanced (divide and conquer, rung 4).

3. Optimal - min-heap of the k heads

heap = [(node.val, i, node) for i, node in enumerate(lists) if node]
heapq.heapify(heap)
while heap:
    _, i, node = heapq.heappop(heap); tail.next = node; tail = node
    if node.next: heapq.heappush(heap, (node.next.val, i, node.next))
  1. The heap holds exactly one node per non-empty list: its current head. Start by pushing every non-null head.
  2. The heap top is the smallest node left anywhere. Every other node in a list is at least that list's head, and every head is in the heap.
  3. Pop it, link it, push its successor. The successor is the new head of that list, so the first rule still holds.
  4. Splice, do not copy. Reuse the input nodes and a dummy head; no new nodes are needed.
  1. Push the head of every non-empty list: the heap holds 1(B), 2(A), 3(C). Its top is the smallest value in the whole input.
  2. Pop 1(B) and append it to the output. B's next node, 6, takes B's place in the heap.
  3. Pop 2(A), append it, push A's next node 6. The heap never holds more than k = 3 nodes.
  4. Pop 3(C), push 7(C). Every value still waiting is at least the heap top, because each list is sorted.
  5. Two nodes tie at 6. Either may go first; the output stays sorted. Pop 6(A), push 9(A).
  6. Pop 6(B), push 8(B).
  7. Pop 7(C). List C is now empty, so nothing is pushed and the heap shrinks to 2.
  8. Pop 8(B), then 9(A). The heap is empty: the output 1,2,3,6,6,7,8,9 is the answer. 8 pops and pushes, each O(log 3).
O(N log k)time: N pops and pushes on a heap of size ≤ k
O(k)extra space (the heap)

Why it works: each step outputs the smallest remaining node, so the output is sorted. Each node is pushed once and popped once, so there are N pops. The heap never holds more than k nodes, so each operation costs O(log k).

Proof (optional)

Invariant: before each pop, the heap contains the head of every non-empty remaining list and nothing else. Let m be the heap minimum and x any remaining node, in list j. List j is sorted, so x ≥ head(j) ≥ m. Hence m is the global minimum of the remaining nodes, and appending it keeps the output sorted. Pushing m.next (if any) restores the invariant for m's list; other lists are unchanged. The loop ends when every list is empty, so all N nodes are output.

4. Optimal, O(1) extra space - divide and conquer

Idea: merge the lists in pairs: (0,1), (2,3), ... Then merge the results in pairs again, until one list is left. This is merge sort where the "elements" are whole lists.

O(N log k)time: log k rounds × N nodes
O(1)extra space, iterative (O(log k) stack if recursive)

When to pick it: when the interviewer asks for no extra data structure, or when the lists can be merged in parallel (each round's merges are independent). The heap version is easier to turn into a streaming iterator, which is the usual follow-up.
