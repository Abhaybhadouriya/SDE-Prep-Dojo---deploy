Approaches: brute → better → optimal

Hint 1

Before you reverse anything, how do you know a full group of k exists? What should happen if it does not?

Hint 2

After reversing a group, two links are wrong: the one coming into the group and the one going out of it. Which nodes do you need to remember to fix them?

Hint 3

When you reverse, start prev at the first node of the next group instead of null. The outgoing link then fixes itself.

1. Brute force - copy into an array (or swap values)

Idea: walk the list into an array of node pointers, reverse each block of k in the array, then re-link next pointers in the new order. Swapping vals is not allowed by the statement, but re-linking node pointers is.

O(n)time
O(n)extra space

What is wasted: the array. A linked list can be reversed in place, so the order can be fixed while walking. -> rung 2.

2. Better - recursion, one group per call

Idea: count k nodes from head. If fewer, return head unchanged. Otherwise recursively solve the rest (starting at node k+1), then reverse the first k nodes so the old head points to the solved rest. This is the most-voted community answer.

def solve(head, k):
    node, cnt = head, 0
    while node and cnt < k: node, cnt = node.next, cnt + 1
    if cnt < k: return head
    prev = solve(node, k)                  # the rest, already done
    for _ in range(k):                     # head-insert this group in front of it
        head.next, prev, head = prev, head, head.next
    return prev
O(n)time
O(n/k)stack space

What is wasted: one stack frame per group (5000 frames when k = 1). It also fails the O(1)-space follow-up. -> rung 3 does the same thing with a loop.

3. Optimal - iterative, dummy head + probe + stitch

kth = prev_tail
for _ in range(k):
    kth = kth.next
    if kth is None: return dummy.next      # fewer than k left
first, after = prev_tail.next, kth.next
prev, cur = after, first                   # prev starts at the next group
while cur is not after: cur.next, prev, cur = prev, cur, cur.next
prev_tail.next, prev_tail = kth, first     # stitch, advance
  1. Dummy head. dummy.next = head, prevTail = dummy: the node right before the group to work on. The first group is no longer special.
  2. Probe. Step k times from prevTail. If you hit null, fewer than k nodes remain: stop, they stay as they are. Otherwise the node you reached is kth, the last node of the group.
  3. Remember the seams. first = prevTail.next (it becomes the group's tail) and after = kth.next (the first node of the next group).
  4. Reverse with prev = after. The usual loop, but the first node's next becomes after, so the outgoing seam is already right.
  5. Stitch and advance. prevTail.next = kth fixes the incoming seam; prevTail = first moves to the new tail.
O(n)time (each node probed once, reversed once)
O(1)extra space

Why it works: the loop keeps one invariant: the list from dummy to prevTail is the finished answer for the groups processed so far, and prevTail.next is the first unprocessed node. A full group is reversed among itself with its outgoing link set to after; the stitch restores the invariant one group later. An incomplete tail is never touched, because the probe runs before any pointer changes.

Proof of O(n) (optional)

Each loop iteration probes k nodes and reverses those same k nodes, so it costs O(k) and advances prevTail by k. There are floor(n/k) full iterations plus one failed probe of fewer than k steps: total O(n). Only five pointer variables exist at any time: O(1) space.
