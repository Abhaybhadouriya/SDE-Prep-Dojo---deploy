The problem (in our words)

You get the head of a singly linked list and a positive integer k. Split the list, from the front, into consecutive groups of exactly k nodes, reverse the order of the nodes inside every complete group, and return the head of the resulting list. If the length is not a multiple of k, the last few nodes (fewer than k) stay in their original order.

You must rearrange the nodes themselves; changing the values stored in the nodes is not allowed.

Signature: ListNode reverseKGroup(ListNode head, int k), where ListNode has val and next.

Constraints:

  • The list has n nodes.
  • 1 <= k <= n <= 5000
  • 0 <= Node.val <= 1000

Follow-up from the original: can you do it with O(1) extra memory?

Practice it: LeetCode 25 · GfG Linked List Group Reverse · TUF article

Constraints tell you: n <= 5000 is tiny; time is not the issue. The O(1)-space follow-up is the real ask: it rules out copying values into an array and rebuilding, and it makes the recursive version (O(n/k) stack) second best.
