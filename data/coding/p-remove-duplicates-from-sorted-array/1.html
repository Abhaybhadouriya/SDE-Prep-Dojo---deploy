The problem (in our words)

A sensor log gives an integer array nums sorted in non-decreasing order. Remove the repeated readings in place so that each distinct value appears once, keeping the original (sorted) order. Let k be the number of distinct values. Return k; the first k slots of nums must hold the distinct values in sorted order. What is left in slots k and later does not matter.

Signature: int removeDuplicates(int[] nums). The judge calls it, checks the returned k against the expected count, and then checks nums[0..k-1] element by element.

Constraints:

  • 1 <= nums.length <= 3 * 104
  • -100 <= nums[i] <= 100
  • nums is sorted in non-decreasing order.
  • The change must be made in the given array with O(1) extra memory.

Practice it: LeetCode 26 · GfG Remove duplicates in a sorted array · TUF in-place removal

Constraints tell you: n ≤ 3·104 would even allow O(n²) in time, but "in place, O(1) extra memory" rules out copying into a set or a second array. n ≥ 1, so slot 0 always exists and is always kept. The values fit in a small range (201 possible), so k ≤ 201, but the method must not depend on that.
