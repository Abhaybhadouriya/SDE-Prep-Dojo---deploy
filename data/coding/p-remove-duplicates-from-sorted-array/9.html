  • Cue: in place + keep some elements + return new length -> read/write pointers.
  • Insight: sorted -> a value is new iff it differs from the last KEPT value nums[k-1].
  • State: k = count kept (starts 1), i = read index from 1.
  • Trap: k is a count (return k), not an index; Python must mutate, not rebind.
  • Cost: O(n) time, O(1) space; shifting O(n²); "at most m copies": compare nums[k-m].
k = 0
for x in nums:
    if keep(x, nums[:k]):          # e.g. k < m or x != nums[k - m]
        nums[k] = x; k += 1
return k

For [1,1,2,2,2,3], what does the function return?

  1. 6
  2. 3
  3. 2
  4. 4
Three distinct values: 1, 2, 3. The first three slots become [1,2,3].

Why can the write to nums[k] never destroy a value that is still needed?

  1. The array is sorted
  2. Values are small
  3. k starts at 1
  4. k ≤ i, so slot k was already read
The write pointer never passes the read pointer; everything at or left of i has been read.

To keep each value at most twice, compare x with...

  1. nums[k-2]
  2. nums[i-2]
  3. nums[k-1]
  4. nums[i-1]
In the sorted kept prefix, nums[k-2] == x means two copies of x are kept already. nums[i-2] may have been overwritten.
