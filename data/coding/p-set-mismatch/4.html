Approaches: brute -> better -> optimal

Hint 1

With a boolean array seen[1..n] this is easy. Can the input array hold that information for you?

Hint 2

Every value is positive. A sign bit is a free one-bit flag per slot.

1. Brute force - count every candidate

Idea: for each v in 1..n, count how many times it occurs by scanning the array. Count 2 is the duplicate, count 0 is the missing value.

O(n²)time
O(1)extra space

What is wasted: n full scans to answer n yes/no questions. One scan could answer all of them if we had somewhere to write the answers. Sorting first (then look for equal neighbours and the gap) is O(n log n), but it still mutates the order and is not the best answer.

2. Better - a count array

cnt = [0] * (n + 1)
for x in nums: cnt[x] += 1
dup  = next(v for v in range(1, n + 1) if cnt[v] == 2)
miss = next(v for v in range(1, n + 1) if cnt[v] == 0)

Idea: one pass to count, one pass over 1..n to read the counts. Easy to get right and the first thing to say.

O(n)time
O(n)extra space

What is wasted: the count array has n slots, and so does the input. The input values are exactly the indices we need, so the input can carry the marks itself.

3. Optimal - sign marking in the input

for x in nums:
    v = abs(x)
    if nums[v - 1] < 0: dup = v          # slot already marked
    else: nums[v - 1] = -nums[v - 1]     # mark value v as seen
miss = 1 + first index with nums[i] > 0
  1. Each value owns one slot. Because values are in 1..n and there are n slots, value v maps to slot v - 1 with no collisions.
  2. The sign is the flag. All values are positive, so a negative slot means "the value of this slot was seen". The magnitude is untouched, which is why we read abs(x): a cell may have been marked before we read it.
  3. A second visit names the duplicate. The duplicate is the only value whose slot is reached twice.
  4. The positive slot names the missing value. n - 1 distinct values mark n - 1 slots; exactly one stays positive.
  5. Restore. The second pass flips the negatives back, so the caller sees the array unchanged. Say this out loud: interviewers often ask "you modified my input?"
O(n)time, two passes
O(1)extra space

Why it works: the array is a multiset over 1..n where the duplicate d occurs twice, the missing m occurs zero times and everything else once. Marking slot v - 1 the first time v occurs is exactly a seen bitmap stored in the sign bits; the bitmap ends with every slot set except m - 1, and the only "already set" event happens on the second copy of d. The top-voted community answer for this problem is this four-line idea in Java.

Proof (optional)

Invariant after processing the first t elements: slot j is negative if and only if value j + 1 occurs among those t elements. It holds for t = 0 (all positive). Processing element t + 1 with magnitude v: if v already occurred, slot v - 1 is negative, we report v and change nothing, so the invariant holds; otherwise we negate slot v - 1, which now correctly records v. Only d can occur twice, so the report fires once, with v = d. After all n elements, the positive slots are exactly the values that never occurred, which is {m}.

4. Read-only input - two equations (or XOR)

Idea: compare the array with 1..n. Every value except d and m cancels.

  • d1 = sum(nums) - sum(1..n) = d - m
  • d2 = sumsq(nums) - sumsq(1..n) = d² - m² = (d - m)(d + m), so d + m = d2 / d1 (d1 is never 0 because d ≠ m).
  • d = (d2/d1 + d1) / 2, m = (d2/d1 - d1) / 2.

The code keeps running differences (d1 += x - i, d2 += x*x - i*i), so it never forms the large sum 1² + ... + n² on its own. XOR variant: XOR all values and 1..n to get d ^ m; take its lowest set bit, split both lists by that bit and XOR each half: one half gives d, the other m; one more scan tells which is which. Same O(n), O(1), no overflow at all.
