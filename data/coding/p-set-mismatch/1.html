The problem (in our words)

A badge printer was supposed to print every ID from 1 to n exactly once. Because of a fault, one ID was printed in place of another: some ID appears twice and some other ID is missing. You get the printed IDs as an integer array nums of length n, in any order.

Return an array of two numbers: first the ID that appears twice, then the ID that is missing.

Signature: int[] findErrorNums(int[] nums), returning [duplicate, missing].

Constraints

  • 2 <= nums.length <= 104
  • 1 <= nums[i] <= 104
  • The array is the set 1..n with exactly one value replaced by another value of 1..n, so every nums[i] is in [1, n].

Practice it: LeetCode 645 - Set Mismatch · GfG - Missing And Repeating (same task, judged on GfG) · TUF - Find the repeating and missing numbers · Code360 version

Constraints tell you: n ≤ 104, so anything O(n log n) or better passes; even O(n²) is 108 and risky. The interview is about O(1) extra space. Values are guaranteed to be in 1..n, which is exactly what lets each value use slot v - 1 as its own marker. The sum of squares reaches about 3.3 · 1011 for n = 104, so the math approach needs 64-bit arithmetic or running differences.
