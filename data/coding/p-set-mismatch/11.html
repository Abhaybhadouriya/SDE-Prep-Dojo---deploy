Interview follow-ups

You modified my array. Can you avoid that?

Two options. Restore it: the second pass already flips every negative back, so the caller sees the original array (but it was written to, which matters for shared or read-only memory). Or never write: keep d1 = Σ(x - i) and d2 = Σ(x² - i²), then d + m = d2 / d1. Or XOR split. All are O(n) time and O(1) space.

How to answer

Name the trade-off: sign marking is the simplest to get right; the equations are read-only but need 64-bit care.

Likely follow-ups
  • Is the restored array thread-safe for concurrent readers? No: readers can see negative values mid-run.
Do it with XOR only.

x = XOR(nums) ^ XOR(1..n) = d ^ m, non-zero because d ≠ m. Take bit = x & -x. XOR every value and every number of 1..n that has this bit into bucket A, the rest into bucket B. Pairs cancel inside each bucket, so A and B are d and m in some order. One more scan: whichever of the two appears in nums is d.

How to answer

"XOR leaves d ^ m; a bit where they differ separates them into two independent single-number problems."

Likely follow-ups
  • Why is x & -x the lowest set bit? Two's complement: -x = ~x + 1 flips everything above the lowest 1.
Solve it with cyclic sort instead of signs.

For each i, while nums[i] != nums[nums[i]-1], swap nums[i] into slot nums[i]-1. Each swap places one value at home, so there are at most n swaps. Then the one index with nums[i] != i + 1 holds the duplicate, and i + 1 is missing.

How to answer

Stress the loop condition compares with the target slot's value, not with i, otherwise two copies of d swap forever.

Likely follow-ups
  • Why O(n) with a nested while? Every swap fixes one slot permanently.
Two values are duplicated and two are missing.

Sign marking still works directly: every "already negative" event is a duplicate and every positive slot at the end is a missing value. The equation approach would need four equations (sums of powers up to 4), which is why marking generalises better.

How to answer

Show that the marking approach is really a bitmap and so handles any number of duplicates; the math trick does not scale.

Likely follow-ups
  • A value may appear three times? Then report it once: mark on the first visit, report only if not already reported (or use a second flag bit).
The IDs arrive as a stream of n numbers that you cannot store.

Use the read-only accumulators: Σ(x - i) and Σ(x² - i²) (or the XOR of values and indices plus the bit-split buckets, which needs a second pass). The equations need only one pass and two 64-bit words, and partial sums from several shards add up, so it parallelises.

How to answer

Point out that cancelling aggregates are associative, so a map-reduce over shards just sums them.

Likely follow-ups
  • Overflow for n = 109? Use 128-bit, modular arithmetic with two primes, or a bitmap of n bits (125 MB).
