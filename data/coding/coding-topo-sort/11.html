Interview questions

Can a student finish all courses? Walk me through your approach and complexity.

Model courses as vertices and each prerequisite pair [a, b] as an edge b → a. All courses can be finished exactly when this directed graph has no cycle. I would run Kahn's algorithm: count in-degrees, queue all in-degree-0 courses, pop and decrement neighbours, pushing those that reach 0. If I pop all n courses, return true; otherwise the remaining ones are stuck on a cycle. Time O(V + E), space O(V + E).

How to answer

Name the reduction (cycle detection), state the edge direction, give the algorithm in four lines, then complexity. Mention the DFS alternative and why you chose Kahn's.

Likely follow-ups
  • Return the order too. (Return the popped sequence; that is Course Schedule II.)
  • Print the cycle. (Three-colour DFS with a parent array; on meeting a GRAY vertex, walk parents back to it.)
Why can you not detect a directed cycle with a simple visited set, the way you do for undirected graphs?

In a directed graph a vertex can be reached twice without any cycle: a → b, a → c, c → b reaches b from two routes. A visited set cannot distinguish "seen again via another path" from "seen again on my own current path". Only the second is a cycle. Three colours separate them: GRAY means on the current recursion stack, BLACK means finished. An edge to GRAY is a back edge, and a directed graph has a cycle iff DFS finds a back edge.

How to answer

Draw the diamond. It makes the point in five seconds.

Likely follow-ups
  • What about undirected graphs? (There, any visited neighbour other than the parent closes a cycle, so two states suffice; union-find also works.)
  • Could you use an "on stack" boolean instead of GRAY? (Yes: visited + onStack is the same three states encoded in two flags.)
Alien Dictionary: what are the edge cases that make candidates fail?

Four. First, a longer word before its own prefix ("abc", "ab") makes the input invalid, so return "". Second, only the first differing letter of an adjacent pair gives an edge; letters after it carry no information. Third, letters that never appear in any edge still belong in the output, so every letter of every word must be a vertex. Fourth, the same edge can be derived from several pairs; store neighbours in a set and only count in-degree for new edges. After that it is plain Kahn's, returning "" if fewer letters come out than exist.

How to answer

Separate the problem into "build the graph" and "sort it", and list the graph-building pitfalls before coding.

Likely follow-ups
  • Is the order unique? (Only if Kahn's queue never holds two letters at once.)
  • Complexity? (O(C) for C total characters; the graph has at most 26 vertices.)
Kahn's algorithm or DFS: which do you pick, and when would you pick the other?

Both are O(V + E). I default to Kahn's: no recursion depth risk, cycle detection is just a count, and it extends naturally to levels (rounds), smallest order (min-heap) and uniqueness checks. I pick DFS when the problem is already a DFS, for example memoised DP over a DAG (Longest Increasing Path), "safe states" where the colour itself is the answer, or when I must print the actual cycle.

How to answer

One sentence each on strengths, then a concrete problem for each side.

Likely follow-ups
  • Make the DFS iterative. (Explicit stack of (vertex, next edge index); append to the finish list when the index runs out.)
How do you check whether the topological order is unique?

Run Kahn's. If at any moment the ready queue holds two or more vertices, either could go first, so at least two orders exist. If the queue size is exactly 1 at every step and all vertices come out, the order is unique. Equivalently, a DAG has a unique topological order iff it has a Hamiltonian path, i.e. every consecutive pair in the order is joined by an edge. This is the core of Sequence Reconstruction.

How to answer

Give the queue-size test, then the equivalent edge test as a proof sketch.

Likely follow-ups
  • Count the number of orders. (Exponential in general; bitmask DP for n ≤ 20.)
Each task has a duration and tasks may run in parallel. What is the minimum total time?

That is the longest weighted path in the DAG (the critical path). Process vertices in topological order and keep finish[v] = time[v] + max over predecessors u of finish[u]; the answer is the maximum finish. It is O(V + E). Longest path is NP-hard in general graphs but easy in a DAG, because the topological order guarantees every predecessor is final before you use it.

How to answer

Say "DP in topological order", write the recurrence, and mention why it only works without cycles.

Likely follow-ups
  • Only k workers at a time? (Becomes a scheduling problem, NP-hard in general; small n uses bitmask DP, large n uses heuristics such as list scheduling.)
Edges arrive one at a time. How would you reject an edge that would create a cycle?

Adding u → v creates a cycle iff v can already reach u. The simple answer is a DFS or BFS from v looking for u before accepting the edge: O(V + E) per insert, fine for small graphs. This is what the kernel's lockdep does conceptually when it records a new lock-order edge. For heavy workloads there are incremental topological order algorithms that keep a current order and only re-sort the affected range, but in an interview the reachability check plus its cost is the expected answer.

How to answer

Reduce to a reachability query, give its cost, then mention that faster incremental algorithms exist without overclaiming details.

Likely follow-ups
  • Undirected version? (Union-find: the edge closes a cycle iff both ends already share a root; that is Redundant Connection.)
