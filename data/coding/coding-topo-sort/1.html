What a topological order looks like

Here is a small course catalogue. An arrow means "take this first". Below it, the same six courses are lined up in one valid order. Notice that every dashed arrow in the line-up points right: that is the whole definition.

Three facts to keep in your head before writing any code:

  • The order is usually not unique. Any two vertices with no path between them can appear in either order. Problems that say "return any valid order" accept all of them; problems that ask for a unique or smallest order need extra work (see variants).
  • No order exists exactly when there is a cycle. So "can all courses be finished?" is the same question as "is this directed graph acyclic?".
  • Both algorithms are O(V + E). Each vertex is output once and each edge is looked at once. Space is O(V + E) for the adjacency list plus O(V) for in-degrees or colours.

Edges always point from "first" to "later"

Before any algorithm, decide what an edge means and stick to it. This page always uses u → v = "u before v". Interview inputs often use the opposite convention. LeetCode's Course Schedule gives pairs [a, b] meaning "to take a you must first take b", so the edge is b → a. Getting this backwards still detects cycles correctly (a reversed graph has the same cycles) but produces the order backwards, which is the most common wrong answer on Course Schedule II.
