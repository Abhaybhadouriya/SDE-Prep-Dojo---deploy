How to recognise a topological sort problem

  • The statement has "before", "after", "depends on", "prerequisite", "requires", or a list of pairs that are clearly ordered.
  • It asks "is it possible to finish / schedule / build everything?": that is directed cycle detection.
  • It asks for "an order", "a valid sequence", "the build order", "the order of letters".
  • It asks for "minimum number of rounds / semesters / days" with unlimited parallelism: Kahn levels.
  • It asks for "earliest finish time" or the longest path with durations: DP in topological order.
  • A sorted list of strings in an unknown alphabet: derive edges from adjacent pairs.
  • Any DP whose states depend on each other along a directed graph with no cycles: evaluate in topological order (or memoised DFS, which computes the same order implicitly).

Counter-cues: if the edges are undirected, you want connected components or union-find, not topological sort. If edges have weights and you want the shortest path in a general graph, you want Dijkstra (though on a DAG, relaxing in topological order is faster and also handles negative weights).
