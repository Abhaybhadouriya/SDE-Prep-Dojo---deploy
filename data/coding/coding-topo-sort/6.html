Parallel Courses: counting rounds

The problem (restated). There are n courses labelled 1 to n and a list of relations [prev, next], each meaning prev must be taken before next. In one semester you may take any number of courses, as long as every prerequisite of each was finished in an earlier semester. Return the minimum number of semesters to take all courses, or -1 if it is impossible. Limits: n ≤ 5000, up to 5000 relations. Reference: LeetCode 1136 (Premium).

Run Kahn's algorithm, but pop the queue one whole level at a time. Level 1 is every course with no prerequisites, level 2 is everything they unlock, and so on. Taking each level as one semester is optimal, because a course can never be taken earlier than its level: its level is exactly the length of the longest prerequisite chain ending at it.

// 4. Parallel courses: Kahn level by level; each level is one semester.
func minSemesters(n int, relations [][]int) int {
	adj := make([][]int, n+1)
	indeg := make([]int, n+1)
	for _, r := range relations {
		adj[r[0]] = append(adj[r[0]], r[1])
		indeg[r[1]]++
	}
	level := []int{}
	for i := 1; i <= n; i++ {
		if indeg[i] == 0 {
			level = append(level, i)
		}
	}
	semesters, taken := 0, 0
	for len(level) > 0 {
		semesters++
		next := []int{} // the whole level is taken together
		for _, u := range level {
			taken++
			for _, v := range adj[u] {
				indeg[v]--
				if indeg[v] == 0 {
					next = append(next, v)
				}
			}
		}
		level = next
	}
	if taken != n {
		return -1
	}
	return semesters
}
// 4. Parallel courses: Kahn level by level; each level is one semester.
int minSemesters(int n, const vector<vector<int>>& relations) {
    vector<vector<int>> adj(n + 1);
    vector<int> indeg(n + 1, 0);
    for (const auto& r : relations) { adj[r[0]].push_back(r[1]); indeg[r[1]]++; }
    queue<int> q;
    for (int i = 1; i <= n; i++) if (indeg[i] == 0) q.push(i);
    int semesters = 0, taken = 0;
    while (!q.empty()) {
        semesters++;
        for (int sz = q.size(); sz > 0; sz--) {                  // the whole level at once
            int u = q.front(); q.pop();
            taken++;
            for (int v : adj[u]) if (--indeg[v] == 0) q.push(v);
        }
    }
    return taken == n ? semesters : -1;
}

static bool validOrder(int n, const vector<pair<int,int>>& e, const vector<int>& order) {
    if ((int)order.size() != n) return false;
    vector<int> pos(n);
    for (int i = 0; i < n; i++) pos[order[i]] = i;
    for (const auto& x : e) if (pos[x.first] >= pos[x.second]) return false;
    return true;
}

static int minSemesters(int n, int[][] relations) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i <= n; i++) adj.add(new ArrayList<>());
    int[] indeg = new int[n + 1];
    for (int[] r : relations) { adj.get(r[0]).add(r[1]); indeg[r[1]]++; }
    ArrayDeque<Integer> q = new ArrayDeque<>();

            int u = q.poll();
            taken++;

        }

def min_semesters(n, relations):
    """Courses 1..n, relations [prev, next]. Fewest semesters, or -1 on a cycle."""
    adj = [[] for _ in range(n + 1)]
    indeg = [0] * (n + 1)
    for a, b in relations:
        adj[a].append(b)
        indeg[b] += 1
    q = deque(i for i in range(1, n + 1) if indeg[i] == 0)
    semesters, taken = 0, 0
    while q:
        semesters += 1
        for _ in range(len(q)):              # take the whole current level together
            u = q.popleft()
            taken += 1
            for v in adj[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    q.append(v)
    return semesters if taken == n else -1


def valid_order(n, edges, order):
    pos = {v: i for i, v in enumerate(order)}
    return len(order) == n and all(pos[u] < pos[v] for u, v in edges)

When courses take different amounts of time

Parallel Courses III gives each course a duration and unlimited parallelism, and asks for the earliest time everything is done. Levels no longer work, because a short course on a long level can finish early. Instead keep finish[v] and relax it in topological order: when you pop u, set finish[v] = max(finish[v], finish[u] + time[v]) for each successor. The answer is the largest finish time. This is the critical path of project scheduling, and it is the general pattern: any DP over a DAG is computed in topological order, because each state's inputs are finished before it.

From your world

make -j is Parallel Courses III with unlimited workers: the wall-clock build time is the longest chain of compile and link steps, not the sum of all of them. Kernel initcall levels (core_initcall, subsys_initcall, device_initcall...) are the level-by-level version: everything in one level may run in any order, but only after the previous level is done.
