Prove that never lowering maxFreq still gives the right answer.

Let best be the answer so far = window size. A window of size best + 1 can only be valid if some letter appears at least best + 1 - k times in it, i.e. more than the old maxFreq (because best = maxFreq + k at the moment it was set, or less). So until maxFreq increases, no longer window is valid, and sliding at constant size loses nothing. When maxFreq increases, it does so because the current window really has that count, so the grown window is valid.

How to answer

Frame it as "the answer is maxFreq + k, capped by n; we only care about new records of maxFreq".

Likely follow-ups
  • Why does the final window not need to be valid?

Answer many queries (k values) on the same string.

For each target letter c, the longest window with at most k non-c letters is non-decreasing in k. Precompute, per letter, the positions of the other letters; for a given k the best window for c is the max gap spanning k+1 consecutive "other" positions. Then each query is 26 lookups after O(26·n) preprocessing.

How to answer

Fix the target letter first; that turns the problem into Max Consecutive Ones III, which is easy to precompute.

Likely follow-ups
  • Binary search on the answer length with a fixed-size window check: O(n log n).
Every change must turn a letter into one given letter c. What changes?

The target is fixed, so the cost of a window is just "letters that are not c". Keep one counter of non-c letters, shrink while it exceeds k: this is exactly Max Consecutive Ones III. Running it for each of the 26 letters and taking the max is the O(26·n) alternative solution to the original problem.

How to answer

Show that fixing the target removes the need for maxFreq altogether.

Likely follow-ups
  • Each change has a different cost per letter: the budget becomes a sum of costs, same window.
