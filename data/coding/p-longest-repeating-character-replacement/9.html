Revision card

  • Cue: longest substring with "at most k fixes" -> variable sliding window.
  • Insight: window is OK iff size - maxCount <= k; never shrink - if broken, slide by one, so the answer only grows when maxCount grows.
  • State: count[26], left, maxCount (best count seen in any window).
  • Trap: maxCount may be stale - fine for the size, not for "is this window valid".
  • Cost: O(n) time, O(26) space; O(26·n) with a rescanned max.
left = maxf = 0
for right, ch in enumerate(s):
    cnt[ch] += 1; maxf = max(maxf, cnt[ch])
    if right - left + 1 - maxf > k:
        cnt[s[left]] -= 1; left += 1
return len(s) - left

Why can maxFreq stay stale (never decrease) when left moves?

  2. it saves memory
  3. the answer only grows when a larger maxFreq appears, so a stale value never inflates the result

The window never shrinks below the best size; a larger answer needs a new, real, larger maxFreq.

The window only grows or slides, so its final length equals the best length seen.
