Now each operation can add or subtract 1.

The best target for a sorted window is no longer its maximum but its median (the point minimising the sum of absolute distances). Cost of [l..r] = median × (left count) - left sum + right sum - median × (right count), computed from prefix sums in O(1). The window still only moves right: shrinking a window cannot raise its median cost. That is LC 2968.

How to answer

Name the change of target (max → median) and why it holds (sum of |x - t| is minimised at a median).

Likely follow-ups
  • Why prefix sums now? (The cost is two sums split at the median, not one running total.)
Can you avoid the O(n log n) sort?

Values are at most 10^5, so a counting sort runs in O(n + V). The window then works on the expanded counts, or directly on (value, count) pairs if you handle a partially included bucket at the left edge. In an interview, mention counting sort and keep the comparison sort in code.

How to answer

Tie the improvement to the bounded value range from the constraints.

Likely follow-ups
  • What if values reach 10^9? (Back to O(n log n); the sort is the bottleneck.)
Answer many queries with different k on the same array.

Sort once and build prefix sums. For each query, binary search the answer size m: a size m is feasible if some block nums[i-m+1..i] has cost ≤ k. The minimal cost over all blocks of size m can be precomputed for every m in O(n²), or checked in O(n) per query for O(n log n) per query. If queries are offline, sort them by k and grow the window: the best size is non-decreasing in k.

How to answer

Show the monotonicity in k (more budget never hurts), then pick offline sorting or binary search.

Likely follow-ups
  • Online queries with updates to nums: a balanced tree or segment tree over sorted values.
Explain the version where the window never shrinks.

Use if instead of while: on an over-budget step, move left by one. The window size then never decreases, so it always equals the best size found so far, even when the current window itself is over budget. At the end, the answer is n - left. It works because we only care about the maximum size, not about a valid window at every moment.

How to answer

Say what the window means in this version: "the best size so far, slid to the current right edge".

Likely follow-ups
  • Which other "longest" window problems allow this? (Any where you only return the length: LC 424, LC 1004.)
