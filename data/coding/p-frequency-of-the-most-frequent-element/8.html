Common mistakes

32-bit overflow in target * size. In C++ and Java, nums[right] * (right - left + 1) is computed in int even if you compare it with a long. Cast one side to 64-bit before the multiply.

Targeting the most common value or the median. The target must be the window's largest value, because you can only increase. A median-based idea answers a different problem (moves in both directions, LC 462).

Shrinking from the wrong end. Dropping the target (right) instead of the smallest value (left) loses the cheapest structure: the leftmost value is always the most expensive to raise.

Using a sum of differences recomputed per step. Looping over the window to add up target - nums[j] makes it O(n²). Keep a running sum and use target × size - sum.

Mixing the if and while styles. With the single-step if shrink, the window can be over budget, so best = max(best, size) inside the loop is still right only because the size never shrinks. If you change the update, the trick breaks; keep one style.
