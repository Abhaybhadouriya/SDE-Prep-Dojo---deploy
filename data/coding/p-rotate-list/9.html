60-second recall

  • Cue: rotate / shift a list by k, k possibly huge -> length + modulo + re-link.
  • Insight: rotation by len is identity; the new tail is node len - k.
  • State: tail, len, newTail; no extra memory.
  • Trap: empty list, k % len == 0 (do not leave a ring), off-by-one walk.
  • Cost: O(n) time, O(1) space.
tail, n = head, 1
while tail.next: tail, n = tail.next, n + 1
k %= n
if k == 0: return head
nt = head
for _ in range(n - k - 1): nt = nt.next
new_head, nt.next, tail.next = nt.next, None, head

Quick quiz

List of 6 nodes, k = 14. Which node (1-based) becomes the new head?

  1. 3
  2. 4
  3. 5
  4. 2
14 % 6 = 2; the new tail is node 6 - 2 = 4, so the new head is node 5.

Why check k % len == 0 before linking the tail to the head?

  1. Otherwise you return a circular list
  2. To avoid integer overflow
  3. Because len may be 0
  4. It is only an optimisation
With no cut, the ring stays closed and any traversal of the result never ends.

How would you rotate left by k instead?

  1. Use k % len as the new tail position
  2. Rotate right by len - (k % len)
  3. Reverse the list first
  4. It is impossible in O(1) space
Left by k equals right by len - k; the new tail is node k (k reduced modulo len).
