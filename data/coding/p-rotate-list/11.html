Interview follow-ups

Rotate left by k instead.

Reduce k modulo len; if 0 return head. The new tail is node k (k - 1 steps from head); cut after it and link the old tail to the old head. Equivalent to rotating right by len - k.

Can you do it in a single pass?

Not when k can exceed len: you must know len to reduce k. If k < len is promised, two pointers k apart find the new tail in one pass (like Remove Nth From End). Either way it is O(n).

How to answer

Explain that "one pass" buys nothing asymptotically here; clarity wins.

The list is doubly linked.

Same plan, but also fix the prev pointers: newHead.prev = null, head.prev = oldTail. With a tail pointer you can walk backwards k steps from the tail instead of len - k forwards, picking the shorter side.

The list is rotated many times by different k. Make each rotation O(1).

Keep it circular permanently and store only a head pointer and the length: rotating right by k means moving the head pointer len - (k % len) steps. With an array-backed ring buffer (offset + modulo), each rotation is an O(1) offset update.

How would you rotate an array in place?

Three reversals: reverse the whole array, reverse the first k % n, reverse the rest. O(n) time, O(1) extra (LC 189).
