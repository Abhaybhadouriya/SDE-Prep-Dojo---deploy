The problem (in our words)

A playlist is stored as a singly linked list starting at head. Pressing "bring the last track to the front" once takes the final node and makes it the new first node. You are asked to press it k times (a non-negative integer, possibly far larger than the playlist) and hand back the node that is first afterwards. In list terms: shift every node k positions toward the tail, wrapping around, and return the new head.

  • Input: ListNode head (may be null) and int k.
  • Output: the new head. Signature: ListNode rotateRight(ListNode head, int k).

Constraints

  • The number of nodes is in the range [0, 500].
  • -100 <= Node.val <= 100
  • 0 <= k <= 2 * 10^9

Practice it: LeetCode 61 - Rotate List · GfG - Rotate a Linked List (left rotation) · takeuforward

Constraints tell you: k can be 2 × 10^9 while the list has at most 500 nodes, so rotating one step at a time (O(k) or O(nk)) is far too slow; you must reduce k modulo the length. Zero nodes is allowed, so a null head must not reach a division by zero.
