Interview follow-ups

All numbers are positive. Can you do it in O(1) space?

Yes. With positive values the window sum strictly grows as r moves and strictly shrinks as l moves, so a sliding window counts the windows with sum exactly k in O(n) time and O(1) space: grow r, shrink l while the sum exceeds k, count when it equals k.

How to answer

Name the property the window needs (monotonic sum) and show it holds only without negatives (zeros need atMost(k) - atMost(k-1)).

Likely follow-ups
  • What if zeros are allowed? Use atMost(k) - atMost(k - 1).
Return true/false only: does any subarray sum to k?

A set of prefixes is enough: at each step check whether run - k is in the set, then add run. Stop at the first hit.

How to answer

Show the count map degrades to a set when only existence matters.

Likely follow-ups
  • Return the indices of one such subarray: store the index with the prefix.
The numbers arrive as a stream. Report the running count after each one.

The algorithm is already online: it keeps run, count and the map, and each new number is one O(1) update. Memory grows with the number of distinct prefixes; with bounded values and a sliding time window you would also delete old prefixes when they leave the window.

How to answer

Point out that nothing looks ahead; the state is the map.

Likely follow-ups
  • Only subarrays inside the last W elements: remove pre[i - W] from the map as it expires.
Do the same on a 2-D matrix.

Fix a top row and a bottom row, compress each column between them into one number (column prefix sums make this O(1) per column), and run this 1-D count on that row of column sums. O(R2 C) time; put the smaller dimension in the R2.

How to answer

Reduce to the 1-D problem you just solved; that is LC 1074.

Likely follow-ups
  • Maximum sum rectangle not larger than k? Same reduction plus a sorted set (LC 363).
Can the count overflow? What about the prefix sums?

Here the prefix fits in 32 bits (|run| ≤ 2·107). The count is at most n(n+1)/2 ≈ 2·108, which also fits. With n = 105 or values up to 109, switch both to 64-bit.

How to answer

Do the bound arithmetic out loud; interviewers like seeing it.

Likely follow-ups
  • Worst case for the hash map? Adversarial keys in Java/C++; mention a randomised hash if needed.
