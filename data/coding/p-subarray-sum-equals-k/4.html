Approaches: brute → better → optimal

Hint 1

Write sum(l..r) using two prefix sums. What equation must the two satisfy?

Hint 2

Fix the right end r. You need the number of l with pre[l] = pre[r+1] - k. What structure counts values seen so far?

1. Brute force - every subarray, summed from scratch

Idea: three loops: pick l, pick r, add nums[l..r].

O(n3)time
O(1)space

What is wasted: sum(l..r+1) is sum(l..r) + nums[r+1]; we recompute it every time. -> rung 2.

2. Better - fix the start, extend the end

Idea: for each l, keep a running sum while r moves right; count every time it equals k. (Do not stop early: with negatives a later r can bring the sum back to k.)

O(n2)time
O(1)space

What is wasted: for each end r we still ask n different starts. But the question "which starts work for r?" only depends on one number, pre[r+1] - k. -> rung 3.

Why not a sliding window? A window works when growing it always increases the sum and shrinking always decreases it. With -1 in the array, adding an element can lower the sum, so "sum too big, shrink from the left" can skip valid answers. On [3,-1,1,2,0], k = 3 a shrink-when-too-big window returns 2: once it drops the 3 the sum is 2, and it will not drop the -1 (that would raise the sum), so it never sees [1,2] or [1,2,0].

3. Optimal - prefix sums + count map

seen = {0: 1}; run = count = 0
for x in nums:
    run += x
    count += seen.get(run - k, 0)   # starts that make a sum of k ending here
    seen[run] = seen.get(run, 0) + 1
  1. Prefix identity. With pre[0] = 0 and pre[i+1] = pre[i] + nums[i], we have sum(l..r) = pre[r+1] - pre[l].
  2. Fix the end. The subarrays ending at r that sum to k are exactly the l with pre[l] = pre[r+1] - k, l ≤ r.
  3. Count, do not search. The map holds how many of pre[0..r] took each value, so one lookup gives that number.
  4. Seed with {0: 1}. pre[0] = 0 is the empty prefix; without it, subarrays that start at index 0 are missed.
  5. Look up before you insert. Inserting pre[r+1] first would pair it with itself when k = 0 and count an empty subarray.
O(n)time (average, hashing)
O(n)space (distinct prefixes)

Why it works: every subarray has exactly one right end r and one left end l, and it is counted exactly once: at step r, through the entry for pre[l], which was inserted at an earlier step and never removed. Pairs (l, r) with pre[r+1] - pre[l] = k are in one-to-one correspondence with the answers, and the map counts those pairs. This is Two Sum on the prefix array, counting all pairs instead of returning one.
