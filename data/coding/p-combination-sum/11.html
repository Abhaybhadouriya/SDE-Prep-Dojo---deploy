Now each candidate may be used only once and the array may contain duplicates (LC 40).

Sort, recurse with i + 1, and in the loop skip c[i] when i > start && c[i] == c[i - 1]: at one tree level, the same value must start only one branch. Equal values in deeper levels are still allowed, so [1,1,6] survives.

How to answer

Two changes, one per new rule: i + 1 for "use once", the same-level skip for "duplicates in the input".

Likely follow-ups
  • Why i > start and not i > 0? (i > 0 would also forbid using the second copy deeper down.)
Only return the number of combinations.

That is Coin Change II: ways[0] = 1; for each value c (outer loop), for s from c to T, ways[s] += ways[s - c]. O(n · T) time, O(T) space. Values in the outer loop means each multiset is counted once, in one canonical order: the DP version of the start index.

How to answer

Draw the link: start index in backtracking = value-outer loop order in the DP.

Likely follow-ups
  • Swap the loops? (Then you count ordered sequences: LC 377.)
Return only the combinations with the fewest numbers.

Fewest coins is a shortest-path / DP problem (Coin Change, LC 322) for the count; to list all minimal combinations, first compute the minimum k with DP, then backtrack with a depth limit of k, pruning any branch where pick.size() + ceil(left / maxValue) > k.

How to answer

Separate "find the optimum" (DP) from "list optimal solutions" (bounded search).

Likely follow-ups
  • Could BFS do it? (Yes, BFS by number of coins finds the minimum level first.)
Target is up to 109 but values are large too. What breaks?

The DP table of size T is no longer possible and the depth T/min can be huge. The backtracking still works if the number of answers is small, because the break pruning keeps it output-sensitive, but recursion depth may need an explicit stack. Also use 64-bit sums if values are big.

How to answer

Name which resource scales with which parameter: DP with T, depth with T/min, work with the output size.

Likely follow-ups
  • Convert the recursion to an explicit stack of (start, left) frames.
Why is "break" safe here and "continue" needed elsewhere?

After sorting, the values from i on are all ≥ c[i]; if c[i] > left, none of them fits, so stop the loop. If the array is not sorted, or the condition is not monotone (for example "skip duplicates"), only continue is correct.

How to answer

Tie break to monotonicity of the condition along the loop.

Likely follow-ups
  • What does the sort cost relative to the search? (O(n log n), negligible.)
