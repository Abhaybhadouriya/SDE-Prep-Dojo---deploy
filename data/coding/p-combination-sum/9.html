  • Cue: list ALL combinations hitting a target; values reusable; order irrelevant.
  • Insight: next choice from index ≥ start, so each multiset is built once, in sorted order.
  • State: dfs(start, left), shared pick; recurse with i (reuse), pop after.
  • Trap: loop from 0 (permutations); i + 1 (no reuse); not copying pick; break unsorted.
  • Cost: exponential, ~n^(T/min), depth T/min; count-only version = unbounded-knapsack DP.
def dfs(start, left):
    if left == 0: out.append(pick[:]); return
    for i in range(start, len(c)):          # c sorted
        if c[i] > left: break
        pick.append(c[i]); dfs(i, left - c[i]); pick.pop()   # i: reuse; i+1: use once

What single change turns this solution into "each candidate at most once"?

  1. Loop from 0
  2. Recurse with i + 1
  3. Remove the sort
i + 1 moves past the value after using it once.

Why does the loop start at start instead of 0?

  1. To build each multiset in one non-decreasing order, avoiding duplicates
  2. To make the recursion shallower
  3. Because the problem forbids reuse
Looking back would generate the same multiset in other orders.

Interviewer: "only return how many combinations". Best approach?

  1. The same backtracking, counting leaves
  2. Sort and binary search
  3. Unbounded-knapsack DP: ways[s] += ways[s - c] with the value loop outside
Counting does not need the lists: O(n · T) DP, values outer loop so each multiset counts once.
