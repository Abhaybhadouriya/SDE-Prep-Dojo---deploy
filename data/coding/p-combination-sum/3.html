Recognise the pattern

When you see "return all combinations / subsets / arrangements" with small inputs, think backtracking: choose, recurse, un-choose.

When you see "order does not matter" in the output, think a start index: the next choice comes from index ≥ the last one, so each set is generated in one canonical (sorted) order.

When you see "each element unlimited times" vs "each at most once", think recurse with i vs i + 1; that one character is the difference between LC 39 and LC 40.

If the question only asked how many combinations, it would be a counting DP (unbounded knapsack, like Coin Change II). Because it asks for the lists themselves, the answer can be exponential in size and you must enumerate.

Taxonomy: Backtracking → combinations & combination sum → combination sum family. Pattern lesson: Backtracking.
