Technique: backtracking over "which element next", with a forward-only start index to make results unordered; the recursion index (i or i + 1) and a skip-duplicates rule select the variant.

Closest match: GfG Combination Sum (Target Sum Combinations)

  • Same: unlimited reuse, unordered combinations hitting a target.
  • Different: the input may contain duplicates and the output must be sorted.
  • So: sort and remove duplicate values first, then the same DFS (it already emits sorted lists in sorted order).

How to recognise it:

  • "Return all ..." with inputs around 20-30: backtracking.
  • "Unique combinations" / "order does not matter": start index; "may reuse": recurse with i.
  • "How many ways": switch to DP.

Practice order:

  1. Warm-up: LC 78 Subsets and LC 77 Combinations.
  2. This problem, then LC 40 (duplicates, use once) and LC 216 (fixed size).
  3. Then LC 518 and LC 377 to see the counting DP versions and why their loop order differs.
