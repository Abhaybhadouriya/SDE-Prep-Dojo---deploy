Interview follow-ups

Prove that the two-pointer version never needs the exact maximum of the other side.

The pointer that moves is on the lower bar. A bar at least as tall as everything already passed on the moving side exists on the other side, so the other side's max is at least the moving side's max, and the min is the moving side's max.

How to answer

State the invariant in one line, then point at one step of a dry run where leftMax > rightMax and show the answer is still right (step 6 above).

Likely follow-ups
  • What happens on ties? (Either side is safe; the code moves the right.)
Return how much water sits over each column, not the total.

Same loop, but write out[l] = leftMax - height[l] (or out[r]) instead of adding. Still O(n) time; the output array is O(n) by necessity.

How to answer

Point out each column is settled exactly once, so the per-column value is final when written.

Likely follow-ups
  • Return the pools (ranges of contiguous water) instead.
Heights arrive as a stream. Can you report the water so far?

Two pointers need the right end, so they do not stream. The monotonic stack does: each new bar closes the layers it is taller than, and that water is final (no future bar can drain it). Water above the current top of the stack is still open; it becomes final only when a taller bar arrives.

How to answer

Separate "final" from "pending" water; the stack holds the pending walls in decreasing order.

Likely follow-ups
  • Memory if the stream is a long descending run? (O(n) stack in the worst case.)
Now the map is 2D (a height grid). How does it change?

That is LC 407. Push all border cells into a min-heap; pop the lowest, look at its unvisited neighbours, add max(0, level - h) where level is the max height on the pop path, push them with height max(h, level). O(mn log(mn)).

How to answer

Say "the lowest boundary is the limit", the same rule as the lower pointer in 1D.

Likely follow-ups
  • Why does a plain BFS without a heap give wrong answers?
Bars can be 109 high and n is 106. What breaks?

The total can reach about 1015, so use long / int64 for the sum. The per-column difference still fits in 32 bits. Time is still O(n).

How to answer

Do the bound arithmetic out loud: n times max height.

Likely follow-ups
  • Bars of different widths? (Multiply each column's water by its width.)
