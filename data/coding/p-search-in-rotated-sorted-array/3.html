Recognise the pattern

When you see "sorted, then rotated" + "O(log n)", think binary search where each step first finds which half is sorted. The same split works for the minimum (LC 153) and the rotation count. If values can repeat, expect a worst case of O(n).

Try a few midpoints in [40,45,51,58,63,70,2,9,17,24,33] (lo = 0, hi = 10):

midnums[lo] <= nums[mid]?Sorted halfHolds the drop
3 (58)40 <= 58 ✓[0..3] = 40..58[3..10]
5 (70)40 <= 70 ✓[0..5] = 40..70[5..10]
7 (9)40 <= 9 ✗[7..10] = 9..33[0..7]

Always exactly one half is guaranteed sorted.
