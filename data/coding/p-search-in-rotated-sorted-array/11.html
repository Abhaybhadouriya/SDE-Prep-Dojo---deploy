Interview follow-ups

Now values can repeat. What changes and what is the new complexity?

If nums[lo] == nums[mid] (and equal to nums[hi]) you cannot tell which half is sorted, e.g. [3,3,3,1,3] vs [3,1,3,3,3]. Skip one end (lo++) and loop. The worst case becomes O(n) for an array like [3,3,...,3,1,3,...,3], and no algorithm can beat that in the comparison model.

How to answer

Show the two arrays that look the same at lo, mid, hi; that proves the lower bound.

Likely follow-ups
  • Return the first index of the target when duplicates exist.
Return how many times the sorted array was rotated.

That is the index of the minimum: binary search with nums[mid] > nums[hi] ? lo = mid + 1 : hi = mid, ending with lo = rotation count. Comparing with hi (not lo) avoids the "not rotated" special case.

How to answer

Explain why comparing with nums[hi] is safer than with nums[lo].

Likely follow-ups
  • Find the maximum instead (index of minimum - 1, mod n).
Write it recursively and say what it costs.

Same branch logic, recursing on (lo, mid - 1) or (mid + 1, hi). Time stays O(log n); the stack adds O(log n) space. It is tail recursion, so the loop is the natural form in C/Java/Go.

How to answer

Code the iterative version and mention the stack cost of the recursive one.

Likely follow-ups
  • How would a compiler turn this into the loop?
Return the target's index in the original array, before the rotation.

Find the rotation rot (index of the minimum) with rung 2's first loop. The element at rotated index i came from original index (i - rot + n) % n. Or search directly in "original" coordinates and map each probe with (m + rot) % n; the answer is then m itself.

How to answer

Check the mapping on one tiny example, e.g. [40,45,2,9], rot = 2: index 0 (40) came from original index 2.

Likely follow-ups
  • Rotate the array back in place in O(n) time, O(1) space (three reversals).
Why use mid = lo + (hi - lo) / 2?

With 32-bit ints, lo + hi can overflow when both are above 230. Here n <= 5000, so it cannot, but the safe form costs nothing and is the habit interviewers look for (the bug sat in Java's own binary search for years).

How to answer

Give the overflow bound in one line.

Likely follow-ups
  • Python has no overflow; why is the habit still useful there?
