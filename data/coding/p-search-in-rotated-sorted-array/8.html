Common mistakes

nums[lo] < nums[mid] instead of <=. When lo == mid the left half is one cell and sorted; with < the code treats the right half as sorted and fails on [30,10], target 10.

Testing the unsorted half. Checks like target > nums[mid] alone go wrong when the drop is on that side. Only use range checks on the half you proved sorted.

Mixing loop styles. With while lo < hi and hi = mid - 1, the last remaining cell is never probed, so [8], target 8 returns -1. Use lo <= hi with mid ± 1 (as here), or lo < hi with hi = mid plus a final check.

Using this on arrays with duplicates. With [3,1,3,3,3], nums[lo] == nums[mid] does not tell which half is sorted. LC 81 adds "if nums[lo] == nums[mid], lo++", which makes the worst case O(n).
