Common mistakes

  • Fenwick index 0. 0 & -0 is 0, so i += i & -i loops forever at i = 0. Keep the tree 1-based inside and shift by one in add.
  • Update = set, but Fenwick only adds. For update(i, val) add the difference val - a[i], and keep a copy of a[] to know a[i].
  • Forgetting to compress. A Fenwick tree sized by value with values up to 109, or negative values used as indices.
  • Query before insert, in the right direction. In Count Smaller After Self you walk from the right and query before adding the current value; otherwise it counts itself (with duplicates, that is a wrong answer, not just an off-by-one).
  • Wrong identity in a segment tree. 0 for min gives a minimum of 0 for ranges of positive numbers.
  • Inclusive vs half-open. The iterative query works on [l, r); convert with r + 1 once, at the top. My Calendar intervals are half-open: [10, 20) and [20, 30) do not overlap.
  • C++ floor with lower_bound. lower_bound is ceiling. Floor is prev(upper_bound(x)), and only if that iterator is not begin().
  • 32-bit overflow. Sums of 105 values of 109: use 64-bit in the tree.
  • Reaching for a segment tree too early. If n is 1,000, or the array never changes, a simpler answer is better and safer to write.
