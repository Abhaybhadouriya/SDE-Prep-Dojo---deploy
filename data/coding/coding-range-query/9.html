How to recognise a range query problem

When you see "queries and updates interleaved", "after each insertion report ...", or "count pairs i < j where a value condition holds", think Fenwick or segment tree. When you see bookings, intervals or timestamps arriving one by one, think ordered map with floor and ceiling.

  • update(i, val) + sumRange(l, r) as a class to design: Fenwick tree.
  • "number of smaller / larger elements to the right / left": Fenwick over compressed values, walk in one direction.
  • Range min / max with updates, or "first position where value >= x": segment tree.
  • "Add v to every element in [l, r]" many times, then read: difference array; if reads are interleaved, Fenwick on the difference array.
  • "Book [start, end) if free", "merge into disjoint intervals", "value at time t": ordered map / binary search on sorted keys.
  • DP whose transition is "best over a range of previous values" (LIS with a gap limit): segment tree over values.

Not this pattern: a static array (prefix sums are simpler), a fixed-size sliding window max (monotonic deque, O(n)), top-k (heap), and interval problems where everything is given up front (sort and sweep, see intervals).
