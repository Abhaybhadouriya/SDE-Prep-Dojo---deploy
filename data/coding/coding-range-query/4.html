The segment tree

A segment tree is a binary tree over the array. The root covers the whole array, each node's two children cover its left and right halves, and the leaves are single cells. Each node stores op of its range: the sum, the minimum, the maximum, the gcd. Any associative operation works (one where (a op b) op c = a op (b op c)), because a range answer is just op over a few nodes that tile it.

The mental model for a query on [l, r] starts at the root and asks every node one of three questions:

  • Outside (the node's range does not touch [l, r]): return the identity (0 for sum, +infinity for min).
  • Fully inside: return the stored value without going deeper.
  • Partial: ask both children and combine.

At most two nodes per level are partial, so a query visits O(log n) nodes. A point update changes one leaf and recomputes its ancestors: also O(log n).

The iterative version you can write in five minutes

For interviews, the bottom-up (iterative) segment tree is shorter and has fewer off-by-one traps than the recursive one. Store it in an array of size 2n: leaves at t[n..2n-1] (so a[i] is t[i + n]), and each parent at t[i] = op(t[2i], t[2i+1]). A query uses a half-open range [l, r) and two pointers that climb toward the root:

  • If l is odd, it is a right child, so its parent would also include something to the left of the range: take t[l] and step right (l++).
  • If r is odd, the node r - 1 is a left child sticking out on the right: step left (r--) and take t[r].
  • Then both go up a level (l /= 2; r /= 2) until they meet.

Watch it answer a[1..5] on the same eight values, then do a point update:

  1. Query the sum of a[1..5]. Leaves live at t[n..2n-1], so a[i] is t[i + n]. Set l = 9 and r = 14: the half-open range [l, r) of leaves t[9]..t[13].
  2. l = 9 is odd (a right child): take t[9] = 2 (a[1..1]), l++. r = 14 is even: take nothing. Sum so far 2. Both pointers move up one level: l = 5, r = 7.
  3. l = 5 is odd (a right child): take t[5] = 6 (a[2..3]), l++. r is odd: r-- to 6, take t[6] = 25 (a[4..5]). Sum so far 33. Both pointers move up one level: l = 3, r = 3.
  4. l and r met, so we stop. The answer 33 came from 3 nodes. At most two nodes are taken per level, so a query is O(log n).
  5. Point update a[3] = 7: write leaf t[11], then walk up with i /= 2 and recompute each parent from its two children: t[5], t[2], t[1]. log2(8) = 3 parents.
class SegTree:                       # leaves at t[n..2n-1]; op must be associative
    def __init__(self, nums, op=lambda a, b: a + b, identity=0):
        self.n, self.op, self.id = len(nums), op, identity
        self.t = [identity] * self.n + list(nums)
        for i in range(self.n - 1, 0, -1):
            self.t[i] = op(self.t[2 * i], self.t[2 * i + 1])
    def set(self, i, val):            # a[i] = val
        i += self.n
        self.t[i] = val
        while i > 1:
            i //= 2
            self.t[i] = self.op(self.t[2 * i], self.t[2 * i + 1])
    def query(self, l, r):            # op over a[l..r], both included
        res_l = res_r = self.id
        l, r = l + self.n, r + self.n + 1
        while l < r:
            if l & 1: res_l = self.op(res_l, self.t[l]); l += 1
            if r & 1: r -= 1; res_r = self.op(self.t[r], res_r)
            l //= 2; r //= 2
        return self.op(res_l, res_r)

Three details that make it correct for every n, not only powers of two:

  1. Size 2n, not 4n. The bottom-up layout needs exactly 2n slots. (The recursive version needs 4n because its tree is not packed.) When n is not a power of two some internal nodes mix the end of the array with the start; the climbing loop never uses them in a wrong way, which is why the tested code includes an n = 3 case.
  2. Two accumulators. res_l collects from the left and res_r from the right, combined in order at the end. For sum or min it does not matter, but for a non-commutative operation (say "concatenate" or a matrix product) it keeps the order right.
  3. The identity. 0 for sum, +infinity for min, -infinity for max, 0 for gcd. A wrong identity silently corrupts every answer.

Common segment-tree jobs in interviews: range min or max with updates; Longest Increasing Subsequence II, where a tree over values stores the best LIS ending at each value and you query the max over [v - k, v - 1]; and "first index whose value is at least x", where each node stores the max and you walk down to the leftmost child that is big enough (Booking Concert Tickets in Groups).
