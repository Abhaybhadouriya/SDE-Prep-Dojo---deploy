Lazy propagation (know the idea, keep it light)

If an update hits a whole range ("add 5 to a[100..90000]"), updating every leaf is O(n). Lazy propagation stops at the O(log n) nodes that are fully inside the range, updates their stored value, and leaves a note (a tag) saying "my children still owe +5". The note is handed down only when a later query or update needs to go below that node.

class LazySeg:                       # range add, range sum (recursive, 4n slots)
    def __init__(self, n):
        self.n, self.sum, self.tag = n, [0] * (4 * n), [0] * (4 * n)
    def _apply(self, x, lo, hi, v):   # add v to every cell of node x
        self.sum[x] += v * (hi - lo + 1)
        self.tag[x] += v              # "my children still owe +v"
    def _push(self, x, lo, hi):       # hand the debt to the children
        if self.tag[x]:
            mid = (lo + hi) // 2
            self._apply(2 * x, lo, mid, self.tag[x])
            self._apply(2 * x + 1, mid + 1, hi, self.tag[x])
            self.tag[x] = 0
    def add(self, l, r, v, x=1, lo=0, hi=None):
        hi = self.n - 1 if hi is None else hi
        if r < lo or hi < l: return                 # outside
        if l <= lo and hi <= r:                     # inside: tag and stop
            self._apply(x, lo, hi, v); return
        self._push(x, lo, hi)                       # partial: split
        mid = (lo + hi) // 2
        self.add(l, r, v, 2 * x, lo, mid)
        self.add(l, r, v, 2 * x + 1, mid + 1, hi)
        self.sum[x] = self.sum[2 * x] + self.sum[2 * x + 1]
    def query(self, l, r, x=1, lo=0, hi=None):
        hi = self.n - 1 if hi is None else hi
        if r < lo or hi < l: return 0
        if l <= lo and hi <= r: return self.sum[x]
        self._push(x, lo, hi)
        mid = (lo + hi) // 2
        return self.query(l, r, 2 * x, lo, mid) + self.query(l, r, 2 * x + 1, mid + 1, hi)

This sketch is Python only; it was checked against a brute-force array on 3,000 random operations. It is here so you recognise the shape, not as a must-memorise template.

At SDE-2/3 level the expected answer to "range update and range query" is usually the design: "segment tree with lazy tags, O(log n) each; tags must compose (add then add = add the sum; assign overrides add)". Many of the LeetCode problems that list "segment tree" have an easier interview answer: Falling Squares has n = 1,000 so O(n²) passes; My Calendar III and Range Module are cleaner with an ordered map. Offer the simple one first, then mention the tree.

From your world

A lazy tag is copy-on-write, or a deferred TLB flush: record that the work is owed at the highest level that covers it, and only do it at the lower level when someone actually touches that part. Same trade: cheap bulk operations, a small "push" cost on the next access.
