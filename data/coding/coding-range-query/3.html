What a Fenwick tree is really used for: counting

Range Sum Query - Mutable is the obvious use, but the interview favourite is different: a Fenwick tree over values that counts how many numbers seen so far fall below some value. That turns many "count pairs i < j with a condition on values" problems into O(n log n).

Count of Smaller Numbers After Self

Count of Smaller Numbers After Self: for every position, report how many values to its right are strictly smaller. Values range from -104 to 104 and n is up to 105. It is a Google favourite in our company data, with Amazon, Microsoft and Meta also listed.

  1. Compress the values. Sort the distinct values and replace each value by its rank 0..m-1. Now the Fenwick tree has size m, whatever the original range (this also handles negatives and 109).
  2. Walk from the right. When you are at i, the tree holds exactly the values after i.
  3. Query, then insert. out[i] = prefix(rank) counts the ranks strictly below; then add(rank, 1).
rank = {v: i for i, v in enumerate(sorted(set(nums)))}
bit = Fenwick(len(rank))
for i in range(len(nums) - 1, -1, -1):
    out[i] = bit.prefix(rank[nums[i]])   # how many smaller values are to my right
    bit.add(rank[nums[i]], 1)

Same shape, different question:

  • Inversions (pairs i < j with a[i] > a[j]): sum of the answers above. The merge sort count from sorting also works; say both.
  • Reverse Pairs (a[i] > 2 · a[j]): compress both a[j] and 2 · a[j]; query "how many seen values are greater than 2x".
  • Count of Range Sum: number of subarrays with sum in [lower, upper]. With prefix sums this is "how many earlier P lie in [P - upper, P - lower]": a Fenwick tree over compressed prefix values, one range count per step.

Two more tricks worth knowing

  • Range add, point query. Store the difference array in the Fenwick tree: add(l, v); add(r + 1, -v), and the value at i is prefix(i + 1). It is the difference array you already know, made dynamic. (Range add with range sum needs two Fenwick trees or a lazy segment tree; mention it, do not write it unless asked.)
  • O(n) build. Copy the values into t, then for each i push t[i] into its parent i + (i & -i). Useful when the interviewer asks "can you build it faster than n log n?".
