Revision card

  • Cue: Range sum or min with point updates, count smaller after self, bookings that must not clash.
  • Insight: Precompute partial answers over power-of-two blocks so query and update both touch O(log n) of them.
  • State: Fenwick t[1..n] (undoable operations) or segment tree (min, max, gcd); ordered map for floor/ceiling.
  • Trap: Fenwick is 1-based; half-open vs closed ranges in the segment tree; using Fenwick for min.
  • Cost: O(log n) per query and update, O(n) space.

More to remember

  • Static array: prefix sums. Changing array: Fenwick or segment tree, O(log n) for both operations.
  • Fenwick: 1-based, t[i] covers lowbit(i) cells ending at i. Query i -= i & -i; update i += i & -i.
  • Fenwick only does undoable operations (range = two prefixes subtracted). Min / max / gcd: segment tree.
  • Counting pairs by value: compress, walk in one direction, query then insert.
  • Iterative segment tree: 2n slots, leaves at n..2n-1, half-open [l, r), take t[l] if l odd, take t[--r] if r odd, climb.
  • Range updates: lazy tags; know the idea, offer simpler answers first.
  • Ordered map: floor and ceiling are the only neighbours that can clash (My Calendar).
  • +1/-1 in an ordered map plus a sweep = a sparse difference array.
