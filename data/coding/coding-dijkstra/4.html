At most K stops: Bellman-Ford by rounds

Cheapest Flights Within K Stops gives directed flights with prices and asks for the cheapest trip from src to dst using at most K intermediate airports, that is, at most K + 1 flights. Plain Dijkstra on cities fails: the cheapest way into a city might use too many stops, and Dijkstra would throw away a pricier route with fewer stops that is the only one that can still reach dst in time.

Bellman-Ford fits this perfectly, because its rounds count edges. After round r, dist[v] is the cheapest cost using at most r edges, provided each round reads the previous round's values. Run K + 1 rounds and read dist[dst].

  1. Round 0 (no edges used yet): only the source has a cost. Row r of this table = cheapest cost using at most r edges.
  2. Round 1: relax every edge once, reading only row 0. P → Q gives Q = 50, P → T gives T = 900. R needs two edges, so it is still infinity.
  3. Round 2: relax every edge reading row 1. Q → R gives R = 100; Q → T gives 50 + 400 = 450, better than 900. With k = 1 stop (2 edges) the answer is 450.
  4. Round 3: R → T gives 100 + 50 = 150. With k = 2 stops the answer is 150. Each extra round allows one more edge, which is exactly one more stop.
  5. The classic bug: update the same array in place. If edges are scanned in the order P → Q, Q → R, R → T, round 1 already chains all three and reports T = 150 for k = 0. That is why every round reads a COPY of the previous row.
// 3. Bellman-Ford limited to k stops (= at most k + 1 edges). -1 = impossible.
func cheapestWithinK(n int, flights [][3]int, src, dst, k int) int {
	const INF = math.MaxInt64
	dist := make([]int, n)
	for i := range dist {
		dist[i] = INF
	}
	dist[src] = 0
	for round := 0; round <= k; round++ {
		next := append([]int(nil), dist...) // relax from LAST round's copy only
		for _, f := range flights {
			if dist[f[0]] == INF {
				continue
			}
			if dist[f[0]]+f[2] < next[f[1]] {
				next[f[1]] = dist[f[0]] + f[2]
			}
		}
		dist = next
	}
	if dist[dst] == INF {
		return -1
	}
	return dist[dst]
}
// 3. Bellman-Ford limited to k stops (= at most k + 1 edges). -1 = impossible.
int cheapestWithinK(int n, const vector<vector<int>>& flights, int src, int dst, int k) {
    const int INF = INT_MAX;
    vector<int> dist(n, INF);
    dist[src] = 0;
    for (int round = 0; round <= k; round++) {
        vector<int> next = dist;              // relax from LAST round's copy only
        for (const auto& f : flights) {
            if (dist[f[0]] == INF) continue;
            if (dist[f[0]] + f[2] < next[f[1]]) next[f[1]] = dist[f[0]] + f[2];
        }
        dist.swap(next);
    }
    return dist[dst] == INF ? -1 : dist[dst];
}
// 3. Bellman-Ford limited to k stops (= at most k + 1 edges). -1 = impossible.
static int cheapestWithinK(int n, int[][] flights, int src, int dst, int k) {
    final int INF = Integer.MAX_VALUE;
    int[] dist = new int[n];
    Arrays.fill(dist, INF);
    dist[src] = 0;
    for (int round = 0; round <= k; round++) {
        int[] next = dist.clone();                 // relax from LAST round's copy only
        for (int[] f : flights) {
            if (dist[f[0]] == INF) continue;
            if (dist[f[0]] + f[2] < next[f[1]]) next[f[1]] = dist[f[0]] + f[2];
        }
        dist = next;
    }
    return dist[dst] == INF ? -1 : dist[dst];
}
# 3. Bellman-Ford limited to k stops (= at most k + 1 edges). -1 = impossible.
def cheapest_within_k(n, flights, src, dst, k):
    INF = float('inf')
    dist = [INF] * n
    dist[src] = 0
    for _ in range(k + 1):
        nxt = dist[:]                     # relax from LAST round's copy only
        for u, v, w in flights:
            if dist[u] + w < nxt[v]:
                nxt[v] = dist[u] + w
        dist = nxt
    return -1 if dist[dst] == INF else dist[dst]

Time O(K x E), space O(V). Two other answers are fine: BFS by level (each level is one more flight; keep the best price per city and only push improvements, which is the same rounds idea with a queue), or Dijkstra on (city, stops) states, which must not discard a state just because the city was seen cheaper with more stops.

General Bellman-Ford and negative cycles

Without a stop limit, run V - 1 rounds (in-place updates are fine here, they only speed convergence). If a V-th round still improves something, the graph has a negative cycle reachable from the source: you could loop forever and keep getting cheaper, so "shortest" is undefined. That detection is the main reason to know Bellman-Ford outside the K-stops problem; currency arbitrage (log of exchange rates) is the textbook story.

RIP routers do these rounds in parallel: every 30 seconds each router relaxes its table using its neighbours' tables. RFC 2453 defines a metric of 16 as infinity, so a route can be at most 15 hops long. That bound exists for the same reason as K here: it caps the rounds, and it ends count-to-infinity loops when a link fails.
