Variants: change the cost, change the state

Most "hard" Dijkstra questions are the template with one of three twists. Spot the twist and the code changes by one or two lines.

Twist 1: the cost of a path is not a sum

In Path With Minimum Effort, you walk a grid of heights and a route is as bad as its single steepest step. In Swim in Rising Water, a route is as bad as its highest cell. Both ask you to minimise a maximum. Dijkstra still works, with max(d, w) in place of d + w.

The general rule: Dijkstra is correct whenever extending a path can never make it cheaper. Plus with non-negative weights has this property; so do max, and multiplication by probabilities in [0, 1] when you maximise (Path with Maximum Probability uses a max-heap and d * p).

// 2. Minimax Dijkstra on a grid: a path costs its LARGEST step.
// Reuses minHeap from template 1; the vertex is encoded as r*C + c.
func minimumEffortPath(h [][]int) int {
	R, C := len(h), len(h[0])
	best := make([]int, R*C)
	for i := range best {
		best[i] = math.MaxInt64
	}
	best[0] = 0
	pq := &minHeap{{0, 0}}
	dirs := [4][2]int{{1, 0}, {-1, 0}, {0, 1}, {0, -1}}
	for pq.Len() > 0 {
		top := heap.Pop(pq).(item)
		if top.d > best[top.u] {
			continue // stale
		}
		r, c := top.u/C, top.u%C
		if r == R-1 && c == C-1 {
			return top.d // first pop of the target is final
		}
		for _, d := range dirs {
			nr, nc := r+d[0], c+d[1]
			if nr < 0 || nr >= R || nc < 0 || nc >= C {
				continue
			}
			step := h[nr][nc] - h[r][c]
			if step < 0 {
				step = -step
			}
			ne := top.d
			if step > ne {
				ne = step // max instead of +
			}
			if ne < best[nr*C+nc] {
				best[nr*C+nc] = ne
				heap.Push(pq, item{ne, nr*C + nc})
			}
		}
	}
	return 0
}
// 2. Minimax Dijkstra on a grid: a path costs its LARGEST step (Path With Minimum Effort).
int minimumEffortPath(const vector<vector<int>>& h) {
    int R = h.size(), C = h[0].size();
    vector<vector<int>> best(R, vector<int>(C, INT_MAX));
    typedef array<int,3> Item;                              // {effort so far, r, c}
    priority_queue<Item, vector<Item>, greater<Item>> pq;
    best[0][0] = 0;
    pq.push(Item{{0, 0, 0}});
    const int dr[] = {1, -1, 0, 0}, dc[] = {0, 0, 1, -1};
    while (!pq.empty()) {
        Item t = pq.top(); pq.pop();
        int e = t[0], r = t[1], c = t[2];
        if (e > best[r][c]) continue;                       // stale
        if (r == R - 1 && c == C - 1) return e;             // first pop of the target is final
        for (int k = 0; k < 4; k++) {
            int nr = r + dr[k], nc = c + dc[k];
            if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
            int ne = max(e, abs(h[nr][nc] - h[r][c]));       // max instead of +
            if (ne < best[nr][nc]) { best[nr][nc] = ne; pq.push(Item{{ne, nr, nc}}); }
        }
    }
    return 0;
}

static int minimumEffortPath(int[][] h) {
    int R = h.length, C = h[0].length;
    int[][] best = new int[R][C];
    for (int[] row : best) Arrays.fill(row, Integer.MAX_VALUE);
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0])); // {effort, r, c}
    best[0][0] = 0;
    pq.add(new int[]{0, 0, 0});
    int[][] dirs = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
    while (!pq.isEmpty()) {
        int[] t = pq.poll();
        int e = t[0], r = t[1], c = t[2];
        if (e > best[r][c]) continue;              // stale
        if (r == R - 1 && c == C - 1) return e;    // first pop of the target is final
        for (int[] d : dirs) {
            int nr = r + d[0], nc = c + d[1];
            if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
            int ne = Math.max(e, Math.abs(h[nr][nc] - h[r][c]));   // max instead of +
            if (ne < best[nr][nc]) { best[nr][nc] = ne; pq.add(new int[]{ne, nr, nc}); }
        }
    }
    return 0;
}
# 2. Minimax Dijkstra on a grid: a path costs its LARGEST step.
def minimum_effort_path(h):
    R, C = len(h), len(h[0])
    best = [[float('inf')] * C for _ in range(R)]
    best[0][0] = 0
    pq = [(0, 0, 0)]                      # (effort so far, r, c)
    while pq:
        e, r, c = heapq.heappop(pq)
        if e > best[r][c]:
            continue                      # stale
        if (r, c) == (R - 1, C - 1):
            return e                      # first pop of the target is final
        for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
            if 0 <= nr < R and 0 <= nc < C:
                ne = max(e, abs(h[nr][nc] - h[r][c]))   # max instead of +
                if ne < best[nr][nc]:
                    best[nr][nc] = ne
                    heapq.heappush(pq, (ne, nr, nc))
    return 0

Minimax problems have two other correct answers, and naming them earns credit. Binary search on the answer: "can I get through with effort at most X?" is a plain BFS that only uses steps ≤ X, and the answer is monotone in X, so binary search X; O(RC log(maxHeight)). Union-find: sort all edges by weight and add them one by one until the start and the target join; the last weight added is the answer. That second one is Kruskal's MST idea, and the MST deep dive explains why it works.

Twist 2: count or compare shortest paths

Number of Ways to Arrive at Destination asks how many different shortest routes exist. Keep ways[v] next to dist[v]. When relaxing gives a strictly smaller distance, set ways[v] = ways[u]; when it gives an equal distance, add ways[v] += ways[u] (mod 109+7). This is correct because vertices are settled in order of distance, so ways[u] is final before u is used. Use 64-bit distances: the sums overflow 32 bits.

Related: Find Edges in Shortest Paths runs Dijkstra from both ends; edge (u, v, w) lies on some shortest path exactly when distS[u] + w + distT[v] == distS[target] (or the same with u and v swapped). Minimum Weighted Subgraph With the Required Paths runs three Dijkstras (from both sources forward and from the destination on the reversed graph) and tries every meeting vertex.

Twist 3: the vertex alone is not enough state

If two arrivals at the same vertex can have different futures, the vertex is not the state. Minimum Cost to Reach Destination in Time has a time budget: arriving cheaper but later may be useless. The fix is to run Dijkstra on pairs (vertex, extra): (city, time used), (cell, obstacles removed), (node, stops used). The graph gets bigger, the template does not change. The constraint on extra tells you whether the bigger graph fits.

Special weights: 0-1 BFS

When every weight is 0 or 1 (Minimum Obstacle Removal to Reach Corner, Minimum Cost to Make at Least One Valid Path in a Grid), use a deque instead of a heap: push 0-weight neighbours to the front and 1-weight neighbours to the back. The deque stays sorted by distance, so it is Dijkstra without the log factor, O(V + E).

from collections import deque

def zero_one_bfs(n, adj, src):          # adj[u] = [(v, w)], w in {0, 1}
    dist = [float('inf')] * n
    dist[src] = 0
    dq = deque([src])
    while dq:
        u = dq.popleft()
        for v, w in adj[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                if w == 0: dq.appendleft(v)
                else:      dq.append(v)
    return dist
