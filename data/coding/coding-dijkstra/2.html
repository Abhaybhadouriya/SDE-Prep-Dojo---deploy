Dijkstra with a heap and the stale-entry check

Dijkstra keeps a min-heap (priority queue) of (distance, vertex) pairs. The loop is short:

  1. Pop the cheapest entry (d, u).
  2. Skip it if it is stale: if d > dist[u], a cheaper entry for u was already popped, so this one is old news.
  3. Otherwise u is settled. Relax every edge out of u; each time a distance improves, push the new pair.

Why can a vertex appear in the heap more than once? Textbook Dijkstra uses a "decrease-key" operation to lower a vertex's priority in place. The heaps in Python, Java and C++ do not have one. The standard interview answer is the lazy version: push a duplicate with the better distance and ignore the old copy when it surfaces. Watch it happen to vertex A below.

  1. Start: dist[S] = 0, every other distance is infinity, and the heap holds one entry (0, S).
  2. Pop (0, S), the cheapest entry. S is now final. Relax its edges: A gets 0 + 4 = 4, B gets 0 + 1 = 1. Push both.
  3. Pop (1, B). B is final at 1. Relax B → A: 1 + 2 = 3 beats 4, so A improves to 3 and (3, A) is pushed. The old (4, A) stays in the heap: it is now stale. B → C gives C = 6.
  4. Pop (3, A). A is final at 3. Relax A → C: 3 + 1 = 4 beats 6, so C improves and (4, C) is pushed. Now (6, C) is stale too.
  5. Pop (4, A). But dist[A] is 3, and 4 > 3: this is the stale entry. Skip it without relaxing anything. This one if-statement is the whole trick of lazy Dijkstra.
  6. Pop (4, C). C is final at 4. Relax C → D: D = 7, push (7, D).
  7. Pop (6, C): stale, skip. Pop (7, D): final. The heap is empty. The thick edges are the shortest-path tree: S → B → A → C → D. Store parent[v] when you improve v to rebuild it.

Why the first pop is final

Suppose u is popped with distance d, the smallest key in the heap. Any other route to u must leave the settled region through some vertex x that is still in the heap with dist[x] ≥ d. Every edge after that adds a weight ≥ 0, so that route costs at least d. Nothing can beat d, so it is final. Notice exactly where "non-negative" was used: that is why Dijkstra breaks with negative edges.

// 1. Dijkstra with a min-heap and the stale-entry check.
// Needs: container/heap, math. edges {u, v, w} directed, w >= 0. math.MaxInt64 = unreachable.
type item struct{ d, u int }
type minHeap []item

func (h minHeap) Len() int            { return len(h) }
func (h minHeap) Less(i, j int) bool  { return h[i].d < h[j].d }
func (h minHeap) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *minHeap) Push(x interface{}) { *h = append(*h, x.(item)) }
func (h *minHeap) Pop() interface{} {
	old := *h
	x := old[len(old)-1]
	*h = old[:len(old)-1]
	return x
}

func dijkstra(n int, edges [][3]int, src int) []int {
	type arc struct{ v, w int }
	adj := make([][]arc, n)
	for _, e := range edges {
		adj[e[0]] = append(adj[e[0]], arc{e[1], e[2]})
	}
	dist := make([]int, n)
	for i := range dist {
		dist[i] = math.MaxInt64
	}
	dist[src] = 0
	h := &minHeap{{0, src}}
	for h.Len() > 0 {
		top := heap.Pop(h).(item)
		if top.d > dist[top.u] {
			continue // stale entry: u was settled cheaper already
		}
		for _, a := range adj[top.u] {
			if nd := top.d + a.w; nd < dist[a.v] {
				dist[a.v] = nd
				heap.Push(h, item{nd, a.v})
			}
		}
	}
	return dist
}
// 1. Dijkstra with a min-heap and the stale-entry check.
// n vertices 0..n-1, edges {u, v, w} directed, w >= 0. LLONG_MAX = unreachable.
vector<long long> dijkstra(int n, const vector<vector<int>>& edges, int src) {
    vector<vector<pair<int,int>>> adj(n);
    for (const auto& e : edges) adj[e[0]].push_back({e[1], e[2]});
    vector<long long> dist(n, LLONG_MAX);
    typedef pair<long long,int> Item;                       // {distance, vertex}
    priority_queue<Item, vector<Item>, greater<Item>> pq;   // min-heap
    dist[src] = 0;
    pq.push({0, src});
    while (!pq.empty()) {
        long long d = pq.top().first; int u = pq.top().second; pq.pop();
        if (d > dist[u]) continue;            // stale entry: u was settled cheaper already
        for (const auto& a : adj[u]) {
            int v = a.first; long long nd = d + a.second;
            if (nd < dist[v]) { dist[v] = nd; pq.push({nd, v}); }
        }
    }
    return dist;
}
// 1. Dijkstra with a min-heap and the stale-entry check.
// edges {u, v, w} directed, w >= 0. Long.MAX_VALUE = unreachable.
static long[] dijkstra(int n, int[][] edges, int src) {
    List<List<int[]>> adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    for (int[] e : edges) adj.get(e[0]).add(new int[]{e[1], e[2]});
    long[] dist = new long[n];
    Arrays.fill(dist, Long.MAX_VALUE);
    PriorityQueue<long[]> pq = new PriorityQueue<>((a, b) -> Long.compare(a[0], b[0]));
    dist[src] = 0;
    pq.add(new long[]{0, src});
    while (!pq.isEmpty()) {
        long[] top = pq.poll();
        long d = top[0];
        int u = (int) top[1];
        if (d > dist[u]) continue;                 // stale entry
        for (int[] a : adj.get(u)) {
            long nd = d + a[1];
            if (nd < dist[a[0]]) { dist[a[0]] = nd; pq.add(new long[]{nd, a[0]}); }
        }
    }
    return dist;
}
import heapq

# 1. Dijkstra with a min-heap and the stale-entry check.
def dijkstra(n, edges, src):
    """edges: (u, v, w) directed, w >= 0. Returns distances, inf = unreachable."""
    adj = [[] for _ in range(n)]
    for u, v, w in edges:
        adj[u].append((v, w))
    dist = [float('inf')] * n
    dist[src] = 0
    pq = [(0, src)]                       # (distance, vertex)
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue                      # stale entry: u was settled cheaper already
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

Cost. Every edge can push at most one entry, so the heap holds at most E entries and each push or pop costs O(log E) = O(log V). Total O((V + E) log V) time and O(V + E) space. On a dense graph (E close to V2) the old array version, which scans all vertices for the minimum instead of using a heap, is O(V2) and actually faster.

From your world

"Always process the smallest key next" is how the kernel picks work too: CFS keeps runnable tasks in a red-black tree ordered by virtual runtime and always runs the leftmost one, and hrtimers sit in a time-ordered tree so the earliest expiry fires first. A Dijkstra heap is the same idea with "distance from the source" as the key.

Early exit. If the question asks about one target only (Path With Minimum Effort, Swim in Rising Water), return the moment the target is popped, not when it is first pushed. A pushed distance can still improve; a popped one cannot.
