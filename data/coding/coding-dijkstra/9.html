Common mistakes

  • No stale check. The answer stays correct, but a vertex can be expanded many times and dense inputs time out. One line: if d > dist[u]: continue.
  • Using a visited set marked on push. That is the BFS habit. In Dijkstra a pushed distance can still improve; only a pop is final.
  • Returning when the target is pushed instead of popped. Same reason.
  • Dijkstra with negative weights. Check the constraints. Negative weights mean Bellman-Ford (or a reweighting trick you will not be asked to code).
  • In-place updates in K-stops Bellman-Ford. Chains several edges in one round; always relax from a copy.
  • Off-by-one on stops. K stops = K + 1 edges = K + 1 rounds.
  • Overflow. INT_MAX + w wraps negative in C++ and Java. Skip infinite sources before adding, use 64-bit sums, and use INF / 4 in Floyd.
  • Wrong loop order in Floyd. The intermediate k goes outermost.
  • Building edges in only one direction for an undirected graph (roads, cables): add both.
  • Heap of the wrong kind. Java's PriorityQueue and Python's heapq are min-heaps; C++ priority_queue is a max-heap unless you pass greater.
