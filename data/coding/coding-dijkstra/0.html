The story: fuses that burn at the same speed

Explain like I'm 5

Lay out fuses on the floor between towns. A long fuse is a long road. Light the fuse at your home town. Fire spreads along every fuse at the same speed. When the fire reaches a town for the first time, it came the quickest way, because any other way is still burning somewhere behind it. Dijkstra's algorithm is a careful way to simulate this fire without waiting: always jump to the town the fire will reach next.

A weighted graph gives every edge a number: distance, time, price, latency, risk. The shortest path from a source s to a vertex v is the path with the smallest total weight. Three algorithms cover almost every interview question about it:

  • Dijkstra: one source, weights that are never negative. The workhorse. O(E log V).
  • Bellman-Ford: one source, negative weights allowed, or a limit on the number of edges. O(V x E).
  • Floyd-Warshall: every pair of vertices at once, small graphs. O(V3).

From your world

You already run all three. An OSPF or IS-IS router floods link-state adverts so every router holds the whole weighted topology, then runs an SPF calculation, which is Dijkstra from itself, to fill the routing table (RFC 2328, section 16). RIP is distributed Bellman-Ford: each router repeatedly relaxes "my cost to X = neighbour's cost to X + link cost", and its 15-hop limit is exactly the "at most K edges" variant below. A precomputed all-pairs latency matrix in a controller is Floyd-Warshall territory.
