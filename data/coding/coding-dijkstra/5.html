All pairs: Floyd-Warshall

Some questions need the distance between every pair: "which city has the fewest neighbours within distance T", "answer many queries of a/b", "is course a a prerequisite of course b". When V is small (up to about 400; 4003 is 64 million simple steps), Floyd-Warshall is three nested loops over a V x V matrix.

The idea is dynamic programming over the intermediate vertex. After the outer loop has handled k = 0..m, d[i][j] is the best path from i to j whose middle vertices all come from {0..m}. Adding vertex m + 1 as a possible middle stop either helps (go i → m+1 → j) or does not. That is why k must be the outermost loop: put it inside and you use rows that have not been finished yet.

// 4. Floyd-Warshall: all-pairs shortest paths, O(V^3). edges {u, v, w} directed.
func floydWarshall(n int, edges [][3]int) [][]int {
	const INF = math.MaxInt64 / 4 // /4 so INF + INF cannot overflow
	d := make([][]int, n)
	for i := range d {
		d[i] = make([]int, n)
		for j := range d[i] {
			d[i][j] = INF
		}
		d[i][i] = 0
	}
	for _, e := range edges {
		if e[2] < d[e[0]][e[1]] {
			d[e[0]][e[1]] = e[2]
		}
	}
	for k := 0; k < n; k++ { // k = the intermediate vertex: OUTERMOST loop
		for i := 0; i < n; i++ {
			if d[i][k] == INF {
				continue
			}
			for j := 0; j < n; j++ {
				if d[i][k]+d[k][j] < d[i][j] {
					d[i][j] = d[i][k] + d[k][j]
				}
			}
		}
	}
	return d
}
// 4. Floyd-Warshall: all-pairs shortest paths, O(V^3). edges {u, v, w} directed.
vector<vector<long long>> floydWarshall(int n, const vector<vector<int>>& edges) {
    const long long INF = LLONG_MAX / 4;      // /4 so INF + INF cannot overflow
    vector<vector<long long>> d(n, vector<long long>(n, INF));
    for (int i = 0; i < n; i++) d[i][i] = 0;
    for (const auto& e : edges) d[e[0]][e[1]] = min(d[e[0]][e[1]], (long long)e[2]);
    for (int k = 0; k < n; k++)               // k = the intermediate vertex: OUTERMOST loop
        for (int i = 0; i < n; i++) {
            if (d[i][k] == INF) continue;
            for (int j = 0; j < n; j++)
                if (d[i][k] + d[k][j] < d[i][j]) d[i][j] = d[i][k] + d[k][j];
        }
    return d;
}

static long[][] floydWarshall(int n, int[][] edges) {
    final long INF = Long.MAX_VALUE / 4;           // /4 so INF + INF cannot overflow

# 4. Floyd-Warshall: all-pairs shortest paths, O(V^3). edges (u, v, w) directed.
def floyd_warshall(n, edges):
    INF = float('inf')
    d = [[INF] * n for _ in range(n)]
    for i in range(n):
        d[i][i] = 0
    for u, v, w in edges:
        d[u][v] = min(d[u][v], w)
    for k in range(n):                    # k = the intermediate vertex: OUTERMOST loop
        dk = d[k]
        for i in range(n):
            dik = d[i][k]
            if dik == INF:
                continue
            di = d[i]
            for j in range(n):
                if dik + dk[j] < di[j]:
                    di[j] = dik + dk[j]
    return d

The same triple loop solves other "all pairs" questions by swapping the operators:

  • Reachability (Course Schedule IV): booleans, reach[i][j] |= reach[i][k] && reach[k][j]. This is the transitive closure.
  • Ratios (Evaluate Division): ratio[i][j] = ratio[i][k] * ratio[k][j] when both are known. A DFS or weighted union-find per query also works and is what most top solutions use when queries are few.
  • Character conversion costs (Minimum Cost to Convert String I): only 26 letters, so Floyd on a 26 x 26 matrix, then sum the per-position costs.

Floyd or V runs of Dijkstra? V Dijkstras cost O(V x E log V). On a sparse graph that is much less than V3; on a dense graph Floyd wins and is far simpler to write. Floyd also tolerates negative edges (no negative cycles), and a negative d[i][i] afterwards reveals one.
