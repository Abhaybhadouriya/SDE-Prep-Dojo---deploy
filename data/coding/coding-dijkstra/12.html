Quiz

In lazy Dijkstra you pop (9, v) but dist[v] is already 6. What do you do?

  1. Relax v's edges using 9
  2. Update dist[v] to 9
  3. Skip the entry: it is stale
  4. Push (6, v) again
v was already settled at 6 from an earlier pop. The entry with 9 is an old duplicate; relaxing from it cannot improve anything.

When is a vertex's distance final in Dijkstra?

  1. When it is first popped (with a non-stale entry)
  2. When it is first pushed
  3. Only after the heap is empty
  4. When all its neighbours are pushed
Pushed distances can still improve. The first pop is the minimum key in the heap, and non-negative weights mean no later route can beat it.

Cheapest trip with at most 2 stops. How many Bellman-Ford rounds?

  1. 1
  2. 3
  3. 2
  4. V - 1
2 stops means up to 3 flights, and each round allows one more edge.

Why must K-stops Bellman-Ford relax from a copy of the previous round?

  1. The heap needs it
  2. In-place updates can chain several edges in one round, breaking the edge count
  3. Without it negative cycles go undetected
  4. It makes the code faster
Round r must mean "at most r edges". Reading values updated in the same round lets one round use many edges.

A path's cost is its largest single step. Which change makes Dijkstra solve it?

  1. Use a max-heap
  2. It cannot; you need Floyd
  3. Replace d + w with max(d, w)
  4. Negate the weights
max is monotone like +, so the greedy proof still holds with a min-heap.

In Floyd-Warshall, which loop must be outermost?

  1. k (intermediate vertex)
  2. Any order works
  3. j (destination)
  4. i (source)
The DP is over "which vertices may be used in the middle". Each k layer must be complete before k + 1 builds on it.

All edge weights are 0 or 1 and V = 106. Best choice?

  1. BFS with a normal queue
  2. 0-1 BFS with a deque
  3. Bellman-Ford
  4. Floyd-Warshall
The deque keeps vertices in distance order (0-edges to the front, 1-edges to the back), giving O(V + E). A plain queue ignores the 0 weights.
