The decoded string could be 1012 long. Return only the character at index K.

Do not build it. Compute expanded lengths per group (with 64-bit ints, capped), then walk down: inside a group repeated t times with inner length L, replace K by K mod L and descend. This is the idea of LC 880 Decoded String at Index; O(input) time and space.

How to answer

Lengths first, characters never; the modulo step is the key.

Likely follow-ups
  • Overflow of the length? (Cap at K + 1 or use saturating multiply.)

Write the encoder: given a plain string, produce a short k[...] form.

For the shortest encoding, it is interval DP (LC 471): dp[i][j] = the best encoding of s[i..j], either split into two parts or, if s[i..j] is a repetition of a period p (found via (t + t).find(t, 1)), k[dp of the period]. O(n³) for n ≤ 150.

How to answer

Say that encoding is an optimisation (DP), decoding is parsing (stack).

Likely follow-ups
  • A greedy encoder? (Run-length on repeated blocks: fast, not optimal.)

Parse into a tree (groups with counts and children), then emit by a DFS that loops over each group's count: memory is O(input), output is produced on the fly, like a generator.

How to answer
