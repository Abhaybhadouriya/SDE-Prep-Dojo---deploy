Approaches: brute -> better -> optimal

Hint 1

Which bracket group can be expanded right away, without knowing anything else?

Hint 2

When you see [, what must you remember so that you can continue after the matching ]?

1. Brute force - repeatedly expand an innermost group

Idea: find a [ whose group contains no other bracket (for example with a regex (\d+)\[([a-z]*)\]), replace it by its expansion, and repeat until no brackets remain.

pat = re.compile(r'(\d+)\[([a-z]*)\]')
while '[' in s:
    s = pat.sub(lambda m: m.group(2) * int(m.group(1)), s)
O(depth · output)time
O(output)space

What is wasted: every round rebuilds the whole, already long string; deep nesting means many rounds over a growing string. -> rung 2.

2. Better - recursion: decode a sequence until ]

Idea: a function reads letters and groups from position i until it meets ] or the end. On a digit it reads the full number, skips [, calls itself for the inside, skips ], and appends the result k times.

def parse(i):                      # returns (text, index of ']' or end)
    out = []
    while i < len(s) and s[i] != ']':
        if s[i].isdigit():
            k = 0
            while s[i].isdigit(): k, i = k*10 + int(s[i]), i + 1
            inner, i = parse(i + 1)    # skip '['
            out.append(inner * k); i += 1   # skip ']'
        else:
            out.append(s[i]); i += 1
    return ''.join(out), i
O(output)time
O(depth)call stack + output

What is left: this is already optimal and a great interview answer. The iterative version below says the same thing with an explicit stack, which interviewers often ask for next ("now without recursion"), and it cannot overflow the call stack on very deep input. -> rung 3.

3. Optimal - one pass with a stack of (outer text, count)

for c in s:
    if c.isdigit(): k = k*10 + int(c)
    elif c == '[':  stack.append((cur, k)); cur, k = [], 0
    elif c == ']':  outer, t = stack.pop(); outer.append(''.join(cur) * t); cur = outer
    else:           cur.append(c)
  1. Digits build the count. k = k*10 + digit, so "10" and "300" work.
  2. [ saves the context. Push what the outer level had written so far and the count for this bracket; start a fresh cur and reset k.
  3. Letters go to cur. cur is always the text of the innermost open bracket (or the top level).
  4. ] merges. Pop (outer, t): the inner text repeated t times is appended to the outer text, which becomes the current text again.
O(output)time
O(output)space (stack holds partial texts)

Why it works: brackets are well nested, so the ] always closes the most recently opened, still-open [, which is the top of the stack. Inductively, when a ] is read, cur is exactly the fully decoded content of that bracket (inner groups were already merged into it when their own ] came), so outer + cur·t is the decoded text of the parent up to this point.

Cost detail (optional)

Each output character is written once per nesting level it is copied through, so the honest bound is O(Σ over groups of the group's expanded length), which is at most depth × output; with depth ≤ 15 here (30 chars) and output ≤ 105 it is linear in practice. Using lists/builders and joining once per group avoids the O(n²) of repeated s += c in languages with immutable strings.
