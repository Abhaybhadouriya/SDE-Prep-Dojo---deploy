60-second recall

  • Cue: nested k[...] / open-close groups whose inside must be done first -> stack of contexts.
  • Frame: (text before '[', count for this '[').
  • Moves: digit: k = 10k + d; '[': push, reset; letter: cur += c; ']': cur = outer + cur·t.
  • Trap: multi-digit counts; reset k; keep the outer text.
  • Cost: O(output) time; recursion is the same with the call stack.
for c in s:
    if c.isdigit(): k = 10*k + int(c)
    elif c == '[': st.append((cur, k)); cur, k = '', 0
    elif c == ']': outer, t = st.pop(); cur = outer + cur * t
    else: cur += c

What must a stack frame hold so the parent can resume?

  1. Only the count
  2. The text decoded before the '[' and the count
  3. The index of the '['
  4. The whole decoded output
On ']' you need both the prefix to glue in front and how many copies to make.

"2[a3[b]]" decodes to:

  1. abbbabbb with k = 23
  2. aabbb
  3. abbbabbb
  4. ababab
Inner: bbb, group: abbb, twice: abbbabbb.

Why can the output be far longer than the input?

  1. Counts multiply along nesting
  2. Letters are doubled
  3. Brackets become letters
  4. It cannot
2[2[2[q]]] is 10 chars and decodes to 2·2·2 = 8 q's; with 300s it explodes, hence the 105 cap.
