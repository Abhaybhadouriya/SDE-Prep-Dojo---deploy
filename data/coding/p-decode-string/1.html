The problem (in our words)

A compression tool writes repeated text as k[encoded], meaning the encoded part inside the brackets is repeated exactly k times; k is always a positive integer. Brackets may be nested. Given a compressed string s, return its decoded form.

You may assume the input is always valid: no extra spaces, brackets are well formed, and so on. The original text contains no digits; digits appear only as repeat counts, so there is never input like 3a or 2[4]. Test cases are generated so that the output length never exceeds 105.

Signature: String decodeString(String s).

Constraints:

  • 1 <= s.length <= 30
  • s consists of lowercase English letters, digits and square brackets '[]'.
  • s is guaranteed to be a valid input.
  • All the integers in s are in the range [1, 300].

Practice it: LeetCode 394 · GfG Decode the string

Constraints tell you: the input is tiny (30 chars) but the output can be 105, so the cost is the output size: build strings without repeated quadratic concatenation. Counts go up to 300, so they can have three digits: read numbers digit by digit.
