Approaches: brute → better → optimal

Hint 1

Move 1 lets you sort the word for free. What does that say about the information you need to keep?

Hint 2

Move 2 swaps the counts of two letters. If you list the counts without the letter names, does move 2 change that list?

1. Brute force - explore the reachable words

Idea: treat each word as a node and each move as an edge. Run a BFS from word1 over all words you can reach and stop when you meet word2. It is correct by definition, which makes it a good first sentence.

O(n! · ...)time: up to n! orderings alone
exponentialspace (the visited set)

What is wasted: move 1 makes all orderings of one multiset equivalent, so storing them as separate nodes is pointless. Describe a word by what the moves cannot change instead.

2. Better - compare hash maps of counts

Idea: build a map letter → count for each word. The words are close when the two maps have the same keys and the same values once sorted. In Python this is two Counters; in Java two HashMaps plus sorting the value lists.

O(n + k log k)time (k = distinct letters)
O(k)space

What is wasted: nothing asymptotically, and for a general alphabet this is the version to write. With only 26 letters, plain arrays avoid hashing and make the "same set of letters" test a 26-step loop.

3. Optimal - two arrays of 26 counts

c1, c2 = [0] * 26, [0] * 26                    # core
for ch in word1: c1[ord(ch) - 97] += 1
for ch in word2: c2[ord(ch) - 97] += 1
same_set = all((a == 0) == (b == 0) for a, b in zip(c1, c2))
return same_set and sorted(c1) == sorted(c2)
  1. Lengths first. No move changes the length; different lengths answer false at once (it also means the sorted counts would differ).
  2. Same letter set. A letter that occurs in one word but not the other can never appear or vanish: move 2 only swaps names of letters already present.
  3. Same multiset of counts. Sort both 26-slot arrays and compare. The zeros of absent letters sort to the front on both sides, so they line up when the letter sets match.
O(n)time (+ O(26 log 26) to sort)
O(1)space (52 counters)

Why it works: necessity: move 1 keeps every letter's count, move 2 exchanges two existing letters' counts, so neither changes the letter set or the multiset of counts. Sufficiency: if both match, the counts of word1 are a permutation of those of word2 over the same letters. Any permutation is a product of swaps, and each swap of two counts is one move 2. After those relabels, word1 has exactly word2's count per letter, so it is an anagram of word2, and move 1 reorders it into word2.

Proof detail: why the zeros cause no trouble (optional)

If both words use the same k letters, each sorted array is 26 - k zeros followed by the k positive counts in order. Equal sorted arrays then means equal multisets of positive counts. Without the set check, "uuv" and "wwv" would pass: both sorted arrays are 24 zeros, 1, 2.
