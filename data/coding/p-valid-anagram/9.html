Revision card

  • Cue: "same letters, any order" -> compare counts, not positions.
  • Insight: one array, +1 for s and -1 for t; anagram iff all zero.
  • State: int count[26]; different lengths -> false before counting.
  • Trap: sets ignore counts ("aab" vs "abb"); Unicode needs a map.
  • Cost: O(n) time, O(1) space (26 ints); sorting is O(n log n).
if len(s) != len(t): return False
cnt = [0] * 26
for a, b in zip(s, t):
    cnt[ord(a) - 97] += 1; cnt[ord(b) - 97] -= 1
return not any(cnt)

Quick quiz

Why does a set comparison fail for "aab" vs "abb"?

  1. it does not fail
  2. both sets are {a, b}, so counts are lost
  3. sets are unordered
  4. the lengths differ
Both strings have the same distinct letters; only the counts differ, and a set throws counts away.

After one pass that adds for s and subtracts for t, when are they anagrams?

  1. when the sum of the counts is 0
  2. when at least one count is 0
  3. when every count is 0
  4. when the first count is 0
A zero sum can hide +1 and -1 on two letters; every bucket must be zero.

The input can contain any Unicode character. What changes?

  1. replace the 26-int array with a hash map
  2. nothing
  3. sort is the only correct option
  4. use a bitmask
The fixed 26-slot table assumes 'a'..'z'; a map keyed by code point handles any alphabet in O(n).
