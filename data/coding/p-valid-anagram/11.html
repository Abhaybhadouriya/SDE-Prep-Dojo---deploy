Interview follow-ups

The strings may contain Unicode. What changes?

Replace the 26-array with a hash map from code point to count (Counter, HashMap<Integer,Integer>, unordered_map<char32_t,int>). Iterate by code point, not by UTF-16 unit or byte, so a surrogate pair or a multi-byte UTF-8 letter counts as one character. Optionally normalise first (NFC), since "é" can be one code point or "e" + combining accent.

How to answer

Name the three layers: bytes vs code points vs user-visible characters, and pick code points plus normalisation.

Likely follow-ups
  • Case-insensitive and ignoring spaces: normalise each character before counting.
Can you do it without the final 26-counter scan?

Yes: count s up, then for each letter of t decrement and return false if the counter drops below 0. Because the lengths are equal, the total of the counters is 0; if none is negative, all must be 0.

How to answer

Give the "sum is zero and nothing is negative, so everything is zero" argument in one sentence.

Likely follow-ups
  • Which version exits earliest on random inputs?
The strings are huge streams that do not fit in memory.

The counter array is the whole state: stream s and t chunk by chunk and update the counts; memory stays O(alphabet). Counts must be 64-bit if a stream can exceed 231 characters. For a distributed version, each worker counts its chunk and the counts are summed (counts are mergeable).

How to answer

Point out the state is a commutative sum, so it can be split and merged freely.

Likely follow-ups
  • Probabilistic check with a hash of the multiset (e.g. sum of random values per letter mod a prime).
Many queries: is word w an anagram of any word in a dictionary?

Precompute a canonical key per dictionary word (the sorted word, or the 26 counts joined as a string) into a hash set. Each query computes its key in O(len) (counts) and does one lookup. This is Group Anagrams with lookups.

How to answer

Move the work to preprocessing; the key design is the whole question.

Likely follow-ups
  • Return all words that are anagrams of a query (map key -> list).
Minimum number of letter changes to make t an anagram of s.

Compute the same difference array; the answer is the sum of the positive entries (each extra letter of s that t lacks must be created by changing one surplus letter of t). This is LeetCode 1347.

How to answer

Reuse the +1/-1 array and argue each change fixes one positive and one negative unit.

Likely follow-ups
  • Deletions allowed from both strings: sum of absolute values.
