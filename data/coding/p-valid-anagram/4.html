Approaches: brute -> better -> optimal

Hint 1

If you sort both strings, what do two anagrams look like?

Hint 2

You do not need the sorted order, only how many of each letter. How many different letters can there be?

1. Brute force - match and cross out

Idea: for each letter of s, search t for an unused copy and mark it used; fail if none is found. Correct, but each search is O(n).

O(n2)time
O(n)used flags

What is wasted: we search t again and again for the same letter. -> put the letters in a canonical order once.

2. Better - sort both and compare

return sorted(s) == sorted(t)

Why it works: sorting maps every rearrangement of the same multiset to the same string, and different multisets to different strings.

O(n log n)time
O(n)sorted copies (O(1) if you may sort in place)

What is wasted: sorting builds a full order we never use. -> count instead.

3. Optimal - one counter array, +1 / -1

  • If the lengths differ, return false (this also guarantees that "all counters are 0" is the only way to balance).
  • Walk both strings together: count[s[i]]++, count[t[i]]--.
  • Return true only if all 26 counters are 0.
O(n)time (one pass + 26 checks)
O(1)26 ints

Why it works: after the loop, count[c] = (#c in s) - (#c in t). The strings are anagrams exactly when this difference is 0 for every letter, which is the definition of "same multiset". Using one array instead of two halves the memory and the final comparison.

Early exit variant (from the top-voted community answers): first add all of s, then for each letter of t decrement and return false the moment a counter goes negative. With equal lengths, "never negative" implies "all zero at the end", so the final scan can be skipped.
