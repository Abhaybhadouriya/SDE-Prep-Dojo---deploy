Approaches: brute -> better -> optimal

Hint 1

If you could use a second array, you would append every value that is not val. Where in the same array could that "second array" live?

Hint 2

The next free slot for a kept value is never to the right of the value you are reading.

1. Brute force - shift left on every hit

Idea: scan with i; when nums[i] == val, shift everything after it one place left and shrink n (do not advance i, the shifted-in value must be checked). It is how vector::erase or list.remove in a loop behaves.

O(n²)time (many hits)
O(1)space

What is wasted: a kept value near the end is moved once per hit before it, so up to n times. It only needs to move once, straight to its final slot.

2. Optimal (order kept) - reader and writer

w = 0
for r in range(len(nums)):
    if nums[r] != val:
        nums[w] = nums[r]; w += 1
return w
  1. Invariant: nums[0..w) holds exactly the kept values among nums[0..r), in input order.
  2. A hit (nums[r] == val) only advances r; slot w now holds an already-read value that may be overwritten later.
  3. A kept value is copied to slot w and w advances. Because w <= r, the copy never destroys an unread value.
  4. At the end r = n, so nums[0..w) is every kept value: return w.
O(n)time, one pass
O(1)space
n - (#hits)writes

Why it works: each kept value is written once, at the next free position, so the survivors appear in input order and nothing is lost. This is the shortest correct code and the version most top-voted community solutions give; it also preserves order, which the problem does not require but interviewers like.

3. Optimal (few removals) - overwrite with the last element

i, n = 0, len(nums)
while i < n:
    if nums[i] == val:
        n -= 1; nums[i] = nums[n]   # do not advance i
    else:
        i += 1
return n

Idea: because the order of survivors is free, a hit can be filled by the last live element, and the live part shrinks by one. The moved-in value has not been checked yet, so i stays put. It is the standard variant to offer when val is rare.

O(n)time
O(1)space
#hitswrites

Trade-off: on [1,2,3,4,5] with val = 1, the copy loop writes 4 times (every survivor moves left); this one writes once. It does scramble the order.
