Common mistakes

Advancing i after overwriting with the last element. On [2,3,3] with val 3: slot 1 gets the 3 from slot 2, and if i moves on, that 3 is never checked; k comes out as 2 instead of 1.

Erasing inside a for-loop. nums.erase(nums.begin() + i) or nums.remove(x) while iterating skips the element after each erased one and costs O(n) per erase.

Returning the wrong count. Return the number of kept elements (w, or the final n), not the number of removed ones, and not len(nums).

Building a new list. nums = [x for x in nums if x != val] in Python rebinds a local name; the judge reads the original list. If you use a comprehension, assign to nums[:], and still expect to be asked for the in-place loop.

Unsigned underflow. In C/C++, size_t n = nums.size(); ... nums[--n] is fine only while n > 0; with signed ints and the i < n guard, the empty case is safe.
