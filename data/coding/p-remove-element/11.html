Interview follow-ups

Minimise the number of writes when val is rare.

Use overwrite-with-last: each hit costs one write and kept values never move. The copy version writes every survivor after the first hit, which is almost n writes when the only hit is at index 0.

How to answer

Give both write counts (#hits vs #kept-after-first-hit) and say the swap version gives up order.

Likely follow-ups
  • Can you skip self-copies in the copy version? Yes: write only when r != w.
Keep the relative order of the remaining elements.

The reader/writer copy already does: survivors are written left to right in the order they are read. The swap-with-last version does not, so it is ruled out.

How to answer

Point to the invariant nums[0..w) = kept values in input order.

Likely follow-ups
  • Also put the removed values at the end: swap instead of copy (the Move Zeroes loop); every removed value equals val, so the tail is just val repeated.
Remove every value contained in a given set, not just one value.

Same loop with a different test: put the set in a hash set (or a bitmap of 51 bits, since values are 0..50) and keep nums[r] when it is not in it. O(n + m) time.

How to answer

Show that the "keep" predicate is the only thing that changes; mention the bitmap for small value ranges.

Likely follow-ups
  • Remove values in a range [lo, hi]: the test is a comparison, no set needed.
Do the same on a singly linked list.

Use a dummy node before the head and a pointer prev; when prev.next.val == val, unlink it (prev.next = prev.next.next), otherwise advance prev. Return dummy.next. In C, free the unlinked node.

How to answer

The dummy removes the special case of deleting the head; do not advance prev after an unlink, the new next must be checked.

Likely follow-ups
  • Pointer-to-pointer version in C: for (struct node **pp = &head; *pp; ) if ((*pp)->val == val) *pp = (*pp)->next; else pp = &(*pp)->next;
The data arrives as a stream or a file that does not fit in memory.

Stream it: read each value, write it to the output if it is not val, and count the writes. That is the reader/writer loop with the writer on another file; O(1) memory, sequential I/O.

How to answer

Say "in place" stops mattering for streams; what matters is one sequential pass.

Likely follow-ups
  • Many machines: each shard filters locally and reports its k; the total is the sum.
