The problem (in our words)

A sensor log is an integer array nums, and val is a faulty reading. Remove every occurrence of val from nums in place and return k, the number of elements that are not equal to val.

After your function returns, the first k slots of nums must hold exactly the values that are not val, in any order. What you leave in slots k and beyond, and the array's physical size, do not matter.

Signature: int removeElement(int[] nums, int val). The judge checks that you returned the right k, then sorts nums[0..k) and compares it with the sorted expected values.

  • 0 <= nums.length <= 100
  • 0 <= nums[i] <= 50
  • 0 <= val <= 100

Practice it: LeetCode 27

Constraints tell you: n <= 100, so speed is never the issue: the interview is about doing it in place, getting the returned length right and not reading a slot after overwriting it. The array can be empty. val can be larger than every element (up to 100 while values are <= 50), in which case nothing is removed.
