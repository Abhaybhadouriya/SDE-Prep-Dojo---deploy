The story

Explain like I'm 5

You have 50 square floor tiles and want to lay the biggest square patio you can. A 7 by 7 patio uses 49 tiles; 8 by 8 needs 64, which is too many. So the answer is 7. You could try 1, 2, 3 ... in order, but with two billion tiles that takes forever. Instead you guess the middle size, and each guess tells you "too big" or "fits", which throws away half of the remaining sizes.

That "too big or fits" answer only flips once as the size grows, and anything that flips once can be found by halving.

From your world

This is the same bisection you run with git bisect or when you hunt for the largest MTU that gets through a path: a monotone pass/fail test and a range that halves each probe. Kernels compute integer square roots this way too (Linux has int_sqrt() in lib/math/int_sqrt.c, a bit-by-bit variant), because floating point is not available in kernel context.
