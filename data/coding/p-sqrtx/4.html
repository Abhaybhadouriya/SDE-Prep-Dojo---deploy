Approaches: brute -> better -> optimal

Hint 1

If 20 · 20 is more than x, what do you know about 21, 22, 23?

Hint 2

Write the loop so the range always contains the answer and lo is always a valid root.

Hint 3

With lo = mid in one branch, what happens when hi = lo + 1 and mid rounds down?

1. Brute force - count up

Idea: r = 0; while (r + 1) * (r + 1) <= x: r += 1.

O(√x)time
O(1)space

What is wasted: every failed or passed test tells you about all the numbers on one side of it, but the scan only uses it for one number. 46k steps is fine here, but say it is O(√x) and move on. -> rung 2.

2. Optimal - binary search on the answer

lo, hi = 0, x
while lo < hi:
    mid = (lo + hi + 1) // 2
    if mid * mid <= x: lo = mid
    else: hi = mid - 1
return lo
  1. Search range [0, x]. The root of x is never above x (for x ≥ 1 it is at most x; for 0 and 1 it is x itself). Tighter: x / 2 + 1, which also covers x = 1.
  2. Invariant: lo is a valid root, and the answer is in [lo, hi]. True at the start, since 0 · 0 <= x.
  3. mid fits -> lo = mid. mid might be the answer, so keep it.
  4. mid too big -> hi = mid - 1. Monotone test: everything above mid is too big too.
  5. Round mid up. With lo = 3, hi = 4, a rounded-down mid is 3, the "fits" branch sets lo = 3 again and the loop never ends. Rounding up gives mid = 4 and progress either way.
O(log x)time
O(1)space

Why it works: the yes/no row is monotone, and each probe removes the half that cannot hold the boundary while keeping lo valid. When lo == hi the range holds one number, it is valid, and nothing above it is (hi only drops below numbers that failed). So it is the largest valid root. About 31 probes for any 32-bit x.

No 64-bit? Divide instead of multiply

mid <= x / mid (for mid ≥ 1) is equivalent to mid * mid <= x with integer division, and it never overflows. Start the range at lo = 1 (handle x = 0 separately) so you never divide by zero.

3. Follow-up - integer Newton's method

Idea: start at r = x and repeat r = (r + x / r) / 2 while r · r > x. The tangent-line step roughly doubles the number of correct digits each round once r is near the root. With integer division the sequence falls monotonically and stops exactly at ⌊√x⌋ (a known property of integer Newton, and one top community post checked it for every x from 0 to 231-1).

r = x
while r * r > x:
    r = (r + x // r) // 2
return r
O(log x)worst (halving phase)
O(1)space

From a far start like r = x the first steps only halve r, so the worst case is still logarithmic; after that it converges quadratically. Our test files run this version against the same cases (Python).
