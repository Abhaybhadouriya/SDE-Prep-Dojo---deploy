The problem (in our words)

You are given a non-negative integer x (a tile count). Return the integer square root of x: the largest integer r with r · r <= x, which is the square root rounded down. The returned value must be a non-negative integer. You may not use any built-in exponent or square-root function or operator (no pow(x, 0.5) in C++, no x ** 0.5 in Python, no Math.sqrt).

Signature: int mySqrt(int x) (LeetCode style).

  • 0 <= x <= 231 - 1

Practice it: LeetCode 69 · GfG Square root · TUF article

Constraints tell you: x up to 2.1·109 means the root is at most 46,340, so even a linear scan is only about 46k steps and would pass; the interviewer wants O(log x). The real trap is overflow: mid * mid in a 32-bit int overflows once mid passes 46,340, and with hi = x the first mid is about 109.
