Interview follow-ups

Do it without 64-bit integers.

Compare mid <= x / mid instead of mid * mid <= x. For positive mid and integer division they are equivalent: mid · mid <= x iff mid <= ⌊x / mid⌋. Search [1, x] and return 0 for x = 0.

How to answer

Name the overflow before the interviewer does, then give both fixes and pick one.

Likely follow-ups
  • Is x / mid safe when mid = 0? (No: that is why the range starts at 1.)
Can you converge faster than binary search?

Integer Newton: r = (r + x / r) / 2 from r = x until r · r <= x. Each step near the root roughly doubles the correct digits. Starting closer (for example r = x >> (bitlength / 2) or 1 << ((bitlength + 1) / 2)) removes the initial halving phase.

How to answer

Explain the tangent-line idea in one sentence, then why integer division keeps the sequence above the floor root until the last step (by AM-GM, (r + x/r)/2 ≥ √x before rounding).

Likely follow-ups
  • Prove it terminates. (r strictly decreases while r · r > x, and never drops below ⌊√x⌋.)
Return the square root to 5 decimal places.

Two options: binary search on doubles for a fixed number of rounds (about 50-60 halvings reach double precision; a loop on hi - lo > 1e-6 can hang for large x), or find the integer part first and then search each decimal digit 0-9 in turn. Newton on doubles also works: r = (r + x / r) / 2 until |r · r - x| is small.

How to answer

Mention why a fixed iteration count is safer than an epsilon on large values.

Likely follow-ups
  • Cube root of a negative number? (The function is monotone over all reals, so search [-|x|-1, |x|+1].)
Find the n-th root of m (integer), or report that it is not an integer.

Same search on [1, m] with the test midn vs m. Compute the power with an early exit: multiply step by step and stop as soon as the product exceeds m, so it never overflows. Return mid if the power equals m, else -1.

How to answer

Point out that the test is now O(n) (or O(log n) with fast power), so the total is O(n log m).

Likely follow-ups
  • What if m has 30 digits? (Big integers, or search digit by digit.)
How would you compute an integer square root without division at all (for a tiny CPU)?

The bit-by-bit method: decide the result's bits from the top. For bit b from 15 down to 0, try r | (1 << b) and keep the bit if its square is still <= x. With incremental updates of the remainder it needs only shifts, adds and compares, which is how many embedded and kernel implementations work.

How to answer

Show it is a binary search too: each bit decision halves the candidate range.

Likely follow-ups
  • How many iterations for a 64-bit x? (32, one per result bit.)
