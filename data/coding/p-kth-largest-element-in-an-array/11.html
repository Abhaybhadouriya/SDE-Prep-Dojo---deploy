Interview follow-ups

The numbers arrive as a stream; answer the k-th largest after each one.

How to answer: size-k min-heap; each new value is pushed and, if the size exceeds k, the smallest is popped. O(log k) per value (LC 703).

Likely follow-ups: k changes over time, or you need deletions - use two heaps or an order-statistics tree.

Why is quickselect O(n) on average but O(n^2) worst case? Can you guarantee O(n)?

How to answer: the expected range shrinks geometrically with a random pivot; a bad pivot every round gives n + (n-1) + ... . Median of medians guarantees O(n) but with a large constant; introselect (used by std::nth_element) falls back to it when recursion gets deep.

The array has 10^9 elements on disk, k = 100.

How to answer: one pass with a size-100 heap: O(n log k) time, O(k) memory, sequential reads. Quickselect needs random access and many passes.

Likely follow-ups: spread over machines - each machine sends its local top k; merge them (k·m values).

Return the k largest elements in sorted order.

How to answer: heap of size k, then pop all and reverse: O(n log k + k log k). Or quickselect for the k-th, then sort the right part: O(n + k log k).

Values are bounded by 10^4 in absolute value. Anything faster?

How to answer: counting array of 20,001 buckets, walk from the top: O(n + R). Exactly what the constraints allow.

Does quickselect modify the input? What if that is not allowed?

How to answer: yes, it reorders in place. Copy first (O(n) memory), or use the heap version, which only reads the input.
