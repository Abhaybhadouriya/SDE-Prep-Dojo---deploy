The problem (in our words)

You get an integer array scores and an integer k. Return the k-th largest element of the array, meaning the element that would be at position k if the array were sorted in decreasing order. It is not the k-th distinct value: duplicates count separately.

The original asks you to try to solve it without sorting the whole array.

Signature: int findKthLargest(int[] scores, int k)

  • Constraints:
  • 1 <= k <= scores.length <= 10^5
  • -10^4 <= scores[i] <= 10^4

Practice it: LeetCode 215 - Kth Largest Element in an Array · GfG - Kth Largest · TUF article

Constraints tell you: n = 10^5 allows O(n log n), so sorting passes; the interview wants better. The value range is only 20,001 wide, so a counting array of that size also gives O(n + range) - a valid trick worth mentioning.
