  • Cue: k-th largest / top k of an array or a stream.
  • Insight: keep k best in a min-heap; or partition and keep only the side with n - k.
  • State: heap of size k; or lo, hi, target = n - k, lt / i / gt for the 3-way split.
  • Trap: min-heap for largest; random pivot; 3-way for duplicates; duplicates count.
  • Cost: sort n log n; heap n log k, O(k); quickselect O(n) avg, O(1) space.
target = len(a) - k; lo, hi = 0, len(a) - 1
while True:
    p = a[random.randint(lo, hi)]
    lt, gt = three_way_partition(a, lo, hi, p)
    if target < lt: hi = lt - 1
    elif target > gt: lo = gt + 1
    else: return p

Size-k heap for the k-th LARGEST: min-heap or max-heap?

  1. max-heap
  2. min-heap
  3. either
  4. a sorted array
Keep the k largest seen so far; the smallest of them is on top and is popped when a bigger value comes. After the scan the top is the k-th largest.

[7, 1, 7, 3, 9, 3, 5], k = 3. What is the answer?

  1. 5
  2. 7
  3. 9
  4. 3
Sorted descending: 9, 7, 7, 5, ... Duplicates count as separate elements, so the 3rd largest is 7, not 5.

Why use a random pivot (and a 3-way split) in quickselect?

  1. it is required for correctness
  2. a fixed pivot on sorted or all-equal input gives O(n²)
  3. random pivots use less memory
  4. the heap needs it
A first-element pivot on sorted input removes one element per round. The 3-way split keeps all-equal input O(n) too.
