The problem (in our words)

Write a function that raises a real number x (a growth factor) to an integer power n, returning xn as a double. The power can be negative (meaning 1 / x|n|) or zero (the result is 1). Do not call the library power function; the judge accepts answers within normal floating-point error.

Signature: double myPow(double x, int n) (LeetCode style).

  • -100.0 < x < 100.0
  • -231 <= n <= 231 - 1, and n is an integer
  • Either x is not zero or n > 0 (no 0 to a non-positive power)
  • -104 <= xn <= 104

Practice it: LeetCode 50 · GfG Implement Pow · TUF article

Constraints tell you: |n| up to 2.1·109 means a linear loop of multiplications times out; you need O(log n), about 31 iterations. The range of n includes -231, the one int whose negation overflows: that is the trap this problem is testing. The result bound (|xn| ≤ 104) means the final answer never overflows a double, but intermediate squares can (they become infinity only when not needed, see the edge cases).
