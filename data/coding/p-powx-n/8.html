Common mistakes

n = -n in an int. For n = -231 this is undefined behaviour in C++ and stays negative in Java, so the loop either never runs or runs forever with >>. Copy into long long / long first.

Calling the recursion twice. pw(x, n/2) * pw(x, n/2) recomputes the half: T(n) = 2T(n/2) + 1 = O(n). Store the half in a variable.

Taking 1 / result at the end. It works for most inputs, but when result overflows to infinity (x = 2, n = -231 computed as 2231) you get 1/inf = 0 by luck; with x = 0.5 and a large negative n the intermediate 0 gives 1/0 = inf. Flipping x first keeps the values in range.

Using n % 2 == 1 on a negative n. In C++/Java, -3 % 2 is -1, so the odd test fails. Make e non-negative first, or use e & 1.
