Revision card

  • Cue: same associative op applied n times, n up to 1e9+ -> square and multiply.
  • Insight: x^n = product of x^(2^k) over the set bits k of n; squaring makes each in 1 step.
  • State: result = 1, base = x (or 1/x), e = |n| as 64-bit; invariant result·base^e = x^n.
  • Trap: widen n before negating (-2^31); compute the half ONCE in recursion.
  • Cost: O(log n) time, O(1) space; recursion O(log n) stack; naive O(n).
def power(base, e, op=mul, unit=1):
    result = unit
    while e:
        if e & 1: result = op(result, base)
        base = op(base, base)
        e >>= 1
    return result

n = -2^31 stored in a 32-bit int. What goes wrong with n = -n?

  1. nothing
  2. -(-2^31) overflows back to -2^31
  3. it becomes 0
  4. it raises an exception in C++
Widen to 64 bits first: long long e = n; then e = -e.

Recursive version: why compute half = pow(x, n/2) once and square it?

  1. it is shorter
  2. calling pow(x, n/2) twice makes T(n) = 2T(n/2), which is O(n)
  3. to avoid overflow
  4. doubles need it
One call per level gives O(log n) calls.

x = 2.0, n = -2^31. What should you return?

  1. an error
  2. 0.0, the true value underflows below the smallest double
  3. infinity
  4. -0.0
The true value is about 10^(-6.46 × 10^8), far below about 4.9 × 10^-324, so the double result is 0.0, which the judge accepts.
