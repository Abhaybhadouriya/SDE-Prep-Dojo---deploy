What about precision? Is the result exact?

Not always exact. Any rounding in x (or in an early square) is amplified n times by the power itself: squaring doubles a relative error, so after k squarings it is about 2k times larger. Both the naive loop and square and multiply end up near n · 2-53 relative error, about 2·10-7 for n = 231, which the judge accepts. The fast version is not less accurate, just much faster; results are exact only when every intermediate is representable (small integers).

How to answer

Separate the error of the problem (xn amplifies errors in x by n) from the error of the method; neither version can beat the first.

Why does flipping x before the loop beat taking 1/result after it?

With x = 0.5 and n = -231, the "after" version computes 0.5231 = 0 and then 1/0 = infinity, while the real answer (2231) is excluded by the result bound anyway. In general, flipping first keeps intermediate values on the same side of 1 as the answer.

How to answer

Tie it to the constraint |xn| ≤ 104: the inputs where order matters are exactly the extreme ones.
