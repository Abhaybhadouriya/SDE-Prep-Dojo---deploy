Approaches: brute → better → optimal

Hint 1

If you fix the first number x, what exact value must the second one be?

Hint 2

How can you answer "is that value somewhere to my left?" in O(1)?

1. Brute force - check every pair

Idea: two nested loops, i < j; return the first pair with nums[i] + nums[j] == target.

O(n²)time
O(1)space

What is wasted: for a fixed nums[i] we already know the partner's exact value; scanning for it is a search we can index.

2. Better - sort a copy, then two pointers

Idea: sort (value, index) pairs. Put lo at the start and hi at the end: if the sum is too small move lo right, if too big move hi left. Return the stored original indices.

O(n log n)time (the sort)
O(n)space (the pairs)

What is wasted: the sort is needed only to make the search monotone. A hash map gives O(1) lookups without any order.

3. Optimal - one pass with a value → index map

for i, x in enumerate(nums):                # core: 4 lines
    if target - x in seen: return [seen[target - x], i]
    seen[x] = i
  1. The map holds only elements to the left of i. So any hit is a different position.
  2. Look up before you insert. That is what stops x pairing with itself when target = 2x, and it still finds [6, 6] because the first 6 is stored before the second is read.
  3. Every pair is found when its right element is read. At that moment the left element is already in the map.
O(n)time (expected, hash map)
O(n)space

Why it works: let the answer be (p, q) with p < q. When the loop reaches q, nums[p] was stored at step p, and target - nums[q] = nums[p], so the lookup hits. The loop cannot return a wrong pair, because a hit means the two values really sum to target.

Proof (optional) - duplicates

With duplicate values, seen[x] is overwritten with the latest index. That is safe: any earlier index that holds the needed value is a correct partner, so keeping any one of them is enough. The pair [v, v] works because the first copy is stored before the second copy is read, and a single copy can never match itself because the lookup happens before the insert.
