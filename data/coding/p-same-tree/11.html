Write it without recursion.

Queue (or stack) of pairs. Start with (p, q); pop a pair; if both null, continue; if one null or the values differ, return false; else push both child pairs. Return true when the queue empties.

How to answer

The base cases do not change; only the call stack is replaced by your own container.

Likely follow-ups
  • Which uses less memory, BFS or DFS? (O(w) vs O(h); depends on the tree's shape.)
Check whether a tree is a mirror of itself.

That is LC 101: pair(root.left, root.right) with crossed recursion pair(a.left, b.right) and pair(a.right, b.left). Same base cases, same O(n).

How to answer

Show that the only change is which children you pair.

Likely follow-ups
  • Iterative version with a queue of mirrored pairs.
Is tree t a subtree of tree s? Do better than O(n·m).

Brute force: run isSameTree(node, t) from every node of s, O(n·m) worst case. Faster: serialise both with null markers and use KMP / string find (O(n + m)), or give each subtree a canonical id or hash bottom-up and look for t's id among s's.

How to answer

Start with the brute force built on this problem, then offer hashing, and mention hash collisions (use ids from a map of (left id, val, right id) triples to avoid them).

Likely follow-ups
  • Find all duplicate subtrees (LC 652) with the same triple-to-id map.
Children may be swapped at any node. Are the trees still equivalent?

LC 951: at each pair, accept if values match and either (left-left and right-right) or (left-right and right-left) are equivalent. With unique values you can pick the right pairing by comparing child values, keeping it O(n).

How to answer

Write the OR of the two pairings, then explain why unique values avoid the exponential blow-up.

Likely follow-ups
  • Canonical form: sort children at every node, then compare.
The trees have 107 nodes and live on two machines. How do you compare them?

Compute a Merkle hash per subtree (hash of value and both child hashes) on each machine. Compare root hashes; if they differ, compare child hashes and descend only into differing subtrees. Network cost is proportional to the number of differences times the depth, not to n.

How to answer

Link it to how Git, Cassandra anti-entropy and rsync-like tools find differences.

Likely follow-ups
  • How do you keep the hashes up to date after an update? (rehash the path to the root, O(h).)
