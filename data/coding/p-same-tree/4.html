Approaches: brute -> better -> optimal

Hint 1

When are two empty trees equal? When is an empty tree equal to a non-empty one?

Hint 2

If both roots exist and hold the same value, what two smaller questions decide the answer?

1. Brute force - serialise both and compare strings

Idea: write each tree as a pre-order string with explicit null markers, e.g. 4,7,#,#,#, and compare the strings. The null markers are essential: without them [4,7] and [4,null,7] produce the same listing.

O(n)time
O(n)extra space for the strings

What is wasted: the whole of both trees is serialised even when the roots already differ, and the strings cost memory.

2. Better - iterative BFS over pairs

Idea: push the pair (p, q) on a queue; pop a pair, apply the three checks, push (p.left, q.left) and (p.right, q.right). Stops at the first mismatch.

O(n)time
O(w)queue, w = widest level

When to prefer it: very deep trees, where recursion depth is a risk. For 100 nodes the recursive version is cleaner.

3. Optimal - recursive pair DFS

def same(p, q):
    if p is None or q is None:
        return p is q                 # both empty -> True, one empty -> False
    return p.val == q.val and same(p.left, q.left) and same(p.right, q.right)
O(min(n, m))time, stops at the first difference
O(h)call stack

Why it works: by induction on size. Two trees are equal exactly when both are empty, or both roots exist with equal values and the left subtrees are equal and the right subtrees are equal. The function checks exactly this definition, and each recursive call is on strictly smaller trees. Every pair of positions is visited at most once, and and short-circuits at the first difference.
