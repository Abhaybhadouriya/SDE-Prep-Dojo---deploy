Return index triplets instead of values, and you may not sort the input.

Sort an array of indices by value (the input stays untouched) and run the same scan, emitting the original indices. Or use the hash version (rung 2) with a map from value to index. Both stay O(n²).

How to answer

Ask first whether duplicates are defined by values or by indices; that changes whether dedup is needed at all.

Likely follow-ups

Generalise to k-Sum.

Recursion: kSum(start, k, target) loops over the first number (skipping duplicates) and calls kSum(i+1, k-1, target - a[i]); the base case k = 2 is the two-pointer scan. Time O(nk-1). Prune when a[i] * k > target or a[-1] * k < target.

How to answer

Show that 3Sum is kSum with k = 3 and 4Sum adds one level; mention 64-bit sums.

Likely follow-ups
  • Can you beat O(n²) for 3Sum? (No known strongly sub-quadratic algorithm in this model; mention it is a famous open problem.)
Why is the hash-set version not O(n) per i in practice, and when would you still choose it?

It is O(n) per i on average, but hashing has a larger constant and memory churn. Choose it when the data cannot be sorted (stream, read-only) or when only existence is asked.

How to answer

Compare constants: two pointers touch a contiguous array, the set does random accesses.

Likely follow-ups
  • Worst-case hashing (adversarial collisions) in Java/Python?
The values are in a small range, say [-1000, 1000], but n is 106.

Count each value (2001 buckets) and loop over pairs of distinct values a ≤ b, checking c = -a-b ≥ b and the counts (need 2 copies if a value repeats, 3 for 0,0,0). That is O(R²) with R = 2001, independent of n.

How to answer

Read the constraint on values, not only on n: counting replaces sorting when the range is small.

Likely follow-ups
  • FFT-based counting for larger ranges (mention only).
Find the triplet whose sum is closest to a target (LC 16).

Same loops; at each step compare |sum - target| with the best so far and move by the sign of sum - target. Return immediately when the difference is 0.

How to answer

Reuse the code; only the "record" step changes.
