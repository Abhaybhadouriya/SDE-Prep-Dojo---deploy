  • Cue: all distinct k-tuples with sum T, order free -> sort + loops + two pointers.
  • Insight: fix the smallest; on a sorted suffix the sum's sign says which end is useless.
  • State: i, lo = i+1, hi = n-1, sum; skip i == i-1, skip lo copies after a hit.
  • Trap: compare with the PREVIOUS value; break only on nums[i] > 0; keep lo < hi.
  • Cost: O(n²) time, O(1) extra; hash version O(n²)/O(n); brute O(n³).
a.sort()
for i in range(n - 2):
    if i and a[i] == a[i - 1]: continue
    lo, hi = i + 1, n - 1
    while lo < hi:
        s = a[i] + a[lo] + a[hi]
        if s < T: lo += 1
        elif s > T: hi -= 1
        else: emit(); lo += 1; hi -= 1; skip_copies(lo)

Skipping duplicate anchors: which test is right?

  1. nums[i] == nums[i + 1]: skip
  2. i > 0 and nums[i] == nums[i - 1]: skip
  3. skip every repeated value anywhere
  4. no skip; dedupe with a set at the end
Comparing with the NEXT value skips the first copy and loses triplets such as [-1, -1, 2].

When can you stop the outer loop early?

  1. when nums[i] >= 0
  2. when nums[i] > 0 (the sorted suffix cannot sum to 0)
  3. after n/3 steps
  4. never
With nums[i] == 0 you still need [0, 0, 0].

After a hit, what do you do with lo and hi?

  1. stop
  2. move both inwards and skip copies of the values just used
  3. move only lo
  4. reset to the ends
Otherwise the same triplet is reported again.
