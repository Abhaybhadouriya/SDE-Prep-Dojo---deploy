The problem (in our words)

You are given an integer array nums (think of it as a list of ledger entries). Return every distinct triplet [nums[i], nums[j], nums[k]] with i != j, i != k, j != k and nums[i] + nums[j] + nums[k] == 0. Two triplets are the same if they hold the same three values (in any order); the answer must not contain the same triplet twice. The triplets, and the numbers inside each, may be returned in any order.

Signature: List<List<Integer>> threeSum(int[] nums) (LeetCode style: read the array, return a list of 3-element lists).

  • 3 <= nums.length <= 3000
  • -105 <= nums[i] <= 105

Practice it: LeetCode 15 · GfG All Triplets with Zero Sum · TUF article

Constraints tell you: n ≤ 3000 means O(n³) = 2.7·1010 is far too slow, while O(n²) = 9·106 is easy. Values are at most 105 in size, so a sum of three is at most 3·105: a 32-bit int is safe. Sorting (n log n) is free next to n².
