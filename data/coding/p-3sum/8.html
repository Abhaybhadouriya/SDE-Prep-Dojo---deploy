Common mistakes

Skipping duplicates of i the wrong way. if nums[i] == nums[i+1]: continue skips the first copy, so [-1,-1,2] is lost. Compare with the previous element: i > 0 and nums[i] == nums[i-1].

Deduplicating before every move. Skipping copies of lo when the sum is not zero is harmless but noisy; skipping copies before checking a hit loses [-2,1,1]. Only skip after recording.

Using a set of lists to remove duplicates. It works but hides the reasoning and costs O(answer) memory; in Java, a HashSet<List<Integer>> of unsorted lists does not dedupe [0,-1,1] vs [-1,0,1] at all.

Forgetting lo < hi inside the skip loop. while nums[lo] == nums[lo-1]: lo += 1 runs off the end on [0,0,0,0].

Early break on nums[i] >= 0. That drops [0,0,0]. Break only when nums[i] > 0.
