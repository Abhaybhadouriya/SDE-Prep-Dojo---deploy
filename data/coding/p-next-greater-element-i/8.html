Common mistakes

Keeping an increasing stack. For next greater, pop while the top is smaller than x; the stack is decreasing. Mixing up the direction answers next smaller instead.

Using <= vs < carelessly. "Strictly greater" means pop on top < x. Values are unique here, but in LC 503 and 739 equal values exist and the choice matters.

Running the stack over nums1. The "right side" is defined in nums2. nums1 is only a list of queries in any order.

Forgetting the leftovers. Values never popped need -1: use getOrDefault(q, -1) or fill the map at the end.

Calling it O(n²) because of the nested loop. Count pushes and pops instead: each value is pushed once and popped at most once.
