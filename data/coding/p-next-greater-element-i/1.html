The problem (in our words)

The next greater element of a value x in an array is the first value to the right of x that is strictly bigger than it, or -1 if there is none.

You get two arrays of distinct integers, nums1 and nums2, where every value of nums1 also appears in nums2. For each nums1[i], find its position j in nums2 and report the next greater element of nums2[j] inside nums2. Return an array ans of length nums1.length with these answers.

Signature: int[] nextGreaterElement(int[] nums1, int[] nums2).

Constraints:

  • 1 <= nums1.length <= nums2.length <= 1000
  • 0 <= nums1[i], nums2[i] <= 10^4
  • All values in nums1 and in nums2 are unique.
  • Every value of nums1 also appears in nums2.
  • Follow-up: can you do it in O(nums1.length + nums2.length)?

Practice it: LeetCode 496 · TUF: next greater element · GfG: Next Greater Element (the plain "for every element" version).

Constraints tell you: with n = 1000, even O(n·m) = 106 passes, so the brute force is accepted. The interview is about the follow-up: the linear stack solution. Unique values is why a value -> answer map works; with duplicates you would key by index instead.
