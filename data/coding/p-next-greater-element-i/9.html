60-second recall

  • Cue: "first bigger to the right" for many elements -> decreasing monotonic stack.
  • Insight: the value that pops y is y's next greater element; never popped = -1.
  • State: stack of waiting values (decreasing), map value -> answer.
  • Trap: stack runs over nums2, not nums1; strict <; default -1.
  • Cost: O(n + m) time (each value pushed and popped once), O(m) space.
stack, nxt = [], {}
for x in nums2:
    while stack and stack[-1] < x:
        nxt[stack.pop()] = x
    stack.append(x)
return [nxt.get(q, -1) for q in nums1]

For next greater, the waiting values on the stack are always...

  1. increasing from bottom to top
  2. decreasing from bottom to top
  3. in no fixed order
A bigger new value would have popped any smaller value below it.

nums2 = [3, 1, 2]. What is the next greater element of 3?

  1. -1
  2. 2
  3. 1
2 pops 1 and stops at 3; nothing bigger than 3 ever arrives.

Why is the total time O(m) even with the inner while loop?

  1. The while loop runs at most once
  2. The values are unique
  3. Each value is pushed once and popped at most once
Total pops can never exceed total pushes.
