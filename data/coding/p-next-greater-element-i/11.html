The array is circular: after the last element, wrap to the first.

Loop i from 0 to 2n - 1 using nums[i % n]; push indexes only when i < n. The second lap only answers values still waiting. O(n). That is LC 503.

How to answer

Explain why two laps are enough: any next greater is within n steps.

Likely follow-ups
  • Why push indexes now? Values may repeat in LC 503.
Values can repeat. What breaks?

The value -> answer map: two equal values can have different answers. Push indexes on the stack and store ans[index]. If queries are by value, ask which occurrence they mean.

How to answer

Point at the constraint that made the map valid ("all values unique").

Likely follow-ups
  • Pop on < or <=? Strictly greater means pop on <; equal values keep waiting.
Return the distance to the next greater element instead of its value.

Push indexes; when i pops index j, the answer for j is i - j. That is Daily Temperatures (LC 739).

How to answer

Show it is the same loop with indexes.

Likely follow-ups
  • Previous greater element? Scan right to left, or read the stack top before pushing.
nums2 is a stream; answer queries as values become resolved.

The stack works online: each arriving value pops and resolves waiting values right away, so you can emit answers as they happen. Memory is the size of the current decreasing run, which can be O(n) for a falling stream.

How to answer

Note what is bounded (work per element, amortised) and what is not (stack size).

Likely follow-ups
  • Bound memory: only track values that are in the query set.
Find the second greater element for each value (LC 2454).

Use two stacks. Values popped from the first stack (they found their first greater) move to the second stack in the same order; a later value that beats them on the second stack is their second greater. Still O(n).

How to answer

Describe the "waiting for the 1st" and "waiting for the 2nd" groups.

Likely follow-ups
  • Why must the moved block keep its order? So the second stack stays decreasing.
