1. Brute force - repeatedly scan for a free level

Idea: simulate: n times, scan all levels for one that is not done and has all prerequisites done; mark it done. If a scan finds none while levels remain, return false.

O(V^2 + E)time (with in-degree counts)
O(V + E)space

What is wasted: each round rescans all V levels to find one free level, although only the neighbours of the level we just finished can have become free. -> keep the free ones in a queue (rung 3), or switch to DFS (rung 2).

2. Better - DFS with three colours

Graph: edge b -> a per rule. Traversal: DFS from every unvisited node. Visited rule: white = not seen, grey = on the current DFS path, black = fully explored. Answer: meeting a grey node means we came back to our own path: a cycle, return false.

def dfs(u):
    color[u] = GREY
    for v in adj[u]:
        if color[v] == GREY or (color[v] == WHITE and not dfs(v)):
            return False
    color[u] = BLACK
    return True
O(V + E)time
O(V + E)space incl. recursion

Why it is not our first pick: it is optimal in time, but the recursion can be V deep (Python needs sys.setrecursionlimit for a 2000-chain), and "grey vs black" is easy to mix up under pressure. Two states (visited / not) is a classic bug: a black node reached again by a second path is not a cycle.

3. Optimal - Kahn's algorithm (BFS on in-degrees)

ready = deque(c for c in range(n) if waiting[c] == 0)
while ready:
    c = ready.popleft(); taken += 1
    for nxt in after[c]:
        waiting[nxt] -= 1
        if waiting[nxt] == 0: ready.append(nxt)
return taken == n
  1. Count what each level still waits for. waiting[a] = number of rules [a, *] = in-degree of a.
  2. Zero means ready. Every level with nothing missing goes into a queue.
  3. Finishing a level releases its dependants. Decrement each neighbour; one that hits 0 joins the queue.
  4. Count, do not search for cycles. If all n levels were taken, there is no cycle. Anything left is on a cycle or waits on one.
O(V + E)time
O(V + E)space
0recursion

Why it works: a level on a cycle can never reach in-degree 0, because the cycle edge pointing into it comes from a level that is itself waiting. Conversely, a finite graph with no cycle always has at least one node with in-degree 0 (walk backwards along incoming edges; without a cycle the walk must stop), and removing it leaves another acyclic graph. So Kahn's loop takes everything exactly when there is no cycle.

Proof (optional)

Suppose the loop stops with a set S of untaken levels, S non-empty. Every node in S has in-degree at least 1 counting only edges from S (edges from taken nodes were already subtracted). Start at any node in S and repeatedly step to one of its in-neighbours inside S. S is finite, so some node repeats: that is a directed cycle. Hence "taken < n" implies a cycle, and a cycle implies "taken < n" by the argument above.
