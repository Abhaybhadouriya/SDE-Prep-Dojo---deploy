Interview follow-ups

Return a valid order of levels.

How to answer: record pops in a list (LC 210). Return it if its length is n, else an empty list.

Likely follow-ups: the lexicographically smallest order - replace the queue with a min-heap: O((V + E) log V).

What is the minimum number of terms if any number of levels can be taken per term?

How to answer: process Kahn in layers (like level-order BFS); the number of layers is the answer, or -1 on a cycle. That is the longest path in the DAG.

Likely follow-ups: at most k per term - LC 1494, a bitmask DP, much harder.

Print the cycle when the answer is false.

How to answer: DFS with colours and a parent array; when you meet a grey node v from u, walk parents from u back to v.

Likely follow-ups: Kahn alone cannot show the cycle, but the leftover nodes are a superset of it.

Rules arrive one at a time; after each, say whether it is still finishable.

How to answer: before adding b -> a, check whether a already reaches b (DFS/BFS, O(V + E) per rule). If yes the new rule closes a cycle.

Likely follow-ups: faster incremental topological order algorithms exist, but per-query search is the expected interview answer.

DFS or BFS - which do you prefer here and why?

How to answer: same O(V + E). Kahn is iterative (no stack overflow on a 2000 chain), produces the order directly, and its correctness is a simple count. DFS is better when you need the cycle itself or post-order for other reasons.

The graph is huge and spread over machines (a build system).

How to answer: Kahn parallelises naturally: every node in the ready set can run at once; workers decrement shared in-degree counters atomically and push newly ready nodes. That is how build tools schedule jobs.
