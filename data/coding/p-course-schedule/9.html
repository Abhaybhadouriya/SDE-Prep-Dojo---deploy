  • Cue: "b before a" rules + "can all be done / give an order" -> topological sort.
  • Insight: finishable iff the directed graph has no cycle; Kahn takes all n iff acyclic.
  • State: adjacency b -> a, in-degree per node, queue of in-degree 0, taken count.
  • Trap: edge direction; seed every 0 in-degree; DFS needs grey (on path) vs black.
  • Cost: O(V + E) time and space; no recursion with Kahn.
indeg = [0]*n; adj = [[] for _ in range(n)]
for a, b in edges: adj[b].append(a); indeg[a] += 1
q = deque(i for i in range(n) if indeg[i] == 0); order = []
while q:
    u = q.popleft(); order.append(u)
    for v in adj[u]:
        indeg[v] -= 1
        if indeg[v] == 0: q.append(v)
ok = len(order) == n

The pair [a, b] means what edge?

  1. a → b
  2. b → a (take b first)
  3. an undirected edge
  4. a self-loop
[a, b] says you need b before a, so b points to a and a's in-degree goes up. Getting the direction backwards still detects cycles, but gives the reverse order in 210.

Kahn's algorithm pops 4 of 6 courses and the queue is empty. What does that mean?

  1. the answer is true
  2. there is a cycle, so the answer is false
  3. two courses have no prerequisites
  4. the graph is disconnected
Every node on or after a cycle keeps in-degree > 0 and is never popped. All n popped means no cycle.

DFS cycle check: why do you need three colours (white, grey, black) and not one visited flag?

  1. to make it faster
  2. a visited node that is already finished (black) is not a cycle; only a node still on the current path (grey) is
  3. to support undirected graphs
  4. to sort the output
With one flag, reaching a finished node through a second path looks like a cycle, a false positive in a DAG with a diamond.
