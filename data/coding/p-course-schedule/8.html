Common mistakes

  • Reversing the edge. [a, b] means b before a, so the edge is b -> a and waiting[a]++. Reversed edges still give the right yes/no for 207 (a cycle reversed is a cycle), but give the wrong order in 210 - so build it right from the start.
  • DFS with only "visited". A node reached twice through two different paths (a diamond) is not a cycle. You need the "on the current path" state (grey).
  • Starting Kahn from node 0 only. Seed the queue with every node of in-degree 0, or disconnected parts are missed.
  • Treating it as undirected cycle detection (union-find). 0->1, 0->2, 1->2 has an undirected loop but is finishable.
  • Returning queue empty instead of comparing the count. The queue is always empty at the end; the signal is taken == n.
