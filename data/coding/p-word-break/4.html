Approaches: brute → better → optimal

Hint 1

Look at the last word of a valid split. It ends at the end of s. What must be true about the part before it?

Hint 2

Define a yes/no answer for every prefix. The empty prefix is "yes".

1. Brute force - try every first word, recurse on the rest

Idea: for each dictionary word that is a prefix of s, cut it off and ask the same question about the remaining suffix. An empty remainder means success.

O(2^n)time (worst case)
O(n)stack depth

Why 2^n and not n^n: a split is fully described by which of the n - 1 gaps between letters are cuts, so there are at most 2^(n-1) splits. Input "aaa...ab" with words a, aa, aaa, ... makes the recursion visit all of them before failing on the b. (This is the argument in the top-voted community post linked below.)

What is wasted: the call for "the suffix starting at i" is the same no matter how we got to i. There are only n + 1 starting points.

2. Better - memoise on the start index (top-down)

Idea: the same recursion, with memo[i] = can s[i..] be split. Each i is solved once; solving it tries every end j > i and checks s[i..j) in a hash set.

O(n²·n)time (n² substrings, each hashed in O(n))
O(n)memo + stack

What is wasted: trying ends j far beyond the longest dictionary word, and a recursion stack 300 frames deep. Both are fixed by the bottom-up form with a length cap.

3. Optimal - bottom-up prefix DP with a length cap

ok = [True] + [False] * n                 # ok[0]: empty prefix
for i in range(1, n + 1):
    ok[i] = any(ok[j] and s[j:i] in words
                for j in range(max(0, i - L), i))
return ok[n]
  1. State: ok[i] = the prefix s[0..i) (first i letters) can be split into dictionary words.
  2. Transition: ok[i] = true if there is a j with ok[j] true and s[j..i) in the word set. j only needs to go back L = longest word length.
  3. Base case: ok[0] = true. The empty prefix needs zero words; without this seed nothing ever becomes true.
  4. Answer: ok[n].
  5. Space optimisation: none needed (n + 1 booleans). You cannot keep only a window of L values cheaply in all languages, and it buys nothing at n = 300.
  6. Top-down version: rung 2 with the same length cap; fine to code if the interviewer likes recursion.
O(n·L²)time (n ends × L lengths × hash of L chars)
O(n + D)space (ok[] + word set of D chars)

Why it works: in any valid split of a prefix, the last word starts at some j and the words before it are a valid split of s[0..j). So ok[i] is true exactly when such a j exists. We fill i from left to right, so every ok[j] with j < i is final when we read it.

Proof (optional)

Induction on i. ok[0] is correct (the empty split). Assume ok[j] is correct for all j < i. If the prefix of length i has a split w1..wk, let j = i - |wk|; then w1..w(k-1) splits s[0..j), so ok[j] is true, and s[j..i) = wk is a word, so the loop sets ok[i]. Conversely, if the loop sets ok[i] through some j, a split of s[0..j) followed by s[j..i) is a split of s[0..i). The length cap is safe because |wk| ≤ L.

4. Alternatives worth naming

  • BFS over start indices: nodes 0..n, an edge i → j when s[i..j) is a word; ask if n is reachable from 0 with a visited array. Same complexity; some people find the graph view easier to explain.
  • Trie instead of a hash set: from each true start i, walk a trie of the words along s[i..]; every word-end node marks ok[i + depth]. No substrings are built, so it is O(n·L) and is the right answer to "the dictionary is huge".
