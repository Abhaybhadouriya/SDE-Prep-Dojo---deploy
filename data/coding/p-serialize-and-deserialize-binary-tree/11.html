Interview follow-ups

Make the string smaller.

Drop trailing "#" tokens; use a binary format (2 bytes per value since |val| <= 1000, plus a bitmap of which child slots are present: 2 bits per node); or, if it is a BST, store only the preorder values (LC 449). For general trees the shape needs about 2 bits per node at minimum, because there are Catalan(n) ≈ 4n shapes.

How to answer

Separate the cost of the values from the cost of the shape, then shrink each.

Likely follow-ups
  • Varint encoding for wide value ranges.
Preorder or level order: which would you choose?

Both are O(n). Preorder gives the shortest code and streams subtree by subtree (good for lazy loading a subtree), but recursion depth is O(h). Level order is iterative and matches LeetCode's display format, but the queue can hold O(width) ≈ n/2 nodes for a complete tree. For a very deep tree choose BFS or an explicit-stack preorder.

How to answer

Name the trade-off in terms of height vs width.

Likely follow-ups
  • Write the preorder version without recursion.
What if node values are arbitrary strings that may contain commas or "#"?

Use length-prefixed tokens (5:hello) or escape the delimiter, exactly as in Encode and Decode Strings. A null can be a length of -1 or a distinct tag byte.

How to answer

Say "never rely on a delimiter that can appear in the data".

Likely follow-ups
  • Unicode lengths: count bytes, not characters.
The tree is too large for memory. How do you serialize to disk and load part of it?

Preorder streams naturally: write tokens to a file as you traverse. Store, for each node, the byte offset of its right subtree (or the subtree size) so a reader can skip a whole left subtree without parsing it. This is how B-tree pages and some on-disk indexes are laid out.

How to answer

Move from "string" to "file with offsets"; show you think about I/O.

Likely follow-ups
  • Concurrent readers while one writer appends.
Serialize a general graph (with cycles) instead of a tree.

Give every node an id on first visit (BFS/DFS with a visited map), write the node list with values, then the edge list as id pairs. The reader creates all nodes first, then links them. This is Clone Graph done through a string.

How to answer

The visited map replaces the null markers: shared nodes must be written once.

Likely follow-ups
  • Copy List with Random Pointer uses the same id idea.
