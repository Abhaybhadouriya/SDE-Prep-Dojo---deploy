Approaches: brute -> better -> optimal

Hint 1

Why can you not rebuild a tree from its preorder alone? What information is missing?

Hint 2

Write something for every null child. Now, while reading, how do you know when a subtree ends?

1. Two traversals (preorder + inorder)

Idea: store both the preorder and the inorder sequence; rebuild with the classic "root splits the inorder" method (LeetCode 105).

O(n)time with a value -> index map
2nvalues stored

Why it fails here: it needs unique values to find the root in the inorder list; values here repeat (e.g. a tree of all 1s). It also stores everything twice. -> store the shape directly.

2. Better - preorder with null markers (recursive)

Idea: visit root, left, right; write the value, or "#" for null. To read, take the next token: "#" means null; otherwise make a node and recursively build its left subtree, then its right subtree, from the following tokens.

def ser(node):
    if not node: out.append("#"); return
    out.append(str(node.val)); ser(node.left); ser(node.right)

def build(it):                      # it = iterator over the tokens
    v = next(it)
    if v == "#": return None
    node = TreeNode(int(v))
    node.left = build(it); node.right = build(it)
    return node
O(n)time both ways
O(h)recursion depth (h up to n)

Why it works: by induction on the tree size, build reads exactly the tokens that ser wrote for one subtree and no more: a "#" is a complete subtree of one token, and a value is followed by the complete encodings of its left and then right subtree. So the reader always knows where a subtree ends, even with duplicate values. This is the most-voted community approach.

What could be better: the depth of the recursion equals the height of the tree; a 104-node chain overflows Python's default stack. -> do the same idea level by level with a queue.

3. Optimal (iterative) - level order with null markers

  • Serialize: BFS from the root. Pop a node: if null, write "#"; else write its value and push both children, null or not.
  • Deserialize: token 0 is the root (or "#" = empty). Keep a queue of parents; each popped parent consumes the next two tokens as its left and right child, and real children join the queue.
O(n)time both ways
O(n)queue + string (width of the tree)

Why it works: the writer emits the children of the nodes in the order the nodes were dequeued, and the reader dequeues parents in that same order, so every pair of tokens is given to the right parent. A tree with n nodes has exactly n + 1 null children (2n child slots, n - 1 used by edges), so the string has 2n + 1 tokens and the reader uses all of them.

Size trick: trailing "#" tokens can be dropped (LeetCode's own format does this) if the reader treats "ran out of tokens" as null. It saves up to half the markers; we keep them for simpler code.
