Revision card

  • Cue: encode/decode a tree -> one traversal + a marker for every null child.
  • Insight: markers make the shape explicit: 2n + 1 tokens, works with duplicate values.
  • State: a token cursor read in the writer's order (preorder: recursion; BFS: each parent takes two).
  • Trap: separator for negatives, StringBuilder, deep recursion in Python, local cursor.
  • Cost: O(n) time and space both ways.
tok = data.split(","); root = node(tok[0]); q = deque([root]); i = 1
while q:
    p = q.popleft()
    p.left = node(tok[i]); p.right = node(tok[i + 1]); i += 2
    q.extend(c for c in (p.left, p.right) if c)   # node("#") -> None

Quick quiz

Why must the string record null children?

  1. to make it shorter
  2. a preorder list without nulls cannot tell left from right children
  3. the problem says so
  4. to support negative values
Preorder alone fits many trees; null markers pin down exactly where each subtree ends.

Values can be negative or multi-digit. What prevents misreading -12?

  1. fixed-width numbers
  2. nothing is needed
  3. a separator between tokens
  4. storing values in hex
Splitting on a comma gives whole tokens, so '-12' is read as one value.

In the BFS reader, how many tokens does each dequeued non-null node consume?

  1. exactly two (its left and right child)
  2. one
  3. as many as its subtree size
  4. zero if it is a leaf
The writer emitted two child slots for every real node, null or not, so the reader takes two.
