The alphabet is all of Unicode, not 26 letters.

Use a hash map for diff and count mismatched = number of keys with a non-zero value; record a start when it is 0. Delete a key when its value returns to 0 so the map holds at most m + m keys. Time stays O(n + m) expected; the 26-step compare would now be O(distinct characters), which is why the counter matters here.

How to answer

Say why approach 2 degrades and approach 3 does not.

Many patterns p1 .. pq, all of the same length, against one long s.

Slide one window over s and compute a canonical key for it in O(1) per step: an order-independent hash such as the sum of random 64-bit values per letter. Put each pattern's key in a hash map. For each window, look up its key, then confirm with a 26-slot compare (or trust the hash with a stated collision probability). O(n + total pattern length).

How to answer

Turn "compare with one target" into "look up in a set of targets"; that needs a key, not a counter.

Likely follow-ups
  • Patterns of different lengths: one sliding pass per distinct length.
Return only the number of anagram windows, with O(1) extra space.

Replace the result list with an integer. The diff array is 26 integers, so extra space is O(1). That is the GfG "Count Occurrences of Anagrams" version.

How to answer

Point out that the output list is the only non-constant memory.

Likely follow-ups
  • Count the distinct anagram substrings instead: hash each matching window's text into a set.
s is a live stream of characters; report each match as soon as it ends.

Keep a ring buffer of the last m characters (so you know which letter leaves), the diff array and matched. On each new character: update(in, -1), and once the buffer is full update(out, +1) for the evicted one; emit the start position when matched == 26. O(1) per character, O(m) memory.

How to answer

Name the minimum state: the window contents and the diff table.

Likely follow-ups
  • Bound memory below O(m)? Not exactly: you must know the leaving letter.
Each window may differ from an anagram of p in at most k letters.

Both strings have length m, so the number of letters to replace is half of Σ|diff[c]|. Maintain absSum = Σ|diff[c]| in O(1) per update (it changes by exactly ±1) and record when absSum / 2 <= k. Still O(n + m).

How to answer

Generalise matched: any aggregate of diff that changes in O(1) per update works.

Likely follow-ups
  • Why half? Equal lengths: total surplus equals total shortage.
