Interview follow-ups

Minimise the number of writes.

The one-pass swap with the r != w guard writes only when a zero sits before a non-zero; each such non-zero costs one swap. With no zeros it writes nothing, while compact-and-fill always writes n slots.

How to answer

Compare both versions on [1,2,3,0] (0 swaps vs 4 writes) and on [0,1,2,3] (3 swaps = 6 writes vs 4 writes): say which one wins when zeros are rare or common.

Likely follow-ups
  • Count the swaps exactly: the number of non-zeros that have at least one zero before them.
Move the zeros to the front instead, keeping the order of the non-zeros.

Mirror the loop: scan from the right with the write pointer starting at n - 1, and swap each non-zero into it while moving left.

How to answer

Point out that the direction of the scan must match the side where the kept items go, otherwise their order flips.

Likely follow-ups
  • Generalise: move every element equal to k to the end.
The order of the non-zeros does not matter. Can you do fewer writes?

Yes: two pointers from opposite ends. Move the left pointer to the next zero and the right pointer to the last non-zero, swap, repeat. Each zero that is not already in the tail costs exactly one swap.

How to answer

Say this is the Quicksort partition step; it is not stable, which is why it is wrong for the original task.

Likely follow-ups
  • Which one is cache-friendlier? Both are sequential; the same-direction scan touches memory strictly left to right.
Do the same on a singly linked list.

Build two chains with dummy heads: one for non-zero nodes, one for zero nodes. Walk once, append each node to its chain, then link the non-zero tail to the zero head and terminate the last node. O(n) time, O(1) extra, and stable for free.

How to answer

Relink nodes instead of copying values; mention clearing the final next to avoid a cycle.

Likely follow-ups
  • This is the same as Partition List (LC 86) with "x = 0".
The data is a huge file that does not fit in memory.

Stream it: write every non-zero to the output as you read it and only count the zeros; at the end, write that many zeros. One sequential read, one sequential write, O(1) memory. It is the two-pass idea with the second pass replaced by a counter.

How to answer

Show that "in place" stops mattering once the data is streamed; what matters is sequential I/O.

Likely follow-ups
  • Split across machines: each shard compacts locally, then a concatenation of the non-zero parts and a zero tail of size sum(counts).
