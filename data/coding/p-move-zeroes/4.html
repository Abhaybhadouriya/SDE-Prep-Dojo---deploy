Approaches: brute -> better -> optimal

Hint 1

If you were allowed a second array, how would you fill it? Now notice that the "second array" can be the front of the same array.

Hint 2

The place where the next non-zero belongs is never ahead of the element you are reading.

1. Brute force - extra array (or bubble the zeros)

Idea: copy the non-zeros into a new array in order, pad with zeros, copy back. Correct and O(n), but it breaks the "in place" rule. The in-place brute force is to bubble each zero to the end by repeated adjacent swaps, which is O(n2) when many zeros sit at the front.

O(n)time (copy) / O(n²) (bubble)
O(n)extra (copy) / O(1) (bubble)

What is wasted: the copy needs a buffer we do not have to allocate; the bubble moves the same zero many times. Each non-zero needs to move exactly once, to a known slot.

2. Better - two passes: compact, then fill

w = 0
for x in nums:
    if x != 0: nums[w] = x; w += 1
for i in range(w, len(nums)): nums[i] = 0

Idea: the first pass copies each non-zero down to slot w. It is safe because w <= r always: we only overwrite slots we have already read. The second pass writes zeros over the tail.

O(n)time
O(1)space
nwrites, always

What is wasted: it writes every slot even when the array has no zeros ([1,2,3] still costs 3 writes plus 0 fills). The follow-up asks to minimise operations.

3. Optimal - one pass, swap into the write slot

w = 0
for r in range(len(nums)):
    if nums[r] != 0:
        if r != w: nums[w], nums[r] = nums[r], nums[w]
        w += 1
  1. Invariant: nums[0..w) is every non-zero seen so far, in input order; nums[w..r) is all zeros.
  2. A zero at r just extends the zero block: r++, nothing written.
  3. A non-zero at r swaps with nums[w], which is the first zero of the block (or itself if the block is empty). The non-zero joins the front; the zero moves to the back of the block.
  4. The r != w guard skips self-swaps while no zero has been seen, so an array without zeros costs no writes.
O(n)time, one pass
O(1)space
≤ #non-zerosswaps

Why it works: the swap never changes the order of non-zeros, because each one is placed at the very next free slot when it is read, and they are read left to right. Zeros only ever trade places with zeros or move right, so when r reaches the end the block [w, n) is the tail of zeros. The top-voted community solution calls this the "snowball": the zeros gather into a ball that rolls forward through the array.

Proof (optional)

Induction on r. Initially w = r = 0 and both ranges are empty. If nums[r] = 0, the zero block grows to [w, r+1). If nums[r] ≠ 0 and the block is empty (w = r), nothing changes except w and r both grow. If the block is non-empty, nums[w] = 0; swapping puts the non-zero at w (the next position after the earlier non-zeros, so order holds) and the zero at r (the new end of the block). At r = n the block is [w, n), which is exactly "all zeros at the end".
