60-second recall

  • Cue: in place + keep order + push matching items to one end -> reader/writer pointers.
  • Insight: [0,w) = kept items in order, [w,r) = zeros; swap a non-zero into slot w.
  • State: w (next write slot), r (next read); w <= r always.
  • Trap: back-swap breaks order; skip self-swap when r == w to minimise writes.
  • Cost: O(n) time, O(1) space, one swap per non-zero at most.
w = 0
for r in range(len(a)):
    if keep(a[r]):
        a[w], a[r] = a[r], a[w]   # or a[w] = a[r] when the tail is ignored
        w += 1
# a[:w] = kept items in order

[0, 1, 0, 3, 12] with the swap version (w = write slot). What does the array hold after r = 3?

  1. [1, 3, 0, 0, 12]
  2. [1, 0, 3, 0, 12]
  3. [1, 3, 12, 0, 0]
  4. [0, 1, 3, 0, 12]
r = 1 swaps into slot 0, r = 3 swaps into slot 1, and w = 2. The 12 moves at r = 4.

A version swaps zeros at the front with non-zeros taken from the back. It is in place and O(n). What does it break?

  1. The relative order of the non-zero values
  2. O(n) time
  3. O(1) space
  4. All-zero arrays
The problem requires the non-zero values to keep their order. Only the forward writer/reader scan keeps it.

Why skip the swap when r == w?

  1. It would swap an element with itself: harmless, but a wasted write
  2. It corrupts the array
  3. [0] fails without it
  4. It changes the order
The follow-up asks you to minimise writes, and a self-swap is a write that changes nothing.
