Common mistakes

Swapping with the back. Two pointers from opposite ends (swap a zero with the last non-zero) is fast but breaks the relative order of the non-zeros: [0,1,2] becomes [2,1,0].

Erasing inside a loop. nums.erase(it) + push_back(0) (or list.remove in Python) is O(n) per zero, so O(n2), and it is easy to skip the element after the erased one.

Sorting with a custom key. sort(key=lambda x: x == 0) works only because Python's sort is stable, and it is O(n log n); std::sort is not stable and scrambles the order.

Forgetting the fill in the two-pass version. After compacting, the old values are still in the tail: [0,5] becomes [5,5] until you write the zeros.

Returning a new array. The judge reads the array you were given; in Python, nums = [...] rebinds a local name and the caller sees nothing. Use nums[:] = ... or write in place.
