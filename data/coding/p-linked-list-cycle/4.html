Approaches: brute -> better -> optimal

Hint 1

What do you remember in the simple solution, and could two moving pointers replace that memory?

Hint 2

If two pointers are both inside the loop and one moves one node per round faster, how does the gap between them change?

1. Brute force - count steps

Idea: walk the list; if you take more than 104 steps (the maximum length) without reaching null, there must be a loop.

O(Nmax)time
O(1)extra space

What is wasted: it only works because the judge told you a length limit; in real code there is none. Say it as a joke, not as the answer.

2. Better - hash set of visited nodes

Idea: walk the list and store each node's address. If you meet an address that is already in the set, there is a cycle; if you reach null, there is not.

O(n)time
O(n)extra space

What is wasted: n stored pointers. A destructive O(1) trick (point each visited node's next at a sentinel) also works, but it breaks the list.

3. Optimal - Floyd's tortoise and hare

slow = fast = head
while fast and fast.next:
    slow, fast = slow.next, fast.next.next
    if slow is fast:
        return True
return False
  1. No loop: fast finds the end. fast is always ahead, so if there is a null it meets it first, after about n/2 rounds. Checking fast and fast.next makes the two-step move safe.
  2. Loop: both get inside. After at most μ rounds slow enters the loop; fast is already in it.
  3. The gap shrinks by one per round. Measure how far fast is behind slow going round the loop: d, with 0 < d < λ. Each round slow adds 1 and fast adds 2, so d becomes d - 1. It cannot skip from 1 to -1: it goes 1, then 0, which means they are on the same node.
  4. So they meet within λ more rounds. Total work at most μ + λ rounds, which is at most n.
  1. Start: slow = fast = head (4). fast and fast.next exist, so the loop runs.
  2. Round 1: slow moves 1 to 9, fast moves 2 to 2. Both are now inside the loop. Going round the loop, fast is 3 steps behind slow.
  3. Round 2: slow → 2, fast → 7 → 5. Each round fast gains exactly one step, so the gap drops 3 → 2.
  4. Round 3: slow → 7, fast → 9 → 2 (it went round the back edge). Gap 1.
  5. Round 4: slow → 5, fast → 7 → 5. slow == fast: return true. It took 4 rounds, never more than μ + λ.
O(n)time: at most μ + λ rounds
O(1)extra space: two pointers

Why it works: the only thing that matters is the relative speed. Seen from slow, fast moves one node per round towards it around the loop. A pointer that approaches one node at a time cannot overshoot, so the meeting is guaranteed. That is also why speed 2 is the natural choice: with speed 3 the relative speed is 2, and on a loop of even length with an odd gap the two pointers can jump over each other forever without ever landing on the same node.

Where do they meet, and why does that matter? (optional)

The meeting point is not the loop's entry in general. LC 142 asks for the entry: after the meeting, reset one pointer to the head and move both at speed 1; they meet exactly at the entry, because the distance from the head to the entry equals the distance from the meeting point to the entry, modulo λ. Mention this as the natural next step.
