The problem (in our words)

You get head, the first node of a singly linked list. Return true if the list contains a cycle: some node can be reached again by following next pointers. Otherwise return false.

Signature: boolean hasCycle(ListNode head).

How the judge builds the test: a value list plus an index pos. The tail's next points to the node at index pos, or to null when pos = -1. pos is not passed to your function.

Constraints

  • The number of nodes is in the range [0, 10^4].
  • -10^5 <= Node.val <= 10^5
  • pos is -1 or a valid index in the list.

Follow-up asked by the original: can you solve it with O(1) memory?

Practice it: LeetCode 141 - Linked List Cycle · GfG - Detect Loop in Linked List · TUF - Detect a cycle in a linked list

Constraints tell you: 104 nodes means a hash set is fine for time; the interview is about the O(1)-memory follow-up. The list can be empty (0 nodes), and values repeat, so "seen this value" is not "seen this node".
