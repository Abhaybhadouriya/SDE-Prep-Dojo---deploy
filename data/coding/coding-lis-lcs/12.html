Common mistakes

  • Returning dp[n-1] for LIS. The best run can end anywhere; return the max.
  • Wrong bound for "strict". upper_bound on a strict LIS counts [2, 2] as length 2. Use lower_bound / bisect_left.
  • Printing tails as the answer. It holds the best ending per length, not a real subsequence.
  • Envelopes sorted height-ascending on ties. Equal widths then nest. Sort heights descending within a width.
  • No empty row and column. Without the extra row/column you need special cases for i = 0 and j = 0, and off-by-one errors follow. Use (n+1) x (m+1) and index characters with i-1, j-1.
  • Forgetting the base cases of edit distance. Row 0 is 0..m and column 0 is 0..n, not all zeros. In the rolling version, set cur[0] = i at the start of every row.
  • 1-D loop in the wrong direction. In distinct subsequences, a forward j loop reads the new dp[j-1] and counts one character twice.
  • Regex: treating * on its own. * belongs to the character before it. Look ahead at p[j+1], and skip two pattern characters, not one.
  • Regex/wildcard: the i = n row. An empty rest of s can still match a* or *. Start i at n.
  • Interleaving without the length check. If n + m != len(s3) the answer is false; the table cannot tell you that.
