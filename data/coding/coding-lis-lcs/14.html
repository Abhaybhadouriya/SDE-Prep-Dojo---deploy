Revision card

  • Cue: Longest increasing subsequence, envelopes, LCS, edit distance, regex or wildcard match.
  • Insight: One string: best run ending at i. Two strings: dp over pairs of prefixes with three arrows.
  • State: tails[] with binary search (LIS); dp[i][j] of size (n+1) x (m+1) (two strings).
  • Trap: lower_bound vs upper_bound for strict vs non-decreasing; substring resets to 0, subsequence carries the best.
  • Cost: LIS O(n log n); two strings O(n m) time, O(min(n, m)) with one row.

More to remember

  • LIS: dp[i] = best run ending at i (O(n2)); tails = smallest tail per length, binary search (O(n log n)); answer = max, not the last cell.
  • Strict = lower_bound / bisect_left; non-decreasing = upper_bound / bisect_right.
  • Two keys: sort one up, the other down on ties, then LIS on the second.
  • Two strings: dp[i][j] over prefixes, size (n+1) x (m+1), three arrows: diagonal, up, left.
  • Optimise with max/min, count with +; in 1-D, loop backwards when you need the old left value.
  • Substring = reset to 0 on a mismatch; subsequence = carry the best.
  • Regex: x* is one token: skip it (j+2) or eat one and stay (i+1).
