LIS the simple way: O(n2)

Problem (restated from LeetCode 300, Longest Increasing Subsequence). You get an integer array nums. Return the length of the longest subsequence whose values are strictly increasing. Example: for [8, 6, 1, 4, 2, 5, 90, 12] the answer is 4 (for example 1, 4, 5, 90). For [3, 3, 3] the answer is 1, because equal values do not count as increasing. Limits: 1 <= n <= 2500 and -104 <= nums[i] <= 104. Follow-up: can you do it in O(n log n)?

Define dp[i] = the length of the longest increasing subsequence that ends exactly at index i. The words "ends at" matter: they make the state small enough to combine. To end at i, the step before must be some j < i with nums[j] < nums[i], and the best you can do is dp[j] + 1. If no such j exists, i starts its own run and dp[i] = 1.

Two loops, O(n2) time and O(n) memory. With n = 2500 that is about 3 million comparisons: fast enough for LeetCode 300. The answer is max(dp). It is not dp[n-1], because the best run may end anywhere. This "ends at i" state, combined by looking back at every earlier j, is the same shape you will reuse for string chains and divisible subsets below.

To print the subsequence itself, store parent[i] = j whenever dp[j] + 1 wins, then follow parents back from the index with the largest dp value. To count how many longest subsequences there are (LeetCode 673), keep cnt[i] next to dp[i]: when dp[j] + 1 beats dp[i], set cnt[i] = cnt[j]; when it ties, add cnt[j].
