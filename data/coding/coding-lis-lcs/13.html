Interview questions

Explain the O(n log n) LIS. Why is tails sorted, and why does replacing keep the answer right?

tails[k] is the smallest last value of any increasing run of length k+1 seen so far. It is sorted because the first k items of a length-(k+1) run form a length-k run that ends lower. A new x goes into the first slot with tails[k] >= x: it extends the run of length k (whose tail is < x) and gives a length-(k+1) run ending at x, which is no worse than the old tail. Appending means a new longest length. The length of tails only grows when a longer run really exists, so it equals the LIS length.

How to answer

Give the O(n2) dp first in one sentence, then the tails definition, the sortedness argument, and the strict vs non-strict bound. Trace a 6-element example by hand.

Likely follow-ups
  • Print the sequence. (tailIdx + prev arrays.)
  • Non-decreasing version? (upper_bound.)
  • Count the longest ones? (O(n2) with cnt[], or a Fenwick tree keyed by value for O(n log n).)
Russian doll envelopes: why sort heights descending for equal widths?

After sorting by width we want a strictly increasing run of heights to mean "nests". Two envelopes with the same width never nest, but if their heights were ascending, LIS would pick both. With heights descending inside one width, any strictly increasing run uses at most one envelope from each width group, so every step in the run has a strictly larger width and height.

How to answer

Show the counterexample [[4, 5], [4, 7]] first; then the fix; then O(n log n) by patience on heights.

Likely follow-ups
  • Rotation allowed? (Normalise each to (min, max) first; with 3-D boxes see LeetCode 1691.)
  • Return the nesting order? (Track indices in tails.)
Edit distance: what do the three neighbours mean, and how do you cut memory?

dp[i][j] is the cost to turn a[0..i) into b[0..j). Diagonal = match (free) or replace (+1); up = delete a[i-1]; left = insert b[j-1]. Base row 0..m and column 0..n. Each row reads only the row above and the cell to its left, so keep two rows and swap: O(nm) time, O(min(n, m)) memory.

How to answer

Draw a 3 x 3 corner of the table and label the arrows. Then the code, then the space trick. Mention that keeping the full table lets you print the edit script.

Likely follow-ups
  • Different costs per operation? (Put the costs on the arrows.)
  • Only "is the distance at most 1"? (One Edit Distance, LeetCode 161: a linear two-pointer scan.)
  • Distance at most k for long strings? (Only fill cells with |i - j| <= k: O(nk).)
LCS: prove that taking a matching last pair is always safe, and rebuild the string.

If a[i-1] == b[j-1] = c, take any optimal common subsequence of the two prefixes. If it does not end with c matched at these positions, either its last letter can be swapped for this pair, or c can be appended. Either way the length does not drop, so dp[i-1][j-1] + 1 is optimal. To rebuild, start at (n, m): on a match emit the letter and go diagonal, else move to the larger of up and left. Reverse the emitted letters.

How to answer

State the recurrence, give the exchange argument in two sentences, then the traceback.

Likely follow-ups
  • Delete operation, ASCII delete sum, supersequence: one line on top of LCS.
  • Memory O(m) and still print the string? (Hirschberg's divide and conquer: O(nm) time, O(m) memory.)
Regular expression matching with . and *: walk me through the recurrence and the edge cases.

dp[i][j] = does s[i..) match p[j..)? first = i < n and (p[j] == s[i] or p[j] == '.'). If p[j+1] == '*': dp[i][j] = dp[i][j+2] or (first and dp[i+1][j]). Else dp[i][j] = first and dp[i+1][j+1]. Base dp[n][m] = true, and i must run from n so that an empty rest of s can match a*b*. O(nm) time and memory.

How to answer

Start with recursion plus memo on (i, j), since it reads naturally, then show the table. Test with s = "", p = "a*"; s = "aa", p = "a"; s = "ab", p = ".*".

Likely follow-ups
  • How is wildcard different? (* is standalone: dp[i][j+1] or dp[i+1][j].)
  • Add '+'? (x+ = x then x*.)
  • Why not backtracking alone? (Exponential on patterns like a*a*a*...b.)
Distinct subsequences: why add the two arrows, and why loop backwards in 1-D?

For s[i-1] we either skip it (ways = dp[i-1][j]) or, if it equals t[j-1], use it as the last letter of t (ways = dp[i-1][j-1]). The two choices use different position sets, so the counts add. In one row, dp[j] needs the old dp[j-1]; looping j from m down to 1 reads dp[j-1] before it is updated.

How to answer

Contrast counting (add) with optimising (max/min) on the same grid. Mention overflow of middle values.

Likely follow-ups
  • Answer modulo 109+7? (Take mod on every add.)
  • Count distinct subsequences of s itself? (LeetCode 940: subtract the count at the last time this letter appeared.)
Interleaving string: why does greedy fail, and how do you get O(len(s2)) memory?

When both s1[i] and s2[j] equal the next character of s3, greedy has to guess, and a wrong guess fails later (s1 = "aab", s2 = "aac", s3 = "aacaab"). DP tries both: dp[i][j] = (dp[i-1][j] and s1[i-1] == s3[i+j-1]) or (dp[i][j-1] and s2[j-1] == s3[i+j-1]). Row i needs only row i-1 (same column) and the current row (left), so one array of size m+1 updated left to right works.

How to answer

Show the failing greedy case, then the length check, then the table as a right/down path.

Likely follow-ups
  • Return one valid weaving? (Keep the full table and walk back.)
  • Three source strings? (3-D state; same idea.)
Longest string chain: why sort by length, and what is the cost?

A predecessor is always exactly one letter shorter, so processing words by length guarantees every predecessor's answer is ready (a topological order of the DAG "A is a predecessor of B"). For each word, delete each of its L letters and look up the shorter word in a map: O(L) candidates, each O(L) to build and hash. Total O(n L2) after an O(n log n) sort, against O(n2 L) for checking all pairs.

How to answer

Name it as LIS on a DAG, give the sort, then the delete-one-letter lookup. Mention a bucket by length instead of sorting.

Likely follow-ups
  • Print the chain? (Store the best predecessor per word.)
  • Words up to length 1000? (The L2 factor hurts; compare pairs of adjacent lengths with a two-pointer check instead.)
