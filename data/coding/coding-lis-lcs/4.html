The LIS family: chains and envelopes

Longest string chain

Problem (restated from LeetCode 1048, Longest String Chain). You get a list of words made of lowercase letters. Word A is a predecessor of word B if you can insert exactly one letter anywhere into A, without moving the other letters, and get B. A chain is a sequence of words where each word is a predecessor of the next; a single word is a chain of length 1. Return the length of the longest chain you can build from the list. Example: from ["c", "ca", "cat", "cart", "chart", "bat"] the chain c → ca → cat → cart → chart has length 5. Limits: 1 <= words.length <= 1000 and each word has 1 to 16 letters.

This is LIS where "comes after and is bigger" means "is one letter longer and contains the other". A predecessor is always shorter, so sorting by length gives an order in which every predecessor is handled first. Then, instead of scanning every earlier word (O(n2) pairs, each an O(L) check), go the other way: delete each of the word's L letters and look the result up in a hash map. That is O(n · L2) with L <= 16, the version most top-voted solutions use.

// Longest string chain: sort by length; dp[word] = 1 + best predecessor
// (delete each letter, look the result up).
func longestStrChain(words []string) int {
	sort.Slice(words, func(i, j int) bool { return len(words[i]) < len(words[j]) })
	dp := map[string]int{}
	best := 0
	for _, w := range words {
		cur := 1
		for k := 0; k < len(w); k++ {
			if v, ok := dp[w[:k]+w[k+1:]]; ok && v+1 > cur {
				cur = v + 1
			}
		}
		dp[w] = cur
		best = max(best, cur)
	}
	return best
}
// Longest string chain: sort by length, dp[word] = 1 + best over its
// one-letter-shorter predecessors (delete each letter, look it up).
int longestStrChain(vector<string> words) {
    sort(words.begin(), words.end(), [](const string& a, const string& b) { return a.size() < b.size(); });
    unordered_map<string, int> dp;
    int best = 0;
    for (auto& w : words) {
        int cur = 1;
        for (size_t k = 0; k < w.size(); k++) {
            auto it = dp.find(w.substr(0, k) + w.substr(k + 1));   // delete letter k
            if (it != dp.end()) cur = max(cur, it->second + 1);
        }
        dp[w] = cur;
        best = max(best, cur);
    }
    return best;
}
// Longest string chain: sort by length; dp[word] = 1 + best predecessor
// (delete each letter, look the result up).
static int longestStrChain(String[] words) {
    Arrays.sort(words, Comparator.comparingInt(String::length));
    Map<String, Integer> dp = new HashMap<>();
    int best = 0;
    for (String w : words) {
        int cur = 1;
        for (int k = 0; k < w.length(); k++)
            cur = Math.max(cur, dp.getOrDefault(w.substring(0, k) + w.substring(k + 1), 0) + 1);
        dp.put(w, cur);
        best = Math.max(best, cur);
    }
    return best;
}
def longest_str_chain(words: List[str]) -> int:
    """Sort by length; dp[w] = 1 + best predecessor (delete each letter, look it up)."""
    dp: dict[str, int] = {}
    for w in sorted(words, key=len):
        dp[w] = 1 + max((dp.get(w[:k] + w[k + 1:], 0) for k in range(len(w))), default=0)
    return max(dp.values(), default=0)

Russian doll envelopes

Problem (restated from LeetCode 354, Russian Doll Envelopes). Each envelope is a pair [w, h]. One envelope fits inside another only if both its width and its height are strictly smaller. You may not rotate envelopes. Return the largest number of envelopes you can nest one inside another. Example: [[4, 5], [4, 7], [2, 3], [5, 8]] gives 3 ([2, 3] inside [4, 5] inside [5, 8]). Limits: up to 105 envelopes, each side 1 to 105, so O(n2) is too slow.

Sort by width, then run LIS on the heights. The trap is equal widths: [4, 5] and [4, 7] must not nest, but sorted by height ascending they would look like a valid step 5 → 7. The fix is to sort equal widths by height descending. Then within one width the heights go down, and a strictly increasing run can use at most one envelope of each width. This tie-break is the whole interview question; say it before you code.

// Russian doll: width ascending, height DESCENDING on ties, then strict LIS on heights.
func maxEnvelopes(env [][]int) int {
	sort.Slice(env, func(i, j int) bool {
		if env[i][0] != env[j][0] {
			return env[i][0] < env[j][0]
		}
		return env[i][1] > env[j][1]
	})
	h := make([]int, len(env))
	for i, e := range env {
		h[i] = e[1]
	}
	return lisFast(h)
}
// Russian doll: sort width ascending, height DESCENDING for equal widths,
// then strict LIS on heights. The descending tie-break stops two envelopes
// of the same width from nesting.
int maxEnvelopes(vector<vector<int>> env) {
    sort(env.begin(), env.end(), [](const vector<int>& p, const vector<int>& q) {
        return p[0] != q[0] ? p[0] < q[0] : p[1] > q[1];
    });
    vector<int> tails;
    for (auto& e : env) {
        auto it = lower_bound(tails.begin(), tails.end(), e[1]);
        if (it == tails.end()) tails.push_back(e[1]);
        else *it = e[1];
    }
    return tails.size();
}
// Russian doll: width ascending, height DESCENDING on ties, then strict LIS on heights.
static int maxEnvelopes(int[][] env) {
    Arrays.sort(env, (p, q) -> p[0] != q[0] ? Integer.compare(p[0], q[0]) : Integer.compare(q[1], p[1]));
    int[] h = new int[env.length];
    for (int i = 0; i < env.length; i++) h[i] = env[i][1];
    return lisFast(h);
}
def max_envelopes(env: List[List[int]]) -> int:
    """Width ascending, height DESCENDING on ties, then strict LIS on heights."""
    env.sort(key=lambda e: (e[0], -e[1]))
    return lis_fast([h for _, h in env])

Two cousins use the same idea. Largest Divisible Subset (LeetCode 368): sort, then dp[i] = 1 + max dp[j] over j with nums[i] % nums[j] == 0, plus parents to print the set. Stacking cuboids (LeetCode 1691): rotation is allowed, so sort each cuboid's own sides first, then sort the list and run the O(n2) LIS, summing heights instead of counting.
