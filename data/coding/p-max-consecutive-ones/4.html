Approaches: brute -> better -> optimal

Hint 1

If you know the length of the run of 1s ending at index i - 1, what is the run ending at i?

Hint 2

Where in the loop must you update the answer so that [1, 1, 1] returns 3?

1. Brute force - extend from every start

Idea: for each index i, walk right while the elements are 1 and record how far you got.

O(n2)time (all 1s)
O(1)extra space

What is wasted: a start in the middle of a block re-counts the same 1s that the block's first index already counted.

2. Better - jump over whole blocks

Idea: the same scan, but after measuring a block from i to j, continue from j + 1 instead of i + 1. Every element is now visited once, O(n). It is correct, but needs an inner loop and careful index bumps; the running counter below is the same idea with one loop.

3. Optimal - running counter

best = run = 0
for x in nums:
    run = run + 1 if x == 1 else 0
    best = max(best, run)
return best
O(n)time: one pass
O(1)extra space: two integers

Why it works: the loop keeps the invariant "after processing index i, run = number of consecutive 1s ending exactly at i, and best = the longest block of 1s inside nums[0..i]". It holds at the start (both 0 for the empty prefix). A 1 at i extends the block ending at i - 1 by one; a 0 ends every block, so the run ending at i is 0. Every block of 1s ends at some index, and at that index run equals its full length, so taking the max at every index sees every block.
