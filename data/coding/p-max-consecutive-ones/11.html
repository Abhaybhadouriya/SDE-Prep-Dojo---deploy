Interview follow-ups

You may flip at most one 0. What is the longest block of 1s now?

Keep a window [l, r] with at most one 0 inside. Extend r; when a second 0 enters, move l to just after the previous 0 (store its index). The answer is the max window length. O(n), O(1). Equivalently keep two counters: the run ending here with no flip, and with one flip (withFlip = noFlip + 1 on a 0).

How to answer

Name the window invariant "at most one zero inside" before coding.

Likely follow-ups
  • Generalise to k flips (LC 1004).
Flip at most k zeros, and the input is an infinite stream.

With a window you would need to move l back over old elements, which a stream does not keep. Store only the positions of the last k + 1 zeros in a queue: when a new 0 arrives and the queue has k + 1 entries, pop the oldest; the window starts just after it. Memory O(k), not O(n).

How to answer

Point out that only zero positions matter for the left edge.

Likely follow-ups
  • k = 1: one variable for the last zero is enough.
Return the start and end index of the longest block, not just its length.

When run beats best at index i, record end = i and start = i - run + 1. On ties, decide (and say) whether you keep the first or the last block: > keeps the first.

How to answer

Derive the start from the run length instead of tracking another pointer.

Likely follow-ups
  • What should you return if there is no 1? (Agree on a sentinel such as [-1, -1].)
The input is a single 64-bit integer: longest run of 1 bits.

Repeat x &= (x << 1) and count iterations until x is 0: each step shortens every run of 1s by one, so the number of steps is the longest run. At most 64 iterations, no loop over individual bits needed.

How to answer

Explain why ANDing with the shifted value trims every run by one bit.

Likely follow-ups
  • Longest run of 0 bits? (Apply the same trick to ~x, minding the leading bits.)
The array is split across machines. How do you combine the answers?

Each machine returns four numbers for its chunk: its length, the longest run of 1s at its start (prefix), at its end (suffix), and the best run inside. Two neighbouring chunks merge as: best = max(bestA, bestB, suffixA + prefixB); prefix = prefixA, or lenA + prefixB if chunk A is all 1s; suffix similarly. It is an associative merge, so it also works as a segment-tree node.

How to answer

Give the summary each chunk returns and the merge rule.

Likely follow-ups
  • Support point updates and range queries (segment tree with the same node).
