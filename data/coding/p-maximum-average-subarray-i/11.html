Now the subarray may have any length >= k. Find the maximum average.

Comparing sums no longer works because lengths differ. Binary search on the answer m between min and max of nums: "is there a subarray of length >= k with average >= m?" is the same as "is there one with sum of (nums[i] - m) >= 0?". With prefix sums P of nums[i] - m, check whether P[j] - min(P[0..j-k]) >= 0 for some j, keeping a running minimum. Each check is O(n), about 40-50 iterations for 10-5 precision: O(n log(range / eps)).

How to answer

Say why the sum trick breaks, then turn the question into a yes/no check that is monotone in m.

Likely follow-ups
  • Why is the check monotone? (If average m is reachable, so is every smaller m.)
Return the start index of the best window too (first one on ties).

When the new sum is strictly greater than best, record start = i - k + 1. Strict > keeps the first window on ties; >= keeps the last. The first window has start 0.

How to answer

State the tie rule out loud before coding it.

Likely follow-ups
  • Return all windows that reach the maximum.
Numbers arrive as a stream. After each one, report the average of the last k.

Keep a ring buffer of size k and a running sum. On each new value, subtract the slot it overwrites (once the buffer is full) and add the new one. O(1) per value, O(k) memory. Before k values have arrived, divide by the count so far. This is LeetCode's "Moving Average from Data Stream" (Premium).

How to answer

Describe the ring buffer index i % k and the warm-up phase.

Likely follow-ups
  • Floating-point inputs over a long stream: the running sum drifts; recompute it from the buffer now and then, or use Kahan summation.
Report the maximum of every window instead of the best sum.

A sum can be "un-added" when an element leaves; a max cannot. Keep a deque of indices with decreasing values: pop from the back while the new value is larger, pop from the front when the index leaves the window. The front is the window's max. O(n) total (LC 239).

How to answer

Name the property that fails: max has no inverse operation.

Likely follow-ups
  • Median of every window (two heaps with lazy deletion, LC 480).
Could the window sum overflow? What type would you use?

|sum| <= k * 104 <= 109, below 231 - 1 ≈ 2.147 * 109, so int is enough for these constraints. The intermediate s + nums[i] - nums[i-k] also stays in range. With looser constraints use 64-bit; say this out loud, it is what the interviewer checks.

How to answer

Do the bound arithmetic in one line.

Likely follow-ups
  • What if values are up to 109? (64-bit sum, up to 1014.)
