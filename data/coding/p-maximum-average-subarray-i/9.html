60-second recall

  • Cue: every window of length exactly k; sum or average.
  • Insight: same length for all windows, so max average = max sum / k; slide: s += nums[i] - nums[i - k].
  • State: s = sum of the current window, best = best sum so far.
  • Trap: best starts at the first window (not 0); divide once as double.
  • Cost: O(n) time, O(1) space. Next: length at least k (LC 644), binary search the average.
s = sum(nums[:k]); best = s
for i in range(k, n):
    s += nums[i] - nums[i - k]
    best = max(best, s)
return best / k

Why is it safe to compare sums instead of averages?

  1. Sums are integers
  2. The array is sorted
  3. Every window has the same length k > 0, so dividing by k keeps the order
That stops being true when window lengths differ (LC 644).

When nums[i] enters a window of size k, which element leaves?

  1. nums[i - k]
  2. nums[i - k + 1]
  3. nums[i - 1]
The window becomes nums[i-k+1..i]; nums[i-k] is the one just outside.

What should best start as?

  1. 0
  2. The sum of the first window
  3. The first element
0 fails on all-negative input; the first element is not a window sum unless k = 1.
