Approaches: brute → better → optimal

Hint 1

Write down for each character of s which character of t it must become. When is that table invalid? Is that the only way to fail?

1. Brute force - compare every pair of positions

Idea: the strings are isomorphic exactly when, for every pair of positions i < j, s[i] == s[j] holds if and only if t[i] == t[j] holds. Check all pairs.

O(n²)time
O(1)space

What is wasted: for position j we only need the first earlier position with the same character, and a table can remember it. That gives the canonical-key view below.

2. Better - compare first-occurrence patterns

Idea: replace each character by the index where it first appears ("tool" → 0 1 1 3). Two strings are isomorphic exactly when the two patterns are equal. This is the canonical-key view and the one that generalises to grouping many strings.

O(n)time (with a first-seen table)
O(n)space for the two patterns

What is wasted: we build two whole arrays when we could compare position by position and stop at the first disagreement.

3. Optimal - forward and reverse tables in one pass

for a, b in zip(s, t):                          # core
    if a not in s_to_t and b not in t_to_s:
        s_to_t[a], t_to_s[b] = b, a             # new pair a <-> b
    elif s_to_t.get(a) != b or t_to_s.get(b) != a:
        return False                            # contradiction in one direction
  1. Both unseen: create the pair. Neither a nor b is used yet, so a → b and b ← a is a fresh, legal choice.
  2. Otherwise both entries must agree. If a was seen, it must map to b; if b was seen, it must come from a. One of them seen and the other not is also a contradiction (a maps elsewhere, or b is owned by another character).
  3. No contradiction to the end: true. The tables then describe a bijection between the characters of s and t that turns s into t.
O(n)time
O(1)space (2 × 256 entries)

Why it works: the replacement must be a function (same character, same image) that is injective (different characters, different images). The forward table enforces "function"; the reverse table enforces "injective". A function that is injective on the characters of s and hits every character of t is a bijection between the two character sets, which is exactly the definition.

A compact variant from the community (optional)

Store, for each character, the last index + 1 where it was seen, one table for s and one for t. At every position the two stored values must be equal; then write i + 1 into both. Equal "last seen" stamps at each step mean the two strings have the same repeat structure. It is the same bijection argument in a different form.
