Approaches: brute -> better -> optimal

Hint 1

Pick a cell as the bottom-right corner of a square. What must be true about the squares ending at its three neighbours up, left and up-left?

Hint 2

Which of the three neighbours limits how far the square can grow?

1. Brute force - grow a square from every top-left corner

Idea: for each 1 cell as top-left, try sides k = 1, 2, ... and check the new bottom row and right column each time; stop at the first 0.

O(m·n·k2)time (k = min(m,n))
O(1)space

With a 2D prefix sum you can test "is this k x k block all 1?" in O(1) (sum == k²), giving O(m·n·k), or O(m·n·log k) with binary search on k. Still slower than needed, and the prefix-sum table costs O(m·n).

What is wasted: the square at (r, c) re-checks cells that the squares at its neighbours already confirmed. -> reuse them.

2. Better - 2D DP table

side[r][c] = 0 if the cell is '0', else 1 + min(side[r-1][c], side[r][c-1], side[r-1][c-1]) (missing neighbours count as 0). Answer = (max side)². Padding the table with a zero row and column (size (m+1) x (n+1)) removes all boundary checks; the top-voted diagram solution does exactly this.

O(m·n)time
O(m·n)space

Why the minimum of three is right: let a = up, b = left, d = up-left and t = min(a, b, d).
(<=) If a (k x k) all-1 square ends at (r, c), then the (k-1) x (k-1) squares ending at (r-1, c), (r, c-1) and (r-1, c-1) are all-1 too (they are inside it). So each of a, b, d is at least k - 1, hence k <= t + 1.
(>=) Conversely, the t x t squares ending at up, left and up-left are all-1. Together with the cell itself they cover the whole (t+1) x (t+1) square ending at (r, c): up covers its top t rows (except the left column part that up-left covers), left covers its left t columns, up-left covers the top-left t x t block, and the corner is the cell. So a square of side t + 1 exists.
Both directions together: side = t + 1. Needing all three is essential: up and left alone can both be large while the top-left corner is a 0 (e.g. a ring of 1s).

3. Optimal - one row plus one saved diagonal

side = [0] * (n + 1); best = 0
for row in matrix:
    diag = 0
    for c in range(n):
        up = side[c + 1]                     # previous row, not yet overwritten
        side[c + 1] = 1 + min(up, side[c], diag) if row[c] == "1" else 0
        best = max(best, side[c + 1])
        diag = up                            # old value becomes next column's up-left
return best * best
O(m·n)time
O(n)space

In the 1D array, side[c+1] is "up" until you overwrite it and side[c] is "left" (already this row). The up-left value was side[c] before this row overwrote it, so save it in diag before each write. Forgetting to reset diag = 0 at the start of each row leaks a value from the previous row's last column.
