Interview follow-ups

Prove the recurrence 1 + min(up, left, up-left).

Upper bound: any k-square ending at (r, c) contains (k-1)-squares ending at each of the three neighbours, so k - 1 <= min. Lower bound: the three min-sized squares plus the cell itself tile the (min+1)-square ending at (r, c). Hence equality.

How to answer

Draw a 3x3 block and shade the three 2x2 squares; the overlap picture is the proof.

Likely follow-ups
  • Why is min(up, left) not enough? (A ring of 1s around a 0: the corner of the would-be square is missing.)
Bring the space down to O(n). What extra variable do you need?

One row array of length n+1 and a scalar diag. Before writing side[c+1], store its old value (the "up") so that it can serve as the up-left of column c+1. Reset diag to 0 at the start of each row.

How to answer

Say which slot is old (up), which is new (left), and which old value would be lost (up-left).

Likely follow-ups
  • O(min(m, n))? (Iterate along the longer dimension so the row is the shorter one.)
Count all square sub-matrices of 1s instead.

A cell with side = s is the bottom-right corner of exactly s all-1 squares (sides 1..s). Sum all side values: same DP, add instead of max. That is LC 1277.

How to answer

Reuse the table; explain the "exactly s squares end here" argument.

Likely follow-ups
  • Count squares whose side is at least K? (Add max(0, s - K + 1) per cell.)
Largest all-1 rectangle instead of square.

The min-of-three trick does not generalise, because a rectangle has two free dimensions. Keep height[c] = run of 1s ending at the current row in column c, and for each row solve Largest Rectangle in Histogram with a monotonic stack: O(m·n) overall (LC 85).

How to answer

Name the reduction "each row is the floor of a histogram".

Likely follow-ups
  • Could you get the square answer from the histogram too? (Yes: for each bar range, side = min(width, height); but the DP is simpler.)
The matrix is streamed row by row and is too large to store. Does the solution still work?

Yes. The 1D DP only needs the previous row's side values, so it processes each row as it arrives with O(n) memory, and the answer is final after the last row. This is the main practical benefit of the rolling-row version.

How to answer

Point out the data dependency only goes one row back.

Likely follow-ups
  • Report where the square is? (Store the (r, c) where best was last improved; top-left = (r - best + 1, c - best + 1).)
The matrix changes: cells flip between 0 and 1 and you must answer after each flip.

A flip at (r, c) can only change side values in the region below and to the right of it, and only within a band of the old answer's size, so recompute that region. In the worst case that is still O(m·n) per update; for many updates on large grids, one option is a 2D Fenwick tree of cell sums so that "is this k x k block all 1?" is a fast range query, combined with a search over k. In an interview, the local-recompute argument is usually enough.

How to answer

Start from the dependency direction (down and right), then discuss the trade-off.

Likely follow-ups
  • Only 0 -> 1 flips? (The answer never shrinks; only check squares containing the flipped cell.)
