Approaches: brute → better → optimal

Hint 1

If you set cur.next = something_else, how do you still reach the node that used to follow cur?

Hint 2

Keep the already-reversed part as its own little list, with a pointer to its head. Each step moves one node from the old list to the front of the new one.

1. Brute force - copy the values out and write them back

Idea: walk the list and push every value onto a stack (or into an array). Walk again and overwrite the values in pop order. The nodes stay where they are; only the values move.

O(n)time (2 passes)
O(n)space

What is wasted: O(n) memory, and it changes values instead of links, which interviewers usually reject: real nodes carry more than an int, and other code may hold pointers to them. -> rung 2.

2. Better - recursion

Idea: reverse everything after head first; that call returns the new head (the old tail) and leaves head.next as the tail of the reversed rest. Hang head behind it and cut head's own forward link.

def rev(head):
    if head is None or head.next is None: return head
    new_head = rev(head.next)
    head.next.next = head      # my old successor now points back at me
    head.next = None           # I am the new tail
    return new_head
O(n)time
O(n)stack space

What is wasted: one stack frame per node. That is 5000 frames at the limit: fine in C++ and Java, a RecursionError in Python unless you raise the limit, and a real risk for long lists in kernel code with small fixed stacks. -> rung 3.

3. Optimal - iterative, three pointers

prev, cur = None, head
while cur:
    nxt = cur.next; cur.next = prev    # save, then flip
    prev, cur = cur, nxt               # advance both
return prev
  1. Two lists at all times. prev heads the reversed part (initially empty), cur heads the part not yet reversed.
  2. Save before you cut. nxt = cur.next must come first, because the next line overwrites the only pointer to the rest of the list.
  3. Move one node across. cur.next = prev puts cur at the front of the reversed part; then prev = cur, cur = nxt.
  4. Return prev. When cur is null, the reversed part holds every node and prev is its head (null for an empty list).
O(n)time, one pass
O(1)space

Why it works: before each round, prev is the first k nodes of the original list in reverse order, and cur is node k+1 with the rest still attached. One round moves node k+1 to the front of the reversed part, so the statement holds for k+1. After n rounds the reversed part is the whole list.

Proof (optional)

Invariant: the nodes reachable from prev are exactly original nodes k, k-1, ..., 1 (in that order, ending in null), and the nodes reachable from cur are original nodes k+1, ..., n. The two chains share no node. Initially k = 0 (prev = null, cur = head). A round saves node k+2 in nxt, points node k+1 at node k, and advances, giving k+1. No node is lost because nxt held the only link that was overwritten. The loop runs n times and ends with k = n.
