Revision card

  • Cue: reverse / read backwards / compare halves of a singly linked list.
  • Insight: move nodes one by one to the front of a second, reversed list.
  • State: prev (reversed head), cur (next to move), nxt (saved rest).
  • Trap: save nxt before cur.next = prev; return prev, not head.
  • Cost: O(n) time, O(1) space; recursive O(n) stack (5000 deep).
prev, cur = None, head
while cur:
    nxt = cur.next
    cur.next = prev
    prev, cur = cur, nxt
return prev

Quick quiz

After the loop ends, which pointer is the new head?

  1. head
  2. prev
  3. cur
  4. nxt
cur is null and head now points at the last node of the reversed list; prev holds the old tail.

The recursive version forgets head.next = null. What happens on [9, 4]?

  1. Nothing, it still works
  2. It returns [9]
  3. 4 → 9 → 4 → ... a cycle
  4. It crashes on null
4.next becomes 9, but 9.next still points to 4.

Why can the recursive form fail in Python on the largest input?

  1. 5000 nested calls exceed the default recursion limit of 1000
  2. Python lists are slow
  3. Integers overflow
  4. It is O(n²)
One frame per node; raise the limit with sys.setrecursionlimit or use the loop.
