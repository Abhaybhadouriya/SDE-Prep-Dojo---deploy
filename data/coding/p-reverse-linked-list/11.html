Write the recursive version too. What does it cost?

Base case: empty or one node, return it. Otherwise reverse head.next, then head.next.next = head; head.next = null, and return the new head from the call. O(n) time and O(n) stack. A tail-recursive form passes the reversed part as an accumulator (rev(cur, prev)), which some compilers turn into the loop, but Java and Python do not.

How to answer

Draw the moment after the recursive call returns (the figure in rung 2), then the two lines are obvious.

Likely follow-ups
  • What is the max list length before a stack overflow? (Depends on frame size and stack limit; that is the argument for the loop.)
Reverse only the nodes from position left to right.

LC 92. Use a dummy node before head, walk to the node before left (call it before), reverse right - left + 1 nodes with the same loop, then before.next.next = cur (the old sub-head now links to the node after the range) and before.next = prev. One pass, O(1) space.

How to answer

Say why the dummy node exists: left = 1 changes the head.

Likely follow-ups
  • Reverse every k nodes (LC 25).
Reverse a doubly linked list.

Walk the list and swap prev and next in every node; the last node visited is the new head. With a sentinel-based circular list (like the kernel's list_head), you swap the pointers in the sentinel too, and no null checks are needed.

How to answer

Point out that after the swap, "next" in the loop is the old prev, so advance with the saved old next.

Likely follow-ups
  • Why is reversing a doubly linked list rarely needed? (You can just walk it backwards.)
Print the list in reverse without changing it.

Recursion (print after the recursive call) or an explicit stack: O(n) extra space either way. With O(1) space, reverse it, print, and reverse it back: two extra passes, and the list is not safe to read concurrently meanwhile.

How to answer

Name the trade-off: O(n) memory versus temporarily mutating shared data.

Likely follow-ups
  • O(√n) space? (Save every √n-th node, print each block from a small stack.)
Other threads push to this list concurrently. How do you reverse it safely?

Do not reverse a list others are modifying. Detach it first: atomically exchange the head with null (this is what the kernel's llist_del_all() does with xchg), so producers start a fresh list, then reverse the detached chain privately with the normal loop (llist_reverse_order()). Reversal itself needs no lock because no one else can reach the detached nodes.

How to answer

Separate "take ownership" (one atomic op) from "process" (plain code).

Likely follow-ups
  • Why is the list newest-first in the first place? (Lock-free push is a compare-and-swap on the head.)
