Why BFS gives shortest paths, and the grid template

BFS keeps a FIFO queue. It pops the oldest item, and pushes every neighbour it has not seen yet. Because of the FIFO order, every node at distance d is popped before any node at distance d + 1, so the queue holds at most two neighbouring layers at any time. The first time BFS reaches a node, it reached it by a shortest path. That proof needs one condition: every edge costs the same.

On a grid, the graph is implicit: the nodes are cells, the edges are the four (or eight) moves, and you never build an adjacency list. Every grid BFS has the same five parts:

  1. Directions array. dr = {1,-1,0,0}, dc = {0,0,1,-1}; add the four diagonals for 8-way moves.
  2. Bounds check first, then the wall check, then the visited check, in that order, so you never index outside the grid.
  3. Mark visited when you push, not when you pop. Marking on pop lets the same cell be pushed by several neighbours, which multiplies the work and can blow memory on big grids.
  4. Distance by levels or by array. Either freeze n = q.size() and process exactly n items per level (a counter goes up once per level), or keep dist[r][c] = dist[parent] + 1.
  5. Early exit. In single-target problems, return when you pop (or push) the target.

Encode a cell as one integer id = r * C + c when your language makes pairs clumsy (Go, Java). Decode with r = id / C, c = id % C. That is the same trick as flattening a 2-D array in C.

Cost: every cell is pushed and popped once, and looks at 4 neighbours, so O(R x C) time and O(R x C) space for the visited marks. DFS cannot replace BFS here: DFS finds a path, not the shortest one.
