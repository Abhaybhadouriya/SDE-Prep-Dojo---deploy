Interview questions

Rotting Oranges: why push all rotten oranges at the start instead of running BFS from each one?

All rotten oranges infect neighbours in the same minute, so their rings grow together. Pushing all of them at distance 0 is exactly a BFS from an imaginary super source joined to each of them with a free edge, and each fresh orange is reached first by the nearest rotten one. One BFS is O(R x C). Running a BFS per rotten orange is O(rotten x R x C) and also gives the wrong time model unless you take a minimum per cell.

How to answer

Say "multi-source BFS, levels are minutes", count fresh oranges first, mark on push, and handle the two edge cases: nothing fresh (0) and unreachable fresh (-1).

Likely follow-ups
  • Can you avoid the queue? (Repeated full-grid sweeps work but cost O((R x C)2) in the worst case; BFS is optimal.)
  • What if some oranges rot in 2 minutes instead of 1? (Unequal costs: Dijkstra, or 0-1/Dial-style buckets for small integer costs.)
01 Matrix: for each cell, the distance to the nearest 0. What is the efficient approach and why?

Push every 0-cell at distance 0, mark the 1-cells as unvisited (for example -1), and run one BFS. When a 1-cell is first reached its distance is final. O(R x C) time and space. An alternative is a two-pass DP: top-left to bottom-right taking min(up, left) + 1, then bottom-right to top-left taking min(down, right) + 1; it works because a shortest grid path to the nearest 0 can be split into those monotone directions, and it uses O(1) extra space if you write into the output.

How to answer

Lead with "start from all zeros", explaining why starting from ones is quadratic. Offer the two-pass DP as a follow-up for O(1) extra space.

Likely follow-ups
  • Diagonal moves allowed? (Use 8 directions in BFS; the DP needs both diagonal neighbours in each pass.)
  • Distance to the nearest 1 instead? (Swap roles: sources are the ones.)
Open the Lock: model it and give the complexity.

Each 4-digit combination is a node; each has 8 neighbours (one wheel up or down, wrapping). Put the dead ends into the visited set, check that "0000" is not one, then BFS from "0000" level by level and return the level at which the target is generated. There are at most 104 states with 8 edges each, each costing O(4) to build, so the work is bounded by a constant (about 3 x 105 character operations) plus the dead-end set, O(D).

How to answer

State the node, the edges and the state count before writing code. Mention bidirectional BFS as an optimisation since the target is known.

Likely follow-ups
  • Faster in practice? (Bidirectional BFS, expanding the smaller frontier.)
  • States as integers instead of strings? (Encode as a 4-digit number and change digits with div/mod; a 104 boolean array replaces the hash set.)
Shortest path with up to k obstacle removals: why is visited[r][c] wrong, and what is the complexity?

Reaching a cell with more removals left keeps more options open later, so (r, c, 2 left) and (r, c, 0 left) are different states. A plain visited[r][c] would let the first (possibly removal-hungry) arrival block a later arrival that kept a removal for a wall further on. Use a state (r, c, left): visited of size R x C x (k + 1), or keep the best "left" seen per cell and only accept arrivals with strictly more. Time and space O(R x C x k). Shortcut: if k >= R + C - 2, answer R + C - 2.

How to answer

Draw a corridor where the short route spends the only removal early and a longer route saves it for the wall that matters. Then give the state, the bound and the shortcut.

Likely follow-ups
  • Minimise removals instead of steps? (That is 0-1 BFS: free cell 0, wall 1.)
  • Minimise steps, then removals as a tie-break? (BFS by steps with the best-left-per-cell rule already prefers more removals left among equal step counts.)
Explain 0-1 BFS. Why is it correct, and when would you use Dijkstra instead?

With edge weights 0 or 1, a deque can play the role of Dijkstra's priority queue: relax a 0-edge and push the neighbour to the front (same distance), relax a 1-edge and push it to the back (distance + 1). Invariant: the deque holds only distances d and d + 1, in sorted order, so the front is always a minimum, just like Dijkstra's heap top. Each push is O(1), so the total is O(V + E). Use Dijkstra when weights are arbitrary non-negative numbers; use plain BFS when all weights are equal.

How to answer

Name the invariant (two distance values, sorted) and contrast with BFS (which would wrongly finalise the first arrival) and Dijkstra (log factor you do not need).

Likely follow-ups
  • Weights 0, 1 or 2? (Dial's algorithm with three rotating buckets, or Dijkstra.)
  • Can a node be popped twice? (Yes, a stale copy; the relaxation check makes it harmless, or skip it if the stored distance is larger than dist.)
Word Ladder: how do you generate neighbours, and how does bidirectional BFS help?

Do not compare all pairs of words (O(N2 x L)). For each popped word, try all 25 other letters at each of its L positions and look the candidate up in a hash set of the remaining words, O(25 x L) lookups per word (each lookup hashes L characters). Remove a word from the set when you first reach it, so the set doubles as visited. Bidirectional BFS grows sets from both ends, always expanding the smaller one by a full level, and returns when a generated word is in the opposite set. With branching factor b and depth d it touches about 2 bd/2 words instead of bd.

How to answer

Code plain BFS first (correct and simple), then say how you would switch to bidirectional. Handle "end word not in list returns 0" before the search.

Likely follow-ups
  • Return all shortest ladders (Word Ladder II)? (BFS that records parents level by level, then DFS from the end word back to the start.)
  • Very long words, small dictionary? (Pattern buckets like h*t built once, so neighbours come from a bucket lookup.)
BFS vs DFS for "minimum steps" on a grid: which and why? What about memory?

BFS, because it explores in order of distance and the first arrival is optimal; DFS finds some path and would need to explore all paths (exponential) to prove the shortest. Memory: BFS holds up to a whole frontier, which on an open R x C grid is O(R + C) wide but O(R x C) in the worst case including visited; DFS uses O(path length) stack, which can also reach O(R x C) and overflow a real call stack. For pure reachability or region counting, either works.

How to answer

Give the layer argument in one sentence, then mention that recursive DFS on a 1000 x 1000 grid can overflow the stack, which is a practical reason to prefer iterative BFS even for flood fill.

Likely follow-ups
  • Grid too large for memory? (Bidirectional search, or A* with a Manhattan-distance heuristic to explore fewer cells.)
  • Path reconstruction? (Store a parent per cell when you push it, then walk back from the target.)
Bus Routes: minimum number of buses from stop S to stop T. What is the node?

The cost is buses taken, not stops visited, so make the routes the BFS nodes. Build a map stop -> routes. Start with every route through S at level 1 (multi-source). Popping a route, check whether it contains T; otherwise, for each of its stops, push every unvisited route through that stop. Mark each route and each stop as processed once so no stop's route list is scanned twice. Time O(sum of route lengths). If S == T, the answer is 0.

How to answer

Start by asking "what does one unit of cost correspond to?" That question picks the node. Then it is multi-source BFS with a stop -> routes index.

Likely follow-ups
  • Why not BFS over stops? (Riding one bus through 100 stops would count as 100 steps; you would need 0-1 BFS with "stay on the bus" edges, which is bigger.)
  • Memory with 105 stops? (Store the index as stop -> list of route ids; skip a stop once processed.)
