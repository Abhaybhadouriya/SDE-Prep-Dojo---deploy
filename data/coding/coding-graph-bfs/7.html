Common mistakes

  • Marking visited on pop. The same cell is pushed many times; on a 1000 x 1000 grid that is a time-out or out-of-memory. Mark when you push.
  • Reading q.size() in the loop condition while pushing into the same queue. Freeze the level size before the inner loop.
  • Off-by-one in level counting. In Rotting Oranges, increment minutes only if the level actually rotted something (or loop only while fresh > 0); otherwise a grid that is already all rotten returns 1 instead of 0.
  • Forgetting the "no fresh orange at all" and "unreachable" cases. Count fresh cells first; return -1 if any remain.
  • Using visited[r][c] when the state has more parts. In obstacles elimination or keys problems, two visits to the same cell with different resources are different states.
  • 0-1 BFS without a dist check. Treating the deque like a plain BFS queue and marking on first sight gives wrong answers, because a cheaper route can arrive later through a 0-edge.
  • Bidirectional BFS that expands both sides by one node at a time or checks contact only at pop time. Expand a whole level of the smaller side, and check contact while generating.
  • Word Ladder: forgetting that endWord must be in the list. If it is not, the answer is 0 before any search.
  • Open the Lock: not checking whether "0000" is itself a dead end.
  • Building the full graph first for word ladder by comparing every pair of words: O(N2 x L). Generate neighbours on the fly.
