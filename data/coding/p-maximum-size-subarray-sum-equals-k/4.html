Approaches: brute → better → optimal

Hint 1

Fix the right end r. The subarray l+1..r sums to k when pre[l] = pre[r] - k. Which l gives the longest subarray?

Hint 2

The smallest such l. What do you store per prefix value so that you always have the smallest index?

1. Brute force - every subarray, summed from scratch

Idea: three loops: l, r, and the sum of nums[l..r]; keep the longest with sum k.

O(n3)time
O(1)space

What is wasted: sum(l..r+1) is sum(l..r) + nums[r+1]. -> rung 2.

2. Better - fix the start, extend the end

Idea: for each l, add nums[r] as r moves right and record r - l + 1 whenever the sum is k. Do not stop at the first hit: with negatives the sum can come back to k later, and later is longer.

O(n2)time
O(1)space

What is wasted: for each r we try every l, but the only l that matters is the earliest one with pre[l] = pre[r] - k. -> rung 3.

Why not a sliding window? On [2,-1], k = 1 a "shrink while sum > k" window sees sum 2 > 1 and drops the 2 at once; it then holds [-1] and returns 0, but [2,-1] sums to 1 (answer 2). A later negative can pull an "over" sum back to k, so shrinking early throws answers away. (We checked this window against the brute force: it fails on many tiny inputs with negatives.)

3. Optimal - prefix sums + first index of each prefix

first = {0: -1}; run = best = 0
for i, x in enumerate(nums):
    run += x
    if run - k in first: best = max(best, i - first[run - k])
    first.setdefault(run, i)         # keep the first index only
  1. Prefix identity. With pre(-1) = 0 and run = pre(i), sum(l+1..r) = pre(r) - pre(l).
  2. Fix the end. Subarrays ending at r with sum k start after an l with pre(l) = run - k.
  3. The earliest l is the best. The length is r - l, largest for the smallest l, so the map keeps only the first index of every prefix value.
  4. Seed {0: -1}. A prefix nums[0..r] with sum k then has length r + 1.
  5. Look up, then insert if absent. Inserting first would be harmless here (with k = 0 it only adds a length-0 match, which never beats best), but look-up-first is the habit that matters in the counting version (LC 560). setdefault / putIfAbsent / emplace never overwrite.
O(n)time (average, hashing)
O(n)space (distinct prefixes)

Why it works: every candidate subarray is a pair (l, r) with pre(r) - pre(l) = k. For each r the scan picks the smallest valid l, which is the longest candidate with that right end. Taking the maximum over all r covers every right end, so the longest subarray overall is found.

Proof (optional)

Entries of first are written once, at the first index where each prefix value appears, and every index l < r has been inserted before r looks up. Hence at step r, first[run - k] = min{l ∈ [-1, r-1] : pre(l) = pre(r) - k}, if that set is non-empty. The longest subarray ending at r with sum k has length r - min, and best = max over r of that value, which equals the answer. If no pair exists for any r, best stays 0.
