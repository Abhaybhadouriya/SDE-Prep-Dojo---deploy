Common mistakes

Overwriting the index on a repeated prefix. first[run] = i keeps the LAST index and finds shorter answers. On [1,-1,5,-5,4], k = 4 (prefixes 1, 0, 5, 0, 4) the overwrite turns the answer 5 into 2.

Using int for the running sum. 2·105 values of 104 reach 2·109, and run - k can be 3·109. In C++ signed overflow is undefined behaviour; in Java it wraps and finds wrong matches.

Forgetting the seed. Prefixes that themselves sum to k are missed: [5], k = 5 returns 0.

Storing counts like in LC 560. A count map answers "how many", not "how long"; the longest needs positions.

Using a sliding window. It is correct only for non-negative values; this problem has negatives.
