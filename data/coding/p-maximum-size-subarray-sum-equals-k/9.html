  • Cue: longest subarray with sum k, negatives allowed -> prefix sum + first-index map.
  • Insight: for end r the best start is the EARLIEST l with pre[l] = run - k.
  • State: run (64-bit), first{prefix: earliest index}, best.
  • Trap: seed 0 : -1; never overwrite (putIfAbsent); 64-bit sums; no window.
  • Cost: O(n) time, O(n) space; brute O(n²) with a running sum.
first = {0: -1}; run = best = 0
for i, x in enumerate(a):
    run += x
    if run - k in first:
        best = max(best, i - first[run - k])
    first.setdefault(run, i)         # first index only
return best

Why must C++ and Java use 64-bit for run?

  1. Hash maps need long keys
  2. k can be negative
  3. n can be 0
  4. |run| can reach 2·109 and run - k 3·109
INT_MAX is about 2.147·109.

  1. Keep the LAST index of each prefix (overwrite) and take the min
  2. Keep the first index and take the min
  3. Keep counts
  4. Nothing
For a fixed end the closest start is the shortest, so the latest index wins.
