Interview questions

Why can you not count "exactly K distinct" with a single sliding window?

Because "exactly K" is not monotone. For a fixed right, the valid left ends form a range [l1, l2], not a single point: shrinking from l1 keeps K distinct until a value's last copy leaves. One left pointer can stand for only one end of that range, so a single window would count one window per right instead of l2 - l1 + 1.

atMost(K) counts all lefts from the at-most-K boundary to right; atMost(K - 1) counts the lefts from the at-most-(K - 1) boundary to right. The difference is exactly the range [l1, l2].

How to answer

Give a tiny counterexample first ([1, 2, 1, 3], K = 2), then the subtraction, then O(n) time and O(K) space.

Likely follow-ups
  • Do it in one pass. (Keep two left pointers, one for "at most K" and one for "at most K - 1", and add their difference each step.)
Max Consecutive Ones III: what is the window invariant, and what is the complexity?

Invariant: after the shrink loop, [left, right] holds at most k zeros and is the longest such window ending at right. Expand with right, count zeros, shrink while zeros > k, record. Each index enters and leaves once: O(n) time, O(1) space.

How to answer

Restate the problem as "longest window with at most k zeros" before coding. That restatement is most of the credit.

Likely follow-ups
  • The array is a stream and k = 1. (Remember the index of the last zero; no buffer needed.)
  • Why is the "if instead of while" version also correct? (The window never shrinks below the best length, so it can only grow when a longer valid window exists.)
Walk me through Minimum Window Substring and prove the O(n) bound.

Keep need[c] (counts of t minus counts in the window, may go negative) and missing (characters still owed). Expand right; if need[c] was positive, missing--. While missing == 0: record, then move left; if need[c] becomes positive, missing++. Answer = best start and length.

Bound: right moves |s| times; left moves at most |s| times in total because it never moves back; each move is O(1). Building need is O(|t|). Total O(|s| + |t|), space O(alphabet).

How to answer

Explain why missing exists (to make the validity check O(1)), then the two transition rules, then complexity.

Likely follow-ups
  • t has many characters that are rare in s. (Filter s to positions of characters in t first; the window runs over the filtered list. This is the "optimised" approach in the official editorial.)
  • Unicode input. (Use a hash map instead of a 128-entry array.)
Count subarrays whose product is less than k. Why do you add right - left + 1?

All values are positive, so the product only grows when the window grows: the condition is monotone. After shrinking, [left, right] is the longest valid window ending at right, and all of its suffixes are valid too. Those are the right - left + 1 windows that end at right, and each window is counted only at its own right end, so nothing is double counted.

How to answer

Say "count windows by their right end". Mention the k <= 1 edge case: no product of positive integers is less than 1, so return 0 early.

Likely follow-ups
  • Products overflow. (Compare logarithms and their prefix sums, or note the product is bounded by k while valid.)
Count subarrays with at least K distinct values. Give two methods.

Method 1 (direct): for each right, shrink while the window still has at least K distinct; then every start before left is valid, so add left. Method 2 (complement): total windows n(n + 1)/2 minus atMost(K - 1). Both are O(n).

Method 1 avoids the n(n + 1)/2 term; method 2 reuses the helper you already wrote. Either is fine; pick the one you can explain without hesitation.

How to answer

State which direction the condition is monotone in ("bigger windows stay valid"), then the counting rule that follows.

Likely follow-ups
  • Exactly K with the at-least helper? (atLeast(K) - atLeast(K + 1).)
Find all anagrams of p in s. How do you make each step O(1)?

Fixed window of length |p|. Keep counts for the window and for p, plus matches = number of letters (out of 26) whose counts agree. When a letter's count changes: if it agreed before, matches--; change it; if it agrees now, matches++. The window is an anagram when matches == 26. Two letters change per step, so O(1) per step and O(n) total.

How to answer

Offer the simple 26-array compare first (O(26 n), perfectly acceptable), then the matches counter as the optimisation.

Likely follow-ups
  • Large alphabet. (Keep a hash map and count "keys still unequal" instead of 26.)
Binary subarrays with sum S: atMost trick or prefix sums? When does each one fail?

atMost(S) - atMost(S - 1) is O(n) time and O(1) space, but needs non-negative values (so "sum at most S" is monotone). Prefix sums with a hash map of counts is O(n) time and O(n) space, and works with negative values too.

How to answer

Give the prefix-sum solution as the general tool, then the window when the interviewer asks for O(1) space, naming the assumption it needs.

Likely follow-ups
  • Values may be negative and you need the shortest subarray with sum at least K. (Prefix sums and a monotonic deque: LC 862.)
Fruit Into Baskets: what is the problem really asking?

The longest contiguous block with at most 2 distinct values. Keep a count map; shrink while it has more than 2 keys; record the length after the loop. O(n) time, O(1) space (at most 3 keys).

How to answer

Strip the story first: "baskets" = distinct values, "pick from consecutive trees" = contiguous window.

Likely follow-ups
  • Constant space without a map. (Track the last two types and the length of the current run of the last type.)
