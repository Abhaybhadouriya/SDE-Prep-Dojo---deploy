Counting windows with "at least K"

Some conditions are monotone the other way: once a window is valid, every bigger window around it is valid too. "Contains at least one a, b and c", "the max appears at least k times", "has at least k distinct values". For these you can count windows in a mirror way.

For each right, shrink while the window is still valid. When the loop stops, [left, right] just became invalid, which means [left - 1, right] was the shortest valid window ending at right. Every start from 0 to left - 1 gives a valid window (they are all bigger). So add left.

The other way to count "at least" is the complement: atLeast(K) = total windows - atMost(K - 1), where total = n(n + 1) / 2. Both are correct. The direct form avoids the big total (and its overflow in 32-bit languages) and reads more naturally for "contains all of".

A variant of the same idea appears in Number of Substrings Containing All Three Characters (LC 1358): many top solutions keep the last index where each of a, b, c was seen and add 1 + min(last[a], last[b], last[c]) for each right. That is the same count, left, computed without a while loop: the smallest last-seen index is the latest start that still contains all three.
