The story: counting groups in a line of children

Explain like I'm 5

Children stand in a line, each in a coloured T-shirt. The teacher asks: "How many groups of children standing next to each other have exactly two colours?"

Counting "exactly two" directly is fiddly: a group with two colours can turn into a group with three if you add one more child, and back into two if you add another. So you count something easier. First count every group with at most two colours. Then count every group with at most one colour. Take the second number away from the first. What is left is exactly the groups with two colours.

From your world: debts, refcounts and completion counters

The missing counter in Minimum Window Substring is a pattern you already use in C. Think of a driver that submits a batch of I/O requests and must wait until all of them complete: it keeps a single outstanding counter (like the count in a struct completion or an atomic pending count). Each completion decrements it; the batch is done when it hits zero. Nobody scans the whole list of requests to check.

need[c] is a per-key refcount that is allowed to go below zero (spare references), and missing is the aggregate of how many keys are still short. Updating the aggregate only when a per-key count crosses zero is exactly the discipline of "take the slow path only on the 0 to 1 and 1 to 0 transitions", the same rule a refcounted object follows when it frees itself only when the count reaches zero.

And "at most K" windows are rate limiters. "At most N packets per window of T" over a sorted packet log is the at-most window over time; "how many intervals of the log broke the limit" is the at-least count. If you have ever written a token bucket or a connlimit style check, the monotone property is the same: a sub-interval of a compliant interval is compliant too.

That one move, counting an easy "at most" quantity twice and subtracting, turns a whole family of Hard problems into two calls of a function you already know. The rest of this page is the set of small, precise rules that make those functions correct: where you record, what you add, when you shrink, and what you keep in the window.
