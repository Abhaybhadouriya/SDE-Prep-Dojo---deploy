Common mistakes

  • Trying "exactly K" with one window. You will miss windows whenever several left ends work for one right end. Subtract two at-most counts.
  • Forgetting the K - 1 < 0 guard. atMost(-1) must return 0; otherwise the shrink loop runs past right and the index goes out of range.
  • Adding the wrong count. At most: right - left + 1, added after shrinking. At least: left, added after shrinking while valid. Mixing them up gives totals that look plausible on tiny tests.
  • Lowering missing on spare characters. In LC 76, decrement missing only if need[c] > 0 before the decrement, and increment it only if need[c] > 0 after the increment.
  • Copying the substring on every improvement. Store start and length; slice once at the end.
  • Map size with zero counts left in it. Delete keys at zero, or keep an explicit distinct counter.
  • 32-bit counts. The number of subarrays is up to n(n + 1) / 2, about 5 × 109 for n = 105. Use long long / long / int64 for totals and sums.
  • Using a window with negatives. The monotone sentence fails. Switch to prefix sums.
