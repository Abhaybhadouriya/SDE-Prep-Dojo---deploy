Counting windows with "at most K"

"Longest" needs one number per step. "Count" needs the number of valid windows, and there can be n(n + 1) / 2 of them, so you cannot list them. The trick is to count them grouped by where they end.

After the shrink loop, [left, right] is the longest valid window that ends at right. Because the condition is monotone, every shorter window that also ends at right is valid: [left+1, right], [left+2, right], up to [right, right]. Windows that start before left are invalid (that is why we moved left). So exactly right - left + 1 valid windows end here.

Each window is counted once, at its own right end. Add the counts for every right and you have the total in O(n). Click through it for "subarrays with at most 2 distinct values" on [1, 2, 1, 2, 3]:

  1. right = 0. The window is just [1], one distinct value, valid. One window ends here: [1]. Total 1.
  2. right = 1. Window [1, 2] has 2 distinct values, still valid. Two windows end here: [2] and [1, 2]. Total 3.
  3. right = 2. Window [1, 2, 1], still 2 distinct. Three windows end here. Total 6.
  4. right = 3. Window [1, 2, 1, 2], still 2 distinct. Four windows end here. Total 10.
  5. right = 4. The 3 enters and there are now 3 distinct values. Invalid: we must shrink before we count anything.
  6. Shrink: 1 leaves (count of 1 drops to 1), 2 leaves (2 is still there once), 1 leaves (count of 1 drops to 0, distinct = 2). left = 3. Two windows end here: [3] and [2, 3]. Total 12.
  7. The same pass with K = 1 gives 5 (just the five single cells, since no two neighbours are equal). So the number with exactly 2 distinct values is 12 - 5 = 7.

The loop behind the steps. Invariant: after the inner loop, [left, right] is the longest valid window that ends at right, so exactly right - left + 1 valid windows end there; exactly K = atMost(K) - atMost(K - 1). Lifted unchanged from the tested templates below.

// AT MOST K distinct: count subarrays. Each valid window ending at right adds right-left+1.
long long countAtMostKDistinct(const vector<int>& a, int k) {
    if (k < 0) return 0;
    unordered_map<int, int> cnt;
    long long total = 0;
    int left = 0;
    for (int right = 0; right < (int)a.size(); right++) {
        cnt[a[right]]++;                                  // expand
        while ((int)cnt.size() > k) {                     // shrink while invalid
            if (--cnt[a[left]] == 0) cnt.erase(a[left]);
            left++;
        }
        total += right - left + 1;                        // count windows ending here
    }
    return total;
}

// EXACTLY K = atMost(K) - atMost(K - 1)   (LC 992)
long long subarraysWithKDistinct(const vector<int>& a, int k) {
    return countAtMostKDistinct(a, k) - countAtMostKDistinct(a, k - 1);
}
# ---- 1. AT MOST K: count windows whose condition is "at most K of something" ----
def count_at_most_k_distinct(nums, k):
    """Number of subarrays with <= k distinct values. Every valid window ending at
    right contributes right - left + 1 subarrays (all its suffixes are valid too)."""
    if k < 0:
        return 0
    count = {}
    left = total = 0
    for right, x in enumerate(nums):
        count[x] = count.get(x, 0) + 1            # expand
        while len(count) > k:                     # shrink while invalid
            y = nums[left]
            count[y] -= 1
            if count[y] == 0:
                del count[y]
            left += 1
        total += right - left + 1                 # count every window ending at right
    return total

# ---- 2. EXACTLY K = atMost(K) - atMost(K - 1) ----
def subarrays_with_k_distinct(nums, k):
    """LC 992: subarrays with exactly k distinct values."""
    return count_at_most_k_distinct(nums, k) - count_at_most_k_distinct(nums, k - 1)

The state needed for "distinct values" is a count map plus its size. When a count drops to zero, delete the key (or keep a separate distinct counter and decrement it). If you forget, the size never goes down and the window never becomes valid again.

For "sum at most S" with non-negative numbers, the state is just a running sum. For "product less than K" with positive numbers, it is a running product, and you divide on the way out. In each case the cost of one step is O(1), so the total is O(n): both pointers move at most n times.
