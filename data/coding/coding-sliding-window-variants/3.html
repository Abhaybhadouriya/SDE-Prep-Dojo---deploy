Exactly K = atMost(K) - atMost(K - 1)

"Exactly K distinct values" is not monotone. Take [1, 2, 1, 3] with K = 2. The window [1, 2, 1] is valid. Grow it by one and it is invalid (3 distinct). Shrink it to [1] and it is invalid too (1 distinct). Validity is lost in both directions, so neither pointer knows which way to go. If you try one window anyway, you will miss windows: when right is fixed, several different left positions can give exactly K, and one left cannot stand for all of them.

The fix is set arithmetic. The windows with at most K distinct values split into two groups that do not overlap: the ones with at most K - 1, and the ones with exactly K. So:

The same trick, different state

  • Binary Subarrays With Sum (LC 930): subarrays of a 0/1 array with sum exactly S. The window state is the sum. atMostSum(S) - atMostSum(S - 1). Guard S - 1 < 0: return 0.
  • Count Number of Nice Subarrays (LC 1248): subarrays with exactly k odd numbers. Map each value to x % 2 and it is LC 930.
  • Subarrays with K Different Integers (LC 992): the distinct-count version above. A Hard that becomes ten lines.
  • Count of Substrings Containing Every Vowel and K Consonants II (LC 3306): "every vowel" is an "at least" condition and "exactly k consonants" is exact, so it is atLeast(k) - atLeast(k + 1) with the at-least shape from the next section. Note the direction flips: for "at least", more is the bigger set.

There is a one-pass alternative for LC 930 and 1248: a prefix-sum hash map ("how many earlier prefixes equal prefix - S?"). It also works with negative numbers, where the window does not. In an interview, give the prefix-sum version when values can be negative and the atMost version when the follow-up asks for O(1) extra space with non-negative values.
