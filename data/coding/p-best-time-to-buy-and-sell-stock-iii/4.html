Approaches: brute -> better -> optimal

Hint 1

The two trades do not overlap. So there is a day that separates them. What would you need to know on each side of that day?

Hint 2

In LC 121 you kept "the lowest price so far". Here keep the best balance for each of four moments: after buy 1, sell 1, buy 2, sell 2.

1. Brute force - try every split day

Idea: for each day k, solve "one trade" (LC 121) on prices[0..k] and on prices[k..n-1], and add them. A one-trade scan is O(n), so the total is O(n2). (Trying every pair of trades directly is even worse.)

O(n2)time
O(1)extra space

What is wasted: the left-side answer for k + 1 is the left-side answer for k plus one more day, yet it is recomputed from scratch.

2. Better - prefix and suffix best trades

Idea: compute left[i] = best single trade within days 0..i (scan left to right with the minimum so far) and right[i] = best single trade within days i..n-1 (scan right to left with the maximum so far). The answer is max(left[i] + right[i]).

O(n)time: three passes
O(n)extra space: the left array
Split version (Python, tested in the same driver) 
def max_profit_split(prices):
    n = len(prices)
    left = [0] * n                 # left[i]: best single trade within days 0..i
    lo = prices[0]
    for i in range(1, n):
        lo = min(lo, prices[i])
        left[i] = max(left[i - 1], prices[i] - lo)
    best, hi, right = left[-1], prices[-1], 0
    for i in range(n - 2, -1, -1):  # right: best single trade within days i..n-1
        hi = max(hi, prices[i])
        right = max(right, hi - prices[i])
        best = max(best, left[i] + right)
    return best

This is a strong answer already, and it is the one to reach for in "two non-overlapping subarrays" problems. Its limit: it does not extend to k trades.

3. Optimal - four-state machine, O(1) space

  1. States (best cash balance, starting from 0): buy1 = after the first buy, sell1 = after the first sell, buy2 = after the second buy, sell2 = after the second sell.
  2. Transitions for price p: buy1 = max(buy1, -p), sell1 = max(sell1, buy1 + p), buy2 = max(buy2, sell1 - p), sell2 = max(sell2, buy2 + p). "max with the old value" means "or do nothing today".
  3. Start: buy1 = buy2 = -prices[0], sell1 = sell2 = 0.
  4. Answer: sell2. It is at least sell1 (the second trade can be an empty same-day buy and sell) and at least 0.
O(n)time: one pass, 4 updates per day
O(1)extra space: four integers

Why it works: after processing day d, each variable equals the best balance over all legal action sequences on days 0..d that end in that state (proof by induction on d: a sequence ending in state "after buy 2" either did that buy on an earlier day, giving the old buy2, or does it today from the best "after sell 1" balance, giving sell1 - p). Updating in the order buy1, sell1, buy2, sell2 within one day lets a state read a same-day value of the previous state; that corresponds to buying and selling on the same day, which adds 0 profit, so it never creates an illegal gain. "At most two" is built in: you can stop in any state, and sell2 >= sell1 >= 0.

Generalising to k trades (LC 188)

Keep arrays buy[1..k] and sell[0..k] with sell[0] = 0; for each price and each j from 1 to k: buy[j] = max(buy[j], sell[j-1] - p), sell[j] = max(sell[j], buy[j] + p). O(n·k) time, O(k) space. If k >= n / 2, the limit never binds: sum every positive day-to-day rise instead (LC 122).
