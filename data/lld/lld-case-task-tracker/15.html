Common mistakes

  • Status as a hard-coded enum with if (status == TODO && to == IN_PROGRESS) chains, so a new status means editing the core.
  • One State class per status that only forwards "next" calls: extra classes without behaviour.
  • Logging in the caller or a listener, so some paths forget it, or a failure loses audit records.
  • Mutating before validating, leaving half-applied changes when a later check fails.
  • Returning live objects from search, so callers can change issues without a log line or read torn state.
  • No answer for concurrent edits, or thinking a lock prevents lost updates.
  • A method per filter combination (findByAssigneeAndStatus, findByLabelAndPriority, ...).
  • Subtask as a subclass or unlimited nesting nobody asked for.
  • Scanning lists by id in a take-home: PhonePe's reviewer explicitly asked to optimise brute-force functions. Use maps keyed by id.
