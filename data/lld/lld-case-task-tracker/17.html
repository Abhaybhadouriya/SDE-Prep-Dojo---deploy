A team wants a new "QA" status between "In review" and "Done". With this design, what changes?

  1. Two allow() calls on that board's workflow
  2. A new State subclass and a new enum value
  3. The move() method
The workflow is a table, so a new status is new data. No class changes.

Why is the activity log not implemented as a TrackerListener?

  1. Listeners are slower
  2. The log must be written atomically with the change; listeners run after the lock and can fail
  3. Java does not allow it
Audit records must never be lost or skipped, so they go in the write path itself.

Alice and Bob both load PAY-3 at version 1. Alice saves first. What happens to Bob's save with expected version 1?

  1. Applied, overwriting Alice's change
  2. It waits for Alice's lock
  3. Refused as stale; Bob reloads and re-applies
The version is now 2. The optimistic check refuses the stale save instead of losing Alice's update.

A sprint is completed with a story in IN_REVIEW that has two subtasks, one DONE. Where do the story and its subtasks end up?

  1. The story stays in the closed sprint; subtasks go to the backlog
  2. The story and both subtasks go back to the backlog
  3. Only the open subtask goes to the backlog
The story is unfinished, so it is carried over, and subtasks always follow their parent.

What is the best way to support "open bugs assigned to bob, or anything critical"?

  1. A SQL string built by concatenation
  2. A new method findOpenBugsForUserOrCritical()
  3. Compose small predicates: open().and(type(BUG)).and(assignee("bob")).or(priorityAtLeast(CRITICAL))
Specification-style predicates cover every combination with a handful of building blocks.

Why does search() copy IssueViews under the lock and filter outside it?

  1. Copies use less memory
  2. Filtering inside the lock is not allowed in Java
  3. Readers see a consistent snapshot and the lock is held only for the copy
Immutable copies prevent torn reads; filtering and sorting outside keeps the lock short.

Which unit should the lock protect?

  1. The whole tracker (one global lock)
  2. One board, because its issues, sprints, key counter and log change together
  3. Each issue separately
The board is the consistency boundary; boards share nothing, so they run in parallel.
