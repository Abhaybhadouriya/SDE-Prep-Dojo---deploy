Class diagram

  • TaskTracker is the facade and the only writer. Every public write follows the same template: find the board, lock it, check the actor is a member, apply the change, append events, unlock, notify listeners.
  • Board is plain data plus its lock (the Java version uses the board object's monitor). It owns its issues, sprints, log and key counter.
  • Issue is mutable but never leaves the lock. It carries a version that increases on every change, for the stale-update check.
  • IssueView is an immutable record copied under the lock. search(), get() and filters only ever see views, so a reader can never observe a half-applied change.
  • Workflow is a transition table: allows(from, to) and isDone(state). TransitionGuard is a one-method interface for extra rules.
  • Filters build Predicate<IssueView> objects that combine with and, or and negate.
  • Event is one immutable audit record. TrackerListener is the Observer for side effects.
