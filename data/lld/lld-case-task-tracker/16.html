Remember this

  • Statuses are data (a transition table per board); rules are guards; side effects are listeners; queries are predicates.
  • Every write follows one template: lock the board, check membership, validate, mutate, log, unlock, notify.
  • The activity log is written inside the write, append-only, and survives deletion.
  • Subtasks are issues with a parent key, one level deep; the parent cannot finish before its children.
  • Readers get immutable views; filters run outside the lock.
  • Locks make each save atomic; versions stop lost updates. They solve different problems.
  • Sprint close uses the workflow's done states; unfinished work goes back to the backlog.
