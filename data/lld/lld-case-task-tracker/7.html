APIs and interfaces

Write these signatures on the board before coding. They are what main, a test or a REST controller calls.

TaskTracker tt = new TaskTracker(clock);               // clock injected for tests
tt.createBoard("PAY", "Payments", Workflow.scrum(), "alice");
tt.addMember("PAY", "alice", "bob");
tt.addGuard("PAY", TransitionGuard.needsAssignee("IN_PROGRESS"));

String k  = tt.createIssue("PAY", "alice", IssueType.BUG, "Double debit", Priority.CRITICAL);
String st = tt.addSubtask(k, "alice", "Add idempotency key");
tt.assign(k, "alice", "bob");
tt.edit(k, "bob", Field.TITLE, "Double debit on retry", expectedVersion);
tt.move(k, "bob", "IN_PROGRESS");
List<String> gone = tt.remove(k, "alice");             // cascades to subtasks

String s = tt.createSprint("PAY", "alice", "Sprint 1");
tt.addToSprint(s, "alice", k);  tt.startSprint(s, "alice");
List<String> carried = tt.completeSprint(s, "alice");

List<IssueView> rows = tt.search("PAY", Filters.open().and(Filters.assignee("bob")));
List<Event> log = tt.history("PAY-1");   List<Event> mine = tt.activityOf("bob");
  • Errors: TrackerException for unknown ids, non-members, bad input and illegal sprint actions; TransitionDenied (a subclass) for workflow and guard refusals; StaleUpdate when the expected version is old. A REST layer maps them to 404 / 403 / 400, 409 and 412.
  • Read side: get and search return immutable IssueViews, never live objects.
  • If asked for REST: POST /boards/{key}/issues, PATCH /issues/{key} with If-Match: "v3", POST /issues/{key}/transitions {to}, GET /boards/{key}/issues?status=IN_PROGRESS&assignee=bob&label=upi, GET /issues/{key}/history, POST /sprints/{id}/complete.

If they ask for the database schema

board(key PK, name, workflow_id)              board_member(board_key, user_id, PK(board_key, user_id))
workflow(id, name, initial)                   workflow_transition(workflow_id, from_state, to_state)
issue(key PK, board_key, type, title, description, status, priority, assignee, reporter,
      parent_key NULL, sprint_id NULL, version, created_at, updated_at)
issue_label(issue_key, label)                 sprint(id, board_key, name, state, start_at, end_at)
issue_event(seq PK, issue_key, actor, action, from_value, to_value, at)   -- append-only, no FK on delete
-- INDEX issue(board_key, status), issue(assignee, status), issue(sprint_id), issue_event(issue_key, seq)
