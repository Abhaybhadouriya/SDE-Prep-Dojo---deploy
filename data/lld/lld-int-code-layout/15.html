The 60-second "how my code is organised" pitch

The evaluation call nearly always opens with "walk me through your code". Have this ready, adapt the nouns, and say it while scrolling the folder tree. About 150 words, a little under a minute at a calm pace.

  1. Shape (10 s). "It is layered: model has the entities and enums, repository hides storage behind an interface with an in-memory implementation, service has one public method per requirement, and Main wires everything and runs a demo."
  2. The seams (15 s). "The rules that vary are behind interfaces: the booking limit is a BookingLimitPolicy, and notifications are listeners. A new tier rule or a new channel is a new class; the service does not change."
  3. Correctness (15 s). "Business errors are one exception hierarchy, caught only in the driver, so bad input prints an error and the program carries on. The demo shows the happy path and five failure cases."
  4. Concurrency (10 s). "Booking takes a per-user lock then a per-class lock, always in that order. A 64-thread test proves the last seat goes to exactly one user."
  5. Next steps (10 s). "For a database I would add a JDBC repository and change one line in Main. With more time I would add an index for bookings by user instead of the scan."

Ending with your own known shortcut ("the scan in activeFor") steers the review to a place you have already prepared. It reads as judgement, not as a gap.
