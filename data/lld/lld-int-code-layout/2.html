The five rooms (and which way the arrows point)

Every project in this style has the same five kinds of file. The rule that makes it work is about who may know about whom: arrows point inwards, towards the entities. Nothing inside knows about the outside.

RoomHoldsMay know aboutMust not
model (entities, enums)User, FitnessClass, Booking, Tier, BookingStatusOther entities, Java/Python standard libraryPrint, parse, call a service or a repository
exceptionOne base FlipFitException + 3-4 subclassesNothingCarry logic
repositoryRepository<T> interface + InMemoryRepositoryEntitiesBusiness rules ("is the class full?")
strategy (or policy)BookingLimitPolicy, TierLimitPolicy, listener interfacesEntitiesKnow which service calls it
serviceUserService, ClassService, BookingServiceEntities, repository interfaces, strategies, other servicesRead stdin, print, know the concrete repository class
driver + MainCommand parser, demo script, wiringEverythingContain business rules

This is the same discipline as "the core stack never includes a driver's private header". The core sees struct net_device_ops, never e1000_main.c. Here the service sees Repository<Booking>, never ConcurrentHashMap. The name for it is the Dependency Inversion Principle.
