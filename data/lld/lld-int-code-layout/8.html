Strategy and listeners: where "extensible" actually lives

Read the problem statement once more and underline every sentence with "types", "tiers", "modes", "can be changed", "different rules for". Each one becomes an interface with one or two small classes. Everything else stays concrete. That is the whole trick behind "extensible", and it is why Strategy is the pattern most often named in these reports.

public interface BookingLimitPolicy {            // strategy: the rule that will change
    int maxActiveBookings(User user);
}
public class TierLimitPolicy implements BookingLimitPolicy {
    private final Map<Tier, Integer> limits;
    public TierLimitPolicy(Map<Tier, Integer> limits) {    // a new tier = one more map entry at the call site
        this.limits = new EnumMap<>(limits);
        for (Tier t : Tier.values())                            // a missing tier fails at wiring, not at booking time
            if (!this.limits.containsKey(t)) throw new IllegalArgumentException("no booking limit for tier " + t);
    }
    public int maxActiveBookings(User user) { return limits.get(user.getTier()); }
}

public interface BookingListener {               // observer: "notify the user" bonus
    void onEvent(String event, Booking booking);
}
class BookingLimitPolicy(Protocol):
    def max_active_bookings(self, user: User) -> int: ...

class TierLimitPolicy:
    def __init__(self, limits: dict[Tier, int]) -> None:
        missing = [t for t in Tier if t not in limits]
        if missing:   # fail at wiring, not at booking time
            raise ValueError(f"no booking limit for tier {missing[0].name}")
        self._limits = dict(limits)

    def max_active_bookings(self, user: User) -> int:
        return self._limits[user.tier]

BookingListener = Callable[[str, Booking], None]   # any function can listen

Syntax notes: EnumMap is a map keyed by an enum and stored as a plain array indexed by the enum's ordinal, like int limits[TIER_MAX]. Callable[[str, Booking], None] is a type alias for "a function taking a string and a booking, returning nothing": a function-pointer typedef void (*listener_fn)(const char *, struct booking *).

BookingLimitPolicy is a one-entry ops table: the service calls through it the way TCP calls icsk->icsk_ca_ops->cong_avoid() without knowing whether Reno or CUBIC is loaded. The listener list is a notifier chain: register_netdevice_notifier() on one side, call_netdevice_notifiers() on the other.
