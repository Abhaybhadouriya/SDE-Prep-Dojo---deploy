Package by layer (model, service, repository...) is what reviewers expect in a 90-minute round with 8-12 classes: it maps one-to-one onto the speech below. Package by feature (booking/, user/, each with its own service and repo) is better past about 30 classes, so mention it if asked how the code would grow, but do not start with it. The public machineCoding repo by iqblmoh (no licence file, so read it, do not copy it) uses the same by-layer idea with folders named dao, entity, enums, exception and service for its cab-booking and URL-shortener solutions.
