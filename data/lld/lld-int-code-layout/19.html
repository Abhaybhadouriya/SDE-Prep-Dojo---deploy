Where should the rule "a class never has more confirmed seats than its capacity" live?

  1. In the driver, before calling the service
  2. In the repository's save method
  3. In the FitnessClass entity, checked by the service under a lock
  4. In a Strategy
It only needs the class's own fields, so the entity owns it; the service makes the check-then-act atomic with the per-class lock.

The reviewer asks how you would add a database. Which design makes that a one-line change in Main?

  1. Making every service a singleton
  2. Services depending on a Repository interface injected through the constructor
  3. Using static maps in each service
  4. Putting SQL strings in the entities
With the interface injected, a JDBC implementation replaces the in-memory one where Main builds the graph.

A CRED candidate wrote RegisterA, RegisterB, RegisterC and RegisterD classes. What was the design mistake?

  1. Too few interfaces
  2. Not using a Singleton
  3. Missing a repository
  4. A class per instance instead of one Register class with four objects
Four registers are four objects of one class, kept in a map by name.

Where should business exceptions be caught and turned into an error line?

  1. Once, in the driver / command runner
  2. Inside every service method
  3. In the repository
  4. Nowhere; let the program crash
Catch where you can do something: the driver prints the message and keeps reading commands.

book() takes the user lock, then the class lock. cancel() takes only the class lock. Can they deadlock with each other?

  1. Yes, always
  2. Yes, if two users book the same class
  3. No: cancel never waits for a user lock while holding the class lock, so no cycle forms
  4. No, because Java prevents deadlocks
A deadlock needs a cycle of waits. With a single global order (user before class) and cancel taking only one lock, no cycle is possible.

For a 90-minute round with about ten classes, which package style do reviewers expect?

  1. Package by feature, one folder per use case
  2. Package by layer: model, repository, service, driver
  3. Everything in the default package
  4. One package per class
By layer maps directly onto the walkthrough. By feature pays off later, when the code grows past a few dozen classes.
