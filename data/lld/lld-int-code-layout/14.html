When the full layout pays
  • 8+ entities or 5+ features
  • An evaluation call where you defend the code
  • Problems that say "extensible", "configurable" or "pluggable"
When it is too much
  • A 45-minute DSA-plus-design round: one class with clean methods wins
  • Atlassian-style rounds that grow step by step: start small, refactor when the follow-up arrives
  • Any time the skeleton is eating minutes needed for a working P0

Over-engineering is a stated failure mode in the reports. Our survey of recent reports found it in a Microsoft parking-lot round and in an Uber SDE-2 round where the candidate wrote LLD-style layered code for a problem that only needed a hash map. The skeleton is a floor plan, not a requirement to fill every room.
