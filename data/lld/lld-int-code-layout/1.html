Why graders care where your files are

A machine-coding round (90-120 minutes of solo coding, then a review call) is graded on code you hand in, not on a diagram. The reviewer opens your zip and has a few minutes to decide whether it is "modular" and "extensible". A clear layout answers that before they read one method. The public practice repo for the Flipkart round says the same in its own words: executable code, functional correctness, code hygiene (readable, modular, testable), language proficiency, error handling, and code that absorbs new requirements with few changes (workattech/flipkart-machine-coding-round).

"Modular but not extensible" is the most common rejection phrase in these reports. It usually means: the files were split up, but every new rule still needs an edit inside one big service method. The cure is not more files. It is one interface at the place where the problem says "types", "tiers", "strategies" or "can be configured".
