The story: a small restaurant

Explain like I'm 5

Picture a tiny restaurant. The waiter listens to you and writes your order on a slip. The cook reads the slip and follows the recipe. The store-room keeper fetches eggs and rice when the cook asks; the cook never walks into the store room. And the food itself (eggs, rice, a plate of fried rice) does not know anything about waiters or cooks.

If the waiter starts cooking, or the cook starts taking orders at the door, things go wrong fast. If the restaurant buys a bigger fridge, only the store-room keeper has to learn where things are now. Nobody else changes.

A machine-coding project is that restaurant. The driver is the waiter (it reads commands). The service is the cook (it runs the rules). The repository is the store-room keeper (it saves and finds things). The entities are the food (plain data with a few rules of their own).

This page gives you that restaurant as a folder layout you can type from memory. It is not a pattern lesson: the patterns each have their own page (Repository, Strategy, Observer, dependency injection). It is the floor plan that puts them in the right rooms, so that the first ten minutes of a 90-minute round are spent on the problem and not on deciding where files go.

From your world

You already build software in layers. A network driver has a struct net_device (the entity: data), a set of lookup helpers over a hash table or idr (the repository: "find the device for this ifindex"), the core stack calling ndo_start_xmit through an ops table (the service calling through an interface), and an ioctl or netlink handler that parses user input and calls into the core (the driver/CLI layer). module_init() is where everything is wired: ops tables filled, devices registered. In Java that wiring function is Main, and people call it the composition root.
