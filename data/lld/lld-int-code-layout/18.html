Remember this

  • Five rooms: model (entities, enums), exceptions, repository (interface + in-memory), strategy/listeners, service; plus Main as the composition root and driver.
  • Arrows point inward: entities know nothing about services, services know only repository interfaces, only Main knows concrete classes.
  • One service method per requirement, named with the verbs from the problem statement.
  • "Extensible" means an interface exactly where the problem says types, tiers, modes or rules vary, and nowhere else.
  • One exception base class, caught once in the driver; the demo shows happy paths and failure lines.
  • Locks live in services around check-then-act on one entity, in a fixed order; prove it with a many-thread test.
  • Practise the empty skeleton until it takes under five minutes, and the 60-second pitch until it takes under a minute.
