One command, through every room

Step through what happens when the demo runs BOOK u3 c1 and class c1 is already full. Watch which layer does what, and what each one does not do.

  1. The driver splits the line and finds the handler for BOOK in a map. It knows nothing about seats.
  2. The service asks the user and class services for both objects; a missing id becomes a NotFoundException here.
  3. The limit comes from the strategy. The service does not know that NORMAL means 2; changing the rule never touches the service.
  4. Under the user lock and then the class lock, the entity says "no free seat", so the booking goes on the waitlist. The class keeps its own invariant (never more than capacity).
  5. The booking is saved through the repository interface, and listeners are told. Printing is a listener's job, not the service's.
  6. The driver turns the returned object into text. A business error would have come back as ERROR ... instead of a stack trace.
