Class diagram

  • Match holds the two teams, creates the two innings (the second with a target), runs the match state machine and fans out events. It never touches a run.
  • Innings is where every cricket rule lives: runs, extras, balls faced, strike rotation, over end, all out, chase complete. It is the "information expert" in GRASP terms because it owns the data the rules need.
  • Ball is an immutable value object with a factory method parse(token). Validation happens here, so a bad token is rejected before any state changes.
  • BattingStats / BowlingStats are small counters with derived values (strikeRate(), economy()).
  • MatchListener is the Observer interface with default no-op methods. ScorecardPrinter and LiveScore are two implementations; a test spy or a commentary writer would be more.
