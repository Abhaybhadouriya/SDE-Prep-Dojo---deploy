Core flow: one purchase

  1. A Rs 50 note goes in. IDLE stores it in the escrow (not the cash box) and switches to HAS_MONEY.
  2. The customer presses A1. The machine takes its lock and hands the event to the current state object. The machine itself contains no if-else on states.
  3. HasMoneyState asks the inventory for the product. An unknown code or an empty slot throws here, before anything has changed.
  4. Price Rs 20, balance Rs 50, so change is Rs 30. The change maker searches the cash box plus the escrowed coins (the customer's Rs 50 note can itself be paid out later) and returns the fewest coins.
  5. If any check fails (sold out, not enough money, no way to make change), an exception goes back to the customer. The state is still HAS_MONEY and the escrow is intact, so they can add a coin, pick another product or cancel.
  6. Only now does the commit run: escrow into the cash box, change out of it, one item out of the slot. These steps cannot fail, because every one was checked above.
  7. The machine moves through DISPENSING and ends in IDLE (or SOLD_OUT if that was the very last item). The customer gets the product and the change.
