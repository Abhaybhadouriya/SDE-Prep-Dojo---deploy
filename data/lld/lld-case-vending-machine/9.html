APIs and interfaces

interface State {                               // one class per state; defaults refuse
    int                insert(VendingMachine m, Denomination d);
    Purchase           select(VendingMachine m, String code);
    List<Denomination> cancel(VendingMachine m);
    void enterMaintenance(VendingMachine m);
    void restock(VendingMachine m, String code, Product p, int qty);
    void loadChange(VendingMachine m, Denomination d, int n);
    void exitMaintenance(VendingMachine m);
}

interface ChangeMaker {
    Optional<List<Denomination>> make(int amount, Map<Denomination, Integer> available);
}

// VendingMachine: what the keypad and the admin panel call (all synchronized)
int insert(Denomination d);           // returns the balance
Purchase select(String code);         // product + change, or throws VendingException
List<Denomination> cancel();         // the exact coins that were inserted
void enterMaintenance(); void restock(String code, Product p, int qty);
void loadChange(Denomination d, int n); void exitMaintenance();

Hardware (coin validator, motor, display) would sit behind small interfaces (CoinAcceptor, Dispenser, Display) that call these methods or are called from the states; in the interview a driver calls the methods directly.
