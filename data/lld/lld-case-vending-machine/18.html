  • Draw the event x state table first; each state column becomes one State class; default answer is "refuse".
  • The machine (context) owns the data; states are stateless and choose their successor.
  • Inserted coins sit in escrow; validate stock, balance and change, then commit in one step.
  • Refund = return the escrow, which can never fail.
  • Limited coins break greedy change; use the bounded coin-change DP and refuse the sale if it finds nothing.
  • One lock per machine for events; a session owner (keypad or customer id) for the whole purchase.
  • Card payment, alerts and coffee recipes are new strategies, observers and states, not rewrites.
