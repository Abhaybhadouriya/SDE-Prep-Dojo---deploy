Clarify the requirements

Functional (P0)

  1. Products in slots Each slot has a code (A1, B2), one product with a price, and a count.
  2. Insert money Accept coins and notes of fixed denominations (we use Rs 1, 2, 5, 10, 20, 50, 100). The balance adds up.
  3. Select Pick a slot code. Dispense if the slot exists, is not empty, the balance covers the price and the machine can return the exact change.
  4. Change Return the difference using the coins the machine actually has, with as few coins as possible.
  5. Cancel / refund At any point before dispensing, cancel returns exactly the coins that were inserted.
  6. Errors Unknown slot, sold out, not enough money ("insert Rs 25 more"), cannot make change: show a message, keep the customer's money, let them choose again or cancel.
  7. Admin In a maintenance mode, restock slots and load change coins. Not allowed while a customer is mid-purchase.

P1

  • Card / UPI / wallet payment; multiple items in one session; an alert when a slot runs empty; sales report; collect cash.
  • Coffee-machine variant: recipes consume ingredients, add-ons (milk, sugar) change the price.

Non-functional

  • Money is conserved: cash box after = cash box before + price of what was sold. Never pay out change you do not have.
  • Atomic purchase: all checks pass, then everything is applied; otherwise nothing changes.
  • Extensible: a new state or payment method should not edit every method of the machine.
  • Thread safe: the keypad, the admin panel and a telemetry thread can touch the machine at the same time.

Out of scope (say it)

Hardware drivers (motor, coin validator, sensors), networking, a fleet of machines, pricing rules. Model hardware behind a Dispenser interface if asked.

Questions to ask

  • Money first, then select? Or select first, then pay? (Both are common; we use money first, the flow most solutions follow.)
  • One product per session, or several? Is there a maximum balance?
  • Which coins and notes? Can inserted coins be used as change for this customer? (Yes, in ours.)
  • If exact change is impossible: refuse the sale, or sell and owe? (Refuse and keep the money in escrow.)
  • Refund the same coins, or any coins of the same value? (Same coins: always possible, never fails.)
  • Card payment needed now? Admin features needed now?
