Do not add a pattern without a requirement behind it. A RestaurantFactory with one product type, or a Singleton service, adds code and gives the evaluator something to question. If they ask "where would a Factory fit?", answer: when restaurants come in kinds with different behaviour (cloud kitchen with unlimited capacity, partner restaurant with opening hours), a factory builds the right one from the onboarding command.

Why the pattern earns its place: the if-ladder it replaces

Without the Strategy, every selection rule is a branch inside placeOrder:

Order placeOrder(String customer, Map<String, Integer> items, Mode mode) {
    Restaurant best = null;
    for (Restaurant r : restaurants.values()) {
        if (!r.canServe(items)) continue;
        if (mode == Mode.LOWEST_PRICE) {
            if (best == null || r.price(items) < best.price(items)) best = r;
        } else if (mode == Mode.MAX_CAPACITY) {
            if (best == null || r.freeCapacity() > best.freeCapacity()) best = r;
        } else if (mode == Mode.HIGHEST_RATING) {       // follow-up 1 edits here
            if (best == null || r.rating() > best.rating()) best = r;
        }                                               // follow-up 2 edits here too
    }
    ...
}
interface RestaurantSelector {
    List<Restaurant> rank(Map<String, Integer> items, Collection<Restaurant> all);
}
final class HighestRatingSelector implements RestaurantSelector { ... }   // the follow-up: a new file

Order placeOrder(String customer, Map<String, Integer> items) {
    for (Restaurant r : selector.rank(items, restaurants.values()))
        if (r.tryReserve(qty)) return book(customer, r, items);
    throw new FoodException("no restaurant can serve the order now");
}

With the ladder, the follow-up "pick by rating" edits placeOrder, the Mode enum and every test of placeOrder. With the interface it adds one class and one line in the driver; FoodService is not opened.

The "after" version is an ops table: the caller holds a pointer to a struct of function pointers and never asks which implementation it has, exactly as the VFS calls file->f_op->read() without a switch on the file system type.
