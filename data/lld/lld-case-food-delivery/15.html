Common mistakes

  • Designing for 40 minutes and coding for 50. The machine-coding round rewards a running demo. Sketch the classes in five minutes and start typing.
  • Re-reading the menu at billing time instead of snapshotting the price on the order.
  • Strategy that mutates state. A selector should only choose. If it reserves capacity, a lost race leaves it holding capacity for an order that does not exist.
  • Status as a public setter. order.setStatus(DELIVERED) from anywhere skips the rules; use one guarded moveTo.
  • Releasing capacity on both cancel and ready without a guard, so capacity drifts upward over time.
  • Calling listeners inside a synchronized block (deadlock risk, slow critical sections).
  • Printing from deep inside the model. Return values and let the driver print; tests then do not need to capture stdout.
  • Patterns without a requirement (Singleton service, a factory with one product). Each one needs a sentence that names the change it absorbs.
