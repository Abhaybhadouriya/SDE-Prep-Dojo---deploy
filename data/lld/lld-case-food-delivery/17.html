Quiz

Where should the "check capacity and claim it" logic live?

  1. In the driver, before calling placeOrder
  2. In the RestaurantSelector, so it only picks restaurants it has reserved
  3. In a synchronized method on Restaurant that checks and increments together
Restaurant owns inUse, so it owns the atomic check-and-claim. A selector that reserves would leak capacity when it loses a race.

A menu price changes after an order is accepted. What should the order's bill show?

  1. The new price, read at delivery
  2. The average of both prices
  3. The price quoted when the order was placed
The order stores a snapshot total (or unit prices on its lines), like an invoice.

Cancel and markReady race on one ACCEPTED order. What guarantees capacity is returned only once?

  1. Releasing capacity is idempotent because it uses a ConcurrentHashMap
  2. Both call a synchronized moveTo first; only the caller whose transition succeeds releases capacity
  3. The Dispatcher lock
The guarded transition picks one winner; side effects follow only for the winner.

Which requirement phrase most directly signals a Strategy?

  1. "Implement lowest price, with the option of selection by a different strategy"
  2. "Keep track of items served per restaurant"
  3. "Orders move from placed to delivered"
"Option of a different rule for the same step" is the Strategy signal. The lifecycle phrase signals State.

Why does the Dispatcher use one lock for both "assign or enqueue" and "next order or mark free"?

  1. Otherwise a rider can free itself while an order is being queued and the order waits forever (lost wakeup)
  2. To make the code shorter
  3. Java requires one monitor per class
Both decisions read and change the same pair (free riders, waiting orders), so they must be atomic with respect to each other.

At minute 50 of a 90-minute round you have placeOrder working but no dispatcher. Best move?

  1. Start the bonus features
  2. Finish all P0 features in the driver first, then add the queue if time remains
  3. Refactor everything into more patterns before continuing
Working P0 features are weighted highest; a report in our set describes a rejection with a clean design but one broken core feature.
