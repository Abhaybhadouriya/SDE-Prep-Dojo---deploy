Common mistakes and how evaluators see them

MistakeWhat the interviewer thinksFix
Naming a pattern before naming what variesmemorised, not understoodAlways start with "the thing that changes here is..."
Pattern stuffing (5+ patterns in a 45-minute round)over-designed, poor judgementOne pattern per named requirement; say what you left out
Singleton for everything (service, repository, game)hidden globals, untestableCreate once in main, inject; keep Singleton for true process-wide resources
Lazy singleton without thread safetydoes not know the memory modelHolder idiom or enum; volatile for DCL
Calling Strategy "State" or Decorator "Proxy"knows shapes, not intentsUse the "who decides / who owns" test
Observer without unsubscribe or error isolationwill leak and cascade failuresReturn a handle; try/catch per observer; async if slow
Interfaces with one implementation everywhereceremony, slows the roundInterface only where a second implementation is required or likely
Answering a different question with patternsnot listeningRepeat the question back in one line before answering
Drawing the class diagram first and never writing runnable code(machine coding) "cannot deliver in 90 minutes"Skeleton classes in 10 minutes, a running main() by minute 40, patterns added where the review will push
Decorator or Proxy that does not implement the same interface as what it wrapsdoes not know why the pattern worksSay "same interface, so the client cannot tell" and show the implements
Factory that still leaks new ConcreteX() into callerspattern in name onlyGrep your own code: only the factory and main() may name concrete classes
Holding a lock across a slow call inside a proxy, observer or facade(SDE-2) weak concurrency judgementTake the lock for the bookkeeping only; call out with no lock held; say why
No trade-off stated ("Strategy is always better")cannot reason about costEnd every pattern choice with one cost: an extra class, an indirect call, a harder-to-follow flow

Machine-coding evaluators (PhonePe, Flipkart, Razorpay style) score extensibility by asking you to add a feature in the review call. A well-placed Strategy or Factory makes that a two-minute change, and that is where patterns earn marks, not in the diagram legend. More in the machine-coding guide.
