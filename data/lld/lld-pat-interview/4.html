How to answer "which pattern?" in five beats

Walk through the steps with a classic prompt: "A parking lot charges differently for cars and bikes, and on weekends. Rules change every month. How would you design the fee part?"

  1. Say what varies, in plain words. "The thing that keeps changing is how the fee is computed." This one sentence is worth more than the pattern name.
  2. Name the pattern and its intent in one line. "That is Strategy: a family of interchangeable fee algorithms behind one interface."
  3. Draw the three boxes. The context (ParkingTicket) holds a reference to the interface; concrete strategies implement it.
  4. Write the smallest code that proves it. The interface and two implementations. A lambda per rule is fine in Java 8+.
  5. Give the cost and the alternative you rejected. Then stop and let the interviewer pick the next topic. Usually: "who picks the strategy?" (a Factory or a config map).

Beat 5 is what turns a junior answer into an SDE-2 answer. "I would not use a pattern here because there is only one rule and it has not changed in a year" is a perfectly strong answer, if you say it with the reason.
