Name that pattern: 20-question identification quiz

Each question describes code or a requirement. Pick the pattern. Aim for 16 or more before your interview. If one surprises you, the explanation tells you which lesson to reread.

1. A Ticket holds a PricingRule interface. Weekday, weekend and EV-charging rules implement it, and the gate picks one when the car enters.

  1. State
  2. Template Method
  3. Strategy
  4. Bridge
The caller picks one interchangeable algorithm, and the rules never switch to each other: Strategy.

2. An ATM object has Idle, CardInserted and PinVerified classes. Calling enterPin() on CardInserted returns a PinVerified object, which the ATM keeps.

  1. State
  2. Strategy
  3. Command
  4. Memento
The states choose the next state themselves: State.

3. new BufferedInputStream(new GZIPInputStream(new FileInputStream(f)))

  1. Composite
  2. Proxy
  3. Chain of Responsibility
  4. Decorator
Each wrapper has the same interface, wraps exactly one stream and adds a feature (buffering, decompression): Decorator.

4. An ImageProxy shows a placeholder and loads the 20 MB image from disk only when draw() is first called.

  1. Flyweight
  2. Proxy (virtual)
  3. Decorator
  4. Facade
It controls when the real object is created: a virtual Proxy. It adds no new feature, so not Decorator.

5. A StripeGateway class wraps Stripe's SDK so it implements your existing PaymentProvider interface.

  1. Facade
  2. Bridge
  3. Adapter
  4. Proxy
It converts one existing interface into the one your code expects: Adapter.

6. OrderService.placeOrder() is the only method the UI calls; inside it calls inventory, pricing, payment, invoice and notification classes.

  1. Facade
  2. Mediator
  3. Adapter
  4. Template Method
One simple entry point in front of a subsystem: Facade. (A Mediator coordinates objects that would otherwise talk to each other.)

7. Directory and File both extend Node; a directory's size() sums its children's size().

  1. Decorator
  2. Visitor
  3. Iterator
  4. Composite
Part-whole tree where leaves and containers share one interface: Composite.

8. Each text-editor action is an object with execute() and undo(), pushed onto a history stack.

  1. Memento
  2. Command
  3. Strategy
  4. Observer
Requests as objects that can be stored and reversed: Command. Memento would store snapshots of the text instead.

9. A leave request goes to the team lead; if the days are above the lead's limit it moves to the manager, then the director.

  1. Decorator
  2. Mediator
  3. Chain of Responsibility
  4. State
A line of handlers where each either handles the request or passes it on: Chain of Responsibility.

10. When a stock price changes, the chart, the alert service and the portfolio view are all told; any of them can sign up or leave at run time.

  1. Observer
  2. Mediator
  3. Command
  4. Chain of Responsibility
One-to-many notification with a changing set of listeners: Observer.

11. HttpRequest.newBuilder().uri(u).header("A","b").timeout(d).GET().build()

  1. Factory Method
  2. Prototype
  3. Decorator
  4. Builder
Step-by-step construction of an immutable object with optional parts, finished by build(): Builder.

12. abstract class Dialog calls createButton() in its render() method; WindowsDialog and WebDialog override createButton().

  1. Abstract Factory
  2. Factory Method
  3. Simple Factory
  4. Template Method only
A subclass decides which product the base class creates: Factory Method. (It is also a Template Method hook, but the intent here is creation.)

13. A CloudFactory interface has storage(), queue() and secrets(). AwsFactory returns S3, SQS and Secrets Manager clients; GcpFactory returns the GCP set.

  1. Factory Method
  2. Bridge
  3. Abstract Factory
  4. Builder
A family of products that must match each other: Abstract Factory.

14. A text renderer keeps one shared object per character glyph (font outline) and passes the position in when drawing, so a 1-million-character document has only about 100 glyph objects.

  1. Flyweight
  2. Prototype
  3. Singleton
  4. Object Pool
Share the intrinsic, immutable state; pass the extrinsic state (position) in: Flyweight. A pool lends objects out and takes them back; flyweights are shared at the same time.

15. Shape (circle, square) holds a Renderer (vector, raster). Both sides grow independently: 3 shapes and 2 renderers need 5 classes, not 6 combinations.

  1. Adapter
  2. Strategy
  3. Decorator
  4. Bridge
Two dimensions varying independently, joined by a reference: Bridge (M + N instead of M x N).

16. abstract class DataImporter has a final method run() that calls open(), parse(), validate() and save(); subclasses override only parse().

  1. Strategy
  2. Template Method
  3. Chain of Responsibility
  4. Facade
A fixed skeleton in a base class with one overridable step: Template Method.

17. Players in an online auction never call each other. They call auctionHouse.bid(this, amount), and the house tells every other bidder.

  1. Observer
  2. Facade
  3. Mediator
  4. Proxy
Peers talk through one coordinator that holds the interaction logic: Mediator.

18. A game saves a Snapshot object of the player's state before a boss fight; only the Player class can read what is inside it.

  1. Memento
  2. Command
  3. Prototype
  4. State
Capture and restore state without exposing it: Memento.

19. A tax calculator adds a new operation over Book, Food and Electronics classes by writing one new class with visit(Book), visit(Food) and visit(Electronics).

  1. Strategy
  2. Iterator
  3. Composite
  4. Visitor
New operations over a fixed set of element classes via double dispatch: Visitor.

20. In the Linux kernel, a driver fills struct net_device_ops with its own ndo_open, ndo_stop and ndo_start_xmit functions, and the network core calls them through the table.

  1. Observer
  2. Strategy (a function-pointer vtable)
  3. Singleton
  4. Chain of Responsibility
The core depends on one interface and each driver supplies the behaviour: Strategy, implemented as a hand-made vtable (some call it Bridge, since the core and drivers vary independently).
