Q&A: structural patterns (Decorator, Proxy, Adapter, Facade, Composite)

Price a coffee (or pizza) with any mix of add-ons. Why Decorator and not inheritance?

Reported as a configurable pizza at Zomato (2025-09-19); Visa asked for "decorator pattern and example" (2026-04-03); an Amazon SDE-1 candidate solved the hinted problem with Decorator (2025-07-03).

With inheritance, every combination is a class: CoffeeWithMilk, CoffeeWithMilkAndCaramel... 3 add-ons already give 8 classes, and "double milk" is impossible. With Decorator, each add-on is one class that implements the same Beverage interface and wraps another Beverage. cost() = inner cost + my price. You stack them at run time in any order and any number.

How to answer

Say "class explosion" and show the count (2n), then write the wrapper in five lines. Mention one limit: order can matter (a discount decorator applied before or after tax), and deep stacks are hard to debug.

Likely follow-ups
  • How do you remove one topping? (rebuild the chain; or keep toppings as data with a Builder)
  • Where does the JDK use Decorator? (BufferedInputStream(new FileInputStream(..)))
Decorator vs Proxy: they have the same shape. What is the difference?

Both implement the subject's interface and hold a reference to it. Decorator adds responsibilities and always forwards; the client decides the stack. Proxy controls access: it may answer from cache, refuse, lazily create the real object, or call it over the network; the client usually does not know a proxy is there. Our runnable demo shows the decorator letting every read hit the disk, while the caching-auth proxy serves a repeat from cache and blocks a forbidden key (code).

Media.net asked candidates to put a transparent proxy between a client and a server (2026-08-02).

How to answer

"Same shape, different intent. Decorator adds and is stacked by the client. Proxy guards and usually manages the real object." Then one example of each.

Likely follow-ups
  • Kinds of proxy? (virtual/lazy, protection, remote, caching, logging)
  • Is a Java dynamic proxy (java.lang.reflect.Proxy) a Proxy or a Decorator? (a mechanism; it can be either)
A library has consumers that speak XML, JSON or CSV and must convert any format to any other. Which pattern?

Microsoft LLD question (2024-10-27); the poster's own guess was Strategy.

The key insight is the count. Direct converters for N formats need N x (N-1) classes (XML-to-JSON, JSON-to-CSV...). Instead define one canonical model (a tree of records). Each format gets one Adapter pair: parse(bytes) -> Model and write(Model) -> bytes. Now N formats need 2N pieces, and a new format touches nothing else. A Factory/registry picks the adapter from the format name, and the converter itself is a tiny Facade: convert(src, srcFmt, dstFmt). Strategy is also a fair name for "pick a parser at run time"; say both and explain that the shape (interchangeable implementations behind one interface) is the same.

How to answer

Lead with "N squared vs 2N" before any pattern name. It shows design thinking, and the patterns then fall out naturally. This is how compilers work too: many front-ends, one IR, many back-ends.

Likely follow-ups
  • How do you stream a 5 GB file? (event-based parse to a streaming writer, not a full tree)
  • What if CSV cannot represent nesting? (validation error, or a flattening rule)
Adapter vs Facade.

Adapter converts one existing interface into the one your code expects; it wraps one object and adds no new feature (a Stripe client behind your PaymentProvider interface). Facade gives a simpler entry point to a whole subsystem of many classes (OrderService.placeOrder() calling inventory, payment, notification). Adapter is about shape, Facade is about size. A Razorpay logger candidate offered "Facade and Factory" as one of two designs (2024-03-05).

How to answer

"Adapter: one object, wrong shape. Facade: many objects, too complex." Pages: Adapter, Facade.

Likely follow-ups
  • Adapter vs Bridge? (Adapter is a retrofit; Bridge is designed up front to vary two dimensions)
Design a calculator for expressions like 2 + (3 * 4) using Composite.

Oracle onsite (2024-12-07). Define interface Expr { double eval(); }. A leaf Num returns its value. A composite BinaryOp holds two Expr children and an operator, and its eval() evaluates the children and combines them. 2 + (3 * 4) becomes Add(Num 2, Mul(Num 3, Num 4)). The client calls eval() on the root and never asks "is this a leaf?". Adding Pow is one new class.

interface Expr { double eval(); }
record Num(double v) implements Expr { public double eval() { return v; } }
record Bin(char op, Expr l, Expr r) implements Expr {
    public double eval() {
        double a = l.eval(), b = r.eval();
        return switch (op) { case '+' -> a + b; case '-' -> a - b; case '*' -> a * b;
                             case '/' -> a / b; default -> throw new IllegalArgumentException("op " + op); };
    }
}
How to answer

Model first, parser second. If asked to parse the string, use two stacks (shunting-yard) or recursive descent that builds the tree. Mention Interpreter (Composite plus a grammar) and Visitor (to add print() or simplify() without touching node classes).

Likely follow-ups
  • How to handle divide by zero?
  • Replace the switch with one class per operator: is that better? (OCP vs simplicity)
Design an in-memory file system. Which pattern holds files and folders?

Composite again: abstract class Node { name; parent; size(); }, File extends Node (leaf, holds bytes), Directory extends Node (holds a Map<String, Node> of children; size() sums them). ls, mkdir -p, find all walk the tree without type checks. In-memory file systems were the most common Uber LLD coding problem in our scan (for example 2026-01-15, 2026-04-20 with wildcard search).

From your world

The VFS dentry tree is a composite of directory and file dentries, each pointing to an inode whose inode_operations table differs by type. Path walk (link_path_walk) is the recursive "find child by name" you will write.

How to answer

Draw Node, File, Directory; use a map for children (O(1) lookup by name); keep the path parser in a separate class. Full design: In-Memory File System.

Likely follow-ups
  • Support * wildcards (a trie or a DFS with pattern matching)
  • Make it thread-safe (a lock per directory, or one read-write lock)
When would you use Flyweight or Bridge? (the "rare" structural patterns)

Flyweight: millions of small objects that share most of their data. Split state into intrinsic (shared, immutable: a glyph's font outline, a tree type's texture) and extrinsic (per use: position). Keep shared parts in a factory cache. Java's Integer.valueOf() cache for -128..127 is a flyweight.

Bridge: two dimensions that vary independently, like shapes and renderers, or notifications (alert, reminder) and channels (SMS, email). Without Bridge you get M x N subclasses; with it you get M + N classes, the abstraction holding a reference to the implementor.

From your world

The kernel's block layer is a Bridge: file systems (abstraction) talk to struct block_device, and drivers (implementors) plug in behind it. Neither side knows the other's concrete type.

How to answer

Flyweight: "share the immutable part". Bridge: "M x N becomes M + N". Pages: Flyweight, Bridge.

Likely follow-ups
  • Is a string intern pool a flyweight? (yes)
