Red-flag phrases: what you say vs what the evaluator writes

Evaluators write short notes during the round. Some phrases you say turn straight into a bad note. Here is our own translation table, built from the guides and from the feedback that candidates quoted.

You say or doThe note they writeSay or do instead
"Let me start coding" (minute 2)Did not clarify scope"Let me list what I think P0 is and check it with you."
"I'll use Factory, Strategy, Observer and Singleton here"Pattern-driven, not problem-driven"Fee rules vary, so fee calculation is an interface. Everything else is plain classes."
"I'll handle errors later"No error handlingThrow a named exception on the first invalid id you write.
"Just add synchronized"Shallow concurrency"The race is two bookings on the same seat. I lock per seat, so different seats proceed in parallel."
Long silence while typingCould not judge reasoningOne sentence per decision: "Map from id to order, because every API takes an order id."
"It works on my machine, it was compiling earlier"Not demoableRun the driver live, top to bottom, before you hand over.
"To add a new vehicle I'd add a case in these five places"Not extensible"A new vehicle is one new class; the spot matcher reads a rule table."
Reading every line during the demoPoor communicationTwo-minute overview: layers, then one flow, then "what I would change next".
Arguing with feedback mid-roundNot coachable"Good point. Here is how I'd change it." Then change it.
