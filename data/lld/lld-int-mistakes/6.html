Mistake 4 up close: one class per thing instead of per kind of thing

This one is worth seeing in code because it looks tidy and is still wrong. A CRED machine-coding problem (2023-08-31) asked for a tiny CPU: four registers A-D and instructions such as SET, INC, DEC, MOVE and ADDR, read as text commands. The candidate wrote four classes, RegisterA to RegisterD, a service holding one field per register, and a switch to find the right one. They were rejected and asked online how to model it better.

From your world

You would never write struct eth0_dev, struct eth1_dev. You write one struct net_device and keep instances in a list or hash keyed by name. Instructions work the same way: a CPU decoder is a table from opcode to handler, like sys_call_table. Adding an opcode adds a row; it does not edit the other handlers. Strictly, that is a dispatch table (table-driven dispatch, close to Strategy): the handlers are stateless and the arguments arrive at call time. Turn each parsed line into an object that carries its own arguments (new SetInstruction("A", 25)) and you have the GoF Command pattern, which gives you a program you can queue, log, replay or undo. Each Java lambda below is an anonymous function whose pointer is stored in the table.

// one class per INSTANCE; register E = new class + field + switch case
static class RegisterA { int value; }
static class RegisterB { int value; }   // ... C, D

int get(String r) {
    switch (r) {
        case "A": return a.value;  case "B": return b.value;
        case "C": return c.value;  case "D": return d.value;
        default:  return 0;        // silent bug: unknown register reads as 0
    }
}
void run(String line) {           // every new instruction edits this method
    String[] p = line.trim().split("\\s+");
    if (p[0].equals("SET"))       set(p[1], Integer.parseInt(p[2]));
    else if (p[0].equals("INC"))  set(p[1], get(p[1]) + 1);
    else if (p[0].equals("MOVE")) set(p[1], get(p[2]));
    // ...
}
static final class Register { private int value; int get() { return value; } void set(int v) { value = v; } }

static final class RegisterFile {               // instances are DATA in a map
    private final Map<String, Register> regs = new LinkedHashMap<>();
    RegisterFile(String... names) { for (String n : names) regs.put(n, new Register()); }
    Register of(String name) {
        Register r = regs.get(name);
        if (r == null) throw new InvalidCommandException("unknown register " + name);
        return r;                                // fails loudly, never a silent 0
    }
}

interface Command { void execute(RegisterFile rf, String[] args); }

static final class Cpu {                         // opcode -> handler table
    private final RegisterFile rf;
    private final Map<String, Command> isa = new HashMap<>();
    private final Map<String, Integer> arity = new HashMap<>();
    Cpu(RegisterFile rf) { this.rf = rf; }

    Cpu register(String op, int args, Command body) {   // the lambda IS the Command: a function pointer in a table
        isa.put(op, body); arity.put(op, args); return this;
    }
    void run(String line) {
        String[] p = line.trim().split("\\s+");
        Command c = isa.get(p[0]);
        if (c == null) throw new InvalidCommandException("unknown op " + p[0]);
        if (p.length - 1 != arity.get(p[0])) throw new InvalidCommandException(p[0] + " needs " + arity.get(p[0]) + " args");
        c.execute(rf, Arrays.copyOfRange(p, 1, p.length));
    }
}

static int num(String s) {                       // parse errors become our own exception
    try { return Integer.parseInt(s); }
    catch (NumberFormatException e) { throw new InvalidCommandException("not a number: " + s); }
}

// wiring: a new instruction is one line, nothing else changes
RegisterFile rf = new RegisterFile("A", "B", "C", "D");
Cpu cpu = new Cpu(rf)
    .register("SET",  2, (f, a) -> f.of(a[0]).set(num(a[1])))
    .register("INC",  1, (f, a) -> f.of(a[0]).set(f.of(a[0]).get() + 1))
    .register("MOVE", 2, (f, a) -> f.of(a[0]).set(f.of(a[1]).get()))
    .register("ADDR", 2, (f, a) -> f.of(a[0]).set(f.of(a[0]).get() + f.of(a[1]).get()));

// follow-up "add MUL": one more line, nothing else changes
cpu.register("MUL", 2, (f, a) -> f.of(a[0]).set(f.of(a[0]).get() * f.of(a[1]).get()));
class RegisterFile:
    def __init__(self, *names):
        self._regs = {n: 0 for n in names}

    def get(self, name):
        if name not in self._regs:
            raise InvalidCommand(f"unknown register {name}")
        return self._regs[name]

    def set(self, name, value):
        self.get(name)            # validates the name first
        self._regs[name] = value


class Cpu:
    def __init__(self, rf):
        self.rf, self.isa = rf, {}          # op -> (arity, fn)

    def register(self, op, arity, fn):
        self.isa[op] = (arity, fn)
        return self

    def run(self, line):
        op, *args = line.split()
        if op not in self.isa:
            raise InvalidCommand(f"unknown op {op}")
        arity, fn = self.isa[op]
        if len(args) != arity:
            raise InvalidCommand(f"{op} needs {arity} args")
        fn(self.rf, *args)
$ java RegisterBefore
before: A=51 B=26 get("Z")=0 (SET Z silently lost: get fell through to default 0)

$ java RegisterAfter
SET A 25  -> A=25 B=0 C=0 D=0
MOVE B A  -> A=25 B=25 C=0 D=0
INC B     -> A=25 B=26 C=0 D=0
ADDR A B  -> A=51 B=26 C=0 D=0
SET Z 5   -> rejected: unknown register Z
JMP A     -> rejected: unknown op JMP
SET A x   -> rejected: not a number: x
MUL B A   -> A=51 B=1326 C=0 D=0

Four rubric boxes move at once. Entity modelling: one concept, one class. Extensibility: register E is one more name in the constructor, MUL is one more line. Error handling: bad register, bad op, wrong arity and non-numbers all fail loudly. Testability: every command is a small function you can test alone. The full files (Java before/after and Python) compile and run; they live in lld-code/lld-int-mistakes/ next to this page's source.

The general rule. If two classes differ only in a name or a number, they are one class with two instances. If two branches of a switch differ in behaviour and more may come, they are a table of handlers (a dispatch table: Strategy, or Command once each request becomes an object). See Command and Strategy.
