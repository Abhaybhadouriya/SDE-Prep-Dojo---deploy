Remember this

  • Two gates, then scores: it runs and P0 is complete come first; structure, extensibility, errors and concurrency decide the grade.
  • Ask in minute one whether they want running code. Wrong round type is a silent killer.
  • Class per concept, never per instance; variants go in a table or behind an interface.
  • Compile and run after every feature, at least every 10-15 minutes; write the driver before any bonus.
  • Every prompt hides one core algorithm (eviction, matching, the window). Write it in real code.
  • Fail loudly and politely: named exceptions for bad ids and illegal transitions, shown in the driver.
  • Concurrency answer = the race, the lock scope, the mechanism, the proof.
  • Explain top-down in two minutes; justify each pattern by what varies.
  • Single feedback is noisy. Fix what repeats across many reports.
