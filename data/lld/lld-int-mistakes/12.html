The two-minute check before you say "done"

Run this list at minute 80 of a machine-coding round, at minute 50 of a code-design round, or before you stop drawing in a whiteboard round.

  1. It runs from clean. Fresh build, run the driver or tests top to bottom. No warnings you cannot explain.
  2. Every P0 appears in the driver output, in the order of the brief, with readable labels.
  3. Three bad inputs are shown failing politely: unknown id, illegal state change, invalid argument.
  4. One concurrency proof if shared state exists: a small thread race with the expected single winner.
  5. Assumptions written down at the top of the driver or a README.
  6. You can name each change point and the one class a new variant would add.
  7. No dead code or commented-out experiments; names say what things do.
  8. You know your answer to the database question (swap the repository; locks become row locks or version checks).

Whiteboard round version: steps 2-3 become "trace one happy path and one failure path aloud with real values", step 4 becomes "say where the lock goes and why".
