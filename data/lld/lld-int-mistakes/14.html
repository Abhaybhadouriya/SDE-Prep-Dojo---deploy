Quiz

At minute 70 of a 90-minute machine-coding round, one P0 feature is broken and a bonus feature is half done. What do you do?

  1. Finish the bonus, it shows more design skill
  2. Fix the broken P0 with the simplest correct code and add it to the driver
  3. Delete the broken feature from the driver so the demo looks clean
P0 completeness is a gate. Bonus features earn little or nothing if a P0 is broken (the Flipkart brief says bonus only after P0).

A candidate writes classes RegisterA, RegisterB, RegisterC and RegisterD. Which rubric box does this mainly fail?

  1. Concurrency
  2. Readability
  3. Entity modelling and extensibility
They are four instances of one concept. One Register type in a map makes adding a register a data change, not a code change.

"Modular but not extensible" most likely means:

  1. The code is split into files, but a new variant needs edits in many of them
  2. The code has no classes
  3. The code is missing comments
Extensible means a new requirement is a new part. Many files that all change together are modular in shape only.

The interviewer asks how to make seat booking thread-safe. The strongest first sentence is:

  1. "I'll mark every service method synchronized."
  2. "I'll use a ConcurrentHashMap for seats."
  3. "The race is check-free-then-book on one seat, so I make that transition atomic per seat."
Name the race and the smallest lock scope. A global lock is correct but serial; a concurrent map does not protect your check-then-act on a value.

In a machine-coding evaluation call, how should you start the walkthrough?

  1. Read the code line by line from Main
  2. A two-minute overview: problem, layers, one flow, what is done and not done
  3. Start with the bonus features
workat.tech lists line-by-line walkthroughs as a red flag. Top-down shows structure and saves time for their questions.

"How would you add a real database?" The best short answer:

  1. "Add a new repository implementation and change one line of wiring; locks become row locks or version checks and multi-step writes need transactions."
  2. "Rewrite the services to call SQL directly."
  3. "It doesn't matter for this round."
Show the seam (interface + composition root) and the parts that are not a simple swap.

Which question should you ask in the first minute of any LLD round?

  1. "Which design patterns do you want me to use?"
  2. "Can I skip the driver?"
  3. "Do you want running code, or class design with the key methods?"
Interviewers differ even inside one company. Guessing the round type wrong fails rounds even with a good design.
