Round-specific traps

Some mistakes only hurt in one kind of round. Each row has a real report behind it.

🧑‍🏫

Whiteboard (A)

Classes but no core logic. The Amazon cache candidate explained classes, named LRU, never wrote it (2025-07-15). Running out of time: Amazon slots share the hour with Leadership Principle questions; one chess design got only 25-30 minutes (2025-02-09). Unasked requirements: Zepto expects functional and non-functional requirements (FRs, NFRs), classes, schema and APIs in 60 minutes.

⌨️

Machine coding (B)

One broken P0. A Flipkart candidate with otherwise clean, modular code lost the round on a bug in one main feature (2025-04-19). Unfinished ordering logic at Razorpay (2024-11-05). Unfinished core method at Dream11 (2025-04-01).

🧪

Code design (C)

No tests, or tests that do not run. Atlassian wants your test framework ready. Rewriting for each follow-up instead of extending. Skipping clarifying questions: the Atlassian snake-game round expects questions such as "what happens at the boundary?" (2025-07-14).

Hybrid rounds have their own trap. Walmart "LLD" rounds often turn into Java concurrency and Spring questions (Callable vs Runnable, double-checked locking, volatile) after a short design (2024-12-14). Being strong at classes but weak at your language's threading API fails the round anyway. See Concurrency interview questions.
