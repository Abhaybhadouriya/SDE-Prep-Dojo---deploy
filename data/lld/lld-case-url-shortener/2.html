Clarify the requirements

Functional (P0)

  1. Shorten Given a long URL, return a short link https://sho.rt/<code>. Codes use base62 (0-9, a-z, A-Z).
  2. Resolve Given a code, return the long URL (the server answers with a redirect), or "not found".
  3. Validate Only http and https URLs with a host, at most 2,048 characters, and never a link to the shortener itself (a redirect loop).
  4. Custom alias A user may ask for sho.rt/team-docs: 3 to 30 characters of letters, digits, _ and -, not a reserved word like admin or api. If it is taken, fail clearly; never silently pick another.
  5. Expiry A link may have a time to live. After it, resolve answers "expired".
  6. Analytics Count clicks per link; list the top K links.
  7. Delete Only the owner may delete a link.

P1 (follow-ups)

  • Dedupe: the same long URL returns the same code (optional; see below).
  • Clicks per day, by country or referrer; a click event stream.
  • Rate limits per user; blocking malicious URLs; unguessable codes.
  • Swap in-memory storage for a database without changing the service.

Non-functional

  • Unique codes, even when many threads shorten at the same time.
  • Short codes: 7 base62 characters give 627 = 3,521,614,606,208 (about 3.5 trillion) codes.
  • Fast resolve: one hash map lookup; reads far outnumber writes.
  • Testable: time and randomness are injected, so expiry and collisions can be tested in microseconds.

Out of scope (say it)

Sharding, replication, caches, a key generation service, CDN and multi-region: those are the HLD version. HTTP servers and HTML: the service returns a status and a URL, and a controller would turn that into a response.
