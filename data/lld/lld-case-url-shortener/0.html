The story: the cloakroom tokens

Explain like I'm 5

At a theatre, you hand your big heavy coat to the cloakroom. The person gives you a tiny token with a number on it, say 417. Later you show token 417 and you get your coat back. The token is small and easy to carry; the coat is big.

The cloakroom has three ways to pick numbers. It can count up: 1, 2, 3 (easy, but anyone can guess the next token). It can shuffle a bag of random tokens (hard to guess, but two people might draw the same number, so it must check). Or it can make the number from the coat itself, like "blue coat with 3 buttons = 317" (the same coat always gets the same number, but two different coats can come out with the same number). Some coats are only kept until midnight: after that the token is no good.

A URL shortener is that cloakroom. The coat is the long URL, the token is a short code (like 4c92 in https://sho.rt/4c92), and the three ways of picking numbers are three code generation strategies. Checking "is this token already given out?" is collision handling. "Kept until midnight" is expiry. Counting how often each token is shown is analytics. In the LLD round you design these as classes and make them correct under many threads. Scale, sharding and caches belong to the HLD round.

From your world

A counter code is like an old TCP initial sequence number: unique and cheap, but predictable, which is why ISNs were randomised (RFC 6528). A hash code is like jhash() picking a conntrack bucket: the same input always lands in the same place, and different inputs can collide. "Claim the code" is a compare-and-swap: putIfAbsent succeeds for exactly one thread, like cmpxchg on a slot. Per-link click counters are LongAdder, which is a per-CPU counter (percpu_counter) summed when read. Expired links are aged out lazily on lookup plus a periodic sweep, like neighbour-table entries and their garbage collector.

Interfaces in C terms: every interface on this page is, in C, a struct of function pointers; each implementation fills one in, like file_operations. Java and C++ build that table (the vtable) for you, and every object carries a pointer to it. More in OOP from C structs and polymorphism and vtables.
