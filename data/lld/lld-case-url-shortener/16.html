Interview follow-ups

How do you generate the short code? Which option do you pick?

Behind a CodeGenerator interface, three options: a counter encoded in base62 (no collisions, short, but guessable), a hash of the URL reduced to its low 7 base62 digits, n mod 627 (same URL gives the same code, but different URLs can collide), or random characters (unguessable, can collide). I start with the counter because it is simplest and collision-free, and I make every generator go through the same atomic claim, so switching to random later is one line in the wiring.

How to answer

List the three, give one strength and one weakness each, pick one for the stated requirements, and show that the choice is pluggable.

Likely follow-ups
  • How long must codes be for 1 billion links? (626 is about 56.8 billion, so 6 characters are enough for a counter; use 7 for random codes to keep collisions rare.)
Every hash function collides. So how can you use a hash?

Treat a collision as a normal event, not an error. Hash url + "#" + attempt; try to claim the code atomically; if another URL holds it, increment the attempt and hash again; give up after a small number of attempts and alert. If the code is taken by the same URL, that is not a collision but a dedupe hit: return it. With 7 characters, collisions are rare, so the retry loop almost never runs twice.

Likely follow-ups
  • Why include the attempt in the input instead of taking the next 7 characters of the hash? (Either works; the attempt version works for any length and any hash.)
How do links expire?

Each link stores expiresAt (or none). resolve checks it on every read: if now >= expiresAt it returns EXPIRED (HTTP 410) without counting a click. That alone is correct. To free memory, a scheduled job calls purgeExpired(). Time comes from an injected Clock, so the test moves a fake clock by 61 seconds instead of sleeping. In a database the same idea is a TTL attribute plus a cleanup job, or a "WHERE expires_at > now()" on reads.

Likely follow-ups
  • Can an expired code be reused? (Only after purge, and only if you accept that old printed links may point somewhere new; many services never reuse.)
Two threads generate the same code at the same moment. What happens?

Exactly one wins, because the only insert is saveIfAbsent, backed by ConcurrentHashMap.putIfAbsent (or a unique key in SQL). The loser sees false and retries with the next attempt. A design with if (!exists(code)) save(code) has a gap between the check and the save, and the second save silently overwrites the first user's link.

Same long URL shortened twice: same code or a new one?

Ask. Same code saves space and is what most people expect, but it needs a URL-to-code index and care: normalize the URL first, keep links with a TTL or a custom alias out of the dedupe (otherwise a temporary link hijacks the permanent one), and make the insert race-free (computeIfAbsent). A new code per request is simpler and lets each user see their own click counts. Our code supports both with a flag.

Ownership trade-off. Once links have owners, key the dedupe index by (owner, normalizedUrl), not by URL alone. Keyed by URL, Ben shortening a URL Asha already shortened would get Asha's link: he could not delete it, his clicks would mix with hers, and when she deleted it his link would die. Our code keys by owner (anonymous links share the anonymous owner), and demo 6b checks that Ben's link survives Asha's delete. If storage matters more, split it into one shared target row plus a small per-owner link row.

301 or 302 for the redirect?

301 is permanent: browsers and proxies may cache it, so repeat visits skip the server. That cuts load but breaks click analytics, expiry and editing for those visitors. 302 (or 307) is temporary and keeps every click coming through. For a service with analytics and expiry, 302.

Counter codes are guessable. How do you fix that without collisions?

Keep the counter for uniqueness, but pass it through a reversible scramble over the code space before base62: for example multiply by a large number coprime to 627 and take the result mod 627, or run a small Feistel network. Because it is a permutation, different counters always give different codes, and neighbours look unrelated. Random codes are the other answer, at the cost of retries.

Where does a database go in your design?

Behind UrlRepository. A JdbcUrlRepository implements saveIfAbsent as an INSERT into a table with a primary key on code; a duplicate-key error returns false, which the service already treats as a collision. find is a primary-key lookup. Nothing in the service, generators or tests changes, and the in-memory repository stays as a test double.

How do you count clicks for a link that gets 10,000 hits a second?

In process, a LongAdder per link: increments go to per-thread cells and do not fight over one cache line; reading sums the cells. For per-day or per-country stats, a listener publishes click events and something else aggregates them, so the redirect stays fast. In HLD terms that becomes a stream (Kafka) and batch counters, and the exact count may lag a little, which is fine for analytics.

What do you validate before shortening?

Scheme is http or https (no javascript:, no ftp:), there is a host, length at most 2,048, and the host is not our own (a short link to a short link can loop). Aliases: 3 to 30 of letters, digits, _, -, not reserved words that collide with our own routes (api, admin), compared case-insensitively. Then normalize: lower-case scheme and host, drop the fragment. Each failure is a specific exception the controller maps to 400.
