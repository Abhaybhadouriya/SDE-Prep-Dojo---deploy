How it is asked

Before you start: this case assumes OOP from C structs (objects as structs with an ops table) and interfaces vs abstract classes. The patterns it uses are explained on their own pages: Strategy, Repository, Facade, Observer. The thread-safety section builds on concurrent collections and atomics (putIfAbsent, LongAdder).

As a system design question, the URL shortener is the most common warm-up there is. As an LLD question it is less frequent but real: it appears in 3 of the 16 LLD course and question-bank sources we surveyed (AlgoMaster, the Coding Shuttle LLD handbook, and a LeetCode LLD question bank), and in interview reports. The hard part for candidates is not the code; it is knowing which round they are in.

The coding core is LeetCode 535 Encode and Decode TinyURL (free): encode(longUrl) and decode(shortUrl). Our shorten and resolve are that pair, grown into a real design.

Both reports point at the same two follow-ups: collisions ("what if two URLs get the same code?") and expiry ("how do links expire?"). Have one sentence ready for each before you write any code. And say early which round you think it is: "I will design the classes for one process in memory, with the storage behind an interface; tell me if you want the distributed version."
