Core flows: shorten and resolve

  1. The client asks to shorten a URL (optionally with an alias, a TTL and an owner).
  2. The validator rejects bad input (wrong scheme, no host, too long, our own host) and normalizes the rest: lower-case scheme and host, drop the #fragment. Normalizing first makes dedupe work for Example.com and example.com.
  3. Generate a code and claim it atomically; on a clash, try the next attempt (at most 5).
  4. Return the short link. With dedupe on, a second shorten of the same URL returns the same code.
  5. Later, a visitor opens the link: one map lookup by code.
  6. If the link has expired, answer "expired" without counting. Otherwise count the click and notify listeners (per-day stats, an event stream).
  7. The controller maps the outcome to HTTP: 302 Found with a Location header, 404 Not Found, 410 Gone.
