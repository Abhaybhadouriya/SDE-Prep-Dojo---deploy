This is the heart of the question. All three are in the code; know when each wins.

  1. The generator makes a code from the URL and an attempt number. For a hash, that is SHA-256 of url#0, read as a 63-bit number, and its lowest 7 base62 digits (n mod 627, padded with leading zeros).
  2. The service tries to claim it with one atomic call. There is no separate "exists?" check, so no other thread can slip in between.
  3. In our demo, a different URL already holds XKOaYAw, so the claim fails.
  4. Retry with attempt 1: a new hash, a new code, and the collision counter goes up (a metric you would alert on).
  5. The claim succeeds. Every step is the same for random codes; for the counter, the claim never fails unless someone took that code as a custom alias.
  6. A broken or exhausted generator must not spin forever: after 5 attempts we throw. Our test uses a generator that always returns "same" to prove it.

How often do random codes collide? With N possible codes and n codes already used, a new random draw collides with probability n / N. For 7 characters, N is 3.5 trillion, so even after 1 billion links the chance per draw is about 0.03%. To see collisions we used 3-character codes in the demo (N = 238,328): the birthday estimate for 8,000 codes is n2 / 2N, about 134 collisions, and our C++ run measured 120, all retried successfully.

Do not take a prefix of the full encoding. Writing a 63-bit hash in base62 gives 10 or 11 digits, most significant first. The leading digit of a number below 263 can only be 1 to 10, so "the first 7 characters" has about 11 choices in its first slot instead of 62: the real code space is about 10 x 626 (5.7 x 1011), six times smaller than 627, and collisions are six times more likely. The low-order digits are uniform. It is the same trap as taking the top bits of a small counter in C: the high bits barely change. Demo 7b checks that the first character takes all 62 values over 10,000 URLs.

A custom alias can occupy a code the counter will produce later (someone asks for 4c95). Because every generated code also goes through saveIfAbsent, the counter simply moves on. Two cheaper fixes: require aliases to contain a character the generator never uses (like -), or keep aliases in a separate namespace.
