Interview Q&A

How does C achieve polymorphism without classes? Give a kernel example.

With a struct of function pointers (an ops table) that each object points to. Generic code calls obj->ops->method(obj, ...) without knowing the concrete type. file_operations: read() on any file calls file->f_op->read_iter of ext4, NFS or a driver. A C++ compiler builds the same thing for virtual functions: one vtable per class and a hidden vptr per object.

How to answer

Mechanism, example, then the C++ equivalence.

Likely follow-ups
  • What does a NULL entry in an ops table mean?
  • How do you do inheritance in C? (container_of.)
Explain container_of and why the kernel prefers embedding over a void * private pointer.

container_of(ptr, type, member) subtracts the member's offset from a pointer to an embedded member to get a pointer to the enclosing struct. Embedding the generic struct inside the specific one gives one allocation, no extra pointer chase and a typed conversion, like inheritance. A void * needs a second allocation, an extra dereference and an unchecked cast, so the LWN analysis calls it usually a poor choice.

How to answer

Define it, then compare the two layouts on allocations, indirection and type safety.

Likely follow-ups
  • Which Java concept matches embedding? (Inheritance; downcast with a cast.)
Notifier chains vs netfilter hooks: which patterns are they and how do they differ?

Both are priority-ordered lists of callbacks. A notifier chain is Observer: an event is broadcast to every registered block, which usually returns NOTIFY_DONE; stopping is the exception. Netfilter is Chain of Responsibility: a packet visits hooks in order and any hook may end processing with a verdict (NF_DROP, NF_STOLEN, NF_QUEUE). The default in one is "everyone hears", in the other "anyone may stop".

How to answer

Shared shape first, then the default behaviour of each.

Likely follow-ups
  • How would you make a Java observer list safe if listeners unsubscribe during a notification? (Copy-on-write list, like CopyOnWriteArrayList; the kernel uses locking or RCU-based chain variants.)
Why does work queued for later need to hold a reference to the object it uses?

Because the object can be released between queueing and running. If the work only holds a raw pointer and the owner drops the last reference first, the worker touches freed memory. Taking a reference (kref_get, dev_hold) before queueing and dropping it at the end of the work function makes the order irrelevant: whichever put is last frees the object. In C++ capture a shared_ptr in the task; in Java hold the resource handle and release it in finally.

How to answer

Describe the use-after-free race, then the ownership rule that fixes it.

Likely follow-ups
  • What if the object must be torn down before the work runs? (Cancel the work synchronously, for example cancel_work_sync(), then drop the reference.)
What is the "midlayer mistake" and how does it apply to object-oriented design?

A midlayer takes control between a top layer and the drivers, does common work and then calls the drivers; because it must anticipate every driver's needs, it accumulates special cases. The kernel prefers a library: the top layer calls the driver, and the driver calls shared helpers it can use, extend or skip. In OOP terms, avoid a rigid framework base class with type checks and special flags; prefer composition, small helpers and injected strategies, which keeps you Open/Closed.

How to answer

Define both, give the page-cache example, then translate to inheritance vs composition.

Likely follow-ups
  • Is Template Method always a midlayer? (No; it is fine when the skeleton is stable and hooks are few.)
Is a workqueue the Command pattern? Who are the participants?

Yes. The work_struct with its function pointer and embedded context is the command (request as an object). The code that calls INIT_WORK and queue_work is the client. The workqueue and its worker pool are the invoker, which decides when and on which thread to run it. The objects the work function touches are the receivers. Java equivalent: a Runnable submitted to an ExecutorService.

How to answer

Map each GoF participant to a kernel object.

Likely follow-ups
  • What does Command add beyond a callback? (Queueing, scheduling, cancellation, logging, undo.)
The TCP stack uses a state field and switch statements, not State classes. Is that bad design?

No. The TCP state set is fixed by the protocol, small and performance-critical, so an enum with switches is clear and fast. The State pattern pays off when states carry a lot of behaviour, new states keep being added, or transitions are business rules that change. A good answer states the trade-off and picks per case.

How to answer

Defend both choices with criteria: stability of the state set, amount of behaviour per state, hot path.

Likely follow-ups
  • How would you model a vending machine? (State classes, or a transition table.)
