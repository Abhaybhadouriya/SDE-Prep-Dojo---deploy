In interviews

Your kernel background is an asset in LLD rounds if you translate it. Interviewers do not expect kernel knowledge, so keep each mention to one sentence and land on the general pattern. Useful moments:

  • Explaining interfaces and polymorphism: "like file_operations: one table of function pointers per implementation."
  • Notification service or pub-sub: Observer and its thread-safety, from notifier chains.
  • Rate limiter or logger: a filter chain, from netfilter.
  • Task scheduler: Command objects queued to a worker pool, from workqueues.
  • LRU cache: embedded list nodes and a hash map, from list_head; lifetime with reference counts when entries are shared.
  • Elevator, vending machine, traffic signal: State, compared with protocol state machines.
  • File system: Composite for directories and Bridge for storage back-ends, straight from the VFS.

Strong 30-second answer to "Have you seen design patterns in C?": "All the time in the Linux kernel. Ops tables like file_operations are interfaces with vtables, used as Bridge between the VFS and file systems. Notifier chains are Observer, netfilter hooks are Chain of Responsibility, workqueues are Command on a thread pool, slab caches are object pools, and kref is shared ownership like shared_ptr. The kernel also taught me to prefer libraries over midlayers, which is composition over inheritance."
