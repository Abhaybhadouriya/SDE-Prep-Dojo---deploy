Slab caches and mempools: Object Pool

kmem_cache_create() makes a pool for one object type; kmem_cache_alloc() and kmem_cache_free() borrow and return objects through per-CPU free lists, and an optional constructor runs when slab memory is first set up rather than on every allocation. mempool_t adds a guaranteed reserve so the I/O path can always make progress. Workqueues: Command plus a thread pool

struct my_ctx {
    struct net_device *dev;
    struct work_struct work;          /* the command, embedded with its arguments */
};

static void my_work_fn(struct work_struct *w)
{
    struct my_ctx *ctx = container_of(w, struct my_ctx, work);   /* recover the arguments */
    /* runs later, in process context, on a kernel worker thread: may sleep */
}

INIT_WORK(&ctx->work, my_work_fn);   /* build the command  */
queue_work(system_wq, &ctx->work);  /* hand it to the pool */

A work_struct is a Command: a request packaged as an object (function pointer plus, via embedding, its data) that can be queued and run later by someone else. The workqueue subsystem is the invoker, and since concurrency-managed workqueues (cmwq) the actual threads come from shared per-CPU worker pools, so you queue work without creating threads, which is what Java's ExecutorService.submit(Runnable) gives you. Interrupt handlers use this to defer slow work out of hard-IRQ context, the same way a web server hands slow jobs to a background executor.
