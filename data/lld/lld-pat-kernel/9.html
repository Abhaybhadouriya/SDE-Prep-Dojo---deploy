VFS and protocol state machines: Bridge, Facade and State

The VFS

The VFS is the kernel's largest example of several patterns working together. To user space, open, read, write and close are a Facade over page cache, dentry cache, permissions and the file system. Inside, struct file calls through f_op (file_operations), inodes through i_op, superblocks through s_op, and page-cache I/O through address_space_operations: a generic layer and a family of implementations growing independently, which is Bridge. And a file system's superblock producing its own inodes, each wired to that file system's ops, behaves like an Abstract Factory for a consistent family. More on the Bridge page.

TCP and other state machines

A TCP socket moves through TCP_SYN_SENT, TCP_ESTABLISHED, TCP_FIN_WAIT1, TCP_TIME_WAIT and the rest of the states defined in include/net/tcp_states.h, and the same incoming segment means different things in different states. The kernel implements this mostly with a state field and switch statements, which is the right call for a fixed protocol on a hot path. The State pattern is the object-oriented version: one class per state, each handling events and choosing the next state. Say both in an interview: "a switch on an enum is fine when the states are fixed and few; I'd use State classes when states carry behaviour and keep growing, as in a vending machine or ATM."
