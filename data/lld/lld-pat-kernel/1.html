The problem: C gives you structs and function pointers, nothing more

C has no class, no virtual, no interface, no inheritance, no destructors and no garbage collector. A program the size of the kernel still needs exactly what those features provide:

  • Polymorphism: one read() that works on ext4, NFS, a pipe and /dev/null.
  • Extension without editing the core: load a new driver or protocol as a module.
  • Lifetime management: know when the last user of an object is gone, across CPUs and interrupt context.
  • Decoupling: let the routing code hear that an interface went down without the driver knowing that routing exists.

The answer was to hand-build the same mechanisms out of structs and function pointers, consistently, for decades. The result is that the patterns are more visible in the kernel than in most Java code, because nothing is hidden by the compiler. Neil Brown's LWN series "Linux kernel design patterns" and the two-part LWN article "Object-oriented design patterns in the kernel" document many of them; this page follows those articles and adds the GoF names.
