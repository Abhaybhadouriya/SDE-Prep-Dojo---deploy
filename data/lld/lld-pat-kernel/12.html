What to copy from the kernel, and what not

Ideas worth copying into any design
  • Small, cohesive interfaces (one ops table per role) and optional operations with sensible defaults.
  • Explicit ownership: every pointer that outlives a call holds a reference, and exactly one put frees.
  • Registration instead of hard-wiring: drivers, protocols, hooks and observers register themselves, so the core never changes to add one (Open/Closed).
  • Libraries over midlayers: give control to the specific code and offer reusable helpers.
  • Priorities and verdicts made explicit in chains, so ordering is documented in code.
Things not to copy blindly
  • Hand-made vtables and container_of in a language that has interfaces and inheritance: use the language.
  • void * private data and untyped event payloads: in Java or C++, use typed events and generics.
  • Big switch state machines when states carry lots of behaviour that keeps changing: that is where the State pattern pays off.
  • Manual refcounting for plain memory in a garbage-collected language: keep it for external resources.
