Quiz

Which feed strategy makes posting cost grow with the number of followers?

  1. Push (fan-out on write)
  2. Pull (fan-out on read)
  3. Neither
Push copies the post into every follower's inbox at write time.

Uber asks that each user can choose how their feed is ranked. The cleanest design is:

  1. A boolean flag per ranking mode on the User class
  2. A FeedRanker strategy stored per user in a map
  3. A switch statement inside getFeed()
Ranking is a Strategy; a map from user to strategy gives per-user choice and new rules without edits.

What does a pull feed use to get the newest N posts across k followees efficiently?

  1. A heap holding one cursor per timeline (k-way merge)
  2. Sorting all posts in the system
  3. A linked list of all followees' posts
Each timeline is sorted already; a heap of size k merges them in O(k + N log k).

Why does each post carry a sequence number as well as a time?

  1. To save memory
  2. Because Java has no time type
  3. To break ties when two posts have the same timestamp, making the order total and stable
Without a unique tie-break, equal timestamps sort unpredictably and pages can repeat or skip posts.

A user votes up, then down, on the same post. What should the counters show?

  1. 0 up, 1 down
  2. 0 up, 0 down
  3. 1 up, 1 down
One vote per user: the second vote replaces the first.

In a push design, how do we handle unfollow cheaply?

  1. Scan and rewrite every inbox in the system
  2. Filter out posts by authors I no longer follow when reading the inbox
  3. Forbid unfollow
Lazy cleanup at read time costs nothing at unfollow; the cap ages old entries out.

Which kernel mechanism is the closest match to FeedListener?

  1. The scheduler run queue
  2. The page cache
  3. A notifier chain (register a callback, every callback is called on an event)
Notifier chains are the kernel's Observer: notifier_blocks are called in turn when the event fires.
