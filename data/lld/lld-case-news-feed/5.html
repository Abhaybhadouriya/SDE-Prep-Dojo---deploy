From your world

FeedRanker is a comparator function pointer, like the cmp argument of the kernel's list_sort() or sort() in lib/sort.c: the sorting code is fixed, the ordering rule is passed in. FeedListener is a struct notifier_block with its notifier_call: post() plays call_netdevice_notifiers(), walking the registered blocks. The one lesson the kernel adds: notifier callbacks must be quick and must not block, because they run inside the caller's path. The same holds here: a slow listener makes every post() slow, which is why big systems put a queue between the post and the fan-out.

Why the pattern earns its place: the if-ladder it replaces

Without the Strategy, pull and push live in one method behind a flag:

List<Post> feed(String user, int n) {
    if (mode == Mode.PULL) {
        List<Post> all = new ArrayList<>();
        for (String a : graph.following(user)) all.addAll(store.timeline(a));
        all.sort(NEWEST_FIRST);
        return all.subList(0, Math.min(n, all.size()));
    } else if (mode == Mode.PUSH) {
        return new ArrayList<>(inbox.get(user)).subList(0, n);
    } else if (mode == Mode.HYBRID) {   // follow-up: celebrities pulled, others pushed
        ...                             // and post() needs the same if-ladder for fan-out
    }
}
interface FeedGenerator {
    List<Post> candidates(String user, int limit);
}
final class PullFeedGenerator implements FeedGenerator { ... }   // k-way merge of timelines
final class PushFeedGenerator implements FeedGenerator, FeedListener { ... }   // inboxes

FeedPage feed(String user, int size, String cursor) {
    List<Post> c = generator.candidates(user, need);   // no mode flag anywhere
    ...rank, then page...
}

With the flag, the follow-up "hybrid fan-out for celebrities" edits both feed and post. With the interface it is one new HybridFeedGenerator class in Feeds.java; SocialNetwork keeps calling candidates.

From your world: the same move in C

struct feed_ops {
    int  (*candidates)(struct feed *f, const char *user, struct post **out, int limit);
    void (*on_post)(struct feed *f, struct post *p);   /* NULL for pull */
};
/* post(): if (f->ops->on_post) f->ops->on_post(f, p);  - no switch on the mode */

The "after" version is an ops table: the caller holds a pointer to a struct of function pointers and never asks which implementation it has, exactly as the VFS calls file->f_op->read() without a switch on the file system type.
