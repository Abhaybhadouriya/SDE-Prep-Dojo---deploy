Clarify requirements

Spend 5 to 8 minutes here. Read the prompt twice and underline every number: slot length, capacity, quota, cutoff. Each number is a test case the evaluator will run.

Functional (P0 - must work in the demo)

  1. Providers Register a doctor with a speciality (or a gym centre with a workout type) and a rating.
  2. Slots A provider declares slots of a fixed length (30 min for doctors, 60 for classes), each with a capacity and a waitlist limit. A provider's own slots never overlap.
  3. Search List open slots for a speciality, ranked by start time by default, by rating if asked.
  4. Book Confirm if there is a free seat, else join the waitlist if it has room, else reject.
  5. Rules No duplicate booking of the same slot; no two confirmed bookings at overlapping times; tier quota (Platinum 10, Gold 5, Silver 3).
  6. Cancel Frees the seat and promotes the head of the waitlist, who is notified. A cutoff (30 min before start) can block late cancels. Cancelling restores quota.
  7. View A user's bookings for the day, with status.

Functional (P1 - bonus, build if time allows)

  • Trending doctor: who has the most confirmed bookings right now (Flipkart bonus).
  • Admin cancels a whole class: everyone confirmed and waiting is cancelled and told (PhonePe).
  • Suggest up to 3 alternative slots for the same workout when the chosen one is full (FlipFit).
  • Pause a slot, reminders 15 minutes before, invite friends (Meesho SDE-3).

Non-functional

  • No overbooking under concurrency: 50 simultaneous requests for a 10-seat class give exactly 10 confirmed.
  • Extensible rules and ranking: a new rule or sort order is a new class, the service does not change.
  • Testable: the clock is injected, so "30 minutes before" is testable without waiting.
  • In-memory, no UI, a driver program: exactly what the prompt says; storage behind maps that could become a repository later.

Out of scope (say it out loud)

  • Payments, login and passwords (Flipkart: "login is optional"; names are identifiers).
  • Multiple days and time zones: one day, minutes since midnight. Say how you would add a date.
  • Persistence and distributed locking (a good follow-up, see follow-ups).
