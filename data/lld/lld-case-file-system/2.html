Clarify the requirements

Spend the first five minutes here. A file system has a hundred features; you will build six. Say out loud which six.

Functional (P0 = must, P1 = if time)

  1. P0 mkdir Create a directory at an absolute or relative path. Error if it exists or the parent is missing; mkdir -p creates missing parents and is quiet if it exists.
  2. P0 cd / pwd Change and print the current directory. . is "here", .. is "parent", and .. of / is / (as in Linux).
  3. P0 ls On a directory: child names, sorted. On a file: just its name (LeetCode 588 rule). A glob in the last part filters: ls /var/log/*.log.
  4. P0 files Write, append and read file content (echo >, echo >>, cat).
  5. P0 wildcard cd A bare * segment matches ., .. or any child directory; r* matches child directories by glob.
  6. P1 rm / rm -r, du, find Remove (refuse a non-empty directory without -r), total size of a subtree, and find with filters such as name, extension, size and type that can be combined with AND, OR, NOT.

Non-functional

  • In memory, single process. No disk, no persistence, no database.
  • Correct under concurrent use. Several shells (sessions) may work on the same tree at once; no lost writes, no torn tree.
  • Extensible. A new command or a new find filter should be a new class or method, not edits all over.
  • Fast enough. Path lookup costs O(depth) hash or tree lookups; find is O(nodes in the subtree).

Out of scope (say it, so nobody expects it)

Permissions and owners, hard links, mount points, file descriptors and seek, persistence, quotas. Each is a good follow-up, and extensibility shows where it would go.
