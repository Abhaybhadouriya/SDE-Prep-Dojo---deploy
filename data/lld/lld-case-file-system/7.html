APIs and interfaces

Agree on these signatures before coding. Every FileSystem method takes the caller's cwd so the tree itself stays stateless about sessions.

// per-session API (what the driver or a command parser calls)
class Shell {
    String pwd();
    void cd(String path);                 // absolute or relative; '*' and globs allowed
    void mkdir(String path);  void mkdirP(String path);
    List<String> ls(String path);         // sorted; a file lists itself; glob in last part filters
    void write(String path, String text); void append(String path, String text);
    String cat(String path);
    void rm(String path);     void rmR(String path);
    long du(String path);
    List<String> find(String path, Spec spec);
}

// shared, thread-safe tree
class FileSystem {
    Directory resolveDir(Directory cwd, String path);          // literal path, must be a directory
    List<Directory> resolveDirs(Directory cwd, String pattern); // every match, sorted
    void mkdir(Directory cwd, String path, boolean parents);
    ...                                                        // one method per command
}

interface Spec { boolean test(Node n); Spec and(Spec o); Spec or(Spec o); Spec not(); }

Errors are one unchecked FsException with Unix-style messages (no such file or directory, not a directory, is a directory, already exists, directory not empty). In a bigger codebase you would make subclasses or an error enum like errno; for 60 minutes one exception type with a clear message is the right size.
