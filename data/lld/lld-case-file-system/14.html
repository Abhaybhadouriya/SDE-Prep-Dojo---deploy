Interview follow-ups

Why model the tree as a Composite instead of one Node class with an isDirectory flag?

With a flag, a file would carry an empty children map and a directory would carry an empty content buffer, and every method would start with if (isDir). With Composite, each class carries only its own state and implements size() its own way, so du is one call on any node. The flag design is acceptable for a 30-minute LeetCode 588; in an LLD round it reads as "did not think about types".

How to answer

Name the pattern, show the three roles on your diagram, then mention you chose the safe variant (add/remove only on Directory) and why (LSP).

Likely follow-ups
  • Where would a symlink fit? (A third leaf type.)
  • Would you ever pick the transparent variant? (When a builder or parser must treat every node the same and a runtime error is acceptable.)
How does your cd handle * matching ".", ".." or any child?

I keep a set of current directories, starting with the cwd (or root for an absolute path). For each segment I map every directory to its candidates: * gives itself, its parent and its child directories; a glob gives matching children; a literal gives one child or nothing. I dedupe by identity and drop dead branches. After the last segment I sort by path and take the first. Cost is bounded by the number of directories visited per level.

How to answer

Draw the set for a two-segment example; say "breadth-first over segments" and state the tie rule you agreed at the start.

Likely follow-ups
  • What if the interviewer wants the first match in DFS order instead? (Recursive backtracking that returns on the first full match.)
  • Why dedupe? (".." of root is root, and two branches can meet at one parent.)
Where does the current directory live, and why not in FileSystem?

In a per-session Shell. The tree is shared by all users; the current directory is one user's state. If it lived in FileSystem, a second user's cd would move the first user. It also keeps FileSystem free of session state, which makes it easy to lock and test.

How to answer

Compare with processes: every process has its own cwd, the dentry tree is global.

Likely follow-ups
  • What if my cwd is deleted by someone else?
  • Can a session be shared by two threads?
Design the Unix find command so new filters can be added without changing find.

Separate the walk from the rule. The walk is written once: a pre-order traversal with an explicit stack that calls spec.test(node). Each rule is a small Specification object (name glob, extension, min size, type). Combinators and, or, not return new Specs, so any expression can be built. A new filter is one class or factory method.

How to answer

Write the interface first (boolean test(Node)), two concrete specs, then the combinators. Show one combined query.

Likely follow-ups
  • How would you parse -name a -o -size +10? (A small recursive-descent parser into a Spec tree; precedence NOT > AND > OR.)
  • How do you stop early, for example "first 10 results"? (Turn the walk into a lazy Iterator.)
How do you make it thread-safe, and how would you scale the locking?

Start with one read-write lock in FileSystem: reads shared, writes exclusive, no deadlock possible. If writes become a bottleneck, move to a lock per directory taken parent-only for create and remove, with a global order for two-directory operations like mv. For read-heavy loads, copy-on-write child maps let readers go lock-free.

How to answer

Name the race first (check-then-act in mkdir), then the coarse fix, then the fine one, then the deadlock rule.

Likely follow-ups
  • Why not ConcurrentHashMap for children? (It makes one map safe, not a multi-step operation like "check parent exists, then insert".)
  • What does Linux do? (i_rwsem per directory, RCU lookup, rename_lock.)
Implement mv. What is the tricky case?

Moving a directory into its own subtree: mv /a /a/b/c would detach /a and hang it below itself, creating a cycle unreachable from root. Before moving, walk up from the target's parent; if you reach the source, refuse. Also handle: target exists (replace a file, refuse a non-empty directory), moving onto itself (no-op), and updating the node's parent and name.

How to answer

Say the cycle case first; it shows you think in trees.

Likely follow-ups
  • Locking for mv? (Both parents, in a fixed order.)
One Uber candidate used a trie. Is a trie better than a tree of directories?

A directory tree is a trie whose alphabet is path segments: each node maps a name to a child. So the two are the same structure. A character-level trie over full path strings helps prefix search (/var/lo... autocomplete) but makes .., rename and per-directory listing awkward. Keep the segment trie (our Directory map) and add a side index only if a query needs it.

How to answer

Agree, then show they are the same idea at different granularity.

Likely follow-ups
  • HashMap or TreeMap for children? (TreeMap gives sorted ls for free at O(log n); HashMap plus a sort on ls is also fine.)
du is O(subtree) every time. Can you make it O(1)?

Cache the size in each directory and, on every content change of size delta d, add d to every ancestor. Reads become O(1), writes O(depth). Under concurrency the ancestor updates must happen in the same critical section as the write, or use atomic counters per directory and accept that a concurrent du may see a slightly stale total.

How to answer

Frame it as moving cost from reads to writes, then ask which is more frequent.

Likely follow-ups
  • What breaks on mv? (Subtract from old ancestors, add to new ones.)
How do you parse paths safely?

Split on /, drop empty segments (that handles // and trailing slashes), start at root if the path begins with /, otherwise at cwd. Walk one segment at a time: . stays, .. goes up (root stays root), a name looks up a child and must be a directory unless it is the last segment. Reject ., .. and wildcard characters as names when creating.

How to answer

Mention LeetCode 71 (Simplify Path) as the same rules on a string.

Likely follow-ups
  • Why not normalise the string first? (Without symlinks it is equivalent; with symlinks, a/../b depends on where a points, so you must walk.)
How would this change if the files lived on disk or on another machine?

The commands and the Shell stay the same. Directory and FileNode become interfaces with an in-memory and a stored implementation (Bridge), and lookups may now fail with I/O errors and be slow, so you add a cache of recently used nodes (a dentry cache) with invalidation. At the HLD level that turns into metadata service plus block storage, as in the file sync design.

How to answer

Point to the seam you already have (FileSystem only uses the Node API) and name the VFS as the real-world proof.

Likely follow-ups
  • How do you keep the cache consistent? (Invalidate on write, version numbers, or leases.)
