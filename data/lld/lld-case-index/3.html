The 7 families (and what each one teaches)

Group the 45 problems by the main design skill they test. Inside a family the problems share a skeleton; across families the skills stack up.

  1. Games and boards (4) Chess, Snake & Ladder, Tic-Tac-Toe, Snake Game
  2. State machines (5) Elevator System, Vending Machine, ATM, Traffic Signal Controller, Coffee Machine
  3. Management systems (8) Parking Lot, Library Management, Amazon Locker, Cricket Scoreboard (Cricbuzz), Task Tracker (Jira, Trello, To-Do), Stack Overflow (Q&A Platform), Customer Issue Resolution (PhonePe), Rating System (Atlassian Code Design)
  4. Booking and reservation (7) Movie Ticket Booking (BookMyShow), Car Rental (Zoomcar), Meeting Room & Calendar Scheduler, Hotel Booking, Train Ticket Booking (IRCTC), Doctor Appointment & Fitness Class Booking, Online Auction
  5. Money and commerce (7) Splitwise / Expense Sharing, Ride Hailing / Cab Booking (Uber, Ola), Stock Exchange & Trading Client (Zerodha), Digital Wallet & Payment Gateway, Food Delivery (Swiggy, Zomato, FoodKart), Quick-Commerce Order & Inventory (Zepto), Shopping Cart, Coupons & Discounts
  6. Infrastructure and data structures (12) LRU / LFU Cache with Pluggable Eviction, Pub-Sub / Message Queue (Kafka-lite), Notification Service, Logging Framework, Rate Limiter, In-Memory File System, Task / Job Scheduler (Delayed, Periodic, DAG), In-Memory Key-Value Store (TTL, Transactions), Rental Search & In-Memory Search Engine (NoBroker), URL Shortener (LLD), Autocomplete, Trie & Wildcard Router, Text Editor with Undo/Redo
  7. Social and messaging (2) Social Network & News Feed, Chat Application
FamilyThe skill it trainsThe bug it teaches you to avoid
Games and boardsClean entity modelling, a game loop, turn handling, rules as small classesA 300-line Game class that knows everything
State machinesStates and legal transitions, the State pattern, rejecting illegal inputBoolean flags (isPaid, isDispensing) that contradict each other
Management systemsEntities vs copies (book vs book copy, spot vs ticket), search, simple allocationStoring derived state in two places
Booking and reservationTime ranges, holds with expiry, all-or-nothing reservation, lockingCheck-then-act races: double booking
Money and commerceLedgers, idempotency, rounding, matching engines, order life cyclesLosing or creating money on retries
Infrastructure and data structuresThe right data structure behind a clean API; pluggable policies; thread safetyCorrect code that is O(n) where O(1) was the point
Social and messagingFan-out, feeds, delivery status, paginationPulling everything into memory for one page

Two lessons hide in that grid. First, Strategy is the single most useful pattern: almost every case has a rule that varies (pricing, allocation, eviction, matching, splitting). Second, the concurrency column is where SDE-2 interviews separate candidates; you meet it first in Parking Lot and properly in BookMyShow.
