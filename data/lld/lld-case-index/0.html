The story: 45 recipes, 7 sauces

Explain like I'm 5

Imagine a cookbook with 45 recipes. It looks scary. But a cook will tell you a secret: most recipes use one of a few basic sauces. Learn the tomato sauce well and you can make pasta, pizza and soup. Learn the white sauce and you can make three more dishes.

Low-level design problems are the same. "Parking lot", "movie tickets" and "car rental" look different, but they share the same few ideas: pick something from a pool, hold it, charge for it, and never give the same thing to two people. Learn those ideas once, deeply, on the most common problem, and the others become small variations.

This page is the map of the cookbook. It answers four questions: which problems matter most (ranked by real interview data), what each one teaches (7 families), in which order to practise, and what shape every solution takes (one template for all 45 pages).

From your world

You did not learn Linux drivers one by one. You learned the three classes (character, block, network), the ops table each one fills in (file_operations, block_device_operations, net_device_ops) and the life cycle (probe, open, I/O, remove). After that, a new driver is mostly "which ops do I fill and what is special". LLD case studies work the same way: a family tells you the skeleton, the problem tells you what is special.

Before you start. Every case page uses interfaces, a few design patterns, class diagrams and (from Level 4) Java locks. If any of these is new, read these first, in this order:

  1. Objects from C: OOP for C programmers (a class is a struct plus its functions; an interface is an ops table) and Interfaces and abstract classes.
  2. Patterns: the pattern map, then the three that appear in almost every case: Strategy, Observer and State.
  3. Diagrams: UML class diagrams (how to read +, -, «interface», 1..* and the arrow heads).
  4. Threads, before any Level 4 case: Concurrency basics (including why Java volatile is not C volatile) and Locks.

Each case page also starts with a short Assumes line that names the 2-3 concept pages it leans on. The sidebar lists the cases in the teaching order below (games first), so "next" always takes you one step up.
