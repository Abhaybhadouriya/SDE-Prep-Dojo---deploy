How to practise one case (so it sticks)

  1. Read only the story and the "how it is asked" section. Close the page.
  2. Set a timer for the round you are preparing for (45, 60 or 90 minutes) and solve it in your IDE or on paper, out loud.
  3. Run your own driver. If it does not run, the attempt counts as failed, exactly as in a Flipkart or PhonePe round.
  4. Compare with the page section by section: entities, diagram, patterns, concurrency. Write down the two biggest differences.
  5. Answer the Q&A follow-ups aloud without opening them first; then check.
  6. Grade yourself with the rubric checklist on the page.
  7. Redo it from scratch 3-4 days later, faster. Spacing beats rereading.

This is how you got good at debugging kernel panics: not by reading postmortems, but by reproducing, fixing, and then seeing the same class of bug again a week later and recognising it in minutes. Treat every case as a reproducible test case for your own design habits.
