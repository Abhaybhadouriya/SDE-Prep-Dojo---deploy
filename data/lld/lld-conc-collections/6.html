The rest of java.util.concurrent

  • CopyOnWriteArrayList / CopyOnWriteArraySet: every write takes a lock, copies the array, changes the copy and publishes it with a volatile write. Reads and iteration take no lock and see a snapshot, so you can add to the list while looping over it (our demo did). Perfect for listener lists in Observer, which are read on every event and changed rarely. Terrible for lists that change often: each write is O(n). The snapshot iterator does not support remove().
  • ConcurrentLinkedQueue / ConcurrentLinkedDeque: unbounded, non-blocking queues built from CAS (the Michael-Scott algorithm). size() walks the whole queue and is only an estimate. Use them when consumers poll and must never block. When consumers should wait, use a BlockingQueue (Producer-Consumer).
  • ConcurrentSkipListMap / Set: a sorted concurrent map, expected O(log n), with firstKey, headMap, ceilingKey. This is the natural order book for a stock-exchange round, a leaderboard, or a scheduler keyed by time.
  • ConcurrentHashMap.newKeySet(): a concurrent Set backed by a CHM.
