StrategyRankingStrategy: ByFrequency, ByRecencyThe ranking rule is the most likely change (recency, trending, personal history, sponsored). The trie, the cache and the session never mention the rule; a new one is a new class. It is exactly what the Microsoft write-up asks for."Ranking is a comparator passed in. The trie and the cache never mention the rule."
Precomputed top-k per node (a cache with an invariant)TrieNode.topKReads are per keystroke and must be O(prefix length + k). The cache is exact as long as scores only go up, so record updates it incrementally; remove breaks that, so it rebuilds the path bottom-up from the children's caches."Each node caches its top k, so a keystroke costs O(prefix + k). The cache stays exact while scores only go up; remove rebuilds the path."
FacadeAutocompleteEngine, PathTrieCallers see record / suggest or put / match; nodes never leak, so the representation (map per node, array of 26, compressed trie) can change."Callers see record and suggest; nodes never leak, so I can swap a map per node for an array of 26."
Recursive structure (Composite-like)TrieNode, NodeEach node is a small trie. Insert, match and collect are short recursive or stack-based walks."Every node is a small trie, so insert and lookup are short walks."
Ordered fallbacks (a fixed chain)match: literal, then param, then *, then **Each branch either answers or passes to the next, with backtracking. Kept as four ifs because the order is fixed; becomes a list of SegmentMatcher objects if the interviewer adds regex or typed params (:id(int))."Literal beats parameter beats wildcard: the first branch that matches answers, and I backtrack if it dead-ends."
Immutable resultsSuggestion, RouteMatchEntries are mutated under the write lock; callers get snapshots so they never see a count change under their feet."Callers get copies, so a count never changes under their feet."

Patterns we deliberately skipped: a Singleton engine (tests build engines with different strategies and k), inheritance such as FrequencyTrie extends Trie (the ranking rule is the only difference, so it is a strategy), and a full Composite with leaf and branch classes (every trie node has the same shape).

Two traps. Do not put the ranking inside the trie as if (mode == FREQUENCY); that is the answer the Strategy follow-up is designed to catch. And do not cache top-k "because it is faster" without saying when it is valid: if the interviewer adds delete or score decay and you have not thought about it, the cache silently returns wrong answers.

From your world

The per-node cache is a summary kept in an augmented tree, like the kernel's augmented rbtree for VMAs (rb_subtree_gap in mm/mmap.c, now in the maple tree): each node stores a fact about its whole subtree, updated along the path on insert so a query need not descend. The router's ordered fallbacks are a netfilter chain: rules tried in priority order, the first that matches decides.
