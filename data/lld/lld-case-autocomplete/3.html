Identify the entities (nouns and verbs)

Method from From use cases to classes.

  1. Start from the requirement sentence. There are two problems in it; keep them separate.
  2. Underline nouns: phrase, prefix, ranking, top k, session, route, path, param, count.
  3. Underline verbs. They become the two facades' methods.
  4. Drop nouns that are only data: the prefix is an argument, a param is an entry in the match result, the count is a field of the stored entry.
  5. "Ranking" varies, so it becomes an interface with implementations. "Top k" becomes a cached list on each trie node. Each trie node type gets its own small class.

The modelling choice that decides the router round: a node has separate slots for literal children, one param child, one * child and one ** child. Storing "*" and ":id" as ordinary keys in the children map works for exact lookup but makes precedence, param capture and conflict detection messy.
