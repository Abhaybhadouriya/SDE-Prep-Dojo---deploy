Clarify the requirements

Functional (P0)

  1. Record record(phrase, times = 1): a phrase was searched. Case-insensitive; runs of spaces collapse to one; empty phrases are rejected.
  2. Suggest suggest(prefix): the best k phrases starting with the prefix. Unknown prefix: empty list. Empty prefix: the overall top k.
  3. Ranking Frequency (count, ties alphabetical) or recency (last recorded first), chosen when the engine is built. New rules without touching the trie.
  4. Typing session LeetCode 642 style: characters arrive one by one, each returns suggestions, # records the sentence.
  5. Remove a phrase (a takedown or a privacy request), and the suggestions update at once.
  6. Router put(pattern, value) with literal segments, :name (one segment, captured), * (one segment), ** (the rest, last segment only). match(path) returns the value, the pattern and the captured params, or "404".
  7. Precedence Literal beats :param beats * beats **, per segment, with backtracking: if the literal branch dead-ends later, try the next branch.
  8. Wildcard get (the Atlassian follow-up) keys are plain paths and the query holds *: return every matching key.

Non-functional

  • Fast reads: suggestions are called on every keystroke; they must not scan the whole subtree. Writes can be slower.
  • Deterministic: same input, same order (ties broken by text), so tests are stable.
  • Thread safe: many readers, occasional writers.
  • Fail at registration, not at request time: duplicate or conflicting routes are rejected by put.

Out of scope (say it out loud)

Fuzzy matching and typo tolerance, personalisation per user, distributed tries and the offline rebuild pipeline (that is the HLD), HTTP methods in the router (one trie per method is the usual answer), regex segments.

Questions to ask

  • What is k, and how are ties broken? (3; alphabetical.)
  • Do we record what the user typed or what they picked? (Typed sentences in P0, like LeetCode 642.)
  • Case and whitespace: is "LRU Cache" the same as "lru cache"? (Yes.)
  • Can phrases be deleted? (Yes, and that changes how the cache is maintained.)
  • Router: does * match one segment or many? Can it match zero? Is /a/ the same as /a? (One; zero only for **; yes.)
  • Router: two patterns that can match the same path, like /users/me and /users/:id? (Allowed; the more specific wins.) And /users/:id next to /users/:uid? (Rejected as a conflict.)
