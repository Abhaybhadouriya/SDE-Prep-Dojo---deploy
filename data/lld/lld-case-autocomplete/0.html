The story: the dictionary with sticky notes

Explain like I'm 5

Imagine a huge book of words where each page has one letter. To find words that start with "lin", you open page "l", then from there the tab "i", then the tab "n". Everything behind that tab starts with "lin". That book is a trie.

Now the librarian is lazy and clever. On each tab she sticks a note: "the 3 most asked words behind this tab are: linux kernel, linked list, lint rules". When someone asks for "lin", she reads the note instead of flipping through every page behind it. When a word gets asked again, she walks down its tabs and fixes each note on the way.

The post room down the hall uses the same kind of book for addresses. Each page is a whole street name, not a letter. Some pages say "any street" (that is *) or "any street, and remember its name" (that is :id). The postman always tries the exact street first, and only if that leads nowhere does he go back and try the "any street" page.

Both problems are "a tree keyed by pieces of the input". In autocomplete the piece is a character and the question is "best k below here"; in the router the piece is a path segment and the question is "which pattern matches, most specific first". The design points interviewers look for: ranking is a Strategy, not an if inside the search; caching top-k per node and knowing exactly when the cache stays correct; and for the router, precedence plus backtracking and rejecting conflicting routes at registration time.

From your world

You already use both. The Linux routing table is a compressed trie (net/ipv4/fib_trie.c, the LC-trie) answering "most specific match for this address", which is exactly the router's "literal beats wildcard". Path lookup in the VFS (link_path_walk()) walks a path one component at a time through the dentry cache, which is our segment trie, with mount points acting like a node that hands over to another tree. And a ranking Strategy is tcp_congestion_ops: the same caller, a struct of function pointers chosen by name.

Interfaces in C terms: every interface on this page is, in C, a struct of function pointers; each implementation fills one in, like file_operations. Java and C++ build that table (the vtable) for you, and every object carries a pointer to it. More in OOP from C structs and polymorphism and vtables.
