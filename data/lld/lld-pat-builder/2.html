Intent: separate how you build from what you get

Builder is a GoF creational pattern. In our words:

Move the construction of a complex object into a separate builder object with one method per step. The client calls the steps it needs, in a readable way, then calls build(), which validates everything and returns the finished product. Optionally, a director stores common step sequences ("recipes") so clients do not repeat them.

There are two flavours you should be able to name:

FlavourShapeUse it for
GoF builderA Builder interface, several concrete builders, a director that drives themThe same steps producing different representations: one report built as HTML, PDF or plain text.
Fluent (Bloch) builderA static nested Builder class, setters return this, private product constructorOne product with many optional fields. This is what interviewers usually mean.
