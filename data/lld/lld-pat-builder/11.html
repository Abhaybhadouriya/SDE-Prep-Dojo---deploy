Interview Q&A

What is the telescoping constructor problem, and how does Builder fix it?

When a class has many optional parameters you end up with a chain of constructors, each adding one more argument. Call sites become a row of numbers where position is the only meaning, and swapping two ints of the same type compiles silently. A builder replaces positions with named methods, gives defaults for everything optional, and validates once in build().

How to answer

Show a bad call like new Packet(a, b, 6, 32, 0, 100, data), ask "which is the VLAN?", then show the builder version.

Likely follow-ups
  • Why not just use setters? (Half-built, mutable, unvalidated objects.)
  • In Python, do you need this at all?
Builder vs Factory: when do you use which?

A factory decides which class to create and returns it in one call. A builder decides how to assemble one object from many parts over several calls. If the variation is in the type, use a factory. If the variation is in the configuration of one type, use a builder. They combine: build() may call a factory to choose the concrete class.

How to answer

"Which vs how", one example each from the same problem (parking lot: VehicleFactory picks Car/Bike; a Ticket builder sets the many ticket fields).

Likely follow-ups
  • And Abstract Factory? (Families of products, still one call per product.)
Where does validation go, and how do you enforce required fields?

Field-level checks can run in each setter (fail fast), but checks across fields (payload fits the MTU, end date after start date) must run in build(), the one moment you see everything. Required fields go into the builder's constructor or entry method (Packet.to(dst)). For several required fields, a step builder uses a chain of interfaces so the compiler forces each required step before build() becomes available.

How to answer

Split: per-field vs cross-field validation; then required fields via constructor or step builder.

Likely follow-ups
  • Exception or result type on failure? (Exceptions for programming errors; a result type when invalid input is expected, for example user input.)
What is the Director for? Is it required?

The director holds a fixed sequence of builder steps, a recipe like "ping packet" or "monthly report", so clients do not repeat it. In the GoF form it also lets the same recipe drive different concrete builders (HTML vs text). It is optional: with a fluent builder, static helper methods or the client itself often play this role.

How to answer

Director = order of steps; builder = how each step is done. Give one recipe example.

Likely follow-ups
  • Show a director that works with two builders.
Make the product immutable and thread-safe. What exactly do you have to do?

All product fields private final; no setters; constructor private and only called from build(); defensive copies of mutable inputs (arrays, lists, dates) on the way in and unmodifiable views or copies on the way out; class final so a subclass cannot add mutable state. Then the object can be shared between threads without locks, because final fields are safely published once the constructor finishes. The builder itself is not thread-safe; use one builder per thread or per build.

How to answer

List the checklist, then name the trap (storing the caller's list).

Likely follow-ups
  • How do you "change" an immutable object? (A toBuilder() or withX() method returns a new object.)
  • See immutability and safe publication.
Builder vs Decorator for a customisable coffee or pizza order?

If the options are just data on one order (size, milk type, extra shot), a builder makes a clean immutable Drink. If each add-on changes behaviour such as price or description computed by wrapping, and add-ons can stack in any order at run time, Decorator fits. Many good answers use both: a builder collects choices, and the price is computed by a chain of decorators or a pricing strategy.

How to answer

Data vs behaviour. Then mention which one you would pick for the given requirements.

Likely follow-ups
  • How do you add a new topping without editing existing classes?
Give a systems example of Builder from your own work.

sk_buff construction: reserve headroom, put payload, push each protocol header layer by layer; or netlink messages built with nlmsg_put and nla_put_*, finished by nlmsg_end. Both are step-by-step assembly of one complex object. The kernel trades immutability for zero-copy speed, which is a good trade-off to discuss.

How to answer

Name the steps, map them to builder methods, and point out what is different (mutable, same buffer).

Likely follow-ups
  • Where is the "build()" moment in the netlink case?
