What actually gets graded

Across company rubrics and candidate reports, the same five things come back. Flipkart's 2026 machine-coding brief, for example, lists demoable and correct code, readability, entity modelling, modularity and extensibility, separation of concerns, abstractions, exception handling and comments (report).

  1. It works. The main flow runs (machine coding) or can be traced on the board (whiteboard). Working beats clever.
  2. Each class has one clear job. No "God class" that does everything. See SRP.
  3. Change is cheap. New types plug in through interfaces. See OCP.
  4. Edge cases and errors are handled. Invalid input, full parking lot, double booking.
  5. You can explain it. Why this class, why this pattern, what you would do with more time.

Over-engineering is a real failure mode. Reports describe candidates marked down for forcing patterns where a map would do. Use a pattern only when you can say which change it absorbs.
