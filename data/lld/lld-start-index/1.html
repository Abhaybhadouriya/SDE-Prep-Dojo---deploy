Some useful words, defined once:

  • Class - a blueprint for objects: some data (fields) plus the functions that work on that data (methods). Think struct plus the functions that take it as the first argument.
  • Interface - a list of method signatures with no body. Any class that "implements" it promises to provide those methods. Think of a struct file_operations that has slots but no driver filled in yet.
  • Design pattern - a named, reusable shape of classes for a common problem (for example "Strategy": swap one algorithm for another behind an interface).
  • Extensibility - how easily new requirements fit in. The usual test: "add a new payment method" should mean adding a class, not editing ten old ones.
  • Machine coding - an LLD round where you must produce running, demoable code in 90-120 minutes, usually on your own laptop. See How LLD rounds work.

From your world

The Linux kernel is one of the largest object-oriented code bases in the world, written in C. struct file_operations is an interface: read, write, open are slots, and each driver fills them. The VFS calls f->f_op->read(...) without knowing which driver is behind it. That is polymorphism and the Strategy/Bridge idea. Notifier chains (register_netdevice_notifier) are the Observer pattern. Netfilter hooks are a Chain of Responsibility. kref is shared ownership. The TCP state machine is the State pattern. You already think in designs; LLD gives you the vocabulary. The full mapping lives in Design Patterns in the Linux Kernel.

The pattern names in one line each (you meet them properly in the patterns week, so do not worry about them yet):

  • Strategy - swap one algorithm behind a fixed interface (tcp_congestion_ops: cubic, reno, bbr).
  • Bridge - two sides that vary independently, joined by a pointer (the VFS front and each filesystem back end).
  • Observer - register a callback, get told when an event happens (netdevice notifier chains).
  • Chain of Responsibility - pass the request along an ordered list until someone handles or drops it (netfilter hooks by priority).
  • State - the object's behaviour depends on its current state, and events move it between states (the TCP state machine).
