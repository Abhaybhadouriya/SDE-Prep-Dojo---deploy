Which language: Java first, Python and C++ in tabs

Code on these pages is written in Java 21 first, with Python 3.11 in a second tab and C++14 where it helps you map an idea to C. Why Java first:

  1. The ecosystem speaks Java. Many of the reference solutions you will meet are Java only: for example kumaransg/LLD (70 machine-coding solutions), kousiknath/LowLevelDesign, Udit Agarwal's anomaly2104 repos and iqblmoh/machineCoding. Reading them is easier if you read Java.
  2. Interfaces and access modifiers are explicit. interface, abstract, private, final make the design visible on the page. In Python the same ideas are conventions.
  3. Concurrency follow-ups have a standard toolbox. java.util.concurrent (ReentrantLock, ConcurrentHashMap, ExecutorService, AtomicInteger) is what interviewers name. Walmart's "Java + LLD" round even asks Java questions directly.
  4. Use the language you are fastest in. Machine-coding rounds (Flipkart, PhonePe, Razorpay) let you pick any language. If C++ is your fastest, use C++ - but practise the STL equivalents (std::unique_ptr, std::mutex, std::unordered_map) so you do not fight memory management in a 90-minute round.

From your world

Your C instincts help and hurt. They help: you already think about ownership, lifetimes and locking. They hurt: interviewers want types for concepts. A C programmer writes int status with #define values; an LLD answer writes enum OrderStatus { CREATED, PAID, SHIPPED }. A C programmer writes one big switch on a type field; an LLD answer usually replaces it with one class per case behind an interface - exactly what you do when you register a new net_device_ops instead of patching the core.
