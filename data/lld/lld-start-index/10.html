Remember this

  • LLD = classes, interfaces, relationships and code inside one service. HLD = services and stores. DSA = the algorithm in one method.
  • The core skill: find what will change and put an interface there. Patterns are names for those shapes.
  • You already know the ideas from C: file_operations is an interface, notifier chains are Observer, netfilter is Chain of Responsibility.
  • Every round walks: requirements, entities, class diagram, APIs, patterns, code, extensions, concurrency.
  • Read in order: Start, OOP, Principles, UML, Patterns, Concurrency, Cases, Interview Hub. SDE-2 adds depth, not new topics.
  • Java first on these pages; in the interview use the language you write fastest and know its concurrency library.
  • Working, readable code beats clever patterns. Over-engineering is marked down.
