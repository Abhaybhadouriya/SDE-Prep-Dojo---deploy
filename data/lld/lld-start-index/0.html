The story: the city, the house and the wiring

Explain like I'm 5

A town planner draws the city: where the roads go, where the water tank sits, which side has the hospital. That is the big picture. Then an architect draws one house: the kitchen is next to the dining room, the bathroom has one door, every room has a light switch, and you can add a new bedroom later without knocking down the kitchen. Then an electrician decides exactly which wire goes into which switch.

The town plan is High-Level Design. The house plan is Low-Level Design. The wire-by-wire work is coding the algorithm. A good house plan is one where each room has one job, rooms connect through doors (not holes in the wall), and a new room can be added without breaking the old ones.

In an interview, LLD means: someone names a small product ("design a parking lot", "design Splitwise", "design a rate limiter") and you turn it into classes, interfaces, relationships and working code that is easy to change. Nobody asks how many servers you need. They ask: which class owns this rule? What happens when a new vehicle type arrives next month? What if two people book the same seat at the same time?

The good news for you: you have written this kind of code for years. A driver with a struct of function pointers, a protocol state machine, a refcounted object shared by two subsystems - those are design decisions. This module gives them their interview names and shows how to explain them in Java, Python or C++.
