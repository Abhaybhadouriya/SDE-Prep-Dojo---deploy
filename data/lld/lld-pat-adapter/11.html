Interview Q&A

You support two payment gateways with different SDKs. How do you design it?

Define a PaymentGateway interface in our domain terms (charge, refund, amounts in minor units as integers, our own result type). Write one adapter per SDK that converts arguments, calls the SDK and maps responses and errors back. Checkout depends only on the interface; a factory or a map picks the adapter by provider name. Adding a gateway is a new class, not an edit.

How to answer

Draw Target, two adapters, two SDKs. Mention minor units (no floating point for money) and idempotency keys.

Likely follow-ups
  • Where do retries and fallback to another gateway go? (Outside the adapter: a routing service or a decorator.)
  • How do you test checkout without the SDKs?
Object adapter vs class adapter: what is the difference and which do you prefer?

An object adapter holds the adaptee and delegates. A class adapter inherits the adaptee and implements the Target. Object adapters work with any adaptee subclass, do not expose adaptee methods, and work in single-inheritance languages, so they are the default. A class adapter can override adaptee behaviour and avoids one extra object, but it is fixed to one concrete class and needs a non-final adaptee (Java) or multiple inheritance (C++, where private inheritance hides adaptee methods).

How to answer

Composition vs inheritance, then two concrete consequences, then your default.

Likely follow-ups
  • Can you write a class adapter in Java?
Adapter vs Decorator vs Proxy vs Facade, in one line each.

Adapter changes an interface to fit. Decorator keeps the interface and adds behaviour, and can be stacked. Proxy keeps the interface and controls access (lazy load, remote, cache, permission, rate limit). Facade gives a new simpler interface over a whole subsystem of many classes.

How to answer

Lead with "they all wrap; they differ in intent", then the four lines. Give one JDK example each if time allows (InputStreamReader, BufferedInputStream, java.lang.reflect.Proxy, a service class over several DAOs).

Likely follow-ups
  • Is BufferedReader(new InputStreamReader(in)) an adapter or a decorator? (Both, stacked: the inner one adapts bytes to chars, the outer one decorates a Reader with buffering.)
What should an adapter never do?

Hold business logic. It translates names, data formats, units and errors. Retries, routing between providers, discount rules or fraud checks live elsewhere. It should also not swallow errors: an adaptee failure must become a clear error in the Target's terms, and a capability the adaptee lacks should be reported, not faked.

How to answer

"Translation only" plus one example of logic that crept in and where you would move it.

Likely follow-ups
  • Where would you put a circuit breaker for a flaky provider?
You are replacing a legacy inventory service. How can Adapter help the migration?

Define the new interface first. Write an adapter that implements it over the legacy service so callers can switch to the new interface immediately. Then build the new implementation behind the same interface and move traffic gradually (feature flag or percentage). When no caller uses the legacy path, delete the adapter. This is the "strangler fig" approach with adapters at the seam.

How to answer

Interface first, adapter over old, new implementation, gradual cut-over, delete.

Likely follow-ups
  • How do you verify both implementations agree? (Shadow traffic, compare results.)
Give examples of Adapter in the JDK or the Python standard library.

InputStreamReader (bytes to chars), OutputStreamWriter (chars to bytes), Arrays.asList (array to List), Collections.enumeration (Collection to Enumeration). In Python, io.TextIOWrapper (binary stream to text stream).

How to answer

Name two and say what each converts from and to.

Likely follow-ups
  • Why does Arrays.asList(...).add() throw?
How does a kernel handle 32-bit programs on a 64-bit kernel, and what pattern is that?

Through a compat syscall layer. 32-bit callers enter through a separate syscall table whose entries are compat wrappers (COMPAT_SYSCALL_DEFINEn). Each wrapper copies in the 32-bit struct layout, widens fields into the native struct, calls the common implementation, and converts results back. It is the Adapter pattern at the ABI boundary: neither user space nor the core implementation changes.

How to answer

Describe the mismatch (field sizes, pointer width), the wrapper, and the shared core. Name the pattern.

Likely follow-ups
  • Why can't the 64-bit handler just be called directly? (Struct layouts and pointer sizes differ.)
