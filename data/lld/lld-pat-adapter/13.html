Quiz

What is the defining job of an Adapter?

  1. Add new behaviour while keeping the interface
  2. Convert one interface into another the client expects
  3. Control access to an expensive object
  4. Simplify a large subsystem
Keeping the interface is Decorator or Proxy; simplifying many classes is Facade.

Why is the object adapter usually preferred over the class adapter?

  1. It is faster
  2. It needs multiple inheritance
  3. It works with any adaptee subclass and does not expose adaptee methods
  4. It can override adaptee methods
Composition keeps the adapter flexible and the adaptee hidden. Overriding is the class adapter's one advantage.

InputStreamReader is an example of:

  1. Adapter: bytes to characters
  2. Decorator: adds buffering
  3. Proxy: lazy loading
  4. Facade: over the file system
It presents an InputStream as a Reader, a different interface. BufferedReader is the decorator.

A gateway adapter starts retrying failed charges and switching to a backup provider. What is wrong?

  1. Nothing; adapters should be smart
  2. It should use inheritance instead
  3. It should be a singleton
  4. Routing and retry are business policy and belong outside the adapter
An adapter translates. Put retry/fallback in a routing service or a decorator around the gateway interface.

You own both the client and the class with the mismatched method. Best move?

  1. Write an adapter
  2. Change one of the interfaces directly
  3. Write a facade
  4. Write a proxy
Adapters are for code you cannot or should not change. Otherwise they are needless indirection.

The Linux compat syscall layer is an adapter because it:

  1. Caches syscall results
  2. Adds logging to every syscall
  3. Converts 32-bit ABI structs into native ones and calls the common code
  4. Limits how often a syscall runs
Neither user space nor the core implementation changes; the wrapper converts between layouts.
