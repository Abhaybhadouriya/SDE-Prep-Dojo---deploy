The story: the control tower

Explain like I'm 5

Ten planes want to land on one runway. If every pilot had to radio every other pilot ("I am landing, are you landing? who goes first?"), there would be 45 conversations and somebody would get it wrong.

So airports have a control tower. Each pilot talks only to the tower. The tower knows who is where, decides who lands next, and tells the others to wait. Pilots do not even need to know the other planes' names. Add an eleventh plane and nobody else changes; the tower just has one more plane to look after.

Software has towers too. A chat server sits between users. An auction house sits between bidders. A dialog box sits between its checkbox, its text field and its OK button. In each case the parts (the pattern calls them colleagues) talk to one mediator, and the mediator holds the rules about who reacts to what.

From your world

The Linux driver core is a mediator. A PCI network card (a struct device) and the e1000 driver (a struct device_driver) never search for each other. Both register with the bus (struct bus_type). When either arrives, the driver core walks the other list, asks the bus's match() callback whether the pair fits, and if so calls the driver's probe(). Order does not matter: device first or driver first, the bus pairs them. Drivers stay reusable because the only thing they know is the bus.
