Core flows

  1. The customer checks out a basket from a location.
  2. The selector filters stores by distance and hasAll() and returns the nearest. This read is unlocked, so it is only a hint.
  3. The real decision: reserveAll takes every SKU lock in sorted order, checks every line, and only then reserves every line. If any line fails, nothing changes. If the store lost a race, drop it and ask the selector again (maybe the farther store has stock).
  4. The order is created in CREATED with expiresAt = now + hold; the client goes to the payment page.
  5. The payment gateway's webhook confirms: the order moves to CONFIRMED and the reservation is committed (both counters drop). A duplicate webhook finds CONFIRMED and returns without touching stock.
  6. For an unpaid order, a scheduled sweeper (every few seconds) moves it to EXPIRED and releases the reservation.
  7. If the webhook and the sweeper hit the same order together, both go through the order's lock; exactly one transition succeeds and only the winner touches inventory.
