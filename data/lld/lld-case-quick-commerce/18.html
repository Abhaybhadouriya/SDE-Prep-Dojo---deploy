Quiz

A store has onHand=5, reserved=3. A customer asks for 3 units. What happens?

  1. Accepted: 5 units are in the store
  2. Rejected: available is only 2
  3. Accepted, and reserved becomes 6
available = onHand - reserved = 2, which is less than 3. Reserving would break reserved <= onHand.

Payment succeeds for an order that reserved 2 units. How do the counters change?

  1. onHand -2 and reserved -2
  2. reserved -2 only
  3. onHand -2, reserved unchanged
Commit turns a promise into a sale: the units leave (onHand) and are no longer promised (reserved). available is unchanged.

Thread A locks milk then bread; thread B locks bread then milk. What fixes the deadlock most simply?

  1. Add a sleep between the two lock calls
  2. Make the locks reentrant
  3. Both lock SKUs in sorted order
A global lock order removes circular wait. Reentrancy only helps the same thread; sleeping just changes timing.

Why does the selector's hasAll() check not prevent overselling by itself?

  1. It runs without the SKU locks, so stock can change before the reservation
  2. It uses the wrong formula
  3. It ignores reserved stock
It is a hint for choosing a store. The decision is the locked check inside reserveAll, followed by a retry if it fails.

A customer cancels a PACKED (already paid) order. What should happen to stock?

  1. Add the units back to onHand
  2. Nothing
  3. Release the reservation
The reservation was already committed at payment. The units are physically back on the shelf, so onHand goes up.

What is the best way to make "release after 5 minutes" testable?

  1. Shorten the hold to 1 ms in production
  2. Use Thread.sleep(300000) in the test
  3. Inject a Clock and advance a ManualClock in tests
Time is a dependency. A fake clock makes expiry deterministic and instant to test.

The payment webhook and the expiry sweeper act on the same CREATED order at once. What guarantees consistency?

  1. ConcurrentHashMap for the orders map
  2. Both go through a synchronized state transition; only the winner commits or releases
  3. The sweeper runs only once a minute
Only one caller can move the order out of CREATED; the inventory effect follows that single winner.
