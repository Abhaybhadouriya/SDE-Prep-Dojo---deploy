How to run one drill (10 minutes)

Set a timer. Use paper or a plain text file, not a UML tool: interviews are on whiteboards, shared docs or your IDE. The four stages are the first half of the interview framework, compressed.

  1. Clarify (2 min). Write the actors and 4-6 use cases as one-line sentences. Write 2-3 questions you would ask and the assumption you will take if nobody answers. Mark one thing explicitly out of scope.
  2. Entities (2 min). Pull the nouns, drop frame nouns, merge synonyms, sort each into entity / value object / enum / attribute, and hunt for the hidden split (see From Use Cases to Classes).
  3. Class diagram (4 min). Draw boxes with only the fields that drive rules. Add relationships with multiplicities. Put the thing that will vary (pricing, ranking, matching) behind one interface.
  4. API (2 min). Write the orchestrator's public methods with argument and return types, and one failure per method (API & Interface Design).
  5. Score. Compare with the model answer and fill in the rubric honestly. Redo the same drill a week later from a blank page.

Whiteboard notation that is fast enough: write each class as Name | fields | methods on three lines, draw a line between related classes, and write multiplicities at each end (1, *, 0..1). A filled diamond means "owns and creates" (composition), an open triangle means "is-a". Full notation: Class Diagrams.
