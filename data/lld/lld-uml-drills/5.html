Drill 2: Gym class booking (FlipFit-style)

Prompt (10 min). A fitness platform partners with gyms (centers) in several cities. Each center runs one-hour time slots on given days; each slot offers some workouts (yoga, cardio, weights...) with a fixed number of seats per workout. New workout types will be added later. A user can book at most 3 classes per day. When a class is full, users join a waiting list of fixed size; when someone cancels, the first waitlisted user is promoted and told. Users can view their plan for a day. If the wanted class is full, suggest up to 3 alternatives ranked by time or distance.

This shape is a repeat in our research: fitness class booking appears in Flipkart, PhonePe and Meesho machine-coding reports (for example this Flipkart SDE-3 FlipFit round).

Model answer: gym class booking

Clarify. Actors: User, Center admin, the system's notifier. Use cases: register, add center / workout / slot, view availability for a day, book, cancel, view plan, recommend. Assume one-hour slots, one city search radius, waitlist promotion is automatic. Out of scope: payments.

Sort. Entities: Center, Slot (one workout at one center, one start time, one day, with seats and waitlist size), Booking, User. Values: WorkoutType, Location. Enum: BookingStatus (CONFIRMED, WAITLISTED, CANCELLED). Hidden split: Slot (the class on offer, with capacity) vs Booking (one user's place in it). Instance trap: WorkoutType must not be a Java enum, because the prompt says new types arrive later; make it a value registered per center.

API. Booking book(UserId u, SlotId s) returns CONFIRMED or WAITLISTED, fails if the daily limit is hit or the waitlist is full. void cancel(BookingId b) is idempotent and promotes the head of the waitlist. List<Slot> recommend(center, time, workout, user, RankingType) picks a RankingStrategy.

Concurrency. The race is the last seat: two book calls on one slot. Lock per slot (or a synchronized service for machine coding) around "has seat? add booking", and the same lock in cancel so promotion and a new booking cannot both take the freed seat.

// lld-code/lld-uml-drills/FlipFit.java (compiled and run) - cancel with promotion
public synchronized void cancel(String bookingId) {
    Booking b = Optional.ofNullable(bookings.get(bookingId))
        .orElseThrow(() -> new NoSuchElementException("no booking " + bookingId));
    if (b.status == BookingStatus.CANCELLED) return;               // idempotent cancel
    Slot s = b.slot;
    boolean freedSeat = b.status == BookingStatus.CONFIRMED;
    if (freedSeat) s.confirmed.remove(b); else s.waitlist.remove(b);
    b.status = BookingStatus.CANCELLED;
    notifier.notify(b.userId, "cancelled " + b.id);
    if (freedSeat && !s.waitlist.isEmpty()) {                      // promote the first in line
        Booking next = s.waitlist.pollFirst();
        next.status = BookingStatus.CONFIRMED;
        s.confirmed.add(next);
        notifier.notify(next.userId, "promoted from waitlist: " + next.id);
    }
}
