Before you start: the six-step method in one picture

Every drill on this page runs the same six steps. If any word below is new, read its page first; the drills assume it.

  • Actor - a person or system outside your design that uses it (member, admin, payment provider). Use case - one thing an actor wants done, written as a short sentence ("member books a class"). Both are on From Use Cases to Classes.
  • Nouns, then sort - each noun becomes an entity (has identity and changing state: Booking), a value object (immutable, equal by value: TimeSlot), an enum (fixed set: BookingStatus), a service (coordinates others: BookingService) or just an attribute of another class.
  • Relationships with multiplicity - lines between boxes, with how many at each end: 1, * (many), 0..1 (optional). Filled diamond = owns and creates, hollow triangle = is-a. Notation: Class Diagrams and Class Relationships.
  • API - the public methods of the orchestrator, with types and one failure each: API & Interface Design.
