Related and often confused patterns

PatternRelation to PrototypeKey difference
Factory Method / Abstract FactoryBoth hide which class gets created.Factories construct from scratch through subclasses or factory objects; Prototype copies a configured instance. GoF notes an abstract factory can store prototypes and clone them.
BuilderBoth help make complex objects.Builder assembles step by step; Prototype starts from a finished object. toBuilder() mixes them.
MementoBoth copy state.Memento saves a snapshot to restore later (undo); Prototype copies to make a new working object.
FlyweightOpposite direction.Flyweight shares one immutable instance; Prototype duplicates so copies can diverge.
Object PoolBoth avoid expensive creation.A pool reuses the same objects (borrow and return); Prototype makes new ones by copying.
Spring "prototype" scopeName only.Means "a new bean per request" built by the container; nothing is cloned.

Prototype also pairs well with Composite: copying a directory or a grouped drawing means each node clones its children. See look-alike patterns for a quiz on these pairs.
