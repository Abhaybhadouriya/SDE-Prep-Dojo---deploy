Intent: ask an object to copy itself

Prototype is a GoF creational pattern. In our words:

Give objects a clone() (or copy()) operation. To make a new object, take a fully configured prototype and ask it to copy itself, then adjust the few fields that differ. Because the object copies itself, the caller does not need to know its concrete class or how it was built.

Two ideas sit inside this:

  • Clone, don't construct. Pay the expensive setup once, then copy.
  • Polymorphic copy. layout.clone() on a base-class reference returns an ImaxLayout if the object is one. In C++ this is called a "virtual copy constructor"; a plain copy constructor cannot do it because it needs the concrete type at compile time.

An optional helper, the prototype registry, is a map from a key ("AUDI-1", "IMAX") to a prototype. Clients say "give me a new AUDI-1" and the registry returns a clone.
