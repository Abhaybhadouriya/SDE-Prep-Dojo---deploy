How it works: a show gets its layout

  1. At startup, the expensive path runs once per screen: load rows and seats from the database, apply pricing rules. The result is stored in the registry under its key.
  2. When a new show is scheduled, ShowService asks the registry for newShow("AUDI-1"). It does not know or care whether the layout is a plain or IMAX one.
  3. The registry calls clone() on the prototype. A deep copy creates a new layout with its own list of new Seat objects. This is a memory copy, no I/O.
  4. Booking A1 on Monday changes only Monday's Seat. Tuesday's copy and the prototype are untouched.
  5. The failure mode: if clone() were shallow (new list, same Seat objects), one booking would appear in every show and even in the prototype, which then poisons every future clone.
