Quiz

Which method signature is the best public API for a cinema booking service?

  1. setSeatStatus(Seat s, int status)
  2. holdSeats(UserId u, ShowId s, List<SeatId> seats)
  3. execute(String command)
Intent-level, typed, and keeps the rules and the atomic check inside the service.

A client sends transfer with key k-9, the server succeeds, the response is lost, the client retries with k-9. What should happen?

  1. A second transfer runs
  2. An error "duplicate key"
  3. The stored receipt is returned, no second debit
Same key + same body = replay the first result. That is the whole point of the key.

Same idempotency key, different amount. Best response?

  1. Reject with a conflict error
  2. Run the new amount
  3. Return the old receipt silently
It is a client bug; silently returning the old result would hide it. Stripe also errors when parameters differ.

Where should "amount must not be negative" be enforced most reliably?

  1. In the driver only
  2. In every service method
  3. In a comment
  4. In the Money value object's constructor
Then an invalid Money can never exist anywhere in the program.

Why must the balance check and the debit be inside one lock?

  1. For speed
  2. Otherwise two concurrent transfers can both pass the check and overdraw
  3. Java requires it
Check-then-act race. Same bug as a seat double-booking.

Which return type fits findAvailableSpot(type) best when a full lot is normal?

  1. Spot that may be null
  2. boolean
  3. Optional<Spot>
"Not found" is an expected outcome of a query; Optional makes the caller handle it.

In a machine-coding round, who reads input lines and prints output?

  1. The driver / main class
  2. The service
  3. Each entity
Keeping I/O out of the service makes it testable and easy to extend in the review call.
