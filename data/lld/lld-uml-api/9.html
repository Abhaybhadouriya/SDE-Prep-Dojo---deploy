Remember this

  • One front door: the orchestrator. One method per use case, named by intent, not setters.
  • Ids and value objects in, receipts or ids out, read-only collections. Never hand out internal entities.
  • Pick an error contract on purpose: exceptions for commands, Optional for lookups, or result types. 3-5 meaningful failure kinds with stable codes.
  • Validate cheapest first: shape, idempotency, state rules, then mutate. Check and act must be atomic.
  • Anything that moves money or books inventory takes an idempotency key; same key + same body returns the stored result.
  • In machine coding the driver parses and prints; the service never does I/O.
