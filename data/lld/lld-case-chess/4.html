Class diagram

How to read this: + public, - private, «interface» a type with only method signatures (an ops table), 1..* one-to-many. Filled diamond = owns (the part dies with the whole), hollow diamond = has (can be swapped), solid line with hollow triangle = extends, dashed line with hollow triangle = implements, dashed arrow = depends on or creates. More in UML class diagrams and relationships.

Notice what is not on the diagram: no Cell, no ChessManager, no MoveValidator god class, no Singleton. Rules about a single piece live in that piece; rules that need the whole position (whose turn, king safety, game end) live in Game.
