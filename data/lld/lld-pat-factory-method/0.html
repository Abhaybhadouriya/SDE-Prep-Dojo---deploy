The story: the lunch-box routine

Explain like I'm 5

Every class in a school follows the same lunch routine: wash hands, open the lunch box, eat, clean the table. The head teacher wrote that routine once and pinned it on every classroom wall.

But the head teacher does not decide what goes inside the box. The kindergarten kitchen packs fruit. The big kids' kitchen packs sandwiches. When a new music class opens, it brings its own kitchen that packs noodles - and the routine on the wall does not change at all.

The routine is the base class. "Pack the box" is the factory method: one step the routine calls but does not fill in. Each class (subclass) fills that step with its own kitchen. The routine works with any box, because every box can be opened and eaten from.

From your world

When user space calls socket(AF_INET, SOCK_STREAM, 0), the generic socket layer (__sock_create in net/socket.c) runs the same steps for every family: check arguments, allocate a struct socket, call security hooks. It does not know how to build a TCP socket. It looks up the registered struct net_proto_family for the family and calls its ->create(net, sock, protocol, kern). For AF_INET that is inet_create; AF_UNIX and AF_NETLINK register their own. That is close, but it is really a registry looked up by a run-time key (the family number), the shape of the previous page, Simple Factory. The cleaner Factory Method analogue is super_operations->alloc_inode: the VFS runs the generic "get a new inode" workflow, and each file system, fixed by its type (its "subclass"), supplies the one step that allocates its own bigger inode struct.

Where this breaks: in C the "subclass" is a struct of function pointers registered at run time, and the table lookup by family number is itself a registry. In Java or C++ the compiler builds the table (the vtable) and you pick the creator by choosing which subclass to instantiate.
