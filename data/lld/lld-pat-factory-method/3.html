Structure: two parallel hierarchies

Participants (the names the GoF book uses, then ours):

GoF roleIn our exampleJob
ProductChannelthe interface the creator's logic works with
ConcreteProductEmailChannel, SmsChannel, PushChannelreal implementations
CreatorNotifierdeclares createChannel() and holds the workflow (notifyUser) that calls it; may give a default
ConcreteCreatorEmailNotifier, SmsNotifier, ...overrides the factory method to return one concrete product

Notice the shape: notifyUser is a fixed algorithm with one overridable step. That is a Template Method (a fixed algorithm in a base class with one or more steps that subclasses fill in, like a driver core that runs the sequence and calls ops->probe), and the overridable step happens to create an object. GoF itself points out that factory methods are often called from template methods. Interviewers like it when you spot this.
