In interviews: where it shows up

Case studyFactory Method use
Notification Serviceexactly this page: a base sender workflow (rate limit, template, retry, audit) with channel-specific creators. HLD version: Notification System.
Logging Frameworka base Logger or LoggerConfig whose subclasses create their appender / formatter
Ride Hailingride types (mini, sedan, auto) as creators that produce their own fare calculator or trip object
Digital Wallet & Payment Gatewaya base payment flow (validate, debit, notify) whose subclasses create the gateway client
Parking Lotfloor or lot types that create their own spot layout; usually a Simple Factory is enough - say so
Chess / board gamesa base Game whose subclasses create the board and pieces for that variant

Say: "Notifier owns the send workflow and calls an abstract createChannel(). Each channel subclass decides the concrete channel, so adding WhatsApp is a new class, not an edit. If the channel only differs in creation, I would inject a Supplier<Channel> instead of subclassing." You have named the pattern, the Open/Closed benefit and the modern alternative.

The classic extensibility probe is "add a new type without touching existing code". With Factory Method the honest answer is: one new product class, one new creator class, and one line where the app chooses that creator (a config map or DI wiring). Be ready to point at that last line; the choice has to happen somewhere, and interviewers check that you know where.
