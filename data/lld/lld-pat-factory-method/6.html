Variants you should be able to name

VariantWhat changesWhen it helps
Abstract creator (our example)base has no default; every subclass must overrideno sensible default product
Default implementationbase returns a default product; subclasses override only to change ita framework with a good default (e.g. a standard iterator, a plain console channel)
Parameterised factory methodcreateChannel(kind) takes a key and may switch on it; subclasses can extend the switch by overriding and calling super for unknown keysa creator makes several product kinds; this mixes in Simple Factory
Function instead of subclasspass a Supplier<Channel> / lambda / std::function into the constructoryou only need to vary creation, not other steps; avoids a class per product (composition over inheritance)

The last row is how modern Java code often does it: new Notifier(SmsChannel::new). It keeps the benefit (the workflow does not know the concrete class) without a parallel hierarchy. If interviewers push on "too many classes", that is the answer. ThreadPoolExecutor taking a ThreadFactory is exactly this: the pool's workflow needs threads, and you inject the thing that makes them.
