How it works: follow one call

  1. The client holds a Notifier reference (here it happens to be an SmsNotifier) and calls the public workflow method. The client never asks for a channel itself.
  2. The workflow code, written once in the base class, calls this.createChannel(). Because the method is virtual, the call lands in the subclass's override.
  3. The override constructs the concrete product. This is the only line that names SmsChannel.
  4. Back in the base workflow, the product is used only through the Channel interface: send() with the formatted body. The channel talks to the outside API.
  5. Results flow back up. The base class does the shared parts (formatting hook, building the result string, auditing) for every channel.
  6. Extension is by addition: a new product class and a new creator subclass. This is the Open/Closed Principle in action.
