Quiz

A class Ticket has a static int created field. You create 3 tickets. How many copies of created exist?

  1. 3
  2. 1
  3. 0 until you call it
  4. 4
Static members belong to the class, so there is exactly one copy regardless of the number of objects.

In Java, where does the object created by new Ticket("T-1", "A12") inside a method live?

  1. In the method's stack frame
  2. In static storage
  3. On the heap; the stack frame holds only the reference
  4. In a CPU register
Objects made with new live on the heap. The local variable in the frame holds a reference to it.

void f(Ticket t) { t = new Ticket("T-9", "Z"); } is called as f(a). What happens to a?

  1. Nothing: a still points to the original ticket
  2. a now points to T-9
  3. a becomes null
  4. It does not compile
The parameter is a copy of the reference. Re-pointing the copy does not change the caller's variable.

You override equals in Seat but not hashCode. What usually goes wrong?

  1. Compilation fails
  2. equals starts returning false
  3. ArrayList.contains fails
  4. HashSet.contains returns false for an equal seat
Hash collections pick the bucket by hashCode. Equal objects with identity hashes land in different buckets. ArrayList uses only equals, so it still works.

Which is a value object rather than an entity?

  1. A user account
  2. Money(250, "INR")
  3. A booking with an id
  4. A parking ticket
Money is defined entirely by its values and should be immutable; two equal amounts are interchangeable. The others have an identity that survives changes.

Which statement about C++ references (T&) is true?

  1. They can be null
  2. They can be re-pointed to another object
  3. They must be bound when created and always refer to that object
  4. They support pointer arithmetic
A C++ reference is an alias fixed at initialisation. Use a pointer when you need "maybe nothing" or re-pointing.

A Java service keeps every completed booking in a static Map forever. What is this?

  1. A memory leak: the objects stay reachable but are never used
  2. Fine: the GC frees them anyway
  3. A stack overflow
  4. A dangling pointer
The GC only frees unreachable objects. A static map keeps everything reachable, so memory grows without bound.
