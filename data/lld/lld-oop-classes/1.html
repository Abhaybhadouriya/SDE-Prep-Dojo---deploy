Blueprint vs instance

A class has three kinds of members:

  1. Fields (also called attributes or member variables): the data each object stores, for example a ticket's id and seat.
  2. Methods: the operations, for example moveTo(seat). A method runs on one particular object, which it can see as this (self in Python).
  3. Constructors: special code that runs once when an object is created and puts it into a valid starting state. (Details on Constructors & Copy Semantics.)

A member marked static belongs to the class itself, not to any object: there is exactly one copy no matter how many objects exist. A counter of "tickets created so far" is static; a ticket's seat is not.

The Java version, trimmed to the parts that matter here:

final class Ticket {
    private static int created = 0;      // one copy per class
    private final String id;             // set once, never changes
    private String seat;                 // state that may change

    Ticket(String id, String seat) { this.id = id; this.seat = seat; created++; }
    void moveTo(String newSeat) { this.seat = newSeat; }
    static int created() { return created; }
}

Ticket a = new Ticket("T-1", "A12");    // object 1 on the heap, reference a
Ticket b = new Ticket("T-2", "B07");    // object 2
Ticket.created();                        // 2: asked of the class, not an object

Interview habit: when you list entities in an LLD round ("Ticket, Seat, Show, Booking"), you are listing classes. When you walk through a scenario ("user 42 books seat A12 for the 7 pm show"), you are talking about objects. Keeping the two words straight makes your explanation sound precise.
