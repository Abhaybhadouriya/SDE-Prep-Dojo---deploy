Interview questions

What is the difference between a class and an object?

A class is a definition: the fields every instance will have and the methods that operate on them, plus any static members shared by all. An object is one instance created from it at run time, with its own memory and its own field values. Ticket is a class; the ticket for seat A12 at the 7 pm show is an object. One class, any number of objects.

How to answer

Definition, one domain example, and the word "instance". Mention static members as the part that belongs to the class itself.

Likely follow-ups
  • Can a class exist without objects? (Yes: utility classes, or before the first new.)
  • Where are static fields stored?
Is Java pass-by-value or pass-by-reference?

Always pass-by-value. For primitives the value is the number; for objects the value is the reference. So a method can mutate the object through its copy of the reference, but assigning a new object to the parameter does not affect the caller's variable. It behaves like passing a pointer by value in C.

How to answer

Say "by value, and for objects the value is a reference", then give the two-line reassign vs mutate example.

Likely follow-ups
  • How would you write a swap(a, b) for two objects in Java? (You cannot swap the caller's variables; return a pair or swap fields.)
  • How does C++ differ?
Explain == vs equals() in Java. Why must hashCode be overridden with equals?

== on references checks identity: same object. equals checks logical equality as the class defines it; Object's default is identity. Hash collections locate entries by hashCode first and only then compare with equals, so the contract says equal objects must return equal hash codes. If you override only equals, two equal objects usually hash to different buckets and contains or get fails. Override both from the same immutable fields, or use a record.

How to answer

Identity vs equality, then the bucket mechanism, then the fix. Bonus: mention the Integer cache trap and mutable keys.

Likely follow-ups
  • Can two unequal objects have the same hash code? (Yes, a collision; that is allowed.)
  • What are the other rules of equals? (Reflexive, symmetric, transitive, consistent, x.equals(null) is false.)
Stack vs heap: where do objects live in Java and in C++?

In Java, local variables and parameters, including references, live in the thread's stack frame; every object created with new lives on the shared heap and is freed by the GC when unreachable. (The JIT may avoid allocating an object that never escapes a method, but that is an optimisation, not something you rely on.) In C++ you choose: automatic objects on the stack, destroyed at scope exit; dynamic objects on the heap via new or smart pointers; static objects for the program's lifetime. The stack is per-thread and fast but limited and short-lived; the heap is shared, larger and needs an ownership story.

How to answer

Draw a frame with references pointing into a heap box. Mention thread-confinement of the stack as the link to concurrency.

Likely follow-ups
  • What causes a StackOverflowError?
  • What is a memory leak in a garbage-collected language?
In your parking-lot design, how do you define equality for Vehicle, Spot and Ticket?

They are entities, so equality is by stable identity: a vehicle by registration number, a spot by floor plus spot number (or a generated id), a ticket by ticket id. I make those id fields final, use them in both equals and hashCode, and keep changeable state (a spot's occupied flag, a ticket's exit time) out of equality, so the objects can sit safely as map keys. Small descriptive types such as Money or a SpotLocation(floor, number) are value objects: immutable records compared by all fields.

How to answer

Shows you think about equality as part of the design, not a language detail. Use the words entity and value object.

Likely follow-ups
  • Why not just use the default identity equality?
  • What breaks if a spot's hashCode uses its occupied flag?
Can a Java program leak memory? Give an LLD example.

Yes: a leak is memory that stays reachable but will never be used. Common LLD examples: an Observer subject whose listener list only grows because nobody unsubscribes; a static Map used as a cache with no eviction or size bound; sessions or bookings stored in a map and never removed after completion; a ThreadLocal on pooled threads that is never cleared. Fixes: explicit unsubscribe or weak listeners, bounded caches with eviction (LRU, TTL), lifecycle methods that remove finished entries, and remove() on thread-locals.

How to answer

Define a leak as "reachable but useless", give two examples from designs you would draw, and one fix each.

Likely follow-ups
  • How would you find such a leak in production? (Heap dump, dominator tree.)
  • What is a WeakHashMap for?
