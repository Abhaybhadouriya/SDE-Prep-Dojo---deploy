The story: one cookie cutter, many cookies

Explain like I'm 5

You have a star-shaped cookie cutter. The cutter is not a cookie; you cannot eat it. But every time you press it into the dough you get a new star cookie. All the stars have the same shape, yet each one is its own cookie: you can put chocolate chips on one and sprinkles on another, and eating one does not make the others disappear. If you write "Asha" on a sticky note and stick it on one cookie, and your friend writes "best one" on another note and sticks it on the same cookie, there are now two notes but still only one cookie. Take a bite through either note and the same cookie gets smaller.

The cutter is a class: a description of what every cookie of that kind has (shape, toppings) and can do. Each cookie is an object, also called an instance of the class, with its own state (its toppings). The sticky notes are references: names that point at an object. Two notes on one cookie are two references to one object, which is called aliasing. Most bugs on this page are "I thought I had two cookies, but I had two notes".

From your world

struct sk_buff in a header is a class; every sk_buff the kernel allocates is an object. A struct sk_buff *skb local variable is a reference, and passing skb to five functions does not copy the packet: five pointers, one buffer. You already know the difference between the type, the memory and the pointer. Java and Python just hide the * and the kfree.
