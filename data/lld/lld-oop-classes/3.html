References vs pointers, and "pass by value"

A Java reference is a pointer with the dangerous parts removed: no arithmetic, no casting to an integer, no pointing into the middle of an object, no dangling (the object cannot be freed while a reference exists). It can be null. A C++ reference is different again: an alias that must be bound at creation, cannot be re-pointed and cannot be null.

Java always passes arguments by value. For an object argument, the value that is copied is the reference. So the method can change the object (both copies point at it) but cannot make the caller's variable point somewhere else. This is exactly C's behaviour when you pass a struct foo *: the callee can write p->x = 1, but p = other only changes its own copy. Step through it:

  1. Ticket a = new Ticket("T-1", "A12"); One object, one reference.
  2. Calling reassign(a) copies the reference into the parameter t. Two references, still one object.
  3. Inside, t = new Ticket("T-9", "Z00") re-points the copy. The caller's a is untouched; T-9 becomes garbage when the method returns.
  4. Calling mutate(a), which does t.moveTo("D99"), changes the object both references share, so a.seat() is now "D99".

C++ lets you choose per parameter: by value (a full copy of the object), by reference T& (an alias, changes are visible), by const T& (an alias you may not change, the usual choice for big inputs), or by pointer (may be null). Python behaves like Java: names are references and arguments are references passed by value ("pass by object reference").

Aliasing bug in LLD code: a ParkingLot constructor that stores the caller's List<Floor> directly. The caller later clears its list and your lot loses its floors. Copy collections you receive (List.copyOf(floors)) and return unmodifiable views, so no one outside can change your state behind your back. This is called a defensive copy.
