Q&A: case-study follow-ups

The follow-up questions that come after you have drawn the classes for a classic problem: new features, hard parts, and the algorithm hiding inside. Each has a full case-study page in the case index.

Parking lot: add peak-hour pricing and EV charging spots. What changes?

Pricing: the fee calculation is already behind a FeeStrategy; add PeakHourFeeStrategy (or a decorator that applies a multiplier during peak windows) and select it in the factory. EV: add SpotType.EV (or an EvSpot with a Charger), extend the allocation strategy to prefer EV spots for electric vehicles, and add a charging fee component. If adding EV forced edits across five classes, your original design was missing a seam.

Seen in reports: Amazon 2026-09-16, Microsoft 2025-11-17.

How to answer

Name the exact class each feature touches. An Amazon SDE-1 report says missing peak pricing hurt.

Likely follow-ups
  • How do you price a stay that crosses the peak boundary? (split by interval)
Splitwise: how do you simplify debts?

Compute each person's net balance (paid minus owed). Debtors are negative, creditors positive. Greedy: repeatedly match the largest debtor with the largest creditor, settle the smaller amount, repeat (a max-heap on each side). That gives at most N-1 transactions. The true minimum number of transactions is NP-hard in general (it needs finding zero-sum subsets), so say greedy is the practical answer.

Seen in reports: Swiggy 2026-11-07, Uber 2026-05-15, Meesho 2024-09-20.

How to answer

Balances first, then greedy matching, then the NP-hard caveat. Splits (EQUAL, EXACT, PERCENT) are Strategies.

Likely follow-ups
  • How do you avoid rounding errors? (integer paise, give the remainder to one person)
  • Group vs global balances? (keep balances per group and simplify inside each; a global view sums the nets across groups)
BookMyShow: how does a seat hold work while the user pays?

On seat selection, atomically move the seats from AVAILABLE to HELD with the user id and an expiry (a CAS per seat, or a per-show lock for multi-seat selection, all or nothing). Payment success moves HELD to BOOKED; failure or timeout moves them back to AVAILABLE. A sweeper thread or a DelayQueue releases expired holds. Never let two users hold the same seat.

Seen in reports: Paytm 2026-11-11, Salesforce 2026-10-31, Amazon 2025-09-27.

How to answer

Draw the three seat states and who moves each transition; the timer is the part people forget.

Likely follow-ups
  • User selects 4 seats and 1 is taken? (fail the whole hold)
  • Across servers? (DB conditional update or Redis with TTL)
Elevator system: how do you choose which elevator serves a request?

Make it a DispatchStrategy. Simple: nearest idle elevator. Better: nearest elevator already moving towards the floor in the same direction (SCAN/LOOK, like a disk scheduler). Each elevator keeps up and down stop sets (sorted) and a state (IDLE, MOVING_UP, MOVING_DOWN, DOOR_OPEN). Capacity and constraints (a Microsoft version had 50 floors, capacity 20) go into the strategy's filter.

Seen in reports: Microsoft 2024-12-16, Microsoft 2024-07-09.

How to answer

Tie it to the disk elevator algorithm; then show State for the car and Strategy for dispatch.

Likely follow-ups
  • Emergency mode? (a state that cancels pending requests and sends every car to the nearest floor with doors open; the dispatch strategy is bypassed)
  • Peak-hour zoning (some cars serve only high floors)?
Chess: where does move validation live?

Each Piece subclass knows its movement pattern (canMove(from, to, board)), polymorphism instead of a switch on piece type. The Game (or a MoveValidator) checks rules that need the whole board: blocked paths, own king in check after the move, castling, en passant. Moves are Command objects so you get history and undo. A piece factory builds the starting position.

Seen in reports: Zepto 2026-05-29, Microsoft 2024-09-12, Amazon 2025-02-09.

How to answer

Split piece-local rules from game-wide rules; that division is what gets graded.

Likely follow-ups
  • Detect checkmate? (no legal move and king in check)
  • Was Strategy for rules over-design? (an Amazon report got that feedback)
Snake and ladder: what must be easy to extend?

Board size, number of dice, the dice itself (a Dice interface: normal, crooked, fixed for tests), board entities (snakes, ladders, maybe crocodiles or mines as a BoardEntity with destination(pos)), and win rules. Keep players in a queue for turns. Inject the dice so tests are deterministic.

Seen in reports: PhonePe 2024-06-01, Microsoft 2025-11-18.

How to answer

Name three extension points and show the injected dice for testing.

Likely follow-ups
  • Multiple winners: does the game continue? (make it a rule: either stop at the first winner, or record the finishing order and continue until one player is left)
  • A PhonePe evaluation added extra features live. (say where the change goes before typing, add it behind an existing seam, and run the driver again)
LRU cache: design for O(1) get and put.

A hash map from key to node, plus a doubly linked list ordered by recency. get: look up the node, move it to the head. put: update or insert at head; if over capacity, remove the tail node and its map entry. In Java, LinkedHashMap with access order and removeEldestEntry does this in a few lines; interviewers usually want the hand-written version.

Seen in reports: Amazon 2026-11-08, Microsoft 2026-08-23, Walmart 2026-05-28.

How to answer

Code the node, the two sentinel nodes, and the four list helpers. Then offer thread safety.

Likely follow-ups
  • Make eviction pluggable (LRU, LFU, FIFO)? (an EvictionPolicy interface)
  • Add TTL per key? (store an expiry with each node, treat expired entries as misses, and evict them lazily or from a timer)
Notification service: channels, retries and user preferences.

NotificationService.send(userId, template, data) looks up preferences (which channels, quiet hours), renders the template, and hands one message per channel to a ChannelSender (Strategy: SMS, email, push, in-app). Sends go through a queue with retry and backoff; failures after N tries go to a dead-letter list. Providers per channel can fail over (an Adapter per provider). Keep a history record for each delivery.

Seen in reports: Salesforce 2026-11-19, Amazon 2026-11-14, Swiggy 2026-03-27, PhonePe 2025-03-29.

How to answer

Layer it: preference, template, channel, provider, retry. The most reported case after parking lot in our survey.

Likely follow-ups
  • Priority notifications (OTP vs marketing)? (separate queues)
  • Rate-limit per user? (a token bucket per user checked before send; on overflow drop or defer marketing messages, never OTPs)
  • Idempotency on retry? (a client-supplied message id stored with a short TTL; a repeat id returns the first result instead of sending again)
Ride hailing: model the trip lifecycle and driver matching.

Trip states: REQUESTED, DRIVER_ASSIGNED, DRIVER_ARRIVED, IN_PROGRESS, COMPLETED, CANCELLED (State pattern or a guarded enum). Matching is a Strategy (nearest available, by vehicle type, by rating). Claiming a driver is atomic (CAS on driver state). Fare is a Strategy by vehicle type and time (surge as a decorator). Location updates are just a map from driver to position for LLD; geo-indexing is HLD.

Seen in reports: Amazon 2026-05-22, Uber 2026-07-27, Salesforce 2025-12-07.

How to answer

State for the trip, Strategy for matching and fare, CAS for the claim.

Likely follow-ups
  • Driver cancels after accepting? (move the trip back to REQUESTED, free the driver, re-run matching and log the cancel against the driver)
  • How do you find nearby drivers fast? (grid or geohash buckets)
In-memory file system with mkdir, cd, ls and wildcard paths (like a/*/c).

A tree (Composite): Directory holds a map from name to child node; File holds content. Paths are split on "/", resolved from root or the current directory, with "." and "..". For a wildcard segment, branch into every child at that level (DFS), collecting matches. ls sorts names. This problem was reported repeatedly at Uber.

Seen in reports: Uber 2026-08-11, Uber 2026-04-20, Uber 2025-10-25, Uber 2026-01-15.

How to answer

Write the path resolver first; every command uses it. Then handle the wildcard as recursion.

Likely follow-ups
  • Wildcards like a*b inside a name? (match with a simple glob or regex per child)
  • Make it thread-safe? (a lock per directory for writes, or one read-write lock on the tree; lookups take the read side)
Car rental: search available cars for a date range.

Each car has a list of bookings (intervals). A car is available if the requested [start, end) overlaps none: overlap test is start < b.end && b.start < end. Keep bookings sorted (a TreeMap by start) to check neighbours in O(log n). Filters (type, branch, price) are Specifications; ordering (cheapest first) is a comparator Strategy.

Seen in reports: Uber 2025-10-26, Amazon 2025-08-21, Adobe 2024-12-23.

How to answer

Write the overlap condition correctly; it is the classic bug.

Likely follow-ups
  • Book a car at one branch and drop at another? (the booking stores pickup and drop branches; the car's location moves at return, and availability is checked at the pickup branch)
  • Two users book the same car at once? (lock the car (or use a unique constraint on car and dates) around the overlap check and the insert)
Meeting room scheduler: find a free room and handle recurring meetings.

Each room keeps a sorted set of booked intervals; booking checks overlap with the neighbours. Room choice is a Strategy (smallest room that fits, or nearest). Recurring meetings: store a recurrence rule and expand occurrences for a window (next 90 days) when checking conflicts, instead of storing infinite rows. Booking all occurrences must be all-or-nothing.

Seen in reports: Zepto 2025-11-16, Uber 2025-06-24, Salesforce 2025-10-25.

How to answer

Interval overlap plus a recurrence rule that expands lazily; mention time zones.

Likely follow-ups
  • Find the earliest common free slot for 5 people? (merge busy intervals, scan gaps)
Quick commerce (Flipkart Minutes): queue orders when no delivery partner is free.

Orders go to a FIFO BlockingQueue when no partner is available. When a partner becomes free (delivers or an assigned order is cancelled), the dispatcher takes the next non-cancelled order. Order states: PLACED, ASSIGNED, PICKED_UP, DELIVERED, CANCELLED; cancel is allowed only before pickup. Every state change and assignment must be atomic (per-order lock, or one dispatcher thread owning assignment). Auto-cancel after 30 minutes is a scheduled task.

Seen in reports: Flipkart 2026-02-18, Zepto 2024-10-22.

How to answer

List the state transitions and the two events that trigger assignment (new order, partner freed).

Likely follow-ups
  • Cancelled order still in the queue? (skip on dequeue)
  • Notifications as a bonus? (Observer)
Stock exchange: implement order matching with partial fills.

Per stock, an order book with two priority queues: buys by highest price then earliest time, sells by lowest price then earliest time. A new buy matches while the best sell price is at or below its limit: trade the smaller quantity, reduce both, remove filled orders, repeat; the rest stays on the book. Each trade is recorded. Lock per stock (or one matching thread per stock) so matching is serial per symbol.

Seen in reports: Groww 2026-04-21, MakeMyTrip 2026-04-27, Meesho 2026-07-15.

How to answer

Price-time priority, then the matching loop, then concurrency per symbol.

Likely follow-ups
  • Market orders? (match at any price)
  • Cancel an order in the middle of the heap? (lazy deletion flag)
Task scheduler where tasks start only after their dependencies finish.

Build a DAG: each task has a count of unfinished dependencies and a list of dependents. Tasks with count 0 go to a ready queue; workers take from it; when a task finishes, decrement each dependent's count (atomically) and enqueue those that hit 0. Detect cycles up front with a topological sort (Kahn's algorithm). Priorities: make the ready queue a priority queue.

Seen in reports: Goldman Sachs 2025-05-05, Rubrik 2024-12-04.

How to answer

Kahn's algorithm plus a worker pool; mention cycle detection.

Likely follow-ups
  • A task fails: what happens to its dependents? (mark them skipped, or retry policy)
Shopping cart: how do you design coupons and discounts?

A Discount interface with apply(cart) returning a discount amount: percentage, flat, buy-X-get-Y, category-specific. Eligibility rules are Specifications (min amount, user tier, date range). Stacking rules (best single coupon vs combinable) live in a DiscountEngine. Money in integer paise, totals recomputed from line items, never stored as running floats.

Seen in reports: Meesho 2025-05-18, Swiggy 2025-08-11, Amazon 2026-10-12.

How to answer

Interface for the discount, specification for eligibility, engine for combining.

Likely follow-ups
  • Coupon usage limits under concurrency? (atomic counter per coupon)
  • Inventory check at add vs at checkout? (show availability at add, but reserve or decrement only at checkout inside one atomic step)
Wallet: how do you support reversing a transaction?

Never edit or delete past entries. A reversal is a new transaction that posts the opposite entries and links to the original (reversalOf). Balances are derived from (or kept consistent with) the ledger. A transfer posts a debit and a credit atomically, locking both wallets in id order to avoid deadlock. Reject a second reversal of the same transaction.

Seen in reports: Groww 2026-09-24, Paytm 2025-04-22.

How to answer

Append-only ledger, compensating entry, lock ordering: three points.

Likely follow-ups
  • Partial reversal? (a new reversal entry for part of the amount, linked to the original; the sum of reversals may not exceed it)
  • Idempotency key for retried requests? (the client sends a key; the first request stores key to result, and a retry with the same key returns that result)
Expiring key counter: count keys that were added in the last N seconds.

Store events in a queue (or a deque per key) with timestamps; on each read or write, pop events older than now - N. Total count is the queue size. For high rates, bucket by second in a circular array of N buckets (like a sliding window rate limiter). Make the clock injectable so tests are deterministic.

Seen in reports: Uber 2025-11-29, Uber 2025-08-04.

How to answer

Lazy expiry on access, buckets for scale, injectable clock for tests.

Likely follow-ups
  • Memory bound? (buckets: O(N) regardless of rate)
  • Thread safety? (one lock around the queue and the count, or a ConcurrentLinkedDeque with an atomic counter if exact counts can lag)
News feed: support follow, post and per-user custom ranking.

User, Post, a follow graph (map from user to set of followees). getFeed(user): collect recent posts of followees (merge the latest K from each with a heap), then rank with a RankingStrategy chosen per user (recency, likes, mixed). Fan-out on read for LLD; fan-out on write is the HLD follow-up.

Seen in reports: Uber 2026-10-01, Microsoft 2025-11-09, Flipkart 2025-01-20.

How to answer

Data model, merge with a heap, ranking strategy. Mention fan-out trade-off as a one-liner.

Likely follow-ups
  • Pagination with a cursor? (return the last item's (timestamp, id) as an opaque cursor; the next page asks for items strictly older than it)
  • Celebrities with millions of followers? (hybrid fan-out)
Food delivery: how do you make order placement idempotent?

The client sends an idempotency key with each order request. The service stores key to result; a retry with the same key returns the stored result instead of creating a second order. The check-and-store must be atomic (putIfAbsent, or a unique constraint in the database). Combine with State for the order lifecycle and Observer for restaurant, rider and customer updates.

Seen in reports: Zomato 2026-10-24, Cleartrip 2026-07-21.

How to answer

Explain the double-tap problem, then the key, then the atomic store.

Likely follow-ups
  • How long do you keep keys? (a TTL longer than the client retry window)
Inventory: reserve stock at order creation and deduct at confirmation.

Track available and reserved per item. reserve(item, qty) atomically checks available >= qty and moves qty to reserved. confirm removes it from reserved; cancel or a timeout moves it back. Per-item locks (or CAS) prevent overselling. Multi-item orders reserve all or nothing (lock items in id order).

Seen in reports: Meesho 2024-10-17, Meesho 2026-04-10.

How to answer

Two counters, three operations, one invariant (available never below zero).

Likely follow-ups
  • Reservation expiry? (store an expiry per reservation and release it on a timer or lazily on the next read)
  • Restock while reserved? (restock raises available only; existing reservations are untouched, so the two counts stay separate)
Customer issue resolution: assign issues to agents by specialisation.

Issue (type, status), Agent (expertise set, current issue, waitlist). An AssignmentStrategy picks an agent: first free agent with matching expertise, or least loaded. If none is free, the issue waits in that agent's (or a global) queue. Resolving an issue frees the agent and pulls the next one. Search issues by filters. Reported repeatedly at PhonePe.

Seen in reports: PhonePe 2026-01-31, PhonePe 2025-09-16, PhonePe 2025-05-07.

How to answer

Strategy for assignment is the expected extension point; show swapping it.

Likely follow-ups
  • Two issues assigned to one agent concurrently? (lock the agent or compare-and-set its state from FREE to BUSY; the loser picks the next agent)
  • Agent goes offline? (mark the agent unavailable and re-queue their open issues at the front with the same priority)
Rating system: agents rated out of 5; show monthly best agents and handle ties.

Store each rating with agent, score and timestamp. Keep running sums and counts per (agent, month) so averages are O(1). Ranking: sort by average descending, then a stated tie-break (more ratings first, then name or earliest). Atlassian-style rounds grow the API step by step (monthly stats, export), so keep it simple and tested at each step.

Seen in reports: Atlassian 2025-08-12, Atlassian 2025-07-09, Razorpay 2024-06-16.

How to answer

Ask how ties should break; write tests for ties explicitly.

Likely follow-ups
  • Top K efficiently? (a heap of size K)
  • Ratings can be edited? (keep one rating per (rater, agent, month); an edit replaces it and adjusts the stored sum and count)
Cache with a pluggable eviction policy.

Cache<K,V> holds a Storage (a map with capacity) and an EvictionPolicy<K> with keyAccessed(k) and evictKey(). LRU uses a linked list, LFU a frequency map with buckets, FIFO a queue. The cache calls the policy on every get and put. New policy is a new class. A PhonePe 1-day take-home asked exactly this.

Seen in reports: PhonePe 2024-11-02, Groww 2025-04-24.

How to answer

Separate storage from policy; show the two policy methods.

Likely follow-ups
  • LFU in O(1)? (frequency to linked set of keys, track min frequency)
Version control (git-like) in memory: commit, branch, checkout, log.

A Commit is an immutable snapshot (map of path to content hash) with a parent pointer. A Branch is a name pointing to a commit; HEAD points to a branch. add stages changes; commit creates a new commit from the staging area; checkout -b creates a branch at HEAD; reset HEAD~n walks parents; log walks from HEAD; diff compares two snapshots. A Razorpay AI-assisted round asked for this.

Seen in reports: Razorpay 2025-10-13.

How to answer

Immutable commits plus movable pointers is the whole model.

Likely follow-ups
  • Merge two branches? (find common ancestor, three-way diff)
