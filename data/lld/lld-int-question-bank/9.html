Q&A: behavioural patterns

Strategy, State, Observer, Command, Chain of Responsibility, Template Method and the rarer ones, plus "which pattern fits this problem?".

Explain Strategy with a payment example.

Define PaymentStrategy { PaymentResult pay(Money amount); } with UpiPayment, CardPayment, NetBankingPayment. The checkout service holds a PaymentStrategy chosen at run time (by the user or a factory) and calls pay() without knowing which. A new mode is a new class; checkout does not change.

Seen in reports: Walmart 2025-09-21, Razorpay 2024-11-05, Uber 2026-10-01.

How to answer

Code the interface and one class, then say 'adding Wallet is one class'. That proves OCP.

Likely follow-ups
  • How is the strategy chosen? (factory from the request, or a map from enum to strategy)
  • What if a mode needs extra data like a UPI id? (pass a request object, or build the strategy with it)
Strategy vs State: they look identical. What is the difference?

Both delegate to an interface with swappable implementations. In Strategy the client picks the algorithm and the strategies do not know each other. In State, the object's behaviour depends on its current state, and the states themselves decide the next state (HasMoneyState.dispense() moves the machine to DispensingState). Strategy is about how; State is about when and what is allowed.

Seen in reports: MakeMyTrip 2025-07-25.

How to answer

Ask 'who changes it?': the client (Strategy) or the state objects (State).

Likely follow-ups
  • Could you implement State with an enum and a switch? (yes for small machines; classes when behaviour per state is large)
Design a vending machine using the State pattern.

States: Idle, HasMoney, Dispensing, OutOfStock, all implementing insertCoin, selectItem, dispense, refund. Each state handles legal actions and rejects others (selecting an item in Idle throws). The machine holds the current state and inventory; states call machine.setState(...). Change calculation can be a separate Strategy.

Seen in reports: MakeMyTrip 2025-07-25, Amazon 2025-12-07, Amazon 2025-04-04.

How to answer

Draw the state diagram first, then turn each box into a class. A MakeMyTrip report says the interviewer expected exactly this.

Likely follow-ups
  • Two users pressing buttons at once? (one machine is single-user; lock the machine)
  • Add a 'maintenance' state: what changes? (one new state class and the transitions into and out of it; each existing state keeps its code unless it can enter maintenance)
Explain Observer and show where it fits in a notification system.

A subject keeps a list of observers behind an interface and notifies them when something changes. Order service publishes OrderStatusChanged; EmailNotifier, SmsNotifier and PushNotifier subscribe. The order service does not know who listens; adding a channel is a new observer. Watch out for: slow observers blocking the subject (make delivery async), exceptions in one observer stopping the rest, and memory leaks from observers never removed.

Seen in reports: Zomato 2026-10-24, Kotak 2026-02-04, Salesforce 2026-03-02.

How to answer

Code subscribe/notify, then give the three failure modes. Observer gets heavy cross-questioning in reports.

Likely follow-ups
  • Push vs pull model? (push sends the data with the event (simple, but every observer gets everything); pull sends only the event and observers fetch what they need)
  • Observer vs pub-sub? (pub-sub adds a broker; publishers and subscribers do not know each other)
Command pattern: what is it, and where does undo come from?

Wrap a request as an object with execute() (and often undo()). The invoker (a button, a queue, a scheduler) runs commands without knowing what they do. Undo: keep executed commands on a stack; undo() pops and reverses. Also gives queuing, logging, retry and macro commands. In machine-coding drivers, a map from command word to handler is a lightweight Command.

How to answer

Text editor example: InsertText command stores what it inserted, so undo removes it.

Likely follow-ups
  • Command vs Memento for undo? (command reverses an action; memento restores a snapshot)
Chain of Responsibility: give two real uses.

A request passes along a chain of handlers; each either handles it, rejects it, or passes it on. Uses: request filters/middleware (auth, rate limit, validation, then the controller), ATM cash dispensing (2000s handler, then 500s, then 100s), logging levels, approval workflows (manager, director, VP by amount). Kernel: netfilter hooks, where each rule returns accept, drop or continue.

How to answer

Show the handler interface with setNext() and one handler body.

Likely follow-ups
  • What if no handler takes it? (a default terminal handler)
  • Chain vs Decorator? (chain may stop early; decorator always delegates)
Template Method vs Strategy.

Template Method uses inheritance: a base class fixes the skeleton (export() { open(); writeHeader(); writeRows(); close(); }) and subclasses fill in steps. Strategy uses composition: the whole algorithm is a separate object passed in. Template Method is fine when the steps are stable; Strategy is better when you need to swap at run time or combine variations.

How to answer

Inheritance vs composition is the one-line answer; give one example each.

Likely follow-ups
  • What is a hook method? (an optional step with a default empty body)
Iterator: why use it instead of exposing the list?

It lets callers walk a collection without knowing its structure (array, tree, paged results from a database) and lets you change the structure later. It also allows several independent traversals at once and lazy loading. Java's Iterable/Iterator and Python generators are built-in versions.

How to answer

Benefit (hide structure), example (tree in-order iterator), built-in support.

Likely follow-ups
  • What is a fail-fast iterator? (throws ConcurrentModificationException if the collection changes underneath)
Mediator: when do you need it?

When many objects talk to each other directly and every change ripples (N objects, up to N x N links). A mediator becomes the hub: components only talk to it. Examples: a chat room relaying messages between users, an air-traffic controller, a UI dialog coordinating widgets, an elevator controller dispatching between cars and floor buttons.

How to answer

Draw the mesh, then the hub. Mention that the mediator itself must not become a god class.

Likely follow-ups
  • Mediator vs Observer? (mediator coordinates two-way; observer is one-to-many broadcast)
Memento: how would you implement undo in a text editor with it?

The editor creates a Memento (an immutable snapshot of its text and cursor) before each change; a History stack stores them; undo restores the last one. The memento's contents are private to the editor (encapsulation kept). For big documents, store diffs or use commands instead of full snapshots.

How to answer

Explain originator, memento, caretaker in one line each, then the memory trade-off.

Likely follow-ups
  • How do you support redo? (a second stack)
Visitor: what problem does it solve, and what is double dispatch?

It adds new operations over a fixed set of classes without editing them: an AST with Number, Add, Mul gets EvalVisitor, PrintVisitor, TypeCheckVisitor. Each node has accept(v) that calls v.visit(this); the right overload is chosen by both the node type and the visitor type: double dispatch. Trade-off: adding a new node class means editing every visitor.

How to answer

Say when to use it: classes stable, operations growing. Opposite case: plain polymorphism.

Likely follow-ups
  • How do Java sealed interfaces plus pattern matching change this? (switch over types replaces many visitors)
Interpreter pattern: when would you use it in an LLD round?

When the problem has a small language: rule expressions ("amount > 1000 AND country == IN"), a calculator, search filters, a command DSL. Each grammar rule becomes a class with interpret(context), forming a Composite tree. For anything bigger, use a parser generator instead.

Seen in reports: Oracle 2024-12-07.

How to answer

Tie it to Composite and say when it stops scaling.

Likely follow-ups
  • Build a parser for '2 + (3 * 4)' (recursive descent into Composite nodes)
Null Object: why is it better than null checks?

Instead of returning null and checking everywhere, return an object that does nothing safely: NoDiscount returns 0, NullLogger drops messages. Callers become simpler and NPEs disappear. Do not use it where absence must be noticed (a missing user should be an error, not a silent no-op).

How to answer

Give the discount example and the 'when not to' case.

Likely follow-ups
  • Null Object vs Optional? (Optional forces the caller to decide; Null Object decides for them)
Specification pattern: how do you build flexible search filters?

Each rule is an object with isSatisfiedBy(item): PriceBelow(500), InCategory("books"), combined with and, or, not. A search service takes a specification and filters. New filters are new classes; combinations need no new code. It fits review search, rental search and product filtering problems.

Seen in reports: Amazon 2025-06-03.

How to answer

Show composition of two specs with and(); that is the selling point.

Likely follow-ups
  • How would specs translate to SQL? (each spec also produces a WHERE fragment)
Which patterns did you use in a recent project, and why?

Pick two you really used and tell each as problem, pattern, result. For example: "Our alert pipeline had five sinks and kept growing; I put them behind an Observer-style listener interface, so adding Slack was one class. Payment retries differed per provider; a Strategy per provider removed a 200-line switch." Avoid listing ten names.

Seen in reports: Walmart 2025-09-21, Walmart 2025-05-25.

How to answer

Two real stories beat ten names. Expect a drill-down into one of them.

Likely follow-ups
  • What would you do differently now? (pick one real thing, such as adding an interface only after the second implementation appeared)
  • Did any pattern make things worse? (an honest example helps: an Observer chain that made one flow hard to trace, so you replaced it with direct calls)
The interviewer asks 'how many design patterns do you know?'. How do you answer?

Give the structure, not a count: "The 23 GoF patterns are in three groups: creational (5), structural (7) and behavioural (11). I use about eight regularly: Strategy, Factory, Builder, Observer, State, Decorator, Adapter and Command. Want me to show one in this design?" Then steer back to the problem.

Seen in reports: MakeMyTrip 2025-07-25.

How to answer

Show you know the map and which parts you use; offer to apply one.

Likely follow-ups
  • Which pattern do you find least useful? (Flyweight or Interpreter, rare in app code)
The problem 'hints at a pattern'. How do you find it?

Look for the change the problem describes. "Different rules per type" means Strategy. "Behaviour depends on status" means State. "Notify when something happens" means Observer. "Add features in combinations" means Decorator. "One of several ways to create" means Factory. "Pass a request through checks" means Chain of Responsibility. Say the hint you saw, then the pattern.

Seen in reports: Amazon 2025-07-03, Swiggy 2026-11-07.

How to answer

Quote the problem's words back, then name the pattern; it shows the reasoning, not a guess.

Likely follow-ups
  • What if two patterns fit? (pick the simpler; mention the other)
How would you make an Observer-based system work with Kafka instead of in-process calls?

The subject becomes a producer that publishes events to a topic; each observer becomes a consumer group. Changes: delivery is asynchronous and at-least-once, so consumers must be idempotent (dedupe by event id); ordering is only per partition (use the entity id as the key); failures go to retry or dead-letter topics. The interfaces in code can stay similar: a Publisher interface with an in-memory and a Kafka implementation.

Seen in reports: Salesforce 2026-03-02.

How to answer

Name what changes semantically (async, at-least-once, ordering) rather than only the API.

Likely follow-ups
  • How do you keep the DB write and the event publish consistent? (transactional outbox)
Rate limiter algorithms: which would you implement in an LLD round and how?

Token bucket is the usual pick: a bucket per key with capacity and refill rate; on each request, refill by elapsed time, then take a token or reject. Others: fixed window counter (simple, bursts at window edges), sliding window log (exact, memory heavy), sliding window counter (a good approximation). Put the algorithm behind a RateLimiter interface (Strategy), keep per-key state in a ConcurrentHashMap, and synchronise per key.

Seen in reports: Microsoft 2026-01-16, Microsoft 2024-12-04.

How to answer

Pick token bucket, write tryAcquire(key), then list the alternatives in one line each.

Likely follow-ups
  • Per-API and combined limits at once? (a composite limiter that checks all)
  • Memory per key? (two longs for token bucket)
Behavioural patterns in the Linux kernel: give three.

Observer: notifier chains (register_netdevice_notifier, call_netdevice_notifiers). Chain of Responsibility (loosely): netfilter hook functions run in priority order; NF_ACCEPT passes the packet on to the next hook, while NF_DROP, NF_STOLEN or NF_QUEUE stop it. Any link can end the request, which is the Chain idea, though netfilter behaves more like a filter pipeline than "first handler wins". Strategy: pluggable TCP congestion control (tcp_congestion_ops) and I/O schedulers. State: the TCP state machine. Template Method: really_probe() in the driver core is the fixed skeleton (bind, set up resources, call the hook, clean up on failure) and drv->probe is the step the driver fills in.

How to answer

Name the pattern, then the kernel object. This answer stands out because few candidates have it.

Likely follow-ups
  • How does the kernel avoid an observer blocking the notifier? (notifier types: atomic vs blocking chains)
