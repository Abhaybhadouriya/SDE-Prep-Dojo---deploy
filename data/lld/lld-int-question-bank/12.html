Q&A: the round itself

Format, time use, grading, the evaluation call, AI-assisted rounds and the reasons people fail.

What happens in an LLD round, and how is it different from machine coding?

Three shapes. LLD discussion (Amazon, Microsoft, Walmart, Salesforce, Zepto): 45-60 minutes; requirements, class diagram, key code, then follow-ups. Machine coding (Flipkart, PhonePe, Razorpay, CRED, Meesho): 90-120 minutes of solo coding from a problem document, then an evaluation call. Code design (Atlassian): 60 minutes in your IDE with tests, a small API that grows. Uber and Microsoft often expect running code within an hour.

Seen in reports: Flipkart 2026-02-18, Amazon 2026-07-07.

How to answer

Ask the recruiter which shape it is, whether code must run, and which platform.

Likely follow-ups
  • Is AI allowed? (some 2026 rounds allow it and grade how you use it; Flipkart bans it)
How do you spend the first 10 minutes of an LLD round?

Clarify scope (actors, the 3-5 core use cases, what is out of scope), list non-functional needs that change the design (concurrency? persistence? scale?), and write the agreed requirements where both of you can see them. Then name the core entities. Several reports note that requirements were withheld on purpose to see whether the candidate asks.

Seen in reports: Amazon 2025-04-04, Groww 2025-04-24.

How to answer

Ask, write down, confirm. Do not start drawing classes before the interviewer agrees on scope.

Likely follow-ups
  • What if the interviewer says 'you decide'? (state assumptions out loud and write them)
What do graders score in a machine-coding round?

From the stated criteria in reports and official guidelines: working, demoable code first; then functional completeness of P0; modularity and separation of concerns; extensibility (a new requirement means small changes); entity modelling; error handling and edge cases; readability and naming; tests or a driver; concurrency where the problem asks. Patterns count only where they fit.

Seen in reports: Flipkart 2026-02-18, PhonePe 2025-09-21, CRED 2023-08-31.

How to answer

Recite the order: works, complete, modular, extensible, robust, readable. Then say how your plan hits each.

Likely follow-ups
  • Which is most important? (working code: some companies do not evaluate code that does not run)
The evaluator asks you to add a feature live in the review call. How do you approach it?

Say where it goes before typing: which class changes, which new class appears, and what stays untouched. Then implement the smallest version and run the demo again. If your design needs edits in many places, admit it and say which seam you would add. PhonePe and Flipkart evaluation calls do this regularly.

Seen in reports: PhonePe 2024-06-01, Flipkart 2025-04-26.

How to answer

Plan out loud, change little, rerun. The grader is testing extensibility in practice.

Likely follow-ups
  • What if it breaks an existing test? (the test is the spec: fix the change, or ask whether the requirement itself changed)
Over-engineering vs under-engineering: how do you hit the right level?

Add an abstraction only where the problem statement signals variation (types, strategies, configurable rules) or where you need a test seam. Everything else is a plain class. Under-engineering looks like one service with 30 methods and switches on type; over-engineering looks like interfaces with one implementation, factories for everything, and unfinished P0.

Seen in reports: Flipkart 2023-04-01, Amazon 2025-02-09.

How to answer

Name both failure modes and the rule you use to choose. Rejection posts cite both.

Likely follow-ups
  • Show one interface in your design you would delete. (the one with a single implementation and no stated change behind it)
Which language should you use for machine coding?

The one you can type fastest without looking things up. Java is the most common choice (rich collections and concurrency library, clear interfaces). Python is accepted and shorter, but be ready to explain thread safety with the GIL. C++ is usually allowed; know std::mutex, smart pointers and how to write interfaces with pure virtual classes. Switching languages before the round is a stated regret in reports.

Seen in reports: Uber 2026-08-29.

How to answer

Pick one and practise the skeleton in it until it is automatic.

Likely follow-ups
  • Does the GIL make Python code thread-safe? (no: compound operations still race)
AI-assisted LLD rounds: what changes?

Some 2025-2026 rounds (Razorpay machine coding, a Microsoft SDE-2 LLD round, CRED AI-native design) allow an AI assistant and grade how you use it: clear prompts, reviewing and correcting the output, keeping the design yours, and testing. Do the requirements and class design yourself, use the tool for boilerplate, and read every line it produces. Flipkart explicitly prohibits AI in its 2026 drives.

Seen in reports: Razorpay 2026-02-13, Microsoft 2026-08-15, CRED 2026-01-03.

How to answer

Treat the AI like a fast junior: you own the design and the review.

Likely follow-ups
  • The AI produced a race condition. How do you spot it? (look for check-then-act on shared state)
Amazon LLD round: what is different?

The 55-60 minute round usually opens with 2-4 Leadership Principle questions, leaving 25-35 minutes for design. Expect a whiteboard tool or a shared editor, little up-front requirement detail, and a class diagram plus key code paths; patterns like Strategy, State and Observer get probed. A weak LLD can trigger an extra LLD round.

Seen in reports: Amazon 2026-11-14, Amazon 2026-10-17, Amazon 2025-05-08.

How to answer

Prepare a 25-minute version of each classic problem, and ask scope questions quickly.

Likely follow-ups
  • UML or code? (ask; reports show both)
How do you demo your machine-coding solution?

A driver (or tests) that runs every P0 feature in order with readable output, then each edge case: unknown id, duplicate, limit reached, double cancel, invalid input. Make input easy to type if the evaluator will enter commands. Keep the demo runnable from one command, and say it in a README.

Seen in reports: PhonePe 2023-06-23.

How to answer

Show the happy path and the failure lines; that answers edge cases and error handling together.

Likely follow-ups
  • No time for unit tests: what then? (a scripted main that asserts expected outputs)
Common reasons people fail LLD rounds.
  • No running code at the end, or a compile error.
  • Everything in one class; "modular but not extensible".
  • Misreading the problem; drifting into HLD.
  • Class per instance instead of class per concept.
  • "Add synchronized" as the whole concurrency answer.
  • Silent coding with no explanation of trade-offs.
  • Over-engineering that leaves P0 unfinished.

Seen in reports: Flipkart 2023-04-01, Razorpay 2025-06-26, CRED 2023-08-31.

How to answer

Turn each into a habit: compile every 10 minutes, one interface per variation point, talk while you code.

Likely follow-ups
  • Which of these have you done in practice, and what did you change? (name one honestly, such as late compiling, and the habit that fixed it)
