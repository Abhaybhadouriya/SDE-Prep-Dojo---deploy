Q&A: OOP fundamentals

Pillars, classes and memory, inheritance vs composition, interfaces, polymorphism and vtables, Java and C++ details that come up in "Java + LLD" rounds.

Explain OOP and its four pillars, with one real example each.

Object-oriented programming groups data with the functions that act on it, into objects that talk through methods.

  • Encapsulation: a BankAccount keeps balance private; only deposit() and withdraw() change it, so it can never go negative.
  • Abstraction: callers see PaymentMethod.pay(amount), not the UPI or card protocol behind it.
  • Inheritance: SavingsAccount extends BankAccount reuses the fields and adds interest.
  • Polymorphism: a list of Shape objects, each area() call runs the right subclass code at run time.

Seen in reports: Microsoft 2024-09-12, Mastercard 2025-10-25, WEX 2026-08-30, Airtel 2026-08-18.

How to answer

One line per pillar, each with a different concrete example. Do not recite textbook definitions; the example proves you understand it. Close with: encapsulation and polymorphism matter most in design rounds.

Likely follow-ups
  • Difference between encapsulation and abstraction? (encapsulation hides the data and guards how it changes; abstraction hides how a thing works behind what it does)
  • Explain OOP to a five-year-old. (see the next card: toys built from one design, each with its own colour)
Encapsulation vs abstraction: what is the difference?

Abstraction is about what a caller sees: a small interface that hides the complexity (Car.start()). Encapsulation is about protecting state: fields are private and only changed through methods that keep the rules (fuel cannot go below zero). Abstraction is a design decision at the boundary; encapsulation is enforced inside the class with access modifiers.

How to answer

Give one object and show both: the interface it exposes (abstraction) and the private field it guards (encapsulation).

Likely follow-ups
  • Is a getter plus a setter for every field encapsulation? (no: it exposes the state with extra steps)
Class vs object vs instance: and where does each live in memory?

A class is the blueprint: field layout plus method code, loaded once (in Java, its metadata sits in the JVM's metaspace). An object (instance) is one copy of the fields, created with new on the heap. A local variable holding it is a reference on the thread's stack. Methods are not copied per object; every instance shares the same code and gets this as a hidden first argument.

How to answer

Use the C picture: struct definition = class, malloc'd struct = object, pointer on the stack = reference, function taking struct* = method.

Likely follow-ups
  • What happens to the object when the last reference goes away? (it becomes garbage; the collector frees it later, in Java with no destructor call you can rely on)
  • Static fields: per class or per object? (per class: one copy shared by all objects, like a file-scope global in C)
Composition vs inheritance: when do you pick which? Why use inheritance at all if composition works?

Use inheritance only for a true, stable is-a where every subclass can honour the parent's contract (LSP), for example IOException extends Exception. Use composition (has-a, holding an interface) when behaviour varies or may change at run time: a Car has an Engine, and a petrol engine can be swapped for an electric one. Composition avoids fragile base classes and deep trees. Inheritance still earns its place for frameworks with template methods and for sharing code among types that truly are the same kind.

Seen in reports: Walmart 2024-10-25.

How to answer

State the default (favour composition), then give one case where inheritance is right. Interviewers want the trade-off, not a slogan.

Likely follow-ups
  • Show a bug caused by inheritance (a subclass overriding add() and addAll() calling each other).
  • How does Strategy relate to composition? (Strategy is composition applied to one behaviour: the object holds a replaceable algorithm instead of inheriting one)
Abstract class vs interface: when do you use each?

An interface is a pure contract: what a type can do. A class can implement many. Since Java 8 it may have default methods but no instance state. An abstract class is a partial implementation: it can hold fields, constructors and protected helpers, and a class can extend only one. Use an interface for a capability many unrelated types share (Comparable, PaymentMethod). Use an abstract class when subclasses share real state and a common skeleton (a Vehicle base with licensePlate and a template method).

Seen in reports: Adobe 2025-06-05, Sunking 2026-03-16, Sprinklr 2026-06-19.

How to answer

Lead with the rule of thumb (capability vs shared base), then the Java facts (multiple implementation, state, constructors).

Likely follow-ups
  • Can an abstract class implement two interfaces? (yes)
  • Why did Java add default methods? (Java 8 needed to add methods such as forEach and stream to existing interfaces without breaking every class that implements them)
  • Can an interface have a constructor? (no)
What is the diamond problem, and how do C++ and Java handle it?

If B and C both inherit from A, and D inherits from both, then D could contain two copies of A, and a call to an A method is ambiguous. C++ allows it and solves the duplicate with virtual inheritance (one shared A subobject); ambiguous calls must be qualified. Java forbids multiple class inheritance. With interfaces, if two default methods clash, the class must override the method and may pick one with B.super.m().

Seen in reports: Adobe 2025-11-15, Sprinklr 2026-06-19, Sunking 2026-03-16.

How to answer

Draw the diamond, then give one sentence per language. Mention that Java avoids state duplication because interfaces have no instance fields.

Likely follow-ups
  • Why does Java allow multiple interface inheritance but not classes? (interfaces carried no state, so there was no question of whose fields or constructor wins; default methods that clash must be overridden explicitly)
  • Cost of virtual inheritance in C++? (extra pointer/offset per subobject)
Compile-time vs run-time polymorphism: how does a virtual call actually work?

Compile-time (static) polymorphism: overloading and templates/generics; the compiler picks the function from argument types. Run-time polymorphism: overriding; the choice depends on the object's real class. In C++ each polymorphic class has a vtable (an array of function pointers) and each object a hidden vptr to it; p->draw() loads the vptr, indexes the table, and calls through the pointer. The JVM does the same with method tables, and the JIT often inlines calls when only one target has been seen.

Seen in reports: Adobe 2025-06-05.

How to answer

Explain the vtable in terms of a struct of function pointers. For a kernel engineer this is the strongest possible answer: it is file_operations.

Likely follow-ups
  • Can a constructor be virtual? (no; the vptr is set during construction)
  • Cost of a virtual call? (a load of the vtable pointer, a load of the slot, an indirect call: a few ns, and it blocks inlining unless the JIT or compiler can devirtualise it)
Overloading vs overriding: give the rules.

Overloading: same name, different parameter lists, in the same class; resolved at compile time; return type alone cannot differ. Overriding: a subclass method with the same signature replaces the parent's; resolved at run time; it cannot reduce visibility, and in Java it may only throw narrower checked exceptions and may return a subtype (covariant return). static, private and final methods cannot be overridden.

How to answer

Two sentences, then one gotcha: a static method with the same signature in a subclass hides, not overrides.

Likely follow-ups
  • What does @Override buy you? (a compile error if you got the signature wrong)
Why must a base class in C++ have a virtual destructor?

If you delete a derived object through a base pointer and the base destructor is not virtual, only the base destructor runs: the derived part's resources leak, and the behaviour is formally undefined. Making the destructor virtual sends delete through the vtable to the most-derived destructor, which then chains up. Rule: any class meant to be used polymorphically gets virtual ~Base() = default;.

Seen in reports: Adobe 2025-11-15.

How to answer

What, why, how, in that order. Show the two-line bug and the one-line fix.

Likely follow-ups
  • When is a non-virtual destructor fine? (classes never deleted through a base pointer, or final classes)
  • Pure virtual destructor: legal? (yes, but it still needs a body)
equals() and hashCode(): what is the contract and what breaks if you ignore it?

If two objects are equals(), they must return the same hashCode(). Break it and a HashMap or HashSet looks in the wrong bucket: you put a key, then get() with an equal key returns null, and sets hold "duplicates". Also: equal objects must stay equal while in a hash structure, so keys should be immutable. Implement both from the same fields (Objects.equals, Objects.hash), or use a Java record.

Seen in reports: Walmart 2025-09-21.

How to answer

State the one-way rule (equal implies same hash, not the reverse), then the HashMap failure.

Likely follow-ups
  • What happens if you mutate a key after inserting it? (its hash changes, so the map looks in the wrong bucket; get returns null and the entry is stranded until the map is rebuilt)
  • Can two unequal objects share a hash code? (yes, a collision)
How does a HashMap work inside (Java 8+)?

An array of buckets. put computes hashCode(), spreads the high bits, and picks bucket (n-1) & hash. Collisions form a linked list; when one bucket reaches 8 entries (and the table has at least 64 buckets) it becomes a red-black tree, so the worst case is O(log n). When size passes capacity x load factor (0.75 by default), the table doubles and entries are redistributed. It is not thread-safe: use ConcurrentHashMap for shared access.

Seen in reports: Walmart 2025-09-21, Cleartrip 2026-07-21.

How to answer

Walk one put: hash, index, collision, resize. Then the thread-safety caveat, which is usually the next question.

Likely follow-ups
  • Why must capacity be a power of two? (so hash & (n - 1) picks a bucket instead of a slower modulo, and a resize splits each bucket into exactly two)
  • How does ConcurrentHashMap avoid one global lock? (a lock-free compare-and-set into an empty bucket, and a lock on only the first node of a busy bucket; reads take no lock)
How do you make a class immutable, and why bother?

Make the class final, all fields private final, set them only in the constructor, no setters, and copy mutable inputs in and out (defensive copies, or List.copyOf). Benefits: safe to share between threads with no locks, safe as a map key, easy to reason about. The cost is new objects for every change, which is why builders and "with" methods exist.

Seen in reports: Walmart 2024-10-25.

How to answer

List the four rules, then give the thread-safety benefit; that is the link interviewers want.

Likely follow-ups
  • Is a final field holding a List immutable? (no, the list can still change)
  • How does String stay immutable? (a final class with a private final array that is never exposed, and every method that would change it returns a new String)
What do the access modifiers mean, and which do you use by default?

Java: private (this class), package-private (no keyword: same package), protected (package + subclasses), public (everyone). C++: private, protected, public, plus friend. Default to private fields and the smallest visibility that works; widen only when a caller truly needs it.

How to answer

Give the table and the default. Bonus: protected fields leak your internals to every subclass forever.

Likely follow-ups
  • Why are public fields a problem even in a small app? (any code can break an invariant and you cannot add a check later without changing every caller)
static vs instance members: what belongs where?

static members belong to the class: one copy shared by all instances (counters, constants, factory methods). Instance members belong to each object. Static methods cannot use this and are not polymorphic. In designs, keep mutable static state rare: it is a global variable, hurts tests and needs locking.

How to answer

Explain with an example, then the warning about mutable statics.

Likely follow-ups
  • Can a static method be overridden? (no, it is hidden)
Shallow copy vs deep copy: and how do copy constructors fit in?

A shallow copy copies field values, so references still point to the same inner objects; changing an inner list changes both copies. A deep copy also copies what the fields point to. In C++, the default copy constructor is shallow (memberwise); if a class owns a raw pointer you need the rule of three/five (copy ctor, copy assignment, destructor, and the move pair). In Java prefer a copy constructor or factory over clone().

How to answer

Draw two boxes pointing at one list. Then name the rule of three for C++ owners of raw memory.

Likely follow-ups
  • What is a move constructor and when does it run? (C++11: it takes an rvalue reference and steals its resources (the pointer) instead of copying; it runs for temporaries, std::move and returns by value)
  • Why is Java's clone() considered broken?
What is RAII, and how does a smart pointer use it?

Resource Acquisition Is Initialisation: tie a resource to an object's lifetime. Acquire in the constructor, release in the destructor, so leaving the scope (normally or by exception) frees it. std::unique_ptr owns one object and deletes it in its destructor; std::shared_ptr keeps a reference count and deletes when it hits zero; std::lock_guard unlocks a mutex the same way.

Seen in reports: Adobe 2026-10-13.

How to answer

Connect it to kernel refcounting: shared_ptr is kref_get/kref_put done by the compiler. Then write a tiny ref-counted pointer if asked.

Likely follow-ups
  • Write a minimal ref-counted smart pointer (copy increments, destructor decrements).
  • Why can shared_ptr cycles leak? (use weak_ptr)
An interface has three methods but a new class only needs two. What do you do?

That is an Interface Segregation smell. Split the interface by client need (for example Readable and Writable), let existing classes implement both, and the new class implement only what it supports. Avoid throwing UnsupportedOperationException from the third method: it breaks callers that trust the interface (an LSP violation). A Java default method is a stopgap, not a fix.

Seen in reports: Walmart 2024-11-28.

How to answer

Name the principle (ISP), give the split, and say why the throw-an-exception shortcut is worse.

Likely follow-ups
  • What if you cannot change the interface (third-party)? (an Adapter)
Design an always-sorted list class. Inherit from ArrayList or wrap it?

Wrap it (composition). If SortedList extends ArrayList, callers can still use add(index, x), set() or Collections.reverse() and break the sorted invariant; you would have to override every mutator. Wrapping a private list exposes only add(x) (binary search for the insert position), get(i), remove(x) and size(), so the invariant cannot be broken from outside.

Seen in reports: Walmart 2024-10-25.

How to answer

Point out the inherited methods that break the invariant: that is the whole argument for composition.

Likely follow-ups
  • Complexity of add? (O(log n) to find, O(n) to shift)
  • When would a TreeMap or skip list be better? (when inserts and deletes interleave with ordered reads: O(log n) per insert instead of O(n) list shifting)
What is cohesion and what is coupling? Which way do you want each?

Cohesion: how closely the parts of one class belong together. High is good: a Ticket class only about tickets. Coupling: how much one class depends on another's details. Low is good: a service that depends on a Repository interface, not on a concrete map. Aim for high cohesion, low coupling.

How to answer

Define both in one line each, then point to one class in your own design as an example.

Likely follow-ups
  • How do you measure coupling in a code review? (count imports of concrete classes, changes that ripple)
Association, aggregation, composition: what is the difference?

All three are has-a. Association: objects know each other, no ownership (a Driver and a Ride). Aggregation: a whole holds parts that can live without it (a Team has Players). Composition: the whole owns the parts and their lifetime (a House and its Rooms; delete the house, the rooms go). In UML: plain line, hollow diamond, filled diamond.

How to answer

Use the lifetime test: if the whole dies, do the parts die? Then draw the three arrows.

Likely follow-ups
  • Is a parking lot's ParkingFloor composition or aggregation? (composition: floors do not exist outside the lot)
What is the Law of Demeter, and what does a violation look like?

"Talk only to your immediate friends": a method should call methods on this, its fields, its parameters, and objects it creates, not on objects returned by them. order.getCustomer().getAddress().getCity() couples you to three classes' structure. Better: order.shippingCity(), so the order decides how to find it.

How to answer

Show the train-wreck chain and the one-method fix. Mention it is a guideline: fluent builders and streams are fine.

Likely follow-ups
  • Is a Java stream chain a violation? (no, every call returns the same kind of object)
Generics: why use them, and what is type erasure?

Generics give compile-time type checks and remove casts: Repository<Booking> cannot hold a User. Java implements them by erasure: the type parameters are checked by the compiler and then removed, so at run time a List<String> is just a List. Consequences: no new T(), no instanceof List<String>. C++ templates instead generate separate code per type.

How to answer

One benefit, one Java fact, one consequence. Bounded types (T extends Entity) are a good example from LLD code.

Likely follow-ups
  • What does ? extends T vs ? super T mean? (producer extends, consumer super)
Checked vs unchecked exceptions: which do you use in an LLD solution?

Checked exceptions (IOException) must be declared or caught; the compiler forces callers to handle them. Unchecked ones (RuntimeException subclasses) do not. For business errors in a design round (seat taken, user not found) most people use unchecked custom exceptions under one base class and catch them at the boundary (driver or controller), which keeps the service signatures clean.

How to answer

Give the definitions, then your rule: checked for recoverable I/O the caller can act on, unchecked for business and programming errors.

Likely follow-ups
  • Where do you catch them? (once, at the boundary)
  • How would they map to HTTP codes? (validation errors to 400, not found to 404, a state conflict or double booking to 409, a missing permission to 403)
What is a marker interface, and what replaced it?

An interface with no methods that tags a class with a property: Serializable, Cloneable, RandomAccess. Code checks instanceof to change behaviour. Annotations (@FunctionalInterface, @Entity) mostly replaced them because they can carry values and need no type relationship. A marker interface is still useful when you want the compiler to check the type in a method signature.

How to answer

Two examples, then the annotation trade-off.

Likely follow-ups
  • Why is Cloneable considered a design mistake? (the marker changes Object.clone's behaviour; clone is not on the interface)
Write the solution to a DSA problem in OOP style. What changes?

Interviewers sometimes ask for a normal algorithm (spiral matrix, a ranking) but "LLD-style". That means: a class for the data (Matrix), an interface for the part that varies (TraversalStrategy with SpiralTraversal, ZigZagTraversal), clean method names, input validation, and a small driver. The algorithm is the same; what is graded is that a new traversal is a new class, not an edit.

Seen in reports: Microsoft 2026-01-25, Uber 2024-06-19.

How to answer

Ask what is likely to vary, put exactly that behind an interface, and keep the rest simple.

Likely follow-ups
  • Add a diagonal traversal now: which files change? (one new traversal class behind the same interface and one line to select it; the grid class does not change)
Explain OOP to a five-year-old. (see the next card: toys built from one design, each with its own colour)

"Think of toys. Every toy car has the same parts: wheels, a colour, a horn button. The instructions for making a toy car are the class. Each car you actually hold is an object. You press the horn button without knowing the wires inside: that is hiding the inside. A fire truck is a special toy car that also has a ladder: that is inheritance. When you press the horn on any car, each one makes its own sound: that is polymorphism."

Seen in reports: Mastercard 2025-10-25.

How to answer

Keep it to one analogy that covers all four pillars. Interviewers use this to check clarity, not knowledge.

Likely follow-ups
  • Now explain it to a new graduate in two sentences. (a class bundles data with the only functions allowed to change it, and callers work through an interface; that lets one part change without breaking the others)
