Q&A: creational patterns

Singleton in all its variants (the most reported single pattern question), the three factories, Builder, Prototype, Object Pool and plain dependency injection.

Write a thread-safe singleton. Give three ways and say which you prefer.
  1. Holder idiom: a private static nested class holds the instance; the JVM initialises it once, lazily, under its class-init lock. No locking on the hot path. Default choice.
  2. Enum: enum Config { INSTANCE; }. One instance guaranteed, and safe against reflection and serialization.
  3. Double-checked locking with a volatile field: needed when creation takes arguments.
final class Config {
    private Config() { }
    private static final class Holder { static final Config INSTANCE = new Config(); }
    static Config get() { return Holder.INSTANCE; }
}

Seen in reports: Goldman Sachs 2025-05-08, Walmart 2025-07-26, Nykaa 2026-04-04, Tripjack 2026-08-18, WEX 2026-08-30.

How to answer

Write the holder version, name the other two, then add: in a service I would rather create one instance in main and inject it, because global state makes tests share data.

Likely follow-ups
  • Why is synchronized getInstance() slow?
  • Eager vs lazy: when is eager fine? (when the object is cheap to build and always used; the JVM creates it at class load with no locking at all)
Why does double-checked locking need volatile?

instance = new Config() is three steps: allocate, run the constructor, publish the reference. Without volatile, the compiler or CPU may publish the reference before the constructor's writes are visible to other threads. A second thread doing the unlocked first check sees a non-null, half-built object. volatile adds a happens-before edge: the constructor's writes are visible before the reference is.

Seen in reports: Walmart 2024-12-14, Walmart 2025-09-21.

How to answer

Name the reordering, then the happens-before fix. Mention it was genuinely broken before the Java 5 memory model.

Likely follow-ups
  • What other uses does volatile have? (stop flags; not for count++)
  • In C++? (std::atomic with acquire/release, or a function-local static)
How can a singleton be broken, and how do you defend it?
  • Reflection: setAccessible(true) on the private constructor. Defend: throw if an instance exists, or use an enum.
  • Serialization: deserialising creates a new object. Defend: readResolve() returning the instance, or an enum.
  • Cloning: do not implement Cloneable, or throw from clone().
  • Multiple class loaders: one instance per loader; usually accepted.

Seen in reports: Walmart 2024-10-25, ServiceNow 2025-04-08, Visa 2026-04-03.

How to answer

List four attacks with one defence each, then say the enum handles the first two for free.

Likely follow-ups
  • Is a Spring singleton bean the same thing? (one per container, not per JVM, and not enforced by the class)
Write a singleton in C++. 
class Config {
public:
    static Config& instance() {
        static Config inst;   // C++11: initialised once, thread-safe
        return inst;
    }
    Config(const Config&) = delete;
    Config& operator=(const Config&) = delete;
private:
    Config() = default;
};

Since C++11 a function-local static is initialised exactly once even with concurrent callers (often called the Meyers singleton). Delete copy and assignment so no second instance can be made.

Seen in reports: Adobe 2026-10-13.

How to answer

Write it, point at the deleted copy operations, and name the C++11 guarantee.

Likely follow-ups
  • Destruction order problems at exit? (statics in different files are destroyed in reverse order of construction, so one may use another that is already gone; leak the instance on purpose or keep the dependency order explicit)
  • Now write a ref-counted smart pointer. (a pointer plus a heap count; copy increments it, the destructor decrements and deletes at zero; use an atomic count when threads share it, like kref)
Simple Factory vs Factory Method vs Abstract Factory.

Simple Factory: one function or class with a switch that returns the right subtype (VehicleFactory.create("CAR")); not a GoF pattern. Factory Method: a base class declares createX() and subclasses decide which class to make (each Dialog subclass creates its own Button). Abstract Factory: an interface that creates a family of related objects that must match (WindowsUIFactory makes Windows buttons and Windows checkboxes).

Seen in reports: Arcesium 2025-09-11, Oracle 2026-04-27, Walmart 2024-11-28.

How to answer

One line each with an example. The key word for Abstract Factory is 'family'.

Likely follow-ups
  • Which one did you use in your design and why? (usually a Simple Factory (a map from type to constructor), because no subclass hierarchy chooses products)
  • Factory vs Strategy? (a Factory decides which object to create; a Strategy is the behaviour you call once you hold it; a factory often creates the strategy)
Factory vs Strategy: they both hide classes behind an interface. What is the difference?

A Factory answers "which object do I create?" and is done once the object exists. A Strategy answers "which algorithm do I run?" and is called again and again during the object's life. They often work together: a factory reads config and returns the right PricingStrategy, which the service then calls on every request.

Seen in reports: Walmart 2024-11-28.

How to answer

Creation vs behaviour. Then show them working together.

Likely follow-ups
  • Can a strategy be chosen at run time per request? (yes, that is the point)
When do you use a Builder? Write one by hand.

When an object has many optional parameters or must be valid once built (no half-set objects), and you want it immutable. Telescoping constructors are unreadable; setters leave the object mutable and possibly invalid.

final class Pizza {
    private final String size; private final List<String> toppings;
    private Pizza(Builder b) { size = b.size; toppings = List.copyOf(b.toppings); }
    static final class Builder {
        private String size = "M"; private final List<String> toppings = new ArrayList<>();
        Builder size(String s) { size = s; return this; }
        Builder topping(String t) { toppings.add(t); return this; }
        Pizza build() { if (toppings.size() > 5) throw new IllegalStateException("max 5"); return new Pizza(this); }
    }
}

Seen in reports: Walmart 2025-05-25, Zomato 2025-09-19.

How to answer

Show validation in build(); that is the part people forget and the part that shows why a builder beats setters.

Likely follow-ups
  • Builder vs Lombok @Builder? (same idea, generated)
  • Builder or Decorator for pizza toppings? (Decorator when each topping adds price or behaviour at run time and they stack; Builder when you only collect options to build one immutable pizza)
Configurable pizza (size, crust, toppings, price): Builder or Decorator?

If toppings only add data and price is a sum from a menu, a Builder plus a price calculator is simpler. If each topping changes behaviour (price rules, prep steps, combos) and you want to stack them at run time, Decorator fits: new Cheese(new Olives(new ThinCrust())), each adding to cost(). Many interviewers accept either if you state the trade-off: decorators make many tiny classes and are harder to inspect ("does it have cheese?").

Seen in reports: Zomato 2025-09-19.

How to answer

Name both, pick one based on whether toppings carry behaviour, and state the cost of the other.

Likely follow-ups
  • How do you price 'double cheese'? (decorate twice, or a quantity in the builder)
What is the Prototype pattern, and when is it useful?

Create new objects by copying an existing configured instance (copy()), instead of building from scratch. Useful when construction is expensive (parsed templates, preloaded game units) or when the exact class is not known to the caller. Watch shallow vs deep copy of inner objects.

How to answer

Give one concrete example and the copy-depth warning.

Likely follow-ups
  • How does Prototype relate to copy constructors? (same idea, chosen by the object itself)
Object Pool: when is it worth it, and how do you make it thread-safe?

When objects are expensive to create and are reused often: database connections, threads, large buffers. A pool keeps idle objects in a BlockingQueue; acquire() takes one (waiting with a timeout if empty and the max is reached), release() validates and returns it. Track the total created with an atomic counter so you never exceed the max. Not worth it for cheap objects: the JVM allocates small objects very fast.

Seen in reports: Walmart 2024-12-14.

How to answer

Describe acquire/release with a BlockingQueue and a max size; mention validation of returned objects (a broken connection).

Likely follow-ups
  • What if a caller never releases? (leases with timeouts, try-with-resources wrapper)
Is Singleton an anti-pattern?

Often, when used as a global variable: it hides dependencies, makes tests share state, and needs care with concurrency. The need behind it (exactly one of something) is fine: create it once in main and inject it. Legitimate cases: a process-wide resource that truly must be unique (a logger backend, a hardware handle), where you still pass it in as an interface.

Seen in reports: Walmart 2025-05-25.

How to answer

Separate 'one instance' (fine) from 'global access' (the problem).

Likely follow-ups
  • You say you avoid singletons, but you use Spring. Explain. (container-managed single instance, injected; not a static global)
A file exporter must support CSV, JSON and XML, with more formats later. Design it.

interface Exporter { void export(List<Record> rows, OutputStream out); } with CsvExporter, JsonExporter, XmlExporter. A small factory (or registry map) returns the exporter for a format name. A new format is a new class plus one registry line. If formats share steps (open, header, rows, footer), a Template Method base can hold the skeleton.

Seen in reports: Oracle 2026-04-27, Microsoft 2024-10-27.

How to answer

Interface first, factory second, template method only if the steps really repeat.

Likely follow-ups
  • Convert between any two formats? (read into one internal model, then export: 2N classes instead of N x N)
How do you generate unique ids in an LLD solution?

In one process: an AtomicLong counter with a readable prefix ("B" + next()), or UUID.randomUUID() when readability does not matter. A plain int++ shared by threads is a race. Across processes: database sequences, or a Snowflake-style id (timestamp + machine id + sequence). Put id generation in one place (an IdGenerator) so it can be swapped.

How to answer

Give the in-process answer, then the distributed one in one sentence.

Likely follow-ups
  • Why are UUIDs bad as database primary keys sometimes? (random inserts fragment B-tree indexes)
Dependency injection without a framework: show it.

Constructor injection plus a composition root:

public static void main(String[] args) {
    Repository<Booking> repo = new InMemoryRepository<>();
    PricingStrategy pricing = new PeakHourPricing();
    BookingService service = new BookingService(repo, pricing);   // dependencies passed in
    new Cli(service).run();
}

No class below main uses new for a collaborator. Tests build the service with fakes in one line.

How to answer

Show the wiring and say where a container would take over (annotations instead of this method).

Likely follow-ups
  • What is a service locator and why is it worse? (dependencies hidden inside methods)
