Why is "add synchronized to put()" not enough for a thread-safe LRU cache?

  1. synchronized does not work on generic classes
  2. get() also changes the recency order, so it is a write too
  3. LinkedHashMap is already thread-safe
  4. put() is never called concurrently
In an LRU every get moves the key to the front of the list, so it mutates shared state and needs the same lock.

Which change breaks the Liskov Substitution Principle?

  1. A subclass that adds a new method
  2. A subclass that accepts more input values than its parent
  3. A subclass whose overridden method throws UnsupportedOperationException
  4. A subclass with a private helper method
Callers that trust the parent's contract now crash. Accepting more input (weaker preconditions) is allowed.

A wrapper returns cached results and sometimes never calls the real object. Which pattern is it?

  1. Proxy
  2. Decorator
  3. Adapter
  4. Facade
It controls access to the real object and may skip it: Proxy. A decorator always delegates and adds behaviour.

What does volatile NOT give you in Java?

  1. Visibility of writes to other threads
  2. Ordering: earlier writes are not moved after the volatile write
  3. Safe publication of a fully built object
  4. Atomic count++
count++ is read-modify-write; two threads can still lose an update. Use AtomicInteger or a lock.

Splitwise has 3 people with net balances +500, -300 and -200. How many payments does the greedy settle-up make?

  1. 1
  2. 2
  3. 3
  4. 6
B pays A 300 and C pays A 200. Greedy needs at most N-1 payments.

Two rental bookings are [10, 20) and [20, 30). Do they overlap under the rule start1 < end2 and start2 < end1?

  1. Yes, they share hour 20
  2. Only if both are for the same car
  3. No: 20 < 20 is false
  4. It depends on the time zone
Half-open intervals touching at an end do not overlap, so back-to-back bookings are allowed.

In Strategy vs State, what is the best one-line test?

  1. Who changes the behaviour object: the client (Strategy) or the states themselves (State)
  2. Strategy uses inheritance, State uses composition
  3. State has one implementation, Strategy has many
  4. Strategy is creational, State is structural
Both use composition and look identical on a class diagram; the difference is who decides the switch.
