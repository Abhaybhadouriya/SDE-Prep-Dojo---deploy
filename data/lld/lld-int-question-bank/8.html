Q&A: structural patterns

Decorator, Proxy, Adapter, Facade, Composite, Bridge, Flyweight and Repository, with the look-alike comparisons interviewers love.

Explain the Decorator pattern with an example.

A decorator wraps an object that has the same interface, adds behaviour before or after delegating, and can be stacked at run time. Example: DataSource with FileDataSource, wrapped by CompressionDecorator and then EncryptionDecorator; write() compresses, then encrypts, then writes. Java's BufferedInputStream(new FileInputStream(f)) is the textbook case. It adds features without subclass explosion (no EncryptedCompressedFileDataSource).

Seen in reports: Visa 2026-04-03, Amazon 2025-07-03, Zepto 2024-09-18.

How to answer

Give the stacking example and name the problem it solves (combinations of features).

Likely follow-ups
  • Does order of decorators matter? (yes: compress then encrypt is not the same as the reverse)
  • Decorator vs inheritance? (inheritance fixes a combination at compile time and needs a class per combination; decorators stack at run time)
Decorator vs Proxy: same shape, so what is the difference?

Both wrap an object with the same interface. A Decorator adds behaviour and is usually stacked by the client (compression, logging, extra toppings). A Proxy controls access to the real object: lazy creation, caching, permission checks, remote calls. It often manages the real object's lifetime and may not call it at all (a cache hit, a denied request).

How to answer

Intent decides it: adds features vs controls access. Say who creates the wrapper (client vs framework).

Likely follow-ups
  • Is a caching wrapper a proxy or decorator? (proxy: it may skip the real call)
Adapter: when do you use it?

When you must use a class whose interface does not match what your code expects, and you cannot change either side. The adapter implements your interface and translates calls to the other one. Example: your PaymentGateway interface with pay(amount); a vendor SDK has makeTransaction(paise, currency); VendorAdapter converts and calls it. Also used to wrap legacy code and in tests.

How to answer

Name the two mismatched interfaces explicitly, then the translation.

Likely follow-ups
  • Adapter vs Facade? (adapter converts one interface; facade simplifies a subsystem)
Facade: what does it do and when does it become a problem?

A facade gives one simple entry point over a complex subsystem: OrderFacade.placeOrder() calls inventory, payment, shipping and notification services in the right order. It helps clients and hides order of calls. It becomes a problem if it grows business logic of its own and turns into a god class; keep it a thin coordinator.

Seen in reports: Razorpay 2024-03-05.

How to answer

Example plus the warning; interviewers like to hear you know the failure mode.

Likely follow-ups
  • Should clients be allowed to bypass the facade? (yes, for advanced use)
Composite: explain with a file system or an expression tree.

Composite treats single objects and groups the same way through one interface. A file system: FsNode with size(); File returns its bytes, Directory holds children and returns the sum. The client calls root.size() without caring what is inside. Expression trees work the same: a Number leaf and an Add node with two children both have eval().

Seen in reports: Oracle 2024-12-07.

How to answer

Draw the tree, then show the recursive method. Mention the Uber in-memory file system problem as a real use.

Likely follow-ups
  • Where do add/remove child methods go: on the interface or only on Directory? (trade-off: uniformity vs safety)
Bridge pattern: what problem does it solve?

It splits two independent dimensions so they can vary separately: an abstraction (shapes, remote controls, notifications) and an implementation (renderers, devices, channels). Without it, N x M subclasses (UrgentSmsNotification, UrgentEmailNotification...). With it, Notification holds a Channel: N + M classes.

How to answer

Show the class explosion first, then the split. Kernel analogy: a block device driver (implementation) under many filesystems (abstraction).

Likely follow-ups
  • Bridge vs Strategy? (same shape; Bridge is a structural split designed up front, Strategy swaps an algorithm)
Flyweight: give a real use.

Share the heavy, unchanging part of many small objects, and pass the changing part in. A text editor stores one Glyph per character and font (intrinsic) and keeps the position per occurrence (extrinsic). A game shares one TreeType (mesh, texture) among a million trees that each store only x, y. Java's Integer.valueOf cache for small numbers is a flyweight.

How to answer

Split intrinsic vs extrinsic state out loud; that is the whole pattern.

Likely follow-ups
  • Why must flyweights be immutable? (they are shared)
Proxy types: list them with examples.
  • Virtual proxy: creates the expensive object only when first used (a large image).
  • Protection proxy: checks permissions before delegating.
  • Remote proxy: looks local, calls over the network (gRPC stubs).
  • Caching proxy: returns stored results for repeated calls.
  • Logging/metrics proxy: records calls; Java dynamic proxies and Spring AOP build these at run time.

Seen in reports: Media.net 2026-08-02.

How to answer

List four with one line each, then say Spring's @Transactional works through a proxy.

Likely follow-ups
  • Why does calling a @Transactional method from the same class skip the transaction? (the call does not go through the proxy)
Design a pluggable logger: levels, multiple sinks, formats.

Logger with log(level, msg); a list of Appenders (ConsoleAppender, FileAppender), each with a Formatter (Strategy) and a minimum level. Level filtering can be a Chain of Responsibility, or simpler, a threshold check per appender. A LoggerFactory returns named loggers. For thread safety, appenders synchronise writes or hand records to a queue drained by one thread (async logging).

Seen in reports: Razorpay 2024-03-05, PhonePe 2026-03-27, Swiggy 2026-03-29.

How to answer

Name the pieces, then pick the simplest pattern that fits each; Razorpay's interviewer expected one specific shape, so ask what they care about.

Likely follow-ups
  • How do you avoid blocking callers on slow disks? (async appender with a bounded queue)
  • Log rotation? (a rolling appender that checks size or date before each write, closes the file, renames it and opens a new one, under the appender's lock)
Several clients speak XML, JSON or CSV and must convert between each other. Which pattern?

Do not write N x (N-1) converters. Define one internal model and, per format, a reader (to the model) and a writer (from the model): 2N pieces. Readers and writers are Adapters (or Strategies chosen by a factory). Adding a format means one reader and one writer.

Seen in reports: Microsoft 2024-10-27.

How to answer

Do the arithmetic out loud (6 formats: 30 converters vs 12 pieces). That is what the question tests.

Likely follow-ups
  • What about data that one format cannot express? (define the model as the union and document losses)
What is the Repository pattern, and how is it different from a DAO?

A repository looks like an in-memory collection of domain objects (findById, save, findByUser) and hides storage completely. A DAO is closer to the table: one object per table with CRUD that mirrors SQL. In LLD rounds, the repository is the seam that lets you say "in-memory today, a database tomorrow".

How to answer

Explain the seam benefit, then the subtle difference (domain-shaped vs table-shaped).

Likely follow-ups
  • Where do transactions go? (in the service, around several repository calls)
How would you add caching to a slow service without changing its code?

A caching proxy (or decorator) that implements the same interface: check a map (an LRU with TTL), call the real service on a miss, store the result. Wire it in at the composition root. Discuss invalidation: write-through (update cache on writes), TTL, or events. Thread safety: ConcurrentHashMap.computeIfAbsent to avoid two threads loading the same key.

How to answer

Proxy plus LRU plus invalidation plus one concurrency detail: four short beats.

Likely follow-ups
  • What is a cache stampede and how do you prevent it? (single-flight loading per key)
Name structural patterns you have seen in the JDK or the Linux kernel.

JDK: BufferedReader (Decorator), Arrays.asList (Adapter), Collections.unmodifiableList (Proxy), dynamic proxies (Proxy), javax.swing component trees (Composite). Kernel: struct file_operations and block drivers under filesystems (Bridge), the VFS over many filesystems (Facade plus Bridge), device trees (Composite), stacked network devices like VLAN over bonding over a NIC (Decorator).

How to answer

Two from each world shows breadth; pick ones you can explain if asked.

Likely follow-ups
  • Explain the VLAN device as a decorator in detail. (the VLAN net_device wraps a real device: on transmit it inserts the 802.1Q tag and hands the skb to the lower device's xmit, so callers see one more device with the same interface)
Adapter vs Facade vs Proxy vs Decorator: one sentence each.

Adapter: converts an interface into the one the client expects. Facade: one simple interface over many classes. Proxy: same interface, controls access to one real object. Decorator: same interface, adds behaviour, stackable.

How to answer

Memorise these four lines; they settle most 'look-alike' questions.

Likely follow-ups
  • Which ones keep the interface the same? (proxy and decorator)
