Structure: a facade and a subsystem that does not know it

  • Facade (OrderFacade): knows which subsystem classes handle a request, calls them in the right order, applies defaults and handles cleanup on failure. Holds references to the subsystem objects (ideally injected).
  • Subsystem classes (Inventory, PaymentService, Shipping, Notifier): do the real work. They have no reference to the facade.
  • Clients: use the facade for the common paths. Nothing stops a client from using a subsystem class directly when it needs a feature the facade does not expose.
  • Optional: an additional facade per audience (an admin facade, a reporting facade) so one facade does not grow without limit.
