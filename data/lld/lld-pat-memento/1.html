The problem: undo that breaks encapsulation

You need undo for a text editor. The quick version lets the history class reach into the editor:

class Editor {
    public StringBuilder text;    // made public so History can copy it
    public int cursor;            // same
    public Style style;           // and this, and every field added later
}

class History {
    Deque<Object[]> stack = new ArrayDeque<>();
    void save(Editor e)    { stack.push(new Object[]{ e.text.toString(), e.cursor, e.style }); }
    void undo(Editor e)    { Object[] s = stack.pop();
                             e.text = new StringBuilder((String) s[0]);
                             e.cursor = (int) s[1];
                             e.style = (Style) s[2]; }   // shared, mutable: not really a copy
}
  • Encapsulation is gone. The editor's fields became public just so history could copy them. Anyone can now set cursor = -7.
  • History knows the editor's insides. Add a selection field and you must remember to update History too. Forget it and undo silently restores half the state.
  • Shallow copies. style is stored by reference. Change the style later and the "saved" state changes with it.
  • No room to optimise. Since history owns the copy logic, the editor cannot switch to cheaper snapshots (deltas, shared immutable chunks) without breaking it.
