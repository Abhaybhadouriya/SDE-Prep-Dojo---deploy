When to use it, when not to

Use it when
  • You need undo, redo, save slots, "restore defaults" or rollback of a batch.
  • Writing an inverse for each operation is hard or error-prone, but copying the state is easy.
  • The state is private and should stay private: other classes should store it without understanding it.
  • You want a checkpoint before a risky multi-step change (all-or-nothing).
Avoid or adapt when
  • The state is large and changes are small: store deltas or use Command undo.
  • Snapshots are taken very often (every keystroke in a huge document): the copy cost shows up in latency.
  • The state includes live resources (connections, threads, file handles) that a copy cannot bring back.
  • The language cannot hide the memento and the team will not respect the convention: you may end up with the leaky design you were avoiding.
