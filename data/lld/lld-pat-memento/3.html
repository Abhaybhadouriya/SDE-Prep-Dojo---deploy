Structure: three participants

  • Originator (Editor): owns the real state. save() makes a memento, restore(m) puts the state back. Because it writes its own snapshot code, a new field is added in one place.
  • Memento (Editor.Snapshot): an immutable value object holding a copy of the state. It should be unreadable to outsiders.
  • Caretaker (History, save slots, a transaction manager): decides when to save and restore and how many mementos to keep. It never inspects or changes them.

How to keep the memento opaque in each language: Java uses a static nested class with private fields and a private constructor, nested inside a top-level originator. Java's rule is that private members are visible only inside the top-level class that encloses them, so if the originator and the caretaker were both nested in one big class, the caretaker could read the snapshot too. Our Editor is its own top-level class for that reason. C++ makes the members private and declares the originator a friend. Python cannot enforce privacy, so it relies on convention (_state) or on handing out an opaque id that maps to a stored blob.
