Evaluator rubric checklist

Tags: must = missing it usually fails the round; strong = separates a pass from a strong pass; bonus = extra credit if time allows.

  • must O(1) get and put, with the linked list written by hand, and complexity stated.
  • must Policy behind an interface; a new policy needs no change to Cache.
  • strong One source of truth: values in one map, order in the policy, always in sync (onPut, onAccess, onRemove, evict).
  • strong Edge cases: capacity 1, overwrite when full, ties, TTL boundary, dirty eviction.
  • strong Thread safety implemented and explained, including why a read lock is not enough.
  • bonus No I/O under the lock, or an explicit note on why it is acceptable.
  • strong Testability: injected clock and fake store; a driver with assertions.
  • bonus Can extend: TTL-after-access, background expiry, multi-level, write-around.

Red flag that fails the round: Eviction is O(n): scanning a list or a sorted map to find the least recently used key, or using LinkedHashMap(accessOrder=true) and then not being able to write the linked list by hand when asked.
