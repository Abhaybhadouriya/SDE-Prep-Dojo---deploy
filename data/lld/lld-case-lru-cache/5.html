Key relationships and patterns (and why each)

PatternWhereWhy
StrategyEvictionPolicyThe exact feedback Groww gave. LRU, LFU, FIFO, MRU, random: each a small class behind four methods. The cache never asks which one it has.
Proxy (caching proxy)Cache in front of a DataStore with the same interfaceCallers use the same load/save calls whether they hit the cache or the database.
Chain of ResponsibilityL1 to L2 to storeEach level tries to answer and passes the miss down. Adding an L3 is one constructor call.
Dependency injectionClock, DataStore, policyTests move a manual clock instead of sleeping, and count loads on a fake database.
Observer (follow-up)EvictionListenerMetrics, logging or cleanup when an entry leaves; Caffeine and Guava offer removal listeners for this reason.

A frequent mistake: the policy stores values too, or the cache keeps its own order list as well as the policy. Then there are two sources of truth for "what is in the cache". Keep values in exactly one map in Cache; keep order only in the policy.
