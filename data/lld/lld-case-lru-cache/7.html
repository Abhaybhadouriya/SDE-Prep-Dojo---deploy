APIs and interfaces

interface EvictionPolicy<K> {
    void onPut(K key);      // new key entered
    void onAccess(K key);   // read or overwrite
    void onRemove(K key);   // left for another reason (remove, expiry)
    K evict();              // pick a victim, forget it, return it
}
interface DataStore<K, V> { V load(K key); void save(K key, V value); void delete(K key); }
interface Clock { long nowMillis(); }

final class Cache<K, V> implements DataStore<K, V> {
    Cache(int capacity, EvictionPolicy<K> policy, DataStore<K, V> storeOrNull,
          WritePolicy writePolicy, long ttlMillis, Clock clock);
    V get(K key);  void put(K key, V value);  boolean remove(K key);
    void flush();  int purgeExpired();  int size();  String stats();
}

Why four policy hooks and not just evict()? Because LRU must hear about every access and LFU must hear about every removal, or their bookkeeping drifts from the real contents. The interface is the contract that keeps the two in sync.
