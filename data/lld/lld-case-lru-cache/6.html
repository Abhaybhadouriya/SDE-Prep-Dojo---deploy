Core flows

LRU, step by step

The hash map gives O(1) lookup of the node; the doubly linked list gives O(1) "move to front" and "remove from tail". Sentinel head and tail nodes remove every null check, the same trick as a kernel list_head that points to itself when empty.

  1. Three puts fill the cache. Order from front: c, b, a.
  2. A get moves the node to the front. Now b is the least recently used.
  3. A put on a full cache first asks the policy for a victim (the node before TAIL), then removes that key from the value map.
  4. The new key goes in at the front. Exactly the sequence the Java demo prints for LRU.

LFU in one picture

get with read-through

  1. Lock, look up If the entry exists but now >= expiresAt, drop it (lazy expiry; flush first if dirty).
  2. Hit policy.onAccess(key), count a hit, return.
  3. Miss Count a miss, release the lock, call store.load(key). Database calls under the cache lock would stall every other thread.
  4. Re-lock and re-check Another thread may have loaded the same key meanwhile; if so, keep theirs. Otherwise insert (evicting if full) and return.

put with a write policy

  1. Existing key Update value and expiry; onAccess.
  2. New key If full, victim = policy.evict(); remove it; if it was dirty, save it to the store first. Insert and onPut.
  3. Write-through store.save() before returning: the store is always up to date; writes are as slow as the store.
  4. Write-back Mark the entry dirty; the store is written on eviction, expiry or flush(). Fast writes; data is lost if the process dies before a flush.
