Key relationships and patterns (and why each)

Pattern / ideaWhereWhy it earns its place
ObserverSubscriber.onMessageThe broker knows one callback interface, never concrete consumers. New consumers subscribe without touching broker code.
StrategyPartitioner, RetryPolicyThe two rules interviewers most often ask to change: "partition by region", "retry 5 times with jitter". Swapping them is a constructor argument.
FacadeBrokerCallers see four methods; topics, partitions and workers stay hidden and can change.
Append-only log + offsetsPartition, nextOffsetReading never mutates shared data, so many groups read one log without coordinating. Replay is just moving a number.
Producer-consumer with a condition variablePartition.read waits on grewWorkers sleep when caught up and wake on append, instead of spinning.
One worker per partition (thread confinement)ConsumerGroup.startThe only way to keep order while still running in parallel: order inside a partition, parallelism across partitions.
Immutable value objectMessage recordShared across threads and groups with no copying and no locks.
Composition over inheritanceGroup has a RetryPolicyNo RetryingConsumerGroup extends ConsumerGroup explosion. See composition.

Do not make Broker a Singleton. Tests need fresh brokers, and two brokers in one process is a legitimate use. Let the caller create one and pass it around (dependency injection).
