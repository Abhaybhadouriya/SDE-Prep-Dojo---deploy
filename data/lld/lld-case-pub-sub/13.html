Evaluator rubric checklist

  • Asked about ordering, fan-out vs sharing, deletion and failure handling before coding.
  • Producer path does not call consumer code and does not hold a lock any reader holds during processing.
  • Per-key ordering is guaranteed by construction (partition + single worker), not by luck.
  • Each group has independent offsets; a new group can start from 0.
  • Failure path exists: bounded retries, backoff, DLQ, and the group continues.
  • Thread safety explained per shared object; condition variable used with a loop; no busy waiting.
  • Strategy interfaces for partitioning and retry; Observer for subscribers; no god class.
  • Code runs, demo shows the requirements, assertions catch regressions.
  • Clean shutdown (no hanging threads), input validation with clear exceptions.
  • Can explain at-least-once vs at-most-once and why consumers must be idempotent.
