Two older prompts still circulate and set the expectations: an Uber machine-coding round where publishers and subscribers must never block one another and all subscribers run in parallel (post), and PhonePe's pub-sub machine-coding problem tagged in the kumaransg/LLD collection.

Read the Razorpay wording closely: "guaranteed delivery of every published message for all the subscribed consumers ... in the same order", "maintain the state of consumption of each message ... for each consumer", "handle cases of consumers not being available". That is exactly log + per-group offsets + retries + DLQ. A design that pushes each message once into a per-subscriber queue and forgets it fails three of those lines.
