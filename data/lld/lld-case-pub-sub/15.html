Common mistakes

  • Deleting messages on consume. Breaks fan-out, replay and "per-consumer state". Use a log plus offsets.
  • Calling subscribers synchronously in publish. The producer inherits every consumer's latency and exceptions.
  • Global ordering by a single lock or a single thread. Correct, but no parallelism; ask what order is really needed.
  • Thread per message or a shared pool for one partition. Messages of one key finish out of order.
  • No failure path. One bad message stops a partition forever, or is silently dropped.
  • Waiting with if instead of while around await, or spinning with sleep loops instead of a condition variable.
  • Holding the partition lock during the callback. Producers stall behind consumer code.
  • Making everything a Singleton and then being unable to write a test with a fresh broker.
  • Over-building: replication, ZooKeeper, HTTP servers in a 90-minute LLD. Mention them as HLD follow-ups, do not code them.
