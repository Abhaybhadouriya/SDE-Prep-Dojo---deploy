Rejection policies: deciding what "full" means

PolicyWhat it doesGood forRisk
AbortPolicy (default)Throws RejectedExecutionExceptionCallers that can return 429 / retry laterCallers that forget to catch it
CallerRunsPolicyThe submitting thread runs the task itselfNatural backpressure: the producer slows downA request thread or event loop becomes slow
DiscardPolicySilently drops the taskMetrics samples, best-effort logsSilent data loss
DiscardOldestPolicyDrops the head of the queue, retries the new one"Latest value wins" (price ticks, GPS)Old but important work is lost

From your world

CallerRunsPolicy is TCP flow control for threads. When the receiver's window is full, the sender stops. When the pool is full, the producer has to do the work itself, so it cannot submit anything more until it finishes. DiscardOldest is a NIC ring that overwrites the oldest descriptor when the host falls behind.

In an interview, choose one and say why: "Payments use Abort, so the API returns 503 and the client retries. The audit logger uses CallerRuns: slow the request rather than lose an audit line."
