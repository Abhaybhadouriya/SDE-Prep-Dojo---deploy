Futures: getting a result back

execute(Runnable) is fire-and-forget. submit(Callable) returns a Future<T>, a handle to a result that does not exist yet:

  • get() blocks until the result is ready. get(timeout, unit) blocks at most that long, then throws TimeoutException.
  • If the task threw, get() throws ExecutionException and the original exception is in getCause().
  • cancel(true) removes it from the queue, or interrupts it if it is running. isDone() polls without blocking.

Swallowed exceptions. With submit(), an exception is stored in the Future. If nobody calls get(), nothing is ever printed, and the bug is invisible. With execute(), the exception reaches the thread's uncaught-exception handler, and the worker thread dies and is replaced. Always consume the Future, or log in a wrapper or afterExecute().

Inside, submit() wraps the Callable in a FutureTask, which is itself a Runnable, and calls execute().

CompletableFuture: compose instead of block

A plain Future forces you to block in get(). CompletableFuture (Java 8+) lets you say "when this finishes, do that", like a callback chain, without blocking a thread:

ExecutorService io = Executors.newFixedThreadPool(4);
CompletableFuture<String>  user = CompletableFuture.supplyAsync(() -> userApi.name(id), io);
CompletableFuture<Integer> bal  = CompletableFuture.supplyAsync(() -> walletApi.balance(id), io);

String page = user.thenCombine(bal, (u, b) -> u + " has Rs " + b)   // wait for both
                  .thenApply(String::toUpperCase)                   // transform
                  .orTimeout(500, TimeUnit.MILLISECONDS)            // Java 9+
                  .exceptionally(ex -> "profile unavailable")       // fallback
                  .join();
MethodLikeUse

If you do not pass an executor, supplyAsync runs on ForkJoinPool.commonPool(), which is shared by the whole JVM and sized for CPU work (cores minus one). Blocking I/O there can stall every parallel stream and every other library in the process. Always pass your own executor for blocking calls.
