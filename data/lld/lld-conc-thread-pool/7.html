Lifecycle and shutdown

A ThreadPoolExecutor moves through five run states, stored together with the worker count in one AtomicInteger called ctl (top 3 bits for the state, low 29 bits for the count), so both can be read and changed with one CAS.

The standard shutdown sequence, which you should be able to write without looking:

pool.shutdown();                                     // 1. stop accepting
try {
    if (!pool.awaitTermination(30, TimeUnit.SECONDS)) {   // 2. let queued work finish
        List<Runnable> never = pool.shutdownNow();     // 3. interrupt the rest
        log.warn("dropped {} tasks", never.size());
        pool.awaitTermination(10, TimeUnit.SECONDS);
    }
} catch (InterruptedException e) {
    pool.shutdownNow();
    Thread.currentThread().interrupt();             // keep the interrupt for our caller
}

shutdownNow() can only ask tasks to stop by interrupting them. A task that loops without checking Thread.interrupted() or calling a blocking method keeps running. Since Java 19, ExecutorService.close() does shutdown plus a wait, so try-with-resources works.
