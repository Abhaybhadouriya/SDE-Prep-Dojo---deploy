Quiz

core=2, max=6, unbounded LinkedBlockingQueue. 100 slow tasks arrive at once. How many threads run?

  1. 6
  2. 2
  3. 100
  4. 4
The queue never fills, so the pool never grows above core. Max is ignored.

Which rejection policy slows down the producer instead of losing work?

  1. DiscardPolicy
  2. AbortPolicy
  3. CallerRunsPolicy
  4. DiscardOldestPolicy
The submitting thread runs the task itself, so it cannot submit more until it finishes: backpressure.

A task submitted with submit() throws, and nobody calls get(). What happens?

  1. The exception is stored in the Future and never seen
  2. The JVM exits
  3. The worker thread dies and a stack trace is printed
  4. The pool shuts down
FutureTask catches it. Only get() would throw ExecutionException.

A request computes for 5 ms and waits 45 ms on I/O. On 4 cores, about how many threads keep the CPUs busy?

  1. 4
  2. 9
  3. 16
  4. 40
4 × (1 + 45/5) = 4 × 10 = 40.

What happens to a scheduleAtFixedRate task whose third run throws?

  1. It is retried immediately
  2. All later runs are cancelled
  3. Only that run is skipped
  4. The executor shuts down
The exception completes the ScheduledFuture exceptionally and the schedule stops. Catch inside the task.

Where does CompletableFuture.supplyAsync(fn) run with no executor argument?

  1. A new thread every time
  2. The caller's thread
  3. ForkJoinPool.commonPool()
  4. A cached thread pool
The JVM-wide common pool, sized for CPU work. Blocking I/O there hurts everything else in the process.

A pool of 4 threads runs 4 parent tasks, each submitting a child to the same pool and calling get() on it. Result?

  1. Thread-starvation deadlock
  2. Children run on the caller
  3. The pool grows to 8
  4. It works, just slower
All 4 threads wait for children that are stuck in the queue with no free thread to run them.
