How many threads?

No magic number, but a rule of thumb:

  • CPU-bound work (parsing, hashing, compression): about one thread per core. More threads only add context switches.
  • I/O-bound work (DB calls, HTTP): threads ≈ cores × (1 + wait time / compute time). This is the well-known formula from Java Concurrency in Practice. If a request computes for 10 ms and waits 90 ms on the database, 8 cores × (1 + 9) = 80 threads keep the CPUs busy.
  • Check it with Little's law: threads needed = arrival rate × time each task holds a thread. 400 requests/s × 0.1 s = 40 busy threads on average. Add headroom, then measure.

Downstream limits matter more than the formula: 80 threads sharing 20 DB connections means 60 threads waiting. Size the two together, and keep separate pools for separate dependencies, so one slow service cannot use up every thread (the bulkhead pattern from Microservices & Resilience).
