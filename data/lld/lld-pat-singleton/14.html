In double-checked locking, what is the job of the second null check (inside the lock)?

  1. To make the common case fast
  2. To release the lock early
  3. To stop a thread that waited on the lock from building a second object
  4. To make the field volatile
A thread that blocked on the lock may find the object already built by the thread before it. The second check catches that.

Why must the DCL field be volatile in Java?

  1. So the garbage collector never frees it
  2. So another thread cannot see the reference before the constructor's writes are visible
  3. So the lock is taken on every call
  4. So the class can be serialized
Without it, assignment and construction may be reordered; volatile adds the happens-before edge.

Which Java singleton is protected against both reflection and serialization without extra code?

  1. Eager static field
  2. Holder idiom
  3. Synchronized getInstance
  4. Single-element enum
The JVM refuses to reflectively create enum constants and serializes enums by name.

What makes the holder idiom lazy?

  1. The nested class is initialised only when get() first touches it
  2. It uses volatile
  3. It uses synchronized
  4. It creates the object in a background thread
Class initialisation happens on first active use, and the JVM does it once, under its own lock.

A teammate makes the database connection a singleton. The best response?

  1. Fine, it saves memory
  2. Make it volatile
  3. Use a single connection pool that hands out many connections
  4. Use an enum instead
One connection serialises every query and is a single point of failure.

What is the main reason Singleton is called an anti-pattern?

  1. It uses too much memory
  2. Global access hides dependencies and makes code hard to test
  3. It cannot be thread-safe
  4. It only works in Java
"One instance" is fine; the global access point couples callers to a concrete class and leaks state across tests.

In C++11 and later, a function-local static Config c; inside instance() is:

  1. Initialised exactly once, even with concurrent callers
  2. Initialised on every call
