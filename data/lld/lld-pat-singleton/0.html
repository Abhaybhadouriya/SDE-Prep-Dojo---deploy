The story: one school bell

Explain like I'm 5

A school has one bell. When it rings, every class knows it is lunch time. Now imagine every teacher bought their own bell and rang it whenever they liked. Class 2 would go to lunch at 12:00, class 3 at 12:07, and the playground would be chaos.

So the school makes a rule: there is only one bell, it lives in the office, and anyone who wants it rung asks the office. Nobody is allowed to buy a second bell. The office does not even put a bell in the room until the first time somebody asks for it.

That rule is the Singleton pattern. "Only one" is the bell. "Ask the office" is the getInstance() method. "Nobody may buy a second one" is the private constructor. "Put it in the room the first time someone asks" is lazy initialisation.

Programs have bells too: one configuration that every part of the program must agree on, one log file writer, one pool of database connections, one hardware register block. Make two of them and the parts of your program start to disagree.

From your world

You have written this in C many times: a file-scope static struct foo_ctx the_ctx; with an accessor foo_get_ctx(), maybe set up once with pthread_once(). The static hides the variable from other files (like a private constructor hides new), and pthread_once makes the first-time setup safe when several threads race. In the kernel, init_net (the first network namespace) and init_task are single, well-known objects that everybody refers to by name. Singleton is the same idea, with the language enforcing the "only one" rule instead of a code comment.
