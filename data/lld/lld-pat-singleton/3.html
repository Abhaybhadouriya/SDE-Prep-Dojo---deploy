Structure: one class, three moving parts

Participants (the named roles in the pattern):

  • Singleton class (Config): owns a static field that points to its only instance, a private constructor, and a static getInstance() method.
  • Clients: any code that calls Config.getInstance(). They never see the constructor.

Notice what is not there: no interface, no subclass, no second class. That is why Singleton is the easiest pattern to draw and the easiest to misuse. Everything interesting is about when the object is built and how two threads are stopped from both building it.
