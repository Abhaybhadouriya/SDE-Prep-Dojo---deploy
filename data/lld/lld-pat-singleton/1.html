The problem: two of something that must be one

Here is a small payment service. Each part of the code builds its own connection pool and its own logger, because new is right there and nothing stops it.

class OrderService {
    private final ConnectionPool pool = new ConnectionPool(50);   // 50 DB connections
    private final FileLogger log = new FileLogger("/var/log/pay.log");
}
class RefundService {
    private final ConnectionPool pool = new ConnectionPool(50);   // 50 more
    private final FileLogger log = new FileLogger("/var/log/pay.log");
}
class ReportJob {
    private final ConnectionPool pool = new ConnectionPool(50);   // and 50 more
}

What goes wrong:

  • Resource blow-up. The database allows maybe 100 connections. Three services each opening 50 means 150. The third service fails at start-up, or worse, at peak traffic.
  • Lost or mixed-up data. Two FileLogger objects each keep their own file handle and buffer. Lines from the two objects interleave, and one buffer can overwrite what the other just flushed.
  • Disagreement. If configuration is loaded into several objects, a reload updates one copy and the rest keep the old values. Half the program thinks the feature flag is on.

We want three things at once: one object, a well-known place to get it, and a guarantee that nobody can make another, not even by accident from a second thread.
