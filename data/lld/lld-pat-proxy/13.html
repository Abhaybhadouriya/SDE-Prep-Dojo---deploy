Remember this

  • Proxy = same interface as the real object, controls access to it. Client cannot tell the difference.
  • Kinds: virtual (when), protection (whether), remote (where), caching (whether at all), rate-limit (how often), smart reference (bookkeeping).
  • Proxies stack; order changes behaviour (rate limit before or after the cache).
  • Proxy vs Decorator: same shape, different intent. Control access vs add features; framework-built vs client-stacked.
  • Dynamic proxies: java.lang.reflect.Proxy (interfaces), CGLIB/ByteBuddy (subclasses, not final), Python __getattr__.
  • Spring @Transactional is a proxy; self-calls through this skip it.
  • Watch for hidden latency, stale caches, thread-safe lazy init, and identity surprises.
