The problem: control code smeared over every caller

A trading app has a QuoteService that talks to the exchange feed. Creating it opens a connection; each call costs money and latency. Without a proxy, every caller does the guarding itself:

class PortfolioScreen {
    private ExchangeQuoteService feed;                 // created eagerly somewhere, or lazily here
    private final Map<String, Quote> cache = new HashMap<>();
    private int callsThisSecond; private long windowStart;

    Quote show(User u, String symbol) {
        if (!u.roles().contains("TRADER")) throw new SecurityException();   // auth check
        if (feed == null) feed = new ExchangeQuoteService();                 // lazy init
        Quote q = cache.get(symbol);                                         // caching
        if (q != null) return q;
        if (++callsThisSecond > 3) throw new IllegalStateException("429");   // rate limiting
        q = feed.quote(symbol);
        cache.put(symbol, q);
        return q;
    }
}
// ...and WatchlistScreen, AlertsJob and ReportService each copy a slightly different version.
  • Duplication. Every caller re-implements auth, laziness, caching and limits, slightly differently. One forgets the auth check.
  • Mixed concerns. A screen class is now also a cache, a limiter and a security gate. It breaks the Single Responsibility Principle.
  • Hard to change. Switching the cache TTL or the limit means editing many classes.
  • Hard to test. You cannot test the screen without the real feed, or test the limiter on its own.
