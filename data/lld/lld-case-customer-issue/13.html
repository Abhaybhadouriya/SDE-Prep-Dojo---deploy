Evaluator rubric checklist

  • All seven functions run from a driver, in the stated priority order, with no manual setup.
  • Assignment rule behind an interface; the service has no if (strategy == ...).
  • One place changes status and it rejects illegal moves; RESOLVED is terminal.
  • Invariants hold: one issue per agent, one agent per issue, FIFO waitlist, history in order.
  • Filters compose; no growing if (filter.email != null) ... if (filter.type != null) ladder in the service.
  • Validation and custom exception with clear messages; a rejected call leaves no trace.
  • Thread safety implemented (at least the coarse lock) and explained, including what you would do at scale.
  • Assumptions written down in code comments, as the statement asks.
  • Readable: small classes, no god object, no public mutable fields, no dead code.

These follow the statement's own evaluation list (completeness, OO principles, efficiency, readability, testability, corner cases, language proficiency) quoted in LC 7218643.
