Key relationships and patterns (and why each)

Pattern / choiceWhereWhy it earns its placeWhat you say in the room
StrategyAssignmentStrategy with FreeFirst and RoundRobinThe statement literally says "based on different strategies; for now, any free agent". The rule is the part most likely to change in the follow-up (least loaded, highest rated, skill level, priority). Swapping it is a constructor argument."The assignment rule is injected. Least-loaded or skill-based is a new class; the service code does not change."
State machine (enum + transition table)IssueStatus.canMoveTo, Issue.moveToEvery status change goes through one method that rejects illegal moves (RESOLVED -> IN_PROGRESS). Four states with no per-state behaviour do not need a full State class hierarchy; say that, and say when you would switch (states that behave differently, like REOPENED with an SLA timer)."Every status change goes through moveTo(), which rejects illegal moves. Four states with no per-state behaviour: an enum is enough."
Specification (lightweight)IssueFilters returning Predicate<Issue>getIssues(filter) must accept "email", "type", "status" and combinations. Composable predicates (byType(GOLD).and(byStatus(WAITING))) mean a new filter is a new one-line factory method, never a new if in the service."Filters are predicates; any combination is and/or, not a new method."
FacadeIssueServiceThe driver, tests or a future REST controller call the same seven methods. The lock lives here, so every invariant is checked in one place."One entry point and one lock, so resolve-and-pull-next is one atomic step."
Per-worker queue (producer-consumer shape)Agent.waitlistEach agent drains its own FIFO when it finishes the current issue. It is the producer-consumer idea without threads: the "consumer" is the resolve call."Each agent has its own FIFO; resolving the current issue pulls the next one in the same critical section."
Observer (follow-up)IssueListenerEmail the customer when an issue is resolved, or update a dashboard, without the service knowing about email. See extensibility."Email and dashboards are listeners, called after the lock is released."

Patterns we deliberately skipped: a Singleton IssueService (tests build several, each with its own strategy), a full State class per status (no state has behaviour of its own yet), and a global work queue with SKIP LOCKED-style competing consumers (issues belong to one agent, so a per-agent FIFO is both simpler and fair).
