Quiz

Every GOLD expert is busy. What does our default strategy do with a new GOLD issue?

  1. Rejects it
  2. Puts it on the waitlist of the GOLD expert with the shortest waitlist
  3. Gives it to any free agent, even without GOLD expertise
  4. Leaves it OPEN forever
FreeFirst returns a free expert if one exists, otherwise the busy expert with the shortest waitlist, and the issue moves to WAITING.

Which transition does our state table reject?

  1. OPEN -> WAITING
  2. WAITING -> IN_PROGRESS
  3. RESOLVED -> IN_PROGRESS
  4. IN_PROGRESS -> RESOLVED
RESOLVED is terminal. Reopening would need a new REOPENED status and its own transitions.

What is the main race that a lock in assignIssue prevents?

  1. Two threads both see the same agent free and both give it an issue
  2. Two issues getting the same id from a UUID generator
  3. The JVM reordering enum constants
  4. A slow email notification
It is check-then-act: "is the agent free?" and "start the issue" must be one atomic step.

The interviewer asks for "least loaded agent first". What do you change?

  1. Add a boolean flag to IssueService
  2. Edit FreeFirstStrategy to check a config string
  3. Subclass IssueService
  4. Add a new class implementing AssignmentStrategy and pass it to the constructor
That is the point of the Strategy: a new rule is a new class; the service and its tests do not change.

How should getIssues support "email AND status" without editing the service for each new combination?

  1. Add getIssuesByEmailAndStatus()
  2. Accept a predicate and compose small filters with and()
  3. Return all issues and let the driver filter
  4. Use reflection on field names
Composable predicates are a lightweight Specification pattern.

An agent resolves its current issue and has two issues waiting. What must happen inside the same critical section?

  1. Nothing; the agent calls assignIssue later
  2. Both waiting issues start at once
  3. The first waiting issue becomes current and moves to IN_PROGRESS
  4. The waiting issues go back to OPEN
One issue at a time, FIFO. Doing it atomically means nobody ever sees the agent free while work is waiting for it.
