Common mistakes

  • Setting status directly (issue.status = RESOLVED) from several places, so a resolved issue can be "resolved" again or a waiting one jumps the queue.
  • Assignment logic inside createIssue with a switch on a strategy name.
  • Forgetting the pull-next step: the agent resolves and then sits idle while its waitlist grows.
  • A Customer class, a Transaction class, an Admin class with no behaviour: time spent that earns nothing.
  • Ignoring expertise in the strategy, so a GOLD issue lands on a payments-only agent.
  • A filter object with ten nullable fields and an if-ladder in the service.
  • No lock and no comment about locking, then freezing in the review call when asked about races.
  • Submitting late. The statement says a partial solution on time beats a complete one after time.
