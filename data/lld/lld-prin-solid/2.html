S: Single Responsibility Principle

Rule: a class should have one reason to change. Martin later sharpened this to "one actor": one group of people whose requests change it (his 2014 post). It does not mean "one method per class".

Smell: a class name ending in Manager, Helper or Service that holds everything; methods that talk about different things (money maths, string formatting, file or DB writes); you describe the class with the word "and".

Cure: split by reason to change. Keep data with the rules about that data; move formatting and storage out.

// BEFORE: pricing, layout and storage in one class
class InvoiceGod {
    long total()            { ... }   // finance team changes this
    String print()          { ... }   // design team changes this
    void save(List<String> db) { ... } // platform team changes this
}

// AFTER: one reason to change each
record Invoice(Map<String, Long> lines) { long total() { ... } }
class InvoicePrinter    { String print(Invoice i) { ... } }
class InvoiceRepository { void save(Invoice i)   { ... } }

From your world

The kernel networking stack is SRP at subsystem scale. A NIC driver moves frames between the ring buffer and sk_buffs; it does not parse TCP. The IP layer routes; it does not know about sockets. Netfilter filters; it does not drive hardware. When a new NIC ships, only one driver changes. A driver that also did routing would be the InvoiceGod of the kernel.
