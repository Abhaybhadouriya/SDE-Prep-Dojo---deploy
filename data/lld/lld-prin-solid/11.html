  1. Liskov Substitution
  2. Single Responsibility
  3. Interface Segregation

Adding a new payment method means editing a switch in three services. Which principle and which pattern fix it?

  1. Open/Closed, with Strategy
  2. Liskov, with Singleton
  3. Interface Segregation, with Builder

Which kernel structure split is the best example of Interface Segregation?

OrderService does new MySqlOrderRepo() in its constructor. What is the DIP-friendly change?

  1. Accept an OrderRepository interface in the constructor
  2. Make MySqlOrderRepo a singleton
  3. Copy the SQL into OrderService
Depend on an abstraction and inject the detail; tests can pass an in-memory repository.
