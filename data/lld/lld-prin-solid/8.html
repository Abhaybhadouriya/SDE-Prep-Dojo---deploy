When SOLID goes too far

SOLID is a set of forces, not laws. Applied blindly, it produces an interface for every class and ten files for a 50-line problem. In a 90-minute machine-coding round, that costs you the working demo, which graders weigh first.

Apply it where change is likely
  • Anything the problem says will "be added later": payment methods, pricing rules, notification channels, vehicle types.
  • Anything external: storage, clock, network, random numbers (so tests can fake them).
  • Anything with two or more variants today.
Skip it where change is unlikely
  • An interface with exactly one implementation and no test need.
  • Splitting a 20-line class into four because "SRP".
  • Abstract factories for objects built in one place. See YAGNI on the DRY, KISS, YAGNI page.

A good line for the interview: "I'll keep this as a concrete class for now; if a second notification channel comes, I'll extract a Notifier interface. Nothing else would change." It shows you know OCP and YAGNI and can trade them off.
