Interview questions

Explain SOLID in two minutes.

One sentence plus one example per letter. S: a class has one reason to change (split Invoice from InvoicePrinter). O: add features by adding classes, not editing old ones (new DiscountRule class). L: any subtype must work wherever the parent is expected (Penguin must not throw from fly; split FlyingBird). I: small role interfaces (Printer, Scanner). D: business logic depends on interfaces, details are injected (OrderService takes a Notifier).

How to answer

Keep each letter to about 20 seconds, then offer: "Shall I show one in code?" Interviewers usually pick O or D.

Likely follow-ups
  • Which principle do you break most often, and when is that fine?
  • Which design patterns support OCP?
Here are Vehicle, Car and Bike classes. Which SOLID principle is violated? Fix it.

Look for three typical shapes. (1) Vehicle has openTrunk() or fly() and Bike throws from it: LSP (and ISP); move the method to a smaller interface that only cars implement. (2) A calculateToll(Vehicle v) with if (v instanceof Car) ... else if (v instanceof Bike): OCP; move the rate into the vehicle (or a toll Strategy) so new vehicles need no edit. (3) Vehicle also saves itself to a DB or prints receipts: SRP.

How to answer

Read the code aloud, name the smell, name the letter, then refactor the smallest piece. Reported at Goldman Sachs (post, 2025-05-08).

Likely follow-ups
  • Add an electric car with a charging fee: what changes?
  • Would composition be better than inheritance here?
Your machine-coding solution has one big ParkingService with every method. What is wrong and how do you fix it in the time you have?

It violates SRP (allocation, pricing, payment and storage change for different reasons) and usually OCP (pricing by vehicle type in a switch). Quick fix order: pull storage into in-memory repositories behind interfaces; extract a PricingStrategy; keep ParkingService as a thin facade that orchestrates. Do it after P0 works, not before.

Likely follow-ups
  • How would you swap the in-memory store for a real database? (DIP: implement the repository interface)
What is the difference between DIP and dependency injection?

DIP is a design rule about the direction of dependencies: policy and details both depend on an abstraction owned by the policy. DI is one way to achieve it: the object receives its collaborators (constructor, setter or framework) instead of creating them. You can do DI without DIP (injecting a concrete class) and DIP without a DI framework (plain constructor arguments in main).

Likely follow-ups
  • Why is constructor injection preferred over field injection?
  • What is an IoC container?
Is Square extends Rectangle an LSP violation? Always?

Only if Rectangle is mutable with independent setWidth/setHeight. Client code like r.setWidth(5); r.setHeight(4); assert r.area() == 20 fails for a square. If the shapes are immutable (no setters, area computed from final fields), a square can be a rectangle safely. LSP is about behaviour and contracts, not about the real-world "is-a".

Likely follow-ups
  • What are preconditions and postconditions in LSP terms?
  • Can an override throw a new checked exception? (no, Java forbids widening it)
An interface has 3 methods and 2 implementations in production. A new implementation needs only 2 of them. What do you do?

This is ISP. Options: split the interface into role interfaces and let the old classes implement both (cleanest); or add a Java default method so the new class need not implement it (fast, but hides a smell); never make the new class throw from the third method (that breaks LSP). A Walmart candidate reported a question of this shape (post, 2024-11-28).

Likely follow-ups
  • When do you use Factory and when Strategy? (asked in the same round)
