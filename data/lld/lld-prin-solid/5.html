I: Interface Segregation Principle

Rule: no client should be forced to depend on methods it does not use. Prefer several small role interfaces over one fat one.

Smell: implementations full of empty methods or throw new UnsupportedOperationException(); an interface with ten methods where most callers use two; changing one method forces many unrelated classes to recompile.

Cure: split by client need: Printer, Scanner, Fax. A class implements the roles it really has. Note how ISP violations often cause LSP violations (the fake scan() throws).

// BEFORE
interface Machine { void print(String doc); String scan(String doc); void fax(String doc, String number); }

// AFTER
interface Printer { void print(String doc); }
interface Scanner { String scan(String doc); }
class CheapPrinter  implements Printer          { ... }
class OfficeMachine implements Printer, Scanner { ... }

From your world

The kernel shows both sides. struct file_operations is a fat table where drivers leave most pointers NULL and the VFS checks before calling: C's way of tolerating a fat interface. But the network stack splits roles: net_device_ops for the data path (open, stop, transmit) and a separate ethtool_ops for configuration and statistics (netdevices docs). A virtual device can skip ethtool entirely. That split is ISP.
