Core flows

Return a late copy when someone is waiting

  1. The driver returns copy C3 on 2026-11-18. It was due on 11-15.
  2. The service takes its lock, checks that C3 is actually on loan (a double return is rejected) and removes the active loan from both the loan index and the member.
  3. It asks the fine strategy for this member's type. A student pays 10.00 a day, so 3 days cost 30.00, added to the member's dues.
  4. The copy becomes AVAILABLE, then the service looks at the FIFO queue for this book and takes the first member, m2.
  5. The copy moves to ON_HOLD for m2 until 11-21. It never touches the shelf, so nobody else can borrow it in between.
  6. Only after the lock is released are the listeners told. A slow email sender cannot block other borrowers. The fine is returned to the caller.

Borrow: which copy?

Order matters. First look for a copy held for this member (they were notified and came in). Otherwise take any AVAILABLE copy. If none, look at why: if some copy is ON_HOLD for someone else, say so ("all copies are on hold for other members"); otherwise say "no copy available; reserve it". All the member checks (dues, loan limit, already holds this title) run before any copy is touched, and a member who borrows is removed from that book's queue if they were still in it.

Expire holds

A daily job (or a call in the demo) walks the ON_HOLD copies. Any hold whose date has passed moves to AVAILABLE and is immediately offered to the next member in the queue, or stays on the shelf. In the demo m2 never comes; on 11-22 the copy passes to m3, who is notified and borrows it.
