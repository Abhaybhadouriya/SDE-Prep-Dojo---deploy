Common mistakes

  • One Book class with a count, so copies, racks, holds and overdue copies cannot be modelled.
  • Returned copy goes straight to the shelf while people are waiting; the walk-in borrower wins.
  • Status as loose booleans (isBorrowed, isReserved) that can both be true.
  • Fine logic as an if-ladder on member type inside returnCopy.
  • Calling LocalDate.now() inside the service, so fines cannot be tested.
  • Changing state before the last check: copy marked BORROWED, then the loan limit check fails.
  • Notifications sent under the lock, or worse, the service talking to an email library directly.
  • Singleton service and Abstract Factory "for patterns"; they add code and no credit.
