The story: the librarian's two notebooks

Explain like I'm 5

The library has one card for every book: "Clean Code, by Robert Martin". But on the shelf there are two real copies of it, each with its own sticker number. When Asha borrows one, the librarian writes "copy C1 is with Asha, bring it back by the 15th" in the loans notebook.

When every copy of a book is out, Ben can ask to be put on a waiting list. When a copy comes back, the librarian does not put it on the shelf. She keeps it behind the desk with a note "for Ben, until Friday" and calls Ben. If Ben does not come by Friday, the copy goes to the next name on the list. If a book comes back late, the librarian writes a fine in the member's page, and students pay a different fine from teachers.

In the interview you write that librarian. Three ideas carry the whole design. First, a Book is not a BookCopy: the title is shared information, the copy is the thing that is borrowed and has a status. Second, a copy moves through a small state machine (available, borrowed, on hold, lost), and every operation is a legal move in it. Third, rules that vary (fines per member type, who gets told when a copy is waiting) are plugged in, not hard-coded.

From your world

Book versus copy is inode versus open file. One struct inode holds what is shared (size, owner); every open() creates its own struct file with its own state (position, flags). Here one Book holds title and author; each BookCopy has its own status and holder. The copy status is a protocol state machine like TCP's: a fixed table says which transitions are legal, and anything else is a bug you want to catch loudly. The waiting list plus "tell the member" is a notifier chain: interested parties register, and the producer calls them when the event happens.
