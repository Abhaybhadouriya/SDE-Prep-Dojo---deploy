Look-alike pairs: the deciding question

PairAsk thisAnswer that decides it
Strategy vs StateWho switches the behaviour object?Client picks: Strategy. States pick the next state: State.
Decorator vs ProxyDoes it add features or control access?Adds, always delegates, stackable: Decorator. Controls, may skip the real call: Proxy.
Adapter vs FacadeOne interface converted, or many simplified?Converts one: Adapter. Simplifies many: Facade.
Factory Method vs Abstract FactoryOne product or a matching family?One, chosen by subclass: Factory Method. A family: Abstract Factory.
Factory vs StrategyCreating an object or running an algorithm?Creation, done once: Factory. Behaviour, called repeatedly: Strategy.
Template Method vs StrategyInheritance or composition?Subclass fills steps: Template Method. Whole algorithm passed in: Strategy.
Observer vs pub-subDo publisher and listener know each other?Subject holds listeners: Observer. A broker in between: pub-sub.
Chain of Responsibility vs DecoratorIs the goal for one handler to take the request, or to add a layer of behaviour around one object?One of many handlers takes it (or passes it on): Chain. Layers wrap one component with the same interface: Decorator. Both can stop early (a caching decorator returns without calling inside), so "can it stop?" does not decide it.
Bridge vs StrategyDesigned split of two dimensions, or a swappable algorithm?Structure planned up front: Bridge. Algorithm swapped at run time: Strategy.
Command vs Memento (undo)Reverse an action or restore a snapshot?Reverse: Command. Restore: Memento.
