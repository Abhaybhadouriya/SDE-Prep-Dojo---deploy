APIs and interfaces

// facade: what the driver (or a REST controller) calls
void  addProduct(Product p, int stock);
void  addCoupon(Coupon c);
void  addItem(String userId, String productId, int qty);     // merges quantities
void  updateQty(String userId, String productId, int qty);   // 0 removes
void  removeItem(String userId, String productId);
void  applyCoupon(String userId, String code);               // throws ShopException(reason)
Bill  price(String userId);
Order checkout(String userId);                               // all-or-nothing

// extension points
interface Rule             { Optional<String> violation(PricingContext ctx); default Rule and(Rule o) {...} }
interface DiscountStrategy { long discount(PricingContext ctx, long runningTotal); }
interface PriceCalculator  { Bill calculate(PricingContext ctx); }

If the problem gives text commands (ADD u1 P1 2, APPLY u1 SAVE10, TOTAL u1), put a thin parser in front of this facade. The rules see only a PricingContext (user id, today, past orders, coupon uses, lines), never the service itself, so they are trivial to unit test.
