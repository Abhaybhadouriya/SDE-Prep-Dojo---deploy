Evaluator rubric checklist

  • Runs and demos every P0 API from a main/driver, including rejections.
  • Correct money: integer paise, basis points, floor rule stated, total never negative.
  • No switch on coupon type; rules and amounts are separate, composable objects.
  • Deterministic stacking: priority order, stackable flag, clear rejection messages.
  • Validation before mutation: a failed checkout leaves stock, cart and usage untouched.
  • Thread safety explained, with the oversell race handled in code and the lock order stated.
  • Clear ownership: Inventory owns stock, Cart owns lines, Rule owns eligibility, Strategy owns the amount, service orchestrates.
  • Readable code: small classes, immutable value objects, no public mutable fields, no dead code.
  • Can extend live: add buy-X-get-Y or an or rule in a few minutes without touching the service.

These match the round descriptions in the reports above (Meesho: completeness, then OOP and patterns) and the published Flipkart machine-coding guideline: demoable, functionally correct, modular, extensible, with error handling (workattech/flipkart-machine-coding-round).
