Quiz

Cart total 1000. Coupons: "10% off" and "100 off". Percent runs first. What is the final total?

  1. 800
  2. 790
  3. 810
  4. 900
10% of 1000 is 100, leaving 900; then 100 off leaves 800. Flat first would give 810, which is why the order must be a defined rule.

Which pair of patterns keeps "when a coupon applies" and "how much it takes off" independent?

  1. Singleton and Factory
  2. Specification and Strategy
  3. Adapter and Proxy
  4. Observer and Command
Rules are composable predicates (Specification); the amount is a swappable algorithm (Strategy).

What makes CouponLayer a Decorator rather than a plain helper?

  1. It has only static methods
  2. It is created by a factory
  3. It stores the cart
  4. It implements PriceCalculator and wraps another PriceCalculator
Same interface as the thing it wraps, delegates to it, adds behaviour on top. That is the definition.

Checkout has 3 lines and the third is out of stock. What should the stock of the first two products be afterwards?

  1. Unchanged
  2. Decremented; the user can retry the third
  3. Decremented, then restored by a background job
  4. Zero
Check every line, then decrement every line, inside one critical section. A failure leaves no trace.

A flat 200 coupon is applied to a cart whose running total is 150. What should the layer take off?

  1. 150, total 0
  2. 200, total -50
  3. 0, coupon rejected silently
  4. 200, and carry 50 to the next order
Every layer takes min(discount, running). Carrying credit forward would be a separate wallet feature.

"Only the first 1000 orders may use LAUNCH50." Which is safe with many app servers?

  1. A synchronized method on each server
  2. Read remaining, then write remaining - 1
  3. Cache remaining in each server's memory
  4. UPDATE ... SET remaining = remaining - 1 WHERE code = ? AND remaining > 0 and check rows affected
Only a conditional update in the shared store is atomic across servers. Local locks protect one process only.

Where should "is the coupon still valid?" be checked?

  1. Only on the client
  2. At apply time and again at price and checkout
  3. Only in a nightly job
  4. Only when the coupon is applied
The cart, the date and the usage count can all change after apply; re-check where money is computed.
