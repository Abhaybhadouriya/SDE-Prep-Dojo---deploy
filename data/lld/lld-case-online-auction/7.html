APIs and interfaces

Write these on the board before coding. They mirror the statement's command list, so the driver is a thin translation.

AuctionHouse house = new AuctionHouse(Clock.systemUTC());
house.addListener(new Notifier());                          // Observer registration
house.addBuyer("buyer1");  house.addSeller("seller1");
house.createAuction("A1", 10, 50, 1, "seller1",            // id, low, high, cost, seller
                    new HighestUniqueBidRules(), null);     // rules (Strategy), duration (null = manual)
house.createBid("buyer1", "A1", 17);                        // CREATE_BID
house.updateBid("buyer1", "A1", 19);                        // UPDATE_BID
house.withdrawBid("buyer1", "A1");                          // WITHDRAW_BID
AuctionResult r = house.close("A1");                        // CLOSE_AUCTION (idempotent)
String p = house.profit("seller1", "A1");                   // GET_PROFIT -> "-12.40"

interface AuctionRules {
    void validate(long amount, long low, long high, Optional<Bid> currentBest);
    Optional<Bid> pickWinner(Collection<Bid> bids, Predicate<String> isPreferred);
    boolean allowsWithdraw();
    default Optional<Bid> best(Collection<Bid> bids) { return Optional.empty(); }
}
  • Errors: every rule violation throws AuctionException with a clear message (unknown buyer, out of limits, below the increment, create twice, update without a bid, auction closed or ended, profit before close, wrong seller). The driver catches and prints it, as sample 2 expects ("this should fail").
  • Read side: history() and participants() return copies made under the lock.
  • If asked for REST: POST /auctions, PUT /auctions/{id}/bids/{buyer} (create or update, idempotent by buyer), DELETE /auctions/{id}/bids/{buyer}, POST /auctions/{id}/close, GET /auctions/{id}/result. A bid request carries the version (sequence) the client saw, so a stale bid returns 409.
