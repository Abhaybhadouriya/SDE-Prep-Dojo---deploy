Common mistakes

  • One "bids" list for both the winner and the bidder count, so sample 2 breaks.
  • Doubles for money, printing -12.399999999999999.
  • Winner logic inside Auction with an if (type == ...), so the "normal auction" follow-up means editing the core.
  • Check and store in two steps without a lock, or one global lock for all auctions.
  • Calling listeners under the lock, so one slow notification blocks every bid.
  • Trusting the timer to enforce the deadline instead of checking the clock on each bid.
  • Non-idempotent close: the timer and a manual close both pick a winner and notify twice.
  • Inheritance for auction types (EnglishAuction extends Auction) when only the rule differs.
  • No running demo: Flipkart's statement says the code must be demo-able.
