The story: the restaurant order slip

Explain like I'm 5

In a restaurant you do not walk into the kitchen and tell the cook what to make. You tell the waiter, and the waiter writes it on a slip of paper: "table 4, one dosa, no onion".

That slip is magic. The waiter can put it on a hook in a line with other slips, so the cook makes them in order. The manager can count the slips at night to see what sold. If you change your mind, the waiter can tear up the slip before the cook starts. And the waiter does not need to know how to cook a dosa at all. The waiter only knows "take slip, put slip on hook".

The slip is a command object. It holds everything needed to do the job later (which dish, which table, which changes), and it separates the person who asks (you, the waiter) from the person who does (the cook).

From your world

An interrupt handler must return fast, so it does not do the heavy work itself. It fills in a struct work_struct (a function pointer plus the context it needs, found later with container_of) and calls schedule_work(). A kworker thread picks it up later and calls the function. The top half never knows what the work does; the workqueue never knows either. That work_struct is a command object: a request frozen into data so that someone else can run it at another time, on another thread.
