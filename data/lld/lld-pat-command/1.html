The problem: buttons that know too much

You are building a text editor. The toolbar has buttons, the menu has items, and there are keyboard shortcuts. A first version wires each one straight to the document:

class Toolbar {
    Document doc;
    void onClick(String button) {
        if (button.equals("bold"))        doc.applyBold(doc.selection());
        else if (button.equals("delete")) doc.delete(doc.selection());
        else if (button.equals("paste"))  doc.insert(doc.cursor(), clipboard.get());
        // ... 40 more branches, copied again in Menu and in KeyboardShortcuts
    }
    // Now product asks for: Undo. Redo. "Repeat last action". A macro recorder.
    // Where do we even remember WHAT was done, with WHICH arguments, so we can reverse it?
}

Three things hurt here:

  • Duplication and coupling. The same "if bold then..." logic is copied into the toolbar, the menu and the shortcut handler, and each one depends on every document method.
  • The action disappears after it runs. A method call leaves no trace. To undo, you need a record of what was done, with its arguments and the data it destroyed (the deleted text).
  • You cannot move the action in time or space. You cannot queue it, retry it, run it on a worker thread or send it to a server, because a method call is not a thing you can hold.
