Quiz

In the Command pattern, which participant actually knows how to perform the work?

  1. The Invoker
  2. The Receiver
  3. The Client
  4. The Command interface
The receiver (the document, the light, the device) does the work. The concrete command just calls it with stored arguments.

After undo, undo, the user types a new character. What happens to the redo stack?

  1. Nothing
  2. The new command is pushed onto it
  3. It is cleared
  4. Its top command is executed
The redo commands were planned for a document state that no longer exists, so a new command clears them.

When should DeleteText remember the text it removes?

  1. Inside execute(), just before deleting
  2. In its constructor
  3. In undo()
  4. Never; the document remembers it
Only at execute time does the command know what is really there. Capturing at construction risks stale data.

A macro of three commands is undone. In what order are its children undone?

  1. The same order they ran
  2. Random order
  3. Only the last one is undone
  4. Reverse order: third, second, first
Each step may depend on the previous one, so reverse order restores the state correctly.

Which kernel object is the closest match to a command object?

  1. struct file_operations
  2. struct work_struct
  3. struct task_struct
  4. struct page
A work item packages a function plus its context to be run later by a worker. file_operations is an ops table (Strategy/Bridge).

"Which pricing algorithm should this ride use?" is best modelled as:

  1. Command
  2. Memento
  3. Strategy
  4. Chain of Responsibility
Choosing how to do a job is Strategy. Command would fit "recalculate the fare for ride 77 later".

A job queue retries failed jobs. What protects you from a job that runs twice?

  1. An idempotency key (the job id) checked by the receiver
  2. A bigger queue
  3. Making the command a Singleton
  4. Clearing the redo stack
Retries plus crashes mean at-least-once execution; idempotency makes the second run harmless.
