The kernel's command objects

/* The shape of a work item (trimmed to the idea, not the real definition) */
struct work_struct {
    /* list linkage and flags owned by the workqueue code */
    work_func_t func;                  /* void (*)(struct work_struct *) */
};

struct my_dev {
    struct work_struct rx_work;        /* the command, embedded in its context */
    int irq;
};

static void rx_work_fn(struct work_struct *w)
{
    struct my_dev *d = container_of(w, struct my_dev, rx_work);   /* get the arguments back */
    /* heavy processing for d->irq, may sleep */
}

/* setup:      INIT_WORK(&d->rx_work, rx_work_fn);
   in the IRQ: schedule_work(&d->rx_work);   -- queue it and return fast */

From your world

Other kernel objects that are commands in all but name: struct bio (a block I/O request carrying its sectors, pages and an bi_end_io completion callback through the block layer); io_uring submission queue entries (an operation code plus arguments, written into a ring by user space and executed later by the kernel); timers (a callback plus data plus "when"). Each one is a request turned into data so that the caller and the executor are separated in time or in thread. Notice that none of them supports undo(): queueing and deferring are the most common reasons to use Command; undo is the most famous one.
