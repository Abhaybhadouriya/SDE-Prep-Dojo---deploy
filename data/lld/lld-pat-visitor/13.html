Quiz

You have 6 AST node types and 4 visitors. A new node type is added. How many visitor classes must change?

  1. 0
  2. 4
  3. 6
  4. 1
Every visitor needs a method for the new type. That is Visitor's main cost.

Why can't you just call taxVisitor.visit(item) with overloads for each subtype when item is declared as Item?

  1. Overloads are slower than virtual calls
  2. Java does not allow overloading
  3. Overloads are chosen at compile time from the static type, so visit(Item) is picked
  4. Visitors cannot take parameters
Only virtual calls look at the runtime type, and only of the receiver. accept turns the element's runtime type into a static one.

Which situation fits Visitor best?

  1. A compiler whose node types rarely change but gains new passes every release
  2. A plugin system where third parties add new element types weekly
  3. A class with one operation
  4. Choosing a sorting algorithm at runtime
Stable types, growing operations. The other cases favour plain polymorphism or Strategy.

In Files.walkFileTree, how does a visitor avoid descending into a directory?

  1. Throw an exception
  2. Return null
  3. Call Files.delete
  4. Return FileVisitResult.SKIP_SUBTREE from preVisitDirectory
The return value steers the walk; TERMINATE stops it entirely.

What does Java 21's sealed interface + pattern-matching switch give you that a plain instanceof chain does not?

  1. Faster virtual calls
  2. A compile error when a permitted subtype is not handled
  3. Automatic accept methods
  4. Thread safety
Exhaustiveness checking is the property that makes it a real alternative to Visitor.

In C, the closest equivalent to a Visitor is:

  1. A global variable per node type
  2. A macro that expands to printf
  3. A struct holding one function pointer per node type, called as v->visit[n->type](n, ctx)
  4. A linked list of nodes
The type tag gives dispatch 1, the choice of visitor struct gives dispatch 2.
