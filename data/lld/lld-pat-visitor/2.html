Intent

Visitor (GoF behavioral pattern): when you keep adding new operations over a fixed set of node types, write each operation as its own class with one method per node type. The nodes only need a single accept hook, so a new operation never edits the node classes.

In plain words: move each operation out of the element classes into its own class, with one method per element type. The elements keep a single generic hook, accept(visitor), which calls back the method for their own type. A new operation is a new visitor class; the element classes stay closed.

The price is the mirror image: adding a new element type now means adding a method to every visitor. Visitor is a bet that your types are stable and your operations are not.
