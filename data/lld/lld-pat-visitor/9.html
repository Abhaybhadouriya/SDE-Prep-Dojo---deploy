Related and confused-with patterns

Compared withLooks similar becauseThe difference
IteratorBoth walk a collectionIterator hands out elements one by one and the caller decides what to do; it does not care about element types. Visitor runs a different method per element type. They combine: an iterator drives the walk, a visitor does the work.
CompositeTrees of nodesComposite is the shape (leaf and container share an interface). Visitor is an operation run over that shape. Most visitors walk a composite.
StrategyAn operation lives in its own objectA Strategy is one algorithm for one context and does not care about element types. A Visitor has one method per element type and is applied across a structure.
CommandAn action packed as an objectCommand captures a request to run later (undo, queue). Visitor captures an operation to run now across many objects of different types.
InterpreterBoth are about expression treesInterpreter puts interpret() on each node class. Once you need many operations on the tree (evaluate, print, optimise), you move them out into visitors.
