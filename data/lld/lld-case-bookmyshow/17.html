Which is the worst place to hold the show lock?

  1. While checking seat states
  2. While writing Held states
  3. While confirming a hold
  4. While calling the payment gateway
Payment can take many seconds; the hold (a timestamp) reserves the seat, not the mutex.

A blockbuster's first show opens; thousands of users want the same 50 seats. Which inventory is the better default?

  1. Optimistic: no locks means faster
  2. Pessimistic with short per-show critical sections
  3. No locking: conflicts are rare
  4. A global lock over all shows
High contention makes optimistic CAS fail and roll back often; short pessimistic sections finish each request in one pass.

Which Redis command fits a seat hold with a 5-minute TTL?

  1. GET seat:SH1:A2
  2. INCR seat:SH1:A2
  3. SET seat:SH1:A2 holdId NX PX 300000
  4. DEL seat:SH1:A2
NX = only if absent (atomic claim), PX = expire in milliseconds (the lease).

Why are seats taken in sorted order?

  1. So two overlapping requests cannot deadlock or keep undoing each other
  2. To print nicely
  3. Java maps require it
  4. It makes pricing cheaper
A global order breaks the cycle needed for deadlock (with per-seat locks) and reduces livelock with CAS.
