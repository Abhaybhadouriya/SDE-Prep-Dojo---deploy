  • Rank 2: asked at Paytm, Salesforce, Amazon, Goldman Sachs, Oracle and Zepto in 2024-26, and as flight/train/concert variants elsewhere.
  • Seat state is per (show, seat): Free -> Held (with expiry) -> Booked; never a flag on Seat.
  • Holds are all-or-nothing and short; payment happens with no lock held.
  • Pessimistic: one lock per show, check all then write all. Optimistic: CAS per seat with rollback. Choose by contention.
  • Expiry is lazy: an expired hold counts as free on the next check; a sweeper is only housekeeping.
  • Check the hold before charging; confirm re-checks; refund if it still fails; idempotency keys for payment retries.
  • Many servers: database row locks or conditional updates, Redis SET NX PX, or partition by show.
