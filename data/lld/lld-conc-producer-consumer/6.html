Clean shutdown: poison pills and interrupts

A consumer loop is while (true) { item = queue.take(); process(item); }. How does it ever stop? There are two standard answers.

Poison pill

A poison pill is a special item that means "no more work, stop". The producer side puts it after the last real item. Because the queue is FIFO, every real item before it gets processed first. Rules that make it correct:

  1. One pill per consumer. Each consumer eats one pill and exits. With 2 consumers, put 2 pills. (Alternative: a consumer that takes the pill puts it back before exiting, so the next consumer also sees it.)
  2. Only after all producers are done. Join the producer threads (or count them down with a latch) before putting pills. A pill put while a producer is still running lets that producer's later items be stranded.
  3. A pill must be impossible as real data. Use a dedicated object (static final Job POISON = new Job(...)) compared by identity, or a sealed type with a Stop variant. Our demo uses -1 because all real values are positive.
// main thread
for (Thread p : producers) p.join();                  // 1. all real work is queued
for (int c = 0; c < consumers; c++) queue.put(POISON); // 2. one pill per consumer
for (Thread c : consumerThreads) c.join();            // 3. everything processed, nothing lost

// consumer
while (true) {
    Job job = queue.take();
    if (job == POISON) return;                        // identity check
    process(job);
}

Interrupts

take(), put() and await() throw InterruptedException when the thread is interrupted, which is how ExecutorService.shutdownNow() stops workers. Interrupts are fast but abrupt: items still in the queue are not processed unless you drain them (queue.drainTo(list)). If you catch InterruptedException and cannot exit right away, restore the flag with Thread.currentThread().interrupt() so code higher up still sees it.
