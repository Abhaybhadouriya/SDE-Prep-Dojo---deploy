Way 1: synchronized with wait and notifyAll

final class MonitorBuffer<T> implements BoundedBuffer<T> {
    private final Object[] items;
    private int head, tail, count;
    MonitorBuffer(int capacity) { items = new Object[capacity]; }

    public synchronized void put(T item) throws InterruptedException {
        while (count == items.length) wait();     // full: release the monitor and sleep
        items[tail] = item;
        tail = (tail + 1) % items.length;
        count++;
        notifyAll();                               // wake everybody; each re-checks its own condition
    }

    @SuppressWarnings("unchecked")
    public synchronized T take() throws InterruptedException {
        while (count == 0) wait();                 // empty: sleep
        T item = (T) items[head];
        items[head] = null;                        // do not keep a reference: let GC reclaim it
        head = (head + 1) % items.length;
        count--;
        notifyAll();
        return item;
    }
}

Three details carry the whole design:

  1. while, not if. When a thread wakes up it must re-check, because another thread may have grabbed the slot first, and because spurious wakeups are allowed. (The Locks, Conditions & Semaphores page explains this in detail.)
  2. notifyAll, not notify. A Java object has only one wait set, and here both producers and consumers sleep in it. With notify(), a consumer that just took an item could wake another consumer instead of a producer. That consumer sees an empty buffer and goes back to sleep, and the producers sleep forever even though there is space. notifyAll() wakes everyone; the wrong ones re-check and sleep again. It is correct, but wasteful.
  3. Every access is inside the monitor. head, tail, count and the array are only touched while holding the lock, which gives both atomicity and visibility.
