The senior answer: immutable snapshots (RCU in Java)

The fastest read lock is no lock. Keep the data in an immutable object. Readers grab the current reference with one volatile read and use it as long as they like. A writer copies the object, changes the copy, and publishes it with a single atomic reference swap. Old readers keep their old, still-valid version; new readers see the new one.

record Config(Map<String, String> flags, long version) {
    Config with(String k, String v) {
        Map<String, String> copy = new HashMap<>(flags);
        copy.put(k, v);
        return new Config(Map.copyOf(copy), version + 1);     // deeply immutable
    }
}
private final AtomicReference<Config> current = new AtomicReference<>(initial);

String flag(String k)          { return current.get().flags().get(k); }        // no lock
void   setFlag(String k, String v) { current.updateAndGet(c -> c.with(k, v)); } // CAS loop
  • Consistency for free. A reader that does Config c = current.get() once sees one coherent version for its whole request, which an RW-locked map cannot promise across several get calls.
  • Writers. updateAndGet retries if two writers race. With a single writer (a config poller), a plain volatile field is enough. With expensive copies and frequent writes, serialise writers with a lock and keep reads lock-free.
  • Cost. Each write copies the object. Fine for config, routes and catalogues updated seconds or minutes apart. Wrong for data that changes thousands of times a second.

From your world

This is RCU with the garbage collector as the grace-period detector. In the kernel, rcu_read_lock() marks a read-side section (nearly free; it may just disable preemption), rcu_dereference(p) is current.get(), and rcu_assign_pointer(p, new) is the publish. The writer must then wait in synchronize_rcu(), or queue call_rcu() / kfree_rcu(), until every CPU has passed a quiescent state before it frees the old version. Java skips that step because the GC frees v1 only when no reader can reach it. CopyOnWriteArrayList is this pattern packaged for lists.
