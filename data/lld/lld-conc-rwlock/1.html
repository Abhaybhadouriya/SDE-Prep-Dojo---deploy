The problem: readers queue behind each other

A feature-flag service. Every request checks a flag, and an admin changes flags a few times a day. The obvious thread-safe version uses synchronized:

class FlagStore {
    private final Map<String, Boolean> flags = new HashMap<>();
    synchronized boolean isOn(String f) { return flags.getOrDefault(f, false); }   // 50,000 calls/s
    synchronized void set(String f, boolean on) { flags.put(f, on); }           // 3 calls/day
}

It is correct, but two readers can never run at the same time, even though reads cannot harm each other. On a 16-core box, 16 request threads take turns on one lock to read a map that almost never changes. The goal: readers run in parallel; a writer gets exclusive access.

Read-mostly data is everywhere in LLD rounds: config and feature flags, a product catalogue, a route table in a URL router, a cache in an LRU question, exchange rates, a seat map that is viewed far more often than it is booked.
