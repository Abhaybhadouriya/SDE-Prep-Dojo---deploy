Remember this

  • RW lock: many readers or one writer. It wins only when reads dominate and read sections are not tiny.
  • Downgrade (write → read) is allowed. Upgrade (read → write) deadlocks: release, take the write lock, re-check.
  • Writer starvation: block new readers while a writer waits. Java's nonfair RRWL does this with a heuristic; fair mode uses arrival order.
  • StampedLock: optimistic read = stamp, copy to locals, validate, else fall back. Not reentrant, no Conditions.
  • Seqlock = StampedLock's ancestor: even/odd counter, readers retry, the writer never waits. Plain data only.
  • Senior answer for read-mostly data: an immutable snapshot behind an AtomicReference. Wait-free reads and a consistent view per request: RCU with the GC as the grace period.
  • If the data is a map, try ConcurrentHashMap before any of these.
