Quiz

Thread T holds the read lock of a ReentrantReadWriteLock and calls writeLock().lock(). What happens?

  1. It upgrades atomically
  2. It blocks forever
  3. It throws IllegalMonitorStateException
  4. It gets the lock after other readers leave
The writer waits for every reader to leave, including T itself. Upgrades are not supported.

A cache uses a reader-preferring RW lock with heavy read traffic. What symptom do you expect?

  1. Readers starve
  2. Deadlock between readers
  3. Updates are delayed for a long time or forever
  4. Torn reads
New readers keep the lock busy, so the waiting writer never gets in: writer starvation.

In a StampedLock optimistic read, when is it safe to use the copied values?

  1. After validate(stamp) returns true
  2. Right after tryOptimisticRead()
  3. After unlockRead(stamp)
  4. Any time, because fields are volatile
Before validation the copy may mix old and new values.

Why can a ReadWriteLock be slower than a mutex for a simple map.get()?

  1. Read locks are reentrant
  2. Writers always go first
  3. It uses more memory
  4. Every reader still updates a shared counter, so cores fight over one cache line
Acquiring a read lock is itself a write to shared state. For tiny sections, that cost dominates.

What does a seqlock reader do if the sequence number is odd?

  1. Blocks until the writer signals
  2. Retries, because a write is in progress
  3. Takes the writer's spinlock
  4. Reads anyway; odd means valid
Odd means mid-write. Readers spin and retry; they never block the writer.

Config is read on every request and changed twice a day. The best structure is:

  1. synchronized getters
  2. A fair ReentrantReadWriteLock
  3. An immutable snapshot swapped through an AtomicReference
  4. A StampedLock write lock on every read
Readers do one volatile read and never wait. Writers copy and swap, like RCU.

Which Java lock is NOT reentrant?

  1. StampedLock
  2. ReentrantReadWriteLock
  3. ReentrantLock
  4. synchronized
Taking a StampedLock write lock twice in one thread deadlocks it.
