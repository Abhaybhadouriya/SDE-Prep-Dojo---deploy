"For read-mostly config I would not lock reads at all. I keep an immutable snapshot behind an AtomicReference, so readers do one volatile read and always see a consistent version. The writer copies, changes and swaps, which is RCU with the GC doing the grace period. If writes were frequent, I would fall back to a ConcurrentHashMap or a read-write lock."
