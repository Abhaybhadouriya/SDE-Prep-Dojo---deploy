The SMP bridge: the same bugs in C

If you have debugged an SMP race in a driver, here is the mapping from what you know to what the interviewer will ask:

/* Lost update: never do this on shared data */
dev->rx_packets++;                       /* load, add, store */
atomic_inc(&dev->rx_dropped);            /* atomic RMW  ~ AtomicInteger.incrementAndGet() */

/* Check-then-act: must be one critical section */
spin_lock(&pool->lock);                  /* ~ synchronized (pool) {            */
if (pool->free > 0)
        pool->free--;                    /*       check + act together          */
spin_unlock(&pool->lock);                /*   } unlock hb next lock of the same lock */

/* Publish data, then a flag: release/acquire pair */
dev->cfg = cfg;                          /* plain write                         */
smp_store_release(&dev->ready, 1);       /* ~ volatile write                    */

if (smp_load_acquire(&dev->ready))       /* ~ volatile read                     */
        use(dev->cfg);                   /* guaranteed to see cfg               */
