Race 1: read-modify-write (count++ is three steps)

count++ looks like one operation. The CPU sees three: load the value into a register, add one, store it back. If two threads interleave between those steps, one increment is lost. Step through it:

  1. Thread A loads count (41) into a register. It has not written anything yet.
  2. The scheduler switches, or Thread B is simply on another core: B loads the same 41.
  3. Both threads add one in their own private registers. Both now hold 42.
  4. A stores 42. So far so good.
  5. B stores 42 on top of it. Two increments ran, the counter moved by one. A's update is lost, and no exception or warning tells you.

The same shape hides in many "one line" statements: balance -= amount, map.put(k, map.get(k) + 1), list.add(x) on an ArrayList (which reads and writes size), hits[i]++. Here is the real thing, four threads doing 100,000 increments each (demo 1 of the full program):

for (int i = 0; i < perThread; i++) {
    plain++;                                   // read, add, write: NOT atomic
    synchronized (LOCK) { locked++; }          // one thread at a time
    atomic.incrementAndGet();                  // one CAS instruction loop
}
1) expected 400000 | plain 398121 | synchronized 400000 | AtomicInteger 400000

The plain counter lost about 1,900 updates in this run; the number changes every run and can be much worse on a quiet machine. Both fixes make the three steps indivisible: synchronized by mutual exclusion, AtomicInteger by a hardware compare-and-swap (CAS) that retries if the value changed in between; see atomics and CAS.

From your world

This is i++ on a shared int in a driver, and you would never write it there. You would use atomic_inc(&v) (a lock-prefixed instruction on x86, an LL/SC or LSE atomic on arm64), or hold a spinlock. AtomicInteger is atomic_t; incrementAndGet() is atomic_inc_return(); compareAndSet() is atomic_cmpxchg(). For a hot statistics counter Java has LongAdder, which spreads updates across cells and sums on read, the same idea as per-CPU counters.
