Quiz

Four threads each run count++ 1,000 times on a shared volatile int. What is the final value?

  1. Always 4,000
  2. Always 1,000
  3. At most 4,000, often less
  4. The program throws an exception
volatile gives visibility, not atomicity; lost updates still happen, silently.

Which of these is a check-then-act race?

  1. if (!map.containsKey(k)) map.put(k, v); on a ConcurrentHashMap
  2. map.putIfAbsent(k, v)
  3. atomic.incrementAndGet()
  4. Reading a final field
Each call is safe, but the pair is not atomic; another thread can put between them.

Which of these does NOT create a happens-before edge from thread A to thread B?

  1. A writes volatile v, then B reads v and sees the write
  2. A unlocks lock L, then B locks L
  3. A finishes, then B returns from a.join()
  4. A unlocks lock L1, then B locks lock L2
Monitor edges only exist between operations on the same lock.

When is volatile alone sufficient?

  1. For a counter incremented by many threads
  2. For a stop flag that one thread sets and a worker reads
  3. For "check balance, then deduct"
  4. Never
The new value does not depend on the old one, so only visibility is needed.

A getter reads a field that setters update inside synchronized. The getter has no lock. What can go wrong?

  1. Nothing, reads are always safe
  2. A deadlock
  3. It may read a stale value, because there is no happens-before edge from the setter
  4. The setter will block forever
Visibility comes from both sides using the same lock (or the field being volatile).

In the kernel, which primitive is closest to a Java volatile write that publishes earlier writes?

  1. smp_store_release()
  2. A C volatile store
  3. kfree()
  4. printk()
Release semantics order earlier writes before the store; a paired smp_load_acquire on the reader side completes it.

Why does CPython code still need locks despite the GIL?

  1. The GIL only exists on Windows
  2. Locks make Python faster
  3. The GIL protects your data structures' invariants automatically
  4. Threads can switch between bytecodes and during I/O, so compound actions interleave
x += 1 is several bytecodes, and a check-then-act around I/O has a wide window.
