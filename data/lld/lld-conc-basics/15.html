Remember this

  • No shared mutable state, no race. Confine or make immutable first; synchronise only what is left.
  • Two race shapes: read-modify-write (count++) and check-then-act (if free, book). Both need the compound action to be atomic.
  • Thread-safe parts do not make a thread-safe whole: use putIfAbsent/computeIfAbsent/merge, or one lock around both calls.
  • Visibility: without a happens-before edge, another thread may never see your write (hoisted reads, store buffers).
  • Happens-before edges: program order, unlock then lock of the same lock, volatile write then read, start, join, transitivity.
  • volatile = visibility + ordering, not atomicity of compound actions. Enough for flags and one-writer cases.
  • Every read of a lock-guarded field also takes the lock.
  • Kernel map: atomic_t = AtomicInteger; struct mutex ≈ synchronized / ReentrantLock (spin briefly, then sleep); a spinlock has no direct Java equivalent (busy-wait on an AtomicBoolean); release/acquire = volatile write/read; C volatile is not Java volatile.
