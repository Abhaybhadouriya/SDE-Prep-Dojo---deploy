The rule of thumb: volatile is enough only when the new value does not depend on the old one (or only one thread ever writes). stop = true qualifies. count++, if (x == null) x = ... and "update two fields together" do not.

A Java lock is not only mutual exclusion. Entering and leaving the same lock also gives visibility. That is why a getter of a guarded field must take the lock too: without it, the getter may read a stale value even though the writer was locked.
