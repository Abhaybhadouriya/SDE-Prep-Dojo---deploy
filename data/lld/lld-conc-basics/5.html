Designing a thread-safe class

In an LLD answer, thread safety is a property of a class, so show it in the class diagram. The question to ask about each field: is it shared, is it mutable, and if both, which lock guards it?

There are only three strategies, and they are listed from cheapest to most expensive:

  1. Do not share. Keep state confined to one thread: local variables, a request-scoped object, a ThreadLocal, or a single owner thread that others message through a queue (the actor style, and how an event loop works).
  2. Do not mutate. Immutable objects (all fields final, no setters, defensive copies) can be shared freely once safely published. A new version replaces the old one by swapping a single reference. See immutability.
  3. Synchronise. Guard each piece of shared mutable state with one lock, or use an atomic variable or a concurrent collection that does it for you. Keep critical sections small, with no callbacks or network calls inside. See locks.
