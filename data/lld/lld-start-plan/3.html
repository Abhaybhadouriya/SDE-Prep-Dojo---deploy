Week 1: OOP, SOLID and UML (days 1-7)

Goal: given a short problem statement, you can list the entities, decide which are classes, which are interfaces and which are enums, connect them with the right relationships, and explain why each class has one job. For a C engineer most of this is new vocabulary for old ideas, so this week is fast if you keep mapping back to kernel code.

Trap for systems engineers: writing one big class with all the logic, as you might write one big .c file with static helpers. Interviewers grade the split into small classes with clear owners. On day 4, keep asking "if a new requirement comes, how many files change?".
