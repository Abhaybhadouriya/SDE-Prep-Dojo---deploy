Questions people ask about LLD prep

How many case studies do I need to solve before an LLD interview?

Depth beats count. Ten to fifteen cases built from a blank file, timed, with a running driver, prepare you better than forty you only read. The cases share a small set of moves: an enum for types, an interface for a pluggable rule, a service that owns state, a lock around booking. After about ten builds you will notice you are reusing those moves, and new problems become variations.

How to answer

If an interviewer asks how you prepared, name a few cases you built and one thing each taught you ("BookMyShow taught me seat locking with a hold timeout").

Likely follow-ups
  • Which case was hardest and why?
  • What would you change in your Parking Lot design now?
Should I learn all 23 Gang of Four patterns?

Know all of them by name and purpose, but practise about eight until you can write them in minutes: Strategy, Observer, State, Factory Method, Singleton, Builder, Decorator and Chain of Responsibility. Interviewers rarely ask "explain Flyweight"; they give a problem and watch whether you reach for the right tool. Using a pattern where it does not fit costs more than not using one.

How to answer

Tie each pattern to a requirement: "prices change by city, so pricing is a Strategy".

Likely follow-ups
  • Strategy vs State: what is the difference?
  • When is Singleton a bad idea?
I write C every day. Can I do the LLD round in C?

Usually not: most companies expect an object-oriented language for LLD, because the round tests classes, interfaces and access control. C++ is the natural bridge for you, and Java is the most common choice. Your C background is still an advantage: you understand what a vtable costs, who owns memory and how locks behave, which many candidates only know as words. Say so when it helps: "this interface is like a file_operations table".

How to answer

Pick Java or C++ before week 1 and use it for every build so the syntax is automatic by week 4.

Likely follow-ups
  • How does a virtual call work in C++?
  • How does Java free memory without free()?
What is the difference between preparing for SDE-1 and SDE-2 LLD rounds?

For SDE-1 the bar is a clean, working object model: sensible classes, a pattern or two used correctly, code that runs. For SDE-2 interviewers also probe extensibility ("add surge pricing without editing the fare code"), concurrency ("two users book the same seat") and trade-offs between designs. In our report set 224 of 311 rounds were SDE-2 level, so most published experiences describe that bar. So SDE-2 candidates should not skip week 3, and should practise answering a follow-up by changing their code live.

How to answer

Show you know the bar: finish P0, then volunteer one extension and one concurrency risk without being asked.

Likely follow-ups
  • How would you make this thread-safe?
  • What breaks if we have 10 parking lots instead of one?
My mock ran out of time with half the code written. What should I change?

Three fixes cover most cases. First, cap clarify plus model at 30 minutes; a perfect diagram is not graded if nothing runs. Second, write the driver early, after the first service, and grow it, so you always have something to demo. Third, build P0 end to end before any P1, and keep storage in-memory (maps) unless asked. Log where the minutes went in each mock; the slow step is usually the same every time.

How to answer

In a real round, tell the interviewer what you are cutting and why: "I will keep payment as an interface with a fake so the booking flow runs end to end".

Likely follow-ups
  • Which parts would you write first if you had 45 minutes?
