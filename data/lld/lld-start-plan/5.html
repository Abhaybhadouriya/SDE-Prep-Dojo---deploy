From your world

This is your strongest week. A Java ReentrantLock is a sleeping mutex, AtomicInteger.compareAndSet is cmpxchg, a BlockingQueue is a ring buffer with a wait queue on each end, and lock ordering to avoid deadlock is the same rule lockdep enforces. What is new is the vocabulary interviewers expect ("optimistic locking with a version column", "ConcurrentHashMap.compute is atomic per key") and the Java memory model's volatile, which is about visibility, not atomicity.

Work each case the same way: read only the story and requirements, close the page, set a 90-minute timer, build it, run your own driver, and only then read the page's design and compare. The Case Study Index has the full list of 45 cases for later practice.
