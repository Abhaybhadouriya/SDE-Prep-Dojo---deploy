The definition and where it comes from

Software entities (classes, modules, functions) should be open for extension, but closed for modification.

Bertrand Meyer coined the phrase in 1988 in Object-Oriented Software Construction. His version used inheritance: once a class is finished, you leave it alone and add features in a subclass. Robert C. Martin later popularised the polymorphic version, which is the one interviewers mean today: code depends on an abstract interface, and new behaviour comes from new implementations of that interface.

  • Open for extension: you can make the module do new things.
  • Closed for modification: you do it without changing the module's existing, tested source code.

Craig Larman described the same goal as Protected Variation: find the points where you expect change, and put a stable interface around them so the change cannot leak into the rest of the system. That framing is useful in interviews because it tells you where to apply OCP: at the points of likely change, not everywhere.

The quick test is the diff. If adding a new variant means editing tested classes, the code is not closed. If it means adding a new class and one line of wiring, it is.
