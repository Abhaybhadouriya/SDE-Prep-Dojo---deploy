From your world: the kernel is built on OCP

From your world

You have used OCP every time you loaded a module. The TCP core calls congestion control through struct tcp_congestion_ops (a table of function pointers such as ssthresh and cong_avoid). An algorithm is a module that fills that struct and calls tcp_register_congestion_control() from its init function. BBR arrived in Linux 4.9 largely as a new module plugged into this interface. You select one with the net.ipv4.tcp_congestion_control sysctl or per socket with setsockopt(TCP_CONGESTION). Netfilter works the same way: a module fills struct nf_hook_ops (hook point, priority, callback) and calls nf_register_net_hook(); the packet path is never edited to add your firewall rule. register_filesystem() does the same for VFS.

The C shape is worth writing once, because it is exactly what the Java registry does: a struct of function pointers is the interface, a static instance is the implementation, and a register function adds it to a list the core owns.

// C-style registry, the same shape as tcp_register_congestion_control() or nf_register_net_hook().
// Build (C++14, g++ 6.3): g++ -std=c++14 -Wall -o fee_ops fee_ops.cpp
#include <cstdio>
#include <cstring>

struct fee_ops {                       // like struct tcp_congestion_ops
    const char *name;
    long (*fee)(long amount_paise);    // the "virtual method"
    struct fee_ops *next;              // intrusive list, like list_head
};

static struct fee_ops *fee_list;       // owned by the "core"

int register_fee_ops(struct fee_ops *ops) {             // core API: closed
    for (struct fee_ops *p = fee_list; p; p = p->next)
        if (strcmp(p->name, ops->name) == 0) return -17; // -EEXIST
    ops->next = fee_list;
    fee_list = ops;
    return 0;
}

long core_fee(const char *name, long amount) {          // core logic: closed
    for (struct fee_ops *p = fee_list; p; p = p->next)
        if (strcmp(p->name, name) == 0) return p->fee(amount);
    return -2;                                           // -ENOENT
}

/* ---- "modules": each one only registers itself ---- */
static long upi_fee(long) { return 0; }
static long card_fee(long a) { return a * 2 / 100; }
static struct fee_ops upi_ops  = { "UPI",  upi_fee,  nullptr };
static struct fee_ops card_ops = { "CARD", card_fee, nullptr };

static long bnpl_fee(long a) { long f = a * 3 / 100; return f > 5000 ? 5000 : f; }
static struct fee_ops bnpl_ops = { "BNPL", bnpl_fee, nullptr };   // new "module", no core edit

int main() {
    register_fee_ops(&upi_ops);        // think: module_init(upi_init)
    register_fee_ops(&card_ops);
    register_fee_ops(&bnpl_ops);
    printf("duplicate register -> %d\n", register_fee_ops(&card_ops));
    const char *names[] = { "UPI", "CARD", "BNPL", "CRYPTO" };
    for (const char *n : names) printf("%-6s fee on Rs 1000 = %ld paise\n", n, core_fee(n, 100000));
    return 0;
}
$ g++ -std=c++14 -Wall -o fee_ops fee_ops.cpp && ./fee_ops
duplicate register -> -17
UPI    fee on Rs 1000 = 0 paise
CARD   fee on Rs 1000 = 2000 paise
BNPL   fee on Rs 1000 = 3000 paise
CRYPTO fee on Rs 1000 = -2 paise

Line by line, the mapping is: struct fee_ops = the Java FeeRule interface; bnpl_ops = an object of class Bnpl; register_fee_ops() = FeeRegistry.register(), including the duplicate check (-EEXIST vs IllegalStateException); core_fee() = FeeCalculator. Netfilter adds one more idea worth mentioning: priority. Its hooks are ordered and each returns a verdict (accept, drop, queue), which is the Chain of Responsibility shape on top of OCP registration.
