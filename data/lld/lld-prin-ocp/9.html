Remember this

  • OCP: add new behaviour by adding code, not by editing tested code.
  • Typical refactor: type switch to interface + one class per branch + registry lookup.
  • The switch does not vanish; it moves to the composition root (Main, factory or DI config).
  • Test it with the diff: one new file and one wiring line is closed; edits in five tested files is not.
  • Numbers that differ are data, not classes. Logic that differs is a class.
  • Strategic closure: protect the axes you expect to change; ask the interviewer which ones those are.
  • Kernel: tcp_congestion_ops, nf_hook_ops and register_filesystem() are OCP with function-pointer tables.
