How it works: a call crossing the bridge

  1. The client calls send(ravi) on an OrderUpdate. Its channel reference currently points at PushChannel.
  2. The abstraction does its own job first: build the order text, and trim it using channel.maxChars(). This logic is shared by every channel.
  3. The call crosses the bridge: channel.deliver(...). Ravi has no app installed, so push returns false.
  4. The client swaps the implementation at runtime: switchChannel(sms). Only one pointer changes; no new class, no new object of the abstraction.
  5. The same send runs again and now crosses the bridge to SmsChannel, which succeeds.

Compare with the M x N design: there, switching from push to SMS means throwing away an OrderPush and constructing an OrderSms, and the "trim to fit" code would live in nine places.
