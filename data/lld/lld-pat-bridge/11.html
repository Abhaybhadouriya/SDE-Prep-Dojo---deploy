Interview Q&A

What problem does Bridge solve? Explain with an example.

When two dimensions vary independently, inheritance alone forces a subclass per combination (M x N) and duplicates code. Bridge gives each dimension its own hierarchy, and the abstraction holds a reference to an implementor. Notifications: Otp/OrderUpdate/Promo on one side, Sms/Email/Push on the other, 6 classes instead of 9, and a new channel works for every notification kind immediately.

How to answer

Start with the explosion, draw the two hierarchies and the reference, count classes before and after.

Likely follow-ups
  • How do you add WhatsApp? (One new Concrete Implementor.)
  • Where does message trimming live?
Bridge vs Adapter: they both forward calls. What is the difference?

Intent and timing. Adapter is applied after the fact to make an existing class fit an interface it was not written for. Bridge is a design decision made up front so an abstraction and its implementations can evolve separately. In practice they combine: a third-party SMS SDK is wrapped by an Adapter so it can act as one Concrete Implementor in a Bridge.

How to answer

"Adapter: make it fit, later. Bridge: keep them apart, from the start." Then the combined example.

Likely follow-ups
  • Can one class be both?
Bridge vs Strategy: the UML looks the same. How do you tell them apart?

Strategy is behavioural: a context delegates one algorithm (pricing, sorting, eviction) and the client chooses which. Bridge is structural: it separates a whole abstraction layer from a whole implementation layer, and the abstraction side has its own refined subclasses. Ask: does the "context" have a hierarchy of its own that grows independently? If yes, it is Bridge. If it is one context with pluggable algorithms, it is Strategy.

How to answer

Admit the shapes match, then give the "two hierarchies" test and one example of each (VFS vs TCP congestion control).

Likely follow-ups
  • Which one is Comparator?
Where is Bridge used in the Linux kernel?

VFS: struct file and the generic vfs_read/vfs_write path call through file->f_op, a struct file_operations provided by each filesystem or driver. Networking: struct net_device calls net_device_ops from the NIC driver. Sockets: struct sock calls sk_prot. Generic code (permissions, position, statistics, queueing) sits on the abstraction side; device-specific code on the implementation side.

How to answer

Name the struct, the ops pointer and one function each side owns.

Likely follow-ups
  • What happens when a driver leaves an op NULL?
  • How is this different from C++ virtual functions? (Same mechanism, written by hand; one table per type, shared by all objects.)
Is JDBC a Bridge? Explain.

It is commonly cited as one. Application code is written against the java.sql interfaces (the abstraction side), and vendor drivers registered with DriverManager supply the implementation. You can switch from MySQL to PostgreSQL by changing the driver and URL, not your data-access code. Strictly, the "abstraction" side is mostly interfaces rather than a class hierarchy, so some people call it a plain plug-in architecture; the decoupling idea is the same.

How to answer

Say yes, explain the two sides, and show nuance by mentioning it is a loose fit.

Likely follow-ups
  • How does DriverManager find drivers? (ServiceLoader on the classpath.)
When would Bridge be over-engineering?

When only one dimension varies, or there is only one implementation and no concrete plan for a second. You pay with extra types and an indirect call on every operation, and readers must jump between two hierarchies. Start with a single interface; introduce the Bridge when a second independent dimension actually appears (refactoring toward it is cheap if dependencies are injected).

How to answer

Cite YAGNI, then name the trigger that would make you add it.

Likely follow-ups
  • How would you refactor nine XxxSms/XxxEmail classes into a Bridge safely?
