The problem: the M x N class explosion

A food app sends three kinds of notification (OTP, order update, promotion) over three channels (SMS, email, push). Model it with inheritance alone and you get one class per pair:

abstract class Notification { abstract void send(User u); }

class OtpSms        extends Notification { ... }   // OTP text, SMS gateway call
class OtpEmail      extends Notification { ... }   // OTP text, SMTP call
class OtpPush       extends Notification { ... }
class OrderSms      extends Notification { ... }   // order text again, SMS call again
class OrderEmail    extends Notification { ... }
class OrderPush     extends Notification { ... }
class PromoSms      extends Notification { ... }
class PromoEmail    extends Notification { ... }
class PromoPush     extends Notification { ... }
// add WhatsApp: 3 more classes. Add "payment failed": 4 more.

The pain is not only the count. The SMS-sending code is copied into three classes; a fix to the SMS retry logic must be made three times. The OTP wording is copied into three classes too. And a user who uninstalls the app cannot be switched from push to SMS at runtime, because the channel is baked into the class.
