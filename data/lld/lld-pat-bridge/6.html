The kernel's bridges, in C

In C, a "Bridge" is a struct with a pointer to an ops table. Here is the shape, trimmed to the idea (not real kernel code):

/* Implementor: what each filesystem or driver provides */
struct file_operations {
    ssize_t (*read)(struct file *, char __user *, size_t, loff_t *);
    ssize_t (*write)(struct file *, const char __user *, size_t, loff_t *);
    /* ... open, release, mmap, poll, unlocked_ioctl ... */
};

/* Abstraction: the object the VFS and user space deal with */
struct file {
    const struct file_operations *f_op;   /* the bridge */
    loff_t f_pos;                          /* owned by the abstraction side */
    /* ... */
};

/* Generic code on the abstraction side: checks, then crosses the bridge */
ssize_t vfs_read_sketch(struct file *f, char __user *buf, size_t n)
{
    /* permission and range checks, locking: same for every filesystem */
    return f->f_op->read(f, buf, n, &f->f_pos);
}

From your world

The same split appears all over the kernel. struct net_device (generic: queues, stats, the stack's view of an interface) holds netdev_ops, a struct net_device_ops with ndo_open, ndo_start_xmit and friends supplied by each NIC driver. struct sock holds sk_prot, a struct proto for TCP, UDP or another protocol. Block devices have block_device_operations. Each time: one generic object that the rest of the kernel uses, one ops pointer to the driver-specific half, and both sides evolve independently. LWN's two-part article on object-oriented patterns in the kernel describes these vtables in detail.

Is file_operations Bridge or Strategy? Structurally both look like "object holds a pointer to an interface". The useful distinction: Strategy swaps one algorithm inside a context (which congestion control does this socket use: tcp_congestion_ops), while Bridge separates a whole layer (the generic file API) from a whole platform (the filesystem), and both sides are hierarchies that grow. VFS is usually given as the Bridge example; per-socket congestion control as the Strategy example. See patterns in the Linux kernel.
