In interviews

Bridge is a Tier 3 pattern: in the interview reports we collected it is rarely named outright. Its value is as the answer to a class explosion. When your class diagram starts to show names like UrgentSmsNotification or PdfEmailReport, stop and say: "these are two independent dimensions; I'll split them into two hierarchies and connect them with composition, which is the Bridge pattern." Places it fits:

  • Notification service: notification type x delivery channel, exactly this page's example.
  • Logger: log level or formatter (what) x appender or sink (console, file, network: how).
  • File system: file and directory API x storage backend.
  • Chat app: message kinds (text, image, system) x transports (WebSocket, push, SMS fallback).
  • Car rental or ride hailing: vehicle kinds x pricing or payment back-ends (often a Strategy is enough; say why you chose one over the other).

Strong 30-second answer: "Bridge separates what a thing does from how it is done, as two hierarchies joined by a reference. It turns M x N subclasses into M + N and lets me swap the implementation at runtime. The Linux VFS is the classic example: generic file code calls through file_operations. Unlike Adapter, it is designed up front; unlike Strategy, both sides are hierarchies."
