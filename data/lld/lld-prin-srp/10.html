Quiz

In Martin's later wording, a "reason to change" is best understood as:

  1. A method that does one thing
  2. An actor: a person, team or role who can ask for changes
  3. A line-count limit
  4. A design pattern
Martin restated SRP as "responsible to one, and only one, actor". Reasons to change are people.

An Order class computes discounts, writes to MySQL and sends SMS. Which split best follows SRP?

  1. One class per method: DiscountAdder, DiscountRounder, MySqlWriter, SmsSender
  2. Keep it, but add comments per section
  3. Order (data + discount rule), OrderRepository, OrderNotifier
  4. Move everything into static utility functions
Group by actor: the business rule, storage and messaging. One class per method is over-splitting.

Which test symptom most strongly suggests an SRP violation?

  1. Testing a pure tax calculation needs a database mock
  2. The test file is long
  3. The class has a constructor
  4. The tests run in parallel
Pure logic should be testable alone. Needing I/O mocks means the rule is tangled with I/O.

One small finance change now forces edits in six classes. This smell is called:

  1. Divergent change
  2. God class
  3. Feature envy
  4. Shotgun surgery
Shotgun surgery is the over-splitting failure; divergent change is the god-class failure.

Why is a thin InvoiceService that calls a repository, notifier and formatter not an SRP violation?

  1. Services are exempt from SOLID
  2. Its single job is the order of steps in one use case; it implements none of them
  3. It has fewer than 50 lines
  4. It uses interfaces, so anything goes
Coordination is a responsibility of its own. It becomes a problem only if it starts doing the work itself.

In a Linux NIC driver, which pair shows splitting by caller?

  1. kmalloc and kfree
  2. module_init and module_exit
  3. net_device_ops for the stack and ethtool_ops for the admin tool
  4. spin_lock and spin_unlock
Two different callers, two separate ops tables: SRP by actor.
