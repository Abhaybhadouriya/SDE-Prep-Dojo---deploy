The definition, said properly

Robert C. Martin ("Uncle Bob") gathered the five SOLID principles. The usual one-liner for the S is:

A class should have one, and only one, reason to change.

That sentence confuses people, because "reason" is vague. In a 2014 blog post Martin clarified it: the reasons to change are people. In his later book Clean Architecture he rewords it as "a module should be responsible to one, and only one, actor". An actor is a group of people (a team, a role, a business function) that can ask for a change. Finance asks for tax changes. The DBA asks for storage changes. Support asks for a new invoice layout. If three actors can each ask to change the same class, that class has three reasons to change.

Three wrong readings come up again and again in interviews. Clear them first:

Wrong readingWhy it is wrongRight reading
"A class must do only one thing"That rule is for functions (a function should do one thing). A class can have many methods.All the methods serve the same actor and change together.
"One method per class"This creates hundreds of tiny classes and makes every change touch many files.Group by who asks for change, not by verb.
"SRP means small classes"A 400-line parser that only the protocol team ever changes can be fine.Size is a hint, not the rule. Mixed actors are the rule.

Two related words help. Cohesion means "the parts of this class belong together" (they use the same fields and change at the same time). Coupling means "this class depends on that one". SRP pushes cohesion up inside each class. A good SRP split also cuts accidental coupling, because the tax math no longer imports the SMTP library.

From your world

You already practise SRP in the kernel. A NIC driver fills a struct net_device_ops for the packet path (ndo_open, ndo_start_xmit) and a separate struct ethtool_ops for the admin tool (link settings, ring sizes, statistics). Two callers, two ops tables. The network stack never calls the ethtool hooks and ethtool never calls the transmit path. A driver also does not parse TCP: layering in the network stack is SRP at the subsystem level, where each layer answers to one "actor", the layer above it.
