What inheritance gives you

Inheritance lets a class (the subclass, child or derived class) be defined as an extension of another (the superclass, parent or base class). The child automatically has the parent's fields and methods, may add new ones, and may override (replace) the parent's non-final instance methods. Two benefits come with it:

  1. Reuse: shared code lives once, in the parent.
  2. Substitution: anywhere code expects a Device, you may pass an EthernetPort. This is what makes polymorphism work, and it is the more important benefit.

The test for whether inheritance is right is the is-a test, made strict: "a Child is a Parent, and every promise the parent makes, the child keeps." An EthernetPort is a NetDevice: yes. A Stack is a Vector: technically Java says yes (java.util.Stack extends Vector) and that is a famous mistake, because a vector lets you insert in the middle and a stack must not. That promise-keeping rule has a name, the Liskov Substitution Principle.

static class Device {
    protected final String name;
    Device(String name) { this.name = name; }
    String describe() { return "device " + name; }
}
static class NetDevice extends Device {
    protected final int mtu;
    NetDevice(String name, int mtu) { super(name); this.mtu = mtu; }
    @Override String describe() { return super.describe() + ", mtu " + mtu; }  // extend, not replace
}

In C++ the same thing is class NetDevice : public Device. The word public matters: public inheritance means is-a (outsiders may treat a NetDevice as a Device). private inheritance means "implemented in terms of": the child reuses the parent's code, but nobody outside may upcast. If you ever want private inheritance, composition is usually clearer.
