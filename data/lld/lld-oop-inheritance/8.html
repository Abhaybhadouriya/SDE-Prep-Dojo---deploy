Interview questions

What is the diamond problem and how do Java and C++ handle it?

When D inherits from B and C, which both inherit from A, two questions arise: does D hold one or two A parts, and which override wins if B and C both override an A method? C++ gives two A sub-objects by default (ambiguous member access) and one shared sub-object with virtual inheritance, constructed by the most-derived class; conflicting overrides must be resolved in D. Java forbids multiple class inheritance; for interface default methods it applies class-wins, then most-specific-interface, else the class must override and may call B.super.m().

How to answer

Draw the diamond, split it into the state question and the behaviour question, then answer per language. Mention Python's C3 MRO if they use Python.

Likely follow-ups
  • Can an interface have state? (Only static final constants.)
  • What does virtual inheritance cost? (An extra indirection to reach the base; most-derived must construct it.)
Can you override a static method in Java? What about a private one?

No to both. A static method with the same signature in a subclass hides the parent's; the call is bound by the static type at compile time, so Device d = new EthernetPort(); d.kind() calls Device.kind(). A private method is not visible to the subclass, so a same-named method there is a brand new method, not an override. Fields are also hidden, not overridden.

How to answer

State "hiding vs overriding", give the two-line example with the surprising output, and recommend calling static methods via the class name.

Likely follow-ups
  • Can you override a final method? (No.) A method that throws more checked exceptions? (No.)
  • What is a covariant return type?
In what order do static blocks and constructors run in a three-level hierarchy?

On first use: static initialisers of the root class, then each subclass down to the one being created (once per class). Then for every object: the constructor chain calls up via super() to Object, and bodies (with each class's instance field initialisers just before its body) run from the root down to the most-derived class. C++ destructors run in the reverse order.

How to answer

Write the output for a small example, distinguish once-per-class from per-object.

Likely follow-ups
  • What if the parent has no no-arg constructor? (The child must call super(args) explicitly, or it does not compile.)
Why is calling an overridable method from a constructor dangerous?

In Java, dispatch is dynamic even during construction, so the parent constructor calls the child's override before the child's fields are initialised: it sees 0 or null and may crash or record wrong state. In C++ the opposite happens: during the base constructor the object's dynamic type is still the base, so the base version runs, which is rarely what the author expected. Either way, keep constructors to field setup and call such hooks after construction, from a factory.

How to answer

Give the Java behaviour, contrast with C++, then the fix (factory method or final methods only).

Likely follow-ups
  • How does this relate to the Template Method pattern? (Hooks are called from a normal method, not the constructor.)
When would you NOT use inheritance? Give an example from an LLD problem.

When the relationship is "has-a" or "uses-a", when only one behaviour varies, when two dimensions vary independently, or when a child cannot keep every parent promise. In a parking lot, HourlyFeeParkingLot extends ParkingLot is wrong: pricing is a behaviour that varies, so ParkingLot holds a PricingStrategy. In a notification system, EmailSmsNotifier is the start of an explosion; hold a list of Channels instead.

How to answer

Name the fragile-base-class risk, the is-a / LSP test, then one concrete refactor to composition + Strategy.

Likely follow-ups
  • Then when is inheritance right? (Real taxonomies with shared invariants, Template Method, sealed hierarchies of states.)
