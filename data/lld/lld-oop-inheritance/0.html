The story: the family recipe book

Explain like I'm 5

Grandma has a recipe book. Mum gets a copy and adds a few pages of her own, and changes the cake recipe to use less sugar. When you grow up, you get Mum's book: all of Grandma's recipes, Mum's extra pages and Mum's cake. You can add your own pages too.

That is inheritance: a new thing starts with everything the old thing had, adds more, and may change (override) some parts.

Now imagine you get books from both Mum and Dad, and both changed Grandma's cake in different ways. Which cake recipe is yours? That puzzle is the famous diamond problem.

In LLD rounds, inheritance is everywhere in the class diagram: Vehicle → Car, Bike, Truck in a parking lot; Piece → King, Queen in chess; Account → Savings, Current. It is also the most over-used tool in junior designs. This page gives you the mechanics precisely, so that you can use it on purpose and explain why you chose it, or chose composition instead.

From your world

The kernel does inheritance by embedding. struct sock begins with a struct sock_common; struct tcp_sock begins with an inet_connection_sock, which begins with an inet_sock, which begins with a struct sock. Because the parent is the first member, a struct tcp_sock * can be used as a struct sock * (an upcast), and tcp_sk(sk) casts back down (a downcast), which is container_of in general. Java and C++ automate exactly this layout, add type checks so you cannot downcast to the wrong type silently, and add the dispatch table (vtable) you would otherwise write as an ops struct.
