Releasing a DAG (step through it)

This is the Rubrik pipeline from the table, run on one worker. Each job holds a count of unfinished parents. When a job succeeds, every child's count drops by one; a child whose count reaches zero is scheduled. That is Kahn's algorithm, run live, driven by completions instead of a loop.

  1. At submit, only A and K have no parents, so only they are scheduled. Everything else is WAITING with a count of pending parents.
  2. A finishes first (it was submitted first). Its children B and E drop to zero and are scheduled. K was already waiting in the ready queue, so it runs next.
  3. K finishes and releases L. B and E run in turn; B releases C, E releases F. G's count drops from 2 to... still waiting for F.
  4. L releases M. C finishes (G: 2 to 1), F finishes (G: 1 to 0), so G is released last.
  5. The demo prints exactly this order. With more workers, siblings run in parallel but the parent-before-child rule still holds.
