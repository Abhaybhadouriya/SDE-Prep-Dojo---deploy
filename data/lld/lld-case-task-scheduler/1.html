The classic statement many candidates practise with is an older Uber machine-coding round (891551, 2020): schedule(task, time), scheduleAtFixedInterval(task, interval) where the next run starts interval seconds after the previous run completes, a configurable number of worker threads, and no library that already does scheduling. A 2026 write-up of the same family (8334514) adds task states (pending, running, completed, failed), cancel, status queries and retries.

Three lessons from the table. First, concurrency is the point: the Salesforce candidate lost the question on threads, not on classes. Second, the DAG variant is common (Rubrik twice, Goldman Sachs, the Microsoft LRU round), so know Kahn's algorithm cold. Third, priority comes as a follow-up almost every time.

Interviewers love hearing, in the first minute: "I will separate when a job may run (a time queue), which due job runs next (a priority queue), and who runs it (a fixed worker pool). Each of the three changes for a different reason."
