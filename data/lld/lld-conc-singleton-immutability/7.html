Safe publication: four ways to hand an object over

An object that is not immutable, or not fully constructed, must reach other threads through a happens-before edge. Java Concurrency in Practice lists four safe ways to publish a properly constructed object:

WayExampleEdge it relies on
Static initialiserstatic final Config C = new Config();, holder, enumClass initialisation
Volatile field or atomic referencevolatile Config c;, AtomicReference<Config>Volatile write / read
Final field of a properly built objectthis.config = config; where config is finalFinal-field semantics
Field guarded by a lockWritten and read inside synchronizedUnlock / lock

Putting the object into a thread-safe collection (ConcurrentHashMap, BlockingQueue, CopyOnWriteArrayList) is the same idea: the JDK documents that inserting happens-before a later retrieval.

The "this escapes" trap

class Sensor {
    private final int threshold;
    Sensor(EventBus bus, int threshold) {
        bus.register(this);          // BUG: another thread may call onEvent() right now ...
        this.threshold = threshold;  // ... before this line runs, and see threshold == 0
    }
    void onEvent(int v) { if (v > threshold) alarm(); }
}
// Fix: a private constructor plus a static factory that registers AFTER construction.
static Sensor create(EventBus bus, int threshold) {
    Sensor s = new Sensor(threshold);
    bus.register(s);
    return s;
}

Even final fields lose their guarantee if this escapes during construction. The same applies to starting a thread in a constructor: create it there if you must, but start it from a separate start() method.
