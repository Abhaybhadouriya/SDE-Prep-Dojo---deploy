Immutability: the lock-free strategy

Every race needs shared data that changes. Remove the "changes" and there is nothing to race on. An immutable object is one whose state cannot change after its constructor finishes. Any number of threads can read it at the same time with no locks, and it can be cached, shared and handed out freely. Goetz's Java Concurrency in Practice sums it up as "immutable objects are always thread-safe".

The five rules

  1. No setters. No method changes a field. "Changing" returns a new object (money.plus(other)).
  2. All fields private final. The compiler then stops you, and you get the final-field visibility guarantee.
  3. The class cannot be subclassed. Make it final (records are final). Otherwise a subclass can add mutable state and be passed where your type is expected.
  4. Defensive copies of mutable parts. Copy collections and arrays in the constructor and never hand out your internal mutable object. List.copyOf copies; Collections.unmodifiableList is only a read-only view of a list the caller may still change.
  5. Do not let this escape the constructor. No registering this as a listener and no starting a thread that uses this inside the constructor; another thread could see the object before its fields are set.
class Route {
    private String id;
    private List<String> stops;
    Route(String id, List<String> stops) { this.id = id; this.stops = stops; }  // shares caller's list
    List<String> getStops() { return stops; }       // caller can modify our internals
    void addStop(String s) { stops.add(s); }         // races with readers iterating stops
}
final class Route {
    private final String id;
    private final List<String> stops;
    Route(String id, List<String> stops) {
        this.id = id;
        this.stops = List.copyOf(stops);              // copy in: unmodifiable, independent
    }
    List<String> stops() { return stops; }           // safe to hand out
    Route withStop(String s) {                       // "change" = new object
        List<String> next = new ArrayList<>(stops);
        next.add(s);
        return new Route(id, next);
    }
}

record Money(long paise, String currency) {          // records: final class, final fields
    Money {                                          // compact constructor: validate once
        if (paise < 0) throw new IllegalArgumentException("negative");
    }
    Money plus(Money o) { return new Money(paise + o.paise, currency); }
}

In Python, @dataclass(frozen=True) raises FrozenInstanceError on assignment and types.MappingProxyType gives a read-only view of a dict you keep private. In C++, const members and std::shared_ptr<const T> express the same intent.

Effectively immutable objects are technically mutable but never changed after publication (for example a HashMap filled in a constructor and never touched again). They are safe only if published safely, which is the next section.
