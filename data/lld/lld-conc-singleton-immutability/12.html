Remember this

  • "Create once and share" is two problems: create only once (exclusion) and make it fully visible (publication).
  • new X() is allocate, construct, assign; without a happens-before edge another thread may see the assignment first.
  • DCL needs volatile (Java 5+) or std::atomic with acquire/release. Copy the volatile into a local.
  • Prefer holder (lazy) or enum (also reflection and serialization safe) in Java; local static or call_once in C++.
  • Happens-before sources: unlock/lock, volatile write/read, class init, thread start/join, final fields.
  • Immutable = final class, private final fields, no setters, defensive copies, no this escape. Always thread-safe.
  • Copy-on-write = immutable snapshot + atomic reference swap. Readers never block; great for read-mostly data. It is RCU with the GC as the grace period.
  • A passing test proves nothing about memory ordering; reason with the JMM.
