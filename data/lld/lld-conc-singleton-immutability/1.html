Two separate problems: "once" and "visible"

"Create something once and share it between threads" hides two different problems. Interviewers check whether you can name both.

  1. Create it only once (mutual exclusion). If two threads both see "not created yet", both create one. Now there are two connection pools, two config objects, two of whatever was meant to be one. A lock fixes this.
  2. Make it fully visible (publication). To publish an object means to make it reachable by other threads, for example by storing it in a shared field. If the reference becomes visible before the object's fields are, another thread can use a half-built object. This is a memory visibility problem, not a mutual exclusion problem, and a lock only fixes it when both sides take the lock.

The second problem is the one people miss. It exists because compilers and CPUs are allowed to reorder memory operations as long as a single thread cannot tell the difference. Another thread can tell. The rules for what another thread may see are the Java Memory Model (JMM), chapter 17 of the Java Language Specification. Thread Safety Basics introduces it; here we use it.
