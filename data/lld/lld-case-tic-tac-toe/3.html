Identify the entities (nouns and verbs)

Underline the nouns (candidate classes) and verbs (candidate methods) in the problem, then remove nouns that are only data. The method itself is covered in use cases to classes.

  1. Start from one or two sentences that describe the game. Read them twice.
  2. Underline the nouns: player, symbol, board, cell, line (win), turn, draw.
  3. Underline the verbs. Each becomes a method, and the verb tells you who owns it: the board places, the game decides turns.
  4. Drop nouns that are only data: a symbol is a field of Player, a cell is a char in the board's array, "turn" and "draw" are values the Game keeps.
  5. "Line / win" is behaviour that changes between variants (full line, 4 in a row), so it becomes a strategy interface. A Move records one placed symbol, which gives you undo and replay for free.

A common shape in tutorials is a PlayingPiece base class with PieceX and PieceO subclasses (the Microsoft candidate above used it). The subclasses have no behaviour, only a different letter, so a char symbol on the Player is simpler and allows any number of players. If the interviewer pushes for pieces, say: "I would add classes only when pieces behave differently, as in chess."
