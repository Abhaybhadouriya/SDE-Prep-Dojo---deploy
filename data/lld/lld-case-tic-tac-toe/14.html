Evaluator rubric checklist

  • Runs: a driver plays full games with no manual input, and prints the board.
  • Correct rules: turn order, taken cells, bounds, win before draw, no moves after the end.
  • Win check is incremental (O(1) or O(N)), not a full-board scan, and you can state the complexity.
  • No hard-coded 3: board size, player count and win rule are parameters.
  • Separation: Board knows cells, rule knows winning, Game knows turns and state; I/O is outside all three.
  • Invalid input leaves no trace and gives a clear message.
  • Edge cases tested, not only the happy path.
  • Can extend to K in a row, bots, undo and a web API without rewriting Game.

The machine-coding criteria behind this list (working demo, modularity, extensibility, error handling) are in workattech/flipkart-machine-coding-round.
