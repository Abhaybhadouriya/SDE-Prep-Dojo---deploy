Core flow: making a move

  1. The driver (a test, a console loop, or a web controller) calls the game with the player's name and a cell.
  2. The game takes its lock and checks the two rules it owns: the game is still in progress, and it is this player's turn.
  3. The board checks its own rules (inside the grid, cell empty) and writes the symbol. Each class validates what it owns.
  4. If the board throws, nothing has changed yet: no history entry, no counter update, the turn stays. The same player can try again.
  5. The game pushes the Move onto the history and asks the rule whether this move won. The counter strategy does four increments.
  6. Won: record the winner and stop. Otherwise, if the board is full, DRAW. Otherwise pass the turn to (turn + 1) % k. The new state goes back to the caller.
