The O(1) win check, step by step

The naive check scans all rows, columns and both diagonals after every move: O(N squared) per move. Better: only the row, column and (maybe) diagonals through the last move can have changed, so check just those: O(N). Best: keep a counter per player per line. Placing at (r, c) adds 1 to rows[p][r], cols[p][c], and to diag[p] if r == c, and to anti[p] if r + c == n - 1. If any of these reaches N, player p owns the whole line: O(1) per move, O(k N) memory.

  1. Asha (X) plays (0,0). Row 0, column 0 and the main diagonal each get +1 for X. (0,0) is not on the anti-diagonal (0 + 0 is not 2).
  2. Ben (O) plays (0,1). Only O's counters move. X's tallies are untouched; no scan of the board happens.
  3. X plays the centre (1,1). It is on both diagonals, so four counters move: row 1, column 1, diag and anti.
  4. O plays (0,2). Still nothing reaches 3 for anyone.
  5. X plays (2,2). diag[X] becomes 3, which equals N: X has the whole diagonal. Four integer updates and four compares, whatever the board size.
  6. For exactly two players you can use one counter per line: +1 for X, -1 for O; a line is won when its absolute value reaches N. With k players keep one set per player (our code), because +1/-1 cannot tell three players apart.

Undo is the same update with -1, which is why the strategy interface has an undo method. K in a row (Gomoku, or "4 in a row on 6 x 6") breaks the counter trick, because a line can hold K of yours without being full. There, walk outward from the last move in 4 directions (horizontal, vertical, two diagonals) and count consecutive symbols: O(K) per move, still independent of the board size.
