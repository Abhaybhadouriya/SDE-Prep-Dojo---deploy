Why the pattern earns its place: the if-ladder it replaces

Without the Strategy, every board rule is a branch in the win check:

boolean isWin(Board b, Move m) {
    if (rule == Rule.FULL_LINE) {
        return rowFull(b, m.r) || colFull(b, m.c) || diagFull(b) || antiDiagFull(b);
    } else if (rule == Rule.K_IN_A_ROW) {
        for (int[] d : DIRS) {
            int run = 1 + count(b, m, d[0], d[1]) + count(b, m, -d[0], -d[1]);
            if (run >= k) return true;
        }
        return false;
    } else if (rule == Rule.FOUR_CORNERS) {   // follow-up edits this method...
        ...
    }                                          // ...and undo() needs its own if-ladder
    return false;
}
interface WinStrategy {
    boolean record(Board b, Move m);   // true if m wins
    void undo(Board b, Move m);        // roll back what record() changed
}
final class CounterWinStrategy implements WinStrategy { ... }   // O(1) per move
final class KInARowWinStrategy implements WinStrategy { ... }   // scans 4 directions

GameState makeMove(...) { ...; if (strategy.record(board, move)) state = WON; ... }

With the ladder, the follow-up "four corners also win" edits isWin and undo in Game. With the interface it is one new class, and Game is unchanged.

From your world: the same move in C

struct win_ops {
    bool (*record)(struct win *w, const struct board *b, const struct move *m);
    void (*undo)(struct win *w, const struct board *b, const struct move *m);
};
/* game->win->ops->record(game->win, &game->board, &mv);  no switch on the rule */

The "after" version is an ops table: the caller holds a pointer to a struct of function pointers and never asks which implementation it has, exactly as the VFS calls file->f_op->read() without a switch on the file system type.

The move history is a journal you replay backwards: undo() pops the last Move and asks the strategy to subtract exactly what record() added, like rolling back a write-ahead log entry.
