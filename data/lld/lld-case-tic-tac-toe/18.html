Quiz

With per-player line counters, what does a win check cost per move on an N x N board?

  1. O(N squared)
  2. O(1)
  3. O(log N)
  4. O(N)
At most four counters change (row, column, two diagonals) and each is compared with N.

A move at (1, 2) on a 4 x 4 board updates which diagonal counters?

  1. Main diagonal only
  2. Both
  3. Anti-diagonal only (1 + 2 = 3 = n - 1)
  4. Neither
Main diagonal needs r == c; anti-diagonal needs r + c == n - 1, which is 3 here.

Why does the single +1/-1 counter trick fail with three players?

  1. It needs floating point
  2. Counters overflow
  3. It uses too much memory
  4. One shared sum mixes everyone's pieces, so "sum reached the target" no longer proves all N cells belong to one player
With two players, |sum| == N only when all N pieces have the same sign. With three players a single +/- sum cannot separate them; keep one set of counters per player.

The ninth move fills the board and completes a row. What must the game report?

  1. An error
  2. Depends on the player
  3. DRAW
  4. WON
Check the winning move before checking "board full".

The interviewer says "now 5 in a row wins on 15 x 15". The cleanest change is:

  1. Increase the counter target to 5
  2. Add an if-else for the new rule inside makeMove
  3. Pass a KInARowWinStrategy(5) to the Game
  4. Subclass Game as GomokuGame
The win rule is the strategy. Raising the counter target is wrong: counters count pieces anywhere in the line, not consecutive ones.

An invalid move (taken cell) arrives. Which statement is true in a good design?

  1. Nothing changes: board, counters, history and turn are untouched
  2. The move is stored and marked invalid
  3. The turn passes to the next player
  4. The game ends
Validate, then mutate. The same player plays again.
