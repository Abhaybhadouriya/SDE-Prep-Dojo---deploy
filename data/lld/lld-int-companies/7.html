Interview questions about the round itself

Questions candidates ask (or get asked) about these formats, with how to handle them. Use the filters to pick a company.

The recruiter says "machine coding round". What exactly should I expect?

At Flipkart, PhonePe, Razorpay, Meesho, Groww and CRED it means: a written problem with P0 and bonus features, 90-120 minutes to build it in memory, and a driver or tests that demo it. Then a review where someone runs it and asks why you built it that way.

How to answer

Ask four things: own IDE or browser? any language? tests or boilerplate provided? AI allowed? Then practise in that exact setup.

Likely follow-ups
  • Is the review the same day? (Flipkart often same day; PhonePe 1-2 days later.)
  • Can I use the internet? (Flipkart: syntax lookups only.)
Amazon: should I draw UML or write code in the LLD round?

Both, briefly. Amazon's official SDE-II page asks for syntactically correct, tested code in coding interviews, and candidates report LLD rounds that want a class sketch plus key methods in real code (post 8382978 (2026-07-07)). With Leadership Principle questions in the same hour, you may get only 25-35 minutes.

How to answer

2-3 min clarify, 8 min classes and relationships as a quick list or diagram, 12 min code for the 2-3 methods that carry the logic, 5 min on one extension and one concurrency point.

Likely follow-ups
  • Which pattern did you use and why? (name the change it absorbs: Strategy for the assignment rule, because the interviewer is likely to change that rule)
  • How do you add a new type without changing old code? (add one class behind the existing interface and register it in the factory map; no if/else chain grows)
The round is "AI-assisted". How do I use the AI without hurting my score?

Reports from Razorpay (post 7575649 (2026-02-13)) and Microsoft (post 8462091 (2026-08-15)) say the interviewer grades how you use the tool: how you frame prompts, refine them, and judge the result. Copying output wholesale is the weak signal.

How to answer
  1. Say your design (entities, interfaces, the tricky part) before opening the tool.
  2. Ask narrow questions: "write a comparator for these fields", "generate 10 test inputs".
  3. Read every line; say what you keep and what you reject.
  4. Own the tricky logic (locking, state transitions) yourself.
Likely follow-ups
  • What did the AI get wrong here? (have a concrete answer ready: a missed edge case, a race it did not lock, or an API it made up; it shows you read every line)
  • Would you ship this code? What would you change? (say what is missing for production: persistence behind the repository, input validation at the edge, logging and metrics, tests for the races)
Flipkart bans AI. What else is not allowed?

The 2026 guidelines in a posted problem statement (post 7588244 (2026-02-18)) say: no AI tools, internet only for syntax, no external database (in-memory only), no UI and no HTTP API (a standalone app), and a driver, main class or tests so the evaluator can run it. Bonus features only after P0.

How to answer

Have a skeleton you can type from memory. Know your language's collections, sorting and string parsing without looking things up.

Likely follow-ups
  • What would change if we added a real DB? (Swap the repository implementation.)
Uber: is the 60-minute LLD round machine coding or LeetCode?

Candidates describe it as backend machine coding in a 60-minute slot: running code, often with threads (post 8306891 (2026-06-01)). Problems like a non-blocking pub-sub (post 1091960 (2021-03-03, older post)) or a scheduler with a configurable worker pool and no library scheduler (post 891551 (2020-10-12, older post)) show the flavour.

How to answer

Scope hard in the first 5 minutes; get a single-threaded version running by minute 35; then add the concurrency piece the interviewer cares about.

Likely follow-ups
  • What if two threads assign the same driver? (make check-and-claim one atomic step: a lock per driver, or a compare-and-set of the driver's state from AVAILABLE to ASSIGNED; the loser picks the next driver)
  • How would you test this? (unit tests per service rule, then a race test: N threads behind a start latch call the same method, and you assert exactly one wins)
Atlassian code design: how many tests, and when do I write them?

Atlassian's own guide calls testing crucial and suggests brushing up on TDD; you bring your IDE and test framework. The problem then grows in stages (post 6770783 (2025-05-22)).

How to answer

One test per rule, written right before or after the code for that rule. Keep them fast. When a new stage arrives, add a failing test first, then change the code - this shows the design absorbs change.

Likely follow-ups
  • What other design would you consider, and why not? (name one real alternative (for example an event log instead of mutable state) and the cost that ruled it out for this size)
  • How does your code handle ties or invalid input? (a stated tie-break (earliest first, then id) in the comparator, and invalid input rejected at the service edge with a named exception)
Which companies will push concurrency inside the LLD round?

In our reports: Walmart (executors, thread pools, singletons - post 7620235 (2026-03-02)), Microsoft (parking spot locking - post 7354634 (2025-11-17)), Meesho (stock and ticket limits - post 5049988 (2024-04-20, older post)), Flipkart 2026 (thread safety as a core requirement - post 7588244 (2026-02-18)), Uber, Rubrik and Adobe.

How to answer

Name the shared state, the operation that must be atomic (check-then-act), the lock and its scope (per spot, per item), and why not coarser or finer. See booking concurrency.

Likely follow-ups
  • Optimistic or pessimistic? When each? (pessimistic locks when conflicts are frequent or a retry is expensive; optimistic version checks when conflicts are rare and reads dominate)
  • How do you avoid deadlock with two locks? (take them in one fixed global order (for example by id), or use tryLock with a timeout and back off)
The platform has pre-written tests. Do I still design?

Yes. At CRED the stated rubric includes extensibility and SOLID on top of passing tests (post 3984528 (2023-08-31, older post)). Tests tell you the API; design decides how cleanly you meet it.

How to answer

Read all tests first (10 min). List the classes the tests imply. Make tests pass one group at a time; refactor between groups.

Likely follow-ups
  • Add a new instruction / feature: how many files change? (the target is one new class plus one registration line; if three services change, the design has a missing seam)
What do they ask in the review call after machine coding?

PhonePe reviewers asked about structure, how to extend for a new use case, how to make it production ready, which DB, and whether parts would be separate services (post 3671731 (2023-06-23, older post)). A Cleartrip review moved quickly to concurrency: two users ordering the last item, item-level vs restaurant-level locking, optimistic vs pessimistic (post 8411392 (2026-07-21)).

How to answer

Prepare a 2-minute tour of your code, then the three standard answers: new feature (which interface), new store (swap the repository), more traffic (which state is shared and how you protect it).

Likely follow-ups
  • Which design patterns did you use? Where would one be overkill? (list each with the change it absorbs; a Factory for a single concrete class, or an Observer with one fixed listener, is overkill)
A third-party interviewer runs my LLD round. Is it different?

Zepto and Swiggy reports describe 60-min LLD rounds run by interview platforms. They expect requirements, a class diagram, DB schema and APIs in one hour, and some candidates report the round drifting into HLD.

How to answer

Timebox each part out loud: 5 min requirements, 15 classes, 10 schema, 10 APIs, the rest for deep dives. If the interviewer drifts to scale, follow but tie it back to your classes.

Likely follow-ups
  • Why SQL here? What indexes? (bookings and balances need transactions and unique constraints; index the columns you look up and check overlaps on (user_id, slot_id, status))
Can I use C++ (or C) in an LLD round?

Most machine-coding rounds allow any mainstream language (Flipkart and PhonePe say so explicitly). C++ was used in reports at Razorpay (post 7600874 (2026-02-22)) and Adobe, where the round tested RAII and smart pointers (post 8569781 (2026-10-13)). Plain C is rarely practical: you need interfaces, collections and quick string handling.

How to answer

Pick one OO language and stay with it. One Uber candidate's lesson was to master a single language rather than switch (post 8488522 (2026-08-29)).

Likely follow-ups
  • How do you express an interface in C++? (pure virtual class)
The interviewer switched from LLD to HLD halfway. What now?

It happens in "LLD+HLD" rounds (13 reports in our set), at Microsoft, Adobe and Salesforce among others. The interviewer is testing range.

How to answer

Finish the sentence you were on, summarise your class model in one line, then move up: which classes become services, which maps become tables or caches, where queues go.

Likely follow-ups
  • How does your in-memory lock become a distributed one? (a database row lock or a conditional update in one store, or a lease in Redis or ZooKeeper with a fencing token; prefer the database you already have)
