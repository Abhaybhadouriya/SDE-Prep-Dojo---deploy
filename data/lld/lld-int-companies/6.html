Company by company

Each block: how the round runs, what was asked recently, and how to prepare. The full dated list of every report for that company is in Recently asked LLD questions.

Flipkart (and Cleartrip) - the reference machine-coding round

  • Flow: recruiter form, a group Meet where an engineer walks through the problem (about 30 min), 90-120 min of coding, zip and upload through a form, then an evaluation call where an engineer runs your code and asks about choices (post 5221179 (2024-05-28, older post), post 6687653 (2025-04-26)).
  • Problem shape: a business app with P0 features and bonus features: BNPL (post 8331479 (2026-06-13)), quick commerce with explicit thread safety and auto-cancel after 30 minutes (post 7588244 (2026-02-18)), a Q&A feed (post 5221179 (2024-05-28, older post)), task scheduler (post 7591327 (2026-02-19)).
  • Feedback seen: "SRP and separation of concerns not followed; modular but not extensible" (post 3365100 (2023-04-01, older post)).
  • Prepare: a reusable skeleton (code layout), timed 90-minute builds, a driver that demos every feature. Guide: Flipkart guide.

Uber - 60 minutes, code must run, threads likely

  • Flow: a 60-min "Coding 2 / Depth in Specialization" round on CodeSignal, HackerRank or in person. Candidates describe building from scratch or modifying a codebase, then discussing production (post 8306891 (2026-06-01)).
  • Repeats: in-memory file system with mkdir/cd and wildcards (post 8454718 (2026-08-11), post 8018831 (2026-04-20)), Kafka-like pub-sub where publishers and subscribers never block each other (post 1091960 (2021-03-03, older post), post 8084315 (2026-04-23)), ride hailing without double-assigning a driver (post 8488522 (2026-08-29), post 8476675 (2026-08-22)), TTL counter (post 7381396 (2025-11-29)).
  • Prepare: type fast in one language, know your concurrency toolkit (producer-consumer, locks). Guide: Uber guide.

Atlassian - code design with tests and staged follow-ups

  • Official: the coding stage has two parts, data structures and code design; 60 minutes; your own IDE with a test framework ready; thinking and trade-offs matter most; testing is called crucial.
  • Repeats: snake game (post 7565749 (2026-02-09)), agent rating system with averages and ties, wildcard router / path key-value store (post 8293408 (2026-05-25)), subscription cost explorer (post 6770783 (2025-05-22)).
  • Watch out: reports say level decisions (down-levelling) often come from this round; typos ate minutes in one report (post 8293408 (2026-05-25)).
  • Prepare: TDD-style practice: write a test, make it pass, add the next rule. Guide: Atlassian guide.

Swiggy - machine coding at SDE-2, LLD rounds by third parties

  • Flow: older SDE-2 drives ran a 2-hour machine coding with Splitwise, where the interviewer ran test cases near the end (post 1777862 (2022-02-17, older post)). Recent rounds are often a 60-min LLD run by a third-party platform with classes, APIs and DB schema (post 7714478 (2026-03-29), post 7702687 (2026-03-27)).
  • Repeats: Splitwise (post 8604140 (2026-11-07)), notification system, parking lot (post 7480610 (2026-01-09)), logger, cart and coupons.
  • Prepare: both a running solution and a 60-min whiteboard version of each. Guide: Food & quick-commerce guide.

PhonePe - working code is the gate

  • Flow: machine coding first (live 90-120 min or a one-day take-home), then a 30-45 min review 1-2 days later on structure, extension, production readiness and patterns (post 3671731 (2023-06-23, older post)).
  • Repeats: customer issue resolution (post 7539137 (2026-01-31)), hackathon platform with pluggable scoring (post 8382058 (2026-07-07)), app version rollout, leaderboard (post 7474219 (2026-01-07)), stage workflow engine (post 8566190 (2026-10-10)), resource allocation with a waiting queue and concurrency as P1 (post 4406681 (2023-12-15, older post)).
  • Prepare: compile as you go; if time runs out, leave a comment like "this should be an interface" rather than nothing. Guide: Indian fintech guide.

Razorpay - live machine coding, AI sometimes allowed

  • Flow: a live round with an interviewer on Meet; your IDE; run manual test cases. Lead roles had 90-min AI-allowed rounds (post 7575649 (2026-02-13)).
  • Repeats: in-memory search engine, ordered pub-sub with offsets (post 7600874 (2026-02-22)), load balancer (post 7360702 (2025-11-19)), git-like VCS (post 7273127 (2025-10-13)), equal-split Splitwise that must extend to other splits.
  • Feedback seen: not modular, not extensible, missing validations (post 6888761 (2025-06-26)); drifting from the asked problem (post 6012081 (2024-11-05)).
  • Prepare: make deletion and update paths work, not only inserts - one 2026 candidate ran out of time on remove (post 7575649 (2026-02-13)).

Amazon - OOD inside a 55-minute loop interview

  • Official: the SDE-II loop is four 55-minute interviews; code should be syntactically correct, tested and handle edge cases.
  • Reality: Leadership Principle questions take part of the hour, so design time is short; requirements are often withheld so you must clarify; a weak LLD can trigger an extra LLD round (post 8612260 (2026-11-14), post 6725210 (2025-05-08)).
  • Repeats: parking lot (post 8525216 (2026-09-16)), logging framework (post 8523912 (2026-09-16)), notification system, vending machine (post 7397939 (2025-12-07)), package tracking (post 8575909 (2026-10-17)), an agentic chatbot (post 8585902 (2026-10-24)).
  • Prepare: a 25-minute version of each classic: classes, relationships, 2-3 key methods in real code, one pattern explained. Guide: Amazon guide.

Microsoft - varies by interviewer

  • Official: the technical interview covers problem solving, design, coding (no pseudocode) and testing your own code.
  • Reality: some want running code end to end (post 6110098 (2024-12-03)), some whiteboard only (post 7636712 (2026-03-09)). Concurrency follow-ups are common: the candidate in post 7354634 (2025-11-17) chose pessimistic locking for parking spots.
  • Repeats: parking lot (post 7619101 (2026-03-02), post 7620569 (2026-03-02)), LRU (post 8477383 (2026-08-23)), rate limiter (post 7498667 (2026-01-16)), snake and ladder (post 7357425 (2025-11-18)), news feed (post 7336181 (2025-11-09)), feature flags (post 7323765 (2025-11-03)).
  • Prepare: be ready for both styles; ask in the first minute. Guide: Microsoft guide.

Google - no separate LLD round

  • Candidates at L3/L4 report no standalone LLD round (post 7357187 (2025-11-18)). Design shows up as "implement this class" inside coding, with thread-safety follow-ups - one candidate found plain synchronized was not enough for a thread-safe LFU cache (post 379416 (2019-09-10, older post)).
  • Prepare: treat OOD as a coding skill: clean class APIs and complexity. Guide: Google guide.

Walmart - design mixed with Java depth

  • Flow: a 60-min "LLD + Java" round that often turns into concurrency: executors, futures, locks, singleton with double-checked locking and volatile (post 6146141 (2024-12-14)).
  • Repeats: design a ThreadPoolExecutor (post 7620235 (2026-03-02)), LRU (post 8299285 (2026-05-28)), rate limiter, wallet, Splitwise.
  • Prepare: thread pools and thread-safe singletons. Guide: Walmart guide.

Salesforce - LLD + coding, or DSA + LLD

  • Flow: 60-90 min on HackerRank or a doc; design first, then implement core logic (post 8461667 (2026-08-15)).
  • Repeats: parking lot, BookMyShow (post 8354296 (2026-06-23)), thread-safe task scheduler (post 7619394 (2026-03-02)), news-alert subscriptions (post 8617812 (2026-11-19)), ride hailing (post 7398700 (2025-12-07)), LRU, Ludo.
  • Prepare: Observer-style subscription problems and schedulers. Guide: Salesforce guide.

CRED - make the given tests pass

  • Flow: HackerRank machine coding with model classes and unit tests already written; you extend the code and keep SOLID (post 3984528 (2023-08-31, older post)). Some rounds ask you to extend an existing codebase (post 7415867 (2025-12-15)). The 2025-26 onsite SDE-2 round was an "AI-native" design + LLD followed by a 24-hour prototype (post 7463243 (2026-01-03)).
  • Lesson from a rejection: one class per register (A, B, C, D) instead of one Register type in a map plus a Command per instruction (post 3984528 (2023-08-31, older post)). Class per concept, not per instance.
  • Prepare: read given tests as the spec; practise Command. Guide: Indian fintech guide.

Meesho - constraints and concurrency

  • Flow: 60-90 min HackerRank machine coding with pre-written test cases; around 7 P0 features plus bonuses.
  • Repeats: inventory with reserve-at-create and commit-at-confirm (post 5925685 (2024-10-17), post 7854949 (2026-04-10)), sprint planner where concurrent edits must keep "max 2 in-progress tickets per user" (post 5049988 (2024-04-20, older post)), stock exchange order book with concurrency (post 8399121 (2026-07-15)), clinic booking with waitlist (post 6702200 (2025-04-30)).
  • Prepare: booking and reservation concurrency.

Zepto and Groww

  • Zepto: 60-min LLD run by a third-party platform, expecting requirements, class diagram, DB schema and APIs; calendar (post 7353272 (2025-11-16)), chess (post 8299909 (2026-05-29)), quick commerce. Guide: Food & quick-commerce guide.
  • Groww: 60-120 min machine coding in your IDE: stock exchange with partial fills (post 8021077 (2026-04-21)), brokerage calculator (post 8539548 (2026-09-25)), wallet ledger (post 8537835 (2026-09-24)).
