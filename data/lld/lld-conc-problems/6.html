5. FizzBuzz Multithreaded: one monitor, four predicates

Problem (LeetCode 1195): four threads print "fizz", "buzz", "fizzbuzz" or the number, for 1..n, in order. Semaphores would need a routing table. A monitor is simpler: one shared counter cur, and each thread sleeps until cur is a number it owns.

class FizzBuzz {
    private final int n;
    private int cur = 1;                                   // guarded by "this"
    FizzBuzz(int n) { this.n = n; }

    private synchronized void loop(IntPredicate mine, IntConsumer act) throws InterruptedException {
        while (true) {
            while (cur <= n && !mine.test(cur)) wait();      // WHILE, never IF
            if (cur > n) { notifyAll(); return; }            // wake the others so they can exit too
            act.accept(cur);
            cur++;
            notifyAll();
        }
    }
    void fizz(Runnable p) throws InterruptedException     { loop(i -> i % 3 == 0 && i % 5 != 0, i -> p.run()); }
    void buzz(Runnable p) throws InterruptedException     { loop(i -> i % 5 == 0 && i % 3 != 0, i -> p.run()); }
    void fizzbuzz(Runnable p) throws InterruptedException { loop(i -> i % 15 == 0, i -> p.run()); }
    void number(IntConsumer p) throws InterruptedException { loop(i -> i % 3 != 0 && i % 5 != 0, p); }
}

Three rules make every monitor correct, and interviewers check all three:

  1. Wait in a while loop. A thread can wake up without its condition being true (a spurious wake-up, or another thread got there first). Re-check after every wake-up.
  2. Change state, then notify, while holding the lock. Otherwise a waiter can miss the wake-up (a lost wake-up).
  3. Use notifyAll when waiters wait for different things. notify wakes one random waiter, which may be the wrong one; it then sleeps again and the program stalls.
