4. Building H2O: limit the group, then release it together

Problem (LeetCode 1117): hydrogen and oxygen threads arrive in any order. Each must call its release function, and the output, read in groups of three, must always be two H and one O. A thread may not run ahead into the next molecule.

This is the first puzzle with two different rules, so it needs two tools:

  1. Who may enter the current molecule? At most 2 H and 1 O. A counting rule = semaphores with 2 and 1 permits.
  2. When may they leave? Only when all three are present. "Wait until N arrive" = a barrier of 3.
class H2O {
    private final Semaphore hSlots = new Semaphore(2);      // at most 2 H in the current molecule
    private final Semaphore oSlots = new Semaphore(1);      // at most 1 O in the current molecule
    private final CyclicBarrier bond = new CyclicBarrier(3); // leave together

    void hydrogen(Runnable releaseH) throws Exception {
        hSlots.acquire();
        try { releaseH.run(); bond.await(); } finally { hSlots.release(); }
    }
    void oxygen(Runnable releaseO) throws Exception {
        oSlots.acquire();
        try { releaseO.run(); bond.await(); } finally { oSlots.release(); }
    }
}
// Without a barrier type, use one monitor with two counters.
class H2O {
public:
    void hydrogen(const std::function<void()>& releaseH) { enter('H', releaseH); }
    void oxygen(const std::function<void()>& releaseO)   { enter('O', releaseO); }
private:
    void enter(char kind, const std::function<void()>& release) {
        std::unique_lock<std::mutex> lk(m_);
        if (kind == 'H') { cv_.wait(lk, [this] { return h_ < 2; }); ++h_; }
        else             { cv_.wait(lk, [this] { return o_ < 1; }); ++o_; }
        release();                                   // printed under the lock: groups never interleave
        if (h_ == 2 && o_ == 1) { h_ = 0; o_ = 0; cv_.notify_all(); }   // molecule done
    }
    std::mutex m_;
    std::condition_variable cv_;
    int h_ = 0, o_ = 0;
};

Why the Java version cannot mix molecules. A permit is returned only after bond.await() returns, which happens only after all three members of the molecule have printed. So the next molecule cannot gather 2 H + 1 O until every member of the current one has printed. The C++ version reaches the same guarantee differently: the counters reset only when the molecule is complete, and printing happens while holding the lock.

Our driver feeds the input OOHHHHHHO (oxygen first, on purpose) 200 times and checks every group of three. Both versions passed every run; the C++ build also ran clean under ThreadSanitizer (-fsanitize=thread) with zero warnings.
