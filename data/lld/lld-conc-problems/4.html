3. Zero Even Odd: a baton with three runners

Problem (LeetCode 1116): three threads. One prints only zeros, one only odd numbers, one only even numbers. For n = 5 the output must be 0102030405.

Spot the tool. Still a single baton, but now the zero thread decides who runs next: after printing 0 before number i, it hands the baton to "odd" if i is odd, else to "even". Each of those hands it straight back. One semaphore per runner, and only one permit in the whole system.

class ZeroEvenOdd {
    private final int n;
    private final Semaphore zero = new Semaphore(1), odd = new Semaphore(0), even = new Semaphore(0);
    ZeroEvenOdd(int n) { this.n = n; }

    void zero(IntConsumer out) throws InterruptedException {
        for (int i = 1; i <= n; i++) {
            zero.acquire();
            out.accept(0);
            if (i % 2 == 1) odd.release(); else even.release();   // route the baton
        }
    }
    void odd(IntConsumer out) throws InterruptedException {
        for (int i = 1; i <= n; i += 2) { odd.acquire(); out.accept(i); zero.release(); }
    }
    void even(IntConsumer out) throws InterruptedException {
        for (int i = 2; i <= n; i += 2) { even.acquire(); out.accept(i); zero.release(); }
    }
}

Tip: the loop bounds matter. If the odd thread looped "while true" it would sleep forever after the last number and the program would never exit. Count the work each thread owns up front, or add an explicit "finished" flag that wakes everyone.
