1. Print in Order: a one-shot gate

Problem (LeetCode 1114): one object, three methods first(), second(), third(). Three threads call them in any order. The output must always be firstsecondthird.

Spot the tool. Each step happens exactly once, and "step 1 is done" never becomes false again. A one-shot event that stays true is a latch. We need two of them: "first is done" and "second is done".

class InOrder {
    private final CountDownLatch firstDone = new CountDownLatch(1);
    private final CountDownLatch secondDone = new CountDownLatch(1);

    void first(Runnable p) { p.run(); firstDone.countDown(); }
    void second(Runnable p) throws InterruptedException {
        firstDone.await(); p.run(); secondDone.countDown();
    }
    void third(Runnable p) throws InterruptedException {
        secondDone.await(); p.run();
    }
}
class InOrder {
public:
    void first(const std::function<void()>& p)  { run(1, p); }
    void second(const std::function<void()>& p) { run(2, p); }
    void third(const std::function<void()>& p)  { run(3, p); }
private:
    void run(int myStage, const std::function<void()>& p) {
        std::unique_lock<std::mutex> lk(m_);
        cv_.wait(lk, [&] { return stage_ == myStage; });  // sleep until it is my turn
        p();
        ++stage_;
        cv_.notify_all();          // two waiters with different predicates: wake both
    }
    std::mutex m_;
    std::condition_variable cv_;
    int stage_ = 1;
};

The C++ version shows the general answer: a single integer stage, a lock, and a condition variable. Every turn-taking puzzle can be solved this way. Latches and semaphores are shortcuts that make the code shorter and harder to get wrong.

Careful: notify_one() here would be a bug. If it wakes thread C while the stage is 2, C goes back to sleep and B is never woken. With several waiters that wait for different things, wake them all.
