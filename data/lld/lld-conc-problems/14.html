Remember this

  • Every puzzle is a relay: decide the baton, who waits for it, who hands it on.
  • Six tools: latch (once), semaphore (turns, at most K), barrier (N leave together), monitor (wait for a predicate), lock ordering (two resources), executor + concurrent set (many jobs).
  • A different thread hands over the turn: semaphore or condition, never a bare mutex.
  • Monitor rules: wait in a while loop, change state and notify under the lock, notifyAll when waiters want different things.
  • Deadlock needs a cycle; global lock order breaks it. Fairness is a separate question.
  • Termination is part of the design: fixed loop counts, a closed flag, or an in-flight counter.
  • Release in finally; never hold a lock while doing slow work.
  • Test hundreds of runs with the worst start order; in C++ run ThreadSanitizer.
