In FooBar, what are the starting permits of fooTurn and barTurn?

  1. 1 and 1
  2. 1 and 0
  3. 0 and 0
  4. 2 and 0
Exactly one permit exists, and it starts on foo's side, so foo prints first and the two threads strictly alternate.

Why is a mutex the wrong tool for passing a turn between two threads?

  1. It is too slow
  2. It cannot be used in Java
  3. Only the thread that locked it may unlock it
  4. It allows two owners
Ownership: the unlocking thread must be the locking thread. A semaphore permit can be released by any thread, which is exactly what a handover needs.

In Print in Order, which tool fits "first() has finished" best?

  1. A latch (one-shot gate)
  2. A read-write lock
  3. A barrier of 3
  4. An AtomicInteger with busy-waiting
The event happens once and stays true. That is a latch (CountDownLatch, or the kernel's completion).

Which Coffman condition does "always take the lower-numbered fork first" remove?

  1. Mutual exclusion
  2. Hold and wait
  3. No preemption
  4. Circular wait
With a global order, the wait-for graph can only point "upward", so no cycle can form.

In the multithreaded web crawler, why is "the queue is empty" not a valid stop condition?

  1. Queues are not thread-safe
  2. A running task may still add new URLs
  3. The executor never empties its queue
  4. Duplicates stay in the queue
Work in flight can create more work. Count tasks in flight and stop when that count reaches zero.

A monitor-based solution uses if (!myTurn) wait();. What can go wrong?

  1. Nothing, if notifyAll is used
  2. It deadlocks immediately
  3. After a spurious or stolen wake-up, the thread runs when it is not its turn
  4. It throws an exception every time
Always re-check the predicate in a while loop after waking.

Strict FIFO in the shared-bathroom problem guarantees no starvation. What does it cost?

  1. Throughput: free slots stay empty when the head of the queue is from the other party
  2. Correctness: parties can mix
  3. It needs two locks
  4. It cannot be written in Java
FIFO blocks a same-party person behind an other-party head. Batching recovers throughput while still bounding the wait.
