8. The shared bathroom: a monitor with a fairness rule

Problem (reported in a Rubrik multithreading round, post, 2024-05; it is a variant of the "unisex bathroom" problem in The Little Book of Semaphores): one bathroom, capacity 3, people from two parties (D and R). The room may never hold a mix of parties. People wait in a queue; the next eligible person should get in as soon as there is room. The candidate in that report says they were asked to compare scheduling policies and then implement FIFO.

void use(char who, Runnable business) throws InterruptedException {
    lock.lock();
    long me;
    try {
        me = nextTicket++;
        queue.addLast(me);
        // FIFO: only the head may enter, and only if the room fits it
        while (queue.peekFirst() != me || !(inside == 0 || (party == who && inside < capacity)))
            changed.await();
        queue.pollFirst();
        party = who;
        inside++;
        changed.signalAll();             // the next person may be able to follow us in
    } finally { lock.unlock(); }

    try { business.run(); }              // never hold the lock during the slow part
    finally {
        lock.lock();
        try {
            if (--inside == 0) party = ' ';
            changed.signalAll();
        } finally { lock.unlock(); }
    }
}

Our driver sends 18 people (DDRDDDRRRDRRDDDRDR) through at once. The check counts "mixes" (someone leaving while the room holds the other party) and the peak occupancy: 0 mixes, peak 3.

Name the trade-off out loud: "FIFO guarantees no starvation but wastes free slots; batching keeps most of the throughput and still bounds the wait." This is the same fairness discussion as read-write locks (reader preference vs writer preference).
