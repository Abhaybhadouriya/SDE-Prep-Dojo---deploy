APIs and interfaces

Write these on the board, or as Java signatures, before writing any method body.

// service API
List<Offer> search(String city, RoomType type, DateRange stay, int rooms);       // cheapest first
Booking     hold(String guest, String hotelId, RoomType type, DateRange stay, int rooms); // throws if not enough rooms
Booking     confirm(String bookingId, String paymentRef);   // idempotent per paymentRef; throws if expired
long        cancel(String bookingId);                       // returns refund in paise
int         expireHolds();                                  // sweep; also called lazily by search and hold
void        addListener(BookingListener l);

// extension points
interface PricingStrategy    { long price(long nightlyRatePaise, DateRange stay, int rooms); }
interface CancellationPolicy { long refund(Booking b, LocalDateTime now); }
interface BookingListener    { void onChange(Booking b); }
interface TimeSource         { LocalDateTime now(); }

And the schema, because both Zepto reports asked for one. The key table is the per-night counter; the unique key and the check constraint make overbooking impossible even if application code has a bug:

CREATE TABLE room_type_inventory (
  hotel_id   BIGINT  NOT NULL,
  room_type  TEXT    NOT NULL,
  night      DATE    NOT NULL,
  total      INT     NOT NULL,
  reserved   INT     NOT NULL DEFAULT 0,
  PRIMARY KEY (hotel_id, room_type, night),
  CHECK (reserved <= total)
);
CREATE TABLE booking (
  id BIGINT PRIMARY KEY, guest_id BIGINT, hotel_id BIGINT, room_type TEXT, rooms INT,
  check_in DATE, check_out DATE, price_paise BIGINT, status TEXT,
  hold_expires_at TIMESTAMP, payment_ref TEXT UNIQUE
);
