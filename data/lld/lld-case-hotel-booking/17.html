A hotel has 2 double rooms. Reserved counts are: 18 Dec = 1, 19 Dec = 2, 20 Dec = 0. How many doubles can be sold for the stay 18..21?

  1. 2
  2. 3
  3. 1
  4. 0
Free is the minimum over the nights: 2-1, 2-2, 2-0 gives 1, 0, 2, so the minimum is 0. The 19th is full.

Alice has the last double for 18..21. Can Bob book the same type for 21..23?

  1. Only with a suite upgrade
  2. No, the 21st overlaps
  3. Yes, the ranges are half-open so the 21st is not one of Alice's nights
  4. Only if Alice checks out early
18..21 covers the nights of the 18th, 19th and 20th. The 21st is Alice's check-out morning.

A hotel wants a weekend surcharge AND a long-stay discount. Which design adds this without new combined classes?

  1. An if/else chain in hold()
  2. Decorators that wrap a base pricing strategy
  3. A Singleton price calculator
  4. A subclass of Hotel for each pricing rule
Each decorator adds one rule and calls the inner strategy, so rules combine by wrapping.

A hold expired 30 seconds ago but no sweep has run. The payment callback now calls confirm. What should happen?

  1. Extend the hold by 15 minutes
  2. Confirm it: the rooms are still reserved
  3. Mark it EXPIRED, release the rooms, and fail so the payment is refunded
  4. Ignore the call
Correctness must not depend on the sweep. Confirm checks the time itself and follows the state machine.

Why does our code take one lock per hotel rather than one global lock?

  1. It avoids the need for a state machine
  2. Global locks are not allowed in Java
  3. Bookings in different hotels never wait for each other, and each booking needs only one lock
  4. It makes search results sorted
Per-hotel locking gives parallelism across hotels with no lock-ordering risk, because a booking touches one hotel.

In SQL, which statement books 1 room for 3 nights safely in one step?

  1. UPDATE ... SET reserved = reserved + 1 WHERE the 3 nights match AND reserved + 1 <= total, then require 3 rows updated
  2. DELETE the inventory rows
  3. SELECT the free count, then UPDATE in a separate request
  4. UPDATE ... SET reserved = reserved + 1 with no WHERE on capacity
The guarded update checks and acts in one statement; fewer than 3 rows updated means a night was full, so roll back.

The gateway retries confirm(B1, PAY-778) after a timeout. What does our service do on the second call?

  1. Throws "cannot go from CONFIRMED to CONFIRMED"
  2. Creates booking B2
  3. Charges the guest again
  4. Returns B1 unchanged, because it is already confirmed with that reference
Confirm is idempotent per payment reference; only a different reference on a confirmed booking is an error.
