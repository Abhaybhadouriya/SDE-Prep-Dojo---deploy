Core flow: one call to allow()

This is the only interesting flow, and it is the one interviewers ask you to walk through. Here alice calls /refund, which has its own rule and also belongs to the money group.

  1. The request handler (or a filter in front of it) calls allow. The service reads the clock once, so every limiter in this call sees the same instant.
  2. It builds one key per applicable rule and gets each limiter with computeIfAbsent. The first request for a key creates the limiter through the factory, atomically.
  3. With more than one rule, the limiters are wrapped in a composite. The per-API limiter says yes and takes a permit.
  4. The group limiter says no: alice already used 3 of /pay + /refund this minute.
  5. The composite gives back the permit the API limiter took. Without this, a rejected request would still eat alice's /refund quota.
  6. The answer is false. The HTTP layer turns it into 429 Too Many Requests (RFC 6585), ideally with a Retry-After header.
