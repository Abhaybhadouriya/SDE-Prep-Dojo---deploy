From your world

The Limiter interface is a two-entry ops table, like struct file_operations with only .read and .write. Each algorithm object is the private_data plus its ops. The factory is the switch in a driver's probe that picks which ops table to install. And the composite is a tiny netfilter hook chain: every hook must return NF_ACCEPT, and the first NF_DROP stops the walk.

Why not one class with a switch(algorithm) inside allow()? Each algorithm needs different state (a deque, two counters, a double). One class would carry all of them as fields, most unused, and every new algorithm would edit that class and risk breaking the others. That is exactly the Open/Closed violation evaluators mark down.
