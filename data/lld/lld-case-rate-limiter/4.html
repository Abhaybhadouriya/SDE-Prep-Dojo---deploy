The five algorithms in one picture

Before the class diagram, be sure you can explain each algorithm in one sentence. Every one of them answers the same question, "may this request pass right now?", with a different trade-off between accuracy, memory and burst tolerance.

  1. Fixed window: one counter per aligned window. Cheapest, but a client can send limit at the end of one window and limit again at the start of the next.
  2. Sliding window log: remember the time of every accepted request in the last window; drop old ones; allow if fewer than limit remain. Exact, but memory grows with the limit.
  3. Sliding window counter: two counters (previous and current window) and a weighted sum. O(1) memory, close to exact; it assumes the previous window's requests were spread evenly.
  4. Token and leaky bucket: a level that changes with elapsed time. Token bucket allows bursts up to capacity; leaky bucket as a meter keeps the output smooth.

Leaky bucket has two meanings. As a queue, requests wait in a FIFO that drains at a fixed rate (traffic shaping, like a qdisc). As a meter, it only decides yes/no, and it is then the mirror image of a token bucket. We implement the meter, because allow() must not block. Say which one you mean.
