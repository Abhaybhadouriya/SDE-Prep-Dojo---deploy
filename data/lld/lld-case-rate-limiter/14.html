Evaluator rubric checklist

This is what a machine-coding evaluator typically ticks. Use it as a self-review before you say "done".

  • Runs: a driver shows each feature working, with no edits needed by the evaluator.
  • Separation: algorithms behind an interface; the service does not know concrete classes.
  • Open/Closed: a new algorithm is one class + one factory line.
  • Correctness: refill capped at capacity; windows aligned; log expiry uses the right comparison (<= now - window).
  • Thread safety: atomic key creation; atomic read-modify-write per limiter; no global lock on the hot path.
  • Testability: injectable clock; deterministic tests; no sleeps.
  • Validation: bad configuration rejected early with clear messages.
  • Naming and size: small classes, intention-revealing names (tryAcquire, not check); no 200-line method.
  • Trade-offs spoken: fixed-window edge burst, log memory, counter approximation, under-admission in the composite.
  • Extensions explained: per-tier rules, Decision object, eviction, distributed version.
