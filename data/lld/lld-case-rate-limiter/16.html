Common mistakes

  • One giant class with a switch on algorithm. Fails Open/Closed and mixes unrelated state.
  • Reading the clock inside each algorithm. Tests then need Thread.sleep, and composites see different instants.
  • Check-then-put on a HashMap. Two threads create two buckets for one new client.
  • A single global lock around allow(). Correct but every client waits for every other client.
  • Forgetting to cap refill at capacity. A client idle for a day gets a day's worth of burst.
  • Off-by-one in log expiry. Using < instead of <= keeps a request alive one millisecond too long; decide and test it.
  • Consuming quota on a rejected request when several limits apply (no rollback).
  • Calling Thread.sleep to "wait for a token" inside allow(). The question asks for a decision; blocking request threads turns a limiter into a self-inflicted outage.
  • Never mentioning memory or the distributed case. Both come up at SDE-2; one sentence each is enough.
