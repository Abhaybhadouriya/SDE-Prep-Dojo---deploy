It was not frequent enough to make our 2024-26 report list (recent-lld.json), so we searched LeetCode Discuss directly. It is almost an Amazon-only question, and Amazon asks it at every stage: phone screen, the coding part of a Leadership Principles round, and the onsite. Zeta has started asking it too. Older posts show the question has been stable since 2019: "use a code to open a locker, find an optimal locker for a package" (233869, where a linear scan over all lockers was not enough and the candidate was rejected), "locker size must be at least the package size, like a parking lot" (260467), and a 2022 Amazon L5 variant with real box dimensions and rotation (1837728).

Three lessons from the table. First, the core is the allocation: every report asks for "the optimal locker", so a free list per size beats scanning. Second, the code flow is the usual follow-up: generate, deliver, check, single use, expiry. Third, the scope is small (the AWS interviewer asked for three classes), so a clean, finished core plus well-chosen extensions wins over a half-built "full system".

Interviewers like hearing, in the first minute: "This is an allocator with size classes. I will keep one free list per size so finding a slot is O(1), put the 'which size' decision behind a strategy, and lock per station, because two stations never share a slot."
