Quiz

Which property best separates a pooled object from a flyweight?

  1. Pooled objects are immutable
  2. Pooled objects are used by one client at a time and reset between clients
  3. Flyweights must be released
  4. Flyweights are created lazily
Pool = exclusive and mutable; Flyweight = shared and immutable.

The pool is at max and nothing is idle. What is the most common production policy?

  1. Create another object anyway
  2. Wait forever
  3. Wait up to a timeout, then fail with an error
  4. Return null silently
A bounded wait keeps short spikes smooth and turns real exhaustion into a visible error.

In acquire(), a permit was taken but the factory throws while creating a connection. What must happen?

  1. Release the permit before rethrowing
  2. Nothing; the permit returns by itself
  3. Retry forever
  4. Mark the pool closed
Otherwise each failure shrinks the pool by one until it is empty.

Which kernel API is a pool whose main promise is forward progress under memory pressure?

  1. kmalloc
  2. vmalloc
  3. alloc_pages
  4. mempool_t
A mempool keeps min_nr reserved elements and can wait for a free, so I/O paths can always proceed.

The best way to stop callers leaking pooled objects is:

  1. Document "please call release"
  2. Return a closeable handle so try-with-resources / with / RAII releases it
  3. Make the pool bigger
  4. Run the garbage collector more often
Make the correct path the default path; detection is the backup.

Which is the weakest reason to add an object pool?

  1. Each object needs a TLS handshake
  2. The database allows only 300 connections
  3. The objects are small Java value holders created per request
  4. Allocation is not allowed in the packet fast path
Small short-lived heap objects are cheap with modern GCs; pooling them usually costs more than it saves.
