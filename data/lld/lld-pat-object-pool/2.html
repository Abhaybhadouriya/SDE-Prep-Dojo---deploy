Intent

Object Pool (a creational pattern, not one of the 23 GoF patterns): keep a set of initialised objects ready to use. Clients acquire one, use it, and release it back, instead of creating and destroying objects on demand.

The pool does three jobs at once:

  1. Reuse pay the creation cost once, not per request.
  2. Bound never have more than max objects alive, which protects whatever is behind them (a database, file descriptors, memory).
  3. Hygiene make sure every object comes back, and comes back clean.

Some people say "a pool is just a cache". Not quite. A cache hands out shared copies of data and many readers can hold the same entry. A pool hands out exclusive use: while you hold a connection, nobody else can use it.
