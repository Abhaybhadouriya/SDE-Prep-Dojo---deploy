The problem: paying the setup cost on every request

A payment service opens a fresh database connection for every request. Opening one means a TCP handshake, a TLS handshake, authentication and session setup. That can easily cost more than the query itself.

class PaymentDao {
    Receipt charge(Order o) throws SQLException {
        // NEW connection per call: TCP + TLS + auth every single time
        try (Connection c = DriverManager.getConnection(URL, USER, PASS)) {
            return insert(c, o);
        }
    }
}
// 2,000 requests per second  => 2,000 handshakes per second.
// A traffic spike            => thousands of connections, the database hits max_connections and refuses everyone.

Two separate pains are hiding here:

  • Latency and CPU: the expensive setup is repeated even though the object could be reused.
  • No upper bound: nothing limits how many connections exist at once. Under load the service does not slow down gracefully; it overloads the database and fails for everyone.

A naive fix, "keep one shared connection in a static field", is worse: one connection cannot serve many threads at once, and it carries the previous user's session state (transaction, temp tables, isolation level).
