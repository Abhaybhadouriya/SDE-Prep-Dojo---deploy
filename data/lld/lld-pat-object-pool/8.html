When to use it, when not to

Use it when
  • Creating the object is expensive compared with using it: network handshakes, threads, large or pinned buffers, GPU contexts.
  • You need a hard upper bound to protect a scarce resource behind the object (database connection limit, file descriptors, licence seats).
  • Objects can be reliably reset to a clean state between users.
  • You need predictable latency, for example no allocation in a packet fast path or a game loop.
Avoid it when
  • Objects are cheap. Modern allocators and garbage collectors make small short-lived objects almost free; pooling them adds locking and can be slower.
  • State cannot be fully reset. A pooled object that remembers the last user's data is a security bug, not an optimisation.
  • Callers cannot be trusted to release (no RAII, no try-with-resources discipline): leaks will drain the pool and the service stalls.
  • The pool would become the hottest lock in the system and you are not willing to add per-thread or per-CPU caching.

Pitfalls that show up in reviews

  • Forgetting to release on the error path. Always release in finally, try-with-resources, with, or an RAII destructor. In C, the goto out_free pattern serves the same purpose.
  • Double release. Two clients end up holding the same object. Track leases and reject a second release (the Java code throws).
  • Use after release. The client keeps a reference after returning it. Hand out a Lease that refuses get() once closed.
  • Dirty objects. Open transactions, changed isolation levels, thread-locals, buffer contents. Reset on return and validate on borrow.
  • Losing a permit. If creation throws after a slot was reserved, give the slot back, or the pool shrinks forever (see the catch in acquire).
  • Waiting forever. A blocking acquire without a timeout turns a leak into a full outage with no error message.
  • Sizing by guess. A bigger pool is not always faster: a database with a few cores can only run a few queries truly in parallel, and HikariCP's own pool-sizing notes argue for smaller pools than people expect. Measure.
