A strong spoken answer: "Check-then-act on the seat is a race. In this machine-coding round I'll keep one ReentrantLock per show, so different shows run in parallel and multi-seat holds take a single lock, which also rules out deadlock. The hold has a five-minute TTL, checked lazily, and confirm re-checks ownership. In production with several servers, the same interface would be backed by a conditional UPDATE ... WHERE status = 'FREE' or a version column, plus a unique constraint as a safety net. I'd go pessimistic for a flash sale and optimistic for normal shows."

Scenario: Uber-style driver assignment

Many riders request at once; the matcher picks the nearest AVAILABLE driver. Two riders get the same driver. Fix it.
"Make assignDriver synchronized." Correct, but it serialises every match in the city, and the interviewer will push on scale.
The driver's state transition AVAILABLE to ASSIGNED is the atomic step. Keep driver state in an AtomicReference (or a version column) and do compareAndSet(AVAILABLE, ASSIGNED). The matcher ranks candidates without locks, then tries CAS on the best one; if it loses, it tries the next. No global lock, no double assignment, losers move on in microseconds.
Follow-ups: what if the driver goes offline between ranking and CAS? (The CAS fails because the state is OFFLINE.) What if the rider cancels? (ASSIGNED back to AVAILABLE with the same CAS.)

Scenario: the last item in stock (Flipkart / Meesho / Cleartrip)

Stock = 1, two carts check out. Inventory must never go negative.
Read stock, if > 0 then write stock - 1. Same check-then-act race.
One atomic decrement with a guard: in memory, stock.getAndUpdate(s -> s > 0 ? s - 1 : s) and compare the old value; in SQL, UPDATE item SET stock = stock - 1 WHERE id = ? AND stock > 0 and check rows changed. For a multi-item cart, reserve item by item in id order and release earlier reservations if a later one fails (a compensation, like a mini saga).
Follow-ups: item-level vs restaurant-level lock? (Item level; never nest.) Flash sale with 100k buyers? (A queue in front, or pre-split stock into buckets.)
