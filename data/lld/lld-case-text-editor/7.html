Core flow: type, undo, redo

  1. The key handler calls type("w"). The editor creates an InsertCommand for position 6 (the cursor) and the text "w".
  2. Grouping check: the last history entry is the insert "hello ", which ends with a space, so "w" starts a new group. Had it been "hell" + "o", the character would be absorbed into the existing entry.
  3. The command runs against the Document: one gap-buffer insert. It returns the new cursor, 7. The command keeps only (6, "w"), which is enough to reverse it.
  4. The editor pushes the command together with the cursor before it (a tiny memento), clears redo, and drops the oldest entry if the history is over its limit.
  5. Later the user types "orld" (absorbed into the same entry) and presses undo. The editor pops "world" and asks the command to undo itself: delete 5 characters at 6.
  6. The cursor goes back to the saved 6, and the entry moves to the redo stack. Redo would call execute again and move it back.

Up and down with a goal column

Up and down are the bug magnet of the Razorpay-style round. On the text "hello there\nab\nlonger line" with the cursor at the end of line 3 (column 12), pressing up should land at the end of the short line "ab" (column 3), and pressing up again should go back to column 12 on line 1, not column 3. The trick is a goal column: the first vertical move remembers the column; later vertical moves aim for it and clamp to the line length; any horizontal move or edit forgets it. Page up and down are just N vertical moves that stop at the first or last line.
