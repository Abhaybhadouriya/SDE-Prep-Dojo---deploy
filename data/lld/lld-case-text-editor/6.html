FacadeEditorThe keyboard handler calls simple methods; the buffer, line arithmetic and history stay hidden and are the single place to lock."The keyboard handler only sees Editor; buffer and history stay hidden behind it."

From your world

Command is the struct edit_ops from the story box: execute and undo slots plus captured arguments, queued like work_structs. Composite is a chained scatterlist: many small pieces that the caller submits and completes as one I/O, just as a MacroCommand is many edits undone as one. Flyweight is the console font: one bitmap per glyph shared by every cell on the screen, with the position kept by the cell, not the glyph. Facade is the syscall layer: write(fd, buf, n) hides the page cache, the block layer and the journal behind one call.

Patterns we deliberately skipped: a Memento per keystroke (a full copy per key is history size x document size: 1,000 edits on a 1 MB file is 1 GB), an Observer for every buffer change (no second view in this round; add it with a split view or collaboration), and inheritance per document type (plain text, code and markdown differ in rendering, not in editing, so that would be a strategy on the renderer).

Command undo vs Memento undo

Command (store the change)
  • Memory is proportional to what was typed
  • Works for 1 GB files
  • Each command must have a correct inverse
  • Best for text, drawing, spreadsheets
Memento (store the state)
  • Trivially correct: restore the copy
  • Memory is history size times document size
  • Good for small state (a game board, a form)
  • Good for checkpoints, as here

Real editors mix the two, as we do: commands for every keystroke, an occasional snapshot as a checkpoint. Our Python test proves the two agree: it runs 9,000 random edits, undos and redos against a reference that stores full snapshots, and checks text and cursor after every step.
