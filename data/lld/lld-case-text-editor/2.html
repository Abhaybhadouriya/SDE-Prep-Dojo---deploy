Clarify the requirements

Functional (P0)

  1. Type Insert text at the cursor (one key or a pasted string). Newline splits a line.
  2. Delete Backspace (before the cursor) and Delete (after it). At the start or end of the text they do nothing.
  3. Move Left, right, home, end, up, down, page up, page down. Up and down keep the column you started from, even across shorter lines.
  4. Replace Replace every match of a string, as one undoable step.
  5. Undo / redo Undo reverses the last edit and puts the cursor back where it was before that edit. Redo replays it. A new edit after undo discards the redo history.
  6. Grouping Typing "hello world" key by key is undone a word at a time, not a letter at a time.
  7. Checkpoint Save a version and later revert to it (and the revert itself can be undone).

P1

  • Selection, cut, copy, paste; find next; line-range operations (TextPad style); bounded history size.
  • Styling (bold, fonts) and rendering; open and save files; multiple documents; collaborative editing.

Non-functional

  • Fast local edits: typing at the cursor is O(1) amortised, whatever the file size.
  • Small history: undo stores changes (deltas), not copies of the document; history has a size limit.
  • Correct inverse: undo then redo of any sequence gives back exactly the same text and cursor.
  • Extensible: a new kind of edit is a new Command class; the editor's undo code does not change.

Out of scope (say it)

The GUI toolkit, fonts and real rendering, file encodings, syntax highlighting, plugins, and real-time collaboration (mention OT and CRDTs only if asked; that is an HLD discussion).

Questions to ask

  • One line or many? Do up, down and page keys matter? How many lines is a page?
  • Does undo restore the cursor? Should consecutive typing be undone as one word or one character?
  • Is cursor movement an undoable action? (Usually no: only edits enter the history.)
  • Replace: first match, all matches, or the current selection? Case sensitive?
  • Is there a limit on undo history? What happens to redo after a new edit?
  • How big can the text get (a tweet, a source file, a 1 GB log)? This decides the buffer.
  • Single user, or several writers at once?
