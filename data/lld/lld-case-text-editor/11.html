Extensibility: the follow-ups interviewers ask

Follow-upChange in our designClasses touched
Selection, cut, copy, pasteEditor keeps anchor and cursor; cut = DeleteCommand on the range plus a clipboard write; paste = InsertCommand. Copy is not an edit, so it is not in the history.Editor only
TextPad line operationsLine n maps to an offset with lineStart; insert line, delete lines n..m, paste at line are Insert/Delete commands on those offsets.Editor methods
Bold, italic, fontsStyle runs (start, end, style) stored beside the text; a StyleCommand saves the old runs for undo. Glyphs become (char, font, style) flyweights.new command, render
Huge files, many cursorsSwap the GapBuffer for a rope or piece tree behind the same insert/delete interface; keep a line-start index for O(log n) line lookup.buffer only
Multiple cursorsA list of cursors; one edit becomes a MacroCommand of inserts applied from the last cursor to the first so offsets stay valid (the same trick as replace-all).Editor
Undo tree (never lose a branch)Instead of clearing redo, keep the redo branch as a child of the current node; undo walks to the parent; redo picks a child.history structure
Persistent undo across restartsSerialize commands (type, pos, text) to a journal file; replay on open.commands get toRecord()
Find next, regexA Matcher strategy (plain, case-insensitive, regex) used by replace and find.new strategy
Observers: status bar, dirty flag, autosaveEditor publishes onChange(range) and onCursor(pos) (Observer); the dirty flag compares the history position with the last saved one.Editor fires events
Commands executed by a server (Microsoft ask)A command's execute and undo may be remote calls; history entries get a status (pending, done, failed); undo of a remote command sends its inverse request; failures roll back local state.command implementations
