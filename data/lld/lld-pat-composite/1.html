The problem: if (isFolder) everywhere

Without the pattern, files and folders are two unrelated classes, and every operation over the tree has to check the type:

class FileEntry   { String name; long bytes; }
class FolderEntry { String name; List<Object> items = new ArrayList<>(); }   // Object!

long totalSize(Object item) {
    if (item instanceof FileEntry f) return f.bytes;
    if (item instanceof FolderEntry d) {
        long sum = 0;
        for (Object child : d.items) sum += totalSize(child);
        return sum;
    }
    throw new IllegalStateException("unknown item " + item);
}

void print(Object item, String indent) {           // the same if-ladder again
    if (item instanceof FileEntry f) System.out.println(indent + f.name);
    else if (item instanceof FolderEntry d) { /* ... loop, recurse ... */ }
}

Count the pains:

  • The type check is copied into every operation. Size, print, search, delete, permission check: each one repeats the same instanceof ladder.
  • A new node type touches every ladder. Add a symlink or a zip archive that behaves like a folder, and you edit every function. That breaks the Open/Closed Principle.
  • The children list is typed Object. Nothing stops someone from putting a String in a folder.
  • The client must know the shape of the tree. "Price of this order" should not care whether the line is one item or a bundle of bundles.
