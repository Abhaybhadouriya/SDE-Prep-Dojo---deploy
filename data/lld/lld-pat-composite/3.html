Structure: Component, Leaf, Composite

  • Component (Node): the interface every element of the tree has. Holds the uniform operations (size(), print(), price(), evaluate()). May hold shared state such as a name and a parent pointer.
  • Leaf (File): an element with no children. Does the real work: it knows its own bytes.
  • Composite (Directory): an element with children. Implements each operation by delegating to its children and combining the results (sum, max, concatenate, all-of).
  • Client: holds a Node and calls the operation. It never asks what kind of node it has.

Safety vs transparency: where does add() live?

This is the design question interviewers actually probe. Leaves cannot have children, so where do you declare add(child) and remove(child)?

Safety (child ops on Composite only)Transparency (child ops on Component)

Who uses itMost modern code; our Java example; Linux (only directory inodes have mkdir)The original GoF description; our C++ menu example; Java AWT Container is a middle ground

Default answer: prefer safety. Uniformity matters most for the operations (size, render, price), which every node supports. Building the tree is usually done by code that knows what it is building, so it is fine for that code to hold a Directory. Say the trade-off out loud; that is what earns the point.
