In interviews

Composite is the expected answer whenever the problem statement has nesting: "folders inside folders", "a menu with sub-menus", "an order can contain bundles", "evaluate 2 + (3 * 4)". The giveaway sentence is "it can contain items or other groups".

  • File system: the classic. Directory and File behind one FileSystemNode; ls, mkdir -p, size, find by extension. Listed by Amazon and Microsoft candidates; our question bank counts it in five of the repos we surveyed.
  • Calculator / expression evaluator: an Oracle onsite asked candidates to design a calculator with the Composite pattern so that nested expressions work (LeetCode Discuss post 6121661). Our Python tab is a model answer.
  • Shopping cart and food delivery: combos and bundles priced as the sum of their parts (often with a bundle discount applied by a Decorator or Strategy).
  • Text editor: document, paragraphs, runs of characters as a tree.
  • Task tracker: an epic contains stories contains subtasks; progress and estimates roll up.
  • Stack Overflow and news feed: nested comment threads.

Strong 30-second answer: "I'll model this as a Composite. Node is the common type with size(); File is a leaf; Directory holds a list of Node and sums its children. I'll keep add and remove on Directory only, the safe variant, so a leaf never has to throw. I'll keep a parent pointer for paths and refuse to add an ancestor to prevent cycles. If size is queried often, each directory caches its total and invalidates up the parent chain."
