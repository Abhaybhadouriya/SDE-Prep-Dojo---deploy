Intent

Composite (GoF structural pattern): arrange objects in a tree that models a part-whole relationship, so client code can handle one object and a whole group of objects through the same interface.

Two words carry the pattern. Part-whole: the domain really is a tree (a folder contains files, a combo contains dishes, an expression contains sub-expressions). Uniformly: the client calls the same method on a leaf and on a whole subtree, and does not branch on the type.

The trick that makes it work is one line of type design: a composite holds a list of the Component type, not of leaves. Because a child can itself be a composite, the tree can be any depth, and recursion falls out naturally.
