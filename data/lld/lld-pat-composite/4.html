How it works: one size() call, step by step

  1. The client holds the root as a plain Node and calls size() once. It does not know the tree has four levels.
  2. root is a Directory, so its size() loops over its children and calls size() on each. It does not check their types either.
  3. src is also a Directory and repeats the same loop. This is plain recursion: the call stack grows one frame per level of the tree.
  4. The files are leaves: they return their own byte counts immediately. net adds them up and returns 6000.
  5. src receives 6000 from net and 900 from main.c, and returns 6900.
  6. root adds 6900 and 300 and hands 7200 back to the client. One call, a full depth-first walk.

Every composite operation has the same skeleton: do something for myself, call the same operation on each child, combine. Size sums, "find largest file" takes a max, "render" concatenates, "is everything paid?" ANDs booleans. If you ever have to stop early (search), return as soon as a child reports a hit.
