The kernel's state machines, in C

The kernel keeps TCP state as a small integer and switches on it, which is the enum style. Trimmed to the idea:

/* include/net/tcp_states.h (abridged) */
enum {
    TCP_ESTABLISHED = 1, TCP_SYN_SENT, TCP_SYN_RECV, TCP_FIN_WAIT1, TCP_FIN_WAIT2,
    TCP_TIME_WAIT, TCP_CLOSE, TCP_CLOSE_WAIT, TCP_LAST_ACK, TCP_LISTEN, TCP_CLOSING,
    TCP_NEW_SYN_RECV, /* ... */
};

/* net/ipv4/tcp_input.c: what does this segment mean in the state we are in? (sketch) */
int tcp_rcv_state_process_sketch(struct sock *sk, struct sk_buff *skb)
{
    switch (sk->sk_state) {
    case TCP_CLOSE:   goto discard;
    case TCP_LISTEN:  /* SYN: create a request sock, send SYN-ACK; ACK: reset */ ...
    case TCP_SYN_SENT: /* expect SYN-ACK */ ...
    }
    /* ... common checks ... then a second switch for ACK processing per state */
    switch (sk->sk_state) {
    case TCP_SYN_RECV: tcp_set_state(sk, TCP_ESTABLISHED); ...
    case TCP_LAST_ACK: tcp_done(sk); ...
    }
}

From your world

Why does the kernel use a switch and not one ops table per state? Partly speed and history, and partly because many TCP states share most of their processing (the common checks between the two switches above), so a table per state would duplicate it. That is a real-world answer to "when is State overkill?". Where behaviour really differs wholesale, the kernel does swap ops tables: a listening socket's request socks, or a socket moving to TIME_WAIT being replaced by a lightweight inet_timewait_sock, a different object for a different phase of life. Other state machines you know: the 802.1X / WPA supplicant states, driver runtime power management (RPM_ACTIVE, RPM_SUSPENDING, RPM_SUSPENDED, RPM_RESUMING), and BGP's Idle, Connect, Active, OpenSent, OpenConfirm, Established if you worked on routers.

One C detail that maps straight across: when a state handler is a callback that receives only a pointer to an embedded member, it recovers the enclosing connection with container_of(). In Java the state method receives the context explicitly (insertCoin(VendingMachine m, ...)) and its own object as the hidden this, so no cast is needed.
