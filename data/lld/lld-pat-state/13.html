Remember this

  • State = one class per lifecycle stage, one method per event; the context forwards events to the current state.
  • States choose the next state; the object appears to change its class.
  • Keep data in the context so state objects are stateless and shareable.
  • Defaults on the interface handle illegal events (ignore, reject, or reset like TCP).
  • Two or three trivial states: enum + switch. Mostly labels: transition table. Real per-state behaviour: State classes.
  • vs Strategy: the client picks a strategy; states replace themselves because of events.
  • Serialize events per context; persist the state's name, not the object.
  • Kernel: sk->sk_state and tcp_rcv_state_process() are the switch version of this pattern.
