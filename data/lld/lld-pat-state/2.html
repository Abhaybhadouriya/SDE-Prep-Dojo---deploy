Intent

State (GoF behavioral pattern): give each mode of an object its own class, and have the object forward every request to the class of its current mode. When the mode changes, the forwarding target changes, so the same call does something different: from the outside, it looks as if the object switched to another class.

In plain words: turn each value of the state enum into a class, move each case into a method of that class, and replace the switch with one call on the current state object. The state objects also decide which state comes next. The behaviour of one state now lives in one place, and adding a state means adding a class.

A useful mental table: states are rows, events are columns, and each cell is "what to do and where to go". The enum version stores the table by column (one method per event, a switch over states). The State pattern stores it by row (one class per state, a method per event). A transition table stores it as data. You pick the layout that makes your change easy.
