Class diagram

Filled diamond = composition (the part lives and dies with the whole). Hollow diamond = aggregation: the part has its own lifetime and may be shared (a strategy object can outlive the context and serve many contexts); whether it can be swapped at runtime is a separate question, said in prose. Dashed line with a hollow triangle = implements. Plain arrow = association. Dashed arrow = dependency.

Why does every state get the Atm as a parameter instead of holding a pointer to it? The states then hold no reference back to the context, so a state object can be created freely and even shared. It is the same reason kernel ops tables take the object as their first argument: f_op->read(file, ...), not a table bound to one file.
