Quiz

The ATM holds 2000x1, 500x1, 200x4 and no 100s. A customer asks for 600. What should happen?

  1. Dispense 2000 and ask for change
  2. Dispense 3 x 200
  3. Dispense 500 and owe 100
  4. Decline, because 500 + 100 is impossible
Greedy takes the 500 and gets stuck. Backing off to zero 500s lets the 200 handler cover 600.

In which order should a withdrawal run?

  1. Reserve notes, debit, eject
  2. Eject, debit, reserve
  3. Debit, eject, reserve
  4. Debit, reserve, eject
Reversible and local steps first; the irreversible eject last.

The debit was approved but the feeder jammed and no notes came out. What does our design do?

  1. Move to OUT_OF_SERVICE and keep the money
  2. Retry the eject forever
  3. Debit again with a new id
  4. Reverse the debit with the same transaction id and release the reserved notes
A compensating transaction undoes the bank's half; the same id makes the reversal safe to retry.

A customer presses "withdraw" while the ATM is in CARD_INSERTED. Where is that rejected?

  1. In the default withdraw method of the AtmState interface, which CardInsertedState does not override
  2. In the cash dispenser
  3. In a switch at the top of Atm.withdraw
  4. In the bank adapter
Each state overrides only its legal actions; everything else falls through to "not allowed in this state".

Two ATMs each numbered their transactions T1, T2, ... from 1. What goes wrong?

  1. Nothing, ids only need to be unique per ATM
  2. Java throws a duplicate key exception
  3. The second ATM debits twice
  4. The bank treats the second ATM's T1 as a retry and does not debit, while cash is dispensed
Idempotency keys must be unique across every sender, so prefix them with the ATM id.

The ATM speaks rupees and enums; the bank's library speaks paise and "51". Which pattern joins them?

  1. Decorator
  2. Adapter
  3. Bridge
  4. Facade
An adapter makes an existing interface look like the one the client was written against.

20 ATMs each withdraw 1,000 from one joint account holding 10,000. What must hold?

  1. Only one succeeds
  2. The result is random and may go negative
  3. Exactly 10 succeed and the balance ends at 0
  4. All 20 succeed because each ATM is synchronized
Locking each ATM does not protect the account; the bank checks and debits atomically.
