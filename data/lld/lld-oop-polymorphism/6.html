Python and duck typing

In Python every method call is looked up at run time on the object, so everything is "virtual". You do not even need a shared base class: if the object has a xmit method, the call works. This is duck typing ("if it walks like a duck and quacks like a duck..."). The flip side: Python has no compile-time overloading. A second def with the same name simply replaces the first. For "dispatch on argument type" the standard library offers functools.singledispatch, which looks at the runtime type of the first argument.

"""Polymorphism in Python: every call is dynamic; there is no compile-time overloading.
Run:  python polymorphism.py
"""
from functools import singledispatch


class Ethernet:
    def kind(self):
        return "ethernet"

    def xmit(self, n):
        return n + 18


class Loopback:
    def kind(self):
        return "loopback"

    def xmit(self, n):
        return n


def report(dev, n):            # no base class needed: "if it has xmit(), it works"
    print(f"  {dev.kind():9} xmit({n}) -> {dev.xmit(n)}")


class Parser:
    def parse(self, data: bytes):
        return "bytes version"

    def parse(self, data: str):    # same name again: this REPLACES the first one
        return "str version"


@singledispatch
def describe(x):
    return "describe(object)"


@describe.register
def _(x: str):
    return "describe(str)"


@describe.register
def _(x: int):
    return "describe(int)"


if __name__ == "__main__":
    print("1. Duck typing: dispatch on whatever object arrives")
    for d in (Ethernet(), Loopback()):
        report(d, 1500)

    print("2. A second def with the same name replaces the first:")
    print("  Parser().parse(b'x') ->", Parser().parse(b"x"))

    print("3. functools.singledispatch picks by the RUNTIME type of the first argument:")
    o: object = "hello"
    print("  describe(o)  ->", describe(o))
    print("  describe(42) ->", describe(42))
    print("  describe(4.2)->", describe(4.2))
$ python polymorphism.py
1. Duck typing: dispatch on whatever object arrives
  ethernet  xmit(1500) -> 1518
  loopback  xmit(1500) -> 1500
2. A second def with the same name replaces the first:
  Parser().parse(b'x') -> str version
3. functools.singledispatch picks by the RUNTIME type of the first argument:
  describe(o)  -> describe(str)
  describe(42) -> describe(int)
  describe(4.2)-> describe(object)

Compare line 3 with the Java run: the same describe(o) call gives Object in Java (static type) and str in Python (runtime type). That contrast is a nice one to mention in an interview.
