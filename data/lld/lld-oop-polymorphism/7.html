Double dispatch: when one vptr is not enough

A virtual call picks code based on one object: the receiver before the dot. That is single dispatch. Sometimes the right behaviour depends on two runtime types. A firewall rule engine might handle each pair (handler kind, packet kind) differently; a game decides what happens when an asteroid hits a ship versus a ship hitting a ship.

You might hope overloading solves it: write handle(TcpPacket) and handle(UdpPacket) and call handler.handle(p). But p is declared as Packet, and overloads are picked from static types, so it does not compile (there is no handle(Packet)). The fix uses two dispatches in a row:

  1. First dispatch (virtual): call p.accept(h). This picks the packet's real class.
  2. Second dispatch: inside TcpPacket.accept, the type of this is statically known to be TcpPacket, so h.handle(this) picks the right overload at compile time, and the call on h is virtual, so it picks the handler's real class.
// ---- 4. Double dispatch preview (the Visitor trick) ----
interface Packet  { void accept(Handler h); }
interface Handler { void handle(TcpPacket p); void handle(UdpPacket p); }
static final class TcpPacket implements Packet {
    public void accept(Handler h) { h.handle(this); } // 'this' is statically TcpPacket here
}
static final class UdpPacket implements Packet {
    public void accept(Handler h) { h.handle(this); }
}
static final class AuditLog implements Handler {
    public void handle(TcpPacket p) { System.out.println("  audit: TCP packet"); }
    public void handle(UdpPacket p) { System.out.println("  audit: UDP packet"); }
}

From your world

In C, double dispatch is two ops-table lookups, one per object: pkt->ops->accept(pkt, h), and inside the TCP packet's accept you write h->ops->handle_tcp(h, pkt). The first lookup finds the packet's type; the slot name handle_tcp is hard-coded in the TCP packet's function, so the second lookup only has to find the handler's type. Java's overload handle(this) is that hard-coded slot name, picked by the compiler. See Visitor for the full pattern.

This is the heart of the Visitor pattern. The cost: every new packet type means a new method on every handler. Some languages (Common Lisp, Julia) have multiple dispatch built in; Java, C++ and Python do not, though Java 21's pattern-matching switch over a sealed type is a readable alternative for the second step.
