Overriding: the object decides

With overriding, a subclass supplies its own body for a method it inherited, keeping the same signature. Code that holds a Shape reference calls area() and gets the circle's or the rectangle's version, depending on which object is really there.

// ---- 2. Run-time polymorphism: overriding ----
static abstract class Shape {
    abstract double area();                    // no body: every subclass must supply one
    String name() { return "shape"; }          // has a body: subclasses MAY replace it
    static String kind() { return "Shape.kind"; } // static: hidden, never overridden
    @Override public String toString() {       // calls two virtual methods
        return name() + " area=" + String.format("%.2f", area());
    }
}
static final class Circle extends Shape {
    private final double r;
    Circle(double r) { this.r = r; }
    @Override double area() { return Math.PI * r * r; }
    @Override String name() { return "circle"; }
    static String kind() { return "Circle.kind"; }
}
static final class Rect extends Shape {
    private final double w, h;
    Rect(double w, double h) { this.w = w; this.h = h; }
    @Override double area() { return w * h; }
    @Override String name() { return "rect"; }
}
2. Overriding uses the real object, decided at run time:
  circle area=3.14
  rect area=6.00
3. Static methods are hidden, not overridden:
  Shape.kind / Circle.kind

Notice that toString() is written once, in Shape, and still prints the right name and area for each object. That is the real power: code in the base class can call code that does not exist yet. It is the same trick as a generic network stack calling a driver's ndo_start_xmit.

The rules of a legal override (Java)

  • Same name and same parameter types. Add @Override so the compiler checks it.
  • Return type: the same, or a subtype (covariant return: Frame copy() may become TcpFrame copy() in the subclass).
  • Access cannot get narrower (a public method cannot become private), and checked exceptions cannot get broader. Both rules exist so that the subclass can stand in anywhere the parent is expected; that idea has a name, the Liskov Substitution Principle.
  • static, private and final methods are not overridden. A static method with the same signature in a subclass only hides the parent's, and which one runs depends on the declared type, like overloading.
  • Fields are never polymorphic. If parent and child both declare a field name, parentRef.name reads the parent's field. Only methods dispatch dynamically.
// ---- 3. Covariant return type: an override may return a subtype ----
static class Frame { Frame copy() { return new Frame(); } }
static class TcpFrame extends Frame {
    @Override TcpFrame copy() { return new TcpFrame(); } // narrower return type is allowed
}

Java vs C++ defaults: in Java every non-static, non-private, non-final instance method is virtual by default. In C++ a method is only virtual if you write virtual (or it overrides one). C++11 added override (compiler checks you really override) and final (nobody may override further).
