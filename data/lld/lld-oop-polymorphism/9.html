Interview questions

These come up in OOP screening rounds and as follow-ups in LLD rounds (Microsoft and Amazon reports often include "explain runtime polymorphism with code").

What is the difference between compile-time and runtime polymorphism?

Compile-time polymorphism is resolved by the compiler from the declared types at the call site: method overloading, operator overloading (C++) and templates/generics. Runtime polymorphism is resolved while the program runs from the actual object: method overriding through a base-class reference or an interface. Overloading costs nothing at run time (each overload is just a differently named function after compiling); overriding costs an indirect call through the vtable.

How to answer

Give the one-line definition of each, a two-line code example (two add overloads; Shape s = new Circle(); s.area()), then the "decided by whom, using what" contrast. Offer the vtable explanation as the next step.

Likely follow-ups
  • Is overloading "real" polymorphism? (Many people call it ad-hoc polymorphism; say both terms exist.)
  • What does describe(o) print when Object o = "hi"?
  • Can you override a static method?
How does a virtual function call work internally?

For each polymorphic class the compiler creates a vtable: an array of function pointers, one slot per virtual function. Each object holds a hidden vptr, set by the constructor, pointing at its class's table. A call p->f() compiles to: load vptr from *p, load the slot for f (fixed index), indirect call with p as this. Subclass tables copy the parent's layout and replace overridden slots, so the same index works for every class in the hierarchy.

How to answer

Draw two objects, two tables, and arrows to code. Mention costs (one pointer per object, an indirect call, blocked inlining) and that this is the same as a C struct of function pointers. Note the standard does not mandate vtables; it is the universal implementation.

Likely follow-ups
  • What is sizeof an empty class with one virtual function? (One pointer on common ABIs.)
  • How does multiple inheritance change the layout? (Several vptrs, pointer adjustment "thunks".)
  • Where is the vtable stored? (Read-only data, one per class.)
Why does a base class need a virtual destructor?

Deleting a derived object through a base pointer calls the destructor through the vtable only if it is virtual. Otherwise the call is bound statically to the base destructor; the standard says this is undefined behaviour, and in practice the derived part is not cleaned up (leaked buffers, file handles, locks). Rule: polymorphic base classes get a public virtual destructor, or a protected non-virtual one if deletion through the base is not allowed.

How to answer

Show the four-line example (Base* b = new Derived; delete b;) and what prints. Mention std::unique_ptr<Base> has the same issue, while std::shared_ptr created by make_shared<Derived> remembers the right deleter.

Likely follow-ups
  • Should every class have a virtual destructor? (No: it adds a vptr; only polymorphic bases.)
  • Can a constructor be virtual? (No; the vptr is set by the constructor. Use a factory or a virtual clone().)
Can you override a static method or a private method in Java?

No. A static method with the same signature in a subclass hides the parent's; which one runs depends on the declared type (or the class name you call it on), not the object. A private method is not inherited, so a same-named method in the subclass is a brand-new method. Final methods cannot be overridden at all. Only non-static, non-private, non-final instance methods dispatch dynamically.

How to answer

State "hidden, not overridden", give the Shape.kind() / Circle.kind() example, and add that fields are also never polymorphic.

Likely follow-ups
  • What happens if you call a static method through an instance reference? (Compiles with a warning; uses the declared type.)
  • What is a covariant return type?
What happens if you call a virtual method from a constructor (C++ vs Java)?

In C++, during the base constructor the vptr points at the base table, so the base version runs (and calling a pure virtual there is undefined behaviour, often a crash with "pure virtual function called"). In Java the object is already its final class, so the subclass override runs, but before the subclass's field initializers and constructor body, so its fields are still default values. Both are bug sources; avoid calling overridable methods in constructors.

How to answer

Explain the "the object becomes more derived as construction proceeds" model for C++, contrast Java, and give the fix: factory method or two-phase init.

Likely follow-ups
  • And in destructors? (C++: the vptr is reset back to the base table as each layer is destroyed, same effect.)
What is double dispatch, and why do we need the Visitor pattern for it?

Single dispatch picks code by the runtime type of one object, the receiver. When behaviour depends on two runtime types (handler and packet, shape and renderer), overloading cannot help because it uses static types. Visitor does two single dispatches: element.accept(visitor) picks the element class, and inside it visitor.visit(this) picks the visitor class, with the overload fixed by the now-known static type of this.

How to answer

Show the failing direct call first, then the accept/visit fix and a sequence diagram. Name the trade-off: adding operations is easy, adding element types is hard. Mention Java 21 sealed types + pattern matching as a modern alternative.

Likely follow-ups
  • Where does Visitor appear in real code? (Compilers walking syntax trees, java.nio.file.FileVisitor.)
Write code that shows runtime polymorphism, and say where you would use it in an LLD.

An interface Vehicle { int fee(int hours); } with Bike, Car and Bus implementations; the parking service holds List<Vehicle> and calls fee() without knowing the type. In an LLD this replaces switch (type) blocks: pricing rules, payment methods, notification channels, eviction policies, chess piece moves.

How to answer

Write the interface first, two implementations, then a loop through a list of the interface type. Say "adding Truck needs no change to the service: Open/Closed".

Likely follow-ups
  • How would the service create the right Vehicle from user input? (A factory, the one place a switch is acceptable.)
  • When would you keep the switch instead?
