The parts of a sequence diagram

There are only a handful of symbols. Learn them on one small example: a client asks a service for a user profile, and the service checks a cache first.

SymbolNameMeans
Box at the top, name:TypeParticipantOne object (or service). :Cache = "some Cache object"; c1:Cache names it.
Dashed vertical lineLifelineThe object exists over time. Time flows down.
Thin bar on a lifelineActivation (execution)The object is busy running a method (including waiting for a call it made).
Solid line, filled headSynchronous messageA call; the sender waits for the answer.
Solid line, open headAsynchronous messageSend and carry on; no waiting (queue publish, executor submit).
Dashed line, open headReply / returnThe answer coming back. Often omitted when obvious.
Dashed arrow to a box lower downCreate messageA new: the object's head sits where it is born.
Big X at the end of a lifelineDestructionThe object ends (closed, freed, released).

Participants are objects, not classes. The heading is :BookingService with a colon, meaning "an instance". When two instances of the same class matter (two players, buyer and seller), name them: buyer:Account, seller:Account.
