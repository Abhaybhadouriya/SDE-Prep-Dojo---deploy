APIs and interfaces

Write these signatures on the board (or as Java interfaces in the IDE) before any method body. They are the contract you will be graded against.

// service API (what the gates call)
Ticket  park(Vehicle vehicle, LocalDateTime at);          // throws LotFullException, IllegalStateException (already inside)
Receipt unpark(String ticketId, LocalDateTime at);        // throws InvalidTicketException
Map<SpotSize, Integer> freeSpots();
void setAllocation(SpotAllocationStrategy s);             // runtime switch
void setPricing(FeeStrategy p);
void addListener(ParkingEventListener l);

// extension points
interface SpotAllocationStrategy { Optional<ParkingSpot> allocate(List<Level> levels, Vehicle v); }
interface FeeStrategy            { long fee(VehicleType type, LocalDateTime entry, LocalDateTime exit); }
interface ParkingEventListener   { void onParked(Ticket t); void onLeft(Receipt r); }

In a Flipkart-style machine-coding round the input is often a list of text commands. Map each command to one service call and keep the parsing in the driver, never inside the service:
