Interview questions

What is a Simple Factory and why is it not one of the GoF patterns?

It is one creation function that maps a key to a concrete class and returns the common interface. It is an idiom, not one of the 23 GoF patterns, because it uses no inheritance or object composition for the creation decision - it is a conditional (or map lookup) moved into one place. The GoF factory patterns are Factory Method (subclasses decide) and Abstract Factory (a factory object makes a matching family).

How to answer

Definition in one line, then the "why": callers depend on the interface only. Then name the two GoF cousins and the one-word difference for each (subclass, family).

Likely follow-ups
  • Show me the class diagram.
  • When would you upgrade it to Factory Method?
Your factory has a switch. Doesn't that violate Open/Closed? How do you fix it?

Yes, a growing switch means editing tested code for each new type. Fix it with a registry: a map from key to maker function (Map<String, Function<String, Vehicle>>, a Python dict, a C++ map of std::function). New types register themselves at start-up; create() never changes. In Java you can also discover implementations with ServiceLoader; in Python, with a class decorator or __init_subclass__.

Be honest about the trade-off: for three stable types, the switch is simpler and easier to read. OCP pays off when change is frequent.

How to answer

Admit the violation, show the registry in three lines, and say when you would not bother.

Likely follow-ups
  • Is the registry thread-safe?
  • What happens when two modules register the same key?
Should the factory method be static? What about testing?

A static method is the classic form and is fine for a small app or a machine-coding round. The cost is testability: a class that calls VehicleFactory.create directly cannot be given a fake factory. In production code, make the factory an instance (or pass a Function) and inject it through the constructor, so tests can supply a stub. That is Dependency Injection, and it also lets you have two differently configured factories.

How to answer

"Static for simplicity, injected instance when I need to test or configure it" - then one sentence on DIP.

Likely follow-ups
  • Would you make the factory a Singleton?
Design a payment processor factory for UPI, card and net banking. What does the factory return, and what does it not do?

Define PaymentProcessor { PaymentResult pay(PaymentRequest r); }. The factory takes PaymentMode (an enum parsed from the request) and returns the matching processor. Processors are usually stateless and can be created once and cached in the map (so the "factory" returns shared instances). The factory does not call pay, retry, or log transactions - that belongs to a PaymentService. Keeping the factory to creation stops it from becoming a god class.

How to answer

Interface first, enum key, map of instances, clear boundary of responsibility. Mention that each processor is a Strategy and the factory picks it.

Likely follow-ups
  • A new mode, wallets, must be added by another team. How?
  • How do you add a fallback gateway when one fails? (Chain of Responsibility or a decorator.)
Why return the interface type instead of the concrete type?

Because the goal is to cut the caller's dependency on concrete classes. If create returns Car, callers will call Car-only methods, and you can no longer swap the implementation or add types without touching them. Returning Vehicle keeps the "only the factory knows" rule enforceable by the compiler.

How to answer

Name the principle: program to an interface; dependency inversion.

Likely follow-ups
  • What if one caller truly needs a Truck-only method? (Then that caller should not go through a generic factory, or the method belongs on the interface.)
Use a string key or an enum key?

Inside the system, prefer an enum: the compiler checks spelling and an exhaustive switch over an enum warns (or, with Java's switch expressions on enums, fails to compile) when a case is missing. Parse strings only at the boundary (HTTP, CLI, config) with one clear error. A registry keyed by strings is still useful when new types come from plug-ins that the core enum cannot know about.

How to answer

Enum for a closed set, string registry for an open set. That shows you know both and the trade-off.

Likely follow-ups
  • Can the enum itself be the factory? (Yes: each constant can hold a constructor reference, CAR(Car::new).)
Is the registry safe if threads register and create at the same time?

A plain HashMap written by one thread and read by others without synchronisation is a data race in Java (readers may see a broken map). Options: register everything during start-up and publish the map safely (a static final field filled in a static initialiser, or wrap it with Map.copyOf), or use a ConcurrentHashMap with putIfAbsent to reject duplicates atomically. In C++ guard the map with a mutex if registration can happen after start-up; a function-local static registry is initialised safely, but later writes are not.

How to answer

Separate "init-time writes, run-time reads" from "run-time writes", and give the tool for each.

Likely follow-ups
  • Why does the Linux crypto API take a lock (or use RCU) around its algorithm list?
