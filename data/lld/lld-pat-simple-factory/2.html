Intent in one line

Simple Factory: one function (often static) that takes a key and returns an object typed as the common interface, so creation logic lives in exactly one place and callers depend only on the abstraction.

Three words to keep straight:

WordMeaning hereParking example
ProductThe interface callers use after creationVehicle with needs()
Concrete productA real class that implements the product. Code that writes new Car(...) (Java's new = allocate + run the constructor, like malloc + car_init) depends on Car by name; the factory keeps that dependency in one placeBike, Car, Truck
FactoryThe one place that maps key to concrete classVehicleFactory.create("car", plate)

Why it is "not a GoF pattern"

The 1994 "Gang of Four" book lists 23 patterns. Simple Factory is not one of them. It is an idiom (a common coding habit) that the Head First Design Patterns book named and used as a warm-up before the two real GoF factory patterns. The difference matters in interviews:

  • Simple Factory = one concrete function with a conditional (or a map). No inheritance needed.
  • Factory Method (GoF) = a base class declares a creation method and subclasses override it. The decision is made by which subclass you are, not by a key.
  • Abstract Factory (GoF) = an object that creates a family of related products that must match.

Many interviewers say "Factory pattern" and mean Simple Factory. Answer with the simple version first, then say which GoF version you would move to if requirements grow. That one sentence shows you know the difference without over-engineering.
