In interviews: where it shows up

Simple Factory is almost never the question. It is the first refactor the interviewer expects once you have more than one subtype. Typical prompts and the line that earns credit:

Case studyWhat the factory createsKey
Parking Lotvehicles and parking spots; often the fee strategy toovehicle type, spot size, pricing plan
SplitwiseEqualSplit, ExactSplit, PercentSplitsplit type from the input command
Digital Wallet & Payment Gatewaypayment method processors (UPI, card, net banking)payment mode in the request
Notification Serviceemail / SMS / push senderschannel name
Logging Frameworkappenders (console, file, remote) and formattersconfig file entries
Chesspieces when setting up the board or promoting a pawnpiece type letter
Shopping Cart & Couponsdiscount rulescoupon type

Say: "I'll put creation behind a VehicleFactory so the gate depends only on Vehicle. Today it is a switch; if new types arrive often I'll turn it into a registry so adding a type does not touch existing code." That covers the pattern, the dependency reason, and Open/Closed in two sentences.

In a machine-coding round, keep the factory tiny and put it next to the products (model/vehicle/VehicleFactory.java). Do not build a generic reflection-based plug-in loader; evaluators reward clear code over clever code. See Machine-Coding Code Layout.
