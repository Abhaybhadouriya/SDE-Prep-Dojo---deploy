The story: the toy shop counter

Explain like I'm 5

You walk into a toy shop and say "one red car, please". You do not go into the back room, find the car parts and build it yourself. The person at the counter knows where every toy lives. You only say the name of the toy, and you get a toy you can play with.

One day the shop starts selling a new toy, a rocket. Nothing changes for you. You just say "one rocket, please". Only the counter person had to learn something new.

That counter is a Simple Factory: one function that turns a name (a type key) into a ready object. The people asking never name the real type. In C terms, the caller never writes struct car *c = car_create();; it asks for "car" and only gets back a struct vehicle *, so it keeps working when the real types change.

From your world

You have used this many times without the name. crypto_alloc_skcipher("cbc(aes)", 0, 0) in the Linux crypto API hands you a cipher handle from a string. You never call an AES constructor; the crypto core looks the name up among algorithms that were registered with it and returns a struct crypto_skcipher *. Choosing a TCP congestion control by name (setsockopt(fd, IPPROTO_TCP, TCP_CONGESTION, "bbr", 3)) or a qdisc by its kind (tc qdisc add ... fq_codel) works the same way: a name goes in, an object behind an ops table comes out.

Where this breaks: the kernel versions are registries (modules register themselves at load time), which is the "registry-map" variant on this page. The plain textbook Simple Factory is a hard-coded switch, more like a big if (strcmp(...)) ladder in one C file.
