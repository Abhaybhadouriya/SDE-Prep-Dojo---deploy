How it works: one call, step by step

  1. The gate reads a plain string from the ticket machine. It knows nothing about classes yet.
  2. It calls the factory with the key and the data the product needs (the plate).
  3. The factory normalises the key ("car" to "CAR") and looks it up in its map of maker functions. A switch would do the same with branches.
  4. The maker runs the real constructor. This is the only line in the system that names Car.
  5. The factory returns the object typed as Vehicle. Later calls such as needs() go through dynamic dispatch (the vtable), so the gate still never sees Car.
  6. Unknown keys fail loudly in one place with one clear message. No null leaks into the rest of the system.
