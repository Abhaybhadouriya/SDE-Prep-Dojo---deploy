An agent has ratings 5 and 4. The code does int avg = (5 + 4) / 2. What does it show?

  1. 4.5
  2. 5
  3. 4
  4. It throws
Integer division truncates: 9 / 2 = 4. Store sum and count, and divide only for display with explicit rounding.

How do you compare a.sum / a.count with b.sum / b.count exactly?

  1. Compare a.sum * b.count with b.sum * a.count
  2. Compare a.sum with b.sum
  3. Convert both to float and compare
  4. Compare a.count with b.count
Counts are positive, so cross-multiplying keeps the inequality's direction, with no division and no rounding.

The interviewer asks for the best agents each month. What is the smallest good change?

  1. Rewrite the service around a list of all ratings
  2. Store the month inside the average
  3. Clear all data at the start of each month
  4. Add a map keyed by month of per-agent Stats, ranked with the same comparator
Bucketing by key: the same Stats and ranking code, one more map.

Why pass the tie-break rule into RatingService as a Comparator?

  1. Comparators are faster than if-statements
  2. So a new tie rule is a new object, with no change to the service or its tests
  3. Java requires it for sorting
  4. To make the class a Singleton
It is the Strategy pattern in its smallest form; the policy varies, the service does not.

Why is Stats immutable in the Java version?

  1. Immutable objects use less memory
  2. Records cannot be mutable
  3. So ConcurrentHashMap.compute can swap in a whole new (sum, count) pair atomically and readers never see a half update
  4. To make JSON export easier
Replacing one reference is atomic; updating two fields is not.

A new agent with a single 5-star rating tops the leaderboard. Which fix fits our design best?

  1. Delete agents with one rating
  2. A new Comparator using a Bayesian (damped) average
  3. Round averages to whole numbers
  4. Sort by count only
Same ranking seam; the damped average pulls small samples toward a prior mean.
