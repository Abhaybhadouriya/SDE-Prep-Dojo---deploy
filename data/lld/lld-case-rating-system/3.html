Identify the entities (nouns and verbs)

Same method as From use cases to classes: nouns become candidate classes, verbs become methods, data-only nouns become fields.

  1. Read the stage 1 statement and the follow-ups you expect.
  2. Nouns: Customer, Agent, Rating, average, month, results.
  3. Verbs: rate, list averages, order, best of the month, export.
  4. Drop what carries no behaviour. The customer is not needed at all. The agent is only an id string in this round. The average is derived from sum and count; storing it is the bug.
  5. What remains: a tiny immutable Stats value, a ranking row, the service, and two Strategy seams, one for ordering and one for output format. "Month" becomes a key for a second set of buckets.

Resist making an Agent class with a List<Rating> in stage 1. Keeping every rating costs memory and makes averages O(n) per agent. Keep only what the questions need: sum and count per bucket. If a later stage needs raw ratings (median, removal), add a ratings log then.
