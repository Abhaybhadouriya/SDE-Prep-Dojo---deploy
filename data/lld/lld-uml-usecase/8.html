Interview questions

How do you go from a problem statement to a list of classes?

List actors and use cases first and confirm scope. Then extract nouns from the use-case sentences, drop the frame nouns (system, app), merge synonyms, demote plain data to attributes and small validated values to value objects, and keep the things with identity and lifecycle as entities. Verbs become methods placed with the class that owns the data. Finally, trace the main use case through the classes to find gaps.

How to answer

Do it live on their problem, not in theory. Speak each filter as you apply it: "user and member are the same, so one class".

Likely follow-ups
  • Which noun did you drop and why?
  • Where does the borrowing limit check live?
You have Car, Bike and Truck. Subclasses or an enum?

If they only differ in data (size, maybe a rate), an enum field VehicleType is simpler and the switch-free way is to put that data on the enum itself. If their behaviour really differs and new kinds will keep coming (each computes fees differently, or needs different spot logic), use an interface with implementations, or keep the enum and move the varying behaviour into a strategy. Avoid a deep hierarchy for differences that are only data.

How to answer

State the test ("behaviour or only data?"), pick, and say what would make you switch.

Likely follow-ups
  • Add an electric car that needs a charging spot. What changes?
What is the difference between an entity and a value object? Give examples from this problem.

An entity has an identity that stays the same while its state changes (a Member who borrows and returns books is still member M-1). Two entities are equal only if they have the same id. A value object has no identity; it is defined by its fields, is immutable, and two with the same fields are interchangeable (Money of 500 paise, an ISBN). Value objects validate themselves in the constructor and return new objects instead of mutating.

How to answer

Definition, one example of each from the current design, then the code consequence (equals/hashCode, immutability).

Likely follow-ups
  • Is an Address an entity or a value? (Usually a value; an entity if users edit and track saved addresses with ids.)
"Book" appears in the requirements. Why did you make two classes?

The word covers two different things: the catalogue title (one per ISBN, holds title and author) and the physical copy on the shelf (one per barcode, has a status and can be lent). Loans, availability and loss happen to copies; search happens on titles. One class would force fields like status onto something that has many physical copies. Similar splits: Movie vs Show vs Seat, Product vs InventoryItem, Flight vs FlightInstance.

How to answer

Name the split, show which use cases touch which half.

Likely follow-ups
  • How do you count available copies of a title quickly?
The problem has four registers A-D. A candidate wrote RegisterA..RegisterD. What is wrong and how would you fix it?

The four classes have identical behaviour and differ only in a name, so they are four instances of one class. The class-per-instance version needs a new class plus a new switch case for every register, duplicates code, and makes tests repeat themselves. Fix: one Register class with a name field, held in a Map<String, Register> inside the processor, with one lookup that throws a clear error for unknown names. New registers become configuration.

How to answer

Point out the duplication, the OCP violation (switch grows), and show the map-based design in a few lines.

Likely follow-ups
  • Now add new commands without editing a switch. (Command pattern: map command name to a handler.)
Is the Librarian a class?

Librarian is an actor. It needs a class only if the system stores data about librarians or treats them differently, for example permissions (only librarians may add copies) or an audit trail of who issued a loan. In that case model a Staff entity or a role on a common Account, not a subclass per job title. If none of that is in scope, the librarian is simply the caller of the service.

How to answer

"Actor first; class only if we track its data." Then ask if permissions are in scope.

Likely follow-ups
  • Members and librarians can both log in. Inheritance or roles?

Scenario: the interviewer says "your Manager class does everything"

You modelled a food-ordering app with Restaurant, Order, User as plain data classes and one FoodAppManager with 25 methods, including price calculation, order status changes and delivery assignment.

"It is fine, the manager is a Singleton so it is easy to access." (Defends a god class with another smell.)

"Agreed. Rules about one object move onto it: Order.addItem, Order.total(), and status transitions on Order itself. Cross-object work splits by use case: OrderService.place, DeliveryAssigner behind an interface for the assignment strategy. The driver now talks to two or three focused services."

Likely follow-ups
  • Where does the rule "a restaurant must be open to accept orders" live?
