The method on one card

  1. Actors. List every role outside the system, human or not.
  2. Use cases. One sentence each: actor + verb + object + condition. Confirm scope.
  3. Nouns. Underline them all. Drop frame nouns, merge synonyms.
  4. Sort. Entity / value object / enum / attribute / actor / drop. Look for hidden splits (Book vs BookCopy, Show vs Movie, Order vs Cart).
  5. Verbs. Turn each into a method; give it to the class that owns the data, or to a service when it spans several objects.
  6. Trace. Push the main use case through the classes. Fix gaps.
  7. Check instances. Any classes that differ only in data? Collapse them into one class plus objects (or an enum).

This is steps 1-3 of the interview framework. Practise it under a timer in Modelling Drills, then design the public methods properly in API & Interface Design.
