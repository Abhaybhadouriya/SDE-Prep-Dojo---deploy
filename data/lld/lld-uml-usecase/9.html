Remember this

  • Actors are roles outside the system (humans, schedulers, other services). Use cases are their goals, written as one sentence each.
  • Nouns are class candidates, not classes. Drop frame nouns, merge synonyms, demote data to attributes.
  • Three kinds: entity (id + lifecycle), value object (immutable, equal by value), service (a verb across objects).
  • Look for hidden splits: Book vs BookCopy, Movie vs Show, Product vs InventoryItem.
  • Same behaviour, different data = one class, many objects (or an enum). Different behaviour that grows = interface + implementations.
  • Give each verb to the class that owns the data it reads; trace the main use case to test the model.
