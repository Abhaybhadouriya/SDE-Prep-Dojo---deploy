Quiz

Why does the snake keep both a deque and a hash set of its cells?

  1. The set keeps the order of the body
  2. The deque is needed for random food
  3. The deque gives O(1) head/tail changes; the set gives O(1) "is this cell body?"
  4. To make the snake thread safe
Order and membership are two different questions. Each structure answers one of them in O(1).

A length-4 snake, not growing, moves its head into the cell its tail occupies. What happens?

  1. Game over: the cell is in the body
  2. Legal: the tail leaves in the same tick
  3. The move is ignored
  4. The snake grows
The tail moves away during this tick, so the cell is free when the head arrives. It is a collision only when the snake grows this tick.

In advance(next), why remove the old tail from the set before adding the new head?

  1. If next equals the old tail, the other order would remove the head just added
  2. Removing is faster than adding
  3. Sets keep insertion order
  4. It does not matter
In the tail-chase case both are the same cell. Add then remove leaves the set one cell short of the deque.

The interviewer adds "the snake wraps around the edges". The cleanest change is:

  1. An if-statement in Snake.advance
  2. A flag in Board
  3. A new subclass of Game
  4. A new BoundaryPolicy implementation
The boundary rule is the Strategy; a new class leaves Game and Snake untouched (open/closed).

Moving RIGHT, the user presses UP and then LEFT within one tick. With a 2-slot buffer validated against the last buffered direction, the snake:

  1. Reverses into itself
  2. Moves up on the next tick, then left
  3. Ignores both keys
  4. Moves left at once
UP is valid after RIGHT and LEFT is valid after UP, so both are queued and applied one per tick.

Why does Game expose tick() instead of running its own timer?

  1. Timers are not allowed in Java
  2. It is faster
  3. Tests and replays become deterministic, and speed changes live only in the loop
  4. To avoid the Observer pattern
Separating time from rules makes the core a pure step function you can test instantly.

In Java, -1 % 4 evaluates to:

  1. -1, so wrap-around must use Math.floorMod
  2. 3
  3. 1
  4. An exception
Java's remainder keeps the sign of the dividend. Math.floorMod(-1, 4) is 3.
