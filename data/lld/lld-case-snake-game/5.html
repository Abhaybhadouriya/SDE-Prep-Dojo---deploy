From your world

BoundaryPolicy is a boundary_ops struct with one slot, next(head, dir, board): the walls version returns NULL at the edge, the wrap version returns the cell on the far side, and Game only ever calls through the pointer, like the VFS calling f_op->read. FoodSpawner and GrowthRule are two more such tables. The Status enum checked at the top of tick() and turn() is the same guard as if (sk->sk_state != TCP_ESTABLISHED) return -ENOTCONN;.

Patterns we deliberately skipped: a Singleton game (the tests run many games side by side), inheritance such as WrappingSnake extends Snake (wrapping is a rule about the board edge, not a kind of snake, so it is a strategy), and a Command object per key press (worth it only for replay, and the replay follow-up records plain (tick, turn) pairs).
