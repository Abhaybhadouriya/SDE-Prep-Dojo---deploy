Watch a change travel

The best way to feel coupling is to follow one change. Below, the tax rule changes (GST is now computed per line item). Step through both designs.

  1. Same six responsibilities, two designs. Left: classes call each other freely and read each other's fields. Right: Order talks to services; tax sits behind a TaxPolicy interface.
  2. The tax rule changes. On the left the Tax class is edited; on the right the GstTax implementation is edited.
  3. Left: every class that touched Tax's fields or methods must be re-checked - five of six. Right: callers only know TaxPolicy, whose signature did not change, so the change stops at the wall.
  4. This is the "what breaks if X changes" test in pictures. The number of red boxes is your practical coupling.
