The cohesion ladder

Cohesion has its own ladder, from "these things are together by accident" to "everything here does one job".

KindParts are grouped because...Example
Coincidentalno reason at allUtils with maskCard(), hoursCeil(), isWeekend()
Logicalthey are the same category of thing, chosen by a flagInputHandler.read(source) that reads keyboard, file or network depending on source
Temporalthey run at the same timestartup() that opens the DB, warms a cache and prints a banner
Proceduralthey run in a fixed ordervalidateThenLogThenSave() on unrelated data
Communicationalthey work on the same dataTicketReport that both counts and prints the same ticket list
Sequentialoutput of one part is input of the nextparse() -> validate() -> price() on one order
Functionalall parts serve exactly one well-defined jobFeeCalculator, TicketRepository
 
// BEFORE: coincidental cohesion. Three unrelated jobs, one name that says nothing.
final class Utils {
    static String maskCard(String n)   { return "****" + n.substring(n.length() - 4); }
    static long hoursCeil(long minutes) { return Math.max(1, (minutes + 59) / 60); }
    static boolean isWeekend(int dow)   { return dow >= 6; }
}

// AFTER: two functional classes. Each name tells you what is inside and what is not.
final class CardMasker   { static String mask(String n) { return "****" + n.substring(n.length() - 4); } }
final class BillingClock {
    static long hoursCeil(long minutes) { return Math.max(1, (minutes + 59) / 60); }
    static boolean isWeekend(int dow)   { return dow >= 6; }
}

Why does it matter? Everything that imports Utils for maskCard is now also coupled to billing rules. A change to weekend rules re-tests the payments code. Low cohesion inside one class creates hidden coupling outside it - the two ideas are two views of the same thing.

From your world

The kernel's lib/ directory could have been one giant utils.c. Instead it is split by function: lib/crc32.c, lib/rbtree.c, lib/kfifo.c, lib/bitmap.c. Each file is functionally cohesive, so the network stack can use kfifo without pulling in anything else. A driver's probe() is the honest exception: it is temporally cohesive by nature (everything that must happen at bind time), which is why good drivers keep it a short list of calls into well-named helpers.
