Measuring it (without a tool)

In an interview you will not run a metrics tool, but knowing what the tools measure gives you vocabulary.

  • Fan-out (efferent coupling, Ce) - how many other classes this class depends on. High fan-out means it is fragile: many things can break it.
  • Fan-in (afferent coupling, Ca) - how many classes depend on this one. High fan-in means it is responsible: changing it breaks many things, so it should be stable and abstract (an interface, a value object).
  • Instability (Robert C. Martin) - I = Ce / (Ca + Ce), from 0 (only depended upon) to 1 (only depends on others). Healthy designs have dependencies that point from unstable classes toward stable ones - the idea behind the Dependency Inversion Principle.
  • LCOM (lack of cohesion of methods) - roughly, how many pairs of methods share no fields. If half the methods use fields A and B and the other half use C and D, you have two classes glued together.

The quick manual version during a round: for each class on your diagram, count its outgoing arrows. Any class with five or more is a candidate for a facade, an interface or a split. Then read each class name and its method list together: if one method does not fit the name, move it.
