Interview questions about the round

How do you plan the first 15 minutes of a machine-coding round?

Read twice, mark P0 and bonus, write assumptions in a comment, list entities and services, and get an empty skeleton with a driver compiling. No feature code yet.

How to answer

Show the plan as a checklist: "P0 1-6 at the top of Main, entities X/Y/Z, one service per area, repositories as maps, custom exception, driver that runs." Then give your time budget.

Likely follow-ups
  • What if the doc is ambiguous and nobody is there to ask? (Assume, write it down, mention it in the review.)
Your code is elegant but two P0 features are missing. Your code is plain but everything runs. Which scores better?

Usually the plain one that runs. The Flipkart guideline puts demoable, functionally correct code first, and one candidate's experience was that fully running code beat neat but incomplete design (post 7591327 (2026-02-19)). Modularity and extensibility are still scored, so plain should still mean separated, named and validated.

How to answer

"Working P0 first, then refactor toward extensibility while it keeps running."

Likely follow-ups
  • How would you refactor it now? (Point to the first switch statement you'd turn into a Strategy.)
What does a good driver or test suite for a machine-coding round contain?

Every P0 feature shown once on its happy path, every documented error shown once, stable output, and one concurrency check if shared state exists. Commands in a table so the evaluator can add their own.

How to answer

Describe the command table and per-command catch from the driver above, and the self-check helper when no framework is available.

Likely follow-ups
  • Why not just write JUnit tests? (Do, if available; the driver is still the demo.)
The problem says "the system must be thread-safe". Where do you start?

List the shared mutable state (orders, partners, stock), then the operations that read-then-write it (assign, cancel, pickup). Each of those must be atomic. Start correct with a coarse lock, then refine to per-entity locks with a fixed lock order.

How to answer

Show it in code (a synchronized block or a lock per entity) and in a race test. Say why ConcurrentHashMap alone is not enough.

Likely follow-ups
  • Optimistic vs pessimistic locking? (See locks.)
  • How would auto-cancel run? (Scheduled executor, or a check with an injected clock.)
In the review: "How would you make this production-ready?"

Swap in-memory repositories for DB-backed ones behind the same interfaces, add transactions around multi-step operations, split services along the entity groups if they scale differently, add logging and metrics, and replace in-process locks with DB row locks or versioned updates.

How to answer

Point to the exact seams in your code. If you can say "only this class changes", the design answered the question for you.

Likely follow-ups
  • SQL or NoSQL for this data? (SQL when you need transactions across rows (money, bookings); a key-value store when access is by one key at high volume)
  • Which part would you make a separate service first? (the part with a different scaling or failure profile, such as notifications, behind an asynchronous queue)
AI is allowed in your machine-coding round. How do you use it well?

Design first yourself; ask the tool narrow questions; review every line aloud; write the risky logic yourself; keep running the driver after each change. Reports say interviewers grade the prompting and judgement (post 8462091 (2026-08-15), post 7575649 (2026-02-13)).

How to answer

Give one example of output you rejected and why. That is the signal.

Likely follow-ups
  • What did you not trust it with? (the concurrency and the core business rule; you write and check those yourself)
How do you show extensibility in a two-hour round without over-engineering?

Add an interface only where the doc already names two or more variants (two payment types, several split types, assignment policies). Elsewhere, keep classes concrete and say where you would add a seam. HelloInterview and workat.tech both warn that forcing patterns or unfinished P0 is a failure mode.

How to answer

"Variants in the doc get an interface now; guessed future variants get a comment."

Likely follow-ups
  • Add a third variant now - how many files change? (one new class and one registration line in the factory or the driver; nothing in the service)
Which language should you pick for machine coding?

The one you can type fastest with collections, sorting, string parsing and threads without looking anything up. Most rounds allow any mainstream language; Java is the most common in reports, and C++ is used too (post 7600874 (2026-02-22)).

How to answer

Coming from C: pick Java or C++ and drill the collections API until it is muscle memory. See OOP for C programmers.

Likely follow-ups
  • How do you express an interface in your language? (Java interface, Python abc.ABC or typing.Protocol, C++ a class with pure virtual functions; in C it is a struct of function pointers)
