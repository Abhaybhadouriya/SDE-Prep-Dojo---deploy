Scenario: the evaluator types a command you did not expect

They run cancel O9 for an order that does not exist.
A stack trace, and the demo ends.
The driver prints "order not found: O9" and keeps going, because each command is wrapped and the service validates ids. This is "fail gracefully" from the guideline.

Scenario: "make it thread-safe" in the review call

Your code uses plain HashMaps and no locks. The evaluator asks what happens with two partners picking up the same order.
"I'll use ConcurrentHashMap." (Safe map operations do not make the check-then-act on an order atomic.)
"The order's status check and change must be one atomic step. I'd lock per order, or compare-and-set the status. Partner and order locks would always be taken in the same order to avoid deadlock."
