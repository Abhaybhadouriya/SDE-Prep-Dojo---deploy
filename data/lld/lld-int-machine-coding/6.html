Tests in a round: small, fast, and visible

CRED's stated rubric counts unit tests (post 3984528 (2023-08-31, older post)); Atlassian's guide calls testing crucial; PhonePe reviewers want demo test cases even if they are not unit tests (post 3671731 (2023-06-23, older post)). In a browser editor you may not have JUnit or pytest, so the code above carries a 10-line test helper: check(name, condition) and expectThrows, and prints "N passed, M failed" before the demo.

Test these first
  • Each P0 rule once (book wins, second waitlisted, cancel promotes)
  • Each documented failure (unknown id, double book, cancel twice)
  • One concurrency race on the hottest resource
Skip in a 2-hour round
  • Mocks and test frameworks you must install
  • Tests of getters and setters
  • Tests that sleep or depend on the wall clock

The race test

The concurrency test starts 50 tasks on 8 threads, holds them at a start gate (a latch or event), releases them together, and asserts exactly one booking won. It passes because the check ("is the slot free?") and the act ("take it") happen under one lock per slot. Remove the synchronized (s) block and the test can fail intermittently - which is exactly the bug the evaluator asks about. More in booking and double allocation.

From your world

It is a smaller cousin of a torture test: hammer one lock from many CPUs and check the invariant afterwards. A start gate makes the threads collide on purpose, the way you would pin threads and release them together to provoke a race.
