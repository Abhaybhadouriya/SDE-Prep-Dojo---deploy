The time plan: 120 minutes and 90 minutes

The workat.tech guide splits the round into clarify (5-10 min), design (about 10-15), code (60-75) and demo. Candidate reports add an upload step (Flipkart gives about 15 min to zip and submit, post 5221179 (2024-05-28, older post)) and a review call. Here is a plan that fits both slot lengths.

Minutes (120 / 90)DoDone when
0-10 / 0-8Read the doc twice. Mark P0 and bonus. Write assumptions in a comment. Ask questions if someone is there to answer.A checklist of P0 features at the top of your main file.
10-20 / 8-15Entities as plain classes, enums for statuses, one service per area, in-memory maps, custom exception, an empty driver that runs."Hello" compiles and runs. Structure is visible.
20-75 / 15-65One P0 feature at a time: method, validation, a driver line that calls it. Compile and run after each.Each feature has a driver line that shows it working.
75-90 / 65-78Edge cases: unknown id, duplicate, wrong state (cancel twice), empty results. Each prints a clear error and the run continues.The demo shows both happy paths and graceful failures.
90-105 / 78-85Thread safety where state is shared (if not already P0), then the cheapest bonus.Still runs. Nothing half-done is wired in.
105-120 / 85-90Stop features. Clean names, remove dead code, short README (how to run, assumptions, what is done), zip and upload.Submitted on time. A late upload can void the round.

Watch the clock at minute 60. If fewer than half of the P0 features run, cut scope inside each feature (simple ordering instead of a strategy, one channel instead of three) rather than leaving features out. A working simple version scores; a perfect half-version does not.
