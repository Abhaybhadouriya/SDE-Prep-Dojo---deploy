Quiz

Every thread takes locks in increasing account-id order. Which Coffman condition is broken?

  1. Mutual exclusion
  2. Hold and wait
  3. Circular wait
  4. No preemption
Threads still hold one lock while waiting, but waits can only point "upwards" in rank, so they can never close a cycle.

Two threads use tryLock and both always sleep exactly 5 ms after a failure. What is the risk?

  1. Deadlock
  2. Livelock
  3. Data race
  4. Memory leak
Identical back-off keeps them in lockstep. Random (and usually exponential) back-off breaks the symmetry.

Why can't you fix a deadlock-prone path with a timeout if it uses synchronized?

  1. synchronized is not reentrant
  2. synchronized is always fair
  3. synchronized only works on static methods
  4. A thread blocked entering a monitor cannot time out or be interrupted
Use ReentrantLock.tryLock(timeout) or lockInterruptibly() when you need to give up.

A fixed pool of 4 threads runs tasks that each submit a sub-task to the same pool and call future.get(). Under load everything stops. Thread dump shows no "Java-level deadlock". Why?

  1. All 4 threads wait on futures whose tasks sit in the queue with no free thread: a wait cycle without locks
  2. The JVM has a bug
  3. future.get() always deadlocks
  4. The pool is too large
Deadlock is any cycle in waiting. The JVM only checks lock cycles, so it does not report this one.

PostgreSQL aborts your transaction with SQLSTATE 40P01. What should the application do?

  1. Ignore it
  2. Retry only the last statement
  3. Roll back and retry the whole transaction, and fix the update order
  4. Restart the database
The database broke the cycle by killing one victim. The victim's whole unit of work must be retried.

A writer never gets a read-write lock because readers keep arriving. This is:

  1. Deadlock
  2. Starvation
  3. Livelock
  4. Priority inheritance
The system progresses (readers finish), but one thread never gets a turn.

What does lockdep report that a thread dump cannot?

  1. Which thread is using the most CPU
  2. Memory leaks
  3. Network timeouts
  4. A possible lock-order cycle the first time it is seen, even if no hang happened
lockdep reasons about the order of lock classes, so it catches the bug on the first run of the inverted path.
