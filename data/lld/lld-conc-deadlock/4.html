The three fixes, as a design

In an LLD round you rarely write raw synchronized blocks for this. You put the rule in one place: an Account exposes its lock and its id, and a TransferService owns the policy for taking two locks. Callers never take two locks themselves.

Fix 1: one global lock order (breaks circular wait)

Give every lock a rank and always acquire in increasing rank. If every thread climbs the ranks in the same direction, no chain of waits can ever come back down to close a cycle. The rank must be stable and unique: a database id, a seat number, an enum "lock level" (ORDER < INVENTORY < PAYMENT). Avoid System.identityHashCode as the only rank: two objects can share a hash, so you need a tie-breaker lock for that case.

void transfer(Account from, Account to, long amt) {
    Account first  = from.id() < to.id() ? from : to;   // rank = id
    Account second = from.id() < to.id() ? to : from;
    first.lock().lock();
    try {
        second.lock().lock();
        try {
            from.debit(amt);
            to.credit(amt);
        } finally { second.lock().unlock(); }
    } finally { first.lock().unlock(); }
}

For N resources (book seats 14, 3 and 9 together), sort the ids and lock in that order. This is exactly the multi-seat hold in the double-booking lesson.

Fix 2: tryLock with timeout and back-off (breaks no-preemption)

Sometimes you cannot know the order up front (you discover the second resource only after reading the first). Then make your own preemption: take the first lock, try the second with a short timeout, and if it fails, release the first and start again after a short random sleep.

while (System.nanoTime() < deadline) {
    if (from.lock().tryLock(10, MILLISECONDS)) {
        try {
            if (to.lock().tryLock(10, MILLISECONDS)) {
                try { move(from, to, amt); return true; }
                finally { to.lock().unlock(); }
            }
        } finally { from.lock().unlock(); }          // give back what we hold
    }
    Thread.sleep(ThreadLocalRandom.current().nextInt(1, 5));   // RANDOM, or you get livelock
}
return false;   // surface "busy, try again" instead of hanging

synchronized cannot do this: a thread waiting on a monitor cannot time out or be interrupted. That is one of the main reasons to choose ReentrantLock in a design.

Fix 3: hold one lock, or none, while you call out (breaks hold-and-wait)

The sneakiest deadlocks are not two locks in one method. They are one lock in your class plus one lock in code you call while holding it: a listener, a callback, a logger, a Map.computeIfAbsent lambda that touches another map. Brian Goetz calls this calling an alien method. The rule: copy what you need under the lock, release it, then notify.

// BEFORE: listener runs while we hold our lock. If it calls back into us
// from another thread, or takes its own lock, we can deadlock.
synchronized void setStatus(Status s) {
    this.status = s;
    for (Listener l : listeners) l.onChange(s);
}

// AFTER: "open call". Mutate under the lock, notify outside it.
void setStatus(Status s) {
    List<Listener> snapshot;
    synchronized (this) {
        this.status = s;
        snapshot = List.copyOf(listeners);
    }
    for (Listener l : snapshot) l.onChange(s);
}

From your world

The kernel's notifier chains and callbacks have the same rule: you do not call blocking_notifier_call_chain() while holding a spinlock, and drivers often drop their lock before calling up the stack (for example before handing a packet to netif_rx()-style paths or calling a completion). "Drop the lock, then call out" is the open-call idea in C.

The code, run

The Java program shows all three behaviours in one run: the naive version deadlocks and the JVM itself finds the cycle (ThreadMXBean.findDeadlockedThreads(), the same check jstack runs); ordered locking finishes 200,000 opposite transfers; tryLock with back-off finishes 4,000 and conserves money. Python shows dining philosophers both ways. The C++14 tab is a toy lockdep: it learns lock order and warns about an inversion before any thread hangs. Files are in lld-code/lld-conc-deadlock/.

import java.lang.management.ManagementFactory;
import java.lang.management.ThreadInfo;
import java.lang.management.ThreadMXBean;
import java.util.concurrent.CountDownLatch;
import java.util.concurrent.ThreadLocalRandom;
import java.util.concurrent.TimeUnit;
import java.util.concurrent.locks.ReentrantLock;

// Three ways to move money between two accounts.
// 1. naive:   lock "from" then "to"  -> two opposite transfers deadlock.
// 2. ordered: always lock the lower id first -> no cycle, no deadlock.
// 3. tryLock: take the first lock, TRY the second with a timeout, back off and retry.
public class DeadlockDemo {

    static final class Account {
        final int id;
        long balance;
        final ReentrantLock lock = new ReentrantLock();
        Account(int id, long balance) { this.id = id; this.balance = balance; }
        public String toString() { return "acct-" + id; }
    }

    // ---------- 1. naive: lock order depends on the call -> deadlock
    static void transferNaive(Account from, Account to, long amt, CountDownLatch bothHoldFirst) {
        synchronized (from) {
            bothHoldFirst.countDown();
            try { bothHoldFirst.await(); } catch (InterruptedException e) { return; }
            synchronized (to) {                    // waits for the other thread forever
                from.balance -= amt;
                to.balance += amt;
            }
        }
    }

    // ---------- 2. global lock order: lower id first, always
    static void transferOrdered(Account from, Account to, long amt) {
        Account first = from.id < to.id ? from : to;
        Account second = from.id < to.id ? to : from;
        synchronized (first) {
            synchronized (second) {
                from.balance -= amt;
                to.balance += amt;
            }
        }
    }

    // ---------- 3. tryLock + random back-off (no global order needed)
    static int retries = 0;
    static boolean transferTry(Account from, Account to, long amt, long deadlineMs) throws InterruptedException {
        long stop = System.currentTimeMillis() + deadlineMs;
        while (System.currentTimeMillis() < stop) {
            if (from.lock.tryLock(10, TimeUnit.MILLISECONDS)) {
                try {
                    if (to.lock.tryLock(10, TimeUnit.MILLISECONDS)) {
                        try {
                            from.balance -= amt;
                            to.balance += amt;
                            return true;
                        } finally { to.lock.unlock(); }
                    }
                } finally { from.lock.unlock(); }       // give back what we hold
            }
            synchronized (DeadlockDemo.class) { retries++; }
            Thread.sleep(ThreadLocalRandom.current().nextInt(1, 5)); // random back-off breaks livelock
        }
        return false;                                    // caller decides: retry later or fail
    }

    public static void main(String[] args) throws Exception {
        // ---- 1. naive deadlock, detected with ThreadMXBean (what jstack does)
        Account a = new Account(1, 100), b = new Account(2, 100);
        CountDownLatch latch = new CountDownLatch(2);
        Thread t1 = new Thread(() -> transferNaive(a, b, 10, latch), "T1 a->b");
        Thread t2 = new Thread(() -> transferNaive(b, a, 20, latch), "T2 b->a");
        t1.setDaemon(true); t2.setDaemon(true);          // let the JVM exit despite the deadlock
        t1.start(); t2.start();
        Thread.sleep(300);
        ThreadMXBean mx = ManagementFactory.getThreadMXBean();
        long[] ids = mx.findDeadlockedThreads();
        System.out.println("1. naive: deadlocked threads = " + (ids == null ? 0 : ids.length));
        if (ids != null) {
            for (ThreadInfo ti : mx.getThreadInfo(ids)) {
                System.out.println("   " + ti.getThreadName() + " holds one monitor and waits for "
                        + ti.getLockName().replaceAll("DeadlockDemo\\$Account@\\w+", "an Account monitor")
                        + " owned by " + ti.getLockOwnerName());
            }
        }

        // ---- 2. ordered locks: 2 threads x 100k opposite transfers, finishes, money conserved
        Account c = new Account(3, 1_000_000), d = new Account(4, 1_000_000);
        Thread o1 = new Thread(() -> { for (int i = 0; i < 100_000; i++) transferOrdered(c, d, 1); });
        Thread o2 = new Thread(() -> { for (int i = 0; i < 100_000; i++) transferOrdered(d, c, 1); });
        o1.start(); o2.start();
        o1.join(5000); o2.join(5000);
        System.out.println("2. ordered: finished = " + (!o1.isAlive() && !o2.isAlive())
                + ", total = " + (c.balance + d.balance) + " (expected 2000000)");

        // ---- 3. tryLock with back-off: same opposite transfers, no order rule
        Account e = new Account(5, 1_000_000), f = new Account(6, 1_000_000);
        int[] ok = new int[2];
        Thread r1 = new Thread(() -> { try { for (int i = 0; i < 2000; i++) if (transferTry(e, f, 1, 1000)) ok[0]++; } catch (InterruptedException ignored) {} });
        Thread r2 = new Thread(() -> { try { for (int i = 0; i < 2000; i++) if (transferTry(f, e, 1, 1000)) ok[1]++; } catch (InterruptedException ignored) {} });
        r1.start(); r2.start();
        r1.join(); r2.join();
        System.out.println("3. tryLock: done " + (ok[0] + ok[1]) + "/4000 transfers, total = "
                + (e.balance + f.balance) + " (back-offs vary per run)");
    }
}

"""Dining philosophers: five threads, five forks (locks).
naive  : everyone picks up the LEFT fork, then the RIGHT one -> can deadlock.
ordered: pick up the LOWER-numbered fork first -> the cycle is impossible."""
import threading

N = 5
MEALS = 2000


def run(ordered: bool, timeout: float = 3.0) -> str:
    forks = [threading.Lock() for _ in range(N)]
    eaten = [0] * N
    all_left = threading.Barrier(N, timeout=1.0)    # forces the worst case in the naive version

    def philosopher(i: int) -> None:
        left, right = i, (i + 1) % N
        first, second = (min(left, right), max(left, right)) if ordered else (left, right)
        for meal in range(MEALS):
            with forks[first]:
                if not ordered and meal == 0:
                    try:
                        all_left.wait()             # everyone now holds exactly one fork
                    except threading.BrokenBarrierError:
                        pass
                with forks[second]:
                    eaten[i] += 1

    threads = [threading.Thread(target=philosopher, args=(i,), daemon=True) for i in range(N)]
    for t in threads:
        t.start()
    for t in threads:
        t.join(timeout)
    stuck = sum(t.is_alive() for t in threads)
    return f"meals={sum(eaten)}/{N * MEALS} stuck_threads={stuck}"


if __name__ == "__main__":
    print("naive   (left then right):", run(ordered=False))
    print("ordered (low fork first) :", run(ordered=True))

// A toy "lockdep": record the order in which lock CLASSES are taken and report a cycle
// the first time an inversion is SEEN, even if the deadlock never actually happened.
// Single-threaded on purpose (g++ 6.3 MinGW has no std::thread); the checker is the point.
#include <iostream>
#include <map>
#include <set>
#include <string>
#include <vector>

class LockDep {
    std::map<std::string, std::set<std::string>> after_;   // edge A -> B: "B was taken while holding A"
    std::vector<std::string> held_;                         // per-thread stack (one thread here)

    bool reachable(const std::string& from, const std::string& to, std::set<std::string>& seen) {
        if (from == to) return true;
        if (!seen.insert(from).second) return false;
        for (const auto& n : after_[from])
            if (reachable(n, to, seen)) return true;
        return false;
    }

public:
    // Called before every lock(). Returns false if this acquisition closes a cycle.
    bool acquire(const std::string& cls) {
        for (const auto& h : held_) {
            std::set<std::string> seen;
            if (reachable(cls, h, seen)) {           // cls -> ... -> h already exists, now h -> cls
                std::cout << "  WARNING: possible circular locking: holding " << h
                          << ", taking " << cls << ",\n           but the recorded order already says " << cls << " comes before " << h << "\n";
                held_.push_back(cls);
                return false;
            }
            after_[h].insert(cls);
        }
        held_.push_back(cls);
        return true;
    }
    void release(const std::string& cls) {
        for (auto it = held_.end(); it != held_.begin();) {
            --it;
            if (*it == cls) { held_.erase(it); return; }
        }
    }
};

int main() {
    LockDep dep;
    std::cout << "path 1: ioctl handler takes dev->lock then queue->lock\n";
    dep.acquire("dev->lock"); dep.acquire("queue->lock");
    dep.release("queue->lock"); dep.release("dev->lock");
    std::cout << "  ok, learned edge dev->lock -> queue->lock\n";

    std::cout << "path 2: completion path takes queue->lock then stats->lock\n";
    dep.acquire("queue->lock"); dep.acquire("stats->lock");
    dep.release("stats->lock"); dep.release("queue->lock");
    std::cout << "  ok, learned edge queue->lock -> stats->lock\n";

    std::cout << "path 3: stats timer takes stats->lock then dev->lock\n";
    dep.acquire("stats->lock");
    bool ok = dep.acquire("dev->lock");
    dep.release("dev->lock"); dep.release("stats->lock");
    std::cout << (ok ? "  no problem found\n" : "  -> cycle dev -> queue -> stats -> dev reported before any real hang\n");
    return 0;
}
