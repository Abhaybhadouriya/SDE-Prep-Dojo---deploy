Watch it happen: the bank transfer deadlock, step by step

The classic interview version: transfer(from, to, amount) locks from, then to. Alice sends money to Bob while Bob sends money to Alice.

  1. T1 runs transfer(a, b) and takes lock a. Nothing unusual.
  2. Before T1 reaches its next line, the scheduler runs T2, which runs transfer(b, a) and takes lock b.
  3. T1 now asks for b. T2 holds it, so T1 blocks, still holding a (hold and wait).
  4. T2 asks for a. T1 holds it, so T2 blocks too. All four Coffman conditions are now true. Neither thread can ever run again, and neither will ever release its lock.
  5. The fix: rank the locks. Both threads compute "lower id first", so both try a first. Whoever loses that race waits while holding nothing, so no cycle can form.
