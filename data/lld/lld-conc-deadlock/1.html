What exactly is a deadlock?

A deadlock is a set of threads where every thread is waiting for something that only another thread in the same set can give. Because all of them are waiting, none of them will ever give anything. The program does not crash. It just stops making progress, often only on one request path, which is why deadlocks are nasty to notice in production.

Four words you will use for the rest of the page:

  • Lock (mutex, monitor): something only one thread can hold at a time. In Java, synchronized (obj) takes the object's built-in monitor; ReentrantLock is the explicit version (both are covered in the locks lesson).
  • Critical section: the code between taking and releasing a lock.
  • Blocked: a thread that wants a lock someone else holds, and is waiting.
  • Wait-for graph: draw an arrow from thread X to thread Y when X waits for a lock Y holds. A deadlock is a cycle in this graph. Detection tools (the JVM, databases, lockdep) all look for this cycle.

The smallest deadlock in Java is two threads and two locks taken in opposite order:

// Thread 1                     // Thread 2
synchronized (a) {              synchronized (b) {
    synchronized (b) {              synchronized (a) {
        // move money                   // move money
    }                               }
}                               }

This code passes every unit test you write, because the two threads must interleave in one exact way: T1 takes a, T2 takes b, and only then each tries the second lock. Under real load that interleaving eventually happens. "It works on my laptop" is not evidence against a deadlock.
