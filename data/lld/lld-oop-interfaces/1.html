What each one is

  • Interface: a named set of method signatures, the what. In Java: interface PaymentGateway { String charge(String id, long paise); }. Methods are public and abstract unless marked default, static or private. Fields are only constants (public static final). No constructors, no instance state.
  • Abstract class: a class marked abstract that cannot be instantiated. It can have fields, constructors, finished methods, and abstract methods (no body) that subclasses must implement. It is an incomplete class, the what plus part of the how.
  • Concrete class: a normal class with every method implemented. Only these can be created with new.

Here is the interface in Java 21, with all three kinds of method it may contain:

// An INTERFACE is a contract: what you can ask for, not how it is done.
interface PaymentGateway {
    String charge(String orderId, long paise);        // abstract (implicitly public)

    default String chargeWithRetry(String orderId, long paise, int tries) {
        // default method: shared behaviour added to the contract (Java 8+)
        String last = "FAILED";
        for (int i = 0; i < tries && !last.startsWith("OK"); i++) last = charge(orderId, paise);
        return last;
    }

    static PaymentGateway alwaysOk() {                // static factory on the interface
        return (id, p) -> "OK " + id;
    }
}

And an abstract class. Notice the state (sent), the constructor, the final method that fixes the order of steps, the overridable hook format, and the hole deliver:

// An ABSTRACT CLASS is a half-built class: shared state + shared steps + holes to fill.
static abstract class AbstractNotifier {
    private int sent = 0;                             // state: interfaces cannot have this
    protected final String sender;

    protected AbstractNotifier(String sender) {       // constructor: interfaces have none
        this.sender = sender;
    }

    public final void notify(String user, String msg) { // template method, cannot be overridden
        String body = format(msg);
        deliver(user, body);
        sent++;
    }

    protected String format(String msg) { return "[" + sender + "] " + msg; } // hook, may override
    protected abstract void deliver(String user, String body);                // hole, must fill
    public int sentCount() { return sent; }
}

static final class SmsNotifier extends AbstractNotifier {
    SmsNotifier() { super("ACME"); }
    @Override protected String format(String msg) { // SMS is short: trim the message
        String s = super.format(msg);
        return s.length() > 30 ? s.substring(0, 30) + "..." : s;
    }
    @Override protected void deliver(String user, String body) {
        System.out.println("  SMS   to " + user + ": " + body);
    }
}

static final class EmailNotifier extends AbstractNotifier implements Retryable, Auditable {
    EmailNotifier() { super("acme.com"); }
    @Override protected void deliver(String user, String body) {
        System.out.println("  EMAIL to " + user + ": " + body);
    }
    @Override public int maxRetries() { return 3; }
}

The shape of AbstractNotifier (a final method that calls abstract steps) has its own name: the Template Method pattern. It is the most common reason to reach for an abstract class.
