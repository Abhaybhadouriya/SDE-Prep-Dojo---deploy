The story: a driving licence and a franchise kit

Explain like I'm 5

A driving licence is a promise: "this person can drive a car". A teacher, a doctor and a taxi driver can all have one. They are very different people, but if you need someone to drive, any of them will do. The licence says what they can do, not how they learned.

A pizza franchise kit is different. It comes with the oven, the sign, the dough recipe and the steps: "make dough, add toppings, bake 8 minutes". One thing is left blank: "choose your local toppings". Every shop built from the kit shares most of its work and only fills in the blank.

The licence is an interface: a contract that many unrelated classes can sign. The franchise kit is an abstract class: a half-built class with shared code and state, plus a few blanks (abstract methods) for its children to fill. One class can hold many licences (interfaces) but can come from only one franchise (in Java, one parent class).

From your world

An interface is like struct file_operations as a type: a list of function signatures with no code. Every driver provides its own table. An abstract class is like the kernel's usbnet framework: it implements most of a USB network driver (URB queues, RX and TX bottom halves, link handling) and asks each small "minidriver" to supply a struct driver_info with a few callbacks such as bind and rx_fixup. The framework is the shared base; the callbacks are the abstract methods.

Where this breaks: in C nothing stops a minidriver from leaving a required callback NULL. Java and C++ refuse to create an object until every abstract method has a body.
