Program to an interface

The Gang of Four book put one rule on its first pages: program to an interface, not an implementation. It means: declare fields, parameters and return types as the interface, and decide the concrete class in one place (a constructor argument, a factory, or main). The class that uses the dependency never writes new RazorGateway().

// Program to an interface: the service depends on the contract, not on a vendor.
static final class CheckoutService {
    private final PaymentGateway gateway;               // injected; never "new RazorGateway()" here
    CheckoutService(PaymentGateway gateway) { this.gateway = gateway; }
    String checkout(String orderId, long paise) { return gateway.chargeWithRetry(orderId, paise, 3); }
}

// A fake for tests: fails twice, then succeeds. No network needed.
static final class FlakyFakeGateway implements PaymentGateway {
    final List<String> calls = new ArrayList<>();
    @Override public String charge(String orderId, long paise) {
        calls.add(orderId);
        return calls.size() < 3 ? "FAILED" : "OK " + orderId;
    }
}

Click through what that buys you:

  1. CheckoutService only knows the interface. Its code compiles without any vendor class on the classpath.
  2. In production, main() (or a DI container) creates RazorGateway and passes it in.
  3. In a unit test, you pass a fake that fails twice and then succeeds, to test the retry logic without a network.
  4. Next year a new vendor arrives. You write one new class. CheckoutService is untouched: that is the Open/Closed Principle, and the dashed "depends on the abstraction" arrow is Dependency Inversion.

From your world

This is how the network stack treats drivers. dev_queue_xmit() was written once and calls dev->netdev_ops->ndo_start_xmit. A new NIC driver adds its own ops table and never edits the core. The test-fake trick is the same as using the dummy or veth devices to exercise the stack without hardware.

This is the core of two SOLID principles you will meet next: Dependency Inversion (depend on abstractions) and Interface Segregation (keep those abstractions small).
