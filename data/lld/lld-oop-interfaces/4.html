Default methods and the diamond rule

Before Java 8, adding a method to a published interface broke every class that implemented it. Java 8 needed to add methods such as forEach to Iterable and stream() to Collection without breaking millions of existing classes, so it introduced default methods: interface methods with a body that implementers inherit unless they override them.

Default methods let a class inherit behaviour from several interfaces, which brings back the old diamond question: what if two interfaces give the same method different bodies? Java's answer is three rules, in order:

  1. Classes win. A method from the superclass chain beats any interface default.
  2. More specific interface wins. If interface B extends A and both define the method, B's version is used.
  3. Otherwise you must choose. The class must override the method, and can call a chosen parent with InterfaceName.super.method().
// Two interfaces with the same default method: the class MUST resolve the clash.
interface Logs   { default String describe() { return "logs"; } }
interface Meters { default String describe() { return "meters"; } }
static final class Gateway implements Logs, Meters {
    @Override public String describe() {                 // compile error without this
        return Logs.super.describe() + "+" + Meters.super.describe();
    }
}
3. Default-method clash resolved explicitly: logs+meters

Careful: default methods are for evolving an interface and for small convenience helpers built on the abstract methods (like chargeWithRetry calling charge). They cannot touch instance state, because interfaces have none. If you find yourself wanting fields in an interface, you want an abstract class.
