Intent

Repository (Martin Fowler, Patterns of Enterprise Application Architecture; Eric Evans, Domain-Driven Design): give the domain a collection-like interface for getting and storing entities, and hide how and where they are stored. Service Layer: put each use case ("borrow a book", "book a seat") in one application service that coordinates entities and repositories and owns the transaction or lock.

From your world

A repository is the storage backend behind a fixed ops API, like a block driver behind block_device_operations: callers ask for blocks (here: books) and never learn whether they come from RAM, flash or the network. The service is the code path that holds the lock across check-then-update, like holding a spinlock across a refcount check and a list insert. In an LLD round, "the transaction" is usually just that: one lock (or a synchronized method) held across the read, the rule check and the save.

Neither is a Gang of Four pattern. They are architecture patterns, and in LLD rounds they are the frame that the GoF patterns hang on: your Strategy for pricing sits inside a service; your Factory creates entities that a repository stores.

The key word is collection-like. Code using a repository should feel like it is using a Map or a Set of domain objects (findById, save, findByStatus), not like it is writing SQL.
