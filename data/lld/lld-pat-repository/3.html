Two different rules, often mixed up. Run-time calls go down: a repository never calls a service, and an entity never calls a repository. That alone is plain layering. The Dependency Inversion Principle is about source-code dependencies: the service layer owns the repository interface, and the low-level InMemoryBookRepository depends upward on it (it imports and implements it). Without inversion the service would import the storage class; with it, storage imports the service's contract. A strong interviewer will probe exactly this difference.
