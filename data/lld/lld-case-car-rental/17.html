Booking A is [10:00, 12:00). Which request overlaps it?

  1. [12:00, 13:00)
  2. [08:00, 10:00)
  3. [09:00, 15:00)
9 < 12 and 10 < 15, so they overlap (it contains A). The other two only touch A's edges, which half-open ranges allow.

Why is "is it free?" followed by "insert" a bug without a lock?

  1. Insert is slow
  2. Two threads can both pass the check before either inserts, so both book the car
  3. Java lists cannot hold reservations
Check-then-act must be atomic for the same car.

Why lock per vehicle instead of one lock for the service?

  1. Bookings of different cars never wait for each other
  2. It uses less memory
  3. Java does not allow a lock on the service
Fine-grained locks remove contention between unrelated cars while still serialising the race that matters.

  2. Hold the per-car lock until payment returns
  3. Book after payment without checking again
