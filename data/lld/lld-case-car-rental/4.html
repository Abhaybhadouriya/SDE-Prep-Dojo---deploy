Class diagram

How to read this: + public, - private, «interface» a type with only method signatures (an ops table), 1..* one-to-many. Filled diamond = owns (the part dies with the whole), hollow diamond = has (can be swapped), solid line with hollow triangle = extends, dashed line with hollow triangle = implements, dashed arrow = depends on or creates. More in UML class diagrams and relationships.

  • Vehicle and Branch are records: static facts, safe to share between threads.
  • TimeSlot is a value object that validates itself (end after start) and knows how to overlap and count billable hours.
  • Reservation is the only mutable entity. Its status changes only through pickUp(), cancel() and complete(), which check the current state.
  • RentalService holds vehicles, reservations, a per-vehicle list of reservations (the index we check for overlap) and a per-vehicle lock object.
  • Spec<T> filters vehicles and combines with and, or, not. PricingStrategy computes a price; WeekendSurcharge wraps another strategy.
