Key relationships and patterns (and why each)

PatternWhereWhy
Strategy (twice)DriverMatchingStrategy, FareStrategyBoth are rules that product teams change all the time (nearest, best rated, least idle; normal, surge, airport flat fare). Swapping one is a setter call, as the demo does.
State (state machine)TripStatus.canMoveTo, Trip.moveToOne place decides legal transitions, so "start a cancelled trip" is impossible everywhere. We use an enum with a transition table because each state has no other behaviour; switch to one class per state when states gain behaviour (for example, fare rules per state, or timeouts).
DecoratorSurgeFare wraps any FareStrategySurge, discounts and taxes stack: new Tax(new Surge(new Standard(), 1.5)). No class explosion.
ObserverTripListenerNotifications, receipts, analytics and driver-app updates react to trip changes without the service knowing them.
Optimistic concurrency (CAS)Driver.tryReserve()The check "is this driver free?" and the act "take this driver" become one atomic step. No global lock on the matching path.
