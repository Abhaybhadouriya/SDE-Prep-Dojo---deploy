Common mistakes

  • Check-then-act on driver status: if (d.isAvailable()) { d.setAvailable(false); ... } without atomicity. The classic double booking.
  • One giant synchronized method and no idea how it scales; or the opposite, locks everywhere with no clear invariant.
  • Claiming concurrency without a test. Uber candidates report that the multithreading scenario is run.
  • Status as free-form strings or booleans (isStarted, isCancelled) instead of one state field with legal transitions.
  • Fare logic in Trip with if (cab == PREMIUM); no way to add surge cleanly.
  • Releasing the driver before moving them to the drop location, so the next match uses the wrong position.
  • Drifting into HLD (Kafka, sharding) before the in-memory core runs. Answer briefly, then return to the code.
