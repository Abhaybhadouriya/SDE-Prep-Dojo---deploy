The story: the school post office

Explain like I'm 5

Children in a school do not run around handing notes to each other. Every note goes to the school post office. The postmaster writes a number on it ("note 7 for the chess club"), puts a copy in the pigeonhole of every club member, and keeps one copy in the club's big book.

If Ben is at school, the postmaster hands him his copy at once and tells Asha "Ben has it" (one more tick). When Ben opens it, the postmaster tells Asha "Ben read it" (blue ticks). If Ben is at home, his copies wait in the pigeonhole and are handed over in number order the moment he walks in. A new club member gets a pigeonhole from today on; the old notes in the big book are not for him.

From your world

The per-chat sequence number is a TCP sequence number: the sender side assigns it under a lock, and the receiver can always put data back in order and spot duplicates, whatever order the network delivers it in. Pending messages for an offline user are a socket receive queue that fills while nobody calls recv(). The receipt per recipient is a protocol state machine like TCP's connection states: a fixed table of legal moves, never backwards. And "push only if this connection has not been pushed this message yet" is the same trick as test_and_set_bit() guarding work that should happen once; the DELIVERED tick itself waits for the device's acknowledgement, like a TCP ACK.

Interfaces in C terms: every interface on this page is, in C, a struct of function pointers; each implementation fills one in, like file_operations. Java and C++ build that table (the vtable) for you, and every object carries a pointer to it. More in OOP from C structs and polymorphism and vtables.
