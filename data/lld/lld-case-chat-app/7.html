APIs and interfaces

// facade (Mediator)
void        register(User u);
DirectChat  direct(String a, String b);                     // idempotent per pair
GroupChat   group(String creator, String name, String... members);
void        addMember(String by, String chatId, String user);    // admin only
void        removeMember(String by, String chatId, String user); // admin, or self-leave
Message     send(String sender, String chatId, String text);     // throws ChatException
void        connect(String user, ChatClient device);         // delivers pending in order
void        disconnect(String user);
int         markRead(String user, String chatId, long uptoSeq); // returns how many changed
int         unread(String user, String chatId);
List<Message> history(String user, String chatId, long beforeSeq, int limit);

// extension points
interface ChatClient {                                       // Observer
    void onMessage(Message m);
    void onReceipt(Message m, String byUser, Receipt now);
}
enum Receipt { SENT, DELIVERED, READ;                        // State: onDelivered(), onRead()
}

If the interviewer wants REST: POST /chats/{id}/messages returns the message with its seq; POST /chats/{id}/read {"upto": 42}; GET /chats/{id}/messages?before=120&limit=50. The sequence number is the cursor, never an offset, so paging stays stable while new messages arrive. Pushes go over the socket, not REST. See API design in LLD.

Cost of each operation

OperationCostNote
sendO(M) fan-outAppend is O(1) under the chat lock; then one receipt per member and one push per online member, after unlock. A 500-member group costs 500 receipt entries and up to 500 pushes per message: this is why large groups are fanned out by a queue in real systems.
connect (sync)O(C + P)Walk the user's C chats and re-push the P messages still SENT for them.
ackO(1)Seqs are 1..n with no gaps, so the message is an array index.
markRead(upto)O(V)Walks the V messages visible to the user; an index from seq to message plus a per-user "read up to" mark makes it O(changed).
history(before, limit)O(V) here, O(log n + limit) with an indexOur version filters the visible list; a real store seeks to before in a seq-ordered index.
unreadO(V)Keep a per-user counter if the badge is shown often.
