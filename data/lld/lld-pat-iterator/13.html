Quiz

What is the main goal of the Iterator pattern?

  1. Make collections thread-safe
  2. Traverse elements without exposing the collection's internal storage
  3. Add operations to elements without changing their classes
  4. Sort a collection
Thread safety is a separate concern; adding operations per type is Visitor.

Why does modifying an ArrayList inside a for-each loop usually throw?

  1. ArrayList is immutable
  2. The JVM locks the list during loops
  3. The iterator sees that the list's modCount no longer matches the value it saved
  4. for-each copies the list first
That is the fail-fast check. It is best-effort bug detection, not locking.

Which iterator never throws ConcurrentModificationException because it walks a copy?

  1. CopyOnWriteArrayList's iterator
  2. HashMap's key iterator
  3. LinkedList's iterator
  4. ArrayList's list iterator
Copy-on-write lists give snapshot iterators. The others are fail-fast.

A BST iterator with a stack uses how much extra memory?

  1. O(1)
  2. O(n)
  3. O(n log n)
  4. O(h), the height of the tree
The stack holds at most one root-to-leaf path of left children.

list.forEach(x -> print(x)) is an example of:

  1. External iteration
  2. Internal iteration
  3. A fail-safe iterator
  4. The Visitor pattern
The collection drives the loop and calls your function for each element.

In the kernel, why use list_for_each_entry_safe?

  1. It takes a spinlock
  2. It is faster
  3. It saves the next node before the body runs, so the body may delete the current node
  4. It walks the list in reverse
Without it, the macro reads next from a node the body may have freed. Locking is still your job.

Calling hasNext() twice in a row skips an element in your custom iterator. What is the bug?

  1. hasNext() consumes an item instead of buffering it for next()
  2. next() should throw
  3. The iterator should be a singleton
  4. The collection is not thread-safe
hasNext() must be idempotent: if it has to read ahead, keep the item in a look-ahead slot.
