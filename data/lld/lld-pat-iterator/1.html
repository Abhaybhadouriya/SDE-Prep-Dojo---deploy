The problem: loops that know too much

Say a music app keeps a playlist in an array, and three screens loop over it:

class Playlist {
    String[] songs;   // public, so everyone can loop
    int size;
}

// Screen 1
for (int i = 0; i < p.size; i++) show(p.songs[i]);
// Screen 2 (shuffle)
int[] order = shuffle(p.size);
for (int k : order) play(p.songs[k]);
// Screen 3 (export)
for (int i = 0; i < p.songs.length; i++) write(p.songs[i]);   // bug: length, not size

Count the pains:

  • Storage leaks out. Every caller knows it is an array with a separate size. Screen 3 already has a bug: it loops to songs.length and prints null slots.
  • Change the storage, break everyone. Move to a linked list, a ring buffer or a database with paging, and every loop must be rewritten.
  • Traversal logic is copied. The shuffle loop and an "only liked songs" loop end up pasted into several classes.
  • No safety. If one screen adds a song while another is looping, nothing notices. You get skipped items, duplicates or a crash later.

We want callers to say "give me the next song" and nothing more.
