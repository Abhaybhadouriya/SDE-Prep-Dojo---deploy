APIs and interfaces

RentalPlatform app = new RentalPlatform();
app.register("asha"); app.login("asha");
Listing l = app.list("asha", "2BHK near lake", "gym, pool", "Bellandur", "HSR Layout",   // nearby csv
                     ListingType.RENT, "32k", "1100 sqft", 2);
Page<Hit> p = app.search(SearchQuery.builder()
        .locations("bellandur, hsr layout").includeNearby()
        .type(ListingType.RENT).price("20k-40k").bhk(2, 3)
        .text("pool")                     // or .typeahead("balc") for prefix on the last word
        .sortBy(SortBy.PRICE_ASC).page(0, 10)
        .build());
app.shortlist("meera", l.id);  app.shortlisted("meera");
app.markSold("asha", l.id);    app.changePrice("asha", l.id, "30k");

interface Spec<T> {                      // Specification
    boolean test(T t);
    default Spec<T> and(Spec<T> o) { return x -> test(x) && o.test(x); }
}
  • Validation: bad prices ("abc", "0"), empty ranges ("40k-20k"), bad page numbers or sizes (over 100), unknown listings, acting while logged out and editing someone else's listing all fail with a clear message.
  • REST shape: GET /listings?loc=bellandur,hsr&type=RENT&price=20k-40k&bhk=2,3&q=pool&sort=price&page=0&size=10, POST /listings, PATCH /listings/{id}, PUT /users/{u}/shortlist/{id}. For deep paging, return a cursor (after=<sortKey, id>) instead of a page number.
  • Blog variant: the same TextIndex with add(id, title, body), remove(id), matchAll(terms); "order by frequency" is sorting the returned scores, "by created / updated" is a comparator on the document's timestamps. Categories are one TextIndex per category, or a category Spec.
