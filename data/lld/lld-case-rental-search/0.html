The story: the librarian's card box

Explain like I'm 5

A town has many houses to rent. A helpful librarian keeps a card for every house: where it is, how much it costs, how many rooms. When a family asks "a 2-room house near the lake, not too costly", she does not walk to every house. She has a second box of cards sorted by word: under "lake" she finds the house numbers that mention a lake, under "pool" the ones with a pool. She takes the short pile, throws out the ones that cost too much or have too few rooms, puts the cheapest on top, and hands over the first five.

When a house is rented, she does not burn the cards. She stamps it "taken", so new families do not see it, but a family that had kept it on their wish list can still see it was taken.

From your world

An inverted index is the dentry cache turned inside out: instead of "for this file, which name?", it answers "for this word, which documents?" in one hash lookup. The query "pool AND gym" walks the shorter list and probes the longer one, the same trick as checking the smaller of two hash buckets first. And the filter chain is a classifier pipeline: like tc filters or iptables matches, each rule is a small predicate and a packet (here, a listing) has to pass all of them.

Interfaces in C terms: every interface on this page is, in C, a struct of function pointers; each implementation fills one in, like file_operations. Java and C++ build that table (the vtable) for you, and every object carries a pointer to it. More in OOP from C structs and polymorphism and vtables.
