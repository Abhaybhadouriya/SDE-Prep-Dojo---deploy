Class diagram

  • RentalPlatform (Facade) maps the statement's commands: users, list, search, shortlist, mark sold. It checks who is asking and parses units; it holds no search logic.
  • ListingSearchEngine owns the primary store byId and two secondary indexes: TextIndex and byLocation (locality to ids, including listings that name it as nearby). upsert and remove change all three under the write lock; search reads under the read lock.
  • TextIndex is the inverted index: postings (term to id to weight, in a TreeMap so a prefix is a range scan) and forward (id to its terms, so remove deletes exactly what add created). It knows nothing about listings, so the Razorpay blog variant reuses it unchanged.
  • SearchQuery is built with a Builder because every parameter is optional. toSpec() composes only the filters that were set.
  • Spec and ListingSpecs are the Specification pattern: one predicate per rule plus and / or / not.
  • SortBy is the ranking Strategy as an enum of comparators. full() always puts exact-location matches before nearby ones and ends with the id, so the order is total and pages never overlap.
