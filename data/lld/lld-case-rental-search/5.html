From your world

The Spec chain is netfilter matches on one rule: -m iprange -m tcp --dport 443 is a list of small match functions, each a function pointer that returns true or false, and the packet must pass all of them. SortBy is the cmp function pointer you pass to sort() in lib/sort.c: the sort code is fixed, the ordering is plugged in. The Builder is a designated initializer, struct query q = { .city = "...", .max_price = 40000 }, with validation when you call build().

Patterns we deliberately skipped: a Singleton engine (tests and the concurrency demo each need their own), a Visitor over listing types (rent and sale differ in one field, not in behaviour), and one class per filter combination (the combinatorial explosion that Specification exists to avoid: filters are composed at runtime, not inherited, see composition over inheritance). A Repository in front of byId is the right next step when they ask for persistence.
