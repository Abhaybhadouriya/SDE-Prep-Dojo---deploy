APIs and interfaces

// what application code sees: tiny on purpose
Logger log = LogManager.get().getLogger("payments");
log.info("charge started id=" + id);
log.error("gateway timeout");

// what the platform team sees: configuration, never in business code
LogManager.get().configure(LoggerConfig.builder()
        .minLevel(LogLevel.INFO)
        .handler(LogLevel.INFO,  new PlainFormatter(), new ConsoleSink())
        .handler(LogLevel.DEBUG, new JsonFormatter(),  new AsyncSink(new FileSink(path), 10_000))
        .handler(LogLevel.ERROR, new PlainFormatter(), pagerSink)
        .build());

// extension points: implement one of these
interface LogFormatter { String format(LogMessage m); }
interface LogSink extends Closeable { void write(String line); default void close() {} }

Notice what is not in the caller API: no sink name, no formatter, no file path. Callers state what happened and how bad it is; configuration decides where it goes. That is the exact point the PhonePe reviewer made.
