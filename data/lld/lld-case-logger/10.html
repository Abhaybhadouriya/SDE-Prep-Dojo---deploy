Extensibility: the follow-ups interviewers add

  1. "Add a DB / Kafka / Slack sink." One new class implementing LogSink; wrap it in AsyncSink because it is slow. Nothing else changes (Open/Closed).
  2. "Search logs for a word" (Swiggy). A SearchIndexSink that keeps an inverted index word -> line numbers. It is in the Java code above and in the demo (step 6). Mention that at scale this is what Elasticsearch does, and link to the HLD design.
  3. "Rotate the file at 10 MB." A RollingFileSink decorator: count bytes, and when over the limit, close, rename to app.log.1, reopen.
  4. "Stop a noisy logger" (rate limiting / sampling). A new handler before the sinks that may stop the chain: this is where Chain of Responsibility beats a plain list.
  5. "Mask card numbers and emails." A scrubbing formatter decorator that runs a regex before the real formatter.
  6. "Per-request id in every line." A context map (MDC) stored in a ThreadLocal; the formatter reads it. Warn that thread pools must clear it after each task.
  7. "Different level for one package." Hierarchical logger names (a.b.c inherits from a.b), like Java's and Python's built-in logging.
  8. "Workflow state-transition logger" (Salesforce variant). Same skeleton; the message becomes a typed event (step, from-state, to-state, time) and one sink is an append-only history store.
