Key relationships and patterns, and why each

PatternWhereWhy here (the sentence to say)
Chain of ResponsibilityLogHandler.nextEach handler decides on its own whether the message is for it. Adding a pager handler is one new link, no if ladder in the logger. Ours is the pass-through style: every handler sees every message; a classic "first one wins" chain is a one-line change.
Strategy (x2)LogFormatter, LogSink"How it looks" and "where it goes" vary independently. Any formatter works with any sink: 2 formats x 4 sinks = 8 combinations from 6 classes, not 8 subclasses.
Singleton (+ registry)LogManagerOne configuration per process, reachable from anywhere. Named loggers are cached in a ConcurrentHashMap (a "multiton"). Eager init: the JVM makes class init thread-safe for free.
DecoratorAsyncSinkAsync is a property you add to any sink, not a new kind of sink. It has the same interface and wraps the real one, so callers and handlers do not change.
BuilderLoggerConfig.BuilderConfig has optional parts and an ordered list of handlers; the builder validates ("at least one handler") and returns an immutable object that can be swapped in one write.
Producer-consumerqueue inside AsyncSinkMany app threads produce lines; one writer thread consumes. Bounded queue = backpressure policy in one place.

Why not one big Logger with a list of sinks? You can, and for a 45-minute round a list is fine. Say so. The chain earns its keep when handlers must be able to stop a message (sampling, dedupe, PII scrubbing filters) or when the order matters. Being able to argue both is worth more than picking the "right" one, as the Razorpay report shows.

From your world

LogSink is struct console: a name plus a write(struct console *, const char *, unsigned) function pointer, registered with register_console(). LogFormatter is the strategy you pass in a function pointer. The chain is the netfilter idea again: a list of hooks, each returning "mine / not mine / stop". The Singleton is a file-scope static struct with an init function guarded by DEFINE_MUTEX or done once at boot.
