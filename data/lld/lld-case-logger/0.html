The story: the school diary

Explain like I'm 5

Every child in class has a diary. When something happens, the child writes one line: "9:05 - I spilled the paint". Small things ("I sharpened my pencil") are only for the diary. Bigger things ("I hurt my knee") also go to the class teacher. Very big things ("the fire alarm rang") go to the diary, the teacher and the principal.

The child does not walk to each person. The child just says "this is a BIG thing" and hands the note to the first person in a line. Each person in the line reads how big it is, keeps a copy if it is big enough for them, and passes it on.

That is a logging framework. The child is your code calling log.error(...). "How big" is the level (DEBUG, INFO, WARN, ERROR, FATAL). The diary, teacher and principal are sinks (file, console, pager). The line of people is a chain of handlers. The way the note is written (plain sentence or a JSON form) is the formatter.

From your world

You have used this design for years. printk(KERN_ERR "eth0: link down\n") carries a level (the KERN_* prefix, 0 to 7). The kernel compares it with console_loglevel and only prints to the console when the message is important enough, but it always appends the record to the log buffer (a ring), which dmesg and klogd/journald read later. Many consoles can be registered (serial, netconsole, VGA), each with its own write function: that is a list of sinks behind one function-pointer interface. pr_debug compiles away unless dynamic debug turns it on: that is the "cheap early exit" every interviewer wants to hear about.
