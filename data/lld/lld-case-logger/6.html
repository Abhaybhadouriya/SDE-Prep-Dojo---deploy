Core flow: one log.error() call

  1. The service calls error("timeout"). The logger reads the current config with one volatile read. No lock: the config object is immutable and replaced as a whole.
  2. Cheap early exit first: if the level is below the global minimum, return before allocating anything. Otherwise build an immutable LogMessage (timestamp, level, logger name, thread) and hand it to the head of the chain.
  3. Handler 1 (console, threshold INFO): ERROR passes, so it formats with its formatter and writes. Then it always passes the message on: this chain is pass-through.
  4. Handler 2 (file, threshold DEBUG) formats and calls write on an AsyncSink. That only puts the line in a bounded queue and returns. The service thread is done: no disk wait.
  5. The writer thread takes lines off the queue in order and does the slow file write. On shutdown, a "poison pill" is queued last, so every line before it is written first.

Shutdown and reconfigure are the other two flows worth one sentence each. Reconfigure: build a new config, publish it with one write to the volatile field, then close the old chain (async sinks drain first). Shutdown: close every sink in chain order; register it as a JVM shutdown hook in real code.
