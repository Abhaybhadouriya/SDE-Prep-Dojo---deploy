Interview follow-ups (Q&A)

Why not make Snake and Ladder separate classes?

Today they hold the same data (start, end) and have the same behaviour (move the piece to end). Two classes would duplicate code and force every lookup to check two collections. One Jump value with a derived isSnake() is enough. If they later behave differently (a snake bite costs a life), Jump becomes an interface and each gets its own class; callers already go through board.resolve(), so they do not change.

How to answer

Data and behaviour first, then YAGNI, then show how you would grow it.

Likely follow-ups
  • How would you add a "skip next turn" cell?
How do you support two dice or a loaded die?

Dice is a Strategy with one method, roll(). Two dice is new RandomDice(2, 6, seed); a loaded die is a new class implementing Dice. The game loop is unchanged. The same seam gives us FixedDice for tests.

How to answer

Point to the interface and say "constructor argument, zero edits to Game".

Likely follow-ups
  • With two dice, does "a six" mean a double six or a total of six? (Ask; it changes the rule, not the dice.)
Add "a six gives another roll, three sixes in a row cancel the turn".

Remember the position at the start of the turn and count sixes. Loop while the roll is a six and the player has not won. On the third six, restore the starting position and end the turn. Keep the rule switches in a Rules object so the classic game still works with defaults.

How to answer

State the precedence order (three-sixes check, overshoot, move, extra roll) before coding it.

Likely follow-ups
  • Does a ladder climbed during a cancelled turn get undone? (Yes, the whole turn is undone.)
How do you detect an invalid board, such as an infinite loop of jumps?

In build(), follow the chain from every jump start with a visited set; seeing a cell twice means a cycle. Also check ranges, one jump per cell, direction, and no jump starting on the last cell. Because the builder is the only way to make a Board, a Board object is always valid and resolve() can loop without a guard.

How to answer

"Validate once at construction, then trust the invariant."

Likely follow-ups
  • Cost? O(J^2) worst case for J jumps; fine for 20 jumps. A colouring DFS makes it O(J).
Why a queue for turns instead of an index into a list?

Removing a winner from a list while you hold an index is a classic off-by-one bug. With a deque, the current player is always the head; a winner is simply not put back. Ranking mode and "player leaves mid-game" both become trivial.

How to answer

Name the bug you avoided.

Likely follow-ups
  • How would you let a player quit mid-game?
Where does printing go, and why not just call System.out in the game?

Into a GameListener (Observer). The game emits events; the console printer formats them. Tests attach a spy, a UI attaches its own listener, and the evaluator's "print the board after every move" request is a new listener. Printing inside the game would couple the rules to one output format.

How to answer

Mention testability and the "different output" follow-up.

Likely follow-ups
  • What if a listener throws? (Catch and log per listener so one bad observer cannot stop the game.)
How would you generate a random valid board?

A BoardGenerator picks random (start, end) pairs, skips cells already used and the last cell, and calls the builder. If build() throws (cycle), retry with a new seed. Keep it out of Board so generation rules (how many snakes, minimum length) can change on their own.

How to answer

Reuse the builder's validation instead of writing a second one.

Likely follow-ups
  • How do you guarantee the game is winnable? (No jump on the last cell; with a die of 1..6 every cell is reachable.)
Make it an online game: many games, players on phones. What changes in the LLD?

The domain classes stay. Add a GameService that holds games by id, a per-game queue or lock so turns are applied one at a time, a turn number on each request for idempotency, and a "not your turn" check. Listeners push events to a message queue instead of the console. Persistence stores the move log; a game can be rebuilt by replaying it with FixedDice.

How to answer

Keep the core unchanged; add a service layer and a concurrency boundary per game.

Likely follow-ups
  • How do you stop a client from faking dice rolls? (Rolls happen only on the server.)
Add capture: landing on another player's cell sends them to 0.

Introduce a post-move hook: interface MoveRule { void afterMove(Player p, Game g); } and a list of rules in the game. CaptureRule scans other players and resets those on the same cell, emitting an event. The core loop changes once (call the hooks); every later rule is a new class.

How to answer

Show the one-time refactor from flags to rule objects.

Likely follow-ups
  • Should capture apply on the cell you climb to, or the cell you first landed on?
How would you add undo of the last move?

Record each applied move as a Command object holding player, from and to (and anything captured). Push it on a stack; undo() pops it and restores positions and the turn queue. This also gives replay and an audit log for free.

How to answer

Command pattern, and remember the turn queue is part of the state.
