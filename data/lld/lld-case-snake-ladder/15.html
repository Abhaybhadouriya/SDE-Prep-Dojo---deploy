Common mistakes

  • Hard-coding 100 and 6 all over the code. Make them inputs.
  • Printing inside Game, so tests have to parse console output.
  • Using Math.random() directly, so no test can predict a move.
  • Following only one jump instead of the chain, or following chains with no cycle check.
  • Index-based turn order that skips or repeats a player after someone wins.
  • A God class: one Game with 300 lines that also parses input and draws the board.
  • Over-design: 100 Cell objects, a Singleton game, a State class per turn phase. Simple wins this problem.
  • No demo: the code compiles but there is no main that shows a full game.
