What is the simplest correct model for snakes and ladders on the board?

  1. 100 Cell objects, each with optional Snake and Ladder fields
  2. A map from start cell to a Jump(start, end)
  3. Two lists, one of snakes and one of ladders, scanned every move
A map gives O(1) lookup, stores only the cells that matter, and one Jump type covers both directions.

The interviewer asks for two dice. With the design on this page, what changes?

  1. Game.playTurn() gets an if for two dice
  2. A new subclass of Game
  3. Only the constructor argument: new RandomDice(2, 6, seed)
Dice is a Strategy, so the game never knows how many dice there are.

A ladder from 10 ends at 29, and 29 is a snake head down to 9. A player lands on 10. Where do they end?

  1. 9
  2. 29
  3. 10
resolve() follows the chain until the piece rests on a cell with no jump.

Why does the Board builder check for cycles?

  1. To make lookups faster
  2. Otherwise resolve() could loop forever on a board like 10 to 20 and 20 to 10
  3. Because Java maps cannot hold cycles
Validating at construction makes "a Board is always valid" an invariant, so resolve() can loop without a guard.

Which pattern lets you change the output format without touching Game?

  1. Singleton
  2. Builder
  3. Observer (GameListener)
The game emits events; any listener can format or record them.

Hundreds of games run on one server. What must be shared and locked?

  1. Nothing mutable: each game owns its state, and the shared Board is immutable
  2. One global lock around all playTurn() calls
  3. A synchronized singleton Dice
Per-game ownership plus immutable shared data needs no cross-game locks.

Why do the tests use FixedDice?

  1. It is faster than Random
  2. A test must know every roll to assert exact positions
  3. Random is not allowed in Java tests
A scripted Strategy makes the game deterministic, which is the whole point of putting dice behind an interface.
