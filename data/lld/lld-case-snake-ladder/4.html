Class diagram

How to read this: + public, - private, «interface» a type with only method signatures (an ops table), 1..* one-to-many. Filled diamond = owns (the part dies with the whole), hollow diamond = has (can be swapped), solid line with hollow triangle = extends, dashed line with hollow triangle = implements, dashed arrow = depends on or creates. More in UML class diagrams and relationships.

  • Game owns the turn queue, the winners list and the end condition. It is the orchestrator: a "Controller" in GRASP terms (GRASP is a short list of rules for deciding which class gets which job; Controller means one object receives the user's actions and delegates the work).
  • Board is immutable once built. It answers two questions: is there a jump at this cell, and where does a piece finally rest.
  • Board.Builder validates the input (range, one jump per cell, direction, no cycles), so a Board object is always valid.
  • Dice is an interface. RandomDice handles any count and number of faces; FixedDice replays a script for tests and demos.
  • Rules is a small value object of switches for the common follow-ups.
  • GameListener receives events. The console printer is one listener; a test spy or a UI would be others.
