From your world

The listener list is a notifier chain. In the kernel, register_netdevice_notifier() adds a notifier_block to a chain and the core later calls call_netdevice_notifiers(NETDEV_UP, dev) without knowing which subsystems care. GameListener is the same idea: addListener() registers, and the game calls every listener on each event. Default no-op methods play the role of "this notifier ignores that event type".

What we deliberately did not use: a Singleton Game (you may want two games in one test), a State pattern for the game (it has only two states, an enum is enough) and a Factory for players (a constructor is enough). Being able to say why you skipped a pattern is worth as much as using one.
