The problem: one finder method per combination

A car-rental search starts simple, and then product asks for "just one more filter":

class CarSearch {
    List<Car> byCity(String city) { ... }
    List<Car> byCityAndType(String city, CarType t) { ... }
    List<Car> byCityAndSeats(String city, int seats) { ... }
    List<Car> byCityAndTypeAndMaxPrice(String city, CarType t, int max) { ... }
    List<Car> byCityAndSeatsAndMaxPriceOrAutomatic(...) { ... }   // what does the "or" bind to?

    // or the "flexible" version:
    List<Car> search(String city, CarType type, Integer seats, Integer maxPrice, Boolean auto) {
        List<Car> out = new ArrayList<>();
        for (Car c : cars) {
            if (city != null && !c.city().equals(city)) continue;
            if (type != null && c.type() != type) continue;
            if (seats != null && c.seats() < seats) continue;
            if (maxPrice != null && c.price() > maxPrice) continue;
            if (auto != null && c.automatic() != auto) continue;
            out.add(c);
        }
        return out;
    }
}
  • Combinatorial explosion. With five filters there are dozens of combinations; named methods cannot keep up.
  • The "flexible" method can only AND. "Cheap or automatic" or "not an SUV" needs a new parameter or a new method.
  • Every new filter edits tested code (the signature and the loop), breaking Open/Closed.
  • Rules are not reusable. The "price at most X" test is also needed for price alerts and for validation, and gets copied.
  • Rules cannot be data. A coupon admin cannot type "age > 18 AND cart > 1000" into a screen if the rule only exists as an if inside a method.
