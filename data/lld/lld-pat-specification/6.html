In memory vs pushed down to the store

An in-memory spec tests objects one by one: fine for a machine-coding round with a few thousand items. In production you cannot load every listing to filter it in Java. So real systems give each spec a second job: translate itself into the store's query language (SQL WHERE, an Elasticsearch bool query, a BPF program). The tree shape stays the same; only the leaves' output changes. Mention this in an interview, and say which filters you would back with an index.
