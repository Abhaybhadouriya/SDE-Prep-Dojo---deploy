Intent

Template Method (GoF behavioral pattern): write the fixed order of steps once, in one base-class method, and leave a few of the steps as hooks for subclasses to fill in. Subclasses change how a step is done, never which steps run or in what order.

The base class owns the what and in which order. Subclasses own a few hows. The refactoring that gets you there has a name in Martin Fowler's catalogue, Form Template Method: find the near-identical methods, pull the identical parts up into the base class, and turn the differing parts into named steps.

The Hollywood principle, "don't call us, we'll call you", describes the control flow: the subclass never calls the base algorithm's steps itself. The base class calls down into the subclass. This upside-down call direction is also called inversion of control, and it is how every framework works.
