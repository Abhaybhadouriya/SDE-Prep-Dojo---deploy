The problem: three importers, one copied algorithm

An inventory service imports stock files. CSV came first; then a partner sent key=value text; then JSON. Each class was copied from the last one:

class CsvImporter {
    int run(String raw) {
        List<Row> rows = parseCsv(raw);                    // differs
        rows.removeIf(r -> r.qty() < 0);                    // same
        db.begin(); db.insertAll(rows); db.commit();        // same
        return rows.size();
    }
}
class KeyValueImporter {
    int run(String raw) {
        List<Row> rows = parseKv(raw);                     // differs
        rows.removeIf(r -> r.qty() <= 0);                   // slightly different
        db.insertAll(rows);                                 // BUG: someone forgot begin/commit
        warehouse.notify(rows.size());                      // extra step
        return rows.size();
    }
}
// JsonImporter: copied again, and nobody remembers which copy has the latest fix.

About 80% of each class is the same, but because it is copied, the copies drift: one forgot the transaction, another validates differently by accident. A fix to the shared part must be made in every copy. And there is no single place that says "this is the import algorithm".
