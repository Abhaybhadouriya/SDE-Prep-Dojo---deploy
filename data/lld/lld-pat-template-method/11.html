Interview Q&A

Template Method vs Strategy: when would you pick each?

Both let part of an algorithm vary. Template Method uses inheritance: the base class owns the order of steps and subclasses fill in some of them; the choice is fixed when the object is created. Strategy uses composition: the context delegates the whole algorithm to an object that can be swapped at runtime. Pick Template Method when the steps and their order must be enforced and one or two steps vary; pick Strategy when variations are many, independent or chosen at runtime.

How to answer

Give the mechanism (inheritance vs composition), then the deciding questions: runtime change? many axes? enforced order?

Likely follow-ups
  • Can you convert one into the other? (Yes: turn each step into a strategy object passed to a final class.)
  • Which one does Collections.sort(list, comparator) use?
What is the difference between an abstract step and a hook?

An abstract step has no default: every subclass must implement it, or the code does not compile (Java, C++) or the object cannot be created (Python ABC). A hook has a default body, often empty or a sensible rule, and subclasses override it only if they want to. Hooks give optional extension points without forcing every subclass to write boilerplate.

How to answer

Use the importer: parse() is abstract, afterSave() is a hook.

Likely follow-ups
  • Name a JDK or Python hook. (unittest setUp()/tearDown().)
Why is the template method usually declared final?

Because its whole value is that the order and the invariant steps are guaranteed. If a subclass can override it, one subclass will eventually reorder or skip a step (the transaction, the cleanup, the security check), and the base class can no longer promise anything. In C++ the same goal is reached with a non-virtual public method (the NVI idiom).

How to answer

"Final protects the invariant." Then give the concrete invariant from your example.

Likely follow-ups
  • What is NVI and why are the virtual steps private?
What is the Hollywood principle and how does it relate to frameworks?

"Don't call us, we'll call you": high-level code calls low-level code at the moments it chooses, and low-level code does not call the high-level steps itself. In Template Method the base class calls the subclass's steps. Frameworks are built this way: a servlet container calls doGet(), JUnit calls your test methods, the Linux driver core calls your probe(). It is one form of inversion of control; dependency injection is another.

How to answer

Define it in one line, then give two framework examples you have used.

Likely follow-ups
  • How does it differ from dependency injection?
What are the downsides of Template Method? When would you refactor away from it?

It relies on inheritance, so subclasses are tightly coupled to the base class's internals (fragile base class), the choice is fixed at creation time, and independent variations multiply into many subclasses. Refactor to Strategy when a second, independent axis of variation appears, when you need to switch behaviour at runtime, or when tests need to replace one step with a fake without subclassing.

How to answer

List the three costs and name the trigger for each refactoring.

Likely follow-ups
  • How does this relate to "composition over inheritance"?
Design a beverage machine that makes tea and coffee with the same steps.

An abstract Beverage with a final prepare(): boil water, brew() (abstract), pour into cup, and addExtras() guarded by a hook wantsExtras() that defaults to true. Tea and Coffee implement brew() and addExtras(). If the menu grows to many combinations (size x milk type x sweetener), keep the skeleton but move each option into a Strategy or a Decorator for add-ons, rather than creating subclasses for each combination.

How to answer

Show the skeleton, then show you know when it stops scaling.

Likely follow-ups
  • Where do pricing and stock checks go?
  • How do you test prepare()?
How does the Linux kernel get Template Method without inheritance?

With generic functions that own the skeleton and call ops-table function pointers at fixed points. The page-cache read path does lookup, read-ahead and copying for every filesystem and calls a_ops->read_folio only when a page is missing. The driver core matches a device and calls the driver's probe(), handling failure in one place. Function pointers replace overriding; the generic function plays the final template method.

How to answer

Say "generic function + ops table", give one path, and explain why it is not just Strategy (the generic code owns a multi-step order).

Likely follow-ups
  • How is a NULL op handled? (The generic code checks and uses a default or returns an error.)
