The kernel's template methods, in C

C has no inheritance, so the kernel cannot use a base class. It gets the same effect with a generic function that calls through an ops table at fixed points:

/* The shape of the idea (not real kernel code) */
ssize_t generic_read_sketch(struct file *f, char __user *buf, size_t n)
{
    /* invariant steps: owned by the generic layer, the same for every filesystem */
    look up the page in the page cache;
    if (page is missing) {
        allocate a page, lock it;
        mapping->a_ops->read_folio(f, folio);   /* the "abstract step": filesystem-specific */
        wait for the I/O to finish;
    }
    copy to user space, advance the file position, update access time;
}

From your world

Two examples you already know. The page-cache read path (filemap_read() and friends) does caching, read-ahead and copying for every filesystem and calls the filesystem's address_space_operations only to fill a missing page. The driver core's probe path matches a device, calls the driver's probe(), and on failure cleans up and tries the next driver. In C, Template Method and Strategy look almost the same, because both are "generic code + ops pointer". The difference is who owns the order of steps: if the generic function owns a multi-step skeleton and the ops fill holes in it, think Template Method; if the ops are the whole algorithm (a congestion-control module), think Strategy.
