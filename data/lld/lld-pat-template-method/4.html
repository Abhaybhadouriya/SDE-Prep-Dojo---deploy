How it works: who calls whom

There is only one object here, a KeyValueImporter. But its code lives in two layers: the base class's run() and the subclass's overrides. Watch control bounce between the layers:

  1. The client calls run(). It cannot call the steps itself (they are protected), and it does not need to know which importer it holds.
  2. The base layer calls parse(), which only the subclass can answer. Control jumps down: the Hollywood principle.
  3. For each row it calls the isValid() hook. KeyValueImporter overrides it with a stricter rule (quantity must be above zero), so "ink, 0" is skipped.
  4. save() is private in the base class: begin, insert, commit. No subclass can forget the transaction any more.
  5. The afterSave() hook is empty in the base class; this subclass uses it to notify the warehouse. CsvImporter does not override it, so nothing happens there.
  6. run() returns the count to the client. The order of steps was decided in one place, by the base class.
