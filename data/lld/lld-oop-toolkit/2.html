Rich enums: constants that carry data and behaviour

An enum (enumerated type) is a type with a fixed, known list of values. In C an enum is just a named integer: enum vtype { BIKE, CAR, TRUCK }; and CAR == 1. Nothing stops you passing 7. In Java an enum is a full class whose only instances are the listed constants. The JVM creates each constant once, at class load. So:

  • Type safe. A method that takes VehicleType cannot receive 7 or "CAAR".
  • Fields and constructors. Each constant can carry data: CAR(2, 50) means 2 slots, Rs 50 per hour.
  • Methods. The code that uses the data lives next to it: v.fee(3), not a switch in five services.
  • Free singletons. Comparing with == is correct and fast. values(), valueOf("CAR"), name(), ordinal() come for free.
enum VehicleType {
    BIKE(1, 20), CAR(2, 50), TRUCK(4, 120);      // slots needed, rupees per hour

    private final int slots;
    private final int ratePerHour;
    VehicleType(int slots, int ratePerHour) { this.slots = slots; this.ratePerHour = ratePerHour; }
    int slots() { return slots; }
    long fee(int hours) { return (long) Math.max(1, hours) * ratePerHour; }
}

From your world

You already write "rich enums" in C, just by hand. The kernel keeps a plain enum for TCP states (TCP_ESTABLISHED, TCP_SYN_SENT...) and then a separate array indexed by that enum for names or flags. A Java enum puts the per-value table inside the value: CAR.slots is the row table[CAR].slots, and the compiler guarantees the index is valid. EnumMap is literally an array indexed by ordinal(), like your table[ENUM_MAX].

Three enum tricks that show up in interviews

  1. EnumMap and EnumSet. Use them for "count of free spots per vehicle type" or "allowed payment modes". They are array- and bit-mask-backed, ordered, and faster than HashMap.
  2. Constant-specific bodies. Declare an abstract method in the enum and let each constant override it. That is a tiny, closed Strategy set (see Strategy).
  3. Enum as a state machine. Keep the allowed transitions in an EnumMap inside the enum, and expose canMoveTo(). Click through:
enum SplitType {
    EQUAL          { long[] split(long total, int n) { long[] r = new long[n]; Arrays.fill(r, total / n); r[0] += total % n; return r; } },
    FIRST_PAYS_ALL { long[] split(long total, int n) { long[] r = new long[n]; r[0] = total; return r; } };
    abstract long[] split(long total, int n);
}
  1. Five constants of enum OrderStatus. In C you would write enum { CREATED, PAID, ... } and keep the legal moves somewhere else.
  2. The happy path. Each legal move is stored in an EnumMap<OrderStatus, Set<OrderStatus>> named NEXT, right inside the enum.
  3. Cancel is legal only before shipping. Two more entries in NEXT, no new if anywhere else.
  4. Someone calls order.moveTo(DELIVERED) on a PAID order. canMoveTo() says no, so the domain throws a typed exception instead of silently corrupting state.
  5. DELIVERED and CANCELLED map to an empty set: terminal states. Every rule of the lifecycle is in one place, easy to test.
enum OrderStatus {
    CREATED, PAID, SHIPPED, DELIVERED, CANCELLED;
    private static final Map<OrderStatus, Set<OrderStatus>> NEXT = new EnumMap<>(OrderStatus.class);
    static {
        NEXT.put(CREATED, EnumSet.of(PAID, CANCELLED));
        NEXT.put(PAID, EnumSet.of(SHIPPED, CANCELLED));
        NEXT.put(SHIPPED, EnumSet.of(DELIVERED));
        NEXT.put(DELIVERED, EnumSet.noneOf(OrderStatus.class));
        NEXT.put(CANCELLED, EnumSet.noneOf(OrderStatus.class));
    }
    boolean canMoveTo(OrderStatus to) { return NEXT.get(this).contains(to); }
}

When NOT to use an enum. An enum is closed: adding a value means editing and recompiling it. Use it for sets that truly are fixed (status, direction, suit of cards, vehicle size). If the interviewer says "new payment methods get added every quarter", use an interface with one class per method and a registry, so you obey the Open/Closed Principle. Saying this trade-off out loud is worth more than either choice.

Do not persist or compare ordinal(). Reordering the constants changes every ordinal. Store name() instead.
