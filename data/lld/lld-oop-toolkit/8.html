Comparable and Comparator: ordering rules as objects

Comparable gives a class its one natural order (Money by amount, Version by number). Comparator is an order defined outside the class, and you can have as many as you like: nearest spot, cheapest ride, highest rated driver. A comparator is a Strategy object for "which comes first".

Comparator<Spot> nearest = Comparator.comparingInt(Spot::floor)
                                     .thenComparingInt(Spot::distance);      // tie-breaker
spots.sort(nearest);                        // [3, 2, 4, 1]
spots.sort(nearest.reversed());             // [1, 4, 2, 3]

PriorityQueue<Spot> free = new PriorityQueue<>(nearest);   // allocator: poll() = best spot, O(log n)
Comparator<Driver> byRating = Comparator.comparing(Driver::rating, Comparator.nullsLast(Comparator.reverseOrder()));

From your world

This is qsort(base, n, size, cmp) where cmp is a function pointer, and the kernel's sort() and list_sort() take one too. A Comparator is that function pointer, wrapped in an object, with helpers to chain and reverse it.

Two classic bugs. (1) return a.x - b.x; overflows for large or negative values; use Integer.compare. (2) A TreeMap/TreeSet treats compare(a, b) == 0 as "same key". If your comparator only looks at rating, two different drivers with the same rating collapse into one entry. Always add a unique tie-breaker such as the id.
