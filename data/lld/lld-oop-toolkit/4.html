Optional: say "maybe absent" in the type

Optional<T> is a box that holds either one value or nothing. Returning Optional<User> from findById makes absence part of the method's contract, so the caller must decide what "not found" means right there.

Optional<User> findById(String id) { return Optional.ofNullable(rows.get(id)); }

String name = repo.findById("u9").map(User::name).orElse("nobody");      // soft default
User u      = repo.findById("u1").orElseThrow(() -> new NotFoundException("user", "u1"));  // hard rule
Use Optional forDo not use it for
Return types of lookups: findById, findFreeSpot, nextAvailableDriverFields (it is not Serializable, and it adds an object per field)
Chains: map, filter, orElse, orElseThrowMethod parameters (pass the value or overload the method instead)
Saying "zero or one" clearlyCollections: return an empty list, never Optional<List<T>>

opt.get() without a check is just a NullPointerException with a new name. Prefer orElseThrow(...), which documents what failure means.
