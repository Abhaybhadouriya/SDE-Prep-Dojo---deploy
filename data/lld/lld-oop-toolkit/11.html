Interview questions on this toolkit

Would you model vehicle type as an enum or as a class hierarchy?

Enum if the set is fixed and the types differ only in data (size, rate). Class hierarchy or interface if types differ in behaviour that will grow, or new types get added often. A common middle ground: an enum for size (SMALL, MEDIUM, LARGE) that drives spot matching, plus a pricing Strategy interface for rules that change.

How to answer

State the trade-off (closed vs open for extension), pick one for the given requirements, and name the change that would make you switch.

Likely follow-ups
  • How do you add an electric vehicle with a charging fee? (new constant vs new class)
  • How would you persist the enum? (by name(), not ordinal)
How do you handle errors in your machine-coding solution?

Validate inputs at the service boundary, throw a specific unchecked exception from a small hierarchy (NotFoundException, InvalidStateException, InsufficientFundsException under one DomainException with an error code), and catch the base type once in the driver so the demo prints a clean message and keeps running. No silent catch, no return null.

How to answer

Show the hierarchy, then show one driver line per failure case. That demonstrates "fails gracefully", which graders score.

Likely follow-ups
  • Checked or unchecked, and why?
  • How would these map to HTTP status codes in a REST layer? (404, 409, 422)
What happens if you override equals but not hashCode?

Hash-based collections break. Two equal objects usually get different identity hash codes, land in different buckets, and contains/get return false or null. A HashSet can hold "duplicates". The contract: equal objects must have equal hash codes.

How to answer

Explain bucket selection first (hashCode), then the equality check inside the bucket (equals). Mention that records generate both.

Likely follow-ups
  • What if a key is mutated after insertion?
  • How does HashMap handle collisions? (bucket list, then a tree when a bucket gets long)
How do you make a class immutable, and why is that useful with threads?

Final class, private final fields, no setters, defensive copies of mutable inputs and outputs, and methods that return new objects. Once the constructor finishes, no thread can change it, so it can be shared without locks; final fields also come with a JMM guarantee that other threads see them fully initialised after construction (as long as this did not escape the constructor).

How to answer

List the five rules, then give a domain example (Money, a seat-map snapshot) and the thread-safety payoff.

Likely follow-ups
  • Is a record deeply immutable? (no, shallow)
  • Is String immutable and why does that matter for a HashMap key?
What is type erasure and what can you not do because of it?

Java removes generic type arguments after compile-time checks, replacing them with their bounds (or Object) and inserting casts. So you cannot write new T(), create a T[], check instanceof List<String>, or overload methods that differ only in type arguments. Workarounds: pass a Class<T> or a Supplier<T>.

How to answer

Contrast with C++ templates, which generate code per type. That shows you understand both models.

Likely follow-ups
  • Explain PECS with Collections.copy or max.
Why return Optional from findById instead of null?

It makes absence part of the signature, so callers handle "not found" at the call site (orElseThrow, orElse, map). A returned null travels and explodes later, far from the cause. Do not use Optional for fields, parameters or collections.

Likely follow-ups
  • Difference between orElse and orElseGet? (orElse evaluates its argument always)
Your TreeSet of drivers sorted by rating is "losing" drivers. Why?

A TreeSet uses the comparator for equality: if compare returns 0, the second element is treated as a duplicate and dropped. Two drivers with the same rating collapse. Fix: comparing(Driver::rating).reversed().thenComparing(Driver::id), so the order is consistent with equals.

Likely follow-ups
  • How would you update a driver's rating that is already in the set? (remove, change, re-insert; or keep immutable entries)
