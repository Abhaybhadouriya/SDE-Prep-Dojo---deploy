Generics: write the container once

Generics let a class or method take a type as a parameter. List<String> is a list the compiler knows holds only strings, so no casts and no ClassCastException at runtime. In LLD the big win is a generic repository: one in-memory store used for users, spots, orders and tickets.

interface Identifiable<ID> { ID id(); }

class InMemoryRepo<ID, T extends Identifiable<ID>> {            // bounded type parameter
    private final Map<ID, T> rows = new LinkedHashMap<>();
    void save(T t) { rows.put(t.id(), t); }                       // legal because of the bound
    Optional<T> findById(ID id) { return Optional.ofNullable(rows.get(id)); }
    List<T> findAll(Predicate<? super T> p) { return rows.values().stream().filter(p).toList(); }
}

InMemoryRepo<String, User>  users = new InMemoryRepo<>();
InMemoryRepo<Integer, Spot> spots = new InMemoryRepo<>();

Bounds and wildcards in one table

SyntaxRead it asUse when
<T extends Shape>T is Shape or a subtypeYou need to call Shape methods on T
List<? extends Shape>a list of some subtype of ShapeYou only read (it produces Shapes)
Comparator<? super T>works on T or any supertypeYou only pass T in (it consumes T)
List<?>a list of unknown typeYou only use Object methods (size, print)

The memory hook is PECS: Producer Extends, Consumer Super. Collections.max is the textbook example and our helper copies its shape:

static <T> T best(Collection<? extends T> items, Comparator<? super T> order) {
    if (items.isEmpty()) throw new NoSuchElementException("empty");
    return Collections.max(items, order);
}

From your world

The kernel's generic containers are struct list_head, hlist and rbtrees, made generic with void * and the container_of() macro. That works but the compiler cannot tell a list of sk_buff from a list of inode. Java generics give you the same "one container, many element types" with a compile-time type check. Like your macros, Java generics are a compile-time feature: type erasure removes the type arguments, so at runtime a List<String> and a List<Integer> are the same class. C++ templates are the opposite: they stamp out a separate copy of the code per type.

Erasure has visible consequences: no new T(), no T[] creation, no instanceof List<String>, and you cannot overload f(List<String>) with f(List<Integer>). A frequent follow-up question.
