Intent

Flyweight (GoF structural pattern), in our words: when you need a huge number of small objects that are mostly identical, store the identical part once and share it. Split each object's state into intrinsic state (shared, context-free, immutable, stored in the flyweight) and extrinsic state (varies per use, kept by the client and passed in when needed).

Two words carry the whole pattern:

  • Intrinsic = "belongs to the thing itself, the same wherever it is used": the font, size and colour of a style; the shaping table of the "voice" QoS class; the value 42 of an Integer.
  • Extrinsic = "depends on where or how it is used": which character, at which row and column; which flow (source and destination port) uses it; which variable holds the 42.

Flyweight is an optimisation pattern. It does not make the design more flexible; it makes it cheaper. Use it when profiling (or simple arithmetic) says memory is the problem.
