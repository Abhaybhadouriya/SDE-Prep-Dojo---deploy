Interview Q&A

What is the difference between intrinsic and extrinsic state? Give an example.

Intrinsic state is independent of context and can be shared: a character's font, size and colour; a QoS class's shaping table. Extrinsic state depends on where the object is used and must be supplied by the client: which character, at what row and column; which flow uses the profile. The flyweight stores only intrinsic state and receives extrinsic state as method arguments.

How to answer

Definition, the test ("would this field be wrong if the object were used in two places?"), one example split.

Likely follow-ups
  • Where does the extrinsic state live then? (In the context objects or computed on the fly, like layout positions.)
Why must flyweights be immutable?

Because many contexts hold the same instance at the same time. If one caller changed the colour of a shared style, every character using it would change colour, which is a silent action at a distance. Immutability also makes the objects safe to share across threads without locks (final fields are safely published in Java). If a context needs a different value, it asks the factory for a different flyweight.

How to answer

Shared by many, so mutation leaks; plus the thread-safety bonus.

Likely follow-ups
  • How does the kernel handle a write to the shared zero page? (Copy-on-write: the writer gets a private copy.)
Integer a = 127, b = 127; a == b is true. With 128 it is false. Why?

Autoboxing calls Integer.valueOf(int), which returns cached instances for -128 to 127 (a flyweight pool the JDK specification requires). Both variables point to the same object, so reference equality is true. 128 is outside the default cache, so each valueOf creates a new object and == compares two different references. The fix is a.equals(b) or unboxing. The cache's upper bound can be raised with -XX:AutoBoxCacheMax, which is one more reason not to depend on ==.

How to answer

Name valueOf, name the range, name the pattern, give the fix.

Likely follow-ups
  • Does new Integer(127) use the cache? (No; the constructor always allocates, and it is deprecated.)
  • Python equivalent? (Small-int cache, and is vs ==.)
Design the data model of a text editor so a 500-page document does not need a million style objects.

Store text in a buffer (a gap buffer, rope or piece table). Store formatting as runs: (start, length, styleRef), where styleRef points to an immutable CharStyle flyweight from a factory keyed by (font, size, weight, colour). Layout computes line breaks and positions on demand and passes them to the renderer. Glyph bitmaps per (font, size, character) are a second flyweight cache in the renderer. Memory now scales with characters plus runs plus distinct styles, not characters times styles.

How to answer

Separate content, formatting and layout. Name the flyweight explicitly, then mention runs as a further saving over one reference per character.

Likely follow-ups
  • How do you implement "make all headings blue"? (Change which flyweight the heading runs reference, or make "Heading 1" a named style the runs point to.)
  • How would undo work? (Command or Memento.)
Flyweight vs Object Pool: both reuse objects. What is the difference?

A flyweight is immutable and shared by many clients at the same time; nobody owns it and nobody gives it back. A pooled object (a DB connection, a thread, a buffer) is usually mutable and used by one client at a time; you borrow it, use it, reset it and return it. Flyweight saves memory by sharing; Object Pool saves creation cost by recycling.

How to answer

Concurrent sharing vs exclusive borrowing; immutable vs mutable; memory vs creation cost.

Likely follow-ups
  • What goes wrong if you forget to return a pooled object? What if you mutate a flyweight?
How do you make a flyweight factory thread-safe, and can its pool leak?

Use an atomic get-or-create: ConcurrentHashMap.computeIfAbsent in Java, a lock around check-and-insert in C++ or Python (Python's GIL makes a single dict operation atomic, but check-then-insert is two operations). Make the flyweights immutable so they are safely published. Yes, it can leak: if keys come from user input (any RGB colour, any string), the pool grows forever. Cap its size with an LRU, or hold the values weakly so unused flyweights can be collected. Careful in Java: a plain WeakHashMap does not work for a pool like ours (Map<CharStyle, CharStyle>, key == value), because it holds keys weakly but values strongly, and the strong value keeps its own key reachable, so nothing is ever collected. Use WeakHashMap<K, WeakReference<V>> (and handle cleared references), Guava's Interners.newWeakInterner(), or a bounded LRU. Python's weakref.WeakValueDictionary is correct as is, because its values are weak.

How to answer

Atomic create, immutable values, bounded or weak pool.

Likely follow-ups
  • Is it a problem if two threads briefly create two equal flyweights? (Only memory and identity; with a proper atomic call it never happens.)
Where does the Linux kernel use the Flyweight idea?

The shared zero page: read faults on untouched anonymous memory map one read-only physical page of zeros; copy-on-write gives a private page on first write. kstrdup_const() returns the original pointer for strings already in read-only kernel data instead of copying. Every open struct file of a driver shares one const struct file_operations table. Shared library text in the page cache is mapped once physically into many processes.

How to answer

Name one with its intrinsic part (page contents) and extrinsic part (virtual address), and point out that immutability is enforced by read-only mappings.

Likely follow-ups
  • Why is the zero page mapped read-only? (So the first write faults and triggers copy-on-write.)
