The story: one stamp, many prints

Explain like I'm 5

Your class is making a birthday banner with 500 stars on it. One way: every child carves their own star out of a potato, 500 potatoes, a huge mess. The clever way: the teacher carves one star stamp. Each child just says where to press it and which colour ink to use today.

The shape of the star lives on the stamp and is the same for everybody. The place on the banner changes every time, so the child brings it. One stamp, 500 prints. That is the Flyweight pattern.

In software the "potatoes" are objects. A text editor holding a long document could create one object per character, each with its own copy of font name, size, weight and colour. A router could keep one object per network flow, each with its own copy of a 64 KB QoS shaping table. Most of that data is identical across objects. Flyweight says: keep the identical part in a few shared, read-only objects and keep only the small, changing part per item.

From your world

You already use this every day. When a process reads anonymous memory it has never written, the kernel does not allocate a fresh zeroed page for each fault. It maps the one shared zero page (ZERO_PAGE()) read-only into the page table. A thousand processes, a million virtual pages, one physical page of zeros. The page contents are the shared intrinsic state; the virtual address in each page table is the extrinsic state. The moment someone writes, copy-on-write gives that process its own page, because a flyweight must never be modified in place.
