How it works: two lookups and a render

  1. The document needs a plain 12pt Inter style. It asks the factory; the factory looks in its pool by the intrinsic key and misses.
  2. The factory creates the one and only CharStyle for that key, stores it, and returns the reference.
  3. The next character with the same style asks again. This time the pool hits, and the factory returns the same object. No allocation.
  4. The document stores just the character and the reference: a few bytes per character instead of a whole style.
  5. At render time the document computes row and column from the window width and passes them, with the character, into the shared flyweight's draw().

The rule of thumb when splitting state: if a field would be wrong as soon as the same object is used in two places, it is extrinsic. Position is wrong in two places at once. Font is not.
