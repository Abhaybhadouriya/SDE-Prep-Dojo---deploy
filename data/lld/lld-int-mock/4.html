Mock 3: Atlassian-style 60-minute code design round

Prompt (our paraphrase of a reported question). A customer subscribes to products on a plan (BASIC 9.99, STANDARD 49.99, PREMIUM 249.99 per month). Build a cost explorer that, on any day of the year, reports the cost for each month of the unit year (including future months) and the yearly total. Follow-up: include a free trial period in the bill (Atlassian code design report, 2025-05-22). We add a third stage, a plan change mid-year, because that is the shape these rounds take: each stage is a new requirement on top of the last.

Atlassian's official guide says the coding interview has a data-structures part and a code design part, that how you think matters most, and that tests are crucial; it suggests coming with your IDE and test framework ready (Atlassian). The candidate behind this prompt wrote modular code but could not run or test it because of an error, and asked online whether they would still pass. A 2026 P50 report describes a code design round (a trie-based middleware router) where a typo cost 5-7 minutes and the follow-ups went unfinished; the same candidate's separate DSA round used JUnit tests (2026-05-25). Both posts say the same thing: code that runs, with tests, early.

Clarify first (minutes 0-5)

  • If a subscription starts mid-month, do we charge the full month or pro-rate by days? (Pro-rate by active days / days in month. Write it down.)
  • Rounding: per month per plan, to cents, half-up? (Yes. Use BigDecimal / Decimal, never double for money.)
  • Several products per customer? (Yes: a list of subscriptions.)
  • Does "on any day" change the answer? (Past and future months use the same formula here; say so.)

From your world

Why not double? 0.1 has no exact binary floating-point value, so 9.99 x 3 drifts by tiny amounts and a rounding step can then go the wrong way. It is the same reason kernel code avoids floating point and counts in integer units (jiffies, nanoseconds, bytes) or fixed point. BigDecimal (Java) and Decimal (Python) are exact decimal numbers with any precision you ask for. Storing money as a long count of cents is the C answer, and interviewers accept it too if you say how you divide and round. We round half-up once per plan per month, at the end of that month's sum, not once per day, so rounding errors do not pile up across 30 daily slices.

floorEntry(day) finds the last rule whose start is <= the key. That is the lookup you know from an interval table or a sorted route list: the entry that covers this key is the greatest one not past it. bisect_right on a sorted list is the same binary search in Python.

How the design grows across three stages

  1. Part 1 (minutes 5-25). For each month, count each subscription's active days and charge price x days / days-in-month, rounded to cents. Write 3 tests first: full year, mid-month start, unknown plan.
  2. Part 2: trial (25-40). Do not touch the loop's math. Pull out one question, "is this day charged?", as a ChargeRule. Trial is one rule. Old tests stay green; add two trial tests.
  3. Part 3: plan change (40-52). The subscription stops holding one plan and holds plan periods; planOn(day) becomes a floor lookup in a sorted map (Java TreeMap.floorEntry, Python bisect on a sorted list). The explorer does not change, because it already asked "which plan on this day?".

The code, with tests

PRICES = {"BASIC": Decimal("9.99"), "STANDARD": Decimal("49.99"), "PREMIUM": Decimal("249.99")}

@dataclass
class Subscription:
    product: str
    start: date
    plan: str
    trial_days: int = 0                                  # part 2
    changes: List[tuple] = field(default_factory=list)   # part 3: (date, new_plan)

    def __post_init__(self):                             # runs after the generated constructor
        if self.plan not in PRICES:
            raise ValueError(f"unknown plan {self.plan}")
        if self.trial_days < 0:
            raise ValueError("trial_days must be >= 0")

    def change_plan(self, on, new_plan):
        if new_plan not in PRICES:
            raise ValueError(f"unknown plan {new_plan}")
        if on < self.start:
            raise ValueError("plan change before start")
        bisect.insort(self.changes, (on, new_plan))      # kept sorted by date

    def plan_on(self, day):
        """Which plan is active on this day, or None if not subscribed yet.
        Floor lookup: the last change dated <= day (Java: TreeMap.floorEntry)."""
        if day < self.start:
            return None
        i = bisect.bisect_right(self.changes, day, key=lambda c: c[0])
        return self.changes[i - 1][1] if i else self.plan


class TrialRule:                                         # a ChargeRule
    def is_free(self, sub, day):
        return sub.start <= day < sub.start + timedelta(days=sub.trial_days)


class CostExplorer:
    def __init__(self, rules=None):
        self.rules = rules if rules is not None else [TrialRule()]

    def monthly_cost(self, subs, year):
        return [self._month(subs, year, m) for m in range(1, 13)]

    def yearly_cost(self, subs, year):
        return sum(self.monthly_cost(subs, year), Decimal("0"))

    def _month(self, subs, year, month):
        days_in_month = calendar.monthrange(year, month)[1]
        total = Decimal("0")
        for sub in subs:
            billable = {}                                # plan -> chargeable days
            for d in range(1, days_in_month + 1):
                day = date(year, month, d)
                plan = sub.plan_on(day)
                if plan is None or any(r.is_free(sub, day) for r in self.rules):
                    continue
                billable[plan] = billable.get(plan, 0) + 1
            for plan, n in billable.items():
                total += (PRICES[plan] * n / days_in_month).quantize(CENT, ROUND_HALF_UP)
        return total
class Part1Basics(unittest.TestCase):
    def test_full_year_basic(self):
        sub = Subscription("Jira", date(2026, 1, 1), "BASIC")
        self.assertEqual(CostExplorer().yearly_cost([sub], 2026), Decimal("119.88"))

    def test_mid_month_start_is_prorated(self):
        sub = Subscription("Jira", date(2026, 4, 16), "STANDARD")   # 15 of 30 April days
        months = CostExplorer().monthly_cost([sub], 2026)
        self.assertEqual(months[3], Decimal("25.00"))              # 24.995 rounds half-up


class Part2Trial(unittest.TestCase):
    def test_trial_crossing_month_end(self):
        sub = Subscription("Jira", date(2026, 1, 22), "BASIC", trial_days=14)  # free Jan 22 - Feb 4
        months = CostExplorer().monthly_cost([sub], 2026)
        self.assertEqual(months[0], Decimal("0"))
        self.assertEqual(months[1], Decimal("8.56"))               # 9.99 * 24 / 28


class Part3PlanChange(unittest.TestCase):
    def test_upgrade_mid_month_splits_the_month(self):
        sub = Subscription("Jira", date(2026, 1, 1), "BASIC")
        sub.change_plan(date(2026, 6, 16), "PREMIUM")               # 15 + 15 June days
        june = CostExplorer().monthly_cost([sub], 2026)[5]
        self.assertEqual(june, Decimal("130.00"))                  # 5.00 + 125.00

    def test_rules_are_pluggable(self):
        class FreeJuly:
            def is_free(self, sub, day):
                return day.month == 7
        sub = Subscription("Jira", date(2026, 1, 1), "BASIC")
        months = CostExplorer(rules=[FreeJuly()]).monthly_cost([sub], 2026)
        self.assertEqual(months[6], Decimal("0"))
enum Plan {
    BASIC("9.99"), STANDARD("49.99"), PREMIUM("249.99");
    final BigDecimal monthly;
    Plan(String p) { monthly = new BigDecimal(p); }
}

static final class Subscription {
    final String product; final LocalDate start; final int trialDays;
    private final TreeMap<LocalDate, Plan> planFrom = new TreeMap<>();   // part 3

    Subscription(String product, LocalDate start, Plan plan, int trialDays) {
        if (trialDays < 0) throw new IllegalArgumentException("trialDays must be >= 0");
        this.product = product; this.start = start; this.trialDays = trialDays;
        planFrom.put(start, Objects.requireNonNull(plan));
    }
    void changePlan(LocalDate on, Plan plan) {
        if (on.isBefore(start)) throw new IllegalArgumentException("plan change before start");
        planFrom.put(on, plan);
    }
    Plan planOn(LocalDate day) {                     // null = not subscribed that day
        Map.Entry<LocalDate, Plan> e = planFrom.floorEntry(day);
        return e == null ? null : e.getValue();
    }
}

interface ChargeRule { boolean isFree(Subscription s, LocalDate day); }

static final class TrialRule implements ChargeRule {
    public boolean isFree(Subscription s, LocalDate day) {
        return !day.isBefore(s.start) && day.isBefore(s.start.plusDays(s.trialDays));
    }
}

private BigDecimal month(List<Subscription> subs, YearMonth ym) {
    int dim = ym.lengthOfMonth();
    BigDecimal total = BigDecimal.ZERO;
    for (Subscription s : subs) {
        Map<Plan, Integer> billable = new EnumMap<>(Plan.class);
        for (int d = 1; d <= dim; d++) {
            LocalDate day = ym.atDay(d);
            Plan p = s.planOn(day);
            if (p == null || isFree(s, day)) continue;
            billable.merge(p, 1, Integer::sum);
        }
        for (Map.Entry<Plan, Integer> e : billable.entrySet())
            total = total.add(e.getKey().monthly.multiply(BigDecimal.valueOf(e.getValue()))
                    .divide(BigDecimal.valueOf(dim), 2, RoundingMode.HALF_UP));
    }
    return total.setScale(2, RoundingMode.HALF_UP);
}

The day loop is O(365) per subscription per year: say that it is deliberately simple, and that a period-overlap formula is the optimisation if the interviewer asks for scale.
