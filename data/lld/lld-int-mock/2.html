Mock 1: Amazon-style 55-minute OOD round

Prompt (our paraphrase of a reported question). Design a package delivery system for an online store. Orders become packages; delivery agents take packages to customers; the system tracks each package's status. Support assigning packages to agents, updating delivery status and handling failed delivery attempts. Time: 30 minutes of design inside a 55-60 minute slot (Amazon's official page says 55; the cited report had 60 minutes on the Bluescape whiteboard). Medium: whiteboard tool; write the key methods in real code. Reported follow-ups: priority for Prime orders, and giving Prime customers the highest-rated agent (Amazon SDE-2, 2026-10-17).

Amazon's official SDE-II prep page describes a loop of 55-minute interviews and asks for syntactically correct code rather than pseudocode, tested and robust to edge cases (atoz.amazon). Candidates also report Leadership Principle (LP) questions in every round, so the design part is short. Plan for 30 minutes.

Clarifying questions worth asking

  • Is one package one order, or can an order split into several packages? (Assume one package per order for now; mention the split.)
  • Does an agent carry one package at a time or a batch? (Assume one, to keep assignment simple; batching is a follow-up.)
  • How many delivery attempts before the package goes back? (Assume 3.)
  • How is an agent chosen: any free agent, nearest, best-rated? (Start with any free; make it pluggable.)
  • Do we model routes, payments, warehouses? (No: out of scope, say it out loud.)
  • Do you want running code, or classes plus key methods? (Ask this every time.)

The class model

From your world

The Status.canMoveTo() table is a protocol state machine, like TCP's state transitions: every event is checked against the current state, and an illegal event is rejected instead of corrupting state. AssignmentStrategy is a function pointer in an ops struct: the dispatcher calls strategy->pick() and does not care which policy is plugged in, the same way the VFS calls f_op->read.

The key methods, in real code

enum Status {
    CREATED, ASSIGNED, OUT_FOR_DELIVERY, DELIVERED, ATTEMPT_FAILED, RETURNED;

    // the state machine lives in one place, like a protocol state table
    boolean canMoveTo(Status next) {
        switch (this) {
            case CREATED:          return next == ASSIGNED;
            case ASSIGNED:         return next == OUT_FOR_DELIVERY;
            case OUT_FOR_DELIVERY: return next == DELIVERED || next == ATTEMPT_FAILED;
            case ATTEMPT_FAILED:   return next == ASSIGNED || next == RETURNED;
            default:               return false;          // DELIVERED, RETURNED are final
        }
    }
}

// change point #1: how we pick an agent (Strategy)
interface AssignmentStrategy { Optional<Agent> pick(Pkg p, Collection<Agent> free); }

static final class AnyFreeAgent implements AssignmentStrategy {
    public Optional<Agent> pick(Pkg p, Collection<Agent> free) { return free.stream().findFirst(); }
}

// follow-up: Prime customers get the highest-rated free agent
static final class PrimeGetsBestRated implements AssignmentStrategy {
    private final AssignmentStrategy fallback = new AnyFreeAgent();
    public Optional<Agent> pick(Pkg p, Collection<Agent> free) {
        if (!p.prime) return fallback.pick(p, free);
        return free.stream().max(Comparator.comparingDouble(a -> a.rating));
    }
}
// ONE service lock: every public method (createPackage, dispatch, pickUp, delivered,
// attemptFailed, addAgent) is synchronized, because they all touch these fields and Agent.busy.
private final Map<String, Long> seq = new HashMap<>();
// follow-up: Prime first, then FIFO by arrival
private final PriorityQueue<Pkg> waiting = new PriorityQueue<>(
    Comparator.comparing((Pkg p) -> !p.prime).thenComparing(p -> seq.get(p.id)));

// core method 1: match waiting packages to free agents
synchronized void dispatch() {
    while (!waiting.isEmpty()) {
        List<Agent> free = new ArrayList<>();
        for (Agent a : agents.values()) if (!a.busy) free.add(a);
        Optional<Agent> chosen = strategy.pick(waiting.peek(), free);
        if (!chosen.isPresent()) return;                  // nobody free: stay queued
        Pkg p = waiting.poll();
        Agent a = chosen.get();
        a.busy = true; p.agentId = a.id;
        move(p, Status.ASSIGNED);
    }
}

// core method 2: a failed attempt re-queues or returns the package
synchronized void attemptFailed(String pkgId) {
    Pkg p = get(pkgId);
    move(p, Status.ATTEMPT_FAILED);
    p.attempts++;
    freeAgent(p);                                    // does not dispatch: re-queue first, then match once
    if (p.attempts >= MAX_ATTEMPTS) move(p, Status.RETURNED);
    else { seq.put(p.id, counter++); waiting.add(p); }
    dispatch();                                      // still inside the one service lock
}

// private helpers run only with the service lock already held
private void freeAgent(Pkg p) { agents.get(p.agentId).busy = false; p.agentId = null; }

private void move(Pkg p, Status next) {
    if (!p.status.canMoveTo(next))
        throw new IllegalStateException(p.id + ": " + p.status + " -> " + next + " not allowed");
    p.status = next;
    p.history.add(next + (p.agentId != null ? "(" + p.agentId + ")" : ""));
}

Read it as the trace you would say aloud: P2 is Prime and takes the best-rated agent ag-2. P3 and P4 queue; when P1's attempt fails and ag-1 is freed, Prime P4 jumps ahead of P3. Delivering P1 after a failed attempt is refused. P3 already took ag-2 when P2 was delivered, so when a new agent ag-3 joins, the only package still waiting is P1, and ag-3 picks up its second attempt. The last line is the race check: 8 threads start together behind a latch, 4 creating 400 packages while 4 deliver or fail the assigned ones, and every agent still holds exactly one package.

Scenario: "Prime orders go first"

Minute 24. The interviewer adds Prime priority, then "the highest-rated agent for Prime customers".

Adds if (order.isPrime()) in createPackage, in dispatch and in the agent loop; keeps two separate queues and forgets to drain one of them.

"Priority is an ordering question, so the waiting queue's comparator changes: Prime first, then arrival order. Agent choice was already a Strategy, so Prime-gets-best-rated is a new class with a fallback to the old one. Nothing else changes." Two small, local edits, said before they are written.

Likely follow-ups
  • Can a non-Prime package starve? (Yes, under constant Prime load; add aging: priority grows with waiting time.)
  • Agents near the customer first? (Another Strategy that needs a location on Agent and Package.)
  • Can a non-Prime package take the top agent? (Yes: when no Prime package is waiting, it takes whatever is free, so a Prime package that arrives a second later gets a worse agent. Fixes: reserve the top-k agents for Prime, or score each agent by expected need instead of picking greedily.)
