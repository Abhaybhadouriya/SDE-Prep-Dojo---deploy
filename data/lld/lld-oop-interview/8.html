What is a virtual destructor and why is it needed?

When you delete a derived object through a base pointer, the destructor call is dispatched like any other method. Without virtual on the base destructor the behaviour is undefined, and in practice only the base destructor runs, leaking whatever the derived class owns. Rule: a class meant to be used polymorphically gets a public virtual destructor (or a protected non-virtual one if deletion through the base is forbidden).

struct Buf  { virtual ~Buf() { } };
struct Ring : Buf { ~Ring() override { /* free ring memory */ } };
std::unique_ptr<Buf> b(new Ring());   // ~Ring then ~Buf runs

Reported: Adobe (C++) (LeetCode Discuss, 2025-11-15).

What is RAII? How does it compare to Java?

Resource Acquisition Is Initialisation: a resource (memory, lock, file, socket) is owned by an object whose destructor releases it. Stack unwinding runs destructors on every exit path, so cleanup cannot be forgotten. std::unique_ptr, std::lock_guard and std::fstream are RAII types. Java has a GC for memory and try-with-resources (AutoCloseable) for everything else.

Reported: Adobe (C++) (LeetCode Discuss, 2026-10-13).

How to answer

Give the kernel contrast: the goto out_unlock ladder is manual RAII; C++ automates it.

What is object slicing?

Copying a derived object into a base-class value keeps only the base part, so virtual calls on the copy run the base version. Our demo prints by value: shape, by reference: circle. Pass polymorphic objects by reference or pointer.
