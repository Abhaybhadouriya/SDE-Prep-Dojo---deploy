Basics and the four pillars

What is OOP? Explain it to a five-year-old.

OOP (object-oriented programming) builds a program out of objects: little things that each know some facts (data) and can do some jobs (methods). A toy car knows its colour and speed and can move and honk. You ask the car to move; you don't push its wheels yourself. A class is the toy's mould; an object is one toy made from it.

Reported: Mastercard (LeetCode Discuss, 2025-10-25); Airtel (LeetCode Discuss, 2026-08-18).

How to answer

Kid version first (10 seconds), then the grown-up line: objects bundle state with behaviour, hide internals, and let you swap one kind of object for another through a shared interface.

Likely follow-ups
  • Now give the four pillars with an example each.
  • What problem does OOP solve that procedures do not?
Name the four pillars of OOP with one real example each.
  • Encapsulation: keep state private, change it only through methods that protect rules. Wallet.debit() refuses to go below zero; nobody sets balance directly.
  • Abstraction: expose what, hide how. PaymentGateway.charge(); callers do not know the bank protocol.
  • Inheritance: a class reuses and specialises another (is-a). SavingsAccount extends Account.
  • Polymorphism: one call, behaviour picked by the real type. for (Notifier n : list) n.send(msg) sends email, SMS or push.

Reported: Mastercard (LeetCode Discuss, 2025-10-25); Microsoft (LeetCode Discuss, 2024-09-12); Walmart (LeetCode Discuss, 2025-09-21).

How to answer

One sentence and one domain example per pillar. Point out that encapsulation is about protecting invariants, not about writing getters and setters.

Likely follow-ups
  • Encapsulation vs abstraction: aren't they the same?
  • Which pillar would you drop first if you had to? (inheritance; composition covers most of it)
Encapsulation vs abstraction: what is the difference?

Abstraction is a design decision about the interface: which operations a type offers (Queue.push/pop). Encapsulation is an implementation discipline: the data behind that interface is hidden and can only change through those operations, so invariants hold. You can have an abstraction with poor encapsulation (public fields behind a nice interface) and the reverse.

How to answer

Use a C analogy: a header file with function prototypes is the abstraction; an opaque struct foo; whose fields are only in the .c file is encapsulation.

Class vs object vs instance; where do they live in memory?

A class is the type definition (fields, methods); one copy of its metadata and method code exists. An object (instance) is one allocated copy of the fields. In Java objects live on the heap, local references on the thread's stack, static fields with the class. In C++ an object can live on the stack, the heap or in static storage, and its lifetime follows that choice.

How to answer

Draw it: stack reference arrow to heap object, object header pointing to class metadata.
