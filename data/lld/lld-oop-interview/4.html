Polymorphism and dispatch

Overloading vs overriding. Which one is runtime polymorphism?

Overloading: same name, different parameter lists, in one class; the compiler picks the version from the declared argument types (compile-time, static dispatch). Overriding: a subclass redefines an inherited method with the same signature; the JVM picks the version from the object's runtime type (dynamic dispatch). Only overriding is runtime polymorphism.

Animal pet = new Dog();
pet.sound();      // "woof"       overriding: runtime type Dog
describe(pet);    // "an animal"  overloading: declared type Animal

How does dynamic dispatch work underneath? (vtable)

Each class has a table of method pointers (a vtable). Each object holds a pointer to its class (a vptr in C++, a class pointer in the JVM object header). A virtual call loads that pointer, indexes the slot for the method, and calls through it. A subclass's table copies the parent's and replaces the overridden slots. JITs often devirtualise hot calls when only one target is seen.

Reported: Adobe (C++) (LeetCode Discuss, 2025-11-15).

Implement polymorphism live: show it in code.
interface PaymentMethod { String pay(long paise); }
record Upi(String vpa)     implements PaymentMethod { public String pay(long p) { return "UPI " + vpa + " " + p; } }
record Card(String last4)  implements PaymentMethod { public String pay(long p) { return "card " + last4 + " " + p; } }

List<PaymentMethod> methods = List.of(new Upi("a@upi"), new Card("4242"));
for (PaymentMethod m : methods) System.out.println(m.pay(5000));   // one call, two behaviours
