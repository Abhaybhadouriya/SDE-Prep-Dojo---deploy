Why did you choose these entities and this class hierarchy?

Defend each class with a noun from the requirements and a responsibility, and each relationship with a reason: composition for owned parts (Order has OrderItems), association for references (Order knows a User), interfaces at variation points. Say which class you would split if it grows (often the service), and why inheritance is shallow or absent.

Reported: Cleartrip (LeetCode Discuss, 2026-07-21); PhonePe (LeetCode Discuss, 2025-04-17).

How to answer

Walk top-down: entities, relationships, services, interfaces. Graders score modelling, separation of concerns and extensibility.

Likely follow-ups
  • Could any class be split further?
  • How would you add a new requirement with minimum change?
Model a chess board in OOP. Which classes and where is polymorphism?

Game (players, board, turn, status), Board (8x8 Cells), abstract Piece with colour and canMove(from, to, board), overridden by King, Queen ... ; Move as a record; an enum GameStatus. Polymorphism lives in canMove; shared sliding logic for rook/bishop/queen can be a helper or a strategy. Check and checkmate belong to a rules class, not to pieces.

Reported: Microsoft (LeetCode Discuss, 2024-09-12).

How to answer

Start from entities, show one class diagram, then code Piece and one subclass.

Likely follow-ups

Interface or abstract class for a family like payment methods, in a 90-minute machine-coding round?

Start with an interface (PaymentMethod with pay(amount)): it is the cheapest change point, any class can implement it, and tests can pass a fake. Add an abstract class under it only when two or more implementations share real state or a fixed sequence of steps (for example AbstractCardPayment holding the card number and running validate, then charge). The service depends on the interface, never on the abstract class. That keeps the "add UPI tomorrow" extension to one new class, which is what the evaluation call checks.

Context: Flipkart machine-coding drives end with a separate call where you explain and extend your code (LeetCode Discuss, 2026-07-17); PhonePe's stated criteria include OOP, separation of concerns and testability (LeetCode Discuss, 2025-09-21).

How to answer

Interface first for the change point, abstract class only for shared state or a template of steps; then show the one-class extension.

Likely follow-ups
  • Java 8+ interfaces have default methods; when is that not enough?
  • Where does the abstract class sit in your class diagram?
How should errors look in a machine-coding solution: return codes, null, or exceptions?

Exceptions for rule violations, with a small typed tree: one base BookingException extends RuntimeException and a few named subclasses (SlotUnavailableException, UserNotFoundException). Validate at the service entry (null and range checks throw IllegalArgumentException), throw domain exceptions from the entity or service that owns the rule, and catch them only in the driver or controller, where you print a clear message and continue the demo. Return Optional for "may be absent" lookups; never return null or -1 to mean failure. A C engineer's habit of -EINVAL returns maps to the exception type, not to an int.

Context: Flipkart's 2026 guideline lists exception handling and edge cases that fail gracefully among the scoring points (LeetCode Discuss, 2026-02-18); a PhonePe problem statement asks that exceptions be handled gracefully (LeetCode Discuss, 2025-02-18).

How to answer

Name the tree, where each exception is thrown and where it is caught; show one line of driver output for a failure case.

Likely follow-ups
  • Checked or unchecked, and why?
  • What does the caller see if two threads book the last seat?
In a 60-minute LLD coding round, how much inheritance should the solution have?

Very little. Most reported Uber problems (parking lot, in-memory file system, pub-sub) need one or two interfaces at the change points and plain final classes for the rest. Inheritance earns a place only for a true "is-a" with shared state, such as File and Directory both being a Node with a name and parent in a file system (the Composite shape). A deep tree like Vehicle -> FourWheeler -> Car -> ElectricCar costs time and invites "what if a car is both electric and a taxi?". Say this trade-off out loud while you code.

Context: Uber's LLD coding rounds run about 60 minutes and expect running code (LeetCode Discuss, 2026-04-13 parking lot; LeetCode Discuss, 2026-04-20 in-memory file system).

How to answer

Give the rule (interfaces at change points, inheritance only for real is-a with shared state), one example where it fits and one where it does not.

Likely follow-ups
  • Model File and Directory: abstract class or interface?
