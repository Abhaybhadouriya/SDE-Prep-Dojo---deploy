Inheritance, diamond and constructors

Why doesn't Java support multiple inheritance of classes?

To avoid the diamond problem with state: if two parent classes both define a field or a method body, the child would have ambiguous or duplicated state and constructors. Java allows multiple inheritance of type (a class can implement many interfaces) and, since Java 8, of behaviour through default methods, with a compile-time rule that the class must resolve conflicts.

Reported: Sunking (LeetCode Discuss, 2026-03-16); Sprinklr (LeetCode Discuss, 2026-06-19).

How to answer

Separate the three kinds: state, implementation, type. Java allows only the last two, with rules.

interface Camera { default String start() { return "camera on"; } }
interface Phone  { default String start() { return "phone on"; } }
class SmartPhone implements Camera, Phone {
    public String start() { return Camera.super.start() + " + " + Phone.super.start(); }   // required

In what order do constructors run? What goes wrong if a constructor calls an overridable method?

Parent constructors run first (top of the hierarchy down), each after its field initialisers. If Base() calls an overridden method, the Derived version runs before Derived's fields are initialised, so it sees null/0. Our demo prints Base() sees name = null. In C++ the call goes to the Base version instead, because the vptr still points at Base's table during Base's constructor.

How to answer

Show the output, then the rule: do not call overridable methods from constructors (make them private or final).

Why do we need inheritance if composition can do the same?

Mostly, we don't. Inheritance is right when there is a true, stable is-a relation and you want subtype polymorphism with shared code (a template method in an abstract base). Composition is better for reuse: it hides the inner object, lets you swap it at runtime, and avoids the fragile base class problem. Example from the same round: an always-sorted list should wrap an ArrayList, not extend it, otherwise callers can still use add(index, x) or set() and break the sort order.

final class SortedList<T extends Comparable<T>> implements Iterable<T> {
    private final List<T> items = new ArrayList<>();        // HAS-A, not IS-A
    void add(T x) { int i = Collections.binarySearch(items, x); items.add(i < 0 ? -i - 1 : i, x); }
    T get(int i)  { return items.get(i); }
}

Reported: Walmart (LeetCode Discuss, 2024-10-25).

Method overriding vs method hiding (static methods).

Static methods belong to the class, so a subclass static method with the same signature hides the parent one; the call is chosen by the declared type at compile time. Instance methods are overridden and chosen at run time. Private methods are neither: they are invisible to subclasses.

How to answer

Short definition plus the one-line demo: Animal.kind() vs Dog.kind().
