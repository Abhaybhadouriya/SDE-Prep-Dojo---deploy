Common ways the framework goes wrong

Mistakes
  • Coding in minute two, then discovering a missed rule in minute thirty.
  • Spending 20 minutes on a perfect UML diagram with every getter.
  • Starting from leaf entities and never building the orchestrator.
  • Listing patterns first ("I'll use Factory, Singleton, Observer") and fitting the problem to them.
  • Getting lost in edge cases before the main flow is designed.
  • Ignoring concurrency until asked, then bolting a global lock on everything.
  • Switching to an unfamiliar language "because it's more OOP".
Fixes
  • Five minutes of requirements, written and read back.
  • Key fields and methods only; ask if they want formal UML.
  • Orchestrator first, then the entities it needs (Hello Interview's advice).
  • Find change points first; the pattern follows from each one.
  • Happy path first, then edge cases, then invalid input.
  • Name the shared state and race yourself, with a scoped lock.
  • Use the language you are fastest in.
