The whole framework on one problem (click through)

Here are all eight steps on the meeting-room problem, in the order you would say them in the room. Use the controls or press Play.

  1. Clarify (0-5 min). Ask about actors, rules, what varies, errors and concurrency. Write P0, P1 and out of scope, and read them back.
  2. Entities (5-9). Nouns with state or rules become classes. The interval becomes an immutable value object. "Employee" stays a plain id.
  3. Class diagram (9-18). Draw ownership: the service owns rooms, each room owns its bookings and its no-overlap rule.
  4. APIs (18-22). Write the orchestrator's signatures. Return a Booking; throw named exceptions instead of returning null.
  5. Patterns (22-26). One rule varies (which room), so one pattern (Strategy). Say why you did not add others.
  6. Code (26-39). Code the logic-carrying path first and trace a real example out loud.
  7. Extend (39-44). The interviewer asks for floor preference: one new strategy class, nothing else edited.
  8. Concurrency (44-49). Name the check-then-act race, lock per room, atomic ids, and the race test that proves it.
