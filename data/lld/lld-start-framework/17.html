Quiz

In a 55-minute round, which step should get the largest single time block?

  1. Clarify
  2. Code
  3. Patterns
  4. Concurrency
Code (about 13 minutes) is the biggest block; a design with no working logic for the core path scores poorly.

Where should class design start, according to the frameworks surveyed?

  1. The smallest entity
  2. The database tables
  3. The orchestrator that callers talk to
  4. The exception classes
Starting from the orchestrator keeps the design driven by use cases; entities are added as the orchestrator needs them.

Two threads both call isFree(), both get true, and both add a booking. What is this bug called?

  1. A check-then-act race
  2. A deadlock
  3. A memory leak
The check and the act are separate steps; the fix is to perform both under one lock (or one atomic operation).

"Employee" appears in the requirements but has no data or rules in P0. Best choice?

  1. An abstract class
  2. A Singleton
  3. An interface
  4. A plain id string for now
Classes without state or rules are bloat. Promote it to a class when a requirement needs its data.

The interviewer asks for "prefer the organizer's floor". In a good design, what changes?

  1. BookingService.book() gets a new if-branch
  2. A new RoomSelectionStrategy class is added; nothing else is edited
  3. Room gets a floor-check method
The room choice was identified as a change point and put behind an interface, so the extension is a new class (Open/Closed).

In a 90-minute machine-coding round, what should be true by about minute 60 of coding?

  1. All bonus features started
  2. The README is written
  3. Every P0 flow runs from the driver
  4. Unit tests for every class
Working, demoable P0 is graded first; bonus features and polish only after that.

Why return a Booking object from book() instead of a room id string?

  1. Callers get the booking id and details they need (e.g. for cancel) with types, not parsing
  2. It is faster
  3. Strings cannot be returned in Java
A typed result carries everything the next API call needs. Failures are signalled with named exceptions, not null.
