Step 3 - Class diagram (8-10 min)

Draw boxes with the important fields and methods, then the relationships. You do not need perfect UML; most interviewers accept simplified notation (Hello Interview says so explicitly - ask if they want formal UML). But a few arrow types carry meaning, and using them correctly is quick credit.

Read the diagram as a set of ownership decisions, because that is what the interviewer is checking:

  • The room owns the no-overlap rule. Room.tryAdd() checks and inserts. The rule lives next to the data it protects (the "Information Expert" idea from GRASP).
  • The service owns the workflow. Validate, ask the strategy for candidates, try each room. Workflow rules go in the orchestrator; data rules go in the entity.
  • The choice of room is behind an interface. That is the change point from step 1.
