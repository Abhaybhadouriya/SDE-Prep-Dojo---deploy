Step 7 - Extensibility (5 min)

The interviewer will now add requirements. A good design absorbs each one by adding code at a seam you already built. Here is the most likely one for our problem - "prefer rooms on the organizer's floor":

final class PreferFloor implements RoomSelectionStrategy {      // new class; nothing else edited
    private final int floor;
    private final RoomSelectionStrategy fallback = new SmallestFitFirst();
    PreferFloor(int floor) { this.floor = floor; }

    public List<Room> rank(List<Room> rooms, int attendees) {
        List<Room> ranked = new ArrayList<>(fallback.rank(rooms, attendees));   // keeps capacity check
        ranked.sort(Comparator.comparingInt((Room r) -> r.floor == floor ? 0 : 1)); // stable sort
        return ranked;
    }
}

Prepare a short answer for the typical extension asks. You do not have to code them; say where they plug in:

"What if..."Where it plugs inWhat does not change
New room selection ruleNew RoomSelectionStrategy classBookingService, Room
Recurring weekly meetingsA RecurrenceRule that expands into intervals; book all-or-nothingRoom.tryAdd rule
Notify attendeesAn Observer (BookingListener) registered on the serviceBooking logic
Rooms with equipment (projector, VC)A filter step / Specification before rankingStrategy interface
Persist bookingsA BookingRepository interface with in-memory and DB versionsService API

This is the Open/Closed Principle in practice: open for extension, closed for modification. Hello Interview notes that interviewers expect less of this from junior candidates and more from senior ones - so for SDE-2, have two or three of these ready.
