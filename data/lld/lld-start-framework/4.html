Step 2 - Entities (3-5 min)

Underline the nouns in your requirements; they are candidate classes. Underline the verbs; they are candidate methods. Then filter: a noun becomes a class if it has its own state or rules, a field if it is just a value of something else, an enum if it is a fixed set of options, and a value object (small, immutable) if it is a value with behaviour, like a time interval.

Notice what did not become a class: "system" (that is the orchestrator), "time slot" (merged into Interval), "employee" (just an id until a requirement needs more). Fewer, well-chosen classes beat many empty ones.

From your world

This is the same judgement as deciding what gets its own struct in a driver. A ring descriptor gets a struct because it has fields and invariants; a VLAN id is just a u16 inside another struct. A value object like Interval is a small struct you pass by value and never modify, like a struct timespec.
