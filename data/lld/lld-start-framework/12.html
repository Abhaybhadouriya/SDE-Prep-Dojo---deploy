The machine-coding variant: 15 + 90 + 15

In a 2-hour machine-coding round (Flipkart, PhonePe, Razorpay, Swiggy), the same 8 steps happen, but the weights change. Steps 1-5 squeeze into a short planning block, step 6 becomes 90 minutes of real coding, and steps 7-8 show up partly in your code (thread-safe P0) and partly in the evaluation call. The workat.tech description of the Flipkart format uses the same three phases: understand and clarify, code, then demo while the evaluator runs tests.

  1. Plan (15 min). Read the whole statement twice. Mark P0 vs bonus. Write entities, enums, the service methods and the in-memory maps on paper. Decide the package layout (model, repository, service, strategy, exception, Driver). Ask the clarifying questions now - there may be nobody to ask later.
  2. Code (90 min). Skeleton first so it compiles; then P0 flows one by one, each demoed from the driver as soon as it works; then validation and custom exceptions; then thread safety if the brief asks for it (Flipkart's 2026 brief did); then bonus. Commit or copy a working version at each checkpoint.
  3. Demo (15 min). Run the driver; show each requirement's output; point at the seams ("new delivery-partner assignment rule = new strategy class"). In the later evaluation call, expect "extend it now" and "make it production-ready".

The detailed playbook - input parsing, README, test drivers and what evaluators check line by line - is in Machine-Coding Round Guide and Code Layout.
