As REST endpoints: GET /trains?from=NDLS&to=NGP&date=2026-12-10, GET /trains/12627/availability?date=&class=3A&from=&to=, POST /bookings with an Idempotency-Key header (a retried request after a timeout must not create a second PNR; respond 201 with the PNR, or 409 "REGRET"), GET /pnr/{pnr}, DELETE /bookings/{pnr} (or a per-passenger cancel POST /bookings/{pnr}/cancellations).

Cost of each operation

OperationCostWhy
search(from, to)O(Tfrom + Tto)Two inverted-index lookups (trains through each station), an intersection, and an O(1) stop-order check per train.
availabilityO(B)One AND of the trip mask with each of the B berth masks.
book (P passengers)O(P x B)Each passenger scans the B berth masks (one AND each) for a free fit, then RAC halves, then the WL length check. All of it under the journey lock, in memory.
cancelO(P + (R + W) x B)Free the P tickets (AND NOT), then walk the RAC queue (R) and the WL queue (W) in order, trying to confirm or move up each one: each try is a berth scan.
pnr(pnr)O(1)Hash map from PNR to booking.

B is small (a coach has 64 to 72 berths; one class of a whole train has a few hundred), so the whole critical section is microseconds even at the O(P x B) worst case. That is why one lock per journey scales.
