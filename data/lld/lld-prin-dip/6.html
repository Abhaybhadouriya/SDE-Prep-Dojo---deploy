Constructor injection and the composition root

DIP says "depend on an abstraction". It does not say how the real object arrives. That is the job of Dependency Injection (DI): the object receives its collaborators from outside instead of creating them. Three forms:

FormLooks likeWhen
Constructor injection (default)new OrderService(repo, notifier)Required collaborators. Fields can be final; the object is never half-built; missing deps fail at construction.
Setter injectionsvc.setNotifier(n)Truly optional or re-configurable collaborators. Risk: forgetting to call it.
Method (parameter) injectionsvc.place(order, clock)The collaborator changes per call (a clock, a request context).

The composition root is the one place where concrete classes are chosen and wired - usually main() in a machine-coding round, or a DI container (Spring, Guice, Dagger) in a real service. Everything else in the code base only sees interfaces.

Field injection (@Autowired private Notifier n;) hides dependencies, prevents final, and makes the class impossible to build in a plain unit test without the container. Spring's own reference documentation recommends constructor injection for mandatory dependencies. Say this in a Java-heavy round (Walmart, Amazon).
