Watch the arrow flip

  1. Before: OrderService imports and constructs the MySQL DAO. Call and dependency both point down.
  2. Describe what the policy needs as an interface, and place it in the policy package.
  3. OrderService now uses only the interface. It has no idea MySQL exists.
  4. The MySQL class moves behind the interface and implements it. Its source-code dependency now points up: inverted.
  5. One composition root (main, a factory, or a DI container) picks the concrete class and injects it.

The runtime call still goes from OrderService to MySQL. Only the compile-time dependency flips. Interviewers sometimes test exactly this: "if the call still goes down, what got inverted?" Answer: the direction of the source-code import, and the ownership of the interface.
