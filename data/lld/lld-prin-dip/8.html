From your world: the kernel already inverts its dependencies

From your world

The Linux networking core is the high-level module. A NIC driver such as e1000 is the low-level detail. The core never includes e1000.h. Instead, the core defines struct net_device_ops (the abstraction) in include/linux/netdevice.h; the driver includes that header, fills the table with its own functions, and calls register_netdev(). The driver depends on the core's interface; the core depends on nothing driver-specific. That is DIP, written in C, decades before the name was common.

Passing a struct my_ops * into an init function instead of hard-coding calls is dependency injection. And the core calling your ndo_start_xmit whenever it has a packet is Inversion of Control: you registered, now it calls you.

/* high level owns the abstraction (think include/linux/netdevice.h) */
struct tx_ops { int (*xmit)(void *dev, const void *pkt, unsigned len); };

struct stack { const struct tx_ops *ops; void *dev; };      /* policy */
void stack_init(struct stack *s, const struct tx_ops *ops, void *dev) {
    s->ops = ops; s->dev = dev;                                /* injection */
}
int stack_send(struct stack *s, const void *pkt, unsigned len) {
    return s->ops->xmit(s->dev, pkt, len);                     /* no driver header needed */
}

/* low level (a driver .c file) includes the stack's header and implements it;
   a fake NIC like this one is also how you unit-test the stack */
struct fake_nic { unsigned sent_bytes; };
static int fake_nic_xmit(void *dev, const void *pkt, unsigned len) {
    (void)pkt; ((struct fake_nic *)dev)->sent_bytes += len; return (int)len;
}
static const struct tx_ops fake_nic_ops = { .xmit = fake_nic_xmit };

The fake NIC is exactly how you would unit-test the stack without hardware - the same benefit as the InMemoryOrderRepository above.
