Quiz

Which feature separates a Chain of Responsibility handler from a Decorator?

  1. It holds a reference to the next object
  2. It implements the same interface as the next object
  3. It may stop the request instead of forwarding it
  4. It is created by a factory
Both hold a next reference with the same interface; only a chain handler may decide not to forward.

A netfilter hook wants the next hook to see the packet. What does it return?

  1. NF_ACCEPT
  2. NF_DROP
  3. NF_STOLEN
  4. NOTIFY_STOP
ACCEPT continues the walk; DROP and STOLEN end it. NOTIFY_STOP belongs to notifier chains.

ATM stock: 500 x 1, 200 x 4, 100 x 0. A purely greedy chain is asked for 600. What happens?

  1. It gives 500 + 100
  2. It gives 200 x 3
  3. It gives 500 + 200 and refunds 100
  4. It takes the 500, cannot make the remaining 100, and fails
Greedy takes the 500 first and is stuck. Backing off at the 500 handler finds 200 x 3.

Why does the ATM plan first and change stock only after the whole plan succeeds?

  1. It is faster
  2. So a failed request never leaves stock half-changed
  3. Java requires it
  4. So the chain can be reordered
Plan-then-commit avoids side effects from a request that a later handler rejects.

A logger where console, file and pager each decide by level, and every one sees every record, is which style?

  1. Classic stop-on-first-handler
  2. Strategy
  3. Pass-through chain (close to Observer)
  4. Command
Nobody stops the record; each handler filters by its own minimum level.

What is the standard protection against a request that "falls off the end" of a chain?

  1. A terminal default handler that always answers
  2. Making the chain longer
  3. Running all handlers in parallel
  4. Using a Singleton chain
A terminal handler (error, default verdict, dead-letter) makes silence impossible.
