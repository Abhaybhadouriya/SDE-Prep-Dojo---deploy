The problem: one method that knows every rule

A payments API checks a request before paying. The first version puts every check in one place:

Response pay(Request r) {
    if (!tokens.isValid(r.token()))            return Response.status(401);
    if (rateLimiter.tooMany(r.user()))         return Response.status(429);
    if (r.amount() <= 0)                       return Response.status(400);
    if (fraud.score(r) > 0.9)                  return Response.status(403);
    if (r.amount() > 100_000 && !r.has2fa())   return Response.status(428);
    // ... and the refund endpoint copies the first three checks,
    // and the payout endpoint copies them again with a different order.
    return doPay(r);
}
  • Every new rule edits this method (and its copies). It breaks the Open/Closed principle.
  • Order is hard-coded. You cannot put the cheap rate-limit check first for one endpoint and the auth check first for another without copy-paste.
  • Checks cannot be reused or tested alone. The fraud check is buried inside one endpoint.

The fix: make each check its own object with one job and a link to the next. Build different chains for different endpoints out of the same pieces.
