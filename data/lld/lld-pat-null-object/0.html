The story: the empty chair

Explain like I'm 5

At a birthday party every child gets a plate, a cup and a party hat. One friend is sick and does not come. The teacher could tell every helper "be careful, chair five is empty, check before you pour juice". Every helper has to remember, and one of them forgets and pours juice onto the floor.

Or the teacher puts a big teddy bear on chair five. The helpers pour juice into the teddy's cup like everyone else's. Nobody has to check. Nothing spills. The teddy bear does not drink, but it plays the part of "someone sitting there".

The teddy bear is a Null Object: something with the same shape as a real participant whose behaviour is the harmless "nothing". Code that calls it does not need a special case.

From your world

You already use null objects. /dev/null is a device whose write accepts every byte and drops it, and whose read returns end-of-file at once; programs write to it with the normal write() call and never ask "is there a real file?". The dummy network driver is an interface that accepts packets and frees them. And you know the other style too: many kernel ops tables let a member be NULL, so the core has to test the pointer before each call, and a missing test is an oops. Helpers such as noop_llseek() exist so a driver can fill the slot with a real do-nothing function instead.
