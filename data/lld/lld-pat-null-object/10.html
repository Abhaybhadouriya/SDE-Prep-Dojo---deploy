In interviews

Null Object is rarely the question. It is a quality signal inside a case study, and a classic follow-up ("how would you remove these null checks?"). The community code mirror of the popular Concept && Coding LLD series includes a Null Object example. Places to use it:

  • Shopping cart: NoCoupon / NoDiscount as the default pricing rule.
  • Logger: a NullAppender or a level that drops everything; ends the handler chain.
  • Notification service: a NoopChannel for users who opted out.
  • Parking lot and car rental: a free-parking or zero-fee pricing strategy.
  • Snake and ladder: a plain cell with a no-op "jump" instead of null for "no snake or ladder here".
  • Pub-sub and observers: an empty subscriber list or a no-op listener instead of null checks on publish.

Strong 30-second answer: "Instead of returning null and checking it everywhere, I return an object with the same interface whose methods do the neutral thing, like NoDiscount returning zero. It is stateless, so one shared instance. I use it only where absence is harmless; where absence is an error, like an unknown account for a refund, I return Optional or throw, so the bug is loud."
