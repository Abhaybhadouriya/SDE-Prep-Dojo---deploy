Access modifiers in Java and C++

An access modifier is a keyword that says which code may name a field, method or class. The compiler rejects any other use. Java has four levels; C++ has three plus friend.

publicEveryoneEveryone+
protectedSame package and subclasses anywhereThe class, its friends, and derived classes (through a derived object)#
package-private (default, no keyword)Same package only(no equivalent; closest is an anonymous namespace or not exporting a header)~

Three details that catch people:

  1. Java protected is wider than C++ protected. In Java, every class in the same package can use it, subclass or not. Many teams therefore treat protected fields as almost public and prefer private fields with protected methods.
  2. Access is per class, not per object. In both languages, a method of Account may read other.balancePaise of a different Account. That is why equals() and copy constructors can read private fields of their argument.
  3. C++ friend is a named exception the class grants itself. Used for tightly coupled helpers (an operator<<, a test fixture, an iterator). It does not inherit and it is not transitive. Use it sparingly.
struct Plain { int x = 1; };              // struct: members public by default
class Sealed { int x = 2; };              // class: members private by default

class Counter {
public:
    void inc() { ++value_; }
    int value() const { return value_; }
protected:
    int hits_ = 0;                        // visible to subclasses
private:
    int value_ = 0;                       // visible to Counter (and friends) only
    friend void audit(const Counter& c);  // a named exception
};

class RateCounter : public Counter {
public:
    void hit() { ++hits_; inc(); }        // protected OK; value_ is not reachable
};

Python has no access keywords. The convention is a single underscore (_cache: "internal, please do not touch") and double underscore (__balance), which triggers name mangling to _Account__balance so subclasses do not clash by accident. It is a convention, not a lock: our sample still reads a._Account__balance. Use @property to expose a read-only attribute.

Java 9+ adds one more wall above classes: modules (module-info.java). A public class in a package that the module does not export is invisible to other modules. Interviews rarely go there, but it is the honest answer to "is public really public?".
