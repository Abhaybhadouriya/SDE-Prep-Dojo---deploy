The story: the bank teller window

Explain like I'm 5

At a bank you cannot walk into the vault and take money. You go to a window and say "I'd like to take out 300 rupees". The teller checks that you have enough, counts the money, writes it in the book and hands it over. If you ask for more than you have, the teller says no.

The vault is the data. The window is the method. Because everyone must use the window, the rule "nobody's balance goes below zero" can never be broken. That is encapsulation: keep the data inside, let people in only through doors that check the rules.

And you do not need to know how the vault is built, which safe holds your money or how the counting machine works. You only know "deposit" and "withdraw". That is abstraction: show the simple idea, hide the details.

From your world

You have used encapsulation in C for years. FILE * in stdio is an opaque handle: you call fopen, fread, fclose and never touch the buffer pointers inside. In the kernel, drivers are told to use accessors like skb_put(), skb_headroom() or netdev_priv() instead of poking at sk_buff or net_device internals, because the layout and its rules (head <= data <= tail <= end) belong to the networking core. The difference in C is that hiding is a convention or a header trick; in Java and C++ the compiler enforces it.
