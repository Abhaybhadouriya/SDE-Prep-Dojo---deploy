Remember this

  • Encapsulation hides state to protect invariants; abstraction hides complexity behind a simple interface.
  • An invariant is a rule that is always true outside a method call. Private state means only the class's own methods can break it.
  • Java: public, protected (package + subclasses), package-private (default), private. C++: public, protected, private, plus friend; class defaults private, struct public.
  • Private fields with public setters are not encapsulation. Tell, don't ask: expose intent (withdraw, cancel), not raw state.
  • Never leak mutable internals: defensive copy in, read-only view or copy out.
  • C does it with opaque handles (incomplete struct + functions); C++ pImpl is the same trick.
