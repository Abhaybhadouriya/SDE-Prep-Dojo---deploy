The same idea in C: opaque handles

C has no private, but it has something just as strong: an incomplete type. The header declares struct ringbuf; without its fields. Callers can hold a struct ringbuf * and pass it to functions, but the compiler refuses rb->count because it does not know the layout. Only ringbuf.c sees the full definition, so only it can break the invariants.

struct ringbuf;                                  /* layout is private to ringbuf.c */

struct ringbuf *ringbuf_create(size_t capacity);  /* "constructor" */
void ringbuf_destroy(struct ringbuf *rb);         /* "destructor"  */
int  ringbuf_push(struct ringbuf *rb, int value); /* 0 ok, -1 full  */
int  ringbuf_pop(struct ringbuf *rb, int *out);   /* 0 ok, -1 empty */
size_t ringbuf_count(const struct ringbuf *rb);   /* a "getter" */
struct ringbuf {            /* invariant: 0 <= count <= cap, head/tail < cap */
    size_t cap, head, tail, count;
    int *slots;
};

int ringbuf_push(struct ringbuf *rb, int value) {
    if (rb->count == rb->cap) return -1;
    rb->slots[rb->tail] = value;
    rb->tail = (rb->tail + 1) % rb->cap;
    rb->count++;
    return 0;
}
struct ringbuf *rb = ringbuf_create(2);
ringbuf_push(rb, 1);
ringbuf_push(rb, 2);
printf("push 3 -> %d (full)\n", ringbuf_push(rb, 3));
/* rb->count = 99;  does not compile: struct ringbuf is incomplete here */
ringbuf_destroy(rb);
$ gcc -std=c99 -Wall -Wextra -o rb ringbuf/main.c ringbuf/ringbuf.c && ./rb
push 1 -> 0
push 2 -> 0
push 3 -> -1 (full)
pop -> 1, count now 1

From your world

Map it one to one: the incomplete struct is a private section; the functions in the header are the public methods; ringbuf_create/ringbuf_destroy are the constructor and destructor; a static function in ringbuf.c is a private method. The kernel uses the variant "visible struct, documented accessors" for speed (inline accessors need the layout), and relies on review and checkpatch to keep drivers from poking. C++'s pImpl idiom is this same opaque-pointer trick, used to keep a class's private fields out of its header so changes do not force recompiles.
