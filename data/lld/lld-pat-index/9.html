Look-alikes: same shape, different intent

Many patterns draw the same class diagram (a class holding an interface). The difference is why. These pairs are a favourite quick-fire round:

PairSame shapeThe difference
Strategy vs Statecontext delegates to an interfacethe client picks a strategy; states switch to the next state themselves
Strategy vs Template Methodvary an algorithmcomposition at run time vs inheritance at compile time
Decorator vs Proxywrapper with the same interfaceadds behaviour (stackable) vs controls access to the real object
Adapter vs Facadewrapperconverts one interface vs simplifies a whole subsystem
Simple Factory vs Factory Method vs Abstract Factoryhide the concrete classkey vs subclass vs family
Observer vs Pub-Subone-to-many notificationsubject knows its observers vs a broker decouples both sides (and often time)
Command vs Strategyan object wrapping behaviourwhat to do (and when, undo) vs how to do it
Composite vs Decoratorrecursive structuremany children (a tree) vs one wrapped object (a chain)
