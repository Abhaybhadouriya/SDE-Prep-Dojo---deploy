Interview questions

What is a code smell? Is it a bug?

A surface sign in the code that usually points to a deeper design problem - a long method, a repeated switch on type, a long parameter list. It is not a bug by itself; the code may work. It means the code will be hard to change or easy to break later.

How to answer

Definition, two examples, and "smell = reason to look, not automatic rewrite".

Likely follow-ups
  • Name the smell groups.
  • Which smell do you see most in your own code?
What is refactoring, and how is it different from rewriting?

Refactoring changes structure without changing behaviour, in small steps with tests green after each. Rewriting replaces code, and the program may be broken for a long time. Refactoring keeps the program shippable at every step.

How to answer

Stress "behaviour unchanged" and "small steps + tests". Mention the two-hats rule.

Likely follow-ups
  • What if there are no tests? (Characterization tests first.)
Here is a method with a switch on vehicle type in three places. Fix it.

Replace Conditional with Polymorphism: an interface (VehicleRules or a rich enum) with the varying methods, one implementation per type, and the selection done once in a factory or map. Callers call the method without checking the type. If types differ only in data (rate, size), a rich enum is enough; if they differ in behaviour, use classes (Strategy).

How to answer

Name the smell and the refactoring, sketch the interface and one class, then show how a new type is added without editing callers.

Likely follow-ups
  • Where does the remaining "choose the class" logic live?
  • Enum vs classes - when which?
Why should money not be a double? What do you use instead?

Binary floating point cannot represent most decimal fractions exactly, so sums drift and rounding loses paise. Use integers in the smallest unit (paise) or BigDecimal with an explicit rounding mode, wrapped in a Money value object that owns arithmetic, currency and splitting (remainder distributed so totals match).

How to answer

Show the Rs 100 / 3 example, then the value object. This is Replace Data Value with Object.

Likely follow-ups
  • How do you handle multiple currencies?
  • Who gets the extra paisa in a split?
Shotgun Surgery vs Divergent Change - what is the difference?

Divergent Change: one class is changed for many unrelated reasons (low cohesion) - fix with Extract Class. Shotgun Surgery: one reason forces changes in many classes (a responsibility is scattered) - fix with Move Method/Field to bring it together. They are mirror images.

How to answer

One class, many reasons vs one reason, many classes. Link to SRP and coupling.

Likely follow-ups
  • Which one did you see in the last codebase you worked on?
You find a bug while refactoring. What do you do?

Keep the hats separate. Finish or roll back the current refactoring step so behaviour is unchanged and tests are green. Then write a failing test for the bug, fix it in its own commit, and continue refactoring. Mixing the fix into a refactoring commit makes both harder to review and to revert.

How to answer

Describe the sequence; mention commits and reviewability.

Likely follow-ups
  • What if other code depends on the buggy behaviour?
When is duplication better than an abstraction?

When the two copies serve different owners or will change for different reasons, or when you have only one or two examples (rule of three). A premature shared abstraction couples both callers, grows flags for each special case (control coupling), and becomes the wrong abstraction. Inline it back and re-extract when the real shared part is clear.

How to answer

Rule of three, change reasons, and the "flag parameters growing" warning sign.

Likely follow-ups
  • How does this relate to DRY?

Scenario: the review call

Your machine-coding solution works. The reviewer says: "Walk me through what you would improve."
"It's fine, I followed SOLID." Or a vague "I'd clean up the code."
"Three things, in order. BookingService.book() is 70 lines - I'd extract validation, pricing and seat locking. Prices are double - I'd introduce Money in paise. And the status int in Booking drives four if-ladders - Replace Type Code with State. Each is behaviour-preserving, and my driver re-checks the outputs after each step."
Follow-ups: which one first and why? How would you prove nothing broke?
