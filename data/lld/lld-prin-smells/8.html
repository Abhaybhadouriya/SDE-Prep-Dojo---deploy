Remember this

  • A smell is a hint, not a bug. Refactoring changes structure, never behaviour, in small tested steps.
  • Fix Tier 1 first: Large Class, Long Method, Switch on type, Primitive Obsession, Duplicate Code. Families (from the Mäntylä et al. taxonomy): too big, OO misuse, change cost, unneeded, coupling.
  • Top cures: Extract Method, Extract Class, Introduce Parameter Object, Replace Data Value with Object, Replace Conditional with Polymorphism, Replace Type Code with State, Move Method, Guard Clauses, Hide Delegate, Introduce Null Object.
  • No tests? Write characterization tests first. Two hats: refactor or add features, never both in one step.
  • Money is never a double: a Money value object in paise.
  • Rule of three before extracting; speculative generality is a smell too.
  • In machine coding: write clean from the start, run end to end, then cheap refactors, then name the rest in the review.
