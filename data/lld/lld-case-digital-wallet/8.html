APIs and interfaces

Wallet      createWallet(String userId);
Transaction deposit (String key, String walletId, long paise, PaymentMethod m, String source); // source = VPA or card token
Transaction withdraw(String key, String walletId, long paise);
Transaction transfer(String key, String fromWallet, String toWallet, long paise);
Transaction reverse (String txnId);                               // key = "reverse:" + txnId, so it is idempotent too
List<LedgerEntry> statement(String walletId, Predicate<LedgerEntry> filter, Comparator<LedgerEntry> order);

// extension points
interface PaymentGateway { ChargeResult charge(String source, long paise, String idempotencyKey); }
GatewayRouter register(PaymentMethod m, PaymentGateway g, long maxPaisePerTxn);

Business failures (low balance, card declined, over limit) come back as a FAILED transaction with a reason, because they are normal outcomes that must be recorded and replayed. Programming errors and contract violations (amount <= 0, same key with a different body, transfer to self) throw.
