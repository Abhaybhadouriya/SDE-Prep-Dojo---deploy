Common mistakes

  • double for money.
  • Checking idempotency with get-then-put: two duplicates both pass.
  • Updating two balances under two separate, unordered locks, or under no lock.
  • Only a balance field, no ledger: no statement, no audit, no reversal history.
  • Deleting or editing entries to "undo" instead of posting a reversal.
  • Vendor SDK types in the service (a RazorpayResponse parameter in deposit): no Adapter.
  • One big if (method == UPI) ... else if (CARD) in the service.
  • Treating a gateway timeout as failure and retrying with a fresh key.
  • Calling the gateway while holding wallet locks: a slow network call blocks every transfer touching that wallet. (Our deposit calls it before post() takes any wallet lock.)
