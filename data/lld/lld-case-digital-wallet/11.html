Extensibility: the follow-ups

  1. New payment method (net banking, wallet-to-bank). One adapter + router.register(...). No service change.
  2. "Disable modes by amount, prefer by category" (CRED). Replace the per-method limit with a rule list per method (min, max, allowed categories) and a preference order per category; the router returns the first allowed gateway, falling back down the list.
  3. Gateway fail-over. If the primary UPI provider returns "unavailable" (not "declined"), try the next provider with the same key. Wrap it as a fail-over decorator around PaymentGateway.
  4. Offers and cashback (PhonePe). After a SUCCESS, evaluate offer rules (Strategy / Specification); a cashback is just a transfer from a SYS_PROMO wallet with its own idempotency key ("cashback:" + txnId).
  5. Fixed deposits (Flipkart). A transfer from the user wallet to a per-user FD wallet; maturity is a scheduled transfer back plus an interest transfer from a system wallet.
  6. EXPENSE / RECEIPT (Groww). Transfers to and from merchant or system wallets with a type tag for reporting.
  7. Daily limits and fraud checks. A chain of pre-checks before post() (velocity, daily total, blocked users).
  8. Notifications. Publish an event after SUCCESS (Observer); never send SMS inside the wallet locks.
  9. Statement queries. Already a Predicate + Comparator; for large histories, index entries per wallet instead of scanning the whole ledger.
