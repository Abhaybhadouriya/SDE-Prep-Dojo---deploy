In the transition label select [balance >= price] / dispense, what is [balance >= price]?

  1. The event
  2. The action
  3. The guard
  4. The target state
Square brackets hold the guard: a condition checked when the event (select) arrives. The action follows the slash.

Which implementation fits a machine with many states but almost no per-state behaviour?

  1. A transition table
  2. One class per state
  3. Inheritance from a base Order
  4. A singleton
A table keeps the diagram as data: easy to read, test and extend when the states differ only in where they can go.

Two drivers accept the same ride at once. What makes only one succeed?

  1. Checking the state, then setting it, in two statements
  2. Making Trip a singleton
  3. An activity diagram
  4. An atomic compare-and-set from REQUESTED to ASSIGNED
Check-then-set in two steps lets both pass the check. CAS (or a conditional UPDATE) makes the check and the change one atomic step.

Which TCP state does the side that closes first sit in after receiving the peer's FIN?

  1. CLOSE-WAIT
  2. TIME-WAIT
  3. LAST-ACK
  4. SYN-RECEIVED
The active closer goes FIN-WAIT-1, FIN-WAIT-2, then TIME-WAIT on the peer's FIN, and waits 2MSL. CLOSE-WAIT and LAST-ACK are the passive closer's states.

What does a fork bar in an activity diagram mean?

  1. A decision with two guards
  2. The end of the process
  3. The flows after it run in parallel
  4. A state change
A fork splits control into concurrent flows; a join waits for all of them. Decisions are diamonds.

An order's cancel() is written as if (status != DELIVERED). What is the main risk?

  1. Any state not listed, including Shipped or states added later, is silently allowed
  2. It is too slow
  3. It cannot be unit tested
  4. It violates encapsulation
Negative checks allow everything you forgot. Encode the allowed source states positively, as arrows in the diagram.

You need to show who (customer, checkout service, warehouse) does each step of a checkout. Best diagram?

  1. A state diagram of the order
  2. An activity diagram with swimlanes
  3. A class diagram
  4. A use-case diagram
Swimlanes on an activity diagram show the performer of each action; the state diagram follows one object only.
