The parts of a state diagram

Here is a door with a lock. Every symbol you need is on it.

SymbolNameMeaning
Rounded boxStateA condition the object stays in until something happens. Exactly one is active at a time (in a simple machine).
Filled dotInitial pseudostateWhere the object starts. One arrow leaves it, with no event.
Dot inside a ring (bullseye)Final stateThe object's lifecycle is over (order closed, connection gone).
Arrow with event [guard] / actionTransitionWhen event arrives and guard is true, run action and move to the target state. All three parts are optional.
entry / x, exit / y, do / zState behavioursRun x on entering, y on leaving, z while inside (an ongoing activity).
Arrow back to the same stateSelf-transitionHandle the event without changing state (it does run exit then entry; an internal transition, written inside the box, does not).
after(30 s), when(balance < 0)Time / change eventsFire on a timeout or when a condition becomes true.

Events not drawn are ignored (or are errors). If the door is Opened and someone sends lock, nothing on the diagram handles it. Decide and say which: silently ignore, or throw IllegalStateException. In a payment or order system, throwing (and logging) is usually right: a "ship" on a cancelled order is a bug somewhere upstream.
