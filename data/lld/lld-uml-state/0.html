The story: a traffic light has moods

Explain like I'm 5

A traffic light is always in exactly one mood: red, green or yellow. It never is "a bit red and a bit green". When the timer rings, it changes mood: red to green, green to yellow, yellow to red. It can never jump from green straight to red.

Draw each mood as a rounded box and each allowed change as an arrow. Write on the arrow what makes it happen ("timer rings"). Now anyone can check the light: if it ever went green to red, it broke the drawing.

That drawing is a state diagram (UML calls it a state machine diagram). It is the right picture for any object whose behaviour depends on its history: an order that can be cancelled before shipping but not after, a ride that can be assigned only once, a vending machine that ignores the button until you pay. Interviewers love these objects because the bugs live in the transitions. Uber's cab-allocation question explicitly hinges on the trip lifecycle and the available-to-assigned transition (see the sequence diagram page for the request flow), and vending machines are a regular Amazon prompt.

At the end we add the activity diagram, a flowchart with parallel branches, for when the question is "what steps happen in what order" rather than "what state is this object in".
