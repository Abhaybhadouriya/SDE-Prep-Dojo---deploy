Remember this

  • A state diagram follows one object: rounded boxes are states, arrows are transitions labelled event [guard] / action.
  • Filled dot = start; bullseye = end; entry/, exit/, do/ run on entering, leaving, staying.
  • Events with no arrow are ignored or errors: decide and say which.
  • Code it as switch (tiny), transition table (many states, little logic) or State pattern (rich per-state behaviour).
  • The transition that races (assign driver, book seat) must be atomic: CAS in memory, conditional UPDATE in a database.
  • TCP's eleven states are the bridge: a table of (state, event) to next state is how C codes any state machine.
  • Activity diagrams follow a process: actions, decisions, fork/join for parallel work, swimlanes for who does what.
