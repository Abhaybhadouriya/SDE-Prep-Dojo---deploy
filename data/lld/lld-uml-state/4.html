From your world: the TCP state machine

From your world

You already know the most famous state diagram in computing: the TCP connection state machine in RFC 9293 (it replaced RFC 793). Eleven states, events that are either user calls (connect, listen, close) or segments arriving (SYN, ACK, FIN), and actions that send segments. In Linux the current state lives in sk->sk_state and moves through tcp_set_state(); ss -tan shows you each socket's state right now. Every protocol stack you have worked on (BGP's FSM, OSPF neighbour states, LACP, PPP) is a state diagram in code.

A C engineer codes this as a table: rows are states, columns are events, cells are the next state (and an action). That is the most direct translation of any state diagram, in any language. Our slice of it, lld-code/lld-uml-state/tcp_fsm.c:

struct transition { int valid; enum state next; };
static struct transition table[NSTATES][NEVENTS];

on(CLOSED,      E_ACTIVE_OPEN, SYN_SENT);
on(SYN_SENT,    E_RCV_SYNACK,  ESTABLISHED);
on(ESTABLISHED, E_CLOSE,       FIN_WAIT_1);
on(FIN_WAIT_2,  E_RCV_FIN,     TIME_WAIT);
/* ... 15 rows in all ... */

static void fire(struct conn *c, enum event e) {
    struct transition t = table[c->st][e];
    if (!t.valid) { printf("%s ignores %s\n", sname[c->st], ename[e]); return; }
    c->st = t.next;
}
$ gcc -std=c99 -Wall -Wextra -o tcp_fsm tcp_fsm.c && ./tcp_fsm
