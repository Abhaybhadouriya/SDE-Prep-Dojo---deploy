A subclass overrides add and addAll to count items; the base's addAll calls add. Adding 3 items with addAll counts...

  1. 3
  2. 6
  3. 0
The subclass counts 3 in addAll, then the base's loop calls the overridden add three times: 6.

Formats {JSON, CSV, Protobuf} × sinks {File, HTTP} × compression {none, gzip}. How many classes with pure inheritance, and how many parts with composition?

  1. 7 and 12
  2. 12 and 12
  3. 12 leaf subclasses vs 7 small part classes
3 × 2 × 2 = 12 combinations by inheritance; 3 + 2 + 2 = 7 parts by composition.

What can composition do that inheritance cannot?

  1. Change an object's behaviour at run time by swapping a part
  2. Let a subclass be used wherever the parent is expected
  3. Reuse code
An object's class is fixed; a held part can be replaced. Substitutability comes from inheritance or a shared interface.

Why is java.util.Stack extends Vector considered a design mistake?

  1. Vector is slow
  2. Stack inherits methods such as add(index, e) that break LIFO order
  3. Stack cannot hold null
Inheriting a general list's API lets callers break the stack's invariant. A stack should hold a list, not be one.

Which is a good reason to use inheritance?

  1. You want to reuse two helper methods from an unrelated library class
  2. Behaviour must change per request at run time
  3. The base class is designed for extension with documented hooks, and the subclass is a true is-a
Inheritance is right for stable is-a with bases built to be extended. The other two are composition cases.

In the kernel, switching a socket's TCP congestion algorithm with setsockopt(TCP_CONGESTION) is closest to...

  1. Composition with a swappable strategy (an ops pointer)
  2. Multiple inheritance
  3. Method overloading
The socket holds a pointer to tcp_congestion_ops; replacing it changes behaviour for that one object.
