Remember this

  • Inheritance = is-a, fixed at compile time, couples you to the parent's implementation. Composition = has-a plus delegation, chosen and swappable at run time.
  • Fragile base class: a parent's self-calls dispatch into your overrides; parent changes break children. Wrap and forward instead, or make classes final.
  • Class explosion: N independent axes give a product of subclasses. Extract each axis into an interface and compose: the count adds instead of multiplies.
  • Swappable part = Strategy; stacked wrappers = Decorator; two linked hierarchies = Bridge.
  • Refactor: add field, forward, drop extends, extract interface, inject.
  • Inheritance is still right for true is-a with bases designed for extension (frameworks, exceptions, skeletal classes).
  • Kernel habit to copy: embed stable data, point to swappable ops (tcp_congestion_ops, qdiscs).
