Class explosion, fixed by composition + Strategy

The second problem with inheritance appears when behaviour varies along more than one independent axis. Say a metrics exporter (you have written one for interface counters) can format as JSON or CSV, send to a file or over HTTP, and optionally compress. With inheritance you need one subclass per combination:

The fix below uses a Strategy: a small object behind an interface that does one varying step (format, send, compress). The owner holds one and can swap it, like setsockopt(TCP_CONGESTION) swapping the socket's tcp_congestion_ops. That is all the pattern name means; the full page is Strategy.

Composition adds instead of multiplying. Pull each axis out into its own small interface, and give the exporter one of each:

// ---- Part 2: class explosion ----
// Inheritance version: one subclass per combination of (format x sink x compression).
//   JsonFileExporter, JsonFileGzipExporter, JsonHttpExporter, JsonHttpGzipExporter,
//   CsvFileExporter,  CsvFileGzipExporter,  CsvHttpExporter,  CsvHttpGzipExporter  ... 2 x 2 x 2 = 8
//   Add Protobuf -> 12. Add a Kafka sink -> 18. Add zstd -> 27.

abstract class Exporter { abstract void export(String metric, double value); }
class JsonFileExporter extends Exporter { /* format JSON, write to file */ }
class JsonFileGzipExporter extends JsonFileExporter { /* ...and compress */ }
class CsvHttpExporter extends Exporter { /* duplicate of half of the above */ }
// ...and five more
// Composition version: three small interfaces, one class that HAS one of each.
interface Formatter  { String format(String metric, double value); }
interface Sink       { void write(String payload); }
interface Compressor { String compress(String payload); }

static final class JsonFormatter implements Formatter {
    public String format(String m, double v) { return "{\"" + m + "\":" + v + "}"; }
}
static final class CsvFormatter implements Formatter {
    public String format(String m, double v) { return m + "," + v; }
}
static final class ConsoleSink implements Sink {          // stands in for a file
    private final String name;
    ConsoleSink(String name) { this.name = name; }
    public void write(String p) { System.out.println("  [" + name + "] " + p); }
}
static final class NoCompression implements Compressor { public String compress(String p) { return p; } }
static final class FakeGzip implements Compressor {        // demo only: marks the payload
    public String compress(String p) { return "gz(" + p.length() + " bytes)"; }
}

static final class MetricsExporter {
    private Formatter formatter;
    private Sink sink;
    private final Compressor compressor;

    MetricsExporter(Formatter f, Sink s, Compressor c) { formatter = f; sink = s; compressor = c; }

    void export(String metric, double value) {               // delegation: each part does one job
        sink.write(compressor.compress(formatter.format(metric, value)));
    }
    void setSink(Sink s) { this.sink = s; }                  // swap behaviour at RUN time
    void setFormatter(Formatter f) { this.formatter = f; }
}
"""Composition over inheritance in Python: parts passed in, behaviour swapped at run time.
Run:  python composition.py
"""
import json
from dataclasses import dataclass
from typing import Callable, Protocol


class Formatter(Protocol):
    def format(self, metric: str, value: float) -> str: ...


class JsonFormatter:
    def format(self, metric, value):
        return json.dumps({metric: value})


class CsvFormatter:
    def format(self, metric, value):
        return f"{metric},{value}"


@dataclass
class MetricsExporter:
    formatter: Formatter                       # has-a formatter
    sink: Callable[[str], None]                # has-a sink (any callable)
    compress: Callable[[str], str] = lambda p: p   # has-a compressor, default: none

    def export(self, metric: str, value: float) -> None:
        self.sink(self.compress(self.formatter.format(metric, value)))


if __name__ == "__main__":
    ex = MetricsExporter(JsonFormatter(), lambda p: print("  [file]", p))
    ex.export("rx_drops", 3)
    ex.formatter = CsvFormatter()              # swap a part at run time
    ex.export("rx_drops", 4)
    MetricsExporter(JsonFormatter(), lambda p: print("  [http]", p),
                    compress=lambda p: f"gz({len(p)} bytes)").export("tx_errs", 1)
2. Composition: 2 formats x 2 sinks x 2 compressors from 6 small classes
  [file] {"rx_drops":3.0}
  [http] rx_drops,4.0
  [http] gz(15 bytes)
3. A lambda is a composed part too:
  [stdout] LINK_FLAPS,2.0

Look at what composition bought:

  • Runtime change: setSink and setFormatter switch behaviour on a live object. An object's class can never change.
  • Independent testing: each part is a few lines with one job; you can test CsvFormatter without a sink.
  • Additive growth: a Kafka sink is one class. With inheritance it was a new branch under every format.
  • Lambdas as parts: when an interface has one method, a lambda or method reference is a valid part (step 3 in the output).

Each swappable part is the Strategy pattern (one varying step behind an interface). When the parts should stack (compress, then encrypt, then sign) you wrap them, which is Decorator. When two whole hierarchies vary independently (shapes and renderers, devices and remotes), splitting them and linking by composition is Bridge.
