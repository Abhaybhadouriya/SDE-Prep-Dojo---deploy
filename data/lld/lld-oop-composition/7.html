Interview questions

What does "favor composition over inheritance" mean?

Build behaviour by having objects hold other objects behind interfaces (has-a) and delegate to them, rather than by extending classes (is-a). Composition keeps classes small, lets parts vary independently and change at run time, and avoids coupling to a parent's internals. Inheritance remains right for true, stable is-a relationships with bases designed for extension.

How to answer

Define both in one line each, give one concrete benefit with an example (Car has an Engine interface; swap Petrol for Electric), then the balanced "when inheritance is fine" sentence.

Likely follow-ups
  • Which patterns rely on composition?
  • What is delegation?
What is the fragile base class problem? Show an example.

A subclass depends on implementation details of its parent, so a change inside the parent breaks the subclass. Classic case: the parent's addAll calls add; a subclass overrides both to count items and counts each item twice. If the parent later stops calling add, a subclass that only overrode add counts nothing. Fix: wrap and forward instead of extending, or make classes not designed for extension final.

How to answer

Write the two small classes, state the wrong output (6 for 3 items), explain dynamic dispatch of the self-call, then show the wrapper.

Likely follow-ups
  • How should a class designed for inheritance document itself? (State which overridable methods it calls internally, or avoid self-use.)
  • Why does the wrapper not have the problem?
Your design has a subclass for every combination of options. How do you fix it?

Identify the independent axes of variation, extract each into an interface (Formatter, Sink, Compressor), and have the main class hold one of each. Combinations are made at construction time, the class count grows by addition rather than multiplication, and parts can change at run time. Each extracted axis is a Strategy; stacking behaviours uses Decorator; two whole hierarchies linked together is Bridge.

How to answer

Do the arithmetic aloud (2×2×2 = 8 versus 6 parts), draw the composed UML, and show one constructor call.

Likely follow-ups
  • Who builds the right combination? (A factory or builder reading config.)
  • How do you make sure invalid combinations are rejected?
Is java.util.Stack a good use of inheritance?

No. Stack extends Vector, so it inherits methods like add(int, E) and remove(int) that let callers bypass last-in-first-out order. A stack has storage; it is not a general list. The JDK documentation recommends Deque implementations such as ArrayDeque instead. A composed stack would hold a list privately and expose only push, pop and peek.

How to answer

Name the inherited method that breaks the invariant, connect it to Liskov, and sketch the composed alternative in three lines.

Likely follow-ups
  • Another JDK example? (Properties extends Hashtable allows non-String entries.)
What are the downsides of composition?

More objects to create and wire; extra indirection when reading code; forwarding boilerplate in wrappers; and a wrapper is not automatically a subtype of what it wraps, so you need a shared interface. Identity-based code (==, callbacks that pass this) can also see the inner object instead of the wrapper, which Bloch calls the "self problem".

How to answer

List two or three costs and say how you handle each (constructor injection, small interfaces, generated delegates).

Likely follow-ups
  • When would you choose inheritance anyway?
What is the difference between composition, aggregation and association?

All three are "uses or holds" links. Association: two classes know about each other (a Driver and a Car). Aggregation: a weak has-a; the part can exist without the whole (a Team and its Players; hollow diamond). Composition: a strong has-a; the part's lifetime is owned by the whole (an Order and its OrderLines; filled diamond). In "composition over inheritance" the word is used loosely for any has-a with delegation.

How to answer

Give one example per kind and the UML symbol. Point to lifetime as the deciding question.

Likely follow-ups
  • How does each look in code? (Composition: the whole creates or exclusively owns the part.)
