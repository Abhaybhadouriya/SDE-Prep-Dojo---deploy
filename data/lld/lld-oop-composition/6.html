The Walmart question

A Walmart SDE-3 candidate reported a round named "LLD" that was really scenario questions on Java and Spring, including: why do we need inheritance when we can achieve this with composition? (LeetCode Discuss, Oct 2024). The candidate was not selected. Here is how to handle it.

Scenario: "Why inheritance at all, if composition can do everything?"

The interviewer pushes: "You keep saying prefer composition. Then why does Java even have extends?"
"Inheritance is bad and should be avoided." (One-sided; the interviewer will ask about exceptions, frameworks or AbstractList next, and you have nothing.)
"They solve different problems. Inheritance gives two things at once: code reuse and a subtype relationship, so a subclass can be passed wherever the parent is expected and the framework can call its hooks. That is right for a true is-a with a base designed for extension: exception hierarchies, template-method frameworks, skeletal classes like AbstractList. Composition gives reuse without the subtype and without coupling to the parent's internals, so it is better when I only want reuse, when behaviour varies on several axes, or must change at run time. For substitutability with composition I add an interface. So my default is interface + composition, and I use inheritance deliberately, with final on classes not designed for it."
Follow-ups: "Show me a fragile base class bug" (the addAll double count). "Which design patterns are built on composition?" (Strategy, Decorator, Bridge, Composite, State.) "How does Spring wire composed parts?" (constructor injection of interfaces; see Dependency Injection).
