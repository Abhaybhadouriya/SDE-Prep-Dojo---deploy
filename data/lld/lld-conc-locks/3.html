synchronized: the lock built into every object

Every Java object has a hidden lock called its monitor (or intrinsic lock). The synchronized keyword takes it on entry and releases it on exit, including when an exception is thrown. You cannot forget the unlock, which is why it is the right default.

class Counter {
    private int value;

    public synchronized void inc() { value++; }        // locks "this"
    public synchronized int get()  { return value; }   // reads need the lock too

    private final Object lock = new Object();           // or: a private lock object
    public void reset() {
        synchronized (lock) { /* ... */ }               // block form, locks "lock"
    }
}

A monitor has two waiting areas. The entry set holds threads that want the lock. The wait set holds threads that already had the lock, called wait(), gave the lock up and are sleeping until someone calls notify() or notifyAll().

Three facts interviewers check:

  • Reentrant. A thread that holds the monitor can enter another synchronized method on the same object without blocking itself. The JVM keeps a hold count.
  • What is locked. An instance method locks this. A static synchronized method locks the Class object. They are two different locks, so a static and an instance method do not exclude each other.
  • Private lock objects are safer. If you lock this, any outside code can also lock your object and block you. A private final Object lock cannot be touched from outside.
