The story: the key, the tokens and the waiting room

Explain like I'm 5

A small cafe has one bathroom with one key hanging by the counter. Whoever holds the key goes in. Everyone else waits. When you come out you hang the key back. That key is a lock (also called a mutex, short for "mutual exclusion": only one person at a time).

The cafe also has three tables. The waiter keeps three wooden tokens. You take a token to sit down and give it back when you leave. When the tokens run out, the next family waits at the door. Tokens that let a few people in at once are a semaphore.

Sometimes you have the key but cannot use it yet: the bathroom has no soap. You do not stand inside holding the key forever. You hang the key back, sit in the waiting room, and ask the cleaner to tap your shoulder when the soap is refilled. That waiting room is a condition.

And on the first day, the owner says "nobody opens until all four cooks have arrived". She counts down 4, 3, 2, 1 and then opens the door. That counter is a latch.

A program with many threads has the same problems. Several threads want to change the same object. Some must wait until something becomes true. Some resources only allow a few users at once. Some work must not start until other work is done. This page gives you a tool for each, in Java first, then C++ and Python.

From your world

You already know all of these from the kernel. spin_lock() and struct mutex are locks. wait_event() / wake_up() on a wait_queue_head_t is a condition. struct semaphore with down() / up() is a counting semaphore. struct completion with wait_for_completion() / complete() is a latch of size one. Java's names are different, the ideas are exactly the same, and the bugs (forgetting to unlock on an error path, sleeping while holding a spinlock, checking a condition with if instead of a loop) are the same bugs you already know.
