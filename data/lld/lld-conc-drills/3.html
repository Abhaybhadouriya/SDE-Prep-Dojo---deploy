Drill 2: a thread-safe token-bucket rate limiter

A token bucket holds up to capacity tokens and gains rate tokens per second. Each request takes one token; with no token, it is rejected. Capacity sets the allowed burst; rate sets the long-term average. The full design with other algorithms is the distributed rate limiter; here we focus on making one in-process limiter correct under threads.

synchronized boolean tryAcquire() {             // refill + check + take = one atomic step
    long now = clock.getAsLong();
    tokens = Math.min(capacity, tokens + (now - last) * refillPerNano);   // lazy refill
    last = now;
    if (tokens >= 1) { tokens -= 1; return true; }
    return false;
}
  • Why the whole method is one critical section: tokens and last form one invariant. If refill and take were separate, two threads could both see 1 token and both take it, letting 11 requests through a limit of 10. The drill fires 800 concurrent requests at a full bucket of 10 and gets exactly 10.
  • Lazy refill: no timer thread per bucket (a million users would mean a million timers). Elapsed time times rate gives the refill on demand. This is also how the kernel's TBF and most libraries work.
  • Inject the clock: LongSupplier for nanoseconds. Tests set time to 0, then 1 s, and check exactly 5 tokens came back. Never test rate limiters with Thread.sleep. Use System.nanoTime() (monotonic) in production, not wall-clock time that can jump.
  • Bucket creation: computeIfAbsent creates exactly one bucket per key even under a race. A get then put could create two buckets and double the user's limit.
  • Memory: buckets for idle users pile up. Evict buckets that are full and idle (a full bucket is the same as a new one, so dropping it changes nothing), for example with a periodic sweep or an expiring cache as the map.
  • Lock-free variant: pack (tokens, last) into one immutable object in an AtomicReference and CAS-loop. It avoids blocking but retries under contention; the per-bucket lock is simpler and usually fast enough.

From your world

The tbf qdisc's rate and burst are exactly ratePerSec and capacity here, and __ratelimit() (behind printk_ratelimited()) is a simple interval-plus-burst limiter protected by its own spinlock. A per-key bucket map is the same idea as a per-flow policer.
