Shallow copy vs deep copy

A shallow copy copies the object's fields one by one. If a field is a number, the copy gets its own number. If a field is a reference (pointer) to another object, the copy gets a copy of the reference, so both objects now point at the same inner object. A deep copy also copies the inner objects, recursively, so the two copies share nothing that can change.

static class RouteTable {
    final String vrf;
    final List<String> routes;
    RouteTable(String vrf, List<String> routes) { this.vrf = vrf; this.routes = routes; }
    RouteTable shallowCopy() { return new RouteTable(vrf, routes); }                 // shares the list
    RouteTable deepCopy()    { return new RouteTable(vrf, new ArrayList<>(routes)); } // own list
}
4) shallow vs deep copy:
  original [10.0.0.0/8, 192.168.0.0/16]
  shallow  [10.0.0.0/8, 192.168.0.0/16]  <- changed too (same list)
  deep     [10.0.0.0/8]  <- unchanged

"Deep" only needs to go as deep as the mutable parts. Immutable things (Java String, Integer, records of immutable fields, Python tuples of ints) can be shared safely; that is one big reason immutable objects are so pleasant (see immutability and safe publication).

Copying in each language

  • Java: assignment b = a copies the reference only (no new object). Object.clone() exists but is widely seen as broken: it needs the Cloneable marker interface, it is shallow by default, it bypasses constructors and does not work with final fields that need fresh values. Prefer a copy constructor (new Port(other)) or a static copy factory (Port.copyOf(other)). For collections: new ArrayList<>(list) (shallow copy of the list), List.copyOf(list) (immutable copy).
  • C++: assignment and pass-by-value really do copy, by calling the copy constructor / copy assignment. The compiler-generated ones copy member by member, which is shallow for raw pointers. That is the source of the next section.
  • Python: assignment binds a second name to the same object. copy.copy(x) is shallow, copy.deepcopy(x) is deep; a class can customise them with __copy__ / __deepcopy__.

From your world

skb_clone() vs skb_copy() is exactly this choice. A clone gets its own struct sk_buff header but shares the packet data (refcounted), which is cheap and fine as long as nobody writes to the data. skb_copy() duplicates header and data so you may modify it. pskb_expand_head() / "copy before write" is the kernel deciding when a shallow copy must become deep. Same trade-off: speed and memory vs safety under mutation.
