Interview questions

Lifecycle questions show up as quick OOP warm-ups (Walmart and Microsoft Java/C++ rounds often open with them) and as follow-ups in machine coding ("your Order holds a list - what happens when someone copies it?"). Public OOP question lists such as this LeetCode Discuss collection repeat the same core set.

What is a constructor, and can it be private? Why would you do that?

A constructor is the code that runs at creation and leaves the object in a valid state; it has no return type and is not inherited. Yes, it can be private. Then only the class itself can create instances, which you use for: static factories with validation or caching (Vlan.of(100)), Singleton, a Builder that calls the private constructor, and utility classes that should never be instantiated.

How to answer

Definition in one line, then list two or three concrete uses of a private constructor with a short example. Mention that Java's enum constructors are implicitly private.

Likely follow-ups
  • Can a constructor be final, static or abstract? (No - none of those make sense for something that is not inherited or overridden.)
  • How do you stop reflection from calling a private constructor in a Singleton? (Throw if an instance exists, or use an enum.)
Does Java have destructors? How do you release a file or socket deterministically?

No destructors. Memory is reclaimed by the GC at an unspecified time. For non-memory resources, the class implements AutoCloseable and callers use try-with-resources, which closes in reverse order on every exit path and records close failures as suppressed exceptions. finalize() is deprecated for removal (JEP 421); Cleaner may be used only as a safety net for callers who forget to close.

How to answer

Separate memory from resources. Contrast with C++ RAII where the destructor runs at scope exit. Show the try-with-resources syntax.

Likely follow-ups
  • What happens if both the body and close() throw? (Body's exception is thrown; close's is in getSuppressed().)
  • What is the difference between Closeable and AutoCloseable? (Closeable is the older I/O sub-interface, throws IOException and should be idempotent.)
Explain shallow vs deep copy. How do you copy an object correctly in Java?

Shallow copy duplicates fields, so reference fields still point at the same inner objects; deep copy duplicates the inner mutable objects too. In Java, prefer a copy constructor or static copy factory that explicitly copies mutable fields (new ArrayList<>(routes)) and shares immutable ones. Avoid clone(): it is shallow by default, needs Cloneable, skips constructors and fights final fields.

How to answer

Draw the two-boxes-one-list picture. Then say "deep only as far as the mutable state" and mention immutability as the way to make copying unnecessary.

Likely follow-ups
  • How do you deep copy a graph with cycles? (Keep an identity map from original to copy - Python's deepcopy does this with its memo dict.)
  • Where is this asked in design? (Prototype pattern, defensive copies in getters.)
What is the rule of three / five / zero in C++?

If a class needs a user-written destructor, copy constructor or copy assignment, it needs all three (rule of three), because it owns a resource the memberwise defaults mishandle (double free, leak). Since C++11 add move constructor and move assignment (rule of five); declaring any of the others suppresses the implicit moves. The rule of zero says most classes should define none and hold resources in RAII members like vector and unique_ptr.

How to answer

Start from the bug (raw pointer + default copy = double free), then the three rules as the fix in increasing order of preference.

Likely follow-ups
  • Why should the destructor of a base class be virtual? (Deleting a derived object through a base pointer otherwise skips the derived destructor - see polymorphism.)
  • What is copy-and-swap and why is it exception safe?
  • What state is a moved-from object in? (Valid but unspecified; it must be destructible and assignable.)
A constructor needs to open a connection and that can fail. How do you design it?

Either the constructor throws (and the object never exists), or you move the risky work into a static factory that returns the object or an error, keeping the constructor trivial. Do not leave a "half-constructed" object with an init() that callers may forget. If the constructor acquires several resources, acquire them through RAII members (C++) or release them in a catch before rethrowing (Java), because the destructor / close of a half-built object does not run.

How to answer

Name the two clean options (throw, or factory returning a result), name the anti-pattern (two-phase init), and mention cleanup of partially acquired resources.

Likely follow-ups
  • Should constructors do I/O at all? (Prefer injecting an already-open dependency - easier to test; see dependency injection.)
In what order are fields, the parent constructor and the constructor body executed in Java?

Memory is zeroed; the constructor's first statement runs this(...) or super(...); the parent chain is built top-down; then this class's instance field initializers and instance initializer blocks run in source order; then the rest of the constructor body. Static initializers ran earlier, once, when the class was first loaded and initialised.

How to answer

Give the order as a numbered list and mention the trap: an overridable method called from the parent constructor sees the child's fields still at zero.

Likely follow-ups
  • Order with static blocks across parent and child? (Parent static, child static, then per object: parent instance init + ctor, child instance init + ctor.)
