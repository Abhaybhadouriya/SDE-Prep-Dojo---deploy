What actually runs when you write new Port(1)

Interviewers like to ask "in what order do things happen?" because it shows whether you know the language or just its syntax. Here is the Java order for our Port, which extends a tiny Base class. Click through it.

  1. new asks the JVM for memory. Every field starts at its zero value (0, false, null). In C you would call kzalloc().
  2. The one-argument constructor does nothing itself except call this(number, "eth"+number, 1500). Delegation must be the first statement.
  3. The full constructor's first action is super() (written or implied). The parent is always built before the child: Base() body prints first.
  4. Only after super() returns do the field initializers run (mtu = 1500), in the order they appear in the source. They run once, in the constructor that called super().
  5. Finally the constructor body: validate the arguments, assign the fields. If it throws here, nobody ever receives the half-built object.
  6. The caller gets the reference. From now on the object must satisfy all its invariants.

Real output from our sample (lld-code/lld-oop-lifecycle/Lifecycle.java, Java 21):

$ javac -d . Lifecycle.java && java -cp . Lifecycle
1) new Port(1):
  Base() body
  Port field initializer: mtu = 1500
  Port(int,String,int) body: eth1(#1, mtu=1500)

C++ follows the same spirit with one firm rule worth remembering: members are initialised in the order they are declared in the class, not the order you list them in the initializer list. If len_ is declared after data_ but you write : len_(n), data_(new char[len_]), then data_ is built first from a garbage len_. Compilers warn with -Wreorder; read the warning.
