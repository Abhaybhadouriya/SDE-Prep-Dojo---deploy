Constructors: making an object valid from line one

A constructor is a special method that runs when an object is created. It has the same name as the class (Java, C++) or is called __init__ (Python), and it has no return type. Its one job: leave the object in a valid state. After the constructor returns, every rule the class promises (its invariants, for example "port number is never negative") must already be true. If the arguments make that impossible, the constructor should throw, so nobody ever holds a broken object.

Python has only one __init__ per class (no overloading), so "alternate constructors" are written as @classmethod factories such as Port.from_config(line). That is the same idea as a Java static factory.

Chaining keeps the rules in one place

The most common junior mistake is copying the same validation into three constructors. Then someone fixes one of them and forgets the others. Instead, write one full constructor that checks everything, and let the short ones delegate to it.

class Port {
    int number; String name; int mtu;
    Port(int number) {
        this.number = number;          // no check here...
        this.name = "eth" + number;
        this.mtu = 1500;
    }
    Port(int number, String name, int mtu) {
        if (number < 0) throw new IllegalArgumentException();   // ...only here
        this.number = number; this.name = name; this.mtu = mtu;
    }
}
class Port {
    private final int number;
    private final String name;
    private int mtu = 1500;

    Port(int number, String name, int mtu) {    // the ONE place with the rules
        if (number < 0) throw new IllegalArgumentException("port number < 0");
        this.number = number;
        this.name = name;
        this.mtu = mtu;
    }
    Port(int number)     { this(number, "eth" + number, 1500); }   // delegate
    Port(Port other)     { this(other.number, other.name, other.mtu); } // copy constructor
}
class Port {
public:
    Port(int number, std::string name, int mtu)
        : number_(number), name_(std::move(name)), mtu_(mtu) {   // member initializer list
        if (number_ < 0) throw std::invalid_argument("port number < 0");
    }
    explicit Port(int number) : Port(number, "eth" + std::to_string(number), 1500) {}
private:
    int number_;
    std::string name_;
    int mtu_;
};
class Port:
    def __init__(self, number: int, name: str | None = None, mtu: int = 1500):
        if number < 0:
            raise ValueError("port number < 0")
        self.number, self.name, self.mtu = number, name or f"eth{number}", mtu

    @classmethod
    def from_config(cls, line: str) -> "Port":      # alternate constructor
        num, name, mtu = line.split(",")
        return cls(int(num), name, int(mtu))

In C++, mark single-argument constructors explicit. Without it, Port p = 7; compiles silently by converting the integer into a port. In C++, also prefer the member initializer list (: number_(number)) over assigning in the body: const members and references can only be set there, and members are built once instead of default-built then overwritten.

Private constructor + static factory

Sometimes a plain new is too open. A VLAN id must be 1 to 4094; you might want to cache common objects; you might want a clear name like Vlan.of(100) or Money.ofCents(250). Make the constructor private and expose a static method. This is the seed of the Simple Factory, Builder and Singleton patterns.

static final class Vlan {
    private final int id;
    private Vlan(int id) { this.id = id; }
    static Vlan of(int id) {
        if (id < 1 || id > 4094) throw new IllegalArgumentException("VLAN id must be 1..4094, got " + id);
        return new Vlan(id);
    }
}

Do not call overridable methods from a constructor. In Java, if Base() calls init() and a subclass overrides init(), the subclass version runs before the subclass fields are set and sees zeros and nulls. (C++ is the opposite: during Base() the object is still "a Base", so the base version runs.) Both behaviours surprise people; the safe rule is "no virtual calls in constructors".
