Interview follow-ups

How do you prevent duplicate votes, and what if the same user clicks twice at the same instant?

Votes are a map from voter id to vote type on each post, so a user has at most one entry. The check and the write happen under the post's lock, so two simultaneous clicks serialise and the second finds the vote already there. In a database the same guarantee is a unique key on (post_id, voter_id) and an upsert.

How to answer

Data structure first (map, not counter), then the lock, then the DB constraint.

Your feedback says "modular but not extensible". Show me how a new rule gets added.

Write a class that implements PermissionRule, for example NoActionsOnClosedQuestions, and add it to the list passed to the constructor. QaService does not change. The same for points (a new ReputationPolicy) and feed rules (a new Predicate). Extensible means the change lands in new code, not in edits to the core.

Why do Question and Answer share a base class? Would composition be better?

They are both "a post that can be voted and commented on", with the same invariants, so inheritance from an abstract Post is natural and lets vote() take any post. If later comments also become votable, a composed Votes component (map plus lock) that Post, Comment and others own would be cleaner. Both answers are fine if you give the reason.

Reputation uses an atomic, votes use a lock. Why the difference?

A vote is a compound action: read the old vote, write the new one, apply two deltas. That needs mutual exclusion. Reputation is one integer changed by votes on many posts; an atomic add is enough and avoids taking a user lock while holding a post lock, which would need a lock order to avoid deadlock.

The asker accepts A1, then changes to A2. What happens to reputation?

A1's author loses the 15, A2's author gains 15, and the asker keeps one +2 (it is not paid twice). If either answer is the asker's own, no points move for that side. All of it runs under the question's lock so two concurrent accepts cannot both pay.

How does keyword search work, and how would you make it better?

An inverted index maps each lowercased word of a title and body to the set of question ids; a query intersects the sets of its words (AND), then sorts by score and recency. Better: store term frequencies and rank by TF-IDF or BM25, add stemming, index tags separately, and at scale use a search engine fed by an event stream.

Feed filters: what if they ask for "java AND unanswered AND asked this week"?

Each filter is a Predicate<Question> (Specification pattern), so combinations are and / or / negate calls, and "asked this week" is one more small predicate. No new service method per combination.

How would you implement the 200-per-day reputation cap?

A decorator around ReputationPolicy or around the reputation update: keep per-user, per-day totals of vote-based gains; clip a positive delta to what remains under 200. Accepts and bounties are exempt (they are not vote-based). Reversals must reverse only what was actually granted, so store the granted amount per vote.

Who gets notified and how do you keep notifications from slowing down votes?

On a new answer: the asker and earlier answerers (followers), not the author. On accept: the answerer. On comment: the post author. Events are collected while the state changes and listeners are called after locks are released; a production listener would push to a queue for a notification service.

Store this in a database. What tables and what changes in the code?

users, posts (id, type, parent_id, author_id, body, title, accepted_answer_id, score), tags and post_tags, votes (post_id, voter_id, type, unique on the pair), comments, subscriptions. A vote is one transaction: upsert the vote row, update the cached score, update reputations. The service keeps its rules; storage moves behind repositories.
