From your world

The permission rules are LSM hooks: before an operation, the core calls every registered hook, and any one may return -EPERM. SELinux and AppArmor plug in without the VFS knowing which is loaded. Here TopicSubscriptionRule and ReputationPrivileges plug in without QaService knowing which site it is.

Reputation is derived from events, so make every event reversible

Each vote applies two deltas: one to the post's author and one to the voter. Changing a vote is "apply the old vote with sign -1, then the new vote with sign +1". Retracting is just the first half. Because the same applyVote(voter, post, type, sign) does all three, reversals can never drift from the original amounts. Moving an accept works the same way: take the +15 back from the old answerer, give it to the new one, and pay the acceptor's +2 only once, and only when the accepted answer is not their own.

One honest wrinkle: reputation is floored at 1. If a user at 1 gets a -2 and later that downvote is retracted, they end at 3, not 1. Stack Overflow has the same effect. Mention it; if exact reversal matters, store an event log and recompute instead of applying deltas.
