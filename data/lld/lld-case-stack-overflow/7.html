As a REST API this maps to POST /questions, POST /questions/{id}/answers, PUT /posts/{id}/vote (idempotent: the body is the desired vote), DELETE /posts/{id}/vote, POST /answers/{id}/accept, GET /feed?topic=java&answered=false. See API design for LLD.

Cost of each operation

OperationCostNote
askO(W)W = words in title and body, each added to the inverted index.
answer, commentO(F)F = followers to notify (after the lock).
vote, retractVote, acceptO(R + log V)R permission rules, one map update in the post's V votes, two atomic reputation updates.
feed(user, filter)O(Q log Q)Filter all Q questions, then sort newest first. For "top 20" keep a TreeSet (or a heap of size k) ordered by time, and the feed becomes O(k log Q) or O(Q log k).
search(text)O(sum of posting lists + m log m)Intersect the id sets of each word, then sort the m hits by score. Real engines keep posting lists sorted to intersect in one merge pass.
score()O(V)Counted from the votes map on demand; keep a running counter if feeds sort by score often.
