Real-world uses

  • Regular expressions: java.util.regex.Pattern.compile and Python's re parse the pattern text into an internal node structure that is then matched against input.
  • Expression languages: Spring Expression Language (SpEL) parses strings like #user.age >= 18 into an AST and evaluates them against a context object; rule engines and feature-flag targeting rules work the same way.
  • Python's own ast: ast.parse turns source into the same kind of tree; the CPython compiler then turns it into bytecode rather than walking it.
  • Packet filters: libpcap expressions compiled to classic BPF; netfilter match expressions; seccomp filters (classic BPF over syscall data).
  • Query filters: search syntax like status:open AND label:bug in issue trackers, and SQL WHERE clauses inside small embedded databases.

From your world

The kernel shows the whole spectrum. A GoF tree-walker is the simplest form. Classic BPF is a register machine with a tiny instruction set: the "tree" has been flattened into jumps (jt/jf targets). eBPF adds a verifier and a JIT so the "interpreter" mostly disappears into native code. In an interview, saying "a tree-walking interpreter is fine for config rules; for per-packet hot paths you compile, as BPF does" shows you know when the pattern stops scaling.
