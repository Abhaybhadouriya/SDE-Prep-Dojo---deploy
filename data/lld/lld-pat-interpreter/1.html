The problem: rules that change every week

Marketing wants "show the banner to users who are 18 or older and are in Bangalore or are VIP, and are not blocked". Next week they want a different rule. Hard-coding each rule means a deploy per campaign:

boolean showBanner(User u) {
    return u.age() >= 18 && (u.city().equals("BLR") || u.vip()) && !u.blocked();
}
// next week: showBannerV2, then showBannerDiwali, then ... each one a code change and a release

What you want is for the rule to be data: a string stored in a config table, written by a non-developer, checked and evaluated at runtime. To evaluate a string you need two things: a parser that turns text into structure, and something that evaluates the structure. The Interpreter pattern is a clean answer for the second part.
