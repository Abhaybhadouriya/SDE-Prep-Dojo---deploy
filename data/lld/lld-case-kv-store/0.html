The story: the locker room with sticky notes

Explain like I'm 5

A school has a wall of lockers. Each locker has a name on it and something inside. Some lockers have a sticky note: "empty this at 3 o'clock". The caretaker does not stand at every locker waiting for 3 o'clock. Instead, whenever a child opens a locker, she glances at the note: if it is past 3, the locker counts as empty. And every few minutes she walks to her list of notes, sorted by time, and empties the lockers whose time has come.

Sometimes a teacher wants to try something: "Let's move these books around, but if it goes wrong, put everything back." So she writes her changes on a tracing sheet laid over the wall plan instead of touching the lockers. If she likes it, the caretaker copies the sheet onto the real lockers in one go. If not, she throws the sheet away. She can even put a second tracing sheet on top of the first.

From your world

Transaction layers are overlayfs: an upper directory over a lower one, reads fall through, and a delete in the upper layer is a whiteout file that hides the lower entry. Our tombstone is exactly a whiteout. TTL expiry is the neighbour (ARP) table or conntrack: entries carry a timestamp, a lookup of a stale entry treats it as gone, and a garbage collector sweeps in the background.

Interfaces in C terms: every interface on this page is, in C, a struct of function pointers; each implementation fills one in, like file_operations. Java and C++ build that table (the vtable) for you, and every object carries a pointer to it. More in OOP from C structs and polymorphism and vtables.
