Reading Java as a C programmer

The LLD pages use Java 21 for most code. The design ideas are the ones above; what trips a C reader is a handful of syntax pieces with no C spelling. Keep this table open during the first week. Each row gives the Java form, what it means, and the nearest thing you already know.

JavaWhat it meansNearest C / kernel idea
List<Ticket>, Map<K, V> (generics)A container whose element type the compiler checksA list_head container where the compiler knows what container_of would return
x -> expr, (a, b) -> { ... } (lambda)An anonymous function written inlinePassing a function pointer plus the context it captured (the usual void *data argument)
Type::method (method reference)A reference to an existing method, used like a lambdaA function pointer to a named function: .open = ring_open
final fieldSet once, in the constructor, never changed afterA field that is const after init
record Interval(int start, int end)An immutable struct; constructor, getters, equals, hashCode and toString are generatedA const struct with its compare function written for you
synchronized methodTakes this object's lock for the whole method and releases it on return or exceptionA mutex embedded in each struct: mutex_lock(&obj->lock); ... mutex_unlock(&obj->lock);
List.of(a, b), Map.of(...)An immutable list or map literal; add throwsA static const array initialiser
@OverrideCompiler check that this method really fills a slot from the parent class or interfaceA designated initialiser .xmit = ... that fails to compile if the slot name is wrong
var x = ...The compiler infers the local variable's typeGNU C __auto_type, C++ auto
Optional<T>A value that may be absent, stated in the return typeReturning NULL or ERR_PTR(-ENOENT), except the caller cannot forget to check
