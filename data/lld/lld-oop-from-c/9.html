What Java and C++ add over C (and what they cost)

ConcernC (you enforce it)Java / C++ (the compiler or runtime enforces it)
Filling every slotMissing slot = NULL; crash or a caller-side NULL checkA class that misses an abstract method does not compile (unless it is itself abstract)
Type of thiscontainer_of trusts youAlways correct; checked casts when you downcast
Hiding internalsstatic in a .c file, opaque struct in the headerprivate, protected, package-private (Java), friend (C++)
InitialisationRemember to set ops, init locks and krefConstructor runs on every creation; final fields must be set
Cleanupgoto out ladders, release callbacksC++ destructors (RAII); Java GC + try-with-resources
Generic containerslist_head + container_of, macrosGenerics / templates: List<Ticket> is type-checked
ErrorsNegative errno returns, ERR_PTRExceptions (plus return values where they fit)

The costs are real but small for LLD: an object header per instance in Java (the JVM stores class and lock information there), garbage-collection pauses that kernel code cannot afford, and less control over layout. None of these matter in an interview design; they matter when someone asks "why is the kernel not written in Java?". The honest answer: no garbage collector in interrupt context, predictable layout for hardware, and decades of C. (The kernel now accepts Rust for some drivers, which keeps manual layout control and adds compile-time ownership checks.)

Other translation traps

  • Public fields everywhere. C structs are open; a Java class should keep fields private and expose operations (account.withdraw(50), not account.balance -= 50). See Encapsulation.
  • Deep inheritance trees. The kernel embeds one level, sometimes two. Keep it that way: prefer an interface plus composition. See Composition over Inheritance.
  • Global state. A file-scope static table becomes a Singleton by reflex. Usually it should be a normal object passed in through the constructor (Dependency Injection), which also makes it testable.
  • Utility classes full of static methods. A "class" that is just a namespace of functions is C in disguise. Ask which object should own each method; GRASP gives rules for that.
