file_operations and net_device_ops are interfaces

An interface is a named list of operations with no data and (mostly) no code. A class implements an interface by providing every operation. In class diagrams (UML, covered on Class Diagrams) a class is a box with three compartments: the name, the fields, and the methods. An interface is marked <<interface>>, and "implements" is a dashed line with a hollow triangle pointing at the interface.

The kernel has dozens of these tables, and they map cleanly to interview vocabulary:

Why is file_operations a Bridge but net_device_ops a Strategy? With file_operations two whole hierarchies grow on their own: the VFS side (new syscalls, page cache, splice) and the filesystem side (ext4, xfs, procfs). The pointer joins them, and either side can change without the other. With net_device_ops the stack is one fixed caller and the driver is just the swappable "how to transmit" step. In C the two shapes look the same; the difference is how many sides vary. You meet all four patterns properly in the patterns week; Patterns in the Linux kernel collects the kernel examples in one place.

Interviewers love a concrete example when they ask "where have you used interfaces?". "In the kernel, a net_device_ops table is an interface: the stack calls ndo_start_xmit without knowing the NIC, and each driver is an implementation" is a better answer than a textbook Shape/Circle story, because you lived it.
