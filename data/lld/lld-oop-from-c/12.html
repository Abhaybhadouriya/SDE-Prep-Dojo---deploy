In C++ terms, what is the ops pointer inside struct net_dev?

  1. A template parameter
  2. A friend function
  3. The vptr: a pointer to the class's vtable
  4. A static member
Each object carries one pointer to its type's shared table of functions. C++ generates exactly this as the hidden vptr.

What does container_of(dev, struct ring_dev, base) do?

  1. Subtracts the offset of base from dev to get the enclosing ring_dev
  2. Allocates a new ring_dev
  3. Checks at run time that dev really is a ring device
  4. Copies base into a new struct
It is pointer arithmetic with no check, the C version of a downcast. Pass the wrong pointer and you corrupt memory.

Which Java feature corresponds to a NULL slot in an ops table that means "use the default behaviour"?

  1. A final class
  2. A static method
  3. An abstract method
  4. A default method in an interface
A default method gives every implementer a behaviour they may override, with no caller-side NULL check.

Which kernel structure is the clearest example of the Strategy pattern?

  1. struct list_head
  2. struct tcp_congestion_ops
  3. struct page
  4. spinlock_t
Congestion-control algorithms (cubic, reno, bbr) implement the same table and can be swapped per socket: interchangeable algorithms behind one interface.

A C++ shared_ptr and a kref both leak in which situation?

  1. When the object is on the stack
  2. When two threads copy the pointer
  3. When two objects hold counted references to each other (a cycle)
  4. When the class has a virtual destructor
Counts in a cycle never reach zero. Break cycles with a non-owning (weak) back reference. Java's tracing GC does not have this problem.

Your design has switch (vehicle.type) in five methods to compute fees, spot size and display names. What is the best refactor when each type has growing behaviour?

  1. An interface with one class per vehicle type
  2. More case labels
  3. A global table of if-else chains
  4. Make all fields public
Polymorphism puts each type's behaviour in its own class, so a new type is one new class (Open/Closed Principle).

What does a C++ compiler check that C does not, when a class implements an abstract base?

  1. That every function is inlined
  2. That every pure virtual function is implemented before you can create an object
  3. That the vtable is in read-only memory
  4. That no pointer is ever NULL
A class with an unimplemented pure virtual is abstract and cannot be instantiated. In C a forgotten slot is just NULL until it crashes.
