Dynamic dispatch, step by step

"Dynamic dispatch" means the function to run is chosen at run time from the object, not at compile time from the variable's type. In C you write the indirection yourself. In C++ a virtual call compiles to the same machine steps. Click through what happens on dev_send(eth0, "ping").

  1. The caller holds a pointer typed as the base (struct net_dev *, or NetDevice& in C++). It does not know the driver.
  2. Read the vtable pointer out of the object (dev->ops; in C++ the hidden vptr).
  3. Read the function pointer from the right slot (in C by field name; in C++ by a fixed index the compiler assigned).
  4. Make an indirect call, passing the object as the first argument (this).
  5. Inside, the implementation sees its own full type: via container_of in C, automatically in C++ and Java.

The cost is two dependent loads and an indirect branch: the same as your C code. Java's JIT compiler often removes even that: when it sees only one implementation at a call site, it inlines the call directly (and undoes the optimisation if a new class loads later). So "virtual calls are slow" is rarely a reason to avoid interfaces in LLD answers. More detail on Polymorphism & vtables.
