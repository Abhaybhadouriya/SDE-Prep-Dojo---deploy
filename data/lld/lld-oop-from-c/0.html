The story: one remote, many TVs

Explain like I'm 5

A hotel has a hundred rooms and five different brands of TV. The hotel gives every guest the same remote with the same buttons: power, volume up, channel up. Inside, each TV does something different when you press "power": one clicks a relay, another wakes a little computer. The guest does not care. The guest only knows the buttons. When the hotel buys a sixth brand next year, nobody prints new instructions for the guests; the new TV just has to answer the same buttons.

In programming, the set of buttons is an interface: a list of operations that anything of that kind must support. Each TV brand is a class: one particular way of doing those operations. Each real TV on a wall is an object (an instance of its class), with its own state such as the current channel. Pressing the same button and getting brand-specific behaviour is polymorphism ("many shapes"). Object-oriented programming (OOP) is the habit of building programs this way.

From your world

The Linux kernel's virtual file system is the hotel. A user process calls read(fd, buf, n), one button. The VFS looks at the open file, follows file->f_op, and calls f_op->read_iter: ext4 does one thing, procfs another, your character driver a third. struct file_operations is the remote's button list; each filesystem or driver that fills one in is a class; each struct file is an object. Neil Brown's two LWN articles (linked in Resources) walk through how much of the kernel is built this way. You already know OOP; you just know it under different names.
