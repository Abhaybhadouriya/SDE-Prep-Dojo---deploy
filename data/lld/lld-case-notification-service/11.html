Extensibility: the follow-ups interviewers ask

Follow-upChangeTouches
"Add WhatsApp" / "add the PhonePe soundbox"Add the enum value, a WhatsAppSender implements ChannelSender, an address for it on User, a template body, one registerSender line.One new class, setup
"Several accounts per provider; OTP traffic on its own account" (PhonePe)Register a separate sender chain for HIGH priority, or a RoutingSender that picks the account by priority. Still a decorator; the service does not change.One new decorator
"Pick a random active provider"A RandomSender next to FailoverSender: shuffle the providers, skip ones marked unhealthy, try the rest.One new class
"Quiet hours: no push 22:00-08:00"Preference check in deliver that re-queues the job for 08:00 instead of skipping; or a QuietHoursPolicy list of rules (Chain of Responsibility).Preference model
"Fallback channel: if push fails, send SMS"A per-request fallback list; on FAILED, submit a derived request for the next channel with a derived key (n1/fallback/SMS).deliver
"Digest: one e-mail per day instead of ten"A DigestCollector listener that buffers LOW requests per user and submits one scheduled request at the digest time.New listener
"Track delivered / opened / clicked"Providers call a webhook; map provider message id to our delivery record and append status events (state: SENT, DELIVERED, OPENED).History model
"Template versions and languages"Key templates by (id, channel, locale, version); the request carries the locale.TemplateRegistry
"Survive restarts"Repository interfaces for queue and history (memory now, DB later); the worker polls the table as in the schema.Two interfaces
"Many machines"Switch to the HLD shape: Kafka topic per priority, worker groups per channel. See HLD Notification System.Out of LLD scope

Answer "how would you add X?" with "a new class implementing Y, registered at Z; nothing else changes". For this problem Y is almost always ChannelSender (new channel, provider, routing, retry rule) or EventListener (new trigger, digest). If your answer edits NotificationService for a new channel, the design has a leak.
