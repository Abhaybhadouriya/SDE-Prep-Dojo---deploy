Class diagram

How to read this: + public, - private, «interface» a type with only method signatures (an ops table), 1..* one-to-many. Filled diamond = owns (the part dies with the whole), hollow diamond = has (can be swapped), solid line with hollow triangle = extends, dashed line with hollow triangle = implements, dashed arrow = depends on or creates. More in UML class diagrams and relationships.

  • ElevatorController is the only object that talks to every car. Buttons, cars and displays never call each other. It checks requests, queues them, runs the clock (tick()) and asks the dispatcher which car takes each hall call.
  • Request is one button press turned into an object. There are two kinds, HallCall (a floor button: floor and direction) and CarCall (a button inside a car: car and floor). Each knows how to apply itself to the controller, so any thread can create one while only the controller's thread applies it.
  • Elevator holds position, direction, stops and the current state. It exposes small questions the states and policies need (hasStopsBeyond, shouldStopHere, farthestStop) and two actions (moveOneFloor, serveHere).
  • ElevatorState has one method, tick(e), that does one time step and returns the next state. The four states hold no data of their own (everything is in the car), so one object per state is shared by all cars.
  • MovementPolicy answers one question: keep going in direction d? DispatchStrategy answers another: which of these cars? One decides inside a car, the other across cars.
