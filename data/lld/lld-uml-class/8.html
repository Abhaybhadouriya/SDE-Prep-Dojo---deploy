How much UML to draw in a round

The question "UML or code?" comes up again and again on LeetCode Discuss (Amazon SDE2, 2026-07; Walmart SDE-3, 2024-04; general, 2025-05; a course taught use-case, class and activity diagrams - draw all? 2024-08). The reported answer depends on the round:

Round typeDiagramNotes from reports
Whiteboard LLD (Amazon, Microsoft, Walmart, Salesforce)Yes, 8-10 min: main classes, relationships, multiplicities, the orchestrator's methodsThen code the key methods. A Walmart candidate whiteboarded while the interviewer wanted IDE code and felt it cost them (2024-12)
Machine coding (Flipkart, Swiggy, PhonePe, CRED)A quick sketch on paper during the 15-min design phaseGraded on running, modular code; the diagram is not submitted
Code design (Atlassian, some Uber rounds)Rarely; an API sketchTests and a growing API matter more
Design + DB rounds (some Zepto/CRED onsite)Classes plus schemaExpect a table design next to the class diagram

Whiteboard and text notation

On a whiteboard, three stacked rectangles are enough. In a shared doc or a chat-based round, a text notation is faster and still unambiguous:

+--------------------------+         +---------------------------+
|        ParkingLot        |<#>-------|          Level            |
+--------------------------+ 1  1..* +---------------------------+
| - levels: Level [1..*]   |         | - floor: int              |
| - pricing: PricingStrat. |         | - spots: ParkingSpot[1..*]|
+--------------------------+         +---------------------------+
| + park(v): Ticket        |         | + findSpot(v): ParkingSpot|
| + unpark(t, h): long     |         +---------------------------+
+--------------------------+
legend: <#>--- composition (filled diamond)   <>--- aggregation (hollow)
        ---> association with navigation      --|> inheritance

If the round allows a tool, Mermaid and PlantUML both turn a few lines of text into a diagram:

classDiagram
    class Vehicle {
        <<abstract>>
        -String plate
        +getType()* VehicleType
    }
    class PricingStrategy {
        <<interface>>
        +fee(int hours) long
    }
    Vehicle <|-- Car
    PricingStrategy <|.. HourlyPricing
    ParkingLot "1" *-- "1..*" Level
    ParkingSpot "1" --> "0..1" Vehicle

Interviewers love this: "I'll sketch the main classes in about eight minutes so we agree on the model, then go straight to code for park and unpark. Tell me if you'd rather I code first." It shows you know the format and respect the clock.
