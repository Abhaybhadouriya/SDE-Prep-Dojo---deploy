The story: a recipe card for objects

Explain like I'm 5

A recipe card has three parts. At the top, the name: "Pancakes". In the middle, the ingredients: flour, milk, eggs. At the bottom, the steps: mix, pour, flip.

A class diagram is a wall of recipe cards for a program. Each card says what a thing is called, what it has, and what it can do. Lines between cards say how things go together: pancakes need a pan; a pan is a kind of cookware.

In UML (the Unified Modeling Language, a standard drawing notation maintained by the OMG), the card is a class box with three compartments - name, attributes (the fields an object stores) and operations (the methods it offers). Lines between boxes are relationships. That is all a class diagram is. You do not need the full UML specification; interviews use a small, stable subset, and this page teaches exactly that subset.

From your world

You already read class diagrams in disguise. A header file with struct net_device (the attributes) and struct net_device_ops (the operations as function pointers) is a class box split across two structs. The kernel's Documentation/ ASCII drawings of which struct points at which are relationship lines. UML just gives every box and arrow a fixed meaning so a stranger reads it the same way you do.
