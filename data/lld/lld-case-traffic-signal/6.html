From your world

ControllerState is the per-state handler table you would write in C instead of one big switch: struct state_ops { void (*tick)(struct ctl *); void (*emergency)(struct ctl *, int dir); ... }, one table per state, and ctl->ops = &yellow_ops; is a transition. The TCP stack keeps the switch (sk->sk_state) form because its states share most code; here each mode reacts differently to almost every event, which is when the table wins. TimingStrategy is a tcp_congestion_ops-style slot chosen at runtime.

Patterns we deliberately skipped: a Singleton timer (see the warning below), inheritance per junction type such as FourWayController extends Controller (junctions differ in their phase list, which is data), and per-state locks (states only run inside the controller's lock).

The 2022 LeetCode poster wanted a Singleton timer. Resist it: a global timer makes tests wait in real time and hides who drives the clock. Inject time (a tick method, or a Clock interface) and let main own the real loop. That is also how you would test a kernel timer wheel: drive jiffies by hand.
