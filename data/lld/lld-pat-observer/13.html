  • Observer = subject keeps a list of observers behind one interface and notifies them on change.
  • It flips the dependency: the subject knows an interface, not SMS, search or analytics.
  • Push an immutable event; let observers pull more if needed.
  • Return an unsubscribe handle; forgotten subscriptions leak (lapsed listener).
  • Catch exceptions per observer; never call observers under your lock; use copy-on-write for the list.
  • Slow observers go async; back-pressure via Flow.Subscription.request(n).
  • Observer vs pub-sub: subject holds the list vs a broker holds topics (and can persist).
  • Kernel: notifier chains (notifier_block, priority, NOTIFY_STOP), inotify, rtnetlink groups.
