The problem: a subject that knows everybody

An online store's inventory service. When stock changes, several things must happen. The first version calls each one directly:

class Inventory {
    private final SmsService sms;          // to tell waiting customers
    private final OpsDashboard dashboard;  // low-stock alert
    private final AuditLog audit;
    private final SearchIndex search;      // hide out-of-stock items
    private final Analytics analytics;     // added last sprint

    void setQty(String sku, int qty) {
        int old = stock.put(sku, qty);
        if (old == 0 && qty > 0) sms.sendBackInStock(waitlist.get(sku), sku);
        if (qty < 3) dashboard.lowStock(sku, qty);
        audit.log(sku, old, qty);
        search.setAvailable(sku, qty > 0);
        analytics.track("stock", sku, qty);  // if this throws, nobody after it runs
    }
}
  • Inventory depends on five unrelated services. It cannot be compiled, tested or deployed without all of them. A change in Analytics recompiles Inventory.
  • Every new reaction edits the subject. "Also notify the recommendation engine" means opening setQty again (Open/Closed broken).
  • Nothing can be turned on or off at runtime. A customer who no longer wants the SMS cannot be removed without changing data structures inside Inventory.
  • One failure stops the rest. An exception in analytics skips anything written after it.
