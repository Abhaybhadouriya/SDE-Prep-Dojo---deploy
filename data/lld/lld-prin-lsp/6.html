Enforcing LSP: contract tests

The compiler cannot check behaviour, so tests must. The practical technique is a contract test: write the tests for the base type's promises once, then run the same tests against every implementation. In JUnit this is an abstract test class with an abstract factory method (createShape()), and one tiny subclass per implementation. In the code above, shapeContract and check(Account) are minimal versions of the same idea.

abstract class AccountContractTest {
    abstract Account create(long opening);              // each subtype's test supplies this

    @Test void withdrawReducesBalanceByExactlyAmount() {
        Account a = create(500);
        a.withdraw(100);
        assertEquals(400, a.balance());
    }
    @Test void rejectsAmountAboveBalance() {
        assertThrows(IllegalArgumentException.class, () -> create(50).withdraw(100));
    }
}
class FeeAccountTest extends AccountContractTest {       // this one fails: caught before production
    Account create(long opening) { return new FeeAccount(opening); }
}

Other ways to keep subtypes honest:

  • Prefer composition. If a "subtype" needs to switch off half of the parent's behaviour, it should hold the parent, not extend it (OCP and composition work well together).
  • Make classes final by default. Inheritance becomes a decision, and the base author writes down the contract when they open it up.
  • Document the contract. Javadoc that says what a method accepts, returns, throws and leaves unchanged is the spec that subtypes must meet. The kernel does this for file_operations in the VFS documentation.
  • Use sealed hierarchies (Java 17+) when the set of subtypes is fixed, so every subtype is visible and reviewed.

Scenario: the read-only repository

In a library-management round you have interface BookRepository { find(id); save(book); delete(id); }. Now you need an ArchiveRepository for old books that must never be changed, so you make save and delete throw.

"Throwing is fine, callers can catch it." (Every caller written for BookRepository now has a hidden failure path. That is Bird/Penguin again.)

Split the interface: ReadableRepository { find } and WritableRepository extends ReadableRepository { save, delete }. The archive implements only the readable one, and code that writes asks for the writable one. The compiler now enforces the rule.
