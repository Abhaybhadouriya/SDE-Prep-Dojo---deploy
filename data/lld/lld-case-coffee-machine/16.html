Common mistakes

  • A class per drink (Latte, Cappuccino) or per combination (LatteWithShot) instead of recipes as data.
  • Decorator that does not implement Beverage, so add-ons cannot wrap add-ons.
  • Mutating the base recipe when adding an add-on, so the next espresso has an extra shot too.
  • Check-then-act across two calls (hasIngredients, then consume), or consuming ingredient by ingredient and leaving half a recipe taken on failure.
  • Creating a new thread per order, which does not limit parallelism to N.
  • Holding the inventory lock while brewing, which makes N outlets pour one at a time.
  • Low alert on every order instead of on crossing the mark; calling listeners inside the lock.
  • Doubles for quantities and money; use integers (ml, g, rupees).
  • No tests for the parallel case, when the statement explicitly asks for integration tests.
