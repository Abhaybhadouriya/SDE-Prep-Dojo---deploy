The story: the barista with one fridge and three taps

Explain like I'm 5

A barista has one fridge with water, milk, coffee and sugar, and a card for every drink: "latte = a little water, some coffee, lots of milk". When you order, she reads the card and checks the fridge. If anything on the card is missing, she says no before she touches a single bottle. If everything is there, she takes it all out at once and makes your drink.

You can say "and an extra shot, and caramel". She does not need a new card for "latte with extra shot and caramel". She takes the latte card and clips a small "extra shot" note on top, then a "caramel" note on top of that. Each note adds a bit to the price and a bit to the recipe.

Her counter has three taps, so three drinks can be poured at the same time. A fourth customer waits for a free tap. When the milk bottle gets low, a little light turns on so the owner refills it.

That is the whole problem. The interviewer is checking four things: can you model a drink as data (a recipe) instead of a class per drink; can you add toppings without a class explosion (the Decorator pattern); can you build any drink from a name (a Factory with a registry); and, the real test in the Dunzo version, is the shared inventory correct when N outlets run at once?

From your world

The inventory is a resource pool with admission control. Taking all ingredients of a recipe or none is the same rule as charging an skb's full truesize to a socket's send buffer before queueing it: you check the budget and charge in one step, or you refuse the packet. N outlets are a fixed set of workers, like a workqueue with max_active = N: work items beyond N wait in the queue. An add-on that wraps a drink and forwards calls to it is a stacked driver: a device-mapper target wraps the block device below it, adds its own behaviour, and calls down. The menu registry is register_filesystem() plus get_fs_type("ext4"): look up a constructor by name instead of a long if-else.

Interfaces in C terms: every interface on this page is, in C, a struct of function pointers; each implementation fills one in, like file_operations. Java and C++ build that table (the vtable) for you, and every object carries a pointer to it. More in OOP from C structs and polymorphism and vtables.
