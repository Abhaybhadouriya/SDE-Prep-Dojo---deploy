How the decorator stack computes a price

  1. The machine calls price() on the outermost object. It does not know or care that it is a Caramel wrapper.
  2. Caramel does not know the base price, so it calls price() on the beverage it wraps.
  3. That inner beverage is itself a wrapper (ExtraShot), which asks the beverage inside it.
  4. The base Espresso answers 120. This is the end of the chain, like the bottom device in a stacked block driver.
  5. ExtraShot adds its 40 and returns 160.
  6. Caramel adds its 30 and returns 190. recipe() unwinds the same way, each layer merging its extra ingredients into a new map. name() builds "espresso + extra shot + caramel".

From your world

In C the decorator is a struct that embeds a pointer to the same ops type: struct beverage { const struct bev_ops *ops; }; struct addon { struct beverage base; struct beverage *inner; int extra; }; with addon_price(b) { struct addon *a = container_of(b, struct addon, base); return a->extra + a->inner->ops->price(a->inner); }. Stacked block devices (dm-crypt over dm-linear over a disk), a tc qdisc tree, and a stacked filesystem such as overlayfs or ecryptfs all work by "do my part, then call the one below".
