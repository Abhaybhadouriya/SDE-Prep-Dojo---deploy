It is a simple factory with registration; a full Factory Method hierarchy is not needed here."The factory maps a name to a recipe and applies the add-ons in order; a new drink is one registration."

Bounded worker poolfixed thread pool of N = outlets"At most N in parallel" is exactly what a fixed pool guarantees. Waiting orders queue inside the executor. No manual thread juggling."At most N pour at once because the pool has N threads; the rest queue."

From your world

Decorator is a stacked block device: dm-crypt sits on dm-linear, which sits on the disk; each layer implements the same block interface, does its part and calls the one below. Factory with a registry is register_filesystem() and get_fs_type("ext4"): a constructor found by name. Observer is a notifier chain fired when a watermark is crossed, like the memory pressure notifications of the page allocator. Brewer is a hardware abstraction layer: the driver core calls one ops table and the board-specific code (or a test stub) fills it in.

Patterns we deliberately skipped. Two patterns the LeetCode community design used that we did not: a Singleton machine (it makes every test share one machine; create it in main and pass it in) and a full State pattern for the Dunzo version (with no payment step the machine has no meaningful states per order; add State only when payment or maintenance modes arrive, see extensibility). Saying why you skipped a pattern scores as well as using one.
