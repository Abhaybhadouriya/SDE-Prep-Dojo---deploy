APIs and interfaces

interface Beverage {                  // base drinks and add-on wrappers
    String name();
    int    price();                   // whole rupees
    Recipe recipe();                  // immutable ingredient -> quantity
}

class BeverageFactory {
    void     registerDrink(String name, int price, Map<String, Integer> recipe);
    void     registerAddOn(String name, UnaryOperator<Beverage> wrap);
    Beverage create(String drink, List<String> addOns);      // throws CoffeeException
}

class Inventory {
    List<String> tryReserve(Recipe r);   // [] = all taken; else every reason, nothing taken
    void release(Recipe r);              // give a reservation back
    void refill(String ingredient, int qty);
    List<String> lowIngredients();       // the indicator
    void subscribe(LowStockListener l);  // alert on crossing the low mark
}

interface Brewer { void brew(Beverage b) throws Exception; }   // the hardware

class CoffeeMachine {                    // N outlets
    Future<Result> order(String drink, String... addOns);
}

In the Dunzo take-home the input is a JSON file with outlet count, ingredient quantities and recipes. A small loader turns it into inventory.add(..) and factory.registerDrink(..) calls, so the core classes never parse JSON.
