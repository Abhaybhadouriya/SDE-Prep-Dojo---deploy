Interviewers love this: before you say "done", spend 60 seconds on a self-review out loud. "My BookingService was getting big, so I pulled pricing into a strategy. Seats protect their own state. Nothing calls getInstance(); main wires everything. If you add a new seat type, it is one class." That one paragraph answers half the rubric.

The 60-second anti-pattern self-check

  1. Biggest class: does it have more than one reason to change? Pull one out.
  2. Entities: does each rule live next to its data? Replace a setter with a verb.
  3. Globals: any getInstance() or static mutable map? Inject it.
  4. Patterns: can you name the requirement each one serves? If not, inline it.
  5. Types: any status strings, money doubles or boolean flags? Enum, value object, named method.
  6. Errors: any empty catch? Throw a domain exception.
