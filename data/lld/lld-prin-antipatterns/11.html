Quiz

Which sign most strongly suggests a god object?

  1. The class has a long name
  2. Different groups of methods use different groups of fields, and several teams edit the class
  3. The class has more than one constructor
  4. The class implements an interface
Low cohesion (disjoint field/method clusters) plus many reasons to change is the real signal. Size and naming are only hints.

Martin Fowler's "anemic domain model" complaint is mainly about...

  1. DTOs used in REST APIs
  2. Domain objects that hold data but no behaviour, with all rules in services
  3. Classes without constructors
  4. Using records in Java
DTOs are fine. The complaint is about the core domain objects having no behaviour, so invariants are not protected.

What is the cleanest fix for OrderService calling Db.get() inside its methods?

  1. Make OrderService a Singleton too
  2. Pass an Inventory interface into the OrderService constructor and let main decide the instance
  3. Make Db.get() synchronized
  4. Copy the Db code into OrderService
Constructor injection makes the dependency visible and swappable; one shared instance can still exist, chosen by the composition root.

In the LWN "midlayer mistake", the recommended alternative to a midlayer is...

  1. A thicker midlayer with more flags
  2. A thin top layer that calls drivers directly, plus an optional library of helpers
  3. Making every driver inherit from the midlayer
  4. Moving the midlayer into user space
Shared code becomes a library that drivers may use, augment or ignore, so no special cases accumulate in the middle.

Which is a golden-hammer smell in a 90-minute machine-coding round?

  1. Using a Map for lookups
  2. Writing an AbstractFactory, a Builder and a Visitor before any P0 feature runs
  3. Writing a driver main
  4. Using an enum for vehicle type
Patterns applied because they are familiar, not because a requirement needs them, burn the time you need for working P0 code.

Four registers modelled as four classes that differ only in their stored value is an example of...

  1. Polymorphism
  2. Class per instance
  3. Composition
  4. Dependency inversion
When objects differ only in data, they are instances of one class (or enum values), not separate classes.

Which statement about anti-patterns is correct?

  1. An anti-pattern is any bug
  2. An anti-pattern is a common, tempting solution that predictably costs more than it saves, with a known better refactoring
  3. Anti-patterns only exist in Java
  4. A code smell and an anti-pattern are the same thing
A smell is a symptom you notice in code; an anti-pattern is a named recurring wrong solution with a known cure.
