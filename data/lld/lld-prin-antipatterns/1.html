The catalogue: anti-patterns an LLD grader notices

Here are the ones this page covers, how each looks inside a 60-minute LLD answer, and where the cure lives. The first five get a full section below.

Anti-patternWhat it looks like in your answerWhy it hurtsCure
God object (also called "the Blob")One ParkingLotManager / BookingService with every map and every methodMany reasons to change; no seams to extend; hard to testSplit by responsibility; thin coordinator (SRP)
Anemic domain modelEntities that are only getters/setters; all rules in servicesInvariants unprotected; rules copied into every callerMove behaviour into entities; Tell, Don't Ask
Singleton abuseX.getInstance() called from everywhereHidden dependencies, shared test state, lock hot spotConstructor injection (DIP)
Golden hammer / pattern-itisFactory, Builder and Visitor before anything runsTime gone; design harder to read than the problemYAGNI; add a pattern when a requirement asks for it
Midlayer mistakeA base "engine" class that runs every flow and grows if (type == X) flagsSpecial cases pile up in shared code; nobody can opt outThin top + helper library; composition, Strategy
Class per instanceRegisterA, RegisterB, RegisterC...Class explosion; switch statements to pick oneOne class, many objects, a map or enum
Speculative generalityIUserService + UserServiceImpl for every class, generic Repository<T, ID> with 12 methodsIndirection without a second implementationRule of three; inline it
Stringly typed / primitive obsessionstatus = "BOOKED", money as doubleTypos compile; rounding bugsEnums, value objects (Money)
Swallowed exceptionscatch (Exception e) {}Failures vanish; double bookings go silentSpecific exceptions; fail loudly or return a result type
Circular dependencyOrder knows Payment knows Order, both constructed in each otherCannot build or test one without the otherExtract an interface or an event; one-way arrows
Big ball of mudNo structure at all; everything calls everythingNothing can change safelyLayers and boundaries, one seam at a time

Two older names you will see on SourceMaking's anti-pattern catalogue: lava flow (dead code nobody dares delete) and poltergeist (a class that exists only to call another class and disappear). They matter in real codebases more than in a one-hour round.
