The kernel's midlayer mistake

In 2009 Neil Brown wrote a three-part LWN series on Linux kernel design patterns. The last part names the midlayer mistake. A midlayer sits between a generic top layer (the block layer, the VFS) and the specific drivers below it, does work that "everyone needs", and then hands a simplified request down. It looks like perfect code sharing. The article's thesis: midlayers are a mistake; the shared code should be a library that drivers can use, extend or ignore, and the top layer should call drivers directly.

  1. The midlayer: every request from the top passes through one shared layer that sorts it with an elevator before any driver sees it. Looks like neat code sharing.
  2. RAID does not want the elevator. The midlayer learns its first special case, and RAID requests start bypassing it.
  3. A fast SSD does not want sorting either. Special case number two. The midlayer now knows details of its drivers - the layering is upside down.
  4. The library design: the thin top layer calls each driver's own entry point directly. The shared code moves into a library.
  5. Drivers call the helpers they want. RAID calls none. Adding a new kind of driver needs no change to shared code.

The article lists the tell-tale signs, and they translate directly to classes:

Kernel tell-taleOO equivalent you will write in an interview
Special cases grow for drivers the midlayer did not foreseeA base GameEngine or VehicleProcessor that grows if (type == CHESS) or isElectric() flags
The primary struct carries a pointer to the midlayer's own private dataA base class that stores fields only some subclasses use
Unrelated code gets grouped and called for everyoneA template method that calls ten hooks, most of them empty overrides
Drivers cannot opt outSubclasses forced to inherit behaviour they then override to do nothing (an LSP warning sign)

The library version is composition: each concrete class is the entry point for its own work and calls small shared helpers or strategies. Template Method is still fine when the flow really is fixed (a game loop, a request pipeline); the mistake is forcing a flow on cases that do not share it.

/* Midlayer vs. library: a tiny model of the LWN "midlayer mistake" idea.
   Build: gcc -std=c99 -Wall -o midlayer midlayer.c && ./midlayer */
#include <stdio.h>

struct request { long sector; int len; };

/* ---------- BEFORE: a midlayer that every driver is forced through ---------- */
struct mid_driver { const char *name; int is_raid; void (*do_io)(struct request *r); };

static void sort_queue(struct request *r) { printf("  midlayer: elevator sort sector %ld\n", r->sector); }

static void midlayer_submit(struct mid_driver *d, struct request *r)
{
    if (d->is_raid) {                 /* special case: the midlayer had to learn about RAID */
        printf("  midlayer: RAID bypass for %s\n", d->name);
        d->do_io(r);
        return;
    }
    sort_queue(r);                    /* everyone else gets the elevator, wanted or not */
    d->do_io(r);
}

static void disk_io(struct request *r) { printf("  disk: write %d bytes\n", r->len); }
static void raid_io(struct request *r) { printf("  raid: split %d bytes\n", r->len); }

/* ---------- AFTER: thin top layer + optional helper library ---------- */
struct lib_driver { const char *name; void (*make_request)(struct request *r); };

/* library helper: drivers MAY call it, nobody is forced to */
static void lib_elevator_sort(struct request *r) { printf("  lib: elevator sort sector %ld\n", r->sector); }

static void disk_make_request(struct request *r) { lib_elevator_sort(r); printf("  disk: write %d bytes\n", r->len); }
static void raid_make_request(struct request *r) { printf("  raid: split %d bytes over 2 disks\n", r->len); }

static void top_submit(struct lib_driver *d, struct request *r) { d->make_request(r); } /* no policy here */

int main(void)
{
    struct request r = { 2048, 4096 };
    struct mid_driver md[] = { { "sda", 0, disk_io }, { "md0", 1, raid_io } };
    struct lib_driver ld[] = { { "sda", disk_make_request }, { "md0", raid_make_request } };
    int i;

    printf("BEFORE (midlayer):\n");
    for (i = 0; i < 2; i++) midlayer_submit(&md[i], &r);
    printf("AFTER (library):\n");
    for (i = 0; i < 2; i++) top_submit(&ld[i], &r);
    return 0;
}

From your world

The article's own example: in 2.2-era kernels every block request went through the elevator, with a hard-coded exception for md RAID devices. Later, drivers registered their own make_request function, so the elevator became a library that virtual drivers (md, dm, loop) simply skip. A make_request_fn pointer is exactly a Strategy interface with one method.
