Smaller anti-patterns that cost points

These rarely fail a round on their own, but graders write them down, and three of them together read as "not production quality".

Writes this
  • class RegisterA, class RegisterB... one class per object (CRED, 2023-08)
  • book(userId, showId, true, false) - boolean flag parameters
  • if (status.equals("CANCELED")) - stringly typed state, typo included
  • double amount for money
  • catch (Exception e) { }
  • Order creates Payment, and Payment creates Order
  • Constants like if (mins > 60) repeated in five places
Writes this instead
  • One Register class, a Map<String, Register>
  • Two named methods, or a small options object / enum
  • enum BookingStatus { HELD, CONFIRMED, CANCELED }
  • long paise or a Money value object
  • A specific domain exception (SeatUnavailableException) that the caller can act on
  • One-way dependency; the back reference is an ID or an event
  • A named constant or a policy object

Circular dependencies come up as a Java/Spring question too: a Walmart LLD round asked which annotation handles a cyclic dependency between two beans (2024-12). Know the answer (@Lazy on one injection point breaks the cycle at startup), then say the better fix: remove the cycle by extracting an interface or publishing an event.
