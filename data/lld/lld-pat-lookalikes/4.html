Family 1: the wrappers

3. Decorator vs Proxy

Same shape: a class that implements the same interface as the object it wraps and forwards calls to it.

Decorator exists to add responsibilities: logging, compression, encryption, metrics. The client assembles the stack, decorators can be layered in any order, and every layer forwards the call. Proxy exists to control access to one real subject: lazy creation (virtual proxy), permission checks (protection proxy), caching, or a stand-in for a remote object (remote proxy). The proxy often creates or owns the real object, and may decide not to call it at all.

Tell-tale: if wrapping twice makes sense ("log, then compress"), it is a Decorator. If the wrapper's job is to decide whether and when the real object is used, it is a Proxy. Java examples: BufferedInputStream (Decorator) vs a Spring transactional or java.lang.reflect.Proxy-based proxy (Proxy). Linux: device-mapper targets stack like decorators; a stub that forwards to a remote service is a proxy.

4. Adapter vs Facade

Same shape: a class that sits in front of other code and translates calls.

Adapter converts one existing interface into another interface a client already expects; the target interface is fixed by someone else. Facade invents a new, simpler interface over a whole subsystem of many classes; nobody required that exact interface, you designed it to make life easy. Adapter is about compatibility; Facade is about simplicity.

Tell-tale: count what is behind it and ask who defined the interface in front. One adaptee and a pre-existing target: Adapter. Many classes and an interface you invented: Facade. Kernel: the compat syscall layer that converts 32-bit structures for 64-bit code is an adapter; a system call such as sendfile() that hides page cache, sockets and file systems behind one call behaves like a facade.

5. Adapter vs Bridge

Same shape: an abstraction forwards to an implementation object through an interface.

Adapter is applied after the fact, to make two pieces that were never meant to work together fit. Bridge is designed up front so that an abstraction hierarchy and an implementation hierarchy can grow independently (M + N classes instead of M x N). They combine: you write an Adapter to plug a third-party SDK in as one concrete implementor of a Bridge.

Tell-tale: "we have to integrate this old library" is Adapter; "we will have many front-ends and many back-ends" is Bridge. Kernel: struct file calling through file_operations is the classic Bridge.

10. Composite vs Decorator

Same shape: a class that implements an interface and also holds component(s) of that same interface: recursive composition.

Composite holds many children and represents a part-whole tree, so clients treat one item and a group of items the same way (a folder's size is the sum of its children). Decorator holds exactly one child and adds behaviour to it, forming a chain, not a tree.

Tell-tale: a list of children means Composite; a single inner field means Decorator. A directory tree or a menu with sub-menus is Composite.
