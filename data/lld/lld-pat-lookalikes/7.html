How to identify a pattern in someone else's code

  1. Start from the shape every look-alike shares: a class that holds a reference to some interface X. First question: does the class itself also implement X? If yes, you are in the wrapper family.
  2. Wrapper with the same interface: does it always call the inner object? Then it adds behaviour: Decorator (or a Chain of Responsibility if some links may return early). If it can refuse, cache, or delay the call, it controls access: Proxy.
  3. Wrapper with a different interface: converting one existing class into a required interface is Adapter; a simple new front over many classes is Facade.
  4. Not a wrapper: the held object does a job for the class. Find who replaces it. The client or configuration: Strategy (and if the holder has its own growing hierarchy, Bridge). The held object returns its own successor: State.
  5. Last check: if these objects are created, stored in a queue, a log or an undo stack and executed later, they are Commands, whatever they look like.
