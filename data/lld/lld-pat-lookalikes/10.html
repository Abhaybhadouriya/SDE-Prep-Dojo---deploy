When the line really is blurry

Interviewers like it when you admit that some real code fits two names. Good examples to have ready:

Honest "both" answers
  • Middleware stacks (servlet filters, Express, Django): most links forward and add work (Decorator), some stop early (CoR).
  • A caching wrapper: called a Decorator if the client stacks it on purpose, a Proxy if it hides and controls a single expensive object.
  • Kernel ops tables: file_operations is called Bridge (two layers vary) and also Strategy (pluggable behaviour). Name the intent you are stressing.
  • Pub-Sub vs Observer: an in-process event bus is a broker with observer-style callbacks.
Mistakes that cost points
  • Naming a pattern from the class diagram alone, without stating the problem it solves.
  • Calling every wrapper a Decorator and every interface field a Strategy.
  • Saying "Facade" for a class that just forwards to one other class (that is an Adapter or plain delegation).
  • Using State but letting callers set any state they like: the transitions must live in the states.

A safe phrase when the line is blurry: "Structurally this is a wrapper; I'm using it as a Proxy because its job is to decide whether the real service is called. If I only added logging, I'd call it a Decorator."
