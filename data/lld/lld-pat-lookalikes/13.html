Identification drills (Q&A)

Strategy and State have the same UML diagram. How do you tell them apart?

By who changes the delegate. In Strategy the client or configuration picks an algorithm and the strategies do not know each other. In State each state handles events and returns or sets the next state, so the object changes its own behaviour and invalid transitions are impossible. Example: fare algorithms vs a ride's Requested, Accepted, OnTrip, Done lifecycle.

How to answer

Concede the same shape, give the "who decides" test, give one example of each.

Likely follow-ups
  • Can a State implementation use a transition table instead of classes? (Yes, for simple machines.)
A class implements PaymentGateway, wraps a PaymentGateway, and retries failed calls three times. Decorator or Proxy?

Decorator. It keeps the interface, always forwards, and adds a responsibility (retry) that could be stacked with others such as logging or metrics. It would lean towards Proxy if its main job were to decide whether the real gateway is called at all: rate limiting, authorisation, lazy connection, or a remote stub.

How to answer

Name it, then say exactly what would change your answer.

Likely follow-ups
  • Where does a circuit breaker fit? (Proxy-like: it refuses calls while open.)
A CheckoutService.placeOrder() calls inventory, payment, shipping and email. Which pattern?

Facade: one simple entry point over several subsystem classes, with an interface we designed. It is not an Adapter because there is no pre-existing target interface to satisfy and more than one class behind it. Watch that it does not grow into a god object that owns business rules of all four subsystems.

How to answer

"Many classes, invented simple interface" equals Facade.

Likely follow-ups
  • If steps must be coordinated with rules about which to retry or compensate, is it still a Facade? (It moves towards a Mediator or an orchestrator.)
Netfilter hooks, notifier chains, and stacked device-mapper targets all link handlers together. Which pattern is each?

Netfilter hooks: Chain of Responsibility, since each hook returns a verdict and NF_DROP or NF_STOLEN stops the traversal. Notifier chains: Observer, since every registered callback is told about the event (a callback can return NOTIFY_STOP, which adds a CoR flavour). Stacked device-mapper targets: Decorator-like layering, since each target forwards I/O to the device below after transforming it (crypt, mirror).

How to answer

Use the "can a link stop the call" and "broadcast vs handle" tests on each.

Likely follow-ups
  • Why does the order of netfilter hooks matter? (Priorities; an early drop saves work.)
Factory Method vs Abstract Factory, in one minute.

Factory Method is a single overridable method that lets a subclass choose which one product to create. Abstract Factory is an object with several creation methods for a family of products that must match, and you switch families by swapping the factory object. Factory Method relies on inheritance; Abstract Factory on composition. An abstract factory's methods are often factory methods.

How to answer

One product vs a family; subclass vs object. Then one example each.

Likely follow-ups
  • Adding a new product kind to an Abstract Factory: what breaks? (Every concrete factory must change.)
For undo in a text editor, would you use Command or Memento?

Usually Command: each edit stores enough to reverse itself, so memory grows with the size of edits, not the size of the document, and commands also give you redo, macros and a change log. Memento is simpler and safer when operations are hard to invert or state is small; some editors combine them, taking periodic snapshots plus a command log.

How to answer

Name the trade-off: memory and correctness of inverses vs simplicity.

Likely follow-ups
  • How do you merge many single-character inserts into one undo step?
Observer vs Pub-Sub vs Mediator: when do you pick each?

Observer when a subject in the same process must tell a few known listeners about a change, synchronously. Pub-Sub when publishers and subscribers must not know each other, may live in different services, and delivery can be asynchronous or buffered, through a broker. Mediator when several objects interact with rules ("if A then B must do C"), so the rules live in one coordinator instead of spreading across listeners.

How to answer

Coupling and location of logic: direct list, broker, coordinator.

Likely follow-ups
  • What delivery guarantees change when you move from Observer to a Kafka topic?
