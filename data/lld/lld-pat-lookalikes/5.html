Family 2: the context delegates to an interface

1. Strategy vs State

Same shape: a context object holds a reference to an interface and forwards work to it; concrete classes implement the interface.

Strategy encapsulates interchangeable algorithms for one job. The client (or configuration) chooses the strategy, and strategies usually do not know about each other. State models an object whose behaviour depends on its current mode. Usually the states themselves (or a transition table in the context) decide the next state, so the object changes its own behaviour as events arrive; Strategy is chosen from outside. GoF allows either the context or the states to own the transitions, and states do not make illegal transitions impossible by themselves: you still reject them explicitly.

Tell-tale: look for the line that changes the delegate. ride.setFare(SURGE) called from outside: Strategy. state = state.next(event) inside the context: State. Kernel: picking a congestion control algorithm per socket through tcp_congestion_ops is Strategy; the TCP connection state machine (TCP_SYN_SENT, TCP_ESTABLISHED, TCP_FIN_WAIT1, ...) moving on received segments is State.

2. Strategy vs Template Method

Same shape: a fixed algorithm with one or more steps that vary.

Template Method uses inheritance: a base class defines the skeleton and calls abstract "hook" methods that subclasses override. The choice is fixed when you pick the subclass. Strategy uses composition: the varying step is an object passed in, and you can swap it at runtime or combine several strategies in one context.

Tell-tale: extends plus protected abstract hooks is Template Method; a constructor parameter of an interface type is Strategy. Java: AbstractList (you implement get and size, it gives you the rest) is Template Method; Collections.sort(list, comparator) is Strategy.

9. Command vs Strategy

Same shape: an object with one main method (execute() or apply()) that wraps a piece of behaviour.

Command captures a request: what to do, with which arguments, to which receiver. Because the request is now an object, you can queue it, log it, retry it, schedule it or undo it. Strategy captures a way of doing one job that the context performs anyway. Commands are usually different operations; strategies are different algorithms for the same operation.

Tell-tale: if the objects sit in a queue, a history list or an undo stack, they are Commands. If they are interchangeable answers to "how do we compute X", they are Strategies. Kernel: a work_struct queued on a workqueue is a Command (a deferred request plus its function); tcp_congestion_ops is a Strategy.

11. Chain of Responsibility vs Decorator

Same shape: a linked series of handlers, each holding the next.

In a Chain of Responsibility each handler decides whether to handle the request and stop, or pass it on; the request may end anywhere, or nowhere. In a Decorator chain every layer always forwards to the inner object and adds work before or after.

Tell-tale: can a link return early without calling the next? Then it is CoR. Kernel: netfilter is the pipeline variant of Chain of Responsibility: every hook may act on the packet and pass it on with NF_ACCEPT (conntrack, NAT and filtering all touch the same skb), and any hook can end the walk with NF_DROP or NF_STOLEN. Classic GoF CoR stops at the first handler that takes the request (ATM denominations, approval levels); a shared IRQ line, where handlers return IRQ_HANDLED or IRQ_NONE, is the closer kernel fit. Servlet filters and middleware stacks are interesting because they can do both: most links forward (decorator-like), an auth filter may stop (CoR-like). Say which behaviour you mean.
