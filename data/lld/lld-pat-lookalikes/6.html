Family 3 and 4: creating, notifying, undoing

6. Factory Method vs Abstract Factory

Same shape: client code asks for an object through an interface and never calls new on a concrete class.

Factory Method is one method, usually in a base class, that subclasses override to decide which single product to create. Abstract Factory is an object with several creation methods that produce a family of related products that must match (Windows button with Windows checkbox). An abstract factory is often implemented with several factory methods.

Tell-tale: one product and inheritance: Factory Method. Several products that must be consistent, chosen by passing a factory object: Abstract Factory. Kernel: net_proto_family->create() making the family-specific socket on socket(2) is really a registry keyed by the family number (a parameterised factory), while super_operations->alloc_inode, fixed by the file system type, is the cleaner factory method; a file system whose superblock hands out matching inodes, inode ops and file ops is closer to an abstract factory.

7. Observer vs Publish-Subscribe

Same shape: one event, many interested receivers.

In Observer, the subject keeps its own list of observers and calls them directly, usually synchronously and in the same process. Subject and observers know each other's interfaces. In Publish-Subscribe, publishers send to a topic on a broker (an event bus, Kafka, Redis channels); publishers and subscribers do not know each other, and delivery may be asynchronous, buffered or even across machines.

Tell-tale: is there a middleman that owns the subscriptions? Then it is Pub-Sub. Kernel: register_netdevice_notifier() puts your callback directly on a notifier chain: Observer. Netlink multicast groups that user-space processes join are closer to Pub-Sub. Case study: pub-sub system.

8. Observer vs Mediator

Same shape: objects stop calling each other directly and go through something in the middle.

Observer is one-to-many broadcast: the subject announces "I changed" and does not care what observers do. Mediator is many-to-many coordination with logic: colleagues tell the mediator what happened, and the mediator decides who must do what next (a control tower telling planes when to land). A mediator is often built using observer-style notifications, which is where the confusion comes from.

Tell-tale: where do the rules live? Spread among listeners: Observer. In one central class that knows all participants: Mediator. Case study: an elevator system dispatcher is a mediator between cars and floor buttons.

12. Memento vs Command (for undo)

Same shape: both put something on an undo stack.

Memento stores a snapshot of state; undo restores the snapshot. It is simple and always correct, but snapshots can be large. Command stores the operation with enough data to reverse it (insert("abc", 10) knows its inverse is delete(10, 3)); undo calls undo(). It is compact, but every command must implement a correct inverse.

Tell-tale: what is on the stack, copies of state or verbs? A text editor usually uses commands (small edits, huge documents); a game save slot is a memento. Databases mix both: undo log records reverse operations, snapshots capture state.
