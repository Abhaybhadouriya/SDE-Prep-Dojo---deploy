Aggregation vs composition: who owns the lifetime?

Both are special associations that say "whole and part". The difference is one question: if the whole is destroyed, must the part be destroyed too?

  • Composition (filled diamond): yes. The part belongs to exactly one whole at a time, the whole usually creates it, and the part makes no sense alone. An OrderLine without its Order is meaningless. The UML spec phrases it as: a composed part is deleted together with its composite.
  • Aggregation (hollow diamond): no. The whole groups parts that exist on their own and may be shared. A Player outlives a Team; a player can move to another team.

Click through the lifetimes. This is the picture to keep in your head when an interviewer asks "aggregation or composition?".

  1. An order is created with two lines (the order called new OrderLine). A team is formed from two players who already existed.
  2. Delete the order. Its lines are destroyed with it: nobody else holds them, and a line without an order means nothing. That is composition.
  3. Delete the team. The players are untouched: they were only grouped, not owned. That is aggregation.
  4. Ravi joins Team Red. A part of an aggregation can be shared or move. A part of a composition can never belong to two wholes.

Before and after: composition that leaks

The most common bug in "composition" code is a getter that hands out the internal list. Now any caller can keep the parts, add to them or share them, and the diagram's filled diamond is a lie.

class Order {
    private final List<OrderLine> lines = new ArrayList<>();
    public List<OrderLine> getLines() { return lines; }     // caller can add, remove, keep
    public void addLine(OrderLine line) { lines.add(line); } // a line built elsewhere, maybe shared
}
final class Order {
    private final List<OrderLine> lines = new ArrayList<>();
    void addLine(String sku, int qty, long price) {           // the whole is the creator
        lines.add(new OrderLine(sku, qty, price));
    }
    List<OrderLine> lines() { return Collections.unmodifiableList(lines); }  // read-only view
}

In Java "destroyed" means "unreachable". The garbage collector frees objects, not you. So composition in Java is about design responsibility: the whole creates the part, controls it, and never lets anyone else keep a reference. In C or C++ it is literal: the part is embedded by value or freed in the whole's destructor.
