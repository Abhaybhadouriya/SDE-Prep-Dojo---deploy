From your world: the six lines in C and the kernel

From your world

You have written all six relationships in C for years. UML just gives them names and line endings.

  • Composition = a struct embedded by value. struct sk_buff embeds its struct list_head; your struct order embeds struct order_line lines[4]. One free() of the outer struct and the parts are gone. They cannot outlive it because they live in its bytes.
  • Aggregation = a pointer to a refcounted object. A team holds struct player * and takes a reference with a get; when the team goes, it drops its references with a put, and the player is freed only when the last holder lets go. This is exactly kref_get() / kref_put(), or dev_hold() / dev_put() on a net_device.
  • Association = a plain pointer to an object someone else manages, often in both directions: struct device points to its struct device_driver, and the driver core keeps lists from driver back to devices.
  • Realization = filling an ops table. A filesystem "implements the interface" struct file_operations by providing .read, .write, .open. The VFS only calls through the table. That dashed triangle is a static const struct file_operations myfs_fops = { ... }.
  • Generalization = embedding the base struct and getting back to the child with container_of(). struct usb_device embeds a struct device; driver-model code works with the base, the USB code recovers the child.
  • Dependency = a function that takes a pointer as an argument and does not store it.

The runnable C version of this page's example (embedded order lines, refcounted players, an ops table and a container_of payment) lives in lld-code/lld-uml-relationships/relationships.c.

This is also why the C view helps in interviews: when you hesitate between aggregation and composition, ask yourself "would I embed it, or hold a pointer and a refcount?". Embed means composition. Pointer plus refcount means aggregation.
