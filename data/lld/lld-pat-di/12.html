Related and confused-with patterns

PatternRelationship to DI
Dependency Inversion PrincipleThe goal (depend on abstractions). DI is the usual way to reach it.
Service LocatorThe alternative: pull from a registry instead of being pushed. See the table above.
Factory Method / Abstract FactoryFactories create objects; DI decides who holds the factory. You often inject a factory when a class must create many short-lived objects at run time.
SingletonDI replaces most singletons: make one instance in the composition root and inject it. You keep "only one" without the global access point that hurts testing.
StrategyA strategy is usually a dependency injected through the constructor or a setter.
ProxyContainers return proxies (transactions, caching) in place of your beans; the client never notices because it was injected an interface.
RepositoryThe most commonly injected dependency in LLD answers: an in-memory repository in interviews and tests, a database one in production.
Template MethodIoC by inheritance: the base class calls your hooks. DI is IoC by composition.
