The forms of injection

FormHowUse it forWatch out
Constructor (default)new OrderService(gw, repo, notifier, clock)Required dependencies. Fields can be final; the object is complete and valid the moment it exists; dependencies are visible in the signature.A constructor with 8+ parameters is a design smell (too many responsibilities), not a DI problem.
Settersvc.setAuditHook(hook)Optional dependencies with a sensible default; reconfiguration; breaking a genuine cycle.Object can be used half-configured; fields cannot be final; order of calls matters.
Method / parameterreport.render(Clock clock)A dependency needed by one method only, or one that changes per call (the current user, a request context).Callers must have it at hand.
Field (container only)@Autowired private Notifier n;Quick demos.Hidden dependencies, no final, impossible to construct in a plain unit test without reflection. Spring's own documentation recommends constructor injection for required dependencies.
Interface injectionClass implements NotifierAware.setNotifier(..)Historical (Avalon); Spring's *Aware interfaces are a remnant.Rarely worth it.

Inject the clock, the random number generator and ID generators too. They are the most common hidden dependencies in LLD interview code, and the reason "how would you test the late fee?" or "how would you test token-bucket refill?" stumps people. java.time.Clock exists for exactly this.
