Spring basics: what the container automates

Short version: Spring is a container like our 25-line one, scaled up. In a machine-coding round, write constructor injection and wire it in main().

In an LLD machine-coding round, do not pull in Spring. Write constructor injection and wire it in main() (or a small AppFactory). Then say one sentence: "In production a container like Spring would do this wiring." That shows you know the idea without hiding your design behind annotations.

Only if your interviewer is a Spring shop (Level 5, Java-specific)

Annotation = metadata attached to a class or method (@Component, @Service) that a framework reads at start-up. Think __attribute__((section(".initcall"))) plus module_init(): you tag the thing, and the framework finds it and wires it, instead of you calling it by hand.

Everything Spring does on top of our mini container: it scans for classes, reads their constructors, builds the graph in the right order, manages lifetimes, and wraps beans in proxies for transactions and caching. A minimal example (shown for reading; it needs the Spring libraries, so it is not part of our compiled demos):

@Component
class CardGateway implements PaymentGateway { /* ... */ }

@Component
class EmailNotifier implements Notifier { /* ... */ }

@Service
class OrderService {
    private final PaymentGateway gateway;
    private final Notifier notifier;
    private final Clock clock;

    // A single constructor needs no @Autowired (Spring 4.3+). Spring finds one bean per parameter type.
    OrderService(PaymentGateway gateway, Notifier notifier, Clock clock) {
        this.gateway = gateway; this.notifier = notifier; this.clock = clock;
    }
}

@Configuration
class AppConfig {
    @Bean Clock clock() { return Clock.systemUTC(); }   // for classes you do not own, declare a factory method
}
  • Beans and scopes. Each managed object is a bean. The default scope is singleton (one per container, not the GoF Singleton: you can still create others in tests). prototype gives a new instance per injection; web apps add request and session.
  • Two candidates for one type (both EmailNotifier and SmsNotifier) fail startup with an ambiguity error. Mark one @Primary, pick by @Qualifier("sms"), or inject List<Notifier> to get all of them (handy for a notification fan-out).
  • Circular dependencies (A needs B, B needs A) cannot be satisfied with constructor injection, and Spring Boot refuses circular references by default since 2.6. That is a feature: a cycle usually means a missing third class.
  • Profiles (@Profile("test")) swap implementations per environment, the container version of "fakes in tests".
  • Other containers: Guice (modules and bindings in Java code), Dagger (generates the wiring code at compile time, popular on Android), and .NET's built-in IServiceCollection.
