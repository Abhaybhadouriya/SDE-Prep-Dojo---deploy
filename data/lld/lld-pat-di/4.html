How it works: building the object graph at startup

  1. At startup, the composition root creates the leaf objects first: things with no dependencies of their own (a clock, a gateway client, a notifier).
  2. It then creates the service, passing the leaves into the constructor. The service stores them in final fields and never calls new on them.
  3. It keeps going up the graph: the controller receives the service. The graph is built bottom-up, exactly once.
  4. At run time, requests flow top-down through objects that only know interfaces. Nobody looks anything up.
  5. In a unit test you build the same graph with fakes. The service code is identical; only the wiring differs.
