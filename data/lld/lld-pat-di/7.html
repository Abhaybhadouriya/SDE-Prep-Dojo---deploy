Service locator vs Dependency Injection

A service locator is a registry that classes call to fetch their dependencies: ServiceLocator.get(PaymentGateway.class). It also decouples a class from concrete implementations, so people ask "isn't that the same?" No. The difference is who reaches for whom:

Dependency InjectionService Locator
DirectionDependencies are pushed inThe class pulls them from a registry
Visible in the API?Yes: the constructor lists themNo: hidden inside method bodies
Missing dependency foundWhen the object is built (startup)When that code path first runs (maybe in production)
Class depends onOnly the interfaces it usesThe interfaces and the locator (a global)
TestsPass fakes to the constructorRegister fakes in global state and clean up after; tests can leak into each other
Where it is fineAlmost everywherePlug-in discovery at the edges, legacy code you cannot refactor yet, framework internals

java.util.ServiceLoader

ServiceLoader.load(Notifier.class) finds implementations listed in META-INF/services/<interface name> files on the classpath (or declared with provides ... with ... in a module-info.java) and creates them with their public no-argument constructor. It is how JDBC drivers, java.nio file system providers and logging back-ends plug themselves in. Technically it is a locator for plug-ins: great at the edge of the system to discover implementations, which your composition root then injects into the classes that use them. Do not call it from deep inside business code.
