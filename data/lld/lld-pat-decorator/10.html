In interviews

Decorator is a Tier 1 pattern because its trigger is easy to spot: "the customer can add any number of toppings / add-ons / extras, and each changes the price", or "add logging / metrics / caching to this service without changing it".

  • Coffee machine and pizza or burger pricing: base item plus stackable add-ons. Coffee-house designs posted on LeetCode Discuss use exactly this shape (post 2163726).
  • Food delivery and shopping cart: item customisations, gift wrap, express delivery fees, discount wrappers.
  • Ride hailing: base fare decorated with surge, toll and night charges (also commonly done with a Strategy list; discuss both).
  • Logger and notification service: formatting, timestamping, retry or rate-limit wrappers around a sink or channel.
  • Rate limiter and cache: a caching or limiting wrapper around a service with the same interface (often called a proxy).
  • Text editor: bold / italic / underline formatting layered on text.

The usual extensibility probe from our recent interview notes is "now add a new add-on without touching existing classes". With decorators that is one new class.

Strong 30-second answer: "Subclassing every combination explodes, and flags violate Open/Closed. I'll make AddOn a decorator: it implements Beverage and holds one Beverage. Milk.price() is inner.price() + 20. The order is built at run time by stacking wrappers, and a new add-on is one new class. Watch out for order-dependent rules like size multipliers; I'd apply those in a fixed order from a builder."
