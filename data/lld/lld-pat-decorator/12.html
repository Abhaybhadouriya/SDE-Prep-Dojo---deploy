  • Decorator = same interface, wraps one object, adds a responsibility, stackable at run time.
  • Participants: Component, ConcreteComponent, Decorator (abstract, forwards by default), ConcreteDecorators.
  • Each method: optional work before, forward to inner, optional work after.
  • Beats subclassing for combinable optional features; avoids the subclass explosion and boolean flags.
  • Watch order-dependent rules, identity checks and big interfaces; let a builder own the order.
  • Decorator adds behaviour; Proxy controls access; Adapter changes the interface; Composite has many children.
  • Kernel bridge: device-mapper targets and stackable file systems are decorators.
