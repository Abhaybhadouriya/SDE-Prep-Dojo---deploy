Related and confused-with patterns

PatternInterface vs wrapped objectWhy it existsOne-liner
DecoratorSameAdd behaviour, stackable, chosen by the client"Same interface, more features."
ProxySameControl access: lazy creation, remote, cache, permission, rate limit. Usually manages the real object's life cycle itself."Same interface, guarded."
AdapterDifferentMake an existing class fit an expected interface"Changes the interface."
CompositeSameGroup many children into a tree and combine results"Many children; Decorator has one."
Chain of ResponsibilitySame handler typePass a request along until someone handles it"Any link may stop; every decorator forwards."
Strategyn/aSwap the guts (the algorithm) of an object"Strategy changes the inside; Decorator changes the skin."
FacadeNew, simplerHide a whole subsystem behind one entry point"Simplifies many."

Proxy and Decorator have identical class diagrams, so the interviewer is really asking about intent. A caching wrapper can be described either way: call it a proxy when it guards access to an expensive real object, a decorator when it is one of several stackable features the client composes. The look-alike patterns page compares all of these.
