Common mistakes

  • double for money, then rounding each share separately so the sum is 99.99.
  • A switch on split type inside addExpense (or instanceof on Split subclasses).
  • Updating balances before validating, so a bad PERCENT expense leaves half its debts behind.
  • Storing only one direction of each debt and then forgetting to net "A owes B" against "B owes A".
  • Printing "owes 0.00" or printing a user owing themselves (payer's own share).
  • Parsing mixed into the domain: the service takes a raw command string. Hard to test, hard to extend.
  • Starting with simplify debts or groups before P0 runs. Bonus features never rescue a broken core.
  • A Singleton ExpenseService "because there is one". It makes tests share state; just create it in main.
