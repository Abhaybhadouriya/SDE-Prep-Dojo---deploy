Identify the entities (nouns and verbs)

Read the problem once and underline nouns (candidate classes) and verbs (candidate methods). Then throw away nouns that are only attributes. This is the method from From use cases to classes; here it is applied step by step.

  1. Start from the requirement sentence. Read it twice.
  2. Underline nouns. Each is a candidate class: User, Expense, Split, Balance, amount, participant.
  3. Underline verbs. They become methods, and they tell you which class owns the behaviour.
  4. Remove nouns that are only data: "amount" is a field of Expense; "participant" is just a User in a list.
  5. "Split" turns into a type enum plus one strategy class per type, because the behaviour (how to divide) varies. "Balance" becomes a BalanceSheet that owns the who-owes-whom map.

The single most important modelling choice: the expense stores the computed shares (user to paise), not the raw percentages. After validation, the rest of the system never needs to know which split type was used. It only sees "this user consumed this many paise".
