Interview Q&A

What is the Strategy pattern? Give an example from a real design.

A family of interchangeable algorithms behind one interface, held by a context that delegates to whichever one it has. Parking lot: FeeStrategy with HourlyFee and FlatFee; the exit gate calls pricing.fee(stay) and never branches on the tariff. Swapping is a reference change.

How to answer

Definition in one line, then the before (growing if/else) and after (interface plus classes), then the OCP benefit.

Likely follow-ups
  • Who chooses the strategy?
  • Write the interface.
Strategy vs State: the UML is identical. What is the real difference?

Who changes the delegate, and why. In Strategy the client or configuration chooses the algorithm, and strategies are independent of each other. In State the current state object handles an event and itself sets the next state on the context; the states know about each other and model a lifecycle. Pricing is a Strategy; "idle, has-coin, dispensing" is State. A system often has both: an order has states, and each state may use a pricing strategy.

How to answer

Agree the diagram is the same, then give the "who triggers the swap" test and one example of each.

Likely follow-ups
  • Can a state object use a strategy?
  • Where would you put the transition logic?
How does Strategy help the Open/Closed principle? Is the code really closed?

The context is closed: adding a tariff does not touch ExitGate. But something must still map "mall" to FirstHoursFlatFee. Keep that in one factory or registry (or let DI do it), so the only edit is one line in one place, or none at all if strategies register themselves (like tcp_register_congestion_control from a module's init function or Java's ServiceLoader).

How to answer

Say yes, then be honest about the selection point and how you shrink it.

Likely follow-ups
  • How would you load strategies from config without recompiling?
Design payment processing for UPI, card and wallet, with a gateway that may change.

PaymentStrategy with pay(order, amount) returning a result; UpiPayment, CardPayment, WalletPayment implement it. A PaymentService context does the common work (idempotency key, audit, retries, status update) and delegates the method-specific part. The gateway SDK (Razorpay, Stripe) is wrapped by an Adapter behind a Gateway interface so switching vendors does not touch the strategies. A factory chooses the strategy from the request's method field.

How to answer

Separate "what varies by method" from "what is common"; keep the common work in the context.

Likely follow-ups
  • How do you make pay idempotent?
  • Where does the refund go?
Is Comparator a Strategy? What other JDK examples are there?

Yes. Collections.sort, List.sort, TreeMap and PriorityQueue are contexts that take a Comparator deciding order. Others: RejectedExecutionHandler in ThreadPoolExecutor, and lambdas passed to stream().filter or map in the broad sense. In Python, the key= argument of sorted.

How to answer

Name two or three, and point out that a functional interface turns a strategy into a lambda.

Likely follow-ups
  • Sort tickets by fee then by time with one expression (comparing(...).thenComparing(...)).
Your strategies need different inputs (surge needs demand data, pool needs co-riders). How do you keep one interface?

Pass a small request object (FareRequest with trip, time, city) instead of loose parameters, and inject the extra dependencies into the strategy's constructor (SurgeFare(DemandService)). The interface stays fare(FareRequest); each strategy pulls what it needs from its own collaborators. If the inputs are truly unrelated, they are not one family, and you should have two interfaces.

How to answer

Parameter object plus constructor injection; then the honesty check.

Likely follow-ups
  • How do you combine surge with a promo code? (Compose: a strategy wrapping another, or a chain of adjusters.)
Are strategies thread-safe? Should they be singletons?

Stateless strategies are thread-safe by construction and can be shared, one instance per kind. A strategy with mutable state (a token bucket's counters, Reno's ACK counter) must be one instance per context, or protect its state. Swapping a strategy on a live context from another thread needs a safe publication: make the field volatile or use an AtomicReference, and read it once per call.

How to answer

Split stateless vs stateful, then mention the swap race.

Likely follow-ups
  • How does the kernel stop a congestion module being unloaded while sockets use it? (The owner module reference.)
Where does Linux use Strategy?

TCP congestion control (tcp_congestion_ops, picked per socket with setsockopt(TCP_CONGESTION) or system-wide by sysctl), block I/O schedulers per queue, qdiscs per interface, cpufreq governors. All follow the same recipe: an ops struct, a register function, a name-based lookup, and a module reference while in use.

How to answer

Name the struct, the register call and how a user selects it.

Likely follow-ups
  • How is that different from a C++ virtual function? (Same idea, written by hand.)
