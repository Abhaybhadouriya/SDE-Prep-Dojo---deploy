How it works: one checkout, then a runtime swap

  1. The client reads the lot's configuration ("mall") and asks the registry for that strategy. The client never writes new FirstHoursFlatFee() itself, so adding a tariff does not touch client code.
  2. The strategy is injected into the context through the constructor. ExitGate.pricing now points at it.
  3. A car leaves after 200 minutes. checkout does the context's own work (ticket lookup) and makes one delegated call: pricing.feeRupees(stay).
  4. The strategy computes 4 started hours: Rs 50 for the first two, Rs 30 for each of the other two, total Rs 110. The gate prints the receipt; it has no idea which formula ran.
  5. On a festival day an operator swaps the rule at runtime with setPricing(...). One reference changes. No new gate, no restart, no if.
  6. The same checkout now crosses to the new strategy and returns 0. This is exactly what setsockopt(TCP_CONGESTION) does to one socket.
