The problem: the if/else that keeps growing

A parking lot charges money at the exit gate. Version one charged by the hour. Then a mall client wanted "first two hours flat". Then weekends got a surcharge. Here is how the code usually looks after a year:

class ExitGate {
    long fee(String pricingMode, VehicleType type, int minutes, boolean weekend) {
        long hours = Math.max(1, (minutes + 59) / 60);
        long fee;
        if (pricingMode.equals("HOURLY")) {
            if (type == VehicleType.BIKE) fee = hours * 10;
            else if (type == VehicleType.CAR) fee = hours * 40;
            else fee = hours * 100;
        } else if (pricingMode.equals("MALL")) {
            fee = 50 + Math.max(0, hours - 2) * 30;
        } else if (pricingMode.equals("AIRPORT")) {
            fee = ...;                       // 40 more lines, added last month
        } else {
            throw new IllegalStateException("unknown mode " + pricingMode);
        }
        if (weekend && !pricingMode.equals("AIRPORT")) fee += fee / 4;   // special case of a special case
        return fee;
    }
}

Why this hurts:

  • Every new rule edits tested code. Adding "festival free parking" means opening fee() again and risking the hourly branch. This breaks the Open/Closed principle.
  • The rules cannot be tested alone. To test the mall rule you must go through a method that knows about every other rule.
  • The same switch spreads. The receipt printer needs if (mode == "MALL") to print "first 2 h flat"; the admin screen needs it to show the tariff. Now three files must change for one new rule.
  • Nobody can add a rule without the source. A franchise in another city cannot plug in its own tariff.
