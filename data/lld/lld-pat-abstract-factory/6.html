Where you meet it in real code

WhereAbstract factoryFamily it makes
JDBC (java.sql)A Connection from one drivercreateStatement(), prepareStatement(), prepareCall() all return that driver's classes, so a MySQL statement never runs on a Postgres socket.
Java XML (javax.xml)DocumentBuilderFactory, TransformerFactory, XPathFactorynewInstance() finds an implementation at run time; the parser, documents and nodes you then get all come from that one implementation.
Java SwingPluggable look and feel (UIManager.setLookAndFeel)One setting changes the UI delegates for buttons, menus and scrollbars together.
Python DB-API (PEP 249)A connection object from sqlite3, psycopg and othersconn.cursor() gives a cursor of the same driver; exception classes come from the same module.
Cloud SDKs, test codeA "client factory" per provider or per environmentStorage, queue and secrets clients that share credentials and region; a fake factory gives in-memory versions for unit tests.
Linux kernelfile_system_type + super_operations; per-chip driver info structsInodes with matching inode_operations / file_operations; matching MAC/PHY ops for one chip.

In modern Java and Spring code you will rarely see a class named ...AbstractFactory. A dependency injection container often wires the right family at startup (for example, one Spring profile per environment). The pattern is still there; the container plays the role of picking the concrete factory. See Dependency Injection.
