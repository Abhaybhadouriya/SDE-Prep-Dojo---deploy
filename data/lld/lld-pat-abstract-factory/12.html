Remember this

  • Abstract Factory = one object with a create method per product kind; one concrete factory per family.
  • The client holds the factory and uses only interfaces, so families can be swapped in one line and can never mix.
  • Grid view: families are rows, kinds are columns. New row is cheap; new column touches every factory.
  • Factory Method = one product, chosen by subclassing. Abstract Factory = many related products, chosen by passing an object.
  • Real examples: JDBC Connection, DocumentBuilderFactory, Swing look and feel, Linux VFS ops tables.
  • Inject the factory; do not make it a global singleton. Fake factories make tests easy.
