Quiz

What problem does Abstract Factory mainly solve?

  1. Building one object with many optional fields
  2. Creating several related objects that must come from the same family
  3. Making sure only one instance of a class exists
  4. Copying an existing object cheaply
Families of related products that must stay consistent. Optional fields = Builder, one instance = Singleton, copying = Prototype.

Your GatewayFactory has 3 methods and 4 gateway families. Product wants a new payout() operation for all gateways. How many classes must change or be added at minimum?

  1. Only the client
  2. Only the interface
  3. The interface, all 4 concrete factories, plus a new product interface and 4 new product classes
  4. Nothing, abstract factory is open for extension
Adding a product kind is the expensive direction: the factory interface grows, every family implements it, and each family needs its own payout class.

In Abstract Factory, how does the client get a specific family?

  1. It is given (injected with) a concrete factory object
  2. It subclasses the factory and overrides a method
  3. It calls a static method with a string
  4. It clones a prototype
Abstract Factory uses composition: the client holds a factory object. Overriding a method is Factory Method; a static method with a key is Simple Factory.

Which is the best JDK example of an abstract factory?

  1. Math.max
  2. Integer.valueOf
  3. StringBuilder
  4. java.sql.Connection
A Connection creates statements of the same driver. Integer.valueOf is a static factory method for one product, StringBuilder is a builder.

In Linux VFS terms, what plays the role of a concrete factory for ext4?

  1. The open() system call
  2. ext4's superblock with its super_operations, which creates ext4 inodes carrying ext4 op tables
  3. The page cache
  4. The block I/O scheduler
The superblock operations allocate inodes for that file system, and each inode gets that file system's operations tables: a matching family.

Which situation is the weakest reason to use Abstract Factory?

  1. A UI that must support light and dark widget sets
  2. Running the same service against AWS or GCP clients
  3. Creating one kind of Vehicle from a type string
  4. Swapping every external client for fakes in tests
One product kind needs a simple factory or factory method, not a whole family interface.
