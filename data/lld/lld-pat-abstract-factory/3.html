From your world

You already write this in C. An abstract factory is a struct of function pointers whose functions return other ops tables or objects. The Linux VFS is the classic case: a file_system_type mounts a superblock, the superblock's super_operations->alloc_inode creates that file system's inodes, and each inode carries that file system's inode_operations and file_operations. ext4 never ends up with an XFS inode op table, because one object hands out the whole matching set.

Drivers do it too. A NIC driver that supports several chip generations often keeps a per-chip "info" struct pointing at matching MAC, PHY and NVM ops tables, picked once in probe() from the PCI device ID. That info struct is a concrete factory; the PCI ID table is the registry.
