How it works: one call sequence, step by step

  1. Startup code reads gateway=zen and looks it up in a map of factories. It creates ZenPayFactory. This is the only line that knows a concrete family.
  2. The factory is passed into CheckoutService's constructor (dependency injection). The service asks it for a Charger and gets a ZenCharger, typed as the interface.
  3. It asks the same factory for a Refunder and a WebhookVerifier. Because one object made all three, they are guaranteed to be the Zen family.
  4. At run time the service calls charger.charge(...) through the interface. Dynamic dispatch (the vtable) lands in ZenCharger.
  5. To move to Acme, change the config value. The map hands out AcmePayFactory and every product changes at once. No client code was edited.
