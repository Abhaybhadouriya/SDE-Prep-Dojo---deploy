Remember this

You might confuse this with:

  • 301 vs 302: 301 = "moved for good", browsers cache it and stop asking us (less load, no analytics); 302 = "moved for now", every click comes back to us (analytics and expiry work).
  • Hash vs counter: a hash of the long URL can collide and needs a check; a counter never collides but is guessable unless scrambled.
  • Short code vs ID: the ID is the number (56,800,235,585); the code is that number written in base62 (1000001). Same value, two spellings.

Remember this

  • It is a read-heavy key lookup: ~100 reads per write. Design the read path separately and cache it.
  • Per day ÷ 105 = per second. 100M/day ≈ 1.2k/s; 10B/day ≈ 116k/s.
  • Base62, 7 characters ≈ 3.5 trillion codes; 6 characters ≈ 56.8 billion (not enough for 5 years at 100M/day).
  • Counter + base62 + range leasing = no collisions, no read-before-write. Scramble if guessability matters.
  • 302 keeps analytics and expiry; 301 saves load but hides repeat clicks.
  • Clicks go to Kafka and are counted asynchronously; redirects never wait for analytics.
  • Viral link = hot key: CDN, in-pod cache, request coalescing.
  • Redirects are sacred; analytics and creation can degrade first.
