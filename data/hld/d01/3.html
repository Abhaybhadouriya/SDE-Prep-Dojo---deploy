Key APIs

An API (application programming interface) is the list of requests a client can send. We use plain REST over HTTPS: each request is a verb (POST, GET, DELETE) plus a path. Two calls do 95% of the work.

# 1) Create a short link
POST /api/v1/urls
Authorization: Bearer <api-key>        # who is creating (for quotas and abuse)
Content-Type: application/json
{
  "long_url":   "https://www.example.com/products/2026/winter-sale?ref=email",
  "custom_alias": "diwali-sale",          # optional
  "expires_at":   "2027-01-31T00:00:00Z"  # optional
}
-> 201 Created
{ "code": "aZ3kP9q", "short_url": "https://sho.rt/aZ3kP9q", "expires_at": "2027-01-31T00:00:00Z" }
-> 409 Conflict   if custom_alias is taken
-> 429 Too Many Requests  if the caller exceeds its quota (see the rate limiter design)

# 2) Follow a short link (what a browser does)
GET /aZ3kP9q
-> 302 Found
   Location: https://www.example.com/products/2026/winter-sale?ref=email
-> 404 Not Found  if unknown;  410 Gone  if expired or disabled

# 3) Analytics (stretch)
GET /api/v1/urls/aZ3kP9q/stats?from=2026-11-01&to=2026-11-23
-> 200 { "total_clicks": 18342, "by_day": [ ... ] }

# 4) Delete / disable
DELETE /api/v1/urls/aZ3kP9q   -> 204 No Content

The create call is protected by the rate limiter so one script cannot burn through millions of codes. Note that the redirect path is not under /api: it must be as short and as fast as possible.

301 or 302? (the classic trap)

StatusMeaningBrowser caches it?Good forCost
301 Moved Permanently"This address moved forever."Yes, can cache for a long timeLess load on usRepeat clicks never reach us, so click counts are lost; you cannot change the target later
302 Found (or 307)"Go here for now."No (unless headers allow)Analytics, editable or expiring linksEvery click hits our servers or CDN

Our pick: 302, because analytics and expiry are requirements. If the interviewer drops analytics, say 301 cuts load. Either way, say why. That sentence is what they are listening for.

Try it: a 40-line shortener on your laptop

To see the real HTTP exchange, here is a toy version using only the Python standard library (a dict stands in for the database). Save the base62 functions from the deep dive below as b62.py, this file as tiny.py, then run python tiny.py in one terminal and the curl commands in another.

# tiny.py - toy URL shortener (one process, in-memory)
import json, threading
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
from b62 import encode

lock = threading.Lock()
counter = 62**6          # start at the first 7-character number
store = {}               # code -> long URL

class H(BaseHTTPRequestHandler):
    def do_POST(self):
        global counter
        body = json.loads(self.rfile.read(int(self.headers["Content-Length"])))
        with lock:                       # the "global counter"
            counter += 1
            code = encode(counter)
        store[code] = body["long_url"]
        out = json.dumps({"code": code, "short_url": f"http://localhost:8080/{code}"}).encode()
        self.send_response(201)
        self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(out)))
        self.end_headers()
        self.wfile.write(out)

    def do_GET(self):
        url = store.get(self.path.lstrip("/"))
        if url is None:
            self.send_response(404); self.send_header("Content-Length", "0"); self.end_headers(); return
        self.send_response(302)
        self.send_header("Location", url)
        self.send_header("Cache-Control", "private, max-age=0")
        self.send_header("Content-Length", "0")
        self.end_headers()

if __name__ == "__main__":
    ThreadingHTTPServer(("127.0.0.1", 8080), H).serve_forever()
