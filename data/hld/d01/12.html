Quick quiz

100 million new links a day is roughly how many writes per second?

  1. About 100
  2. About 1,000
  3. About 100,000
100M ÷ 105 seconds ≈ 1,000 (exactly about 1,157). Reads at 100:1 are about 116,000/s.

You need 182.5 billion codes. What is the shortest base62 length that fits?

  1. 5 characters
  2. 6 characters
  3. 7 characters
626 is only about 56.8 billion. 627 is about 3.5 trillion, comfortably enough.

Why do we return 302 instead of 301 when we want click analytics?

  1. Browsers do not cache 302 by default, so every click reaches us
  2. 302 is faster for the browser
  3. 301 is not allowed for short links
A 301 is cached by the browser, so repeat clicks skip our servers and we never count them.

What is the main benefit of counter + base62 over "MD5 and take 7 characters"?

  1. Codes are shorter
  2. No collisions, so no lookup before each write
  3. The same URL always gets the same code
A counter gives every link a different number by construction. Hashing needs a collision check. (Same URL → same code is actually the advantage of hashing.)

Each write pod leases blocks of 1,000 IDs. Peak is 3,500 writes/s. How many requests per second reach the range service?

  1. 3,500
  2. 350
  3. About 3.5
3,500 ÷ 1,000 = 3.5 block requests per second. That is why range leasing removes the hot counter.

Kafka is down. What should happen to redirects?

  1. They keep working; click events are buffered or dropped
  2. They fail with 503 until Kafka is back
  3. They switch to 301
Analytics is off the critical path. Losing some click events is far better than breaking every link.

Bots request millions of random codes that do not exist. Which fix targets this?

  1. Increase the cache TTL
  2. Cache "not found" briefly or use a Bloom filter, and rate-limit the client
  3. Switch to SQL
This is cache penetration: every request misses the cache. Negative caching or a Bloom filter stops misses reaching the store.

In a Pastebin design with metadata in a database and bodies in S3, which write order is safest?

  1. Upload the body to S3, then insert the metadata row
  2. Insert the metadata row, then upload the body
  3. Do both in parallel and return as soon as either finishes
Body first means a crash leaves at worst an orphan object that cleanup removes. Row first could publish a URL that points at a missing body.
