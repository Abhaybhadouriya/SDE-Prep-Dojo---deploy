Requirements

The first thing you say when the interviewer finishes the prompt (you asked for this script): "Before I draw anything, let me pin down what the system must do and how big it is. Can I ask a few questions?" Then ask these, and write the answers on the board.

  1. Who uses it? Public users on the internet, or employees only? (Public. Assume anyone can create links.)
  2. How many new links per day? (Assume 100 million new URLs a day. This is the classic textbook number.)
  3. How many clicks per new link? (Assume read:write is 100:1, a common interview assumption.)
  4. Custom aliases? Can a user ask for sho.rt/diwali-sale? (Yes, optional.)
  5. Expiry? Do links expire? (Default never, but the user may set an expiry date.)
  6. Analytics? Do creators see click counts? (Stretch goal: count clicks per link per day.)

Functional (what it does)

  • Shorten: given a long URL, return a unique short URL.
  • Redirect: given a short code, send the browser to the long URL.
  • Custom alias (optional) and expiry date (optional).
  • Analytics (stretch): clicks per link, per day, per country.
  • Delete or disable a link (for abuse reports).

Non-functional (how well it does it)

  • Very low redirect latency: the redirect is on the user's click path. Target p99 under ~100 ms at the server (a goal we set, not a fact).
  • Highly available reads: if redirects fail, every printed QR code and SMS link breaks. Aim for 99.99% (about 52.6 minutes of downtime a year).
  • Codes never collide and never change once given.
  • Codes are short: 7 characters or fewer.
  • Codes should not be easy to guess (nice to have).
  • Eventual consistency is fine for analytics; the code-to-URL mapping must be correct.

Say what you will NOT build: "I'll skip user accounts, billing and a web UI. I'll focus on the shorten and redirect paths, then analytics if we have time." Interviewers like a clear scope. It also stops you from over-explaining internals, which you told us is your habit.

Words used here: p99 means "99 out of 100 requests are faster than this". Availability 99.99% means the system answers correctly 99.99% of the time. New terms on this page are explained in the "New words" note in the story above and in the site glossary.
