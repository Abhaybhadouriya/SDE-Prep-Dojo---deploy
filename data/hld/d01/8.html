"What if this box fails?" (one line per box)

  • A read pod dies: the LB's health check removes it; Kubernetes starts a new one. Users see nothing.
  • Redis shard dies: its replica is promoted; meanwhile misses fall through to the store (latency rises, still correct). Protect the store with coalescing so it is not flattened.
  • A store shard's primary dies: a replica takes over. Reads continue from replicas; writes to that shard pause for seconds.
  • Range service down: pods finish their current blocks (seconds to minutes). Then creation fails with 503 while redirects keep working. That is the right priority order.
  • Kafka down: the read pod's producer buffers in memory and then drops click events. Redirects still work; analytics has a gap. Say this out loud: "analytics is best effort; redirects are sacred".
  • Whole region down: replicate the store to a second region; DNS or anycast fails over. Because codes are immutable, multi-region read replicas are easy (no write conflicts on existing rows). Give each region its own ID range so new codes never clash.
