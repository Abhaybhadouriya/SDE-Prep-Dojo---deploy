How real systems do it

  • Dropbox - "Streaming File Synchronization" (2014): namespaces, 4 MB blocks hashed with SHA-256, blocklists, the Server File Journal with JIDs, block vs metadata servers, commit / need-blocks / store_batch / list / retrieve_batch, long-poll notifications, and streaming sync (up to 2x faster).
  • Dropbox - "Inside the Magic Pocket": their exabyte-scale block store - buckets, volumes, cells (~50 PB), OSDs, multi-zone replication, erasure coding, sharded MySQL block index.
  • Dropbox - "Rewriting the heart of our sync engine": why the client engine (Nucleus) was rewritten in Rust with stable file IDs, a single deterministic control thread and randomized simulation testing.
  • Microsoft Graph delta query (OneDrive) and Google Drive changes API: both expose exactly the "give me changes since this token / cursor" model to developers.
  • rsync tech report: the rolling-checksum delta algorithm behind efficient block transfers.

Related designs: S3 Object Storage (the blob store underneath), YouTube Upload (chunked uploads + async processing), Collaborative Editor (when you can merge), Notification System, and the Handling Large Blobs pattern.
