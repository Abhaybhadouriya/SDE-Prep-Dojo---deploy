Remember this

  • Split metadata (small, transactional, sharded SQL by namespace) from bytes (huge, immutable, blob store by hash).
  • Files = blocklists of 4 MB SHA-256 blocks; only changed blocks move; identical blocks are stored once.
  • Protocol: commit -> need blocks -> upload missing (directly) -> commit again -> journal row.
  • Devices: cursor per namespace + long-poll doorbell + list(cursor). Never short-poll millions of devices.
  • Big files: parallel, idempotent block uploads; the server's "need blocks" is the resume point.
  • Concurrent edits: parent revision check; loser becomes a conflicted copy. No silent overwrite.
  • Kafka fans out committed changes (thumbnails, search, notifications); the journal stays the truth.
  • Shared blocks need careful GC; global dedup has a privacy cost.
