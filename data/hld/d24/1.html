Requirements

Functional (in scope)
  • Upload a file from any device; download from any device.
  • Automatic sync: a change on one device appears on the others.
  • Share a file or folder with other users; see what is shared with you.
  • Keep previous versions; restore a deleted file (stretch).
  • Handle offline edits and two devices editing the same file.
Out of scope (say it)
  • Editing documents in the browser (that is Collaborative Editor).
  • Previews, thumbnails, full-text search (mention as async consumers).
  • Per-user quotas and billing; virus scanning (mention as a hook).
  • Designing the blob store from scratch (see S3 Object Storage).
Non-functional requirementTargetWhy it matters
DurabilityNever lose a committed file versionPeople store their only copy of photos and contracts here

File sizeUp to 50 GB per fileForces chunked, resumable, parallel upload
Sync latencySeconds from commit to other devices starting downloadUsers notice when the phone does not show the new file
Bandwidth efficiencySend only changed blocks; dedup identical blocksMobile data and upload links are slow and costly
Correctness under concurrencyConcurrent edits never silently overwrite each otherLeads to the "conflicted copy" rule

"You might confuse this with" object storage. S3 stores whole objects by key. A sync service uses a blob store but adds the hard parts on top: a per-user file tree, versions, sharing, change feeds per device, delta upload and conflict handling. In an interview, treat the blob store as a building block and spend your time on the sync protocol.
