Quick quiz

A user edits one page in the middle of a 40 MB PDF. With 4 MB fixed blocks, roughly how much is uploaded?

  1. 40 MB
  2. About one block (4 MB), maybe two
  3. Nothing
Only blocks whose bytes changed get new hashes; unchanged blocks are already on the server (assuming the edit did not shift later bytes).

What does the first commit call usually return for a brand-new file?

  1. A new revision number
  2. A conflict
  3. "Need blocks" listing the hashes the server does not have
Commit doubles as a question; the client then uploads the missing blocks and commits again.

Why do devices use a long-poll instead of asking for changes every second?

  1. Hundreds of millions of devices polling would mean ~100M mostly empty requests per second
  2. HTTP cannot poll
  3. Long-poll sends the file data
Long-poll only answers when something changes; it is a doorbell, and list(cursor) fetches the actual rows.

Two devices commit edits that were both based on revision 41. What should happen to the second commit?

  1. It overwrites revision 42
  2. It is merged byte by byte
  3. It is silently dropped
  4. It is rejected and saved by the client as a conflicted copy
Optimistic concurrency: the parent revision no longer matches, so the client keeps both versions visible to the user.

Where should the file bytes travel during upload?

  1. Through the metadata API servers into the SQL database
  2. Directly from the client to block servers / blob storage
  3. Through Kafka
Keep the data plane separate from the control plane; metadata servers only handle small blocklists.

Inserting one byte at the start of a file changes every fixed-size block hash. What technique fixes that?

  1. Bigger blocks
  2. MD5 instead of SHA-256
  3. Content-defined chunking with a rolling hash
  4. Compression
Cut points chosen by content (rolling hash pattern) move with the data, so only chunks near the insert change.

Why can't you delete a block as soon as one file that used it is deleted?

  1. Other versions, files or users may reference the same content-addressed block
  2. Blob stores do not allow deletes
  3. Kafka still holds it
Dedup makes blocks shared; use reference counting or delayed mark-and-sweep that respects version retention.
