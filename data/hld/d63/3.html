Key APIs

# create alerts (auth required); server returns the computed absolute trigger where possible
POST /v1/alerts  { "symbol": "TSLA", "type": "FROM_CLOSE", "direction": "DOWN", "percent": 5 }
POST /v1/alerts  { "symbol": "INFY", "type": "DELTA", "direction": "ANY", "percent": 2 }        # vs price at creation
POST /v1/alerts  { "symbol": "AAPL", "type": "WINDOW", "direction": "UP", "percent": 3, "window": "1h" }
  -> 201 { "alertId": "al_77", "expiresAt": "2026-12-23T00:00:00Z" }

GET    /v1/alerts?status=active
DELETE /v1/alerts/al_77

# internal: feed handler -> Kafka (not an HTTP API)
topic ticks, key = symbol, value = { "symbol": "TSLA", "price": 241.10, "close": 255.00, "ts": 1795400000123, "seq": 88123 }

# internal: evaluator -> notification service
topic alerts-fired, key = user_id, value = { "alertId": "al_77", "symbol": "TSLA", "price": 241.10, "rule": "DOWN 5% from close" }

Two details worth saying. (1) window is an enum (1m, 5m, 1h, 1d, 1w, 1M, 1y), not free text, so windows can be shared. (2) Each tick carries a seq per symbol so evaluators can drop duplicates and detect gaps after a feed reconnect.
