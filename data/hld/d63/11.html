Remember this

  • Never hit the DB per tick: rules live in memory in evaluators that own symbols.
  • Convert "from close" and "delta" rules to absolute triggers; keep UP and DOWN books sorted per symbol.
  • Ticks and rule changes are co-partitioned by symbol in Kafka.
  • Rolling windows: shared per (symbol, window size), monotonic deques over multi-resolution bars; subscribers sorted by percent.
  • Fire once: remove from memory, conditional update ACTIVE to FIRED, de-dupe in the notifier.
  • Expiry: heap in memory plus a nightly DB sweep.
  • Recovery: snapshot plus replay for rules; checkpoint or rebuild from bars for windows; commit offsets after checkpoint.
  • Size the notification path for the crash-day burst; draw the basic design fast because interviewers dive early.
