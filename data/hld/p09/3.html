Lambda vs Kappa: how do you fix yesterday's numbers?

Lambda feeds the same immutable events to a fast stream job and a slower, exact batch job, and merges them at query time; the batch result overwrites the stream estimate once it is ready. It gives both speed and correctness, and is the common answer for ad billing. Jay Kreps' well-known essay "Questioning the Lambda Architecture" names its cost: the same logic lives in two systems that must be kept in sync, and operating both is painful.

Kappa is Kreps' alternative: keep the raw events in Kafka long enough (his example is 30 days), use one stream job, and when the logic changes or a bug is found, start a second copy of the job from the beginning of the log writing to a new table. When it catches up, switch reads to the new table and delete the old one. One codebase; reprocessing only when needed.
