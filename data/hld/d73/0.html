The story

Explain like I'm 5

Imagine a big toy shop with a help desk. Many kids come with problems: "my toy car is broken", "I got the wrong doll", "where is my parcel?".

At the door stands a clever helper. She looks at the receipt in your hand and says, "You bought a car yesterday and it is broken? Go to the Repairs line." She did not even need to ask much. That is predicting the issue.

Each line has helpers behind it. Every helper wears a little sign: green means "I am free", red means "I am busy". Some helpers are so good they can help three kids at once by writing notes. When a helper gets free, the kid who waited the longest goes next. That is routing.

One rule is sacred: no kid is ever forgotten. Even if a helper goes home in the middle, the kid's ticket goes back to the front of the line. And every note passed between kid and helper is copied into a big book, so the next helper can read what happened.

The story already contains the whole design:

  1. Receipt = recent orders. An intent predictor reads the customer's last few orders, shipments and refunds and guesses the issue ("late delivery", "refund status", "damaged item").
  2. Lines = skill queues. Each issue type maps to a queue. A queue holds waiting contacts in order.
  3. Green/red sign = presence. Each agent has a state (available, busy, after-contact work, offline) and a capacity (for example 1 voice call or up to N chats).
  4. Who goes next = matching. A router pairs the oldest waiting contact with the best free agent - like Uber pairing a rider with a nearby driver.
  5. Notes = real-time chat. Messages travel over a WebSocket both ways and are saved for history.
  6. Never forget a kid = durability. A contact is a row in a database with a state machine. It can be re-queued but never silently dropped.

From your world

This is a call-admission and scheduling problem you already know from networking. Skill queues are like per-class QoS queues on a router port. Agents are the servers draining them. Agent capacity is a token count, like credits in credit-based flow control. "Never drop a contact" is the difference between a lossless queue with backpressure and a tail-drop queue. And the router choosing the longest-idle agent is a work-conserving scheduler.
