Requirements

Clarify the channel first. The Amazon version is chat (text, customer-to-agent). The Flipkart version is voice calls into a helpline. The routing core is the same; only the media path differs. Design for chat and say how voice plugs in.

Functional

  • Customer starts a chat from an order page or the help page; optionally a bot answers first.
  • System predicts the likely issue from the customer's recent orders and pre-selects the topic.
  • Contact is routed to a skill queue, then to an available agent with that skill and spare capacity.
  • Customer sees queue position and estimated wait; agent sees order context on screen.
  • Real-time messages both ways, typing indicator, delivered/read receipts, attachments (photo of damaged item).
  • Agent can transfer to another queue or agent and escalate to a supervisor.
  • Full chat history: customer can resume later; the next agent sees the transcript.
  • After close: summary, disposition code, satisfaction survey.

Out of scope (say so): the bot's NLP internals, agent workforce scheduling, the knowledge base, billing.

Non-functional

  • No dropped contacts. Once accepted, a contact must reach an agent or an explicit end state (callback, email, abandoned by customer). This was the stated rule in the Flipkart round.
  • Never double-assign a contact to two agents, never exceed an agent's capacity.
  • Message latency under ~500 ms end to end (Slack reports about 500 ms worldwide for its messaging).
  • Routing latency: offer to an agent within a second or two of one becoming free.
  • Spiky load: a delivery outage or a sale day can multiply contacts within minutes (the Amazon follow-up).
  • Availability 99.9%+ for chat; history must be durable (compliance - Amazon Connect keeps contact records for 24 months).
  • Privacy: agents see only the orders relevant to this customer; PII masked in logs.

Ask early: "Chat, voice, or both? Is a bot in front? How many agents and what peak? Can an agent handle several chats at once?" The last answer changes the matching from "one agent per contact" to "capacity slots per agent", which is the most interesting part.
