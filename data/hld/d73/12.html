Quick quiz

Chats arrive at 50/s and each spends 10 minutes in the system. Roughly how many chats are open at once?

  1. 500
  2. 3,000
  3. 30,000
  4. 300,000
Little's law: 50/s x 600 s = 30,000.

Two router instances both try to give the last free slot of agent A1 to different contacts. What stops both succeeding?

  1. A Redis sorted set ordered by wait time
  2. A conditional UPDATE on used < max inside a transaction
  3. Kafka ordering on the contact-events topic
  4. The WebSocket gateway's sticky sessions
Only the guarded update in the database serialises the two writers; the loser updates 0 rows and retries.

An agent gets an offer but their laptop is closed. What should happen?

  1. Offer expires, slot is freed, contact goes back to the front of the queue
  2. The contact stays assigned until the agent comes back
  3. The contact is closed with "agent unavailable"
  4. The router waits for a manual supervisor action
Offers must expire. Re-queue at the front so the customer does not lose their place.

Why is it a mistake to make Redis the only store for waiting contacts?

  1. Redis sorted sets cannot order by time
  2. Redis is too slow for 35 inserts per second
  3. Redis cannot be clustered
  4. A failover can lose recent writes, breaking "no dropped contact"
Redis replication is asynchronous by default, so failover can lose writes. Keep SQL as truth and Redis as a rebuildable index.

The intent predictor times out. What does the contact service do?

  1. Return an error and ask the customer to retry
  2. Route to the general queue and continue
  3. Wait until the model responds
  4. Put the contact on hold without a queue
Prediction is an optimisation. It must never block or fail contact creation.

Which store suits chat messages best at this scale?

  1. The same SQL table as contacts, with a JOIN per read
  2. Kafka with infinite retention as the only store
  3. A NoSQL table partitioned by contact_id, sorted by seq
  4. An in-memory map on the gateway
Append-only, high volume, read by one key in order: classic partition key + clustering key.

The best agents get far more contacts than others under "most idle agent" with skill priority. What helps?

  1. An occupancy cap per agent
  2. Removing skills from the best agents
  3. Random assignment
  4. Making contacts pull-based
Occupancy-aware routing leaves an over-occupied agent idle briefly and spreads load.
