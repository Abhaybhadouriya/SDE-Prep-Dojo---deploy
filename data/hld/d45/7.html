Where Kafka, Kubernetes and Docker fit

What Reddit actually used. RabbitMQ for its job queues (votes, comments, thumbnails, precomputed queries, spam). ByteByteGo's summary adds Kafka for real-time streams for content safety and moderation rules, Debezium change data capture to keep caches consistent, and AWS + Kubernetes for hosting (ByteByteGo: Reddit's core architecture).

How you would build the vote pipeline on Kafka today:

  • A topic votes with, say, 64 partitions. The producer key is community_id, so all votes for one community land in one partition and are read by exactly one consumer in the group. That gives you Reddit's "one writer per listing" for free, with ordering per partition (Consumer groups, Kafka core concepts).
  • Split per query type, like Reddit did: a separate topic for domain listings keyed by domain, and one for profile listings keyed by author.
  • Hot key problem: one giant community can still overload its one partition. Fix: key by community_id + bucket and merge the small per-bucket listings, or pre-aggregate deltas in a short window before mutating the listing (Kafka Streams or Flink, see Kafka Connect, Streams & Flink).
  • Retention gives you replay: if a listing gets corrupted, rebuild it by re-consuming from an offset. Bounded topics also play the role of Reddit's queue quotas.
  • Consumer lag per partition is your key alert. It is the "vote queue depth" that warned Reddit.

Kubernetes: API, listing, vote and comment services are stateless Deployments behind a Service and an Ingress. Vote workers scale on consumer lag (for example with KEDA on top of the HorizontalPodAutoscaler) but never above the partition count, since extra consumers sit idle (Scheduling & Autoscaling). Cassandra, if self-run, is a StatefulSet with an operator (StatefulSets & Operators). Reddit's 2016 lesson applies directly: "stateful services are very different from stateless ones, don't use the same tooling for them". Give cache pods PodDisruptionBudgets and never let an autoscaler kill many cache nodes at once.

Docker: each service ships as one image; the same vote-worker image runs with a different QUEUE_KIND=subreddit|domain|profile environment variable (Dockerfile).
