Key APIs

# Create a post (idempotency key stops duplicate posts on retry)
POST /v1/r/{community}/posts
  { "title": "...", "kind": "text|link|image", "body": "...", "url": "...", "idempotency_key": "uuid" }
  -> 201 { "post_id": "t3_9xk2", "created_at": "..." }

# Vote: PUT-like semantics. Sending the same direction twice changes nothing.
POST /v1/things/{thing_id}/vote
  { "dir": 1 }          # 1 = up, -1 = down, 0 = remove my vote
  -> 202 { "your_vote": 1 }     # accepted; score updates asynchronously

# A listing (cursor pagination: "after" is the last post id you saw)
GET /v1/r/{community}/listing?sort=hot|new|top|controversial&t=day&after=t3_9xk2&limit=25

# A post with its comment tree, cut at a depth and a count
GET /v1/posts/{post_id}/comments?sort=best&depth=8&limit=200
# Expand a collapsed branch ("load more comments")
GET /v1/posts/{post_id}/morechildren?children=t1_a,t1_b,t1_c&sort=best

# Reply
POST /v1/posts/{post_id}/comments  { "parent_id": "t1_a", "body": "..." }

# Home feed (joined communities, or followed topics on Quora)
GET /v1/feed?sort=best&after=cursor

Notes for the interviewer:

  • The vote API takes the desired state (up, down, none), not "add one". Setting state is naturally idempotent: two identical requests leave the same result. Reddit's public API uses the same idea, a dir of 1, 0 or -1.
  • Return 202 Accepted for votes: the record of your vote is stored now, the score and ranks follow later.
  • Use cursor pagination on listings. Offsets break when posts move up and down between page loads (more in API Design).
