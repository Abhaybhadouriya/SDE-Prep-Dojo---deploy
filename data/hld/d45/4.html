Data model

Reddit's original data model, the Thing model, is worth knowing because it is unusual. Each noun (link, comment, account, subreddit) gets two PostgreSQL tables: a thing table with fixed columns needed for sorting and filtering (id, ups, downs, deleted, spam), and a data table of key/value rows for every other property (title, url, body...). New features add keys, not columns, so no schema migrations (reddit wiki: Architecture Overview, QCon 2017 slides). The cost is more joins, which is why the whole Thing object is cached in memcached.

In an interview, draw a cleaner version and mention the Thing model as a real-world twist:

SQL or NoSQL, and why

DataStoreWhy
Posts, comments, users, communitiesPostgreSQL / MySQL, shardedModerate write rate, needs secondary indexes and transactions (post + author karma). Reddit uses Postgres; Quora uses MySQL (tens of terabytes, hundreds of thousands of QPS, per Quastor's summary of Quora's post).
Vote recordsCassandra (or DynamoDB)Highest write rate, simple key access, must survive node loss. Reddit moved votes to Cassandra and calls it a big win (High Scalability).
Precomputed listingsCassandra for durability, memcached for readsReddit's slides: the listing cache "isn't really a cache anymore", it is a denormalized index persisted in Cassandra and read from memcached.
Ads, premium, paymentsRelational, strongly consistentMoney needs transactions (Reddit keeps it relational).
Images, videoObject store + CDNBig immutable blobs.

Sharding. Shard comments by post_id so a whole thread is on one shard (one query, no scatter). Shard posts by post_id too; the community listing index tells you which posts to fetch. Quora chose range-based sharding for its big tables because range queries were its most common pattern, and keeps the shard map in ZooKeeper (systemdesign.one).
