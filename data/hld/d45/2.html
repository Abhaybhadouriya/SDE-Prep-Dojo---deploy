Back-of-envelope estimation

We anchor on Reddit's published 2017 numbers and mark everything else as an assumption. Method from Back-of-Envelope Estimation: 1 day is about 86,400 s, round to 105 when you are in a hurry.

Step 1: write QPS (from published numbers)

EventPer day (source)Average per secondPeak (assume 3x)
Posts1M1,000,000 / 86,400 = ~12/s~35/s
Comments5M5,000,000 / 86,400 = ~58/s~175/s
Votes75M75,000,000 / 86,400 = ~870/s~2,600/s

Lesson: the raw write rate is small. One well-tuned Postgres primary can take a few thousand simple writes per second. So why did Reddit's vote queue back up for hours in 2012? Because each vote is not one write. It fans out into many cache and listing updates (deep dive 3). Interviewers want you to spot that.

Step 2: read QPS (assumptions)

  • Assume 50M daily active users, each loading 20 pages a day: 50M x 20 = 1 billion page views a day.
  • 1,000,000,000 / 86,400 = ~11,600 views/s average, ~35,000/s at a 3x peak.
  • Each page needs 1 listing read + 25 post objects, or 1 post + up to 200 comments. With batching (one multi-get per page), that is roughly 35k listing reads/s and 35k batched object reads/s at peak.
  • Read:vote ratio = 11,600 / 870 = about 13 page views per vote, and far higher per post. Caching listings is the main lever.

Text is cheap. Images and video dominate bytes, and they go to an object store behind a CDN (see S3-like Object Storage), not into the database.

Step 4: cache size for listings

  • A listing entry is (post_id 8 B, sort score 8 B) = 16 B.
  • Keep the top 1,000 entries per (community, sort): 1,000 x 16 B = 16 KB per listing.
  • Assume 100,000 active communities x 6 sorts (hot, new, rising, top day/week/all) = 600,000 listings x 16 KB = ~9.6 GB. That fits in RAM on a small memcached or Redis cluster, with room for post objects too.

Step 5: bandwidth

  • Assume a listing API response is 50 KB of JSON (thumbnails are separate CDN fetches): 1B views x 50 KB = 50 TB/day.
  • 50 TB / 86,400 s = ~580 MB/s = ~4.6 Gbit/s average, ~14 Gbit/s peak. Reddit puts a CDN in front and serves logged-out users from fully cached pages (High Scalability, 2013), so the origin sees only a fraction.

From your world

This is the control plane vs data plane split you know from routers. Votes are like routing updates: rare, but each one can touch many entries. Page views are like packet forwarding: huge volume, must be a cheap lookup. You never run the routing algorithm per packet; you precompute a FIB. Reddit never runs ORDER BY hot per page view; it precomputes listings.
