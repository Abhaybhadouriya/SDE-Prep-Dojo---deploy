Quick quiz

The vote API should accept:

  1. "Increment the upvote count by 1 and return the new count"
  2. "Toggle my vote, flipping whatever the server stores now"
  3. "Here is the new total score the client computed"
  4. "Set my vote on this item to +1, 0 or -1"
Setting state is idempotent; the server computes the delta from the old state, so retries never double count.

In Reddit's hot formula, how much newer must a post be to tie with one that has 10x its score?

  1. 12.5 hours (45,000 s)
  2. 45 minutes, since the time constant is 45 minutes
  3. 1 hour, because the formula counts hours since epoch
  4. About 4 hours, because log10 of 10x adds only a little
Time is divided by 45,000 s = 12.5 h, and 10x score adds 1 to log10.

Why does Reddit's hot score not need to be recomputed every minute for old posts?

  1. Old posts fall out of the cache, so their score is never read
  2. Votes on old posts freeze after 24 hours, so scores never move
  3. It uses the post's creation time, not the current time
  4. The CDN recomputes it lazily whenever the cached page expires
All posts age equally relative to each other, so ordering only changes when votes arrive.

Which comment ranks higher by Wilson lower bound: 1 up / 0 down, or 100 up / 1 down?

  1. 1 / 0, because a 100% positive ratio always wins
  2. They tie, since both are close to 100% positive
  3. 1 / 0, because Wilson heavily penalises any downvote
  4. 100 / 1, since more votes give a surer estimate
At 80% confidence, 1/0 scores about 0.38 and 100/1 about 0.97.

Reddit's vote queue backed up and adding consumers made it worse. The root cause was:

  1. Lock contention on shared listing updates
  2. Slow disks on the Cassandra vote store
  3. Network bandwidth between workers and the broker
  4. Rebalance storms every time a new worker joined
Many workers waited on the same listing mutation lock; partitioning by subreddit fixed it.

What is the best shard key for comments?

  1. comment author, so a user's profile page is one read
  2. post_id, so a thread lives on one shard
  3. random, so writes spread evenly over every shard
  4. comment_id, so each comment has its own home
The hot read is "all comments of a post". Author lookups can use a secondary index.

Why is pull-and-merge a good home feed for Reddit?

  1. Push feeds cannot show live scores, so ranking would always be stale
  2. It needs no cache, because listings are read straight from Postgres
  3. It is the only feed model where hot ranking can be computed at all
  4. Shared community listings exist; pushing to millions would explode writes
Fan-out on write is costly for huge communities; merging precomputed listings is cheap.

A user taps upvote on a phone and a laptop at the same moment. With "read the old direction, then upsert the new one" as two separate steps, what can go wrong?

  1. Nothing: the upsert on (user_id, thing_id) already makes it idempotent
  2. Both reads see old = 0, so the counter gets +1 twice for one vote
  3. The second upsert fails on the primary key and the vote is lost
  4. The Bloom filter gives a false negative and the vote is skipped
The vote row stays correct (one row), but both workers computed a delta from the same stale old value. Do the read and upsert as one atomic step that returns the previous value, or serialise per (user_id, thing_id) through one queue partition.
