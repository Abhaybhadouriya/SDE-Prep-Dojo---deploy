Forward proxy, reverse proxy, load balancer, API gateway

These four words get mixed up constantly. They are all "a box in the middle that forwards traffic". The difference is whose side the box is on and how much of the request it reads.

The system design primer lists what a reverse proxy gives you, even in front of a single server: it hides backend IPs, can block IPs and limit connections per client, terminates SSL so app servers do not need certificates, compresses responses, caches responses, and serves static files. A load balancer is a reverse proxy whose main job is spreading load across many identical servers. An API gateway is a reverse proxy that understands your API: it routes different paths to different services and runs cross-cutting rules like authentication and rate limiting.

"The same software can play all three roles. NGINX or Envoy can be a reverse proxy, an L7 load balancer and a simple gateway at once. In my diagram I separate them by job, not by product." That single sentence clears up the most common confusion interviewers probe.
