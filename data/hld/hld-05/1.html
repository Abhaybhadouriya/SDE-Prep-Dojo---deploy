The journey of one request

Here is the full path for a request like GET /api/orders/42 to shop.example.com from a phone. Each hop has one job. Watch the dots: the green one is a static image served from the CDN edge, the orange one is an API call that goes all the way to a service.

  1. DNS turns shop.example.com into an IP address. The answer is cached for its TTL (time to live, in seconds).
  2. CDN edge (content delivery network) is a server in a city near the user. It keeps copies of files and sometimes whole API responses. If it has the answer, the trip ends here.
  3. Load balancer (LB) is the front door of a region. It spreads connections across many identical machines and hides failed ones.
  4. API gateway checks who you are, applies rate limits, and decides which service gets the request based on the path, such as /api/orders going to the order service.
  5. Services do the real work and talk to databases, caches and queues. Those parts get their own pages.

Tip: in an interview you usually draw the LB and the gateway as one box ("LB + gateway") and spend no more than a minute on it. Hello Interview's API gateway guide says over-investing in the gateway is a more common mistake than under-investing. Go deeper only when the question is about the network itself, like designing a load balancer or a video CDN.
