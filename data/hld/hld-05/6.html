TLS termination: where does the encryption stop?

TLS termination means the box that holds the certificate and private key decrypts the traffic. Anything after it sees plaintext unless you encrypt again. There are three standard choices:

OptionProsConsTypical use
Terminate at LB/edgeOne place for certs; L7 routing, WAF (web application firewall), caching; backends save CPUPlaintext inside the networkMost web apps inside a trusted VPC
Re-encrypt (TLS or mTLS to backends)L7 features and encryption everywhereDouble crypto cost; certificate management for every servicePayments, health data, zero-trust, service mesh (Istio, Linkerd)
PassthroughLB never sees keys or dataNo L7 routing (only SNI), no WAF, no HTTP retriesStrict compliance, non-HTTP TLS, databases

Two terms from the table. A WAF (web application firewall) is an L7 filter that reads HTTP requests and blocks attack patterns such as SQL injection and cross-site scripting (XSS); it can only work where TLS has been decrypted. SNI (Server Name Indication) is the hostname the client sends in clear inside the TLS ClientHello, before encryption starts, so a passthrough LB that never decrypts can still route api.example.com and shop.example.com to different pools.

mTLS (mutual TLS) means both sides present certificates, so a service knows which service is calling it. Service meshes give every pod a sidecar proxy that does mTLS automatically. Terminating TLS at the CDN edge also cuts latency: the expensive handshake round trips happen with a server 10 ms away instead of 150 ms away, and the edge keeps warm, long-lived connections back to the origin.
