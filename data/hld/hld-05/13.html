Quick quiz

Your region failed and you changed DNS, but many users still reach the dead region for minutes. Why?

  1. Resolvers and clients cache the old answer for the TTL, sometimes longer
  2. DNS uses TCP and the connections are still open
  3. The authoritative server is down
  4. Anycast routes have not converged
DNS answers are cached at every layer until the TTL expires, and some caches ignore short TTLs. That is why DNS picks regions, not servers.

Which load balancer can send /images/* to one pool and /api/* to another?

  1. L7, because it reads the HTTP request
  2. L4, because it is faster
  3. Either, if you enable sticky sessions
Path routing needs the HTTP request line, which only an L7 balancer that terminates the connection can read.

After scaling a gRPC service from 3 to 9 pods behind an L4 balancer, the new pods are idle. The main reason is:

  1. gRPC uses UDP
  2. gRPC multiplexes many calls on one long-lived HTTP/2 connection, and L4 balances connections
  3. The new pods failed their health checks
L4 picks a backend once per connection. Long-lived HTTP/2 connections keep all calls on the original pods. Use L7 or client-side balancing.

What problem does HTTP/3 fix that HTTP/2 could not?

  1. Text headers
  2. Only one request per connection
  3. A lost TCP packet stalling every multiplexed stream
  4. Lack of encryption
HTTP/2 already multiplexes and compresses headers, but over TCP a single loss blocks all streams. QUIC makes stream ordering independent.

Why should 0-RTT early data be used only for safe, idempotent requests?

  1. It is not encrypted
  2. It only works with HTTP/1.1
  3. It can be replayed by an attacker
Early data is sent before the handshake proves freshness, so it can be captured and resent. A replayed "pay" request would charge twice.

Which is the best way to update a cached JavaScript file on a CDN?

  1. Give the new file a new versioned or content-hashed URL
  2. Set TTL to 0 for everything
  3. Purge the whole CDN on every deploy
  4. Ask users to clear their cache
A versioned URL is a new cache key, so there is nothing stale to purge, and the old version can stay cached for a year with immutable.

Which load balancing algorithm fits a fleet of WebSocket servers best?

  1. Plain round robin
  2. Least connections
  3. DNS round robin only
Connections are long-lived, so the number of open connections is the right load signal. After a deploy, least-connections steers new connections to the empty servers, while round robin keeps giving the already-full ones an equal share, because existing long-lived connections never move.

A page loads 30 small images over HTTPS from one server that only speaks HTTP/1.0 without keep-alive. What dominates the load time?

  1. 30 separate TCP and TLS handshakes, each starting in slow start
  2. Header compression
  3. Head-of-line blocking inside one TCP connection
HTTP/1.0 closes the connection after each response, so every image pays a fresh handshake. HTTP/1.1 keep-alive removed that cost; HTTP/2 then multiplexed requests over one connection.
