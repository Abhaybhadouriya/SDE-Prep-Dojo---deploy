Key APIs

REST over HTTPS, with JSON bodies. The shapes below follow the spirit of the public Google Calendar API and Microsoft Graph, simplified. See API Design & Client-Server Communication.

# Create an event (idempotency key makes a retried POST safe)
POST /v1/calendars/{calendarId}/events
Idempotency-Key: 7c1e...
{ "summary": "Team sync",
  "start": {"dateTime": "2026-12-01T09:00:00", "timeZone": "America/New_York"},
  "end":   {"dateTime": "2026-12-01T09:30:00", "timeZone": "America/New_York"},
  "recurrence": ["RRULE:FREQ=WEEKLY;BYDAY=TU"],
  "attendees": [{"email": "asha@example.com"}, {"email": "li@example.com"}],
  "reminders": {"overrides": [{"method": "popup", "minutes": 10}]} }

# Read a range (server expands recurring series into instances)
GET  /v1/calendars/{calendarId}/events?timeMin=...&timeMax=...&singleEvents=true&tz=Asia/Kolkata

# Edit one occurrence, or this-and-following
PATCH /v1/calendars/{calendarId}/events/{eventId}/instances/{originalStart}
PATCH /v1/calendars/{calendarId}/events/{eventId}?scope=thisAndFollowing&from={originalStart}

# RSVP as an attendee
POST /v1/events/{eventId}/rsvp   { "response": "accepted" }

# Free/busy for many people (returns only busy intervals, no titles)
POST /v1/freeBusy  { "timeMin": "...", "timeMax": "...", "items": [{"id": "asha@example.com"}] }

# Incremental sync for a device
GET  /v1/calendars/{calendarId}/events?syncToken=abc123   -> changes + nextSyncToken (410 Gone = full resync)

Three details make these APIs production-grade:

  • Instance IDs. Google gives every occurrence its own id but all occurrences of a series share one iCalUID. A moved occurrence keeps an immutable originalStartTime so the system can still tell which slot of the rule it replaced.
  • Bounded free/busy. Google's freeBusy call caps calendarExpansionMax at 50 calendars and groupExpansionMax at 100 group members per request (freeBusy reference). Limits like these protect the backend from a "query the whole company" request.
  • Sync tokens. A client saves nextSyncToken, then asks only for changes since that token. If the server returns 410 Gone (token expired or access changed), the client wipes its local copy and does a full sync (sync guide).
