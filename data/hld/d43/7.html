Where Kafka, Kubernetes and Docker fit

ToolJob in this designDetails
KafkaBackbone for derived viewsTopic event-changes keyed by event_id (per-event order). Consumers: invite fan-out, recurrence expander, reminder scheduler, search indexer, sync push. A second topic reminders-due decouples the ticker from slow delivery. Replay the topic to rebuild a broken index. See Consumer groups and Kafka Connect / CDC.
KubernetesRuns every stateless serviceEvent service and API pods scale on CPU with HPA. Ticker workers run as a Deployment whose replicas each lease a range of reminder shards; scale them up before the 09:00 Monday peak with a scheduled scaler, because reactive autoscaling is too slow for a 60-second spike. See Scheduling & Autoscaling.
DockerPackagingEach service is one image. The tzdata package is baked into the image, so a DST rule change means rebuilding and rolling out images; pin and track tzdata versions. See Docker in production.

Careful: a slim base image without tzdata makes every zone silently fall back to UTC. That bug shows up only for users outside UTC, which may be all of them.
