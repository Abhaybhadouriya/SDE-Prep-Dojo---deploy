How real systems do it

  • Google Calendar API (events doc, sync guide) models a recurring event as a parent plus instances. Every instance has its own id, all share an iCalUID, and a changed instance is an "exception" with fields such as a different time or extra attendees. Up to 5 reminder overrides per event, each 0-40,320 minutes before start. Sync uses nextSyncToken with a 410 full-resync fallback.
  • Microsoft Graph / Outlook (findMeetingTimes doc) exposes findMeetingTimes, which suggests slots by averaging each attendee's chance of attendance and by default only searches the organizer's work hours (Monday to Friday, 8am to 5pm in the mailbox time zone, unless configured).
  • Airbnb Dynein (repo, InfoQ) is an open-source delayed job queue: delayed jobs go to an SQS inbound queue that buffers writes, a scheduler stores triggers in DynamoDB and dispatches overdue ones to service queues, conditional updates prevent duplicates, and the target is for most jobs to run within 10 seconds of their time.
  • Meta FOQS is a distributed priority queue on sharded MySQL where every item has a deliver_after time, dequeued items carry a lease, and a nack pushes deliver_after forward for backoff. Meta reports close to one trillion items per day (Meta engineering). It shows that a "deliver at time T" queue on a relational store can scale enormously.
