The story

Explain like I'm 5

Imagine a robot librarian who wants a copy of every book in a huge city. It starts with a short list of addresses. At each house it reads the book, makes a copy, and writes down every new address the book mentions. Then it walks to the next address on its list.

The robot has three good manners. First, it reads the sign on each front door ("please do not enter the kitchen") and obeys it. Second, it never knocks on the same house again and again in one minute, because that would be rude. Third, it keeps a notebook of houses it already visited, so it does not copy the same book twice. And because the city is so big, there are many robots, and each robot gets its own streets so they do not bump into each other.

A web crawler (also called a spider or bot) is a program that downloads web pages, finds the links inside them, and then downloads those links too. Search engines (Google, Bing), archives (the Internet Archive, Common Crawl) and price trackers all run crawlers. In code, the core is a loop you could write in ten lines: take a URL from a to-do list, download it, pull out the links, add the new ones to the to-do list. The interview is about everything that breaks when that loop runs on hundreds of machines against billions of pages owned by other people.

New words, defined once:

  • URL frontier - the to-do list of URLs waiting to be fetched. It is the heart of the design.
  • Seed URLs - the first URLs you put in the frontier (popular home pages, sitemaps).
  • Politeness - rules that stop you from overloading one website (one connection per host, a delay between requests).
  • robots.txt - a small text file at the root of a site (for example https://example.com/robots.txt) that tells crawlers which paths they may not fetch. It is standardised as RFC 9309.
  • Dedup - removing duplicates: duplicate URLs (we already queued it) and duplicate content (two URLs, same page).
  • Crawler trap - a site that produces endless unique URLs, such as a calendar with a "next month" link that never ends.

Reported in the wild: candidates have reported "design a web crawler" in Atlassian system-design rounds (P40 and up), and it is a classic chapter in the standard prep books. The interviewer is testing one thing above all: can you design a queue with constraints (priority + politeness + dedup) and keep it alive when workers die?
