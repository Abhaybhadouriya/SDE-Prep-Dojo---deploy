Key APIs

Keep the API small. Tiles are plain cacheable GETs; navigation uses a long-lived connection.

GET  /tiles/{z}/{x}/{y}.mvt                 -> vector tile (Cache-Control: max-age=86400, ETag)
GET  /geocode?q=221B+Baker+Street            -> [{place_id, lat, lng, name, confidence}]
POST /routes                                 -> {routes:[{route_id, polyline, eta_s, distance_m, steps[]}]}
     body: {origin:{lat,lng}, destination:{lat,lng}, mode:"driving", depart_at, avoid:["tolls"]}
POST /locations/batch                        -> 202 Accepted
     body: {session_id, route_id, points:[{t, lat, lng, speed, heading, accuracy}, ...]}
WS   /navigation/{session_id}                -> server pushes {type:"eta_update"|"reroute", ...}
  • Tiles are addressed by z/x/y, so the URL itself is the cache key - perfect for a CDN.
  • Location batches return 202 immediately; the work is done asynchronously through a queue. Use a session_id (a random per-trip id), not the user id, to help privacy.
  • Navigation updates are pushed (WebSocket or a push channel) because the server learns about a jam before the client does. See Pattern: Real-time Updates.
