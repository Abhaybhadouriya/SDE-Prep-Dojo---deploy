How the real companies do it

  • YouTube metadata: Vitess history explains why YouTube built a sharding layer over MySQL in 2010 instead of moving to a new database. The code is vitessio/vitess, now a CNCF graduated project.
  • YouTube uploads: the Data API resumable upload protocol shows the session URI, Content-Range and 308 resume flow in detail.
  • What creators should upload: YouTube recommended upload encoding settings (containers, codecs, bitrates) tell you what the pipeline expects as input.
  • Copyright checks: How Content ID works describes matching uploads against reference files from rights owners.
  • Netflix: the InfoQ summary of Netflix Cosmos covers a workflow-driven media platform that encodes in chunks in parallel, the same split-and-fan-out idea. Netflix's tech blog also has posts on per-title encoding (open it in a browser; it blocks scripts).
  • A full interview walkthrough: Hello Interview: Design YouTube covers presigned multipart uploads, the DAG and ABR.
