Key APIs

Three groups: start an upload, send the bytes, and ask for status or playback. Real systems give the bytes a separate path from the control calls.

Before the code: a presigned URL is a URL the storage service has signed so whoever holds it can PUT exactly one object until it expires, with no other credentials. That makes it a bearer token: possession = permission. The ETag in the reply is a checksum the store returns per part.

# 1. Create the video and an upload session (control plane, small JSON)
POST /v1/videos
Idempotency-Key: 6f1c...            # retrying the button must not make 2 videos
{ "title": "My trip", "visibility": "private",
  "file_size": 4294967296, "content_type": "video/mp4", "sha256": "ab12..." }
-> 201 { "video_id": "v_9Kx2", "upload_id": "u_77",
         "part_size": 16777216,
         "parts": [ { "n": 1, "url": "https://raw-bucket...&X-Amz-Signature=..." }, ... ] }

# 2. Send the bytes straight to blob storage (data plane, no app server)
PUT {presigned url for part n}      body = 16 MB of bytes
-> 200  ETag: "a54357aff0632cce46d942af68356b38"

# 3. Ask which parts the server already has (after a crash or network change)
GET /v1/uploads/u_77
-> 200 { "received": [1,2,3,5], "missing": [4,6,7,...] }

# 4. Finish: the server stitches parts into one object
POST /v1/uploads/u_77/complete  { "parts": [ { "n":1, "etag":"a5..." }, ... ] }
-> 202 { "video_id": "v_9Kx2", "status": "PROCESSING" }

# 5. Status and playback
GET /v1/videos/v_9Kx2           -> { "status": "READY", "renditions": ["240p","720p","1080p"], ... }
GET https://cdn.example.com/v_9Kx2/master.m3u8     # the player starts here

YouTube's public Data API uses a slightly different resumable style that is worth knowing. The client first gets a session URI, then sends bytes with a Content-Range header. If the connection breaks, it sends an empty PUT with Content-Range: bytes */TOTAL, and the server answers 308 Resume Incomplete with a Range header that says how many bytes it already has. The client continues from there. (See the resumable upload guide.) Both styles solve the same problem; the S3-style parts can also be sent in parallel.

Careful: a presigned URL is a bearer token. Give it a short expiry (minutes to an hour per part), scope it to one key and one HTTP method, and set a maximum size. Never sign a URL for a key the client chose freely.
