Remember this

  • Two hops: server to client (polling, SSE, WebSocket, WebRTC) and source to the right server (poll, registry/hash, pub/sub).
  • Pick hop 1 by "who talks and how often": one-way feeds = SSE; two-way chatty = WebSocket; slow = polling; media = WebRTC.
  • Store first, then push. The socket is a lossy notifier; clients resume by sequence number.
  • Order is per conversation, by routing it through one owner.
  • Gateways are thin and stateless in logic; connections are their only state.
  • Defend against reconnect storms: jitter, dithered lifetimes, slow drains, fail-fast dependencies.
  • Capacity is memory and file descriptors, not CPU: think 100k-1M sockets per box with tuning.
