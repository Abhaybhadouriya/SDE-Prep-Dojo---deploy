The story

Explain like I'm 5

Imagine a teacher who checks math homework. Thousands of kids slide their homework under the door. The teacher cannot let any kid into the classroom, because one naughty kid might draw on the walls or steal the answer key. So the teacher puts every homework into its own glass box. Inside the glass box the homework "runs", the teacher watches the clock, and if it takes too long, the box is closed. Then the teacher writes a sticker: "Correct!", "Wrong answer" or "Too slow". On contest day, a huge crowd arrives at once, so the teacher calls in many helper teachers, each with their own stack of glass boxes, and a big scoreboard on the wall shows who is winning.

That is the whole design. The homework is a code submission. The glass box is a sandbox - an isolated place where untrusted code runs without being able to hurt the host machine. The helper teachers are workers that pull jobs from a queue. The sticker is the verdict (Accepted, Wrong Answer, Time Limit Exceeded, and so on). The scoreboard is the contest leaderboard.

What makes this design special is simple: almost every other system on this site protects itself from bad requests; this one is built to run hostile programs on purpose. That makes it the one HLD question where a Linux kernel background is a real advantage. Namespaces, cgroups, seccomp and rlimits are exactly the tools you need, and you already know them.

This problem appears in five independent curricula (Hello Interview, Educative, Grokking Advanced, AlgoMaster, interviewing.io's "remote compiler") and is self-reported as a Flipkart SDE-2 HLD question ("LeetCode-like platform"). Interviewers use it to see if you understand that executing code is the hard part, not storing problems.
