Key APIs

Keep the API small. Notice that userId and timestamps are never accepted from the client - the server reads the user from the session and stamps the time itself, otherwise a contestant could fake an earlier submission time.

GET  /problems?page=1&limit=100&tag=graphs     -> [{id, title, level, tags}]
GET  /problems/{id}?language=python            -> {statement, sampleTests, codeStub}

POST /problems/{id}/submissions                -> 202 {submissionId, status:"QUEUED"}
     body: {language, code, mode:"run"|"submit", contestId?}
     header: Idempotency-Key: <uuid generated by the browser>

GET  /submissions/{submissionId}               -> {status, verdict?, failedTest?, timeMs, memoryKb}

GET  /contests/{contestId}/leaderboard?top=100 -> [{rank, userId, solved, penaltySec}]
GET  /contests/{contestId}/leaderboard/me      -> {rank, solved, penaltySec}

Submit returns 202 Accepted immediately with an id, because running 100 tests takes seconds. The browser then polls GET /submissions/{id} about once per second. Hello Interview points out that LeetCode itself uses this polling pattern - you can watch it in the browser's network tab. WebSockets or Server-Sent Events would also work (see Real-time Updates), but for a one-second wait a simple poll is cheaper to run.

The Idempotency-Key stops a double click or a retried request from creating two submissions - which would count as two attempts and add a penalty in a contest.
