SQL or NoSQL? Either works; the queries are simple key lookups. Hello Interview picks DynamoDB and nests tests inside the problem document. We prefer keeping the test files in object storage with only a manifest in the DB: some inputs are megabytes, workers download and cache them, and a testSetVersion lets admins fix a broken test without corrupting history. Submissions are append-mostly and keyed by id, so a key-value store or a sharded Postgres (see Choosing Storage) both fit.

CREATE TABLE submission (
  submission_id  BIGINT PRIMARY KEY,         -- Snowflake-style id, time-ordered
  user_id        BIGINT NOT NULL,
  problem_id     INT    NOT NULL,
  contest_id     INT,
  language       VARCHAR(16) NOT NULL,
  code_ref       TEXT   NOT NULL,            -- inline for small code, or an object key
  status         VARCHAR(12) NOT NULL,       -- QUEUED | RUNNING | DONE
  verdict        VARCHAR(8),                 -- AC | WA | TLE | MLE | RE | CE
  time_ms        INT, memory_kb INT,
  created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
  idempotency_key UUID UNIQUE
);
CREATE INDEX ON submission (contest_id, user_id, problem_id);
