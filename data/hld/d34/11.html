  • The hard part is running hostile code; storage is tiny, CPU-seconds are spiky.
  • Async flow: 202 + id, queue, language worker pools, poll the status from cache.
  • Sandbox = namespaces + cgroups + seccomp + no network + read-only FS + non-root, plus a second wall (gVisor or microVM).
  • Time limits use CPU time; wall time only catches sleepers; pin cores for fairness.
  • Contest math: 10k x 100 tests x 100 ms = 100k CPU-s, about 1,667 cores per minute; pre-scale and autoscale on queue depth.
  • Leaderboard: Redis sorted set with an encoded score; cache a top-N snapshot for reads.
  • At-least-once jobs need idempotent verdict and leaderboard writes.
