  • Every special index is "cheap filter to a candidate set, then exact check".
  • B-trees cannot keep 2D neighbours together. Map location to cell IDs or use a spatial tree.
  • Geohash: interleaved bits, base-32, prefix = area. Always query the 3x3 neighbours and post-filter.
  • Quadtree adapts to density, lives in memory, suits static places. R-tree/GiST indexes shapes (PostGIS).
  • S2: cube + Hilbert curve, 64-bit IDs, levels 0-30. H3: hexagons, 16 resolutions, equal neighbour distance, used for Uber surge.
  • Moving drivers: soft state in Redis GEO, sharded by geography, about 2M writes/s for 10M drivers at 5 s.
  • Autocomplete: trie with top-K cached per node, built offline, sharded by traffic-balanced prefix, plus a small trending layer.
  • Full-text: inverted index + BM25 (k1=1.2, b=0.75). Elasticsearch is near real time and never the source of truth.
  • Vector search: HNSW is a skip-list-like graph. It trades recall for speed and costs memory (about 6 KB per 1536-dim vector, plus links).
