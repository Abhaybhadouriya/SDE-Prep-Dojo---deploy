R-tree: boxes around shapes

Points are easy. Real maps also have shapes: a delivery zone polygon, a road, a city boundary. An R-tree wraps every shape in its minimum bounding rectangle (MBR), the smallest axis-aligned box that contains it. Parent nodes hold boxes that contain their children's boxes. Like a B-tree, it is balanced, every leaf is at the same depth, and nodes are sized to a disk page. The catch is that sibling boxes can overlap, so a search may have to walk down more than one branch. The R*-tree variant uses smarter insert rules to reduce overlap.

PostGIS (the geo extension for Postgres) builds its spatial index as an R-tree on top of Postgres's GiST framework. Its workshop shows the two-step idea clearly: the && operator checks bounding boxes only (fast, slightly wrong), and functions like ST_Intersects and ST_DWithin use the box index first and then run the exact test. On the workshop author's machine, one join went from about 300 ms without an index to about 50 ms with one, and the gap grows with table size.

-- Postgres + PostGIS: restaurants within 3 km that deliver to this point
CREATE INDEX restaurants_geo_idx ON restaurants USING GIST (location);

SELECT id, name, ST_Distance(location, ST_MakePoint(77.60, 12.97)::geography) AS metres
FROM   restaurants
WHERE  ST_DWithin(location, ST_MakePoint(77.60, 12.97)::geography, 3000)
ORDER  BY metres
LIMIT  20;

Tip: If the interviewer says "the delivery zone is a polygon drawn by the restaurant", say R-tree or PostGIS. If they say "millions of drivers moving every few seconds", say encoded cells in Redis. Shape decides the index.
