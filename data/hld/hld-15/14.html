Quick quiz

You search geohash prefix tdr1v9 for drivers within 1 km and miss a driver 50 m away. Why?

  1. Geohash is only accurate to 5 km
  2. Redis rounds coordinates
  3. The driver is in a neighbouring cell with a different prefix
  4. The B-tree index is stale
Points close to a cell border can have different prefixes. Query the cell and its 8 neighbours, then filter by exact distance.

Which structure adapts its cell size to how crowded an area is?

  1. Geohash
  2. H3 at a fixed resolution
  3. Inverted index
  4. Quadtree
A quadtree splits a node only when it holds too many points, so dense areas get small cells and sparse areas stay large.

The main reason H3 uses hexagons is:

  1. Hexagons nest perfectly into parents
  2. All 6 neighbours are the same distance from the centre
  3. Hexagon IDs sort by distance
  4. They need fewer bits than squares
Equal neighbour distance makes ring queries and smoothing (surge, demand) simple. Hexagons actually do not nest perfectly, and H3 IDs are not distance-sorted.

A restaurant draws its delivery area as a polygon. Which index fits "which zones contain this address?"

  1. Trie
  2. R-tree (e.g. PostGIS GiST)
  3. Geohash prefix scan only
  4. HNSW
R-trees index bounding boxes of shapes, then an exact containment test confirms each candidate.

Why cache the top-K completions at every trie node?

  1. To make inserts faster
  2. To save memory
  3. To support fuzzy matching
  4. So a lookup is just "walk the prefix and read a list", with no subtree search
It trades memory for read latency: O(prefix length) per lookup, independent of how many queries are stored below.

In BM25, what does the parameter b (default 0.75) control?

  1. How fast repeated terms stop adding score
  2. The number of shards
  3. The IDF base
  4. How much document length reduces the score
b is length normalisation. k1 (default 1.2) controls term-frequency saturation.

About how much raw memory do 1 million float32 vectors of 1536 dimensions need, before HNSW links?

  1. About 600 MB
  2. About 60 GB
  3. About 6 GB
  4. About 6 MB
1536 x 4 bytes = about 6 KB per vector, x 1M = about 6 GB. HNSW links add only a few percent on top (about 0.1-0.3 KB per vector at M = 16), so the vectors themselves are the cost, which is why quantisation is common.
