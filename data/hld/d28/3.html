Key APIs

A CDC platform has no user-facing REST API for shoppers. Its "API" is three things: the event contract consumers read, the control API operators use, and the self-service request a team files to get a table streamed.

1. The event contract (what lands in Kafka)

Debezium emits one event per changed row. The key is the primary key; the value is an envelope with before, after, source and op (c = create, u = update, d = delete, r = read during a snapshot).

// topic: shop.public.orders    key: {"id": 1042}
{
  "before": { "id": 1042, "status": "PLACED",  "total_paise": 249900, "updated_at": 1795416000000 },
  "after":  { "id": 1042, "status": "SHIPPED", "total_paise": 249900, "updated_at": 1795416612000 },
  "source": { "connector": "postgresql", "db": "shop", "schema": "public", "table": "orders",
              "txId": 88231, "lsn": 24023128, "ts_ms": 1795416612004, "snapshot": "false" },
  "op": "u",
  "ts_ms": 1795416612311
}

A delete produces two records: an event with op: "d" (after is null), then a tombstone - same key, value null - so Kafka log compaction can eventually remove the key entirely.

2. The control API (Kafka Connect REST)

CallPurpose
POST /connectorsCreate a connector from JSON config (one per database).
GET /connectors/{name}/statusIs it RUNNING, FAILED, PAUSED? Which worker runs the task?
PUT /connectors/{name}/pause, /resumeStop reading during source maintenance.
POST /connectors/{name}/restart?includeTasks=trueRestart after a failure.
INSERT INTO debezium_signal ...Ask the connector for an incremental snapshot of a table (a "signal", see deep dive 1).

3. Self-service request (platform API)

POST /v1/cdc-streams
{
  "source": "mysql://orders-shard-*",
  "tables": ["orders", "order_items"],
  "pii_columns": { "orders": ["customer_phone"] },
  "sinks": ["lakehouse", "search:orders-index"],
  "owner": "team-orders"
}
// 201 Created -> { "stream_id": "cdc-77", "topics": ["orders.shard-00.orders", "..."], "status": "SNAPSHOTTING" }

Platform teams wrap Connect behind a request like this so 200 product teams do not each hand-write connector JSON with database passwords.
