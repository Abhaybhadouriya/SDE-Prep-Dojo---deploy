Key APIs

APICallerPurpose
POST /webhooks/gitGitHub/GitLabPush / PR / tag events. Verify the HMAC signature header, write the event to Kafka, return 200 fast.
POST /v1/runs {repo, ref, pipeline, params}UI, CLI, schedulesStart a run manually. Returns run_id.
GET /v1/runs/{id}UI, PR status checkStatus of each step, timings, artifacts.
GET /v1/runs/{id}/logs?follow=trueUILive log stream (Server-Sent Events / WebSocket).
POST /v1/runs/{id}/retry?step=EngineerRe-run one failed step with the same inputs.
POST /v1/releases {service, image_digest, envs}PipelinePromote a signed image: opens/commits a change in the GitOps repo.
POST /v1/releases/{id}/rollbackEngineer, automationRevert the GitOps commit to the previous digest.
 
POST /v1/releases
{
  "service": "payments-api",
  "image": "registry.example.com/payments/api@sha256:4c1f...e9",
  "envs": ["staging", "prod-ap-south-1", "prod-us-east-1"],
  "strategy": "canary",
  "requested_by": "pipeline/run-8812"
}
// 202 Accepted -> { "release_id": "rel-5521", "gitops_commit": "a91c3d0", "state": "SYNCING" }

Note the image is referenced by digest (@sha256:...), not a tag like :latest. A tag can be moved to point at a different image; a digest cannot. Deploying digests is what makes "what exactly runs in prod?" answerable.
