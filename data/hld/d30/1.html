Requirements

  1. Who uses it? 5,000 engineers in ~300 teams, ~2,000 services, a mix of one big monorepo and many small repos.
  2. What runs? Builds (container images), unit and integration tests, security scans, and deployments to ~50 Kubernetes clusters across regions.
  3. How fast? Pull-request feedback in under ~15 minutes p90; commit-to-production for a normal service under ~1 hour including canary.
  4. How safe? Only signed images built by the platform may run in production. No human or CI job holds long-lived production credentials.
  5. Multi-tenant? Yes. One team's 10,000-test suite must not starve another team's hotfix.
Functional
  • Trigger pipelines on push, pull request, tag, schedule or manual click.
  • Pipelines defined as code in the repo (.ci.yaml / Tekton / Actions workflow).
  • Live logs, test reports, artifacts, re-run a failed step.
  • Merge queue: main branch must always build and pass.
  • Deploy by environment (dev → staging → prod), canary with automatic rollback, one-click manual rollback.
Out of scope (say it)
  • The Git hosting itself (GitHub/GitLab/Azure Repos exists).
  • Writing the tests (the platform runs them).
  • Infrastructure provisioning (Terraform pipelines can reuse the same runners).

Jargon check (words used below). OIDC (OpenID Connect) = a standard for signed identity tokens: the CI platform hands each job a short-lived JWT that says who the job is ("repo payments/api, branch main, workflow release"), and clouds or signing services trust that signature instead of a stored password. HMAC = a keyed hash; the Git host signs each webhook with a secret we share, so we can prove it really came from the Git host. SLSA ("salsa", Supply-chain Levels for Software Artifacts) = a framework of levels for proving how an artifact was built (provenance). SBOM = software bill of materials, the list of every package inside an image. DinD = Docker-in-Docker, running a Docker daemon inside a container (needs privileged mode). PSA = Pod Security Admission, the built-in Kubernetes check that enforces the privileged / baseline / restricted security levels per namespace. ReplicaSet = the Kubernetes object that keeps N identical pods of one version running; a Deployment or Rollout switches between ReplicaSets. CRD = custom resource definition, a new object type added to the Kubernetes API (Tekton adds Task, Pipeline, PipelineRun). SLO = the reliability target you promise (say 99.9% success); burn rate = how fast you are using up the allowed failures - a burn rate of 10 means the month's error budget would be gone in 3 days. DORA metrics = four delivery measures from the DevOps Research and Assessment program: deployment frequency, lead time, change failure rate, time to restore.
