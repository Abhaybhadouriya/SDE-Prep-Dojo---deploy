Quick quiz

Why is mounting /var/run/docker.sock into a build pod dangerous?

  1. It gives the job root-equivalent control of the host
  2. It makes builds slower
  3. It breaks layer caching
The socket controls a root daemon; a job can start a privileged container mounting the host filesystem.

In GitOps, who applies changes to the production cluster?

  1. The CI job, with kubectl
  2. An agent in the cluster (Argo CD) that pulls desired state from Git
  3. The engineer, by hand
Pull model: no prod credentials in CI, audit trail in Git, drift repaired automatically.

Why deploy image@sha256:... instead of image:latest?

  1. Digests download faster
  2. A digest always means the exact same bytes; a tag can be moved
  3. Kubernetes cannot pull tags
Content addressing makes deploys reproducible and signatures meaningful.

Every PR passes CI but main still breaks. The best fix is...

  1. Run tests twice
  2. Fewer reviewers
  3. A merge queue testing each PR on top of main plus the PRs ahead of it
PRs were tested against a stale base; the queue tests the actual combination that will land.

What does a plain Kubernetes rolling update NOT check?

  1. Error rate and latency of the new version
  2. Readiness probes
  3. maxUnavailable
Rolling updates only wait for readiness. Metric-based analysis needs a tool like Argo Rollouts or Flagger.

How should a CI job get cloud credentials?

  1. An access key stored as a CI secret
  2. Copy them from a teammate
  3. Exchange a short-lived OIDC token for credentials scoped to that job
Workload identity federation: nothing long-lived to leak, and access is scoped by repo/branch claims.
