The story

Explain like I'm 5

Picture a robot kitchen. You drop a recipe card into a slot. A robot cook grabs a clean pan (never a dirty one from the last cook), makes the dish, and a robot taster checks it. If it tastes right, the dish gets a sealed sticker that says "made in this kitchen, from this recipe". Then the waiter does something careful: he gives the new dish to one table first. If those people smile, he serves more tables. If anyone frowns, he quietly takes the dish back and serves yesterday's dish again. Nobody has to stand at the stove at midnight.

That is CI/CD. The recipe card is a commit (a saved change to code in Git). CI (continuous integration) is the cooking and tasting: build the code and run the tests on every change. The clean pan is an ephemeral build pod - a fresh, throw-away container in Kubernetes for every job. The sealed sticker is a signed container image with an SBOM (software bill of materials - the ingredient list). CD (continuous delivery / deployment) is the waiter: a canary release sends the new version to a small slice of traffic first and rolls back automatically if error rates rise.

Interviewers ask this because it touches everything you are learning on this site: Docker images, Kubernetes rollouts, multi-tenant scheduling, security and event-driven design.

From your world

You have shipped firmware like this. A new image is built on a clean build host, run through a regression lab, signed so the box refuses unsigned images, then rolled out to a few line cards or a few routers in one POP first before the whole network - with a plan to reload the previous image if counters look bad. A canary release is exactly a staged firmware rollout; GitOps is "the golden config lives in a repo and every box pulls and converges to it". Where the analogy breaks: web services ship many times a day, not once a quarter, so every step must be automatic and fast, and rollback must take minutes, not a maintenance window.

Asked as "design a CI/CD system", "design GitHub Actions / Jenkins at scale", "how would you deploy safely to 50 clusters?", and very often as a follow-up in any design: "how do you deploy and roll back this service?". It is commonly reported in infrastructure and platform loops at companies such as Microsoft, Google and Uber.
