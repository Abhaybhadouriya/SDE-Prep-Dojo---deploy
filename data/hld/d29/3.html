Key APIs

# Read path (public, cached at the edge for ~30-60 s)
GET /v1/trends?location=IN-BLR&limit=30
200 OK
{
  "location": "IN-BLR", "as_of": "2026-11-23T10:42:00Z",
  "trends": [
    { "rank": 1, "topic": "#INDvAUS", "display": "#INDvAUS", "posts_1h": 184200, "category": "Sports" },
    { "rank": 2, "topic": "power cut", "display": "Power cut", "posts_1h": 12400, "category": "Local" }
  ]
}

GET /v1/trends/{topic}/posts?location=IN-BLR&cursor=...   # sample posts for one trend

# Internal (admin / trust and safety)
POST /v1/trends/blocklist   { "term": "...", "scope": "global", "reason": "policy" }
GET  /v1/trends/debug?location=IN&term=power%20cut         # score, baseline, distinct users

The write side has no public API: it is a Kafka topic of new posts that the posting service already publishes. Trending is just another consumer group on it - the posting path is not slowed at all.

Say it: "Trends is a read-heavy API over a precomputed result, plus an asynchronous stream job. I never compute trends on the request path."
