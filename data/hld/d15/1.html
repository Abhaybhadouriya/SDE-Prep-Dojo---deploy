Requirements

Functional
  • As the user types, return the top 5-10 completions for the current prefix.
  • Rank mostly by popularity (how often people searched it), with a boost for fresh trends.
  • Only prefix matches in the basic version (typing "potter" need not suggest "harry potter").
  • Filter offensive, illegal and legally removed suggestions.
  • Optional, ask first: personalisation (your own past searches), location and language, spelling tolerance ("hary" to "harry").
Non-functional
  • Fast: suggestions must feel instant. Typeahead write-ups usually target under about 100 ms end to end, so the server's share is a few tens of ms.
  • Highly available: if suggestions fail, search still works; autocomplete must degrade silently, never show an error.
  • Read-heavy: every keystroke can be a request; updates to rankings can be minutes to hours late.
  • Eventually consistent: two users may see slightly different lists for a short time. That is fine.
  • Scalable to tens of thousands of requests per second and hundreds of millions of distinct queries.

Say early: "Reads must be instant and writes can be late, so I will precompute. The serving path is a lookup into a prebuilt structure; the ranking is computed offline from search logs, with a small real-time layer for trends."
