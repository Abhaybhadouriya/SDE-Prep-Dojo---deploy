How the real companies do it

  • The textbook design: ByteByteGo: Design a Search Autocomplete System covers the trie with top-k per node, the weekly rebuild from query logs (gather, aggregate, build, store) and browser caching.
  • Elasticsearch / Lucene: the suggesters documentation and the search-as-you-type field show the two built-in approaches (FST completion vs n-gram fields).
  • FSTs explained: Andrew Gallant's "Index 1,600,000,000 Keys with Automata and Rust" is the best deep dive on how finite state transducers compress a sorted key set far beyond a plain trie.
  • Hosted search: Algolia query suggestions builds a suggestions index from search analytics, the same pipeline idea as a managed product.
  • Older typeahead systems: LinkedIn (Cleo) and Facebook described their typeahead systems years ago; those posts have since moved or disappeared, so we only mention them. Both used in-memory prefix indexes with a blend of global and personal (network) results.
  • Kernel connection: the Linux fib_trie notes and What is RCU? show the same two tricks in your home territory: prefix tries and lock-free snapshot swaps.
