Here is a complete, runnable top-k trie in Python. It precomputes the best K at every node during the build, so a lookup only walks the prefix.

import heapq

K = 3

class Node:
    __slots__ = ("kids", "top")
    def __init__(self):
        self.kids = {}     # char -> Node
        self.top = []      # precomputed [(count, query)], best first, at most K

def build(counts):
    root = Node()
    for q, c in counts.items():
        node = root
        for ch in q:
            node = node.kids.setdefault(ch, Node())
            node.top.append((c, q))            # every prefix of q sees q
    stack = [root]
    while stack:                                # keep only the best K per node
        n = stack.pop()
        n.top = heapq.nlargest(K, n.top)
        stack.extend(n.kids.values())
    return root

def suggest(root, prefix):
    node = root
    for ch in prefix:                           # O(len(prefix)) walk
        node = node.kids.get(ch)
        if node is None:
            return []
    return [q for _, q in node.top]             # O(1): already sorted

counts = {"harry potter": 900, "harry styles": 700, "hardware store": 300,
          "harvard": 450, "hari om": 120, "happy birthday": 800}
root = build(counts)
for p in ["h", "har", "harr", "hap", "x"]:
    print(f"{p!r:8} -> {suggest(root, p)}")
$ python trie_topk.py
'h'      -> ['harry potter', 'happy birthday', 'harry styles']
'har'    -> ['harry potter', 'harry styles', 'harvard']
'harr'   -> ['harry potter', 'harry styles']
'hap'    -> ['happy birthday']
'x'      -> []

This toy build appends every query to every prefix node, which is fine for a demo. A production builder works bottom-up instead: each node's top-k is merged from its children's top-k lists plus the query ending at that node, so memory stays bounded. Lookup cost is O(length of prefix), independent of how many queries exist.

Without a hand-made trie: Elasticsearch's completion suggester keeps an in-memory FST (finite state transducer, a compressed cousin of the trie) with weights. Redis sorted sets can store a ranked list per prefix. Both are good answers if you can say what they do inside.
