How the real companies do it

  • Slack real-time messaging: channel servers (stateful, in memory, consistent hash ring, ~16M channels per host at peak), gateway servers in many regions holding WebSocket subscriptions, stateless admin servers, presence servers hashed by user, CHARMs to manage the ring (replacement host ready in under 20 s), Consul and Envoy. About 500 ms worldwide delivery; typing indicators are transient and never stored.
  • Slack Flannel: an application-level edge cache in PoPs. Lazy loading made boot payloads 7x (1.5K users) to 44x (32K users) smaller; 4M simultaneous connections and 600K client queries/s at peak; presence via pub/sub cut presence events 5x.
  • Slack on Vitess: moved from per-workspace MySQL shards to Vitess with message data sharded by channel; 2.3M QPS peak, 2 ms median, 11 ms p99; 99% of query load migrated after about three years.
  • Slack shared channels: one copy of channel data on the originating shard plus a shared_channels bridge table; unified conversation model for channels, groups and DMs.
  • Discord: messages in ScyllaDB partitioned by (channel_id, bucket) with Snowflake ids; 177 Cassandra nodes became 72 ScyllaDB nodes; Rust data services with request coalescing and channel-hash routing. Elixir guild processes fan out to sessions; Manifold groups sends per node; semaphores made sessions fail fast so a presence outage did not cascade.
  • Microsoft Teams: a few hundred microservices on Azure; Cosmos DB as primary storage, Redis caches, Front Door and Traffic Manager for routing, Event Hubs and queues. During the 2020 surge (75M DAU): more regions, typing brownout (-30% peak on parts), mobile calendar prefetch off (-80% requests), protobuf + LZ4 cache payloads (-65% size).
  • LinkedIn presence: heartbeats, TTL entries and per-member delayed triggers on Akka actors; p99 under 200 ms for presence changes.

Related designs: Chat App (WhatsApp), Notification System, Live Comments, Video Conferencing, Post Search, Email Service, Unique ID Generator, Key-Value Store. Patterns: Real-time Updates, Fan-out: Push vs Pull, Scaling Reads. Fundamentals: Networking, proxies & gateways.
