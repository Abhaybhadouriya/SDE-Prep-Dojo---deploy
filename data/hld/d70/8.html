Failure modes

  • Broker or Kafka outage: devices buffer locally (size the buffer: 15-minute meter readings can wait hours; 1 Hz sensors cannot), then replay with old timestamps. Event-time windows absorb it; dashboards show "data delayed" when the watermark lags.
  • Flink job restart: resumes from the last checkpoint and Kafka offset; sinks must be idempotent (HSET is; TSDB inserts dedupe on primary key). Live map freezes for a few seconds, then catches up.
  • Redis down: dashboards fall back to querying the OLAP/TSDB minute buckets every few seconds. Slower, still correct.
  • Hot cell: a stadium after a concert. Keying the aggregation by cell puts it on one Flink subtask; pre-aggregate per device partition first (local combine), then by cell.
  • Silent device: no data is also a signal. A "heartbeat missing for 3 intervals" rule opens a device-offline alert; otherwise a dead sensor looks like a calm one.
  • Bad firmware sends nonsense: validate ranges per type in Flink; route rejects to a quarantine topic; never let one device's garbage turn a whole cell red.
