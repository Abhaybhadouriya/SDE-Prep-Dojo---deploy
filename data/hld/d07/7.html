Where Kafka, Kubernetes and Docker fit

ToolWhereDetail
Kafkaorder-eventsKeyed by orderId, so all events of one order stay in order on one partition (see topics, partitions, offsets). Consumers: restaurant push, notifications, dispatch, analytics, ratings. Each is its own consumer group, reading at its own pace.
Kafkarider-locationsKeyed by riderId, short retention (hours to a few days). Consumers: the location service (updates Redis), the tracking gateways, the ETA feature pipeline. A slow analytics consumer can never slow down tracking, because each group has its own offsets (see consumer groups).
Kafkadispatch-decisionsEvery matching result with its inputs, for debugging ("why did rider 17 get this order?") and for offline experiments on new cost weights.
KubernetesStateless servicesDiscovery, order, restaurant and notification services run as Deployments with an HPA on CPU. Notification consumers scale on Kafka lag with KEDA.
KubernetesDispatch per zoneOne active solver per zone at a time. Use a Lease-based leader election per zone, or partition zones over pods with consistent hashing. A PodDisruptionBudget stops a node drain from killing all solvers at once.
KubernetesTracking WebSocket gatewaysLong-lived connections: set a preStop hook and a long terminationGracePeriodSeconds so a rolling update drains connections gently, and clients reconnect with jitter.
DockerLocal labCompose up Postgres, Redis and Kafka (like the ShopStream pipeline) and replay a recorded day of pings to test dispatch changes offline.
 
# create the topics (Kafka 4.x, KRaft)
kafka-topics.sh --bootstrap-server localhost:9092 --create --topic order-events \
  --partitions 24 --replication-factor 3 --config min.insync.replicas=2
kafka-topics.sh --bootstrap-server localhost:9092 --create --topic rider-locations \
  --partitions 48 --replication-factor 3 --config retention.ms=86400000

# KEDA: scale the notification consumers on Kafka lag, not CPU
apiVersion: keda.sh/v1alpha1
kind: ScaledObject
metadata:
  name: notifier
spec:
  scaleTargetRef:
    name: notifier            # the Deployment
  minReplicaCount: 3
  maxReplicaCount: 24         # no point going above the partition count
  triggers:
    - type: kafka
      metadata:
        bootstrapServers: kafka:9092
        consumerGroup: notifier
        topic: order-events
        lagThreshold: "200"
