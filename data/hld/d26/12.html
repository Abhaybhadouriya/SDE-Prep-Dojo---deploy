Quick quiz

Asks: A 100 @ 50 (first), B 100 @ 50 (second). A buy for 150 @ 51 arrives. What happens?

  1. B fills first because it is newer
  2. Both fill at 51
  3. A fills 100 @ 50, then B fills 50 @ 50
Time priority at the same price puts A first, and trades happen at the resting price (50).

Why is cancel O(1) in a good order book?

  1. Orders are sorted by id
  2. Cancels are rare, so it does not matter
  3. A hash map points from order id to its linked-list node, which can be unlinked directly
Cancels are actually the most common message, so O(1) cancel matters a lot.

What makes a hot standby engine possible?

  1. A deterministic engine fed the same sequenced input
  2. A shared database between the two engines
  3. A distributed lock on every order
Same inputs in the same order through deterministic code give the same state at every sequence number.

1 billion messages a day on an exchange open 6.25 hours. Average rate?

  1. About 11,600/s
  2. About 44,000/s
  3. About 1,000,000/s
Divide by 22,500 trading seconds, not 86,400.

Where does Kafka fit best in an exchange?

  1. Downstream: trades and order events to clearing, surveillance and reporting
  2. Between the gateway and the matching engine for every order
  3. As the order book storage
Kafka adds milliseconds; the core needs microseconds. Downstream consumers are happy with milliseconds.

Why must the engine never read its own wall clock?

  1. Clocks are slow to read
  2. Regulators forbid clocks
  3. Primary and standby would see different times and could diverge
Time must come from the sequenced input (the sequencer's timestamp) to keep the engine deterministic.

Why UDP multicast for professional market data?

  1. It guarantees delivery
  2. One send reaches all subscribers at the same time, and cost does not grow with subscriber count
  3. It encrypts data
Multicast is fair and cheap; loss is handled by sequence numbers plus retransmit or snapshot.
