Architecture, step by step

Click Next or Play. The whiteboard version: Gateway, Risk, Sequencer, Matching Engine, Market Data, Downstream (6 boxes).

  1. Gateway. The broker's FIX session lands on a gateway. It authenticates the member, checks session sequence numbers, validates the message format and throttles (for example N orders/s per session). Gateways are stateless per order and scale horizontally.
  2. Pre-trade risk. An in-memory check: does this member have the credit or margin? Is the price inside today's price band? Is the quantity sane ("fat finger" check)? Rejections go straight back. Nothing here touches a database.
  3. Sequencer. The single point that decides order. It stamps every accepted input with a strictly increasing sequence number, appends it to the journal, and waits until the journal is replicated (to a standby and a second site) before the input is allowed to have external effects. This gives one total order per shard.
  4. Matching engine. One thread per symbol shard, running on a pinned CPU core, reads inputs in sequence order from a ring buffer and applies them to the in-memory books. No locks, no I/O, no allocation on the hot path. Output: a sequenced list of events (accepted, traded, cancelled).
  5. Hot standby. A second engine reads the same sequenced input and runs the same code. Because the engine is deterministic, it has the identical book at every sequence number. If the primary dies, the standby takes over from the last sequence it processed.
  6. Execution reports. The engine's output events go back through the gateway to the right broker session: NEW, PARTIALLY_FILLED, FILLED, CANCELED.
  7. Market data. The same output stream is turned into public feed messages (add, execute, cancel) and sent once by UDP multicast. Every receiver gets the same bytes at the same time.
  8. Downstream. Trades and order events flow into Kafka (off the hot path) for clearing and settlement, surveillance (detecting manipulation), reporting databases, and broker apps. Here milliseconds are fine.

Which process does what: only the sequencer decides order; only the engine thread for a shard mutates that shard's books; only the journal is the truth. Everything else (DBs, Kafka topics, dashboards) is a projection that can be rebuilt by replaying the journal.
