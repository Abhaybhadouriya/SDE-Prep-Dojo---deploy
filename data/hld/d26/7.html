Where Kafka, Kubernetes and Docker fit

Honest answer first: none of the three belong on the matching hot path. A Kafka produce with acks=all takes milliseconds (a network round-trip to followers); the engine's budget is microseconds. Kubernetes can reschedule a pod, throttle its CPU through cgroup quotas, and routes through an overlay network; all three add jitter. Saying this clearly is a strong signal.

ToolWhere it fitsDetail
KafkaDownstream of the engineTopics trades, order-events, market-data-conflated, keyed by symbol so each symbol stays ordered. Consumers: clearing and settlement, surveillance, reporting DB, broker notifications ("your order filled"), analytics. Kafka's log model mirrors the journal: ordered, replayable. See topics and partitions.
KafkaBroker sideA broker (Zerodha-like) uses Kafka between its OMS, risk, notifications and price-alert service. "Design price alerts": consume ticks keyed by symbol, keep per-symbol alert thresholds in memory, fire notifications.
KubernetesEverything around the coreMember portals, reference data APIs, retail market-data WebSocket fan-out, surveillance jobs, reporting. Deployments + HPA. See scheduling and autoscaling.
KubernetesIf you must run the core on itDedicated node pool, Guaranteed QoS (requests = limits), CPU manager static policy for exclusive cores, host networking or SR-IOV, no autoscaling. At that point it is bare metal with a YAML file; most venues keep the core on tuned bare metal.
DockerDeterministic replay testsPackage the engine; replay yesterday's journal in a container in CI and compare output hashes with production. A mismatch means a non-determinism bug.
 
$ kafka-topics.sh --bootstrap-server localhost:9092 --create --topic trades --partitions 64 --replication-factor 3 --config min.insync.replicas=2 --config retention.ms=-1
Created topic trades.
$ kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic trades --formatter-property print.key=true --from-beginning --max-messages 2
INFY	{"seq":88123477,"trade_id":"T-551","px":150020,"qty":40,"buy":"X7781","sell":"X7702"}
TCS	{"seq":88123480,"trade_id":"T-552","px":410500,"qty":10,"buy":"X7790","sell":"X7611"}
Processed a total of 2 messages

(Kafka older than 4.2: use --property print.key=true; on 4.2+ that flag still works but prints a deprecation warning.) retention.ms=-1 keeps trades forever (or use tiered storage), because trades are records you must keep, and the seq field lets consumers detect gaps and deduplicate.
