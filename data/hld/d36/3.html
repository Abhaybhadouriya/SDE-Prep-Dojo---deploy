Key APIs

PUT    /{bucket}                                   create bucket
PUT    /{bucket}/{key}            body=bytes       -> 200, ETag (checksum), x-version-id
GET    /{bucket}/{key}            Range: bytes=0-1048575   -> bytes
HEAD   /{bucket}/{key}                             -> size, ETag, metadata
DELETE /{bucket}/{key}                             -> 204 (versioned: adds a delete marker)
GET    /{bucket}?list-type=2&prefix=photos/2026/&continuation-token=...   -> up to 1,000 keys

# multipart upload
POST   /{bucket}/{key}?uploads                     -> uploadId
PUT    /{bucket}/{key}?partNumber=7&uploadId=U     -> ETag of part 7   (parts 1..10,000, 5 MiB-5 GiB)
POST   /{bucket}/{key}?uploadId=U   body=[{part, ETag}...]   -> object becomes visible
DELETE /{bucket}/{key}?uploadId=U                  abort, free the parts

A presigned URL is the same request with a signature and an expiry baked into the query string, so a browser can upload straight to the store without your app server touching the bytes (see Handling Large Blobs). The client sends a checksum (for example Content-MD5 or a CRC) so the server can reject a corrupted upload.
