Where Kafka, Kubernetes and Docker fit

📨

Kafka

Two ways: (1) the store publishes "object created/deleted" events to Kafka for indexing, replication and lifecycle jobs; (2) Kafka itself uses object storage for tiered storage (KIP-405), moving old log segments to S3-like storage.

 ☸️

Kubernetes

Run an object store on K8s with an operator (MinIO, Rook-Ceph): StatefulSets with stable identity and local PersistentVolumes per disk, anti-affinity to spread pods over nodes and zones.

 🐳

Docker

Container registries store image layers as content-addressed blobs, usually in object storage. And you can run an S3-compatible store locally in one container to develop against.

 
# S3-compatible store for local development (MinIO); set the root user and password
# through environment variables from a local env file, never on the command line.
docker run -d --name minio -p 9000:9000 -p 9001:9001 \
  --env-file ./minio.env -v minio-data:/data \
  quay.io/minio/minio server /data --console-address ":9001"

# then use any S3 client against http://localhost:9000
aws --endpoint-url http://localhost:9000 s3 mb s3://demo
aws --endpoint-url http://localhost:9000 s3 cp ./big.iso s3://demo/   # CLI switches to multipart automatically
# Spread object-store pods across zones so one zone loss removes at most a third of the shards
topologySpreadConstraints:
- maxSkew: 1
  topologyKey: topology.kubernetes.io/zone
  whenUnsatisfiable: DoNotSchedule
  labelSelector: { matchLabels: { app: object-store } }
