Choreography
  • No central component; services stay decoupled.
  • Easy to add a new listener (analytics, search).
  • Good for simple, linear flows.
Orchestration
  • One place to read and change the flow.
  • Compensation order is explicit.
  • Easier to monitor "where is order 42?".

Interviewers love this: "Inside one database I use a normal transaction. Across services I use an orchestrated saga with compensations, an outbox for reliable events, and idempotency keys on every external call. If the flow waits on humans or runs for hours, I'd use a durable workflow engine such as Temporal instead of building timers and state tables myself."
