Architecture

Big companies converged on the same layered shape: DNS / anycast picks a region or PoP, routers spread packets over L4 nodes with ECMP, the L4 tier (Google Maglev, Meta Katran, GitHub GLB, Cloudflare Unimog) consistently hashes each flow to an L7 proxy, and the L7 tier (Envoy, HAProxy, NGINX, Meta's Proxygen) terminates TLS and routes requests to services.

A new HTTPS connection, step by step

  1. DNS. The client resolves shop.com and gets a VIP. With anycast, the same VIP is announced from many sites and BGP brings the client to the nearest one.
  2. ECMP. Every L4 node announces the VIP (via BGP, e.g. ExaBGP in Katran). The router hashes the packet's 5-tuple and picks one of the equal-cost next hops: L4 node 1.
  3. Maglev lookup. SYN packet, so no connection-table entry. Node 1 hashes the 5-tuple into the VIP's 65,537-entry lookup table, gets proxy P7, records the choice in its connection table, and encapsulates the packet (GRE in Maglev, IP-in-IP in Katran, GUE in GLB/Unimog) to P7. The kernel stack is bypassed for speed.
  4. L7 work. P7 decapsulates, accepts the TCP connection (it owns the VIP on loopback), terminates TLS, parses the HTTP request and matches routes: /cart goes to the cart pool.
  5. Pick a backend. P7 uses power-of-two-choices least-request (Envoy's default for equal weights): pick 2 random healthy backends, send to the one with fewer active requests, over an already-open pooled connection.
  6. Direct server return. P7 replies to the client with the VIP as source address, straight to the router. The L4 tier never sees the 10x larger response traffic.
  7. L4 node dies. Routers drop it from ECMP; the flow's packets now land on node 2. Node 2 has no conntrack entry, but every node builds the same Maglev table from the same backend list, so it also picks P7. The connection survives.
