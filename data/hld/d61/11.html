  • Three data shapes: small related metadata (SQL + cache), huge immutable audio (S3 + CDN), firehose events (Kafka + Cassandra + lake).
  • The play API returns a signed CDN URL; servers never stream bytes. 100M x 160 kbps = 16 Tbps proves why.
  • Chunks + adaptive bitrate + next-track prefetch + client cache = fast start and no gaps.
  • Every track belongs to a release typed album or single; singers via a track_artist join table.
  • Search = analyse, inverted index, fuzzy edit distance, BM25 x popularity; fed by CDC; p95 under 200 ms with caching and debounce.
  • Playlists: rank keys (one-row moves), operations with item ids, a version number, shuffle play is not an edit.
  • Strong consistency for money, auth and rights; eventual for counts and the index; exact royalties from the batch log.
  • Voice (Alexa) is another front door to the same search, entitlement and CDN path.
