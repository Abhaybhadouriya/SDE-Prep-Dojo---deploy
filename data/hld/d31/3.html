Key APIs

Two shapes exist: a library linked into every service (no network hop), or a small ID service. The API is the same idea in both.

# As a service (HTTP or gRPC)
GET  /v1/ids?count=1            -> 200 {"ids": ["2124805152568709162"]}
GET  /v1/ids?count=100          -> 200 {"ids": [ ...100 ids... ]}      # batch to amortise the RTT
GET  /v1/ids/2124805152568709162/decode
     -> 200 {"timestampMs": 1795428000000, "datacenter": 3, "worker": 17, "sequence": 42}
# Errors
503  {"error": "CLOCK_MOVED_BACKWARDS", "retryAfterMs": 4}   # refuse rather than risk a duplicate
// As a library
long id = idGenerator.nextId();          // in-process, ~microseconds, no network
long[] ids = idGenerator.nextIds(100);

Return IDs as strings in JSON. JavaScript numbers are 64-bit floats and lose precision above 253. Discord's API documentation says its snowflakes are sent as strings "to prevent integer overflows in some languages". Store them as BIGINT, send them as strings.
