Data model: the log on disk

Learner question answered: "SQL or NoSQL?" Neither. The storage engine is a set of append-only files, because the only operations are "append at the end" and "read forward from position X". A database would add indexes, locks and in-place updates we never use.

  • A topic is split into partitions. Each partition is an independent ordered log, and a directory on a broker: orders-0/, orders-1/.
  • Each partition directory holds segment files. The file name is the offset of the first record inside it (the base offset): 00000000000000000000.log, then 00000000000000368769.log. Only the newest (active) segment is written; Kafka's default segment size is 1 GiB.
  • Next to every .log are a sparse offset index (.index: offset to byte position, one entry every few KB, not every record) and a time index (.timeindex: timestamp to offset, used for "replay from 10:00").
  • Records are written in batches. A batch header carries the base offset, the producer ID, epoch and sequence number (for idempotence), a compression codec, and the records with small offset and timestamp deltas. The broker stores the batch exactly as the producer sent it (still compressed), so the bytes on disk are the bytes on the wire.
  • Consumer positions live in an internal compacted topic, __consumer_offsets, keyed by (group, topic, partition). Cluster metadata (topics, partitions, leaders, ISR) lives in the Raft-replicated __cluster_metadata log managed by the controllers (KRaft).

A toy version in 40 lines of Python makes the idea concrete: fixed headers, an append-only file named by base offset, and a sparse index every 64 bytes.

import os, struct

class Segment:
    """One append-only segment: <base>.log plus a sparse in-memory index."""
    HDR = struct.Struct(">QI")          # 8-byte offset, 4-byte length (big-endian)
    INDEX_EVERY = 64                    # add an index entry every 64 bytes of log

    def __init__(self, directory, base_offset):
        name = f"{base_offset:020d}"
        self.base = base_offset
        self.log = open(os.path.join(directory, name + ".log"), "ab+")
        self.index = []                 # sparse: (offset, byte_position)
        self.next_offset = base_offset
        self.bytes_since_index = self.INDEX_EVERY

    def append(self, value: bytes) -> int:
        pos = self.log.seek(0, os.SEEK_END)
        if self.bytes_since_index >= self.INDEX_EVERY:
            self.index.append((self.next_offset, pos))
            self.bytes_since_index = 0
        rec = self.HDR.pack(self.next_offset, len(value)) + value
        self.log.write(rec)
        self.bytes_since_index += len(rec)
        self.next_offset += 1
        return self.next_offset - 1

    def read_from(self, offset: int, max_records=3):
        # real systems binary-search the index; a linear scan keeps it short
        start = max((p for o, p in self.index if o <= offset), default=0)
        self.log.flush(); self.log.seek(start)
        out = []
        while len(out) < max_records:
            hdr = self.log.read(self.HDR.size)
            if len(hdr) < self.HDR.size:
                break
            off, n = self.HDR.unpack(hdr)
            val = self.log.read(n)
            if off >= offset:
                out.append((off, val.decode()))
        return start, out

os.makedirs("orders-0", exist_ok=True)
seg = Segment("orders-0", 0)
for i in range(10):
    seg.append(f"order-{i}".encode())
print("files:", sorted(os.listdir("orders-0")))
print("sparse index:", seg.index)
print("read from offset 6 ->", seg.read_from(6))

From your world

A partition is a descriptor ring that lives on disk: the producer is the writer advancing the tail, each consumer group is a reader with its own head index, and the offset is the ring index. The difference: a ring buffer overwrites old slots as soon as the reader moves on; a Kafka log keeps them until retention deletes whole segments, so a reader can go back. Where this breaks: a NIC ring has one consumer (the driver); a log has any number of independent readers, each with its own index.
