Where Kafka, Kubernetes and Docker fit

Here the design is Kafka, so the question becomes: how do you run it?

  • Docker: one container in KRaft combined mode (broker + controller) is perfect for local development and tests, as in the API section. Use separate controller and broker processes in production; combined mode is for development only.
  • Kubernetes with an operator: Strimzi (a CNCF project) manages Kafka with custom resources: Kafka, KafkaNodePool (separate controller and broker pools), KafkaTopic, KafkaUser, KafkaRebalance (Cruise Control). Each broker pod gets its own persistent volume and a stable identity, because a broker's disk is its partitions. See Deploy on Kubernetes (Strimzi) and Operations & Kafka on K8s.
  • The number-one gotcha: clients must reach the specific broker that leads a partition, not a random pod behind a load balancer. Every broker needs its own advertised address (per-broker NodePort, LoadBalancer or route) for clients outside the cluster.
  • Zones: map Kubernetes topology labels to broker.rack so the three replicas of each partition land in three zones. Let consumers fetch from the closest replica (KIP-392, client.rack) to cut cross-zone network cost.
# Strimzi 1.x: KRaft controllers + a 3-broker pool on persistent disks, spread over zones (excerpt)
# Strimzi 1.0+ serves only the kafka.strimzi.io/v1 API; KRaft and node pools are always on.
apiVersion: kafka.strimzi.io/v1
kind: KafkaNodePool
metadata:
  name: controllers
  labels:
    strimzi.io/cluster: shop
spec:
  replicas: 3
  roles: [controller]
  storage:
    type: persistent-claim
    size: 50Gi
    deleteClaim: false
---
apiVersion: kafka.strimzi.io/v1
kind: KafkaNodePool
metadata:
  name: brokers
  labels:
    strimzi.io/cluster: shop
spec:
  replicas: 3
  roles: [broker]
  storage:
    type: persistent-claim
    size: 2Ti
    deleteClaim: false
---
apiVersion: kafka.strimzi.io/v1
kind: Kafka
metadata:
  name: shop
spec:
  kafka:
    listeners:
      - name: tls
        port: 9093
        type: internal
        tls: true
    rack:
      topologyKey: topology.kubernetes.io/zone
    config:
      default.replication.factor: 3
      min.insync.replicas: 2
      unclean.leader.election.enable: false

Trap: autoscaling brokers like stateless pods does not work. Adding a broker adds no capacity until partitions are moved onto it (a data copy). Scale Kafka deliberately, with Cruise Control or tiered storage making moves cheaper; autoscale the consumers, up to the partition count.
