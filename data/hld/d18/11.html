Remember this

  • A topic is N partitions; a partition is an append-only log of segments with a sparse index.
  • Key hash picks the partition: order per key, parallelism = partitions; adding partitions remaps keys.
  • Leader + followers; ISR; high watermark = what consumers may read.
  • RF 3 + min.insync.replicas 2 + acks=all + idempotence = no acked loss on one failure.
  • Pull consumers, one committed offset per group-partition in __consumer_offsets.
  • Fast because: sequential I/O, page cache, zero-copy sendfile, batching + compression.
  • Exactly-once inside Kafka; outside, use idempotent sinks or the outbox.
  • Disk (retention x RF) sizes the cluster; tiered storage fixes it. KRaft controllers hold metadata.
