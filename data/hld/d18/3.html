Key APIs

New words, once each (used in the API below and everywhere after it):

  • Partition = one ordered, append-only log; a topic is split into N of them. Offset = the position of a record inside one partition (0, 1, 2, ...).
  • Leader / follower = each partition has one replica that takes all writes (the leader) and copies (followers) that fetch from it.
  • ISR (in-sync replicas) = the leader plus the followers that are caught up recently enough to take over.
  • LEO (log-end offset) = the next offset a replica will write; each replica has its own.
  • High watermark (HW) = the highest offset that every ISR member has; consumers may read only below it.
  • acks = how many replicas must have a write before the producer is told "done": 0 (none), 1 (leader only) or all (every ISR member).

Clients speak a binary protocol over long-lived TCP connections straight to the broker that leads each partition (no load balancer in the data path). The essential calls:

# Producer side
Metadata(topics)                                  -> partitions, leader broker for each, replicas
Produce(topic, partition, batch[ (key, value, headers, ts) ], acks)
                                                  -> base_offset | error (NOT_LEADER, NOT_ENOUGH_REPLICAS)
# Consumer side (pull)
Fetch(topic, partition, from_offset, max_bytes, max_wait_ms)  -> records up to the high watermark
OffsetCommit(group, topic, partition, offset)     # "I have processed everything before this"
OffsetFetch(group, topic, partition)              -> last committed offset
Heartbeat / JoinGroup (or ConsumerGroupHeartbeat) -> partition assignment for this member
ListOffsets(topic, partition, timestamp)          -> first offset at or after a time (for replay)
# Admin
CreateTopics(name, partitions, replication_factor, configs)

Try the real thing with one broker in Docker (KRaft mode, no ZooKeeper). The deeper hands-on lab is on Kafka core concepts.

docker run -d --name kafka -p 9092:9092 apache/kafka:4.4.0
K=/opt/kafka/bin
docker exec kafka $K/kafka-topics.sh --bootstrap-server localhost:9092 \
  --create --topic orders --partitions 3 --replication-factor 1
docker exec kafka $K/kafka-topics.sh --bootstrap-server localhost:9092 --describe --topic orders
