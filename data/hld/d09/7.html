Where Kafka, Kubernetes and Docker fit

ToolWhereDetail
Kafkasale-reservationsThe shock absorber between the burst and the database. Producer acks=all, idempotent producer, min.insync.replicas=2. Keyed by reservationId to spread load evenly. Per-user order does not matter here, because each user has at most one reservation. See replication and ISR.
KafkaOrder-writer consumer groupIts consumer count controls how fast SQL is written. Lag is the queue depth: alert on it, but do not panic, because users already have their answer. See consumer groups.
Kafkasale-eventsSold-out, stock-returned and wave-opened events feed the edge config, the waitlist notifier and analytics.
KubernetesPre-scalingRaise minReplicas on the HPA before T0 (a scheduled job or the KEDA cron scaler), and keep low-priority placeholder pods so nodes already exist when real pods need them.
KubernetesProtecting the sale cellA dedicated node pool (taints and tolerations) for reservation pods, a PodDisruptionBudget, and a deploy freeze during the sale. Flipkart's Aerospike talk describes running its 90M QPS Aerospike estate on Kubernetes across three data centres.
DockerLocal rehearsalCompose Redis + Kafka + Postgres, fire thousands of concurrent reserve calls with a load tool, and assert the invariant: reservations never exceed stock, and there is one per user.
 
# KEDA cron trigger: hold 200 replicas from 11:30 to 13:00 IST on sale day
apiVersion: keda.sh/v1alpha1
kind: ScaledObject
metadata:
  name: reservation-svc
spec:
  scaleTargetRef:
    name: reservation-svc
  minReplicaCount: 20
  maxReplicaCount: 300
  triggers:
    - type: cron
      metadata:
        timezone: Asia/Kolkata
        start: 30 11 1 10 *        # 11:30 on 1 October
        end: 0 13 1 10 *           # 13:00 on 1 October
        desiredReplicas: "200"
    - type: cpu
      metricType: Utilization
      metadata:
        value: "60"
# Placeholder pods: a negative priority so real pods evict them instantly,
# while the nodes they keep warm are already in the cluster
apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
metadata:
  name: overprovisioning
value: -10
globalDefault: false
description: "Placeholder pods that reserve spare capacity before the sale"
$ kubectl apply -f priorityclass.yaml
priorityclass.scheduling.k8s.io/overprovisioning created
$ kubectl scale deployment order-writer --replicas=24
deployment.apps/order-writer scaled
