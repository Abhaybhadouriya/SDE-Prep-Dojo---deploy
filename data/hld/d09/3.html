Key APIs

# 1. Static, cached at the CDN for everyone (contains the server time for the countdown)
GET  /sale/bbd-phone-26/page.html

# 2. Join the waiting room (edge). Returns a SIGNED token with the arrival time.
POST /v1/sales/bbd-phone-26/queue
-> 200 { "queueToken": "eyJ...signed...", "state": "WAITING", "pollAfterMs": 4000 }

# 3. Poll status (with jitter). Admitted users get a short-lived admission token.
GET  /v1/sales/bbd-phone-26/queue/status          (Cookie: queueToken)
-> 200 { "state": "WAITING", "pollAfterMs": 5000 }
-> 200 { "state": "ADMITTED", "admissionToken": "eyJ...", "expiresInSec": 120 }
-> 200 { "state": "SOLD_OUT" }

# 4. Try to reserve one unit (needs the admission token; idempotent per user + sale)
POST /v1/sales/bbd-phone-26/reservations
Authorization: Bearer <admissionToken>
Idempotency-Key: 3b0f...
-> 201 { "reservationId": "rs_88121", "payBy": "2026-10-01T12:10:00Z" }
-> 409 { "error": "ALREADY_RESERVED", "reservationId": "rs_88121" }
-> 410 { "error": "SOLD_OUT" }

# 5. Pay and turn the reservation into an order (the normal checkout saga)
POST /v1/orders  { "reservationId": "rs_88121", "paymentMethodId": "upi-1" }

Use 410 or a sold-out page, not 500 or a timeout. A clear, fast final answer stops the client from retrying. An error or a hang makes every user press refresh, which multiplies your load at the worst moment. The client app should also retry with exponential backoff and jitter, as the Amazon Builders' Library recommends.
