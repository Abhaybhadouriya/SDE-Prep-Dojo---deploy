Quick quiz

Why is the product page served as a static file from a CDN?

  1. CDNs are cheaper to code
  2. At about 1.5M requests/s, a 100 KB page would need about 1.2 Tbps from the origin
  3. Static pages cannot show prices
1.5M x 100 KB = 150 GB/s. Only an edge network can absorb that. The origin only answers the tiny "can I buy?" call.

What does the Redis Lua script give us that GET then DECR does not?

  1. Persistence to disk
  2. Replication to other regions
  3. Atomicity: check user, check stock, decrement and record in one step
Redis runs a script without interleaving other commands, so no other client can act between the check and the change.

Why do both keys in the script share the hash tag {bbd26:b3}?

  1. So they land in the same Redis Cluster slot and one script may use both
  2. To encrypt the keys
  3. To make the keys expire together
Only the text inside the braces is hashed. A multi-key script must touch keys in one slot.

Shopify's first throttle (Part I) was unfair. Why?

  1. It used a database
  2. Users polled with random timeouts, so newcomers could get in before people who had waited longer
  3. It returned HTTP 429
Part II fixed it with a signed arrival timestamp and a moving "now serving" threshold.

How should an unpaid reservation be expired safely?

  1. Delete the Redis key and hope
  2. Rely on Redis keyspace notifications
  3. UPDATE ... SET status='EXPIRED' WHERE status='HELD', and return the stock only if one row changed
The conditional transition makes "paid" and "expired" mutually exclusive, so a late payment and the expiry cannot both win.

Why pre-scale instead of relying on the HPA?

  1. Metrics, pod start-up and new nodes all take longer than a one-second spike
  2. The HPA does not work with Kafka
  3. Pre-scaling is cheaper
Autoscaling reacts in minutes. Raise minReplicas ahead of time and keep placeholder pods so nodes are ready.

After a Redis failover the counter may be too high. What is the durable record to rebuild from?

  1. The CDN logs
  2. The reservation events in Kafka (and SQL)
  3. The waiting room tokens
Every reservation is written to Kafka with acks=all before the user is told "yes". Rebuild: total minus recorded reservations.

Stock is split into 10 buckets. A user's bucket is empty. What should happen?

  1. Show sold out immediately
  2. Put the user back in the waiting room
  3. Try the other buckets before saying sold out
Buckets empty unevenly. Sold out is true only when every bucket is 0.
