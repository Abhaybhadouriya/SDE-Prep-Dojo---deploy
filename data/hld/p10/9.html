Quiz

Why does a B-tree index on latitude alone perform badly for "within 2 km of me"?

  1. B-trees cannot store decimal numbers
  2. It returns a band around the whole Earth, far more rows than the small area
  3. Latitude values are not unique
A 1-D range on latitude covers every longitude, so it scans a strip around the planet.

Two cafes are 15 m apart but their geohashes share no prefix. What is the right fix?

  1. Use a longer geohash
  2. Switch to a B-tree on latitude
  3. Query the centre cell plus its 8 neighbours, then filter by exact distance
Nearness does not guarantee a shared prefix at cell edges; the 3 x 3 neighbour search plus post-filter closes the gap.

Which structure adapts its cell size to data density?

  1. Quadtree
  2. Fixed grid
  3. Geohash at a single length
A quadtree splits only the squares that hold too many points, so dense areas get small cells.

Uber chose hexagons for H3 mainly because...

  1. Hexagons use less memory than squares
  2. All six neighbours are the same distance from the centre
  3. Hexagons tile the sphere perfectly with no exceptions
Equal neighbour distance makes rings approximate circles and makes smoothing fair. H3 still needs 12 pentagons, so the tiling is not perfect.

10 million drivers each send a location every 5 seconds. Roughly how many writes per second is that?

  1. 20,000
  2. 200,000
  3. 2,000,000
10,000,000 / 5 = 2,000,000 writes per second, which is why the latest location lives in memory.

"Is this address inside our delivery zone?" Which index fits best?

  1. R-tree (for example PostGIS GiST) with point-in-polygon
  2. Redis GEOSEARCH by radius
  3. A geohash prefix scan only
Zones are polygons. R-trees index bounding boxes of shapes and then run the exact containment test.

In an S2-sharded index, why do cell ids make "everything in this cell" cheap?

  1. They are random UUIDs
  2. A cell's descendants form one contiguous id range on a Hilbert curve
  3. Each cell is stored in its own table
A parent cell maps to [range_min, range_max], so a normal B-tree range scan finds every point inside it.
