Data model and storage

The state is small and every byte matters, so it lives in a replicated state machine: an ordered log of commands, applied in the same order on every replica, plus an in-memory tree and periodic snapshots. No SQL vs NoSQL debate here: it is a custom store, because we need consensus on every write and linearizable reads from the leader (every read sees the latest committed write, as if one copy existed). An ephemeral node, in the table below, is deleted automatically when its owner's session dies.

From your world

The replicated log is a journaling file system's journal, copied to five machines. The "generation" counter is like an epoch number in a routing protocol (or a sequence number in TCP): receivers keep the highest one they have seen and drop anything older. The in-memory tree is the RIB; the log is how every card rebuilds the same RIB.
