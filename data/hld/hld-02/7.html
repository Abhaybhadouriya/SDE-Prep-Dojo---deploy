Bloom filters: "definitely not" in a few bits

Explain like I'm 5

A bouncer has a stamp book. If your stamp pattern is not in it, you are definitely not on the guest list - go home. If it is there, you are "maybe" on the list, and the bouncer checks the real list. The stamp book is tiny, and it saves most trips to the real list.

A Bloom filter is an array of m bits, all starting at 0, plus k hash functions. To add an item, hash it k times and set those k bits to 1. To check an item, look at its k bits: if any is 0, the item was never added (no false negatives). If all are 1, it was probably added - the bits might have been set by other items (a false positive).

The sizing rule of thumb: about 10 bits per item gives about a 1% false-positive rate (Wikipedia gives 9.6 bits per element for 1%), with the best number of hashes k = (m/n) x ln 2. You cannot delete from a plain Bloom filter (clearing a bit might remove other items); a counting Bloom filter keeps small counters instead of bits to allow it.

Try it: a 30-line Bloom filter

import hashlib, math

class BloomFilter:
    def __init__(self, n_items, fp_rate):
        # m = bits, k = hash functions (standard formulas)
        self.m = math.ceil(-n_items * math.log(fp_rate) / (math.log(2) ** 2))
        self.k = max(1, round(self.m / n_items * math.log(2)))
        self.bits = bytearray(self.m)          # 1 byte per bit, simple to read

    def _positions(self, item):
        h = hashlib.sha256(item.encode()).digest()
        h1 = int.from_bytes(h[:8], "big")
        h2 = int.from_bytes(h[8:16], "big")
        return [(h1 + i * h2) % self.m for i in range(self.k)]   # double hashing

    def add(self, item):
        for p in self._positions(item):
            self.bits[p] = 1

    def might_contain(self, item):
        return all(self.bits[p] for p in self._positions(item))

bf = BloomFilter(n_items=100_000, fp_rate=0.01)
print("bits:", bf.m, "hashes:", bf.k, "bits/item:", round(bf.m / 100_000, 2))
for i in range(100_000):
    bf.add(f"user{i}")
print("user42 ->", bf.might_contain("user42"))
false_pos = sum(bf.might_contain(f"stranger{i}") for i in range(100_000))
print("false positives:", false_pos, "of 100000 =", false_pos / 1000, "%")
$ python bloom.py
bits: 958506 hashes: 7 bits/item: 9.59
user42 -> True
false positives: 1005 of 100000 = 1.005 %

That run was measured while writing this page. The filter needs 958,506 bits - about 117 KB if packed as real bits (this demo uses one byte per bit for readability, so about 940 KB) - for 100,000 names, at a measured 1.0% false-positive rate, exactly as the formula predicts. In production you would use a real bit array (or Redis's Bloom commands in Redis Stack / Redis 8).

Where you will use it in designs: Cassandra and RocksDB keep a Bloom filter per on-disk file so a read can skip files that surely do not contain the key; a web crawler asks "have I already seen this URL?"; a URL shortener asks "is this custom alias taken?" before hitting the database; a cache uses one to stop requests for keys that do not exist (cache penetration).
