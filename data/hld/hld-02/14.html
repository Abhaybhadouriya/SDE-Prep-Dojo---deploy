Common mistakes and gotchas

MistakeWhy it hurtsSay this instead
"We'll use 2PC across the Order, Payment and Inventory services."Blocking, couples availability, most brokers and NoSQL stores do not join XA (the 2PC interface)"A saga with compensations, outbox for the events, idempotent consumers."
Writing to the DB, then publishing to Kafka, in application codeDual-write: a crash between them loses or invents events"Outbox table in the same transaction, Debezium relays it."
Client creates a new idempotency key on each retryEvery retry looks like a new payment"One key per logical operation, reused on retries, stored server-side with a unique constraint."
SELECT-then-INSERT to check for duplicatesTwo concurrent requests both pass the SELECT"INSERT ... ON CONFLICT DO NOTHING on a unique key."
Leader lease without fencingA paused old leader writes after a new one is elected"Lease plus a monotonically increasing (only ever goes up) fencing token checked by storage."
Even-sized consensus cluster (4 nodes)Same fault tolerance as 3, more traffic"3 or 5 nodes: 2f + 1 survives f failures."
Bloom filter "yes" treated as "yes"False positives"Bloom says maybe; confirm with the real store. Its 'no' is certain."
Count-min sketch for exact billing countsOver-counts small items"Sketch for heavy hitters; exact counters (or batch) for money."
Geo search in one geohash cell onlyMisses close points across the border"Query the cell plus its 8 neighbours, then filter by distance."
Rate limiter with non-atomic read-then-write in RedisRace lets bursts through"Lua script or INCR-based check, which Redis runs atomically."
Rate limiter that fails closedRedis outage = whole API outage"Fail open with alerts and a local fallback limit."
Unbounded queues "for safety"Latency explodes, then out-of-memory"Bounded queue; when full: block, reject, or shed low priority."

You might confuse: replica (a copy for safety) with partition/shard (a slice for scale); consensus (agreeing on an order of operations) with quorum (how many replicas must answer); rate limiting (protect from callers) with backpressure (protect stages from each other); idempotent (safe to repeat) with exactly-once delivery (a message arrives once - generally impossible across a network; you get the same effect with at-least-once plus idempotency).
