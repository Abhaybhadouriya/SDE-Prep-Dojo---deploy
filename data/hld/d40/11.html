  • Inventory = one row per (hotel, room type, date). A stay touches N rows in one transaction.
  • Booking is ~3 TPS for a 5,000-hotel chain. Views are ~100x that. Cache reads, and keep writes ACID.
  • Fix the last-room race with a conditional atomic update + row-count check + a DB constraint.
  • Hold with a TTL (~10 min), lazy expiry, and a sweeper only for cleanup. The state machine uses conditional transitions.
  • Idempotency key on every write. Store the outcome. Read it from the primary. Never call the PSP inside a DB transaction.
  • Search is AP (CDC-fed index, stale is OK). Booking is CP (source-of-truth DB).
  • Keep reservation + inventory in one service/DB to avoid a saga, unless forced to split.
