Design the data model for a food delivery app (Swiggy / Zomato).

Entities: users, restaurants, menu_items, orders, order_items, riders, plus deliveries (order to rider assignment). Orders carry user_id, restaurant_id, status, created_at and a total. order_items use a composite PK (order_id, line_no) and copy price_at_order so later menu edits do not rewrite history. Indexes: (user_id, created_at DESC) for order history, (restaurant_id, status) for the kitchen screen, a geo index on restaurants. Rider locations are hot, high-write, short-lived data, so they go in Redis GEO, not Postgres.

How to answer

List APIs first, write the query for each, then show the table and the index next to each query. Call out one deliberate denormalization (price_at_order) and one data store split (locations in Redis).

Likely follow-ups
  • How do you shard orders? (By user_id for history, but kitchens query by restaurant: use a second read model.)
  • How do you stop two riders taking the same order?
  • Where do order status events go? (Kafka, see d07.)
