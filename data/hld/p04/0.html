The story

Explain like I'm 5

There is one big library book about dinosaurs, and every child in school wants to read it. If they all queue at the one librarian, the line goes out the door. So the librarian makes some photocopies and puts them in every classroom. Now most children read the copy in their own room and never walk to the library.

But there are tricky bits. When a new dinosaur is found, the old copies are a little out of date. If every copy is thrown away at the same moment, all the children run to the library together. And if the book is about the most famous dinosaur in the world, even one classroom copy is not enough - you need several.

That is the whole pattern. The database is the library: it holds the true answer, but it can only serve so many people at once. A read replica is a full copy of the library in another building. A cache is a photocopy of just the popular pages, kept in fast memory. A CDN (content delivery network) is a photocopy kept in every neighbourhood of the world. A read model is a copy that is already arranged the way readers want it, like a summary sheet.

Each copy makes reads cheaper. Each copy can also be stale (out of date), and each one creates a new way for the system to fall over. Scaling reads well means picking the cheapest copy that is fresh enough, and planning for the moment that copy goes missing.
