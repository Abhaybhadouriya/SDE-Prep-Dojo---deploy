Failure modes

  • Bid service crashes after the DB commit but before replying: the client retries with the same idempotency key; the unique (bidder_id, idem_key) returns the original result.
  • Pub/sub publisher down: bids still commit (the outbox holds the events); watchers see stale prices and fall back to polling; events flow on recovery.
  • Closer late: no wrong winner, because bids after ends_at are rejected by the bid check; only the announcement is late. Alert on "auctions past end still LIVE".
  • Shard failover during the last minute: a few seconds of rejected bids for that auction. Consider extending the end time automatically if a shard was unavailable during the final window (fairness).
  • Search index lag: results show an old price; the item page shows the real one. Acceptable.
  • Shill bidding or bots: out of core scope; mention rate limits per user per auction and anomaly detection.
