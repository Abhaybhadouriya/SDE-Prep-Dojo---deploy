  • The bug is read-check-write. The first fix is to put the check in the write and count rows affected.
  • Pessimistic = lock first (frequent conflicts, short transactions). Optimistic = version check and retry (rare conflicts).
  • Never hold a DB lock during human think-time; use holds with an expiry checked inside the write.
  • Distributed locks: efficiency vs correctness. Correctness needs fencing tokens or DB atomicity.
  • The best lock is no lock: single writer per key (Kafka partition, one thread per order book).
  • Hot keys are a throughput problem: shard the counter, batch writes, and add a waiting room.
