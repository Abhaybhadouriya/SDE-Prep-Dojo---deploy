  1. Location stream Hello Interview's Uber breakdown uses 10M drivers pinging every 5 s: 10M / 5 = 2M events/s. At ~100 bytes each, that is 200 MB/s into Kafka, about 17 TB/day before compression. This is the supply input.
  2. Demand stream Assumption: 30M trips/day and ~5 fare views per trip (people check prices before booking) = 150M estimates/day. 150M / 86,400 is about 1,700/s average; at 3x peak, ~5K/s. Each estimate is a demand event and also a read of the surge value.
  3. Cell size H3 resolution 8 cells average 0.737 km² (edge ~0.53 km); resolution 7 cells are 5.16 km². Res 8 is about a few city blocks: fine enough to separate a stadium from the next neighbourhood, coarse enough to have several drivers per cell.
  4. Number of active cells Assumption: 1M km² of served urban area. 1M / 0.737 = ~1.36M cells. Per cell we keep a few counters (~100 bytes): 1.36M x 100 B = ~136 MB of state per window. Small. The challenge is the 2M/s input rate, not the state size.
  5. Surge output writes Recompute every 60 s: at most 1.36M keys / 60 s = ~23K writes/s to the key-value store, far less if you only write cells whose value changed.
  6. Surge reads Every fare estimate reads 1 key (~5K/s), the driver heatmap reads a viewport of cells. Cache per city in memory; this is trivial.
  7. ETA load Uber's routing post: hundreds of thousands of ETA requests/s. Why so many? Matching computes ETAs for many candidate drivers per request, the app shows ETAs for nearby cars, and every fare quote needs a trip ETA. Size the ETA tier for ~500K/s.
  8. ETA servers Assumption: one routing server handles ~2,000 queries/s at single-digit ms on a city-partitioned graph. 500K / 2,000 = 250 servers, plus redundancy across zones, so ~400. The ML model serving tier is sized separately (DeepETA is "the highest QPS model at Uber").

From your world

2M pings/s of 100-byte records is like a busy NetFlow/IPFIX collector. You would never write each record to a database row; you aggregate in memory per key and per interval, export counters, and drop late records. Surge is exactly that, with H3 cell id as the flow key.
