Key APIs

# Rider: fare estimate (creates a short-lived quote)
POST /v1/quotes   body: {pickup:{lat,lng}, dropoff:{lat,lng}, product:"uberx"}
  -> {quoteId:"q_8f2", price:{amount:412, currency:"INR"}, surge:1.4, pickupEtaSec:240, tripEtaSec:1320, expiresAt:"...+5m"}

# Rider: request a ride with the quote (price is locked by quoteId)
POST /v1/rides    Idempotency-Key: ...  body: {quoteId:"q_8f2"}

# Driver: heatmap for the map viewport
GET  /v1/surge/heatmap?city=blr&bbox=...&res=8  -> [{cell:"8861892...", multiplier:1.6}, ...]

# Internal: ETA
POST /v1/eta      body: {origins:[{lat,lng}...], destination:{lat,lng}, mode:"pickup"}  -> [{etaSec:212}, ...]

# Internal: surge lookup (hot path, in-memory)
GET  /v1/surge?cell=8861892...&product=uberx  -> {multiplier:1.4, version:"2026-11-23T18:41Z"}

The ETA API is batched (many origins to one destination) because matching asks "how far is each of these 20 drivers from this rider?" in one call. The quote carries a version of the surge snapshot it used, so support and audit can explain any price later.
