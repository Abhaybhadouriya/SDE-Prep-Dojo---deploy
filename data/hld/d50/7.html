Where Kafka, Kubernetes and Docker fit

ToolRoleDetails worth saying
KafkaInput streams (driver pings, rider demand, trip state), surge output topic, ETA vs ATA logsPartition by H3 parent cell or city so ordering and locality hold; regional + aggregate clusters for multi-region; short retention for pings. Uber measures ETA accuracy by reading actual arrival times from Kafka logs. See Kafka core concepts, Replication.
FlinkWindowed aggregation and pricingEvent-time tumbling windows, watermarks, keyed state in RocksDB, checkpoints to object storage. See Connect, Streams & Flink.
KubernetesQuote, ETA front end, heatmap and model-serving pods; Flink via an operatorHPA on QPS for ETA pods; node pools with big memory for routing servers (graph held in RAM); pod anti-affinity across zones. See Scheduling & Autoscaling, Operators.
DockerPackaging routing engine with a versioned map build, and model serversMap data and models change on their own schedules; ship them as versioned artifacts the container pulls at start, so you can roll back a bad map or model independently.
 
-- Flink SQL sketch: supply and demand per H3 cell per minute
-- (h3_cell is a UDF wrapping the open-source H3 library)
SELECT h3_cell(lat, lng, 8)                      AS cell,
       TUMBLE_START(event_time, INTERVAL '1' MINUTE) AS win,
       COUNT(DISTINCT CASE WHEN kind = 'driver_open' THEN driver_id END) AS supply,
       COUNT(CASE WHEN kind IN ('fare_view','request') THEN 1 END)        AS demand
FROM marketplace_events
GROUP BY h3_cell(lat, lng, 8), TUMBLE(event_time, INTERVAL '1' MINUTE);
