  • Problem = concurrent edits on different copies; goal = convergence + intention.
  • OT: positional ops + transform; practical with a central server ordering ops (Google Docs).
  • CRDT: unique ID per element + tombstones; ops commute; great offline/peer-to-peer; costs metadata (Yjs, Automerge).
  • One owner session server per document gives a total order; find it via a lease registry; fence zombies with an epoch.
  • Clients apply locally first, send ops with baseRev and (clientId, seq) for dedup.
  • Op log (doc_id, rev) + snapshots every ~1,000 ops = durability, fast load, version history.
  • Presence and cursors are ephemeral; cursors must be transformed too.
  • Scale problem = millions of sockets: separate gateways, drain on deploy, jittered reconnect.
