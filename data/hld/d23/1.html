Requirements

Functional (in scope)
  • Create, open and edit a text document.
  • Many users edit the same document concurrently.
  • Everyone sees others' changes in (near) real time.
  • See other users' cursors and presence ("Bob is here").
  • Stretch: offline editing, version history, comments, sharing permissions.
Out of scope (say it)
  • Rich layout (tables, images) - assume plain text, the algorithm extends.
  • Spreadsheet formulas, slides.
  • Search across all documents, spam / abuse.
  • Full permission model (just check editor / commenter / viewer at connect).
Non-functional requirementTargetWhy it matters
ConvergenceAll replicas of a document end with identical contentThe one thing that must never break
DurabilityAn edit the server acknowledged is never lostLosing a paragraph destroys trust
LatencyYour own typing appears instantly (local first); others' edits within about 100-200 ms in the same regionTyping must never wait for the network
Concurrency per docTens of simultaneous editors comfortably, many more viewersReal product limits exist; ask the interviewer
ScaleMillions of concurrent connections, billions of documentsDrives the WebSocket and storage design
AvailabilityA server crash causes a brief reconnect, not lost workClients buffer and resend

Jargon check. Optimistic local apply = show my keystroke on my screen immediately, before the server agrees. Ack = the server's "got it, you are revision 43". Revision = a version number of the document that goes up by one per accepted operation. Presence = who is online in the doc and where their cursor is - temporary data that is fine to lose.
