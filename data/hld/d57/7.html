Where Kafka, Kubernetes and Docker fit

  • Kafka is the backbone of the near-line path: crawler emits page-fetched events, parsers and dedupers consume them, and the real-time indexer builds small fresh segments. Partition by URL host so per-host politeness and ordering are simple; replay a topic to rebuild after a bug. Query logs also go to Kafka for spelling models, popularity and ranking training. See Kafka core concepts and Big Data & Streaming.
  • Kubernetes runs the stateless tiers well (frontends, mixers, query understanding) with HPA on QPS. Index leaves are stateful and large; run them as StatefulSets with local SSDs and an operator that loads shard versions, or on dedicated nodes. Google itself runs on Borg, the system Kubernetes was inspired by. See StatefulSets and operators.
  • Docker: try a real inverted index locally with Elasticsearch in a container, index a few documents and inspect analyzers and scoring (run and manage containers).
$ docker run -d --name es -p 9200:9200 -e discovery.type=single-node \
    -e xpack.security.enabled=false docker.elastic.co/elasticsearch/elasticsearch:8.15.0
$ curl -s -X POST localhost:9200/pages/_doc -H 'Content-Type: application/json' \
    -d '{"title":"Red panda facts","body":"The red panda lives in the Himalayas"}'
$ curl -s 'localhost:9200/pages/_search?q=body:panda&explain=true'   # see BM25 scoring
