What if this box fails?

  • Scoring pods: stateless; Kubernetes restarts them; the payment service uses the fallback policy during the gap.
  • Online feature store node: replicas serve reads; if a shard is gone, score with missing features (degraded) rather than time out.
  • Flink job down or lagging: features go stale silently. Alert on lag in seconds; the sync 60-second counters still catch bursts; restart from the last checkpoint and catch up from Kafka.
  • Kafka unavailable: scoring keeps answering (publishing is async with a local buffer); some events may be published late, so features lag.
  • Bad model or rule pushed: block rate spikes. Automatic guard: if block rate or challenge rate moves beyond a band, roll back to the previous version. Always keep the last good version hot.
  • Model drift: fraudsters adapt, so performance decays. Monitor score distributions and early-label precision weekly; retrain regularly.
Strengths
  • Fast path is small and stateless
  • Kafka log lets you rebuild features and retrain on exact history
  • Rules give same-minute response to new attacks
Costs
  • Three paths to keep consistent (skew risk)
  • Labels are late and biased
  • Stale features fail silently, so monitoring is essential
