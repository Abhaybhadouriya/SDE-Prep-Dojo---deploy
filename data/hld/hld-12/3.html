MapReduce: the idea that started it

In 2004 Jeffrey Dean and Sanjay Ghemawat published MapReduce. You write two small functions. map turns each input record into (key, value) pairs. reduce receives all values for one key and merges them. The framework does the hard parts: splitting the input, scheduling tasks on thousands of commodity machines, moving data between them, and re-running tasks when machines die. The paper says over a thousand MapReduce jobs ran on Google's clusters each day. Click through the classic word count.

  1. Split. The input in the distributed file system is cut into pieces, typically 16-64 MB each in the paper, so each piece sits on a local disk of some worker.
  2. Map. The master sends the code to where the data is (data locality) and each mapper emits (word, count). A combiner pre-adds locally, so map 1 sends a:2, not a:1, a:1.
  3. Shuffle. Every pair is routed by hash(key) mod R, so all values for one key land on the same reducer. This all-to-all network step is usually the slowest part.
  4. Reduce. Each reducer sorts its pairs by key and adds up the values for each word.
  5. Output. Each reducer writes one output file to the distributed file system.
  6. Failures. Workers that stop answering pings get their tasks re-run elsewhere. Near the end, the master starts backup tasks for slow stragglers. Without backups, the paper's 1 TB sort took 44% longer.

# Word count, MapReduce style (single machine sketch)
from collections import defaultdict

def map_fn(line):
    for word in line.split():
        yield word, 1

def reduce_fn(word, counts):
    return word, sum(counts)

lines = ["a b a", "b c", "a c c"]
groups = defaultdict(list)                 # the "shuffle"
for line in lines:
    for k, v in map_fn(line):
        groups[k].append(v)
print(sorted(reduce_fn(k, vs) for k, vs in groups.items()))   # [('a', 3), ('b', 2), ('c', 3)]

From your world

The shuffle is ECMP hashing on a 5-tuple: the same key always goes to the same "next hop" (reducer), so per-key order and grouping are kept. Backup tasks are like sending a request down two paths and taking the first reply. Where this breaks: unlike ECMP, the shuffle buffers, sorts and spills all the data to disk, and it is a barrier: no reducer can finish until every mapper has finished. A dead reducer is re-run from the saved map output; it is not simply re-routed.
