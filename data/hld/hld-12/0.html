The story: counting the whole school's lunch boxes

Explain like I'm 5

The principal wants to know how many kids brought apples this year. One teacher counting every lunch box alone would take forever. So each class teacher counts their own class (that is the map step). Then one helper adds up all the class totals (that is the reduce step). That is batch work: done once, after lunch, over a big pile.

Now the principal wants a scoreboard that changes while kids walk in. A helper stands at the door and adds one every time an apple goes by. That is streaming. But some kids are late, and some walk in through the back door later. The helper has to decide, "I will wait 5 more minutes for late kids, then write the final number." That waiting rule is a watermark.

Finally, the principal asks "How many different kids came today?" Remembering every face is hard. A clever trick, a small notebook where you only write down a few patterns, gives an answer that is almost right using almost no paper. Those tricks are probabilistic data structures.

From your world

Batch is like post-processing a full packet capture file: all the data is there, and you can re-run your script as often as you like. Streaming is like a line-rate counter in the forwarding path: it updates per packet and must cope with packets that arrive out of order. A watermark is like the IP reassembly timeout you already know: "wait this long for missing fragments, then give up". Where this breaks: a reassembly timer runs on the wall clock per flow, while a watermark moves with the event timestamps inside the data.

This page covers all three ideas. First, where analytics data lives (warehouses, lakes, lakehouses). Then how big jobs are split across machines (MapReduce, Spark). Then how continuous streams are processed (Flink, windows, watermarks, lambda vs kappa). Last, the three small structures interviewers love: Bloom filter, HyperLogLog and count-min sketch.
