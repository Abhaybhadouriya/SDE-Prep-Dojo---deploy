OLTP vs OLAP: two very different jobs

OLTP (online transaction processing) is the app's own database: "place this order", "get user 42". Many tiny reads and writes, each touching a few rows, and each must be fast and correct (Postgres, MySQL, DynamoDB). OLAP (online analytical processing) answers questions about the business: "revenue by city by week for two years". Few queries, but each scans billions of rows and only a few columns (Snowflake, BigQuery, Redshift, ClickHouse, Pinot, Druid).

OLTPOLAP
Query shapePoint reads/writes by keyScans + aggregates over huge ranges
UsersThe app, millions of end usersAnalysts, dashboards, ML pipelines
LayoutRow-oriented, B-tree/LSM indexesColumnar, compressed, partitioned by date
FreshnessNowMinutes to a day old (seconds for real-time OLAP like Pinot)
SchemaNormalisedDenormalised star schema (fact table + dimension tables)

Never run heavy analytics on the production OLTP database: one big scan can evict the cache and slow every user. Copy the data out, usually by CDC (change data capture: streaming the database's change log into Kafka). See CDC Data Pipeline (d28) and Data Modeling & Storage Engines (hld-07).
