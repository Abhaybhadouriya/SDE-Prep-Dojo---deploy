Where Kafka, Kubernetes and Docker fit

  • Kafka is the spine: the durable, replayable log between OLTP (via CDC) and every processor. Partitions set parallelism, keys keep per-entity order, and retention decides how far back Kappa-style replay can go. See Kafka Core Concepts, Connect, Streams & Flink and Exactly-Once.
  • Kubernetes runs Flink and Spark through operators (Flink Kubernetes Operator, Spark Operator): a custom resource describes the job, and the operator creates JobManager/TaskManager pods and restores them from checkpoints or savepoints. See StatefulSets & Operators and Autoscaling.
  • Docker packages each job with its exact library versions so batch and stream jobs behave the same in dev and prod. Try it end to end in Pipeline: Stream Processing, Retries & DLQ.

Here is what a Flink job looks like to Kubernetes. You build a Docker image that contains your job JAR, then apply one custom resource. The Flink Kubernetes Operator reads it, starts a JobManager pod and enough TaskManager pods for the parallelism, and on an upgrade takes a savepoint first, then restarts the job from it.

# FlinkDeployment custom resource (Flink Kubernetes Operator)
apiVersion: flink.apache.org/v1beta1
kind: FlinkDeployment
metadata:
  name: ad-click-counter
spec:
  image: registry.example.com/ad-click-counter:1.4.2   # Docker image with the job JAR
  flinkVersion: v1_19
  serviceAccount: flink
  flinkConfiguration:
    taskmanager.numberOfTaskSlots: "2"
    execution.checkpointing.interval: "30s"              # snapshot state every 30 s
    state.checkpoints.dir: s3://flink-ckpt/ad-clicks     # where snapshots live
  jobManager:
    resource: { memory: "2048m", cpu: 1 }
  taskManager:
    resource: { memory: "4096m", cpu: 2 }
  job:
    jarURI: local:///opt/flink/usrlib/ad-click-counter.jar
    parallelism: 8              # 8 slots = 4 TaskManager pods of 2 slots
    upgradeMode: savepoint      # on change: savepoint, stop, restart from it

Match parallelism to the Kafka topic: with 8 partitions, 8 source tasks each read one partition. Extra source tasks beyond the partition count just sit idle.
