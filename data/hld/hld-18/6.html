Inside a WAF rule engine

Good to know (SDE-2)

A web application firewall (WAF) inspects each HTTP request against an ordered list of rules. In AWS WAF this list is a web ACL (also called a protection pack): rules and rule groups evaluated in priority order, each with a match statement and an action.

Managed rule sets

You rarely write SQL-injection regexes yourself. Vendors ship managed rule groups, maintained as new attacks appear: in AWS, groups like the core rule set, known bad inputs, SQL database, IP reputation and anonymous IP lists, plus paid ones such as Bot Control and account-takeover prevention. The open-source equivalent is the OWASP Core Rule Set (CRS), run by ModSecurity or Coraza.

CRS uses anomaly scoring instead of "first match blocks": each matching rule adds points by severity (critical 5, error 4, warning 3, notice 2), and the request is blocked only if its total reaches the inbound threshold, which is 5 by default. One weak indicator does not block; several do. CRS also has paranoia levels 1 to 4: level 1 is the baseline that rarely produces false positives; each higher level adds more aggressive rules and more false positives that must be tuned away.

Capacity and cost

Rules are not free to evaluate. AWS WAF prices rule complexity in web ACL capacity units (WCUs): a web ACL has a default budget of 1,500 WCUs (a rate-based rule costs 2 base plus 30 per custom aggregation key; Bot Control costs 50). Regex-heavy rules on large bodies cost more, and bodies are only inspected up to a size limit, which attackers know about. Put cheap, high-hit rules (IP lists, geo) first so most junk terminates early.

Rate-based rules

A rate-based rule counts requests per aggregation key over an evaluation window and applies its action to the excess. In AWS WAF the window can be 60, 120, 300 (default) or 600 seconds, the lowest limit is 10, and the key can be the source IP, an IP from a header such as X-Forwarded-For, or custom keys (a header, cookie, query argument, label, or combinations). A scope-down statement limits which requests are counted, so you can set a tight limit on POST /login without touching static assets. The limit is approximate: WAF checks frequently but not per request, so a few extra requests slip through before it reacts. For exact, per-user business quotas you still want an application limiter like d02.

From your world

A web ACL is a TCAM ACL: ordered entries, first terminating match wins, implicit default at the end, and a hardware budget (WCUs are your TCAM entries). Count is permit ... log with a hit counter. Labels are like QoS marking in an ingress policy that a later egress policy matches on. A rate-based rule is a policer keyed on a flow tuple; choosing the aggregation key is the same decision as choosing per-source vs per-destination vs per-5-tuple policing, and the wrong key either punishes a whole NAT pool or lets a distributed source through.
