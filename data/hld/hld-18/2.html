How the layers stack at the edge

Must know (SDE-1)

Each layer removes one class of junk cheaply so the next, more expensive layer only sees what it can handle. The order matters: you want to drop a volumetric flood before you spend CPU parsing HTTP, and you want to parse HTTP before you run a machine-learning model.

LayerExample productsDecides onCost per request
1 DDoS shieldAWS Shield (Standard is automatic and free; Advanced adds L7 help and a response team), Cloudflare, Google Cloud ArmorPackets, flows, protocol anomaliesTiny (often in kernel, XDP/eBPF)
2 WAF rulesAWS WAF, Cloud Armor, Cloudflare WAF, ModSecurity / Coraza with OWASP CRSOne request's headers, URI, bodySmall (regex and string matching)
3 Bot managementAWS WAF Bot Control, Cloudflare Bot Management, reCAPTCHA Enterprise, Akamai, DataDomeClient fingerprint, token, behaviour over timeMedium (state lookups, models)
4 Rate limitsWAF rate-based rules, API gateway quotas, your own limiter (d02)Counters per key over a windowSmall, but needs shared state
5 App risk engineYour own fraud and account-security serviceAccount history, device, payment, graphHighest (database and model calls)

Hide the origin. All of this is useless if attackers can reach your origin directly. Accept traffic only from the CDN or edge ranges (security groups, a secret header the edge adds, or mTLS between edge and origin), or the attacker simply skips the bouncer and uses the back door.
