Signals: what the edge can see

Must know (SDE-1)

A bot detector is a classifier, and a classifier is only as good as its features. Signals come in four families, from cheapest and weakest to most expensive and strongest:

FamilyExamplesStrengthHow bots fake it
NetworkIP reputation, ASN (data centre vs residential vs mobile), geo, proxy/VPN/Tor lists, request rate per IPCheap, available on the first packetResidential proxy networks rotate through millions of home IPs
Protocol / TLSJA3/JA4 TLS ClientHello fingerprint, HTTP/2 settings and header order, User-Agent consistencyPassive, hard to fake perfectlyLibraries that mimic Chrome's TLS stack
Client environmentJavaScript challenge results: headless-browser markers, canvas/WebGL, fonts, automation extensions, inconsistencies between claimed and real browserStrong, needs JS (or a mobile SDK)Patched headless browsers, anti-detect browsers
BehaviourMouse and touch movement, typing rhythm, time between pages, navigation path, how a session's requests are spread over timeStrongest, needs time and dataReplaying recorded human traces; very slow, "low and slow" bots

JA4 deserves a moment. When a client opens TLS it sends a ClientHello listing cipher suites, extensions, supported groups and ALPN. Each TLS library does this in its own characteristic way. JA3 hashed those fields; when Chromium began randomising the extension order in 2023, JA3 became unstable, so JA4 sorts the fields before hashing and adds ALPN and other dimensions. The killer feature is the mismatch: a request whose User-Agent says "Chrome on Windows" but whose TLS fingerprint says "Python requests" is almost certainly a script.

From your world

This is exactly passive OS fingerprinting. p0f identifies a Linux or Windows stack from the TCP SYN: initial window, TTL, MSS, window scale and the order of TCP options. JA4 does the same for the TLS ClientHello. And the "claimed vs real" mismatch is the same trick an IDS uses when a packet claims to be from an internal subnet but arrives on the internet-facing interface: like a uRPF check, it is the inconsistency, not any single value, that gives the game away.

The token trick: carrying evidence between requests

Heavy signals (JavaScript interrogation, a CAPTCHA solve) are too expensive to collect on every request. So the edge collects them once and gives the client a signed, short-lived token (usually a cookie) that says "this browser passed checks at 10:02 with these properties". Later requests just present the token. AWS WAF does this with its challenge and CAPTCHA tokens and labels each request as accepted, rejected or absent. The token itself then becomes a signal: if one token shows up from more than a handful of IPs, countries or ASNs within five minutes (AWS Bot Control has rules for exactly this), it was copied into a bot farm.
