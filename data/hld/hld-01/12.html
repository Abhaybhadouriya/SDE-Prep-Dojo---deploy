Queues and logs: do it later, safely Must know

Some work does not need to happen while the user waits. Sending the order-confirmation email, resizing an uploaded photo, updating the search index - the user only needs to hear "order placed". A message queue lets one service (the producer) drop a message into a buffer and move on, while other services (consumers) pick messages up and do the work at their own pace. This is called asynchronous (async) processing.

What a queue buys you:

  • Decoupling: the producer does not need to know who consumes, or whether they are up.
  • Smoothing spikes (load levelling): 10,000 orders in one second become work that consumers drain over the next minute.
  • Retries: if a consumer fails, the message is still there. After too many failures it goes to a dead-letter queue (DLQ) for a human to inspect.

Queue vs log (SQS/RabbitMQ vs Kafka)

Delivery guarantees

GuaranteeMeaningRisk
At-most-onceSend and forgetMessages can be lost
At-least-once (the usual default)Retry until acknowledgedDuplicates - so consumers must be idempotent
Exactly-onceEach message affects the result onceKafka offers it for read-process-write inside Kafka; end to end it is at-least-once + idempotent writes

Idempotent means "doing it twice has the same effect as doing it once". Setting status = 'PAID' is idempotent; balance = balance - 100 is not. The usual trick: give every message a unique ID and have the consumer skip IDs it has already processed (for example with a unique constraint on a processed_messages table).

From your world

A queue is the ring buffer between a NIC and its driver: the producer writes at the head, the consumer reads at the tail, and the buffer absorbs bursts. Consumer lag is ring occupancy; if it keeps growing, the drain is slower than the fill. Backpressure is TCP flow control or PFC pause frames: a slow consumer tells the producer to slow down. Kafka consumers pull (poll) like NAPI rather than being interrupted per message. An idempotency key is a TCP sequence number at the application level: a retransmitted duplicate is recognised and dropped. Where this breaks: a ring buffer overwrites old entries; Kafka never overwrites, it deletes whole old segment files after the retention time or size.
