SQL vs NoSQL: pick by access pattern Must know

A relational (SQL) database such as PostgreSQL or MySQL stores data in tables with a fixed schema, enforces rules (unique, foreign keys) and gives ACID transactions: a group of changes happens completely or not at all, and other users never see half of it. NoSQL is a loose name for everything else, built to scale out across many machines with simpler access patterns.

You asked for a one-sentence justification. Use this shape: "I'll use [store] because the main access pattern is [pattern] and we need [property]; the cost is [weakness], which is fine here because [reason]." Example: "I'll use Cassandra for messages because we always read the latest messages of one chat by chat ID and need very high write throughput; we lose joins and cross-chat transactions, which this feature does not need."

Tip: "SQL does not scale" is a myth interviewers will push back on. A single PostgreSQL primary on a large machine handles a lot (planning figure: thousands to tens of thousands of simple writes per second, an order-of-magnitude guess, not a benchmark), and read replicas multiply read capacity. Pick SQL when you need its guarantees; say how you would shard it later. More in Choosing Storage and Data Modeling & Indexing.
