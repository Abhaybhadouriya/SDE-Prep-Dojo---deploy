How real systems do it

  • Tinder geosharding (2019 series) - S2 levels 7-8, load-scored cells grouped into geoshards, one Elasticsearch cluster with an index per geoshard and per-shard replica counts, Kafka by user id for ordered moves, Get API for strongly consistent reads, background re-sync.
  • Tinder on Elasticsearch 8 (2025) - more than 90% of recommendations from one cluster; geosharding about 12% CPU vs about 50% single-index; p99 latency down 12-56%; Kafka as the source of truth for backfilling a new cluster; ECK on Kubernetes.
  • systemdesign.one newsletter - about 26 million matches a day, around 500 microservices, profiles in DynamoDB, about 3 shards per 160 km query, ordering by user id through Kafka.
  • High Scalability "Designing Tinder" - left swipes to S3 for analytics, right swipes to a stream and a likes cache, logistic regression ranking.
