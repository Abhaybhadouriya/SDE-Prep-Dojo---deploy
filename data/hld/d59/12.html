Quiz

Why store both swipe directions under the key min(a,b):max(a,b)?

  1. It saves disk space
  2. So write-and-check is a single-key atomic operation, removing the race
  3. So swipes sort alphabetically
Both users' swipes go to the same key and shard, where operations are serialised.

2 billion swipes a day is about how many writes per second on average?

  1. 200
  2. 2,000
  3. 20,000
2,000,000,000 / 100,000 s = 20,000/s (about 23,000 with 86,400 s).

A Bloom filter says a candidate was "probably seen", but it was not. What happens to the user?

  1. One profile is hidden that could have been shown - acceptable
  2. They see a repeat profile
  3. The swipe fails
Bloom filters have false positives only; here that hides a card, it never shows a repeat.

Why did Tinder group S2 cells by load instead of using equal-sized shards?

  1. S2 cells cannot be equal-sized
  2. Equal areas give hot city shards and empty rural or ocean shards
  3. Elasticsearch requires it
Load (active users, queries) is what must be balanced, not area.

How does Tinder keep one user's location updates in order across geoshard moves?

  1. A global lock
  2. Two-phase commit
  3. Kafka partitioned by user id
Same key, same partition, in-order processing - plus a background re-sync.

Where should the API get the swiper's user id?

  1. From the authenticated token
  2. From the request body
  3. From a query parameter
Anything in the body can be forged; identity comes from the verified token.

Why do S2 cells suit load-based geosharding better than geohash rectangles?

  1. S2 cell ids are shorter strings
  2. S2 cells at one level have roughly equal area on the sphere and follow a Hilbert curve, so neighbouring cells are easy to group by load
  3. Geohash cannot represent cities
Geohash rectangles distort with latitude; S2's near-equal areas and Hilbert ordering make "group adjacent cells until the load threshold" simple. Geohash still works for smaller systems.

Why is the pair key min(a,b):max(a,b) and not "a:b"?

  1. Shorter keys use less memory
  2. Redis requires sorted keys
  3. Asha swiping on Ben and Ben swiping on Asha must produce the same key, or the two swipes land on different shards and race
Sorting the two ids makes the key identical from both directions, so both swipes hit the same key on the same shard, where one atomic script serialises them.
