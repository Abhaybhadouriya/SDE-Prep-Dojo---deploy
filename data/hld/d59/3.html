Key APIs

POST /v1/profile            body: {ageMin, ageMax, interestedIn, maxDistanceKm, bio}
PUT  /v1/location           body: {lat, lng}                       # on app open / significant move
GET  /v1/stack?limit=100    -> [ {userId, name, age, photos[], distanceKm} ]   # no page numbers; ask again when low
POST /v1/swipes             body: {targetUserId, decision: "yes"|"no", swipeId}
                            -> { matched: true|false, matchId? }
GET  /v1/matches?cursor=... -> [ {matchId, otherUser, createdAt} ]
  • The swiper's id comes from the auth token (session or JWT), never from the body - otherwise anyone could swipe as anyone. See Authentication & SSO.
  • swipeId is an idempotency key generated on the phone, so a retry on a flaky network does not count twice.
  • The swipe response says matched: true when this swipe completed a match - so the second swiper sees "It's a match!" instantly. The first swiper is told by a push notification (APNs / FCM) or over an open WebSocket.
