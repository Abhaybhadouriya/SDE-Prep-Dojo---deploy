Wide-column stores

A wide-column store (Bigtable, HBase, Cassandra, ScyllaDB) looks like a table but behaves like a sorted map of maps. The partition key decides which machine holds the row group (it is hashed onto a ring). The clustering key decides the sort order of rows inside that partition. Every column value carries a write timestamp, and conflicting writes resolve by "last write wins".

Under the hood it is an LSM-tree (see hld-07): commit log, memtable, immutable SSTables, compaction. That is why it is the classic pick for "billions of writes per day".

The one rule: you model tables per query. Cassandra has no joins and weak secondary indexes, so if two screens ask different questions you usually keep two tables with the same data, written together. Hello Interview calls this query-driven modeling. Discord's message table is the textbook example:

CREATE TABLE messages (
  channel_id bigint,
  bucket     int,          -- 10-day window since Discord's epoch
  message_id bigint,       -- Snowflake ID, sorts by time
  author_id  bigint,
  content    text,
  PRIMARY KEY ((channel_id, bucket), message_id)
) WITH CLUSTERING ORDER BY (message_id DESC);

"Give me the last 50 messages of channel 7" becomes one partition, read from the top. The bucket stops a busy channel from growing one endless partition. Discord ran this on 177 Cassandra nodes and later 72 ScyllaDB nodes, with p99 reads (p99 = the latency that 99% of requests beat; 1 in 100 is slower) dropping from 40-125 ms to 15 ms after the move. The pain they hit is the pain you should name in an interview: hot partitions for popular channels, compaction falling behind, and JVM garbage-collection pauses.

Tunable consistency in one picture

Consistency is chosen per request: ONE (fastest, may read stale), QUORUM (n/2 + 1 replicas) or ALL. A failed replica's writes are held by the coordinator as hints and replayed when it returns (hinted handoff). The deeper theory (quorums, gossip, anti-entropy) is in hld-09; the Dynamo design that inspired all of it is d32 Key-Value Store.
