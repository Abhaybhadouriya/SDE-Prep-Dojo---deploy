Quick quiz

A ride-hailing app stores each driver's live location every 4 seconds and only needs the latest one. Best fit?

  1. Elasticsearch
  2. S3
  3. An in-memory key-value / geo store such as Redis
Hot, short-lived, overwrite-heavy data that you can lose and rebuild: Redis GEO is the usual answer.

Why does a Cassandra message table include a time bucket in the partition key?

  1. To enable joins
  2. To keep any one partition from growing without limit
  3. To make writes strongly consistent
Without a bucket a busy channel becomes one ever-growing, hot partition. Discord used 10-day buckets.

A DynamoDB table has spare capacity but one partition key is throttled. Why?

  1. Capacity limits apply per partition (about 1,000 write units per second)
  2. GSIs are strongly consistent
  3. Items are larger than 16 MiB
A single hot key cannot use the whole table's capacity. Spread it with write sharding or caching. (16 MiB is MongoDB's document limit; DynamoDB items cap at 400 KB.)

With erasure coding k=4, m=2, how many shards can be lost without losing the object?

  1. 2
  2. 0
  3. 1
Any k=4 of the 6 shards rebuild the object, so up to m=2 can fail, at 1.5x storage overhead.

Which tag would cause a cardinality explosion in a time-series database?

  1. region
  2. user_id
  3. host
Millions of unique values multiply the number of series and exhaust the in-memory index.

Why is a column store faster for "SUM(revenue) GROUP BY country" over 2 billion rows?

  1. It keeps every row in RAM
  2. It reads only the needed columns, which compress well
  3. It uses B-tree indexes on every column
Columnar layout plus compression and vectorized execution means far fewer bytes read per query.

What is the safest way to keep Elasticsearch in sync with Postgres?

  1. CDC from the Postgres WAL into Kafka, applied by an idempotent indexer
  2. Write to both from the app
  3. Lower the refresh interval
Dual writes diverge on partial failure. CDC gives one ordered stream of changes that can be replayed.

How does Facebook's TAO store the social graph?

  1. As objects and associations in sharded MySQL behind a cache tier
  2. In a dedicated graph database
  3. In Elasticsearch
TAO is a graph API over MySQL with write-through caching, serving over a billion reads per second.
