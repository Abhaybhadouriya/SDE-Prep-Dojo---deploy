The eight shapes of data

The System Design Primer splits NoSQL into four classic families (key-value, document, wide-column, graph). ByteByteGo's "how to choose the right database" guide adds OLAP, full-text search, embeddings (vectors) and geospatial. Put those together with relational (SQL) and object storage and you get the map below. Every real product is one of these, or a mix.

FamilyMental modelGreat atBad atProducts
RelationalTables of rows, foreign keysTransactions, joins, ad-hoc queries, constraintsHuge write rates on one node, schema churnPostgres, MySQL, SQL Server, Aurora, Spanner
Key-valueA giant hash mapO(1) get/put, caching, sessions, countersAny query not by keyRedis, Memcached, DynamoDB, RocksDB
DocumentKey → JSON treeEntities read whole, flexible fieldsMany-to-many joins, cross-document transactions at scaleMongoDB, Couchbase, DynamoDB, Firestore
Wide-columnPartition key → sorted rowsMassive append-heavy writes, range in a partitionAd-hoc queries, joins, strict consistencyCassandra, ScyllaDB, HBase, Bigtable
GraphNodes and edgesMulti-hop traversals ("friends of friends")Bulk analytics, sharding big graphsNeo4j, Neptune; Facebook TAO on MySQL
Time-series(series, timestamp) → valueIngest millions of points, compress, roll upTop-K across millions of series, updatesPrometheus, InfluxDB, TimescaleDB, Netflix Atlas
SearchWord → list of documentsFull-text, fuzzy match, facets, relevanceBeing the source of truth, heavy updatesElasticsearch, OpenSearch, Solr
VectorPoints in many-dimensional space"Find items similar in meaning"Exact answers, cheap memorypgvector, Pinecone, Milvus, Qdrant, Weaviate
Columnar (OLAP)Each column stored togetherScans and aggregates over billions of rowsSingle-row updates, point lookupsClickHouse, Druid, Redshift, BigQuery
Blob / objectKey → immutable bytesCheap, durable storage of big filesLow-latency small updates, queriesS3, Azure Blob, GCS

The default. Hello Interview's data modeling guide and ByteByteGo ("when in doubt, you can simply use PostgreSQL") give the same advice: start with a relational database and move away only when a requirement forces you. Postgres has extensions for most families: PostGIS (geo), pgvector (vectors), Timescale (time-series), full-text search. Saying "Postgres until a number says otherwise" is a strong, honest opening.
