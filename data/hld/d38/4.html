DataShapeStoreWhy
Posts (source of truth)post_id -> author, text, created_at, ...Sharded KV / wide-column (Cassandra, DynamoDB) or sharded MySQLPoint lookups by id to "hydrate" search hits.

Popularity indexterm -> sorted set (score = approx likes, member = post_id)Redis sorted sets or a second Lucene fieldTop-K by score without sorting at query time.
Like counts (truth)post_id -> countSharded counter service - see Distributed Counter100K writes/s; index only gets milestones.
Query cache(normalised query, sort, page) -> result idsRedis + CDN, TTL < 1 minHot queries ("world cup") repeat millions of times.

Why not SQL WHERE text LIKE '%cup%'? A leading wildcard cannot use a B-tree index, so the database scans every row. Sharding only divides the scan; it never removes it. An inverted index turns "find posts with cup" into "read one list". See Data modeling & indexing.
