Key APIs

Part A

# search (the hot path)
GET /v1/search/nearby?lat=37.7564&lng=-122.4016&radius=2000&category=pizza&cursor=abc
-> 200 { "businesses": [ {"id": "b_123", "name": "...", "distance_m": 412, "rating": 4.5}, ... ],
         "next_cursor": "def" }

# business details (cacheable, CDN-friendly)
GET    /v1/businesses/{id}

# owner actions (low QPS, authenticated)
POST   /v1/businesses            { name, address, lat, lng, category, hours }
PUT    /v1/businesses/{id}
DELETE /v1/businesses/{id}

# reviews
POST   /v1/businesses/{id}/reviews   { stars: 1-5, text }   # 409 if this user already reviewed it
GET    /v1/businesses/{id}/reviews?cursor=...

Notes: the radius is in metres; pagination is cursor-based (see API design). The server, not the client, picks the index precision from the radius.

Part B (WebSocket messages)

// phone -> server, every 30 s while sharing
{ "type": "location_update", "lat": 37.7564, "lng": -122.4016, "ts": 1763856000 }

// server -> phone, on connect: snapshot of nearby friends
{ "type": "nearby_snapshot", "friends": [ { "id": "u_9", "dist_mi": 1.2, "ts": 1763855990 } ] }

// server -> phone, when a friend moves (only if within radius)
{ "type": "friend_location", "id": "u_9", "lat": 37.76, "lng": -122.41, "ts": 1763856030 }

// server -> phone
{ "type": "friend_offline", "id": "u_9" }

Why WebSocket and not polling? Polling every 5 s by 10M phones would be about 2M requests/s, mostly answering "nothing changed". A WebSocket keeps one TCP connection open in both directions (see Pattern: Real-time Updates).
