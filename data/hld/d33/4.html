Data model

Part A tables

-- source of truth (PostgreSQL / MySQL, primary + read replicas)
CREATE TABLE business (
  business_id  BIGINT PRIMARY KEY,
  name         TEXT NOT NULL,
  category     TEXT,
  lat          DOUBLE PRECISION NOT NULL,
  lng          DOUBLE PRECISION NOT NULL,
  rating_sum   BIGINT DEFAULT 0,     -- for the average, see deep dive 4
  rating_count INT    DEFAULT 0,
  updated_at   TIMESTAMPTZ
);

-- the geo index: one row per business, keyed by its geohash
CREATE TABLE geo_index (
  geohash      CHAR(6),              -- precision 6 (~1.2 km x 0.6 km cells)
  business_id  BIGINT,
  PRIMARY KEY (geohash, business_id) -- prefix/equality lookups use this B-tree
);

CREATE TABLE review (
  user_id      BIGINT,
  business_id  BIGINT,
  stars        SMALLINT CHECK (stars BETWEEN 1 AND 5),
  body         TEXT,
  created_at   TIMESTAMPTZ,
  PRIMARY KEY (business_id, user_id)  -- enforces one review per user per business
);

SQL or NoSQL? For Part A, SQL is a good fit. The data is small (200 GB), relational (business, owner, reviews), and read-heavy, so a primary with read replicas works well. The geo index is so small it can live in the same database, in Redis, or inside each search server's memory. Some candidates store one geo_index row per precision (4, 5 and 6) so any radius maps to one equality lookup; that triples the index (still only about 10 GB).

Part B is different: the live location goes in a Redis key with a TTL (loc:{user_id} = lat, lng, ts; expires after 10 minutes), the friend graph in a sharded SQL or graph store, and history (if you keep it) in Cassandra, partitioned by (user_id, day) and clustered by timestamp.

From your world

A geohash prefix is an IP prefix for the planet. "9q8yy" is like 10.1.2.0/24: everything inside shares those leading bits, and a longer prefix is a smaller subnet. A prefix query on a B-tree (WHERE geohash LIKE '9q8yy%') is longest-prefix matching. And the same gotcha you know from routing applies: two hosts can be physically next to each other but sit on either side of a /24 boundary, so they share a much shorter prefix.
