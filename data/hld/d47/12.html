Quick quiz

20K prompts/s arrive and each answer streams for ~6 s. How many concurrent streams?

  1. 20K
  2. 120K
  3. 3.3K
Little's law: in-flight = rate x time = 20K x 6 = 120K.

Why is LLM decode throughput mainly limited by GPU memory?

  1. Each step reads all weights regardless of batch size, and batch size is capped by KV-cache memory
  2. Tokens are very large
  3. The CPU tokenizer is slow
Decode is memory-bandwidth bound, so larger batches are nearly free; KV memory decides how large a batch can be.

What does continuous batching change compared to static batching?

  1. It uses more GPUs
  2. It sorts prompts by length
  3. It re-forms the batch every iteration so finished sequences leave and new ones join
Iteration-level scheduling (Orca) removes idle slots.

PagedAttention is most like which OS mechanism?

  1. Process scheduling
  2. Virtual memory with page tables (and copy-on-write sharing)
  3. File system journaling
Fixed-size blocks, a block table per sequence, demand allocation, shared blocks with reference counts.

Why should an LLM API rate-limit by tokens per minute?

  1. Cost depends on tokens; one huge prompt can cost more than hundreds of small requests
  2. Tokens are easier to count than requests
  3. HTTP requires it
Requests are not equal; TPM tracks real cost. Use both RPM and TPM.

Why route a conversation's next turn to the same GPU worker?

  1. For security
  2. Because workers cannot share models
  3. Its KV cache may still hold the earlier turns, so prefill can skip them (prefix caching)
Prefix hits save expensive prefill compute and cut TTFT.

What should happen when a user clicks "Stop generating"?

  1. Only hide the text in the UI
  2. Send a cancel to the worker so the sequence leaves the batch and its KV blocks are freed
  3. Restart the worker
Otherwise the GPU keeps generating tokens nobody will read.
