Requirements

Functional

  1. Send a prompt, get a streamed answer Text in, text out, tokens appear as they are generated.
  2. Conversation history List past chats, open one, continue it with the earlier messages as context.
  3. Stop generating The user can cancel; the GPU work must stop too.
  4. Tiers Free and paid users; paid users get priority and higher limits.

Out of scope (Hello Interview's list): editing or branching messages, images/audio, sharing, custom GPTs, tool calling, web browsing, full-text search of history. Say you would add input and output moderation as a filter step (ByteByteGo's ChatGPT guide shows moderation before and after the model).

Non-functional

PropertyTargetNotes
Scale~200M daily active users, ~20K prompts/s peak, ~120K streams open at onceHello Interview's numbers
Time to first token (TTFT)p50 under ~1 s, p99 a few secondsHello Interview: first-token latency matters more than total time
Time per output token (TPOT)Faster than reading speed, roughly 20-50 ms per tokenUsers read as it streams
CostMaximise tokens per GPU-secondGPUs are scarce and expensive; this is the top constraint
DurabilityNo lost messages once shownHistory is a product feature
FairnessNo single user can monopolise GPUs; paid tiers get better serviceLimits are counted in tokens, not just requests

The two latency words come from the serving research (DistServe): TTFT covers the prefill phase, where the model reads the whole prompt in one parallel pass; TPOT is the average time for each later token in the decode phase. Total latency = TTFT + TPOT x output tokens.
