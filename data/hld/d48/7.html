Where Kafka, Kubernetes and Docker fit

📨

Kafka

The event backbone: impressions, clicks, plays, orders, keyed by user_id so one user's events stay ordered. Flink/Kafka Streams jobs compute nearline features; Kafka Connect sinks raw events into the lake. Uber's Michelangelo used Kafka plus Samza for the same job.

 ☸️

Kubernetes

Rec API and rankers as Deployments autoscaled on QPS and latency; ranker pods on GPU or high-CPU node pools; ANN shards as a StatefulSet with the index on local SSD; batch training as Jobs/CronJobs or a workflow engine.

 🐳

Docker

One serving image per model runtime; the model artifact is pulled from the registry by version at start, so rolling back a model does not need a new image.

 
// Kafka Streams sketch: maintain "last 20 items viewed" per user (nearline feature)
StreamsBuilder b = new StreamsBuilder();
b.stream("item-views", Consumed.with(Serdes.String(), viewSerde))      // key = userId
 .groupByKey()
 .aggregate(RecentItems::new,
            (userId, view, recent) -> recent.push(view.itemId(), 20),
            Materialized.with(Serdes.String(), recentSerde))
 .toStream()
 .to("feature-recent-items", Produced.with(Serdes.String(), recentSerde)); // sink to online store
