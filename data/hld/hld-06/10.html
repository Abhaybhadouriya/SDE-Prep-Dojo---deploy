Remember this

  • Default: REST outside, gRPC inside; GraphQL only for many clients with different data needs. Give a reason for any deviation.
  • Resources are plural nouns; user identity comes from the token; 4xx = client fault (do not retry blindly), 5xx = server fault (retry with backoff).
  • Paginate every growing list and cap the page size. Offset for small/admin data; opaque cursor on (sort key, id) for feeds and live data.
  • Additive changes are safe; anything else is a new version. /v1 in the URL is the interview default.
  • Every money or booking POST gets an idempotency key: client UUID, stored atomically with a unique constraint, replay the stored result.
  • Webhooks: sign, 2xx fast, queue, de-duplicate, reconcile. They are server-to-server only.
  • Polling for slow updates, SSE for one-way real time, WebSocket for two-way, WebRTC for media. Persistent connections need gateways, a registry or pub/sub, and reconnect handling.
  • Spend about five minutes on the API in an interview, then move on.
