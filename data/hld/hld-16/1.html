Hello Interview groups LLD grading into five areas: problem analysis (entities, scoping), class design (responsibilities, signatures, ownership), code quality (encapsulation, state, composition vs inheritance), extensibility (absorbing a follow-up requirement without a rewrite) and communication. It also notes that US Big Tech tends to want partial code in a real language, while interviews in India and Asia usually accept structured pseudocode and give vaguer requirements, so you must scope more yourself.

From your world

You have done both already. Drawing how a packet goes from line card to fabric to route processor is HLD. Writing the C struct for a neighbour entry, with its state enum (INCOMPLETE, REACHABLE, STALE), its lock and its timer callbacks, is LLD. The jump from C structs with function pointers to Java interfaces is much smaller than it looks.

Where this breaks: in the kernel you optimise for cache lines and lock contention first; in an LLD round the interviewer grades readability and extensibility first, and accepts a slower but cleaner design.
