Running a 90-minute machine-coding round

In a machine-coding round you get a problem statement (often 1-2 pages), your own laptop and IDE, and roughly 90 minutes. You must produce code that compiles, runs and demos the required features with in-memory storage, then explain and extend it in a review. Recent Flipkart reports describe the review as a viva on your own code: expect "why did you do this?" and "now add this feature" questions. Click through the plan below.

  1. 0-10 min: read and scope. Underline every "must" in the statement. Write down which features are mandatory and which are bonus. Ask about anything unclear. Confirm in-memory storage and a CLI or main driver.
  2. 10-20 min: entities and interfaces. List nouns (classes) and verbs (methods). Sketch the package layout: model, service, repository, strategy, exception. Decide the one or two places where things will vary, such as split types or pricing, and put an interface there.
  3. 20-60 min: core flows end to end. Implement the main happy path first, through all layers, and run it. A thin working slice beats five half-built features.
  4. 60-80 min: edge cases and safety. Validation, custom exceptions, "seat already booked", "insufficient balance", and thread safety where two users can hit the same object.
  5. 80-90 min: demo and tidy. A main that runs the scenarios from the statement, readable names, no dead code. Write a short README if allowed.
  6. The most common way to fail is code that does not run. Get the core path compiling and demoable early, then grow it.

  Main.java                                                       # demo driver: runs the sample inputs

Tip: Put storage behind a Repository interface even though it is just a HashMap. The reviewer's favourite follow-up is "how would you move this to a database?" With an interface, your answer is "write a new implementation and inject it", and nothing else changes. That one move shows SRP, DIP and OCP at once.
