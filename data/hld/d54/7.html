Where Kafka, Kubernetes and Docker fit

ToolRole hereConcrete setup
Kiosk to cloudHow a door event leaves the kioskThe kiosk agent holds one long-lived MQTT connection (a small publish/subscribe protocol made for devices on flaky links) over mutual TLS to the device gateway. Each event (DOOR_OPENED, DOOR_CLOSED, OCCUPIED, CODE_USED) carries the kiosk's own sequence number and stays in the kiosk's local outbox until the gateway acks it (MQTT QoS 1, at-least-once). If MQTT is down for long, the agent falls back to a batched HTTPS upload of the outbox. This is the same outbox you saw in deep dive 3: the gateway is the other end of it.
KafkaEvent backbone between kiosks, lockers and the rest of the companyThe device gateway writes locker-events keyed by locker_id (order per kiosk). Consumers: access service (issue code on DOOR_CLOSED+occupied), notification, expiry, analytics and the capacity forecaster. parcel-lifecycle events (Assigned, Delivered, PickedUp, Expired) go to the order service. parcel-lifecycle is keyed by parcel_id, so every state change of one parcel stays in order on one partition. The gateway dedupes on (locker_id, seq) before producing, so a kiosk re-sending after a lost ack does not create a second event. Use the outbox pattern so a DB change and its event never disagree. If consumers lag (say after an outage, when 2,000 kiosks flush their outboxes at once), pickups are not affected, because the kiosk validates codes locally; only notifications and expiry run late.
KubernetesRuns the cloud servicesDiscovery, capacity, assignment, access and expiry as Deployments with HPAs; the expiry sweep as a CronJob or a scheduler service; the MQTT device gateway as a StatefulSet (long-lived connections, stable identities). Regional clusters limit blast radius. See StatefulSets.
DockerPackages the kiosk agent tooThe kiosk agent can ship as a container image on the kiosk's small Linux computer, updated by pulling a new signed image and rolling back if health checks fail. Write-ups on locker design stress signed firmware and mutual TLS between kiosk and cloud. See Docker production & security.

From your world

The kiosk-to-gateway link is a management-plane session like NETCONF notifications or gNMI telemetry from a router to its controller: one persistent, authenticated session per device, sequence-numbered notifications, and a resync on reconnect. The device gateway is the collector; Kafka is the bus behind it that fans the events out to every interested service.
