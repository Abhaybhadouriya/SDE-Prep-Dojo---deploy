Key APIs

Three audiences: the shopper (website and app), the driver (handheld and kiosk), and the kiosk itself (a device talking to the cloud). API style background in API Design & Client-Server Communication.

Shopper

GET  /v1/lockers?lat=12.97&lng=77.59&radiusKm=5&size=M&deliveryDate=2026-11-25
  -> 200 { "lockers": [ { "lockerId": "L_BLR_0412", "name": "MG Road Metro", "distanceKm": 1.2,
                          "hours": "06:00-23:00", "available": true } ] }

POST /v1/reservations          # called by the order service when the order is placed
  { "orderId": "O_771", "lockerId": "L_BLR_0412", "size": "M", "deliveryDate": "2026-11-25",
    "idempotencyKey": "O_771-res" }
  -> 201 { "reservationId": "R_9001", "status": "HELD" }
  -> 409 { "error": "NO_CAPACITY" }       # order service offers another locker or home delivery

DELETE /v1/reservations/R_9001             # order cancelled: release capacity

Driver and kiosk

POST /v1/lockers/L_BLR_0412/dropoffs       # kiosk asks for a compartment for this parcel
  { "reservationId": "R_9001", "parcelId": "P_55", "driverId": "D_12", "requestId": "k-0412-88812" }
  -> 200 { "compartmentId": "C_17", "size": "M", "action": "OPEN" }

POST /v1/lockers/L_BLR_0412/events         # door and sensor events, batched, at-least-once
  [ { "seq": 9921, "type": "DOOR_CLOSED", "compartmentId": "C_17", "occupied": true, "at": "..." } ]

POST /v1/lockers/L_BLR_0412/pickups        # code typed at the kiosk (when online)
  { "code": "482913" }   -> 200 { "compartmentId": "C_17", "action": "OPEN" }
                         -> 403 { "error": "INVALID_OR_EXPIRED" }

Notice every write carries an idempotency key or a request id. A kiosk on a flaky 4G link will retry. "Retried drop-off" must return the same compartment, not open a second door. Kiosk events carry a per-kiosk sequence number so the cloud can drop duplicates and spot gaps.
