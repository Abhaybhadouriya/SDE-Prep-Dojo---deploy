Architecture: one parcel, checkout to pickup

Click Next or Play. The cloud owns reservations and codes; the kiosk owns doors and sensors and can act alone for a while. The service names follow the split many write-ups use (discovery, capacity reservation, assignment, secure access, pickup and expiry).

  1. Discover. The checkout page asks for lockers near the shopper's address. Locker discovery runs a geo query (geohash cells around the point) over a cached copy of location data, filters by size, weight, hours and status, and asks the capacity service for a yes/no per locker for the expected delivery day.
  2. Reserve capacity, not a box. When the order is placed, the capacity service atomically increments held for (locker, size, day) only if held < total. It does not pick a specific compartment yet, so a box is not wasted waiting for a parcel that is still in a truck.
  3. Driver arrives. The driver authenticates at the kiosk (badge or app) and scans the parcel. The kiosk agent is a small computer inside the locker that drives door locks and reads door and occupancy sensors.
  4. Assign a compartment. The kiosk asks the assignment service for a compartment. The service picks the smallest free compartment that fits and claims it with a compare-and-set on (state = AVAILABLE, version). The kiosk opens that door. The request id makes a retry return the same compartment.
  5. Door closes on a parcel. The kiosk sees the door closed and the sensor reports "occupied". It publishes an event (with its sequence number) that lands on Kafka. The access service now generates the pickup code with a secure random generator, stores only its hash, and sets the deadline (3 days at Amazon).
  6. Notify. The shared notification system sends the email and app message with the code, a barcode and the deadline. A reminder is scheduled before expiry.
  7. Pick up. The cloud has already pushed the code's hash to the kiosk, so the kiosk can check it locally even if it is offline. The right door opens; the code is marked used; the event flows back to the cloud and the compartment returns to AVAILABLE once the sensor says empty.
  8. Expire. If no pickup happens in time, the expiry scheduler revokes the code, creates a retrieval task for a driver, and tells the order service to start the return and refund. The compartment is freed only after the sensor confirms the parcel has been physically removed.

The heartbeat and event stream between kiosks and cloud never stops. Each dot is one batch of door events or one heartbeat.
