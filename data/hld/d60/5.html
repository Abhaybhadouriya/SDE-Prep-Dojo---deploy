Architecture: log in, call an API, refresh

  1. Login: the edge gateway terminates TLS and applies per-IP rate limits. The auth service loads the user's credential row and sends the password to a dedicated hashing pool (Argon2id is slow on purpose, so it is isolated from everything else). If MFA is on, it asks for the second factor.
  2. On success the token service creates a session (a "refresh family") in the session store and signs a short-lived access token with a private key that never leaves the KMS/HSM.
  3. The client gets an access token (JWT, about 15 minutes) and a refresh token (opaque, long-lived, single use). On the web, keep them in Secure, HttpOnly cookies, not in localStorage.
  4. Every API call carries the access token. Each service (or a sidecar / the gateway) verifies the signature, issuer, audience and expiry locally with cached public keys from JWKS. No network call to the auth service.
  5. For fast revocation, services also check a small denylist of revoked session ids, kept in memory and updated by pub/sub. It only needs entries for 15 minutes.
  6. When the access token expires, the client calls refresh. The token service checks the family is not revoked, issues a new access token and a new refresh token, and invalidates the old one (rotation).
