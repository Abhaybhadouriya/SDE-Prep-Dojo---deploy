Requirements

Functional (in scope)
  • Sign up and log in with email and password; optional MFA (authenticator app codes, passkeys).
  • Issue a session or tokens to web and mobile clients; refresh them silently.
  • Validate identity on every API call across many microservices.
  • Log out, "log out of all devices", and admin "revoke this user now".
  • Act as an OpenID Connect provider, so first-party and partner apps get SSO ("Sign in with Dojo").
  • Password reset and account recovery.
Out of scope
  • Fine-grained authorisation policy engine (we produce identity and scopes; see Security & Identity for RBAC/ABAC).
  • Enterprise directory sync (SCIM), full SAML IdP features - we mention them.
  • Fraud and bot scoring beyond basic risk signals.
Non-functional requirementTargetWhy
Availability99.99% or better for token validationIf auth is down, everything is down.
Validation latencyUnder 1-2 ms added per requestIt runs on every call; it must be local, not a network hop.
Login latencyUnder 500 ms (the password hash itself is deliberately slow)Users notice login; attackers must find it expensive.
RevocationA revoked session stops working within seconds to a few minutesStolen laptop, fired employee, hacked account.
SecurityNo plaintext secrets stored; resistant to credential stuffing and phishingThe highest-value target in the company.

The tension that drives this whole design: validation wants to be local and stateless (fast, always up), while revocation wants a central, stateful check (instant control). Every serious answer is a compromise between the two. Say it early.
