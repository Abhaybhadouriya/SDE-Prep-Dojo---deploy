Where Kafka, Kubernetes and Docker fit

PieceRole here
KafkaSecurity events: auth-events (logins, failures, MFA changes, password resets) keyed by user id for the audit log, anomaly detection (impossible travel, stuffing waves) and user notifications ("new sign-in from..."). A revocations topic can fan out denylist updates to every region. Never put passwords or tokens in events. See Kafka core concepts.
KubernetesAuth and token services as Deployments with PodDisruptionBudgets and spread across zones; the Argon2id hashing pool as its own Deployment with CPU/memory requests sized from the estimate and its own HPA. Secrets (pepper, DB credentials) from a vault or KMS via the CSI secrets driver, not plain env vars. A service mesh (mTLS) for service identity. See Config & Secrets and Security & RBAC.
DockerMinimal, distroless images for the auth services (fewer packages, smaller attack surface), run as non-root with a read-only root filesystem; secrets never baked into layers. See Docker production security.
