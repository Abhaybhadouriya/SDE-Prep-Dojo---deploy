PUT  <pre-signed S3 url>                     (client sends the bytes directly to S3)

POST /v1/documents/doc_7Q/complete          (or rely on the S3 ObjectCreated event)
  -> 202 {status: "UPLOADED"}

GET  /v1/documents/doc_7Q
  -> {status: "VALIDATING", steps: [{scan: "ok"}, {extract: "ok"}], updated_at}

GET  /v1/documents/doc_7Q/events            (SSE stream for the tracking page; optional)

# for B2B callers
POST /v1/webhooks   {url, events: ["document.verified", "document.rejected"], secret}
  -> webhook body is signed (HMAC) and carries an event_id for dedupe
  • Create-then-upload. The server creates the row first, then signs a URL for exactly one object key (docs/{tenant}/{document_id}). The client cannot write anywhere else.
  • Short expiry. S3 allows pre-signed URLs up to 7 days with SigV4 (console: up to 12 hours); use 5-15 minutes. A URL signed with temporary role credentials dies when those credentials expire.
  • Tracking link is an opaque token mapped to the document, safe to put in an SMS. Never put PII in it.
  • 202 Accepted is the honest status for "we have it, the work is not done".
