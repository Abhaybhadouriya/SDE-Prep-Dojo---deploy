Quick quiz

Peak is 100 validations/s and each vendor call takes 2.5 s. How many calls are in flight?

  1. 40
  2. 100
  3. 250
  4. 2,500
Little's law: 100/s x 2.5 s = 250.

A worker receives a message, finishes the work, and crashes before deleting it. What happens?

  1. After the visibility timeout the message is delivered again
  2. The message is lost
  3. SQS deletes it automatically on receive
  4. It goes straight to the DLQ
Receive only hides the message. Without a delete it reappears - so workers must be idempotent.

Which error should NOT be retried?

  1. HTTP 503 from the vendor
  2. A connection timeout
  3. HTTP 429 Too Many Requests
  4. The PDF is password-protected
A permanent error fails the same way every time. Reject with a reason.

Why should the file not go inside the queue message?

  1. Queues cannot store binary data at all
  2. Messages are small (SQS max 1 MiB) and the file already lives in S3
  3. It would make the message ordered
  4. Workers cannot read message bodies
Pass a pointer (document_id / S3 key), not the payload.

The DB says VERIFIED but the user never got an email. The service wrote the DB and then published to Kafka. What fixes this class of bug?

  1. Publish to Kafka first, then write the DB
  2. Retry the email three times
  3. The outbox pattern: write the event row in the same transaction
  4. Use a bigger Kafka cluster
Two separate writes can be split by a crash. The outbox makes them one commit; a relay publishes later.

What is the right autoscaling signal for OCR workers?

  1. Queue depth or age of the oldest message
  2. API server CPU
  3. Number of S3 objects
  4. Database connections
Workers exist to drain the queue; scale on how much is waiting and for how long.

Adding more validator workers does not increase throughput. Why?

  1. Kubernetes limits pods per node
  2. S3 is throttling downloads
  3. The queue is FIFO
  4. The vendor quota (token bucket) is the real cap
An external rate limit caps the stage. More workers only wait on the bucket.
