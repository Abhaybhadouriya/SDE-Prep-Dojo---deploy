Requirements

Functional

  • User uploads a document (PDF, JPG, PNG; say up to 20 MB) for a purpose: KYC, invoice, insurance claim.
  • System returns at once a document id and a tracking link.
  • Pipeline: virus scan, file checks, extract fields (name, ID number, invoice total), validate with a third-party service that takes 2-3 s per call.
  • User and calling service see status: uploaded, processing, verified, rejected (with reason), needs review.
  • Notify on completion: push, email, or a webhook to the client business.
  • Re-upload after rejection; full audit trail of each step.

Out of scope (say so): the OCR model internals, the reviewer UI, billing.

Non-functional

  • Upload request answered in < 300 ms (excluding byte transfer).
  • End-to-end processing p95 < 60 s in normal load (our target; say it).
  • Durable: an accepted document is never lost; every job ends in a final state.
  • At-least-once processing, effectively-once effects: no duplicate vendor charges, no double "verified" emails.
  • Absorb spikes (month-end invoices, a marketing campaign) without failing uploads.
  • Respect the vendor's rate limit and survive vendor outages.
  • Security: KYC files are PII - encrypted at rest, short-lived access links, least privilege.

Ask: "How large are files? How fast must the user know the result? What does the validator cost and what is its rate limit? Who needs to be told when it finishes - the user, another service, or both?" These four answers decide sync vs async, the notification channel, and how you size workers.
