Remember this

  • Slow, external or flaky steps leave the request path: 202 + tracking link, then queue + workers.
  • Bytes to S3 via pre-signed URL; metadata and status in SQL; messages carry only ids.
  • Queues are at-least-once: visibility timeout, retries with backoff + jitter, DLQ after N tries.
  • Idempotent everything: conditional state transitions, results keyed by step, event ids, vendor result cache.
  • Size the vendor pool with Little's law; protect it with a token bucket, timeouts and a circuit breaker.
  • Status change and event commit together via the outbox.
  • Scale workers per stage on queue depth/age, not CPU.
