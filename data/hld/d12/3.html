API design

# Browse (control plane, heavily cached)
GET /v1/home?profile_id=p_9           -> rows of titles (personalised)
GET /v1/titles/t_81234                -> metadata, episodes, artwork URLs

# Start playback: "what and from where"
POST /v1/playback/start
{ "title_id": "t_81234", "profile_id": "p_9",
  "device": { "codecs": ["av1","hevc","avc"], "max_height": 2160, "drm": "widevine", "hdr": true } }

200 { "playback_id": "pb_5xQ", "resume_at_s": 1312,
      "manifest_url": "https://oca-7.isp.example/m/pb_5xQ.mpd?token=...",
      "fallback_urls": ["https://oca-12.ixp.example/...", "https://oca-3.isp.example/..."],
      "license_url": "https://license.example/v1/widevine" }

# DRM licence: the player sends a challenge, gets keys for this device only
POST /v1/license          (binary challenge -> binary licence)

# Video bytes (data plane): plain HTTPS GETs to the OCA, segment by segment
GET https://oca-7.isp.example/v/t_81234/av1_1080p_3000k/seg_00042.m4s?token=...

# Telemetry and resume position (every ~30 s and on pause/stop)
POST /v1/playback/events
{ "playback_id": "pb_5xQ", "position_s": 1342, "bitrate_kbps": 3000,
  "rebuffer_ms": 0, "oca": "oca-7", "event": "heartbeat" }
  • One start call returns everything the player needs: manifest, ranked OCA URLs, licence URL and resume point. Fewer round trips mean faster start.
  • URLs carry short-lived signed tokens, so a copied link stops working soon and an OCA can check access without calling the cloud.
  • The data plane is plain HTTP(S). That is what lets simple, fast cache boxes serve it, and what lets players use ordinary range or segment requests.
