Quick quiz

Where do the video bytes come from when you watch Netflix at home?

  1. The playback microservice in AWS
  2. An Open Connect box in or near your ISP
  3. A commercial CDN rented per region
  4. The S3 origin bucket, through a cache
After Play, bytes come from an Open Connect appliance a few hops away. The AWS playback service only decides what and where; it never sends video. Netflix runs its own CDN instead of renting one. S3 is the origin that fills the boxes at night, not the source for viewers.

How does an embedded OCA learn which customers it should serve?

  1. It pings every IP in the region
  2. Players register their IPs at sign-in
  3. The ISP advertises its prefixes over BGP
  4. Anycast routing sends nearby users to it
Open Connect's docs describe ISPs setting up BGP sessions with their OCAs. Pinging cannot tell you who is a customer. Sign-in knows accounts, not network topology. Netflix uses unicast URLs from a steering service, not anycast.

15M concurrent streams at 5 Mbps average need roughly how much peak egress?

  1. 750 Gbps
  2. 7.5 Tbps
  3. 75 Tbps
  4. 750 Tbps
15,000,000 x 5 Mbps = 75,000,000 Mbps = 75 Tbps. The other answers are the same digits off by a factor of 10 or 100, the classic unit slip; write the zeros down.

Why are all renditions cut into segments on the same time boundaries?

  1. So the player can switch rung at any edge
  2. So each rung needs fewer keyframes
  3. So DRM keys rotate once per segment
  4. So the CDN can merge identical segments
Aligned boundaries make every rung interchangeable at each segment edge, which ABR needs. Alignment forces keyframes at fixed points, so it does not reduce them. DRM key rotation is a separate setting. Segments from different bitrates are different bytes, so nothing can be merged.

A viewer's network slows down mid-film. What does a good ABR player do?

  1. Ask steering for a closer OCA
  2. Keep the rung and enlarge the buffer
  3. Step down a rung before the buffer empties
Dropping quality for a few seconds beats a rebuffer. Steering picks boxes at start-up, and the slow part is usually the last mile anyway. A buffer cannot grow while the link delivers less than the bitrate.

Why does Netflix push titles to OCAs overnight instead of caching on first request?

  1. Pull caching cannot work over HTTPS
  2. Pre-filling avoids prime-time misses
  3. ISP contracts forbid pull caching
  4. Overnight fill gets cheaper S3 prices
Demand is predictable, so filling off-peak means a new release is already local when everyone presses Play. Pull caches work fine over HTTPS (most CDNs do it). ISPs do not forbid it. S3 has no night-time discount; the saving is idle link capacity.

Why do bookmark (resume position) writes go through Kafka to a wide-column store?

  1. Huge small-write volume, simple key reads
  2. Wide-column stores give strong transactions
  3. Kafka keeps bookmarks forever as the store
Hundreds of thousands of tiny writes per second, read back by key, fit an async pipeline into Cassandra, and duplicates are harmless with last-timestamp-wins. Cassandra is not chosen for multi-row transactions. Kafka keeps data for a retention period; it is the pipe, not the store.

In the encoding Job, what does backoffLimitPerIndex: 3 do?

  1. Runs at most 3 chunks in parallel
  2. Fails the Job after 3 pod failures total
  3. Restarts a crashed pod in place 3 times
  4. Retries each chunk up to 3 times
Per-index backoff gives every chunk its own retry budget, so one bad chunk cannot use up the budget for all 240. Parallelism is a different field. A Job-wide limit is what plain backoffLimit does. restartPolicy: Never means failed pods are replaced, not restarted in place.
