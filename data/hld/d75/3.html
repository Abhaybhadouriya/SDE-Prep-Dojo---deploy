Key APIs

# broadcaster
POST /v1/channels/{id}/stream-key              -> {ingest_url: "rtmp://ingest.example/live", stream_key}
rtmp://ingest.example/live/{stream_key}        (or srt://... ; WebRTC/WHIP for browsers)

# subscriptions and entitlement
POST /v1/subscriptions   {plan: "TOURNAMENT_PASS", tournament_id}   -> {subscription_id, valid_until}
GET  /v1/matches/{id}                          -> {status: "LIVE", starts_at, stream_id}

# playback (the "dynamic access link")
POST /v1/streams/{id}/playback                 (auth: user session, device id)
  -> {manifest: "https://cdn.example/live/s123/master.m3u8",
      token: {type: "signed-cookie", expires_in: 600},
      refresh_after: 480, heartbeat_every: 30}

# viewer presence and count
POST /v1/streams/{id}/heartbeat   {session_id}  -> 204
GET  /v1/streams/{id}/viewers                   -> {count: 48213117, as_of}   (cached, pushed)
  • Playback is a separate call from browsing. It checks entitlement, device limits and region, then hands back a short-lived credential. The video bytes then go straight to the CDN.
  • Signed cookie, not signed URL, for HLS. A live stream is thousands of segment files. CloudFront's own guidance: signed URLs for single files, signed cookies for many files such as all files of an HLS video.
  • refresh_after lets the player renew the token before expiry without interrupting playback; revoking a user just means refusing the next refresh.
