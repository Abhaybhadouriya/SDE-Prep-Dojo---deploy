Quick quiz

Which column makes "find due jobs" fast?

  1. An index on (shard_id, next_run_at)
  2. An index on job_id
  3. An index on tenant_id
The scheduler asks "which jobs in my shard have next_run_at <= now?", a range scan on that composite index.

A worker finished the job but crashed before committing the Kafka offset. What happens?

  1. The job is lost
  2. Kafka deletes the message
  3. The message is redelivered and the job may run again
Uncommitted messages are redelivered: at-least-once. That is why jobs must be idempotent.

What does a fencing token protect against?

  1. A slow database query
  2. Kafka broker failure
  3. A paused worker writing after its lease expired and another worker took over
The store rejects writes with an older token, so a zombie worker cannot overwrite the new owner's work.

Two scheduler pods both believe they lead shard 7. Why don't jobs run twice?

  1. etcd stops the second one instantly
  2. The run id (job id + scheduled time) is a primary key, so only one run row is created
  3. Kafka removes duplicates automatically
Leader election is for efficiency; the unique run id is what guarantees correctness.

Using Little's law: 2,000 runs/s, 3 s each. How many run at once?

  1. 6,000
  2. 667
  3. 2,000
Concurrency = rate x time = 2,000 x 3 = 6,000.

Why add jitter to retry delays?

  1. To stop all failed jobs from retrying at the same instant and overloading the recovering service
  2. To make jobs run in order
  3. To save storage
Without jitter, retries from one outage line up into a retry storm.

Kubernetes CronJob concurrencyPolicy: Forbid means...

  1. Run every schedule even if the last run is still going
  2. Skip the new run if the previous one is still running
  3. Kill the old run and start the new one
Allow overlaps, Forbid skips, Replace kills the old run.
