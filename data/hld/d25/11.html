Remember this

  • A scheduler is a durable timer (DB with an index on next_run_at) in front of a queue and a worker pool.
  • The DB is the truth; an in-memory timer wheel for the next minute gives precision.
  • Run id = job id + scheduled time: duplicates collide on the primary key.
  • At-least-once + idempotency key at the target = effect happens once. Never promise exactly-once.
  • Leases detect dead workers; fencing tokens stop paused "zombie" workers.
  • Commit the queue offset after the job, not before.
  • Round times cause spikes: jitter, Kafka buffering, priorities, lag-based autoscaling.
  • The headline metric is start delay (actual start - scheduled time).
