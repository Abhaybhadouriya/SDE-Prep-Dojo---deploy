Quick quiz

1 billion clicks per day is about how many per second on average?

  1. ~12,000
  2. ~1,200
  3. ~120,000
1,000,000,000 / 86,400 ≈ 11,600, so about 12k/s.

Why does the sink upsert the full window count instead of incrementing?

  1. Upserts are faster
  2. OLAP stores cannot increment
  3. Kafka exactly-once alone already prevents any double count
  4. A replayed write then gives the same result instead of double counting
Retries happen after crashes. Overwriting by key is idempotent; adding is not.

A watermark of "newest event minus 30 s" means...

  1. Events older than 30 s are deleted
  2. The job checkpoints every 30 s
  3. Windows close 30 s after newer events show their time has passed
The watermark is the job's estimate of "all events up to time T have arrived". A window closes when the watermark passes its end.

What should happen to a click that arrives after its window has closed and the allowed lateness has passed?

  1. Drop it silently
  2. Count it in the current minute
  3. Keep every window open forever so nothing is ever late
  4. Send it to a side output for correction / the batch recount
Paid clicks must not vanish, and counting them in the wrong minute breaks correctness.

One ad's partition lags while others are idle. Best fix?

  1. Salt the hot key and aggregate in two stages
  2. Add more Flink workers
  3. Increase Kafka retention
More workers do not help one key on one partition; salting spreads the key.

What does Flink restore after a crash to avoid double counting?

  1. Only the Kafka offsets
  2. Only the dashboard cache
  3. Operator state and the matching Kafka offsets from the same checkpoint
  4. Nothing - Kafka exactly-once makes recovery automatic
State and input position must describe the same instant; restoring them together gives a consistent replay.

Why does the click service return the 302 before Kafka acknowledges?

  1. Kafka cannot acknowledge
  2. To keep the user path fast and independent of the counting pipeline
  3. Because the event is not important
The producer buffers and retries asynchronously (with disk spill), so the user never waits for counting.

Which is the best idempotency key for a billable click?

  1. The signed impression ID
  2. ad_id
  3. user IP address
One impression can produce at most one billable click, and the signature stops forgery.
