Key APIs

Apps do not call an API to log. They just print to stdout/stderr, and the agent picks it up. This is a key decision: the app stays simple and cannot be slowed down by the log system. The APIs below are for agents and for humans.

APIWho calls itNotes
POST /v1/logs:push (batch of streams, gzip/snappy)Agents that cannot use Kafka directly (VMs, edge)Returns 429 with Retry-After when the tenant is over quota; agent backs off.
GET /v1/query?q=...&start=...&end=...&limit=1000UI, CLIq is a label selector + filters, e.g. LogQL. Time range is required.
GET /v1/tail?q=... (WebSocket / SSE)UI "live tail"Streams new matching lines; server-side rate limit.
POST /v1/alertsTeamsSaved query + threshold + window, evaluated every minute.
PUT /v1/tenants/{team}/limitsPlatform teamIngest MB/s, max labels, retention per tenant.
 
// One push request body (agent to gateway). Labels identify the stream; lines are the payload.
{
  "streams": [
    {
      "labels": { "namespace": "checkout", "app": "payments", "pod": "payments-7c9f-x2k", "level": "error" },
      "entries": [
        { "ts": "2026-11-23T10:15:02.123Z", "line": "{\"msg\":\"charge timeout\",\"order_id\":\"42\",\"trace_id\":\"a1b2c3\"}" }
      ]
    }
  ]
}

Mention two rules for the query API: a time range is mandatory (so the store can skip everything outside it), and results are limited/paginated. Unbounded log queries are how log clusters fall over.
