Say the choice out loud (pattern: "I would pick X because A; the cost is B; if C becomes a problem I would switch to Y"):

  • "I would pick Loki-style label indexing because at 40 TB a day the full-text index would cost more than the logs; the cost is slow needle searches across all streams; if the security team needed fast arbitrary search, I would route their subset to Elasticsearch or ClickHouse."
  • "I would put Kafka between agents and the store because a slow or broken store must never lose lines or touch apps; the cost is a cluster to run and a few seconds of delay; if we were a small team with one cluster, I would ship straight from Fluent Bit to the store with a disk buffer on the agent."
  • "I would choose at-least-once delivery because a duplicate log line is harmless; the cost is the odd repeated line after a crash; if billing ever read these logs, I would add a line id and dedupe in the writer."
Why this design works
  • Apps are fully decoupled from the log system.
  • No data loss once the agent has a line.
  • Cheap long retention via object storage.
  • Replay fixes processing bugs.
What it costs
  • More moving parts (Kafka cluster to run).
  • Extra latency (seconds) from buffering.
  • Labels-only stores are slow for global needle searches.
  • Needs strong governance on labels and volume.
