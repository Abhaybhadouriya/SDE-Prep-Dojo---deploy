What SDE-1 vs SDE-2 interviewers expect

The same question is graded differently by level. Interview formats vary by company and team (the notes below come from official prep pages and many candidate reports, so treat them as "commonly reported"), but the pattern is consistent:

SDE-1 (new grad to ~2 years)SDE-2 (~2-6 years)
Who drives?You, with hints accepted gracefullyYou, start to finish, with almost no prompting
RequirementsAsks clarifying questionsAlso quantifies them and cuts scope deliberately
EstimatesRough QPS and storageUses the numbers to justify choices (shard count, cache size)
DesignA working, sensible design with standard parts (LB, cache, DB, queue)Picks specific technologies with reasons and alternatives
Deep divesCan go deep when askedChooses the 1-2 deep dives that matter and leads them
Trade-offsKnows that trade-offs existStates each one: what you gain, what it costs, when you would switch
FailureAnswers "what if X fails?" when askedRaises failure modes, monitoring and rollout without being asked

Same moment, two levels: "How do you store the messages?"

A good SDE-1 answer
  • "Messages are written a lot and read by conversation, so I'd use a NoSQL store like Cassandra with the conversation ID as the partition key and a time-ordered message ID as the sort key. That way loading a chat is one partition read."
A good SDE-2 answer
  • "Same choice, plus: a very busy group chat would make one huge partition, so I'd bucket by (conversation, fixed time window) the way Discord does - they chose about 10 days so even the busiest channel's partition stays under ~100 MB. I'd write with LOCAL_QUORUM (a majority of the replicas in the local data centre; see quorums) so a write survives one replica loss without waiting on another region. The cost is that a cross-region read can lag by a second, which is fine for chat history. If we needed strict ordering across devices, I'd assign sequence numbers per conversation on the server."

By company (as commonly reported)

  • Amazon - SDE-1 loops are mostly coding with light design; SDE-2 adds a full HLD round ("scale an existing architecture"). Every round includes Leadership Principle questions answered in STAR form; there is a Bar Raiser from another team.
  • Microsoft - SDE-2 loops often have one HLD round or a mixed HLD + LLD round (a distributed LRU cache, a unique ID generator, a chat app have been reported). Some loops use object-oriented design instead.
  • Google - L3 (SDE-1) usually has no standalone system design; at L4 design discussion may appear inside a coding round. Standalone HLD is more typical from L5.
  • Flipkart - A machine coding round first (working, extensible code in 90 minutes), then DSA and design; SDE-2 adds HLD with e-commerce flavours.
  • Walmart Global Tech - Reports are Kafka-heavy: partitioning, keeping events for one entity on one partition, handling failed messages, designing an order system.
