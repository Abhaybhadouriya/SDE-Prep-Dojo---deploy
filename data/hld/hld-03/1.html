The fixed order (learn it by heart)

Every good framework - Alex Xu's 4 steps, Hello Interview's delivery framework - boils down to the same order. Use it for every design on this site.

  1. Requirements What must it do (functional)? How well (non-functional: scale, latency, availability, consistency)? What is out of scope?
  2. Estimates A few numbers - requests per second, storage, bandwidth - only as deep as they change the design. See Back-of-Envelope Estimation.
  3. Core entities and API The nouns (User, Url, Order) and 2-4 endpoints.
  4. Data model Tables or keys, and which kind of database, with a one-line reason.
  5. High-level design 4-7 boxes that make the core flows work. Walk one request through it.
  6. Deep dives 1-3 hard parts: the scaling bottleneck, consistency, a hot key, failure.
  7. Bottlenecks, failures and wrap-up What breaks first, what you would monitor, what you would do at 10x.

One honest difference: Hello Interview goes further and suggests skipping upfront estimates entirely, doing the maths only at the point where a number changes a decision (its order is requirements, core entities, API, data flow, high-level design, deep dives). Alex Xu does the estimates right after requirements. Either is fine if each number ends with "so...".

The first thing you say after the prompt is not a technology. It is: "Before I design, can I ask a few questions to pin down the scope?"
