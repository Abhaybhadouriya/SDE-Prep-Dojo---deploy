Paxos in five minutes (intuition only)

Paxos (Lamport) is the older algorithm that Raft simplifies. You will almost never be asked to code it, but you should be able to sketch why it is safe. Roles: proposers suggest a value, acceptors vote, learners find out the result.

  1. Prepare (phase 1a). A proposer picks a proposal number n bigger than any it has used and asks a majority of acceptors: "promise to ignore anything lower than n".
  2. Promise (phase 1b). Each acceptor promises, and also reports the highest-numbered value it has already accepted, if any.
  3. Accept (phase 2a). If a majority promised, the proposer sends accept(n, v). Crucially, if any acceptor reported a previously accepted value, the proposer must reuse that value instead of its own. This is how an already-chosen value survives.
  4. Accepted (phase 2b). Acceptors accept unless they promised a higher number. Once a majority accepts, the value is chosen forever.

Basic Paxos picks one value. Real systems run Multi-Paxos: elect a stable leader and skip phase 1 for every following slot - which ends up looking very much like Raft. Google's Chubby lock service runs Paxos inside a 5-replica cell; Google's "Paxos Made Live" paper is a good read on how messy the real engineering is.
