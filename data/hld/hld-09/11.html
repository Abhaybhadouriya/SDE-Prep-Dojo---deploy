Choosing the right tool

You need...UseAvoid

Strongly consistent metadata (config, membership)Raft/Paxos store: etcd, ZooKeeper, ConsulGossip (eventually consistent)

Mutual exclusion on one DB rowDB row lock / optimistic version checkA separate distributed lock service
Global sortable IDsSnowflake-style or UUIDv7One central auto-increment
Consensus gives you
  • One agreed order of operations
  • No split brain (majority rule)
  • Linearizable reads/writes on small data (linearizable: every read sees the latest committed write, as if there were only one copy)
Consensus costs you
  • Every write waits for a majority round trip (cross-region RTT is 10-100 ms)
  • Minority partition is unavailable (CAP: it chooses C)
  • Leader is a throughput ceiling - keep data small, shard if needed

This is the CAP and PACELC discussion from Fundamentals made concrete. Meta's FlexiRaft shows the escape hatch: use a small in-region quorum for commits (2 of 3) and a larger quorum for elections, so writes avoid cross-region round trips while elections still overlap every data quorum.
