Remember this

You might confuse this with:

  • Fan-out on write vs fan-out on read: on write (push) = copy the post id into every follower's feed when it is posted, so reads are cheap; on read (pull) = gather posts from everyone you follow when you open the app, so writes are cheap.
  • Feed cache vs post cache: the feed cache holds a list of post ids per user; the post cache holds each post's body once. Hydration joins the two.
  • Cursor vs offset: a cursor says "after this item" and stays correct as new posts arrive; an offset says "skip N items" and shifts, causing duplicates.

Remember this

  • Feeds are read-heavy (~100 reads per post), so precompute them.
  • Push = pay at write (N followers). Pull = pay at read (M followees). Hybrid = push for most, pull for celebrities.
  • Feed cache stores ids with a score, trimmed to a few hundred; hydrate from one post cache.
  • Skip fan-out to inactive users; rebuild their feed by pull when they return.
  • Cursor pagination, never offsets.
  • Outbox to Kafka; fan-out workers are a consumer group; idempotent ZADD makes at-least-once safe.
  • Deletes, blocks and privacy are enforced at hydration, not by cleaning millions of feeds.
  • Ranking is a funnel with a strict time budget and a chronological fallback.
