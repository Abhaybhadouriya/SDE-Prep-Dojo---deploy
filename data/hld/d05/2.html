Back-of-envelope estimation

All numbers here are round assumptions chosen to make the maths easy, not real Meta numbers. Use the trick from Back-of-Envelope Estimation: one day is 86,400 seconds; round it to 100,000 (105) when speed matters, then fix it up.

~58K/sfeed reads, average
~175K/sfeed reads, peak
~580/snew posts, average
~116K/sfan-out inserts
~4 TBRAM for feed caches
  1. Feed reads per day 500M DAU x 10 feed opens or page loads per day = 5 billion reads/day (assumption).
  2. Read QPS 5B / 86,400 is about 58,000/s on average. Quick way: 5 x 109 / 105 = 50K/s. Peak is evening time and big events; plan for 3x: ~175K/s.
  3. Posts per day Most people only scroll. Say 10% of DAU post once a day: 50M posts/day, about 580 posts/s on average, ~1,700/s peak. Reads beat writes by about 100 to 1. That ratio is the reason to precompute feeds.
  4. Fan-out cost If the average poster has 200 followers (assumption), push fan-out does 50M x 200 = 10 billion feed inserts/day, about 116K inserts/s. Each insert is tiny (an 8-byte post id plus a score), and they are batched, so a Redis cluster handles it. Notice: one post is cheap, but the total is big.
  5. The celebrity number One account with 50M followers posting once would cause 50M inserts by itself, which is 5 minutes of the whole cluster's average fan-out budget (50M / 116K is about 430 s) for a single post. This one line is why the hybrid design exists. Say it out loud.
  6. Feed cache memory Keep the newest 500 post ids per user (assumption; Twitter kept about 800 tweets per timeline). 500 x 8 bytes = 4 KB of ids; with scores and Redis overhead call it 8 KB per user. Only active users need a cache: 500M x 8 KB = 4 TB of RAM. With machines of 64 GB usable memory that is about 63 shards, and with 1 replica each about 125 cache nodes. Big, but normal for a top-10 app.
  7. Post storage Post row (ids, text up to ~2 KB, timestamps, media keys): call it 1 KB. 50M x 1 KB = 50 GB/day of metadata, about 18 TB/year, x3 replicas = ~55 TB/year. Easy for a sharded database.
  8. Media storage If 30% of posts have one photo stored at ~500 KB (several sizes together), that is 15M x 500 KB = 7.5 TB/day, about 2.7 PB/year. That goes to blob storage (S3-like) behind a CDN, never into the database.
  9. Bandwidth A feed page of 20 posts as JSON is maybe 20 KB (without images). 175K/s x 20 KB = 3.5 GB/s out of the feed service at peak. Images are many times bigger, which is why the CDN serves them and the feed only sends URLs.

What each number changed: 100:1 read/write -> precompute feeds. 50M-follower accounts -> hybrid fan-out. 4 TB of ids -> a sharded in-memory cache that stores ids, not whole posts. 7.5 TB/day of media -> blob storage + CDN. If a number does not change a decision, skip it in the interview.
