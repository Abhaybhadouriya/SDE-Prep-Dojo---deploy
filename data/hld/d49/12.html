Quick quiz

Why is updating a price inside a Lucene/Elasticsearch document expensive?

  1. Prices are stored as strings
  2. The index is encrypted
  3. Segments are immutable, so an update is a delete plus a full re-insert
  4. Elasticsearch has no update API
Segments never change in place. An update marks the old document deleted and writes a new one, and merges clean up later.

Flipkart saw ~40K searches/s at the service layer but ~10K/s at Solr. What explains the gap?

  1. Most queries failed
  2. A result cache absorbed most repeated queries
  3. Solr dropped requests
  4. Users cancelled searches
Popular queries repeat heavily, so a short-TTL result cache in front of the engine absorbs most traffic.

Which is the safest way to keep the search index in sync with the catalog DB?

  1. Change data capture from the DB log into Kafka
  2. Write to DB, then to search, in the same request
  3. Nightly full reindex only
  4. Let the search engine query the DB
CDC turns every committed change into an ordered event. Dual writes can diverge, and nightly reindex is too stale.

What decides the number of replicas in the search tier?

  1. The number of categories
  2. The size of each document
  3. The number of Kafka partitions
  4. The query throughput you need
Shard count follows data size; replica count follows QPS, because each copy can serve queries in parallel.

A product has 2 reviews averaging 5.0; another has 20,000 averaging 4.6. How should ranking treat them?

  1. 5.0 first, it is higher
  2. Use a Bayesian average that pulls low-count items towards the category mean
  3. Hide products with fewer than 1,000 reviews
  4. Sort by review count only
A Bayesian average blends the item's ratings with a prior, so tiny samples cannot dominate.

How did Flipkart cut its review-index size so much?

  1. Deleting old reviews
  2. Moving to a bigger Redis cluster
  3. Replacing string UUIDs with per-product integer review numbers and de-duplicating data
  4. Storing reviews as images
36-byte UUID strings became ~2-byte varints, and duplicated translated text was removed: over 97% smaller index.

The index can lag by seconds; truth lives in the inventory service.
