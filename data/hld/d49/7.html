Where Kafka, Kubernetes and Docker fit

ToolRole hereDetail to mention
KafkaThe spine of change propagation: CDC topics (catalog, price, stock, offers), indexer output topic consumed by every search node, review eventsKey by product_id for per-product ordering; enable log compaction on "latest state" topics so a new node can rebuild by reading the compacted topic; Flipkart used Kafka as both source and sink of its Storm topologies. See Kafka core concepts and Connect & Streams (Debezium is a Kafka Connect source).
Stream processorIndexer topologies that join partial updates with the snapshotStorm in Flipkart's 2017 post; Flink or Kafka Streams today. Must be idempotent and version-aware.
KubernetesStateless tiers: search API, query understanding, ranker, review API, indexersHPA on CPU/QPS; search cluster itself is stateful, usually on dedicated nodes or via an operator (ECK for Elasticsearch) using StatefulSets and local SSD PVs. See StatefulSets & Operators and Autoscaling.
DockerEvery service and the ranking model server ship as imagesSame image runs in CI relevance tests and prod; models versioned with the image tag or pulled from a model registry.
