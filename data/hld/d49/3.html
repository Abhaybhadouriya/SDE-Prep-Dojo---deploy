Key APIs

# Search and browse (read path, cacheable)
GET  /v1/search?q=running+shoes&category=footwear&brand=nike,puma&price=1000-3000&sort=relevance&cursor=eyJzIjoxMH0
  -> { results:[{productId, title, image, bestPrice, rating, inStock}], facets:{brand:[{value:"nike",count:1240}], price:[...]}, nextCursor }

# Product page
GET  /v1/products/{productId}                 -> details, attributes, listings summary
GET  /v1/products/{productId}/offers          -> per-seller price + availability (fresh, not from search)
GET  /v1/products/{productId}/reviews?sort=helpful&aspect=battery&page=2
GET  /v1/products/{productId}/rating-summary  -> {avg:4.3, count:18234, histogram:[...]}

# Catalog writes (seller / internal tools)
PUT  /v1/products/{productId}       Idempotency-Key: ...   body: {categoryId, title, attributes:{ram_gb:8, color:"black"}}
PUT  /v1/listings/{listingId}/price  body: {price:24999, version:17}

# Reviews
POST /v1/products/{productId}/reviews  Idempotency-Key: ...  body: {orderId, stars:4, text, imageIds}
POST /v1/reviews/{reviewId}/votes      body: {helpful:true}

Use cursor pagination (an opaque token) instead of page numbers for search; deep offsets are expensive in search engines (Hello Interview notes cost climbs past about 10,000 results). Price writes carry a version so an old update arriving late cannot overwrite a newer one. See API Design.
