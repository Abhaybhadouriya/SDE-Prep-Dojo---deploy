The map: where these algorithms sit

Must know (SDE-1)

Every real recommender (Amazon "customers also bought", Netflix rows, YouTube "Up next") is a funnel. You cannot run a heavy model over 100 million items for every page view, so you split the work:

  1. Candidate generation (retrieval) picks a few hundred to a few thousand items out of millions, cheaply. This is where collaborative filtering, item-item tables, embeddings and ANN live. This page is about this stage.
  2. Ranking scores those candidates with a richer model (many features: price, freshness, the user's context) and orders them.
  3. Re-ranking / business rules removes items already bought, adds diversity, applies stock and policy filters.

Google's YouTube paper (Covington et al., 2016) describes exactly this two-stage shape: a candidate generator narrows millions of videos to hundreds, then a ranking network orders them. The full system is designed on Recommendation System (d48); this page teaches the algorithms inside the first box.

The utility matrix and the two kinds of feedback

Everything starts from one giant table, the user-item matrix (also called the utility or interaction matrix): one row per user, one column per item, and a cell filled when the user did something with the item. It is extremely sparse. In the Netflix Prize data, about 480,000 users rated 17,770 movies with about 100 million ratings, so only about 1 cell in 85 was filled (Simon Funk's write-up). Real catalogues are far sparser.

Explicit feedbackImplicit feedback
WhatThe user tells you: 1-5 stars, thumbs up/downYou observe behaviour: views, clicks, watch time, purchases, add-to-cart
VolumeSmall (few people rate)Huge (every session produces it)
NegativesLow stars are real negativesNo real negatives: a missing click may mean "never saw it", not "dislike"
Typical targetPredict the rating (minimise RMSE)Rank items the user is likely to engage with (precision@k, recall@k)

Most production systems run on implicit feedback, which changes the maths (see implicit feedback below). Two families of algorithms fill in the empty cells:

  • Memory-based CF keeps the matrix (or a summary of it) and computes similarities between rows or columns directly. No training, just counting and comparing.
  • Model-based CF learns a compact model (usually low-dimensional vectors per user and item) from the matrix, then throws the matrix away at serving time.
