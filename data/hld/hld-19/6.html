Implicit feedback: preference plus confidence

Good to know (SDE-2)

With clicks and plays there are no 1-star ratings. Hu, Koren and Volinsky's 2008 paper "Collaborative Filtering for Implicit Feedback Datasets" reframed the problem:

  • Preference p(u,i) = 1 if the user interacted at all, else 0. Every cell gets a target, including the empty ones (0 = "probably not interested").
  • Confidence c(u,i) = 1 + alpha x r(u,i), where r is the raw count (plays, minutes). Watching a show 20 times gives high confidence; one accidental click, low. Empty cells get confidence 1, so they count, but weakly. The paper used alpha around 40.
  • Loss: sum over all cells of c(u,i) x (p(u,i) - u.v)2 plus regularisation.

Good to know (SDE-2) - skip on first read Summing over all users x items cells sounds impossible, but the ALS solve has a trick: VTCV = VTV + VT(C - I)V, and VTV is computed once per half-step for everyone. C - I is non-zero only on the cells the user actually touched. So each user still costs about O(k2 nu + k3), where nu is that user's number of interactions. This is weighted ALS (WALS), and Google's ML course lists "easier to handle unobserved entries" as its main advantage over SGD.

als = ALS(rank=128, maxIter=15, regParam=0.1,
          implicitPrefs=True, alpha=40.0,          # Spark default alpha is 1.0
          userCol="userId", itemCol="itemId", ratingCol="plays")

Spark's docs say to set implicitPrefs=True whenever the "rating" is inferred from behaviour. With implicit data, judge models with ranking metrics (precision@k, recall@k, NDCG on a time-based holdout), not RMSE.

Negative sampling is the SGD-world answer. Deep and two-tower models (see d48 deep dives) cannot afford all cells, so for each positive they sample a few random items as negatives. Sampling by popularity matters: uniform sampling makes popular items look too good.
