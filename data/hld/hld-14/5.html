Encryption in transit: TLS, mTLS and zero trust

TLS (the successor of SSL; certificates are still called "SSL certificates" out of habit) gives three things: encryption (no one can read the bytes), integrity (no one can change them unnoticed) and authentication (the server proves it owns the name via a certificate signed by a trusted certificate authority). In normal TLS only the server proves its identity.

In mutual TLS (mTLS) the client presents a certificate too, so both ends are authenticated by cryptography rather than by network location. Inside a microservice system this is how service A proves to service B that it really is A.

  • Workload identity: SPIFFE is an open standard for giving each workload a verifiable identity, issued as short-lived X.509 or JWT documents (SVIDs) through a Workload API that rotates them automatically. SPIRE is its reference implementation, running on Kubernetes, VMs and bare metal. Service meshes such as Istio and Linkerd do the same job for Kubernetes.
  • Zero trust: Google's BeyondCorp paper (2014) describes removing the idea of a privileged corporate intranet: being "inside the network" grants nothing; every request is authenticated and authorized based on user and device. mTLS between services is the service-to-service version of the same idea.
  • Where TLS terminates: usually at the edge load balancer or CDN for public traffic, then re-encrypted (or mTLS) inside. Say this explicitly, because "TLS to the LB, then plain HTTP to the backends" is a common gap.
  • Webhooks and partner calls: sign payloads with an HMAC shared secret plus a timestamp so the receiver can reject forged or replayed requests (see d03 Notifications and d10 Payments).

From your world

mTLS is IKE/IPsec with certificate authentication, moved from the tunnel endpoint into each service: both peers prove identity before any data flows, and the "inside" interface earns no trust by itself. Short-lived auto-rotated certificates are like rekeying SAs frequently, so a leaked key has a small window. TLS termination at the LB is like decrypting at the VPN concentrator: everything behind it is plaintext unless you encrypt again.
