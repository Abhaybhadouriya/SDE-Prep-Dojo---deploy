Key APIs

# Cart: cheap, frequent, always writable
GET    /v1/cart
POST   /v1/cart/items          { "sku": "B0-PHONE-128", "qty": 1 }
PATCH  /v1/cart/items/{sku}    { "qty": 2 }
DELETE /v1/cart/items/{sku}

# Checkout session: freezes a price QUOTE for a few minutes
POST   /v1/checkout/sessions   { "addressId": "a1", "shippingSpeed": "STANDARD", "coupon": "DIWALI10" }
-> 201 { "sessionId": "cs_77", "quoteId": "q_9", "total": { "amount": 1899900, "currency": "INR" },
         "deliveryBy": "2026-11-27", "expiresAt": "2026-11-23T10:15:00Z" }

# Place order: THE idempotent call
POST   /v1/orders
Idempotency-Key: 0d5c3f0a-6b0e-4a39-9a51-2f1f8d0b6c11
{ "sessionId": "cs_77", "quoteId": "q_9", "paymentMethodId": "pm_card_4242" }
-> 202 { "orderId": "o_5001", "status": "PENDING" }           # saga running
-> 201 { "orderId": "o_5001", "status": "CONFIRMED" }         # finished fast
-> 409 { "error": "PRICE_CHANGED", "newTotal": 1949900 }       # quote expired or changed

GET    /v1/orders/{orderId}
POST   /v1/orders/{orderId}/cancel

# From the payment provider (verify the signature; dedupe by event id)
POST   /v1/webhooks/payments   { "eventId": "evt_123", "type": "payment.authorized", "paymentRef": "o_5001" }

Why a separate checkout session? Pricing depends on the address (tax, shipping), the coupon and the time (deals end). The session computes it once and freezes it as a quote with an expiry. Place Order then only has to check "is quote q_9 still valid?" instead of recalculating everything in the critical path. If it expired, the client shows the new total and asks again. Never charge a number the customer did not see.

From your world

An idempotency key is the application-level version of a TCP sequence number. A retransmitted segment with the same sequence number is not delivered to the application twice, and a retried POST with the same key does not create a second order. Where it breaks: TCP's window is short-lived, but a shopper can retry minutes later from another network, so the server keeps keys for hours (Stripe documents pruning them after 24 hours).
