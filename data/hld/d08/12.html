Quick quiz

Who should generate the idempotency key for Place Order?

  1. The server, when the request arrives
  2. The client, once per checkout attempt, reused on retries
  3. The payment provider
A server-made key is new on every retry, so it cannot detect a retry. The client must create it once and resend it.

Which statement prevents overselling the last unit?

  1. SELECT stock, then UPDATE if stock > 0
  2. Decrement in the cache, then write the DB later
  3. UPDATE ... SET reserved = reserved + 1 WHERE on_hand - reserved >= 1
The check and the change are one atomic statement. Rows affected tells you whether you won.

Payment is declined after stock was reserved. What happens?

  1. Compensations run in reverse: release the reservation, mark the order failed
  2. The order is confirmed and payment is retried later
  3. The reservation stays until a human removes it
That is the saga: each completed step has an undo step, run in reverse order.

The payment provider times out. What is the right state?

  1. FAILED, and let the user retry with a new key
  2. UNKNOWN: query or retry with the same key, then reconcile
  3. SUCCESS, ship the order
FAILED with a new key risks a double charge. SUCCESS risks free goods. Only UNKNOWN + same key + reconciliation is safe.

Why do we use a transactional outbox?

  1. Kafka cannot store order events
  2. To make Kafka faster
  3. A DB commit and a Kafka send are two writes that are not atomic together
The dual-write problem: a crash between the two writes loses or invents an event. The outbox puts both in one DB transaction.

Why is the cart stored in an AP key-value store?

  1. It must accept writes even during failures, and a merge is cheap
  2. Carts need multi-table joins
  3. Carts are rarely written
Dynamo's motivating example: never refuse "add to cart". Conflicts are merged (the union of items).

Which step is the saga's pivot?

  1. Reserve inventory
  2. Confirm the order (with the outbox row)
  3. Send the email
After the order is confirmed the saga only moves forward. Later steps are retried, not compensated.
