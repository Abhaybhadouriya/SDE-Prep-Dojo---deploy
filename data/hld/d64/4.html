Data model

EntityKeyStoreWhy
instrument(exchange, segment, token)Postgres + in-memory copySmall (thousands of rows), refreshed daily from exchange master files.
orderorder_id; unique (user_id, client_order_id)Postgres, partitioned by trade_date, sharded by user_idStrict state machine, transactions, audit queries.
order_event(order_id, seq)Append-only table + Kafka topic order-eventsHistory and replay. Never updated in place.
position, holding(user_id, instrument, product)Postgres, hot copy in RedisDerived from fills; Zerodha serves orders, positions and portfolio from hot Redis caches.
margin_accountuser_idIn-memory in the risk engine, journaledChecked on every order in microseconds.
gttgtt_id; index (status, instrument)Postgres (source of truth)Must survive anything for a year. Conditional updates for state changes.
last_quoteinstrumentRedis hashSnapshot sent when a client subscribes, before the stream starts.
candle(instrument, tf, start_ts)Current minute in Redis; closed candles in TimescaleDB / partitioned PostgresTime-range scans; idempotent upserts.
 
CREATE TABLE gtt (
  gtt_id          BIGINT PRIMARY KEY,
  user_id         BIGINT NOT NULL,
  client_gtt_id   TEXT   NOT NULL,
  instrument_id   INT    NOT NULL,
  type            TEXT   NOT NULL,           -- SINGLE | OCO
  trigger_values  BIGINT[] NOT NULL,         -- price in paise (integers, never floats)
  orders          JSONB  NOT NULL,
  status          TEXT   NOT NULL,           -- ACTIVE | TRIGGERING | TRIGGERED | FAILED | CANCELLED | EXPIRED
  version         INT    NOT NULL DEFAULT 1,
  placed_order_id BIGINT,
  expires_at      TIMESTAMPTZ NOT NULL,
  updated_at      TIMESTAMPTZ NOT NULL,
  UNIQUE (user_id, client_gtt_id)
);
CREATE INDEX gtt_active_by_instr ON gtt (instrument_id) WHERE status = 'ACTIVE';

Prices are integers in the smallest unit (paise) or in ticks. Floating point makes "price reached 1,400.05?" give wrong answers. Same rule as payments.
