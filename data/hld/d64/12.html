Quick quiz

5,000 instruments, conflated to one update every 500 ms. How many updates per second does the whole market produce after conflation?

  1. 1,000,000
  2. 10,000
  3. 100
5,000 x 2 per second = 10,000/s. Small enough to send the whole conflated feed to every gateway.

The exchange did not answer a new order within the timeout. What should the broker do?

  1. Resend the order immediately
  2. Mark it rejected and tell the user
  3. Mark it UNKNOWN and query the exchange for its status before any resend
The order may exist at the exchange. Resending could double-buy; marking rejected could hide a live order.

What stops two trigger-engine replicas from both placing an order for the same GTT?

  1. A conditional update from ACTIVE to TRIGGERING plus an idempotency key on the order
  2. A Redis lock with a 10-second TTL
  3. Running only one replica
Only one conditional update can succeed; the idempotency key covers retries. A lock can expire in the middle of the call.

Why is "re-place every GTT as a day order with a cron at 09:15" wrong?

  1. Crons cannot run at 09:15
  2. It puts untriggered orders on the exchange, blocks margin, and a half-finished run cannot be safely retried
  3. The exchange does not accept limit orders
It changes the meaning of GTT and has no per-item state for recovery.

20M orders a day on NSE equity hours. Average orders per second?

  1. About 230
  2. About 9,000
  3. About 900
20M / 22,500 trading seconds = about 900/s. 230 comes from wrongly using 86,400 s; 9,000 is the peak.

A phone on a slow network cannot keep up with price frames. Best gateway behaviour?

  1. Keep one pending frame per connection and overwrite it with the newest
  2. Queue all frames in memory until it catches up
  3. Slow down the conflator for everyone
Latest-wins prevents unbounded memory growth; old prices are useless anyway.

What key makes a 1-minute candle write idempotent?

  1. A random UUID per write
  2. (instrument_id, timeframe, start_ts)
  3. The arrival time of the last tick
Replaying the same ticks produces the same key, so an upsert gives the same result.
