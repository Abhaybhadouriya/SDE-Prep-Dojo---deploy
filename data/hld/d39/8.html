  • Cache stampede on a viral post: its count key expires and 100K readers hit the store together. Use request coalescing, refresh-ahead, or never expire hot keys - let the rollup job push new values. SoundCloud invalidated its whole counts cache daily with a randomised TTL to avoid synchronised spikes. See Pattern: Scaling Reads.
  • Aggregator crash: if batching is in memory only, the batch is lost. Keep Kafka as the source and commit offsets only after the counter write (or atomically with it).
  • Hot Kafka partition: all events for post 42 hit one partition. Pre-aggregate in the like service for a second, or salt known-hot keys.
  • Drift: retries, bugs or a skipped event make the counter disagree with the edges. Run periodic reconciliation from the truth (edges) and alert on the difference.
  • Abuse: bots inflate views. Filter before counting (Reddit's rules consumer), rate-limit likes per user, and keep raw events for later re-scoring.
