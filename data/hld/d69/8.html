Failure modes

  • Config service fully down: clients keep running on memory and last-known-good; new changes wait. Alert, but no customer impact. This is the property you designed for.
  • Bad config passes validation: canary alarms catch it, rollback in seconds. If it slipped through all waves, rollback is still one pointer move.
  • Distributor falls behind: clients still ask with their version; monotonic-read rule stops downgrades; a lag metric (store revision minus distributor revision) alerts.
  • Consensus store loses quorum: writes stop (CP), reads continue from distributor caches.
  • Reconnect storm: jitter and backoff in the SDK; distributors shed load with 503 + Retry-After rather than falling over.
  • Config that depends on another config: make it one config, or order the rollout; never rely on two independent rollouts landing together.
