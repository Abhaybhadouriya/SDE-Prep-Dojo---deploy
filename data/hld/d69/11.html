  • Off the request path: services read from memory; an outage stops changes, not traffic.
  • Immutable versions + pointers per target + a global revision. Rollback is a pointer move.
  • Strong at write (CAS, one order); eventual but monotonic at read; changes must be safe to run mixed.
  • Long-poll or stream to a distributor tier; clients send their version, so delivery self-heals.
  • SDK: validate, atomic swap, last-known-good on disk, jittered reconnect, report applied version.
  • Rollout: canary, waves, bake time, automatic rollback on alarms (AppConfig-style).
  • ZooKeeper/etcd are the store, not the fan-out; secrets go to a secrets manager.
