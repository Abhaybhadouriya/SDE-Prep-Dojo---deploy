Key APIs

APIDirectionNotes
GET /metrics on every targetScraper pulls from appPlain text exposition format (or OpenMetrics/protobuf). The app only keeps counters in memory.
POST /api/v1/push (remote write: protobuf + snappy)Prometheus/agent pushes to long-term storeBatches of series + samples. Retries with backoff; 429 if tenant over limit.
GET /api/v1/query?query=...&time=...UI / rulesInstant query: one value per series at a time.
GET /api/v1/query_range?query=...&start&end&step=30sDashboardsRange query: one point per step. step controls cost.
POST /api/v2/alerts (Alertmanager)Rule evaluator pushes firing alertsAlertmanager groups, dedups, silences and routes them.
 
$ curl -s localhost:9100/metrics | grep -A3 "node_cpu_seconds_total"
# HELP node_cpu_seconds_total Seconds the CPUs spent in each mode.
# TYPE node_cpu_seconds_total counter
node_cpu_seconds_total{cpu="0",mode="idle"} 183942.57
node_cpu_seconds_total{cpu="0",mode="user"} 7310.12

That is a real scrape: each line is one series (name + labels) with its current value. The scraper adds the timestamp and target labels (job, instance) when it stores it.
