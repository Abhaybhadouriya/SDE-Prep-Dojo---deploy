What can go wrong (and how teams notice)
  • Redis latency spike → every API slows (watch limiter p99 separately from backend p99).
  • Rule typo sets limit to 1/min → mass 429s (dark-launch rules, alert on 429 rate jump).
  • Clients retry 429 instantly → retry storms (enforce Retry-After, document backoff).
Common gotchas
  • Limiting by IP behind a corporate NAT or a mobile carrier's CGNAT punishes thousands of real users sharing one IP.
  • Trusting X-Forwarded-For blindly: clients can fake it unless your own proxy sets it.
  • Using gateway clocks instead of Redis time: skew makes buckets refill wrongly.
  • Forgetting TTLs: millions of dead keys fill memory.
