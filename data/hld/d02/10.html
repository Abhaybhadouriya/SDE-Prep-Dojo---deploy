How real companies do it

  • Stripe: "Scaling your API with rate limiters". Four limiters in production: a per-user request rate limiter (a token bucket in Redis, the most important one); a concurrent-requests limiter; a fleet usage load shedder that keeps a share of capacity for critical requests and answers the rest with 503; and a worker utilisation load shedder. Lessons: fail open if Redis is down, dark-launch, add kill switches, show clear errors. Read the post.
  • Cloudflare: "Counting things, a lot of different things". Explains the sliding window approximation (two counters per key, previous window weighted by overlap) and why it is accurate enough at their scale. Read the post.
  • Envoy global rate limiting. Envoy proxies call an external rate limit service (gRPC) with "descriptors"; the reference service envoyproxy/ratelimit keeps counters in Redis. Docs.
  • NGINX limit_req. A per-box leaky bucket with burst and nodelay. Docs.
  • Microsoft Azure: Rate Limiting pattern. Covers limiting your own calls to a throttled downstream (queue and pace the work), the other side of the same problem. Docs.
  • Redis INCR docs include the classic rate limiter patterns built on INCR and EXPIRE. Docs.
