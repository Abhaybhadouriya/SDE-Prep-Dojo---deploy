The story

Explain like I'm 5

Imagine a magic post office. Every child in town has a long string tied from their house to the post office, so they never need to walk there. When Asha wants to send a note to Ben, she ties it to her string and tugs. The post office worker catches it, writes a number on it, and tugs back once: "Got it!" (one tick). Then the worker looks at a big board that says which string goes to Ben's house, and sends the note down Ben's string. Ben's string tugs back: "Ben has it!" The worker tells Asha (two ticks). When Ben opens the note and reads it, his string tugs again and Asha sees the ticks turn blue. If Ben is asleep and his string is untied, the worker keeps the note in Ben's own little box and rings Ben's doorbell (a push notification). When Ben wakes up and ties his string again, every note in his box slides down to him, in order.

That is the whole design. The string is a long-lived network connection, usually a WebSocket (a TCP connection that both sides can send on at any time, unlike normal web requests where only the client asks). The post office workers are gateway servers that hold millions of these connections. The big board is a session registry: a fast lookup table that says "user Ben is connected to gateway server 17". Ben's little box is an offline inbox, stored in a database. The doorbell is Apple's or Google's push service (APNs or FCM).

The hard part is not sending one note. It is doing it for hundreds of millions of people at the same time, with no lost notes, no duplicates on screen, the right order inside each chat, and a reply in well under a second.

New words, once each: QPS means queries (or requests) per second. p99 latency means "99 out of 100 requests are faster than this". Idempotent means "doing it twice has the same effect as doing it once". All of these are in the glossary.
