Architecture: follow one message

Click Next or Play. We follow Asha's message "Hi!" to Ben, then the receipts coming back, then what happens when Ben is offline.

  1. Connect. Asha's app opens a WebSocket. A layer-4 load balancer picks gateway 3, and the connection stays there. Gateway 3 writes asha -> gw3 into the session registry with a 60 s TTL that every ping refreshes.
  2. Send. Asha types "Hi!". The app encrypts it, gives it a client_msg_id, and sends a frame on the open socket. Gateway 3 does not think; it forwards the frame to a stateless chat service.
  3. Store, then ack (1 tick). The chat service checks Asha may write to this chat, gets the next seq for the chat, and writes the message to the store (quorum write). Only after the write succeeds does it send the ack. The rule: never ack before it is durable.
  4. Find Ben. The chat service asks the session registry "which gateways hold Ben's devices?" and gets gw17.
  5. Push to Ben. The chat service sends the message to gateway 17 (internal gRPC, a binary RPC protocol between services over HTTP/2), which writes it down Ben's socket. Total path: about four network hops inside one region.
  6. Delivered (2 ticks). Ben's app saves the message locally and sends a receipt up_to_seq: 4182, delivered. It flows back the same way to Asha. A "read" receipt later turns the ticks blue.
  7. Offline path. If the registry has no entry for Ben (or the push to gw17 fails), the message is already safe in the store and in Ben's inbox. The chat service emits an event to Kafka; a push worker sends an APNs/FCM notification. When Ben reconnects, his app calls /sync with its last cursor and drains the inbox in order.

Why is the gateway "dumb"? Gateways hold millions of sockets and are painful to restart (every restart forces clients to reconnect). Keeping business logic in a separate stateless chat service means you can deploy logic ten times a day without dropping a single connection. This is the same split as a router's data plane (fast, stable) and control plane (smart, changes often).
