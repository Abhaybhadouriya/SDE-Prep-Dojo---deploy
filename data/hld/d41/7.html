Where Kafka, Kubernetes and Docker fit

ToolWhereDetail
KafkaLedger event fan-outTopic ledger-entries keyed by account_id gives per-account order. Use a transactional outbox or CDC, never "commit to the DB, then send to Kafka" as two separate writes. Consumers: statements, notifications, fraud, analytics, reconciliation. See Kafka and CDC pipeline.
KafkaCommand log (the ByteByteGo variant)Commands go into a FIFO log, a single-writer state machine per partition applies them, and events go to another topic. Use idempotent producers and acks=all.
KubernetesStateless tierGateway, wallet, orchestrator and risk run as Deployments with an HPA. Saga workers scale on Kafka lag (KEDA).
KubernetesStateful tierLedger databases often run outside K8s (managed RDS/Spanner), or as StatefulSets with operators. Square's Books is reported (per StackShare) to run on GKE with Spanner. A PodDisruptionBudget keeps a Raft majority up during node drains.
KubernetesRecon jobsA nightly CronJob (or a Spark-on-K8s job) per bank file. It is idempotent per (bank, date).
DockerTesting correctnessSpin up Postgres and run property tests: random concurrent transfers, then assert that the sum of all balances is unchanged and no balance is negative.
