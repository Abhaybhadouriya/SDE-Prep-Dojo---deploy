Architecture: a P2P transfer, step by step

  1. Validate. The wallet service authenticates the user, checks limits and KYC, and scores fraud risk. It records the idempotency key on the primary. If the key already finished, it returns the stored response.
  2. Orchestrate. The transfer orchestrator writes a transfer record in state STARTED. If both accounts are on one shard, it runs the single ACID transaction shown above, and the transfer is done.
  3. Debit first. Cross-shard: a local transaction on shard 1 debits A, guarded by balance >= amt. A only loses money if it had enough.
  4. Then credit. A local transaction on shard 7 credits B. Each step is idempotent, keyed by (transferId, step). If the credit keeps failing, the compensation credits A back. Debiting before crediting means that a crash never leaves money that can be spent twice.
  5. Publish. The ledger change goes out through the outbox or CDC to Kafka. History, push notifications, fraud models and reconciliation consume it asynchronously.
  6. Respond. The client gets COMPLETED (or PENDING if a step is still retrying), and the response is stored under the idempotency key for any retry.

Step 5 in plain words. CDC (change data capture) tails the database's write-ahead log and publishes each committed row change to Kafka. The outbox pattern writes the event into an outbox table in the same DB transaction as the postings, and a small relay publishes it. Either way the ledger commit and the event can never disagree, which a "write the DB, then send to Kafka" dual write cannot promise. It is like a journal replay in a filesystem: the log is the truth and every downstream copy is rebuilt from it.

From your world

An append-only ledger plus a derived balance is a journaling file system (ext4 / XFS journal) or a write-ahead log: the journal is the truth, and the in-place structure is a cache you can rebuild by replaying it. Debiting before crediting is like ordering writes so that a crash leaves a safe state, the same idea as soft updates, where you never point to a block before it is written.
