Key APIs

# Search (results stream in as suppliers answer)
POST /search  {trip: ONE_WAY|ROUND_TRIP, legs:[{from:"BLR", to:"DEL", date:"2026-12-20"}],
               pax:{adt:2, chd:0}, cabin:"ECONOMY", max_stops:1}
     -> 202 {search_id}
GET  /search/{search_id}/results?cursor=...   -> {complete:false, itineraries:[...], cursor}

# Re-price one itinerary live; returns a signed, expiring price token
POST /offers/price {itinerary_id}  -> {offer_id, total, breakdown, price_token, expires_at}

# Seat map for a segment (per-seat prices)
GET  /offers/{offer_id}/segments/{seg}/seats -> [{seat:"12C", type:"AISLE", price: 45000, available:true}]

# Booking (idempotent)
POST /bookings  {idempotency_key, offer_id, price_token, passengers:[...], seats:{seg1:"12C", seg2:"14A"}}
     -> 202 {booking_id, status:"HOLDING"}
POST /bookings/{id}/payment {idempotency_key, method_token}
GET  /bookings/{id}           -> {status: HOLDING|AWAITING_PAYMENT|TICKETING|CONFIRMED|FAILED|CANCELLED, segments:[...]}
POST /bookings/{id}/cancel
  • Async search (202 plus polling, or SSE/WebSocket streaming) lets fast suppliers show results in under a second while slow ones fill in. Never make the user wait for the slowest supplier.
  • price_token is a signed blob (offer, amount, user tier, expiry). The booking service accepts the price only if the token is valid; this is how a "member price" shown in search is honoured at booking.
  • Amounts in minor units (paise), with currency. Idempotency keys on every write. See idempotency key.
  • Amadeus's self-service flow is the same shape: Flight Offers Search, then Flight Offers Price to confirm availability and final price, then Flight Create Orders to book.
