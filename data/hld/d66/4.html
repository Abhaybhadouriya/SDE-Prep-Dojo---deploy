SQL for bookings because a booking and its segments change together in transactions with status checks; volume is tiny. Redis for search because it is a cache with TTLs. Search results can also be logged to a columnar store for analytics (which suppliers win, cache accuracy).

An OTA usually does not own a seat_inventory table: the airline does. Flipkart's version of this question ("airline ticket management system") expected entities, schema and APIs as if you were the airline, so be ready to design both sides, and say which one you are.
