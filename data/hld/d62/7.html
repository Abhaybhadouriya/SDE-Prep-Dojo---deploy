Where Kafka, Kubernetes and Docker fit

Concrete settings. Partition key tenant_id keeps one tenant's tag events in order (an add never overtakes its delete). Consumer-group sizing: one consumer per partition at most, so 24 partitions cap each group at 24 pods; a giant tenant still lands on one partition, so watch per-partition lag, not only the total. The Tag API HPA scales on CPU and p99; consumers scale on lag with KEDA.
