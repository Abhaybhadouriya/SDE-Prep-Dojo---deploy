Quiz

Which index serves "entities with tag T, newest first"?

  1. PRIMARY KEY (tenant_id, entity_ref, tag_id)
  2. (tenant_id, tag_id, tagged_at DESC, entity_ref)
  3. (entity_ref)
The second index starts with the tag and is sorted by time, so a cursor walks it directly.

Why is adding a tag a PUT and not a POST?

  1. PUT on the link is idempotent, so retries cannot create duplicates
  2. PUT is faster
  3. POST cannot carry a body
The link has a natural identity (entity + tag); PUT expresses "make this exist".

Two users create the tag "Urgent" and "urgent" at the same time. What prevents two tags?

  1. A Redis lock
  2. A retry loop
  3. A unique constraint on (tenant_id, normalized_name) plus an upsert
The database serialises the conflict; the loser gets the winner's id back.

Why shard by tenant first?

  1. Tenants are the biggest objects
  2. Both lookup directions stay on one shard, and it isolates customers
  3. It makes trending global
Sharding by entity would scatter the by-tag query; tenant keeps both local.

How do you get top-10 trending in the last 24 hours cheaply?

  1. Union 24 hourly sorted sets (with decaying weights) and ZREVRANGE 0 9
  2. SELECT tag, COUNT(*) FROM entity_tag GROUP BY tag on every request
  3. Scan all tags in Redis with KEYS
Buckets avoid subtracting old events, and reading the top 10 of a sorted set is O(log N + 10).

A tag is on 3M entities. What should never happen on each read?

  1. Reading the first page from the index
  2. Checking the cache
  3. COUNT(*) over all its links
Maintain usage_count from events and reconcile nightly.

Who filters "entities of tag" by what the viewer may see?

  1. Nobody; tags are public
  2. The product that owns the entities, with a batch permission check
  3. The browser
The tag service stores references only; permissions live in Jira, Confluence and Bitbucket.
