The story

Explain like I'm 5

Your class has toy boxes, drawing books and sticker albums. The teacher gives everyone the same roll of coloured stickers: a red one means "dinosaurs", a blue one "space". You can stick "dinosaurs" on a toy box and on a drawing book. Now the teacher wants two things fast: "show me everything with a dinosaur sticker" and "which stickers does this drawing book have?". So she keeps two notebooks. One notebook is sorted by sticker: under "dinosaurs" it lists every thing that has it. The other is sorted by thing: under "drawing book 7" it lists its stickers. Every time someone adds a sticker, she writes in both notebooks. And on the board she keeps a tally of which stickers were used most this week: the trending stickers.

That is the whole design. The things are entities (a Jira issue, a Confluence page, a pull request). The stickers are tags (Jira and Confluence call them labels). The two notebooks are one mapping table indexed in both directions. The tally board is the trending counter, usually a Redis sorted set fed by an event stream. The classroom is a tenant: one customer's site, whose tags other customers must never see.

Say this early: "This is a many-to-many relationship served at scale in both directions, plus a counting problem. The data model is the heart of it: tag, entity reference and a mapping table with one index per direction, everything scoped by tenant. Trending is a separate, eventually consistent pipeline." Atlassian interviewers in these reports cared most about the API and the schema.

From your world

The two indexes are like a forward and a reverse lookup table: the ARP cache maps IP to MAC, and you sometimes need MAC to IP. A routing table and a FIB, or a socket table looked up by 5-tuple and by process. Keeping two views of the same pairs in sync is the core job here, just as the kernel keeps several hash tables over the same connection objects.

New words, once each. A tenant is one customer (one Atlassian site) whose data is isolated from others. A mapping table (also called a join or junction table) stores pairs (tag, entity). A secondary index is an extra sorted copy of some columns so a different lookup is fast. Sharding splits data across database servers by a key. A Redis sorted set keeps members ordered by a score. Idempotent means doing it twice equals doing it once. The rest are in the glossary.
