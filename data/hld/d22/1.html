Requirements

We design the version from Alex Xu's book (a mobile game with monthly tournaments) and add the twists interviewers usually ask next. In an interview, say these out loud and write them down before drawing any box - that is the habit that separates SDE-2 from SDE-1.

Functional (in scope)
  • A player wins a match and gets points; the board updates in near real time.
  • Top 10 players of the current tournament.
  • My rank (and my score) for any player.
  • Around me: 4 players above and 4 below a given player (bonus).
  • A new leaderboard every month; old ones are kept as history.
  • Stretch: daily / weekly boards, friends-only board, per-region board.
Out of scope (say it)
  • Matchmaking and the game itself.
  • Anti-cheat machine learning (we only make sure clients cannot write scores).
  • Arbitrary ranges like "rank between 3 May and 17 May".
  • Payments, prizes, notifications (mention a hook, nothing more).

Questions to ask first: "How is the score computed - +1 per win, or the best single score?", "Is it one global board or per region/game mode?", "How do we break ties?", "How many players are on one board?", "Do we need history?" Each answer changes a command or a key name, so asking them is the cheapest way to look senior.

"You might confuse this with" Top-K. A leaderboard tracks a total per player and must answer "my rank" for anyone. Top-K / Heavy Hitters only cares about the few most frequent items out of billions of events and can be approximate. Different questions, different data structures.
