Quick quiz

Which Redis command returns a member's position with the highest score first?

  1. ZRANK
  2. ZSCORE
  3. ZREVRANK
  4. ZCARD
ZREVRANK ranks in descending score order (0-based). ZRANK is ascending; ZSCORE returns the score, ZCARD the size.

With 5M DAU and 10 matches each per day, what is the average score-update rate (using 105 s/day)?

  1. 50/s
  2. 500/s
  3. 5,000/s
  4. 50,000/s
5,000,000 x 10 / 100,000 = 500/s; peak is about 5x = 2,500/s.

Why can you not "just enable Redis Cluster" to shard one giant leaderboard?

  1. A sorted set is one key, and one key lives in one hash slot on one node
  2. Redis Cluster does not support sorted sets
  3. Cluster mode loses data
Cluster shards keys across 16,384 slots. A single key cannot be split, so you must partition the board yourself.

A consumer crashed after ZINCRBY but before committing its Kafka offset. What prevents double points?

  1. acks=all on the producer
  2. A Redis replica
  3. Increasing partitions
  4. An atomic check of the match_id before incrementing
Redelivery is normal in at-least-once processing. An idempotency key checked atomically with the update makes the second delivery a no-op.

You pack "points + earliness" into one Redis score. What limit must you respect?

  1. Scores must be below 231
  2. Scores are doubles, so integers stay exact only up to 253
  3. Scores cannot be negative
IEEE-754 doubles have a 53-bit mantissa; above 253 neighbouring integers collide and the tie-break is silently lost.

Where should the authoritative copy of every match score live?

  1. Only in Redis, it is fastest
  2. In the client's local storage
  3. In a durable score log (database and/or Kafka), with Redis as a rebuildable view
Redis replication is asynchronous and memory is volatile; keep the truth somewhere durable and replayable.

For a hash-partitioned board, how do you get a player's exact global rank?

  1. Sum, over all shards, the number of members with a higher score (ZCOUNT), in parallel
  2. Ask only the player's own shard
  3. It is impossible
Each shard can count members above a score in O(log N); adding the counts gives the global (tie-aware) rank.
