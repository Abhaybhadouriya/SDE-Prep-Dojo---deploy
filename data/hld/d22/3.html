Key APIs

# Internal only: called by the GAME SERVER after it has verified a match result.
POST /v1/scores
  body: { "user_id": "mary1934", "match_id": "m-88f2", "points": 3, "ts": 1795442400 }
  -> 202 Accepted          # accepted; the board updates a moment later

# Public reads (clients)
GET  /v1/leaderboards/{boardId}/top?limit=10
  -> { "board": "2026-11", "asOf": 1795442403, "entries": [ { "rank": 1, "user_id": "ravi", "name": "Ravi", "score": 120 }, ... ] }

GET  /v1/leaderboards/{boardId}/users/{userId}
  -> { "rank": 361, "score": 87, "percentile": 99.99 }   # a percentile, not "top %"

GET  /v1/leaderboards/{boardId}/users/{userId}/around?n=4
  -> { "entries": [ ...4 above..., { "rank": 361, "user_id": "mallow007", ... }, ...4 below... ] }

GET  /v1/leaderboards/{boardId}/friends/{userId}     # stretch
  • Writes come only from the game server, never from the phone. A client that can say "I scored 1,000,000" will. The game server knows the real match result.
  • match_id is the idempotency key - a unique ID for this score event so a retried request does not add points twice (deep dive 4). Same idea as a sequence number that lets a receiver drop a retransmitted duplicate.
  • boardId encodes the window: 2026-11 for the monthly tournament, 2026-11-23 for daily, 2026-W47 for weekly, 2026-11:eu for a regional board.
  • Return asOf (time of the data) so the UI can show "updated 2 s ago" when the pipeline is behind.
