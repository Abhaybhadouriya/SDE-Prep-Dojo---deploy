Key APIs

Three kinds of interfaces, one per plane. Keep them separate when you draw them. Background on choosing protocols is in API Design & Client-Server Communication.

1. REST (control plane, request/response)

POST /v1/meetings                       # create or schedule
  body: { "title": "Sprint review", "start": "2026-11-24T10:00:00Z", "settings": { "waitingRoom": true } }
  -> 201 { "meetingId": "842-113-907", "joinUrl": "https://meet.example/j/842113907" }

POST /v1/meetings/{meetingId}/join       # ask to join
  body: { "displayName": "Asha", "clientRegion": "ap-south-1" }
  -> 200 { "participantId": "p_77", "joinToken": "<short-lived signed token>",
           "signalUrl": "wss://sig-ap-south-1-12.meet.example/ws",
           "media": { "sfu": "sfu-blr-0412.meet.example:3478" },
           "iceServers": [ { "urls": "stun:stun.meet.example" },
                           { "urls": "turns:turn.meet.example:443", "username": "...", "credential": "..." } ] }

POST /v1/meetings/{meetingId}/recordings  # host starts cloud recording
GET  /v1/recordings/{recordingId}         # status and a pre-signed download URL when ready

2. Signalling (WebSocket, JSON messages)

{ "type": "publish",   "tracks": [ { "kind": "video", "simulcast": ["q","h","f"] }, { "kind": "audio" } ], "sdp": "..." }
{ "type": "answer",    "sdp": "..." }
{ "type": "subscribe", "participant": "p_31", "track": "video", "maxLayer": "h" }
{ "type": "mute",      "track": "audio", "muted": true }
{ "type": "speaker",   "dominant": "p_31" }      // server -> client
{ "type": "roster",    "joined": ["p_90"], "left": ["p_12"] }

3. Media (UDP)

SRTP over UDP to the assigned SFU, with RTCP for feedback. Fallback order, as Zoom documents for its clients: UDP first, then TCP/TLS, including TLS on port 443 which looks like HTTPS to a corporate firewall.

The join response already contains the chosen SFU. The client does not pick its media server; the meeting service does, so that everyone in the same meeting lands on the same SFU (or the same cascade). Discord does exactly this: its Guilds service assigns a voice server and returns its address.
