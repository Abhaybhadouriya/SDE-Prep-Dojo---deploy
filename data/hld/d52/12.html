Quick quiz

In a 10-person peer-to-peer mesh call at 1.5 Mbps per stream, how much does each person upload?

  1. 1.5 Mbps
  2. 3 Mbps
  3. 13.5 Mbps
Each sender uploads one copy to each of the other 9 people: 9 x 1.5 = 13.5 Mbps. That is why groups use an SFU.

What does an SFU do with incoming video?

  1. Forwards selected encoded packets to each receiver without decoding
  2. Decodes, mixes and re-encodes one stream per receiver
  3. Stores it in Kafka for replay
Forwarding without decoding is what makes the SFU cheap and E2EE-compatible. Decoding and mixing is an MCU.

Which server is needed when a user is behind a symmetric NAT?

  1. A STUN server only
  2. A TURN relay
  3. A DNS server
A symmetric NAT creates a new mapping per destination, so the STUN-learned address does not work for anyone else. TURN relays the media.

Why is media sent over UDP instead of TCP?

  1. UDP is encrypted and TCP is not
  2. Late packets are useless, and TCP's in-order retransmission causes head-of-line blocking
  3. TCP cannot carry video
For live media, late equals lost. UDP lets the receiver skip and conceal a lost packet; TCP would stall everything behind it.

With simulcast, who decides which quality a given receiver gets?

  1. The sender, for all receivers at once
  2. The database
  3. The SFU, per receiver, using that receiver's bandwidth feedback
The sender uploads several layers; the SFU picks one per receiver based on RTCP feedback and layout rules.

Where should Kafka appear in this design?

  1. Meeting lifecycle events and QoS telemetry
  2. Every RTP video packet
  3. The TURN relay
Kafka is for durable, replayable events. Media is real-time, disposable and latency-critical.

Using Teams' 4.1B meeting minutes a day, roughly how many people are in a meeting at an average moment?

  1. About 280K
  2. About 2.8M
  3. About 28M
4.1B minutes / 1,440 minutes per day = about 2.85M concurrent participants on average; peak is a few times higher.

What is the main cost of turning on end-to-end encryption in an SFU-based product?

  1. The SFU can no longer forward packets
  2. Clients can no longer use UDP
  3. No server can decode the media, so cloud recording and transcription stop working
The SFU only needs RTP headers, so forwarding still works. Anything that must see the pictures or sound on the server cannot.
