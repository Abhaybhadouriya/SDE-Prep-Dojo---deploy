You might confuse this with... RAG vs fine-tuning: RAG looks facts up at question time (fresh, citable, per-user permissions), fine-tuning changes the model's weights (style and format, not fresh facts). And the three caches: a response cache stores whole answers for the exact same prompt, a semantic cache returns an answer for a similar prompt (risk: wrong hits), and a prefix (KV) cache reuses the GPU work for a shared start of the prompt (always exact).

The 60-second answer. "I treat the model as a black box on scarce GPUs. Requests come through a gateway that authenticates and enforces token budgets per tenant, then a router sends them to an inference pool running continuous batching with a paged KV cache, and tokens stream back over SSE. I size the fleet by KV memory per concurrent stream, not by QPS. For company data I use RAG: documents flow through CDC into an ingestion pipeline that chunks, embeds and writes to a vector index with permission metadata; at query time I do hybrid vector plus BM25 retrieval, re-rank, and put the top chunks in the prompt. I add a prefix cache for shared system prompts, guardrails on input and output, and an offline eval set plus online feedback so I know when quality drops."
