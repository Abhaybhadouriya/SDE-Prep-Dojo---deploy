Caching: three different caches

"Add a cache" means three different things in an LLM system. Name all three and say what each saves.

Semantic cache

GPTCache (an open-source project) shows the parts: an embedding generator, a vector store to find the most similar past question, a similarity evaluator that decides "same question or not", a store for answers, and an eviction policy (LRU, LFU, FIFO). Its README itself warns about false positives, where a hit returns an answer to a question that only looks the same ("cancel my order" vs "cancel my subscription"). Use it for public, non-personal, FAQ-like traffic, scope keys by tenant, and keep a strict threshold.

Prefix caching on the server

Many requests start with the same thousands of tokens: the system prompt, tool definitions, or a long document a user keeps asking about. vLLM's automatic prefix caching gives each full KV block a hash built from the parent block's hash plus this block's tokens (plus extras like adapter IDs). A block is therefore identified by its whole prefix, like a hash chain. Blocks are reference-counted, freed blocks sit in an LRU queue and stay reusable until evicted, and an optional cache_salt limits sharing to one trust group, because cache-hit timing could otherwise leak what another tenant sent.

Hosted APIs expose the same idea with a price. Anthropic's prompt caching docs say: the cached prefix must match 100% up to the breakpoint; the default lifetime is 5 minutes, refreshed on every hit (a 1-hour option exists); writing to the cache costs 1.25x the normal input price and reading costs 0.1x by default. So put stable content first and changing content last. A timestamp at the top of the system prompt silently disables caching for every request.

Design consequence: route requests from the same conversation to the same GPU replica (consistent hashing on conversation ID or prefix hash) so the KV blocks are still warm. This is session affinity, and it trades perfect load balance for cache hits - the same tension as sticky sessions in load balancers.
