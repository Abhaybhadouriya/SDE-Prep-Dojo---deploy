Token-based rate limits and fair scheduling

Request counts lie in LLM systems. One request with a 100,000-token document costs thousands of times more GPU work than "hi". So providers limit several dimensions at once. OpenAI's docs list requests per minute (RPM), requests per day (RPD), tokens per minute (TPM), tokens per day (TPD) and images per minute, and whichever limit is hit first applies.

The counting problem

You know the input tokens when the request arrives, but the output tokens only when it finishes. OpenAI's docs say the limit is computed from the maximum of max_tokens and an estimate from the request's length, which is why a large max_tokens eats your budget even if the answer is short. The common design is reserve, then reconcile:

# Token bucket per (tenant, model) in Redis; run as one atomic Lua script in production.
def admit(tenant, prompt_tokens, max_tokens):
    estimate = prompt_tokens + max_tokens          # worst case
    if not bucket.try_take(tenant, estimate):      # refills at TPM / 60 per second
        return reject(429, retry_after=bucket.seconds_until(tenant, estimate))
    return Reservation(tenant, estimate)

def on_finish(res, prompt_tokens, output_tokens):
    actual = prompt_tokens + output_tokens
    bucket.give_back(res.tenant, res.estimate - actual)   # refund the unused part
  • Tell clients where they stand. OpenAI returns headers such as x-ratelimit-remaining-tokens and x-ratelimit-reset-tokens, plus Retry-After on a 429.
  • Clients back off with jitter. OpenAI's guidance: treat Retry-After as a minimum, otherwise exponential backoff with jitter (their examples start at 1 s and cap at 60 s), and remember failed attempts still count toward per-minute limits.
  • Limit concurrency too. A token bucket controls rate, but GPU memory is about concurrent streams. Cap in-flight requests per tenant so one customer cannot fill every KV slot.
  • Tiers and priority. Paid traffic goes to a higher-priority queue or a reserved pool; free traffic gets a smaller model or waits. Batch jobs (embedding a whole corpus) run in a separate low-priority lane that fills idle GPU time.
  • Load shedding. When the queue wait would exceed the TTFT target, reject early with 429 or 503 instead of letting requests time out after using GPU time. See resilience patterns.

From your world

This is QoS on a router. TPM is a token-bucket policer measured in bytes, not packets; the concurrency cap is a queue-depth limit; paid vs free tiers are priority queues with weighted fair queuing; reserve-then-refund is like admission control for a reserved-bandwidth flow. Counting requests instead of tokens is like policing by packets per second while someone sends jumbo frames.
