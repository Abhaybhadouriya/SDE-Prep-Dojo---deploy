GPU capacity: a whiteboard estimate

Interviewers love one rough GPU estimate. Keep it simple, state assumptions, and show which resource runs out first. (Method from Back-of-Envelope Estimation.)

  1. Load. Hello Interview's ChatGPT breakdown assumes about 200M daily users, about 20k prompts per second at peak, and about 120k responses streaming at any moment (each takes several seconds).
  2. Memory per stream (our assumption). Say a 13B-class model at about 1 MB of KV cache per token, and an average live context of 2,000 tokens (history + retrieved text + answer so far). That is about 2 GB per active stream.
  3. Streams per GPU. With about 14 GB left after weights on a 40 GB A100 (Anyscale's figure), one GPU holds about 7 such streams.
  4. Fleet. 120,000 / 7 is about 17,000 GPUs before any headroom. That number is shocking on purpose: it tells you which levers matter.
  5. Levers. Bigger-memory GPUs (H100 80 GB also has 2.15x the A100-40GB's bandwidth, per Databricks), grouped-query attention (fewer KV heads, smaller cache), KV-cache quantization, shorter contexts (summarise old history), prefix sharing, routing easy prompts to a smaller model, and caching whole answers.

Careful: the 2,000-token average and 13B model are assumptions for practice, not facts about any real product. Say "assume" out loud. What the interviewer grades is that you size KV memory per concurrent stream, not QPS alone.

Throughput check: decode speed per GPU is roughly memory bandwidth divided by bytes read per step. Databricks' example: a 7B model at 16-bit is 14 GB, so a 14 ms per-token step moves about 1 TB/s, which is 50% "model bandwidth utilisation" on a 2 TB/s GPU.
