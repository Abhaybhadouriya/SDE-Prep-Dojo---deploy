The map: boxes in an LLM product

Here is the request path of a typical LLM feature, from the user's browser to a GPU and back. Every box is something you already know from other designs, except the last two.

  1. Gateway authenticates the user and checks a token budget, not just a request count. See d02 Rate Limiter for the base algorithms.
  2. Cache may answer instantly if the same (or a very similar) question was answered recently.
  3. Orchestrator loads chat history, runs retrieval (RAG), and assembles the final prompt: system instructions + retrieved passages + history + the new question.
  4. Guardrails screen the input (prompt injection, personal data) and later the output (unsafe content, broken JSON).
  5. Router picks a model (small and cheap or big and smart) and queues the request for a GPU replica that has room.
  6. Inference server (for example vLLM or Hugging Face TGI) runs the model loop and pushes each token back as soon as it exists, usually over Server-Sent Events.

Say this early: "The LLM is the expensive, slow, stateful-per-request part. Everything else in my design exists to send it fewer tokens, keep it busy, and protect it."
