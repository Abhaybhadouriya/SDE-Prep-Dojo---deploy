The story

Explain like I'm 5

Imagine a very clever storyteller who lives in a library. You ask a question and the storyteller answers one word at a time, and before saying each new word, they quickly re-read their notebook of everything said so far. The storyteller is expensive: there are only a few of them, and lots of kids want stories.

So the library gets helpers. A librarian runs to the shelves and brings back the three pages that best match your question, so the storyteller does not have to guess from memory. A doorkeeper gives every kid a few word-tickets per minute, so one loud kid cannot keep the storyteller busy all day. A memory board by the door remembers answers to questions people ask again and again. And a grown-up checker listens to every answer before it reaches the kid, to stop anything rude or wrong.

That is the whole page: the storyteller is the LLM, the notebook is the KV cache, the librarian is RAG with a vector database, the tickets are token rate limits, the board is a cache, and the checker is guardrails and evaluation.

From your world

Treat the GPU as a very expensive line card with a small, fast buffer. Each chat is a long-lived flow that keeps per-flow state in that buffer (the KV cache), so the number of flows a card can hold is set by buffer memory, not by its compute. Batching is like packing many flows into one DMA burst, token rate limits are a token-bucket policer counted in tokens instead of bytes, and RAG is a lookup table you consult before forwarding. Where this breaks: a packet is forwarded once, while a chat request runs for seconds and its state keeps growing with every token it produces.

A large language model (LLM) is a program that, given some text, predicts the next small piece of text. That small piece is a token (roughly a word piece; NVIDIA's guide uses "one token is about four English characters"). To write an answer, the model predicts one token, appends it, and predicts again, over and over. Everything hard about AI systems at scale comes from that loop: it is slow, it runs on scarce and expensive GPUs (graphics processors used as giant parallel calculators), and its memory grows with every token.

Words on this page (one line each, no model-internals background needed):

  • Token: the unit the model reads and writes, about 4 English characters. Prices, limits and speed are all counted in tokens.
  • Attention layer: the part of the model that, for each new token, looks back at all earlier tokens to decide what matters. A model is a stack of dozens of these layers.
  • FP16: a 16-bit (2-byte) floating-point number. Model weights and the KV cache are usually stored in FP16, so a 7-billion-parameter model is about 14 GB.
  • GQA (grouped-query attention): a model design where several attention heads share one set of keys and values, so the KV cache is several times smaller.
  • Quantization: storing numbers with fewer bits (8-bit or 4-bit instead of 16-bit) to save memory and bandwidth, at a small cost in accuracy.
  • Embedding: a fixed-length list of numbers that represents the meaning of a text; similar meanings give nearby vectors.
  • ANN (approximate nearest neighbour): an index that finds vectors close to a query quickly, accepting that it may miss a few true matches.
  • p99 latency: the latency that 99% of requests beat; 1 in 100 is slower. See glossary.

Interviewers do not expect you to train models. They treat the model as a black box and ask you to build the system around it: how requests reach GPUs, how answers stream back, how you ground answers in company data, how you stop one customer from eating all capacity, and how you know the answers are any good. Those are classic distributed-systems questions in new clothes, which is good news for you.
