Where Kafka, Kubernetes and Docker fit

  • Kafka carries payment-events (fan-out to many teams), a retry topic and a dead-letter topic for merchant webhooks, and the CDC stream from the outbox. Use acks=all, min.insync.replicas=2 with replication factor 3, and the idempotent producer, so a broker failure loses nothing that was acknowledged (see Replication & ISR). Kafka is not the source of truth for balances here; the SQL database is. (PhonePe made a different, valid choice; see real world.)
  • Kubernetes runs the stateless services as Deployments with an HPA on CPU or request rate, readiness probes that fail when the database pool is exhausted, and a PodDisruptionBudget so a node drain never takes all replicas. Card-handling services live in a separate namespace with NetworkPolicies, which shrinks the PCI zone (see Security & RBAC).
  • Docker images are small and pinned (distroless or slim bases, non-root user), so security scanners have less to flag and every deploy is reproducible (see Production, Security & CI).

  --topic payment-events --partitions 12 --replication-factor 3 \
  --config min.insync.replicas=2 --config retention.ms=604800000
