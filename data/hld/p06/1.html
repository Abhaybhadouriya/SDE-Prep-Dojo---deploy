When you hit it

Hello Interview's pattern page gives a handy rule of thumb: if a file is over about 10 MB and you do not need to query inside it with SQL, it belongs in blob storage, not in a database column. A 100 MB value in a database row slows queries, bloats backups and makes replication crawl. Object stores are built for the opposite: practically unlimited capacity, per-object pricing, and S3's famous design target of eleven nines (99.999999999%) of durability.

Signals in the interview question

  • "Users upload videos / photos / files." YouTube, Dropbox, Instagram, attachments in email and chat.
  • Mobile or flaky networks. A 2 GB upload over Indian 4G will drop at least once. You need resume.
  • "Design S3 / Google Drive." Then the blob store is the system (S3-like Object Storage).
  • Global, heavy downloads. Video, game patches, app updates, ML model weights.
  • Private files. Medical reports, invoices: downloads must be authorised, yet fast.

Why the naive design breaks

From your world

This is the "do not copy through user space" lesson. You would never read() a file into a buffer and write() it to a socket when sendfile() or DMA can move it without the CPU touching every byte. The API server is the CPU here; the presigned URL is the DMA descriptor: the control plane sets up the transfer (address, length, permission), and the data plane moves the bytes. Control plane vs data plane is the same split you know from routers - the route processor programs the forwarding table and never sees most packets.

Worked estimate: what the proxy design costs

Example numbers for practice (not from a source): 1M uploads a day, 50 MB average.

  1. Daily volume. 1M x 50 MB = 50 TB/day.
  2. Average bandwidth. 50 TB x 8 bits / 86,400 s = about 4.6 Gbit/s, all day.
  3. Peak. Peak is often 2-3x average, so plan for about 14 Gbit/s.
  4. Proxied. Every byte enters the API fleet and leaves it again towards the store, so the API NICs carry about 28 Gbit/s at peak, and every in-flight upload pins a worker and its buffer. With presigned URLs the API sees only small JSON calls (1M a day is about 12 per second on average), and the 14 Gbit/s goes straight to the blob store.

Part math for one 2 GB video. 2 GiB / 16 MiB parts = 128 parts, well under the 10,000-part limit. If the network drops at 99%, only the parts in flight are lost: about 16 MiB per lost part instead of the whole 2 GB. Pick the part size so that file size / part size stays under 10,000: a 100 GB file needs parts of at least 10 MB.
