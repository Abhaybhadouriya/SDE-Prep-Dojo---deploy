  • Dual write = two systems written without a shared transaction; a crash between them silently corrupts state.
  • Fix rule: write atomically to one place (your DB), derive everything else from it.
  • 2PC: prepare then commit; atomic and isolated, but blocking and lock-heavy. Use inside one distributed DB, not across services.
  • Saga: local transactions + compensations. Compensable steps, one pivot, retryable steps. No isolation - use semantic locks and commutative updates.
  • Choreography for a few simple steps; orchestration (Temporal, Step Functions) for anything bigger.
  • Outbox: event row in the same transaction; a relay (poller or CDC) publishes at least once, keyed by aggregate id.
  • CDC streams the DB log to Kafka to keep search, caches and warehouses in sync; it gives "what changed", not "why".
  • Event sourcing: state = fold(events), snapshots, optimistic append; pairs with CQRS read models.
  • Kafka exactly-once = idempotent producer + transactions with offsets + read_committed; it ends at Kafka's edge.
  • Every consumer and every retried API call must be idempotent: dedup table, upserts, idempotency keys.
