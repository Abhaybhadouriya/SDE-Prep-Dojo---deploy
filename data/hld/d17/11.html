Remember this

  • A cache is a copy; the DB is the truth. Always set a TTL.
  • O(1) LRU = hash map + doubly linked list; Redis approximates it by sampling.
  • Never modulo-N; use consistent hashing or Redis's 16,384 hash slots (CRC16).
  • Replication is async: a failover can lose acked writes. Fine for caches only.
  • Cache-aside: on write, commit to DB then delete the key (do not update it).
  • Hot keys: local L1 cache + key replication. Stampedes: coalescing, leases, jitter.
  • A cache outage multiplies DB load by 1/(1 - hit ratio). Plan for it.
  • CDC through Kafka makes invalidation reliable and multi-region.
