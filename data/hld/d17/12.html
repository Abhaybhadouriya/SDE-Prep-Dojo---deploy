Quick quiz

Which two structures give an O(1) LRU cache?

  1. A min-heap keyed by last access time
  2. A hash map plus a doubly linked list
  3. A sorted array plus binary search
  4. A hash map plus a singly linked list
The map finds the node and the doubly linked list moves or removes it in O(1). A heap needs O(log n) per access update. A sorted array needs O(n) shifts on every move. A singly linked list cannot unlink a node in O(1) without its predecessor.

How many hash slots does Redis Cluster use?

  1. 1,024
  2. 4,096
  3. 65,536
  4. 16,384
slot = CRC16(key) mod 16384. 65,536 is the full CRC16 range; Redis chose 16,384 so the slot bitmap in gossip messages stays at 2 KB. 1,024 and 4,096 are not used.

On a write in cache-aside, what should the app do to the cache key?

  1. Delete it after the DB commit
  2. Update it before the DB commit
  3. Nothing; let the TTL expire it
Deleting is idempotent and order-safe; the next read loads fresh data. Updating before commit caches a value that may roll back, and two writers can race their SETs. Waiting for the TTL serves stale data for the whole TTL.

Hit ratio is 95%. The cache vanishes. Roughly how much does DB read load grow?

  1. 2x
  2. 5x
  3. 20x
  4. 95x
The DB went from serving 5% of reads to 100%: 1 / 0.05 = 20. 2x and 5x underestimate a cold cache badly. 95x confuses the hit ratio with the multiplier.

What does a hash tag like {user:42}:cart do?

  1. Hashes only the braces part, so keys share a slot
  2. Marks the key as a tag for bulk deletion
  3. Encrypts the user id inside the key name
Keys with the same tag land in the same slot, so multi-key commands and Lua scripts work on them. Redis has no tag-based deletion. Braces have nothing to do with encryption.

What is Redis's default maxmemory-policy?

  1. allkeys-lru
  2. noeviction
  3. volatile-lru
  4. allkeys-lfu
The default is noeviction: writes fail with OOM errors when memory is full, so a cache must set a policy. allkeys-lru and allkeys-lfu are common choices you set yourself. volatile-lru only evicts keys that have a TTL.

Your redis.conf has maxmemory 48gb # headroom. What happens at startup?

  1. Redis ignores the comment and starts
  2. Redis starts but uses no maxmemory
  3. Redis refuses to start: bad arguments
  4. Redis caps memory at 48 GB minus headroom
redis.conf only treats # as a comment at the start of a line, so the extra words become arguments and Redis exits with a config error. It does not silently ignore them, and it does not drop the setting and carry on. Redis does not parse comments as settings.

Which technique did Meta's memcache use to stop both stampedes and stale sets?

  1. Bloom filters
  2. Leases
  3. Two-phase commit
A lease token lets one client refill a missing key, and a delete invalidates outstanding tokens so a stale value cannot be set. Bloom filters answer "maybe present", not who may refill. Two-phase commit is far too heavy for a cache.

Why add random jitter to TTLs?

  1. So keys filled together do not expire together
  2. To save memory on the expiry index
  3. So hot keys live longer than cold keys
Synchronised expiry causes synchronised misses, which is a stampede on the database. Jitter does not change memory use. Keeping hot keys longer is what LFU eviction or explicit TTL choices do, not random jitter.
