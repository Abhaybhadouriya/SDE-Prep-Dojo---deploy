Key APIs

# reader-facing (public, cacheable)
GET /v1/feed?region=IN&category=tech&limit=20&cursor=<opaque>
    -> { stories: [ {storyId, headline, snippet, imageUrl, sourceCount,
                      leadArticle: {articleId, publisher, publishedAt}} ],
         nextCursor: "<opaque>" }
GET /v1/stories/{storyId}               -> all articles in one story ("Full Coverage")
GET /v1/r/{articleId}                   -> 302 redirect to the publisher URL, logs the click

# ingestion (internal / publisher-facing)
POST /v1/websub/callback/{feedId}       -> hub pushes new feed content (HMAC signed)
GET  /v1/websub/callback/{feedId}?hub.challenge=...   -> echo challenge to confirm subscription
  • Cursor, not page number. The cursor is an opaque token that encodes "where you stopped" (more in the deep dives). Page numbers break when new stories arrive at the top.
  • Redirect endpoint. /r/{articleId} lets us count clicks (input for ranking and personalisation) and lets us change the target URL if a publisher moves the article. It returns a 302, not a 301, so browsers do not cache it forever (the same reasoning as in URL Shortener).
  • Feeds are public. The non-personalised feed has no user id in it, so the CDN can cache one copy for everybody in a region.
