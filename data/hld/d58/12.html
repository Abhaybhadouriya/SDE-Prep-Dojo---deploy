A feed has not changed since our last poll. What should the publisher's server return to our conditional GET?

  1. 200 with the full feed
  2. 304 Not Modified with no body
  3. 404 Not Found
With If-None-Match / If-Modified-Since, an unchanged resource returns 304 and no body, saving bandwidth.

Why can't SHA-256 of the page body catch a wire story reprinted with a different footer?

  1. SHA-256 is too slow
  2. SHA-256 values are too long to store
  3. Any small change produces a completely different hash
Cryptographic hashes are designed so that one changed byte changes about half the bits. SimHash is designed so that similar inputs give similar fingerprints.

In Google's crawler study, which SimHash setting worked for 8 billion pages?

  1. 64-bit fingerprints, near-duplicate if at most 3 bits differ
  2. 32-bit fingerprints, exact match only
  3. 128-bit fingerprints, at most 20 bits differ
Manku, Jain and Das Sarma validated f = 64 and k = 3 on 8B pages.

The reader scrolls while 5 new stories arrive at the top. With offset pagination, what happens on page 2?

  1. Nothing - offset is stable
  2. Five stories from page 1 repeat
  3. The request fails
Everything shifted down by five, so "skip 20" now lands five items earlier.

Why is the first page of a non-personalised feed so cheap to serve?

  1. It is stored in Postgres
  2. It is computed by a GPU
  3. It is the same for everyone in a region and category, so the CDN caches it
No user id in the response means one cached copy per (region, category) at the edge.

In WebSub, how does the hub confirm that the subscriber really asked to subscribe?

  1. It sends a GET with hub.challenge, which the subscriber must echo back
  2. It emails the subscriber
  3. It trusts every POST
Verification of intent: the callback must return 2xx with the challenge in the body.

Personalising every reader's whole feed mainly hurts which part of the design?

  1. The ingestion fetchers
  2. The CDN hit rate and read latency
  3. The SimHash index
Personal responses cannot be shared at the edge. Re-rank a shared candidate list instead.
