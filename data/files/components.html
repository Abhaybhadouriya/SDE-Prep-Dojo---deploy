  4. Each section is <section id="..."><h2>...</h2> - the TOC is built from these.

From your world (bridge)

Map a new idea to kernel / networking knowledge the learner already has.

From your world

A Kubernetes Service is a virtual IP. kube-proxy writes iptables or nftables rules (IPVS mode is deprecated) that DNAT traffic to one of the pod IPs - the same NAT you have configured on routers.

Where this breaks: a router NATs on one box, but a Service rule is copied to every node in the cluster, so a rule change takes a moment to reach all nodes and connections already open keep their old backend.

Remember this

  • A topic is split into partitions.
  • Order is guaranteed only inside one partition.
  • One partition is read by at most one consumer in a group.

Interview Q&A

Level colours the left edge and the L1-L5 pill automatically. data-company is read by the question bank filter.

How does Kafka keep messages in order?

Order is kept inside a partition only. Messages with the same key go to the same partition, so all events for one user stay in order.

How to answer

State the guarantee, explain keys, then the trade-off with parallelism.

Likely follow-ups
  • What breaks ordering on retries?
  • What if one key is very hot?

Scenario drill

A production problem with a weak answer (red) and a strong answer (green).

Scenario: consumer lag keeps growing

It is Big Billion Days. The order-events consumer group is 2 million messages behind and growing.

"I would add more consumers." (Does not help if there are more consumers than partitions.)

Check lag per partition. If even, scale consumers up to the partition count and speed up processing (batching, async I/O). If one partition is hot, fix the key skew. Protect downstream with backpressure.

Likely follow-ups
  • How do you add partitions without breaking ordering?
