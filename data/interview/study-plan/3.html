Before you start

You need

  • A laptop with 16 GB RAM if possible (8 GB works, but run fewer containers at once).
  • Docker Desktop (with WSL 2 on Windows) or Docker Engine on Linux.
  • kind or minikube for Kubernetes, and kubectl.
  • A notebook (paper) for designs. Drawing by hand is what you will do in interviews.
  • About 2 hours a day, 6-7 days a week on the 12-week pace. The 8-week pace needs 2 hours a day early on and 3-4 hours a day in weeks 6-7.

You already have

  • Linux, processes, memory, sockets, TCP/IP. That covers most "hard" parts of Docker.
  • Routing, bridges, NAT, VXLAN. That covers most of Kubernetes networking.
  • Ring buffers, flow control, HA pairs. That covers most of Kafka's ideas.
  • Debugging under pressure. That is exactly what the scenario drills test.

On Windows with Docker Desktop, read this before Day 2. Docker Desktop runs the Docker daemon inside a small Linux virtual machine, not on your Windows host. So host commands such as ps -ef | grep nginx, sudo iptables -t nat -L DOCKER -n and sudo unshare either fail or show nothing, because the containers are not on that host. Two fixes:

  1. Best for this plan: open your WSL 2 distro (for example Ubuntu), install Docker Engine inside it (Docker's apt repository, or sudo apt install docker.io), and turn off Docker Desktop's WSL integration for that distro. Now the distro is the Linux host, and every lab below works exactly as written.
  2. Quick look, no install: open a root shell inside the Docker Desktop VM with docker run -it --rm --privileged --pid=host alpine nsenter -t 1 -m -u -n -i sh. In that shell, ps and iptables see the real containers (no sudo needed: you are already root). Type exit to leave.

Each Week-1 lab shows what the output should look like, so you can tell "it worked" from "it silently saw nothing".
