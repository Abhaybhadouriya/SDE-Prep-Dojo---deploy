DaemonSet
Kubernetes		One helper sitting at every single table.Runs one copy of a pod on every node (or every matching node). Used for log shippers, monitoring agents, CNI and storage drivers. New nodes get the pod automatically. From your world: A process that must run on every line card, like a local agent.Deployments, ReplicaSets & Rollouts
Dark store
HLD		A shop with no shoppers inside, only helpers who pack your order very fast.A small warehouse inside a city that serves only online orders, used by 10-minute delivery apps. Search and stock are scoped to the one store that can reach the user in time, so each store has its own inventory.Quick Commerce
Data lake / lakehouse
HLD		A huge toy chest where everything is thrown in first and sorted later.Cheap object storage (S3, ADLS, GCS) holding raw and processed data in open file formats (Parquet) for analytics. A lakehouse adds table formats (Iceberg, Delta, Hudi) that give transactions and schema on top.Big Data: Batch, Streaming & Probabilistic Structures
Database index
HLD		The index at the back of a book, so you jump to the right page instead of reading everything.An extra data structure (usually a B-tree, sometimes hash, LSM or inverted) that lets the database find rows by a column without scanning the whole table. Speeds reads; slows writes and uses space.Data Modeling, Indexing & Storage Engines
Deadlock
LLD must know		Two kids each hold one toy the other wants, and neither lets go.Threads wait forever for each other's locks. Needs all four Coffman conditions: mutual exclusion, hold and wait, no preemption, circular wait. Break one, usually with a global lock order or tryLock with timeout. From your world: The lock-ordering rules lockdep checks for you.Deadlock, Livelock & Starvation
Debezium
Pipeline		A helper who copies every new line of the shop's book onto a message belt.An open-source CDC platform, usually run as Kafka Connect source connectors, that reads database logs (MySQL binlog, Postgres WAL and others) and publishes change events to Kafka topics. Includes an outbox event router.Kafka Connect, Streams & Flink
Decorator (pattern)
LLD		Putting a coat on a toy, then a hat on top: it is still the same toy, with extras.A structural pattern that wraps an object in another object with the same interface to add behaviour (logging, caching, compression), stackable at runtime without subclassing. From your world: Stacking a tracing or compression layer that forwards to the real ops.Decorator
Denormalization
HLD		Writing your friend's name on every party invite instead of a number you must look up.Storing the same data in more than one place (copying fields into the rows that read them) so reads need no joins. Speeds reads, costs extra writes and the risk of copies disagreeing.Data Modeling, Indexing & Storage Engines
Dependency injection (DI)
LLD must know		The teacher hands you the crayons you need instead of you running to the shop.Objects receive their collaborators (usually as interfaces) through the constructor instead of creating them. Makes code testable (pass a fake) and lets wiring happen in one place. A DI container automates it (inversion of control). From your world: Passing an ops table to a module's init() instead of hard-coding the driver.Dependency Injection & Inversion of Control
Deployment
Kubernetes must know		The plan "always keep three of these running, and swap them gently for new ones when I say so".A Kubernetes object that manages ReplicaSets for stateless pods. You declare the image and replica count; it performs rolling updates (controlled by maxSurge and maxUnavailable) and keeps revision history for rollback. From your world: In-service software upgrade (ISSU), card by card.Deployments, ReplicaSets & Rollouts
Desired state (declarative)
Kubernetes		You show a photo of the tidy room, and helpers keep tidying until the room matches it.You describe what you want (YAML: "3 replicas of image X"), not the steps to get there. Controllers keep comparing the actual state to it and correcting differences, forever. The opposite of imperative scripts. From your world: Intended configuration vs operational state, reconciled by daemons.Why Kubernetes?
DIP (Dependency Inversion Principle)
LLD		The lamp needs a socket, not a particular power station.The D in SOLID: high-level policy and low-level details both depend on abstractions; the abstraction is owned by the high-level side. From your world: The block layer defines the ops; each driver implements them.Dependency Inversion Principle
Distributed lock
HLD		A single "talking stick": only the child holding it may speak.A lock that many machines respect, usually built on a consensus store (etcd, ZooKeeper) with leases. Must be paired with fencing tokens, because a paused holder may still think it owns an expired lock.Distributed Lock Service (Chubby / ZooKeeper)
Distributed trace
Kubernetes		Footprints showing everywhere one visitor walked in the building.The record of one request as it passes through many services, made of spans that share a trace id. OpenTelemetry is the standard; Jaeger and Tempo store and show traces. From your world: A packet trace across every hop of a path.Observability & Troubleshooting
Distroless image
Docker		A lunch box with only the sandwich, no extra toys.A minimal base image with just the app runtime and its libraries: no shell, no package manager. Smaller, with fewer CVEs and less for an attacker to use. Debug with kubectl debug or a debug variant.Production, Security & CI
DLQ (dead-letter queue / topic)
Pipeline must know		A box for letters that cannot be delivered, so they do not block the rest.A separate topic or queue where messages go after they fail processing a set number of times (a "poison" message). The main flow keeps moving; people inspect, fix and replay the dead letters later. From your world: The punt path / drop queue for packets the fast path cannot handle.Stream Processing, Retries & DLQ
DNS
HLD		The phone book of the internet: names in, numbers out.The Domain Name System maps names to IP addresses through a hierarchy of resolvers and authoritative servers, with caching controlled by TTLs. Often the first load-balancing and failover layer (GeoDNS, weighted records).Networking for HLD: DNS, Proxies, LBs & API Gateways
Docker Compose
Docker		A party plan that says which friends come, what each brings and who talks to whom.A tool that reads a compose.yaml describing several services, networks and volumes and starts them together on one host with docker compose up. Ideal for local development and labs; not a production orchestrator.Docker Compose
dockerd (Docker daemon)
Docker		The big helper who listens to your Docker commands and passes the work along.The Docker Engine daemon. The docker CLI talks to it over a Unix socket; it handles images, networks, volumes and builds, and asks containerd to run containers, which uses runc.Internals: Namespaces, cgroups, OverlayFS
Dockerfile
Docker must know		The recipe card for baking an image.A text file of instructions (FROM, RUN, COPY, CMD ...) that docker build turns into an image. Filesystem-changing instructions create layers; order affects caching.Writing a Dockerfile
Double-checked locking
LLD		Look in the box before getting the key; if empty, take the key and look again before filling it.Lazy initialisation that checks a field without the lock, then again inside it. In Java it is only correct if the field is volatile; the holder-class idiom or an enum singleton are simpler. From your world: The same memory-ordering trap as a lockless fast path without barriers.Thread-Safe Singleton & DCL
Downsampling (time series)
HLD		Keeping every minute's reading for today, but only one reading per hour for last year.Replacing old high-resolution time-series points with coarser rollups (min, max, average per 5 minutes or per hour) so storage stays bounded while long-range charts stay fast. Usually paired with a retention policy per resolution.IoT Telemetry & Heatmaps
DSA (data structures and algorithms)
Interview		The puzzle part of the interview: sort the blocks, find the shortest path, fit things in a box.The coding rounds: arrays, hash maps, trees, graphs, heaps, dynamic programming, solved in 30-45 minutes with correct code and a stated time and space complexity (Big-O). Most SDE-1 and SDE-2 loops have two or more DSA rounds, so design study never replaces daily DSA practice.8-Week Study Plan
Dual-write problem
Pipeline must know		Writing in two notebooks one after the other; if you trip after the first, they disagree forever.Writing to two systems (for example a database and Kafka) as separate steps with no shared transaction. A crash between the writes leaves them inconsistent. Fixed with the outbox pattern or CDC.Distributed Transactions & Event-Driven Data
Dunning
HLD		Politely reminding someone, again and again, that a payment did not go through.The retry-and-remind process after a failed recurring payment: retry on a schedule over several days, notify the customer, and pause or cancel the subscription after N failures. It must be idempotent so a retry never charges twice.Recurring Subscriptions
Durability
Kafka		Once you are told your note is saved, it is never lost, even if a computer breaks.The guarantee that acknowledged data survives failures. In Kafka it comes mostly from replication (RF=3, min.insync.replicas=2, acks=all), not from fsync on every write.Replication & ISR
