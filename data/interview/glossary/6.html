Cache
HLD must know		Keeping your favourite toy on the table instead of in the attic.A fast, smaller store (memory, often Redis or Memcached) that keeps copies of frequently read data so most reads skip the slower source. Measured by hit ratio. The hard parts are invalidation, stampedes and stale data. From your world: CPU cache, TLB and FIB cache: hit ratio, eviction (LRU), invalidation.Fundamentals: Scale, Cache, DB, CAP
Cache-aside (lazy loading)
HLD must know		Look on the table first; if the toy is not there, fetch it from the attic and leave it on the table.The most common caching pattern. The application reads the cache; on a miss it reads the database and fills the cache with a TTL. On a write it updates the database and deletes (or updates) the cache entry.Pattern: Scaling Reads (and Caching Pitfalls)
Canary release
Kubernetes		Letting one brave friend taste the new soup before serving it to everyone.Sending a small share of real traffic (say 1-5%) to the new version, watching error rate and latency, and only then increasing the share. Done with weighted routes (Gateway API, service mesh) or tools like Argo Rollouts. From your world: Like turning up a new path with a small ECMP weight before full cut-over.Deployments, ReplicaSets & Rollouts
CAP theorem
HLD must know		If the phone line between two shops breaks, each shop must either stop selling or risk selling the same last toy twice.During a network partition, a replicated system must choose between consistency (every read sees the latest write, or an error) and availability (every request gets a non-error answer). It is not "pick any two": partitions happen, so the real choice is C or A while partitioned. From your world: Split brain in an HA pair when the heartbeat link fails.Fundamentals: Scale, Cache, DB, CAP
CAS (compare-and-swap)
LLD must know		Swap the sticker only if it still shows the number you saw; otherwise look again and retry.An atomic CPU instruction: write a new value only if the memory still holds the expected old value, and report success. The basis of lock-free counters and queues (AtomicInteger, std::atomic). Watch for the ABA problem. From your world: Cmpxchg, exactly the primitive behind atomic_t and lock-free ring buffers.Concurrent Collections & Atomics (CAS)
CDC (change data capture)
Pipeline must know		A helper who reads the shop's sales book and shouts out every new line as it is written.Reading a database's own change log (MySQL binlog, Postgres WAL) and turning each insert, update and delete into an event, typically into Kafka with Debezium. Avoids the dual-write problem and needs no change in the application code. From your world: Like tapping a mirror port: you see every change without the application sending it twice.Kafka Connect, Streams & Flink
CDN (content delivery network)
HLD must know		Little copies of the library in every town so nobody travels far for a book.A network of edge servers in many locations that cache static content (images, video, JS) close to users. Requests reach the nearest edge via DNS or anycast; misses go back to the origin. From your world: Anycast plus caching at edge PoPs.Networking for HLD: DNS, Proxies, LBs & API Gateways
cgroup (control group)
Docker must know		A lunch-money limit, so one child cannot spend all the class's money.A kernel feature that limits and accounts CPU, memory, I/O and process count for a group of processes. Docker and the kubelet write files such as memory.max and cpu.max under /sys/fs/cgroup. Going over the memory limit triggers the OOM killer. From your world: Exactly the cgroup v2 you know; container limits are just cgroup files.Internals: Namespaces, cgroups, OverlayFS
Chain of Responsibility
LLD		A note passed down a row of desks until someone can answer it.A behavioural pattern: a request travels through a list of handlers; each one handles it, passes it on, or stops it. Used for middleware, validation pipelines and approval flows. From your world: Netfilter hooks: each hook returns ACCEPT, DROP or passes the packet to the next.Chain of Responsibility
Cherry-pick
CI/CD		Copying one recipe card from one book into another.git cherry-pick -x <sha> applies the change from one existing commit onto the current branch as a new commit; -x records the original hash in the message. The standard way to backport a fix from main to a release or hotfix branch. From your world: how stable kernel trees take fixes from mainline.Git for Teams: backports
CI / CD
Docker		Every time you change your drawing, a robot checks it and pins it on the wall.Continuous integration: every code change is built and tested automatically. Continuous delivery/deployment: every good build can be (or is) released automatically, typically by building an image, scanning it, pushing it to a registry and updating manifests.Production, Security & CI
CIDR block
Cloud		A house-number range written as "where it starts, and how many houses".Classless notation for an address range: 10.10.0.0/16 fixes the first 16 bits, so it holds 65,536 addresses. Plan non-overlapping blocks per VPC so peering, Transit Gateway and VPN routing keep working.AWS Networking: CIDR planning
Circuit breaker
HLD must know		If the toy shop is closed, stop walking there every minute; check again later.A wrapper around calls to a dependency. After too many failures it "opens" and fails fast for a while; then it lets a few test calls through ("half-open") and closes again if they succeed. Stops a slow dependency from tying up all your threads. From your world: Like BFD tearing down a path quickly instead of black-holing traffic.Microservices & Resilience Patterns
Class diagram
LLD must know		A map of all the toys, what each one has and which toys hold hands.The UML diagram LLD interviews expect: boxes for classes and interfaces with fields and methods, and lines for association, aggregation, composition, inheritance and dependency, with multiplicities. From your world: Like drawing your header file structs and which pointers link them.Class Diagrams
Cluster
Kubernetes		A team of computers that work together like one big computer.A group of machines managed as one. In Kubernetes: a control plane plus worker nodes. In Kafka: a set of brokers plus controllers. From your world: A chassis: supervisor cards plus line cards acting as one router.Why Kubernetes?
Cluster Autoscaler
Kubernetes		When there are no more chairs, it brings in a new table; when a table is empty, it takes it away.A Kubernetes add-on that adds nodes when pods are Pending because nothing fits, and removes underused nodes whose pods can move elsewhere. It works through cloud node groups. Karpenter is a newer alternative that creates right-sized nodes directly.Scheduling & Autoscaling
ClusterIP
Kubernetes must know		A pretend phone number that always rings whichever helper is free.The default Service type: a stable virtual IP reachable only inside the cluster. It is not on any interface; kube-proxy (or an eBPF data plane) programs every node to DNAT traffic for that IP to one of the ready pod IPs. From your world: A VIP that exists only as NAT rules, like a load-balancer VIP with nobody answering ARP for it.Services & Cluster Networking
CMAF (Common Media Application Format)
HLD		One lunch box shape that fits both kinds of bags.A fragmented-MP4 segment format that both HLS and DASH players can read, so a live stream is packaged once. Its small chunks are what make low-latency live streaming possible.Live Streaming
CNI (Container Network Interface)
Kubernetes		The electrician who plugs each new pod into the network.A spec plus plug-ins (Calico, Cilium, Flannel and others) that the container runtime calls when a pod sandbox is created or deleted. The plug-in creates the pod's interface, gives it an IP from the node's pod CIDR and sets up routes or an overlay. From your world: Plug-ins that create veth pairs, VXLAN tunnels or BGP routes for you.Services & Cluster Networking
CoderPad
Interview		A shared notebook you and the teacher both write in at the same time.An online collaborative code editor used for live coding interviews; it can run code in many languages, so interviewers may expect code that compiles and passes examples.Interview Hub
Cohesion
LLD		A pencil case that holds only pencils, not lunch.How closely the members of one module or class belong together. High cohesion (one job) makes code easier to change and test. It pairs with low coupling. From your world: A driver file that only does its device, not logging and config parsing too.Coupling & Cohesion
Collaborative filtering
HLD must know		Kids who liked the same games as you also liked this one.Recommending from the user-item interaction matrix alone, without item content. Memory-based CF compares users or items directly (often with cosine similarity); model-based CF learns latent factors, for example by matrix factorization.Recommendation Algorithms
Command (pattern)
LLD		Writing each wish on a card so it can be done later, done again, or torn up (undo).A behavioural pattern that turns a request into an object with execute() (and often undo()). Enables queues, logging, retries and undo/redo stacks. From your world: A work_struct queued to a workqueue: the action packed with its data.Command
Compensating transaction
HLD		Saying sorry and putting back the toy you took, because you cannot un-take it.A step that undoes the effect of an earlier, already-committed step in a saga: refund the payment, release the reserved stock. It is a new action, not a rollback, so it must itself be idempotent and retryable. From your world: Like withdrawing a route you advertised earlier rather than pretending you never sent it.Pattern: Multi-step Processes (Sagas & Workflows)
Composite (pattern)
LLD		A box of boxes: you can count the toys in a box the same way whether it holds toys or more boxes.A structural pattern that treats single objects and groups the same way through one interface, forming a tree (files and folders, UI widgets, org charts). From your world: The VFS treating a directory and a file through the same inode operations.Composite
Composition over inheritance
LLD must know		Build a robot from swappable parts instead of breeding a new robot kind for every feature.Prefer giving a class a field that does the job (has-a) over extending a class to reuse code (is-a). Behaviour can change at runtime and you avoid deep, fragile hierarchies. From your world: Embedding an ops pointer in a struct instead of copying a whole driver to change one function.Composition over Inheritance
Condition variable
LLD		A waiting bench: you sit until someone taps your shoulder and says 'your turn'.A primitive that lets a thread wait, with a lock released, until another thread signals that a condition may now be true. Always re-check the condition in a loop (spurious wake-ups). From your world: A kernel wait queue: wait_event() and wake_up().Locks, Conditions & Semaphores
ConfigMap
Kubernetes		A note of settings stuck to the fridge that every pod can read.A Kubernetes object holding non-secret key-value configuration, given to pods as environment variables or as files in a volume. Keeps configuration out of the image so one image works in every environment.ConfigMaps & Secrets
Configuration drift
Kubernetes		The toy room slowly gets messier than the photo, one toy at a time.When the real state of servers or clusters slowly stops matching what is written down, because of manual changes. GitOps and controllers fight drift by continuously re-applying the desired state. From your world: Running config vs startup config that nobody saved.StatefulSets, CRDs & Operators
Conflation
HLD		Telling your friend only the latest score every few seconds, not every single point.Sending only the newest value of a fast-changing item at a fixed interval (for example every 200-500 ms) instead of every update. It caps fan-out cost no matter how fast the source changes; used for live prices and auction bids.Stock Broker App
Connection pool
HLD		Keeping a few phone lines always open, instead of dialling every time.A set of already-open database or HTTP connections that requests borrow and return. Saves the cost of TCP and TLS handshakes and protects the database from too many connections.Choosing Storage: DB Types & Key Technologies
Consensus
HLD must know		A group of friends agreeing on one answer even if some of them fall asleep.Getting several nodes to agree on one value (or one ordered log) despite crashes and message delays. Raft and Paxos do it with a majority quorum, so 2f+1 nodes survive f failures. etcd, ZooKeeper and KRaft use it. From your world: A safer cousin of VRRP master election: decisions need a majority, so split brain cannot commit.Replication, Consensus & Coordination
Consistency model
HLD		The rule for how quickly everyone sees a change on the class board.A contract about what reads may return after writes: linearizable (strong), sequential, causal, read-your-writes, monotonic reads, eventual. Stronger models are easier to reason about but cost latency and availability.Replication, Consensus & Coordination
Consistent hashing
HLD must know		Children sit around a circle; each toy goes to the next child clockwise, so a new child only takes a few toys.Placing both nodes and keys on a hash ring and giving each key to the next node clockwise. Adding or removing a node moves only about 1/N of the keys. Virtual nodes smooth out the load. Used by Dynamo-style stores, caches and load balancers. From your world: Resilient hashing in ECMP: a member change only remaps that member's buckets.Distributed Building Blocks
Consumer
Kafka		A reader who comes to the post office and reads the letters in order.A client that reads records from Kafka partitions by pulling (polling) batches, processes them, and commits the offsets it has finished. Consumers keep their own position; reading does not delete anything. From your world: Polling (NAPI) instead of interrupts: consumers pull; brokers do not push.Consumers & Consumer Groups
Consumer group
Kafka must know		A team of readers sharing the piles of letters so each pile is read by exactly one team member.A set of consumers with the same group.id. Each partition is assigned to exactly one member, so the group splits the work; extra consumers beyond the partition count sit idle. Different groups each get all the data. From your world: Each group has its own read pointer into the same rings.Consumers & Consumer Groups
Consumer lag
Kafka must know		How many letters are waiting on the shelf that the reader has not read yet.Per partition: log end offset minus the group's committed offset. Growing lag means consumers are slower than producers. The key metric for pipelines and for autoscaling consumers (KEDA). From your world: Queue depth / buffer occupancy: depth growing means drain slower than fill.Consumers & Consumer Groups
Container
Docker must know		A lunch box for a program: everything it needs is packed inside, so it works the same anywhere.A normal Linux process (or group of processes) that the kernel isolates with namespaces (what it can see) and limits with cgroups (what it can use), running on a root filesystem unpacked from an image. It shares the host kernel; there is no guest OS. From your world: A process with clone flags plus a cgroup, nothing more magical.What is a Container?
Container orchestration
Kubernetes		A conductor who tells every musician when to play, so the whole band sounds right.Automating the placement, networking, scaling, healing and updating of containers across many machines. Kubernetes is the dominant orchestrator; ECS and Nomad are others.Why Kubernetes?
containerd
Docker		The stage manager who gets images ready and tells the stagehand to start the show.A container runtime daemon that pulls images, manages snapshots (layers) and runs containers through a per-container shim that calls runc. Docker Engine uses it underneath, and kubelet talks to it directly through CRI.Internals: Namespaces, cgroups, OverlayFS
Continuous delivery / deployment (CD)
Docker		Every good drawing goes straight up on the fridge without waiting for the weekend.Continuous delivery: every change that passes the pipeline is ready to release with one click. Continuous deployment: it is released automatically. Usually paired with CI.CI/CD Platform on Kubernetes
Control plane (Kubernetes)
Kubernetes must know		The head office that makes plans; the shops (nodes) do the actual selling.The components that decide and record what should run: kube-apiserver, etcd, kube-scheduler, kube-controller-manager (and cloud-controller-manager). If it goes down, running pods keep running, but nothing new is scheduled or healed. From your world: Router control plane (route processor) vs line cards; pods keep forwarding like non-stop forwarding.Architecture: Control Plane & Nodes
Control record (transaction marker)
Kafka		A little "the end" card slipped between letters to say a set of letters is complete.A special record a broker writes into a partition to mark that a transaction committed or aborted. It takes up an offset but is never handed to your application, which is why offsets in a transactional topic have gaps.Delivery Semantics & Exactly-Once
Controller (Kafka, KRaft)
Kafka		The head post-master who decides which post office is in charge of each shelf.In Kafka 4.x, a node with process.roles=controller. A Raft quorum of controllers stores cluster metadata in the __cluster_metadata log; the active controller chooses partition leaders and tracks broker liveness.KRaft, Controllers & Cluster Metadata
Controller (Kubernetes)
Kubernetes		A helper who keeps checking "is the room how it should be?" and fixes it when it is not.A control loop that watches objects through the API server, compares desired state (spec) with actual state (status) and acts to close the gap, for example the ReplicaSet controller creating missing pods. Many run inside kube-controller-manager. From your world: A routing daemon reconciling the RIB into the FIB, forever.Architecture: Control Plane & Nodes
Copy-on-write
Docker		Everyone reads the same picture book; if you want to draw in it, you get your own photocopy of that page first.Sharing read-only data until someone writes; only then is a private copy made. Image layers are shared by every container, and a file is copied up into the container's writable layer the first time it is changed. From your world: The same trick as fork() page sharing in the kernel.Images & Layers
CoreDNS
Kubernetes		The class phone book that turns names like "orders" into phone numbers.The DNS server inside Kubernetes. It answers names like orders.shop.svc.cluster.local with the Service's ClusterIP (or pod IPs for a headless Service).Services & Cluster Networking
CORS (cross-origin resource sharing)
HLD		A rule that a page from one shop may only ask another shop for things if that shop says it is allowed.The browser rule that a page served from site A may only call site B from JavaScript if B's response headers allow A. Needed when browsers upload straight to a storage bucket; for multipart uploads the bucket must also expose the ETag header. From your world: Like an ACL on the far end that lists which sources may talk to it.Pattern: Handling Large Blobs
Count-min sketch
HLD		A small tally board that guesses how many times each word was said, maybe a little too high, never too low.A probabilistic structure (a small 2-D array of counters with several hash functions) that estimates item frequencies in a stream using fixed memory. It can over-count but never under-counts. Used for trending topics and heavy hitters.Big Data: Batch, Streaming & Probabilistic Structures
Coupling
LLD		How many strings tie two puppets together: cut one and see how much the other moves.How much one module depends on another's details. Low coupling (depend on small interfaces) lets you change one side without breaking the other. From your world: Calling through an ops table instead of a driver's static functions.Coupling & Cohesion
CPU throttling
Kubernetes		Being told to sit still for the rest of the minute because you used your share.When a container uses its CPU limit within a CFS period (100 ms by default), the kernel stops it until the next period. Shows up as latency spikes without high average CPU. From your world: cgroup cpu.max quota, visible in cpu.stat nr_throttled.Scheduling & Autoscaling
CQRS
HLD		One window for giving the shop orders and another window for asking what is in stock.Command Query Responsibility Segregation: separate write models from read models. Writes go to one store; events update one or more read-optimised views (search index, cache, denormalised tables). The views are eventually consistent.Distributed Transactions & Event-Driven Data
CrashLoopBackOff
Kubernetes must know		The toy keeps falling over, so the grown-up waits longer and longer before standing it up again.A pod status meaning a container keeps exiting and the kubelet is restarting it with growing delays (up to 5 minutes). Look at kubectl logs --previous and kubectl describe pod for the exit code and reason. From your world: A process respawning under a watchdog with an exponential hold-down.Observability & Troubleshooting
CRD (CustomResourceDefinition)
Kubernetes		Teaching the class notebook a brand-new kind of page.A way to add your own object types (like Kafka or KafkaTopic from Strimzi) to the Kubernetes API. The API server stores and serves them like built-in objects; an operator gives them behaviour.StatefulSets, CRDs & Operators
CRDT
HLD		Sticky notes that can be added in any order and still end up the same on everybody's board.Conflict-free replicated data type: a data structure whose concurrent updates can be merged in any order and always converge to the same state, without a central server. Used in collaborative editors and multi-leader stores.Collaborative Editor (Google Docs)
CRI (Container Runtime Interface)
Kubernetes		The plug shape that lets Kubernetes work with different kinds of container engines.The gRPC API the kubelet uses to ask a runtime (containerd, CRI-O) to pull images and run pod sandboxes and containers. Since Kubernetes 1.24 dockershim is gone, so nodes use a CRI runtime directly; Docker-built images still run.Architecture: Control Plane & Nodes
CronJob
Kubernetes		An alarm clock that starts a chore every day at the same time.A Kubernetes object that creates a Job on a cron schedule, such as nightly reports or clean-ups. Has settings for missed runs and whether runs may overlap. From your world: cron, but the work runs as pods anywhere in the cluster.Deployments, ReplicaSets & Rollouts
