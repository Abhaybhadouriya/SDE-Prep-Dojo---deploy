WAF (web application firewall)
HLD must know		A guard who reads every letter at the door and throws out the ones with dangerous words.A layer-7 rule engine in front of an app (AWS WAF, Cloudflare, Akamai): ordered rules match on IP, headers, path, body and request rate, and each rule can allow, block, count or challenge. Managed rule groups cover common OWASP attacks and known bots.Edge Defense & Bots
Watch (Kubernetes API)
Kubernetes		Instead of asking "anything new?" every second, you ask once and get told whenever something changes.A long-lived API request that streams every change to a set of objects from a resource version. Controllers, the scheduler and kubelets use watches (through informers with local caches) instead of polling. From your world: Like a subscription to route updates instead of polling the table.Architecture: Control Plane & Nodes
Watermark (event time)
Pipeline		A sign that says "I think every photo taken before 10 o'clock has arrived now".A stream processor's estimate that no more events older than time T will arrive, used to decide when a window is complete. Late events after the watermark are dropped, sent aside or used to update results.Stream Processing, Retries & DLQ
Webhook
HLD		"Call me when the parcel arrives" instead of you checking the door all day.An HTTP callback: one system calls a URL you registered when an event happens (payment succeeded, git push). Receivers must verify signatures and be idempotent because senders retry.API Design & Client-Server Communication
WebSocket
HLD		A phone call that stays open so both sides can talk whenever they want.A protocol that upgrades an HTTP connection to a long-lived, two-way channel. Used for chat, live updates and games. Needs sticky connections and connection-aware scaling. From your world: A persistent TCP session instead of request-response.Pattern: Real-time Updates
Wide-column store (Cassandra, HBase, Bigtable)
HLD		A giant set of drawers: you find the right drawer by its name, then the papers inside are already in order.A NoSQL database where each row is found by a partition key and holds many columns, sorted inside the partition by a clustering key (for example, all messages of one chat sorted by time). Writes are cheap (an LSM tree), reads are fast only for the access pattern the key was designed for, so you model tables from your queries. Cassandra, ScyllaDB, HBase and Google Bigtable are the usual examples.Choosing Storage: DB Types & Key Technologies
Window (tumbling, sliding, session)
Pipeline		Counting cars in each 5-minute box of the clock.Grouping an endless stream into finite buckets of time. Tumbling: fixed, non-overlapping (every 5 minutes). Sliding/hopping: overlapping (5-minute windows every minute). Session: closes after a gap of inactivity.Stream Processing, Retries & DLQ
Write-ahead log (WAL)
HLD		Writing what you are about to do in a diary before you do it, so you can finish after a fall.A database first appends every change to a sequential log on disk, then updates its data files. After a crash it replays the log. CDC tools read this log to stream changes. From your world: A journaling filesystem's journal.Data Modeling, Indexing & Storage Engines
Write-through / write-back cache
HLD		Write-through: write in the notebook and on the board together. Write-back: write on the board now, the notebook later.Write-through updates the cache and the database on every write (consistent, slower writes). Write-back (write-behind) updates the cache and flushes to the database later (fast, risks loss). Write-around skips the cache on writes. From your world: The same policies as CPU caches.Pattern: Scaling Reads (and Caching Pitfalls)
