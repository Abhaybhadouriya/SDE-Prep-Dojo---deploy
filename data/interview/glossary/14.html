Kafka Connect
Pipeline		Ready-made pipes that pour data into the belt and out to other places.A framework and runtime for moving data between Kafka and other systems using source and sink connectors (JDBC, Debezium, S3, Elasticsearch) configured by JSON, with offsets and scaling handled for you.Kafka Connect, Streams & Flink
Kafka Streams
Pipeline		A small counting machine you put inside your own program that reads from the belt and writes back.A Java library (not a cluster) for stream processing that reads from and writes to Kafka, with local state stores backed by changelog topics, windows and exactly-once support.Kafka Connect, Streams & Flink

Karpenter

An alternative to Cluster Autoscaler.Scheduling & Autoscaling
KEDA
Kubernetes		A helper who adds more readers when the pile of unread letters grows, even from zero.Kubernetes Event-Driven Autoscaling. It feeds external metrics such as Kafka consumer lag or queue length into the HPA and can scale a workload to zero and back. From your world: Scaling on queue depth instead of CPU.Scheduling & Autoscaling
Key (Kafka record key)
Kafka must know		The name written on the letter that decides which pile it goes in.An optional field on every record. Records with the same key go to the same partition (so they stay in order) and compaction keeps the latest value per key. Pick keys that spread load evenly. From your world: The flow 5-tuple of a record.Core Concepts: Topics, Partitions, Offsets
kind (Kubernetes in Docker)

KIP (Kafka Improvement Proposal)
Kafka		A written idea for making Kafka better, with a number.A numbered design document for a Kafka change, like an RFC. For example KIP-500 (KRaft), KIP-848 (new consumer rebalance protocol) and KIP-932 (queues / share groups). From your world: An IETF RFC for Kafka.KRaft, Controllers & Cluster Metadata
KRaft
Kafka		Kafka keeps its own notebook of who is in charge, instead of borrowing a separate notebook.Kafka's built-in Raft-based metadata quorum that replaced ZooKeeper. Controllers store metadata in the __cluster_metadata log; brokers fetch it. Kafka 4.0 removed ZooKeeper entirely.KRaft, Controllers & Cluster Metadata
ksqlDB
Pipeline		Asking questions about the moving belt using sentences like a database.A streaming SQL engine from Confluent built on Kafka Streams. You write SQL to filter, join and aggregate topics into new topics or materialised tables.Kafka Connect, Streams & Flink
kube-controller-manager
Kubernetes		The building where all the room-tidying helpers live.A control-plane binary that runs many built-in controllers (Deployment, ReplicaSet, Node, Job, EndpointSlice, ServiceAccount ...). Only one instance is active at a time, chosen by a leader-election lease.Architecture: Control Plane & Nodes
kubectl
Kubernetes		The walkie-talkie you use to talk to the head teacher.The Kubernetes command-line client. It reads your kubeconfig and sends REST calls to the API server, for example kubectl apply -f app.yaml, kubectl get pods and kubectl logs. From your world: The CLI to the management plane.Architecture: Control Plane & Nodes
kubelet
Kubernetes must know		The teacher's helper in each classroom who makes sure the right lunch boxes are open and healthy.The agent on every node. It watches the API server for pods bound to its node, asks the container runtime (via CRI) to run them, runs probes, mounts volumes and reports status back. From your world: The line-card agent that programs local hardware from the control plane's instructions.Architecture: Control Plane & Nodes
kube-proxy
Kubernetes must know		A helper on every street who rewrites addresses so letters for "orders" go to a real house.A node agent that watches Services and EndpointSlices and programs the node's packet rules (iptables, nftables, or IPVS) so traffic to a ClusterIP or NodePort is DNATed to a ready pod. Some CNIs (Cilium) replace it with eBPF. From your world: Pushing NAT tables to every line card.Services & Cluster Networking
Kubernetes (K8s)
Kubernetes		A head teacher who decides which classroom every lunch box goes to and replaces any that break.An open-source container orchestrator. You declare the desired state (what should run, how many, how it is reached), and its control plane schedules pods onto nodes and keeps reconciling: restarting, rescheduling, scaling and rolling out new versions. From your world: A distributed control plane programming many "line cards" (nodes).Why Kubernetes?
kube-scheduler
Kubernetes must know		The seating helper who picks the best table for each new child.The control-plane component that assigns each Pending pod to a node. It filters nodes that cannot fit (resources, taints, affinity), scores the rest, then binds the pod to the winner by writing spec.nodeName through the API server. From your world: Admission control plus placement, like assigning a flow to a line card with capacity.Scheduling & Autoscaling
