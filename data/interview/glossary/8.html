ECS (Elastic Container Service)
Docker		Amazon's own team manager for running lunch boxes.Amazon's container orchestrator, a simpler alternative to Kubernetes inside AWS. It runs tasks on EC2 or on Fargate (serverless). EKS is AWS's managed Kubernetes.Production, Security & CI
Elastic IP
Cloud		A phone number you own and can move to a new phone.A static public IPv4 address allocated to your account that you can attach to an instance, a NAT gateway or a network load balancer, and move later. Since February 2024 every public IPv4 address, attached or not, is billed by the hour.AWS Networking: subnets
Elasticsearch / OpenSearch
HLD		A super librarian who can find every book that mentions a word.Distributed search engines built on Lucene inverted indexes. Data is split into shards with replicas; they support full-text search, filters and aggregations. Common sinks for logs and product search.Geospatial, Text & Prefix Indexes
Encapsulation
LLD must know		A toy with a battery door that only opens with a screwdriver, so nobody breaks the wiring.Keeping an object's state private and changing it only through methods that keep its rules (invariants) true. Different from abstraction, which is about hiding complexity behind a simpler interface. From your world: An opaque struct handle with accessor functions instead of a public struct.Encapsulation, Abstraction & Access Modifiers
EndpointSlice
Kubernetes		The up-to-date list of which helpers are ready to answer the pretend phone number.The object listing the ready pod IPs and ports behind a Service, kept current by the EndpointSlice controller using the pod readiness. kube-proxy watches them to program the node's rules. Slices hold up to 100 endpoints by default. From your world: The next-hop list behind a VIP.Services & Cluster Networking
ENTRYPOINT and CMD
Docker		ENTRYPOINT is the game; CMD is the default level you start on.ENTRYPOINT sets the executable a container runs; CMD gives default arguments (or the whole command if there is no ENTRYPOINT). Use the exec (JSON array) form so your process is PID 1 and receives signals.Writing a Dockerfile
Envoy
Kubernetes		A smart traffic officer who stands at doors and directs every car.A high-performance L4/L7 proxy configured through APIs. It is the data plane of many service meshes (Istio) and Gateway API implementations; it does load balancing, retries, mTLS and metrics.Ingress & Gateway API
EOS (exactly-once semantics)
Kafka must know		Every letter counts exactly one time, even if the postman trips and has to try again.Kafka's guarantee that a read-process-write flow inside Kafka has each input's effect appear once, using idempotent producers plus transactions and read_committed consumers. It does not cover side effects outside Kafka (emails, payments); those need idempotency keys.Delivery Semantics & Exactly-Once
Ephemeral container (kubectl debug)
Kubernetes		Sending a doctor into the room for a moment without stopping the game.A temporary container added to a running pod for troubleshooting with kubectl debug. It shares the pod's namespaces, so you get tools (shell, curl, tcpdump) even when the app image is distroless. From your world: nsenter into a running process's namespaces.Observability & Troubleshooting
Escalation policy
SRE		If the first grown-up does not answer, ring the next one.The ordered rule in a paging tool (PagerDuty, Opsgenie, incident.io) for who is notified when a page is not acknowledged in time: primary, then secondary, then a manager or the owning team.On-Call & Postmortems
etcd
Kubernetes must know		The class notebook where every decision is written down, kept by a few friends who must agree.A strongly consistent, Raft-replicated key-value store that holds all Kubernetes objects. Usually 3 or 5 members; it keeps working while a majority is up. Lose quorum and the cluster can no longer change, though running pods keep running. From your world: The replicated config database / RIB, with Raft instead of VRRP-style election.Architecture: Control Plane & Nodes
Event
Kafka		A note saying something happened, like "Sam bought a kite at 10 o'clock".A small immutable record of a fact in the past tense, such as "order 7 was created at 10:02". Usually has a key, a value, a timestamp and headers. Events flow through topics.Why Messaging? (Sync vs Async)
Event sourcing
HLD		Keeping every coin you ever put in or took out, instead of just the total.Storing the full sequence of state-changing events as the source of truth and rebuilding current state by replaying them (with snapshots). Gives a complete audit trail and easy new views, at the cost of more complex reads and schema evolution. From your world: Like a replayable transaction log rather than a status register.Distributed Transactions & Event-Driven Data
Event time vs processing time
Pipeline		When the photo was taken vs when you looked at it.Event time is when the thing happened (stamped at the source). Processing time is when your system sees it. Networks and retries make them differ, so correct windows use event time plus watermarks. From your world: Packet capture timestamp vs the time your analyser read it.Stream Processing, Retries & DLQ
Event-driven architecture
HLD		Instead of phoning everyone, you ring a bell and whoever cares comes running.Services communicate by publishing events to a broker and reacting to events from others, instead of calling each other directly. Gives loose coupling and buffering, at the cost of eventual consistency and harder tracing. From your world: Interrupt-driven design across services.Why Messaging? (Sync vs Async)
Eventual consistency
HLD must know		The news reaches every classroom, just not at the same second.If writes stop, all replicas will eventually return the same value, but for a while some reads may return older data. Cheap and highly available; the application must tolerate stale reads. From your world: Async route propagation: everyone converges, but not instantly.Fundamentals: Scale, Cache, DB, CAP
Eviction (pod)
Kubernetes		Asking a child to leave the crowded table so the table does not break.The kubelet removing pods from a node under resource pressure (memory, disk, PIDs), lowest QoS first; or the API removing pods to drain a node, respecting PodDisruptionBudgets. Also pods are evicted from a dead node after a timeout.Scheduling & Autoscaling
Exit code 137 / 143
Docker must know		The secret number a program leaves behind to say how it stopped.Codes above 128 mean "killed by signal (code - 128)". 137 = SIGKILL (9), often the OOM killer when a container passed its memory limit (Kubernetes shows OOMKilled). 143 = SIGTERM (15), a normal stop request. From your world: Plain POSIX wait-status decoding.Running & Managing Containers
Expand-migrate-contract
CI/CD		Adding the new road before closing the old one, so traffic never stops.A zero-downtime schema change done in three releases: expand (add the new column or table, write to both), migrate (backfill old rows, switch reads), contract (drop the old column once no running version uses it). Every step is safe to roll back because old and new code both work against the schema.Zero-Downtime Releases
