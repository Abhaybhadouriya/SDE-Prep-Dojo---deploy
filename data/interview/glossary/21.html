Race condition
LLD must know		Two kids grab the last cookie at the same time and both think they got it.The result depends on the timing of threads touching shared state, typically check-then-act or read-modify-write without a lock or atomic. From your world: The classic unlocked counter++ in an interrupt and a process context.Thread Safety Basics
Rack awareness (broker.rack)
Kafka		Never keep all three copies of your homework in the same backpack.Tell each Kafka broker which rack or availability zone it lives in with broker.rack, and Kafka spreads a partition's replicas across racks, so losing one rack or zone does not lose every copy. Consumers can also set client.rack to fetch from the nearest replica (KIP-392) and save cross-zone traffic cost. From your world: Putting the two members of a redundancy pair in different chassis or sites.Operations, Tuning & Kafka on K8s
Raft
HLD		The class votes for a captain; the captain writes every rule in a book and the class copies it.A consensus algorithm: nodes elect a leader for a numbered term; the leader appends entries to its log and replicates them; an entry is committed once a majority stores it. Used by etcd, Consul and Kafka KRaft. From your world: Leader election plus replicated log, with majority commit to prevent split brain.Replication, Consensus & Coordination
RAG (retrieval-augmented generation)
HLD		Letting the robot read the right book pages before it answers you.Fetching relevant documents (often by vector similarity search) and putting them in an LLM's prompt so answers use fresh or private data and can cite sources.AI/LLM System Building Blocks
RAII
LLD		A library book that returns itself when you walk out the door.Resource Acquisition Is Initialisation (C++): a resource is owned by an object whose destructor releases it, so cleanup happens on every exit path, exceptions included (lock_guard, unique_ptr). Java uses try-with-resources. From your world: The goto-cleanup ladder, made automatic by the compiler.Constructors, Destructors & Copy Semantics
Rate limiter (token bucket)
HLD must know		Each child gets a few tokens; each turn on the slide costs a token, and tokens slowly refill.Limits how many requests a client may make per time window. Token bucket allows bursts up to the bucket size and refills at a fixed rate; leaky bucket smooths output; sliding windows count recent requests. Distributed versions keep counters in Redis. From your world: A token bucket policer / shaper in QoS: the same algorithm.Distributed Rate Limiter
RBAC (role-based access control)
Kubernetes		A list saying which children may use which toys.Kubernetes authorization: a Role or ClusterRole lists allowed verbs (get, list, create ...) on resources; a RoleBinding or ClusterRoleBinding gives it to users, groups or service accounts. Everything not allowed is denied. From your world: AAA command authorization by privilege level.Security & RBAC
Read replica
HLD		Copies of the notice board in other rooms, for reading only.A copy of a database that follows the primary (usually asynchronously) and serves reads. Scales reads; may return slightly stale data (replication lag), so read-your-own-writes needs care. From your world: An async mirror that may lag.Fundamentals: Scale, Cache, DB, CAP
read_committed
Kafka		Only read stories that are finished, not ones still being written.A consumer setting (isolation.level=read_committed) that only returns records from committed transactions and stops at the LSO. The default read_uncommitted returns everything.Delivery Semantics & Exactly-Once
Rebalance
Kafka must know		Re-sharing the piles of letters when a team member joins or leaves.Reassigning partitions among the members of a consumer group after a member joins, leaves, crashes or times out, or partitions change. The old eager protocol paused everyone; cooperative and the new KIP-848 protocol move only what must move. From your world: Re-hashing ECMP buckets when a member joins or leaves.Consumers & Consumer Groups
Rebase
CI/CD must know		Lifting your stack of cards and putting it back on top of the newest pile.git rebase main replays each of your branch commits as a patch on top of the current main, giving them new hashes and a straight history. Never rebase commits others have built on; push the result with --force-with-lease --force-if-includes. From your world: git format-patch + git am onto a new base.Git for Teams
Reconciliation loop
Kubernetes must know		Look, compare with the photo, fix one thing, and look again, forever.The core Kubernetes pattern: a controller watches desired state and actual state and repeatedly takes actions to make them match. It is level-based, so a missed event is fixed on the next pass. From your world: A routing daemon continuously pushing RIB state into the FIB.Architecture: Control Plane & Nodes
Redis
HLD		A super-fast memory notebook everyone can share.An in-memory data store with rich types (strings, hashes, lists, sets, sorted sets, streams). Used for caches, rate limiters, leaderboards, sessions and locks. Can persist and replicate; Redis Cluster shards across 16,384 hash slots.Distributed Cache (Redis-like)
Registry
Docker		A library shelf where images are stored and borrowed.A server that stores and serves images over the OCI distribution HTTP API: Docker Hub, GitHub Container Registry, Amazon ECR, Azure ACR, Harbor. Layers are fetched by digest, so identical layers are shared. From your world: A TFTP/HTTP image server for line-card firmware, content-addressed by SHA-256.Images & Layers
ReplicaSet
Kubernetes		The helper who counts the pods and adds or removes some until the count is right.A controller object that keeps a set number of identical pods (matched by a label selector) running. You rarely create one directly; a Deployment creates a new ReplicaSet for each version.Deployments, ReplicaSets & Rollouts
Replication factor
Kafka must know		How many friends keep a copy of each pile of letters.How many brokers hold a copy of each partition. RF=3 is the common production choice; the broker default is 1, which is not durable.Replication & ISR
Replication (leader-follower, multi-leader, leaderless)
HLD must know		Keeping copies of the class notebook with several friends in case one is lost.Keeping copies of data on several nodes. Leader-follower: one node takes writes. Multi-leader: several take writes and resolve conflicts. Leaderless: clients write to several replicas with quorums. Synchronous copies are safe but slow; asynchronous ones can lose recent writes.Replication, Consensus & Coordination
Repository (pattern)
LLD		A librarian: you ask for 'books by this author' and do not care which shelf they sit on.A collection-like interface (save, findById) that hides how entities are stored, so services can use an in-memory map in a machine-coding round and a database later. From your world: A lookup table API that hides whether it is a hash or a radix tree.Repository & Service Layer
Requests and limits
Kubernetes must know		A request is the seat you book; a limit is the most you are allowed to take.Per-container resources. Requests are what the scheduler reserves when placing the pod. Limits are the cap enforced by cgroups: over the CPU limit you are throttled; over the memory limit you are OOMKilled. From your world: cgroup cpu.weight (requests) and cpu.max / memory.max (limits).Scheduling & Autoscaling
ResourceQuota and LimitRange
Kubernetes		The pocket-money limit for a whole team, not just one child.ResourceQuota caps total CPU, memory, storage and object counts per namespace. LimitRange sets default and maximum requests and limits for each container in a namespace.Security & RBAC
REST API
HLD		Asking for things by their address and a simple verb, like "GET the menu" or "POST an order".An HTTP API style built around resources identified by URLs and standard methods (GET, POST, PUT, PATCH, DELETE) with status codes. Stateless requests make it easy to cache and load-balance.API Design & Client-Server Communication
Restart policy
Docker		What to do when a toy falls over: leave it, or stand it back up.Docker: no, on-failure[:N], always, unless-stopped. Kubernetes pods: Always (default), OnFailure, Never; the kubelet restarts containers with an exponential back-off.Running & Managing Containers
Retention
Kafka		How long old letters stay on the shelf before they are thrown away.Kafka deletes old data by time (retention.ms, 7 days by default) or size (retention.bytes per partition), whole segments at a time. Reading does not delete anything, so consumers can replay within the retention window. From your world: Unlike a ring buffer, nothing is overwritten early; old segments age out.Storage Internals & Performance Secrets
Retry topic
Pipeline		A "try again later" box, so one stuck letter does not hold up the line.A separate topic where a failed message is sent to be retried after a delay, so the main partition keeps moving. After several retry stages it goes to the DLQ.Stream Processing, Retries & DLQ
Reverse proxy
HLD		A receptionist who takes every visitor's question and asks the right person in the back.A server in front of backends that accepts client connections and forwards requests to them (NGINX, Envoy, HAProxy). Adds TLS termination, caching, compression, routing and load balancing. From your world: An inline middlebox that terminates and re-originates sessions.Networking for HLD: DNS, Proxies, LBs & API Gateways
Rollback
Kubernetes		Putting the old toy back when the new one turns out broken.Returning to the previous version. kubectl rollout undo deployment/web scales the previous ReplicaSet back up. Database schema changes must stay backward compatible for rollbacks to be safe. From your world: Booting the previous software image.Deployments, ReplicaSets & Rollouts
Rolling update
Kubernetes must know		Swapping old players for new ones a few at a time, so the game never stops.A Deployment replaces old pods gradually: it creates new ones (up to maxSurge extra) and removes old ones (up to maxUnavailable missing), waiting for readiness at each step. Zero downtime if probes and graceful shutdown are right. From your world: In-service software upgrade, card by card.Deployments, ReplicaSets & Rollouts
Rootless containers
Docker		Letting the children play without giving them the head teacher's keys.Running the container engine and containers as an unprivileged user (with user namespaces), so an escape lands as a normal user, not root on the host.Production, Security & CI
Route table (AWS)
Cloud		The signpost at each crossroad that says which road leads where.A set of rules attached to subnets in a VPC that picks the next hop for each destination CIDR: local inside the VPC, an Internet Gateway for public subnets, a NAT gateway for private ones, or a peering, transit gateway or VPC endpoint. The most specific matching prefix wins.AWS Networking
RPO and RTO
HLD		RPO: how much homework you could lose. RTO: how long until you can work again.Recovery Point Objective is the maximum data loss you accept after a disaster (measured in time). Recovery Time Objective is the maximum time to restore service. Together they drive backup and replication choices.Reliability at Scale: SLOs, Multi-Region & DR
runc

Given a bundle (config.json plus a root filesystem), it creates namespaces and cgroups, sets up mounts and capabilities, then execs the container's process and exits. From your world: The bit that calls clone, pivot_root and exec.Internals: Namespaces, cgroups, OverlayFS
