Backoff (exponential, jitter)
HLD		If knocking does not work, wait a little, then a bit longer, then longer still.Waiting longer after each failed try (for example 2 s, 4 s, 8 s). Jitter picks a random wait up to that limit so that many clients do not retry at the same moment and knock the server over again. From your world: The same idea as Ethernet CSMA/CD backoff or TCP retransmit timers.Microservices & Resilience Patterns
Backpressure
HLD must know		When the slide is full, the line stops at the ladder until there is room.A way for a slow receiver to make the sender slow down, instead of being flooded. In Kafka it is natural: consumers pull, so a slow consumer just builds lag; a full producer buffer makes send() block. From your world: TCP flow control: the receive window shrinks and the sender waits. PFC pause frames.Stream Processing, Retries & DLQ

Batching (batch.size, linger.ms)
Kafka		Waiting a moment so you can carry many letters to the post box in one trip.The producer groups records per partition into batches and sends a batch when it reaches batch.size (16 KiB default) or after linger.ms (5 ms default since Kafka 4.0), whichever comes first. Bigger batches mean higher throughput and better compression, at a small latency cost. From your world: Interrupt coalescing / NAPI budget: trade a little latency for a lot of throughput.Producers

Bridge network (docker0)
Docker		A little switch inside your computer that the containers plug into.Docker's default network driver. Each container gets a veth pair: one end inside its network namespace as eth0, the other plugged into a Linux bridge (docker0 or a user-defined bridge). Outbound traffic is masqueraded; inbound needs -p. User-defined bridges also give DNS by container name. From your world: It is a normal Linux bridge: a software L2 switch with veth ports.Docker Networking

A cluster is several brokers; in Kafka 4.x the metadata is managed by KRaft controllers.Core Concepts: Topics, Partitions, Offsets
B-tree / B+ tree
HLD		A library with signposts on every floor so you can find any book in a few steps.A balanced tree with very wide nodes sized to disk pages, used by most relational database indexes. Lookups, range scans and updates take O(log n) page reads; updates happen in place. From your world: Like a multi-level page table: a few hops reach any entry.Data Modeling, Indexing & Storage Engines

Build cache
Docker		Remembering the steps you already did, so you only redo the ones that changed.BuildKit reuses a layer when the instruction and its inputs (for COPY, the file checksums) are unchanged. Once one step changes, every step after it is rebuilt, so put rarely-changing steps (installing dependencies) before often-changing ones (copying source). From your world: Like incremental make: change one input and only dependent targets rebuild, in order.Writing a Dockerfile
