You might confuse these

These pairs trip up nearly everyone. Interviewers sometimes use them on purpose to see if you notice.

Thisis notThe difference in one line
Linux namespaceKubernetes namespaceA kernel isolation feature vs a name tag for grouping API objects.
High watermarkEvent-time watermarkHow far every in-sync replica has copied vs how far a stream processor thinks event time has moved.
Kafka partitionNetwork partition (CAP)An ordered log that splits a topic vs a broken link that splits a cluster.
PartitionReplicaPartitions split data for parallelism; replicas copy the same partition for safety.
Kafka controllerKubernetes controllerThe node that manages Kafka metadata and leaders vs any control loop that reconciles Kubernetes objects.
ServiceDeploymentHow you reach pods (stable IP and name) vs how you run and update pods.
ImageContainerThe frozen read-only template vs a running process made from it.
VolumeBind mountStorage Docker manages vs any host path you mount in.
At-least-onceExactly-onceDuplicates are possible and you make them harmless vs Kafka's transactions make the effect appear once (inside Kafka only).
Message queueKafka logA message is deleted once one consumer takes it vs records stay for the retention period and every group reads them all.
LivenessReadinessFailing liveness restarts the container; failing readiness only stops traffic to it.
RequestLimitWhat the scheduler reserves vs the cap the kernel enforces (throttle CPU, OOM-kill memory).
Scale outScale upMore machines vs a bigger machine.
SLOSLAAn internal target vs a promise to customers with a penalty.
Event timeProcessing timeWhen it happened vs when your system saw it.
Cache-asideWrite-throughThe app fills the cache on a miss vs every write updates cache and database together.
