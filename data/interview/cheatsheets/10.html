Quick quiz

Which command shows why the last run of a crashing container failed?

  1. kubectl get pods -w
  2. kubectl logs POD --previous
  3. kubectl top pod POD
The current container has just restarted. --previous returns the logs of the instance that crashed.

docker run --cpus=1.5 writes which cgroup v2 value?

  1. cpu.weight = 1500
  2. memory.max = 1.5G
  3. cpu.max = 150000 100000
Quota 150,000 microseconds per 100,000 microsecond period: one and a half CPUs' worth of time.

With RF 3, min.insync.replicas=2 and acks=all, two brokers go down. What happens to writes for a partition whose ISR is now one replica?

  1. They fail with NotEnoughReplicas
  2. They succeed with one copy
  3. They are queued on the broker until replicas return
min ISR 2 refuses to acknowledge writes with fewer than two in-sync copies: durability over availability.

Roughly how many requests per second is 100 million requests per day?

  1. About 120
  2. About 1,200
  3. About 12,000
100M / 10^5 seconds = 1,000; with 86,400 seconds it is about 1,160.

You run --reset-offsets --to-earliest on a group and nothing changes. The most likely reason?

  1. The topic is compacted
  2. Retention is too short
  3. Consumers are still running, or you left off --execute
Resets need an inactive group, and without --execute the tool only prints a plan.
