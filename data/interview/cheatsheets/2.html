Sheet 1: Docker CLI

Remember the chain: docker CLI talks to dockerd, which asks containerd, which starts a shim that calls runc to create namespaces and cgroups and exec your process. Full story on Docker internals.

Container lifecycle

Exit codes

CodeMeaning
0Finished normally
1App error (read the logs)
125 / 126 / 127Docker failed to run it / not executable / command not found
137128 + 9 = SIGKILL (OOM killer or docker kill)
143128 + 15 = ended by SIGTERM (docker stop / pod deletion) without handling it. An app that catches SIGTERM and drains usually exits 0; JVMs report 143 even after shutdown hooks.

Dockerfile rules on one card

# syntax=docker/dockerfile:1
FROM golang:1.25 AS build            # 1. build stage has the full toolchain
WORKDIR /src
COPY go.mod go.sum ./                # 2. dependency manifests first...
RUN --mount=type=cache,target=/root/go/pkg/mod go mod download
COPY . .                             # 3. ...source last (changes most)
RUN CGO_ENABLED=0 go build -o /out/app ./cmd/app

FROM gcr.io/distroless/static        # 4. tiny runtime stage
COPY --from=build /out/app /app
USER 10001                           # 5. numeric non-root user
ENTRYPOINT ["/app"]                  # 6. exec form: app is PID 1, gets SIGTERM
  • Only RUN, COPY and ADD make filesystem layers. Once one step misses the cache, every later step rebuilds.
  • Deleting a file in a later layer does not shrink the image. Download, use and delete in one RUN, or use multi-stage.
  • Secrets: RUN --mount=type=secret,id=npmrc. Never ARG or ENV (visible in docker history and docker inspect).
  • EXPOSE publishes nothing. It is documentation.
  • Keep .git, node_modules and secrets out with .dockerignore.
