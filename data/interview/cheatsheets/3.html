Click through: debugging a broken pod in five commands

  1. get pods. The STATUS column tells you which family of problem you are in. Decode it before doing anything else.
  2. describe pod. The Events section names the component that complained and why. Last State shows the previous exit.
  3. logs --previous. For crashes, the current container has just started; the useful logs belong to the one that died.
  4. endpointslices. If the pod runs but users get errors, check that the Service actually points at it.
  5. events. Cluster-wide events in time order show the bigger picture: evictions, failed scheduling, node trouble.
