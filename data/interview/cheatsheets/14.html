Sheet 7: Terraform state, plan and apply

The commands and rules that keep state safe. Full lessons: Terraform State and safe apply.

Everyday commands

terraform initdownload providers and modules, configure the backend
terraform plan -out=tfplandiff code vs state vs real world; save it
terraform apply tfplanapply exactly the reviewed plan
plan -detailed-exitcode0 no changes, 2 changes (drift check), 1 error
terraform state list / showinspect what Terraform tracks
terraform state pull > backup.jsonback up before any surgery
terraform force-unlock IDonly after confirming no run is active

Backend and state rules

BackendS3 bucket: versioning, encryption, Block Public Access
Lockinguse_lockfile = true (Terraform 1.11+); DynamoDB table is the older way
Secretsstate stores them in plain text: restrict and encrypt it, never commit it
Split stateby environment and layer (network, data, cluster, app)
Environmentsfolder per env by default; workspaces for short-lived copies
Versionspin required_version, providers ~>, commit .terraform.lock.hcl

Prefer blocks to state surgery

NeedBlock (reviewed in plan)CLI (immediate)
Rename or move into a modulemoved { from = A to = B }terraform state mv A B
Adopt an existing objectimport { to = ADDR id = "..." }terraform import ADDR ID
Stop managing, keep the objectremoved { from = ADDR lifecycle { destroy = false } }terraform state rm 'ADDR'
Rebuild one broken object-terraform apply -replace='ADDR'

Plan symbols: + create, - destroy, ~ update in place, -/+ replace (destroy first), +/- replace with create_before_destroy. Read every "destroy" on a stateful resource twice.
