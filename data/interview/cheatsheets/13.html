One page to redraw a production VPC on a whiteboard. Full lessons: AWS Networking and security groups vs NACLs.

Address plan and subnets

VPC CIDR/16 = 65,536 IPs; never overlap with peers or on-prem
Reserved per subnet5 (network, router .1, DNS .2, future .3, broadcast)
Public subnetroute 0.0.0.0/0 -> igw; ALB/NLB, NAT gateways
Private subnetroute 0.0.0.0/0 -> nat in the same AZ; apps, nodes, pods
Isolated subnetno default route; databases, VPC endpoints for AWS APIs
EKS podsVPC CNI uses real VPC IPs: size private subnets /19 or larger
Layoutone public + one private + one data subnet per AZ, 3 AZs

NAT, IGW and endpoints

Internet Gatewayfree; 1:1 NAT for public IPs; needs a route + public IP + SG rule
NAT gatewayoutbound only; zonal: one per AZ; billed per hour + per GB
NAT limit55,000 simultaneous connections per unique destination per IP
Public IPv4every one billed hourly since Feb 2024
S3 / DynamoDBgateway endpoint: free, a route-table entry
Other AWS APIs (ECR, STS...)interface endpoint: an ENI per AZ, hourly + per GB

Security group vs NACL

Security groupNetwork ACL
Attached toeach ENI (instance, pod, LB, endpoint)the subnet
Statestateful: replies allowed automaticallystateless: allow return ports 1024-65535
Rulesallow only; can reference another SGnumbered allow and deny, lowest number wins
Use foreveryday app-to-app rules (ALB SG -> app SG -> DB SG)coarse subnet blocks, explicit denies

Packet walk to remember: DNS -> IGW -> ALB node (public subnet, SG 443) -> local route -> target ENI (private subnet, SG from ALB SG) -> reply by the same path. Debug with VPC Flow Logs and Reachability Analyzer.
