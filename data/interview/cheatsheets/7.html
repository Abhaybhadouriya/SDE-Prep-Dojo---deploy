Common mistakes these sheets prevent

Publishing to the world by accident. docker run -p 8080:80 listens on all interfaces, and host firewalls such as ufw do not see it because Docker's DNAT runs first. Bind to 127.0.0.1 for local work, or filter in the DOCKER-USER chain.

Running kubectl against the wrong cluster. Contexts persist between terminals. Check kubectl config current-context before deletes, or put the context in your shell prompt.

A new consumer group sees nothing. auto.offset.reset defaults to latest, so a brand-new group starts at the end. Use --from-beginning on the console consumer or set earliest when you mean it.

Offset reset that does nothing. --reset-offsets refuses to run while the group has active members, and without --execute it only prints a preview. Stop the consumers first.

Trusting "acks=all" alone. With min.insync.replicas=1 it can mean one copy. The pair matters, not one setting.

Deleting a StatefulSet pod to "fix" it. It comes back with the same name and the same disk, so a corrupted volume stays corrupted. Look at the PVC and the app's own recovery tooling.

Pruning volumes on a shared machine. docker system prune --volumes deletes unused named volumes, which may be someone's database. Prune images and build cache first.

Quoting stale defaults. linger.ms changed from 0 to 5 ms in Kafka 4.0; ZooKeeper is gone in 4.x; Compose v1 (docker-compose) is end of life. Old blog posts are wrong on all three.
