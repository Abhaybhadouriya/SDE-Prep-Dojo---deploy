Docker and containers

Goal: explain why a container is not a VM, write a good multi-stage Dockerfile, and draw what happens on the host when you publish a port. On this site: Docker track.

Start (Level 1-2)

  • Docker: Get started doc if you open only one - the official path from install to your first Compose app. Do every hands-on step.
  • Julia Evans: What even is a container? blog - a friendly, kernel-first explanation: namespaces, cgroups, seccomp, overlay filesystems. Old (2016) but the kernel facts have not changed.
  • Play with Docker course - free Docker hosts in the browser for a few hours at a time. Nothing to install.

Build (Level 3)

  • Dockerfile best practices doc - small base images, multi-stage builds, .dockerignore, cache-friendly ordering. Read it with your own Dockerfile open.
  • Docker networking overview doc - every driver (bridge, host, none, overlay, macvlan, ipvlan) and the port-publishing rules.
  • iximiuz: Container networking is simple blog - builds a bridge, veth pairs and NAT by hand with ip and iptables. Written for exactly your background.
  • docker/awesome-compose repo - ready compose.yaml samples (web + database, Kafka and more) to copy and break.
  • dive repo - a terminal tool that shows each image layer and the wasted space in it. Best way to "see" layers.

Go deep (Level 4-5)

  • namespaces(7) man page doc - the source of truth for every namespace type and clone flag. You will recognise most of it.
  • LWN: Namespaces in operation, part 1 blog - Michael Kerrisk's series with C examples. Perfect for a kernel engineer.
  • lizrice/containers-from-scratch and containers-the-hard-way repo - build a container yourself, step by step.
  • iximiuz: You don't need an image to run a container blog - runs runc with a hand-made bundle; shows what an OCI runtime really needs.
  • Fly.io: Docker without Docker blog - how an image is "a stack of tarballs plus JSON", and why Fly runs images as microVMs instead of shared-kernel containers.
  • Datadog container report blog - real usage data (runtimes, resource requests) across many companies. Useful for grounded interview claims; note the report's date.
