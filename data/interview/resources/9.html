System design (HLD)

Goal: run a 45-minute design round with a fixed framework, estimate in three minutes, and talk trade-offs in the "pick X because A, cost B, switch to Y if C" pattern. On this site: HLD track and design gallery.

Start (Level 2)

  • Hello Interview: System Design in a Hurry course if you open only one - free, compact, interview-shaped. The best first read for someone who has never done HLD.
  • System Design Primer repo - the classic free primer: scalability topics, latency numbers, worked designs and Anki cards.
  • Tech Interview Handbook: system design doc - how the round works and how to prepare, in plain words.

Build (Level 3)

  • Designing Data-Intensive Applications book - Martin Kleppmann (O'Reilly; a second edition with Chris Riccomini is out). The single best book for this site: replication, partitioning, transactions, consistency and streams. Chapters 1-6 first.
  • System Design Interview, Vol. 1 and 2 book - Alex Xu (Vol. 2 with Sahn Lam). Short, diagram-heavy chapters per classic design; Vol. 2 adds message queue, metrics, payments, stock exchange and more.
  • Latency numbers every programmer should know doc - plus the interactive version by year. Connect them to NIC, PCIe and memory numbers you already know.
  • Hello Interview: numbers to know course - modern hardware numbers for estimation (big-memory boxes, zone latency).
  • Azure cloud design patterns doc - one page per pattern (cache-aside, circuit breaker, saga, sharding, leader election). Microsoft interviewers use these names.
  • karanpratapsingh/system-design repo - a free book-style course from fundamentals to full designs.

Go deep (Level 4-5)

  • Amazon Builders' Library blog - how Amazon really does it. Start with timeouts, retries and backoff with jitter and making retries safe with idempotent APIs. Gold for Amazon loops.
  • Dynamo paper (2007) paper - consistent hashing, quorums, vector clocks and hinted handoff in one paper.
  • Scaling Memcache at Facebook (NSDI 2013) paper - leases against thundering herds and stale sets; the best real caching paper.
  • Raft paper - the paper plus a live visualisation of elections and log replication. Play with it for ten minutes.
  • Stripe: designing robust APIs with idempotency and Stripe: scaling your API with rate limiters blog - two short posts that answer two of the most asked HLD deep dives.
  • Discord: how we store trillions of messages blog - a database migration story with hot partitions and request coalescing.
  • aphyr/distsys-class repo - Kyle Kingsbury's distributed systems class outline; dense and honest about failure.
