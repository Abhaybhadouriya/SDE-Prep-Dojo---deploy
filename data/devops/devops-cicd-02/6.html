Artifact repositories: Nexus and Artifactory

Must know (SDE-1)

An artifact repository manager is a server that stores build outputs by coordinates and version, and serves them over HTTP to builds and deployers. Sonatype Nexus and JFrog Artifactory are the two common ones; both speak Maven, npm, PyPI, Docker/OCI, Helm and more. Cloud registries like Amazon ECR or GitHub Packages do the same job for fewer formats. Three repository types matter:

  • Hosted - your own artifacts. Keep releases and snapshots apart: a snapshot repo accepts many uploads of 1.5.0-SNAPSHOT (each stored with a timestamp), a release repo should be set to disable redeploy, so 1.4.2 can be written exactly once.
  • Proxy - a caching mirror of a remote repo (Maven Central, npmjs, Docker Hub). Faster builds, fewer rate limits, and a record of exactly which third-party bytes you shipped.
  • Group (Artifactory calls it virtual) - one URL that searches several repos in order. Builds only ever know this one URL.

Point Maven at the group with a mirror in settings.xml and read credentials from the environment, never from the file in git:

<!-- ci-settings.xml (committed; contains no secrets) -->
<settings>
  <mirrors>
    <mirror>
      <id>nexus</id>
      <mirrorOf>*</mirrorOf>
      <url>https://nexus.example.internal/repository/maven-public/</url>
    </mirror>
  </mirrors>
  <servers>
    <server>
      <id>nexus-releases</id>                <!-- matches distributionManagement id -->
      <username>${env.NEXUS_USER}</username>
      <password>${env.NEXUS_PASS}</password>
    </server>
  </servers>
</settings>
$ mvn -B deploy -DskipTests -Drevision=1.4.2 -s ci-settings.xml
[INFO] --- deploy:3.1.3:deploy (default-deploy) @ payment-api ---
Uploading to nexus-releases: https://nexus.example.internal/repository/maven-releases/com/dojo/payments/payment-api/1.4.2/payment-api-1.4.2.jar
Uploaded to nexus-releases: .../payment-api-1.4.2.jar (84 kB at 1.2 MB/s)
Uploaded to nexus-releases: .../payment-api-1.4.2.pom (3.1 kB at 96 kB/s)
[INFO] BUILD SUCCESS

$ mvn -B deploy -DskipTests -Drevision=1.4.2 -s ci-settings.xml     # same version again
[ERROR] Failed to deploy artifacts: Could not transfer artifact com.dojo.payments:payment-api:jar:1.4.2
        from/to nexus-releases: status code: 400, reason phrase: Repository does not allow updating assets: maven-releases (400)

That second failure is the feature, not a bug. It is how the repository enforces immutability: once 1.4.2 exists, nobody can quietly replace it.

From your world

The URL layout com/dojo/payments/payment-api/1.4.2/ is just a path derived from the GAV, the same way a package mirror lays out pool/main/o/openssl/. A proxy repo is a caching forwarder: like a local DNS resolver, it answers from cache and only goes upstream on a miss, and it keeps working (for cached entries) when upstream is down.
