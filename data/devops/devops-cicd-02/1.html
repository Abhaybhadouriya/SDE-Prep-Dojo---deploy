From commit to artifact: the whole flow

Must know (SDE-1)

Continuous Integration (CI) means every push is built and tested automatically, so the main branch is always in a working state. Continuous Delivery (CD) means every build that passes CI produces something that could go to production with one button. The thing that moves between those stages is the artifact: a built, versioned file such as a JAR, a Docker image or an npm package.

Three tools share the work, and interviewers like it when you keep them apart:

LayerExample toolsIts one job
Build toolMaven, Gradle, npm, Go toolchainTurn source + dependencies into an artifact, run tests. Works the same on a laptop and on CI.
Pipeline orchestratorJenkins, GitHub Actions, GitLab CIDecide when to build (push, PR, tag), where (which machine), in what order, and with which secrets.
Artifact repositoryNexus, Artifactory, ECR, GHCRStore artifacts by version forever, proxy public repos, serve them to builds and deploys.

From your world

You already did this with firmware. A release engineer compiled the router image once, stamped it with a version and a checksum, put it on the TFTP or SCP server, and every line card in the lab and in the customer network loaded that image. Nobody recompiled the kernel per chassis, because then the image in the field would not be the image QA tested. Maven is your make, Jenkins is the nightly build box, Nexus is the image server, and the version number plus SHA is your show version answer during an outage.
