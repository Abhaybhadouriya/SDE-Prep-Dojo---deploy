GitHub Actions: workflows, jobs, runners, matrix, cache, secrets

Must know (SDE-1)

GitHub Actions is CI built into GitHub. A workflow is a YAML file in .github/workflows/. It is triggered by events (push, pull_request, a tag, a schedule, a manual workflow_dispatch). A workflow has jobs; each job runs on a fresh runner (a VM hosted by GitHub, or a self-hosted machine) and is a list of steps. A step is either a shell command (run:) or a reusable action (uses:), such as actions/checkout.

# .github/workflows/ci.yml
name: ci
on:
  push:
    branches: [main]
    tags: ['v*']
  pull_request:

permissions:
  contents: read                     # least privilege for the GITHUB_TOKEN

concurrency:                         # cancel superseded PR runs only
  group: ci-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

jobs:
  test:
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest]
        java: [21, 25]               # the two current LTS releases
        include:
          - os: windows-latest
            java: 25
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-java@v5
        with:
          distribution: temurin
          java-version: ${{ matrix.java }}
          cache: maven               # caches ~/.m2/repository keyed on pom.xml hashes
      - run: mvn -B verify

  publish:
    needs: test
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-java@v5
        with: { distribution: temurin, java-version: 21, cache: maven }
      - name: Deploy to Nexus
        env:
          NEXUS_USER: ${{ secrets.NEXUS_USER }}
          NEXUS_PASS: ${{ secrets.NEXUS_PASS }}
        run: mvn -B deploy -DskipTests -Drevision=1.4.${{ github.run_number }} -s ci-settings.xml

Matrix

The matrix above produces three jobs: (ubuntu, 21), (ubuntu, 25) and the extra (windows, 25) added by include. Java 25 has been the current LTS since September 2025, so a late-2026 matrix tests 21 and 25. fail-fast: false lets the other legs finish when one fails, so you see every broken combination in one run instead of one at a time.

Caching

A runner is a fresh VM, so ~/.m2 is empty every time. The cache saves a directory at the end of a job under a key and restores it at the start of the next one. The usual key is a hash of the files that decide the dependencies, so the cache is reused until pom.xml changes:

      - uses: actions/cache@v5
        with:
          path: ~/.m2/repository
          key: m2-${{ runner.os }}-${{ hashFiles('**/pom.xml') }}
          restore-keys: |
            m2-${{ runner.os }}-

Lookup order (from the GitHub docs): exact key match first, then prefix matches on restore-keys in order, newest first. A run can read caches from its own branch and the default branch (and a PR can read its base branch), but not from sibling branches. Each repository gets 10 GB of cache by default, and entries not used for 7 days are evicted.

Secrets

Secrets are stored encrypted in repository, environment or organization settings and exposed only through ${{ secrets.NAME }}. They are masked in logs, and they are not passed to workflows triggered by pull requests from forks. Put production credentials in an environment (for example production) with required reviewers, so a job that uses them waits for a human approval. Better still, prefer short-lived cloud credentials through OIDC (the job proves its identity to AWS or GCP and gets a token valid for minutes) over long-lived keys in secrets.

Pin what you run. uses: some-org/some-action@v1 runs whatever code that tag points to today. For third-party actions, pin to a full commit SHA, set permissions: to the minimum, and never echo a secret even to "debug" (masking only catches the exact string, not a base64 of it).

      # first-party actions on their current Node 24 majors
      - uses: actions/checkout@v5
      # third-party action pinned to an immutable commit; the comment keeps it readable
      - uses: hashicorp/setup-terraform@dfe3c3f87815947d99a8997f908cb6525fc44e9e   # v4.0.1

GitHub-hosted runners are moving actions off Node 20, so keep majors current (checkout v5+, setup-java v5, cache v5, configure-aws-credentials v5). Dependabot can bump both version tags and pinned SHAs for you.

Never cancel a publish or deploy mid-flight. cancel-in-progress: true on pushes to main would let a second merge kill the first run while its mvn deploy is half done: a half-uploaded release, or a merged commit with no artifact at all. Cancel only superseded PR runs (as above), or move publishing into its own job or workflow with a non-cancelling concurrency group.
