Jenkins vs GitHub Actions

Good to know (SDE-2)
JenkinsGitHub Actions
HostingYou run controller + agents (VMs or Kubernetes)GitHub-hosted runners, or self-hosted runners you register
Pipeline fileJenkinsfile (Groovy DSL).github/workflows/*.yml (YAML)
Unit of reusePlugins, shared librariesActions (uses:), reusable workflows
Parallelismparallel { } blocks, matrix directiveJobs parallel by default, strategy.matrix, needs: for order
SecretsCredentials store + withCredentialsRepo / environment / org secrets, OIDC to clouds
Approvalsinput stepEnvironment protection rules (required reviewers)
Main painPlugin upgrades, controller is a pet to patch and back upTied to GitHub; minutes cost; less control over hosted runners
Pick it whenMany SCMs, air-gapped networks, heavy custom hardwareCode already on GitHub, want zero CI ops

The concepts map one to one: agent = runner, stage = job (or step group), Jenkinsfile = workflow file, credentials = secrets, input = environment approval. Say that mapping out loud in an interview and the tool question becomes easy.
