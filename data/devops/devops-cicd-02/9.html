Gotchas that break real pipelines

  • Snapshot in production. 1.5.0-SNAPSHOT resolves to "the newest upload", which changes under you. Release builds must not depend on any snapshot (the Maven Enforcer plugin's requireReleaseDeps rule catches this).
  • Version ranges. [1.0,2.0) in a pom means two builds of the same commit can pick different libraries. Pin exact versions; let a bot (Dependabot, Renovate) propose upgrades as PRs.
  • mvn install on CI. It writes to the runner's local repo, which is thrown away. Use verify for PRs and deploy for publishing.
  • Running tests twice. A verify stage followed by a full deploy stage reruns all tests. Pass -DskipTests to the publish step only if the same pipeline run already tested the same commit.
  • Cache key too broad. A key without the pom hash restores an old, ever-growing ~/.m2 forever. A key that is too narrow (includes the commit SHA) never hits.
  • Secrets in logs. set -x in a shell step, or printing a config object, leaks credentials. Masking only replaces the exact secret string.
  • Pets as build agents. A long-lived agent accumulates tools and files, so builds pass there and nowhere else. Use ephemeral agents built from an image.
  • Rebuilding on tag. Building again when a release tag is pushed creates a second, untested artifact. Promote the already built one, or make the tag build the only build.
  • PR from a fork. Secrets are not available, so a step that needs one fails. Do not "fix" it with pull_request_target plus checkout of the fork's code: that runs untrusted code with your secrets.
  • Deployed POM still says ${revision}. On Maven 3 without flatten-maven-plugin, the published .pom keeps the placeholder and consumers fail to resolve it. Add the plugin (or move to Maven 4's consumer POM).
  • Cancelling a publish job. A concurrency group with cancel-in-progress: true on main can kill a half-finished mvn deploy. Cancel only PR runs.
  • An approval that holds an executor. A Jenkins input inside a pipeline-wide agent blocks a build slot for as long as nobody clicks, and a pipeline-wide timeout aborts it.
