How does Terraform know a subnet must be created after its VPC?

  2. Alphabetical order of resource types
  3. The subnet's vpc_id = aws_vpc.main.id reference

References create implicit dependency edges. File order does not matter.

Which situation actually needs depends_on?

  1. An instance's boot script needs an IAM policy that the instance block never references
  2. A subnet needs its VPC ID
  3. A route table association needs a route table ID
The other two already have references. Hidden behavioural dependencies are what depends_on is for.

What does -/+ mean in a plan?

  1. Update in place
  2. Read a data source
  3. Create only
  4. Destroy and create a replacement
An argument that cannot be changed in place forces replacement. With create_before_destroy it shows as +/-.

  1. Exactly 6.0.0

The pessimistic constraint allows the rightmost component to grow only.

You delete a data "aws_vpc" "shared" block. What happens to the VPC in AWS?

  1. Terraform destroys it
  2. Terraform marks it tainted
  3. Nothing: data sources only read

Why prefer for_each over count for a set of subnets that will change?

  1. Keys keep addresses stable, so removing one does not shift the others
  2. for_each is faster
  3. count cannot create subnets
count addresses by index; removing an early element renumbers the rest and triggers replacements.
