Declarative IaC vs click-ops vs scripts

Must know (SDE-1)

There are three ways to build cloud infrastructure. It helps to see why the industry settled on the third.

Click-ops (console)Imperative script (bash + AWS CLI)Declarative IaC (Terraform)
You writeNothingThe steps: "create VPC, then create subnet..."The end result: "a VPC with these 4 subnets exists"
Run it twiceTwo of everything (or you forget)Fails or creates duplicates unless you write checksSecond run: "No changes." It is idempotent
Change one thingClick and hopeWrite a new script for the changeEdit one line; Terraform computes the diff
ReviewScreenshotsCode review of stepsCode review and a plan preview of exact API changes
Delete everythingHunt through every screenWrite a reverse scriptterraform destroy, in the right order
Audit trailCloudTrail onlyGit history of scriptsGit history of the desired state itself

The key word is declarative. You declare the desired state; the tool figures out the actions. You have already met this idea in Kubernetes: a Deployment says "3 replicas" and controllers make it so. Terraform is the same idea for cloud resources, with one difference: Terraform is not a loop that runs forever. It runs when you (or CI) call it, does its work, and exits.

From your world

Think of a router. Typing ip route add commands one by one on a live box is click-ops: the box ends up in some state and nobody can reproduce it. A startup-config file is declarative: it describes the full intended config, and the box converges to it on boot. Tools like NETCONF/YANG with "replace" semantics (send the whole intended config; the device computes the diff against the running config) are exactly the Terraform model. Terraform's plan is the "show the diff before commit" step, like commit check / show | compare on Junos.

Terraform vs other tools in one line each. AWS CloudFormation is declarative too, but AWS-only and the state lives inside AWS. Pulumi uses real programming languages (TypeScript, Python, Go) instead of HCL. Ansible is mostly procedural configuration of what runs inside servers. OpenTofu is an open-source fork of Terraform (Linux Foundation), created in 2023 after HashiCorp moved Terraform to the Business Source License; its CLI is tofu and the language is the same HCL, so everything on this page works with either.

Terraform or OpenTofu? The 2023 licence change

In August 2023 HashiCorp moved Terraform (from version 1.6) from the open-source MPL 2.0 licence to the Business Source License. For end users running Terraform on their own infrastructure nothing changed; the BSL restricts companies that offer a competing hosted Terraform product. In response the community forked the last MPL version as OpenTofu, now a Linux Foundation project. HCL and state are mostly compatible, so moving is low-risk, and OpenTofu has added its own features such as client-side state encryption and provider-defined functions. In 2025 IBM completed its acquisition of HashiCorp. Everything on these pages works the same in both tools unless a note says otherwise.
