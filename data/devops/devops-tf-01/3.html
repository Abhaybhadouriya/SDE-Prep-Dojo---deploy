Your first config: a VPC with public and private subnets

This is the VPC you designed by hand in AWS Networking: build it. Same CIDRs, same subnets, now as code you can review and re-run.

Must know (SDE-1)

Here is a small but real project. It builds a VPC, one public and one private subnet in two Availability Zones, an internet gateway, and a route table with a default route. Every resource here maps to a networking idea you already know.

terraform {
  required_version = ">= 1.11"

  required_providers {
    aws = {
      source  = "hashicorp/aws"   # registry.terraform.io/hashicorp/aws
      version = "~> 6.0"          # any 6.x, never 7.0
    }
  }
}

provider "aws" {
  region = var.region

  default_tags {
    tags = {
      Environment = var.env
      ManagedBy   = "terraform"
    }
  }
}
variable "region" {
  type    = string
  default = "ap-south-1"
}

variable "env" {
  type        = string
  description = "dev, staging or prod"
  validation {
    condition     = contains(["dev", "staging", "prod"], var.env)
    error_message = "env must be dev, staging or prod."
  }
}

variable "vpc_cidr" {
  type    = string
  default = "10.0.0.0/16"
}

locals {
  name = "dojo-${var.env}"
  # two AZs; cidrsubnet(10.0.0.0/16, 8, n) gives 10.0.n.0/24
  azs  = slice(data.aws_availability_zones.up.names, 0, 2)
}
data "aws_availability_zones" "up" {
  state = "available"
}

resource "aws_vpc" "main" {
  cidr_block           = var.vpc_cidr
  enable_dns_hostnames = true
  tags = { Name = local.name }
}

resource "aws_subnet" "public" {
  count                   = 2
  vpc_id                  = aws_vpc.main.id              # reference = dependency
  cidr_block              = cidrsubnet(var.vpc_cidr, 8, count.index)        # 10.0.0.0/24, 10.0.1.0/24
  availability_zone       = local.azs[count.index]
  map_public_ip_on_launch = true
  tags = { Name = "${local.name}-public-${count.index}" }
}

resource "aws_subnet" "private" {
  count             = 2
  vpc_id            = aws_vpc.main.id
  cidr_block        = cidrsubnet(var.vpc_cidr, 8, count.index + 10)       # 10.0.10.0/24, 10.0.11.0/24
  availability_zone = local.azs[count.index]
  tags = { Name = "${local.name}-private-${count.index}" }
}

resource "aws_internet_gateway" "igw" {
  vpc_id = aws_vpc.main.id
}

resource "aws_route_table" "public" {
  vpc_id = aws_vpc.main.id
  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.igw.id   # default route out
  }
}

resource "aws_route_table_association" "public" {
  count          = 2
  subnet_id      = aws_subnet.public[count.index].id
  route_table_id = aws_route_table.public.id
}
# outputs.tf
output "vpc_id" {
  value = aws_vpc.main.id
}

output "private_subnet_ids" {
  value = aws_subnet.private[*].id     # splat: list of all ids
}

# dev.tfvars  (used with: terraform apply -var-file=dev.tfvars)
env      = "dev"
vpc_cidr = "10.20.0.0/16"

From your world

Read this as a network config. The VPC is a private routing domain with its own address space, very close to a VRF. A subnet is a prefix pinned to one Availability Zone (one data-center fault domain). An internet gateway is the edge router to the internet (it also does 1:1 NAT between an instance's private IP and its public IP). A route table is a small RIB attached to subnets; the 0.0.0.0/0 -> igw line is your default route, and a subnet is "public" only because its route table has that line. cidrsubnet("10.0.0.0/16", 8, 10) is just "extend the prefix by 8 bits and take the 10th /24": 10.0.10.0/24. The full AWS networking picture is in the AWS & Cloud section of this module.

Notice what is not in the file: no order. The route table block comes after the subnets in the file, the internet gateway before the route table, but that is for humans. Terraform works out the order from the references (next sections).
