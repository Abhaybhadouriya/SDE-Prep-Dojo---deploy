HCL: the shape of every block

Must know (SDE-1)

A Terraform project is a folder of .tf files. Terraform reads all of them in the folder together (file names do not matter to it; they matter to humans). Everything in them is a block:

The seven block types you will see on day one:

BlockWhat it doesHow you refer to it
terraform { }Settings: required Terraform version, required providers, backend (where state lives, see Terraform State)-
provider "aws" { }Configures a plugin that talks to one API (region, credentials, default tags)-
resource "aws_vpc" "main" { }Something Terraform creates and owns (create, update, delete)aws_vpc.main.id
data "aws_availability_zones" "up" { }Something Terraform only reads (existing AMI, AZ list, a VPC another team owns)data.aws_availability_zones.up.names
variable "env" { }An input: set from *.tfvars, -var, or TF_VAR_envvar.env
locals { }Named expressions computed inside the module (like a const)local.name_prefix
output "vpc_id" { }A value printed after apply and readable by other configs or scriptsterraform output vpc_id

A resource vs a data source is the first thing to get right. A resource says "this thing must exist, and I own it": remove the block and Terraform deletes the real object. A data source says "go and look this up": remove the block and nothing in the cloud changes.
