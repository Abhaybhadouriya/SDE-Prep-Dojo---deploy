The story: the LEGO instruction sheet

Explain like I'm 5

You built an amazing LEGO castle by hand. Your friend wants the same castle. You try to remember: "First the blue base... then I think the tower... or was it the wall?" You forget a window. Your friend's castle looks different.

Now imagine you had drawn a picture of the finished castle with a list of every brick. Anyone can build the exact same castle from it, as many times as they like. And if a brick falls off, you look at the picture and see straight away which brick is missing.

And a magic helper reads the picture and builds it for you. It knows the walls must stand before the roof goes on, so you never have to tell it the order.

In the cloud, building things by clicking in a web console is the "remember how I did it" way. People call it click-ops. Terraform is the magic helper. You write the picture of the finished infrastructure in text files using HCL (HashiCorp Configuration Language). Terraform compares that picture with what really exists and makes the smallest set of API calls to make reality match. This is called Infrastructure as Code (IaC): your servers, networks and databases are described in files that live in Git, get reviewed in pull requests, and can be rebuilt on demand.

Before you start. Read AWS Networking first: the example in this page builds the same VPC. Comfort with a shell and Git is enough otherwise. Recommended order across the four new tracks: aws-01 -> aws-02 -> tf-01 -> tf-02 -> aws-03 -> aws-04 -> tf-03 -> cicd-01 to cicd-03 -> sre-01 and sre-02.
