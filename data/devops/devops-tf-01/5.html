Dependencies: implicit references and the graph

Must know (SDE-1)

Terraform builds a dependency graph (a directed acyclic graph, DAG) before doing anything. The rule is simple: if block A's arguments mention block B (for example aws_vpc.main.id), then A depends on B. These are called implicit dependencies, and they cover 95% of real configs. How Terraform walks this graph (from the Terraform internals docs):

  1. Add nodes. One node per resource (and per instance with count / for_each), plus provider nodes, plus "orphan" nodes for things in state that are no longer in config (they will be destroyed).
  2. Add edges. From every reference in an expression, and from every depends_on.
  3. Check. The graph must have no cycles. A cycle is an error (Error: Cycle: aws_security_group.a, aws_security_group.b), never a deadlock at runtime.
  4. Walk. A node starts as soon as all of its dependencies have finished. Up to 10 nodes run concurrently by default (-parallelism=n changes it).
  5. Destroy in reverse. On destroy, edges are reversed: associations go first, the VPC last. You cannot delete a VPC that still has subnets, and Terraform knows this from the same graph.

You can print the graph in Graphviz DOT format:

$ terraform graph | head
digraph G {
  rankdir = "RL";
  node [shape = rect, fontname = "sans-serif"];
  "aws_internet_gateway.igw" [label="aws_internet_gateway.igw"];
  "aws_route_table.public" [label="aws_route_table.public"];
  "aws_subnet.public" [label="aws_subnet.public"];
  "aws_vpc.main" [label="aws_vpc.main"];
  "aws_internet_gateway.igw" -> "aws_vpc.main";
  "aws_route_table.public" -> "aws_internet_gateway.igw";
  "aws_subnet.public" -> "aws_vpc.main";
  ...
$ terraform graph | dot -Tsvg > graph.svg    # needs Graphviz installed

A topological sort, run with a worker pool of 10. The "wave" picture is the same as running make -j10: everything whose prerequisites are built runs in parallel.
