Providers: one core, many clouds

Must know (SDE-1)

Terraform core knows nothing about AWS. All cloud knowledge lives in providers: separate plugin binaries that core starts as child processes and talks to over gRPC on localhost. The AWS provider knows how to turn aws_subnet into a CreateSubnet API call; the Google provider knows google_compute_subnetwork; there are providers for Azure, Kubernetes, Helm, Cloudflare, GitHub, Datadog, PagerDuty and thousands more on the public registry.

Three things to know about providers:

  1. Pin versions. version = "~> 6.0" means "6.x, at least 6.0, never 7.0" (the pessimistic constraint operator). Major versions of the AWS provider do break things.
  2. Commit .terraform.lock.hcl. It records the exact provider version and checksums chosen by init, like package-lock.json or go.sum. Your laptop and CI then use the identical plugin. Do not commit the .terraform/ folder (downloaded binaries). Upgrade on purpose with terraform init -upgrade.
  3. Aliases for multiple regions or accounts. One provider block per region, picked per resource:
provider "aws" {
  region = "ap-south-1"                 # default provider
}

provider "aws" {
  alias  = "dr"
  region = "ap-southeast-1"            # disaster-recovery region
}

resource "aws_s3_bucket" "backup" {
  provider = aws.dr                    # this one lives in Singapore
  bucket   = "dojo-dr-backups-123456"
}

And a multi-cloud example in one config: a GCP Cloud DNS record pointing at an AWS load balancer. Same plan, same graph, two providers:

resource "google_dns_record_set" "api" {
  managed_zone = "dojo-zone"
  name         = "api.dojo.example."
  type         = "CNAME"
  ttl          = 300
  rrdatas      = ["${aws_lb.api.dns_name}."]   # cross-cloud reference = a graph edge
}

Credentials never go in .tf files. The AWS provider reads the standard AWS credential chain: environment variables, ~/.aws profiles (SSO), or, best in CI, a short-lived role via OIDC (GitHub Actions assumes an IAM role, no stored keys). A hard-coded access_key in a provider block ends up in Git history.
