Before you start

You need very little. Everything Kafka-specific is explained the first time it appears.

  1. Basic networking and Linux. You already have this. TCP, sockets, page cache, sendfile, ring buffers and flow control will all come back in this track, used as bridges.
  2. What a container is (for the lab). We run Kafka in Docker so you install nothing else. If Docker is new, read What is a Container? and Running & Managing Containers first. Only docker run and docker exec are needed.
  3. A tiny bit of "web" vocabulary. A service (or microservice) is just a long-running program with a network API, such as an "order service" that accepts orders over HTTP. A request is one call to that API. That is all you need here.
  4. Words you will meet. If a word stops you, open the Glossary. Each term has a one-line meaning and a "from your world" hint. These few show up early, so here they are up front:
    • KIP = Kafka Improvement Proposal, the numbered design document behind each feature (KIP-848, KIP-1147...). Think of it like an RFC number. You never need to memorise the numbers; they just tell you where to read more.
    • REST / gRPC = two common ways for one service to call another and wait for a reply over HTTP (REST sends JSON text, gRPC sends compact binary Protobuf).
    • Upsert = insert-or-update by key: write the row if it is new, overwrite it if it exists. Doing it twice is harmless, which makes duplicates safe.
    • p99 = the 99th percentile latency: 99 of 100 requests were faster than this number. It shows the slow tail that an average hides.
    • Eventual consistency = other services see a change a little later (milliseconds to seconds), not at the same instant.
    • SLO / SLA = service level objective (the target you aim for, such as "99% of orders confirmed within 2 s") and service level agreement (the contract with a customer, with a penalty if you miss it).
