Your two-minute Kafka lab

The Kafka project publishes an official Docker image, apache/kafka. One container runs a complete single-node Kafka in KRaft combined mode (the same process is both the broker that stores data and the controller that manages the cluster). That is perfect for learning and wrong for production, where you run at least 3 brokers.

Shell and version notes. Every command in this track is bash. On Windows, use Git Bash or WSL; in PowerShell, set variables as $K="/opt/kafka/bin" and replace a trailing \ with a backtick ` (or put the command on one line). The console tools use the Kafka 4.2+ flag names from KIP-1147 (--command-property, --reader-property, --formatter-property); the old names (--producer-property, --property, --producer-props) still work on 4.x until 5.0 but print a deprecation warning.

# 1. start one broker (Docker Desktop must be running)
docker run -d --name broker -p 9092:9092 apache/kafka:4.4.0

# 2. create a topic with 3 partitions
docker exec -it broker /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --create --topic hello --partitions 3

# 3. terminal 1: type events, one per line (Ctrl+C to stop)
docker exec -it broker /opt/kafka/bin/kafka-console-producer.sh --bootstrap-server localhost:9092 --topic hello

# 4. terminal 2: read everything from the start
docker exec -it broker /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic hello --from-beginning

What you should see (the image download line appears only the first time):

$ docker exec -it broker /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --create --topic hello --partitions 3
Created topic hello.

$ docker exec -it broker /opt/kafka/bin/kafka-console-producer.sh --bootstrap-server localhost:9092 --topic hello
>kid arrived: asha
>lunch ordered: pasta
>book returned: the gruffalo

$ docker exec -it broker /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic hello --from-beginning
kid arrived: asha
lunch ordered: pasta
book returned: the gruffalo

Do this experiment: stop the consumer, type three more lines into the producer, then start the consumer again without --from-beginning. You see nothing old - it starts at the end. Now run it again with --from-beginning: everything is still there. The messages were not deleted when they were read. That is the single biggest difference between Kafka and a classic queue, and page 02 explains why.

Order surprise: with 3 partitions and no key, the consumer may print lines in a slightly different order from the one you typed. Kafka keeps order inside one partition only. Keep this puzzle in mind; page 02 solves it.

Clean up when you are done: docker rm -f broker. A ready-made multi-service stack (Kafka, a web UI, Postgres, Debezium) comes later in Build It Locally.
