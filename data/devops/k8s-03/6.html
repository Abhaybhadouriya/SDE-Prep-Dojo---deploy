The pod lifecycle and CrashLoopBackOff

Must know (SDE-1)

A pod has a phase, a one-word summary in status.phase. There are only five:

PhaseMeaning
PendingAccepted by the API server, but not all containers are running yet: waiting to be scheduled, pulling images, or running init containers.
RunningBound to a node, and at least one container is running (or starting or restarting).
SucceededAll containers exited with success and will not be restarted (typical for Jobs).
FailedAll containers have stopped and at least one failed (and will not be restarted).
UnknownThe control plane cannot get the pod's state, usually because it lost contact with the node.

Each container also has a state: Waiting, Running or Terminated, with a reason. The STATUS column of kubectl get pods often shows that reason instead of the phase. That is why you see words like ContainerCreating, ImagePullBackOff, CrashLoopBackOff, OOMKilled or Completed, which are not phases.

The back-off starts at 10 seconds and doubles each time, up to a cap of 5 minutes. If the container then runs fine for 10 minutes, the timer resets. Try it:

$ kubectl run crasher --image=busybox:1.36 -- sh -c "echo boom; exit 1"
pod/crasher created

$ kubectl get pod crasher
NAME      READY   STATUS             RESTARTS      AGE
crasher   0/1     CrashLoopBackOff   3 (21s ago)   75s

$ kubectl logs crasher --previous
boom

$ kubectl describe pod crasher | grep -A3 "Last State"
    Last State:     Terminated
      Reason:       Error
      Exit Code:    1

Debugging CrashLoopBackOff in 3 commands: kubectl describe pod X (events and Last State with exit code), kubectl logs X --previous (the output of the crashed run, not the current one), and check the exit code: 1 = your app failed (bad config, missing env var); 137 = 128 + 9, killed with SIGKILL, often OOMKilled (memory limit too low); 143 = 128 + 15, stopped by SIGTERM. Full troubleshooting playbook in Observability & Troubleshooting.

The pod's restartPolicy controls what the kubelet does when a container exits: Always (default, for servers), OnFailure (restart only on non-zero exit, for batch Jobs), or Never.
