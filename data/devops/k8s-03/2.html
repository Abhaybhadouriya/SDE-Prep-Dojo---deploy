Why not just schedule containers directly?

Must know (SDE-1)

You might ask this yourself, and it is a common interview question. Some programs must live together: a web server and a helper that refreshes its files, an app and a local proxy that handles TLS, an app and a log shipper reading its log files. They need to be on the same machine, start and stop together, and share files or localhost. If Kubernetes scheduled containers one by one, it could put the web server on node 1 and its helper on node 7. The pod is the "unit of co-location": everything in it is placed, started, scaled and deleted as one.

Two practical rules follow:

  1. One main process per pod. Put your API in one pod and your database in another, because they scale differently. You might want 20 API pods but one database.
  2. Extra containers only if they truly belong. A container goes in the same pod only if it must share the network or files and live and die with the main one. That is the sidecar idea, covered below.
