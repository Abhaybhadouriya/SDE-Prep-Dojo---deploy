What a pod really is (in Linux terms)

Must know (SDE-1)

You know from the Docker internals page that a container is a process wrapped in Linux namespaces (what it can see) and cgroups (what it can use). A pod is simply a set of containers that share some of those namespaces:

  • Network namespace: shared. One IP address for the whole pod, one set of ports, one loopback. Container A reaches container B at localhost:8080. Two containers in one pod cannot both listen on port 80.
  • IPC and UTS namespaces: shared. They can use shared memory and System V IPC with each other, and they see the same hostname (the pod name).
  • Volumes: shareable. A volume declared on the pod can be mounted into several of its containers, for example an emptyDir scratch folder.
  • Mount namespace and filesystem: separate. Each container has its own image and root filesystem.
  • PID namespace: separate by default. You can turn on shareProcessNamespace: true so containers see each other's processes (handy for debugging).
  • cgroups: per container, inside a pod-level cgroup. Each container can have its own CPU and memory requests and limits.

From your world

You could build a pod by hand: ip netns add podA, create a veth pair, move one end into the namespace, give it an IP, then start two processes with ip netns exec podA .... They would share the IP and see each other on 127.0.0.1. That is a pod. The pause container is a tiny process that mostly sleeps. Its real job is to hold the pod's namespaces open, so that something keeps /proc/<pid>/ns/net alive even while the app containers restart. Only when the pod sets shareProcessNamespace: true is it PID 1 for the whole pod, and then it also reaps zombie processes; by default each container has its own PID 1. Where the analogy breaks: the kubelet, the runtime and the CNI plugin do all of this for you, and they also tear it down and rebuild it on another node when the pod is replaced.
