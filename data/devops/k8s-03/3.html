Your first pod (lab)

Must know (SDE-1)

This pod has two containers. The writer sidecar writes the current time into a shared folder every 5 seconds, and nginx serves that folder. Save it as pod.yaml:

apiVersion: v1
kind: Pod
metadata:
  name: web
  labels:
    app: web                 # labels are how Services and controllers find pods
spec:
  volumes:
    - name: html
      emptyDir: {}           # a scratch folder that lives as long as the pod
  containers:
    - name: nginx
      image: nginx:1.27
      ports:
        - containerPort: 80
      volumeMounts:
        - name: html
          mountPath: /usr/share/nginx/html
    - name: writer
      image: busybox:1.36
      command: ["sh", "-c", "while true; do date > /html/index.html; sleep 5; done"]
      volumeMounts:
        - name: html
          mountPath: /html
kubectl apply -f pod.yaml
kubectl get pod web -o wide
kubectl exec web -c writer -- wget -qO- http://localhost:80
kubectl exec web -c writer -- ip -4 addr show eth0
$ kubectl apply -f pod.yaml
pod/web created

$ kubectl get pod web -o wide
NAME   READY   STATUS    RESTARTS   AGE   IP           NODE
web    2/2     Running   0          14s   10.244.1.7   dojo-worker

$ kubectl exec web -c writer -- wget -qO- http://localhost:80
Mon Nov 23 10:15:05 UTC 2026

$ kubectl exec web -c writer -- ip -4 addr show eth0
2: eth0@if9: <BROADCAST,MULTICAST,UP,LOWER_UP,M-DOWN> mtu 1500 qdisc noqueue
    inet 10.244.1.7/24 brd 10.244.1.255 scope global eth0

Look closely. READY 2/2 means both containers are ready. The writer container reached nginx on localhost, and its eth0 has the pod's IP: proof that they share one network namespace. (Your IP and interface index will differ.) A few more commands you will use every day:

kubectl describe pod web             # spec, status, conditions and the Events list (start here when debugging)
kubectl logs web -c nginx            # stdout/stderr of one container
kubectl logs web -c nginx -f         # follow, like tail -f
kubectl exec -it web -c nginx -- sh  # a shell inside a container
kubectl port-forward pod/web 8080:80 # then open http://localhost:8080 on your laptop
kubectl get pod web -o yaml          # the full object, including status filled in by the kubelet
kubectl delete pod web

Now peek under the hood. A kind node is a Docker container running containerd, so you can ask the runtime directly with crictl (the CRI command-line tool):

$ docker exec dojo-worker crictl pods --name web
POD ID          CREATED          STATE   NAME   NAMESPACE   ATTEMPT   RUNTIME
5b1c0e9a2f4d3   2 minutes ago    Ready   web    default     0         (default)

$ docker exec dojo-worker crictl ps --pod 5b1c0e9a2f4d3
CONTAINER       IMAGE           CREATED         STATE     NAME     ATTEMPT   POD ID          POD
a81f3c2d9e7b6   0f8a1c2b3d4e5   2 minutes ago   Running   writer   0         5b1c0e9a2f4d3   web
3e4d5c6b7a891   9b8a7c6d5e4f3   2 minutes ago   Running   nginx    0         5b1c0e9a2f4d3   web

The "pod" at runtime level is the sandbox (the pause container and its namespaces), and the two containers run inside it. (IDs shortened and will differ.)

In real life you almost never create a bare Pod. If a bare pod's node dies, nothing recreates it. You create a Deployment (or StatefulSet, DaemonSet, Job) and it creates pods for you from a template. See Deployments. Bare pods are for learning and debugging.
