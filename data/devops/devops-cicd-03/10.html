Remember this

  • Rolling, blue-green and canary all run v1 and v2 against one database; GitOps is how the desired state reaches the cluster.
  • Every schema must work for the running app (backward compatible) and the previous app must work with it (rollback).
  • Expand (add), migrate (dual write, backfill, switch reads), contract (stop old writes, drop) - one step per release.
  • Backfill only after dual write is 100% rolled out: small batches, idempotent, throttled, verified.
  • Constraints come last: NOT VALID, VALIDATE, then SET NOT NULL. Always set lock_timeout.
  • Migrations run once, before the rollout, as a gated Job - not on every pod's startup.
  • The drop is the point of no return; bake first.
