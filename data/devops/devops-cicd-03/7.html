Good to know (SDE-2)
ChangeExpandMigrateContract
Rename columnAdd new columnDual write, backfill, switch readsStop writing old, drop old
Change type (int id to bigint)Add bigint columnDual write, backfill, switch reads (often trigger-based on huge tables)Swap, drop old
Add NOT NULL columnAdd nullable (or with constant default)App always writes it, backfillCHECK NOT VALID, VALIDATE, then SET NOT NULL
Split a table (users to users + addresses)Create new tableDual write, backfill, read from joinDrop old columns
Drop a column(nothing)Release that stops reading/writing it; ORM ignores itDrop column
Change an API fieldAdd new field in responseClients move to it (track usage)Remove old field in a new API version
Kafka event schemaAdd optional field with a defaultProducers fill it, consumers read itRemove old field once no consumer reads it (enforce with a schema registry compatibility mode)

For very large MySQL tables where even an online ALTER is risky, teams use copy-based tools such as GitHub's gh-ost: it creates a shadow table with the new schema, copies rows in the background while tailing the binlog for live changes, then swaps the tables in a brief cut-over. It is expand-migrate-contract automated at the table level.
