Before you start

What you need to know (you already do)

  • Basic Linux shell: ls, cd, cat, pipes, environment variables.
  • What a process, a file system and a TCP port are. Your kernel and networking background covers more than enough.
  • No web development knowledge is assumed. When we need an "app", it is a tiny Python or Go web server and we explain every line.

What to install

  • Linux: Docker Engine from the official instructions for your distro. Add yourself to the docker group only on a personal machine, because that group is equal to root (page 09 explains why).
  • Windows or macOS: Docker Desktop. It runs a small Linux VM (WSL 2 on Windows) because Linux containers need a Linux kernel. Docker Desktop is free for personal use and learning.

Lab setup on Windows or macOS. Most Docker commands work the same in Docker Desktop. But some labs on pages 01, 05 and 08 look at the host side: iptables -t nat, /sys/fs/cgroup, nsenter, unshare, mount -t overlay, conntrack. On Docker Desktop the "host" is a small hidden Linux VM, not your laptop. Two ways to reach a real Linux host:

  1. (a) Ubuntu in WSL 2 with Docker Engine inside it (recommended on Windows). In PowerShell: wsl --install -d Ubuntu. Open Ubuntu, then install Docker Engine with Docker's official Ubuntu instructions (or the convenience script curl -fsSL https://get.docker.com | sh on a learning machine), plus the tools: sudo apt install -y iptables conntrack util-linux. If Docker Desktop is also installed, turn off its WSL integration for this distro so the two daemons do not clash. Every lab on this track works here.
  2. (b) A root shell inside Docker Desktop's own VM (quick, Windows or macOS). Run docker run -it --rm --privileged --pid=host debian nsenter -t 1 -m -u -n -i sh. This starts a privileged container in the VM's PID namespace and uses nsenter to join PID 1's mount, UTS, network and IPC namespaces, so you are effectively on the VM. Good for reading /sys/fs/cgroup, ip link, ls /var/lib/docker and ps of container processes. The VM is minimal, so tools like iptables or conntrack may be missing; use path (a) for those.

Which labs need what: page 01 "look from outside" and page 08 namespace/cgroup labs work with (a) or (b). Page 05's iptables/conntrack packet walk and page 08's unshare, mount -t overlay and mini-container script need (a) or any native Linux machine or VM.
