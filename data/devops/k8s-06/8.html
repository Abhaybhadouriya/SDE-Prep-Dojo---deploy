Running the front door in production

Deep dive (platform teams)

Good to know for SDE-2 and platform roles.

  • It is a single point of failure unless you make it not one. Run several proxy replicas spread across zones (topology spread constraints), with a PodDisruptionBudget and an HPA. Separate the control plane (controller) from the data plane (proxies) so a controller crash does not drop traffic.
  • Client IP. Behind a cloud LB the proxy may see the LB's or a node's IP. Use externalTrafficPolicy: Local on the proxy's Service or the PROXY protocol, and pass the client IP onward in X-Forwarded-For.
  • Timeouts and long connections. WebSockets, server-sent events and gRPC streams need longer idle timeouts at every hop (cloud LB, proxy, app). A mismatch causes mysterious disconnects every N seconds.
  • Draining. When proxy pods roll, their long-lived connections must drain; when backend pods roll, the proxy must stop picking them as soon as they leave the EndpointSlice (same SIGTERM/preStop story as in Deployments).
  • Edge features. The gateway is the natural place for rate limiting, authentication (JWT validation), request size limits, CORS and WAF rules. That keeps them out of every microservice - see HLD: proxies, LBs and API gateways.
  • Blast radius. One shared Gateway for 200 teams means one bad config can hurt everyone. Larger companies run several Gateways (per domain, or internal vs external) and use allowedRoutes plus RBAC to limit who can attach.

Scenario: "We are still on Ingress NGINX. What do we do?"

It is late 2026. Your company's 40 services are exposed through the community Ingress NGINX controller with lots of annotations. Security asks for a plan.

Weak answer: "It still works, so leave it." (It receives no security fixes since March 2026, and it is the internet-facing component.)

Strong answer: "Inventory every Ingress and annotation. Pick a maintained Gateway API implementation (or a maintained Ingress controller if a fast move is needed). Convert with ingress2gateway, review the annotation gaps by hand, and run the new gateway side by side on a new IP. Shift traffic gradually with DNS weights or by host name, compare error rates and latency, keep the old path ready for rollback, then decommission. Meanwhile, tighten exposure on the old controller (WAF, patch the nodes, restrict snippets annotations)."
