Which front door? LoadBalancer vs Ingress vs Gateway vs mesh

Good to know (SDE-2)

Two direction words first. North-south traffic crosses the cluster edge: from users on the internet into the cluster (and back). East-west traffic stays inside: pod to pod, service to service. Think of a map: the edge is at the top, services sit side by side.

You might confuse this with... a service mesh puts a proxy next to (or on the node of) every pod to handle service-to-service calls: mutual TLS, retries, per-call metrics. A Gateway is one shared entry point at the edge. Many companies run both. Start with a Gateway; add a mesh only when you need its features.

Migrating from Ingress: the SIG Network (the Kubernetes special interest group that owns networking) project ingress2gateway converts Ingress objects (and some common annotations) into Gateway API objects. The statement from the Kubernetes Steering Committee (the project's top-level governance body) is clear that no alternative is a perfect drop-in replacement for Ingress NGINX, so test annotations such as rewrites, timeouts and body-size limits one by one.
