Visibility first: tagging, showback and chargeback

Must know (SDE-1)

You cannot optimise what you cannot attribute. The AWS Well-Architected cost pillar puts "expenditure and usage awareness" before "cost-efficient resources" for exactly this reason. The FinOps Foundation describes the practice as a loop of three phases: Inform (make spend visible and allocated), Optimize (act on it) and Operate (make it a routine with owners, budgets and reviews).

A tagging standard that survives contact with reality

Pick a small set of mandatory tags and enforce them in code. Four keys cover most needs:

  • team - who gets the bill (maps to a cost centre).
  • service - which product or microservice.
  • env - prod, staging, dev. Dev spend is the easiest to cut.
  • owner - a person or alias to ask "is this still needed?".

Set them once at the provider level so every resource Terraform creates inherits them, instead of hoping each module remembers:

provider "aws" {
  region = "ap-south-1"
  default_tags {
    tags = {
      team    = "payments"
      service = "checkout-api"
      env     = "prod"
      owner   = "payments-oncall"
    }
  }
}

Tags only appear in billing data after you activate them as cost allocation tags in the management (payer) account. Activation is not retroactive, so do it on day one:

$ aws ce update-cost-allocation-tags-status \
    --cost-allocation-tags-status TagKey=team,Status=Active TagKey=service,Status=Active
{
    "Errors": []
}

Then ask the bill a question. This groups last month's cost by the team tag (output trimmed; numbers are an example):

$ aws ce get-cost-and-usage \
    --time-period Start=2026-10-01,End=2026-11-01 \
    --granularity MONTHLY --metrics UnblendedCost \
    --group-by Type=TAG,Key=team \
    --query 'ResultsByTime[0].Groups[].[Keys[0],Metrics.UnblendedCost.Amount]' --output text
team$payments     18342.11
team$search       9120.40
team$platform     22781.95
team$             6410.73

That last line, team$ with an empty value, is untagged spend. Driving it toward zero is the first FinOps KPI. Shared costs (the EKS control plane, NAT gateways, a shared Kafka cluster) need an agreed split rule: by requested CPU, by bytes, or evenly.

Showback
  • Easy to start: a weekly report per team
  • Creates awareness without arguments over accounting
  • Good for the first 6-12 months
Chargeback
  • Real budget pressure: teams feel the cost
  • Needs accurate allocation and agreed shared-cost rules
  • Can cause gaming ("move it to the platform team's account")

From your world

Tags are the cloud's version of VLAN tags or DSCP marks used for accounting: a key stamped on every flow so the collector can aggregate by it. An untagged resource is like traffic on the native VLAN - it still flows and still costs, but your per-customer report cannot see it. Separate AWS accounts per team or environment are the stronger tool, the way a separate VRF is stronger than an ACL: billing splits at the account boundary automatically, with no tag discipline needed.

Budgets and anomaly alerts. AWS Budgets can alert when actual or forecast spend crosses a threshold, and Cost Anomaly Detection flags unusual jumps per service or tag. Wire both to the owning team's channel, not to a finance inbox nobody reads.
