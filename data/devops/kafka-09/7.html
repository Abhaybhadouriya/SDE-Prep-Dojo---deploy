Common mistakes and gotchas

You might confuse these:

  • Kafka Connect vs Kafka Streams vs Flink. Connect moves data between Kafka and other systems (databases, S3, Elasticsearch) using configuration, with little or no logic. Kafka Streams processes data from Kafka to Kafka, as a Java library inside your own service. Flink also processes data, but as a separate cluster you submit jobs to, with many sources and sinks beyond Kafka. Rule of thumb: copy = Connect, transform inside a service = Streams, big shared stateful pipelines = Flink.
  • KStream vs KTable. Same topic bytes, different meaning. KStream: every record is a new event, so you count or sum them. KTable: every record replaces the previous value for its key, so you look up "the latest". Reading a payments topic as a KTable would silently keep only each customer's last payment.
  • Source vs sink connector. A source connector writes into Kafka (Debezium reading Postgres). A sink connector reads from Kafka and writes out (to S3 or Elasticsearch). The naming is from Kafka's point of view.
  • Converter vs SMT. A converter turns bytes into Connect records and back (JSON, Avro); an SMT (single message transform) changes one record at a time (rename a field, route to a topic). Format vs content.
