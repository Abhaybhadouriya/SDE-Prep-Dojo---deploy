Remember this

  • Five pod phases only (Pending, Running, Succeeded, Failed, Unknown); CrashLoopBackOff, ImagePullBackOff, OOMKilled are container reasons.
  • Order of tools: get -> describe (Events!) -> logs --previous -> top -> exec/debug.
  • Pending = scheduler (uses requests). ImagePull = runtime + registry. CrashLoop = your process. OOMKilled = kernel cgroup, exit 137. 0/1 Ready = readiness probe.
  • CrashLoopBackOff delay: 10 s doubling to a 5-minute cap, reset after 10 minutes of healthy running.
  • Readiness removes from traffic; liveness restarts. Never put dependency checks in liveness.
  • CPU over limit = throttled (invisible in status). Memory over limit = killed. Node pressure = kubelet eviction.
  • metrics-server = live numbers for kubectl top and HPA. Prometheus = history, PromQL, alerts.
  • Events last about 1 hour; pod logs vanish with the pod. Ship both off the node.
