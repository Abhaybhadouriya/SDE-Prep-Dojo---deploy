Quick quiz

Which of these is an actual pod phase?

  1. CrashLoopBackOff
  2. OOMKilled
  3. Pending
  4. ImagePullBackOff
There are only five phases: Pending, Running, Succeeded, Failed, Unknown. The others are reasons attached to a container's state that kubectl shows in the STATUS column.

A pod is Pending and the event says "2 Insufficient memory", but the nodes are only 30% used. Why?

  1. metrics-server is broken
  2. The scheduler counts memory requests, and existing pods have requested most of it
  3. The kubelet is down
The scheduler never looks at real usage. It adds up the requests of pods already on the node. Over-generous requests make a cluster "full" while it sits idle.

Your pod restarts and kubectl logs POD shows nothing. What do you run next?

  1. kubectl logs POD --previous
  2. kubectl delete pod POD
  3. kubectl top node
The current container may be waiting in back-off and has not logged anything yet. --previous shows the output of the container instance that just crashed.

Exit code 137 means...

  1. The image was not found
  2. A normal SIGTERM shutdown
  3. The process got SIGKILL (128 + 9), often from the OOM killer
Exit codes above 128 mean "killed by signal (code - 128)". 137 - 128 = 9 = SIGKILL. 143 would be SIGTERM.

A pod shows Running, 0/1 Ready. What happens to it?

  1. The kubelet restarts it every 10 seconds
  2. It keeps running but its IP is removed from the Service's endpoints, so it gets no traffic
  3. The scheduler moves it to another node
A failing readiness probe never restarts anything. It only controls whether the EndpointSlice controller lists the pod behind the Service.

Which tool keeps metric history and can fire alerts?

  1. Prometheus
  2. metrics-server
  3. kubectl top
metrics-server only holds the latest values in memory to serve kubectl top and the HPA. Prometheus stores time series and evaluates alert rules.

Every pod on one node suddenly loses network, while the same apps on other nodes are fine. Where do you look first?

  1. The application code
  2. The Deployment YAML
  3. The node: CNI agent, routes and rules, kube-proxy, node Conditions
A failure that follows the node, not the app, points to the node data plane, like the Datadog 2023 incident where policy-routing rules were flushed.
