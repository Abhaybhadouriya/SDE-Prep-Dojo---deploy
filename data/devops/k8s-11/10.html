Common mistakes and gotchas

Good to know (SDE-2)
  1. Forgetting --previous. The current container in back-off has no useful logs. The dead one does.
  2. Reading the top of describe and not the Events at the bottom. The Events section is the scheduler's and kubelet's diary.
  3. Waiting too long. Events expire after about an hour. Copy them into the incident doc early.
  4. Treating kubectl top as monitoring. It is a live snapshot from metrics-server with no history.
  5. Liveness probe that checks the database. When the DB blips, every pod restarts at once: you turned a slow dependency into a full outage.
  6. Same probe for liveness and readiness with the same thresholds. The pod gets killed before it is ever taken out of rotation gently.
  7. CPU limits on latency-sensitive services causing throttling that never shows in any status. Many teams set CPU requests and leave CPU limits off; memory limits stay on.
  8. Debugging the pod when the node is the problem. If all pods on one node fail, run kubectl describe node and look at Conditions (MemoryPressure, DiskPressure, NetworkUnavailable, Ready).
  9. App listening on 127.0.0.1. Works inside the pod, unreachable from outside.
  10. Logs to files inside the container. Not collected, lost on restart, fill the disk.
