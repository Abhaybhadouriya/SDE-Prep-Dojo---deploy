Quiz

You pin a Git-sourced module with version = "2.3.0". What happens?

  1. Terraform downloads tag v2.3.0
  2. Terraform downloads the latest 2.x tag
  3. It does not work: version only applies to registry sources; use ?ref=v2.3.0
  4. It pins the provider instead
The version argument is only for registry modules. Git sources are pinned with the ref query parameter in the source URL.

Why are CLI workspaces a weak choice for separating dev and prod?

  1. They cannot have separate state files
  2. They share one backend and one set of credentials, so there is no access isolation
  3. They only work with local state
  4. They are deprecated
Each workspace has its own state, but the backend and credentials are shared. HashiCorp says workspaces are not appropriate when deployments need separate credentials and access controls.

A nightly job runs terraform plan -detailed-exitcode. Which exit code means drift or pending changes?

  1. 0
  2. 1
  3. 127
  4. 2
0 = no changes, 1 = error, 2 = success with a non-empty diff.

Someone opened port 22 in the console, and the team agrees it should stay. What is the cleanest fix?

  1. Add the rule to the code via a PR so the plan shows no changes
  2. Run terraform apply immediately
  3. Delete the state file
  4. Run terraform apply -target on the security group
Codify the change so git, state and the cloud agree. A plain apply would revert the rule.

What is the main reason to apply a saved plan file in CI instead of running a fresh terraform apply?

  1. It is faster
  2. It skips the state lock
  3. It applies exactly the reviewed changes, and is rejected if state changed since
  4. It hides secrets
A saved plan guarantees reviewed == applied, and Terraform refuses a stale plan. Note it actually contains secrets, so store it carefully.

A database has prevent_destroy = true. A PR deletes the whole resource block. What happens on apply?

  1. Terraform errors because of prevent_destroy
  2. The database is destroyed, because the lifecycle setting was removed with the block
  3. Terraform ignores the missing block
  4. AWS refuses automatically in all cases
Lifecycle settings live in config. Removing the block removes the protection. Pair it with provider deletion protection and policy checks.

You moved aws_instance.web into module.web. The plan shows destroy + create. What prevents that?

  1. -target
  2. ignore_changes
  3. terraform refresh
  4. A moved block from the old address to the new one
A moved block tells Terraform the object just changed address, so it updates state instead of replacing the instance.
