Gotchas that bite in production

  • Refactors look like destroys. Moving a resource into a module changes its address from aws_instance.web to module.web.aws_instance.this. Without a moved block, the plan says destroy + create. Always read refactor plans for - lines.
  • count index shifts. Removing item 0 from a count list renumbers every later item, so Terraform replaces them all. Prefer for_each over a map with stable keys.
  • Workspace confusion. terraform workspace show before every manual command, or better, do not use workspaces for prod.
  • Saved plans leak secrets. Treat tfplan and plan.json as secrets; mark variables sensitive so they are at least masked in text output.
  • Module upgrades change many things at once. A minor version bump of a community module can add tags to 200 resources; that is noise that hides the one real change. Upgrade modules in their own PR.
  • Provider upgrades change defaults. Pin providers with ~> and commit .terraform.lock.hcl; upgrade on purpose with terraform init -upgrade.
  • Two stacks, one object. If two states manage the same security group rule, they will fight forever and each plan shows drift. One object, one owner.
  • Long plans hit API rate limits. A state with thousands of resources can take many minutes to refresh and get throttled. Split it.
