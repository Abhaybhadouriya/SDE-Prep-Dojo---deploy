Common mistakes and gotchas

Good to know (SDE-2)
MistakeWhat happensDo this instead
Running Kafka or a DB as a Deployment with one PVCReplicas fight over one disk (Multi-Attach) or share data they should notStatefulSet or operator: one PVC per replica
Forgetting the headless Service / serviceNamePods get no per-pod DNS names; peers cannot find each otherCreate it first, with clusterIP: None
Force-deleting a StatefulSet pod on an unreachable nodePossible two writers with one identity: data corruptionConfirm the node is gone (or use the out-of-service taint) first
Expecting kubectl delete sts to free disksPVCs (and cloud disks) remain and cost moneyDelete PVCs explicitly, or set a retention policy
Editing volumeClaimTemplates to grow disksThe API rejects most changes to the templateExpand each PVC directly (if the class allows), or let the operator do it
Deleting a CRD to "clean up"Every custom resource of that kind is deleted too - for Strimzi, the operator then removes your clusters' resourcesTreat CRDs as cluster infrastructure; never delete casually
Hand-editing objects an operator ownsThe next reconcile reverts your changeChange the CR; the operator is the source of truth
Advertising internal addresses to external Kafka clientsBootstrap works, then every produce fails to connectExternal listener with per-broker addresses
Adding brokers and expecting load to spreadNew brokers sit emptyRebalance partitions (KafkaRebalance / Cruise Control)
