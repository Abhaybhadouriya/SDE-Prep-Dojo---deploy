Why stateful apps break the Deployment model

Must know (SDE-1)

A Deployment assumes three things that are false for Kafka brokers, databases and ZooKeeper-style quorums:

  1. "Any pod is as good as another." False: broker 1 leads some partitions and follows others; clients and the other brokers talk to that specific broker.
  2. "Pods can share or forget storage." False: each broker has its own log directory with its own partitions. Losing it means copying all of it again over the network.
  3. "Pods can start and stop in any order, with random names." False: many clustered systems need a stable identity in their config (a node ID), and some need members to come up one at a time.

From your world

Think of predictable interface names. Old Linux could call a NIC eth0 on one boot and eth1 on the next, which broke configs; udev's stable names (enp3s0) fixed that by tying the name to a physical slot. A StatefulSet does the same for pods: the name is tied to an ordinal "slot", and the slot owns a disk. Where this breaks: the slot is logical, not physical - kafka-1 may run on a different node each time, and only its disk and name come along.

"Why are there so many controllers?" - pick one in 10 seconds

Every workload controller answers the same question differently: "how many copies, where, and for how long?" Once you see that, the list stops looking random. Ask yourself three things: does it run forever or finish? Does each copy need its own identity and disk? Must it run on every node?

From your world

A DaemonSet is the "one agent process on every line card" pattern: a new card is inserted, the agent starts on it automatically. A Job is a one-shot script (like a firmware upgrade task) that must finish with exit code 0. A Deployment is a pool of identical workers; a StatefulSet is a set of HA peers that each own their own config and state.

Say it like this: "Deployment for stateless, StatefulSet when each replica needs a stable identity and its own disk, DaemonSet for one-per-node agents, Job or CronJob for work that finishes. I never create a bare ReplicaSet."
