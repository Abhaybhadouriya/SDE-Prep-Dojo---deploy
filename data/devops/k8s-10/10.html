Quick quiz

A StatefulSet named db with a claim template named data has 3 replicas. What is the PVC of the second pod called?

  1. db-data-2
  2. data-db-2
  3. data-db-1
  4. A random name
Ordinals start at 0, so the second pod is db-1, and the claim is <template>-<pod> = data-db-1.

With the default OrderedReady policy, when is db-1 created?

  1. After db-0 is Running and Ready
  2. At the same time as db-0
  3. After db-2
Ordered creation waits for each previous pod to be Ready. Parallel would create them together.

What does a headless Service (clusterIP: None) give a StatefulSet?

  1. A load-balanced virtual IP
  2. A DNS record per pod, such as db-1.db-headless
  3. An external load balancer
DNS returns pod IPs directly and each pod gets a stable name, so peers and clients can address one specific member.

A node with kafka-1 becomes unreachable. After 10 minutes, where is kafka-1?

  1. Recreated on another node after 5 minutes
  2. Recreated immediately
  3. Deleted along with its PVC
  4. Not recreated until the old pod is confirmed gone
StatefulSets guarantee at most one pod per identity, so they wait for proof the old one stopped (node back, node deleted, out-of-service taint, or a fenced force delete).

You install a CRD and create a custom resource, but nothing happens. Why?

  1. CRDs only work in kube-system
  2. The API server rejected it
  3. No controller (operator) is watching and acting on that resource
A CRD only defines and stores a new type. Behaviour comes from a controller's reconcile loop.

In Strimzi, which resource creates the topic orders?

  1. A ConfigMap
  2. A KafkaTopic CR handled by the Topic Operator
  3. The Kafka CR's listeners
The Entity Operator runs the Topic Operator, which turns KafkaTopic resources into real topics inside Kafka.

Which was a reason Strimzi replaced StatefulSets with StrimziPodSets?

  1. StatefulSets can only remove the highest-ordinal pod and give all pods one identical template
  2. StatefulSets cannot use PVCs
  3. StatefulSets cannot run on more than one node
Kafka needs per-broker config and the ability to retire a specific broker; StatefulSets made both awkward.

"Level-triggered" reconciliation means the controller...

  1. Only acts on the exact event it received
  2. Runs at a fixed priority level
  3. Compares the whole current state with the desired state each time, so missed events do not matter
It reacts to state, not to edges. That is why reconcile must be idempotent and why periodic resyncs work.
