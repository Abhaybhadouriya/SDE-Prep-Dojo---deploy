Quick quiz

A node has 4 CPUs; pods on it request 3.5 CPUs but are actually using 1 CPU. A new pod requests 1 CPU. Can it be scheduled there?

  1. Yes, 3 CPUs are idle
  2. No, only 0.5 CPU is unrequested
  3. Yes, if it has no limit
The scheduler adds up requests, not usage. This is why oversized requests waste money.

A container goes over its CPU limit. What happens?

  1. OOMKilled
  2. Evicted from the node
  3. Throttled until the next CFS period
  4. Nothing
CPU is compressible: the CFS quota pauses the cgroup's threads. Memory over limit is what kills.

Every container in a pod has requests equal to limits for CPU and memory. QoS class?

  1. Guaranteed
  2. Burstable
  3. BestEffort
Guaranteed requires requests == limits for both resources in every container. Guaranteed pods are evicted last.

You taint GPU nodes and give ML pods a matching toleration. ML pods still land on normal nodes. Why?

  1. The taint is wrong
  2. Tolerations are ignored for Jobs
  3. The scheduler is broken
  4. A toleration only allows entry; you also need node affinity
Taints repel; tolerations un-repel. Attraction needs nodeAffinity or a nodeSelector.

HPA target is 50% CPU; 6 pods average 75%. Desired replicas?

  1. 8
  2. 9
  3. 12
  4. 6, within tolerance
ceil(6 x 75 / 50) = ceil(9) = 9. The ratio 1.5 is well outside the 10% tolerance.

What signal makes the Cluster Autoscaler add a node?

  1. Node CPU above 80%
  2. HPA reaching maxReplicas
  3. Pods that are Pending because they do not fit
  4. A cron schedule
It simulates whether Pending pods would fit on a new node of some group. Busy-but-fitting nodes do not trigger it.

A topic has 8 partitions. KEDA scales the consumer group to 12 pods. What do the extra 4 pods do?

  1. Sit idle with no partitions assigned
  2. Double the throughput
  3. Read duplicates
Within one group each partition goes to one consumer. Cap maxReplicaCount at the partition count.

An HPA shows cpu: <unknown>/60%. Most likely cause?

  1. The Deployment has too many replicas
  2. metrics-server is missing or the pods have no CPU request
  3. The cluster has no nodes
Utilization is a percentage of the request; with no request (or no metrics API) the HPA cannot compute.
