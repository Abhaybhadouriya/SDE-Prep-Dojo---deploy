PV, PVC and StorageClass - three objects, three owners

Must know (SDE-1)

Kubernetes splits storage into objects owned by different people, so that an app developer never needs to know which storage array exists:

  1. StorageClass (cluster admin writes it) A recipe: "disks of this kind come from this CSI driver, with these parameters". Example: fast-ssd = AWS EBS gp3. Cluster-scoped.
  2. PersistentVolumeClaim (app developer writes it) A request in a namespace: "I want 20 GiB, ReadWriteOnce, from class fast-ssd". The pod refers to the claim by name, never to the disk.
  3. PersistentVolume (created by the system, or by an admin) The real disk as a Kubernetes object: its size, access modes, which driver owns it and its volume ID (for example vol-0abc...). Cluster-scoped. Bound one-to-one to a claim.

You might confuse this with... a PV and a PVC sound alike. PV = the thing (the locker). PVC = the request (the form). Pods use PVCs. Admins and drivers make PVs. PVs have no namespace; PVCs do. If you remember only one sentence: "Pods claim, PVs supply."
