Common mistakes and gotchas

Good to know (SDE-2)
SymptomLikely causeFix
PVC stuck Pending, no pod yetNormal with WaitForFirstConsumerCreate the pod; it binds then
PVC Pending, pod existsNo default StorageClass, wrong class name, driver not installed, access mode the driver cannot do (RWX on a block disk)kubectl describe pvc Events; kubectl get sc; check driver pods
Pod Pending: "volume node affinity conflict"Disk is in another zone than every node with roomWaitForFirstConsumer; capacity in that zone; spread replicas per zone
Multi-Attach error during a Deployment rolloutA Deployment with one RWO PVC: the new pod lands on another node while the old pod still holds the diskUse strategy: Recreate for single-replica stateful Deployments, or a StatefulSet
Pod stuck ContainerCreating after its node diedDisk still attached to the dead node (ReadWriteOnce). The attach/detach controller only force-detaches after a safety wait of about 6 minutes, and only once the pod is goneConfirm the VM is really off, then add the taint node.kubernetes.io/out-of-service=nodeshutdown:NoExecute (non-graceful node shutdown, GA in 1.28; see page 10) or delete the Node object. Volumes are then detached and the pod can start elsewhere
PVC stuck TerminatingA pod still uses it (pvc-protection finalizer)Find and delete the pod; do not just strip finalizers
Data gone after deleting a namespacereclaimPolicy: Delete on the classRetain for precious data, plus snapshots and real backups
Slow pod start on big volumesRecursive chown from fsGroupfsGroupChangePolicy: OnRootMismatch
Config file in volume never updatesMounted with subPathMount the whole directory instead
 
$ kubectl describe pod web-6d9f7c-xk2lp | tail -4
Events:
  Type     Reason              Age   From                     Message
  ----     ------              ----  ----                     -------
  Warning  FailedAttachVolume  25s   attachdetach-controller  Multi-Attach error for volume "pvc-7f3a..." Volume is already used by pod(s) web-6d9f7c-abcde

That Multi-Attach event is the single most common storage error beginners hit. Read the From column: it names the process (the attach/detach controller) - which tells you this is an attach problem, not a mount or filesystem problem.
