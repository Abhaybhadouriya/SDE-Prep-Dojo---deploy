Tuning recipes: durability, throughput, latency

There is no single "best" config. Name the goal first, then pick the knobs. Always confirm with a measurement (kafka-producer-perf-test.sh, shown in the lab).

The ranges above are common starting points, not laws. The direction of each knob is what you must know cold:

Raising linger.ms / batch.size / compression
  • Fewer, bigger requests; far less broker CPU per record
  • Less network and disk (compressed end to end)
  • Higher peak throughput per producer
The price
  • Up to linger.ms extra latency when traffic is light
  • More memory held in the accumulator
  • Compression costs producer and consumer CPU

The cheapest big win on most busy producers: give records the right key (or no key, so sticky batching works), set compression.type to lz4 or zstd, and raise linger.ms a little. Measure before and after. Deeper broker-side tuning is on page 11.
