What a container really is

Now the real words. There are only four you need today:

  • Image - a read-only package that contains a program's files: the program itself, its libraries, its settings. An image sits on disk and does nothing. It is a frozen template.
  • Container - a running copy of an image. When you "run an image", Docker starts a process from it and gives that process its own private, writable space on top of the frozen files.
  • Docker - the tool (a command called docker plus a background service called dockerd) that builds images, downloads them and starts containers.
  • Registry - an online shelf of images, such as Docker Hub. You download (pull) images from it and upload (push) your own.

From your world

Image vs container is ELF binary vs running process. /usr/bin/nginx on disk is like an image: it does nothing until you run it. Run it five times and you get five processes, each with its own memory, all reading the same file. Run one image five times and you get five containers, each with its own writable layer, all sharing the same read-only image files. Where it breaks: an image also carries a whole root filesystem (libraries, /etc files), not just one executable.

Your first container

Type these yourself. The --rm flag deletes the container when it exits, and -it gives you an interactive terminal.

docker run --rm -it alpine:3.24 sh

Docker downloads the tiny Alpine Linux image (a few megabytes) the first time, then drops you into a shell inside the container. Now look around:

/ # ps
PID   USER     TIME  COMMAND
    1 root      0:00 sh
    7 root      0:00 ps
/ # hostname
5c1e0a9d7b31
/ # cat /etc/os-release | head -2
NAME="Alpine Linux"
ID=alpine
/ # uname -r
6.8.0-45-generic
/ # exit

Four tiny facts, four big lessons:

  1. Your shell is PID 1. The container sees only its own processes. Your laptop has hundreds of processes, but inside the container there are just two. This is the PID namespace at work.
  2. The hostname is a random ID. The container has its own hostname, separate from your computer's. This is the UTS namespace.
  3. It says "Alpine Linux". The files you see (/etc, /bin) come from the Alpine image, even if your computer runs Ubuntu. This is the mount namespace plus the image's filesystem.
  4. But uname -r shows the host's kernel version. There is no Alpine kernel here. The container borrows the one and only kernel of the machine. On Docker Desktop you will see the kernel of its small Linux VM, for example a version ending in -microsoft-standard-WSL2 on Windows. That single line is the whole "container vs VM" story.

Try this: open two terminals and run docker run --rm -it alpine:3.24 sh in both. Create a file with touch /hello in one. It does not appear in the other. Same image, two separate containers, two separate writable layers.

A web server in one line

docker run -d --name web -p 8080:80 nginx:1.30
curl -s http://localhost:8080 | head -4
docker ps
docker stop web && docker rm web
$ docker run -d --name web -p 8080:80 nginx:1.30
Unable to find image 'nginx:1.30' locally
1.30: Pulling from library/nginx
...
Status: Downloaded newer image for nginx:1.30
8d3f1c2a9e4b7f60c1d2e3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2b3c4
$ curl -s http://localhost:8080 | head -4
<!DOCTYPE html>
<html>
<head>
<title>Welcome to nginx!</title>
$ docker ps
CONTAINER ID   IMAGE        COMMAND                  STATUS         PORTS                                   NAMES
8d3f1c2a9e4b   nginx:1.30   "/docker-entrypoint.…"   Up 6 seconds   0.0.0.0:8080->80/tcp, [::]:8080->80/tcp   web

What each flag means: -d runs it in the background (detached), --name web gives it a friendly name, and -p 8080:80 publishes a port, meaning "connect port 8080 on my computer to port 80 inside the container". You just ran a real web server without installing nginx on your machine. When you remove the container, nothing is left behind on your system except the downloaded image.
