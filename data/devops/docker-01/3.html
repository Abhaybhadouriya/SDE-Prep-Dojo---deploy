Container vs virtual machine, side by side

This is the single most asked Docker question for beginners, so let us draw it properly. Read each stack from the bottom up. Watch the boot bars: each one is a rough picture of how long the thing takes to become ready.

QuestionVirtual machineContainer
What is isolated?A whole computer: virtual CPU, memory, disk, NIC, its own kernelA process: its view of files, PIDs, network, hostname, users
Who enforces it?The hypervisor using CPU features (Intel VT-x, AMD-V, nested page tables)The host kernel using namespaces, cgroups, seccomp, capabilities
KernelOne per VMShared by every container on the host
Typical sizeGigabytesA few MB (Alpine base is under 10 MB) to hundreds of MB
Start time (typical)Seconds to tens of secondsTens to hundreds of milliseconds
Run a different OS?Yes: Windows VM on a Linux host is fineMust match the host kernel: Linux containers need a Linux kernel
Isolation strengthStrong: a guest kernel bug stays in that VMWeaker: a host kernel bug affects every container

Common confusion: "Docker on my Mac runs Linux containers, so containers can run any OS." No. Docker Desktop quietly runs a small Linux VM, and your containers share that VM's kernel. Windows containers also exist, but they need a Windows kernel. A container can never bring its own kernel.
