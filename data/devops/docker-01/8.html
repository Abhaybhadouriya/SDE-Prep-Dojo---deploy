Common mistakes and gotchas

  1. Treating a container like a small VM. People install SSH, cron and five services in one container. A container should run one main process. Need a shell? Use docker exec -it web sh, which joins the running container's namespaces with the setns() system call.
  2. Saving important data inside the container. Files you write go into the container's writable layer. docker rm throws that layer away. Put databases and uploads on a volume.
  3. Using localhost to reach another container. Inside a container, localhost means that container itself, because it has its own network namespace. Reach other containers by name on a shared network (page 05).
  4. App listening on 127.0.0.1 inside the container. Then -p 8080:80 forwards traffic to eth0, where nobody is listening. Bind your server to 0.0.0.0 inside the container.
  5. Building on an Apple Silicon Mac and deploying to an x86 server. The image contains ARM64 machine code, and the server cannot run it (exec format error). Containers share the kernel, but they do not emulate the CPU. Build for the target platform (--platform linux/amd64) or build multi-arch images (page 09).
  6. Thinking "container" means "secure". Root in a container is UID 0 on the host unless user namespaces are on. Run as a non-root user and never use --privileged in production.
