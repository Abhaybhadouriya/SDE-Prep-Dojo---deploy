Quick quiz

Inside an Alpine container on an Ubuntu host, what does uname -r show?

  1. An Alpine kernel version
  2. Nothing, containers have no kernel
  3. The host's kernel version
Containers share the host kernel, so the kernel version is the host's even though the files in /etc say Alpine.

Which kernel feature decides what a container can see?

  1. Namespaces
  2. cgroups
  3. The hypervisor
Namespaces control visibility (files, PIDs, network, hostname). cgroups control how much CPU and memory it can use.

A container with --memory=64m tries to allocate 200 MB. What happens?

  1. It gets slower
  2. The OOM killer kills it and it exits with 137
  3. Docker gives it more memory automatically
Going over memory.max triggers the kernel OOM killer: SIGKILL, so exit code 128 + 9 = 137.

What happens when a container uses more CPU than its --cpus=0.5 limit allows?

  1. It is killed
  2. It is throttled and runs slower
  3. The host crashes
CPU limits are enforced by the scheduler's bandwidth control. The cgroup waits for the next period; nothing is killed.

Which program actually creates the namespaces and cgroup for a Docker container?

  1. The docker CLI
  2. The registry
  3. runc
The CLI only sends an API call. dockerd and containerd coordinate, and runc is the low-level runtime that calls the kernel and then exits.

Your app logs "listening on 127.0.0.1:3000" inside a container started with -p 3000:3000, and you cannot reach it. Why?

  1. 127.0.0.1 is the container's own loopback; traffic arrives on eth0
  2. Port 3000 is blocked by Docker
  3. Containers cannot use TCP
The container has its own network namespace. Published ports forward to the container's eth0 address, so the app must listen on 0.0.0.0.

What is the best tool for running untrusted code from strangers on shared servers?

  1. A plain container with root inside
  2. A sandbox like gVisor or a microVM like Firecracker
  3. Running it directly on the host
Plain containers share the kernel. Sandboxes and microVMs add a much stronger boundary, which is why AWS Lambda uses Firecracker.
