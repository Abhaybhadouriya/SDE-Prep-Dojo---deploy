Pattern 1: CloudWatch Logs subscription to Lambda (security signals)

Must know (SDE-1)

Your services write logs to a CloudWatch Logs log group. A subscription filter on that group says "send every log event that matches this pattern to this destination, in near real time". The destination can be Lambda, Kinesis Data Streams, Data Firehose or OpenSearch. When the destination is Lambda, the function receives a JSON event like {"awslogs": {"data": "..."}} where data is base64 of gzip of JSON.

From your world

A subscription filter is a port mirror (SPAN) with an ACL in front. The switch (CloudWatch Logs) keeps forwarding traffic normally; a copy of matching frames goes to an analyser port (Lambda). The filter pattern is your match rule, like a tcpdump BPF expression or an iptables -m string match. And the decode step (base64, then gunzip, then JSON) is exactly what you would do with a compressed capture before you can read the headers.

Wire it up

Two commands: allow CloudWatch Logs to invoke the function, then create the filter. The --source-arn limits the permission to one log group, which protects you from the "confused deputy" problem (another account's logs calling your function).

# 1. Let the CloudWatch Logs service invoke the function, only for this log group
aws lambda add-permission \
  --function-name auth-log-parser \
  --statement-id cwlogs-prod-auth \
  --principal logs.amazonaws.com \
  --action lambda:InvokeFunction \
  --source-arn "arn:aws:logs:us-east-1:111122223333:log-group:/prod/auth:*" \
  --source-account 111122223333

# 2. Send only failed SSH logins (from /var/log/secure) to the function
aws logs put-subscription-filter \
  --log-group-name /prod/auth \
  --filter-name security-signals \
  --filter-pattern '"Failed password"' \
  --destination-arn arn:aws:lambda:us-east-1:111122223333:function:auth-log-parser

# 2b. Failed console logins are CloudTrail events, so they live in the CloudTrail log group
aws logs put-subscription-filter \
  --log-group-name /aws/cloudtrail/org \
  --filter-name console-login-failures \
  --filter-pattern '{ $.eventName = "ConsoleLogin" && $.responseElements.ConsoleLogin = "Failure" }' \
  --destination-arn arn:aws:lambda:us-east-1:111122223333:function:auth-log-parser

# 3. Check it
aws logs describe-subscription-filters --log-group-name /prod/auth
{
    "subscriptionFilters": [
        {
            "filterName": "security-signals",
            "logGroupName": "/prod/auth",
            "filterPattern": "\"Failed password\"",
            "destinationArn": "arn:aws:lambda:us-east-1:111122223333:function:auth-log-parser",
            "distribution": "ByLogStream",
            "creationTime": 1763891200000
        }
    ]
}

Two sources, two patterns: the OS auth log only ever contains sshd lines, while ConsoleLogin is a CloudTrail event, so it is matched with a JSON pattern on the CloudTrail log group. In plain-text patterns a ? prefix means "OR" (?"Failed password" ?"Invalid user"). Quotas worth knowing: at most 2 subscription filters per log group; an account-level subscription filter can cover many log groups at once; and when more consumers need the same stream, send it to Kinesis Data Streams or Firehose and fan out from there. An empty pattern "" means "send everything", which is fine for a small group and expensive for a busy one.

The handler: decode, parse, enrich, emit

This Python handler decodes the payload, finds failed SSH logins, enriches each one with the source IP, and emits a metric using the Embedded Metric Format (EMF): a JSON log line with an _aws block that CloudWatch turns into a real metric for you. No PutMetricData API call is needed, so no extra latency or throttling.

import base64, gzip, json, re, time, os
import boto3

SNS = boto3.client("sns")             # created once per environment, reused when warm
TOPIC = os.environ["ALERT_TOPIC_ARN"]
FAILED = re.compile(r"Failed password for (invalid user )?(?P<user>\S+) from (?P<ip>[\d.]+)")

def handler(event, context):
    raw = gzip.decompress(base64.b64decode(event["awslogs"]["data"]))
    batch = json.loads(raw)
    if batch["messageType"] == "CONTROL_MESSAGE":   # reachability probe from CW Logs
        return {"skipped": "control"}

    per_ip = {}
    for ev in batch["logEvents"]:
        m = FAILED.search(ev["message"])
        if m:
            per_ip[m["ip"]] = per_ip.get(m["ip"], 0) + 1

    # One EMF line = one metric datapoint, dimension = log group
    print(json.dumps({
        "_aws": {"Timestamp": int(time.time() * 1000),
                 "CloudWatchMetrics": [{"Namespace": "Security",
                                        "Dimensions": [["LogGroup"]],
                                        "Metrics": [{"Name": "FailedSshLogins", "Unit": "Count"}]}]},
        "LogGroup": batch["logGroup"],
        "FailedSshLogins": sum(per_ip.values()),
    }))

    noisy = {ip: n for ip, n in per_ip.items() if n >= 20}
    if noisy:
        SNS.publish(TopicArn=TOPIC, Subject="Possible SSH brute force",
                    Message=json.dumps({"logGroup": batch["logGroup"], "ips": noisy}))
    return {"events": len(batch["logEvents"]), "ips": len(per_ip)}

Test locally by faking the payload the same way CloudWatch builds it:

python - <<'EOF'
import base64, gzip, json
doc = {"messageType": "DATA_MESSAGE", "logGroup": "/prod/auth", "logStream": "i-0abc",
       "logEvents": [{"id": "1", "timestamp": 0,
                      "message": "sshd[811]: Failed password for root from 203.0.113.9 port 52811 ssh2"}]}
print(json.dumps({"awslogs": {"data": base64.b64encode(gzip.compress(json.dumps(doc).encode())).decode()}}))
EOF
{"awslogs": {"data": "H4sIAAAAAAAC/0WOy2rDMBBFf2WYdQK2..."}}

Paste that JSON into aws lambda invoke --payload (with --cli-binary-format raw-in-base64-out) or a console test event, and you should see {"events": 1, "ips": 1} plus one EMF line in the function's own log group.

Never subscribe a function to its own log group (or to a group that receives its output). The function logs, the log triggers the function, the function logs again: an infinite loop that bills you for every turn.
