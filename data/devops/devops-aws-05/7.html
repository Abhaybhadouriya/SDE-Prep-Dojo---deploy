Retries, DLQs and destinations: never lose a log line silently

Must know (SDE-1)

Every source gives you at-least-once delivery. So the two rules are: make processing idempotent (same input twice gives the same result, for example by keying writes on the log event ID or the S3 object key + ETag), and always configure somewhere for failures to land.

# Async sources: fewer retries, shorter age, and a destination with the error details
aws lambda put-function-event-invoke-config \
  --function-name auth-log-parser \
  --maximum-retry-attempts 1 \
  --maximum-event-age-in-seconds 3600 \
  --destination-config '{"OnFailure":{"Destination":"arn:aws:sqs:us-east-1:111122223333:auth-parser-failed"}}'

Alarm on the DLQ, not just on errors. ApproximateNumberOfMessagesVisible > 0 on a DLQ is the "problem letters box is not empty" signal. A DLQ nobody watches is just a slower way of losing data. The metrics and monitoring design shows where those alarms fit.
