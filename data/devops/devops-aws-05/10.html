Gotchas from production

  1. Recursive loops. A function that logs into the group it subscribes to, or writes into the S3 prefix that triggers it. Separate inputs and outputs by group, bucket or prefix.
  2. SQS visibility timeout shorter than the function timeout. Messages reappear mid-processing and run twice. Keep it several times the function timeout.
  3. Throwing on a whole batch. One bad line retries hundreds of good ones (and with Kinesis, blocks the shard). Use partial batch responses and bisect.
  4. Unbounded Kinesis retries. The default MaximumRetryAttempts is -1 (forever until the record expires). One poison record can stall a shard for the full retention. Always cap it and set an on-failure destination.
  5. Forgetting the CONTROL_MESSAGE. CloudWatch Logs sometimes sends a reachability probe; treat it as a no-op instead of a parse error.
  6. One log storm starves the account. Use reserved concurrency (and SQS MaximumConcurrency) for heavy functions so critical APIs keep their share.
  7. Downstream gets flattened. Lambda scales faster than your OpenSearch or database. Cap concurrency to what the sink can take; that is backpressure by configuration.
  8. Creating clients inside the handler. Create SDK clients and compile regexes at module level so warm invocations reuse them.
