What Lambda is, in one picture

Must know (SDE-1)

A Lambda function is a piece of code (Python, Node.js, Java, Go and more) plus settings (memory, timeout, permissions). You do not start it yourself. An event starts it: "a file landed in S3", "new log lines arrived", "100 records are waiting in a stream". AWS finds or creates an execution environment (a tiny, isolated micro-VM with your code loaded), calls your handler(event, context) function with the event as JSON, and bills you per millisecond of run time and per request.

  • Cold start: the first call in a new environment must boot it and run your init code (imports, clients). Later calls reuse the warm environment, so globals such as an SDK client survive between calls.
  • Stateless: you cannot count on the same environment being used again. Anything that must last goes to S3, DynamoDB, CloudWatch or a queue.
  • Limits: memory from 128 MB to 10,240 MB (CPU grows with memory; about 1 vCPU at 1,769 MB), a timeout of at most 15 minutes (900 s) per invocation, /tmp of 512 MB by default (configurable up to 10,240 MB), a 6 MB synchronous payload and 1 MB asynchronous payload. Check the quotas page for the current numbers; they do change.

From your world

Think of a Lambda handler like an interrupt handler plus a work queue. The event is the interrupt: it arrives, the kernel (AWS) picks a CPU (an execution environment), runs a short handler, and returns. Just like a top half, you keep it short, you do not block forever, and you do not keep state on the stack between interrupts. The "warm environment" is like a cached, already-initialised worker thread in a kernel workqueue: reusing it avoids the setup cost.
