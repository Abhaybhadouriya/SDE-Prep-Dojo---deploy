Concurrency: how many copies run at once

Good to know (SDE-2)

Concurrency = the number of execution environments busy at the same moment. A simple rule (it is Little's law): concurrency = invocations per second x average duration in seconds. 200 invocations per second that each take 0.5 s need about 100 concurrent environments.

  • Account limit: by default 1,000 concurrent executions per Region, shared by all functions (new accounts may start lower). One noisy function can starve the rest.
  • Reserved concurrency: guarantees a function a slice and also caps it. Setting it to 0 is an emergency "stop" switch.
  • Scaling rate: each function can add up to 1,000 execution environments every 10 seconds.
  • Per source: a Kinesis ESM runs one batch per shard at a time, times ParallelizationFactor; 100 shards x factor 2 = up to 200 concurrent invokes. An SQS ESM starts with 5 concurrent invokes and adds up to 300 per minute, up to 1,250 by default; its MaximumConcurrency setting (2 to 1,000) caps one queue so it cannot eat the account.

From your world

Concurrency limits are admission control, like a token bucket on an interface or a listen backlog on a socket. Reserved concurrency is a guaranteed queue in a QoS scheduler (CBWFQ with a bandwidth guarantee): the class gets its share, and cannot take more. Throttling is a tail drop that the sender (async queue or SQS) will retransmit later.
