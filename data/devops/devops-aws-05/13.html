Quick quiz

How does a CloudWatch Logs subscription deliver log data to a Lambda function?

  1. As plain text lines in the event body
  2. As base64-encoded, gzip-compressed JSON in awslogs.data
  3. As a pointer to an S3 object
  4. Through an SQS queue the function polls
The function must base64-decode, gunzip, then parse JSON with logGroup, logStream and logEvents.

For an SQS-triggered function, where should the dead-letter queue be configured?

  1. On the Lambda function's async settings
  2. In the event source mapping's on-failure destination
  3. As a redrive policy on the source SQS queue
  4. Nowhere, SQS never fails
With SQS, the queue owns retries; after maxReceiveCount the redrive policy moves the message to its DLQ.

A function averages 300 ms and receives 500 invocations per second. About how much concurrency does it need?

  1. 150
  2. 500
  3. 1,500
  4. 30
Little's law: 500 per second x 0.3 s = 150 concurrent executions.

Which setting stops one bad Kinesis record from blocking a shard for the whole retention period?

  1. A larger BatchSize
  2. A longer batching window
  3. More memory
  4. A finite MaximumRetryAttempts with an on-failure destination (plus bisect)
The default is infinite retries until the record expires; capping retries lets the poller move on and record the failure.

A VPC-attached Lambda in a private subnet cannot reach the SNS API. The best fix is:

  1. Give the function more memory
  2. Add an interface VPC endpoint for SNS (or a NAT gateway route)
  3. Open all ports in the network ACL
  4. Move the database to a public subnet
The ENI has no public IP, so public AWS endpoints need a NAT gateway or a private VPC endpoint.

Which workload is the weakest fit for Lambda?

  1. Parsing nightly ALB log files from S3
  2. Alerting on rare root console logins
  3. A 24 x 7 stream at very high steady volume needing hour-long session windows
  4. Enriching a few thousand log events per minute
High steady volume plus long-lived state points to a long-running stream processor such as Flink or Kafka Streams on containers.

Why should SDK clients be created outside the handler function?

  1. Warm invocations reuse them, saving setup time on every call
  2. Lambda forbids network calls inside the handler
  3. It makes the function stateful across all environments
Module-level code runs once per execution environment; warm calls skip it.
