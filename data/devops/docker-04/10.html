Common mistakes and gotchas

Mistakes beginners make
  • Container exits instantly. The main process finished (or crashed). Check docker logs and docker ps -a for the exit code. A container is not a VM; it does not "stay on" without a running process.
  • Editing files inside with docker exec and expecting them to survive a re-create. Changes in the writable layer die with the container. Put config in the image or a volume.
  • docker stop always takes 10 s. Shell-form CMD or no SIGTERM handler. Use exec form and handle the signal.
  • Using :latest and being surprised when a new pull changes behaviour. Pin a version tag (or a digest).
  • No memory limit on a shared host, so one leak takes down the neighbours.
  • Unrotated logs fill /var/lib/docker.
Habits that save you
  • Always --name things you keep, and --rm things you do not.
  • First debug step: docker ps -a, then docker logs, then docker inspect (exit code, OOMKilled).
  • Log to stdout/stderr only, never to files inside the container.
  • Set --memory, --cpus and --pids-limit on anything long-lived.
  • Use --init for apps that spawn children.
  • Run docker system df once a week on build machines.
