Your first docker run, flag by flag

Almost everything starts with docker run. It looks scary because people pile flags on it, so let us take one real command apart.

# 1. Run nginx in the background, publish host port 8080 to container port 80
docker run -d --name web -p 8080:80 nginx:1.30

# 2. Is it up?
docker ps

# 3. Talk to it from the host
curl -s localhost:8080 | head -n 4
$ docker run -d --name web -p 8080:80 nginx:1.30

Your container ID and pull lines will differ. The long hex string printed by -d is the full container ID; docker ps shows the first 12 characters, and any unique prefix works in commands.

The flags you will use every day

FlagMeaningWhen to use it
-dDetached: run in the background, print the IDServers (web, DB, Kafka)
-it-i keep stdin open + -t give it a terminalShells and interactive tools: docker run -it ubuntu bash
--rmDelete the container (and its anonymous volumes) when it exitsOne-off commands, experiments
--nameGive a name instead of a random one like quirky_turingAlways, for anything you will refer to again
-p H:CPublish container port C on host port HTo reach it from outside the host (details on Networking)
-e K=V, --env-fileSet environment variablesConfig: DB URL, log level
-v / --mountAttach a volume or host folderData that must survive (see Volumes)
--networkJoin a specific networkSo containers can find each other by name
--memory, --cpusResource limits (cgroups)Always in shared or production hosts
--restartRestart policyLong-running services
--initRun a tiny init (tini) as PID 1Apps that do not handle signals or spawn children

Tip: docker run IMAGE CMD replaces the image's default CMD. Try docker run --rm alpine:3.24 echo hello: the container starts, prints hello, its main process exits, and the container is gone. That is a perfectly normal, healthy container life of about one second.
