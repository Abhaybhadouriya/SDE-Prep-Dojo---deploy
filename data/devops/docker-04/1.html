The life of a container

A container is always in one of a few states. Learn this picture and most Docker commands become obvious: each command just moves the container along one arrow.

StateWhat it meansHow you get there
createdConfig and writable layer exist, no process yetdocker create
runningThe main process (PID 1 of the container) is alivedocker start, docker run
pausedAll processes are frozen by the cgroup freezer; memory keptdocker pause
restartingA restart policy is bringing it back after it exited--restart policy
exitedThe main process ended; files and logs are keptdocker stop, docker kill, or the app finished/crashed
removedGone. Writable layer deleted. Image untouched.docker rm, or --rm on exit

Key idea: a container lives exactly as long as its main process. When that one process exits, the container is "exited", even if it started helper processes. This is why a container whose command is bash with no terminal exits immediately: bash sees no input and quits.
