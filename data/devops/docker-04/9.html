Cleaning up: where did my disk go?

Docker never deletes things by itself. Stopped containers, old images, unused volumes and build cache all stay until you remove them.

$ docker system df
TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
Images          14        3         6.1GB     4.9GB (80%)
Containers      9         2         312MB     301MB (96%)
Local Volumes   6         2         1.8GB     1.1GB (61%)
Build Cache     88        0         3.4GB     3.4GB
docker container prune          # remove all stopped containers
docker image prune              # remove dangling (untagged) images
docker image prune -a           # remove every image not used by a container
docker builder prune            # remove build cache
docker volume prune             # unused ANONYMOUS volumes only (since Engine 23)
docker volume prune -a          # also unused NAMED volumes - CAREFUL, this is data
docker system prune             # containers + networks + dangling images + build cache
docker system prune -a --volumes   # the nuclear option (volumes: anonymous only on Engine 23+)

Careful: removing a container does not remove its image or its named volumes. Since Docker Engine 23 (API 1.42), docker volume prune removes only anonymous unused volumes by default. But docker volume prune -a (or docker system prune -a --volumes on older engines) can delete a database volume you forgot was not attached right now. Read the prompt before typing y.
