Quick quiz

You ran docker run ubuntu and it exited immediately. Why?

  1. The image is broken
  2. Its main process (bash) had no terminal input and finished, so the container ended
  3. Docker needs --restart always to keep containers up
A container lives as long as its main process. Without -it, bash reads end-of-input and exits, so the container exits with code 0.

A container's exit code is 137 and OOMKilled is true. What happened?

  1. The app threw an exception
  2. The app received SIGTERM and exited
  3. The kernel OOM killer sent SIGKILL because the memory limit was exceeded
137 = 128 + 9 (SIGKILL), and OOMKilled=true confirms the memory cgroup limit was hit.

Which command opens a shell in an already-running container without restarting it?

  1. docker exec -it web sh
  2. docker run -it web sh
  3. docker start -i web
exec starts a new process inside the running container's namespaces. run would create a new container from an image called "web".

A container goes over its --cpus 1 limit. What happens?

  1. It is killed with exit 137
  2. It is throttled until the next CFS period, so it slows down
  3. Docker moves it to another core
CPU limits are a quota per period (cpu.max). Over quota means waiting, not dying.

Your Dockerfile ends with CMD python app.py and stop always takes 10 seconds. Best first fix?

  1. Increase the stop timeout
  2. Use docker kill instead
  3. Switch to exec form CMD ["python", "app.py"] and handle SIGTERM
Shell form makes /bin/sh PID 1, which does not forward SIGTERM. Exec form makes your app PID 1 so it receives the signal.

Which restart policy does NOT bring a container back after a reboot if you had stopped it manually?

  1. unless-stopped
  2. always
  3. Both restart it
always restarts it when the daemon starts even if you stopped it; unless-stopped remembers your manual stop.

Where does docker logs read from with the default settings?

  1. Log files inside the container's filesystem
  2. A JSON file on the host written by the json-file logging driver from the app's stdout/stderr
  3. The registry
Docker captures stdout/stderr through the shim and the logging driver writes /var/lib/docker/containers/<id>/<id>-json.log.
