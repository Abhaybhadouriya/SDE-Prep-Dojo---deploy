You might confuse this with...

ThisIs not the same asThe difference
docker execdocker run / docker attachexec starts a new process inside an existing container. run makes a new container. attach connects your terminal to the main process's stdio, so Ctrl+C there can stop the container.
docker stopdocker killstop sends SIGTERM, waits (10 s by default), then SIGKILL. kill sends SIGKILL at once (or the signal given with -s).
docker pausedocker stoppause freezes every process with the cgroup freezer; memory stays and nothing exits. stop ends the main process, so the container is exited.
docker startdocker restartstart starts a stopped container. restart is stop (with its timeout) then start, on a running one.
docker rmdocker rmirm deletes a container and its writable layer. rmi deletes an image. Neither deletes named volumes.
Restart policyHealth checkA restart policy reacts to the process exiting. A stuck but alive process is not restarted by plain Docker, even if its HEALTHCHECK says unhealthy; Kubernetes liveness probes do that.

In interviews, say "I would exec in, not attach", and "137 after a stop means the app ignored SIGTERM".
