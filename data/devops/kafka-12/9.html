How to choose: a decision walk

Click through the questions in order. This is the reasoning to say out loud, not a law.

  1. Start with the shape. Do several teams need the same data, or will you ever want to re-read history? That single answer decides log vs queue most of the time.
  2. Yes → a log. Event backbones, CDC, clickstreams, audit trails, feeding analytics and search all want a log.
  3. Then pick who runs it. Self-run Kafka only with a team to operate it; otherwise managed Kafka (MSK, Confluent, Event Hubs). All-in on AWS and modest scale? Kinesis. A platform for many tenants with geo-replication? Pulsar is a fair answer.
  4. No → a queue. Now ask: do you need routing rules, priorities, or must it run outside a cloud?
  5. Pick the queue. RabbitMQ for routing and self-hosting; SQS (with SNS for fan-out) for zero-ops on AWS. Google Pub/Sub plays the same role on GCP.
  6. The "one more system" check. Every new system costs on-call, upgrades and security reviews. If you already run Kafka 4.2+, share groups give queue behaviour (per-message ack, more consumers than partitions) without a second broker.

Kafka grows a queue: share groups (KIP-932)

For years the honest answer to "I need a work queue and I have Kafka" was "partitions cap your consumers, and one slow message blocks its partition". Uber and Walmart each built consumer proxies to get around this (see Consumers & Consumer Groups). Kafka's share groups are the built-in answer: many consumers read the same partition, each record is acquired with a lock (30 s by default), and acknowledged one by one (accept, release, reject, and since 4.2 renew). After 5 failed deliveries a record is archived, and since 4.4 it can go to a dead-letter queue. The trade: no ordering guarantee inside a share group.

$ bin/kafka-console-share-consumer.sh --bootstrap-server localhost:9092 \
    --topic resize-jobs --group resize-workers

{"photo":82}

The tool above ships with Kafka 4.x. Run two of them with the same --group against a one-partition topic and both receive records, which a classic consumer group can never do.
