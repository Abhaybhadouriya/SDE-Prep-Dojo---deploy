The learner input asked for a reusable pattern: "I would pick X because A; the cost is B; if C becomes a problem I would switch to Y." Here it is applied five times.

  1. Order events for many services. "I would use Kafka keyed by orderId because payments, inventory, email and analytics all need the same events in order per order, and we can replay; the cost is running Kafka, so I would start on MSK; if we only ever had one consumer, SQS FIFO would be simpler."
  2. Thumbnail jobs on AWS. "I would use SQS because each job is independent and AWS runs it for us; the cost is no replay and possible duplicates, so the worker writes thumbnails idempotently by photo ID; if we needed priorities I would add a second high-priority queue."
  3. Routing alerts by region and severity. "I would use a RabbitMQ topic exchange because routing keys like alert.critical.apac map directly to bindings; the cost is no history; if we later needed analytics on alerts I would also publish them to a Kafka topic."
  4. Clickstream into analytics. "I would use Kafka (or Kinesis if we are all-in on AWS at moderate scale) because it is high volume, append-only and feeds several sinks; the cost is partition planning; if a key gets hot I would salt it."
  5. A platform for 300 internal teams. "Managed Kafka with quotas per team, or Pulsar for built-in tenancy and geo-replication; the cost of Pulsar is three components to run; if our team is small, managed Kafka wins."
