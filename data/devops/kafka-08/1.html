What is "cluster metadata"?

must know

Metadata is everything about the cluster except the messages themselves. Clients never see the controller directly; they ask any broker for metadata ("who leads orders-3?") and then talk to the right broker.

Kafka servers have a process.roles setting:

  • process.roles=controller - this node only joins the metadata quorum.
  • process.roles=broker - this node only stores partitions and serves clients.
  • process.roles=broker,controller - "combined mode", fine for a laptop, not recommended for critical environments because you cannot roll or scale controllers separately from brokers, and a busy broker can starve its controller.

Every node has a unique node.id (the old broker.id name is deprecated since 4.4).
