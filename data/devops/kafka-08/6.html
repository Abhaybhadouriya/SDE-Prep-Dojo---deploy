Migrating from ZooKeeper (what interviewers may ask)

deep dive

Stop here for SDE-1? Knowing that KRaft replaced ZooKeeper, that a Raft quorum of controllers holds the metadata log, and why you run 3 controllers is enough for SDE-1. The ZooKeeper migration below is SDE-2 / deep dive: it only matters if you will operate an older cluster or the interviewer asks about upgrades.

You cannot upgrade a ZooKeeper-based 3.x cluster straight to 4.x. The supported route is:

  1. Upgrade to the bridge release (3.9.x) while still on ZooKeeper.
  2. Add a KRaft controller quorum in migration mode. The controllers copy all metadata from ZooKeeper into the metadata log.
  3. Roll brokers into KRaft mode one by one. During this "dual write" phase, the KRaft controller also writes metadata back to ZooKeeper so you can still roll back.
  4. Finalize: remove the ZooKeeper settings, after which rollback is no longer possible. Then upgrade to 4.x.

Managed services (Amazon MSK, Confluent Cloud, Azure Event Hubs with its Kafka endpoint) hide this from you, but it is still a good "how would you migrate a live system without downtime?" story: phase it, keep a rollback path, verify at each step.
