Security is layers, like an onion

Must know (SDE-1)

No single feature makes a cluster safe. You stack layers, and an attacker must break all of them. A common way to picture it is four rings: the cloud (or data centre) holds the cluster, which runs containers, which run your code. A hole in an outer ring weakens everything inside it.

The RBAC vocabulary in one picture

RBAC has only four object kinds. Learn them as two pairs.

  • A Role is a list of rules: verbs (get, list, watch, create, update, patch, delete) on resources (pods, deployments, secrets...). A Role lives inside one namespace.
  • A ClusterRole is the same thing but not tied to a namespace. It can cover cluster-wide things like nodes, or be reused in many namespaces.
  • A RoleBinding says "give this role to these subjects in this namespace".
  • A ClusterRoleBinding gives a ClusterRole to subjects everywhere in the cluster.

A subject is who receives the rights: a User (a human, identified by a certificate or an OIDC login), a Group (for example everyone in your company's "sre" directory group), or a ServiceAccount (an identity for a program running in a pod).

You might confuse this with: a Kubernetes namespace and a Linux namespace. They share a name and nothing else. A Linux namespace is a kernel feature that isolates what a process can see (PIDs, network, mounts). A Kubernetes namespace is just a folder for API objects, a scope for names, RBAC, quotas and policies. Two pods in different Kubernetes namespaces can still run on the same node and talk to each other freely unless you add NetworkPolicies.
