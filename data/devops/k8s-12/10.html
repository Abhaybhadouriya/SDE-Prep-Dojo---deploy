Common mistakes and gotchas

Good to know (SDE-2)
  1. "Secrets are encrypted." Not by default. Base64 is encoding. Turn on encryption at rest and restrict RBAC.
  2. Giving cluster-admin to CI pipelines. A leaked CI token then owns the cluster. Give the deploy ServiceAccount edit in the namespaces it deploys to.
  3. Binding rights to the default ServiceAccount. Every pod that does not set a ServiceAccount inherits them.
  4. NetworkPolicies on a CNI that ignores them. No error, no effect. Test with a pod that should be blocked.
  5. Default-deny egress without DNS. Everything breaks, and it looks like a database problem.
  6. Assuming a namespace is a security wall. Without NetworkPolicy, pods in different namespaces talk freely; they may even share a node.
  7. Enforcing Pod Security on a live namespace without warn first. Deployments still apply, but ReplicaSets quietly stop creating pods at the next rollout.
  8. Admission webhooks with failurePolicy: Fail and no high availability. If the webhook pod is down, nobody can create pods, sometimes not even the webhook itself.
  9. Using latest tags. You cannot prove what is running. Pin digests.
  10. Public API server endpoint with no IP restrictions. Authentication still protects it, but every unauthenticated scanner on the internet can knock on the door. Use a private endpoint or allow-lists.
