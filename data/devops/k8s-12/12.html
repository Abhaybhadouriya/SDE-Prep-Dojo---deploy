  • Request path: TLS -> authentication (401) -> authorization/RBAC (403) -> mutating admission -> schema -> validating admission -> etcd.
  • Role/RoleBinding = one namespace; ClusterRole/ClusterRoleBinding = cluster-wide. RBAC only allows; no deny rules.
  • "Create pods" in a namespace is nearly "read every Secret" in it. system:masters bypasses RBAC.
  • Every pod has a ServiceAccount; tokens are short-lived; turn automount off if unused; use workload identity for cloud access.
  • Pod Security Standards: Privileged, Baseline, Restricted, enforced by namespace labels. PodSecurityPolicy is gone (v1.25).
  • Network is allow-all by default. NetworkPolicy needs a CNI that enforces it. Default deny + allow DNS.
  • Secrets are base64, not encrypted, unless you enable encryption at rest (KMS v2).
  • Kubernetes namespace is not a Linux namespace and not a hard security boundary.
