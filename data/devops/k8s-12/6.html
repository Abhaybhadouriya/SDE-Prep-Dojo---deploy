NetworkPolicy: walls between pods

Good to know (SDE-2)

By default, every pod can talk to every other pod in the cluster, in every namespace. That is the Kubernetes network model: flat and open. A NetworkPolicy is a firewall rule written in YAML that selects pods by label and says which traffic may reach them (ingress) or leave them (egress).

The rules of the game:

  • If no policy selects a pod, all traffic is allowed.
  • Once any policy selects a pod for a direction (ingress or egress), only traffic that some policy explicitly allows is let through in that direction. Everything else is dropped.
  • Policies only add allows; there is no "deny" rule in the standard API, and the order does not matter.
  • Return traffic of an allowed connection is allowed automatically (the policy is stateful).
  • The CNI plugin enforces it. Calico and Cilium do; plain Flannel does not, and then your policies are silently ignored.
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-all
  namespace: shop
spec:
  podSelector: {}          # {} = every pod in the namespace
  policyTypes: ["Ingress", "Egress"]
  # no ingress/egress rules listed = nothing allowed
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: backend-from-frontend
  namespace: shop
spec:
  podSelector:
    matchLabels: { app: backend }
  policyTypes: ["Ingress"]
  ingress:
  - from:
    - podSelector:
        matchLabels: { app: frontend }
    ports:
    - protocol: TCP
      port: 8080
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: backend-egress
  namespace: shop
spec:
  podSelector:
    matchLabels: { app: backend }
  policyTypes: ["Egress"]
  egress:
  - to:                                  # DNS in kube-system
    - namespaceSelector:
        matchLabels: { kubernetes.io/metadata.name: kube-system }
      podSelector:
        matchLabels: { k8s-app: kube-dns }
    ports:
    - { protocol: UDP, port: 53 }
    - { protocol: TCP, port: 53 }
  - to:
    - podSelector:
        matchLabels: { app: postgres }
    ports:
    - { protocol: TCP, port: 5432 }

Careful: the number one NetworkPolicy outage is a default-deny egress policy without the DNS allow. Every name lookup times out, and the app logs look like "cannot connect to database" when the real problem is DNS. Another trap: in from, putting namespaceSelector and podSelector in the same list item means AND (pods with that label in that namespace); writing them as two items (two dashes) means OR, which is usually far more open than you meant.

From your world

A NetworkPolicy is a stateful ACL, like a reflexive ACL or a zone-based firewall: allowed flows get their return path for free through connection tracking. The big difference is the match fields. You match on labels, not IP prefixes, because pod IPs change all the time. The CNI agent on each node turns the labels into concrete IP sets and programs iptables, nftables or eBPF maps, and updates them whenever a pod starts or stops. Where this breaks: standard NetworkPolicy is L3/L4 only. To say "allow GET /orders but not DELETE" you need L7-aware tools such as Cilium policies or a service mesh.
