What terraform.tfstate holds, and why it must exist

Must know (SDE-1)

State is a JSON file. After the VPC apply from the previous page, a trimmed version looks like this:

{
  "version": 4,                      // state file format version
  "terraform_version": "1.14.0",
  "serial": 7,                       // +1 on every write
  "lineage": "3f6c1d2e-8a4b-...",    // unique id given when this state was born
  "outputs": {
    "vpc_id": { "value": "vpc-0a1b2c3d", "type": "string" }
  },
  "resources": [
    {
      "mode": "managed",             // "data" for data sources
      "type": "aws_vpc",
      "name": "main",
      "provider": "provider[\"registry.terraform.io/hashicorp/aws\"]",
      "instances": [
        {
          "attributes": {
            "id": "vpc-0a1b2c3d",    // THE link to the real object
            "cidr_block": "10.20.0.0/16",
            "enable_dns_hostnames": true,
            "tags": { "Name": "dojo-dev" }
          },
          "dependencies": []
        }
      ]
    },
    {
      "mode": "managed", "type": "aws_subnet", "name": "public",
      "instances": [
        { "index_key": 0,
          "attributes": { "id": "subnet-0aa11", "vpc_id": "vpc-0a1b2c3d", "cidr_block": "10.20.0.0/24" },
          "dependencies": ["aws_vpc.main", "data.aws_availability_zones.up"] }
      ]
    }
  ]
}

(JSON has no comments; they are added here to explain.) Four jobs, straight from the Terraform docs:

  1. Mapping to the real world. aws_vpc.main is vpc-0a1b2c3d. Cloud APIs mostly do not let Terraform tag "this one is mine" reliably on every resource type, so the binding lives in state. One resource address maps to exactly one real object.
  2. Metadata, especially dependencies. Each instance records what it depended on. When you delete the VPC block and the subnet blocks from config, the config no longer says which to delete first. State does: subnets, then the VPC.
  3. Performance. State caches every attribute. On a large estate you can plan with -refresh=false and trust the cache instead of making thousands of read calls.
  4. Sync. Shared state is how a team (and CI) agrees on "what exists". This is why it must be remote, below.

From your world

A switch SDK keeps shadow tables in RAM: a software copy of every route, ACL and TCAM entry it programmed into the ASIC, with the hardware index of each one. To change a route it diffs the new RIB against the shadow table and issues only the delta writes. Lose the shadow table and the driver cannot tell its own entries from garbage; you have to do a full hardware resync or reboot. terraform.tfstate is exactly that shadow table, and the resource id is the hardware index. serial is a generation number; lineage is like a boot ID that stops you writing one box's shadow table onto another.

Lose state, lose control. The infrastructure keeps running, but Terraform now thinks nothing exists. The next apply tries to create everything again (and fails on names that are taken, or worse, creates duplicates), and nothing will ever be destroyed by Terraform. Recovery means importing every resource back. This is the single best argument for a versioned remote backend.

Never edit the JSON by hand. To read it, use terraform show, terraform state list, terraform output -json or terraform show -json. To change it, use the state commands further down.
