How plan uses state: refresh, diff and drift

Must know (SDE-1)

Someone added a tag in the AWS console by hand and also changed the VPC's CIDR in code. Click through what terraform plan does:

  1. Load the last saved state (serial 7) from the backend, after taking the lock.
  2. Refresh: read each object by its ID through the provider. Bob's console tag shows up. This difference between state and reality is drift.
  3. Compare config (desired) with the refreshed state (actual).
  4. Print the plan: the CIDR change forces replacement, and Bob's tag will be removed, because config is the source of truth.
  5. On apply, make the API calls, then write the new state (serial 8) and release the lock.

Two useful variants: terraform plan -refresh-only shows only drift (no config changes), and terraform apply -refresh-only accepts reality into state without touching the cloud. Use them when someone fixed something by hand during an incident and you want to see, then decide.
