Local vs remote state

Must know (SDE-1)

By default state is a file next to your code. That is fine for a tutorial and wrong for anything else.

ProblemLocal file on a laptopState committed to GitRemote backend (S3, HCP Terraform, GCS, azurerm)
Teammates and CI see the same stateNoOnly if everyone pulls firstYes
Two applies at onceNot possible to detectMerge conflict after the damageBlocked by a lock
Secrets in stateOn a laptop diskIn Git history foreverEncrypted at rest, access via IAM
Laptop dies / file deletedState goneOld copy, maybeVersioned, every write kept
Audit who changed itNoCommit authorCloudTrail on the bucket

A backend is where state is stored and how it is locked. On AWS the standard choice is the s3 backend. AWS's own prescriptive guidance recommends S3 for most AWS users, or HCP Terraform (HashiCorp's managed service) if you want storage, locking, run history and policy checks handled for you.
