Versioning: undo for overwrites and deletes

Must know (SDE-1)

A bucket is in one of three states: unversioned (default), versioning-enabled, or versioning-suspended. Once enabled it can never go back to unversioned - only suspended. With versioning on, each PUT to the same key adds a new version with its own VersionId, and a plain DELETE does not remove data: it adds a tiny delete marker on top. A GET without a version id returns the newest version, or 404 if the newest thing is a delete marker.

aws s3api put-bucket-versioning --bucket dojo-uploads-surbhi \
  --versioning-configuration Status=Enabled
aws s3 rm s3://dojo-uploads-surbhi/config/app.yaml
aws s3api list-object-versions --bucket dojo-uploads-surbhi --prefix config/app.yaml \
  --query '{V:Versions[].[VersionId,IsLatest],M:DeleteMarkers[].[VersionId,IsLatest]}'
delete: s3://dojo-uploads-surbhi/config/app.yaml
{
    "V": [["Lt3xQ2pZ...", false], ["9Fq0kW1b...", false]],
    "M": [["nB7vR0aT...", true]]
}

Every version is billed as a full object. A bucket that is overwritten often grows silently - which is why versioning and lifecycle rules (next section) always go together. For "nobody, not even root, may delete this for 7 years" there is S3 Object Lock (WORM retention, compliance or governance mode), which requires versioning.
