Buckets, keys and objects: a flat key-value store

Must know (SDE-1)

A bucket lives in one AWS Region and its name is globally unique (it becomes part of a DNS name: my-bucket.s3.ap-south-1.amazonaws.com). Inside, there are no real folders. There is only a flat map from key (a UTF-8 string up to 1,024 bytes) to object (bytes + metadata + a version id). The "folders" you see in the console are just the console splitting keys on /. A list call with Prefix=logs/2026/ and Delimiter=/ simulates a directory listing.

From your world

Think of S3 as a giant hash table behind an HTTP API, not as a filesystem. There are no inodes, no directories, no rename(2), no partial writes, no seek-and-write. A PUT replaces the whole value atomically - like swapping a pointer to a new buffer rather than memcpy into the old one. Reads can use a byte range (Range: bytes=0-1023), which is how big files are read in parallel. Since December 2020, S3 gives strong read-after-write consistency for PUTs, DELETEs and LISTs: once a PUT returns 200, every reader sees the new object.

Your first commands (AWS CLI v2). The output is what you should expect to see:

aws s3 mb s3://dojo-uploads-surbhi --region ap-south-1
aws s3 cp app-1.gz s3://dojo-uploads-surbhi/logs/2026/11/23/app-1.gz
aws s3 ls s3://dojo-uploads-surbhi/logs/ --recursive
aws s3api head-object --bucket dojo-uploads-surbhi --key logs/2026/11/23/app-1.gz
make_bucket: dojo-uploads-surbhi
upload: ./app-1.gz to s3://dojo-uploads-surbhi/logs/2026/11/23/app-1.gz

Notice "ServerSideEncryption": "AES256" even though you asked for nothing: every new object has been encrypted with SSE-S3 by default since 5 January 2023. Two more numbers worth knowing: S3 Standard is designed for 99.999999999% (eleven nines) durability by storing data across at least three Availability Zones, and each partitioned prefix supports at least 3,500 PUT/COPY/POST/DELETE and 5,500 GET/HEAD requests per second. Spread hot traffic over several prefixes if you need more.
