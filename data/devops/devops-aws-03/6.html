Lifecycle rules, TTL and storage classes

Must know (SDE-1)

A lifecycle configuration is a list of rules, each with a filter (prefix, tags, object size) and actions that S3 runs for you in the background, roughly once a day: transition to a cheaper storage class after N days, expire (delete) after N days - S3's version of a TTL - expire noncurrent versions, remove expired delete markers, and abort incomplete multipart uploads.

A typical "logs" rule in JSON (the same shape works in Terraform's aws_s3_bucket_lifecycle_configuration):

{
  "Rules": [
    {
      "ID": "logs-tiering-and-ttl",
      "Status": "Enabled",
      "Filter": { "Prefix": "logs/" },
      "Transitions": [
        { "Days": 30, "StorageClass": "STANDARD_IA" },
        { "Days": 90, "StorageClass": "GLACIER" }
      ],
      "Expiration": { "Days": 365 },
      "NoncurrentVersionExpiration": { "NoncurrentDays": 30, "NewerNoncurrentVersions": 3 }
    },
    {
      "ID": "abort-stale-multipart",
      "Status": "Enabled",
      "Filter": {},
      "AbortIncompleteMultipartUpload": { "DaysAfterInitiation": 7 }
    }
  ]
}
aws s3api put-bucket-lifecycle-configuration --bucket dojo-uploads-surbhi \
  --lifecycle-configuration file://lifecycle.json
aws s3api get-bucket-lifecycle-configuration --bucket dojo-uploads-surbhi --query 'Rules[].ID'
[
    "logs-tiering-and-ttl",
    "abort-stale-multipart"
]

From your world

This is a memory hierarchy with an eviction policy you write yourself: Standard is DRAM, IA is SSD, Glacier is tape. Lifecycle is a background reaper thread - like a kernel thread aging pages from the active to the inactive list - except it runs on calendar days, not on access recency. If you want access-based aging (the real LRU-style behaviour), that is Intelligent-Tiering.

Lifecycle cost traps: (1) objects under 128 KB are not transitioned by default (since September 2024), because the per-object transition request would cost more than the saving; (2) moving out of IA or Glacier before the minimum duration still bills the full minimum; (3) a rule cannot move objects to Standard-IA or One Zone-IA before they are 30 days old; (4) every object archived to Glacier Flexible or Deep Archive carries about 40 KB of extra billed metadata, so millions of tiny files should be bundled first.
