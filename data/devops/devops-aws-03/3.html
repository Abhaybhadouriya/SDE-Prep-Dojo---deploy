Pre-signed URLs: a 10-minute ticket for one object

Must know (SDE-1)

Your mobile app must upload a 200 MB video. Streaming it through your API servers wastes their bandwidth and memory. Instead, the API (which has an IAM role) signs a URL that allows exactly one operation - PUT on one key - until a short expiry. The client then talks to S3 directly. Nothing secret travels: the URL carries a signature computed from the role's credentials, not the credentials themselves.

import boto3

s3 = boto3.client("s3", region_name="ap-south-1")

def upload_url(user_id: str, upload_id: str) -> str:
    # Key is chosen by the server, never by the client.
    key = f"incoming/{user_id}/{upload_id}.mp4"
    return s3.generate_presigned_url(
        "put_object",
        Params={"Bucket": "dojo-uploads-surbhi", "Key": key,
                "ContentType": "video/mp4"},
        ExpiresIn=600,          # seconds
    )
aws s3 presign s3://dojo-uploads-surbhi/reports/nov.pdf --expires-in 600
https://dojo-uploads-surbhi.s3.ap-south-1.amazonaws.com/reports/nov.pdf?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=...&X-Amz-Date=20261123T051400Z&X-Amz-Expires=600&X-Amz-SignedHeaders=host&X-Amz-Signature=...

Rules that interviewers check:

  1. Short expiry. Minutes, not days. With Signature V4 the maximum is 7 days (604,800 s); the console caps it at 12 hours.
  2. Temporary credentials cut it short. A URL signed with a role's session credentials stops working when that session expires, even if ExpiresIn is longer. A URL signed on a Lambda or ECS task role often dies after a few hours for this reason.
  3. The signer needs the permission. The URL can do only what the signing principal may do at the moment of use. If the role loses s3:PutObject, every outstanding URL fails.
  4. Server chooses the key and validates size/type afterwards (or uses a presigned POST policy, which can enforce content-length-range).
  5. It is a bearer token. Anyone holding the URL can use it until expiry - do not log full URLs.
