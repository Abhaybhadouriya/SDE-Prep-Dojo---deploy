Same-region and cross-region replication

Good to know (SDE-2)

Live replication copies new objects asynchronously from a source bucket to one or more destination buckets. CRR (Cross-Region Replication) targets another Region - for disaster recovery, compliance distance or lower latency for users there. SRR (Same-Region Replication) targets a bucket in the same Region - typically to aggregate logs from many accounts, or to copy prod data into a separate account that an attacker in the prod account cannot delete.

What you must know to set it up and to answer follow-ups:

  • Versioning must be enabled on source and destination. S3 assumes an IAM role you provide to read the source and write the destination (plus KMS permissions if objects are SSE-KMS).
  • Only new writes. Objects that existed before the rule are not copied; use S3 Batch Replication for those and to retry objects whose status is FAILED.
  • Deletes. Delete markers are not replicated unless you enable delete-marker replication. Deleting a specific version id is never replicated - a deliberate protection against a malicious or buggy delete wiping both copies.
  • Timing. Most objects replicate within minutes, but there is no guarantee unless you pay for S3 Replication Time Control (RTC): 99.99% of new objects within 15 minutes, backed by an SLA, plus replication metrics.
  • Two-way replication with replica modification sync keeps metadata changes in sync both ways; combined with a Multi-Region Access Point it gives active-active buckets with failover.
  • No chaining by default. A replica in bucket B is not replicated on to bucket C by B's own rule.

From your world

CRR is asynchronous replication, like a routing protocol flooding updates or DRBD in async mode: the write is acknowledged locally and shipped later, so the gap between source and replica is your RPO. RTC is the knob that bounds that gap with an SLA, the way you would bound convergence time with timers. Replication traffic runs on the AWS backbone; you pay inter-region data transfer per GB, which is often the biggest line item.

{
  "Role": "arn:aws:iam::111122223333:role/s3-crr",
  "Rules": [{
    "ID": "uploads-to-sg",
    "Status": "Enabled",
    "Priority": 1,
    "Filter": { "Prefix": "incoming/" },
    "DeleteMarkerReplication": { "Status": "Disabled" },
    "Destination": {
      "Bucket": "arn:aws:s3:::dojo-uploads-surbhi-sg",
      "StorageClass": "STANDARD_IA"
    }
  }]
}
aws s3api put-bucket-replication --bucket dojo-uploads-surbhi \
  --replication-configuration file://replication.json
aws s3api head-object --bucket dojo-uploads-surbhi --key incoming/u42/a1.mp4 \
  --query ReplicationStatus
"COMPLETED"
