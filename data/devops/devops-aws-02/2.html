Launch templates: the recipe card for every new machine

Must know (SDE-1)

A launch template is a versioned description of an instance: AMI, instance type, security groups, IAM instance profile, EBS volumes, metadata options and user data (a script cloud-init runs on first boot). Auto Scaling Groups launch from it, so changing the fleet means publishing a new template version, never logging in and editing servers.

aws ec2 create-launch-template --launch-template-name web-lt \
  --launch-template-data '{
    "ImageId": "ami-0abcdef1234567890",
    "InstanceType": "m7i.large",
    "IamInstanceProfile": {"Name": "web-instance-role"},
    "SecurityGroupIds": ["sg-0app1111"],
    "MetadataOptions": {"HttpTokens": "required", "HttpPutResponseHopLimit": 1},
    "UserData": "IyEvYmluL2Jhc2gKc3lzdGVtY3RsIHN0YXJ0IHdlYi1hcHA="
  }'
{
    "LaunchTemplate": {
        "LaunchTemplateId": "lt-0a1b2c3d4e5f67890",
        "LaunchTemplateName": "web-lt",
        "DefaultVersionNumber": 1,
        "LatestVersionNumber": 1
    }
}
  • HttpTokens: required forces IMDSv2: the instance metadata service (169.254.169.254) only answers with a session token from a PUT request. This blocks the classic SSRF attack where a bug tricks the server into fetching its own IAM credentials.
  • UserData is base64. Here it decodes to a two-line script that starts the app. Bake heavy setup into the AMI (with Packer or EC2 Image Builder) so boot takes seconds, not minutes - this directly controls how fast you can scale out.
  • The instance gets AWS credentials from its instance profile (an IAM role), never from keys on disk.
