Security groups vs network ACLs

Must know (SDE-1)

Two firewalls, at two places, with two very different brains. This comparison is one of the most-asked AWS questions in SDE interviews.

Security group (SG)Network ACL (NACL)
Attached toENI (instance, LB node, pod ENI, Lambda ENI)Subnet: every packet crossing the subnet boundary
StateStateful: replies to an allowed flow are allowed automaticallyStateless: replies need their own rule (ephemeral ports 1024-65535)
Rule typesAllow only. Default: deny all inbound, allow all outboundAllow and deny. Default NACL allows all; a new custom NACL denies all
EvaluationAll rules considered togetherNumbered rules in ascending order; first match wins
Can referenceOther security groups, prefix lists, CIDRsCIDRs only
Best forThe primary control: "app tier accepts 8080 only from the LB's SG"Coarse guard rails and explicit denies: block a bad CIDR for a whole subnet
 
# app tier accepts 8080 only from whatever is in the ALB's security group
aws ec2 authorize-security-group-ingress --group-id sg-0app1111 \
  --protocol tcp --port 8080 --source-group sg-0alb2222
# database accepts 5432 only from the app tier
aws ec2 authorize-security-group-ingress --group-id sg-0db3333 \
  --protocol tcp --port 5432 --source-group sg-0app1111

Referencing security groups instead of IPs is the superpower: when the ASG adds ten instances, they join sg-0app1111 and are allowed into the database instantly, with no rule change.

Connection tracking details that bite in production

  • Changing an SG rule does not cut existing tracked connections. They live until they time out. To kill traffic immediately, use a NACL deny (stateless, evaluated on every packet).
  • Some flows are untracked: if a TCP/UDP rule allows 0.0.0.0/0 inbound and the outbound rule allows all traffic to 0.0.0.0/0, AWS does not track that flow. Removing the rule then drops those connections at once.
  • Tracked connections are a per-instance limit. When an instance runs out, new connections are dropped; the ENA metric conntrack_allowance_exceeded tells you. The idle TCP established timeout is configurable per ENI (default 432,000 s - 5 days - on most types, 350 s on Nitro v6 types), so long-lived idle connections need keepalives under 5 minutes on the newer generation.

From your world

A security group is a per-interface stateful firewall - Linux iptables/nftables with -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT pre-installed, plus allow rules, enforced on the Nitro card instead of your kernel. Referencing another SG is like matching on an ipset that is updated automatically with every member's IP. A NACL is a classic stateless router ACL on the subnet's "interface": numbered ACEs, first match wins, implicit deny at the end (*), and you must open the return ephemeral range yourself, just as on a Cisco extended ACL without established.
