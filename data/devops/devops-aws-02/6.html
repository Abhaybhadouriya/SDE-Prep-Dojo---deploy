Instance refresh: rolling out a new AMI safely

Good to know (SDE-2)

You patched the OS and built a new AMI. Publish launch template version 2, then ask the ASG to refresh: it replaces instances in batches while keeping a minimum healthy percentage in service (default 90 % if you set nothing else), waits for each batch to warm up and pass health checks, and can pause at checkpoints or roll back on a CloudWatch alarm.

aws autoscaling start-instance-refresh --auto-scaling-group-name web-asg \
  --desired-configuration '{"LaunchTemplate":{"LaunchTemplateName":"web-lt","Version":"2"}}' \
  --preferences '{
    "MinHealthyPercentage": 90,
    "MaxHealthyPercentage": 110,
    "InstanceWarmup": 120,
    "CheckpointPercentages": [20, 50, 100],
    "CheckpointDelay": 600,
    "SkipMatching": true,
    "AutoRollback": true,
    "AlarmSpecification": {"Alarms": ["web-5xx-high"]}
  }'
aws autoscaling describe-instance-refreshes --auto-scaling-group-name web-asg \
  --query 'InstanceRefreshes[0].[Status,PercentageComplete,InstancesToUpdate]'
{
    "InstanceRefreshId": "08b91cf7-8fa6-48af-b6a6-d227f40f1b9b"
}
[
    "InProgress",
    20,
    8
]
  • MaxHealthyPercentage 110 lets the ASG launch new instances before terminating old ones (launch-before-terminate), so capacity never dips. Defaults to 100 when you set nothing.
  • Checkpoints pause after 20 % and 50 % so you can watch dashboards; that is a canary deployment for machines.
  • AutoRollback + alarm: if web-5xx-high fires, the refresh fails and the ASG goes back to the previous configuration on its own.
  • SkipMatching skips instances already on the desired configuration, so a retried refresh does not replace everything again.
