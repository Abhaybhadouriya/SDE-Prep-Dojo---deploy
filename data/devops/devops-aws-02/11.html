Common mistakes and gotchas

  • Only EC2 health checks. The process is hung but the VM is "running"; the ASG never replaces it. Turn on ELB health checks.
  • Grace period 0 from the CLI with a slow-starting app: an endless launch-kill loop.
  • Scaling on the wrong metric: total request count, or CPU on an I/O-bound service. Use a metric that falls when you add capacity.
  • Burstable t instances for steady load: CPU credits run out and the instance is throttled - a slow-motion outage that looks like an app bug.
  • SG rule removed but traffic still flows: tracked connections persist until they time out. Use a NACL deny for an immediate block.
  • NACL without ephemeral ports: inbound 443 allowed, outbound 1024-65535 forgotten, so replies die. Stateless means both directions.
  • "Multi-AZ" with one EBS-backed instance: EBS cannot move AZs. HA needs replication across AZs (RDS Multi-AZ, app-level replicas).
  • Assuming two AZs is enough: losing one leaves 50 % capacity unless you run at 200 %. Three AZs at 150 % is the common sweet spot.
  • Graviton node group, x86-only sidecar image: pods crash with exec format error. Check every image is multi-arch before migrating.
