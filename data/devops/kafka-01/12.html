Common mistakes and gotchas

  1. Making everything async. Putting a login check or a price lookup behind a queue makes the user wait for a reply that is now harder to get. Keep request/response for things the user is waiting on.
  2. Forgetting duplicates. Writing a consumer that sends an email or adds money every time it sees a message, with no check. With at-least-once delivery, it will see some messages twice. Make handlers idempotent.
  3. Using Kafka as a request/response bus. Sending a request on one topic and waiting for a reply on another, with a timeout, rebuilds the phone call badly. If you need the answer now, call the service.
  4. Ignoring lag until it is too late. If consumers are slower than producers for hours, the backlog can outlive the topic's retention (7 days by default) and data is deleted before anyone reads it. Alert on lag growth.
  5. A new consumer group that reads nothing. Default auto.offset.reset=latest starts new groups at the end. Set earliest when you need history.
  6. Writing to the database and Kafka separately and hoping. That is the dual-write problem. Use the outbox pattern when the event must match the database.
