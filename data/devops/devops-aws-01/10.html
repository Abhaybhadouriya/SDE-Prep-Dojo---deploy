Common mistakes and gotchas

  • "Public subnet" without the IGW route (or with the route but no public IP): both are needed for inbound internet access.
  • Subnets accidentally using the main route table. If someone adds an IGW route to the main table, every unassociated subnet becomes public. Keep the main table boring.
  • One NAT gateway for three AZs. Cheap until that AZ fails and every private subnet loses outbound internet; also costs cross-AZ data all the time.
  • Tiny subnets for EKS. /24 private subnets plus the VPC CNI warm pool run out of IPs quickly. Size /19 or bigger, or plan a 100.64.0.0/10 secondary CIDR.
  • Overlapping CIDRs with the office network, another VPC, or Docker's 172.17.0.0/16. Peering and VPN routes become impossible.
  • AZ names are not the same across accounts. ap-south-1a in your account may be a different physical AZ from ap-south-1a in a partner's account. Use AZ IDs (aps1-az1) when coordinating across accounts.
  • Forgetting the NACL return ports. A NAT gateway or any client uses ephemeral ports 1024-65535 for replies; a stateless NACL that only allows 443 inbound breaks every outbound call.
  • Expecting broadcast or multicast to work (VRRP, gratuitous ARP failover, keepalived): the VPC does not support broadcast, and multicast needs Transit Gateway multicast. Use an Elastic IP move, a route update or a load balancer for failover instead.
