Packet walk: from a phone on the internet to a private pod

Must know (SDE-1)

Put it all together. A user opens https://shop.example.com. The site runs on EKS: an internet-facing Application Load Balancer (ALB) in the public subnets, created by the AWS Load Balancer Controller with target-type: ip, sends traffic straight to pod IPs in the private subnets. Click Play.

  1. DNS returns the load balancer's public IPs, one per AZ it runs in.
  2. The client sends a SYN across the internet to one of those public IPs.
  3. The Internet Gateway translates the public destination IP to the ALB node's private IP.
  4. The ALB terminates TLS and opens a separate connection to a healthy pod IP.
  5. The VPC local route carries it to the worker node ENI that owns that IP as a secondary address.
  6. The node kernel hands it to the pod through its veth pair. Same flat VPC network, no tunnel.
  7. The reply retraces the path; stateful security groups and NAT state make the return automatic.

Compare with cross-node pod traffic on a VXLAN overlay: on EKS with the VPC CNI there is no encapsulation, because the VPC itself routes pod IPs. The cost is IP consumption (see CIDR planning). For the L4 vs L7 load balancer side of this walk, see Networking for HLD. Outbound traffic from a pod to the internet is the opposite path: the VPC CNI SNATs it to the node's primary IP, the private route table sends it to the NAT gateway, then the IGW.
