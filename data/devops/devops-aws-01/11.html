Interview questions

What makes a subnet public versus private in AWS?

Only its route table. A public subnet's table has 0.0.0.0/0 -> internet gateway; a private subnet's default route points to a NAT gateway (or nothing). Resources in a public subnet also need a public IPv4 or Elastic IP to be reachable, and their security group must allow the traffic. Private resources can make outbound connections through NAT but cannot accept inbound connections from the internet.

How to answer

Lead with "it is the route, not a flag". Then the three things inbound access needs: IGW route, public IP, security group rule. Mention isolated subnets for databases.

Likely follow-ups
  • Can an instance in a public subnet without a public IP reach the internet? (No: the IGW has nothing to translate it to. It needs a public IP or a NAT gateway.)
  • What happens to unassociated subnets? (They use the main route table.)
How would you plan CIDR ranges for a company with 3 environments in 2 regions that will also connect to an on-prem network?

Start from a company-wide plan, not per VPC. Reserve a big private block (for example 10.0.0.0/8), carve it hierarchically: per region a /12, per environment a /16 (prod, staging, dev), and keep the on-prem ranges out of it. Inside each /16: three public /20s, three large private /19s (pods consume IPs with the VPC CNI) and three data /22s, leaving spare space. No two VPCs overlap, so peering, Transit Gateway and VPN routing all work, and each region can be summarised. Track allocations in AWS VPC IPAM so new accounts get the next free block automatically.

How to answer

Say "non-overlapping and hierarchical" in the first sentence. Show the maths for one /16. Mention growth (secondary CIDRs, 100.64.0.0/10 for pods, IPv6) and the 5 reserved IPs.

Likely follow-ups
  • Two acquired companies both use 10.0.0.0/16. Options? (Re-IP one side, or use private NAT gateways / PrivateLink to expose only specific services across the overlap.)
  • Why not just make every VPC a /16 of 10.0.0.0? (They would all overlap.)
Why one NAT gateway per AZ? What does it protect against and what does it cost?

A zonal NAT gateway is redundant only inside its own AZ. If all private subnets route to one NAT gateway in AZ-a and AZ-a has an outage, every AZ loses outbound internet, which defeats the multi-AZ design. One NAT gateway per AZ, with each private route table pointing at its own AZ's gateway, keeps failures contained and also avoids cross-AZ data transfer charges. The cost is the hourly charge times the number of AZs. Newer regional NAT gateways give per-AZ presence automatically behind one ID.

How to answer

Failure domain first, then cost (hourly + per GB + cross-AZ), then the regional NAT gateway as the modern option.

Likely follow-ups
  • How do you cut NAT cost? (S3/DynamoDB gateway endpoints, interface endpoints for ECR, cache images, centralised egress VPC.)
  • What is ErrorPortAllocation? (Port exhaustion: over 55,000 concurrent connections from one NAT IP to one destination.)
Walk me through what happens to a packet from an internet user to an app running in a private subnet.

DNS resolves the name to the internet-facing load balancer's public IPs. The packet reaches the VPC's internet gateway, which translates the public IP to the load balancer node's private IP in a public subnet. The NACL and the load balancer's security group allow 443. The load balancer terminates TLS and opens a new connection from its private IP to a target's private IP in a private subnet; the local route carries it, the target's security group allows traffic from the load balancer's security group. On EKS with the VPC CNI the target can be the pod IP itself, delivered via the node's ENI and a host route to the pod's veth. Replies go back the same way; security groups are stateful so no return rules are needed.

How to answer

Draw it as you speak: DNS, IGW, public subnet, LB, private subnet, target. Name the control at each hop (route table, NACL, SG). Say explicitly that the backend is never directly reachable.

Likely follow-ups
  • What source IP does the app see? (The load balancer's private IP; the client IP is in X-Forwarded-For for ALB, or preserved with NLB client IP preservation.)
  • And outbound from the pod? (SNAT to node IP, NAT gateway, IGW.)
Your EKS pods are stuck in ContainerCreating with "failed to assign an IP address to container". What is going on and how do you fix it long term?

With the AWS VPC CNI each pod takes a real IP from the node's subnet, and the CNI keeps a warm pool of IPs per node. The subnet (or the node's ENI/IP limit for its instance type) is exhausted. Short term: check AvailableIpAddressCount, tune WARM_IP_TARGET/MINIMUM_IP_TARGET, or enable prefix delegation (the node gets /28 prefixes, raising pods per node). Long term: bigger subnets, add a secondary CIDR (AWS recommends 100.64.0.0/10) and use custom networking or subnet discovery so pods draw from it, or run the cluster on IPv6.

How to answer

Explain why EKS is different from an overlay CNI (real VPC IPs), then the two limits (subnet size and per-instance ENI/IP limits), then short vs long term fixes.

Likely follow-ups
  • Why not just use an overlay CNI? (Possible, e.g. Cilium in overlay mode, but you lose direct VPC routability of pods and some AWS integrations like target-type: ip.)
A database in an isolated subnet must back up to S3, but the subnet has no internet route. How?

Add an S3 gateway endpoint and associate it with the data subnet's route table. It adds a route with the S3 prefix list as destination and the endpoint as target, so traffic to S3 in the same region goes privately, for free, without NAT. Lock it down with an endpoint policy (only the backup bucket) and a bucket policy requiring aws:sourceVpce. Security groups and NACLs must allow 443 to the S3 prefix ranges.

How to answer

Name the endpoint type, how it routes (prefix list), that it is free, and how to restrict it from both sides.

Likely follow-ups
  • Would that work for an S3 bucket in another region? (No, prefix lists are per region; you need an interface endpoint or another path.)

60-second answer - "Design the network for this service on AWS."
"One VPC per environment per region with a non-overlapping /16 from our company plan. Three AZs. In each AZ a public subnet for the load balancer and a NAT gateway, a large private subnet for app nodes or EKS pods, and an isolated data subnet for the database. The public route table sends 0.0.0.0/0 to the internet gateway; each private table sends it to the NAT gateway in its own AZ; the data tables have only the local route. Gateway endpoints for S3 and DynamoDB, interface endpoints for ECR and secrets. Security groups reference each other: LB to app, app to DB. Flow logs on, everything in Terraform, and Transit Gateway when we connect to other VPCs or the office."
