Route tables and the Internet Gateway

Must know (SDE-1)

Every subnet is associated with exactly one route table. A table can serve many subnets. When you create a VPC you get a main route table; any subnet you do not explicitly associate silently uses it. Good practice: leave the main table with only the local route, and give every subnet an explicit table, so a forgotten subnet is isolated rather than accidentally public.

Each route is destination -> target. AWS picks the longest prefix match. If two routes have the same prefix, static routes beat propagated (VPN/BGP) ones. Every table has a local route for each VPC CIDR (10.10.0.0/16 -> local) that you cannot delete: it is what lets every subnet reach every other subnet in the VPC.

What the Internet Gateway really does

An Internet Gateway (IGW) is a horizontally scaled, redundant VPC component; one per VPC, no bandwidth limit you manage, no AZ to worry about, no cost of its own. For IPv4 it performs one-to-one NAT: an instance's OS only ever sees its private IP (10.10.1.25). When a packet leaves for the internet, the IGW rewrites the source to the instance's public IP (say 13.234.10.7); inbound packets to 13.234.10.7 are rewritten back to 10.10.1.25. That is why ip addr on an EC2 instance never shows the public IP. For IPv6 there is no NAT: addresses are globally unique, and you use an egress-only internet gateway when you want "outbound only" for IPv6.

From your world

A route table is a static FIB per subnet: the destination is the prefix, the target is the next hop (an interface-like object such as igw-, nat-, tgw-, pcx- or an ENI). The IGW is the edge router doing static 1:1 NAT (like ip nat inside source static on a Cisco box) for every instance that owns a public IP. The local route is the "connected" route you cannot remove. And there is no routing protocol inside the VPC: AWS's mapping service programs every hypervisor, so a route change takes effect without convergence or flapping.

Look at it from the CLI

aws ec2 describe-route-tables \
  --filters Name=association.subnet-id,Values=subnet-0priv1a \
  --query 'RouteTables[0].Routes[*].[DestinationCidrBlock,DestinationPrefixListId,GatewayId,NatGatewayId,State]' \
  --output table

A route in state blackhole means its target is gone (for example someone deleted the NAT gateway). Traffic matching it is dropped silently - one of the first things to check when "the private subnet lost internet".
