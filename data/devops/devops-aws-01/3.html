Public, private and isolated subnets, one of each per AZ

Must know (SDE-1)

Here is the sentence interviewers want to hear: a subnet is "public" only because its route table has a route 0.0.0.0/0 -> igw-.... There is no "public" checkbox. Same subnet, different route table, different answer.

Three words used from here on. A security group is a stateful firewall attached to each network interface (ENI): allow rules only, and replies are let back in automatically. A network ACL (NACL) is a stateless, numbered allow/deny list on the whole subnet, so return traffic needs its own rule. An Elastic IP is a static public IPv4 address you own and can move between resources. Both firewalls are taught in depth in Security groups vs NACLs.

Why repeat each tier in every AZ? Because a subnet lives in one AZ. If your app servers are all in the AZ-a private subnet and AZ-a has a power event, your whole app is gone. With one private subnet per AZ, the load balancer and the Auto Scaling Group (next page: Multi-AZ) keep serving from the survivors.

Public IP does not mean public subnet. An instance needs both: a route to the IGW in its subnet's table and a public IPv4 address (auto-assigned or an Elastic IP). Since February 2024 AWS charges for every public IPv4 address (USD 0.005 per hour, about USD 3.6 a month), which is another reason to keep app servers private and put only the load balancer in front.
