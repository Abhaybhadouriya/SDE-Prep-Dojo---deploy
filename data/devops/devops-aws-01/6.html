VPC endpoints: reach AWS services without the internet

Good to know (SDE-2)

Your private app talks to S3, DynamoDB, ECR, Secrets Manager and SQS all day. Without endpoints, that traffic goes app -> NAT gateway -> IGW -> the service's public endpoint. It stays on the AWS network, but you pay NAT processing on every byte and your isolated data subnets cannot do it at all. VPC endpoints fix both.

How it worksA route: destination = the service's prefix list, target = the endpoint. Added to the route tables you choose.An ENI with a private IP in each subnet you pick; private DNS makes the normal service name resolve to that IP
CostNo additional chargePer hour per AZ plus per GB
Reachable from on-prem / peered VPCsNo (route-table based, same region only)Yes (it is just an IP in your subnet)
SecurityEndpoint policy + bucket policy (aws:sourceVpce)Endpoint policy + a security group on the ENI

For an EKS cluster in fully private subnets, the usual minimum set is the S3 gateway endpoint (image layers live in S3) plus interface endpoints for ecr.api, ecr.dkr, sts, ec2 and logs. Gateway endpoint routes win over 0.0.0.0/0 -> nat because the prefix list entries are more specific (longest prefix match again).
