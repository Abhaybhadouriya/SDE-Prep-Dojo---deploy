What Kubernetes is not

Must know (SDE-1)

Beginners often think Kubernetes does everything. The official overview page is careful to say what it does not do. In plain words:

  • It does not build your code or images. You still use Docker (or another builder) and a CI system to build images and push them to a registry. Kubernetes only runs images that already exist.
  • It does not run containers itself. On each node, a container runtime such as containerd or CRI-O (two programs that implement the Container Runtime Interface, the plug-in API the kubelet uses) starts the containers. Kubernetes tells the runtime what to do. (Since v1.24, Kubernetes no longer talks to Docker Engine directly, but images built with Docker still run fine, because they follow the OCI image standard (OCI = Open Container Initiative, the open, vendor-neutral format for container images).)
  • It is not a full platform. It does not give you a database, a message queue, logging or monitoring out of the box. You install those, often as apps running on Kubernetes (for example Kafka with the Strimzi operator, which you will meet in Deploy on Kubernetes).
  • It is not a virtual machine manager. Containers on a node share that node's Linux kernel. Kubernetes places processes; the cloud or your hypervisor provides the machines.
  • It does not make a bad app reliable. If your app cannot handle being restarted or having two copies at once, Kubernetes will expose that problem quickly.

You might confuse this with... Kubernetes namespace vs Linux namespace. They share a name and nothing else. A Linux namespace is a kernel feature that changes what a process can see (its own PID numbers, network stack, mount table). Containers are built from these. A Kubernetes namespace is just a folder-like label for API objects, such as team-payments or kube-system, so that names do not clash and you can apply permissions and quotas per team. Putting two pods in different Kubernetes namespaces does not give them different Linux namespaces, and it is not a security wall on its own.
