Quick quiz

You tell Kubernetes "I want 3 replicas". Which style is that?

  1. Imperative
  2. Declarative
  3. Event-driven
You describe the end state, not the steps. Kubernetes works out and keeps re-working the steps.

A pod is deleted by mistake. Why does a new one appear with a different name?

  1. The kubelet copies the old pod
  2. Kubernetes keeps a backup of every pod
  3. A controller sees fewer pods than desired and creates a new Pod object
The ReplicaSet controller only counts. Want 3, have 2, so it creates one new Pod. New object, new name, new IP.

What does "level-triggered" mean for a controller?

  1. It looks at the current state every time, so missed events are fixed on the next pass
  2. It only reacts when an event arrives
  3. It runs only when CPU is low
Like a polling loop that checks the queue level, rather than an interrupt that might be lost.

Which of these does Kubernetes NOT do by itself?

  1. Restart crashed containers
  2. Build your Docker image from source code
  3. Spread traffic across healthy pods
Building images is the job of Docker or another builder in your CI pipeline. Kubernetes runs images that already exist in a registry.

A node loses power. Roughly how long until its pods are replaced elsewhere, with default settings?

  1. About 1 second
  2. About 10 seconds
  3. About 5-6 minutes
About 50 seconds to mark the node NotReady, then a default 300-second toleration before eviction. Then scheduling and start-up.

Two teams' pods are in different Kubernetes namespaces. Are they isolated at kernel level?

  1. No, a Kubernetes namespace is only an API grouping; they may share a node and kernel
  2. Yes, each Kubernetes namespace gets its own kernel
  3. Yes, each Kubernetes namespace is a separate VM
Kubernetes namespaces scope names, permissions and quotas. Real isolation needs more (policies, separate node pools, sandboxed runtimes, or separate clusters).
