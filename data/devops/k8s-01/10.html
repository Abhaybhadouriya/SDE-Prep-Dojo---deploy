Common mistakes and gotchas

Good to know (SDE-2)

"Kubernetes will make my app highly available." Only if you run more than one copy, on more than one node, with health checks. One replica on Kubernetes is still one replica.

Treating pods like pets. Pods are disposable. They get new names and new IPs when replaced. Never hard-code a pod IP; use a Service (page 05). Never store important data only inside a container's filesystem; use a volume (page 08).

Expecting instant failover from a dead node. By default it takes minutes, not seconds (see above). Plan for it with multiple replicas spread across nodes and zones.

Mixing imperative and declarative. If you kubectl scale by hand but your YAML in git says replicas: 3, the next apply silently puts it back. Pick one source of truth (usually git).

Running Kubernetes for one tiny app. You take on upgrades, security patches and add-ons for very little gain. Say this honestly in interviews; it shows judgement.
