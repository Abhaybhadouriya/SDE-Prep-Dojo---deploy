Try it: see transactions and isolation levels for yourself

One broker in Docker is enough. (Transactions need the internal topic __transaction_state; on a single broker its replication factor must be 1 - the official image's default single-node config already handles that.)

$ docker run -d --name kafka -p 9092:9092 apache/kafka:4.4.0
$ docker exec -it kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 \
    --create --topic payments --partitions 1
Created topic payments.

Save this as txn_demo.py (needs pip install confluent-kafka). It commits one transaction and aborts another:

from confluent_kafka import Producer

p = Producer({"bootstrap.servers": "localhost:9092", "transactional.id": "demo-1"})
p.init_transactions()

p.begin_transaction()
p.produce("payments", key="ord-1", value="PAID 500")
p.commit_transaction()          # visible to everyone

p.begin_transaction()
p.produce("payments", key="ord-2", value="PAID 900")
p.abort_transaction()           # hidden from read_committed readers
print("done")

Now read the topic twice, once per isolation level:

$ python txn_demo.py
done
$ docker exec -it kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 \
    --topic payments --from-beginning --formatter-property print.key=true \
    --command-property isolation.level=read_uncommitted --timeout-ms 5000
ord-1   PAID 500
ord-2   PAID 900
Processed a total of 2 messages
$ docker exec -it kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 \
    --topic payments --from-beginning --formatter-property print.key=true \
    --command-property isolation.level=read_committed --timeout-ms 5000
ord-1   PAID 500
Processed a total of 1 messages

The aborted record really is in the log - a read_uncommitted reader shows it. Check the end offset: two records plus two control markers means the log ends at 4, not 2.

$ docker exec -it kafka /opt/kafka/bin/kafka-get-offsets.sh --bootstrap-server localhost:9092 --topic payments
payments:0:4

Inspect transactions with the admin tool (Kafka 3.0+). The output columns look like this:

$ docker exec -it kafka /opt/kafka/bin/kafka-transactions.sh --bootstrap-server localhost:9092 list
TransactionalId  Coordinator  ProducerId  TransactionState
demo-1           1            0           CompleteAbort
$ docker exec -it kafka /opt/kafka/bin/kafka-transactions.sh --bootstrap-server localhost:9092 \
    find-hanging --broker-id 1
# lists transactions open longer than the max timeout - the ones that freeze read_committed readers

Exact numbers (producer ID, coordinator ID) will differ on your machine. What matters: aborted data is physically present, hidden only by the reader's isolation level, and offsets jump over markers.
