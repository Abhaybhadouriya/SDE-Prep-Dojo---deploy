Across hosts: overlay (VXLAN), macvlan and ipvlan

A bridge network lives on one host. To connect containers on different machines you need either a tunnel or real L2/L3 presence on the physical network.

  • overlay is used by Docker Swarm (Docker's built-in orchestrator, mostly replaced by Kubernetes in industry). Ports to open between nodes: TCP 2377 (cluster management), TCP/UDP 7946 (gossip between nodes), UDP 4789 (VXLAN data). --opt encrypted adds IPsec ESP between hosts, and then IP protocol 50 (ESP) must also be allowed between the nodes, in addition to UDP 4789, TCP/UDP 7946 and TCP 2377. If it is blocked, encrypted overlays fail silently: the control plane works, but data packets vanish.
  • macvlan gives each container its own MAC and IP on the physical LAN, so it looks like a separate physical machine. With -o parent=eth0.50 Docker creates an 802.1Q sub-interface for VLAN 50. Two gotchas: many NICs and virtual switches need promiscuous mode, and the host cannot talk to its own macvlan containers through the parent interface (a classic macvlan limit; you add a macvlan interface on the host to work around it).
  • ipvlan gives containers their own IPs but shares the parent's MAC. L2 mode behaves like macvlan without extra MACs, useful when port security limits MACs per switch port. L3 mode routes between the parent and containers, with no broadcast domain at all.
# A container that appears on VLAN 50 of the physical network
docker network create -d macvlan \
  --subnet 192.168.50.0/24 --gateway 192.168.50.1 \
  -o parent=eth0.50 vlan50
docker run -d --name legacy --network vlan50 --ip 192.168.50.20 nginx:1.30

From your world

Overlay is a VXLAN fabric with one VNI per Docker network; Swarm's gossip protocol plays the role that EVPN plays in a data-centre fabric (telling each VTEP which MAC/IP lives behind which remote VTEP). macvlan with parent=eth0.50 is a VLAN sub-interface on a trunk. ipvlan L2 is like many IPs behind one MAC. Where it breaks: there is no BGP or route reflector here; Docker's control plane is much simpler than a real fabric, and on Kubernetes the CNI plugin (Flannel VXLAN, Calico BGP, Cilium eBPF) replaces all of this.
