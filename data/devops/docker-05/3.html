Why "localhost" lies inside a container

This answers the classic "it works on my laptop but not in the container" question. Every network namespace has its own loopback interface. So localhost inside a container means "this container", not the host and not other containers.

  1. Symptom 1: "Connection reset" (from the host) or "connection refused" (from another machine) on the published port. Your Flask/Node dev server listens on 127.0.0.1:5000 inside the container. The forwarded packet arrives on eth0, nothing listens there, and the connection fails. (Why a reset and not "refused"? When you connect from the host, the docker-proxy helper usually accepts your TCP connection first, then fails to reach the app and closes it, so you see a reset or an empty reply. From another machine, the packet is DNAT'd straight to the container's eth0, where nothing listens, so the kernel answers with a RST and you see "connection refused".) Fix: flask run --host 0.0.0.0 (or your framework's equivalent).
  2. Symptom 2: app cannot reach the database at localhost:5432. The database is a different container, so it has a different loopback. Fix: put both on a user-defined network and connect to db:5432 by name.
  3. Symptom 3: container needs a service on the host. On Docker Desktop use host.docker.internal. On Linux add --add-host=host.docker.internal:host-gateway, which writes the bridge gateway IP into the container's /etc/hosts.
