Debugging "pod cannot reach the Service"

Deep dive (platform teams)

Work from the top of the stack down - the same discipline as tracing a packet through a router:

  1. DNS - nslookup backend from a debug pod. No answer? Check CoreDNS pods and whether a NetworkPolicy blocks UDP/TCP 53.
  2. Endpoints - kubectl get endpointslices -l kubernetes.io/service-name=backend. Empty? Selector vs labels mismatch, or pods are not Ready (readiness probe failing).
  3. Ports - does targetPort match the port the container actually listens on? Is the app bound to 0.0.0.0, not 127.0.0.1?
  4. Bypass the Service - curl a pod IP directly. Works? The problem is in Service/kube-proxy. Fails? It is the pod or the CNI.
  5. Policy - kubectl get networkpolicy -A: is a default-deny in place?
  6. Node dataplane - kube-proxy / CNI agent pods healthy? Rules present (iptables-save or nft list ruleset)? conntrack full? MTU?
# a throwaway debug pod with dig, curl, tcpdump, etc.
kubectl run netshoot --rm -it --image=nicolaka/netshoot -- bash
  dig backend.default.svc.cluster.local +search
  curl -sv http://backend:80/healthz
  curl -sv http://10.244.2.9:8080/healthz      # straight to a pod

# attach a debug container to an existing pod (shares its network namespace)
kubectl debug -it frontend-5c9d --image=nicolaka/netshoot --target=frontend

# forward a Service to your laptop to test it from outside
kubectl port-forward svc/backend 8080:80
