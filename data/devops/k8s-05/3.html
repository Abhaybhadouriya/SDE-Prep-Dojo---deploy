Service types: inside-only to internet-facing

Must know (SDE-1)

The types are layered: each one builds on the previous.

TypeReachable fromHowUse it for
ClusterIP (default)Inside the clusterVirtual IP + DNAT rules on every nodeService-to-service calls (95% of Services)
NodePortAnyone who can reach a node IPSame port (30000-32767) on every node, then ClusterIP rulesLabs, or as the target behind an external LB
LoadBalancerThe internet / VPCcloud-controller-manager creates a cloud LB pointing at nodes (or straight at pod IPs on some clouds)Exposing one L4 service; Ingress/Gateway controllers themselves
Headless (clusterIP: None)InsideNo virtual IP; DNS returns the pod IPs directlyStatefulSets, Kafka brokers, client-side load balancing (gRPC)
ExternalNameInsideDNS CNAME to an outside name; no proxyingPointing db at mydb.example.com

You might confuse this with... a LoadBalancer Service is L4 (TCP/UDP, one per service, one cloud LB each, so it gets expensive). Ingress / Gateway is L7 HTTP routing: one entry point for many services, routing by host and path. See Ingress & Gateway API.
