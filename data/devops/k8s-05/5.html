Across nodes: overlay (VXLAN), routing (BGP), cloud and eBPF

Must know (SDE-1)

The underlay network (your data-center switches or cloud VPC) knows node IPs like 192.168.1.11, but it has no idea that 10.244.2.0/24 lives behind node-2. There are three ways to fix that:

  1. Overlay (encapsulate). Wrap the pod packet inside a UDP packet addressed node-to-node. The underlay only sees node IPs. Flannel's default is VXLAN; Calico and Cilium can do it too.
  2. Routing (teach the network). Each node advertises "10.244.2.0/24 is behind me" with BGP (Calico's classic mode), or the nodes share one L2 segment and add plain routes (Flannel host-gw). No encapsulation, full MTU.
  3. Cloud-native (pods get real VPC IPs). The AWS VPC CNI gives pods secondary IPs from the node's network interfaces (ENIs, Elastic Network Interfaces: a cloud VM's virtual NICs), so the VPC itself routes them. Fast and simple, but you can run out of subnet IPs.

From your world

You already know all of this. Each node's flannel.1 is a VTEP; Flannel's agent fills the forwarding database (bridge fdb) and ARP entries from data in the Kubernetes API instead of using multicast flood-and-learn. Calico's BGP mode is a real BGP speaker (BIRD) on each node, peering full mesh or through route reflectors, exactly like iBGP. Where it breaks: in Kubernetes the "control plane" for these tunnels and routes is the Kubernetes API itself, and when that goes wrong it goes wrong in Kubernetes-specific ways (see the Reddit story below).

eBPF: Cilium

eBPF lets you load small verified programs into the kernel at hooks such as tc (traffic control) and XDP (eXpress Data Path: an eBPF hook in the NIC driver that runs before the kernel even allocates an skb). Cilium uses this to forward pod traffic, enforce L3-L7 policy, and even replace kube-proxy entirely: instead of NAT rules, it can translate the Service IP to a pod IP at the socket level, when the app calls connect(), so the packet leaves the pod already addressed to the real backend. Cilium is the dataplane behind GKE Dataplane V2 (Google's name for its eBPF-based cluster networking) and an option on AKS ("Azure CNI powered by Cilium").
