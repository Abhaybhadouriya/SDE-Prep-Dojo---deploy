Your first Service

Must know (SDE-1)

A Service picks pods by label selector, exactly like a ReplicaSet does (see Deployments). It has a port (what clients call) and a targetPort (what the container listens on).

apiVersion: v1
kind: Service
metadata:
  name: backend
  namespace: default
spec:
  type: ClusterIP          # the default; reachable only inside the cluster
  selector:
    app: backend           # every Ready pod with this label is a backend
  ports:
  - name: http
    port: 80               # clients call backend:80
    targetPort: 8080       # the container listens on 8080
    protocol: TCP
$ kubectl get svc backend
NAME      TYPE        CLUSTER-IP    EXTERNAL-IP   PORT(S)   AGE
backend   ClusterIP   10.96.45.10   <none>        80/TCP    1m

$ kubectl get endpointslices -l kubernetes.io/service-name=backend
NAME            ADDRESSTYPE   PORTS   ENDPOINTS                         AGE
backend-x7k2p   IPv4          8080    10.244.1.7,10.244.2.9,10.244.2.12  1m

$ kubectl run tmp --rm -it --image=busybox:1.36 --restart=Never -- wget -qO- http://backend
<html>... response from one of the three pods ...</html>

Two controllers do the bookkeeping, both inside kube-controller-manager:

  • The EndpointSlice controller watches pods and Services. Whenever a pod matching the selector becomes Ready (or stops being Ready), it updates the Service's EndpointSlices - lists of pod IP:port pairs, up to 100 endpoints per slice by default.
  • The ClusterIP itself is allocated by the API server from the service CIDR (with kubeadm the default is 10.96.0.0/12).

Then kube-proxy on every node watches Services and EndpointSlices and programs the kernel so that packets to 10.96.45.10:80 get rewritten to one of the pod IPs. More on that below.

Most common bug: the Service selector does not match the pod labels (a typo such as app: backnd). The Service exists, has an IP, DNS resolves... and EndpointSlices are empty, so every connection fails. Always check endpoints first.
