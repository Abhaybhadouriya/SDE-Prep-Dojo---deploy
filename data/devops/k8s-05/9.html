Traffic policies, source IPs and NetworkPolicy

Must know (SDE-1)

For traffic from outside (NodePort / LoadBalancer), there is a choice:

  • externalTrafficPolicy: Cluster (default) - any node accepts traffic and may forward it to a pod on another node. To make the reply come back through the same node, it SNATs the packet, so the pod sees the node's IP, not the client's. Even spread, extra hop, client IP lost.
  • externalTrafficPolicy: Local - a node only sends to pods on itself. The client IP is preserved and there is no extra hop. But nodes without a ready pod fail the load balancer's health check (on purpose, so the LB skips them), and load can become uneven if pods are not spread evenly.
  • internalTrafficPolicy: Local - for in-cluster traffic, only use endpoints on the same node. Useful for a per-node DaemonSet such as a local agent.

NetworkPolicy is the firewall layer: by default every pod can talk to every pod. Once any policy selects a pod, only the traffic the policies allow gets through in that direction. It is enforced by the CNI (Calico, Cilium); plain Flannel ignores it silently. A full treatment, with a default-deny example and the "remember to allow DNS" trap, is on Security & RBAC.
