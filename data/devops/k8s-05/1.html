The Kubernetes network model: three rules

Must know (SDE-1)

Kubernetes does not ship its own network. It sets rules, and a plugin must make them true:

  1. Every pod gets its own IP. Not a port on the host, a real IP. Containers inside one pod share it and talk over localhost.
  2. Any pod can reach any other pod without NAT, on any node. Pod B sees pod A's real IP as the source.
  3. Node agents (like the kubelet) can reach every pod on their node.

Those rules create four problems to solve, and this page covers each:

ProblemSolved bySection
Container to container in one podShared network namespace: localhostPods
Pod to pod (same node and across nodes)CNI plugin: veth, bridge or routes, overlay or BGP or eBPFPod networking
Pod to Servicekube-proxy (iptables / nftables / IPVS) or eBPF, plus CoreDNSkube-proxy, DNS

From your world

Think of the cluster as one big flat L3 routed domain where every pod is a host with its own /32, and each node owns a subnet (the pod CIDR, for example 10.244.1.0/24 on node-1, 10.244.2.0/24 on node-2) - just like each site or interface owning a prefix. How packets get between subnets (tunnel or routing protocol) is the CNI's choice. Where it breaks: nobody runs a routing protocol between pods; the "routes" are programmed by an agent from data in the Kubernetes API.
