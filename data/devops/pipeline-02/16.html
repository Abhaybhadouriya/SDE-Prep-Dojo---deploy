Quick quiz

Why does topics-init show Exited (0) and that is good news?

  1. It crashed but Compose ignores it
  2. It is a one-shot container that created the topics and finished successfully
  3. It is paused until you need it
Exit code 0 means success. Services wait on service_completed_successfully, so they start only after the topics exist.

From inside the enricher container, which address should the Kafka client use?

  1. kafka-1:19092,kafka-2:19092,kafka-3:19092
  2. localhost:9092
  3. 127.0.0.1:29093
Containers resolve service names via Docker DNS and use the INTERNAL listener. localhost would be the container itself; 29093 is the controller port.

You send the same order JSON with the same order_id twice. How many rows end up in Postgres?

  1. Two
  2. Zero, the second one cancels the first
  3. One, because the sink upserts on order_id
Kafka has two records; the second upsert updates the existing row. That is effectively-once at the sink.

Load is 50 orders/s and each enricher handles 20/s. How many enricher instances do you need, at minimum, to stop lag from growing?

  1. 2
  2. 3
  3. 6
2 x 20 = 40 is less than 50, so lag still grows. 3 x 20 = 60 is more than 50, so it drains at about 10/s.

You start --scale enricher=8 on a 6-partition topic. What do the 7th and 8th instances do?

  1. Share partitions with the others
  2. Read the retry topic instead
  3. Sit idle as standbys; each partition has one owner per group
Parallelism inside a group is capped by the partition count.

You sent one order and analytics printed no WINDOW line. Why?

  1. The window closes only when newer events move the watermark past its end plus allowed lateness
  2. analytics is broken
  3. analytics only reads the DLQ
Event-time windows need later events to know that a minute is "done". Keep sending orders.

You edited db/init.sql and restarted. Nothing changed. Why?

  1. Postgres caches SQL files
  2. Init scripts run only when the data volume is empty; you need down -v
  3. Compose does not mount the file
The Postgres image runs /docker-entrypoint-initdb.d files only on first initialisation of the data directory.

Which command shows lag per partition for one consumer group?

  1. docker compose ps
  2. kafka-topics.sh --describe
  3. kafka-consumer-groups.sh --describe --group enricher
kafka-topics shows leaders and ISR; consumer-groups shows offsets and lag.
