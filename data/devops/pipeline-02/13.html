Troubleshooting and common mistakes

SymptomCause and fix
kafka-1 keeps restarting, log says Invalid cluster.idAn old volume was formatted with a different KAFKA_CLUSTER_ID. Run docker compose down -v.
topics-init exits 1A broker was not ready. docker compose up -d topics-init runs it again; --if-not-exists makes that safe.
.sh scripts fail with $'\r': command not foundWindows line endings (CRLF). The repo's .gitattributes forces LF; or run dos2unix scripts/*.sh scripts/chaos/*.sh.
Services log Failed to resolve 'kafka-1:19092'They started before the brokers were resolvable; librdkafka retries by itself. If it continues, check docker compose ps.
A host tool cannot connect to localhost:9092Use all three: localhost:9092,localhost:9192,localhost:9292. Inside containers use kafka-1:19092. That is why there are two client listeners.
order-api returns 503 producer queue fullBrokers are down or slow and the producer buffer is full. This is backpressure working. Check broker health.
order-api returns 504No broker ack within 10 s. Usually fewer than 2 brokers alive, so min.insync.replicas=2 cannot be met.
Lag never goes downA consumer crash-looping: docker compose logs enricher. A fatal ProducerFenced means two instances shared a transactional.id.
analytics shows no windowsNot a bug: windows close only when newer events push the watermark past window end + 10 s. Keep sending orders.
Grafana panels emptyWait 30 s for scrapes; open localhost:9090/targets: all should be UP.
Ports are not availableSomething else uses 8000, 8080, 3000, 5432 or 9092. Stop it, or change the left side of ports:.
Containers get OOM-killed (exit code 137) or Docker Desktop is slowRaise Docker's memory, or use compose.single-broker.yml.

Editing init.sql and expecting a change. Postgres runs files in /docker-entrypoint-initdb.d only when the data volume is empty. After the first start, edits are ignored until you docker compose down -v.

Using docker compose restart after changing .env. restart reuses the old container with the old environment. Use docker compose up -d <service>, which recreates the container when its configuration changed.

Running admin scripts against localhost:9092 inside a container. Inside kafka-1, localhost:9092 is the EXTERNAL listener, which advertises localhost:9092, and that only works for broker 1. Use kafka-1:19092 as the README does.
