Step 4: look at it in kafka-ui

Open localhost:8080. kafka-ui is a web console that talks to the cluster through the same admin and consumer APIs as the scripts above. No login is configured; it is a local lab.

  1. Brokers. Three brokers, ids 1 to 3, and which one is the active controller.
  2. Topics, then orders.created, then Messages. Find your order. Open it: the value is the JSON event, and the Headers show event-type: OrderCreated and schema-version: 1. Note the partition and offset match what the API returned.
  3. Topics, then orders.created, then Overview / Partitions. The same leader, replica and ISR table as the describe output, plus per-partition message counts. Send ten orders for C-42 and watch one partition's count grow while the others stay flat.
  4. Consumers. Four groups: enricher, retry-worker, postgres-sink, analytics. Open one to see its members and lag per partition.
  5. Topic settings. Each topic's configuration shows min.insync.replicas=2 and its retention.ms.

The image provectuslabs/kafka-ui is no longer updated; the maintained fork is ghcr.io/kafbat/kafka-ui, with the same environment variables. The compose file pins the older tag because it is stable and well known. Swapping is a one-line change.
