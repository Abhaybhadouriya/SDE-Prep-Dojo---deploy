The story: letters and a shared dictionary

Explain like I'm 5

Imagine kids in a class send each other secret letters in a made-up code. "Blip" means apple, "zork" means 3. If Asha changes her code and does not tell anybody, Ravi opens her letter and reads nonsense.

So the teacher keeps one big dictionary on her desk. Every code ever used is written on its own numbered page. When Asha writes a letter, she writes "see dictionary page 42" at the top. Ravi reads "page 42", looks it up once, and now he understands every letter that says "page 42".

And the teacher has a rule. If you want a new page, it must still make sense to kids who only know the old pages. You may add a new word, but you must say what it means if someone does not have it. You may never quietly change what "zork" means. If you break the rule, the teacher says "no" and does not add your page.

That dictionary is Schema Registry. The code is a schema: a precise description of the fields in a message and their types. The page number is the schema ID, and every Kafka message carries just that number, not the whole schema. The teacher's rule is the compatibility check.

Your questions answered. "What is Schema Registry and why do people care about Avro / Protobuf?" Kafka brokers only see bytes. They never check what is inside. In a company with hundreds of producers and consumers, the only thing stopping one team from breaking another is an agreed, machine-checked format. Avro and Protobuf give compact binary messages plus clear rules for changing them; Schema Registry stores the versions and enforces the rules. "How do schema changes roll out without breaking old consumers?" Make only compatible changes, check them in CI against the registry, and upgrade in the order the compatibility mode requires.
