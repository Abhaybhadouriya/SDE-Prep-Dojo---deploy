Common mistakes and gotchas

You might confuse these:

  • BACKWARD vs FORWARD: who upgrades first? BACKWARD means the new schema can read old data, so you upgrade consumers first, then producers. FORWARD means old schemas can read new data, so you upgrade producers first. FULL means both, so the order does not matter. Memory trick: the mode names what the new reader can look at; BACKWARD looks back at old data.
  • Subject vs topic. A topic is where Kafka stores records. A subject is the name under which the registry keeps a list of schema versions. With the default naming strategy the subject is the topic name plus -key or -value (orders-value), so they look alike, but one topic has two subjects, and other strategies can put several event types (subjects) in one topic.
  • Schema ID vs schema version. The ID is global and unique across the registry (it is what sits in each message). The version is a counter per subject (1, 2, 3). The same schema registered under two subjects keeps one ID but can have different version numbers.
