Quick quiz

What does a message produced with the registry's Avro serializer contain?

  1. The full schema followed by the data
  2. Only the Avro data, nothing else
  3. A magic byte, a 4-byte schema ID, then the Avro data
  4. A schema version number and a JSON copy of the data
Five bytes of header: magic byte 0 and the schema ID. The schema itself is fetched from the registry once and cached.

Under BACKWARD compatibility, which change is allowed?

  1. Adding a field with a default value
  2. Adding a required field with no default
  3. Changing a field from string to int
  4. Renaming a field without an alias
The new reader can fill the new field from its default when reading old records.

With FORWARD compatibility, who should be upgraded first?

  1. Consumers
  2. Producers
  3. The brokers
  4. It does not matter
FORWARD means old readers can read new data, so producers may start writing the new version before consumers upgrade.

Why prefer BACKWARD_TRANSITIVE over BACKWARD for a compacted customer topic?

  1. It allows more kinds of change
  2. It makes messages smaller
  3. It disables the compatibility check
  4. New consumers read from the beginning, so the newest schema must read every old version still stored
Non-transitive checks only compare with the latest version. Compacted and long-retention topics still hold records written with much older versions.

A consumer using a plain JSON deserializer fails with "unexpected character at position 0" on a topic. Most likely cause?

  1. The broker corrupted the data
  2. Compression is enabled
  3. The values are registry-encoded: the first bytes are the magic byte and schema ID
  4. The topic is compacted
Registry-encoded messages start with 0x00 and the 4-byte ID. Use the matching deserializer.

In Protobuf, you deleted field coupon = 4. What should you do with tag 4?

  1. Reuse it for the next new field
  2. Mark it reserved so it is never reused
  3. Renumber all later fields down by one
  4. Nothing; tags do not matter
Old data on disk still has tag 4. Reusing it would decode old coupon values into an unrelated new field.

The registry is down for 10 minutes. What still works?

  1. Producers and consumers that already cached the schema IDs they use
  2. Nothing: every message needs a registry call
  3. Only consumers
  4. Only producers with auto-register on
Lookups are cached per client. New clients, or a first-time schema, need the registry.
