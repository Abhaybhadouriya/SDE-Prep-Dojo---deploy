Compatibility modes and the upgrade order

This is the part interviewers probe. Each mode answers one question: who must be able to read whose data? "New schema" means the version being registered.

ModeGuaranteeAllowed changes (Avro)Upgrade first
BACKWARD (default)New schema can read data written with the previous versionDelete fields; add fields with defaultsConsumers
FORWARDPrevious schema can read data written with the new oneAdd fields; delete fields that had defaultsProducers
FULLBoth directions, against the previous versionAdd or delete only fields with defaultsAny order
*_TRANSITIVESame as above, but against all earlier versionsSame rules, checked across historyAs above
NONENo checksAnythingPray (or use a new topic)

A crisp way to say it: "BACKWARD means new readers understand old data, so I upgrade consumers first. FORWARD means old readers understand new data, so I upgrade producers first. FULL is both. Because Kafka retains history and consumers may replay from the beginning, I would choose BACKWARD_TRANSITIVE or FULL_TRANSITIVE for long-retention topics, so a new consumer can read every version still on disk."

How Avro resolves writer vs reader schema

Avro decoding uses two schemas: the writer's (from the schema ID in the message) and the reader's (the version compiled into the consumer). Fields are matched by name:

  • Field in writer but not in reader: skipped (ignored).
  • Field in reader but not in writer: filled with the reader's default. No default means an error, which is why the registry refuses that change under BACKWARD.
  • Type changes: only certain promotions are allowed (for example int to long, float to double). Anything else fails.
  • Renames: use aliases in the reader so it accepts the old name.

Protobuf matches fields by tag number instead. Unknown tags are skipped, missing ones get the type's zero value. So in Protobuf you can add fields freely, but you must never change a field's type in an incompatible way or reuse a deleted field's number; mark deleted numbers and names as reserved.
