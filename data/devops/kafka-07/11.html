Key takeaways

Remember this

  • Partition = folder; segment = .log + sparse .index + .timeindex, named by base offset. Only the active segment is written.
  • Offset lookup = floor search over segments, binary search in the mmapped index, short forward scan.
  • Fast because: sequential appends, page cache, sendfile() zero-copy reads, batching + compression, same format on wire and disk.
  • No fsync per message by default; durability comes from replication across racks/AZs.
  • Zero-copy is the read path only, and TLS disables it.
  • Retention deletes whole closed segments by time or per-partition size; it is "at least", not "exactly".
  • Compaction keeps the latest value per key; tombstones (null value) delete keys after delete.retention.ms.
  • Tiered storage keeps a hot local tail and offloads closed segments to object storage via a plugin; no compacted topics.
