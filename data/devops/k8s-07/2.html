$ kubectl create secret generic db-cred -n shop \
    --from-literal=username=app --from-literal=password='S3cr3t!'
secret/db-cred created

$ kubectl get secret db-cred -n shop -o yaml
apiVersion: v1
kind: Secret
type: Opaque
metadata:
  name: db-cred
  namespace: shop
data:
  password: UzNjcjN0IQ==
  username: YXBw

$ kubectl get secret db-cred -n shop -o jsonpath='{.data.password}' | base64 -d
S3cr3t!

Base64 is not encryption. One command decoded it. Anyone who can get Secrets in that namespace, anyone who can create a pod there (a pod can mount any Secret in its namespace), and anyone with access to etcd or its backups can read every Secret - unless you add protection. Never commit Secret YAML to git as-is.

Using a Secret in a pod looks exactly like a ConfigMap, with secretKeyRef / secretRef / a secret: volume. In YAML you may write plain text under stringData; the API server encodes it into data for you:

apiVersion: v1
kind: Secret
metadata:
  name: db-cred
  namespace: shop
type: Opaque
stringData:                     # write plain text here; stored base64 in .data
  username: "app"
  password: "S3cr3t!"           # keep the keys the pod below asks for, or it fails
  DB_URL: "postgres://db:5432/shop"
---
# api-tls (mounted below) is a kubernetes.io/tls Secret, made for example with:
#   kubectl create secret tls api-tls -n shop --cert=tls.crt --key=tls.key
---
# in the Deployment's pod template
        env:
        - name: DB_PASSWORD
          valueFrom:
            secretKeyRef:
              name: db-cred
              key: password
        volumeMounts:
        - name: tls
          mountPath: /etc/tls
          readOnly: true
      volumes:
      - name: tls
        secret:
          secretName: api-tls
          defaultMode: 0400     # owner read-only

Tip: prefer files over environment variables for secrets. Env vars leak more easily: they show up in /proc/<pid>/environ, crash dumps, debug endpoints that print the environment, and child processes inherit them. Files on a tmpfs mount with mode 0400 are easier to contain and can be rotated without restarting.
