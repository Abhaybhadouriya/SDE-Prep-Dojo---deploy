Advanced details and production lessons

Deep dive (platform teams)
  • Rotation without downtime. Support two valid credentials at once: add the new password to the database, update the Secret, roll the pods (or let them reload files), then remove the old password. The same "expand then contract" idea as schema changes.
  • Config is a deploy. Several big outages in the industry started with a configuration push, not a code push. Use the same canary and rollback discipline for config (versioned ConfigMaps or checksum annotations make that automatic) - see Deployments.
  • Missing keys stop pods. If a pod references a ConfigMap or Secret key that does not exist, the container will not start: status shows CreateContainerConfigError. Mark a reference optional: true only when the app truly copes without it.
  • Projected volumes combine several sources (ConfigMaps, Secrets, the Downward API and ServiceAccount tokens) into one directory. The Downward API exposes pod facts such as its name, namespace, labels and resource limits as env vars or files - handy for logging and for JVMs sizing their heap from the container limit.
  • Static pods (manifests the kubelet runs directly from disk) cannot reference ServiceAccounts, ConfigMaps or Secrets. This has always been documented, and v1.37 now rejects such static pods instead of letting them half-work. Use a DaemonSet if a per-node pod needs them.
  • Scale. Every mutable ConfigMap/Secret mounted by pods is watched or polled by kubelets. Thousands of pods mounting frequently changing objects means API server load; immutable: true removes that cost for objects that never change.
  • Not a database. The 1 MiB limit is per object, and etcd's default request limit is about 1.5 MiB. Large files (ML models, certificates bundles of many MB) belong in object storage or an image layer, not a ConfigMap.
