ConfigMaps: create one, use it two ways

Must know (SDE-1)

A ConfigMap is a namespaced object that holds key-value pairs, where a value can be a short string or a whole file. The limit is 1 MiB per object (it lives in etcd, which is not built for big blobs).

apiVersion: v1
kind: ConfigMap
metadata:
  name: shop-config
  namespace: shop
data:
  LOG_LEVEL: "info"
  FEATURE_NEW_CHECKOUT: "false"
  KAFKA_BOOTSTRAP: "kafka-bootstrap.kafka.svc:9092"
  app.properties: |            # a whole file as one key
    cache.ttl.seconds=60
    orders.page.size=20
# or imperatively
kubectl create configmap shop-config -n shop \
  --from-literal=LOG_LEVEL=info \
  --from-file=app.properties

A pod can consume it in two ways, and the difference matters a lot later:

    spec:
      containers:
      - name: api
        image: myorg/shop-api:1.8.0
        env:
        - name: LOG_LEVEL                  # one key, renamed if you like
          valueFrom:
            configMapKeyRef:
              name: shop-config
              key: LOG_LEVEL
        envFrom:                           # or: every key becomes a variable
        - configMapRef:
            name: shop-config
    spec:
      containers:
      - name: api
        image: myorg/shop-api:1.8.0
        volumeMounts:
        - name: config
          mountPath: /etc/shop             # each key becomes a file here
          readOnly: true
      volumes:
      - name: config
        configMap:
          name: shop-config
          items:                           # optional: pick keys
          - key: app.properties
            path: app.properties
$ kubectl exec -n shop deploy/shop-api -- printenv LOG_LEVEL
info

$ kubectl exec -n shop deploy/shop-api -- ls -la /etc/shop
lrwxrwxrwx 1 root root   21 Nov 23 10:02 app.properties -> ..data/app.properties
lrwxrwxrwx 1 root root   31 Nov 23 10:02 ..data -> ..2026_11_23_10_02_11.123456789
drwxr-xr-x 2 root root   60 Nov 23 10:02 ..2026_11_23_10_02_11.123456789

$ kubectl exec -n shop deploy/shop-api -- cat /etc/shop/app.properties
cache.ttl.seconds=60
orders.page.size=20

Notice those odd ..data symlinks. They are how the kubelet updates files atomically - we come back to them in a moment.

You might confuse this with... a ConfigMap is for non-sensitive settings; a Secret is for sensitive ones. Technically they behave almost the same (same 1 MiB limit, same env/volume options). The differences are about handling: Secrets get separate RBAC, can be encrypted at rest, are mounted on tmpfs (RAM) on nodes, and are hidden by many tools' output.
