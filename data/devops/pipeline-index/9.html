Remember this

  • ShopStream = order-api, Kafka (4 topics, 3 brokers), enricher, retry-worker, postgres-sink, analytics, Postgres, Prometheus, Grafana, kafka-ui.
  • The API does one thing: write the event durably and answer 202 ACCEPTED.
  • The key is customer_id: same customer, same partition, same order.
  • Temporary failures go to orders.retry; hopeless records go to orders.dlq. Nothing blocks the main flow.
  • Every reader has its own bookmark (offset). A slow reader only builds lag; it never slows the others.
  • The code is real and runnable: pipeline/code, started with docker compose up -d --build.
