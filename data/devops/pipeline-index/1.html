The whole system on one page

Here is everything you will run. Watch the dots: green dots are good orders flowing all the way to the database and the dashboard, the red dot is a broken order that is safely set aside. Do not try to memorise it yet. The next page, Pipeline Architecture, explains every box and every arrow.

In plain words, an order goes through five hops:

  1. The customer places an order. A script (loadgen.py) or you with curl sends JSON to POST /orders on the order-api.
  2. The API writes one event to Kafka. It builds an OrderCreated event, writes it to the topic orders.created with the customer id as the key, waits until Kafka has stored it safely on at least two brokers, and answers 202 ACCEPTED.
  3. The enricher checks and prices it. It reads orders.created, looks up each product price, and writes an OrderEnriched event to orders.enriched. Temporary failures go to orders.retry; hopeless ones go to orders.dlq.
  4. Two independent readers use the result. postgres-sink stores each order in Postgres. analytics adds up revenue per minute. They read the same topic but keep separate bookmarks, so one being slow never hurts the other.
  5. You watch it all. kafka-ui shows the topics and messages. Prometheus collects numbers like consumer lag. Grafana draws them.

New words, one line each. Event: a small record of something that happened ("order 7 was created"). Topic: a named stream of events, like a folder. Partition: one ordered slice of a topic; a topic is split into several so work can run in parallel. Producer: a program that writes events. Consumer: a program that reads them. Consumer group: a team of consumers that share the work of reading one topic. All of these are explained slowly in Kafka Core Concepts; see also the glossary.
