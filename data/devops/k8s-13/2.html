The whiteboard picture to redraw in 30 seconds

Half the questions below are easier if you sketch this first. Six boxes, two zones. Practise until you can draw it without looking.

The most asked one: "What happens when you run kubectl apply?"

Interviewers use this question to see if you know who does what. Click Next and say each step out loud. The trick: no component calls another directly. Each one writes to the API server, and the next one notices the change because it is watching.

  1. kubectl reads your YAML and sends it to the API server over HTTPS. With apply it is a server-side or three-way merge, not a blind overwrite.
  2. The API server checks who you are (authentication), what you may do (RBAC authorization) and runs admission controllers (defaults, policies, webhooks). Then it saves the Deployment object in etcd. kubectl returns now - nothing is running yet.
  3. The Deployment controller (inside kube-controller-manager) is watching Deployments. It sees the new one and creates a ReplicaSet object through the API server.
  4. The ReplicaSet controller sees a ReplicaSet that wants 3 replicas and has 0, so it creates 3 Pod objects. They have no node yet.
  5. The scheduler watches for Pods with an empty nodeName. It filters nodes (resources, taints, affinity), scores the rest and writes a binding: this Pod goes to node 2.
  6. The kubelet on node 2 watches for Pods bound to its node. It sees the new Pod and starts the work.
  7. The kubelet asks the container runtime (containerd, over CRI) to pull the image and start the containers; the CNI plugin gives the Pod its IP. Probes start running.
  8. When the readiness probe passes, the kubelet writes the Pod status back. The EndpointSlice controller adds the Pod IP, kube-proxy updates its rules, and the Service sends it traffic. Say "level-triggered reconcile loops" here.

From your world

This is like a routing control plane. You never program each line card by hand; you change the desired config in one database, and each agent that watches that database converges its own piece (forwarding table, ACLs) to match. If an agent restarts, it simply re-reads the desired state and catches up.
