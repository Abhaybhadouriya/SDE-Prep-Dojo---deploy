Three layers: Deployment, ReplicaSet, Pod

Must know (SDE-1)

There are three kinds of objects stacked on top of each other. Each one has exactly one job:

  1. Pod - one running copy of your app. It does not know about its brothers and sisters. If its node dies, it is gone forever.
  2. ReplicaSet - keeps exactly N pods that match a label (a name tag, such as app=web). Too few? It creates pods. Too many? It deletes some. That is all it does. It knows nothing about versions.
  3. Deployment - manages ReplicaSets over time. Each version of your pod template gets its own ReplicaSet. An upgrade means "grow the new ReplicaSet, shrink the old one". A rollback means "grow the old one again".

You might confuse this with... A Deployment runs your pods. A Service (next page, Services & Networking) gives those pods one stable address. They are separate objects that only meet through labels. Beginners often think "I made a Deployment, so it has an IP" - it does not.

Labels and selectors: how the parent finds its children

Kubernetes does not keep a list like "ReplicaSet X owns pods A, B, C" as the primary link. Instead, every pod wears labels (key=value tags), and the ReplicaSet has a selector (a query such as "all pods with app=web and pod-template-hash=5f8c6d"). The controller counts the pods that match the query. This is why a typo in a label is so dangerous: a pod with the wrong label is invisible to its parent, and the parent will happily create another.

Labels vs annotations (you will see both on every page from now on):

  • Labels are short key/value tags such as app: web or tier: frontend. They are selectable: ReplicaSets, Services, NetworkPolicies and kubectl get -l app=web all match on them. Keep them small and meaningful.
  • Annotations are notes for tools and humans, such as kubernetes.io/change-cause: "bump nginx to 1.28" or a Prometheus scrape hint. They can be long (even JSON), but nothing can select on them.

Rule of thumb: if a controller must find the object by it, it is a label; if it is just information about the object, it is an annotation.
