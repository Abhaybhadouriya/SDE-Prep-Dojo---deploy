Remember this

  • Deployment -> ReplicaSet (one per template version) -> Pods. You write Deployments.
  • The ReplicaSet controller in kube-controller-manager watches the API server and is level-triggered: it compares count vs desired and fixes.
  • Changing the pod template = new hash = new ReplicaSet = rollout. Changing replicas = just a scale.
  • maxSurge (default 25%, rounds up) = extra pods; maxUnavailable (default 25%, rounds down) = missing pods. Safe: 1 / 0.
  • Zero downtime needs readiness probes, SIGTERM handling, a preStop delay and backward-compatible changes.
  • kubectl rollout undo scales the previous ReplicaSet back up; revisionHistoryLimit default is 10.
  • Deployment = interchangeable, StatefulSet = identity + disk, DaemonSet = per node, Job/CronJob = has an end.
  • PDBs protect against voluntary disruptions (drains), not crashes. Node death means about 5 minutes before eviction by default.
