Self-healing: which process notices, and how

Must know (SDE-1)

"Kubernetes heals the pod" sounds like magic. It is not. Here is exactly who does what when a pod disappears. Click Next or Play.

  1. Normal day. The ReplicaSet wants 3 pods. Pods A, B, C are running on two nodes. Every component talks only to the API server; only the API server talks to etcd.
  2. Pod C dies. Maybe its process crashed for good, someone ran kubectl delete pod, or it was evicted. The pod object is removed or marked failed through the API server.
  3. The ReplicaSet controller notices. It runs inside kube-controller-manager and holds a long-lived watch on pods. The API server pushes a "pod deleted" event. The controller counts matching pods: 2, but desired is 3.
  4. It creates a new pod object. The controller POSTs pod D to the API server, with an ownerReference to the ReplicaSet. Pod D has no nodeName, so it is Pending.
  5. The scheduler places it. kube-scheduler watches for pods with no node, filters nodes that fit (CPU/memory requests, taints, affinity), scores the rest, and writes a Binding: D goes to node-2.
  6. kubelet runs it. The kubelet on node-2 watches for pods bound to its node, asks the container runtime (containerd) to start it, and reports status back. When the readiness probe passes, D receives traffic. Count is 3 again.

From your world

The ReplicaSet controller is a reconciliation loop, the same shape as a routing daemon keeping the FIB in sync with the RIB: it reacts to events (like netlink notifications) and periodically re-lists everything to catch missed events. This is called level-triggered: it acts on "the current level is 2, want 3", not on "an event said -1". So a lost event cannot cause permanent drift. Where the analogy breaks: there is no hardware here; "programming" means writing objects to the API server, and a separate agent (kubelet) on each node does the real work, like a line-card agent.

Trap: "Does Kubernetes replace pods on a dead node instantly?" No. If a whole node dies, its kubelet stops renewing its heartbeat Lease. The node controller waits for the grace period (default 50 s) before marking it NotReady, and pods carry a default toleration of 300 s for not-ready/unreachable before they are evicted. So replacements typically appear after roughly 5-6 minutes, not seconds. A plain pod crash on a healthy node is much faster: the kubelet simply restarts the container in place.
