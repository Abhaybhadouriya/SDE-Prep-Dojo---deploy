Remember this

  • There is no "container" object in the kernel: it is a process + namespaces + cgroups + a root filesystem + security filters.
  • Namespaces = what you can see (pid, net, mnt, uts, ipc, cgroup; user and time optional). Inspect with /proc/PID/ns, enter with nsenter.
  • cgroup v2 = what you can use. Memory over memory.max = OOM kill (exit 137). CPU over cpu.max = throttling, not killing.
  • OverlayFS = lower (image, read-only) + upper (container, writable) + merged. Copy-up copies whole files; deletes are whiteouts.
  • Chain: CLI -> dockerd -> containerd -> shim -> runc -> your process. runc exits; the shim stays so daemons can restart.
  • OCI = image, runtime and distribution specs, so Docker-built images run on containerd, CRI-O, gVisor and Kata.
  • Default Docker keeps 14 capabilities and a seccomp allowlist; no user namespace by default, so root inside is UID 0 outside.
  • Shared kernel = weaker isolation than a VM. Untrusted code: gVisor or microVMs.
