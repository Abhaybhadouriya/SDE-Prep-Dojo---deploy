Build a container from scratch (putting it together)

Liz Rice's famous talk builds a container live in about 60 lines of Go. Here is the same idea as a bash script you can read top to bottom. It uses an Alpine root filesystem, a cgroup, and unshare. Run it on a Linux VM as root.

#!/usr/bin/env bash
# mini-container.sh - a toy container. For learning only. Run as root on cgroup v2.
set -euo pipefail
ROOT=/tmp/mini/rootfs
CG=/sys/fs/cgroup/mini

# 1. A root filesystem: borrow one from an image (any OCI image works).
mkdir -p "$ROOT"
[ -e "$ROOT/bin/sh" ] || docker export "$(docker create alpine:3.24)" | tar -C "$ROOT" -xf -

# 2. A cgroup with limits (the "meter").
mkdir -p "$CG"
echo 64M          > "$CG/memory.max"
echo "50000 100000" > "$CG/cpu.max"      # half a core
echo 32           > "$CG/pids.max"
echo $$           > "$CG/cgroup.procs"   # this shell and its children are now metered

# 3. New namespaces (the "walls"), then switch root and start a shell as PID 1.
exec unshare --pid --fork --mount --uts --ipc --net --cgroup \
  /bin/sh -c "
    hostname mini
    mount --make-rprivate /
    mount --bind $ROOT $ROOT
    cd $ROOT
    mkdir -p old_root
    pivot_root . old_root
    mount -t proc proc /proc
    umount -l /old_root && rmdir /old_root
    exec /bin/sh
  "
$ sudo ./mini-container.sh
/ # hostname
mini
/ # ps
PID   USER     TIME  COMMAND
    1 root      0:00 /bin/sh
    5 root      0:00 ps
/ # ip link
1: lo: <LOOPBACK> mtu 65536 qdisc noop state DOWN qlen 1000
/ # cat /etc/alpine-release
3.24.x

What is missing compared with Docker: no overlay (we used one plain folder, so writes change it forever), no veth or bridge, no capability dropping, no seccomp filter, no user namespace, no log handling and no clean-up. Each of those is a few more steps. That gap is exactly the value runc and Docker add. Why pivot_root instead of chroot? A root process can break out of a chroot (chroot only changes path lookup for one process); pivot_root swaps the root mount for the whole mount namespace, and after we unmount the old root, the host's files are simply not reachable. If you prefer C, containers-the-hard-way does it step by step; bocker implements a toy Docker in about 100 lines of bash.
