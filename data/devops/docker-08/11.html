Quick quiz

Which kernel feature stops one container from using all of the host's RAM?

  1. The mount namespace
  2. seccomp
  3. The memory controller of cgroups
  4. OverlayFS
Namespaces only hide things. Limits come from cgroups; memory.max is the cap and the OOM killer enforces it.

A container has --cpus=0.5 and runs a busy loop. What happens?

  1. It is killed with exit code 137
  2. It runs about 50 ms of every 100 ms period and is throttled the rest
  3. Docker restarts it
  4. Nothing; CPU limits are advisory
cpu.max becomes 50000 100000. The CFS bandwidth controller pauses the group when the quota is used up. CPU limits throttle; only memory limits kill.

Why do you need --fork in unshare --pid --fork bash?

  1. Because only children of the caller enter the new PID namespace, and the first child becomes PID 1
  2. Because unshare cannot run bash directly
  3. To create a new network namespace
  4. To mount /proc
After unshare(CLONE_NEWPID) the caller stays where it is; its next child becomes PID 1 in the new namespace. --fork makes that child run bash.

A container edits a 1 GB file that came from an image layer. What does OverlayFS do on the first write?

  1. Writes only the changed block into the upper layer
  2. Edits the image layer in place
  3. Refuses because layers are read-only
  4. Copies the whole 1 GB file into the upper layer, then edits the copy
Copy-up is file-level, not block-level. That is why big, frequently written files belong on volumes.

After docker run -d nginx, which program is the direct parent of the nginx process on the host?

  1. dockerd
  2. runc
  3. containerd-shim-runc-v2
  4. The docker CLI
runc creates the container and exits. The shim stays as the parent, holds stdio and reports the exit code, so dockerd and containerd can restart without killing the container.

What does Docker's default seccomp profile do?

  1. Encrypts container traffic
  2. Blocks a list of risky system calls (about 44) before the kernel runs them
  3. Maps container root to an unprivileged host UID
  4. Limits CPU usage
seccomp is a BPF filter on system calls. UID mapping is the user namespace; CPU limits are cgroups.

Kubernetes removed dockershim in v1.24. What happened to images built with docker build?

  1. They keep working, because they are OCI images that containerd and CRI-O run
  2. They must be rebuilt with a Kubernetes tool
  3. They only run on Docker Desktop
  4. They need to be converted to VM images
The OCI image spec is the shared contract. Only the runtime adapter changed; kubelet talks CRI to containerd or CRI-O.

Which is the strongest isolation for running untrusted customer code?

  1. A container with --privileged
  2. A container running as a non-root USER
  3. A Firecracker microVM per workload
  4. A separate Kubernetes namespace
A microVM gives each workload its own guest kernel behind hardware virtualization. A Kubernetes namespace is only API scoping, and --privileged removes protections.
