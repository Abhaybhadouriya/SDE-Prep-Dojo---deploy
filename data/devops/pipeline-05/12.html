The same drills on Kubernetes

With the cluster from Deploy on Kubernetes, k8s-drills.sh runs the broker, pause, poison and rebalance drills against Strimzi:

  • broker: deletes a broker pod. Watch kubectl -n kafka get pods -w: Strimzi recreates a pod with the same name, it reattaches the same PersistentVolumeClaim, and it only catches up the gap. The under-replicated list shows the same story as drill 1.
  • pause: scales postgres-sink to 0 replicas for 30 seconds. Lag grows, then drains when the 2 replicas return. (This is a clean stop, so the members leave the group at once; compare that with drill 2's frozen process.)
  • poison: writes "not json" into orders.created and reads the DLQ.
  • rebalance: prints the ScaledObject, the HPA and group members, so you can see KEDA's decision next to Kafka's assignment.

Pod names include node IDs, which can differ per cluster, so the script finds the broker pods by the label strimzi.io/pool-name=broker instead of hard-coding names. It runs the admin tools in the first broker and deletes the second.
