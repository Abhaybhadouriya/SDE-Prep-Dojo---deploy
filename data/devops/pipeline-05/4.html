Reading the Grafana dashboard

The dashboard file is infra/grafana/dashboards/shopstream-lag.json, loaded automatically at start. Its ten panels, and what each one is for:

PanelHealthy looks likeLook closer when
Total enricher lagnear 0, small spikesa line that keeps rising
Total sink lagnear 0rising while enricher lag is flat: the database is slow
DLQ end-offset span (includes txn markers)flatany step up (an upper bound on DLQ records, see above)
Under-replicated partitions0anything above 0 for more than a minute
Consumer lag by groupall groups lowone group high: that consumer, not Kafka
Enricher lag by partitionroughly evenone partition much higher: hot key
Messages in per second by topicmatches your loadsudden drop to 0: producers stopped
Enricher outcomes per secondmostly enrichedretry or dlq lines rising
Revenue per minute (INR)follows loadflat 0 while orders flow: analytics is stuck
order-api accepted vs errors /serrors at 0errors rising: brokers down or slow (503/504). publish_errors counts producer failures (full queue, failed delivery, ack timeout), not HTTP status codes: a 422 validation error is not counted. For the user's view, also chart an HTTP status histogram (for example with prometheus-fastapi-instrumentator).

A strong on-call habit to describe: "I read the dashboard from the outside in. First the user-facing panel (accepted vs errors), then throughput, then lag by group to find which stage is behind, then lag by partition to see if it is one key, then that service's logs."
