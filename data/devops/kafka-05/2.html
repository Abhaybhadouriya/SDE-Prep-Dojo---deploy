The ISR, LEO and high watermark

must know

Three words, defined once:

  • LEO (log end offset): on each replica, the offset the next record will get. If a replica holds offsets 0 to 4, its LEO is 5.
  • ISR (in-sync replicas): the leader plus every follower that is caught up. The leader drops a follower from the ISR if it has not fetched, or has not reached the leader's LEO, for replica.lag.time.max.ms (30 seconds by default). It is added back once it catches up. The ISR is stored in the cluster metadata by the controller.
  • HW (high watermark): the smallest LEO among the ISR. Everything below the HW is on every in-sync replica, so it is committed. Consumers can only read below the HW.

The rule "lag is measured in time, not in messages" matters: a follower that is 10,000 messages behind but fetching quickly stays in the ISR; a follower that has not fetched for 30 s is out, even if only 3 messages behind. Step through one write:

  1. Start. All three replicas hold offsets 0 to 2. Every LEO is 3, so the high watermark is 3. Consumers can read 0, 1, 2.
  2. Produce. The producer sends records 3 and 4 to the leader on B1. The leader appends them: its LEO becomes 5. The HW does not move yet, so consumers cannot see 3 and 4.
  3. Followers fetch. B2 and B3 send fetch requests and append what they receive. B2 now has up to 4; B3 has only 3 so far.
  4. HW moves. Each fetch request carries the follower's current position, so the leader learns the LEOs: 5, 5, 4. HW = the minimum = 4, so offset 3 is now committed and visible to consumers.
  5. Fully replicated. B3 fetches record 4. HW = 5. A producer that used acks=all receives its acknowledgement at this point. Followers learn the new HW in their next fetch response.
  6. A follower falls behind. B3's disk stalls and it stops fetching. After replica.lag.time.max.ms (30 s) the leader shrinks the ISR to {B1, B2}, and the HW advances based on those two only.

From your world

The high watermark is a TCP cumulative ACK across the ISR: "every byte below this number has been received by every in-sync peer". The leader's LEO is like snd_nxt, the HW is like snd_una - bytes between them are in flight. Where it breaks: TCP has one receiver; the HW is the minimum over several followers, and the set of followers that count (the ISR) can change.

You might confuse this with: consumer lag. Replica lag is a follower behind its leader (a safety problem). Consumer lag is a consumer group behind the log end (a speed problem, see Consumers & Groups). Different numbers, different alerts: UnderReplicatedPartitions vs records-lag-max.
