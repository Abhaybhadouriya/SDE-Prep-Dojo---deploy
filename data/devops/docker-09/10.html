Quick quiz

You COPY a private key in one step and RUN rm it in the next. Is the key in the final image?

  1. No, it was deleted
  2. Yes, it is still in the earlier layer and can be extracted
  3. Only if you use Alpine
  4. Only in the build cache, not the pushed image
Layers are additive. The later rm adds a whiteout but the earlier layer, with the key, ships with the image. Use a secret mount and rotate the key.

You run docker run -p 8080:80 nginx and have a ufw rule denying 8080. Can the internet reach it?

  1. No, ufw blocks it
  2. Only over IPv6
  3. Yes: Docker's DNAT happens before the INPUT chain where ufw filters
  4. Only if icc is true
The packet is rewritten in PREROUTING and forwarded, so it never hits INPUT. Filter in DOCKER-USER or publish on 127.0.0.1.

What is the main difference between rootless Docker and USER 10001 in a Dockerfile?

  1. Rootless runs the daemon itself as an unprivileged user; USER only changes the app process
  2. They are the same thing
  3. USER makes the daemon rootless
  4. Rootless disables cgroups entirely
USER protects against the app using root. Rootless also protects against a compromised or abused daemon, because the daemon has no root to give.

Why deploy image@sha256:... instead of image:1.4.2?

  1. Digests download faster
  2. Tags are not allowed in Kubernetes
  3. Digests skip vulnerability scanning
  4. A digest is immutable, so you run exactly the bytes you scanned and signed
Tags are movable pointers. A digest is a content hash; if the bytes change, the digest changes.

A container takes exactly 10 seconds to stop every time and exits with 137. Most likely cause?

  1. The memory limit is too low
  2. Shell-form CMD: /bin/sh is PID 1 and does not forward SIGTERM, so Docker sends SIGKILL after the timeout
  3. The image is too large
  4. The registry is slow
10 seconds is docker stop's default grace period. Use exec form, handle SIGTERM, or add --init.

Which of these does NOT reduce risk from a container escape?

  1. userns-remap
  2. Patching runc
  3. Mounting /var/run/docker.sock read-only
  4. Dropping all capabilities
A read-only bind of the socket still lets you send API requests (the socket file mode is about the file, not the API). Socket access is root regardless.

Your CI fleet suddenly fails with "toomanyrequests" when pulling base images. Best fix?

  1. Authenticate and use a pull-through cache or mirror
  2. Switch every image to :latest
  3. Add more CI runners behind the same NAT IP
  4. Disable BuildKit
Docker Hub limits anonymous pulls per IP over 6 hours. Logging in raises the limit; a pull-through cache (ECR, ACR, Harbor) removes repeated pulls.
