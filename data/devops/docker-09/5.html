You might confuse this with...

ThisIs not the same asThe difference
USER 10001 (non-root container)Rootless DockerUSER only changes the app's UID; the daemon is still root. Rootless runs the daemon itself as your normal user, so even a daemon bug does not give host root.
userns-remapRootless DockerWith userns-remap the daemon is still root, but container UID 0 is mapped to a high, harmless host UID. Rootless goes further: no root daemon at all.
--cap-drop=ALLNon-root userCapabilities are root's powers cut into separate keys. Dropping them limits even a root process. A non-root UID has none in its effective set to start with; both together are the safe default.
Scanning (Trivy, Scout)Signing (cosign)A scan says "this image has no known bad packages today". A signature says "this exact digest came from our pipeline". You need both: one checks the content, the other the origin.
SBOMProvenance (SLSA)The SBOM is the ingredient list (packages and versions). Provenance is the recipe card: who built it, from which commit, with which steps.
--privileged--user rootRoot inside a normal container still has dropped capabilities, seccomp and AppArmor. --privileged turns all of those off and exposes every host device: treat it as "no container at all".
