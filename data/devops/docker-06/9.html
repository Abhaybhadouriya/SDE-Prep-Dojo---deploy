Common mistakes and gotchas

Mistakes
  • Database without a volume: data gone on the next docker rm or deploy.
  • docker compose down -v or docker volume prune -a run casually, deleting real data (plain docker volume prune only removes anonymous volumes since Engine 23).
  • -v data:/x when you meant -v ./data:/x (volume vs bind mount).
  • Typo in a bind path with -v: Docker silently creates an empty root-owned folder and the app starts with no config.
  • Bind-mounting over a directory that held the image's files, hiding them.
  • Non-root container user without permission on the bind-mounted folder.
  • Writing logs to files in the container layer (fills the disk, invisible to docker logs).
  • Two containers writing the same files on one volume without the app supporting it (corruption).
Good habits
  • Name every volume you care about; use --mount syntax in scripts.
  • :ro for config files and anything the container should only read.
  • --read-only root filesystem plus a sized tmpfs for production services.
  • Back up with the database's tool, test the restore.
  • Label volumes (--label owner=payments) so cleanup scripts can tell them apart.
  • Keep the app stateless; push state to managed stores.
