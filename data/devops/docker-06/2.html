The three kinds of mounts

Docker can attach storage from outside the layer stack in three ways: a volume, a bind mount and a tmpfs mount. The difference is simply where the data lives on the host and who manages it.

Named volumeBind mounttmpfs
Lives at/var/lib/docker/volumes/<name>/_dataAny host path you chooseRAM
Survives docker rmYesYes (it is just a host folder)No
Portable across hostsYes (no host path in config)No, depends on host layoutn/a
Pre-filled from imageYes, if the volume is new and emptyNo, it hides the image's filesNo
SpeedNative disk, no copy-upNative on Linux; slower on Docker DesktopFastest
Best forDatabases, Kafka logs, uploadsSource code hot-reload in dev, config filesSecrets, scratch, caches

One-sentence rule: "Named volume for data the app owns, bind mount for files I own on the host (dev code, a config file), tmpfs for things that must never hit disk."
