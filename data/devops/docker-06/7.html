Backups, drivers and shared storage

Deep dive: stop here for SDE-1 (but read the anonymous-volume and prune warning at the end of this section). Volume drivers, NFS and backup recipes are for SDE-2, SRE and platform roles.

Back up and restore a volume

A volume is just a directory, so the standard recipe is: run a throwaway container that mounts the volume and a host folder, and tar between them.

# Backup: volume pgdata -> ./pg-backup.tgz  (stop the DB first, or use pg_dump, for a consistent copy)
docker run --rm -v pgdata:/data:ro -v "$(pwd)":/backup alpine:3.24 \
  tar czf /backup/pg-backup.tgz -C /data .

# Restore into a fresh volume
docker volume create pgdata-restored
docker run --rm -v pgdata-restored:/data -v "$(pwd)":/backup alpine:3.24 \
  tar xzf /backup/pg-backup.tgz -C /data

File copy is not a database backup. Copying a live database's files can capture a half-written state. For real backups use the database's own tool (pg_dump, pg_basebackup, mysqldump) or stop the container first. In the cloud, managed databases and volume snapshots are the normal answer.

Volume drivers: storage that is not on this host

The default local driver stores data on the host's disk. The local driver can also mount NFS or CIFS with options, and plugins can provide cloud block storage.

docker volume create --driver local \
  --opt type=nfs \
  --opt o=addr=10.0.0.5,rw,nfsvers=4 \
  --opt device=:/exports/shared \
  shared-nfs

This is how a volume can outlive not only the container but the host. In Kubernetes the same idea becomes PersistentVolumes backed by cloud disks (EBS, Azure Disk, Persistent Disk) through CSI drivers; see K8s Storage.

Anonymous volumes and the VOLUME instruction

If a Dockerfile says VOLUME /var/lib/mysql and you run the image without mounting anything there, Docker creates an anonymous volume with a random 64-character name. They pile up quietly. docker run --rm deletes them on exit; otherwise docker volume prune cleans up unused anonymous ones. Since Docker Engine 23 (API 1.42) that is all plain prune touches; docker volume prune -a also deletes unused named volumes, so docker volume prune -a (or docker system prune -a --volumes on older engines) can delete a database volume you forgot was not attached right now. Read the prompt: it deletes data.

$ docker volume ls

local     pgdata
$ docker system df -v | sed -n '/Local Volumes/,/^$/p'
