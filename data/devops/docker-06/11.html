Remember this

  • Default writes go to the container's writable layer: kept on stop, deleted on remove, invisible to new containers.
  • Named volume = Docker-managed folder (/var/lib/docker/volumes/<name>/_data), survives docker rm.
  • Bind mount = any host path; great for dev code and config; hides image files beneath it.
  • tmpfs = RAM only; for secrets and scratch; counts against the memory limit.
  • Volumes skip OverlayFS copy-up, so databases need them for speed as well as safety.
  • UIDs are numbers: match the container user to the folder's owner.
  • --read-only + tmpfs + volumes for known paths is a strong production pattern.
  • Stateless containers, stateful services: put state in DBs, object storage, caches, Kafka.
