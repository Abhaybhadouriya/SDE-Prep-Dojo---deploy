tmpfs and read-only containers

A strong production pattern: make the container's root filesystem read-only, and give it a small tmpfs for the few places that must be writable. An attacker who gets code execution cannot drop files into /usr/bin, and you instantly find out if your app writes somewhere unexpected.

docker run -d --name api \
  --read-only \
  --tmpfs /tmp:size=64m,mode=1777 \
  --mount type=volume,src=uploads,dst=/srv/uploads \
  myapi:1.4.2
$ docker exec api sh -c "touch /etc/hacked"
touch: /etc/hacked: Read-only file system
$ docker exec api sh -c "touch /tmp/ok && echo fine"
fine

tmpfs counts towards the container's memory limit (it is RAM), so always give it a size. It is also the right place for decrypted secrets a process needs as files: they never reach disk and vanish when the container stops. Orchestrators do the same thing: Docker Swarm and Kubernetes mount secrets on in-memory filesystems.
