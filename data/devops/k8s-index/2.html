What you will be able to do

These are the abilities this track is built around. Each one is something an interviewer can actually ask you to do on a whiteboard.

1

Explain why Kubernetes exists

In 60 seconds, without jargon: scheduling, self-healing, stable addresses, safe rollouts, autoscaling, all driven by "desired state".

2

Name every part and what it does

API server, etcd, scheduler, controller manager, kubelet, kube-proxy, container runtime, CNI. One line each, and which process talks to which.

3

Trace kubectl apply end to end

From your keyboard to a pod serving traffic, naming each component and what it writes. This is the single best question to prepare.

4

Run and debug real workloads

Pick Deployment vs StatefulSet vs DaemonSet vs Job, set probes and resource limits, explain OOMKilled and CPU throttling, fix Pending and CrashLoopBackOff.

5

Answer interview questions and scenarios

"What happens when a node dies?", "How do you do zero-downtime deploys?", "How does a Service find pods?" - with timings, trade-offs and follow-ups.

Honest note about interviews: in general SDE-1/2 loops, Kubernetes usually shows up in three places: the resume deep-dive ("you deployed on K8s - how?"), inside an HLD round ("how would you deploy and scale this?"), and much more heavily if you interview for a platform, infra or cloud team (for example teams that build AKS, EKS or GKE). Your systems background fits that last group very well.
