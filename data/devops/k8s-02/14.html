  • Control plane: kube-apiserver (door), etcd (state), scheduler (where), controller-manager (loops), cloud-controller-manager (cloud).
  • Node: kubelet (agent), container runtime via CRI, CNI plugin, kube-proxy.
  • Hub and spoke: everyone watches and writes through the API server; only it talks to etcd.
  • kubectl apply returns after the etcd write; controllers, scheduler and kubelet do the rest.
  • etcd: odd sizes, quorum = floor(n/2)+1; 3 tolerates 1, 5 tolerates 2.
  • Node death: about 50 s to NotReady plus 300 s toleration before pods move.
  • Control plane down = running pods continue (non-stop forwarding), but nothing changes.
  • Upgrade control plane first, kubelet at most 3 minors behind, no downgrade: back up etcd.
