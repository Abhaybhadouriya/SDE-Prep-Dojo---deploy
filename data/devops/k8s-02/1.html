The big picture

Must know (SDE-1)

A Kubernetes cluster is a set of machines (physical or virtual) split into two roles. The control plane stores the desired state and makes decisions. The worker nodes (usually just called nodes) run your containers. Small clusters can run both roles on one machine (your kind cluster does that for the control-plane node); production clusters keep them apart.

Every component in one line

ComponentWhere it runsOne-line jobPlain-word nickname
kube-apiservercontrol planeThe only door into the cluster: a REST API that checks, validates and stores every object. The only component that talks to etcd. Stateless, so you can run several copies.front desk
etcdcontrol planeA small, strongly consistent key-value database (it uses the Raft consensus algorithm). It holds the whole cluster state: every Pod, Deployment, Secret, node.register book
kube-schedulercontrol planeWatches for new pods with no node, filters out nodes that cannot fit them, scores the rest, and writes the chosen node into the pod.seating teacher
kube-controller-managercontrol planeOne process running many control loops: Deployment, ReplicaSet, Node lifecycle, Job, EndpointSlice (keeps the list of ready pod IPs behind each Service; page 05), ServiceAccount (creates the default identity pods run as; page 12) and more.hall monitors
cloud-controller-managercontrol plane (cloud only)Loops that talk to the cloud's API: create cloud load balancers for Services, label nodes with zones, notice deleted VMs.the office's phone to the landlord
kubeletevery nodeThe node agent. Watches for pods assigned to its node, asks the runtime to start them, runs health probes, reports status and heartbeats.class helper
container runtimeevery nodeActually creates containers (namespaces, cgroups, filesystems). containerd or CRI-O, spoken to over the CRI (Container Runtime Interface, a gRPC API).the hands
CNI pluginevery nodeGives each pod a network interface and an IP, and makes pod-to-pod traffic work across nodes (Calico, Cilium, Flannel, cloud CNIs).the network cabler
kube-proxyevery node (optional)Programs the node's kernel (iptables or nftables rules) so a Service's virtual IP is translated to a real pod IP. Some CNIs, like Cilium, replace it with eBPF.the switchboard
CoreDNSruns as pods (add-on)Cluster DNS: turns names like cart.shop.svc.cluster.local into Service IPs.the phone book

Memory trick: the control plane has one database (etcd), one door (API server), and two kinds of brains (scheduler for "where", controllers for "how many and what"). Each node has one agent (kubelet), one pair of hands (runtime + CNI), and one switchboard (kube-proxy).
