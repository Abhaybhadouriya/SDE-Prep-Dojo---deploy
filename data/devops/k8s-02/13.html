"A Kubernetes cluster is split into a control plane and worker nodes, very much like a router's control and data planes. The control plane has the API server, which is the single entry point and the only thing that talks to etcd; etcd, a Raft-replicated store holding all desired and actual state; the scheduler, which picks a node for each new pod; and the controller manager, which runs reconciliation loops for Deployments, ReplicaSets, nodes and endpoints. Each node runs the kubelet, which watches for pods assigned to it and drives the container runtime over CRI, a CNI plugin for pod networking, and kube-proxy for Service virtual IPs. Nothing calls anything directly: every component watches the API server, does one job, and writes back. So if the control plane goes down, running pods keep serving traffic, but no new scheduling or healing happens. In production I'd run three control-plane nodes across zones, with leader election for the scheduler and controller manager and a three- or five-member etcd."
