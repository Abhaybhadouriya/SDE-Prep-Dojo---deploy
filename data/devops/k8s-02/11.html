Common mistakes and gotchas

Good to know (SDE-2)

"The scheduler starts the pod." No. The scheduler only writes a node name into the pod. The kubelet starts it, through the container runtime.

"kubectl apply waits until my app is running." No. It returns as soon as the object is stored. Use kubectl rollout status deployment/web or kubectl wait to wait for readiness.

"Components talk to etcd." Only the API server does. If someone draws the scheduler connected to etcd in an interview diagram, that is a mistake.

Running 2 or 4 etcd members. Even numbers add failure points without adding tolerance. Use 3 or 5.

Upgrading nodes before the control plane, or skipping several minor versions at once. Both break the version-skew rules.

No etcd backups on a self-managed cluster. There is no downgrade and no undo. Reddit's 2023 "Pi-Day" outage (314 minutes) after a 1.23 to 1.24 upgrade ended with restoring the control plane from backup. See the scenario below.
