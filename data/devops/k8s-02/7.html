etcd: the register book, and why odd numbers

Must know (SDE-1)

etcd is a key-value store built for small, critical data. Kubernetes keeps every object there under keys like /registry/pods/default/web-7c9d8f6b5-x2l8q. It uses the Raft consensus algorithm: one member is the leader, the others are followers, and a write is only committed when a majority (a quorum) of members has saved it.

MembersQuorum (majority)Failures toleratedComment
110Fine for a lab (your kind cluster). Any failure loses the control plane.
220Worse than 1: twice the machines to fail, still zero tolerance.
321The common production choice.
431No gain over 3, and more replication work per write.
532For bigger or more critical clusters. The etcd FAQ treats 5 as a sensible upper size; more members make writes slower.

Quorum = floor(n / 2) + 1. That is why you use odd numbers: adding a 4th member does not let you survive more failures. Useful numbers from the etcd docs: the default maximum request size is about 1.5 MiB (one reason a ConfigMap or Secret is capped at 1 MiB), and the default storage quota is 2 GB, with a suggested maximum of 8 GB. etcd is sensitive to disk latency (every commit is an fsync), so production etcd wants fast SSDs.

From your world

Raft is closer to a cluster-membership protocol with majority voting than to VRRP. VRRP picks a master by priority and can split-brain if the two routers lose sight of each other. Raft cannot split-brain: a leader cut off from the majority cannot commit anything, and the majority side elects a new leader. The price is that losing quorum (for example 2 of 3 members down) makes etcd read-only/unavailable for writes, and so the whole Kubernetes control plane stops accepting changes.

What if etcd is lost completely? Running pods keep running (the data plane does not need etcd). But the cluster forgets everything: Deployments, Services, Secrets. You must restore from an etcd snapshot (etcdctl snapshot save). Kubernetes has no supported downgrade, so backups are your undo button. Managed services (EKS, AKS, GKE) run and back up etcd for you.
