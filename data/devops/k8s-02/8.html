Node heartbeats and the famous 5-minute delay

Must know (SDE-1)

How does the control plane know a node is alive? The kubelet sends two kinds of signals:

  • Lease heartbeat: a tiny Lease object per node in the kube-node-lease namespace, renewed about every 10 seconds. Cheap, so it can be frequent.
  • Node status: the full status (conditions like MemoryPressure, DiskPressure, capacity, images). Sent when something changes, or every few minutes otherwise.

Who does what: the node lifecycle controller (in kube-controller-manager) checks leases on a short period. After --node-monitor-grace-period (50 s by default in current versions; older docs say 40 s) with no renewal, it sets the node's Ready condition to Unknown and adds the taint node.kubernetes.io/unreachable. Every pod gets a default toleration for that taint with tolerationSeconds: 300. When that expires, the taint eviction logic deletes the pods, and their ReplicaSets create replacements.

"Why did my pods take 5+ minutes to move after a node died?" is a classic. Answer with the two timers, explain they are there to avoid flapping on a temporary network blip, and say how to tune it: lower tolerationSeconds on latency-critical pods, and always run several replicas spread across nodes so users do not notice in the first place.
