The story: from a toy town to a city with a mayor

Explain like I'm 5

With Docker Compose you built a toy town on your desk. You set up every building yourself, and if one fell over, you had to notice and stand it back up.

Now we move to a real city. The city has a mayor's office with a big notebook. You do not build anything. You write in the notebook: "I want two shops, one bank, and a post office with three towers." Clerks read the notebook all day. If a shop burns down, a clerk sees that the notebook says "two shops" but there is only one, and orders a new one built. Nobody needs to phone them.

The post office is special. It has towers that must agree with each other, mail that must never be lost, and rules about which tower can be repaired when. The ordinary clerks do not know those rules. So the city hires a post-office expert who reads only the "post office" pages of the notebook and does all the careful work: repair one tower at a time, wait until it has caught up, then the next.

The city is Kubernetes (K8s). The notebook is the API server and its database etcd. The clerks are controllers: programs that watch the notebook and fix the real world to match it. The post-office expert is an operator: a controller that understands one complicated application. Ours is Strimzi, the operator for Kafka. For autoscaling the consumer we add one more helper, KEDA (Kubernetes Event-Driven Autoscaling), which watches Kafka consumer lag (how far a consumer group is behind the newest offset of each partition).

From your world

Kubernetes is a router's control plane for processes. The API server plus etcd is the configuration database (think of the running config plus RIB, replicated with Raft). Controllers are the daemons that read it and program the "hardware" (container runtimes on nodes), like a routing daemon pushing a FIB to line cards. An operator is a protocol-specific daemon: the OSPF process understands OSPF, Strimzi understands Kafka. Where it breaks: a router's daemons are compiled into one image, while K8s operators are just pods you install and remove like any other app.

Before this page: Kubernetes basics help a lot: Pods, Deployments, Services, and especially StatefulSets, CRDs & Operators. You should also have run the pipeline once with Docker Compose. All files are in pipeline/code/k8s/.
