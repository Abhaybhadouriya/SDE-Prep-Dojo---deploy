Try it: break things on Kubernetes

The project has Kubernetes versions of the failure drills:

bash scripts/chaos/k8s-drills.sh broker      # delete a broker pod; Strimzi recreates it
bash scripts/chaos/k8s-drills.sh pause       # scale postgres-sink to 0 for 30 s; lag grows, then drains
bash scripts/chaos/k8s-drills.sh poison      # write "not json" into orders.created; it lands in orders.dlq
bash scripts/chaos/k8s-drills.sh rebalance   # show the ScaledObject, HPA and group members
# PowerShell: .\scripts\chaos\k8s-drills.ps1 -Drill broker

For the broker drill, watch the pods in a second terminal with kubectl -n kafka get pods -w. You will see the broker go Terminating, a new pod with the same name go Pending, ContainerCreating, Running, and it reattach the same PersistentVolumeClaim, so it only has to catch up on what it missed. Meanwhile --under-replicated-partitions lists the partitions that had a replica on it. What each drill shows and why is explained in Observability & Failure Drills.

Clean up with kind delete cluster --name shopstream: it deletes the four node containers and everything inside them.
