Step 1: a four-node cluster with kind

The cluster shape is a file. Three workers, each labelled with a zone, so we can pretend we have three data centres and see Strimzi spread replicas across them:

# k8s/kind-config.yaml (excerpt)
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
name: shopstream
nodes:
  - role: control-plane
    extraPortMappings:
      - {containerPort: 30080, hostPort: 30080, protocol: TCP}   # order-api NodePort
  - role: worker
    labels: {topology.kubernetes.io/zone: zone-a}
  - role: worker
    labels: {topology.kubernetes.io/zone: zone-b}
  - role: worker
    labels: {topology.kubernetes.io/zone: zone-c}

Run from pipeline/code:

kind create cluster --config k8s/kind-config.yaml
kubectl get nodes -L topology.kubernetes.io/zone
$ kubectl get nodes -L topology.kubernetes.io/zone
NAME                       STATUS   ROLES           AGE   VERSION   ZONE
shopstream-control-plane   Ready    control-plane   75s   v1.3x.x
shopstream-worker          Ready    <none>          58s   v1.3x.x   zone-a
shopstream-worker2         Ready    <none>          58s   v1.3x.x   zone-b
shopstream-worker3         Ready    <none>          58s   v1.3x.x   zone-c

The VERSION column depends on your kind release (the project was checked with kind v0.33.0). Strimzi 1.x needs Kubernetes 1.32 or newer.

From your world

A kind "node" is a container acting as a whole machine: it has its own network namespace, runs systemd, kubelet and containerd, and starts more containers inside itself (nested). It is like running a virtual router image in a lab instead of buying the chassis. The extraPortMappings line is a DNAT from your laptop's port 30080 into the control-plane container, where kube-proxy then forwards NodePort 30080 to an order-api pod.
