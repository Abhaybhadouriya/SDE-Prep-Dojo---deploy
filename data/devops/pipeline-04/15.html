Quick quiz

You apply a Kafka custom resource. Which process creates the broker pods?

  1. The kube-scheduler
  2. The Strimzi cluster operator, which watches Kafka resources
  3. etcd
  4. kubectl
The CR is only data in etcd. The operator watches it and creates pods, services and volumes; the scheduler then only picks nodes for those pods.

The enricher's CPU is at 10 % but lag is 50,000. What happens with a CPU-based HPA?

  1. It scales up quickly
  2. It scales to the partition count
  3. Nothing: CPU is under target, so lag keeps growing
  4. It restarts the pod
That is why the consumer uses KEDA on lag: the work waiting is the right signal, not CPU.

Why is maxReplicaCount 6 for the enricher?

  1. orders.created has 6 partitions; in a consumer group a 7th member would be idle
  2. kind has 6 CPUs
  3. KEDA's hard limit
  4. Kafka allows at most 6 consumers
Each partition is assigned to one member of the group, so parallelism is capped by the partition count.

Kafka is unreachable for 20 seconds. What should happen to order-api pods?

  1. Liveness fails and all pods restart
  2. Nothing at all
  3. The HPA scales them to zero
  4. Readiness fails, they leave the Service, and they return when Kafka is back, without restarting
Dependency checks belong in readiness. Restarting would not fix Kafka and would slow recovery.

Why does the enricher PDB use maxUnavailable: 1 instead of minAvailable: 1?

  1. maxUnavailable is newer
  2. At 1 replica, minAvailable: 1 allows zero evictions, so node drains would hang forever
  3. KEDA requires it
  4. It makes rebalances faster
The PDB must allow at least one eviction or upgrades get stuck; maxUnavailable: 1 still prevents mass evictions.

What is the shopstream-kafka-bootstrap Service used for?

  1. All produce and fetch traffic, load balanced
  2. Only the KRaft controllers
  3. The first connection and metadata; then clients connect to each leader broker directly
  4. Prometheus scraping
Bootstrap is just the front door for metadata. Data traffic goes to the partition leaders' own addresses.

How do the locally built shopstream/*:dev images get into the kind cluster?

  1. kind load docker-image copies them into each node's container runtime
  2. Kubernetes builds them from the Dockerfile
  3. They are pulled from Docker Hub
  4. Strimzi builds them
With imagePullPolicy IfNotPresent, the kubelet uses the copied image and never contacts a registry.
