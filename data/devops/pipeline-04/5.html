Step 5: topics as code

In Compose, a one-shot container ran a shell script to create topics. On Kubernetes we declare them, and the Topic Operator keeps Kafka in sync with the YAML. Change retention.ms in git, apply, and the topic changes.

# k8s/11-kafka-topics.yaml (one of four)
apiVersion: kafka.strimzi.io/v1
kind: KafkaTopic
metadata:
  name: orders-created          # a valid k8s name (no dots)...
  namespace: kafka
  labels:
    strimzi.io/cluster: shopstream
spec:
  topicName: orders.created     # ...so the real Kafka name goes here
  partitions: 6
  replicas: 3
  config:
    min.insync.replicas: 2
    retention.ms: 604800000
kubectl apply -f k8s/11-kafka-topics.yaml
kubectl -n kafka get kafkatopics
NAME              CLUSTER      PARTITIONS   REPLICATION FACTOR   READY
orders-created    shopstream   6            3                    True
orders-dlq        shopstream   3            3                    True
orders-enriched   shopstream   6            3                    True
orders-retry      shopstream   3            3                    True

Partitions can only go up. Kafka cannot reduce a topic's partition count, and adding partitions changes which partition each key hashes to, which breaks per-key ordering for a while. Pick the count up front. ShopStream uses 6, which also caps useful consumer replicas at 6.
