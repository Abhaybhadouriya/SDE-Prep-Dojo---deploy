NetworkPolicy: default deny, then allow-list

By default every pod can talk to every pod. 40-networkpolicy.yaml flips that for incoming traffic in the shopstream namespace: deny everything, then allow exactly what is needed.

# k8s/40-networkpolicy.yaml (excerpt)
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: postgres-ingress
  namespace: shopstream
spec:
  podSelector:
    matchLabels: {app: postgres}
  policyTypes: [Ingress]
  ingress:
    - from:
        - podSelector: {matchLabels: {app: enricher}}
        - podSelector: {matchLabels: {app: postgres-sink}}
      ports: [{port: 5432, protocol: TCP}]

From your world

The file's own comment says it: these are stateful ACLs on each pod's virtual interface. The CNI plugin (kindnet here, Calico or Cilium elsewhere) compiles them into iptables, nftables or eBPF rules on each node. Where it breaks: ACLs match addresses, but NetworkPolicies match labels, and the CNI re-renders the rules every time a pod with that label appears or disappears. And a policy object does nothing at all if the CNI does not enforce policies.

Monitoring on kind is not included in this lab. The policy opens port 8000 to a namespace called monitoring, but nothing creates it. To get the Grafana dashboard from page 05 on Kubernetes, install kube-prometheus-stack there: helm repo add prometheus-community https://prometheus-community.github.io/helm-charts, then helm install mon prometheus-community/kube-prometheus-stack -n monitoring --create-namespace. One catch: that chart finds targets through PodMonitor / ServiceMonitor objects, not through the prometheus.io/scrape annotations on our pods, so you would also write a small PodMonitor for port http of the shopstream pods and one for Strimzi's kafkaExporter, which provides the lag numbers.
