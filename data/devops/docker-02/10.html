Quick quiz

Which Dockerfile instruction does NOT create a filesystem layer?

  1. RUN
  2. CMD
  3. COPY
CMD, ENV, EXPOSE and LABEL only change the image config; docker history shows them as 0 B.

You add RUN rm /big.bin after the line that created a 50 MB file. What happens to the image size?

  1. It shrinks by 50 MB
  2. It doubles
  3. It stays the same; the file is still in the earlier layer
Layers are append-only. The delete adds a whiteout, but the 50 MB is still shipped in the earlier layer.

A container writes one byte to a 1 GB file that came from the image. What does OverlayFS do first?

  1. Copies the whole file into the container's upper layer
  2. Writes the byte into the image layer
  3. Copies only the changed block
OverlayFS copy-up is file-level, not block-level, which is why databases should use volumes.

What is a digest like sha256:4f2c...?

  1. A human-friendly, movable name
  2. A hash of the manifest that can never change
  3. The size of the image
Digests are content addresses. Change any byte and the digest changes, so a digest always means the exact same image.

How does one tag like python:3.12-slim work on both Intel servers and ARM Macs?

  1. Docker translates the CPU instructions automatically
  2. The image contains a VM
  3. The tag points to an index listing a manifest per platform
The image index lists per-platform manifests. The client picks the one matching its OS and CPU.

During docker pull, you see Already exists next to some layers. Why?

  1. Those layer digests are already on disk, so they are skipped
  2. The registry is down
  3. The image is corrupted
Content addressing lets the client skip any layer whose digest it already holds, often from a shared base image.

What marks a deleted lower-layer file in the container's upper layer?

  1. An empty folder
  2. A whiteout: a character device 0/0
  3. A file called DELETED
OverlayFS hides lower files using whiteout entries, which you can see with ls -l in the upperdir.
