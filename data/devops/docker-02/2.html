Layers are shared, containers add one thin sheet

Here is the picture you should be able to redraw from memory. One image, three running containers. The image layers exist once on disk. Each container adds its own small writable layer.

1ximage layers on disk, however many containers
0 BCMD, ENV, EXPOSE layers (config only)
1 copyin the page cache for a shared file, for N containers

This sharing gives four practical wins:

  1. Less disk. One copy of the 175 MB of image layers, plus a few KB or MB per container.
  2. Less network. Pulls and pushes skip layers the other side already has. If 50 services share the same base image, a server downloads that base once.
  3. Less memory. When ten containers read the same library file from a shared layer, the kernel's page cache (the RAM the kernel uses to keep recently read file data) holds it once. That is part of why you can pack many containers on one host.
  4. Fast builds. Docker can reuse a layer from a previous build if nothing it depends on changed. That is the build cache, and the Dockerfile page is mostly about using it well.

When you delete a container, its writable layer is gone. Anything the app wrote there (uploads, a SQLite file, logs written to files) disappears with docker rm. Data you want to keep belongs in a volume, which lives outside the layer stack.
