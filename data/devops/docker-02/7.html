Common mistakes and gotchas

  1. Deploying :latest. It can point to a different image tomorrow, so two servers "on the same version" may run different code, and rollback is unclear. Deploy an immutable tag (like the git SHA) or a digest.
  2. Copying a secret into the image "just for the build". Deleting it later leaves it in a lower layer. Use build secrets (RUN --mount=type=secret, shown on the next page).
  3. Writing data into the container's filesystem. It vanishes with docker rm and is slow for large files. Use volumes.
  4. Building on ARM, running on x86. The image has the wrong CPU instructions: exec format error. Build for the right platform or multi-arch.
  5. Thinking docker images SIZE adds up. Shared layers are counted in every image that uses them, so the sum is bigger than the real disk use. Use docker system df for the truth.
