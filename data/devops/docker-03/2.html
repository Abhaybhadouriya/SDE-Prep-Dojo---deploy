The build context and .dockerignore

When you run docker build ., the CLI sends the files in that folder to the builder (BuildKit, which runs inside or next to dockerd). The builder may be on another machine entirely, so it can only see what you send. COPY can only copy from this context, never from arbitrary paths like ../secrets.

A good .dockerignore gives you three things: faster builds (less to upload and hash), fewer accidental cache misses (a changed file in .git would otherwise invalidate COPY . .), and safety (your .env file with passwords never ends up in an image layer).
