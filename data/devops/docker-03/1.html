Your first real Dockerfile

We will containerize a tiny Python web service. You do not need to know Flask (a small Python library for writing web servers); it is three lines that answer HTTP requests. To run it we use gunicorn, a production web server process that runs your Python app with several worker processes. Why not just python app.py? That starts Flask's built-in development server: one process, not built for real traffic, and it prints a warning telling you not to use it in production. Make a folder with these three files.

from flask import Flask

app = Flask(__name__)

@app.get("/")
def hello():
    return "Hello from a container!\n"

@app.get("/healthz")
def healthz():
    return "ok\n"
flask==3.0.3
gunicorn==23.0.0
# syntax=docker/dockerfile:1
FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8000
CMD ["gunicorn", "-b", "0.0.0.0:8000", "app:app"]

Line by line:

  1. # syntax=docker/dockerfile:1 An optional first line that tells BuildKit (Docker's builder) to use the latest stable Dockerfile syntax. It unlocks newer features like cache mounts. Keep it.
  2. FROM python:3.12-slim Start from an existing image: a slim Debian Linux with Python 3.12 installed. Every Dockerfile starts with FROM. Its layers become the bottom of your stack.
  3. WORKDIR /app Create the folder /app (if needed) and make it the current directory for all later steps and for the running container. Like mkdir -p /app && cd /app.
  4. COPY requirements.txt . Copy one file from your folder (the build context) into /app inside the image. We copy only the dependency list first, on purpose. You will see why in the cache section.
  5. RUN pip install ... Run a command at build time inside a temporary container, and save the resulting file changes as a new layer. --no-cache-dir stops pip from keeping its download cache in the image.
  6. COPY . . Now copy the rest of the source code.
  7. EXPOSE 8000 Documentation only: "this app listens on 8000". It does not open or publish any port. You still need -p when running.
  8. CMD [...] The default command when a container starts. Written in exec form (a JSON list), which matters a lot for signals, as you will see below.

Build it and run it

docker build -t hello-py:1.0 .
docker run -d --name hello -p 8000:8000 hello-py:1.0
curl http://localhost:8000/

The -t hello-py:1.0 flag gives the image a name and tag. The final . is the build context: the folder whose files COPY can see. Your timings will differ.

Shortcut for real projects: docker init looks at your project (Python, Node, Go, Java, Rust...) and generates a good starting Dockerfile, compose.yaml and .dockerignore. Read what it generates; this page teaches you why each line is there.
