The 5-step answer pattern

For almost every Docker question, this order works. It keeps you from rambling and it shows the interviewer you think about production, not only definitions.

The worked example, said out loud: "Exit 137 is 128 + 9, so the process got SIGKILL (1 define). Usually that is the memory cgroup's OOM killer firing when the container hits its --memory limit (2 mechanism). Limits protect the neighbours, but the limit must fit the app's real heap plus overhead (3 trade-off). I confirm it with docker inspect: State.OOMKilled is true (4 gotcha + detection). In Kubernetes the same thing shows as OOMKilled in the pod's last state (5 in K8s)."

When you do not know: say what you do know and reason from first principles. "I have not used that flag, but since a container is a process in a cgroup, I would expect the limit to live in cpu.max, and I would check it by reading the file." Interviewers reward reasoning far more than memorized flags.
