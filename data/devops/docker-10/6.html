Whiteboard drill: the docker run walk

This is the single most useful diagram for Docker interviews. Click through, then redraw it from memory.

  1. CLI to daemon. REST call over /var/run/docker.sock; dockerd expands nginx to docker.io/library/nginx:latest.
  2. Pull. Fetch the image index, pick the manifest for this CPU, download only missing layers by sha256 digest.
  3. containerd. Unpack layers into overlay snapshots, add a writable layer, write the OCI bundle (config.json + rootfs).
  4. shim + runc. The shim launches runc: clone with new namespaces, cgroup limits, pivot_root, drop capabilities, seccomp filter. runc exits; the shim stays as parent.
  5. Process. nginx is PID 1 inside its namespaces, listening on port 80 of its own eth0.
  6. Network. A veth pair links eth0 to the docker0 bridge; iptables DNAT maps host port 8080 to 172.17.0.2:80; conntrack handles replies; outbound traffic is MASQUERADEd.
  7. Logs. Everything nginx writes to stdout and stderr goes to the json-file driver (rotate it!).
