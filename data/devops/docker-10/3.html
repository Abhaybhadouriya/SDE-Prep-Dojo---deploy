Level 2 questions: fundamentals

What is a container and how is it different from a VM?

A container is a process on the host kernel, isolated by namespaces (pid, net, mnt, uts, ipc, cgroup) and limited by cgroups. A VM boots its own kernel on virtual hardware via a hypervisor. Containers start in milliseconds and are megabytes in size; VMs take seconds and are gigabytes, but give hardware-level isolation. Middle ground: gVisor (user-space kernel) and microVMs like Firecracker.

How to answer

Avoid "a lightweight VM". Say "shared kernel" in the first sentence, then the trade-off, then the real-world proof (containers inside VMs on clouds).

Likely follow-ups
  • Can I run a Windows container on a Linux host?
  • Can a container crash the host kernel? (Yes, through a kernel bug, since it is shared.)
What is the difference between an image and a container?

An image is a read-only, layered template plus config (class). A container is a running instance with its own writable layer (object). Many containers can share one image; deleting a container deletes only its writable layer.

How to answer

Use the binary-vs-process analogy, mention layers and the writable layer, then the consequence: data in the container layer is lost on removal.

Likely follow-ups
  • Where do writes go?
  • Can you turn a container back into an image? (docker commit, but prefer a Dockerfile.)
Is Docker the same thing as a container?

No. Containers are a Linux kernel capability (namespaces, cgroups) standardized by the OCI. Docker is a toolset on top: the CLI, the dockerd daemon, BuildKit for builds, Docker Hub, Compose, Desktop. You can run containers with Podman, containerd's nerdctl, CRI-O or plain runc, without Docker.

How to answer

Separate "the idea" (kernel features + OCI formats) from "the product" (Docker's tools). This sets you up for the dockershim follow-up.

Likely follow-ups
  • What is Podman and why is it daemonless?
  • Why did Kubernetes stop using Docker?
Walk me through the main Dockerfile instructions.

FROM picks the base image. WORKDIR sets the working folder. COPY/ADD bring files in. RUN executes a build command and creates a layer (RUN, COPY and ADD make filesystem layers; WORKDIR can add a tiny one when it creates the directory; the rest only change config). ENV sets runtime environment variables, ARG build-time variables. USER sets the user. EXPOSE documents a port. HEALTHCHECK defines a health command. ENTRYPOINT and CMD define what runs.

How to answer

Group them: base, files, build steps, runtime config, start command. Mention the "only three create layers" fact; it shows depth.

Likely follow-ups
  • In what order would you put them for best caching?
CMD vs ENTRYPOINT, and shell form vs exec form?

ENTRYPOINT is the fixed program; CMD gives default arguments (or the whole command if there is no ENTRYPOINT). docker run image args replaces CMD only; --entrypoint replaces ENTRYPOINT. Exec form ["node","server.js"] runs the binary directly as PID 1 so it receives signals. Shell form node server.js runs /bin/sh -c, which becomes PID 1 and usually does not forward SIGTERM, so docker stop waits 10 seconds and then SIGKILLs.

How to answer

Give the override rules with an example, then the signal consequence of shell form. That second part is what interviewers are really fishing for.

Likely follow-ups
  • Why does my container take 10 seconds to stop?
  • What is a wrapper entrypoint script and how do you make it signal-safe? (End it with exec "$@".)
COPY vs ADD?

COPY copies files from the build context. ADD does the same but can also fetch URLs and auto-extracts local tar archives. Prefer COPY, because it is predictable; use ADD only when you want extraction or a remote file with --checksum.

How to answer

One line each, then "prefer COPY because surprise behaviour is bad in builds".

Likely follow-ups
  • What is the build context and why does .dockerignore matter?
ARG vs ENV?

ARG exists only during the build (and an ARG before FROM is only usable in FROM lines). ENV persists into the image and the running container. Both are visible: ARG values appear in docker history, ENV in docker inspect. Neither is safe for secrets; use BuildKit secret mounts.

How to answer

Lifetime difference first, then the security warning.

Likely follow-ups
  • How do you pass a private npm token during a build?
What does EXPOSE do?

Nothing on the network. It is metadata saying which port the app listens on. Publishing happens with -p host:container at run time (or -P, which publishes all EXPOSEd ports to random host ports).

How to answer

Short and confident. This is a trap question; the mistake is saying it "opens the port".

Likely follow-ups
  • What does -p 8080:80 actually do on the host?
What is a registry, and what is in an image name?

A registry is an HTTP service that stores images, following the OCI Distribution Spec: clients fetch manifests and content-addressed blobs (layers). Examples: Docker Hub, GHCR, Amazon ECR, Azure ACR, Google Artifact Registry, Harbor. A full name is registry/namespace/repo:tag@sha256:digest, for example docker.io/library/nginx:1.30; with no registry, Docker assumes docker.io. Pushes and pulls skip layers that already exist.

How to answer

Say "it is an HTTP file server for content-addressed blobs plus manifests". Then explain tag vs digest.

Likely follow-ups
  • Why pin a digest in production?
  • What are Docker Hub pull limits and how do you avoid them?
Volumes vs bind mounts vs tmpfs: when do you use each?

Named volumes are managed by Docker (under /var/lib/docker/volumes), survive container removal and are the right choice for databases. Bind mounts map any host path into the container; great for live code during development but tied to the host's layout and UIDs. tmpfs is RAM-only and vanishes on stop; good for secrets and scratch files. All three bypass the overlay, so they avoid copy-up cost.

How to answer

One use case each, then "containers should be stateless; state lives in volumes or external services".

Likely follow-ups
  • How do you back up a named volume?
  • Why are bind mounts slow on Docker Desktop for Mac?
docker stop vs docker kill, and what do exit codes 0, 1, 137 and 143 mean?

docker stop sends SIGTERM, waits 10 seconds by default, then SIGKILL. docker kill sends SIGKILL immediately (or another signal with -s). Exit 0 = clean exit; 1 = application error; 143 = 128 + 15, the process ended on SIGTERM; 137 = 128 + 9, SIGKILL, from a kill, a stop timeout or the OOM killer.

How to answer

Teach the "128 + signal" rule; then any code can be decoded on the spot.

Likely follow-ups
  • How do you tell OOM from a manual kill? (State.OOMKilled.)
What is Docker Compose, and when would you not use it?

Compose describes a multi-container application in one compose.yaml: services, networks, volumes, health checks, dependencies. docker compose up starts everything on one host with a shared network where services find each other by name. It is ideal for local development and CI integration tests. It is not a production orchestrator: single host, no cross-machine scheduling or self-healing. For that, Kubernetes or ECS (AWS's managed container service). Note depends_on only orders start-up unless you add condition: service_healthy.

How to answer

Say what it is, where it shines, where it stops. A Walmart SDE-2 candidate reported Compose follow-ups in an LLD round, so be ready to write a small compose file.

Likely follow-ups
  • Write a compose file for an app, Postgres and Kafka.
  • Why does my app crash because Kafka is not ready yet?
What happens to data written inside a container when it is removed?

It is gone. Writes go to the container's writable layer, which is deleted with the container. Stopping keeps it; removing deletes it. Use named volumes or external stores (a database, object storage) for anything that matters. This is why containers are treated as disposable ("cattle, not pets").

How to answer

Distinguish stop vs rm, then the design principle (stateless containers).

Likely follow-ups
  • How does Kubernetes keep data for a database pod? (PersistentVolumes, StatefulSets.)
