Topics: named streams

A topic is a named category of records. Producers write to a topic by name; consumers subscribe to a topic by name. They never need to know about each other. Teams usually name topics after the kind of fact they carry: orders, payments.completed, user.clicks, driver.locations.

A topic is a logical thing. On disk there is no single "topic file". A topic is really a set of partitions, and each partition is a directory of files on some broker. A topic has settings of its own, such as how long to keep data (retention.ms, default 7 days) and how many copies to keep (replication factor).

Careful in production: by default a broker creates a topic automatically the first time someone writes to a name that does not exist (auto.create.topics.enable=true). A typo like oders silently creates a new topic with default settings (1 partition, replication factor 1 on a stock broker). Most companies turn this off and create topics deliberately, often through code review.
