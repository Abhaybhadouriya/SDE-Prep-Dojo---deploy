Quick quiz

Topic orders has 3 partitions. Which statement is true?

  1. Kafka keeps all records of the topic in one global order
  2. Offsets are unique across the whole topic
  3. Records are ordered within each partition, and each partition has its own offsets
Each partition is an independent log with offsets starting at 0. There is no order across partitions.

Two events for order o-981 must be processed in order. What do you do?

  1. Use o-981 as the record key
  2. Send them with no key
  3. Send them to two different topics
Same key, same partition, so they are stored and read in order.

You increase a keyed topic from 3 to 4 partitions. What happens?

  1. Kafka moves old records to the right new partitions
  2. Most keys map to a different partition for new records, breaking per-key order across the change
  3. Nothing changes for keyed records
The partitioner computes hash modulo 4 instead of 3. Old records stay where they are.

A consumer group has processed offsets 0 to 41 in partition 2. Which offset does it commit?

  1. 41
  2. 0
  3. 42
The committed offset is the next record to read: 42.

Where does Kafka store committed consumer offsets?

  1. In ZooKeeper
  2. In the internal topic __consumer_offsets
  3. Only in the consumer's memory
Since long ago (0.9), offsets live in a compacted internal topic. ZooKeeper is removed entirely in Kafka 4.0.

How does a producer find out which broker to send a record for partition 5 to?

  1. It fetches cluster metadata and sends directly to that partition's leader
  2. It sends to a load balancer that forwards it
  3. It sends to every broker
Clients cache metadata (partition to leader) and refresh it when a leader changes.

A topic has 6 partitions and replication factor 3. How many partition replicas exist in the cluster?

  1. 6
  2. 9
  3. 18
Each of the 6 partitions has 3 copies: 6 x 3 = 18. Partitions split data; replicas copy it.

Why might a record survive a little longer than retention.ms?

  1. Retention is only a suggestion
  2. Kafka deletes whole closed segments, and the record's segment may still be active
  3. Consumers extend it by reading the record
Retention works on segment files, not on single records.
