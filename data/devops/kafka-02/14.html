Key takeaways

Remember this

  • Topic = named stream. Partition = ordered, append-only log. Offset = position inside one partition. Broker = server. Cluster = brokers (+ controllers).
  • The partition is the unit of ordering and of parallelism. No ordering across partitions.
  • Same key, same partition: murmur2(key) % partitions. Null key: sticky partitioner spreads batches.
  • Adding partitions remaps keys and breaks per-key order; partitions can never be removed.
  • Consumers commit offsets ("next to read"); the broker stores them in __consumer_offsets. Lag = log-end offset - committed offset.
  • Clients fetch metadata and talk directly to each partition's leader; there is no load balancer in between.
  • On disk: partition = directory of segment files; retention deletes whole old segments (default 7 days).
