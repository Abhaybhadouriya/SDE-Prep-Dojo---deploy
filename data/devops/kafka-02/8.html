Topic vs partition vs segment

One more layer, because "what is on disk?" is a favourite question. A partition is not one giant file. On the broker's disk, each partition is a directory named topic-partition (like orders-1), and inside it the log is cut into segment files of up to 1 GiB each by default. Only the newest segment (the active segment) is written to. When it is full or old enough, it is closed and a new one starts.

This explains two behaviours. First, retention is not exact: Kafka deletes whole closed segments, so a record can live a bit longer than retention.ms while its segment is still active. Second, reading by offset is fast: the segment file names let Kafka find the right file, and the sparse .index lets it jump close to the right byte. Page 07 opens these files byte by byte and explains the page-cache and zero-copy tricks.

Retention and compaction in one paragraph

Every topic has a cleanup policy. The default, delete, removes old segments when they are older than retention.ms (7 days by default) or when the partition is bigger than retention.bytes (unlimited by default). The other policy, compact, keeps at least the latest record for each key and throws away older values for the same key - perfect for "current state" topics such as "latest address per customer" or Kafka's own __consumer_offsets. You can even combine both (compact,delete).
