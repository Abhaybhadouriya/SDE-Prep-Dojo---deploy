Quick quiz

In a Compose project, how should the api service connect to the db service (Postgres)?

  1. localhost:5432
  2. db:5432
  3. host.docker.internal:5432
Each container has its own localhost. On the project network the service name resolves via embedded DNS.

What does depends_on: [db] (no condition) guarantee?

  1. The database accepts connections before api starts
  2. The database's healthcheck passed
  3. Only that the db container is started before api
Start order only. Use a healthcheck with condition: service_healthy for readiness.

You ran docker compose down. What happened to the named volume pgdata?

  1. It is kept
  2. It is deleted
  3. It is moved to the image
down removes containers and networks. Only down -v deletes named volumes.

Which file does Compose read to substitute ${PG_TAG} inside compose.yaml?

  1. The file listed in env_file:
  2. The .env file in the project directory (and your shell environment)
  3. /etc/environment inside the container
.env is read by Compose for interpolation. env_file sets variables inside the container.

You edited an environment variable for one service. What applies the change?

  1. docker compose restart
  2. Nothing; you must run down first
  3. docker compose up -d, which re-creates only the changed service
restart restarts the same container with its old config. up -d compares config and re-creates what changed.

A Kafka broker in Compose advertises only localhost:9092. Who fails?

  1. Clients in other containers, which get told to connect to their own loopback
  2. Clients on the host
  3. Nobody
After bootstrap, clients use the advertised address. Inside a container, localhost is that container.

Which statement about Compose vs Kubernetes is right?

  1. Compose reschedules containers to another host when one fails
  2. Compose is single-host and acts only when you run it; Kubernetes reconciles continuously across nodes
  3. Kubernetes uses depends_on for start order
Kubernetes controllers keep reconciling; there is no depends_on there, you use readiness probes and retries.
