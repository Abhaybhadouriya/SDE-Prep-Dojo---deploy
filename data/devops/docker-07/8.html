ThisIs not the same asThe difference
.env fileenv_file:.env is read by Compose to fill ${VAR} placeholders in the YAML; the container never sees it. env_file: loads variables into the container's environment.
depends_on (plain)"wait until ready"Plain depends_on only orders start-up. Waiting for readiness needs condition: service_healthy plus a healthcheck.
docker compose (v2, a CLI plugin)docker-compose (v1, Python)v1 is retired. Use docker compose with a space; the file is compose.yaml and the old top-level version: key is ignored.
Compose (one host)Swarm stack (docker stack deploy)Compose runs everything on one Docker host. A Swarm stack takes a similar file and spreads services across a Swarm cluster of many hosts with rescheduling. Same YAML shape, different engine.
ports:expose:ports publishes to the host (DNAT rule). expose only documents a port; other services on the network can reach any port anyway.
docker compose downdocker compose down -vWithout -v named volumes (your database data) survive. With -v they are deleted.
