Overrides, profiles, scaling and watch

Override files

If a file named compose.override.yaml exists, Compose merges it on top of compose.yaml automatically. Teams put production-like settings in the base file and developer conveniences (bind-mounted code, debug ports) in the override. For other environments, pass files explicitly: docker compose -f compose.yaml -f compose.ci.yaml up; later files win.

# compose.override.yaml  (auto-loaded in dev)
services:
  api:
    command: ["uvicorn", "app:app", "--host", "0.0.0.0", "--reload"]
    volumes:
      - ./src:/app/src          # live code reload via bind mount
    ports:
      - "5678:5678"             # debugger

Profiles: optional services

Not everyone needs Grafana or a Kafka UI every day. Give a service a profile and it only starts when asked:

services:
  kafka-ui:
    image: ghcr.io/kafbat/kafka-ui:v1.5.1     # maintained fork of the unmaintained provectuslabs/kafka-ui
    profiles: ["tools"]
    ports: ["8080:8080"]
    environment:
      KAFKA_CLUSTERS_0_NAME: local
      KAFKA_CLUSTERS_0_BOOTSTRAPSERVERS: kafka:19092   # a container, so it uses the INTERNAL listener
docker compose up -d                    # kafka-ui NOT started
docker compose --profile tools up -d    # now it is

Scaling and limits

docker compose up -d --scale worker=3   # three worker containers: shop-worker-1..3

All three share the DNS name worker (round-robin answers). You cannot scale a service that publishes a fixed host port, because three containers cannot all bind host port 8000. Resource limits go under deploy.resources.limits (for example cpus: "1.0", memory: 512M) and become the same cgroup settings as --cpus / --memory from Running & Managing.

docker compose watch

services:
  api:
    build: .
    develop:
      watch:
        - action: sync           # copy changed files into the running container
          path: ./src
          target: /app/src
        - action: rebuild        # rebuild the image when dependencies change
          path: requirements.txt

docker compose watch then keeps the container in step with your editor. sync is faster than a bind mount on Docker Desktop because it copies only changed files instead of sharing the whole folder across the VM boundary.
