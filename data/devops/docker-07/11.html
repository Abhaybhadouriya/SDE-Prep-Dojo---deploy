Remember this

  • Compose = one declarative compose.yaml + docker compose up / down; a client of dockerd, not a new engine.
  • up: resolve file → network <project>_default → volumes → pull/build → start in dependency order.
  • Services talk by service name and container port; publish only entry points.
  • depends_on = start order. Add a healthcheck + service_healthy for readiness, and still retry in code.
  • .env fills ${VARS} in the YAML; environment/env_file go into containers; secrets become files.
  • down keeps volumes; down -v deletes them.
  • Kafka needs two listeners: internal kafka:19092, external localhost:9092.
  • Compose for dev/CI on one host; Kubernetes for multi-node production.
