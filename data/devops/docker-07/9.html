Common mistakes and gotchas

Mistakes
  • localhost in a connection string between services. Use the service name.
  • Using the host port between containers. Inside the network use the container port (db:5432, even if you published 15432:5432).
  • depends_on without a healthcheck, then "connection refused" at startup.
  • docker compose restart after editing the file; it does not apply changes. Use up -d.
  • docker compose down -v out of habit, deleting the database volume.
  • Publishing every service's port "just in case", including the database, to 0.0.0.0.
  • Kafka advertising only localhost, so other containers cannot produce or consume.
  • Committing .env with real secrets.
  • Old version: "3.8" lines and the old docker-compose (hyphen) binary. Modern Compose ignores version and is docker compose (space).
Good habits
  • Pin image tags (postgres:17-alpine, not latest).
  • Healthchecks on every stateful service; service_healthy on dependants.
  • One-shot init jobs with service_completed_successfully (migrations, topic creation).
  • Publish only the entry points; bind dev-only ports to 127.0.0.1.
  • Run docker compose config when something looks wrong.
  • Base file + override file; profiles for optional tools.
  • Client-side retries with backoff anyway.
