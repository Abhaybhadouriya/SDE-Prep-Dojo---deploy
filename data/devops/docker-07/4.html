Environment, .env files and secrets

Two different things are both called "env" in Compose, and mixing them up is a classic confusion.

MechanismWho reads itPurpose
.env file next to compose.yamlCompose itself, while parsingFill ${VAR} placeholders in the YAML (image tags, ports)
environment: in a serviceThe containerSet env variables for the app
env_file: in a serviceThe containerSame, loaded from a file
secrets:The container, as a file in /run/secrets/Passwords and keys that should not appear in docker inspect
 
# .env   (read by Compose for ${...})
PG_TAG=17-alpine
API_PORT=8000

# compose.yaml
services:
  api:
    build: .
    ports: ["${API_PORT:-8000}:8000"]      # default 8000 if unset
    env_file: [./config/api.env]          # vars go INTO the container
    secrets: [db_password]
  db:
    image: postgres:${PG_TAG}
    environment:
      POSTGRES_PASSWORD_FILE: /run/secrets/db_password
    secrets: [db_password]

secrets:
  db_password:
    file: ./secrets/db_password.txt       # keep this file out of Git

Run docker compose config and you will see the final values substituted. Never commit real passwords in compose.yaml or .env; the example passwords on this page are for a local laptop only. Many official images (Postgres, MySQL) support the *_FILE convention shown above so the secret is read from a file.
