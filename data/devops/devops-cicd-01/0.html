The story: one class, one storybook

Explain like I'm 5

Your class is writing one big storybook together. If thirty kids write in the same book at the same time, pages get torn and sentences get mixed up.

So the teacher keeps the main book safe on her desk. Each kid gets a photocopy of the book as it is today and writes their new chapter on the copy. When a chapter is ready, a friend checks it, and then the teacher glues it into the main book.

Sometimes two kids changed the same page. The teacher must decide which sentence stays. That is a conflict. And if one kid wrote "draft, draft, fixed spelling, oops, real chapter" on ten scraps, the teacher may glue in just one clean page instead of ten messy ones. That is a squash.

In git terms: the main book is the main branch, a photocopy is a feature branch, the friend's check is a pull request (PR) review, gluing in is a merge, and redoing your chapter on top of today's book instead of last week's is a rebase. This page explains each one as an operation on a graph, because once you can see the graph, every git command becomes predictable.
