Merge: fast-forward or a merge commit

Must know (SDE-1)

git merge feature run while on main has two possible outcomes:

  • Fast-forward: if main has not moved since the branch started, git just slides the main label forward to the feature tip. No new commit is created.
  • Three-way merge: if both sides have new commits, git compares the merge base, the tip of main and the tip of the feature, and creates a merge commit with two parents.
git switch main
git merge --no-ff feature/login -m "Merge feature/login"   # always create a merge commit
Merge made by the 'ort' strategy.
 src/login.py | 42 ++++++++++++++++++++++++++++++++++++++++++
 1 file changed, 42 insertions(+)
git merge --ff-only feature/login    # refuse unless a fast-forward is possible
fatal: Not possible to fast-forward, aborting.

Merging is non-destructive: existing commits keep their hashes, and the merge commit records exactly when two lines of work joined. The cost is a busier graph: on an active repo, git log --graph becomes a railway map.
