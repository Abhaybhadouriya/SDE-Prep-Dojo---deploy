The commit graph: snapshots, parents and labels

Must know (SDE-1)

A commit is a snapshot of the whole project plus a little metadata: author, message, and a pointer to its parent commit (two parents for a merge commit). Its ID is a hash of all of that, so if anything changes, including the parent, the ID changes. A branch is just a label that points at one commit and moves forward when you commit. HEAD is the label for "where you are now".

git switch -c feature/login        # new label at the current commit, and move HEAD to it
git commit -am "add login form"    # feature/login moves forward; main does not
git log --oneline --graph --all
* 9f3c2e1 (HEAD -> feature/login) add login form
| * 7b1d4a0 (origin/main, main) fix header colour
|/
* 4e8a91c add navbar
* 1c02f7d initial commit
cat .git/HEAD
cat .git/refs/heads/feature/login   # a branch really is a 40-hex hash in a file (or in packed-refs)
ref: refs/heads/feature/login
9f3c2e1a5d0b7c4e2f8a6b3d1c9e0f7a2b4c6d8e

From your world

Git's object store is content-addressed, like a dedup store keyed by checksum: same bytes, same hash, stored once. The commit graph is a DAG of parent pointers, like a singly linked list that can fork and join. A branch is a symlink-like pointer to a node (literally a small file holding a hash), and HEAD is a pointer to that pointer. Because a commit's hash covers its parent's hash, the chain works like a hash chain: changing any old commit changes every hash after it. That single fact explains why rebase "rewrites history".
