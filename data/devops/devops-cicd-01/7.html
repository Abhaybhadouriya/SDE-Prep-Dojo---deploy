Squash: turn WIP noise into one clean commit

Must know (SDE-1)

Real branches look like this: "wip", "fix test", "typo", "review comments", "really fix test". Nobody needs that on main. Squashing combines several commits into one. You can do it yourself with an interactive rebase, or let the platform do it with a squash merge.

By hand: interactive rebase

git rebase -i origin/main

Git opens an editor with a "todo list", oldest commit first. Change pick to squash (combine and merge the messages) or fixup (combine and drop this message):

pick   a1b2c3d add login form
fixup  b2c3d4e wip
fixup  c3d4e5f fix test
squash d4e5f6a add rate limit to login
fixup  e5f6a7b review comments
# Commands: p pick, r reword, e edit, s squash, f fixup, d drop ...
[detached HEAD 5e6f7a8] add login form
 Date: Mon Nov 23 10:02:11 2026 +0530
 2 files changed, 87 insertions(+)
Successfully rebased and updated refs/heads/feature/login.

Even easier: when you make a fix for an earlier commit, record it as one with git commit --fixup=a1b2c3d. Later, git rebase -i --autosquash origin/main lines up every fixup under its target automatically.

By the platform: squash merge

With "Squash and merge", the platform builds one new commit on main containing the whole PR diff. Your branch's individual commits never land on main. That keeps main's history readable (one line per PR) and makes git bisect point straight at the guilty PR.

After a squash merge, delete the branch. If you keep committing on it and open a second PR, git does not know the first commits are already in main (the squashed commit has a different hash), so you get conflicts against your own work. Start the next change from fresh origin/main.

Squashing loses detail. If a branch contains several logically separate changes (a refactor, then a feature), keep them as separate, well-written commits (rebase-merge) or separate PRs. Squash the noise, not the meaning.
