Undo and recovery: reflog, revert, reset

Good to know (SDE-2)
  • Reflog: every move of HEAD and branch labels is recorded locally. A rebase that went wrong is not lost: git reflog shows the old tip and git reset --hard HEAD@{5} (or ORIG_HEAD right after a rebase) puts the label back.
  • Revert (safe on shared branches): git revert <sha> adds a new commit that undoes an old one. History only moves forward. Use this on main.
  • Reset (local only): git reset --hard <sha> moves the label backwards and discards work. Never on a shared branch.
  • Bisect: git bisect start; git bisect bad; git bisect good v1.4 does a binary search over history to find the commit that broke something. A clean, linear, one-commit-per-change main makes bisect fast and its answer meaningful.
$ git reflog -5
c41e0b7 (HEAD -> feature/login) HEAD@{0}: rebase (finish): returning to refs/heads/feature/login
c41e0b7 HEAD@{1}: rebase (pick): add rate limit to login
5e6f7a8 HEAD@{2}: rebase (pick): add login form
7b1d4a0 HEAD@{3}: rebase (start): checkout origin/main
9f3c2e1 HEAD@{4}: commit: add login form

From your world

git bisect is the same binary search you run when a kernel regression appears between two releases: mark good, mark bad, build, boot, repeat. With N commits it needs about log2(N) steps, so 1,000 commits take around 10 tries. Squash-merged PRs make each step land on a whole, buildable change instead of a half-done WIP commit.
